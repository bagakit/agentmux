# Native source and system verification

`node packages/native-desktop/scripts/verify-native.mjs --source-only` parses the production Swift, Core, tests and independent fixture. It does not typecheck against the SDK, link, run tests, launch UI or constitute feature acceptance.

`node packages/native-desktop/scripts/verify-native.mjs --source --scratch-path <owned-build-directory>` performs real Swift tests and a DEBUG bare binary build. It compiles the production Node package into its own output and uses its unmodified `NativeDesktop` connection, authentication and native dispatch to consume handshake, OS applications, displays and permission readouts. It does not assemble an app or change permissions. Both baseline and mutant test reports must contain actual XCTest cases. The two isolated Core mutations change an unknown AX reply into a fallback permission and remove capture classification from an explicit pixel snapshot. Only a nonzero test run with actual failed test cases kills a mutant; missing reports, empty selections, compiler failure and process signals fail verification.

`--source` also launches the independent bare `Fixture.swift` process. The fixture supplies only its exact PID/window number, control geometry and read-only field/counter observations. The runner obtains process birth, window and snapshots from production native discovery, submits each input once with its original instance/operation identity, observes actual text and button effects, then captures only that exact window. There is no fixture mode or authentication bypass in the production provider. Missing OS authorization, unavailable effects or failure to capture fails this requested scope. The fixture does not modify the general clipboard. Closing stdin ends its own window/process; cleanup never searches for or kills a process by a guessed PID.

Every source run creates an invocation directory under the supplied scratch path with logs, XCTest XML, the mutated source copies, Node output and a structured report. It also retains its own fixture window PNG and operation metadata. These are local verification artifacts, not a second product state store. Inspect disk space before starting; these commands compile SDK modules and deliberately preserve evidence rather than deleting unrelated caches.

The report always says `featureAccepted:false`: even a successful DEBUG fixture does not prove release signer rejection/acceptance, LaunchServices, permission continuity, selection success/cancellation, multiple displays/HiDPI, macOS 12/13 availability or remaining clipboard/partial-input branches. Those require their separate real-system checks. `--source` cannot succeed by omitting the isolated fixture; `--source-only` remains the syntax-only entry and cannot satisfy T001 acceptance.
