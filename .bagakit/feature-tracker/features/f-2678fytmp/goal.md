# 项目图标：每个项目在左栏显示自己的标识

Contract: `bagakit.feature-goal.v1`
Feature: `f-2678fytmp`

## 目标

左栏十个项目此前顶着同一枚灰色文件夹，这一列不提供任何识别力，只占宽度。目标是让每一行
显示**这个项目自己的**标识；探不到真图标时，仍然给出一个有区分度的兜底，而不是退回那枚
全同的字形。

## 已验证的现状（2026-09-14 逐条核对，每条都给了判别命令）

四条前提在 2026-08-31 定下，**不要重新调研**；下面同时记录它们今天是否已兑现。

1. **照抄参考实现的固定清单，实测 0/10 命中。** 那份清单只探项目根附近，而真实图标在
   `apps/desktop/resources/icon.png` 这类 3-4 层深处。值得抄的是**机制**（主进程探测 →
   magic bytes 嗅探格式 → 编 data URI → 走 IPC → 尺寸上限 → 并发批量），不是那份清单。
   **已兑现**：`grep -n 'SKIP_DIRS\|MAX_DIR_DEPTH' apps/desktop/src/main/project-appearance.ts`
   给出有限深度 BFS 与跳过集（node_modules/.git/dist/build/out/coverage/.next/.cache/.worktrees）。

2. **CSP 是硬约束，不是风格选择。** `apps/desktop/src/renderer/index.html` 的
   `img-src 'self' data:` **没有 `file:`**，所以把路径塞进 `<img src>` 一定加载不出来。
   **已兑现**：`grep -n "base64" apps/desktop/src/main/project-appearance.ts` —— 主进程编
   `data:${mime};base64,…` 过 IPC。

3. **十个项目只有四个有图标。** 其余五个仓库里根本没有任何图标文件，所以兜底必须统一，
   混排会让左缘参差。**已兑现且已超出**：兜底现在是三段而不是两段——真图标 → 名字派生的
   字母牌（`project-monogram.ts`）→ 仓库/文件夹 glyph。字母牌是后加的一层：它让"没有图标"
   的那五个项目**彼此之间**也有区分度，而统一 glyph 只解决了"不参差"。

4. **这条推翻了一条既有设计约束，必须先改 SSOT 再动断言。** 密度合同《控件语言》的
   「一列全同的图标不是信息，是宽度开销」写于"每行都是同一枚文件夹"的时代。
   **已兑现且顺序正确**：交互合同 `docs/design/agentmux-desktop-interaction.md:64` 已写明
   前提变化（"前提变了才改的"，并说明 glyph 退化为"未知"态），
   `apps/desktop/test/project-rail.test.tsx` 的 "removes the repeated project icon" 那条
   已翻面成断言每个普通行**都带** `project-rail-row__icon`。没有出现"偷偷改测试迁就实现"。

## 字母牌那一层的既定决策（2026-09-14，都有判别器）

- **取首个字素簇，不是 `name[0]`。** `"🚀 deploy"` 取码元会拿到孤立高代理项，渲染成 `�`；
  带 ZWJ 的家族 emoji 同理被劈开。`Intl.Segmenter` 是平台自带的答案，不引库。
- **大写钉死 `'en-US'`，不跟随宿主 locale。** 身份不能因为谁的机器语言设置不同就变样
  （土耳其语环境下 `istanbul` → `İSTANBUL`）。**这条没有进程内的行为判别器**——跑测试的
  机器就是 en-US，无参调用逐字相同。试过两稿都是恒真的，已删除，只留注释说明这个缺口。
- **大写后再取一次首簇**：`ß` → `SS`、`ﬁ` → `FI`，牌面只有一格，`overflow:hidden` 会裁掉半个。
- **前导零宽字符要剥掉**，而 `trim()` 不认识 U+200B（NBSP / 表意空格 / BOM 它都认识）。
  只剥**前导**：U+200D 在串中间承重，全串剥会把 `👨‍👩‍👧` 拆成 `👨`。
- **色相复用说话人头像那套派生**（FNV-1a + avalanche + 保留弧补集），键取 `workspaceId`
  而不是项目名——改名不该换颜色。**不新造调色板**：身份色撞上语义色（amber=需要你、
  red=失败、green=成功、blue=人类）比撞色难查得多。
- **色相的判据是统计性的，不是逐对的。** 可用色相只有 190 个整数度，五个点里出现一对靠得近
  是生日问题——一个**正确**的实现在 41.2% 的连续 id 窗口、81.2% 的随机 id 组上都会违反
  "两两隔开 15°"。判据因此改成"200 个相邻对里落在 15° 内的比例 ≤ 25%"
  （实测真实实现 6.5%，朴素字符和 91.5%）。

## 还没做的（有意的，不是遗漏）

- **孤立组合重音 / 变体选择符 / 孤立代理项**开头的名字仍会画出一枚看不懂的牌子。真实项目名
  不长这样；要修就得定义一份"什么才配当字母"的允许清单，那是比本 Feature 更大的决定，
  且猜错会把一枚难看的牌子换成一个**错的字母**。
- **同字母同色相的两个项目不去重。** 参考项目里没有一家做这件事；先看真实使用中撞不撞。
- **色相的感知亮度不随色相补偿**（固定 L=72%，黄比蓝显亮）。除非某个色相实测对比度不够，
  否则不为它把一条 CSS 规则变复杂。

## 边界

图标只表达**身份**，不模拟运行状态——运行仍走独立的尾部状态槽。Scratch 用它自己的品牌图标，
不进这套 per-project 体系。
