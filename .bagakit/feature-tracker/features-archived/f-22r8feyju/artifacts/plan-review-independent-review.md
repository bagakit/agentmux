# 计划修订：把「独立 Reviewer 审查」写成验收条款

日期: 2026-08-29 · 评审结论: **approved**
依据: 用户明确要求「注意每个实现都要被其他的 subagent review 过」。

## 为什么要改计划而不是记在脑子里

上一轮我是临时派 agent 去审的，而**四个 Feature 的验收里一条 review 条款都没有**。也就是说下一次
照计划执行会直接跳过这一步——依赖我记得，不依赖契约。

而它确实值钱：上一轮的独立审查抓出两个我**自己验证过却没看见**的缺陷——

1. 跨 workspace 的可见性判定，导致后台 workspace 里 Agent 完成时通知被**静默抑制**（恰是该功能存在的理由）
2. `removeWorktree` 里一个 `git worktree prune`，会注销**任何**目录当前缺失的 worktree；我还为它写了
   假注释和一个空测试

两个都在我"验证过"的代码里。**自审有盲区，这是证据而非推测。**

## 放在最后一个 task 上

逐个 task 审会审到还在动的代码。最后一个 task 是交付面已经稳定、审查能得出结论的时刻，也正是 closeout
所在的位置。

## 条款要求

审查对着代码逐项核对交付面，重点四类：数据丢失、孤立状态、越过分层边界、以及**空测试**（把生产代码
改坏后仍会通过的断言）。结论与处置记录在该 Feature 的 artifacts 下；**发现的问题先修再收尾**。
