# Cross-device Project groups: private native proof

This fixture renders the actual `App`, `WorkspaceSidebar`, `ProjectGroupsTree`,
`ProjectGroupDialog` and `WorkspaceWorkbench`. The normal Store initializes from
the public Core `AgentMuxSpatialStateStore`. A second store instance observes
the same durable file through the actual filesystem watcher and forwards its
revisions to the Renderer. The production save/dissolve and flush fences stay intact.

The registered local and two remote Projects, file contents, Git associations,
and empty Runtime catalogs are controlled preview facts. Git discovery is a
separate owning qualification. No SSH connection, Agent, terminal process, remote
owner or installed application is involved. No entity snapshot is injected into
localStorage. Only the initial Core graph is seeded, using `desktopSpatialGraph`
and the product's original file Tab/Region and split-layout constructors.

The first ordinary Electron process creates a group through the actual name,
checkbox and submit controls, renames the same identity, creates a second purpose group with overlapping members, then uses an original Folder
to select its workface without moving focus to any group, then uses ArrowDown/Enter to activate the
remote member. Durable ACKs must preserve every original space, zone, Tab,
Region, binding, layout, resource and execution directory. The unknown original
member remains visible and selected in its separate retained group's editor.

The second ordinary Electron process reads the same Core revision, graph and
private Chromium preferences. It verifies the original remote selection and
complete workface, checks that an unavailable member does not redirect to
another device, then dissolves only the first newly created group while the second overlapping membership survives through the actual
neutral confirmation. Core's explicit original group-ID removal receipt is required.

Full-frame wide/narrow dialogs and workfaces, directory alias focus, remote
selection, unknown retention and dissolution are captured with per-image SHA,
dimensions, phase, PID and original DOM/state facts. The actual Vite module
inputs and PostCSS imported stylesheet inputs are sealed against source bytes.
Both generations consume one preserved compiled candidate. Independent visual
review remains required: successful capture never declares aesthetic acceptance.

The final visual scenes also use three explicit raster project images, transient
controlled 12 working / 3 idle and 2 Needs you / 1 error projections, actual
pointer-hover group actions, and one controlled save transport failure with the
same editor and retry. These previews do not establish live Agent or SSH health.
