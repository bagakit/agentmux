# Parallel group control Renderer capture

Run `node apps/desktop/scripts/capture-browser-task-orchestration.mjs` from the repository root.
This private Electron process has isolated home/appData/userData/sessionData and uses the original
production Editor, Parallel, Continue and BrowserPane components with explicit fixture API ports.
It does not operate the user's Sessions or Browsers and does not prove Main execution or permission.

The Editor selects immutable v3 while the retained group and its target run use immutable v1.
Native pointer input reviews the original target, fills its unfinished original call item, and
submits a distinct continuation. The completed item stays completed with its exact original ID.
Unknown dispatch clears fresh values and preserves the continuation ID. A null original-ID lookup
remains unknown; another lookup confirms the same ID without submitting again. An explicit new
continuation can be refused with its inputs retained. An unknown Stop preserves original group
facts, completed actions and the group lookup. No fresh parameter values are written to receipts.

Capture ten complete frames: review in 620/390 dark/light, unknown continuation in 390 dark/light,
known refusal in 390 dark/light, and unknown group stop in 390 dark/light. Inspect target/status
spacing, v1 versus v3 identity, completed/unfinished call items, current warnings, original IDs,
lookup and explicit correction actions. Full-page frames preserve the surrounding real Editor.

The same native process then mounts the production BrowserPane with its source marked driving.
Native input submits a third, distinct continuation through the Pane's actual trusted-event
callback with different fresh item data. Exact callback count, original group/target/run/version,
new read calls and cleared values are asserted independently of the preceding Editor callback.
This proves the Renderer consumer/typed seam only. Root's native owner receipt separately proves
public RPC/CLI authorization, original execution, durable IDs, restart and actual Browser health.

The capture is captureOnly with aestheticReview not-performed. An independent Agent must open
all actual images and write an explicit deliverability conclusion. Source fingerprints include
the original task CSS leaf and imported production modules; changed visual source needs recapture.
