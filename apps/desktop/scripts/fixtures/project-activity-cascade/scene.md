# Project activity cascade scene

This isolated Electron scene mounts the production `ProjectActivity`, shared
Agent reader, real Store navigation and window overlay host. Typed preview
Session and timeline inputs are explicit fixture data. The spatial graph is
committed through the production Core filesystem owner and admitted through
the production Store initialization boundary; execution Host identity is never
inferred from visible placement.

The scene covers multiple Agents, split Regions, repeated Agent occurrences,
an Agent with no confirmed position, and a Mote member. Native Chromium input
checks hover, nested navigation, shared reading, selection, scrolling, Pin,
keyboard navigation and exact explicit navigation at wide and narrow widths.
The wide scene also checks one readable root summary, two-line Zone choices,
the absence of repeated compact metrics, direct single-group entry and explicit
repeated-Agent position cues. Activity cards retain one shared reading target;
the shared Reader still exposes every confirmed original position.

It does not operate the user's application or Runtime, create real Provider
processes, prove Session restart, or certify visual quality. Saved PNGs require
an independent Agent's visual review.

`node apps/desktop/scripts/capture-project-activity-cascade.mjs` captures the
candidate. `--evidence <directory>` selects the private evidence directory.
`--mutation branch-protection` removes the actual menu owner's three branch
interaction guards in the isolated compiled scene, without editing the shared
working tree. The same Reader interaction assertion must then fail; restore the
ordinary compiled scene and run again for Green. Dependency freshness remains
the repository's original workspace guard; this bounded scene does not rerun a
full repository qualification.
