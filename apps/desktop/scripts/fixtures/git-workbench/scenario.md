# Git reading surfaces: ordinary private Desktop

Run against an explicitly pinned candidate HEAD and source snapshot; a dirty worktree is supported. Freeze both values before the native invocation:

```sh
candidate=$(git rev-parse HEAD)
source_digest=$(node apps/desktop/scripts/verify-git-workbench.mjs --print-source-digest)
node apps/desktop/scripts/verify-git-workbench.mjs --candidate "$candidate" --source-digest "$source_digest"
```

`--print-source-digest` reads files only, prints one SHA256 line, and exits before Git subprocesses, imports of built Core, evidence writes, builds or Electron launch. The source manifest includes current tracked and newly added source bytes under `apps/` and `packages/`, root build/config inputs, file modes and symlink targets, including this harness and its fixture documentation. Generated `dist/`, `out/`, native `target/`, dependency trees, local caches/evidence/worktrees, Desktop release outputs, generated brand icons and the compiled workspace-move helper are excluded. Their sources remain bound. A new or deleted input changes the manifest; a digest printed before implementation finishes is not a pin for the final candidate.

Native mode verifies the explicit digest and HEAD, saves `source-manifest.json` plus the relevant binary `source-tracked.diff` and added-source paths, then actively runs `pnpm --filter @agentmux/client-ui... build` followed by `pnpm --filter @agentmux/desktop build`. Each exact command, exit result, complete stdout/stderr logs and log hashes are retained. Source, tracked-diff and added-source identities are checked around both builds, before each launch and after the second process quits. Generated brand resources are not mistaken for source drift. A changed source or candidate is a failed qualification, not permission to discard user work or silently refresh the pin. Build and native execution are separate deadlines; no pre-existing build receipt substitutes for this frozen build.

The script resolves the shared repository from `git-common-dir`. Every round is unique under that repository's `.bagakit/feature-tracker/space-zone-git-tools/native-*`; its private home, userData, runtime and real Git fixture live in a `private/` child removed in `finally`. A unique `amx-gr-*/p` in the system temporary directory symlink to that child shortens macOS socket addresses; the final Runtime directory remains real for Core's owner check, and cleanup verifies the target before removing only its own alias. It neither opens the user's installed App nor accesses their profile, Sessions or repositories. No Store mutation, replacement bridge or storage seed is used.

The production chain is actual built Main/preload/Renderer → original Git owner → real Git, with actual mouse, keyboard and wheel input, public `git.commit`/`git.diff`/`git.open`, and real `packages/core/bin/amux git open` with and without `--oid`. `build-identity.json` binds the frozen source, commands, built files and release manifest. Every release file and release ID is checked; actual loaded entry/lazy JS and CSS resources are checked against the same built identity in both processes. Native window visibility and actual document visibility/focus are required; OS foreground focus is diagnostic, while successful control hits and committed input prove operation. Renderer release shell identity alone does not prove Renderer source compilation; this gate additionally binds the build between equal frozen source snapshots.

Scenes:

- The content tool remains internally `files-branches`, visibly `Files + Zones`; it has no Git view switch or Git branch-candidate rows. Capture normal dark and narrow light navigation. The parallel Git tool is clicked through `button[data-space-tool="git"]`, initially selecting Changes. Its native `Git view` History/Branches buttons are scoped to that tool. The Zones `Manage worktrees` entry must reach the original Git Branches owner, not imply creation or create a second branch directory under Files.
- The real Git fixture has two existing worktrees with distinct staged files and frozen HEAD/index/status/file-byte baselines. Only the primary resource is configured at startup. Open the second worktree by actually clicking its existing Git Branches row; observe the original WorktreeService registration through native config and the displayed exact resource ID, then wait for its real Zone binding in the durable catalog. No second Workspace, Zone, layout or storage record is seeded.
- Open one real file per discovered Zone through public `file.open`, retaining its actual placement/navigation receipt, exact original Tab/Region/display occurrence and visible Monaco body. In Files + Zones, compare the nonempty directory to the two actual catalog bindings, excluding branch-only candidates. Click the original Zone buttons to restore both workfaces without creating replacement Tabs.
- Changes qualification records the actual `data-git-workspace`, full displayed worktree path, checkout branch, enabled staged-file input and same-owner native `git.status` result for each exact resource. Type different unsent commit messages through real CDP mouse/input events. Verify empty initial isolation and preservation through Agents/Git, Changes/History and both Zone round trips; no commit button is pressed. Capture the primary and secondary worktree contexts and restored messages in complete normal/narrow, dark/light frames.
- Previously visited resource forms remain mounted under hidden ancestors. All UI queries and actions resolve only elements with actual `getClientRects()` and visible computed visibility, including Git view controls, History roots/selects, Changes inputs, workface editors and portal menus. Hidden retained forms cannot satisfy the active-resource assertions or receive input. Loaded JS/CSS resource identity intentionally covers all loaded modules, including modules backing retained hidden surfaces; that is not a visible-UI query.
- While the secondary worktree remains selected, choose the different `refs/heads/main` History reference through the real native select. Record the chosen range, unchanged original Zone/Tab/Region, and subsequent Changes DOM/native status still targeting the secondary worktree with its own checkout branch and unsent message. Capture both the ref context and exact Changes path. Freeze both Git baselines before this UI sequence and compare them afterwards and across ordinary restart, rather than rebasing the expected result after an unintended write.
- Capture Git Branches with the unbound `topic/pure-branch` still available as a resource candidate. Unknown-Zone refusal and asynchronous late-result injection are not claimed by these real known-resource interactions; they need separate evidence.
- Click a sidebar subject: independent fixed commit details, full message/all parents, no embedded History; long subject/path at normal dark and measured narrow light Region.
- Select a file: readonly Monaco appears within that same Region, without adding Regions. Attempted input and every UI/public read preserve fixture HEAD, index and exact dirty-file bytes.
- Explicit repository History: no implicit first selection; one main History plus sidebar summary. Preserve range/pages/scroll through expand/return; a larger viewport may prefetch further along the same snapshot.
- Actual wheel prefetch happens before the original loaded edge. The observed DOM rows/SVG nodes are windowed and drawn edges match real parent OIDs. CPU/render-isolation claims require the separate actual-owner qualification.
- Locate an unread root commit: locating alone does not drain pages; each explicit `Read next history page` is bounded. Once loaded, the actual older row appears inside the virtual viewport. A one-commit reference proves an outside-range target keeps the selected fixed details and current filter.
- Explicitly open a separate Diff, move its Tab with the real menu, choose Git History and observe the ordinary durable `workspaceTool`/`workspaceGitView`, workface selection and two resource-keyed unsent commit messages without setting storage. Quit normally and move fixture refs. Relaunch the same private profile: before any navigation, the nondefault Git tool and History view, content label, saved workface and both drafts must match; capture that complete screen. Both original workfaces and their bindings persist with the whole graph. Original Region/resource/selection/file/history range/layout persist, inline and separate Diff still read the original fixed OID, and the secondary worktree's HEAD/index/staged bytes remain unchanged. The second launch receives no replacement state or fixture seed.

Theme is a controlled presentation input; the App, Git data, Monaco and ordinary restart are real. This scene does not qualify installed-package identity, remote Git transport, Agent recovery, source-mutation coverage or unrelated-Session scaling costs. A behavioral `passed` receipt does not sign aesthetics or the whole T-003 Task. Independent reviewers must open every final full PNG, identify concrete issues, and require recapture after candidate changes, following [the visual review guide](../../../../../docs/guides/agent-visual-e2e-review.md). Development of this harness is not authorization to run it: the coordinating Agent chooses the final frozen candidate before native execution. No product commit, package or installation is part of this gate.

Each normal Quit has a bounded 90-second observation budget within the whole native deadline. Its original PID, start, effective budget, elapsed time and actual exit result are recorded even on failure. Only an actual `exitCode: 0` with `signal: null` permits relaunch qualification; probe cleanup, a killed process or a successful blank-profile diagnostic cannot substitute for this scene's ordinary exit and original-profile restart.
