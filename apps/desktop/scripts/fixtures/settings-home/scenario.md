# Settings Home and navigation review

The source contract is [Settings information architecture](../../../../../docs/design/behavior/settings-and-observation.md#设置页的信息架构) and [Overview, brand and composition](../../../../../docs/design/presentation/settings-and-observation.md#overview品牌与阅读构图).

Run `node apps/desktop/scripts/verify-settings-home.mjs`. `--visual-only` captures a changed visual candidate without repeating completed behavioral mutation tests. `--pages=overview,profile` limits page review to an explicit nonempty subset of actual catalog IDs; requested and resolved scope are recorded, and unknown or repeated IDs fail. Common navigation, draft and exact-object checks still run.

The fixture mounts the production App, SettingsPanel, module catalog, editors and CSS over the existing public Preview API in an isolated Electron profile. Setup provides valid controlled directories and three authored Prompt samples through the original configuration API, then selects an existing matching Preview Agent through the original Store. The actual Settings button, sidebar, compact picker, search, editor and Avatar action are then operated through trusted Electron input. Config saves and original work-surface references remain observable. The fixture does not use a real user Session or claim Runtime, persistence, external-service or installation qualification.

The capture covers the Home in wide, short, compact and narrow windows in both themes; real search with a retained draft; every page in the production catalog in both themes; continued reading of overflowing pages; compact versions of every selected configuration page; and the exact Executor entry from the original Avatar. No hand-maintained page list establishes completeness.

The runner falsifies the actual owning source for the initial group expansion, ordinary App entry, retained editor lifetime, exact-object route forwarding and Home destination callback, then restores the same source. `--navigation-mutation` removes the local selection-surface rebind and must fail the actual Electron geometry check after a group disclosure changes. A load failure or timeout is not a passing mutation result. The generated receipt records the loaded source identity, product callers and native interaction boundary. Screenshots are evidence for an independent reviewer; successful capture does not claim aesthetic approval.

The decision-feedback subset (`--pages=continuity,automation,survey,mobile,focus,browser-agent-control`) edits combined follow-up conditions and retry bases, opens same-operation rechecks in wide/compact dark/light views, selects real local PNGs through Chromium's file-input protocol, and separates scanning from copying the exact displayed connection link. The isolated Preview link and clipboard ports are observed without contacting a phone or writing the system clipboard. Focus and takeover compare and return twice in both compact and short windows; assertions preserve the original input, value, focus, pane scroll and every App ancestor scroll. Trusted pointer preparation scrolls real readers only, so a test click cannot move the overflow-hidden App frame.

`--preview-return-mutation --pages=focus` (or `browser-agent-control`) changes the loaded production return owner to reset its pane scroll. The native original-reading-position assertion must fail; startup failures and timeouts do not qualify. Full native screenshots still require independent visual approval.

The full-page audit captures both wide themes through every outer and inner reader. After the original task flow it clicks all visible original progressive-disclosure summaries, including newly revealed nested summaries, then captures the expanded page in both wide and compact themes. These are isolated reading actions with zero implicit configuration saves; no external application authorization is implied. The longer native process bound accommodates the additional complete-page captures without weakening assertions.

`--focus-content-mutation --pages=focus` restores the original fixed canvas height in each CSS bundle that consumes its owning rule. The real idle-reading or Links geometry must reject the unused space. A restored run checks both content-sized examples and preserves the populated reading and exact return flows.

The Lark subset uses typed isolated connector results through the actual SettingsPanel and original setup owner. It opens the bot library, credentials, saved bot, current setup, progress, permissions and publication in wide, narrow and short panes. Navigation and disclosure have zero connector writes. Separate explicit service save, credential save, permission request and version creation retain their exact original inputs; a newly saved bot remains unconfirmed. These observations do not establish live platform authorization, approval or message delivery.

## Bounded Capsule / Goals introduction review

`--concept-intros` selects only Capsule and Goals before the general Home/navigation audit. It captures the production introductions and original configuration through their real readers at 1440×940 and 500×840, in dark and light themes. Actual cross-page navigation retains the same Capsule and Goals draft inputs, edits remain unsaved until one explicit save per original owner, and exact save payloads and original work-surface preservation are asserted. The controlled Capsule ports supply running/config/list observations only; no real service lifecycle, page creation, backend persistence or installation is qualified.

`--concept-intros --concept-intro-mutation` privately removes the exact `<CapsuleIntroduction />` consumer from its original production pane. The actual missing-introduction assertion must fail; compiler errors and timeouts do not count. Source, loaded mutation and complete native frame evidence are written only under `.tmp/settings-companion-intros`. Independent aesthetic review remains required.

The same bounded review now requires both production artwork images to exist and decode before capture. `--concept-intros --goals-art-mutation` privately removes the whole production image element whose source is `goalsArt`, without changing dimensions, replacing the introduction or modifying the working tree. The original Goals image-presence assertion must fail before waiting for a missing resource. This complements the retained Capsule introduction-consumer mutation; run only the mutation relevant to the current change.
