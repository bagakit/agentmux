Run from the repository root. Reuse `capture-agent-collaboration-graph.mjs --scenario list-feedback`; this is the original source App/List/card/operation chain, not a component showcase. Product JS/CSS is pinned to an immutable Git ref. Current fixture, observer, resolver/package metadata and compiler-loader bytes are separately hashed; this is not a hermetic repository snapshot.

## Native visual and interaction arm

```sh
COLLABORATION_CAPTURE_SOURCE_REF="${CANDIDATE_REF:?set immutable candidate ref}" \
node apps/desktop/scripts/capture-agent-collaboration-graph.mjs \
  --evidence "${LIST_NATIVE_EVIDENCE:?set new empty evidence directory}" --scenario list-feedback

node apps/desktop/scripts/capture-agent-collaboration-graph.mjs \
  --verify "${LIST_NATIVE_EVIDENCE:?set completed native evidence}" --scenario list-feedback
```

Fourteen bounded complete PNGs cover directions, exact same-name/different-Host subjects, finite native intermediate phase, settled feedback, narrow/light/dark, early real viewport departure/return, reduced motion, actual document visibility, and the original Stop/detail/focus path. The original Map return adds one integrated static frame, not another Map matrix. Frame count alone never qualifies the arm: actual phase clocks, readable text geometry/hit, exact controls, unchanged original workfaces/draft and native focus restoration are checked. Independent Agent image review remains separate.

Only the real visibility episode temporarily disables CDP focus emulation. BrowserWindow `showInactive`/`hide`, visibility events, List activity and raw visible-return observations occur before emulation is restored in `finally`. No visibility getter, explicit DOM focus or user window focus is assigned. An unobservable native state remains failed/unknown.

Three separately confirmed Stop cases use three distinct original private controls/Runs. The original menu, confirmation and operation controller call a typed private API whose promise is deferred. Rejection of an exact captured promise exercises the original unconfirmed/failed owner. The fixture never writes operation or phase props, replays an unknown request or executes a user Run/Provider lifecycle.

For a bounded two-frame correction after independent image review, set `COLLABORATION_CAPTURE_LIST_VISUAL_REFRESH=1` with the same `--scenario list-feedback` entry and a new evidence directory. This mode cannot run cost. It captures only the dark middle and exposed failed detail, declares its own source/compiled/harness identity, and verifies through the ordinary `--verify` command. Middle requires a shown-inactive private window, nonpending finite native start/current time and actual original rAF/CSS clock advance before the real capturePage bracket. Failed detail reveals the same original operation through its scrollport and records full clip/hit/actions; it never resends an existing request. Other independently approved PNGs remain separately attributed to their original receipt, not adopted as new captures or aesthetic approval. No duration/currentTime/CSS/focus manipulation is permitted.
