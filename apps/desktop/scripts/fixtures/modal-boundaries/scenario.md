# Modal boundaries native proof

Run `node apps/desktop/scripts/verify-modal-boundaries.mjs --case scrim|input|shared --mutations` from the repository. Each invocation creates a fresh local evidence directory; `--output DIRECTORY` selects an explicit empty directory. The script compiles actual production source and binds consumed source, dependency, external Core loader and compiled artifact hashes. Mutations are private compiler transforms; production files remain unchanged. Each selected case must pass, its selected defects must fail through the independent oracle, and the same original candidate must pass again.

`scrim` reads actual native compositor alpha at all four Browser corners and center, verifies gaps stay transparent and overlapping Browser bounds are dimmed once, and checks lower opaque Chrome exclusion with rounded corners. Its oracle uses predetermined physical sample points and expected alpha; it does not call the production geometry or SVG helper to calculate expected results.

`input` creates an actual Browser through BrowserViewManager and exercises NativeOverlaySurfaces over the same original page. Native top-hit synthetic pointer, keyboard and wheel events must not change the background page during preparation, visible or nested modals; CDP commands addressed to the original page, including the actual public page dispatcher's `cdp` capability, must still produce the real page-side action. Agent and modal isolation compose on the same native owner; each release retains the other demand. Presentation failure keeps the original page and draft usable; a profile change retires the exact old page and barrier. This is native input forwarding evidence, not a claim about physical OS devices.

`shared` mounts actual Modal, ConfirmationDialog, HostFolderDialog and DocumentOverlayPortal with authored production styles. It verifies focus fallback without focusable children, busy confirmation and removal of the last control, Cancel autofocus, attached controls, single Escape dismissal, both IME ownership markers, actual ordinary Chromium form submission, and retained input identity, draft and text selection when the Portal moves to a second real document and returns. HostFolder uses an explicit private API receipt; no actual directory or Agent is created.

The existing ui-layering proof retains the full Workbench close → Stop confirmation → shared Modal → collector → Hook → IPC → real Browser owner → native projection consumer and its window/attachment matrix. Its preparation assertion now checks both original native hit isolation and original-page CDP action, rather than preventing every mouse event on the page.

An OS image is captured only when the existing screen permission is already granted and the exact private Window media-source identity is available. Otherwise evidence names the missing capability; the proof does not request screen permission or start another application. Renderer and native compositor captures are never presented as an OS composition. Independent image review remains separate from machine behavior assertions.
