Owning behavior: [common Conversation protocol](../../../../../docs/design/behavior/conversation-mode.md#共同对话协议与外部交流入口). Presentation: [conversation mode](../../../../../docs/design/presentation/conversation-mode.md).

The mounted native SDK → original Core → public RPC → registered IPC consumer creates the private public-scene input. This preview mounts the actual common message card, speaker resolver, Channel metadata hook, connection header and cache panel with production CSS. Only subsequent typed cache DTOs and metadata notifications are controlled. It does not control a user Session, hold live credentials or certify native account delivery.

Use native clicks to open saved profiles, refresh, observe pending and failure states, and clear the exact profile. Simulate an original group rename through the preview's notification source. Capture wide and narrow reading, busy, failed and cleared views; verify complete original body, recorded identity, current name, status and available controls. Independently open and review the resulting full images. A captured image is not aesthetic approval.

`node apps/desktop/scripts/capture-channel-profiles.mjs --mailbox-reading` retains those five states and adds the actual Desktop Mailbox reading entry. It requires the qualified T019 positive consumer's immutable original outputs and report hashes. The producer has already exercised the original Core/SDK/IPC/preload chain; this capture reuses its exact bounded timeline, input journal and saved profile DTOs. It mounts the production `SessionMailbox`, which independently demands the visible actors through its normal metadata hook. It does not dispatch inputs, open another Core reader, control the producer's former Run or certify a live tenant.

Use the original Mailbox button and Inputs tab. Capture the list containing both the Desktop history row and shared input-journal row. Select the history row, capture its original detail, return through the original Back to Inputs button, then select and capture the journal detail. These are three mutually exclusive product states, not a composite or a product layout change. Observe each exact row's original key, author, full body and saved avatar URL; the list uses its original 18px avatar and the detail its original 20px avatar. Require the actual images to finish loading before capture. The producer's example CDN URLs are retained in the DOM; only these private fixture requests are redirected to deterministic loopback avatar bytes, explicitly recorded in the capture. No real profile image content or external network delivery is claimed.

The three Mailbox frames are a narrow visual delta. They do not replace or expand T006's eighteen representative images, and the original default capture remains the five profile states. Independent review must actually open the complete Mailbox list and both detail images, judging readability, identity hierarchy and original compact density. A passing consumer proof, matching URL or successful capture does not sign visual acceptance.
