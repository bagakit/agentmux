# Start-page personalization and pointer cost

Run `capture-browser-start-page-refresh.mjs --evidence <new local directory> --personalization`.

The same real App → Survey → Workbench → BrowserPane is mounted. Customize uses the original SettingsNavigation context and Survey settings module. Title, count, interactive-background checkbox, actual HTML file input and FileReader are operated with native CDP input. A private preload bridge sends the original configuration edit to actual ConfigOwner.edit → ConfigStore.save → confirmSaved. A fresh ConfigStore validates separately reread disk bytes before the Settings surface closes. This does not claim the complete production IPC registration or an ordinary installed-application restart.

The unsent original Browser address and Browser/Profile/Workspace identity survive both personalization save cycles. The first cycle saves a title, six cards, an inline locally selected JPEG and disabled interaction; the second enables interaction through the original setting. Before that, two additional original settings saves produce default-page off/on cost baselines. The image comes from this same probe's native local HTTP-page capture, not user data. Screenshots cover default dark/light/narrow/large, two actual pointer positions, reduced motion, settings draft, disabled custom background, custom dark/light/narrow.

Cost observations keep one visible homepage. Exactly 100 then 1000 unrelated launcher Tabs are retained in the same production store and layout of another Workspace. The same 48 native pointer moves cross the empty top strip; there are no hover-card events. Both original plane and sheen style mutations must occur and differ. A minimum 360 ms settle exceeds the 280 ms finite transitions. CDP Performance metrics and native timeline traces retain Layout, style, Paint/Raster/Composite/DrawFrame/Commit and main-thread tasks over 50 ms. Idle, reduced-motion and actual Electron-hidden document windows must write no layer styles. Disabled interaction has no atmosphere layer. On/off baseline uses unchanged default title/history/image/theme/viewport, with the same native trajectory at both retained scales; custom-wallpaper off is a separate scenario.

Native LayerTree events retain the matched atmosphere content layers, their dimensions, paint counts and compositing reasons, plus whole-page content area and the largest five layers. `native width × native height × 4` is explicitly one hypothetical RGBA backing estimate, not measured GPU memory; tiling, buffering and actual allocation remain unknown. Native Electron GPU feature/device facts and available CPU-side GPU-process trace work are retained; they do not measure hardware execution, power or VRAM. CDP dispatch acknowledgement is not input-to-photon latency. These boundaries are recorded in the receipt instead of inferring low rendering cost from zero Layout alone.

Full trace files are gzipped beside the receipt. No user Run, PTY, native Browser resource or background periodic animation is introduced. Hidden-state sampling makes one bounded attempt: hide only this private Electron window, read actual document visibility, request nonblocking native Electron pointer events, and restore original background throttling. Hidden platform input delivery is not claimed. If visibility observation cannot finish, the receipt says unavailable; it never synthesizes visibility or operates the user's window.

Ratios report this machine and trace window, not a universal latency guarantee. Whole-Renderer costs include normal App and trace overhead; the check blocks a proportional increase with unrelated retained Tabs.
