# 工作区媒体播放真实 Renderer 采图场景

本说明对应 [main.cjs](./main.cjs) 驱动的采图与重启两段进程，由 [verify-workspace-media-playback.mjs](../../verify-workspace-media-playback.mjs) 构建并执行。设计预期只读取当前 SSOT：交互合同的 [主观审美端到端验证](../../../../../docs/design/behavior/shared-rules.md#agent-主观审美的端到端验证)、[本地链接的真实格式预览与二进制保全](../../../../../docs/design/behavior/files-and-git.md#本地链接的真实格式预览与二进制保全)，以及密度合同的 [主观审美判断边界](../../../../../docs/design/presentation/shared-rules.md#agent-主观审美的判断边界)、[本地文件查看与编辑表面](../../../../../docs/design/presentation/files-and-git.md#本地文件查看与编辑表面)。此处不复制设计规则。

## 真实入口与操作

[entry.tsx](./entry.tsx) 初始化真实 store，挂载 `FileExplorer`、`WorkspaceWorkbench` 与 `WindowOverlayHost`，使用产品 `styles/index.css`；页面的 Content-Security-Policy 在构建时从产品 `renderer/index.html` 原样注入。HTML 只设宿主根容器尺寸。Main 侧是真实的 `WorkspaceFiles`、`WorkspaceMediaStreams` 与 `AgentMuxSpatialStateStore`，经生产 preload 暴露；File 通过 store 的 `openFile` 打开，与人点击文件树走同一入口。

| 帧 | 实际操作 | 观察对象 |
| --- | --- | --- |
| `video-start-dark` | 打开 55 MB H.264/AAC 的 `promo.mp4`，等首帧，空闲 5.5 秒不播放 | 开播前主播放圆盘、画面适配后的舞台 |
| `video-controls-dark` / `-light` | 播放、暂停、拖到 95%，唤出控件并指向进度条 2% 处，等指向帧解码 | 玻璃控件条、已缓冲范围、指向帧与时间、明暗主题 |
| `preview-mid-dark` | 真实指针在同一次指向中依次跳到三个位置，取第二个位置的帧显示后 | 指向帧以指针为中心，帧与时间组成一个单元 |
| `preview-first-dark` | 一次新指向的最初时刻，指向帧尚未解码 | 只有时间，没有空框或旧帧 |
| `drag-held-dark` | 播放中按住进度条拖动 32 步后保持按住 | 主画面跟手、没有播放圆盘、按住时不显示指向帧 |
| `preview-reduced-dark` | 模拟减少动态与减少透明度后指向 | 结束态仍显示帧与时间 |
| `preview-short-dark` | 窗口压矮到进度条上方只剩 120–124 px，刚过显示画面的门槛 | 规则允许的最小画面（约 72–76 px 高）仍能辨认，在画面以内，不压住主播放圆盘；看不清就提高门槛。控件条按画面自身宽度收起，显示的每个按钮（含全屏）都完整落在画面内 |
| `preview-too-short-dark` | 再压矮到不足 120 px，指向进度条末端 | 只显示时间，时间停在画面右侧以内 |
| `video-narrow-dark` | 右侧并排 `notes.md`，视频 Region 约 34% 宽 | 窄 Region 中保留的播放、静音、时间与全屏 |
| `preview-narrow-dark` | 同一窄 Region 指向 55% 处 | 窄宽度下的帧尺寸与边界，主播放圆盘不被压住 |
| `preview-edge-dark` | 同一窄 Region 指向进度条末端，此处以指针为中心的帧会越过画面右侧，并落在主播放圆盘上 | 帧停在画面两侧以内并留出间距，圆盘让位 |
| `audio-card-dark` / `-light` / `-narrow-dark` | 打开 `tone.m4a`，再并排到约 30% 宽 | 音频卡片、主绿走带控件、窄宽度下的收起 |
| `hls-vod-dark` | 打开本地 HLS 点播 `hls/index.m3u8` | 列表播放与点播时长 |
| `live-dark` / `-light` | ffmpeg 正在写入的 `live/live.m3u8`，播放超过 2 秒后再观察 15 秒 | LIVE 标记、无伪造总时长、明暗主题 |
| `deleted-dark` | 打开 `doomed.mp4` 后删除文件，拖到 95% 读取从未取过的尾部 | 「File was deleted」而不是格式不支持 |
| `restart-dark` | 同 profile 第二个进程启动 | 原 Tab、Region 与 File 引用恢复后重新解码 |

## 断言与边界

行为断言写在 [main.cjs](./main.cjs)：开播前读取量小于整份文件且空闲 4 秒增长不超过 1 MiB，拖动产生非零起点的 206，观看与拖动后总读取仍小于文件；窄 Region 四类控件可命中；直播 15 秒内列表请求不超过 20 次；删除后的失败原因来自租约事实；生产 CSP 不拦任何媒体请求；重启后 Tab 与布局和退出前落盘的一致。PNG 成功不代表审美通过。

指向预览阶段用真实指针输入，先暂停主播放并等其读取归零，此后开出的请求才记为预览读取：掠过进度条不开请求；三个位置各自的首帧时限，读取起点与范围对照 ffprobe 从夹具得到的关键帧表；位置取在关键帧之后、整个窗口在选定位置前无人读过之处，因为同一 URL 的已读字节可能由平台缓存直接供给，基线前和选定位置前开出的连接此后都不能再增长；放不下三个这样的窗口时判本轮夹具不适用，不放宽条件；窗口只判请求起点，因为请求发出的字节包含解码器没有读走的 socket 缓冲，夹具每个窗口在目标之后至少容纳 4 秒媒体，否则判夹具不适用；三个位置由同一个解码器元素显示，每个位置都要有自己发出了字节的媒体数据请求，帧显示后读取在 1 秒内停止，随后空闲 4 秒增长不超过 1 MiB；索引区读取不超过索引大小加 G（相邻关键帧之间的最大字节跨度）；短时回返由同一解码器元素显示，不重读索引只作旁证；离开后 4 秒内解码器消失且非空的预览请求全部关闭，之后 4 秒不再开请求，主播放位置与播放状态不变；播放中停在一个解码字节仍无人读过的关键帧上，控件隐去后 4 秒内解码器消失，该窗口非空的请求和新解码器的索引读取全部关闭；随后的连续扫动始终用同一个解码器元素，最多一个在途 seek；指针停下后至多再开始一次 seek，它在停下时仍在途的 seek 落地后 50 ms 内开始（没有在途的从停下算），最后位置的帧在落地后 1 秒内显示；扫动止于关键帧之后，最后一次 seek 读得少、解码得少，但这 1 秒仍包含一次未读字节上的重开读取；扫动前先清空长任务记录，再在页面里执行一次约 80 ms 的任务，它必须被记为长任务，之后扫动期间主播放持续前进、没有 waiting、没有超过 200 ms 的长任务；按住拖动跟手，松手落点后续播且不播报暂停或播放，紧接着一次拖动之外的暂停必须播报 Paused，且自拖动开始只有这一条播报，证明同一观察能记到播报，松手后也没有迟到的 Playing；原地按下与按在滑块上都落在指向时间；HLS 点播的拖动与落点。到达一律以元素自身的 seeking、readyState 与官方位置判定，帧回调的呈现时间只作旁证。文档隐藏时的释放只由组件测试覆盖，因为采图窗口从不显示。

媒体全部由 ffmpeg 现场生成（测试图与正弦音），不含真实用户内容。Session、Git 与 Host 只在 API 边界给出空集或「非 Git 仓库」，不代表这些能力的验收。远端 Workspace 的播放不在本场景内。
