# Capsule conversation presentation

The fixture mounts the real ConversationMessage, Capsule card, trusted question controls and shared image viewer. The private Capsule HTTP owner, native Browser manager, SDK and capture pipeline supply the actual page. Only transport, reply delivery and Workbench editor persistence use private test ports. The fixture supplies its actual provider avatar to the timeline; the unused global-identity fallback throws if invoked and records the attempt. Notification read receipts use the existing narrow UI storage port; no user Session or Run is contacted.

`node apps/desktop/scripts/verify-conversation-capsule.mjs` retains the full native first-press, used-document lifetime and clipped-input counterexample. It needs an explicitly available foreground window.

`node apps/desktop/scripts/verify-conversation-capsule.mjs --presentation-only` keeps the private native window hidden. CDP operates only Renderer controls and never supplies native input eligibility. This scope checks current formal CSS on the same real DOM, live page pixels, bounded preview and diagram viewer, Host keyboard input, Hide/Show editor identity, remounted draft bytes, partial metadata failure, and the saved unknown operation without repeating its submission. The native used-page lifecycle is outside this scope.

Capture wide light and dark cards, narrow and short views, long Chinese titles and drafts, pending and unknown answers, and missing-recipient questions. Pair whole-card images with answer views so the draft and primary action are both visible. An independent reviewer must inspect the complete images for hierarchy, alignment, readable controls and overflow; successful assertions or captures do not prove aesthetic quality.

The presentation contract is in [Capsule presentation](../../../../../docs/design/presentation/local-page-hosting.md). Browser input ownership remains with the original native implementation. A hidden-scope result does not establish full native input, installed-build behavior or application recovery.
