# Browser operation feedback Native scenes

This private producer consumes the current production BrowserViewManager and dispatcher in stock Electron. It uses generic HTTP controls, strict CSP/Trusted Types and two embedded documents. No product package, installed App, user page, credential or Agent Run is controlled.

Normal, narrow and short original pages exercise a single real hover/click/fill, completion feedback, waiting, native input takeover and reduced motion. The parent Window and the original WebContentsView retain their actual owner. Native page captures and exact-PID OS captures have separate provenance. The independent reviewer must open the original PNGs, judge whether ordinary single actions are perceptible, and check page readability and restraint; capture success alone does not approve appearance.

Two ordinary private process exits and launches consume the retained Browser/profile input and real profile storage. This thin producer can prove that local Browser/profile restoration and absence of old feedback work. It does **not** prove Desktop Tab/Region/focus restoration or health of a real Core/ctxmux Run. Those remain required by T023 and must come from a genuine complete product restart receipt. A thin receipt cannot substitute a generated DTO for those facts.

The producer never holds an original action or loops actions to make its single-action picture pass. It retains failed receipts and identifies Source drift. Only its own temporary root/processes are cleaned after evidence is copied.

The `actual-async-page-work` scene is a separate real fetch and finite SHA-256 page job. The pre-capture read must show real unfinished work and running glow. The actual page job's recorded start/finish must bracket the whole native capture, and its real RPC must be unsettled at capture return. Post-capture CDP/Mojo reads may be queued until completion; preserve their actual returned timestamps and completed values rather than rewriting them as working. It cannot substitute for the ordinary single click/hover captures, and it never delays their return.

The source-derived target frame is reacquired through the current CDP document sender. Same-process and cross-process targets are distinguished by actual frame/session identity, not URL/name matching. Previous child completion cues are observed directly after a new operation, hide and actual native input. Electron's main-widget sendInputEvent may clear child feedback while failing to route a click to an OOPIF. That attempted-input clear has a separate label; a successful child-click label additionally requires a trusted event and real child counter increment. True OS OOPIF input remains unverified when the exact-PID OS service cannot read the window. Observation must precede the old real expiry or the counterexample is inconclusive. A fixed bottom-right page control checks real center and full label visibility; one actual script navigates and clicks in the new document.

Commands: `node apps/desktop/scripts/verify-browser-operation-feedback.mjs`. Private presentation may disable background throttling and explicitly enable accessibility; those actual conditions do not certify product defaults. Source-resolved target handles are observed passively, and a fresh read-only session is acquired only after the original Manager releases its debugger, so delayed RPC cleanup cannot consume the short completion cue. New layout is captured before single actions. The author runs this only after the production Source owner supplies a stable slice. The output attempt contains actual loaded Source bytes, the exact executed thin bundle, raw process reports, original PNGs and exact-PID OS metadata with hashes. `passed` is technical private-scope proof only; `taskComplete` remains false, aesthetic review is independent, and full Desktop/real Core Run recovery is not tested here.
