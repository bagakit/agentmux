# Space context clarity capture

Run only after the owning product inputs are stable and the final product file
list in `inputs.mjs` is confirmed:

```sh
node apps/desktop/scripts/capture-space-context-clarity.mjs
```

`--knowledge-only` captures the 12 Knowledge scenes against the two stable
Knowledge product inputs while the independent shared-frame slice is still
under development. It still mounts the actual Dock/Sidebar and records all
compiled inputs, but does not qualify the Mote/Folder integration or T-003.
Run a fresh full integrated round after all five owning inputs are stable.

`--details-only` captures four affected regression frames: normal list/control,
normal detail, short mixed-status detail and its original list after Close. This
mode guards all five owning inputs. It qualifies only this affected subset;
unaffected earlier images and their independent review retain their own receipt.
Detail checks intersect header/Close/body and actual text lines with the Knowledge
viewport and every clipping ancestor, with hit testing. They do not scroll a
detail into view to disguise clipping. Native reader wheel and Close must leave
the same original result row focused and both diagnostic disclosures open.
The short mixed reader also submits alpha, keeps its confirmed selected source
after beta fails, and checks that the entire Last confirmed count/query/scope
metadata line remains visible beside the real reader, not merely in hidden DOM.

The optional first argument names a new, empty evidence directory. By default,
each independent round is stored under the ignored local
`.bagakit/feature-tracker/space-context-clarity/capture-*` directory. Failed
rounds remain failed and are not overwritten or promoted to success.

## Actual consumers and controlled observations

The fixture mounts the original production Sidebar and Dock, which select the
original Topic Navigation, Knowledge, Folder Zones/Git and Mote Files consumers.
The full production CSS, real Store and original Category/Topic/Mote bindings,
Tab/Region identities and drafts are used. There is no replacement Store or
hand-drawn content. Fixture CSS controls only the outer host geometry.

Topic RPC observations are configured inputs validated by the original public
Topic parameter/result parsers. Raw structured code/message/source/recovery and
all original transport receipts are retained. The fixture changes an observation
mode, then actual pointer input presses the production Refresh or Search button;
it never sets product component state to manufacture the result. Category,
Topic, Mote, tool, detail and file-tree navigation use actual Chromium input.

The configured module-derived logical/physical fixture paths, Git and file observations are
not real filesystem, Runtime, Main/preload or provider evidence. Existing Mote
preparation returns its configured original object and does not create one.
No live Agent, installed App, user Session or process restart is operated or
claimed. The private window uses `showInactive`; no window/app activation or
global keyboard events are used. Native title tooltips may not be included in
`capturePage`: the actual hover, exact original DOM title and matching file
read target are recorded without painting a substitute tooltip.

## Bounded scene matrix

The complete set has 18 full-window frames, including the original Sidebar:

- 100-item partial observation at 300/236 CSS-pixel Dock widths in dark/light.
- Keyboard-expanded original discovery diagnostics and an actual entry reader.
- Partial plus independent read error, with both groups still distinct.
- A 240–300px-high actual Knowledge surface, both diagnostic disclosures open,
  real wheel scrolling in the shared status group, and an accessible original
  result/detail. Neither disclosure is forced closed by the fixture.
- Empty partial and completely successful observations.
- Confirmed query alpha followed by failed query beta: the retained result and
  detail remain attributed to alpha and their original Topic, never beta.
- Separate search-history failure with complete structured diagnostics and
  available results.
- Category and selected-Topic navigation retaining their original file mapping.
- Mote's Files + Mote label and original physical directory title/read scope.
- A new unavailable Mote metadata receipt retains its confirmed directory and
  original detail beside the real scope issue/retry wrapper; native retry then
  reads the same original object again. No identity or Store action is replaced.
- Folder's Files + Zones and original Git/Branches entry.

Receipt identity binds only the confirmed owning product inputs and this
harness before/after, records every actual compilation input and nonempty
emitted asset/JS/CSS, verifies loaded bundle URLs, and hashes every PNG. Shared
Store/App/Core sources are consumed directly, not added to a global final drift
guard or pinned to a shared HEAD. Source aliases avoid incidental dist freshness
as a presentation prerequisite.

Only a scoped Renderer entry is compiled. No source tree/dependencies are copied,
installed or fully packaged. The receipt records compiled/private/evidence bytes
against a 1GB budget and cleans the private build/profile only after its original
process exit and exact owned-process cleanup. Evidence stays local.

Capture success is not aesthetic approval. Leibniz must independently open every
frame from the original receipt and state whether the candidate is deliverable.
Changed owning inputs require a fresh qualified round for affected scenes.
