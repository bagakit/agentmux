# One Focus workflow across original sources

Run `node apps/desktop/scripts/capture-focus-source-unification.mjs --evidence .tmp/unified-focus/visual` from the repository root after the original Core build is current.

This scene mounts the actual App, GlobalFocusSurface, unified source adapter, normal project lanes, shared Context cards, menu, Reader, filters and Store. Only original authority/Native IO and unused terminal/editor paint are controlled typed preview leaves. It does not start a real CLI, install the app, mutate a user workspace, or prove native recovery. The companion `focus-source-unification.test.tsx` uses actual Core B/D/Space/Name and Unix→Main→Preload→Renderer source transport for product behavior.

Three original local tasks have authoritative names, recaps and working/stale/interrupted states. Their explicit Source Tab names are null. The same original Runtime/SID is reachable through ordinary and saved Source paths and must still have one normal Context. Another observed Runtime deliberately uses the same raw SID, has its own name and reading source, and cannot borrow the local recap. One additional original execution source is unavailable; it stays an unknown normal Context. Browser/Launcher Regions remain in the original Space but do not enter the task scanning list.

The scene captures wide/intermediate/narrow in dark and light, the shared filtering menu, the common Reader for the foreign original task, and its primary selection in the ordinary Focus right workface. That original Source Tab contains both the Agent and a Browser Region; primary selection must preserve both and keep Focus open. Every Agent must reside in an ordinary project lane/card; no source-only list/grid is allowed. It checks local deduplication/name/recap, foreign same-SID isolation, document geometry, unchanged original Run/draft values and source Region membership. Foreign reading is a nonempty original-native response page produced by the actual Core bounded Reader in the Node capture harness, then delivered only through the controlled original member IO port. The card and Reader must both show that original body. These are controlled Renderer observations; they do not replace Core permission or native lifecycle tests.

A separate Agent must actually open all final PNGs and assess hierarchy, task/content/state clarity, consistent ordinary project/card language, narrow reading, source failure information and the original Reader. The capture receipt alone does not certify visual quality.
