# Mobile product Renderer scene

Run `node apps/mobile/scripts/fixtures/mobile-product-redesign/capture-ui.mjs` from the repository root. `--baseline` records missing current-product actions while retaining the actual fallback selection as a baseline; it never signs candidate completion. The command prints a private receipt beneath `.tmp/mobile-product-redesign/`.

The scene consumes the original `MobileApp`, shared Composer/Conversation/Interaction and DeviceWorkface. It provides controlled public SDK/catalog/Goal facts for three original Sessions. The same main SID is first presented outside the Mote and then at the exact saved Mote tuple. The Mote has more than one distinct SID, so its default conversation must be read from the original owner facts rather than inferred from cardinality or first location.

Actions tap actual visible controls using Chromium CDP touch events and type into the original shared editor with `insertText`. The scene does not navigate React state, replace the editor or operate live user Sessions. Its owner-state controls only simulate connection and acknowledgement facts. Captures cover 390×844, 320×760 and 390×480, Mote overview/conversation/Profile/result, Focus groups, original permission response, original result reading, unknown input, offline retention and later draft. The receipt records Source and compiled hashes, complete PNGs, actual parameters/call counts, selected original SID/Run and durable device record. Nonempty App, Conversation, DeviceWorkface and shared Composer Source inputs are required.

Owning contracts: [mobile behavior](../../../../../docs/design/behavior/public-control.md#手机版-relay-连接), [mobile presentation](../../../../../docs/design/presentation/public-control.md#手机版-relay-连接的呈现), and [independent visual review](../../../../../docs/guides/agent-visual-e2e-review.md). This fixture supplies scene/actions/facts, not an aesthetic score or independent verdict.

Controlled Chromium is not physical phone validation. It does not prove iOS/Android IME, OS keyboard, native back/safe areas, background/resume, actual Relay/private Host owner, real model input or live Run recovery. Real phone and actual Host evidence remain separate version requirements.

`--input-history` runs only the Agent input-history journey. It explicitly enters the saved original Mote Tab, opens the existing communication sheet, reads recorded Message Tool/native origins, searches within that Agent, continues a zero-match partial range to the older record, fills the maintained editor without sending, and uses its real Undo shortcut to recover the original draft. Captures cover 390×844 and 320×760; input and permission calls must remain unchanged. The history port is a controlled typed SDK port for this visual scene; the actual Unix Hosted SDK → Core Store/Provider consumer is separately exercised by `test/mobile-input-history.test.tsx`. Neither evidence substitutes for the other. Owning history behavior is [Message Tool input history](../../../../../docs/design/behavior/conversation-input.md#message-tool-按-agent-的输入历史).

`--commands-entry` exercises the collapsed Commands tool at 390×844, 320×568 and 430×480 in dark/light appearances. The controlled original Settings port supplies a shared Prompt, a matching Provider Prompt and a foreign Provider Prompt. The scene checks distinct source groups, excludes the foreign binding, searches a keyword shared with a native command, inserts the full semantic body into the same draft without sending, then fails only that settings read and exercises the original 44px retry action. This visual SDK port is separate from the actual ConfigOwner → public RPC → executable CLI/mobile test in `apps/desktop/test/mobile-custom-prompts-rpc.test.tsx`. Requirements remain in [mobile input behavior](../../../../../docs/design/behavior/public-control.md#手机对象身份与工作面) and [input-history/candidate presentation](../../../../../docs/design/presentation/conversation-input.md#message-tool-输入历史列表).

The history journey also captures its explicitly named “历史” entry. It shares the original communication sheet and Inputs list; it does not add a second history surface or treat an unconfirmed input as delivered.

`--spatial-resources` opens a Mote containing an original Launcher and file Regions, including a long filename. At 320, 390 and 840 widths, actual row geometry checks the leading icon/text rail, trailing disclosure, touch height and overflow. The original Launcher opens the existing creation form at its complete Space/Zone/Tab/Region; opening and closing the form must not call `agent.open`. The `resource-leading-icon` loaded CSS variant must fail the real leading-column assertion.

This subset then saves an original conversation draft and two unknown creation intents through DeviceWorkface: a new Tab and an exact Launcher. The first private product process fully exits. A fresh process with the same private userData reads the original selected Session, presentation, conversation and both intents before navigation, restores the visible draft, and explicitly inspects each original operation without creating or sending. Receipts retain the distinct process identities, loaded source hashes and full images for independent review. The visual SDK remains controlled; actual executable CLI → public RPC → original spatial Creator and occupied/unknown behavior are separately exercised by `test/mobile-agent-create.test.tsx`. The private mobile restart does not claim a live Host/Core/Run restart or a physical-phone check.
