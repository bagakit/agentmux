# Standard Mobile startup capture

Run only after the existing build owner has completed the standard package build and granted a private Electron resource window:

`node apps/mobile/scripts/capture-mobile-startup.mjs .tmp/mobile-loading-review/build.json OUTPUT`

The wrapper verifies the build observer's actual entry/static closure/product dynamic chunk and its imported CSS, complete immutable release bytes and source identities. It never rebuilds or replaces the renderer. The installed Host MobileAssetsOwner initializes that exact dist and serves its original HTTP namespace. Only the exact product chunk, its own CSS outside the initial CSS closure, and the public metadata path receive controlled held/503 responses. Shared entry styles remain available. The complete random public key pin has no registered device or real Host secret. No WebSocket handshake or external request is allowed.

The canonical document is obtained from this installed owner's real HEAD `/` redirect. A compiled owner that predates the short `/m/` namespace can serve the same exact release through its original full-digest path; the fixture records that path and does not invent a short alias. This is startup-resource evidence, not another short-namespace acceptance claim.

One private Electron process and profile execute five complete-page captures in order:

1. 390px: actual Root is visible, actual product JavaScript/CSS is held and the original metadata GET is already pending. Vite can await its preloaded CSS before requesting dynamic JavaScript; the receipt distinguishes those actual requests and records the startup text/background styles and unloaded App stylesheet.
2. 667×375: the same held Root and recovery controls in the short landscape viewport.
3. 390px: a real touch cancels the original fetch; foreground cannot retry it. Another real touch explicitly starts GET two. Releasing the first HTTP response late cannot clear the second pending observation or alter the original device record.
4. 390px: a new document rejects the actual product chunk with 503; the original named LoadFailure and preservation/reopen action remain visible.
5. 390px: another document releases all immutable product assets; the actual MobileApp renders its ordinary unpaired connection page.

Real browser abort may have already closed the first metadata socket when it is released; the receipt records whether that response was deliverable. This capture does not claim an ignored-AbortSignal JavaScript completion was invoked. The original mounted Root tests cover that distinct late-success/catch/finally adversary. The normal scene is deliberately unpaired; the receipt cannot stand for authenticated Relay, first remote conversation, a physical phone, installed App or business actions.

The standard dist does not export its private DeviceWorkface instance to a fixture. The probe therefore compares the actual product-created storage bytes without constructing a schema or copying a Store. It does not add a two-OS recovery claim. Existing original lock/first-mount tests and the previously accepted actual App two-process proof retain their own scopes.

The parent receipt binds actual source/release/image SHA, original request conditions, renderer checks and the existing runProbeProcess exit receipt. Independent image review remains required. On confirmed process exit the disposable profile is removed; on unknown exit it is retained with a concrete path. Only reports and original PNG evidence remain.
