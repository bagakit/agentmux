# 对话客户端分层与渐进阅读

本文定义对话客户端的目标技术边界，供共同阅读、输入编排和性能改动使用，不表示下述结构已经实现。当前源码与消费链见[对话机制](../architecture/conversation.md)；记录、角色、原序、来源与窗口协议归 [Core 对话协议](../specs/conversation-protocol.md)。用户可见行为归[对话阅读](behavior/conversation-mode.md)与[输入和邮箱](behavior/conversation-input.md)，视觉语言归[对话呈现](presentation/conversation-mode.md)。

## 对象与职责

| 对象／层 | 持有的事实与责任 | 不持有的事实 |
| --- | --- | --- |
| Core 已接受窗口 | 原记录、事件、贡献关系、角色、顺序、覆盖、版本、分页与资源引用 | DOM、选区、卡片外壳与滚动位置 |
| 共同阅读适配 | 将完整窗口投影为统一 records／originals；附加来源与 speaker 的呈现 | 第二次关联、按正文去重、来源页拼接 |
| 共同呈现序列 | 按原序生成消息／过程布局、稳定展示身份和纯视图锚点 | Provider 特例、输入资格、完成或历史完整性 |
| 一个阅读位置的呈现事务 | 已呈现版本、候选布局、锚点、选区／焦点保护、展开与提交反馈 | 新消息账本、持久状态、其他位置的阅读选择 |
| 共同正文与卡片 | 原文、资源、Copy、来源详情、可访问披露和薄外壳 | 读取调度、发送／恢复状态机 |
| 宿主容器 | 原 Host／Session 绑定、平台能力、输入控制器、布局槽与可见性 | 独立的消息归并或同类过程 renderer |

Core 语义窗口、已呈现布局与视口是三个不同范围。取得完整合法窗口不要求同一帧挂载全部重内容；延后呈现也不能把部分传输片段冒充已接受窗口。所有客户端继续消费同一语义 owner。

Core Reader 的 scope、frontier 与分页位置相等比较复用统一 canonical value 语义，不为纯比较重复生成内容摘要。原记录及事件版本校验、签名续读资格仍由原协议边界执行；相等比较不能替代这些校验。

共同阅读适配复用本阅读位置 Reader 已生成的 Core reading，只附加 speaker、来源等呈现信息，不为同一已接受窗口再次展开记录、建立输入及原记录索引。提交前的候选窗口尚未被接受，仍独立按该候选 snapshot 判断准入；不能复用当前保留帧的 reading 来判断新候选，也不为省去重复计算新增缓存或状态 owner。

阅读来源身份与确认操作身份分开：前者使用完整原生 locator（包含 Provider／Adapter、原生 ID 与记录路径），后者保留原确认 operation，以隔离并发选择及 A→B→A 的旧资格。对同一 locator 重新确认不能把原阅读窗误标为来源改变；已接受另一来源的窗口仍需显式导航。宿主只收窄自身的来源变化提示，不清除 Core 的 scope、过期、held、错误或未知事实；语义目标与前台选择的合同见[同一 Run 内的原生会话切换](behavior/agent-capabilities-and-messaging.md#同一-run-内的原生会话切换)。

## 统一序列与展示身份

共同序列直接消费有序的 `readonly ConversationRecord[]`，不将 canonical records 拆成 native 主干和 captured 插入列表再恢复顺序。来源差异保留在原记录／资源的内容适配中，不成为第二套定位、折叠与排序协议。`originalRecords` 继续供完整原文、来源详情和准确资源定位使用，不能因为统一展示而删除原贡献。

过程分组是呈现投影：依据 Core 的 `role` 与已确认回合信息，遵守消息、历史分界和原序边界。相邻 `process` 并不自动构成一个业务回合；未知回合不能从标题、时间或工具名补齐。已挂载过程的身份在首成员离窗、后续追加与跨源输入分割时保持可追踪，不能用每次新的首项或数组下标导致整组重挂载。原 turn metrics 与 observation 仍保其实际范围。

展示定位以统一记录身份进入，准确 raw 引用通过原贡献映射回该记录；canonical event、原记录和 DOM key 分别表达。合并贡献导致代表记录／事件身份变化时，只沿 Core 的准确关系保持阅读连续性，不以正文相同猜同一节点。折叠选择属于统一记录或稳定过程身份，不再因 native／insertion 分两套。

统一过程组的成员身份也供时间尺和定位消费，包含原生与 captured 记录；折叠头代表其准确组内成员，而不是仅代表已挂载的子节点。点击已加载记录的时间点时，沿同一身份先显露所在过程组及准确步骤，再定位原记录；可见范围计算不因来源或首次展开状态遗漏成员。成员映射属于当前已接受帧的呈现投影，不新增历史账本。

History 分界、当前尾锚点等纯视图节点可以作为明确的布局锚点；它们没有业务记录、作者或回合身份。宿主的时间尺与定位索引派生自同一序列，不能为获取坐标另做一次跨来源拆合。空集合、source-only 与精确记录阅读仍保原覆盖和来源解释。

## 一个阅读位置的呈现事务

选区保护收敛到每个阅读位置的共同呈现事务，而不是仅删除下层检查、保留当前 `beforeCommit`。该事务须同时看到原已呈现树和候选布局，判断正文版本、代表贡献、角色、稳定 key、过程父节点与分界的变化。原窗口准入只检查 raw 页不足以证明这些 DOM 变化安全。

完整窗口到达、跨源贡献合并、纯布局锚点变化，以及宿主直接传入 accepted records，都进入同一个呈现决策；没有 `useConversationView` 的共同组件消费者也必须有此边界。用户主动展开、定位和局部资源到达保各自明确意图，不伪装成新读取操作。结构或正文变化会破坏当前阅读锚点、原选区或焦点时才延后；无选区的向上阅读也须保护，不以存在任何选区冻结整个客户端。

事务以原 `ownerDocument` 为准，拥有一份保护原因、解除通知及待呈现候选；同一阅读位置的嵌套组件不再各自保一份 committed frame、注册 `selectionchange` 或显示重复横条。正文和过程组件提供必要的节点／布局事实，不各自决定哪一个语义版本生效。不同阅读位置仍独立，不能用全局 hold 阻塞其他 Session。

没有非折叠选区、焦点也不在本阅读位置内时，不为选区或焦点保护遍历全部正文节点。跨越本位置的选区仍须检查，无法判断交集时保留原保护；滚动锚点保护独立执行，不能因无选区而略过。

保留候选只持原完整 frame 与必要布局引用，不复制正文或重投影原来源贡献；已呈现的 records、originals、coverage 与布局来自同一接受版本，不能只保旧正文却显示新帧的来源说明。独立的当前权限、输入资格与问题答复回执仍沿原业务 owner 及时更新，阅读保护不能冻结这些事实或授予旧卡片当前资格。解除保护时重核当前准确来源、操作代次、可见性与原意图；旧的 Earlier 结果不能覆盖已返回 Current 的窗口。来源失败、观察失败和阅读保护分别表达，解除保护不自动重试失败输入或读取。原阅读保持合同见[History 阅读面](behavior/conversation-mode.md#history-使用共同对话阅读面)。

统一序列及上述事务为改变父节点／节点生命周期的渐进挂载和删除重复 hold 提供共同边界；有界预取及滚动局部化不必等待全部组件重构。删除任一现有保护前，须能在共同边界解释其原反例，包括：raw 项未改变但 canonical 角色／代表贡献改变、选区跨过程父节点、直接传入共同组件的 records 更新。邮箱、Mobile 控制器和卡片外壳也各有独立职责，不成为改善回翻响应的全局前置条件。

## 数据准备与渐进呈现

选区和阅读锚点以 DOM 即将改变前的真实状态为准。React 开始计算候选后，用户仍可能建立或移动选区；不能用较早的 render 快照或尚未送达的 `selectionchange` 证明提交安全。原呈现准入须在提交前核对选区事实；原几何 owner 在 DOM mutation 前采样，仅在本次捕获成功后于提交后恢复同一阅读位置。选区引起的重渲染本身不授予贴底意图；正文挂载与尺寸改变仍沿宿主原跟随策略处理。新邻居和首次正文挂载沿同一边界保留原节点与屏幕偏移，不另设一层已提交消息缓存。

底部跟随与历史阅读的保锚策略由同一宿主几何事实决定，窗口准入、render 呈现及实际提交保持一致。跟随时不因历史锚点离窗而保留旧帧，也不捕获或恢复历史锚点；原选区和焦点保护仍按准确受影响节点判断。显式查找与定位沿原阅读意图切换，不能靠是否接近底部或某次程序滚动重新授予跟随。离尾阅读的普通内容提交不反复测量无关尾部；真实尺寸变化使浏览器将视口夹回尾部时，仍须更新当前位置与返程控件。位置复核不授予跟随或分页意图。

### 有界的阅读储备

读取仍由原 Core Reader 沿不透明游标完成。宿主调度持有明确阅读方向及有限需求，以已载可读空间表达预取提前量；原记录数或时间跨度不等于有几屏可读内容。折叠过程很多与长正文两种形态都必须成立。读取耗时与可读延迟用于检验提前量是否足够；没有稳定证据表明固定储备不足时，不增加自动调参状态或用户配置。

首次／时间范围补读与主动回翻的方向性补足分别解释，批次与停止规则唯一归[History 阅读面](behavior/conversation-mode.md#history-使用共同对话阅读面)。一次合法页提交后的几何反馈只能继续尚有效的原需求，不能产生新的阅读授权；不形成“布局不足就一直扫全历史”的循环。一个位置只保一个在途读取，显式返程优先；隐藏、换来源、失败或保护使对应补足停止并保原窗。

自动准备不能挤掉正在读的页。没有新的主动阅读需求时，较早后台扩窗复用 Core 的 `preserveCurrent` 合同，预算不足停止该次自动扩充；该合同仅适用于原 older cursor，不能传给 newer 冒充对称能力。用户实际同向阅读或明确 Earlier／Newer 形成的需求沿原 older／newer 导航与呈现保护继续，允许在 Core 原预算内滑动局部窗口；达到保窗扩充边界不能使正常阅读永久停在 Earlier 按钮。准入仍保护当前可见正文、选区与原返程，不能把后台自动保窗和主动历史导航混成一份剩余容量门禁。需要新增等价的后台保窗能力时先在 Core 核对合同，不以客户端扣住旧画面代替保窗。UI 不增加第二套原记录缓存、语义容量或后台 Reader。全部源记录仍在原持久 owner，停止预取不等于删除历史。

### 重内容的工作范围

呈现按稳定消息／过程块渐进进行：优先当前阅读区域及邻近区域，延后尚未呈现的重 Markdown、代码高亮和资源内容；一次新增数据不迫使全部重内容在一次 React 提交中完成。分片属于呈现工作，不拆散 Core 的完整语义帧，也不改原 Copy 与精确定位所访问的完整内容。

首次重内容判据只包含当前应呈现的正文、资源与明确展开的载荷；默认折叠的思考或工具详情不使短答案整体变成占位正文。查找范围与显露行为归[局部查找](behavior/conversation-mode.md#对话消息的阅读复制与标注)：已加载的普通正文不因延后挂载而漏检，命中显露沿原记录身份进入同一呈现边界。查找复用原文的轻量阅读投影，不以同步整窗重正文挂载建立命中集合；未加载历史、资源正文或主动收起的详情不因输入查询自动读取、展开。阅读投影沿正文原有的 Markdown 解析模式及协议可读分支生成，共享惰性解析结果；图像、公式和实际交给宿主渲染的对象保留不透明边界，不能拼接两侧文字制造命中。单个命中显露后，回到原 DOM Range 与同一滚动 owner。

折叠重内容的按需工作沿[智能连续阅读目标](behavior/conversation-mode.md#连续回翻的渐进加载)核对完整链路：原页读取与传输、解析／高亮、DOM 挂载和资源解码分别计算成本，隐藏详情或延后 React 挂载不能证明前面的全文工作已经省掉。先核现有原记录与资源读取能力是否能按准确身份满足摘要、展开、完整 Copy 和定位；接口不能表达的部分作为原 Core／协议设计缺口处理，不由 UI 裁字段、复制存储或另开 Reader 绕过。轻量记录形状、完整载荷交付方式与回收策略须另核来源和消费者，本页不预先指定新的 wire 类型，也不宣称当前已支持。

已呈现正文节点、Range、焦点、展开、草稿和上下返程继续遵守原行为合同。视口外不能一律卸载；估算高度、图片到达和延后挂载均不能改变正在阅读的原记录及屏幕偏移。节点保留与 Core 有界窗口共同控制留存，不能把渐进首次挂载宣称为永久固定的 DOM 数量。

本设计选择先实现上述分离，不预先指定虚拟列表库或离屏节点回收算法。若进一步需要严格的视口级 DOM 上限，必须明确哪些已呈现节点可回收及如何保全选择、键盘查找、定位和返程，并调整相应行为合同；不能用一种列表库的默认卸载策略覆盖现有阅读要求。

滚动本身也须局部化：标尺／可见区更新不驱动整窗语义和正文重算，锚点捕获与恢复只处理当前相关节点：滚动复用已观察候选，恢复已知身份时在原阅读容器内准确定位，不在 JavaScript 枚举同类整窗节点。原选区、保锚、跟随与 Earlier 留白仍沿各自原 owner，不因查找方式改变。共同投影按准确输入复用；局部展示状态不使所有消息的稳定 props 失效。暂未测量的候选热点不能在文档中冒充现场卡顿根因。

## 共同过程、正文与卡片外壳

Desktop、Mobile 与其他阅读位置使用同一过程行、披露、载荷与复制能力；宿主只注入平台动作、容器密度与准确定位意图。合并 renderer 时保全两端能力的并集，包括摘要、完整详情、已有 diff 阅读、定位展开、键盘操作和 `aria-controls`，不能以较小实现替代较完整实现后称为统一。

工具种类只来自原生结构的调用／结果等准确事实，图标合同见[过程层级与详情](presentation/conversation-mode.md#过程层级与详情)。按工具名猜 shell／read／edit 的逻辑不能机械搬入共同组件。厂商特有编辑参数的解释归原 Provider；有准确语义才展示结构化差异，未知形状保完整原载荷，不由通用 renderer 解读厂商工具 schema 或从图标推出执行成功。

`ConversationMessage` 的正文、资源、输入详情、来源与批注能力保持共享。普通发言、原生协作回报与系统记录采用职责清楚的薄外壳；紧凑密度是展示维度，不另造一种作者或业务记录。外壳选择依据原类型事实，避免把独立布尔条件散布在头部、元信息与正文各处；不为减少行数再复制三份正文 renderer。

共同组件同时持有自己的布局和状态样式，Desktop／Mobile 只适配宿主容器、主题 token 与密度。消息的方向、紧凑和过程变体只作用于该消息所属的头部、正文和操作槽；正文中嵌套的原消息继续按自身类型布局，不能被外层的后代选择器重新分配网格列、头像位置或正文宽度。共享组件的样式边界与组件边界一致，不在宿主另加修补规则形成第二套呈现答案。

窄卡片的姓名、准确身份和正文保持正常阅读宽度，时间及操作控件按可用空间换行；复制反馈不能把身份区挤成碎列。普通发言、系统记录与协作回报沿同一头部布局，协作壳只保留自己的披露语言；展开详情使用完整头部宽度，折叠再开保留原正文节点与动作。

复制复用边界是每次动作及其原文取得过程，而非只替换按钮外观：保留 deferred 资源 reader、`copyText` 覆盖、宿主回执与准确取消，独立状态原语供整条、身份和局部动作使用。异步完成顺序与反馈保全遵守[复制行为合同](behavior/conversation-mode.md#对话消息的阅读复制与标注)。现有同步文本按钮不具备这些全部能力，不原样替代消息动作，也不因此新增全局 Clipboard Store。

迁移死 props／分支的删除依据是真实生产调用链与生成路径，不是文件行数。只向废弃入口喂数据的测试不能代签现有产品消费；组件变薄的同时应保留实际当前、历史、退休与无数据阅读路径。

工具字段的阅读状态按原记录及字段身份保持，不按一次快照对象引用重置。相同正文的状态更新保留格式化选择与复制反馈，正文真正改变时清除旧复制反馈；全文 Copy 始终取该准确字段的原文。摘要与展开正文各有明确用途，不重复呈现同一份完整正文，空载荷不制造空披露；有用的原记录详情仍可达。

## 原生结果的共同消费

结果的目标链路使用现有 Provider、Core 读取／归并和原持久 owner：Provider 对同一原生记录一次解释其 `turnOutcome`，当前状态与历史读取复用该解码；Core 保留原 item/ref、turn 和 `same-event` 关系，再独立判断是否更新当前活动。结果类型及公开摘要唯一见[原生结果协议](../specs/conversation-protocol.md#native-request-and-turn-outcomes)，不在客户端引入 occurrence Store、错误扫描器或第二套 Reader。metrics 只表达计量，不能再为完成反馈提供另一种结果。

共同阅读适配将 accepted record 的 `turnOutcome` 原样交给共享结果卡。卡片只决定摘要、详情、复制和定位布局；Desktop、Mobile、History 和 Focus 宿主不解析原生错误，不因自己的当前状态或过程折叠删去历史结果。deferred 阅读先保结果与有限摘要，完整原载荷沿原精确读取取得；当前服务提示的收口不改变历史卡的身份和内容。阅读位置、选区、焦点与草稿仍由原呈现事务保护。

连接器消费同一 accepted outcome，使用原 Provider 的 `publicMessage`、标准恢复建议和现有受众／切点资格生成通用 publication；Channel adapter 仅负责原生卡片格式与平台回执。缺 `publicMessage` 仍以固定通用文案显示失败卡，不外发本地原始错误，也不包装成 Agent 发言。原输入采用关系供 query 反馈关联，原 Outbox 保投递结果；这两者不在 UI 或 Channel 内另造状态。错误摘要及已确认结果的本地阅读不等待外部投递，投递未知也不启动模型重试。

该目标先闭合同一失败的状态、历史、公共输送与两个真实消费者，再逐个收敛 Provider 的贡献校验和厂商协议泄漏。删除过时解释路径时保留原记录与未决操作，不引入兼容层、数据 migration 或客户端替代分类。结构变化必须以真实消费者和承重反例核对；文件变小、helper 导出或类型编译不证明闭环。

## 邮箱、输入控制器与宿主几何

### 三类输入的派生投影

本地草稿、待发及保留操作意图，Core 输入 mailbox 与会话输入历史具有不同事实 owner，不能把三路来源本身认定为重复账本。Inputs 的列表组合从渲染树提取为可独立检验的纯投影：接受各原 owner 的准确记录、范围和原关联，输出有来源的行、原控制 owner 提供的动作引用及可用性；组件负责 hover、pin、选择与控件，不在多层 render-props 中维护归并条件。已进入 journal 的条目仍可关联本地 unknown 意图与原操作控件，不能因分类改变而丢弃。

匹配只消费已确认的 scoped operation／input／record 引用，不以正文、时间或裸 ID 相等删除条目。投递、采用、作者及失败事实继续由 Core／原输入 owner 给出；纯投影不替代发送、持久化、回执查询和来源分页。需要跨客户端复用的新关系应先补原 Core 能力，而非隐藏在一个叫 hook 的第二套 matcher 中。

Core 输入分组比较外部作者时，复用原只读外部作者投影，排除输入授权字段在完整信封与只读记录之间的表示差异；connection、完整 actor、平台会话及消息、binding 与修订仍须一致。比较不改写原作者对象、输入信封或授权回执，不授予新的执行资格；原事实冲突仍表达为未知。

### 准确记录定位

邮箱定位的读取与呈现由原 Session 宿主的同一次导航意图串接。明确定位是该目标阅读位置的需求，即使原界面仍在 Terminal，也先启用其原阅读消费者，再等待该消费者的原读取结果；另一邮箱消费者已返回同一记录不能代签。读取完成的错误和取消随原操作回执交付，不从异步开始前的 React 闭包取状态。已有准确 `ConversationItemRef` 而目标不在最近窗口时，复用 Core 的按记录读取，由该阅读位置打开原来源的有界窗口；不能把固定次数的 Earlier、全历史扫描或另一消费者的窗口当作准确定位。摘要沿自身读取及来源状态持续更新，不充当精确定位的前置读取，也不为定位切换窗口；目标 Reader 独占准确记录读取，并以自身已接受的 originals、来源和读取错误核对原 Host、输入身份及记录，再交付真实呈现回执。最近摘要窗口未包含目标不等于原记录不存在，也不能先读入摘要再由显示位置重复定位。准确记录进入真实 Activity 后才确认呈现；成功、失败或后来用户意图取消均结束本次导航需求，不留下仅为已结束导航而启用的后台 reader、轮询或正文副本；后续需求仍由原可见阅读位置持有。行为保全归[邮箱记录一键定位对话](behavior/conversation-input.md#邮箱记录一键定位对话)。

### 控制器与 Host 身份

Mobile 的手动输入／重连核对与同步权限答复分别由明确生命周期的控制器承接，view 只组合阅读、草稿、状态与动作。抽离保留原 CAS、冻结正文、operation ID、原条件、客户端实例和换 Session fence；未知结果先核对并沿原操作合同处理，重挂载／重连只观察，显式续做保原 key、waiting generation 与 operation，不新建操作、自动重发或丢弃草稿。同步权限与原生异步问题仍是不同业务通路，不能为共用 hook 合并资格。

准确客户端路由、语义来源 Host 与执行 Host 分别处理。对于已经连接到目标 semantic Host 的 Hosted Client，`local` 可以表示该端的 route-local namespace，并不表示手机或 Desktop 所在机器。历史响应、mailbox、资源和诊断各按原接口合同核对；不能把所有 `local` 机械替换为 `session.hostId`，也不能用合法 route-local 语义掩盖跨连接迟到结果。当前转换接线见[Mobile 与 Host 路由](../architecture/conversation.md#mobile样式与宿主差异)。

### 浮层布局边界

待发浮层的避让需求由宿主布局 owner 接收，原 Terminal／interaction owner 提供当前相关的布局槽、锚点或几何引用。子组件测量自身并消费宿主显式提供的锚点／几何，不反向遍历 `.agent-surface`、xterm 私有类名和兄弟权限卡片来发现业务对象。优先补全既有 [`TerminalInputGeometry`](../../apps/desktop/src/renderer/src/lib/terminal-view-observation.ts) 的 Region port 与原 Floating UI 布局；不在共同层建立全局几何 Store，也不把高频 caret rect 放进父工作面 React state 造成整面重渲染。

Resize／Mutation 观察保留在实际需要观察的原呈现 owner，并随可见性与身份释放，不以观察者数量为零作为目标。尺寸、caret 或遮挡属于呈现数据，不能授予输入资格或推断权限状态；几何未知保留可达的待发操作与原正文，不能使健康输入不可用。原浮层不得挤压工作面的要求仍归[输入框外的待发提示](behavior/conversation-input.md#输入框外的待发提示)。

## 公共边界与验证责任

纯序列、布局事务、卡片与宿主控制器重构保持公开行为时复用现有 JSON-RPC／CLI，不新增“重构”“预取”业务命令。若为共同 diff、输入关系或分页能力补充新语义，则回到 Core／Provider 及原公共类型、codec、RPC／CLI 和真实消费者，同一能力不能只在 GUI 成立；判断方法归[公共能力贡献约定](../guides/public-capability-contributions.md)。

验证按承诺结果区分：统一序列保原顺序、贡献和定位；呈现事务覆盖跨贡献变更、跨过程选区、无 Reader 的共同消费者及迟到操作；共同组件覆盖两端差异能力、完整复制、两按钮交错及切换来源；输入控制器覆盖失败／未知、重连、切换与原操作核对。删除真实保护或接线的实现变异必须使对应场景变红，方法归[测试策略](../testing/strategy.md#任务验收与假绿防护)。

渐进阅读分别测量“下一段何时可读”和“数据到达后主线程做了多少工作”，记录读取／组装／提交时刻、长任务、帧耗时、节点规模与锚点偏移；使用折叠过程密集和长正文／已展开过程两类长会话，并核对隐藏位置、无关 Session 输出和双向返程。受控批量输入先以原 Provider／Store 的准确回执确认准备完成，输入状态处理与阅读呈现成本分别记录。新增正文只有进入原接受窗口后才可比较挂载成本；待保护帧尚未呈现时的零挂载不算优化收益。首段可读正文与长答案完整呈现是不同指标，不能互相代签。源码有 memo、分页或虚拟化都不是性能通过证据。文档审查只证明设计与事实边界，不代替这些实现、真实产品或安装验收。

成本比较保留原长任务时长和时间条目，观察到的阻塞量按每项 `max(0, duration - 50ms)` 相加；这是复用[阻塞部分的定义](https://developer.chrome.com/docs/lighthouse/performance/lighthouse-total-blocking-time)，不冒称 Lighthouse 的页面加载窗口或沿用其评分阈值。只记录超过门槛任务的整项时长和不代表全部任务成本。全部工作另以原生 `timeTicks` 任务占用墙钟度量，真实起点到终点、首次可读原样本到同一终点两个窗口分别比较，不能以前段节省抵消连续阅读的增加；它不是 CPU 时间，重叠子类不相加，采样开销不扣除。首次可读延迟、帧及长任务分布仍独立保留。

测量起止点须在正式样本前固定。Current 原状态完成后的两个绘制帧后，依次读取呈现快照与原生最终计数，保留各自真实端点，不将独立读数称为原子同刻。Observer 快照先排空当时已完成且已入队的条目；当前快照任务及其后到原生端点间的任务不保证已在该集合中，须声明覆盖边界。旧失败不按新口径回算成通过；任何窗口或指标持续退化超过同基线样本波动，仍须调查并阻止性能通过。
