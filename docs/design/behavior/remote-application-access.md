# Remote 应用授权同步

本文持有用户配置的应用账户授权同步行为合同。[Remote 管理 PRD](remote-management.md)持有环境工作台与导航；单次 Agent 权限、创建来源信任与设备配对仍归各自 owner。本文定义要交付的行为，不代签某台机器已经配置连接器、已登录或已完成同步。

配置步骤、命令和连接器机器协议见[应用授权同步使用指南](../../guides/remote-application-access.md)；准确字段及解析以其指向的公共源码为准。

## 用户结果与范围

用户明确选择一个应用、来源与目标环境、双方操作系统账户、期望的应用账户以及最小授权范围，先看差异，再执行一次单向同步，最后确认目标应用能以期望账户使用这些能力。一个应用失败不得影响其他应用或原 Agent、Run、Session 和工作面。

默认手动执行。首个完整范围是已登记的本地或 SSH POSIX 执行环境与用户显式配置的命令连接器；其他执行平台清楚报告本次操作不支持，不影响已有工作。连接器没有可迁移合同的应用应说明需要在目标登录或不支持，不能复制任意路径、整个用户目录、Agent 审批记录或系统权限冒充授权同步。

不先建设中央凭证仓、批量分发、后台续期、自动登录或自动撤权。应用账户凭证、Agent 单次 permission、Agent sandbox / approval 姿态、来源 Core 创建信任和设备配对是不同授权；任一成功不能代签或扩大另一项。

## 配置与唯一事实来源

Core 应用授权 owner 持有连接器配置、只含安全元数据的差异计划与原操作记录；客户端只编辑和消费这一 owner，不维护第二份同步配置或状态机。配置能通过同一公共服务读写，修改以当前修订为依据，不覆盖别人刚保存的配置。

环境工作台显示当前 Host 作为来源或目标的相关规则，文案不将当前环境固定说成目标。双端编辑均可选择已登记环境；保存后若规则不再涉及当前 Host，应从本页规则投影移除，原操作及其准确 ID 继续保留并可查询，不因规则改道丢失未知回执。保存期间继续编辑的同一规则草稿保留后来字段；只有它仍基于本次原修订时，采用刚确认的保存修订作为后续基线，其他规则或其他基线不被迟到响应改写。

每项配置必须明确：

- 稳定配置 ID、应用 ID 与人读名称；应用 ID 是连接器协议身份，不从按钮或命令名称推断。
- 来源和目标的准确 Host ID、预期语义 Runtime ID、预期操作系统账户，以及分别在该执行环境运行的固定可执行文件与 argv。命令和参数属于用户配置，操作请求不能临时传入新命令。
- 期望应用账户的稳定 ID 和本次 scope 集合。操作系统账户不是应用账户；同名账户、显示名或目标已经登录不能证明是期望账户。

Host 路由与语义 Runtime 由原配置 / Runtime owner 确认；操作系统账户由该准确执行环境的平台身份读取确认；应用账户、scope、应用配置修订和可迁移性由该应用连接器的结构化协议确认。用户填入值是预期，不能自行变成观察事实。连接器只对自己的应用协议负责，通用 Core 不认识具体产品、站点或凭证路径。

## 查看差异

用户发起只读检查后，服务只访问本次来源、目标和指定应用范围。双方观察至少区分已确认账户及 scope、需登录、应用不可迁移、执行平台不支持和观察未知；不把读取失败显示为未登录或空授权。

计划同时绑定原配置修订、准确双端身份、双方应用修订、期望账户和 scope，给出每项结果及明确下一步：

- 目标以期望账户具备全部 scope：可直接复用，无需复制。
- 来源以期望账户具备可迁移的 scope，目标为空或同一账户缺少 scope：可同步指定最小范围。
- 来源未登录、目标需要原生登录或应用不允许迁移：说明准确端点及所需动作。
- 目标是其他账户：明确冲突，保留原账户；本次首个范围不提供通用强制覆盖。
- 任一所需事实未知：保留原观察与原因，允许重新检查，不假称可以安全执行。

计划与普通响应只包含白名单元数据，不含 token、cookie、私钥、导出正文或应用原始 stdout / stderr。错误按阶段及结构化代码表达，不回显命令正文、输入或未知错误文本。

## 执行、验真与未知恢复

执行必须是用户明确发起、针对原计划的一次动作。调用前重新读取配置、双端身份和应用修订，拒绝本次已经过时或目标不符的计划。拒绝只影响这次同步，不关闭健康 Agent 或原通路。

Core 通过原 ExecutionHost 的固定 argv 和 stdin 机器协议执行连接器。私密导出材料只经过来源连接器、Core 内存和目标连接器 stdin；不进入普通客户端、配置、计划、操作元数据或诊断，不在磁盘暂存。传输使用原本地进程或系统 SSH，不另建凭证传输服务。可取消观察等待不等于撤回已发生的导入。

在目标导入可能发出前，必须耐久保存原 operation ID、准确意图、计划和执行阶段。目标连接器的导入合同必须接受原 operation ID、期望原修订和意图摘要，保护目标已有配置，并提供只读的原操作查询；应用导入事务和准确重复调用语义由连接器负责。Core 不宣称任意应用都具有 exactly-once 导入能力。

导入成功只说明材料导入。随后必须独立调用目标应用的验真协议，确认准确操作系统账户、期望应用账户和全部所选 scope；只凭“ready”、命令 exit 0 或来源 export 成功不得显示同步成功。目标本来可复用时同样要有目标验真事实。

操作记录保留原 ID、应用配置修订、准确双端、阶段、最后确认事实、失败或未知原因及后续动作。回执丢失、断线、服务重启或取消后，原操作保持未知；刷新只查询原 operation 或重新验真，绝不重新 export / import，也不自动换新 ID 重做。无法证明原导入未发生时，不允许以新 ID 绕过同一目标范围上的未决操作。查询失败保留原记录，局部失败不得扩大为全部授权或 Agent 不可用。

停止管理、删除连接器配置、移除目标受管材料和上游撤销授权是不同动作。首个范围只停止使用 / 删除配置，不承诺删除目标材料或注销上游账户；没有具体应用的撤权合同与回执时，不显示统一“已撤销”。原操作元数据仍可查询，不因配置删除或修改丢失。配置清单同时提供相关 Host 下每项配置的最近操作和全部未决操作；删除配置后的未决结果仍能发现，用户离开页面或重启后不需要记住 operation ID 才能恢复原查询。查询按相关配置与未决索引读取，不为当前页面扫描无关历史。

## 公共消费与验收

GUI 与对象优先 CLI 通过同一 typed 公共服务完成配置读写、只读计划、显式执行和原操作查询；参数、结果、发现与准确签名由[公共能力源码入口](../../specs/public-capabilities.md)指向实际定义，不在本文另存方法表。拥有配置命令的传输必须提供真实用户身份；Agent 不能通过一个 JSON 布尔值冒充用户批准。只读元数据同样沿原传输认证，不开放私密导出 / 导入 RPC。

验收覆盖至少两种独立应用协议形态：可迁移授权经真实子进程的导出 / stdin 导入 / 目标验真完成闭环；目标原生登录或不可迁移的应用给出准确限制且不导入。公共 CLI 与实际 GUI 消费同一 owner，不能只验证服务导出存在。必须验证账户冲突、scope 缺失、过时计划、OS / Runtime 身份不符、导入回执未知后的原 ID 查询、服务重启保留原记录，以及局部失败保留其他应用与健康 Agent 能力。变异应能推翻验真、身份或 unknown 不重放等承重不变量；实际远端验收与本地受控协议验证分别报告，不把受控连接器当作真实外部应用登录成功。
