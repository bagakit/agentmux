## Browser 工作面

有界结果存储在新引用得到持久确认后才淘汰既有结果。新结果写入或确认失败时保留已发布的原引用。新引用已经确认后，旧项的回收结果独立表达。

**定位与完整性。** Browser 是面向项目工作、由人和 Agent 共用的网页工作台：研究有来源，操作有可核验结果，人工可接手、交还并从当前页面继续；中断后保留原工作面和准确恢复入口。完整性以这些日常工作链的真实可用为准，不以参考产品功能数量为准。可复用任务沉淀已验证做法，跨系统编排沿 Agent 与现有工具，不因此在 Browser 再建通用业务流程平台。原生引擎不具备的指纹、网络或宿主能力如实表达，不以配置字段代签；高级能力的独立缺口不抹除，也不成为无关健康网页能力的门禁。

**Profile 的主要用途。** Profile 是可重复使用的网站登录环境，持有网站 session、站点数据、网站权限及其环境设置；名称和颜色帮助人识别，不授予 Agent 输入资格。Agent 明确指定 Profile 时只消费该准确身份，未指定时使用未命名的持久默认环境并保留网站登录态，页面留原任务且不自动进入 Survey；不把“未显式选择 Profile”冒作匿名隔离或无持久数据。代理和环境／指纹编辑是按需的附加能力，不承担 Profile 或 Browser 的主定位。Survey 的组织、开页入列和切换范围唯一见[《Profile 与 Survey》](knowledge-workflows.md#profile-与-survey)。

- **网页标识取真实页面事实。** 网页 favicon 由原 Browser Main owner 观察，并连同准确 Browser／当前导航身份向已打开条目的呈现提供；缺失、损坏、不可用或无法确认时回落统一网页图标，不从域名猜标识或另发无关页面请求。后来导航优先，前一页迟到图标不覆盖新页；图标不是权限、加载成功或 Agent 活跃状态。已观察的图标随原 Browser 的页面记忆保留：原生页面已释放或冷启动尚未创建、且该 Browser 仍停在记录的同一地址时，呈现为上次所见的图标；恢复后的页面报告自己的图标、离开该地址或确认没有图标时被替换。活体页面的新导航仍先清除旧图标，上次所见不能冒充当前文档已确认的图标。
- Browser 是 AgentMux 内的一等工作面，不是外链跳板：它可导航、可标记、可被 Agent 安全消费，生命周期与权限事实由准确 Browser 的唯一宿主持有；第一方 Desktop 的 owner 是 Main，独立 headless 宿主消费同一高层合同。Renderer 既不拥有 WebContents，也不持有第二份导航或权限状态。
- **无窗口对象生命周期。** 独立 Browser 宿主通过对象级 create／close 与原 targets／run／history／inspect／follow／stop 公共能力工作，不制造 Region 或 Agent Run。创建与关闭都先保留调用方原 operation identity、typed intent 及回执；未知保留原 Browser／operation，查询原回执、不自动再启动。关闭仅作用于该宿主准确 owned target 与原 document，尊重 beforeunload；缺失 ACK、断连或发现缺口不代签关闭。停止操作保留原页面，释放原生资源保留工作面，均不冒充实体关闭。宿主进程重启按原 Browser ID／engine endpoint／targetId 接回存活页面及未保存输入，不按地址或标题替换、不重放程序。没有真实 Workspace 授权时 workspace 为空且不广告文件能力；引擎由显式宿主配置提供，Core 不管理安装、下载或分发。
- **普通嵌入页自关闭与失联分开。** 原引擎接受的页面关闭事实与准确 WebContents 的实际销毁配对后，沿既有关闭通道收起准确页面投影；不把已完成的自关闭报为连接不可用并自动重开结果页。普通页的关闭请求被取消、已由新导航取代或只有来源不明的销毁时，保留原页面／身份与恢复路径；不能用关闭意图或观察缺口代签终局，也不停止其关联 Agent 或兄弟工作面。网页子窗口仍沿[原生网页子窗口](#原生网页子窗口)的对象生命周期。
- **Browser 是 Agent 自我改进的观察—行动—复盘闭环。** Agent 读取结构化页面事实，执行语义动作，得到页面变化与失败结局，再把这一轮沉淀成可检查的操作记录和可复用脚本；本页标题中的 RSI 指这一自我改进闭环。`browser.run` 的 CLI 是这个闭环的公共入口；每一步都必须有可读结果，不能只有“脚本退出 0”。
- Browser 被 Agent 使用时不抢占人的焦点，Agent 尽量用 AgentMux CLI 操作 Browser，而不是操作界面。Agent 发起的 Browser 打开、导航、页面操作及其进度、结果或失败投影，保留人当前的系统窗口、主面选择、Tab、Region 和键盘输入位置，不自动激活 sidebar、切工作面、抢原输入或移动系统鼠标；放置和驱动页面不是焦点转移授权。人主动点击 New Browser／目的地菜单或明确发起的 focus 仍按其导航意图执行，不与后台 Browser 工具混在一起。Agent 优先用 AgentMux 官方 CLI 发现准确目标、读取页面、按真实 ref 行动和消费结果；能力或 owner 未确认时就近如实说明，不能猜 ID、通过界面重开／聚焦来绕过失败，不能因此阻断健康 Run 或移除原 Browser／工作面。焦点与输入事实沿原 owner，页面反馈只引用本节既有虚拟指针与动效约束。
- **先分析本任务的原页面。** 用户说“看看 browser”或类似未指定页面的请求时，先结合原任务与[准确空间位置](spaces-and-layout.md#agent-的自身位置与邻居发现)，分析是否指自身同 Tab 的邻居 Browser，并只读核对该 Tab 的真实 Region／Browser 绑定；不能直接把泛指当成新建页面的要求，也不能按标题、最近使用或全局焦点挑选无关页面。已给准确 Browser／地址／位置或指定工具时沿原目标；同 Tab 仍有多候选、关系未知或内容不能确认时，保留候选与原工作面，仅对影响本次操作的实质歧义问清。发现邻居不扩大授权，不把可见关系当成页面已授控制权。
- **Agent 的网页就近可见。** Agent 打开或操作网页时优先使用 AgentMux 自带 Browser 与公开 CLI，优先复用本任务已确认的准确 Browser；同一任务通常留在同一 Tab。
  - 默认落点：需要新页面时，Agent 先读取自己的实际 Zone／Tab／Region 及全 Tab 可见布局，默认在同一 Tab 新建可读的方向 Region，使 Agent 与网页同时可读。用户未指定其他位置、双方可读时，优先原 Agent 所在 Tab 的右侧分屏，并适当缩小 Browser；实际方向与尺寸由 Agent 读取布局后结合几何与内容显式指定。
  - Agent 明确创建工作面时不默认另开新 Tab；网页自身的新页请求另沿[场景偏好](#原生网页子窗口)。Focus 中另开的新 Tab 可能不会出现在当前阅读面，也更难找到；创建成功不等于人已看见，不能为“让人看页面”默认另开隐藏工作面或抢焦点。完整原型或截图评审本身不构成改开新 Tab 的理由，不能让采图便利变成人的反复切换。
  - 例外：用户已明确新 Tab、同 Tab、方向与尺寸偏好时优先兑现。布局确实拥挤、阅读确需完整工作面、能力确实不适用或用户指定其他 Browser 时，可以选择相关新 Tab 或指定工具，并简要说明原因和实际位置。
  - 指引与核对：Browser skill、使用指引与运行时指导同时表达同 Tab 新 Region 的默认及上述例外；操作后核对返回的真实 Browser、Tab、Region 和导航回执。
  - 授权边界：创建同 Tab Region 不授权覆盖旧内容、切焦点、夺取人工控制或绕过拒绝；原页面、用户输入及未知操作回执保持。
- **Agent 操作是 Browser 的一等活动。** 一轮操作有稳定的 operation identity、发起 Agent、目标 Browser、脚本/步骤摘要、当前阶段、结果和时间；Browser 宿主是事实 Owner，Desktop Renderer 只投影。驱动开始、动作派发、页面观察、权限等待、用户接管和结束都进入同一条有序记录，不能另建一份只供 UI 使用的“操作状态”。
- **交接必须先让人看懂，再让人接手。** Browser chrome、Tab 标记和页面内提示同时表达“哪个 Agent 正在操作哪一页、当前做到哪一步、下一步会触发什么”。普通点击、滚动、按键及程序派发的原生输入不自动接管、不改变控制权，也不因此中断 Agent；Agent 控制期间的人工网页输入按下文[输入隔离](#agent-操作可见性与输入隔离)处理，不能因没有接管而仍让输入改变网页。本人明确选择“接管”时，通过原 Browser 与仍活动的原操作身份停止后续派发，再将网页输入交给人；有活动程序时返回 `stopped`，没有活动程序仍可接管。单独停止程序只结束执行，不隐含接管；若入口同时停止并接管，必须明确表达这两个作用。已发生的动作保留，仍在途的动作结果按实际确认程度表达，后续动作不得派发。接管／交还入口依据实际控制权与准确 Agent 关联出现，单次操作结束不抹掉已确认的关联；明确没有关联 Agent 时，沿[从 Browser 创建 Agent](#从-browser-创建-agent)提供创建入口，不显示无接收者的交还。交还必须由人明确发起，将准确 Browser 控制交回已关联的 Agent，不自动续跑或重放旧程序；Agent 从当前页面事实重新决定下一次操作，不能靠重试夺权。用户主动把控制权交给 Agent 时，要看到目标、脚本摘要和可停止出口。
- **操作记录可以变成脚本，但不是坐标录制。** 回放资产由语义步骤（观察、ref、导航身份、动作、等待、结果）组成，保留页面身份检查、权限/外部应用交接和不可逆动作的人工闸门；不录入密码、Cookie、原始敏感输入或屏幕坐标。回放默认先预览，执行中可逐步暂停，页面身份不符或结果不确定时停在服务窗。
- **人工闸门是操作记录的一部分，不能靠跳过它让回放变绿。** 敏感输入、带私密参数的导航、未审查代码与协议调用在计划中保留原来的步骤位置和阻断原因；隐去原始值后需要重新确认，不能删除步骤或把地址改成另一个地址后继续执行。失败、不确定和记录裁剪造成的缺口同样必须可见。
- **Agent 身份和操作位置必须同时可见。** Tab/Browser chrome 显示 Agent avatar、名称和驱动状态；页面内用不遮挡内容的语义目标标记表达当前 ref/动作位置，脚本生成或等待时显示对应阶段。颜色只作辅助，头像、名称、动作名和目标语义必须能独立说明是谁在做什么。
- Agent 操作 Browser 时显示虚拟鼠标位置，并有覆盖 Browser 画面的操作光效。虚拟指针只表达当前真实操作的可验证位置，不移动或替代人的系统鼠标；语义目标标记继续说明正在操作什么。位置与光效归实际 Browser、operation、frame 和当前导航，坐标未知时不猜中心、不用上一页的位置补空；滚动、缩放、分割和 frame 投影后仍指向真实位置，失效即清除。
- 执行光效只表示当前真实执行，不把只读观察、脚本生成、等待人工、人工接管、历史步骤或恢复状态冒充成 Agent 正在操作；下文持续的控制权边界提示另表达输入归属，不冒充正在执行。普通单次动作的指针与反馈须实际可感知，不能为显示而延迟原动作；瞬时动作或 operation 正常完成后可保留固定短暂、有界的一次完成反馈（指针运动的窄例外见下一条），明确表示已完成与真实位置，不延长或继续呈现 busy、执行光效或循环。等待、人工接管、停止、失败、页面变化或隐藏时优先立即清除；新 operation 覆盖旧完成提示，旧 timer 或 clear 不得改掉新一轮。同一 operation 内的普通只读观察须重核原目标与 viewport 几何；仍有效时保留原完成提示，不提前清除、不重建，也不续期。普通重启后不复活旧指针或动效。当前控制权允许的网页输入、交还和停止保持可用；装饰提示不持有输入隔离，不遮住阅读、抢焦点、改变控制权或阻断已完成动作，显示失败沿当前 Browser 就近如实说明，原页面、工作面与健康 Run 保留。相关更新仅作用于实际目标 Browser，不扫描或重绘无关页面。控件与减少动态效果的视觉约束只见密度 SSOT[《Browser RSI 操作表面》](../presentation/browser-workface.md#browser-rsi-操作表面)。
- **指针连续移动。** 两个位置之间的移动足够快，但过程看得见（tween），hover 时有轻微浮动。同一实际 target document 与导航下，同 operation 或跨 operation 的两个已验证显示位置之间，应有短促、可看清过程的连续移动。上一位置只是一条已实际显示的坐标与 document／导航／viewport 事实，不携旧提示、权限或 DOM 目标，不重称旧 ref／目标仍有效。
- **完成提示与下一起点。** 正常完成 cue 到期只移除可见提示，历史仍可供下一真实 owner 作为动画起点；新 target 前重核历史与当前实际终点，不成立时保持静态。旧 expiry timer 不擦新 owner 或新历史，不能通过续期旧 cue 留 ghost。新 operation 清除旧提示与归属后，由当前真实 owner 承接仍有效的历史起点；不同 document／frame／nav 或无有效历史时，不猜跨 frame offset、旧页位置或页面中心，首点保持真实静态位置。
- **失效与人工优先。** 人工输入与控制权变化、等待、停止、失败、隐藏、导航、frame／view 失效及真实 anchor／viewport 几何变化，优先清除动效并使历史作废。人工归属沿原宿主输入来源与显式接管事实确认，不能仅凭 DOM `isTrusted` 把合法 Agent 原生输入归为人工而清除反馈；没有宿主输入归属能力的外部共享页保持未知，不冒称已观察到本人输入或即时接管。旧 callback／timer／clear 不能复活旧提示或改新 owner；非人工的迟到 scroll／resize 在滚动后已验证几何没有变化时，不擦新提示，真实几何失效仍立即清除。
- **动画预算与 hover。** 动画不等待、延迟或延长原动作、CDP 或 operation。正常完成立即结束 busy 与执行光效，至多让已启动位移在原短预算内一次到达终点，不重启动画或延长完成提示。hover 浮动仅是当前可信提示的指针装饰：真实目标 anchor、命中、系统鼠标与控制权不变，标签稳定，不冒充仍在执行。历史只属于既有反馈状态，不持久恢复、不建立第二状态 owner／全 frame 缓存，不扫描或唤醒无关 Browser。视觉与减少动态效果规则见[《Browser RSI 操作表面》](../presentation/browser-workface.md#browser-rsi-操作表面)。
- **按键与脚本反馈。** 拟人反馈只消费实际派发的非敏感命名键／已证明的 modifier 语义，以及实际 opaque js／cdp 执行阶段。秘密、非快捷键或无法证明组合语义时使用通用图标，不猜按键，不展示输入值、参数或脚本文本，也不为反馈默认扩展输入协议。snapshot／read／generate／wait 不冒充网页执行；结束或人工接管立即停止执行循环，实际很快时仅沿原有界完成反馈。反馈不等待或延长动作，不增加轮询、JS RAF、全页面重绘或无关 Browser 工作，不另建 owner、配置或工具栏。
- **Browser timeline 与聊天 Activity 共用时间语义。** Browser 面提供可展开的操作时间线，能按轮查看脚本、观察、动作、结果、接管和失败；它复用同一条时间轴和状态词，链接回页面快照、脚本行和可重放入口。时间线缺口、页面导航和人接管不能被折叠成“完成”。
- **历史可达，记录失败可见。** Browser 重建或应用重启后，历史操作仍可从 Browser 的历史入口找到；恢复的记录明确表示中断或不确定，不伪装成正在执行。记录加载、保存或投影失败只降低记录能力，不阻断健康页面或 Agent；对应 Browser 持续显示失败步骤、当前仍可用的能力与恢复动作，不能静默变成“没有历史”。
- **失败恢复面先认页，再行动。** 页面错误与原生连接恢复分别消费原 owner 的准确状态和重试入口，保留 Browser、Region、地址草稿及其他工作面。恢复面用原页面标题、目标地址与简短状态帮助辨认；保留的标题或画面须说明原来源，不冒充当前文档已就绪或最后成功记录。工具的 targets／pageInfo 同步区分原请求地址、native 当前文档、导航及 commit 身份、loading 与原错误；target 可操作和脚本返回不代签请求已载入，也不冒称已看见 Renderer 的恢复面。没有原 owner 确认的最后成功事实时保持未知，不拿旧文档或预览补造；这些观察不另扫图片、磁盘或无关页面。原页面 Retry 与连接 Retry 不互换，不从错误文案推断控制权或自动重放。用户可显式编辑原地址而不覆盖或提交草稿、复制准确目标地址，并按需查看原技术原因；辅助展示或复制失败不拿走恢复入口。已有旧预览时明确其非实时、不可操作及所属页面，没有真实缓存时不补造缩略图。
- **上次查看的外观归原 Browser。** Desktop Main 为准确 Browser／Profile 保留一份有界的历史标题、小图及原页面来源，普通页面可跨应用重启读取，匿名页面只在原临时会话内保留。外观采集只沿相关原页面可用、真实可见的边界异步进行，不等待、唤醒或保活页面，不读取操作证据充当装饰；错误、换页、来源更替或采图失败不以空图覆盖原预览。读取旧外观不创建或恢复网页，图像不进入 Core 空间事实或每次 Browser 状态广播。历史 URL／导航无需等于后来的失败目标，展示必须区分两者，Retry 仍指向原失败目标。显式关闭 Browser 或确认删除 Profile 时，收口准确范围的预览并阻止迟到写入复活；普通原生资源释放不等于删除外观。缓存缺失、不可读、图片损坏或存储未确认只影响这一辅助提示，原地址、恢复入口、控制权及健康 Agent 保持可用。
- **页面记忆归同一外观 owner。** 同一 Main owner 还为准确 Browser／Profile 保存一份有界的页面记忆：最后提交地址、该地址上已观察的图标，以及该页的导航条目（地址与标题）和当前位置。记忆随真实提交、标题和图标事实合并写入，不为写入唤醒、保活或重新加载页面；普通页面跨应用重启保存，匿名页面只在原临时会话内保留。Chromium 的网页内部状态（滚动位置、表单值等）只在同一应用进程内随释放保留，不写入磁盘。显式关闭 Browser 或确认删除 Profile 时一并收口；记忆缺失、不可读或损坏只退回通用图标与单页加载，原地址、恢复入口、控制权及健康 Agent 保持可用。
- **退出应用或恢复失败不能把 Browser Region 当作用户关闭。** 正常退出只释放原生页面资源，保留原 Browser 身份、Tab、Region、焦点与分割布局；重复恢复同一身份返回原页面的真实状态，不重新导航、不更换 Profile。恢复握手、页面创建失败或原生 owner 意外消失时，同一 Region 保留地址与可执行的 Retry，并在服务窗说明失败步骤；Retry 重新取得同一页面 owner。只有明确的关闭事实才移除该页面投影，资源释放、重复握手与未知恢复结果都不是关闭授权。普通进程重启必须验证原工作面仍在且页面可恢复，其他健康工作面不受影响。
- **冷启动先还原描述，页面按真实消费恢复。** 原 Browser 的 durable 身份、URL、Profile、模式和已保存的 Viewport 随原 Tab／Region 与布局先恢复；仅挂载隐藏工作面或查询目录不创建原生页面。首次真实可见展示或已获授权的公开页面操作，沿同一 Main owner 恢复同一 Browser；并发消费不重复创建，已存在的页面优先复用，不重新导航、释放未提交表单或抢焦点。冷描述仍可公开发现，未实例化与真实 ready 可辨，公开操作不能因延迟创建变成无入口的 Unknown Browser。页面记忆的当前条目与原描述地址一致时，首次恢复沿记忆重建前进／后退条目和当前位置；不一致、缺失或读取失败时只加载原地址。恢复失败保留原描述、地址草稿和同身份 Retry；旧记录未保存的 Viewport 或网页 DOM 状态保持未知，不冒充已恢复；本次冷恢复不额外释放仍活着的页面。
- **闲置回收覆盖全部导航位置。** 没有实际消费者、保护中的使用或恢复缺口的后台 Browser，沿同一资源 owner 按闲置时间与最近使用预算释放原生页面；离开项目或 Topic 不成为永久保留理由，返回但仍未显示也不重新开始闲置计时。真实可见展示、正在执行的操作、下载、媒体、未提交输入和有效镜像等保护事实须按准确来源核对，未知不当作可释放。Browser 的预算不改变 Terminal 的 replay 保温、Monaco 或共享导航事实；只读目录及资源查询不唤醒页面或延长其使用时间。
- **自动释放开关只控制 Browser 自动预算。** 默认开启安全闲置释放；关闭后停止新的自动 Browser 释放请求，不影响手动安全释放、原身份恢复或 Terminal、Monaco 的既有资源规则，也不主动唤醒已释放页面。
- **预算请求不冒充已释放。** Main 在不可逆动作前复核原 Browser、当前文档与使用保护，原生关闭确认后才提交释放事实；保留、关闭未确认、失败与来源换代分别返回，不提前撤走仍健康的页面或把未知当作关闭。Renderer、自动策略、人工与公开工具消费同一判定和回执；迟到结果不覆盖后来的原生 owner 或新的消费。释放保留 Browser／Tab／Region、地址草稿、Profile 与 Viewport；释放前在原生关闭之前读取原页面的导航条目、当前位置与 Chromium 页面状态。再次使用沿同一身份，以这份条目重建页面，后退／前进照常可用，Chromium 能恢复的滚动与表单值尽力恢复；条目读取失败或当前位置与原地址不一致时只加载原地址。这不冒充完整恢复任意 JavaScript、DOM 或表单状态。
- **停放不是未知。** 已确认释放的页面和冷启动尚未创建的页面，是没有原生页面、也没有进行中操作的停放状态；条目与列表把它表达为停放、显示时恢复，不用控制未知或恢复中的状态图标。只有恢复失败、原生 owner 不可用、空间位置未确认等真正无法判定的情况才表达为未知，并保留原恢复入口。
- **关闭未确认的原生资源仍有 owner。** Profile 切换或显式关闭不能先丢掉仍活着的原 view；原生关闭抛错、被阻止或尚未确认时，Main 保留准确 Browser／Profile／Workspace 与原生实例的清理归属，直到权威销毁事实到达。资源目录、进程归属和 Profile 使用保护包含这些待清理者；迟到事件不改变后来的新页面，旧资源清理问题也不阻断独立健康页面。未知关闭不自动重放，明确 Close 沿准确原 owner 恢复清理。
- **统一管理所有 Browser 资源。** 设置中的 Browser 资源目录复用 Core 的原位置绑定、Main 的页面存续与保留原因、原公共进程指标，区分未实例化、运行中、已释放与未知；同页多处展示不重复记实体或进程占用。共享进程和未知归属如实表达，不按页面数均分 RSS，不从标题、地址或旧记录猜创建者与当前使用者。原准确目标的安全释放、恢复及每项批量结果经同一公共能力供人和 Agent 使用，失败保留原目录、页面与可执行恢复路径；查看目录本身不创建页面或建立第二生命周期账本。目录明确本次查询的完整或部分覆盖；部分查询或读取失败不证明未返回的页面已删除，保留其上次观测并标明旧范围，当前可用数量只计本次实际观察到的页面。隐藏的设置页不持续订阅或查询目录。释放内存、显式关闭页面及清理网站数据分别表达，清理登录存储仍沿原 Profile／站点数据批准合同。
- **资源管理先认页、再比较占用和动作。** 默认列表能直接认出页面、当前资源状态、进程占用与可执行动作；完整地址、技术身份、全部位置、原始保护原因及进程明细按需展开。页面存续、释放保护、本次目录覆盖和进程采样各自表达，缺测不填零，上次观测不冒充当前；共享进程不显示为单页独占内存，也不承诺释放某页即可收回所列进程占用。排序与刷新保留原对象选择和键盘焦点，不因数值更新切换操作目标。
- 公开目标的页面标题是有界展示字段。超长标题只在该投影收短，保留原页面标题、地址、身份和可用状态，同批目标仍可读取。
- **单页和批量管理都有明确范围。** 批量动作冻结用户明确选择的准确 Browser／文档集合，不把较晚筛选结果或新出现页面补入原批次；各项仍由 Main 在动作前复核原保护事实。结果按原对象分别表达已释放、保留与未确认，局部失败保留其他结果及原页面。安全释放复用原请求，不额外层叠通用批准流程；保护中的页面说明原因，仍可定位、读取详情并沿原恢复入口继续使用。自动释放偏好沿原设置保存，手动资源动作及其回执立即生效，两种范围清楚可辨。
- **公开恢复回执只说明本次原生取得。** 准确目标的公开恢复复用原页面 owner，完整回执仅确认本次已取得的当前原生页面及文档身份，不表示页面内容加载完成，也不提供原 Browser 程序日志之外的恢复历史。未取得完整回执时保留原业务请求身份和未知结果，不自动重发；后续当前页面观察不追认旧恢复已完成。
- **公开释放复用同一安全判定。** 工具按准确 Browser 与当前文档身份请求原 Main owner 释放，不为释放创建页面或扫描全部目录；可见、使用中或风险未知的页面仍按同一保护事实保留。每项回执分别说明已释放、保留或未知及其原因，不关闭 Region、清理网站数据或停止健康 Agent。未获完整回执保留原业务请求身份，不自动重发；当前目录观察不追认旧释放完成。
- **已用操作身份只指向原记录。** 原日志仍保留同一 Browser 程序的 `operationId` 记录时，重复提交不得覆盖原记录、创建页面来重跑程序或把未知结果改称成功。公开入口明确返回操作身份已存在，调用方沿原操作查询、历史与订阅读取当前事实；并发重复提交也由唯一日志 owner 裁决。新操作和原 Browser 的其他健康能力保持可用。
- 原生 Browser 的多位置媒体预览、失败与重试边界只见本页[《多位置呈现、局部遮挡与输入交接》](#多位置呈现局部遮挡与输入交接)。
- **呈现资格依据准确文档，不能依据资源是否加载完。** 受信 App 的当前文档可以在无关资源仍加载时登记和使用原 Browser 呈现；加载进度不证明请求者失去资格。异步准备前确认的原文档请求不能在导航后转由新文档受理，旧文档的租约、采集与输入授权随真实文档更替失效，同文档导航继续保留。失败说明准确的呈现步骤与原因，不把内部登记拒绝说成网站或健康 Agent 失效；原页面和同身份恢复入口保持可用。
- Browser 驱动脚本的 `cdp(method, params)` 是明确的逃生口：Main 必须把 CDP 的成功结果原样交回脚本，并把协议异常作为失败浮现；不能把它变成静默 `undefined`。它是 Agent 自行补齐尚未封装浏览器能力的正式通路，正向结果和异常结果都必须有行为守卫。
- **`cdp` 只作用于当前页面。** 逃生口的范围是本次驱动的这个页面及其 frame；越出它的命令在发出前拒绝（失败事实为 `cdp-scope`、`not-dispatched`），并说明应改用的能力，页面、Profile 与 Agent 保持原样。越界只按命令本身的作用面判定：读取或改写 Profile 的 Cookie 与按站点清理存储或缓存（改用人确认的清理站点数据）、改变证书校验或授予权限、绕过下载 owner、在 Browser owner 之外创建／关闭／连接页面或窗口（改用 `amux browser open`）、浏览器进程级操作。经 cdp 发出的 `Input.*` 照常执行，并与页面动作一样走 Main 的派发回执，不被当成人的输入。其余页面内命令原样转发；拒绝表是 denylist，不发布白名单，以保住逃生口补齐未封装能力的用途。
- **页面自己的对话框与文件选择器只在驱动期间由一个 owner 接管。** 页面在 Agent 程序运行中弹出 alert、confirm、prompt 或离开确认时，正在进行的页面调用立即以带对话框文字的失败结束，不等到程序时限；对话框打开期间需要读写文档的调用在发出前拒绝。程序可用 `acceptDialog`／`dismissDialog` 回答，提示文字只给 prompt；同意离开要求留下的页面由人决定。程序结束时仍开着的对话框被取消，结局记为不确定并提示先看页面。点击打开的文件选择器不弹出系统窗口，程序经 `pageInfo().fileChooser` 的句柄用同一上传 owner 选择文件；更新的选择器替换句柄，导航使其作废。驱动结束或人接管时接管立即撤回，人自己的浏览不受影响；页面通知无法开启时不拒绝任何调用，保持原行为并给出非阻断提示。对话框事实只取协议事件与本 owner 自身状态，不读 CDP 错误文字或页面文字。
- **页面调用的失败事实与后果交给程序。** Main 判定的拒绝或未确认带 `kind` 与 `effects` 进入程序：`not-dispatched` 表示页面未被触及、可安全重试，`unknown` 表示可能已生效、须先看页面；非 Main 判定的错误不带这两项，不冒充页面未被触及。每一步记录 Main 自己观察到的后果：本次调用期间页面打开的 Browser 与切换到的文档；调用结束后才出现的页面不归入任何一步，导航身份未知时不声称发生了导航。
- **New Browser 必须有可见结果。** 在聚焦的 Universal Pane（包括当前不是 Launcher 的 Region）点击 `New Browser` 后，必须创建并显示一个 Browser Tab／Region；Main 持有的 Browser 创建失败时，在同一工作面给出确定、可执行的错误。按钮不得在状态、Tab、Region 和错误提示都不变化的情况下静默无反应；回归验证须覆盖在聚焦的非 Launcher Pane 上点击时 Tab／Region／Browser 状态的变化或错误投影。
- 页面元素选择产出结构化上下文（tagName、role、可访问名、selector、文本、邻近文本、白名单属性与净化后的 HTML），以文本形式进入 Composer 草稿，与其他附件同一条通路。净化在 Main 侧完成，Renderer 不把原始 DOM 当证据传递。元素上下文当前不采集 computed CSS，截图也不自动并入 prompt；图像复制及显式保存可编辑原稿沿[《Browser 页面截图与标记》](#browser-页面截图与标记)。说明元素选择能力时须如实写出这两条边界，不用“看起来完整”的措辞掩盖。
- Agent 发起的元素上下文通过 Browser drive 的显式 `elementContext(ref)` 入口提供：目标必须来自当前 Browser snapshot 的授权 ref，经 Main-owned CDP 句柄解析；入口只能读取结构化字段（tagName、role、可访问名、selector、文本、邻近文本、白名单属性、净化 HTML），不能返回原始 DOM 或执行事件。入口与人工选择是两条有意分开的能力：人工选择继续由真实 `event.isTrusted` 门禁保护，Agent 入口不得删除或绕过该门禁。
- `elementContext` 失败必须保持可区分：ref 不在当前快照、ref 解析后不是 Element、页面导航/句柄失效和提取/净化错误分别给出可行动诊断；不能静默返回空对象或把失败伪装成 Agent 没有权限。读取结果沿 Browser drive 的 typed receipt/Composer 通路交付，不能在 Renderer 另建一份 DOM 事实。
- Browser 截屏的观察、绘图、复制与退出沿[《Browser 页面截图与标记》](#browser-页面截图与标记)的同一生命周期；系统截图入口与草稿／剪贴板交付归[原生截图合同](native-desktop.md#系统截图快捷键与选区)，两者复用同一图片编辑实现，各自保留准确采集来源与结果 owner。
- 链接打开使用统一的目的地菜单（当前 Region／分屏／新 Tab），与 Terminal 链接共享同一套目的地语汇，Browser 不另设一套打开语义。网页链接的右键菜单提供既有的分屏／Tab 打开位置，用户显式选择的位置优先。网页自身请求的新页面沿来源场景的已保存偏好放置，显式本次目的地优先，具体默认值和范围只见[《原生网页子窗口》](#原生网页子窗口)。
- Browser Region 点击内容区时，更新其所在导航上下文的准确选择；选中边界、标题和键盘焦点消费同一原位置事实。Work 与 Survey 不因此共享选择，也不从 URL 或 hover 猜位置；新页和子 frame 的交接沿本页 Browser owner。选中态呈现见[《Browser Region 选中态》](../presentation/browser-workface.md#browser-region-选中态)。
- **Agent 正在驱动某个 Browser 时，不切过去也能知道是哪一格。** 页面内角标只在人看着那一页时有用，而人通常正在别处工作、想知道那边进行到哪里。因此 Tab 标签上的 Browser 标记在被驱动期间与空闲的 Browser 画法不同，且这一差别参与标记去重：同一 Tab 中两个 Browser Region 一个被驱动、一个空闲时，标签上画两个标记，不合并成一个。驱动是瞬时事实，随运行开始和结束，不进入持久化；重启后不显示"正在被驱动"的旧标记。
- Browser Profile 从当前 Browser 的管理入口导入，不强制跳到 Survey；入口归属引用[《Survey、临时 Zone 工作面与知识入口》](knowledge-workflows.md#survey临时-zone-工作面与知识入口)，凭据与 Cookie 归 Main；导入路径落在 Workspace/Profile 约束内，逃出约束一律 typed 失败关闭，不静默降级到默认 Profile。
- **应用链接（非 `http(s)` 的 URL scheme，例如自定义应用 scheme 与 `mailto:`）像一般浏览器那样交给对应应用，不当成非法地址挡掉。** 用户会把本应用当作自己的浏览器使用，行为须与一般浏览器对齐。这类链接不能被静默吞掉，也不能因为某个站点的按钮形态而增加站点专用分支。约束：
  - **页内导航与新窗口请求都要正确交接。** 页内导航、`window.open` 与 `target="_blank"` 分别覆盖同一应用链接语义；应用链接不留在原生页面中加载，也不生成应用管不着的空窗口。原页面与 Browser 工作面保持，普通网页弹窗仍沿既有语义处理。
  - **默认不静默移交，也不静默丢弃。** 每个 scheme 首次出现时问一次，允许记住选择；拒绝或失败在同一工作面说明，并给出下一步。一个被访问的页面可以任意构造 `scheme://…`，不能无条件拿页面给定的参数启动本机应用。
  - 本应用的 `amux://` 对象链接同样经过上述网页来源询问与已记住的选择，获准后沿[统一对象打开边界](public-control.md#对象地址分享与方向)在内部打开；其他应用链接仍由系统移交。页内、重定向、frame、新窗口及 Browser 弹窗中的地址输入均保留准确原 URI、来源请求与同一授权结果，不因改走内部入口重新询问、绕过拒绝或加载空白网页。
  - 当前分类与交接入口见 [browser-app-link.ts](../../../apps/desktop/src/main/browser-app-link.ts) 的 `classifyBrowserTarget`、`appLinkOutcome`、`browserWindowOpenOutcome`；原 [BrowserViewManager](../../../apps/desktop/src/main/browser-view-manager.ts) 将页内导航与 `setWindowOpenHandler` 的结果投影回同一工作面。
  - `mailto:` 属于同一类，不单开一条通路。
  - **公共机制必须使用协议事实而不是站点身份。** 生产代码、公共测试、设计文档和帮助文字不得预设具体站点、产品名、厂商协议、按钮文案或登录流程；测试交接时使用合成 scheme 和通用触发形态，至少覆盖两个不同形态。真实站点只能作为黑盒输入，发现问题时修复它背后的 URL、frame、系统交接或用户确认机制。

- 内置 Browser 只能打开本机网络可达的地址。当前没有 SSH 转发或隧道，因此不能直接查看远端主机上的 dev server。远端 Agent 的 Runtime 管理沿[联邦 Runtime 与远端恢复边界](session-recovery.md#联邦-runtime-与远端恢复边界)；这项能力不提供 Browser 的端口转发，也不为 Browser 单开私有通路。

### 书签与链接文件

把一个链接存成文件、打开一个存着链接的文件，是一般浏览器的既有能力；AgentMux 使用系统与其他浏览器都认得的标准格式，不自造格式。存下来的文件必须能被本机文件管理器与其他浏览器直接打开；自造 JSON 会把这项能力锁在应用内部。

| 格式 | 结构 | 用途 |
| --- | --- | --- |
| `.webloc` | plist，键为 `URL`；读取时 XML 与二进制 plist 都支持 | macOS 上单条链接的首选保存格式；保存时写 XML plist |
| `.url` | `[InternetShortcut]` 段加 `URL=` 行，CRLF 换行 | 单条链接，只读支持 |
| Netscape bookmark HTML | 以 `<!DOCTYPE NETSCAPE-Bookmark-file-1>` 开头 | 整批导入导出，主流浏览器通用 |

- 收藏保存沿原 Workspace 标准文件写入通路。保存期间只有同一保存动作等待，地址提交、前后退、刷新、Viewport 及其它健康页面能力继续可用；动作附近表达保存中、已确认产物、失败或结果未知。结果归本次原页面与导航，迟到回执不冒充后来的页面已保存；未知写入保留准确候选文件与检查入口，不自动再次写入，另存副本必须明确表达新的保存意图。
- 整批导入导出属于 Profile 的书签库，与下文[《Profile 管理、环境与指纹编辑》](#profile-管理环境与指纹编辑)中的受管书签使用同一 owner。受管书签沿原 Profile 元数据保存目录、书签的稳定 ID、修订和原操作回执，支持准确 Profile／目录作用域的创建、编辑、移动和删除。整批导入导出使用上表的 Netscape bookmark HTML；导入仅追加，冲突分项回显并保全原数据，导出写入新文件且不覆盖已有文件。`.webloc`／`.url` 导入复用原链接读取 owner。
- 受管书签的完整地址（含查询和片段）在读、编辑、打开和导出间保全，错误、活动摘要和操作回执不回显原 URL 或本机来源／目标路径。打开须命中同 Profile 的准确 Browser，沿原 Browser 控制权、Agent 资格和应用链接确认；打开回执不代替站点加载成功。原操作未确认时保留原 ID，重启后仍可查阅未决意图，不自动重放。
- 在文件树、正文或 Terminal 中打开单个书签文件、查看其源码与二进制保全，归[《书签文件（.webloc / .url）》](files-and-git.md#书签文件webloc--url)。

### Agent 操作可见性与输入隔离

Agent 操作时，人能看见虚拟鼠标、旁边的头像与标题，以及颜色可配置的 Browser 边框内发光；显式接管前人不能干涉网页，但仍可查看轨迹并与操作者沟通。本节定义这些已确认要求，不证明当前源码或安装版已经满足。

- **控制权与动作进度分别表达。** 持续的身份与边界提示消费准确 Browser 的当前控制事实，瞬时指针与执行反馈只消费真实动作。Agent 已取得 Browser 控制后，等待、导航、页面重绘、单次程序完成或两次程序间隙均不自动转成人工控制；普通人工输入同样不接管。Browser 控制权独立于当前活动程序，转成人工控制须本人显式接管，不能由 Agent Session working、最后操作者、旧 operation 或页面文案推断。原生页面与被动镜像表达同一控制事实，镜像不取得输入权。显示偏好已启用且准确 Browser 已确认由 Agent 控制时，原生页面或镜像中的实际页面范围首次可见即应显示控制边界，不要求先切换工作面、重新选中或再次执行动作来激活；尚未取得页面画面或控制事实时保持其真实未确认状态，不补造边界事实。单次程序结束立即停止 busy 与执行循环，控制身份、边界和输入隔离仍沿原 owner 保留；等待、导航及结束后没有真实目标位置时不保留旧指针，也不编造坐标。已有 chrome 分别说明真实执行阶段与当前控制权，接管／交还入口始终沿原控制事实可达；交还不重放旧程序。边框显示偏好仍由本人选择，隐藏光效不隐藏身份／控制状态或接管入口，也不改变权限；装饰失败与输入隔离分别处理。只读目录与历史查询不取得控制权。
- **就近表达真实动作。** 原 Main 的 Browser／operation／step／navigation 事实沿[通用当前阶段与动作合同](agent-capabilities-and-messaging.md#agent-当前阶段与动作的可见表达)投影到同一操作者旁：snapshot／read 是观察，实际 js 是脚本，raw CDP 是协议／工具调用，click／type／scroll／navigation 分别表达，不从 opaque 调用名或页面文案猜更细动作。Browser 等待不代替 Agent 的思考证明，当前 Provider 只确认 working 时仍只说正在处理；原目标、非阻断、结束和失效继续沿本页既有合同。
- **虚拟鼠标携带真实身份。** 真实目标位置旁显示操作者头像、标题／名称和当前动作；身份沿原 AgentSession／Host 来源，未知不拼造名称，不把任务名当作者。页面内头像复用同一 Session 的既有头像外观，使用宿主核验的有限静态资源，不向网页提供外部资源地址或由网页另取身份资源。头像资源不可用时保留可辨的身份回落，不能阻断页面动作；迟到资源只修饰仍有效的原提示，不重建已消退、隐藏或导航失效的提示，不延长完成反馈。操作呈现偏好与实时模拟由 [Browser use 设置](settings-and-observation.md#browser-use-与-agent-操作呈现)持有，沿原 Settings owner 及同一公开配置能力发现、读取和修改；偏好变化不改变权限、输入资格或任务结果。具体材质、布局与动态效果只见[呈现合同](../presentation/browser-workface.md#browser-控制权提示)。
- **点击反馈取真实派发。** 目标处的一次局部波纹只消费原动作在准确目标上的实际派发确认，不由动作计划、显示指针或 hover 触发，也不把派发确认升级为网页业务结果或整项任务成功。波纹遵守同一提示的 owner、失效和有界预算，不等待动画结束后才交回原动作结果。
- **隔离守在原网页输入入口。** 准确 Browser 确认处于 Agent 控制期间，包括单次程序结束后的空闲阶段，普通人工指针事件（包括 hover）、点击、滚轮、触摸、键盘／IME、粘贴、拖放及网页菜单不能进入网页而改变页面；地址提交、前后退、刷新和修改执行 Viewport 同样不能绕过显式接管。地址草稿、复制链接和宿主自己的阅读、轨迹、消息、框选、切换工作面及接管／停止继续可用。隔离只约束本页，不关闭健康 Agent、不阻断其他 Browser 或工作面，不借透明 DOM 遮罩、页面自述或装饰光效认证输入归属。
- **接管不穿透。** 本人明确接管先在原 Browser／operation 上撤去后续动作派发资格，再交接网页输入；触发接管的那次手势不会同时点击网页。已派发动作与停止回执分别对账，未知副作用不自动重放；不能因为控制权已交人就把仍在途的动作说成已撤销。交还后从当前页重新观察，不续播旧动作。等待本人认证或检查点只开放原请求所需的人工通路，不以普通消息或任意网页点击代替批准。
- **输入隔离与呈现失败分开。** 头像、光效、轨迹或消息投影失败不改变已经确认的控制权；就近持续说明失败步骤和恢复动作，并保留显式接管。观测 unknown 不凭旧记录新建永久隔离，也不称已取得人工控制；沿原 owner 核对原操作与交接事实。当前隔离服务提示沿准确原生恢复或显式人工接管事实消退，不让旧操作的失败记录冒充当前故障；仍未确认的隔离和其他未解决提示继续可见，原操作回执与历史保留曾经失败的事实。外部共享标签若没有宿主输入隔离能力，明确其能力边界，不能把 AgentMux 内的装饰边框冒充对外部浏览器全部人工输入的隔离。
- **看轨迹不操作原页。** 阅读历史步骤、滚动轨迹或查看旧证据不导航、滚动、重放或点击当前网页。历史步骤明确来源 operation、导航与步骤身份，历史预览与 live page 可辨；没有保留的坐标或页面证据就明确缺失，不根据步骤标题编造鼠标路径。展开阅读面不能偷偷改变 Agent 的执行 Viewport：活动程序期间打开轨迹必须保留原执行 CSS Viewport，停靠阅读面若会改变执行尺寸，原程序结束前不停靠，改用不改变尺寸的阅读方式；宿主布局与实际几何变化仍沿原 Browser／Viewport owner 处理，不另建页面身份。

### Browser 协作者选择与交接

Browser 的协作者选择、创建 Agent、网页输入控制和程序执行分别表达。总开关／Profile 许可继续沿[原自动化判定](#破坏性-browser-操作的作用域与人工批准)；关联表示当前 Browser 的协作者及默认沟通对象，不另充当每 Agent 写权限白名单。程序的真实操作者可能与持久关联不同，两者都须可辨，不由一次程序、历史 operator 或展示位置静默替换已确认关联。

- 人工控制且明确没有关联时，按本次准确展示 Tab 的 Agent Region 与原 Core 身份提供已有协作者：没有候选保留创建；一个候选提供“交给该 Agent”；多个候选由本人明确选择。候选按 Host／AgentSession 去重，Tab 成员和排序仅影响选择呈现，不授予权限；不能按 working、标题、焦点或最近活跃推断资格或将未知原 Session 当死亡。需要恢复的原 Session 沿 Core 原身份恢复，不另开替代者。
- 已有准确关联时，主动作仍交还原协作者；本人可在人工控制状态明确选择另一个准确 Agent。可信宿主在同一次交接中核对原 Browser、navigation、控制 revision、被替换的原 Host／AgentSession，以及新目标的准确 Core Session／Run，再原子更新关联和输入控制。原协作者是否空闲、停止或本次可观测不作为替换条件，不伪造退休、不先清空关联，也不删除或停止它的 Session。目标或原条件变化仅拒绝这次交接并保留原页面、双方 Agent 和可达重选入口。
- 交给已有 Agent 只改变准确关联和网页输入控制，不创建 Region／进程、不切换工作面、不自动投递任务或续播旧程序。用户可另行给该协作者发场景消息；已打开草稿继续固定原目标、Run 和捕获来源，沿[场景消息](#browser-场景消息与框选沟通)处理。
- 程序在既有自动化许可下由另一个 caller 执行时，真实 operation.operator 表达本次操作者，已有准确关联保留；两者不一致时就近说明。首次程序可以从“明确无关联”建立已确认 caller 的关联；未知关联或 caller 观察缺口不据此覆盖原事实，发布持续服务说明并保留健康程序通路。只读任务指令不是只读权限，不能以模板或标签限制或宣称已限制 JS／CDP 等操作。
- 关联身份未知时就近说明缺失事实和原连接／关联查验入口，保留原页面、输入草稿、阅读及已具备前提的接管等能力，不显示成无人关联。本人已持有网页输入时，可以明确选择一个准确的新协作者；这次新交接以“原关联仍未知”及原 navigation／revision 为条件，并核实新目标 Session／Run，不猜原人、不自动清理或新建。旧草稿、operation 和未确认的原请求保留各自来源，不能以该选择改投。原关联已确认而本次 Core 状态观察不可用时，保留原关联与既有交还能力，并说明尚未确认的观察和恢复动作；不将观察失败冒作退休或无效目标。新目标仍须本次准确 Session／Run 确认。

### 从 Browser 创建 Agent

- 人工控制的 Browser 明确没有关联 Agent 时，在[协作者选择](#browser-协作者选择与交接)中独立保留“在右侧创建 Agent”。默认一次点击在该 Browser 展示所在的同一 Tab 中、相邻右侧新建 Region 并创建一个 Agent；可明确选择其他分割方向。Survey 从准确网页进入时，创建后显示该准确原 Tab 内的 Browser／新 Agent 分栏，并能聚焦新 Agent；不扩大到来源 Zone 的其他 Tab，也不另建 Tab／Zone 掩盖分栏。创建前能查看实际 Executor／执行 Host 与目录，并可附加本次用户任务；缺省仍按原初始观察指令。落点选择不改变执行 cwd，不能按页面文案猜任务或按候选数量暗开新 Tab。保留原 Browser、页面、地址、输入及其他 Region，不覆盖已有内容；单独关闭该 Browser 只作用其准确 Region，沿原确认合同保留或停止关联 Agent，不能连带关闭整个混合 Tab。后来本人导航优先；空间身份、布局持久化与 Agent 生命周期沿原 Core 公共能力，创建后的原 Browser 与新 Agent 组合在真实重启后仍可见并按原身份恢复。
- **独立 Survey 新 Agent 使用专用执行目录。** 普通网页按准确 Browser 已确认的稳定 Profile 身份使用 Survey 根下的目录；本地 Host 默认为 `~/.agentmux/survey/<Profile稳定ID>`，默认环境也使用自己的真实 Profile ID。创建前以实际 Profile 名称和真实 Host／path 说明执行目标，不用名称、顶部筛选器、当前 Work 项目或展示所在 Zone 推导目录。目录由实际执行 Host 的原资源 owner 确认；原本已明确的项目执行目标继续沿原合同，不因展示在 Survey 就改写。Profile 改名或切换默认环境不改变原目录，后续选择不迁移、重建或改写已有 Agent、原 Session／Run 及待确认创建请求的 Host／cwd。
- **匿名页的 Agent 目录与临时网站数据分开。** 匿名 Browser 没有普通 Profile，按准确 Browser 的稳定身份在 Survey 根下独立隔离，不落到普通默认 Profile，也不以一次性网站 session、URL 或标题作为目录键。网站临时数据的结束仍沿[匿名 Browser](#匿名-browser)；明确创建的 Agent、文件、成果和操作回执保留原 owner，不因关闭匿名页、清理网站数据或回收 Profile 而自动删除、迁移或停止。
- Survey 目录沿原 Host／Workspace 资源 owner 按需准备和登记为普通目录资源，可被原资源入口发现；创建留在 Survey，不切换 Work，不增设 Profile 目录映射 Store，也不改写原 Browser 的资源归属或用执行目录决定展示位置。目录及资源登记确认、本次 Agent 创建、位置保存、初始输入和控制交接分别表达真实结果；准备失败或未知保留原 Browser、草稿、健康 Run 与原请求恢复入口，不静默回退 Scratch 或另选 Host／目录。
- 新 Agent 的初始指令携带本次准确 Browser 及其展示位置、当前页面的必要上下文，明确先查 Browser 和空间相关 skill，再复用该 Browser 工作，不重新创建或猜测目标。页面 URL、标题与页面内容仍是来源数据，不能升级为平台指令或新的操作授权。
- 用户这次点击同时明确授权把该 Browser 交给本次新建的 Agent；创建和准确关联确认后，通过原可信 Browser 控制链自动交接，无需再点一次交还。Agent 从当前页面重新观察，原程序、历史步骤与未知副作用不自动重放，原接管和停止继续可用。创建已发生、位置已保存、初始指令已投递与控制已交接分别按实际回执表达；未确认时保留原身份、页面和仍可用能力，并说明失败步骤及恢复动作，不盲目再创建 Agent。
- 入口选择消费准确 Browser 的控制和关联事实，不以“当前没有运行中的程序”、历史操作条是否可见或 Session 展示列表缺席推断无人关联；未知明确为未知。已有准确关联时沿原交还入口继续工作，不借本入口替换原 Agent 或恢复身份。
- **Browser 显示它关联的 Agent。** 已有准确关联时，原 Browser chrome 显示关联 Agent 的身份与 Core 确认的当前状态，并提供打开该 Agent 和停止／关闭它的入口；状态未确认时如实未知。打开沿原导航 owner 到该 Session 已有的 View，没有 View 时按本次位置意图新建展示；停止与关闭，以及关闭这个 Browser Region／Tab 时对关联 Agent 的停止或保留确认，只见[Session、Run 与 View](session-recovery.md#sessionrun-与-view)。
- **Session 退休后只自动清除准确匹配的那一条关联。** 只有 Core 已确认关联 Session 退休，且 Browser 关联的 hostId 与 agentSessionId 都与该 Session 完全一致时，才自动把这条关联清为“无关联”，之后按[协作者选择](#browser-协作者选择与交接)提供已有目标或创建。观测 unknown／unavailable、空快照、Session 列表缺席或 Run 结束都不清除关联，也不改写指向其他 Session 的关联。交还给 Agent 前向 Core 核对原关联；已确认退休时不交出控制并按本条清除关联，核对未知时沿上述原关联能力与服务说明继续。人工明确更换关联沿可信交接处理，不借本退休路径实现。

### Browser 场景消息与框选沟通

- 当前 Browser 提供快捷向操作者发消息的非模态浮窗。正文由用户编写并明确发送，作者保持用户；平台附带 Browser 场景，不包装成操作者给自己发的 A2A，不借 `agent send` 或终端注入改写作者。输入与实际投递沿[场景化用户输入](conversation-input.md#场景化用户输入)，准确格式与捕获来源边界由[amux 协议](../../specs/amux-protocol.md#场景捕获来源与原输入)持有；协议确认不代签浮窗、框选或安装交付。
- 新草稿按准确 Browser 当前可信 Agent 关联中的 Host／AgentSession，结合该 Session 的实际 `AgentSessionControl`，确认并固定接收者；没有当前或历史 operation 不影响已确认关联的沟通。operation 的 operator、历史步骤、显示名称与 Provider 图标只作场景上下文，不授予投递身份，也不把旧操作者当作当前接收者。关联或实际 SessionControl 未确认时，明确本次接收目标未知及原关联／Session 的查验恢复动作，保留草稿、原页面、健康 Agent 与既有输入能力，不猜另一 Host、Agent 或 Run。
- 旧草稿保留打开时确认的原接收 Host／AgentSession、Run 条件、消息身份与来源 Browser；页面 URL、导航、operation 和步骤带明确的捕获时刻。Agent 继续执行、Run 或关联改变、导航及历史步骤变化都不覆盖草稿、不暗改原目标／Run、不自动重发；捕获来源与后来发送时的已观察状态分别表达，缺失事实保持未知。本人显式建立新意见或处理原未准入输入，继续沿[场景化用户输入](conversation-input.md#场景化用户输入)及原队列的目标、条件与回执合同，不另造 Browser 投递通路。
- 用户可以就当前步骤、某条历史步骤、页面元素或框选区域写消息。框选属于宿主观察工具，不把鼠标拖动／选择事件送进 Agent 正在操作的网页。选区绑定实际捕获帧、原 Browser／navigation、viewport 与坐标空间；页面继续运行时仍标明这是那一帧的意见，不将旧像素当新 DOM ref。实时元素上下文继续沿 Main 净化 owner，截图、裁剪与编号批注复用[既有截图工具](#browser-页面截图与标记)；像素选区不推断 selector 或元素身份。
- 捕获、发送前都能查看并移除附带上下文；只发送本人选择的必要信息。网页 title、URL、文本与截图属于页面来源数据，不升级为平台指令或授权；敏感内容沿原输入与截图边界处理。截图不是默认附件，框选或附图由本人明确选择；无法取得图像时仍可仅发文字，不关闭健康 Browser 或消息能力。
- 打开、关闭浮窗、打字、读轨迹、框选与发送均不自动接管、停止 Browser 程序或批准权限。忙碌时沿已有 Provider／Core 能力决定排队或显式即时输入，不能承诺一发即改变当前动作；需要立即阻止网页副作用时使用明确接管／停止入口。已入队、实际提交、投递确认和 Agent 是否采用意见分别呈现，未知保留原输入身份，不自动重发。

### 匿名 Browser

- Browser 在创建时明确采用 `normal` 或 `private` 模式，Main 持有准确模式与网站数据上下文；创建后不在两种模式间切换。普通 Profile 继续沿原持久 owner 使用和切换，不被匿名创建、更名、清空或替换；匿名 Browser 不使用普通 Profile。失败或未知不回退普通 Profile，也不删除原页面、草稿或健康 Run。
- 每个匿名 Browser 有独立的一次性网站 session，不与普通或其他匿名 Browser 共享 Cookie、网站存储及缓存；其原生子窗口继承所属 Browser 的匿名 session。网站数据不持久化；模式不授予新的自动化、认证、应用交接或文件权限，不承诺隐藏 IP、网络身份或网站指纹。
- 隐藏或只释放原生页面资源不结束匿名 session；重复恢复仍指向原 Browser 和同次 session。本人明确关闭该 Browser 才结束其 session，之后新建不继承旧状态。关闭清理只作用准确匿名 owner 及其子窗口，不能扩大到普通 Profile 或其他匿名页；清理结果未知须如实说明，不复用可能遗留数据的 session。
- 匿名导航与人工地址／搜索输入不持久记录，不读取普通 Profile 的历史建议。普通重启保留原 Tab、Region、混合内容及分割布局，匿名位置恢复为新的匿名空白页并明确临时数据已结束；不保存或恢复匿名访问 URL、标题、favicon、网页历史或临时 session 身份。正常页面的原 URL／Profile 恢复保持。
- Survey 创建菜单和 Browser 更多菜单提供明确的新匿名页动作，沿原准确资源和放置链创建独立 Browser，不改变当前页的模式或 Profile，不要求先关闭原页。公开 `browser.open` 使用同一模式合同，CLI 的 `--private` 明确创建匿名页；返回与目标发现表达必要的非敏感模式，不暴露 partition、Cookie 或本机凭据路径。未指定仍按正常模式创建，不增加默认匿名偏好。
- 用户明确保存的文件、书签、下载及 Agent 操作回执按其原合同保留，匿名不等于磁盘零痕迹；入口说明实际网站数据生命周期和这些留存边界，不自动抹除成果或权威操作身份。网站临时数据结束与工作面身份保全分别验证，不以清空 Profile、删除 Region 或空截图代签隔离。

### Browser 页面截图与标记

Browser 原页面采图、同图编辑、标注／裁剪／遮盖、原稿保存重开、PNG／context 交付及取消与性能要求统一见[《截图与录制：共享图片编辑与标注》](capture-and-recording.md#共享图片编辑与标注)。Browser 的导航、控制、来源资格与工作面身份继续由本页所属合同持有；此入口不复制图像编辑事实。

### Browser 空白起始页

- **起始页通过通用配置接入。** Browser 空白页的主标题、副标题、可选图标、背景图、历史展示开关与首屏条数、交互背景效果由宿主提供的起始页配置表达，不从 Survey 名称、展示归属或控制面开合推导外观。图标未设置即不显示，不暗中补默认品牌；背景图未设置时沿原主题。配置只决定空白起点的呈现，不改变 Browser／Tab／Region 身份、Profile、资源 Workspace、控制权、执行或恢复；Survey 的场景标题只见[《Survey、临时 Zone 工作面与知识入口》](knowledge-workflows.md#survey临时-zone-工作面与知识入口)。
- **顶部与中央输入沿同一导航能力。** Browser 为空白页时，顶部地址／搜索框仍可直接编辑，不被静态页面标题替代；起始页可同时保留中央输入。两处入口操作同一个 Browser，消费同一地址草稿、提交与历史 owner，并共享下述[地址／搜索输入历史与基础编辑](#browser-地址搜索输入历史与基础编辑)的焦点、选区、IME 与失败合同；切换入口不丢草稿，不重复提交或记录，不因同时呈现而争抢焦点。离开空白页后起始页让位于真实网页，顶部输入继续可达，不新建 Browser 或导航 owner。
- **配置沿原 Browser 设置 owner。** 起始页提供就近的自定义入口，定位原设置中的起始页配置；打开和关闭设置保留原 Browser、输入草稿和工作面。主副标题、图标／背景资源、历史显隐与首屏条数、交互效果从同一设置事实读取和更改，不另存起始页私有偏好。用户可选择本地图像或图片 URL、替换与清除背景，未保存的预览不冒充已应用；保存、并发编辑与失败保留沿[设置合同](settings-and-observation.md#设置页的信息架构)。GUI 与公开 Settings 查询及设置入口同源，合法值由原配置 owner 检查；新增字段的发现、持久化和真实消费遵守[设置贡献约定](../../settings-module-contributions.md)与[公共能力贡献约定](../../guides/public-capability-contributions.md)。配置变化仅影响相关宿主的起始页，不导航、创建、关闭或重建已打开页面，也不改原草稿与选择。
- **历史相册是原提交记录的可选视图。** 开关开启时展示当前实际 Workspace／Profile 的最近地址与搜索；范围、隐私、去重、持久化和失败沿原 Main 输入历史 owner，不称全量网页访问历史，不将 Agent／CLI 导航或未提交草稿补成记录。首屏条数是可配置的呈现偏好，只决定初始展示多少条已有记录，不截断或删除持久历史、不改变其保存预算；实际条目不足时按真实数量呈现。有更多真实记录时可继续展开查看，不用固定少量卡片冒充当前全部记录，也不为填满布局生成条目。关闭时不读取该视图所需历史，也不删除存量记录；输入建议仍沿原入口按需可用。仅展示卡片不导航、启动或恢复页面；本人明确选择后沿原 Browser 导航处理准确提交文本，不另建图库、历史存储或截图生命周期。
- **交互装饰是可关闭的呈现。** 起始页可对本页真实指针移动给出轻量视觉反馈，应用自带装饰在输入停止后收束为静态，不以持续循环索取注意或保活。关闭效果、减少动态效果、页面隐藏或离开起始页时停止相应动态更新；静态起点、两处地址输入和历史导航继续可用。指针位置仅作用当前可见起始页，不驱动网页、改变焦点或控制权，不订阅无关 Session、Browser 或工作面；已有自定义背景与实际内容仍按原设置和页面 owner 呈现。
- **历史预览沿原页面外观 owner。** 原范围内存在与历史条目准确 URL 对应的真实页面预览时，可复用其图像、已观察标题与采集时间帮助辨认；预览明确是上次查看的外观，不冒充当前页面、加载或控制状态。不凭同域名、标题相似或排列位置借用其他页面的图，不跨 Workspace／Profile 或借匿名页面补图；缺少准确来源或图像不可用时保留原文本卡片。读取既有预览不启动、导航、恢复或重新截图页面，生命周期、删除与隐私继续由原 owner 持有。
- **辅助内容失败保留起步能力。** 图标、背景或历史读取未确认，只影响对应呈现；历史空集合与读取失败可辨，失败在起始页就近持续说明并提供重试，不能冒称没有历史。中央输入、正常导航、原工作面与健康 Run 保持可用；晚到结果不得覆盖后来的配置、Profile、页面、草稿或焦点。读取与呈现只随当前相关消费者增长，不扫描或唤醒无关 Session／Browser。

视觉、卡片密度与背景可读性唯一见[《Browser 空白起始页》](../presentation/browser-workface.md#browser-空白起始页)。

### 网页上下文菜单

- 人工右键按原网页和 frame 的原生命中显示相关动作。命中链接可复制链接地址，命中图片可复制图片地址，链接内的图片同时保留两项。普通页面可复制当前页面地址。使用命中的实际地址写入系统剪贴板，保留查询参数与片段。文本编辑继续沿本页的[基础编辑合同](#browser-地址搜索输入历史与基础编辑)。
- 网页链接提供就地、新 Tab、分屏、新窗口和匿名打开。右键明确选择 Profile 时，在该登录环境中打开命中的链接，沿 [Profile 与 Survey](knowledge-workflows.md#profile-与-survey) 登记新页引用。原页面、原 Profile 和 Agent 关联保持。匿名源的普通新页面沿原匿名环境；显式匿名打开才创建新的匿名环境。非网页协议仍由原导航／应用链接合同判断。选择搜索文字时沿地址框的搜索规则，新页面携带本次搜索，密码字段的内容不进入搜索。剪切、复制、粘贴、撤销、重做、全选、查词与拼写动作按原文本和平台能力提供。
- 图片及音视频按原生事实提供打开、保存及复制地址；图片像素和视频帧使用原生获取路径。下载使用发起时的原页面和原 Session。普通网页提供后退、前进、重新加载、保存及打印。普通区域命中嵌入文档时，可重新加载该 frame 或把其地址作为新页面打开。同地址的嵌入文档也有独立 frame 身份；重新加载仅作用此 frame，保留宿主原输入。检查元素落到本次命中的坐标。导航和保存都沿原 Browser owner，宿主菜单不执行网页提供的脚本 URL。
- 网页取消默认 `contextmenu` 时，由网页处理该次右键。宿主菜单来自准确的原页面。导航、隐藏、切换输入 owner 或失去原 frame 后，过期菜单不能作用到另一个目标。复制失败沿原 Browser 的提示说明，用户可对同一链接重新打开菜单。

### Browser 地址／搜索输入历史与基础编辑

- 地址／搜索框按提交内容打开：完整网址、可识别的裸域名与本地开发地址沿原导航；其余普通文字（包括单词、中文和数字）直接用当前默认搜索引擎搜索，保留原查询含义并正确编码。空输入、本地文件和明确协议继续沿原边界处理，不用网络探测猜输入，也不把明确协议的失败改成搜索。Main 与同一输入的 Preview 消费共同判定；输入历史仍记录人的原文，搜索不改变焦点、Profile 或原 Browser 身份。

- **建议由人工意图展开。** 打开、恢复 Survey 或程序自动聚焦地址／搜索框时，只准备输入，不自动读取或展开历史。人工点击、编辑文本或按上下方向键时，在当前输入附近展开真实范围的有界建议；空输入及未编辑地址可显示最近提交，人工编辑后按原查询过滤。建议复用下述 Main 历史 owner，不创建导航、启动 Agent、读剪贴板或另造记录。候选补全保留人的输入前缀，以可替换的选中后缀表达建议；未明确采用前不导航或记录为提交，继续编辑、撤回、光标／选区变化和 IME 不被补全反复覆盖。当前输入的直接打开／搜索与召回候选可辨，最终采用仍沿同一地址判定和原提交 owner。Enter 明确采用、Escape 关闭与指针选择可达，IME 合成不提交；关闭或目标／Profile 改变后旧结果不重开浮层、不覆盖新稿。历史读取失败保原输入和正常导航，沿原服务窗说明。
- **候选信息与删除沿原来源。** 地址、搜索与历史来源可辨；只有实际来源已确认的标题、完整地址与 favicon 才用于辅助辨认，已观察过的同一准确地址的标题与 favicon 随原人工历史记录保留，切页、关闭该网页或普通重启后仍可辅助辨认；缺少元数据时保留原提交文本和准确类型，不按相似域名补成同一页面。页面观察只装饰原 Workspace／Profile 已存在的人工记录，不新增访问历史；匿名页面不参与，删除或清空后的迟到观察不恢复记录。装饰保存不阻塞原导航，不因辅助元数据预算挤掉原提交记录。 升级前的既有记录在人工展开建议时，同样复用原范围内已保存的准确页面信息，无需逐条重访；未恢复网页的已确认历史信息也可辅助辨认，不为补信息创建、恢复或联网访问页面。页面当前 favicon 只属于其准确地址，back／forward 中的真实标题分别属于各自完整地址；缺少来源仍保留原输入与类型，不按域名借图。单条删除只消费本条记录所属原历史范围和原 owner 回执，不误提交导航、清空其他条目或删除书签；失败和未知保留原记录、草稿与重试入口，不以隐藏行冒成功。建议呈现不自行引入联网补全、访问采集或跨范围历史。
- 人工点击地址／搜索框必须能聚焦、编辑、移动光标与选择文字；原生内容区域、历史列表及其他浮层不得截走不属于自己的指针或键盘输入，也不能因历史或观察流程失败而封闭仍可用的输入。建议内的清空、删除与重试要保持一次指针按下至松开的原锚点和控件命中；重试后能继续编辑原草稿，迟到结果不夺回后来焦点。原页面、工作面和健康 Run 保留，草稿与编辑归属沿以下约束。
- Browser 地址／搜索输入框记录输入历史，并支持复制、粘贴与剪切。顶部地址／搜索框及 Survey／Launcher 的同一人工入口共享输入行为；只记录人显式提交的非空地址与搜索词，不采集未提交草稿、网页密码／表单或 Agent／CLI／脚本导航，不主动读取剪贴板作为历史来源；人粘贴后显式提交的地址／搜索按同一输入处理。历史按实际 Workspace 与 Profile 隔离，有界、去重、最近优先，保留搜索词与 URL query／fragment 的原意；带 URL userinfo 的输入不持久化，不猜任意文本是否秘密。用户能删除单条或清空当前范围，普通进程重启后仍可召回；历史与网页 back／forward 和 Agent 操作记录分开，未知归属不借默认 Profile 混库。读取／保存失败就近持续说明该能力降级，原输入、页面、正常导航与健康 Run 继续可用。
- 输入建议中的历史按需从原输入框就地展开；键盘上下选择、明确提交、Escape 收回与鼠标选择可用，IME 组合输入不误提交。未选定历史时保留当前草稿与选区；新的编辑、Workspace／Profile 或请求归属变化后，晚到历史与导航投影不能覆盖草稿或夺回焦点。列表不改变原 Browser／Tab／Region／分割生命周期，不因浮层隐藏整页；紧凑呈现只见密度 SSOT[《Browser RSI 操作表面》](../presentation/browser-workface.md#browser-rsi-操作表面)。
- 地址／搜索框和网页基础文本编辑支持平台原生复制、粘贴、剪切及原选择语义；快捷键与按需菜单复用成熟编辑能力，不建立另一份剪贴板或全局快捷键通道。可编辑、只读、空选区、disabled、密码与 contenteditable 沿真实平台能力区分，正常密码编辑不额外受限，不读取或保存秘密／选区／剪贴板内容到历史或日志。人工菜单只编辑原 window／WebContents／frame 与原局部输入目标；导航、销毁、换页或人切到另一个输入后，旧菜单不作用新目标，也不夺回焦点。普通 input、textarea、contenteditable 与嵌入 frame 的基础编辑保持，现 Region 菜单不能截走输入的原生编辑入口；不以脚本赋值或合成 ClipboardEvent 冒充原生编辑成功。

- 网页内容中的复制按钮可沿标准 Clipboard API 写入系统剪贴板；合法写入不被 WebAuthn 等专项能力的 Session 策略误拒绝。通用 Session 权限由同一 owner 组合，专项模块只解释自身能力。写入与读取分别裁决，修复复制不授予网页读取剪贴板或其他权限；原 Chromium 的安全上下文、文档焦点、用户激活及 frame 权限策略继续生效。权限查询通过、页面按钮响应与系统实际写入是不同结果，成功以实际写入确认，不能将声明了 API 或 query granted 视为复制完成。

### Browser 页内查找与网页焦点下的浏览器键位

- **网页获得焦点时，浏览器保留键仍归原 Browser。** 焦点在网页或该 Browser 自身的工具栏内时，⌘L 聚焦该 Browser 的地址／搜索框并全选，⌘R 重新加载该页面，⌘F 打开该页面的页内查找；其他平台用 Ctrl 对应键。Main 只在原生按键入口认这几个明确组合并交给同一 Browser 的宿主动作，其余按键照常交给网页。输入法组字中的按键不拦截；Agent 控制期间沿原输入隔离，人需先显式接管，这些键不能绕过隔离改变页面。键位只作用于准确的那个 Browser，不重载整个应用窗口、不切换其他工作面，也不另建全局快捷键通道。
- **页内查找使用 Chromium 原生查找。** 输入即在当前文档查找，显示当前序号与总匹配数；Enter／Shift+Enter 跳到下一个／上一个，Escape 或关闭按钮结束查找并清除高亮，焦点回到网页。查找属于准确 Browser 的当前文档：导航后旧结果失效，保留查询文字并在新文档上重新查找；迟到的旧结果不覆盖新查询。查找不进入地址历史、操作记录或日志；Agent 控制期间查找与网页输入同受隔离约束，说明需先接管。没有匹配、页面不可用或查找失败时就近说明，原页面、地址草稿与健康 Run 保持可用。

### Browser 页面缩放

- **缩放按站点与原 Profile 记住。** 焦点在网页，或在该 Browser 自身的工具栏、查找条内时，⌘= 与 ⌘- 及 View 菜单的 Zoom In／Zoom Out 按常见浏览器的预设档位放大或缩小该页面，⌘0 与 Actual Size 回到本产品默认的 90%；其他平台用 Ctrl 对应键。焦点在其他位置时，这些键与菜单项仍缩放应用界面。缩放属于该页面的站点与原 Profile：同一 Profile 中同站点的其他页面一起改变，其他站点、其他 Profile 与匿名页面不受影响；导航、Reload、闲置释放后的恢复与普通重启后保持，匿名页面只在原临时会话内保留。缩放沿 Chromium 原 Profile 的站点缩放保存，不另建存储；页面加载不把人选择的缩放打回默认，切换 Profile 后沿目标 Profile 自己的站点缩放。
- **缩放只改变呈现。** 缩放与调整 Pane 尺寸同属人的阅读呈现：不重新加载页面，不改变地址、历史、表单、焦点或 Profile；固定 Viewport 预设、原生投影与输入对位按新缩放重算。Agent 控制期间人仍可缩放；Agent 的读取与操作只消费已应用的缩放，不改变或重置它，进行中的坐标动作遇到几何变化时沿既有核对如实失败、可重试。原生页面尚未创建或已释放时缩放未知，不显示、不猜默认。

### 原生网页子窗口

- **新页按来源场景放置。** Browser 设置分别提供 Space、Focus、Survey 三项网页新开方式，均可选择新窗口、新 Tab 或新 Region；未配置时 Space／Focus 为新 Region，Survey 为新 Tab，沿唯一配置 owner 保存，默认读取不回填写盘。此偏好只影响网页自身请求新页面的链接／修饰点击、`window.open`、命名窗口与表单目标；普通同页导航、明确的本次目的地及 Agent 指定的空间位置保持原语义。既有 Focus 消息与终端的链接选择器独立，不将两种入口叠成优先级或另建配置 owner。来源场景来自原 Browser 的准确呈现绑定，不借当前全局焦点、标题、URL、资源目录或 Scratch 身份猜测。新 Region 挂在原 Tab 的准确来源 Region 旁；新 Tab 留在原场景并保原资源／Profile；新窗口展示同一个原生子页面。网页请求只授权创建／放置其新页，不授权抢系统焦点或覆盖后来选择；显式本次导航仍沿原焦点合同。原生子页确认创建后，首次呈现不等待空间或 Survey 收藏偏好写盘；保存沿原 owner 继续，未确认如实说明，不重放请求。独立窗口自身必需的原意图持久确认仍保留。
- **独立窗口返回原场景。** 显式返回沿原窗口记录的准确导航上下文和原 Tab／Region，Survey 返回原 Survey，Focus 返回原 Focus，Space 返回原 Space；不因页面使用 Scratch 资源就跳到 Space，不改写无关 Work 选择。返回只迁回同一工作面，保 Browser/WebContents、原输入、草稿、历史与 Profile；显式查看 Space／查看来源是可辨的另一动作。来源上下文由原呈现 owner 提供并随原窗口保全，与窗口目标身份分开；缺失或未知不冒原 Space，也不拿走健康窗口／页面。明确返回时的准确目标变化或未确认就近说明，保原操作及恢复入口；自动恢复、原窗口观测失败及迟到回执不抢后来导航。

- **同一 Browser owner 与公共目标。** 网页通过 `window.open`、链接或表单目标打开的子页面，进入与普通页面相同的 Browser 页面、控制与生命周期机制；各子页面具有准确的 Browser／navigation 身份，原 Workspace、Profile／匿名会话及来源关系按实际事实保留，不能借父页面 ID 冒充子页面。公共 `browser.targets` 可发现准确子页面，`browser.run`、历史、停止及其他标准公开能力直接消费同一 owner、授权与操作回执，不要求 Agent 另用窗口探测、标题匹配、同源脚本或 raw CDP 绕过正常目标寻址。能力、身份或观察未确认时如实表达，保留原页面、已有可用能力与恢复入口。
- **同一完整交互。** 子窗口复用正式 BrowserPane 与同一 Browser 的导航、工具、Agent 关联、动作反馈、输入隔离、接管／交还、操作轨迹及场景消息能力；具体资格与行为沿本页各 owning 章节，不因窗口宿主不同形成专属能力、控制状态、导航或轨迹副本。地址编辑、草稿、IME、输入历史与原生剪贴语义沿[原地址输入合同](#browser-地址搜索输入历史与基础编辑)，呈现沿[子窗口的统一 Browser 工作面](../presentation/browser-workface.md#原生网页子窗口导航)。
- **保留原网页对象与创建语义。** 同一 Browser owner 承接原 WebContents，导航、地址、历史栈、加载及可用动作始终消费该原生页面的准确事实；保留原网站 Session、Profile／匿名会话、`opener`／`noopener`、命名窗口复用、表单目标、POST／referrer 策略和 `window.close()`。不能以重建 WebContents、重开 Browser 或重放 URL 替代原创建／导航请求；原页面、未提交输入与其他工作面保持。
- Command／Control 点击、中键点击与网页自身的新窗口请求均保持可用，不因有无原 guest 或创建方式不同导致应用退出、漏接公共目标或留下未导航的空页。原请求的发起 frame、请求体、安全边界及原请求／回执身份随该次导航保留；来源未确认或导航效果未知时就近说明，不自动补发 URL、重复创建窗口或影响原页面、工作面与健康 Run。
- **原触发位置可查、可返回。** 子窗口保留原触发 Browser 与当时已确认的 Tab／Region、展示绑定引用，并提供查看准确来源和一键切回该位置的入口。位置与导航沿 Core 的[空间身份及全部展示绑定](spaces-and-layout.md#统一概念与空间寻址)查询；原对象移动后按原身份解析其当前位置，不用标题、当前焦点、Agent 的执行 cwd 或新出现页面猜来源。原位置已关闭、暂不可用或存在未解的多个展示候选时如实说明，保留原引用与子页面，不自动重建来源或选择首项；只有准确目标确认后才导航，切回不重新打开或重放原页面、不改变控制权，也不丢原输入与草稿。
- **来源未知不阻断子页面可见。** 网页已请求独立子窗口时，为同一原生页面建立普通 Tab 并复用正式窗口；新 Tab 放在哪个 Group 是 Client 的布局选择，不是触发来源事实。Group 按以下顺序选择，取第一个可用者：
  1. 已准确解析的来源 Group；
  2. 原记录中仍有效的 Group；
  3. 当前来源候选中按布局读序的首个有效 Group；
  4. 实际包含该请求 Workspace 内容的 Group；
  5. 其余已存在的有效 Group。

  跨展示工作区时按稳定身份顺序、同一工作区内按布局读序选择，不读取人工焦点。Workspace 绑定只取原请求、实际来源或现存 Tab 的真实身份，不补造空值或虚假身份。这一选择不补写来源位置，不消除来源导航中的未知或多候选，也不改变主工作面的当前选择。只有完全没有可用的现存 Group 与真实 Workspace 绑定时，才保留原页面和待投影请求，并以持续服务提示说明恢复工作区布局后将自动显示同一页面；布局恢复后直接挂接原对象，不要求来源重新唯一，也不重放链接。
- 原生独立窗口可以承载同一完整 Browser 工作面；网页自动创建子窗口时只展示同一原生页面，保留人的系统窗口与键盘输入焦点，沿[Browser 工作面](#browser-工作面-1)的原焦点合同。窗口尺寸、原生关闭及展示位置由宿主处理，不另立简化导航或控制合同。网页新开目的地只沿本节的场景偏好与原请求决定，不由独立窗口的宿主身份反推来源场景。其他 App 的系统 HTTP(S) 入口仍沿[系统网页进入原 Survey](knowledge-workflows.md#survey临时-zone-工作面与知识入口)及原 Settings 的系统默认选择合同，是否设为默认由本人决定。

### Browser 通用认证与 passkey 能力

用户实际通过系统平台认证器（如 Touch ID 与系统钥匙串）或密码管理器使用 passkey；认证接入参照成熟浏览器的宿主机制。页面报告支持不完整或一直等待浏览器交互时，Browser 必须区分网页等待、宿主能力尚未接入、系统／提供方不可用与用户尚未授权，不能用页面文案猜测认证结局，也不能把尚未证实的宿主或签名缺口当成某次失败的确定原因。

- 页面暴露 WebAuthn 不等于宿主凭据来源可用；来源尚未接入时须在当前 Browser 就近如实说明可用范围与下一步，不能只让用户无限等待，也不能把源码已合入当成运行中的应用已生效。
- 认证归实际发起请求的 Browser、profile、frame、页面来源和本次请求；不能从当前焦点或另一个工作面猜归属。只有可信来源和相应系统能力可进入授权，导航、关闭或请求失效后不留下无法结束的选择等待，也不能把旧请求的选择交给新页面。暂时失焦、隐藏或最小化只影响账户选择的展示，不使仍有效的原请求失效；需要人选时就近说明等待本人返回，原 Browser 可见且原窗口获得焦点后才能展示，不主动激活窗口、切 Tab 或抢焦点。超时和真实失效仍结束一次。同 Browser 新请求结束旧请求，同窗口另一 Browser 的新请求不能覆盖已展示选择，可局部取消新请求并说明。发起 frame、祖先跨文档导航或 frame 被拆除后，原请求即失效并收尾。
- 设备接入按通用安全来源和 FIDO 协议裁决：仅 HTTPS 或可信 HTTP loopback 来源进入受限 HID 检查，实际设备必须具有 FIDO usage page；非 FIDO、非可信来源以及仅借 loopback 主机名伪装的其他 scheme 保持拒绝。多个可用设备由本人选择，不按列表首项猜设备；受限设备接线不代表系统 Touch ID 或既有钥匙串凭据已可用。
- 用户自己的设备绑定平台 key 与既有系统／密码管理器 key 是不同来源；可用性、实际创建或使用结果分别说明。页面能力探测、账户面出现、本地平台认证成功都不能冒充同步、跨设备或其他应用的既有 key 已可用；未知保持未知。
- 任意页面的平台凭据能力须由实际系统宿主和合法签名／授权条件证明；声明权限、应用自己的平台 key 或仅覆盖个别来源的关联条件不能冒通用浏览器能力。宿主可实现性或外部授权尚未确认就保持未接入／未验收范围，不能对用户承诺已可用。
- 系统认证和多账户选择必须由用户本人明确完成；选择、取消、明确拒绝与能力不可用各自有结果。原认证器仅返回一个合法候选账户时继续同一原请求，不额外制造一次账户批准；这不替代认证器或系统的用户验证与授权。AI 不在多个账户间代选或代替系统授权，不向 Agent／CLI 提供账户选择 API，不自动重试凭据拒绝，不把认证秘密、PIN、生物特征或凭据私密材料写入 trace、录制或可复用资产。
- 能力未配置、签名身份不匹配、当前来源不支持或认证失败只影响这次认证，沿当前 Browser 的服务窗说明未完成的步骤、实际可用范围和用户下一步。原页面、控制权、工作面与健康 Agent 保留可用，不因握手／探测失败关闭 Browser 或阻断 Agent。
- 普通重启后仍恢复原 Browser、profile 与工作面；认证能力和未完成请求各自按当前事实处理，不能从旧选择推定新授权或伪造认证成功。公共机制依据通用协议、来源、frame 与用户选择，实际站点仅作黑盒输入。

### Browser 页面证书错误

- 证书验证失败在原 Browser 工作面展示真实请求地址、原生错误与原证书的 SHA256 指纹，区分网站 TLS 验证失败和 Browser 资源恢复故障。原页面身份、Profile、Region、地址草稿与可用恢复动作保留。
- 本人可在可信 App 表面拒绝或明确选择继续；选择须绑定仍有效的原 Browser、原生请求、导航及证书，过期、导航、关闭或资源替换后的旧选择不能应用到新请求。人工证书决定不隐含 Browser 控制权转移，也不自动续跑或重放 Agent 程序。
- 继续访问的实际作用范围必须在确认前说明，包括同 Profile 的网络连接复用；不得将共享连接或配置文件范围描述为仅此页面或仅此请求。实现必须以真实原生请求验证隔离和撤销，不能靠关闭无关页面、清理网站数据或中断整个 Profile 的网络连接伪造局部边界。
- 默认 TLS 校验保持。Agent、CLI、页面脚本与普通网页输入不能授予证书例外，不提供自动放行参数，也不因错误文案、显示样式或已记录的历史决定推定授权。未完成的证书决定可以沿现有公共 Browser 发现与操作结果表达，但私钥和认证秘密不进入日志或可复用资产。

### Browser 任务能力与可复用资产

Browser 任务能力采用已验证的通用交互能力，并保持现有 Browser、Agent 与 Terminal 工作面。视觉约束只归密度 SSOT[《Browser 任务工具与证据的紧凑呈现》](../presentation/browser-workface.md#browser-任务工具与证据的紧凑呈现)，本节定义必须成立的行为。

- **任务库可由公开能力维护。** 同一 Browser 任务资产的创建、编辑、不可变版本发布与便携导入导出沿原资产 owner，GUI 与公共 RPC/CLI 消费同一校验、revision 与回执；脚本工具复用与任务资产创作分别表达。导出不包含秘密、Cookie、凭据或可重放的人工批准；导入不取得原演示、页面、权限或运行身份。
- **保存任务包含可核对的数据成果。** 提取定义、字段类型和完成条件沿原任务版本审阅与发布，执行结果绑定准确运行、步骤、操作、导航和原结果产物。字段读取、产物可读与条件满足分别表达；空集合、部分结果、未满足和不可核对不能升级为任务完成。参数及本次新鲜值沿原调用边界，秘密和页面提取值不能因保存、导出或重启而混入流程定义；已做步骤和未知副作用继续保留，不为补结果自动重跑。GUI 与公共创作、运行、检查复用同一任务与成果 owner，不新增独立成果真相或 Runtime。
- **高阶动作仍指向准确页面。** 元素拖放、触摸、响应等待、请求观察/拦截与网络条件作用于准确 Browser、document 和本次操作；监听先于触发，停止和 reader 撤回各守原作用域，导航与迟到事件不会作用于后来页面。上传、下载和原生对话框的任务步骤复用原文件、dialog 与人工确认 owner。
- **流程编排不复制 Runtime。** 循环、子流程及跨多个明确 Browser/Profile 的并行执行复用原任务版本、操作回执、取消与人工检查点。目标集合和逐项结果可查；并行上限来源于实际资源与在途工作，失败或未知不盲目重放已做副作用，不以一个目标失败停止其他健康工作面。
  - 子流程绑定同一 Browser 的准确已发布版本；循环使用本次明确提供的有限 item 集合。原任务 owner 保存父任务、调用步骤、item 与子运行的绑定，检查、停止和续接沿这一绑定取得当前位置与已完成结果。续接保留 item 身份与顺序并重新提供值，已完成项不重跑；人工 Continue 只确认正在等待的准确叶子检查点。
  - 并行执行先确认原操作 ID、源任务准确版本与明确 Browser/Profile 目标集合，再准入页面工作。源任务库与执行页面身份分开，目标共用原不可变定义及其子流程版本，不复制资产。共享 Profile 的在途任务串行，其他 Profile 继续推进；资源上限不随累计历史减少。每目标在原生准入与动作前核对原 Profile 和调用者权限，失败保留该目标的原回执，不改变无关工作面。
  - 原任务 owner 保存并行操作、准备阶段与原目标运行绑定；分页查询不唤醒原生页面，也不把缺失观察变成空结果。未结束的目标是 Profile 的持久使用引用。重启保留原操作、目标、cursor 与已做结果，在途工作明确中断，排队项不自动执行；同 ID 重发只读原结果。新鲜调用值不写入资产、进度或失败文案，未知写入不许可另起 ID 自动重放。
  - 停止始终沿原并行操作和目标绑定，准备、运行和等待人工时均可请求停止；已完成或结果未知的动作不冒充撤回。续接是对准确目标当前游标的新显式动作，保留原操作、Run、版本、item 顺序与成本，重新提供本次值；等待人工的续接必须来自本人的可信 Client 操作，Agent 不能批准人工检查点。原续接请求的写入或回执未知时只查询同一身份，不重放；撤回 reader 不停止业务。
  - 便携任务保留被调版本的来源；导入后引用明确未绑定，不能凭相同 ID、名称或最新版本认领本地任务。沿原创作权限显式绑定准确本地版本并重新审阅后才可运行，不迁移旧 Run、秘密或人工批准。

- Browser 异步状态须可辨，运行、等待人工、人工接管与失败不得互相冒充；动作按需出现且键盘可达。失败与未知沿既有服务窗说明事实和恢复动作，保留原页面、工作面与健康 Run。 重启恢复阶段尚无终局事实的 Unknown 或未附着状态不能被呈现为 Browser 完全损坏；保留正在恢复的原 Browser 与工作面，按服务窗说明未完成的阶段、当前能力与恢复动作。
- 原生 Browser 与 tooltip、菜单等浮层的交叠、对位、点击与焦点交接只见[《原生 Browser 与浮层的交叠、对位和点击》](#原生-browser-与浮层的交叠对位和点击)；工作面只移动位置时原生 Browser 的跟随只见[《Browser 视口与尺寸调整》](#browser-视口与尺寸调整)。
- 每个真实窄 Browser Pane 的必要动作与 More 都必须在自己的可见命中区可达，不能侵入或被 Region 的 Close split 命中区覆盖；收拢工具不改变关闭分割、原 Browser 身份、页面、焦点或健康 Run，不能改验收顺序避开窄分割。
- **操作证据回答具体哪一步出了什么问题。** 一次 Browser 操作的步骤、目标、页面/导航身份、结果来源、失败位置与可执行下一步能相互对应。观察、动作完成、脚本结束与业务成果是不同事实；已经执行过的动作不会因为后续失败、结果过大或证据保存失败而被说成没有执行。自动保存的证据只含有界、去敏后的事实；完整敏感页面、输入与凭据不因调试被默认留存。
- 本人核验 Task 证据时，沿原执行绑定的 operation ID 找生产步骤。近期浏览历史窗口独立呈现，核验结果由原 Browser 宿主确认。
- **局部观察和大结果都可继续读。** Agent 可以请求当前视口、指定 ref 周边或子树的有界观察，返回范围、实际采集范围、数量预算、缺失 frame 与裁剪事实明确。CSS 范围默认属于主 document，ref 范围属于它的真实 frame；未纳入的 frame 与读取失败的 frame 分开表达，不能把局部结果说成全页完整。同源或同进程的嵌入文档也必须按真实文档身份明确观察，或者告知缺失；不能因为它与主页面共用 CDP session 而没读到却报告完整成功。局部结果保留真实 ref 的身份与有效性，同一次 run 不复用已失效 ref，页面变化不会把旧 ref 静默重编号成另一个目标。超过一次回执容量的观察或结果提供归属于原 Browser/operation 的可读取产物引用与边界，不用杀掉健康 Agent、丢掉已做动作或返回空值解决；引用失效、读取失败或记录不可用有明确状态。小返回值不代表底层采集成本已经减小，实际工作量和相关消费者必须可以核对。
- **文件传输有完整闭环。** 浏览器下载从触发、接收、完成到可读取文件的事实连贯，下载失败、取消、尚未完成与成功可区分；先等待事件再触发动作时不会漏掉即时下载。上传只把明确选择的 Workspace 文件交给当前 Browser 的已授权目标，文件缺失、路径越界、导航失效或文件对话框取消不会退成上传了别的文件。传输产物关联来源页面、operation 和目标文件，经过现有 Workspace 路径与权限边界，可在原工具入口查看。
- **结构化输出与有限成果验收各自诚实。** 页面提取按明确的有限 schema 给出可验证的字段或缺失/不确定结果，来源仍是当前页面事实，不以模型自述补齐未观察数据。业务完成只根据当前这次执行登记的文件、结构化产物或明确人工检查点等有限证据判定；历史产物、另一次执行、外观相似页面与脚本退出成功不能代替当前成果。未满足与验收不可用分开表达；下载终局尚未确认、回执保存失败或事实读取失败时，不能把未知当成条件未达成。验收错误不改变健康 Run、Session 或 Browser 的权威状态。对 Agent 公开的成果 `completion` 与脚本结束 `outcome` 分开，保留原 Browser/operation/navigation/workspace 身份、实际资产 Run/版本、有限条件与失败或未知原因；Core 只解析高层 Client 的有界投影，不重新评页面、文件或人工确认，不持有第二份成果事实，也不依赖 Desktop。单项成果投影无效时说明其未知并保留原 operation/history 与健康工作面，不把缺失投影当成成果通过。成果检查的保存回执尚未返回时，该 checked 事实不能进入补发或实时订阅；回执之后，告示仍对应原来的这次检查。同一 operation 的订阅按发生顺序且只收到一次，补发与实时事件不重叠；等待一项成果保存不得延迟其他 operation 的真实进度。
- **人演示一遍，留下可编辑的语义资产。** 显式开始录制后，当前 Browser 的真实人工操作形成可检查的语义步骤，用户可以删改步骤、命名非秘密参数并预览。删除的步骤不能从原始录制自动复活；无法可靠定位的步骤、敏感输入与不可逆动作保留需要人处理的原因。资产有持久身份与明确版本，运行、编辑和验收分别绑定实际版本；重启后仍能找到草稿、已保存版本与已有产物，不能把旧运行验收套到新编辑上。 累计资产、不可变版本、运行和批次事实完整保留，历史条数或共享文档字节不能占用新操作的准入资格；单次任务和批处理的步骤、输入、动作及时长预算继续限定这次执行。任务还在准备时也必须能停；停止后不得因准备或记录迟到而启动后续动作，其他 Browser 的健康 Run 与原工作面保持。人工重新定位只接受这次真实人选目标，页面自述的同名状态不能替代该目标。
- **人工检查点处于真实流程中。** 需要人作决定时，说明当前步骤、目标、已完成动作和待确认结果；当前任务等待人工须在原 Browser 入口就近可辨并关联实际流程与版本，不能用上一步 completed 冒成整项完成，也不能以历史等待覆盖新的健康 Agent 活动；用户处理后从明确检查点继续，不从头重做，也不以 Agent 点击冒充人工批准。现有控制权交还、应用链接选择与敏感动作闸门仍沿[《Browser 工作面》](#browser-工作面-1)的同一事实，不建立第二份批准或控制权状态。
- **恢复只处理有理由恢复的局部失败。** 恢复保留原 Browser、原 operation 与已经完成的动作，记录失败分类、恢复目标、预算、尝试和结果证据。页面定位或导航失败与用户代码主动拒绝、凭据/权限拒绝、用户接管分开处理；副作用未知时先观察或交还人，不盲目重放整个程序。超过恢复预算或恢复能力不可用时，原页面和健康 Agent 仍可正常工作，服务窗说明当前状态与下一步。
- **外部标签只接本人明确分享的那个目标。** 已有的外部浏览器标签可以受控接入，并保留它的登录态。接入、观察和执行始终绑定本人明确分享的真实连接与标签身份；连接凭据可用不等于已授权任意标签，不能默认选第一个页面或接管其他页，也不导入外部 profile、cookie store、系统钥匙串或其他浏览器凭据；分享页内容可观察不等于页面秘密绝对隔离。外部目标和原生内嵌页面来源可辨，接入不代表内嵌认证已修复。撤回、目标关闭、断线和重连分别保留实际状态，身份未确认时不改指向另一页，不重放副作用；原页面、用户焦点、工作面与健康 Run 保留。
- **停止与撤回按实际来源表达。** 显式 `browser.stop` 终止该外部操作并结束该原 Tab 分享，后续操作须本人重新授予；reader cancel 仅停止结果订阅，不等同于 stop 或撤回分享。外部页面 DOM 的 `isTrusted` 不能证明本人接管，不据此归因是谁停止或撤回。
- **已选文件跟随原页面，不跟随连接。** 当原浏览器文档可独立于 Client 继续存在时，已赋给 FileList 的原 Workspace 文件快照必须在 Client 重启、撤回分享或断线后仍可读取；撤权不等于文档结束，不能为了清理继续观察已撤回页面或凭超时猜结束。未知文档保留快照并占原有有界预算，确证的原文档导航或关闭才释放相关快照，不影响其他页面；本人可在 Browser 设置明确丢弃其选中文件，但须先提示“原页面后续上传将不可读，先完成或取消上传”并确认，Agent 公开 CLI 不提供这一不可逆清理能力。
- **演示中的语义草稿及时可读，解释不覆盖人。** 演示时实时显示语义草稿，并异步给出解释；沿上文人工演示的同一真实输入与秘密边界，已经观察到的动作、语义标题与非秘密参数预览可及时查看和纠错。观察事实、正在解释与尚不能确定分开表达，解释失败不挡继续演示；迟到解释不能改写用户已编辑或删除的步骤、打乱顺序或把未观察目标补成事实。停止和重新录制后仍保留原草稿，旧解释不混入新录制。
- **批处理只跑明确且有限的输入。** 每项绑定同一明确资产版本、输入身份和实际执行位置，项数、动作、时间与结果容量都有可检查的边界。逐项结果、已完成位置、失败、停止和待人工可辨，空输入不是业务成功；从检查点继续不重复已确认动作，副作用未知先观察或交还人，秘密不因批处理被保存。批处理不放大无关 Browser、会话或页面的工作。
- **条件分支依据本次有限事实。** 条件、来源、已选路径与未执行路径可检查，真、假和未知不能混为一谈，观察或验收不可用不能落入假值或默认成功路径。执行位置包含实际分支与检查点，重启后不凭不完整状态重放；执行必须有界，不能以任意代码或自然语言判断偷换明确条件。人工批准仍属于原控制权与检查点事实。
- **可靠性按不可变流程版本和真实成果统计。** 来源是该版本的实际执行、步骤与成果事实，不另持一份成功状态。分子、分母、样本范围与缺失事实可读，样本为零不显示成功率；脚本 completed、重试次数与历史结果不能冒充本次成果通过。未满足、验收不可用、停止、未知和人工介入分别说明，重复回执不重复计数，不把旧版本成绩套给新编辑。当前运行沿真实选择，不以最后创建的历史运行替代；统计只处理所选资产版本的相关事实。
- **能力归属与交付成本不变。** ctxmux 继续独占 Run/PTY/ordered bytes 与权威进程事实；Core/Provider 只持有其既有 Agent 和公开适配能力，Browser 原生事实与证据由准确 Browser 宿主持有，Workspace 文件仍归其实际授权的文件 owner；第一方 Desktop 消费 Main 原生适配，流程资产、成果验收和恢复策略是消费公开 API 的高层 Client 能力，不另起 Agent 或 Browser Runtime。新增能力按通用协议、页面和文件事实泛化；真实重启后原 Tab/Group/Region/焦点/布局和健康 Run 保留，新增持久资产与结果引用可恢复或明确说出恢复限制。热路径工作只随被操作的 Browser、相关消费者和实际事实增长，不能扫描、广播或唤醒无关会话来呈现一个工具步骤。单步日志保存只处理该原 operation 的元数据、当前步骤与新增事件，不能因累计历史重复规范化或重写整库；重启后保留完整原步骤与回放屏障，未确认副作用仍为未知。

## Browser 通用交接闭环

- 外部应用交接以系统调用的完成或失败为准；失败在当前 Browser 说明失败步骤与重试动作，网页保持可用。记住选择失败不能阻断用户这一次明确同意的交接，也不能假装保存成功。
- 顶层、子 frame、重定向及新窗口中的应用链接复用同一机制；普通网页导航和原生窗口语义保持可用。异步结果不能覆盖后来的请求或已经离开的页面；一次用户回答只执行一次交接。
- Agent 操作中的指示要有高级的完成度，并参考交接设计：操作中、交还用户和结束必须可区分；接管与停止只消费本节的显式交接事实，不从普通输入猜控制权。提示不抢焦点、不遮挡主内容，页面装饰不能授予 Agent 控制权。

## Browser RSI 记录与回放可达性

- 操作历史是工作面的一等入口：没有新操作时也能打开，重启后仍能看到已完成、已停止和需要复核的记录。当前 Browser 的即时投影与 durable 历史不得各自维护一套语义；选择某条历史后，时间线、来源 Agent、页面身份和回放计划仍指向同一个 operation identity。历史列表和订阅 backlog 可以有界，但呈现窗口不能删除 durable 操作身份或步骤；活跃和结果未知的操作继续可见，窗口外的原记录仍可按准确身份查询，重启不会用新操作替代它。
- 指定 Browser 的历史以该页的原操作顺序确定窗口。其他 Browser 的记录不占该页的窗口，重新打开仍能读取原历史；无指定页面时使用全局窗口。
- 回放计划必须保留所有已观察到的步骤。需要重新输入、权限确认、外部应用交接、脚本或协议逃生口等人工闸门可以阻止执行，但不能从预览和审计记录中消失，也不能让前面的动作先执行后才发现后面不可执行。旧记录存在步骤缺口、执行结果未知或没有安全的回放贡献时，保留原事实并说明复核动作；不能过滤后面的缺口或不可执行步骤，生成貌似完整的计划。缺步骤的原操作不得执行整轮或单步回放，Main 在派发前复核原记录；原操作含人工闸门或不可执行贡献时，不能靠调用者剥去阻断说明或选一个看似安全的单步绕过。拒绝只作用于这次回放，原页面、操作查询和健康 Agent 保持可用。
- 记录或投影写入失败属于流程状态：健康 Browser 继续工作，同时在操作条、历史入口或服务窗持续说明“记录不可用”和恢复动作；不能静默降级，也不能把空历史伪装成“没有操作”。
- 停止、接管、交还和单步回放必须通过同一条 Main-owned 控制链，拥有清晰的下一步和取消路径；Renderer 只能消费事实，不能自己推断某个回放已经成功。

## Profile 管理、环境与指纹编辑

网站离线缓存属于原 Profile 的磁盘数据，须与 Renderer 内存缓存分别观察和处理。管理入口按准确 Profile 和网页来源展示已测占用、采样范围及未知项；关闭的网页也能发现，Cookie 或当前打开页的集合不能冒充完整离线存储清单。读取失败保留已知结果，不能把未测或无法归因的部分显示为零。

清理离线缓存支持单个站点和所选 Profile 全部已识别站点的一键入口；两者均冻结准确来源及原存储分区选集，由本人在一次确认中核对 Profile、站点及范围，并说明离线内容可能丢失。未知或未归因占用单列，不能据此推导或扩大存储分区选集；已选分区在执行时的全部 Cache API buckets 均受影响，包括无法单独计量的部分。清理不扩大为 Cookie、登录、IndexedDB、localStorage、Service Worker 注册或选集外数据。原 Profile、Browser、工作面与健康 Run 保留。Agent 请求不能代替本人批准；操作保留原身份与回执，失败或未知不自动重放，重启不继续旧删除。前后占用是各自采样事实，原生清理完成不冒充已释放指定字节，活跃网页仍可按正常行为重建缓存。公共入口与 Toolkit 共用原 Profile owner，不让内存清理顺带删除网站数据。

Profile 创建／复制，以及其文件夹、保存视图、代理资产的新身份创建，均绑定调用前冻结的原 operation和可信 actor。新对象身份仍由原 Profile Store 分配，创建结果与原请求关联在同一 metadata 原子提交；不增加通用操作平台，不在 CLI 或 label／时间上派生身份。相同原请求先读取既有创建结果，再核首次请求的 source／collection CAS，避免源后来改变遮掉已完成的原复制；同 ID异体或异主体只拒绝本次请求。

GUI与CLI消费同一创建 owner，并能按原operation只读取得原created identity与独立的当前对象观察。原对象后来改名、回收或删除不改写创建归属；丢完整reply不授权生成另一个新ID或按同名首项采用。新回执不含Cookie／凭据／站点内容，不进入普通Profile清单全量输出；原metadata无新字段时原样保留旧身份和数据，不伪造历史创建回执。GUI保原pending意图与查询路径，不能因重绘、双击或未知结果自动换operation。

找到原created identity不等于原保存已获持久确认。只读查询给当前观察，不能清掉GUI保存的完整原请求；每动作一个pending，后来输入继续保留。原Store可以在明确的同原请求确认中，只同步当前同一metadata文件及目录，并最终核对文件witness、完整字节和原receipt；没有原receipt时绝不创建替身，确认不改对象、collection revision或原请求。该回执须标明当前记录同步确认，不能冒称当时reply已送达。GUI用明确的原存储确认动作消费同一owner；只在owner确认及原客户端保存ACK成立后清理该pending，再接受下一次明确新建。读、确认或客户端保存失败均保原请求、后来草稿及健康Browser，不自动重发创建。

Profile 提供标签、文件夹、固定、状态/最近使用筛选、保存视图及准确选集的批量动作。元数据、最近使用和运行时长由原 Profile 与 Browser owner 记录，未知不记为零；独立编辑按准确 Profile 的版本核对，不能让无关身份的更新成为冲突来源。复制设置创建新身份，明确不复制登录态、凭据、人工批准或既有运行记录。

公共 Profile 能力的回执与授权边界：

- 代理登录的设置回执带 `saved` 与 `reconnected`，清除回执带 `cleared` 与 `reconnected`：凭据写入与既有连接更新分开确认；设置与清除只由可信人或设备操作，见下文[《破坏性 Browser 操作的作用域与人工批准》](#破坏性-browser-操作的作用域与人工批准)。
- `browser open --profile` 的开页回执与 `browser targets` 带页面所属的 `profile:{id,label}`；私密页与 Capsule 不带。
- `network check` 只返回该 Profile 原 session 本次可达或未知的观察。
- 删除 Profile 的批准事实由 Main 依 Host 记录的可信调用者构造，不取请求字段；Settings 页删除走同一函数，托管 Agent 调用者被拒（`BROWSER_PROFILE_DELETE_REQUIRES_PERSON`）。

在 Browser 工具栏切换 Profile 是本人动作，会在另一个 Profile 中重新加载该页面；Agent 持有该 Browser 的控制时只列出 Profile、不可切换，须先显式接管。切换期间原页面保持到新 Profile 的页面提交，切换失败回到原 Profile 并就近说明原因。呈现只见[《Browser Profile 工具栏标识》](../presentation/browser-workface.md#browser-profile-工具栏标识)。

删除 Profile 采用可恢复回收：由原 Profile owner 在同一持久事务中确认完整原记录由活动目录转为归档条目，完整原持久分区原位保留，仍由该归档唯一持有；原站点数据、凭据与人工权限继续属于同一原 Profile ID 的既有 owner。回收不复制、搬动、筛选文件或清空原分区，不是独立不可变备份，也不承诺立即释放磁盘；明确永久清理前保留完整原数据。归档保存未确认时保留原 Profile 工作面和数据，依原生产者及严格读回事实展示实际归属，不把未收到确认当作未执行；读写失败、源文件不可读或占用未知仅拒绝当次回收，不退为永久删除或另建空身份。

回收、恢复与原配置写入按准确 Profile 串行，并在回收确认期间守住原生 admission 边界。默认 Profile、原 Browser 的 live／released／candidate／closing owner、Core 保存的冷页、运行 worker、请求、下载或其占用未知都保持保护；不能由没有 WebContents、界面已关闭或发出 flush 请求推断全部原生工作已经结束。归档后的后台活动仍由原数据 owner 如实记录，不能据归档状态清理健康仍占用的数据。恢复返回原 Profile ID 与新的配置版本，原凭据和权限不复制给新身份；元数据或数据归属冲突不覆盖。恢复、保留期清理和明确永久删除保持准确目标、真实回执与人工确认；重启不丢失原身份、归档和恢复入口。

回收记录默认无限期保留。本人可为准确条目明确批准一个未来保留期限，或单独确认永久删除；既有归档不暗加到期时间。到期只使该原授权进入清理候选，不代签当前时间、冷页引用、原生使用或存储独占事实。永久删除意图及原操作身份先由原 Store 确认；已打开过的原生 Session 无可用销毁协议时，保留意图并等待下一 App 进程，不能把 idle 计数当作数据库 writer 已退出。本进程从未打开该 partition 仍不足以删除：还须确认原数据根的 App 单实例锁归属及准确根路径，未知只限制本次清理，不影响其他 Profile 或健康工作面。

清理原目录前，须在原归档记录中确认完整静止数据副本、校验身份和恢复入口。复制、校验或写确认失败不动原数据；部分目录删除失败仍能从该完整副本恢复原 partition 和原 Profile。晚到使用使本次清理资格失效。最后完整副本删除与元数据确认之间的未知保留原操作及阶段，不自动重放、不宣称数据仍可恢复，也不另起空身份。成功删除后保留不含原设置或数据路径的操作回执；原分区删除、Profile 元数据移除、加密代理凭据和记忆权限清理分别确认，不以一个 owner 的成功代签其他 owner。

代理资产由原 Profile 元数据 owner 持有稳定 ID 与配置版本；分配冻结准确 Profile ID/配置 token 和资产版本，逐项沿原 session 应用、保存并返回结果。绑定记录配置来源；编辑资产不暗中改已绑定页面，手动改路由解除来源绑定，仍被活动或归档 Profile 引用的资产不能移除。代理登录沿原每 Profile 加密 owner，不在资产中复制密码。保存配置、原生 session 配置确认与本次出口观察分别显示。代理可作为独立资产供明确 Profile 绑定与批量分配；TCP、认证 SOCKS、UDP 和出口观察分别报告协议与本次证据，不从密码保存或开关选中推断可用。分层诊断保留原操作 ID、准确配置 token、协议作用范围和脱敏观察；发送登录信息前由原凭据 owner 复核配置代次与端点。直接到代理的 TCP／SOCKS 握手不代签原 Browser 的业务通路，出口仍只沿原 Profile session 观察。诊断历史由原 Profile 持久 owner 持有，分页有界；重启或丢回执后只读原记录，不自动重新发送，历史更新不使配置草稿过期。诊断或历史失败不改线路、不关闭健康页面，也不阻断原出口检查。地区与指纹编辑沿 Profile 环境 owner，明确持久配置、待应用、原生应用确认、部分支持及未知；覆盖的语言、时区、位置、UA/client hints、屏幕与硬件/绘制/字体/网络字段按宿主真实能力表达。页面、子文档、Worker 与后续导航各自核对，不以设置 JSON 或改写页面 getter 宣称引擎一致或反检测效果。环境变化不暗中销毁原工作面或丢弃未保存输入；需要重载时明确请求和结果。

当前引擎可原生应用的时区、locale、位置、UA/client hints、屏幕尺寸与硬件并发参数，复用同一 Profile 环境配置与公开编辑入口；应用回执逐页、逐字段说明原生确认和作用范围。屏幕尺寸与 Browser Viewport 的页面布局分别保留，清除环境设置恢复原生默认及原 Viewport，不丢失页面输入。位置配置不授予网站位置权限。Canvas、WebGL、字体、TLS、设备内存及完整指纹一致性没有原生应用能力时明确不支持；子文档、Worker 与首个脚本的覆盖未确认时明确未知。配置变更不重载页面，迟到的旧版本应用不继续派发后续旧字段或覆盖新版本回执。原 DevTools 接管导致调试连接实际断开时，环境应用变为未知，保留页面和其他健康能力；DevTools 关闭后重应用原保存配置，不重放网页操作。

按 Browser 身份公开的环境应用只指原 owner 当前的原生页面与 Profile 绑定；切换中的候选页、已退休但仍待销毁的旧页不冒作当前配置。切换提交后原 owner 重发新旧 Profile 的应用投影，提交前沿用旧 Profile 的当前事实；新配置等待派发时，旧配置的确认不代签新配置已应用。

网站权限独立于 Agent 使用权与指纹配置。摄像头、麦克风、通知、位置等请求由原 session permission owner 绑定准确站点、Profile 和用途，交由人批准或拒绝，决定的保存/撤回与失效范围可查；托管 Agent 和网页不能自授。拒绝或未知保留健康页面，并提供可理解的原因与恢复入口。

扩展安装/更新、受管书签与 Cookie 文件导入导出沿各自原 Profile 数据 owner；来源、作用范围、权限和逐项结果可查，不把外部分享扩展冒作 Profile 扩展库。秘密及不可逆数据操作保留原人工批准边界。独立 Browser 宿主与 headless SDK 复用同一高层对象、公共能力和回执合同，平台/引擎实现留在宿主，Core 不依赖 Electron、GUI 或引擎分发实现。

- **Cookie 文件交换由本人确认准确对象与范围。** 导入读取本人选定的本机文件或原 Workspace 文件，审阅与派发使用同一份固定字节；确认绑定原 Profile、明确站点集合或整个 Profile、源文件及分项数量。导出在读取 Cookie 值前由本人确认原 Profile、明确范围及新文件目标，保留已有文件；Agent 请求、文件内容或请求中的批准字段不能授予权限。可信原生确认可显示私有路径，普通回执、日志和任务资产不包含 Cookie 名、值或文件内容。
- **交换保全原生 Cookie 身份。** JSON 数组保留 domain/host-only、path、Secure、HttpOnly、SameSite、session/expiry 与分区键；站点范围包含该站点的全部 Cookie 分区键。分区顶层站点采用原生 schemeful-site 语义，不把子域、端口或 opaque key 静默当作另一键或普通 Cookie。不支持、重复、范围外和过期项以原索引分别说明；确认期间跨过过期时间的项在派发前跳过，不能以过期 set 删除目标中的更新 Cookie。有效同键替换仅发生在本次已确认的导入，失败不清空 Profile 或撤销无关 Cookie。
- **数据结果与文件结果分别确认。** 原 Session 保有 Cookie 真相；原 Profile 元数据事务只保存安全操作意图、准确私有文件绑定和分项回执，先确认持久意图再派发副作用。部分失败保留已确认的成功项、原登录态和页面输入，未知项保持未决原 ID，跨真实进程重启仍可查询且不自动重派。导出只有原文件 owner 确认新文件写成才报告完成；没有完整原生集合不能冒作空数组。导入或导出回执不代表站点已登录，站点使用另作真实观察。

- **扩展绑定原 Profile 与已审阅的包。** 本地未打包目录、ZIP 与 CRX 沿同一准备、来源／权限审阅及安装入口；准备不运行扩展代码，Agent 请求或包内文字不构成人工批准。API 权限、host 权限、内容脚本匹配范围及可选权限都属于审阅范围，文件访问默认关闭。本机完整路径与文件名只留 Main 可信确认，公共回执用来源类别；验签与解包沿同一份 Main 自持快照。源包提供的主页／更新来源保留，包签名的完整性确认不冒称已信任发布者或任意商店来源。
- **更新保留原身份与原数据。** 派发前的准确待确认意图、已批准描述与安装回执由原 Profile 元数据保存，包文件留在其原分区的数据归属内；更新使用同一扩展身份和不可变包。更换源身份不能静默伪装成旧扩展更新。失败保原包、登录数据与页面输入；旧扩展的恢复须有准确原生加载回执，不能据此承诺已撤销扩展可能执行的任意副作用。未知请求保原操作查询入口，真实进程重启仍不能把原待确认操作重新派发；旧扩展已恢复不代签原操作未发生。
- **安装、加载与兼容范围分开。** 原 Session 在实际页面消费时加载其已批准扩展；只读目录不唤醒其他 Profile。加载失败只影响该扩展，页面与其他健康工作保留，并可明确重试已批准包。原生 loaded 只证明该身份／版本的加载回执，不证明所有 Chrome API、内容脚本或背景能力均受支持；真实支持范围由相应原生场景证明。移除扩展不清网站数据或 Profile 身份。
- **在线来源与版本更新复用原扩展管理。** 本人或调用方明确指定软件包地址或标准更新清单；取得、来源及包身份校验沿原准备入口，不能把远端内容或清单当成人工批准。检查结果表达本次配置、当前／候选版本、来源及失败／未知，不唤醒无关 Profile，也不因远端失败卸载原扩展或关闭页面。更新仍准备不可变包、核对原扩展身份及权限变化，再沿原可信确认和应用回执执行；检查不自动安装，未知应用不自动重放。当前引擎仅支持扩展 API 的已核范围，来源可取得或包格式兼容不承诺任意扩展完整可用。公开接口与 GUI 消费同一 Profile、包与更新事实，不加入站点特例或第二扩展库。

## 原生 Browser 与 Agent 身份浮层

Agent 头像的 hover/focus 详情属于可跨 Region 阅读的非模态身份浮层，沿同一共享浮层协议呈现；原生层级、页面可见性和输入边界统一引用本页[《浮层让位与输入层级》](#浮层让位与输入层级)，不另持手动遮挡租约或第二份 Browser 可见状态。

## Browser 视口与尺寸调整

Browser 在窗口或分栏尺寸调整期间保持最近一次有效画面。Renderer 暂时得到零宽/零高或未完成布局时，属于几何过渡，不得把 Browser 当成关闭而调用隐藏；等下一次有效矩形到达后直接更新边界。真实不可见、明确切换或停放，以及截图／选择工具所需的临时遮挡，沿原可见性与工具归属处理。错误状态本身不构成隐藏授权：媒体捕获、呈现登记、观察或恢复未确认时，保留原页面、输入与服务窗；失败及重试边界见本页[《多位置呈现、局部遮挡与输入交接》](#多位置呈现局部遮挡与输入交接)。尺寸调整不能触发 Browser 销毁、重新导航或空白闪烁。

重启恢复、字体或窗口壳布局变化只改变工作面位置而未改变尺寸时，原生 Browser 也须跟随实际位置；不靠隐藏再显示或强制聚焦纠正对位。

Viewport 固定预设按菜单声明设置原页面的模拟视图尺寸，完整适配当前 Pane；改变 Pane 尺寸后重新适配，Responsive 恢复跟随当前 Pane。任一模式选定后，用户仍能重新打开原 Viewport 菜单或窄 Pane 的 More，使用指针或键盘切换其他模式；进入 Mobile 不使后续切换失效，也不要求先调整窗口、刷新或重建 Browser 才能继续。模式与适配均作用于同一 Main-owned Browser，不改变 App 窗口、页面导航、Profile、草稿或兄弟页面；缩放后的实际画面与原生输入仍正确对位。页面自身有无 viewport meta 都沿标准浏览器布局，不注入 meta、伪造 UA 或改写页面来凑预设尺寸。选中状态对应原生设置实际成功的模式，应用失败说明失败并保留此前已确认模式与原页面，不发布未应用的新选择。

Agent 的公开视口操作复用同一原 Browser owner、尺寸模型和已应用状态，支持预设、自定义宽高及 Responsive；受原程序的控制权、停止和准确页面边界约束，不借改变尺寸取得人工控制权。回执区分已应用的布局尺寸与页面实际观察；截图输出像素密度沿原采图合同，不冒充布局尺寸、真实设备分辨率或完整设备仿真。

Viewport 直接入口与 More 的二级菜单共用相同选择与已应用状态。设备尺寸按手机、平板、桌面分组，提供常见型号尺寸、Portrait／Landscape 和自定义宽高；方向切换交换实际宽高，自定义尺寸沿同一 Main owner 设置、适配和恢复。设备名仅说明参考尺寸，不宣称等同真实硬件、UA、触摸能力或操作系统。


## 破坏性 Browser 操作的作用域与人工批准

- 清理 Profile 数据、删除 Profile 或登出等不可逆操作必须带明确的操作作用域；用户可删除一个指定的非默认 Profile，或清理一个 Profile 内一个站点的数据，不能把整个 Browser 或所有 Profile 作为隐含范围。
- 清理站点数据的作用域是「一个 Profile 内的一个可注册域」。当前 Browser 引擎（Chromium）按站点清除其下全部 Cookie，网站存储按 origin 保存，所以清理覆盖该站点下持有 Cookie 的每个 origin；比可注册域更窄或更宽的名字一律拒绝，结果不少于确认时说出的范围。批准事实写明操作 `clear-site-data`、作用域 `profile-site`、目标 Profile 与站点；站点列表只显示站点名与 Cookie 数量，不显示 Cookie 名或值，只在人打开时读取。完成后说明已从该站点登出，并提示重新加载其已打开的页面；失败保留原站点与原因。
- 破坏性操作必须经过用户在当前界面明确确认。调用入口传递结构化批准事实（操作、作用域、目标 Profile），主进程再次校验目标未被打开的 Browser 使用、不能是默认 Profile，并拒绝缺少批准事实的请求。
- Agent 浏览器自动化不能借用人的 UI 确认；没有专用的人批准事实时必须返回类型化拒绝，健康 Browser 与其登录态保持不变。
- 是否允许驱动页面由一处判定，依据是谁在请求：Core 附上的托管 Agent 调用方，或人（GUI，或不带调用方的 CLI）。Settings › Browser 的总开关对两者同样生效，关闭时以 `BROWSER_AUTOMATION_DISABLED` 拒绝。每个 Profile 另有一个 Agents 开关，只收窄 Agent 调用方：关闭后 Agent 以 `BROWSER_PROFILE_AGENT_ACCESS_OFF` 被拒，人仍可在该 Profile 里运行自己的步骤。没有 Profile 的页面（匿名页、Capsule、外部标签）只看总开关；保存时未记 Profile 的普通页会恢复进默认 Profile，因此按默认 Profile 判定。读不到 Profile 时对 Agent 明确为未知（`BROWSER_PROFILE_AGENT_ACCESS_UNKNOWN`），不猜作允许，也不拦人。Agents 开关只能由人在设置页修改，公共命令不提供 setter；停止操作永远不经这道判定。
- Profile 代理登录的设置与清除由可信人或设备操作，GUI 与公共入口使用同一 Main 凭据 owner；托管 Agent 明确拒绝。CLI 只从文件或 stdin 接受密码，参数、回执、错误和日志不回显密码。凭据已保存／清除与既有连接已更新分别反馈；连接更新失败保留已确认的写入，不要求重复提交密码。出口检测复用准确 Profile 的原 session 和本人配置的 HTTPS 地址，返回可达或未知的本次观察；失败不关闭页面或改变 Profile。
- 代理认证失败或凭据读取未知由原凭据 owner 保留非敏感原因，准确归属 Profile 与代理目标；原 Browser 服务提示及公开目标的 warning 消费同一事实。提示给出原设置入口，保留 Browser 控制、原页面与健康 Agent，不冒充页面死亡或写入 Agent 操作历史。换代理、明确清除或成功保存新凭据后收口原问题；原文件成功重读只解除读取问题，不冒称远端认证成功。本人隐藏一条提示不删除原事实，也不使其他 Profile 的新问题被隐藏。


## 多位置呈现、局部遮挡与输入交接

启动恢复 Browser 或切换 Focus 等工作面时，未被明确选中的原生页面不得越出其展示位置、遮挡主界面或截走输入。媒体准备与采集等待同样遵守此边界，不因预览尚未就绪把原页面暴露在工作面上方；原页面、工作面、Session 与恢复路径保留。

同一 Browser 的多个呈现切换主次内容角色时，每个准确可见位置只显示该位置的一套工具栏与网页。旧位置的隐藏内容不得继续占用新位置接管的显示容器、重复工具栏或挤占网页高度；原内容沿已存在的准确位置或保留位置交接，尚未取得真实位置时不假报放置或原生可见确认。切换保留原输入 DOM、地址草稿与选区、网页及 Guest 身份，不为消除重复而卸载重建内容、关闭 Browser 或更改 Tab／Region／资源绑定。普通隐藏工作面的阅读保留继续按原合同执行，不因 Browser 的这次角色交接强制迁移无关隐藏内容。

设置只遮住当前背景呈现绑定：该绑定的原生 Browser 画面与输入不可见／不可命中，其他合法可见绑定继续按其实际目标呈现。Focus、Space、Survey、Recall、Mote 不赋予实体独占归属；关闭设置返回原绑定，不销毁实体、不重建原页面、不改变共享 Tab／Region／布局、Session／Run、导航、页面输入或草稿。不通过 CSS 遮盖、全实体隐藏或把实体回迁唯一宿主代替局部遮挡；Mote 明确显示在设置之上的绑定继续可操作。

共用 Browser 工作面首次显示不以 Space、Survey 或其他入口名称决定资格。当前明确选择、准确位置与真实可见几何共同决定原生初始化；隐藏注册与未确认激活不消耗后续恢复机会。显示恢复复核原选择，沿原页面与媒体 owner 继续，不重建网页、标签或登录上下文；被动镜像保持原输入归属。仅浏览工作面的导航、切离再返回与重显保留准确 Browser 的 Agent 控制，继续提供可读的原页面或预览；观看不取得网页输入权，也不授权修改执行 Viewport。Agent 正常持有输入、原生输入展示暂不迁移或已有输入隔离，本身均不是登记、采集或播放失败，不能因此要求 Retry 或显式接管才能继续观看；本次真正改变网页输入归属或执行尺寸的操作仍沿原控制边界判定。真实采集未确认保留原页面、地址和导航，并在本页提供重试同一展示的动作；重试不重复导航或创建资源。

同一原生 Browser 的多处画面跟随其活体页面正常导航。以下任一情况发生时，收回该 Browser 的媒体资源：请求媒体的 App 文档失效、原生来源资源被替换或释放、最后一个可见绑定撤去。只撤去部分绑定时，不影响其他合法绑定；媒体流程未确认时，原 Browser 保持可工作并明确说明状态。媒体撤销不等于关闭 Browser 实体。

媒体预览不是原页面加载、导航或人工输入的前置条件。同一次采集失败、被拒绝或超时后，保留原页面与持续服务窗；布局或尺寸变化不得自动反复申请采集或权限，重试由人在原服务窗中显式发起。

同一 App 文档的多个可见 Browser 同时需要采集时，沿原采集协议顺序取得授权、媒体与确认，不把另一个正常在途请求判作本页采集失败。排队尚未开始时复核原展示仍然有效可见，已隐藏或移除的请求不申请媒体；正常隐藏撤销后重显沿原页面重新采集，旧请求的迟到媒体先停止并完成原确认，不能覆盖或堵住新展示。此调度不新增导航、输入归属、权限或自动重试真实失败的资格。

整个 Tab 的准确展示包含其中实际可见的 Browser 兄弟 Region；当前选择引用指向同 Tab 的 Agent Region 时，也不排除该 Browser 的原页面。有效的显式选择意图与几何是否变化无关：相同正面积下的新选择仍取得当前原生呈现，采集失败不阻止这次交接。被动呈现与恢复保留 Composer／编辑器的输入焦点，hover 不自动取得原页面输入归属，过期或已撤去的选择不会复活。

在 Mote 主对话的原 Tab 浏览或关闭旁边的 Browser Region 时，主对话仍锚定原主 Agent。工具栏关闭消费该呈现的准确 Tab／Group／Region，并在原关闭提交后沿同一位置的剩余 Region 继续。没有关闭事实时保留已选目标。

按下 More 显示菜单时，该次释放只完成菜单打开。菜单项响应本人随后在该项的操作，或原键盘选择。

唯一可见、完整的关联工作面可请求 Responsive 被动预览跟随实际栏位尺寸。原生输入或其他可见位置并存时保留原页面布局；固定 Viewport、Agent 控制及真实裁切继续沿各自边界。被动调整只使用原 Browser 的原生显示 owner。

同一位置已经由 Main 确认的原生页面提供当前画面与输入时，该位置不持续消费被原生页面完全遮住的媒体预览。此边界只消费准确原对象、当前展示租约与真实呈现回执，不从期望选择、DOM 可见性、标题或页面内容猜原生归属。原预览帧、共享媒体与其它合法被动镜像继续保留；恢复预览不降清晰度或动态节奏，不重新导航或取得输入权。未确认、交接在途或原生呈现让位时，保留原媒体画面与恢复路径，不用观察缺口关闭原页面或健康 Agent。

同 Browser 的捕获由真正可见的展示共享；某个展示隐藏或被遮挡后，只释放自身的视频接收，不停止其他展示所用的原 stream 或页面。重显接回原展示；失败时仍保留的能力不能冒充零成本。

保留帧只属于原媒体来源，来源更换或展示结束即释放；恢复预览以该来源真实新帧接替，不能把旧帧当作新来源已就绪。保留帧失败仍保原预览和可达重试，不能停止原页面或共享媒体。

当前控制权允许人工网页输入时，用户从同一 Browser 的被动显示位置第一次点击原网页控件，这一击应准确一次送到同一个原生页面；只迁画面、只换焦点或要求再点一次都不算完成。Agent 操作中的被动位置同样消费[输入隔离](#agent-操作可见性与输入隔离)，不因切换呈现绕过显式接管。输入意图与本次准确展示位置、原页面及其当前可见范围绑定，旧页面、过期意图、隐藏位置或未确认坐标不能替用户点到另一个页面。查看、渲染与 hover 不接管输入；媒体可见不冒充原生可操作。输入交接未确认时保原 Browser 健康可工作，持续说明失败步骤、仍可使用的原位置和恢复动作，不停页、不销毁实体、不重建 Run，不静默补点或自动重放。


## 浮层让位与输入层级

浮层让位是共享宿主默认成立的能力，新增浮层沿原协议消费，不逐功能补手动租约。

浮层默认沿共享宿主与浮层库的 Portal/打开态协议呈现，不依赖各组件申请手动遮挡租约，也不维护具体组件清单或扫描应用正文。自定义浮层由承载完整背景、圆角和命中区域的实际绘制外框声明打开态；透明内层的列表等语义不能代替外框的完整投影范围。与原生 Browser 的实际交叠、可见性和输入行为只引用下文[《原生 Browser 与浮层的交叠、对位和点击》](#原生-browser-与浮层的交叠对位和点击)，新增浮层不复制该合同。

非模态浮窗发起的窗口级确认、选择、菜单与输入弹层从首次可见起须完整可读、可命中，不能先被 Browser 盖住再补升层。DOM、HTML top layer 与原生 Browser 合成必须消费同一所属作用域和真实打开顺序；不能只靠普通 DOM 的 z-index、逐功能手动隐藏或另一套业务状态解决遮挡。较高层持有当前焦点、键盘与 Escape，背景浮窗不截走其操作；模态打开及其原生画面准备期间，背景 Mote、Browser 与普通工作面均不接收点击而改变对象、Tab/Region 或执行目标。取消／关闭后沿原准确 document 中的入口与较晚用户焦点返回，保原浮窗所选对象、Tab/Region、非空草稿和健康 Run。危险确认仍先取消、忙碌不重复执行，原停止、保留 Session 与关闭 View 的后果不变。

弹窗管理从底层职责保证同类行为，新增业务弹窗默认复用，不由各功能重复补丁。网页控制权与模态阻挡人工背景输入是独立事实：前者仍归准确 Browser 的输入 owner，后者只持续到本次呈现结束；关闭模态不解除仍有效的 Agent 控制隔离，打开模态也不撤销已授权的程序输入。原生人工命中隔离沿 Browser owner 的原生输入表面实现，不能在原网页入口无差别吞掉合法 CDP 输入，更不能返回成功而实际丢弃动作。

共享模态持有内容和附件共同的焦点与关闭边界；可滚动的绘制表面不代替这份归属。没有可聚焦控件、最后一个控件撤去或暂不可用时，焦点仍能落到当前模态的真实可聚焦节点。IME 拥有的 Escape 留给组合输入，普通 Escape 只关闭最上层；业务的忙碌和取消约束由原调用者提供，共享层统一组合，不要求每个表单重复实现。

每个模态展示的必需内容、遮罩和模态输入边界属于同一个呈现单元。原生适配不得先展示遮罩再等待内容，也不得因内容校验、预算或绘制失败留下孤立遮罩、不可见内容或继续圈住焦点的空模态。失败退出该次模态展示，持续说明失败步骤并提供重试或取消；原待确认意图、准确目标、已输入草稿及仍在进行的原操作保留，重试只重建呈现，不重复停止、提交或其它业务副作用。非模态浮层首次准备或后续更新失败时，同样保留完整可读、可取消／重试的原内容；不能只删原生投影，将仍打开的原浮层留在 Browser 后面，也不能把一次暂时失败变成必须关闭重开才能恢复的遮挡。取消由用户明确选择；不能关闭健康 Browser 或用不可恢复的工作面替换掩盖失败。

菜单、tooltip、身份详情与图片等子弹层须保留所属呈现作用域。非模态附件位于所属内容之上、后开的窗口模态之下；新的窗口模态按真实打开顺序成为同 document 的窗口兄弟。附件的失败或关闭只收口该附件，不撤销健康父模态。现有非模态 popover 不因复用公共组件变为模态。遮罩在原生侧只补 Main 确认的 Browser 像素，不再次压暗已经由 Renderer 遮罩覆盖的区域。

窗口变窄、变矮、最大化、系统全屏、缩放、切换显示器，以及工作面移入独立窗口或返回后，所属 document、层序、坐标、命中、焦点与退场责任继续一致。纯位置变化与实际绘制内容更新都须及时更新所属原生投影；绘制更新不以 DOM 或几何变化为前提，只改变呈现，保留原操作、准确目标、输入与草稿。隐藏、关闭或撤去的弹层释放该次投影、命中区域与相关绘制更新。几何发现与样式更新由实际打开／关闭、锚点与布局变化及相关窗口事件驱动；存在可见 Browser 和打开浮层时，在准确 document 内按显示帧对已知浮层及其 Browser stage 矩形做有界复核，补足没有 DOM 事件的位置变化。复核不做全发现或样式树扫描，几何变化才重新收集；完整描述未变的重复收集不触发重复发布、抓图或编码。真实像素变化仍沿原 Renderer 的相关合成帧更新。共享机制不扫描终端／编辑正文，不随无关 Session 或 Browser 数量扩大工作；隐藏、无 Browser 或无打开浮层时停止几何复核，无浮层时释放帧订阅。响应与成本分别用首次展示、连续移动和动态内容更新的实际证据说明，包含同步布局与整帧读回的剩余成本，不宣称绝对零成本。

系统文件／目录选择、保存与确认框同样归属于发起操作的准确工作面窗口。跨 document 保留的原组件须携带其当前窗口身份与代次，由已有窗口 owner 解析原生 parent；不能把共享 IPC sender、主窗口或当前系统焦点当作发起位置。过期窗口仅拒绝该次展示并在原入口说明，保留原输入、请求和健康工作面，用户可从当前归属重新发起；取消及业务后果沿原操作。

嵌套浮层按各自真实打开、关闭和退场事实收口；关闭下拉不关闭仍打开的对话框，退场内容不再占用原生命中区。协议无法确认的浮层明确暴露限制，不以手动全局隐藏 Browser 作为长期后备路径。

Escape、点击外部、失焦、选中项、组件卸载与异常路径都退出对应浮层；原工作面保留与恢复仍沿下文[《原生 Browser 与浮层的交叠、对位和点击》](#原生-browser-与浮层的交叠对位和点击)的同一合同。

### 原生 Browser 与浮层的交叠、对位和点击

- Tooltip 与小浮层出现时不能让整个 Browser 消失；原生层级只处理实际交叠范围，页面像素与未交叠区域的输入保持可用，不能以静态截图冒充可操作页面。正常 UI 缩放后，浮层与原页面仍须正确对位且可操作。用户缩放或浮层绘制失败，不能留下没有画出来却占用输入的浮层；保留原 Browser，释放失败浮层，并以局部服务窗说明失败及恢复动作。原生页面与 Chrome 浮层的绘制事实须由真正可用的 compositor frame 证明，不能以 DOM、CSS 或图像加载完成代替；依赖须包含已确认的维护方正式修复，不长期保留同一上游缺陷的本地可见性补丁。无关 Browser 不随全局 overlay 变化隐藏或反复重建；普通重启后仍保留原工作面。
- 当前控制权允许人工网页输入时，用户对真实 Browser 页面的点按必须先或同时到达原页面且只触发一次页面输入，并按普通原生外部点击语义关闭点外的菜单或 popover；Agent 操作中的普通点按沿[输入隔离](#agent-操作可见性与输入隔离)，不自动接管或穿透网页。不能抢回工具焦点、执行隐藏 UI 动作或冒充真实权限确认，零浮层时不产生相关扫描、捕获或 IPC，已打开的 HTML popover 只处理该目标。终端或其他工作面的无关滚动，不能触发原生浮层扫描、捕获或 IPC；浮层自身、相关滚动容器与真实锚点移动仍须及时更新对位。
- 点击原生 Chrome 投影时，同一活跃 App 窗口内的焦点交接不关闭正在选择的菜单。原 Renderer 文档失焦不等于原 App 窗口离开；宿主依据原窗口的原生活跃状态及当前可见、已挂接投影的归属区分两者，不从瞬时 WebContents 读数推断焦点目的地。投影等待绘制不改变这一窗口归属；输入是否就绪仍按原投影的真实几何与输入资格单独判定。焦点保护的需求由本 document 的原浮层发布 owner 持有；没有未释放的原生投影需求时，普通窗口失焦不发起同步原生查询。非空发布在途或移除尚未确认时保留原权威查询，确认移除后释放，不能缓存旧焦点或将等待当成已移除。只呈现像素的投影不持有新的操作语义，元素失焦、真实窗口离开、页面外点与 Escape 仍沿原事件处理。
