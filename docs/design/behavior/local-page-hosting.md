# AgentMux Capsule：持久交互页面 PRD

本文定义 AgentMux 页面托管模块的产品目标、身份与恢复、存储和运行模式，以及主题继承与人机交互（HITL）的行为边界。模块及托管进程应独立于 App 和 Core，由原 Run 承载，可在无 UI 的本机或远程 Core 运行环境使用；本文是目标需求，不表示现有文件预览、Browser 恢复或对象链接已经交付这些能力。

模块名为 **AgentMux Capsule**（胶囊，独立封装的持久交互成果），下文的托管页面即 Capsule。首个交付采用浏览器级容器，页面 origin、存储和 DOM 与宿主及无关页面隔离；不引入 Docker 或 OS 级容器。独立包为 `@agentmux/capsule`，公共命令为 `amux capsule`，运行时 skill 由同一公共注册生成。

## 目标与场景

Agent 临时开发的页面应成为可持续定位、展示和交互的本地成果，避免只留下依赖一次 shell 进程的 localhost URL。重启后，用户和 Agent 能找到同一托管页面、读取其内容与当前状态，并继续原交互；内容、服务、页面呈现和 Agent 处理分别有真实回执。

| 场景 | 用户和 Agent 应得到的结果 |
| --- | --- |
| Agent 生成临时报告、原型或工具页面 | 将内容交给 AgentMux 全托管，取得稳定身份与可再次使用的入口；结束 Agent 或重启后仍能找到原成果 |
| 页面内容已有固定本地目录 | 明确配置内容路径并保留准确来源，不必为展示另外维护一个无登记的临时服务 |
| 页面生成于远程 Core 运行环境 | 状态与内容留在准确执行 Host，由同一 Core CLI 管理独立服务 Run；客户端离开后服务仍可保持，访问路径不混淆远端与本机 |
| 页面需要完全独立呈现 | 使用隔离模式，页面容器、样式与存储独立，不获得 App 通信能力 |
| 页面需要贴合 App 外观并请人做选择或反馈 | 使用注入模式，显式复用主题／样式和受控 HITL 通道，保留人工来源与准确 Agent 目标 |
| 重启、内容不可读取、服务或通道暂不可用 | 原页面和未完成请求仍可定位，能区分已知失败与未知，沿原身份恢复，不重建空页面或重复发送答案 |

首个交付覆盖全托管和路径配置、隔离和注入四种组合，支持静态 HTML／资源、已有构建产物及 SPA。SPA 的有效客户端路由能直接打开并在刷新后返回同一页面，资源路径仍按真实文件解析，缺失资源不伪装成已加载的 HTML。托管构建产物不自动执行构建，遇到动态后台或常驻进程需求时明确实际支持范围，不隐式启动进程或建立代理后台；后续执行能力仍须沿原 Runtime 合同确认。

## 实体、身份与唯一 owner

托管页面是持久产品对象，区别于文件路径、当前 HTTP 端点、某次服务进程和展示它的 Browser。重命名、调整内容来源、服务端口变化或打开到另一位置，不自行更换页面身份；模式切换也不自动创建替代对象。

| 对象或事实 | 唯一归属与边界 |
| --- | --- |
| 托管页面 | 托管模块持有登记、稳定页面身份、存储与运行模式、内容来源、发布和恢复事实；新 ID 复用 `@agentmux/identity` 的 [`mintObjectId`](../../../packages/identity/src/index.ts)，分配后持久保留 |
| 内容与发布结果 | 托管模块管理全托管内容及其持久确认，或保留准确外部路径关系；外部文件的 Host、路径、权限、字节和修订仍沿原[文件边界](files-and-git.md#explorer-与-editor)，不建立原资源的第二份修订事实 |
| 服务实例与访问端点 | 托管模块持有该页面当前的服务与可访问性事实；一次端口、PID、URL 或启动成功不代替持久页面 ID，也不证明内容已展示 |
| 托管进程与 Run | 固定 Capsule serve 入口在 ctxmux 原普通 Run 中执行；ctxmux 唯一持有进程、Run、PTY、输出与权威终态，不创建虚假 AgentSession 或另一套 Runtime |
| 运行管理 | Core 唯一持有该领域的持久运行意图、准确 Run 绑定、原管理操作和保活；服务实例、页面对象、Run 与管理操作身份分别表达，不能用 PID 或进程标题替代 |
| 页面容器与展示 | App Host 只适配 Browser 与可信人工输入；Browser／client 原 owner 持有容器、页面导航、控制权、实际可见性和真实输入，Core 持有原空间身份与绑定 |
| Agent 目标与输入 | Core／Provider 持有准确 Host／AgentSession、Run、输入资格、权限、原生请求与投递事实；托管模块只保页面与准确交互对象的关联，不另建 Agent 或消息账本 |
| HITL 请求、答案与操作 | 页面业务请求保留原页面及请求身份，答复保留原请求引用与操作身份；人工来源由可信宿主输入 owner 确认，进入 Agent 的投递与采用仍归原 Core／Provider |
| 主题与样式 | 原主题 owner 持有主题定义及选择；注入适配只提供已授权的投影，不建立页面专用 App 主题 Store |
| 新建默认与设置 | Capsule 领域服务唯一持有默认内容管理模式、默认运行模式、主题跟随与新建受管根，状态和内容位于准确执行 Host；每个页面保存已解析的实际模式、能力和绝对资源地址，不以当前默认重解释旧页面 |
| 工具结果来源 | 原 Toolkit owner 持有真实 toolId／executionId 及已确认结果；Capsule 引用只关联该结果，不改变执行终态，不建立工具专用页面服务或新 Runtime |

模块的公共业务能力不依赖 Electron、React、App 当前焦点或某个 Browser 才能解释准确目标。`@agentmux/capsule` 提供无 Core 依赖的 portable 合同、领域服务与固定 serve 入口，独立进程持有登记、配置、内容、HTTP 与交互记录；ctxmux 原普通 Run 承载执行；Core 管理同一领域的运行、保活与公共 RPC／CLI／skill。三层各持原事实，不在 Capsule 另建 Runtime 或 supervisor。

纯 headless Core 默认组合相同管理能力，不依赖 App Host 注入托管 owner。App Host、Settings、Browser 与 Toolkit 只消费同一 Core 管理入口及领域服务；退出展示客户端不决定服务存续。文件、Browser、空间、Agent 与 Runtime 的原 owner 保持；App Host 与 Core 进程不持有托管 HTTP 实例，停止管理端不能结束健康托管服务。

## 存储模式与运行模式

存储模式回答“内容在哪里、由谁管理”；运行模式回答“页面以什么边界呈现、可获得哪些 App 能力”。两者正交，不能从全托管、项目目录、作者、名称或外观推断页面受信任或已获通信权限。

| 存储模式 | 内容管理结果 | 运行模式选择 |
| --- | --- | --- |
| 全托管 | AgentMux 在合适位置管理页面内容，持久保存登记与已确认内容；内容来源、当前发布结果和管理范围可查询 | 可选择隔离或注入；全托管不自动授予 App 能力 |
| 路径配置 | 明确指定托管所用本地路径，保留准确 Host、资源与路径关系；目录不存在、不可读或来源变化分别可诊断 | 可选择隔离或注入；本地路径不自动获得信任 |

| 运行模式 | 容器、样式与存储 | App 能力 |
| --- | --- | --- |
| 隔离模式 | 完全独立的页面容器，页面样式与存储和 App、无关页面隔离；容器内状态不能污染宿主 | 不注入 App 主题／样式或通信通道；外部公共管理入口仍守原调用者授权，不因页面有本地地址而开放 |
| 注入模式 | 页面仍有独立于宿主 Renderer 的边界，按显式能力复用 App 的主题／样式 | 只提供获准的主题投影和受控 HITL 通道；能力、目标和可用性可发现，不继承 Electron、Node、任意 RPC 或宿主内部对象 |

两种存储模式与两种运行模式的四种组合均须可用；某个 Host 的实际能力和缺失原因须公开表达，不能静默换模式。每个 Capsule 的浏览器 origin 与页面存储隔离于宿主和其他 Capsule；同一页面的多处展示仍引用同一页面身份，不凭 Browser 数量重复登记内容。

## Settings 与页面级配置

Settings 提供独立的 **Capsule** 资源管理模块，复用现有[编译期设置模块贡献、搜索与原 owner 接入](settings-and-observation.md#设置页的信息架构)。默认与新建根由同一份 Capsule 持久领域配置持有，领域服务为唯一 owner；不新增 AppConfig 镜像、scalar 或第二 Store。Settings 壳、Overview 与搜索的摘要只作固定用途介绍，不用 AppConfig 冒充实时 Capsule 配置；进入管理面后经同一 Core 入口查询准确执行 Host 的配置、新建将采用的值及各已有页面的实际选择。

| 设置 | 新建行为与初始值 | 已有页面保护 |
| --- | --- | --- |
| 默认内容管理模式 | 初始为全托管；新建可明确改用路径配置 | 更改默认不改存量页面模式、来源或内容 |
| 默认运行模式 | 初始为隔离；新建可明确选择注入并按能力授权 | 更改默认不转换旧页面，不新增或撤销旧页面权限 |
| 主题跟随 | 初始开启；仅在该页面已采用注入模式并获得主题能力时提供 App 主题投影 | 新建时保存该页的主题策略；已有页面仍沿其明确选择，主题跟随不授予 HITL 通信 |
| 新建受管内容根 | 默认由领域服务在准确执行 Host 的持久位置管理，实际绝对位置可查、可复制；可明确选择后续新页面所用的新根 | 不移动旧内容；已有页面保留已保存的绝对资源地址与原 ID，旧根仍可被原页面使用 |

新建时把默认和页面级覆盖解析为该页面明确、可查询的实际配置并持久保存；默认值来源与本页显式选择可辨。已有页面的配置调整是对准确页面的独立操作，模式与授权变化明确，继续遵守下文切换保全合同，不借改默认批量转换旧页。

受管根设置是“新建到哪里”，不是隐式迁移入口。更换新建根不依赖搬迁旧内容或重写已有页面，不预建本次无需要的复杂迁移器；原根暂不可用时，仅准确受影响页面报告资源问题，不改投新根或造空内容。目录选择、字段编辑与持久保存分别确认，取消、失败和迟到结果保留原配置及后来草稿；选择目录不自行登记 Workspace 或启动页面。

领域配置通过同一公共 `capsule.config.inspect`／`capsule.config.update` 查询与更新，更新绑定准确 operation 与 expected revision，GUI 与 CLI 不各自保存；页面级覆盖仍操作准确页面。冲突、保存失败与结果未知保留原配置、草稿和操作，不自动重放或显示成功。不得增加会因关闭开关而拿走已有页面的 Capsule `enabled` 总开关。内容路径、模式、主题、HITL 权限及服务可用性各自表达，普通配置保存不执行页面脚本或隐式启动动态后台。

## 生命周期、内容与重启恢复

**登记、内容保存、发布、服务就绪和实际展示分别成立。** 登记成功只证明托管对象及模式已建立；内容写入或发布请求已受理不等于持久确认；服务可达不等于页面已被 Browser 正确展示。本模块的“发布”指将确定内容用于本地托管，不隐含向公网发布。

- **创建与更新保留同一意图。** 调用者取得准确页面身份、原内容来源、模式及结果。内容更新仍作用于原页面；晚到结果不得覆盖后来内容、模式或目标。已应用但回执丢失时保原操作并查询，不以新 ID 或改路径重放。
- **全托管保存真实内容。** 已确认托管的页面内容和必要资源随页面登记持久保留；不能只保存一个系统临时目录引用而称为全托管。写入或持久确认失败时保留原已确认内容、待完成意图与可达恢复动作，不以空内容覆盖原成果。
- **路径配置保留来源。** 路径模式持续读取准确外部目录的当前普通文件，不复制或保存外部目录快照，不执行构建。重启后重新核对同一 Host 和准确路径的可读性；原目录或资源未确认时说明缺失步骤，不偷换为 caller cwd、另一个项目或新建空目录。全托管导入与更新复制普通文件，先形成完整内容版本，再原子发布准确页面修订；符号链接与越界路径不作为托管资源。
- **先恢复描述，再恢复服务与呈现。** 托管页面登记、原 ID、内容来源、模式与未完成操作可在重启后重新发现。原内容仍存在且可读取时，按同一页面恢复访问能力；展示沿同一 Browser／空间 owner 恢复原工作面，不以新的空页面或新的 Agent 代替。
- **进程和容器的结束不等于删除页面。** Agent 退出、Browser 关闭、容器释放或服务重启分别作用于各自对象，不自动删除托管内容、页面登记或 HITL 请求。显式删除须指向准确页面并说明数据与原引用的影响；管理页面和外部路径的清理资格分别成立。
- **恢复范围诚实。** 持久页面内容、配置和已确认交互状态可恢复，不冒称保存了任意 JavaScript 堆、DOM、未声明持久化的页面表单或外部后端状态。需持久化的页面草稿与请求状态应有明确保存结果，不能只因旧画面仍显示而称已恢复。

同一 Capsule 领域由一条独立服务 Run 承载多个页面，按固定入口及已保存的准确运行意图加载，不因页面数、Browser 数或客户端数重复启动服务。各页原固定 loopback origin 与独立 Browser partition 保持；端口被占用时保留原 origin、内容和对象，准确报告冲突，释放后沿原页面恢复，不随机改端口。

- **首次运行意图必须明确。** 仅显式 `capsule.runtime.start` 或首次 `capsule.create` 可以建立领域的 running 意图。空域的其他页面、配置和交互领域操作（含原操作查询）返回 `CAPSULE_RUNTIME_UNCONFIGURED` 并提供显式 Start 恢复出口，不保存绑定或启动服务；管理入口的 `capsule.runtime.inspect` 仍只读返回 unconfigured，显式 `capsule.runtime.stop` 可保存 stopped 意图。已有 running 意图的原 Run 核对、恢复与保活继续成立，不因查询入口而撤销。
- **检查原状态不推进服务生命周期。** `capsule.runtime.inspect`、页面／配置／交互读取与原操作查询只核对准确原绑定、Run、已派发创建和服务身份；即使 durable 意图是 running／stopped，也不派发 prepared Start／Stop、不替换终局 Run、不保存新绑定或为读取重新要求持久刷盘。prepared 阶段按 starting／stopping 表达，原派发结果未知继续 unknown；已有服务可读时直接消费，未就绪时保留原 namespace、Run 与 operation 并说明事实。已获授权的显式管理、领域写入和原保活 owner 继续执行同一意图，读取不撤销它们，也不替它们执行。
- **Core／App 退出只 detach。** Core 关闭管理连接、App 关闭展示只释放各自观察和适配，不能 stop 健康服务 Run；HTTP 不依赖 Core／App 进程继续存活。Core 恢复后先核对准确原 Run 与领域绑定，接回仍健康的服务，不重放启动。
- **显式 stop 尊重持久意图。** 停止服务先保留准确管理操作与持久 stopped 意图，保活不能将其重新拉起。停止、停止结果未知和已确认停止分别表达；停止不删除页面、配置、内容或未完成交互，恢复运行须经明确管理意图。
- **新代 Run 只由权威终局推进。** 仅 ctxmux 对原 Run 的权威终局事实允许沿同一领域和页面恢复新代服务 Run，并明确 Run 与服务实例已变化；保活继续守已保存的运行意图。Core 重启、连接断开、探测失败、空观察或 unknown 都不等于 Run 死亡，保原绑定和操作，不重复创建、不改投另一环境。

执行环境或 Runtime 退出期间不承诺 HTTP 在线；重新可用后仍按原领域、页面及固定 origin 恢复，不能把新进程冒称原 Run。远程服务的 loopback 只在远端执行 Host 可达，内容根、状态和路径也属于该环境；本地 Browser 访问须沿原受权连接或明确授权的隧道，不把远端 localhost 当成本机，不自动公网 bind。旧 HTTP 地址与稳定对象链接不同，后者按原页面及准确来源解析当前能力；没有可用访问路径时保对象并如实报告。原 Browser 的持久工作面、按需恢复与失败出口沿[Browser 合同](browser-workface.md#browser-工作面-1)。

默认受管内容根是准确执行 Host 上 Capsule 领域状态目录下的 `content`；查询返回该环境的实际根及每页绝对资源地址，不复制为客户端本机路径。登记、配置、交互及原操作保存在同一领域 owner，Core 的运行管理绑定不镜像这些事实，内容根可单独选择。删除登记与删除受管内容是显式、分别报告的后果；路径模式从不删除原外部目录。没有获得明确删除授权的内容与未知操作不得因重启或资源释放清除。

## 独立容器与模式切换

隔离模式的页面不能读取、改写宿主 Renderer DOM、App 存储、其他页面容器或内部通信对象。注入模式仍在独立浏览器页面边界中运行，不把生成页面脚本直接运行在宿主 Renderer DOM 中；注入的是受控主题／样式与通信能力，不是宿主权限或整个 App 上下文。两个模式都以准确 Capsule 身份隔离 origin、存储和 DOM，不能只因采用 loopback 地址就声称已经隔离。

页面可发现当前实际模式、已授予能力及缺失能力的原因。页面自己声明“注入”、仿制 App 样式或生成一个能力名称都不能改变权限；模式和授权事实只来自原 owner。

Desktop 的同一 Capsule 使用专属持久 Browser partition，与普通 Profile、私密 Browser 和其他 Capsule 分离；同页多视图共享该页的持久网站存储，页面内存与 DOM 仍分别属于各文档。注入通道只接受准确原生主文档：实际成功响应绑定的托管实例、当前导航、原 WebContents／主 Frame、准确页面和当前能力均须成立。端口恢复、同源 URL 或旧页仍可见不能让未确认来源的文档重新获得通道；原服务换实例后，页面保留阅读，明确重新加载受管内容才能建立新的文档绑定。

切换前明确受影响的页面、存储及能力变化。切到注入模式不自动获得通信或更大授权；切到隔离模式停止该页后续 App 通道使用，但已经发生或结果未知的原操作仍可沿原身份核对。切换保留原页面 ID、内容、未完成请求、已编辑答案与操作回执；容器或连接变化不得自动重发。新模式无法满足时保留原可用工作面并说明未完成步骤，不以无声回落冒充切换成功。具体转换与存储保全方式不在本页预设。

## 主题与样式继承

注入模式允许页面显式复用 App 的主题与样式，使临时成果和 HITL 页面能够与产品外观协调。主题投影复用[主题与样式 SSOT](../presentation/shared-rules.md#主题与样式-ssot-规范)的原定义与已解析值；页面不能借样式继承读取设置、凭据、宿主 DOM 或未经授权的业务状态。

主题和样式能力与 HITL 通信能力分别表达，选择跟随主题不隐含可以发消息。主题变化在原页面内更新已授权投影，保留内容、表单草稿、阅读、请求与原授权，不因换主题重建页面或提交输入。页面局部样式不能污染 App 或无关页面；App 主题也不能改变请求资格、状态含义、可访问名称或人工来源。

首个投影只提供原主题 owner 已解析的浅／深色模式与 CSS 语义变量；不导入 App DOM、组件实现、全部内部 CSS 或设置。页面显式使用这些变量组织自己的控件。无 UI Host、外部 Browser 或主题提供者不可用时，公开说明实际可用范围；页面自身可运行的内容和原交互记录保留，不能把没有主题通道解释成页面损坏。

## HITL 请求、人工来源与恢复

HITL 让托管页面展示 Agent 需要人查看、选择、填写或确认的内容，并把人的明确答复送回准确目标。页面展示一个问题不是已建立待答请求，脚本生成一个答案不是人工答复，答案保存在本机也不是 Agent 已收到。

### 原请求与准确目标

- 原请求绑定准确托管页面、内容或交互来源、请求身份，以及目标 Host／AgentSession；需要 Run 或 Provider 原生请求条件的操作同时保留这些条件。名称、页面标题、当前活动 Agent 和页面自由字符串不能替代目标身份。
- 普通页面反馈、页面业务选择、普通 Agent 消息和 Provider 原生权限／问题回答保持各自语义。页面业务请求不因长得像原生权限卡就取得回复或批准资格；确需回答原生请求时只消费[原请求与输入回执](agent-capabilities-and-messaging.md#原请求与输入回执)及[耐久答复回执](conversation-mode.md#同步原请求与耐久答复回执)的准确 typed 通道。
- 页面只持有获准交互的有限能力，不能自行指定任意 Session、代替别人批准、扩大选项或调用任意公共业务。可信 Host 在实际效果前按原 owner 核对准确页面、请求、调用者、当前授权和目标，不把端口、同源或页面声明当作授权。

### 人的输入与答复回执

人工来源沿[场景化用户输入](conversation-input.md#场景化用户输入)由可信宿主的实际输入事实确认。页面脚本、模拟事件或 `Human`／`user` 自由字段不能认证人工；从页面取得的文字、表单和引用数据保留原来源，不转成平台指令。Agent 或页面程序发起的消息仍保留其真实角色和授权。

选择与编辑只更新答案草稿；人的明确提交才创建本次答复意图。可信输入 owner 保留原请求引用、准确目标、答案及操作身份，Core／Provider 沿原输入入口处理，不为页面绕过队列、pending interaction、权限或恢复条件。页面上的“同意”仅回答获授权的那一项请求，不自动批准其他动作。

首个页面 SDK 提供能力与主题读取、建立文本问题、读取原问题、保存草稿及查询原操作，不提供答复提交、任意 RPC 或目标改写。准确接收者由原页面 owner 保存。人的确认入口在可信 App Browser chrome，明确显示页面、原问题、答案及准确接收 Session；提交在原 Capsule owner 中先保存答案及准备结果，冻结原 Run 和输入操作 ID，再沿原 Core 输入 owner 提交。公共 CLI 的答复请求或页面脚本不能自行建立这份原生人工确认。准备后未跨执行边界的原操作，只能在同一 Run 上经新的明确人工确认继续；已跨边界或结果未知只查询原输入，不能借重启、重试或当前 Session 换 Run 重发。

页面呈现、答案持久保存、提交受理、实际投递、Provider 采用和 Agent 业务处理结果分别报告。缺少相应协议事实时保持未确认，不能把保存成功、HTTP 200、字节 ACK 或通道收到消息展示成 Agent 已处理或任务已完成。

### 重启、未知与多个消费者

页面须在调用写操作前通过 `createOperationId()` 取得并保留原操作 ID，显式传给 `request(question, draft, operationId)` 或 `saveDraft(interactionId, expectedRevision, draft, operationId)`；没有初始草稿时传 `undefined`。需要跨页面重载恢复时，页面先持久保存该 ID。缺失 ID 的调用在派发前拒绝，不在 preload 内隐式铸造，也不依赖异常自定义字段或错误文案把身份带回页面。回执未知时只用已保留的 ID 查询 `inspectOperation`，不重新生成 ID 或重复写入。

请求和答复的原身份、内容、目标条件及已确认回执跨页面重载、容器释放、Host 重启和模式切换保留。恢复时重新读取原请求及操作，不自动重复发布问题、重发答案、改投当前 Agent 或创建替代 Run；旧请求的迟到结果不能改变新请求或后来编辑的答案。

多个页面视图或客户端回答同一原请求时，由原请求与输入 owner 收敛有效意图，不能各自建立第二条投递。通道断开、来源未知、请求已变更或资格无法确认时，只拒绝这次未获资格的动作，保留原问题、草稿、操作、诊断和原会话出口；页面仍可阅读，健康 Agent 与正常消息输入保持可用。用户明确重试也须沿原操作及原输入合同核对，未知不解释成从未发生。

## 对象链接与公共 CLI／skill

Capsule 沿既有 [`amux://` 对象链接体系](../../specs/amux-protocol.md#对象链接)，通过 `amux://capsule/<ID>` 按原页面 ID 被引用。打开时由原托管 owner 解析页面、内容和当前服务，再由原展示 owner 选择或恢复合法工作面；复制引用、定位对象、请求服务与获得展示确认分别成立。链接不携带或授予读取、发布、修改、输入或执行权限；名称、内容路径、端口及 Browser ID 都不是页面 ID 的别名。

对象链接格式、[`AmuxObjectLinkTarget`](../../../packages/core/src/sharing.ts) 及公共 formatter／parser 由原协议 owner 在同一能力交付中扩展并验证，不能让 GUI 或 Toolkit 私自识别另一种 Capsule URI。此处定义目标链接，实际支持仍以源码、运行时发现和真实消费验证为准，不以 PRD 中出现链接代签已安装能力。

公共接入按[统一公共业务服务](public-control.md#对象优先-cli-与统一公共业务服务)与[公共能力贡献约定](../../guides/public-capability-contributions.md)提供同源合同，目标覆盖以下能力：

| 使用意图 | 结果要求 |
| --- | --- |
| 发现、登记与查询页面 | 返回可原样用于后续精确操作的身份、准确 Host、存储／运行模式、实际支持范围与来源，不依赖 UI 当前选择 |
| 管理内容、发布与配置模式 | 操作准确页面，返回已应用、已持久确认、失败或未知的真实阶段；模式与权限变化明确 |
| 取得入口、打开与恢复 | 区分页面对象、当前服务端点和实际 Browser／空间位置，确认同一原页面，不以 URL 已返回代签可见 |
| 管理独立服务运行 | 无 UI Core 经同一 CLI／RPC 管理准确领域的固定服务入口、Run 绑定、运行意图、显式停止与保活；退出管理端不停止服务，unknown 只核对原操作与 Run |
| 使用主题与 HITL | 发现本 Host 对本页实际授予的能力；交互保准确原请求、真实输入来源、目标和操作回执 |
| 定位、诊断及核对未完成操作 | 只读取得原 owner 的当前与历史结果，说明覆盖和缺证，不把查询变成启动、重新发布或重投 |
| 显式结束展示、服务或删除页面 | 准确区分对象与后果，保未获删除授权的内容、其他消费者及原会话 |

CLI 只适配公共业务合同，skill 的机械能力说明与运行时实际能力同源；使用指导解释如何选择模式、确认目标和处理未知。无 UI Host、Desktop 和其他 client 使用同一领域 owner，不能只完成 GUI、help 或生成一份静态 skill 就视为公共能力已交付。

## 对话卡中的页面成果

普通 `amux://capsule/<ID>` 及 Markdown 链接继续表达对象引用，不因阅读或 hover 执行页面。独立 Markdown 段落中的 `![页面标题](amux://capsule/<ID>)` 明确表达页面内嵌意图；同段可以包含多条同类引用，各自保原 URI、顺序与身份。沿 Core 严格对象 parser，不增加执行 query、任意 HTML 或 XML 控制协议；引用不认证作者、授予权限或证明页面已发布，完整消息 Copy 保原 wire。

支持该呈现的 client 在原卡片真实可见时先沿原 Browser owner 回接准确既有文档；原服务查询失败不撤回仍可用的页面。首次没有原生文档时，读取准确 Capsule 并在原服务可用后创建消费者；消息到来和读取不 Start 服务、重新发布、导航其他页面或抢输入焦点。普通链接、代码、只读、文档模式及没有 adapter 的 client 保可读标题与原地址，不派发页面工作。服务停止、缺少路由、来源未知或呈现失败在原引用附近如实说明，保重读原对象与完整 Browser 打开入口，不替换成空页面或禁用正常对话。

内嵌复用原 Browser 独立 partition、sandbox、准确文档和 Capsule 模式。页面不进入宿主 DOM，不继承 Node、Electron 或任意 RPC；注入沿原主文档及服务实例资格，隔离页仍没有 App 通道。人工回答仍由可信宿主问题控件和原输入 owner 确认，标签、URL 和页面脚本不能自称 Human。

展示与页面身份分别成立：有 Region 的卡片消费真实承载位置，无空间 Region 的 Gallery／Focus 卡片按已鉴权原 Renderer 和窗口文档标识内嵌 occurrence，不制造 Core Region，不借焦点或 cwd 猜展示。准确原消息／来源、content part、Markdown 嵌入位置、原 URI 和承载工作面共同限定内嵌呈现引用；不同消息或同页的不同嵌入不合并。沿现有身份组件派生同一 Browser 寻址，原 native owner 的 existing／released 绑定保持唯一，消息暂离阅读窗口或组件卸载后再回原位置仍复用原 Browser，不以另开一页代替保留的表单和 DOM。缺少准确来源或承载位置的独立阅读面保原地址；位置未确认时就近说明并保完整打开动作，不创建匿名、可能互串的页面，也不因此判原页面故障。

隐藏撤原 lease 与 capture，沿原 native release 的 released／retained／unknown 回执保原 Browser 和导航身份，不自动 Close、不清表单或重放未知操作。原生输入覆盖不能越出真实滚动窗口或遮住时间尺：部分裁剪时保 live capture 和原页，仅撤下不适用于当前几何的 native 输入覆盖；完整进入阅读窗口或打开原 Browser 后仍可交互，几何不成为页面／Agent 权限或健康事实。完整 Browser 打开仍沿原 Capsule 公共 owner。

共享阅读通过窄 host adapter 呈现，不持页面事实或第二份 Browser／交互账本。外部原生 Channel 卡片按本平台实际能力保原文和引用，不因协议或 skill 获得网页执行能力。公开查询和打开复用 `capsule.inspect`／`capsule.open`，服务、模式、授权和操作查询合同保持。

## Browser 与 Toolkit Library 联动

Capsule 的日常闭环是：Agent 生成或更新页面，经 Capsule owner 取得原页面 ID 和发布回执；可由 Toolkit 的真实执行结果提供该对象引用；人或 Agent 打开／定位同一页面，在已授权模式下查看并交互；可信输入 owner 将人的明确答复交给原准确 Agent，结果沿原 operation 核对。每一阶段保留原对象和来源，不以端口 URL 或显示文字接成另一条链。

### Browser 是统一页面消费者

- 打开、定位和恢复沿同一 Capsule owner 与原 Browser 公共能力，保留原 Capsule 页面 ID、Browser 身份、准确 Tab／Region 与本次展示回执；当前服务端点只是派生入口。服务重启或端口变化后根据原 ID 恢复，不把旧 URL 失效解释成页面被删，也不新造空页面。
- 已有关联 Browser 时优先复用本任务确认的准确实例；多位置或多个合法 Browser 由原空间与导航合同消歧，不猜第一个位置。需要新展示时沿[Browser 就近放置和焦点保护](browser-workface.md#browser-工作面-1)，保用户输入与原工作面；生成页面、读工具结果或 hover 均不自动打开、导航、聚焦或授予控制权。
- Browser 恢复记录保留原 Capsule 引用及 Browser／Region 关系，恢复时先确认页面和本次实际模式，再取得当前服务。普通网页与现有[本地文件预览](files-and-git.md#本地链接的真实格式预览与二进制保全)继续沿各自原入口；本地 URL、相似样式或页面脚本不能自行升级为 Capsule 或获得注入通道。
- 关闭或释放 Browser 仅改变展示／原生资源，Capsule 内容与未完成交互保留。注入通道跟随准确页面、当前文档和已确认授权，导航到其他内容不得沿用原通道；原有 in-flight／unknown 操作仍沿原身份可核对，不重放。

### Toolkit Library 只传递真实结果与对象引用

产品中的工具库名称为 **Toolkit Library**。Capsule 联动复用[Toolkit 原配置、执行和机器结果通道](settings-and-observation.md#toolkit-与官方-performance-工具)：机器结果沿真实 `toolId`、`executionId` 和已确认结果来源声明稳定 Capsule 对象引用，不从终端文本、标题、普通 URL 或文案正则推断页面登记与来源。

工具结果提供打开、定位已有展示及复制 Capsule 链接的准确动作，复用同一 Browser 路径；不为工具结果建立 iframe／URL 预览服务或另一份页面生命周期。工具定义、执行、结果、Capsule 发布和 Browser 可见性分别成立：工具退出成功不证明页面发布或展示成功，页面可用也不改写原执行结果。新的执行结果不冒认上次页面或抢走用户正在阅读的原页面；仅准确来源声明关联时才更新相应引用。

工具显示配置与运行授权保持原合同，查看、复制或打开 Capsule 不自动重跑工具。工具来源用于辨认与核对，不给页面、脚本或接收 Agent 增权；HITL 仍沿原请求与可信人工输入，不能因来自 Toolkit 就自称 Human、自动选当前 Agent 或绕过 pending interaction。Capsule、Toolkit、Browser 与 Core 各持原事实，不新增并行 Runtime、输入 writer 或消息账本。

Toolkit TUI custom kit 可薄封装同一 Core 管理 CLI，沿原工具配置、明确加载和执行合同调用准确领域，不另实现登记、HTTP、保活或 supervisor。工具保留原 toolId／executionId 及自己的 TUI Run，Capsule 服务 Run 仍归原 Core 管理；关闭或停止该工具不隐式停止服务，也不要求将全部现有 TUI 搬迁到 Capsule。打开工具视图、hover 和只读查询不构成新的服务启动意图。

## 定位、诊断与相关成本

定位结果能辨认准确托管页面、执行 Host／来源 Core、领域服务 Run、运行意图、内容来源、模式、当前服务、访问入口与已有 Browser／空间位置；未展示不等于不存在，未连接不等于已删除。稳定对象 ID 不推导授权、时间、顺序或活跃状态。

诊断区分登记读取、内容保存、路径读取、发布、服务启动或恢复、容器加载、主题注入、HITL 准入／保存／投递与实际呈现。每项只报告原 owner 取得的事实，带来源与观察范围；未知、部分结果、历史状态和当前确认分别可辨。就近提供失败步骤、现有可用能力和准确恢复路径，不能只有白屏或一段无法采取行动的错误。

诊断接入[统一 Diagnostic Evidence](../diagnostic-evidence.md)的原身份与查询边界，不新建跨领域状态账本。默认投影不泄露页面正文、答案、凭据或任意原始错误文本；读取原件仍守原来源权限。诊断、握手或主题投影失败只影响相应步骤，不删除页面、内容、请求或原工作面，不停止健康 Agent。

热路径只随实际相关页面、消费者、内容变化和交互增长。一个页面的服务、主题更新、HITL 或诊断不扫描、唤醒或重绘无关页面／Session；目录查询不为证明“存在”而启动所有页面，释放资源不抹持久身份和未完成操作。原 Browser、文件、Core 输入及 Runtime 的成本边界继续成立。

## 验收结果

以下定义模块完成时必须能证明的结果，不是本批已通过证据；实施时按确认范围拆成可证伪任务，遵守[测试策略](../../testing/strategy.md#任务验收与假绿防护)。

| 验收问题 | 必须取得的真实证明 |
| --- | --- |
| 独立模块是否成立 | 无 UI 纯 Core 默认经公共能力管理固定 serve 入口与 ctxmux 普通服务 Run，完成登记、内容管理、查询及恢复；Capsule 包无 Core／App 依赖，Desktop 消费同一 owner，没有进程内 HTTP 回退或客户端专用托管状态 |
| 服务生命周期是否独立 | Core／App 真实退出后原服务 Run 与 HTTP 仍在，重连接回原 Run；显式 stop 的 stopped 意图跨管理端重启仍阻止保活。仅权威终局可产生明确新代 Run，并恢复原领域、页面与 origin；unknown 不重复创建 |
| 远程运行与来源是否准确 | 真实远程 Core 环境加载同一独立服务，状态与内容留在原执行 Host；CLI 管理准确来源，客户端不把远端 loopback 当本机，不自动公网开放，访问能力缺失诚实表达 |
| 页面是否真正持久 | 全托管内容脱离原临时产物后仍可用；路径模式仍指向原准确资源。真实进程重启后原 ID、模式、内容、操作及工作面可找到，原页面能恢复展示 |
| 模式是否正交 | 两种存储与两种运行模式的四种组合均沿实际产品调用验证；来源、实际模式与能力在 CLI 和真实页面一致，未支持范围诚实表达 |
| 静态、构建产物与 SPA 是否完整 | 真实 HTML 和资源可读；已有构建输出可发布，SPA 深层路由可直达与刷新，缺失资源诚实失败；动态后台需求不隐式启动进程 |
| 设置是否只改准确范围 | GUI／CLI 查询与保存同源；修改三个默认及新建根后，新页面采用明确值，旧页模式、权限、ID、绝对资源地址和未完成请求均保持，旧根页面仍可恢复 |
| 隔离与注入是否守边界 | 隔离页不接受 App 样式注入，不能访问宿主存储与通道；注入页能使用明确授予的主题与 HITL 能力，同时无法进入宿主 DOM、Electron／Node 或任意 RPC，越权只拒绝准确操作 |
| 样式继承是否可用 | 主题变化在实际页面生效，保原草稿、阅读和请求；页面局部样式不污染宿主或另一页面。真实产品看图与独立评审沿[视觉验收规则](../../guides/agent-visual-e2e-review.md) |
| HITL 是否闭合 | 人在真实页面提交后，准确原 Session 经原 Core 输入 owner 接收，答复和处理结果按各自回执呈现；页面脚本自称 Human、错误 Session 和陈旧请求均不能取得资格 |
| 未知与恢复是否可靠 | 在保存、服务恢复、HITL 提交及回执阶段中断，重启或切模式后保原内容、请求、答案与 operation，查询不重放；多视图和迟到回执不重复投递或改动新请求 |
| 公共合同与对象链接是否可消费 | CLI、skill、公共协议和真实页面消费同一能力；新增对象链接由公共 formatter／parser 及真实打开路径消费，按原 ID 回到同一页面且不扩授权 |
| Browser／Toolkit 联动是否闭合 | 真实 toolId／executionId 的机器结果经 Capsule 引用进入同一 Browser，打开／定位回执保原页面与 Region；重启端点变化后仍恢复同一页面，并由真实 HITL 经原输入 owner 到达原 Agent。hover、读取和重连不自动运行或投递 |
| TUI custom kit 是否薄封装 | 实际工具经同一 Core 管理 CLI 消费原服务，保工具及执行来源；工具 Run 与服务 Run 分别可查，关闭视图或停止工具不另建或停止服务，不产生第二个保活 owner |
| 故障与成本是否保全正常使用 | 内容缺失、路径不可读、通道／诊断失败均有准确出口；原工作面与健康 Agent 保留。相关页面增加工作，无关页面和 Session 增加不放大热路径成本 |

实现验收包括真实产品调用链与有针对性的变异证明；构建成功、进程启动、一次 HTTP 访问、截图采集或普通测试全绿不能互相代签。原布局／Browser 生命周期发生变化时，必须验证真实重启后的原工作面；视觉验收只针对实际呈现改动，不由本 PRD 代签。

## 非目标与待定边界

本需求不自动授权公网发布、局域网开放、隧道、任意本机文件托管、任意进程执行或任意 RPC；具体扩展须有准确范围与原调用者授权。页面托管不替代 Core 的 Session／权限语义、ctxmux 的 Runtime、原文件服务、Browser 控制或产品空间模型，也不承诺任意页面内存与外部后端完整快照恢复。

以下仍未确定，不应因本文存在而当作实现决定：

- 后续动态后端、构建执行和任意用户常驻进程能力；首个交付只运行明确管理的固定 Capsule 服务，不隐式运行这些用户进程。
- 超出文本问题／答案的 typed 业务表单和更丰富的样式组件；现有可信人工输入能力不足的 Host 必须如实表达，不以页面声明补造。
- 局域网或公网开放；服务在准确执行 Host 仅绑定 `127.0.0.1`，已确认的远程 Core 运行不自动授权新隧道、公开端口或其他监听地址，既有 Capsule 设置、Browser 与 Toolkit 入口不因此扩大访问授权。
