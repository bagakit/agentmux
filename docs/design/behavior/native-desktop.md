# AgentMux 原生层

本文定义本机操作系统能力的统一行为边界。原生层承接应用、窗口、辅助功能对象、系统截图、剪贴板和原生输入；不持有 Agent Session、Run、PTY、Browser 导航或用户草稿。项目分层沿[系统职责](../../architecture/system-ownership.md)，截图与草稿沿[输入合同](conversation-input.md#message-tools-失败反馈与-browser-region-选中态)。本页是已确认需求，不表示实现、安装或授权已通过。

## 原生能力与接入

- 对外统一称“AgentMux 原生层”。平台模块、应用与可执行文件使用 AgentMux 身份；helper 只出现在外部来源说明中。
- 以固定版本的原生实现为引入基线，保留许可与来源。应用／窗口发现、界面读取、窗口截图、键鼠／控件操作、权限状态与授权引导均形成实际能力，不仅复制未接线源码。根据 AgentMux owner 边界调整，不携入另一套 Agent 身份、授权账本或 Runtime。
- Core 公共能力端口与 CLI 提供能力发现、准确目标、原生观察与动作回执；宿主注入原生实现。Core 不依赖 Electron、AppKit 或客户端 Store。平台未支持、原生程序未启动与单项系统权限不足分别表达，不能扩大成 Core 或健康 Agent 不可用。
- 现有系统截图与可复用的原生剪贴板入口消费同一原生层；Browser 页面采图通过同一图像接缝消费原页面渲染源。Electron 自有页面、原生绘制层与准确 WebContents 输入继续由其原 owner 提供，不能因模块统一改成全局鼠标或 OS 窗口采图。
- macOS 接入新的原生系统实现；尚无对应原生程序的平台保留其既有系统能力 owner，不能拿走原本可用的剪贴板。平台选择是静态职责分派，不在一次 macOS 原生调用失败后改走另一实现；公共原生模块未支持的能力仍如实 unavailable。

## 目标、观察与真实输入

- 原生目标由准确 Host、进程身份、窗口身份及本次观察取得的控件引用定位；名称、标题和人类焦点只作展示或显式查询条件，不能替代身份。观察来源、时间和缺口可读；窗口、进程或控件变化后不得把旧动作改投其他对象。
- 界面读取来自操作系统辅助功能协议。调用受理、输入事件投递、控件值回读与应用实际完成分开表达；不能把合成输入已发出称为操作成功，也不能从界面文案猜业务完成或 Agent 权限。
- 输入动作只在准确目标和当前授权范围执行。跨窗口激活、焦点交接、剪贴板改写等副作用须由本次动作语义覆盖；查询不触发输入、授权申请或抢焦点。读取能力与写入能力分别发现，单项观察失败保留其他可用能力。
- 普通界面观察只读 AX；系统像素是带原 operation 的显式采图。粘贴优先使用准确 AX 写入；需要系统剪贴板和快捷键时明确保留待粘贴正文，不在缺少目标已读取回执时自动恢复旧剪贴板。已写剪贴板但输入未确认分别保留原阶段和 unknown／unverified，不能猜消费完成或补发一次。
- 请求携带原 operation 身份。回执未知保留原请求与连接状态，不能自动重放点击、输入、粘贴或拖拽；退出和取消只释放原生层拥有的资源，不停止或替换 ctxmux Run。

## 截图与图像来源

- Message Tool 保留人工拖框选区、取消、保存和原草稿插入体验。原生选择给出明确 captured／cancelled／failed 结果；无图片、无响应或退出状态缺失保持未确认，不能冒充取消。失败保原草稿、附件、Session 目标与可用输入。
- 应用窗口、显示器和选区采图使用准确的 OS 图像来源；多屏、负坐标、HiDPI 与像素尺寸在同一坐标合同中解释。现代系统使用当前支持的原生采图 API，按实际系统版本处理 API 可用性，不因照搬上游最低版本丢掉已有能力。
- Browser 截图仍遵守[Browser 工作面](browser-workface.md)的原页面、导航、视口、GUI／CDP 来源与生命周期合同。隐藏、被遮挡、移动设备模拟和未获系统录屏许可的网页采图保持可用；统一图像入口不改变这些资格。
- 图片资源、PNG 与剪贴板动作返回实际保存／写入结果。系统截图、Browser 截图标注、图片预览和 Composer 继续使用原资源、编辑及发送 owner，不建立第二份图像或草稿 Store。

## 权限、签名与生命周期

- 权限查询与显式申请分开；只查询不弹系统授权窗。读数 unknown、缓存未收敛或查询失败不能阻断一条物理上可执行的通路。真正缺少本次必要授权时拒绝该次操作并给出准确恢复入口。
- 系统授权由本人完成；不自动点同意、不重置或改写权限库、不弱化代码 requirement。首次代码身份转换与后续更新的授权连续性分别验证，不能把签名校验、设置开关或同 signer 当成 TCC 授权回执。
- 主 App 与原生应用沿现有签名流程使用持久 signer、稳定 bundle identifier 和默认 designated requirement。最终启动形态下的实际责任进程由同请求系统证据确认；不同构建的真实授权连续性不能用私有小程序互验代签。
- 生产连接从 OS socket peer 的 audit identity 校验真实动态代码、准确宿主签名 identifier 与同一持久 signer；自发 PID、token 或显示 Bundle 字符串不足授权。开发测试 profile 与正式应用隔离，不提供运行时降级开关。授权还须在实际提交前复核，不能因按需启动等待而使用已撤销资格。
- socket 从目录项首次可见时就须属于原用户且对其他用户私有，不能先公开创建再依赖后续改权限。连接方保留类型、归属与私有权限检查；启动未就绪和真实非法路径分别处理，不因发布时序放宽安全边界或重放操作。
- 原生程序按需启动，按原请求关联返回并清理自己拥有的连接和进程；共享 AX／输入资源局部串行，人工选区等待不阻塞独立剪贴板与状态查询。不常驻重复观察无关窗口，不复制 Session／Run 注册表。资源成本随真实消费者增长，正常终端使用与原工作面不依赖原生层预热。

## 完成边界

实现包含来源与 MIT notice、更名后的原生程序、Node 能力端口、正式构建签名、公共 RPC／CLI 和实际 Desktop 消费。验证真实成功、明确取消、权限拒绝、目标变化、回执未知、进程退出与恢复；变异和产品调用者均非空。原生 UI 的本批实拍与独立看图、真实安装与 A/B 授权连续性沿现有验收责任执行，不把源码存在或构建通过称为全部完成。
