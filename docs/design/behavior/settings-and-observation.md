## 统一观测与诊断机制

统一机制的目标、模块接入、证据与错误码设计由独立 [Diagnostic Evidence 设计](../diagnostic-evidence.md)持有。本文仅定义 Settings、资源面板和 Toolkit 如何消费原 owner 的能力；机制协议与领域诊断不在本页重复定义。

Settings 的诊断入口沿原公共服务读取准确目标、支持范围、原证据与部分结果，保持原来源语义；看板、配置保存和观察失败的产品反馈沿本页及原服务窗合同。通用设计的创建不代表当前 Settings、安装或 CLI 已具备新增能力。

## 状态栏

状态栏保留系统通知与按需资源观察。整窗 Agent 运行数、待处理数和展开入口统一归[Focus 的全窗注意力合同](focus-context.md#focus-执行上下文项目泳道与底部时间音轨)；本页不定义第二组 Provider 计数或 Agent 名册入口。Tab、工作线与单 Session 指示仍只表达各自范围。

Agent 工作状态与待处理状态消费同一 Core 语义事实，不能从 running 猜 Working 或自建计数分类；准确投影、分组与未知只由[Focus](focus-context.md#focus-执行上下文项目泳道与底部时间音轨)持有。

- **面板资源指标只在展开时采样**。折叠态不得触发任何进程扫描——一个常驻的全主机 `ps` 轮询会让空闲窗口持续耗电。展开后按固定周期采样，关闭即停。并发调用共享同一次进行中的采样（in-flight 去重），一次轮询风暴只产生一次子进程。应用自身进程的低频事后摘要沿下文独立的轻量边界，不打开面板采样或全主机扫描。
- **一次全主机扫描，按 pid 子树归并**。为每个 Agent 单独起一个采样进程，开销随 Agent 数线性增长；正确做法是一次扫描后按 run 的 pid 归并出各自子树，共享祖先按注册顺序只归第一个，避免重复计数。
- **只声明证据支持的口径**。输出字节速率就叫字节速率，不除以一个系数冒充 token/s——终端字节含 ANSI 转义与 TUI 重绘，与真实 token 数不成比例，一个无法验证的数字比没有这个数字更糟。
- **token 用量保留原报告范围，永不报速率**。数字必须由 Provider 自己报出，整轮、响应与缺值的共同口径见[原生回合摘要与过程披露](conversation-mode.md#原生回合摘要与过程披露)。声明 `usage` 能力的 Provider 在既有收尾事件上由 Hook 进程读一次自家 transcript 尾部，随原回执带回最近样本，不新增轮询或通道；最后一次响应累计明确称最近一次响应，只有原生整轮依据才称最近一轮，不把最新样本或会话累计冒充整轮（`AgentUsageCapability`／`AgentTurnUsage`，守护：`agent-usage-transcript.test.ts`、`agent-usage-capability.test.ts`；catalog 到 Hook 环境的原注入由 `agent-usage-env-injection.test.ts` 守护）。墙钟耗时包含审批等待、工具执行和网络往返，不能用它把真实 token 数换算为模型生成速度。用量仍落在所属 Agent 的**名册行**，状态栏不重复有作用域的指标，也不跨 Session 加总。报了用量、声明能力但尚无样本（显示不知道）、根本不报用量（明说不报）三态保持可辨，不能因缺席补 0；原真实零值按原报告表达，守护：`agent-usage-display.test.ts`、`agent-roster.test.ts`。

## Settings 中的 Keyboard shortcuts

用户要求「快捷键设置也应该放进设置」。快捷键在同一 Settings 导航、搜索与 Overview 可发现；原快捷键入口与公开 `help.shortcuts` 指向同一实际 registry，命令、平台和弦与作用域不另维护一份列表。作用域、IME 与 Terminal 原生键消费仍沿既有快捷键合同。当前只读手册与可编辑配置必须清楚区分；未接入真实分发和唯一持久 owner 前，不能提供仅修改显示的录键或保存。后续可配置绑定须同时供实际分发、编辑器提示和 CLI 消费，冲突与保存不得另建假配置。

### Message Tool 设置分组

Message Tool 在 Settings 中有专门分组，依次提供五个独立入口：User Input、A2A、Automation、Prompts、amux Protocols。导航、搜索、Overview 和窄窗分类沿同一设置目录，不因归组复制配置、输入队列、资源库或协议解析器。User Input 持有初始一行／两行、快捷输入符与关键词建议，并就近展示同源发送／编辑快捷键；保留原配置键、默认、生效范围和单字段保存。

A2A 设置持有面向用户的后台来信提醒偏好：跟随全局遵从 Notifications 的关闭、停留时长和声音；静默不弹用户提醒；提示在全局关闭时仍用 Standard 时长，其余沿全局时长，声音始终沿全局。三种偏好都不对前台可见收件 Agent 重复弹窗，初始化、观察补读和重连不补弹旧信，同 MID 的后续回执不算新来信。它不改变接收 Agent 的入箱、确认空闲时引用通知与按原 MID 主动取信合同，不代表已读、任务接受或授权。消息与原投递事实仍在准确 Agent 的 Inbox／Outbox，不在 Settings 另建收发箱。全局通知呈现仍归 Notifications。

Automation 集中恢复后的自动续行、持续推进的新任务默认周期／Prompt、日历安排默认时区和 quiet follow-up 默认策略（静默时段、沉默时长、最小间隔、每日预算）。恢复续行复用原 continuity 字段及固定续行正文；恢复方式、时机、失败重试和同操作复查仍归 Session recovery，两页各自只保存所编辑字段，不能用陈旧整份 policy 覆盖另一页。新建任务默认值只在新表单／新目标初始化时消费，不重写已编辑草稿或既有任务；保存不创建、启用、暂停、停止任务，也不发送输入。准确 Agent 的任务创建、周期／Prompt、日历、来源绑定和生命周期动作仍归 Progress。A2A 引用通知继续归 A2A，不收入 Automation；Browser 等其他领域的自动化也不归本页。

Automation 将当前草稿中的静默时段、首次等待、后续间隔与每日预算合成可读示例，说明条件如何共同约束跟进；示例不承诺实际发送时刻或已启用任务。Session recovery 区分重新尝试恢复与观察同一原操作，按原 Core 策略展示有界重试节奏及上限；输入无效时就地说明，不能把旧值、样例或预览当成当前已保存策略或执行事实。

Prompts 保持独立可复用资源库；amux Protocols 保持独立只读公共协议参考。两者用途不同，不能合并为一个页面或按输入来源复制。新偏好复用同一 ConfigOwner 和公共 Settings get/set，发现、校验、持久化与真实新建任务／提醒消费者必须闭合，不提供仅改变显示的设置。

Message Tool 内的快捷键说明与全局 Keyboard shortcuts 消费实际共享输入声明，包含常规发送、立即 steer、换行、历史与候选操作及各自适用条件。按键只在原输入作用域处理；IME、编辑器默认行为、草稿和原可用组合保持，说明收拢不成为新门禁。发送、排队与 steer 的含义唯一沿[输入合同](conversation-input.md#composer-静息形态与主操作)，不把当前只读手册当成可自定义键位。

Prompts 保持原库身份、编辑器实例、保存与公共资源接口。Goals 常用操作、快捷回复、状态动作等消费者继续引用同一条 Prompt，导航归组不复制正文、收窄作用范围或新增配置 owner。

## Activity 工作线展开信息密度

- `Activity by work line` 折叠态保留工作线摘要和“选择一行打开”；展开箭头只在确实有额外可操作或诊断信息时出现。
- 展开项不得重复聚合行已经表达的名称、Provider 数量和状态。明细优先显示 Agent 图标、最近活动、状态原因、空闲/停止时长和可直接处理的动作；没有新增信息时保持折叠或隐藏展开控件。

## Status Bar CPU/Memory 资源面板

Performance 按总览、资源归因、诊断分析与现场原件组织。App、Runs、Runtime 是资源归属范围，不再承担所有分析的主导航；总览区分所在 Host 的环境资源和应用／Run 成本，不能把不同来源、分母或时窗相加。右下角保留快速查看，可在同一 Tool 扩展阅读；切换分析区或显示尺寸不丢弃已取得的现场、独立导入或未知回执，不新建窗口、持久工作面或第二套指标 owner。

磁盘容量标明实际观察卷、普通用户可用字节与源时间；当前 home 所在卷不冒充项目所在卷或全部磁盘。整机 CPU 以全逻辑核容量为分母，与应用的单逻辑核口径分开。系统物理内存、空闲量、压缩、Swap 与压力各消费平台原事实，未支持项明确缺测，不用剩余量猜压力。网络上下行来自准确网卡累计字节的有效区间差分；第一帧、计数重置或接口换代不补零，物理／虚拟／loopback 不直接求和，也不当作应用或某个 Agent 的流量。所有新增观察沿原消费者驱动、共享采样与局部失败边界，不随页面切换另起轮询或自动清理。

资源观察按来源独立取得并保留各自时间：整机进程扫描缓慢、失败或仍在等待时，已可取得的 App／Main 读数仍须可见。公共单次读取返回首个混合来源帧，不等待所有来源齐全；首个无有效 CPU 区间的样本保持未知。后续扫描结果不刷新其他来源的年龄，也不为每个来源另起轮询或扩大普通展示更新量。

Runs 列表由准确 Host／Run 引用关联原 Session，展示既有 Agent 名称和所属 Project；不因公共结果卡片省略而丢失可解析身份。路径文字与提示遵循 Settings 的显示偏好，远端路径不代入本机 home。显式跳转复核原引用与 client Session 身份后沿原空间导航，不创建、重启或输入 Agent；映射不明、歧义或已改变时保留原资源读数和分析面，并说明本次跳转无法确认的原因。

独立的对象持有调查由用户显式请求 native heap snapshot，绑定同一准确 Renderer 五字段目标，与普通 metrics／scene 分开。原生快照会暂停 Renderer、可能触发引擎 GC，并可能占用显著内存与磁盘；对象字符串、URL 与秘密可能进入私有文件，不自动采集、上传或写入错误日志。Main 直接生成原生文件，公共 `system metrics heap capture`／`inspect` 与 Performance 消费同一 captureId、Host 归属、文件引用和原完成事实，不把整个 heap 经普通 RPC／Renderer 复制，也不接受调用方任意服务器写路径。GUI 提供原文件另存、显示位置与显式打开原 DevTools；通过 Memory Load／Retainers 分析单份对象持有关系，不自建 heap 图算法。它不代表 worker／native／GPU 或全部 RSS，也不自动判定泄漏；两文件 Comparison 另需证明 isolate／object-ID 连续性，不能只凭 PID 相同。

原 attempt 仍在 latest／pending 保留窗口内时，同一 heap captureId 不重新启动 native；每次新的采集意图由调用方通过统一 ID 组件提供全新 captureId；原 captureId 与旧 UUID 保留，接收端按 1–128 位 ASCII 字母、数字、下划线或连字符的有界路径安全标识校验。已替换的旧 ID 应先 inspect，不再保留时报告 mismatch（没有保留快照时为 absent）；这份有界保留不提供永久历史幂等。取消或观察超时只结束该读者，不能冒称 V8 已停止，仍在途的原生操作占用原诊断槽，原 Agent／输入／普通 metrics 不受影响。一个最新文件与一个在途／发布未确认的候选有界保留，候选原 ID／目标在 native 前写入固定私有 pending 索引；Main 重建时缺少的原请求／完成观察保持 unknown，文件完整性不能补造 native ACK。新的明确采集会替换已发布文件，保留基线须先另存。已确认替换前保存失败且原材料完整时，显式同 ID 请求只重试小回执发布；替换后 unknown 先按原 ID 检查实际 manifest／文件，不自动重写、回滚或重采，也不以当前可读倒签原耐久 ACK。旧材料合同不可读时保留原字节并说明局部未知；显式另存原文件或无文件时的小回执后，可准确释放该 pending 候选，保留不兼容的旧 latest 字节，不依赖杀 Run／重启恢复。不得无限累积新候选或影响健康工作。

准确 Renderer 的诊断资格由原窗口、WebContents、代次、PID 与创建身份确认；热点详情的合法省略不是该目标不存在。GUI 不因无关进程的热点排序永久关闭原目标入口，采集仍由 Main 在准确目标上复核，来源不可用或目标失配继续明确报告。

- Performance 提供显式的一键现场采集，沿原 metrics owner 绑定准确窗口、WebContents、Renderer 代次、PID 与创建身份，组合资源读数、CPU 调用栈、Chromium timeline、堆分类与短时内存分配采样。各阶段保留实际来源、时间、原件、失败或 unknown；串行采集不冒充同一时刻的快照，部分成功仍可导出。分配采样用于定位窗口内的分配调用栈，不是全部 RSS 分账、历史对象持有链或泄漏判定；不额外调用主动 GC、扫描对象正文或生成会长时间暂停界面的大型堆快照；分配采样所用引擎协议在读取／停止 profile 时仍可能触发 GC，不能承诺零 GC 或把采集成本当作普通观察。严格合同拒绝原件时，沿原错误回执保留有界的固定校验谓词与结构位置；不默认输出 URL、函数名、任意属性名或对象内容，也不放宽合同、把原件清洗成成功或自动重采。
- 现场仅由明确操作启动，查看面板或读取最近现场不启动采集；只保留最近一份本机原件，不新增后台记录、自动上传或历史库。保存失败保留已取得材料并明确实际阶段：替换前失败保旧原件；替换后耐久确认失败时，当前文件可能已变更，沿原 captureId 读取实际原件，不冒称未写、回滚成功或自动重采。面板关闭不丢掉 Main 已取得的现场；重新打开可读取并导出原 JSON 及各类 profile，已替换的旧 captureId 明确不可读。原目标换代后仍表达旧归属，不能改采新进程、重试未知操作或抢占已有 DevTools。公共 RPC／CLI 与 GUI 消费同一现场 owner，大材料沿领域原件能力读取，诊断封套只提供有界摘要或引用。
- 为事后排查应用进程高内存，原 metrics owner 独立于面板可见性保留低频、定量、有界的应用进程内存采样摘要；它只读取 Electron `workingSetSize`（KiB，公共字段 `rssKib`），不是独立的 RSS／footprint 或可回收内存读数；不启动全主机扫描、Run/Agent 轮询、V8 heap、profile、trace 或现场采集。按原进程创建身份与 PID 记录各进程及应用合计的实际样本和峰值，跨应用重启保留已确认写入的有限窗口，并通过 `system metrics app-memory inspect` 的只读公共查询取得。每段报告采样范围、间隔、来源、缺测和持久状态；进程重启、身份缺失、采样失败、写入失败与淘汰不得拼成连续曲线或零值。样本峰值不代表采样间的真正峰值，应用进程合计不包含未归属的 Agent CLI 或 ctxmux，也不能从 RSS 单独判为泄漏。自动摘要与上文需要用户显式启动的重型现场是两种证据，不能相互补造原件。
- Renderer 高 RSS 的明细查询沿原公共 metrics owner，绑定窗口、WebContents、Renderer 代次、PID 与创建身份，显式读取一次原生 V8 isolate heap、backing/external 和 embedder 计数，以 bytes 保留原字段与采样时间。缺失实验字段表达未知；backing 包含 ArrayBuffer、external strings 等，不能把计数与 RSS 相加冒充独占分账，也不能据短时回落宣称无泄漏。此查询不主动 GC、扫描对象正文或常驻采样；既有 debugger／DevTools 保留，取消、目标换代与释放未知只影响本次查询。对象持有链、其他 worker、DOM／原生缓存与终端容量若未测到须明确缺证，不能凭逻辑行数或排队字节排除其成本。

- Performance 在准确当前窗口提供显式短时函数采样与 timeline 入口，委托同一公共 metrics owner；打开面板或下钻不会自动采集。结果保留原目标、实际区间、completed／failed／unknown 与清理事实，不自动重采未知操作。当前观察面分别保留最近一份已完成的函数采样与最新采集回执；后续失败或未知采集不抹掉已可用的 profile，二者各自标明原归属并导出，不建立跨重启历史。原始材料可显式导出；模块热度仅由实际 V8 sample 与 timeDeltas 聚合 self-time，调用栈火焰图保留原树及样本权重，不冒充 React 组件精确成本、全部 native CPU 或泄漏结论。缺样本、无法安全分析或目标失配时具名说明，其他观察与健康工作面仍可用。

- 已导出的 V8 profile 可在本机离线分析，不连接服务或重新采集。GUI 与离线分析复用同一权重和调用树解释；保留原生成脚本位置、行列、实际 profile 区间、样本数与加权时长，分别表达 idle、GC、脚本和无法归属的样本。份额只属于已有样本，不能换算为进程 CPU；未覆盖时段不补零，缺少原捕获身份或源码映射时明确未知，不猜测当前版本或业务模块。
- Performance Tool 可导入用户明确选择的本机 CPU profile，复用同一分析和技术剖面报告；原件导出保留原字节与 hash，不重新序列化。导入不依赖当前进程观察、暂停或采集状态，不启动采集或上传；本机文件的进程和构建归属明确未核验，不能伪造当前窗口回执。只保留一份导入材料，可清除；替换时重置原视图状态，失败或取消保留先前可用材料，清除与卸载后迟到的读取不能重新占用视图。


- Renderer 诊断须区分进程占用、V8 函数样本、交互阶段与 Chromium timeline；缺失阶段保持未知。同一次 Tab 点击以原有界记录保存事件与 handler 的单调起点、原选择动作结束及是否正常返回、选中确认的实际来源；动作正常返回不等于选择成功，layout effect、局部 frame 和输入 gate 不冒充 compositor 呈现或业务输入 ACK。只观察原动作，不改变资格、异常、焦点、身份、工作面或已保留输入。
- 显式短时 timeline 沿原公共 metrics owner 和准确 Renderer 五字段目标取得原生调试会话，采集 Style/Layout、Paint、调度与合成等已启用类别的原事件，保留实际参与进程、原时间单位、采集窗口、丢失与停止／释放事实。协议采集完成与目标事件覆盖分别表达；原材料没有目标 Renderer 事件时明确缺测，保留原 trace 与完成回执，不把其他进程事件作为目标成本，也不自动重采。它的范围是 Chromium timeline，不保证全部 Host、全部 App 子进程或 native 栈；跨进程与业务事件仅按原时间基准及明确来源关联，时间重叠不等于因果。
- timeline 与普通查询分开，计划采集 1–5 秒、原请求返回完整有界 trace，CLI 仅写明确的本机新文件；不截图、读堆正文、自动上传或随 watch 常驻录制。完整编码结果的输送上限为 8MiB，包含压缩材料、编码膨胀与元数据，不冒充原生生成峰值内存上限或所有负载都能成功的保证；超限或原生丢失明确保留阶段、实际字节与清理事实，不截断成成功。已有 DevTools、debugger 或原生 tracing owner 占用时只拒绝本次采集，不接管或停止它；未确认属于本次会话的录制不由本次停止，取消、换代与迟到回执不得改采新目标或冒称清理完成。
- timeline 输送保留平台原生压缩流及完整原始 JSON 字节、根元数据和摘要，不为传输重建或筛减事件。原生录制完成、流的明确 EOF、字节校验、原目标复核、流关闭确认和调试资源释放分别有据可查。公共 CLI 仅在显式本机输出时解压校验，完整成功后才发布新文件；GUI 的独立采集与现场详情均按显式动作导出同一压缩原件，不在打开、刷新或绘制时解压整份 trace。现有现场存储与部分成功语义保持；旧材料版本不可读时明确说明并保留原件，不自动迁移或重采。
- 持续动态可沿同一准确 Renderer 目标显式单次查看平台动画实例，Performance 与公共 CLI 消费同一 metrics owner。读数保留原名称、播放状态、时序及有界的元素标签，并明确省略与截短；已知无限循环、自动时长与未知数值分别表达。只观察当前文档，不扫描正文、读取元素 ID、测量布局或更改动画，不接管已有调试器；打开面板和普通 watch 不触发枚举。结果保留原来源、实际求值完成与取消／失配的未知事实，失败不影响已有工作面。实例存在、播放中或名称相同均不证明 CPU 成本、实际可见或 Runtime 状态，须与原时间线和局部前后测量核对。
- 显式函数采样与普通资源观察分开：公共 Renderer V8 profile 请求绑定准确窗口、WebContents、Renderer 代次、PID 及创建身份，计划采集 1–5 秒，沿同一请求返回完整有界 profile、实际采集区间与停止／释放事实；CLI 可将原 profile 保存到明确的本机新文件供离线读取，不覆盖已有文件。它不自动随查询、watch 或 Toolkit 展示启动，不提供断线后的 handle 找回、跨重启 profile 历史或自动峰值采集；未知回执与本机写出失败不自动重采。
- 函数采样只临时取得空闲的原 Renderer 调试资源。原 DevTools／debugger 占用时只拒绝本次 profile，不关闭、借用或替换原 owner；目标换代、取消、超时与迟到结果不能改采新进程或释放后来 owner。停止请求、原生停止 ACK 及 detach 确认分别表达，未知不冒充已释放，不影响原指标、工作面、焦点或健康 Run。请求沿既有公共授权，不因 profile 可能含路径新增 caller 类别禁令。
- 原始 profile 可能含函数名、脚本 URL 与本地路径，仅在明确采集的原请求中返回和按用户指定本机文件保存，不自动上传或写入普通错误日志，不额外读取 Terminal、Prompt 或历史正文。单次 profile 输送上限 8MiB，元数据另有有界空间；超限如实给出原字节量、阶段和清理事实，不截断调用树冒充成功，也不把结果输送上限当作原生生成时的峰值内存上限。采集区间及原 Profiler 时间单位明确；它仅覆盖原 Renderer 主目标 V8，不代表全部进程、native／compositor／worker CPU，不将样本占比或墙钟当作进程 CPU 秒或优化收益。
- 用户要求「性能指标在右下角的观测面板看不出」「ctxmux 的泄漏管理应该也能看出来」。观测面板必须分清应用、Agent CLI 和 ctxmux：应用按 Main、Renderer、GPU、Browser/Utility 显示 CPU 与内存，Agent 按现有 Run 归属，Runtime 显示其公开合同提供的 Run、attachment、保留输出及回收事实。不能以应用内存总数代替卡顿来源，也不能从 RSS 高直接判为泄漏。
- 用户进一步反馈「有些 agent 的占用不太正常」「Storage 里面有的 agent 占用都有一个多 G 的内存」。Agent 行必须说明其数值是 CLI 本体还是含后代进程的 RSS，并能按同一 Run 的真实进程归属区分本体与子进程用量、数量；磁盘 Storage 不得被读成进程内存。同一 PID 不能重复归给不同 Agent，归属缺失或 PID 身份不能确认时明确未知。高占用复核绑定实际运行版本、采样时窗、活跃负载与进程树；协作子 Agent 或工具进程仍被活 CLI 持有，不等于无用孤儿，低 CPU、进程年龄与 RSS 高都不能单独授权清理。只有证实的无效保留才在原资源 owner 修复，不能停止、重启健康 Run、删除工作面或以改变用户负载制造改善数字。通用成本与连续阅读的验收条件仍以[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)为唯一来源。
- 进程指标、资源 owner 数量、保留历史容量与回收结果是不同事实；观察时间、CPU 聚合口径、未知/过期与失败原因必须可读。应用与 Run 的 CPU 统一以一个逻辑核占满为 100%，并明确这个分母；应用 CPU 由同 PID 与创建身份的累计 CPU 秒数差分及单调时钟间隔取得，不猜平台核数归一化系数。累计值缺失、重置或窗口未形成时 CPU 保持未知，已成功的内存与进程事实继续更新。应用 CPU 的测量区间平均与 Agent 的平台 ps 平均读数必须分开说明；10 秒读数峰值不能冒充同一种瞬时 CPU。Runtime 缺少公开指标时准确说缺少什么，不读写其私有数据库来补一个假完整面板。
- CPU 百分比同时可读为逻辑核等效（100% = 1 个逻辑核），Host 逻辑核容量来自实际硬件观察，不能用核数猜旧版或未知指标的分母。应用分组可展开同批采样的 PID、创建身份、进程类型与 RSS；明细有界并明确遗漏，分组总额保持完整。分组十秒读数峰值与单进程本次区间平均分别标注，不把各自峰值相加解释父组。二级热度只表达有明确口径的独立强度，未知与过期不能着成正常低负载。
- 当前窗口的 V8 堆观测只读固定大小统计，绑定实际 Renderer PID／创建身份及窗口代次；只在原资源消费链请求时读取。堆已用、堆保留、实际堆内存与上限是该 isolate 的事实，不等于整个 Renderer RSS，也不以 RSS 减堆猜 native、Terminal、Monaco 或 DOM 归属。读取失败只影响该事实。Renderer 的近期同步工作、解析回调等待及输入排队从原有有界时段独立展示，重叠墙钟时长不变成 CPU 份额，owner 数量不变成内存占比。
- 资源观察只在有明确消费者期间工作：UI 展开、一次公开查询或一条公开观察流都属于消费；最后一个消费者离开后停止，慢观察不堆积。一次查询结束、期限到达、消费连接关闭、窗口或 owner 销毁时，属于该消费的监听与采样一起释放，建立尚未完成时离场也不能留下迟到消费。多个消费者共享同一 Main 采样，不按指标、消费者或采样 tick 另起采样或 CLI；Runtime 存储不随每秒 process 采样重读。在途读取即使无法取消，其迟到结果也不回写已结束或新的消费。局部指标失败不使其他指标消失，也不停止、删除或重启 Agent；既有孤儿目录回收与当前 Run 的历史回收分别显示，打开面板或查询不是删除历史的授权。
- 公开资源观察说明所在 Unix Host、Main 与窗口身份；本地进程读数只能归属该 Host 上身份已确认的 Run，远程 PID 或未确认归属不得当作本地真值。Renderer 计数属于具体 connected 窗口及其代次，缺席或旧代次不能冒充当前零值；计数 getter 未建立或读取失败保持未知，其他已确认计数仍保留。Runtime 没有公开 CPU/RSS 时保持 unavailable，不以看资源为由连接、恢复或停止 Run。
- 一次公开查询可以返回各来源尚在形成的首帧；尚未取得当前 Renderer 的回答应表达为 pending，只有对应 owner 的实际失败或观察期限到达才表达 unavailable。成功值与失败各自保留采样发起时的窗口身份；旧窗口的失败不能判定新窗口失败，新窗口的真实失败不能被旧成功缓存遮蔽。释放查询只结束该 reader 的观察，不能据此认定 Renderer 卡死。多个 watch 帧可能只更新其中一个来源；判断 CPU 区间是否形成须按应用来源的实际样本时间与测量区间，不能按传输帧数。各来源保留其实际观察时间、最近成功时间与 pending、unavailable 或 stale 原因；process 新帧不刷新旧 Runtime、storage 或 Renderer 值的年龄。存储读取没有源时间时由实际读取 owner 记录本次观察时刻。公开 watch 只承诺有界最新观察，慢消费者不积压无界帧，停止后旧值只能明确作为历史，不能冒充新数据。
- Terminal 访问、切换、滚动与刷新卡顿的诊断须沿既有公开资源查询和观察取得同一 Renderer 代次的有界成本摘要，区分可见与隐藏消费者的检查、实际变化与渲染，以及终端输出处理与 Renderer 事件循环延迟；不能只报 owner 总数或依赖临时 DevTools 注入才取得这些事实。只输出聚合计数、时长、容量、必要归属与观察条件，不读取或导出终端、Prompt、历史正文及用户输入。采样工作量、耗时、保留量与输出量有明确边界，采样自身耗时及截断、缺测可辨；观测不能成为随无关 Session 或内容增长的重复全量遍历。Renderer 繁忙或未回应仍沿本节来源时效与局部失败合同表达，不延长查询至无界，也不干预健康 Run 或原工作面。 该摘要使用 Renderer 存续期间的有界轻量记录器：固定类别计数与最多 36 条慢事件不持有正文、不新增轮询；主线程长任务与 Event Timing 输入等待监听归 Renderer owner，离场即断开，支持性与失败明确。公开查询与 watch 的周期采样仍只在消费期间工作，不因轻量记录常开而常驻进程扫描。终端写入时长是等待解析回调的墙钟时间，展示投影可见、画布揭示、回放、输入 gate、在途写入及积压分别表达；展示投影可见不等于画布已经揭示或已响应，允许输入不等于输入已响应或已被 Runtime 确认。Event Timing 只统计浏览器实际提供、总事件时长至少 16 ms 的样本，等待时长使用 processingStart−startTime，不能以无样本冒充全部输入无延迟；长任务时长也不冒充输入延迟。
- 顶部已有页签的访问等待按实际呈现面与精确 Workspace／Group／Tab／Region 归因，沿同一公开摘要分别记录事件到 handler 的等待、选中、原 host 放置、终端当前揭示、本地帧与输入 gate 开放时点。缺测保持未知；Activity 等非终端模式明确不适用。已揭示的保留终端读取本次当前事实，不要求重新 attach；快切、重复呈现与旧代回调不能串成另一笔成功。只保留最近 16 次切换，不新增正文读取、全工作面扫描、轮询或输入门禁；本地帧不冒充 compositor 首帧，gate 开放不冒充输入响应。
- 主表面切换沿同一 Renderer 有界记录器保留本次准确表面、原触发来源和本地单调阶段；公开资源查询、观察流与 Performance 的机器结果消费同一事实。底部原生键盘激活仍沿原 click，其他导航不冒充 footer 来源。事件等待、原动作结束、根 App 实际选择提交与本地 frame 分别表达；已提交的同目标明确已有提交，未观察、隐藏或覆盖、快切及 owner 离场保持原 pending／未知或准确结束，旧回调不能补完另一笔。本地 frame 不证明 compositor 呈现、目标内容已完整可读、可继续交互或输入 ACK，仍不能代替真实切换预算验收。不新增轮询、正文记录、常用场景历史库、输入门禁或动作重放。
- Terminal 清理计时沿同一记录器，观察原 xterm 与 WebGL addon 的直接同步释放调用。开始时捕获原 Host、Session、Run、Region 和 Renderer 内终端实例，保留固定操作、实际起止与正常返回或抛错事实；没有 addon 时不制造释放事件。清理记录使用独立上下文，不借用终端写入的字节或回放原因，实例移除后仍按原有界策略保留。时长不是 CPU、驱动后续完成或 Runtime 释放 ACK，也不能单凭与长任务重叠认定因果；诊断不改变原调用顺序、异常、生命周期、输入或释放策略。
- 慢事件按六个固定类别公平保留：每类最近四条、当前及上一固定十秒时段各一条最大值，按事件身份去重，合计最多三十六条，并报告累计合格事件减去当前不同保留事件的遗漏数；高频输出不能挤掉其他类别，后续小慢事件不能冲掉时段峰值详情。同值保留先送达事件。事件发生的 Renderer 单调时点与回调送达时点分开，迟到事件按可信发生时点归属仍保留的时段；更早或未知发生时点的事件仅进入最近记录，不冒充当前峰值。近期统计提供当前局部时段和上一时段的各类次数、总时长与峰值，并标明记录起点以区分首段的部分覆盖；它不是精确滚动十秒，重叠等待不相加为 CPU 占用。查询不重置统计、不新增计时器；无样本与观察停止或不支持须结合来源状态解释。终端解析写入在开始时捕获原 Host、Session、Run、Region、Renderer 内终端实例及 live/history/checkpoint 原因，只保存字节数或字符串 code units；实例每次 xterm 创建从原 Renderer 记录器分配，移动、重挂或晚完成不能借新焦点或新 Run 补猜归属。全局长任务与 Event Timing 没有准确终端归属时保留未知。公开查询、CLI、官方 Performance 和其工作等待展开面消费同一有界事实。
- 慢 Session 事件保留原协议类别及事件自带的 Host、Session、Run 身份；事件未提供的归属保持未知，不遍历当前会话或借当前焦点补猜。Terminal 键盘／滚轮分发和原输入请求等待在发生／请求开始时捕获准确 Host、Session、Run、Region 与终端实例，迟到完成或随后切换不改归属。保留的归属只有有界标识和值，不持有原事件、Session 快照、DOM、输入正文或 Store；公开 metrics、CLI 与 Performance 峰值详情沿同一事实读取，聚合类别、原输入和异常行为保持。
- Terminal 切换出现本地帧后仍待输入 gate 的记录保持未完成，查询给出当前等待阶段和单调经过时长；后续 gate 开放、明确只读、快切、原身份替换或最后一个对应 owner 离场各有准确结束事实。结束后时长冻结，重新注册不能补完旧点击；多个对应 owner 中仍有有效 owner 时不因释放一个重复注册而终止。此状态仅用于诊断，不能改变输入门控、焦点或生命周期。
- 终端已展示后的滚动与打字停顿，沿该 Terminal 实例记录自然可信 keydown／wheel 从事件时间到 handler 的等待，以及用户 onData／onBinary 路径实际接受的客户端写请求开始、完成、失败和在途数量；协议自动回复与独立粘贴路径不计入该用户请求指标。事件发生时的 gate、buffer 与鼠标模式帮助解释输入路由。键盘事件、xterm 输出的输入字节与客户端写请求不能假设一一对应；客户端请求完成不代表 PTY ACK、Agent 处理或回显。时间原点不能确认时保持未知，无样本不能冒充零延迟。不读取键值、正文或 DOM target，不新增轮询、全局输入监听与输入门禁；实例释放后旧请求不能写入新实例的观测。
- 长时运行卡顿的诊断沿同一公开资源观察提供各进程的有界阶段事实：输入排队、当前 Run 查询、实际 native input 调用与包含该调用的 operation 墙钟分别记录；嵌套耗时有重叠，不相加。Core 复用原字节分类，区分用户、完整鼠标报告、粘贴、协议回复与语义请求；Renderer 区分实际提交源 user/protocol/paste，不复制协议解释。Main 与 Core 的进程身份和本地时钟分别标明，不将各层汇总拼成同一输入回执；排队期间的原 Run、内容、顺序与错误仍由原输入 owner 管理。诊断不保存输入正文、键值或自动重放字节，也不引入新的输入门禁。
- 同一终端提交在 Renderer 调用前保留只读关联引用：记录器单次 nonce、实际提交来源与该来源的 started 计数；重挂复用共享记录器，重建不复用来源域。Main 与 Core 原样传递，另记真实发送窗口、原 Host／Session／Run 及执行实例；引用不认证身份、不作幂等、输入 operationID 或字节确认。Main 的连接等待、Host 调用与回复就绪、Core 的排队和原输入阶段只报各自本地单调时长，不跨进程相减、不将嵌套等待相加。
- 输入关联复用各 owner 原 active／recent 固定容量；查询时计算在途年龄，不新增计时器或持续关联索引。保留的重复引用明确歧义，遗漏导致唯一性与最老年龄不完备时明确未知；不能把旧 Run／执行实例的晚回执算到新目标。诊断关闭、引用缺失、生成失败或损坏均保留原输入的字节、顺序、返回与错误；坏的可选诊断字段在原业务编码／严格解码前丢弃，原业务错误仍按原合同拒绝。
- Main 事件循环观察随资源消费者启停，缺测为未知；其测量分辨率与采样等待不能冒充键盘延迟。Overlay 记录固定触发类型、调度合并、候选与几何读取数量、采集耗时和真实 Native Browser 需求；Hosted carrier 区分逐帧编解码与完整值编码／最终解码成本。记录有固定容量，过量明确计数，不形成新的 Runtime 或历史账本。当前 Main 用户目录所在卷的可用与总字节帮助识别写满；它不代表其他卷或远端 Host 容量，读取失败明确未知，不授权清理用户数据。所有来源沿同一公开查询、观察流和官方 Toolkit 结果消费。
- 关闭观测面板、切换页面、销毁窗口或替换订阅时，属于这次订阅的采样与生命周期监听必须一起释放；反复打开不能留下逐次增长的监听闭包。释放是同一订阅 owner 的幂等动作，不依赖下次打开或人工清理。
- 每个资源对象尽量显示所属 Project/Workspace、Agent/Provider 和最近活动/idle 时长；没有归属时明确显示 unknown。资源采样与 Agent 语义状态分开，不能把低 CPU 误判成 Agent idle。信息层级与紧凑布局归 Surface 密度合同。

## Toolkit 与官方 Performance 工具

用户要可自行扩展的 Toolkit：「配置一个工具和对应的图标」，包含脚本、Agent 任务、定时执行和交互按钮；hover 能看执行结果与动作，配置和操作也能通过 CLI 完成。用户随后明确：「toolkit 还是默认在 statusbar 从右往左排列吧，和左侧功能区区分」。用户最新纠正：「设置还是放左边」。Settings 的唯一普通入口回到左侧功能导航末端，使用同一设置导航 owner；打开或再次点击收起既有设置面，不改变当前工作面选中状态、原输入或工作面。Toolkit 仍与左侧功能区分开，位于右侧 utilities group，默认由右向左增长，Performance 位于右端工具位；快捷键帮助与状态提醒留在右侧、位于 Toolkit 左侧。Settings 不留第二个右侧入口；不把设置开合伪装成主工作面选中。摆放方向不改变文字方向、原焦点、原生 Tab / Shift+Tab 与输入语义，不新增排序配置、registry 或 RTL 文本。UI 与 CLI 使用同一配置、执行与结果 owner；普通工具保存配置和只读查看不隐含执行或开启定时任务，声明后的可见求值沿下文[《Toolkit 展示时求值》](#toolkit-展示时求值)，显式 TUI 模式的加载启动沿[《TUI Toolkit》](#tui-toolkit)。未交付触发能力须明确其实际范围。

用户进一步确认「performance 就属于一种内置 toolkit」，要求所需查询信息开放 CLI，官方 Performance 通过脚本组合这些 CLI 完成。该脚本随产品发布，可查看但用户不可编辑、覆盖或替换其内置身份；展示内容、启停、样式与布局可配置。Performance 真实经过公开查询、官方脚本和通用 Toolkit 结果展示，不能在 UI 保留另一条绕过脚本的私有取数路径。 Toolkit 的具名类型结果由对应公开 schema 校验，外层包装不得叠加通用 Settings 字段的嵌套深度限制而误拒合法观察；完整结果仍守原消息字节边界和该类型的采样条数约束，不裁剪数据来掩盖解析失败。官方代码只读不等于扩大执行权限；Performance 自身只查询观察。

用户明确要求先提供 Toolkit 标准 Agent 卡片接入能力，再由 Performance 消费。工具通过通用、只含数据的公开结果声明准确的 Host／Session 或 Host／Run 引用及要显示的字段；普通 Custom 工具与官方工具使用同一组件，沿原身份 owner 取得标准头像、名称、Provider、语义状态与工作区，不从显示名、PID 或低 CPU 猜 Agent。字段可配置显示与隐藏，输出不能创造输入、导航或执行授权。卡片所需事实和配置通过既有公开 CLI 可取得，不能只在 Performance 内私有硬接。缺失、旧 Run 或归属未确认明确可辨，不能把后来实例的身份接给原结果。仅相关可见卡片消费身份变化，无关 Session 输出不放大成本。

Performance Runs 在原面板内同时显示可识别的 Agent 卡片与全部已观察 Runs 的 CPU、RSS 汇总；汇总不随前五行、展开、排序或所选 Run 改变。总 CPU 由同批源先合计再按明确时窗聚合，不能相加每个 Run 各自的峰值冒充并发总量；RSS 保留原进程归属和共享页口径。缺测给出覆盖范围及未知数量，过期与暂停仍标为旧读数，不能把未观察到说成零。官方脚本、CLI 结果与界面消费同一事实和通用呈现合同。

用户再次强调「界面和 toolkit 的性能要好好优化」。性能取证覆盖同一条实际执行链的界面呈现、公开查询、脚本、结果解析与消费生命周期；各层只为相关可见消费者做必要工作，不能靠停止健康 Agent 或清空工作面减少成本。资源观察与释放只定义在[《Status Bar CPU/Memory 资源面板》](#status-bar-cpumemory-资源面板)，界面动态与隐藏工作沿《Settings 全分区完成度与相关消费者成本》；低频事后摘要也由原 metrics owner 管理，其他层不建立采样或性能账本。

用户继续明确「performance 界面的设计还是一塌糊涂」，要求真正 Toolkit 化、界面交互发挥全部设计水准。Performance 的第一层帮助用户读懂当前应用与 Agent 的资源占用、观察期间的变化及主要消耗对象；进程树、口径、owner 和 Runtime 存储在具名详情中可达。趋势只使用这次真实观察期间取得的有界样本，缺测或停观不能补假曲线；不同 CPU 口径不合成一个机器负载，RSS 不画成没有总容量事实的系统内存百分比。未知、过期、暖机和观察失败在对应来源就地表达，局部缺失不掩盖其余真实读数。

Performance 的趋势支持悬停、明确点选和键盘阅读原有界采样点的准确数值、单位与采样时刻；CPU 仍按原采样窗口口径，缺测不补曲线或零值。明确选择绑定原执行／Run 与采样身份，新点不抢选择；选中点离开保留范围时如实说明，不跳到另一点冒充原点。切换来源和关闭释放本地阅读状态，不新增 sampler、长期历史或由当前来源补猜旧点元信息；暂停与健康 Agent 语义保持。

Performance 的观察、暂停、恢复、查看官方脚本及显示配置沿同一工具身份和执行结果；暂停只释放本消费者，绝不停止 Agent 或其他观察者。Hover 预览不夺走终端或编辑输入焦点与 selection；点击及键盘可稳定进入同一非模态操作内容，原生 Tab / Shift+Tab 可到动作和具名详情，焦点在浮窗内时不因指针离开而关闭。退出归还本次实际入口；仅 hover 后退出保留原输入焦点，指针移到浮窗操作不会意外关掉。仅 hover 且焦点仍在原 Terminal 输入时，Escape 关闭预览并原样传给终端；显式进入、浮窗内操作或 Settings 编辑输入时，Escape 只关闭最上层工具，不连带关闭 Settings 或丢失草稿。显示或布局配置保留未保存草稿与原字段期望，保存和执行分开，UI / CLI 同一 owner 的冲突与 unknown 事实不可被乐观成功掩盖。

Performance 原执行回执在重启或清理竞态后仍绑定准确 Run。只有 Core 对该 Run 给出已退出或中断的权威状态，才可跳过重复 stop，继续释放附件、移除原工具 Run 并确认清空准入；状态不可得或仍运行时保持 unknown 和原恢复入口，不用错误文案推断终态，也不自动停止健康 Run。清理确认后原 Toolkit 观察入口恢复可用，历史失败证据仍按原故障留存合同读取。

Performance 原准入处于 unknown 时，同一观察入口仍可阅读准确的原执行、Run、失败阶段、错误码与原因；建立状态观察不表示执行或指标采集成功。观察不得隐式重放创建、清除未知准入或另建私有取数路径；明确执行继续遵守原准入边界。已确认失败及终局后的原清理与恢复保持，观察本身的目标、权限、取消或传输错误仍如实失败。

固定官方只读 Performance 的原创建未确认、且没有已确认 Run 时，允许用户明确开启一轮新的独立观察：新调用身份绑定新执行，准确旧执行作为并发前提；原未知准入及原失败保留在同一 owner，可按原执行查询，不改称已退出或未执行。已有准确 Run 的未知状态继续沿该 Run 核对及清理，不以新观察替换。原材料保全和新准入先在同一次持久写入中确认，再派发新创建；同一调用在回执丢失、owner 重建或后续换代后不再次创建。普通打开、watch 及没有该明确输入的 run 不替换未知。原生明确报告准确本次创建 not_applied 时，才可按该回执解除本次创建等待；错误文案、事务未提交、未保留映射或其他操作回执均不提供这份事实。新观察成功只证明新执行的数据，不改写旧结论。

Toolkit 的机器结果与终端诊断使用独立通道。通用 Core `@agentmux/core/toolkit-result-channel` 提供 host 创建与脚本连接能力：host 在执行前建立私有本地 socket 和一次执行凭据，脚本显式连接并提交结果；地址不充当执行身份，Run 关联只来自 Core 创建回执。每个 capability 只接受一个认证字节流，消费者沿原单帧协议校验与回压；取消或关闭回收本通道，不回退扫描 PTY，不创建或管理子进程。原 PTY 输出仍是合流终端材料，不能还原成独立 stdout/stderr，也不能因像 JSON 就认作机器结果。现有用户脚本的文本结果合同保持下文边界；需要具名机器结果的消费者接入这个通用能力。

有限脚本的机器文档消费同一 Core 结果 schema，完整认证帧和 EOF 确认后才沿原执行回执保留。回执未带文档只表示没有保留的具名结果；显式空文档表示机器结果不可用，保留失败步骤，均不从旧终端文本重建。机器结果不可用不改写原 Run 的终态，也不靠停止健康 Run 取得 EOF；已确认终局的原准入正常结束，用户仍可明确重新求值。最近可用文档连同原目标、配置版本和结果时间保留，不被后来缺失或不可用的文档覆盖。UI 与 CLI 消费同一回执，普通文本保持可读，连接工具的缺失结果沿[手机版连接合同](public-control.md#手机版-relay-连接)给出服务窗。

官方观察脚本沿公开协议的单帧预算读取与输出，不自行缩小合法观察范围；输出回压表示等待消费者，不能作为观察失败。等待期间停止继续读取源，恢复后按原顺序处理，内存随单帧与管道缓冲有界；关闭或取消仍只释放本观察者。公开 CLI 的同步订阅输出限制实际积压字节，正常回压仍接纳合法帧；真正超限时如实报告并释放本读取者，显式取消或容量失败在释放订阅后丢弃自身待发送输出，普通结束保完整 flush。Settings 的不透明输入或 Host 数据由叶子 JSON 合同校验，进入 typed 回执或列表不扣减叶子的合法嵌套深度；外层字段和完整消息字节预算各守自己的协议边界。

Performance 原启用与 icon / label 默认、关闭入口不持续观察、手动观察理由与各消费者独立释放保持原合同。有限结果模式的用户工具支持用户保存的本地 JavaScript ESM 脚本、固定目录和参数、名称与图标，普通 UI 与一条 toolkit CLI 使用同配置、执行及结果 owner。保存、显示启用、查看源码、get 及默认 watch 不执行有限结果模式的脚本；普通主脚本和动作仍由显式 run/action 准入，未声明展示入口的 hover 只阅读原结果。关闭浮窗只释放阅读者，在途脚本到真实终局或明确 exact stop。源码可访问当前 Unix 用户本地文件、环境和网络，不承诺 sandbox、权限隔离、secret vault 或自动脱敏；定时、远程和 Agent 任务未交付前不显示成可用能力。持续交互的 shell 脚本使用下文 TUI 模式，不改变有限结果模式的触发合同。

用户要求工作目录支持 home 简写并默认 `~/.agentmux`。新建 inline 与本地包工具的目录均真实预填该默认；inline 目录仍必填，公开包安装省略目录时使用同一默认。目录接受绝对路径、`~`、`$HOME`、`${HOME}` 及这三种 home 写法的 `/…` 后缀；由准确执行 Host 提供 home，Core 的同一纯解析能力供保存与界面预览消费。只展开该前缀，其余内容按字面路径保留，含空格不要求 shell 引号或转义；不执行 shell、不展开任意变量或通配符、不接受相对路径，也不消除 `..` 而改变符号链接路径语义。保存固定的绝对路径，已有配置不迁移，在途 Run 继续使用准入时捕获的目录；目录修改只影响下一次执行。

GUI 与公开 Toolkit 创建、更新、安装共用原配置 owner 的目录解析，回执返回已保存的绝对目录；更新与删除的字段期望使用同一规则比较已提供的目录，不给部分期望补默认值。格式错误具体到目录字段及原因，保存失败保留草稿，不只返回内部校验代码。保存不新增目录存在性或访问探测门禁，不自动建目录；实际运行时的不存在、非目录或权限失败由原执行 owner 如实报告。目录选择只返回本次用户明确选择，不登记 workspace、不保存配置或启动执行；取消、失败与迟到结果不覆盖后来输入或另一工具草稿。该原生人机选择不另设 CLI 同义动作，公开读与 watch 保持原合同；界面未取得 home 时明确预览未知，仍可交由 Host 保存。

工具图标是可保存的用途标识，不表达运行状态或授予执行能力。Desktop 的 inline 配置、本地包 manifest 校验、选择器与状态栏消费同一选择目录和保存值；Core 保持通用字符串合同，既有 CLI／RPC 沿原配置与读取路径传递。目录复用共享语义图标的名称、绘制与主题覆盖，原 `toolkit.*` 身份不改绑；文件、目录、磁盘、分支、处理器、网络、Host、数据库与笔记等用途复用对应对象语义，不在 Toolkit 复制字形或另设图库。搜索与选图仅编辑原草稿，清空筛选、无结果和关闭选择器均不丢失当前选择；保存边界沿原配置 owner。

Toolkit 设置以同一层级的工具列表呈现内置与 Custom 工具，按来源分组。Auth / Account usage 是预装到用户本地配置中的普通 Custom 工具；预装的是独立本地扩展目录、可编辑源码与普通包引用，产品界面消费当前用户配置与本地 manifest，执行读取当前包文件，不在 Renderer 保留一份固定账户业务对象或以“采用模板”为进入它的前置。首次完成预装后，它直接出现在 Custom 分组，与 Performance 等内置工具平级；是否在 status bar 显示沿其本地显示配置。名称、图标、源码与动作在包文件中编辑，启用、显示、固定工作目录和运行参数沿同一配置 owner 保存；整个包可改为完全不同用途，编辑器、列表和结果明确其 Custom 身份。产品只持有通用 Toolkit 加载、配置、执行与结果，账号观测业务由用户脚本持有。后续用户编辑、删除与其他工具内容均完整保留，不能因启动或升级覆盖、重复添加或复活已删除配置；首次安装与已有用户的一次预装须沿同一配置 owner 明确处理，不从空列表猜删除或安装历史。检索词只帮助查找，不代表已取得或验证实时鉴权状态。查看源码、保存及默认订阅不执行用户查询；未声明展示入口的 hover 保持只读，预装也不等于执行。目标未配置时在原工具处明确说明，不猜账户或伪造结果。显式工具目标仍精确直达，缺失目标不替换成另一个工具；切换保留未保存草稿，明确取消新建只撤回该工具草稿、不影响其他工具草稿，删除或取消末个用户工具回到自定义创建空态。官方 Performance 在内置分组清楚可达，保留原不可编辑身份与可写显示配置。

用户进一步明确：「这个不是写死的……完全是用户可以基于 toolkit 自行实现的一个 example」，示例工具可在与 AgentMux 无关的 GitHub 仓库独立开源和维护。AgentMux 只提供通用配置、执行、结果与动作消费；账号查询、额度／重置卡解释和外部工具适配属于示例源码，不进入 Core 或 Main 的业务分支。示例接入遵守公开 Toolkit 的脚本输入、结果和配置合同，无需注册产品专用身份或修改 AgentMux 源码；产品随附配置在新用户首次本地配置初始化时预装为普通用户工具；既有配置不因启动或版本变化被补回或覆盖，已有用户的明确预装沿原公开配置写入。预装不赋予额外权限，也不把独立仓库自动发现、安装或同步描述成已交付能力。

额度窗口的剩余量与自然重置时间、余额、可用重置权益及每项的发放／到期时间分别表达；数量、时间、状态、来源或时效缺失时如实未知，矛盾历史不伪称可信总数。执行完成时间与来源更新时间分开，绝对时间保留可辨时区，快照中的倒计时明确其观测时间；不把缓存成功说成 live 成功，不把卡片到期说成窗口自然重置。账户与查询范围来自保存的脚本和参数，不由 UI 当前焦点或显示名猜选；旧结果不暗换目标。预装脚本默认观察 codexL 全局当前账号，以该查询明确返回的 active_account_key 精确匹配；未返回该身份或匹配不唯一时说明未知，不选择第一个账户，不冒充任何 Agent Run 的账户。预装账号脚本只调用已有公开外部工具，适配位于用户可编辑源码；Core、Main 公共机制不增加厂商分支、第二份账户／凭据存储、registry 或 sampler。首版只提供手动观测，不预置续凭据、切号或用卡动作，不自动执行、后台刷新或定时启用；相应动作以后独立审阅真实公开协议与权限，不能从结果文本产生命令或授权。可权威确认的外部查询失败沿原工具 failed 结果表达，来源字段未知在本次有界文本中就地说明；观察、终局或持久确认未知保原确认事实及必要准入，健康工作面不受影响。恢复沿原配置、执行结果和工作面合同，不新增上一成功快照缓存或结果历史。

用户工具每次准入捕获不可变配置 revision、固定目标和明确 invocation；相同已保留 invocation 复用原请求身份，已确认结果只返回原事实。尚未关联 Run 的普通在途请求，仅可由匹配原完整参数的显式 run/action 继续原创建操作，并使用原捕获定义与包快照；原 Runtime 仍保留该创建操作对应 Run 时复用同一 Run，不产生第二次执行。原 Run 已不再保留时，显式继续可能现在执行原请求，动作及 CLI 说明须在执行前明确这个边界，不能伪装成只读检查；失败或冲突仍保 unknown。普通请求无保留事实时不猜重放，其 unknown 只限制普通 run/action 新准入，不阻挡独立展示求值，也不停止健康 Agent。修改只影响下一次，disable 影响显示与新准入；普通执行或展示求值尚在 pending/running/unknown 时，工具删除沿 UI/CLI 同一持久提交与执行准入完整性拒绝，不以删除配置假装停止。动作仅来自已保存配置，绑定原结果 execution/config 和目标；配置、动作、目标或最新确认结果变化时旧按钮明确冲突，展示数据与输出文本不能创造命令、权限或悄悄改绑旧动作。

用户点停止只针对原捕获的执行。Core 拒绝停止后不能留下“正在停止”或未被接受的 stopped 标记；脚本已自然结束时，只根据同一 Run 的公开终态与 exitCode 确认终局，有限结果模式还须确认完整输出后回收，TUI 的画面保留沿下文合同，不把后来一次停止请求改写成终止原因。停止回执与终态观察并发时也守同一事实边界；确认不足则保留原准入、旧确认结果与真实 unknown 原因，不猜测错误文案、不自动重放，不影响健康 Agent 的输入。

有限结果模式的用户脚本结果是有界 PTY 合流文本，空结果可辨，不伪称独立 stdout，不执行 HTML/脚本。自然完成以 exact Core 终态/exitCode、authoritative 最终输出字节与完整连续接收事实为准，不以静默、观察退出或动画猜成功；Gap、损坏或终局不完整明确失败/unknown。工具 owner 保有限最新确认结果与必要在途准入，仅在关键点持久，不按输出片段写盘；准入先于执行持久确认，结果先于回收持久确认，保存失败保旧确认事实及必要准入，只限对应工具 unknown。有限结果模式普通退出只回收自己创建的 exact 工具 Run；异常重开保结果与准入，经 exact 公开 Core 状态/replay查证，事实不足不清工作面、不猜删或自动重放副作用，不增加 DB/WAL/daemon。

数据权威、Run 与 Agent 生命周期仍由原 owner 持有；指标、unknown、采样及释放只定义在[《Status Bar CPU/Memory 资源面板》](#status-bar-cpumemory-资源面板)，通用工作量与原工作面保护沿[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)。公开查询、脚本和 Toolkit 自身成本也计入，不能按指标或采样周期反复 spawn 多个 CLI、建立第二 sampler 或每工具常驻 loop。执行脚本与 Agent 任务复用现有 Runtime / Core 能力，不把长寿命 Agent 进程管理放进 Renderer。

结果保留真实执行身份、目标、配置版本、来源与时间；未执行、执行中、成功、失败、unknown、disabled 与过期可区分。普通执行与展示求值的当前原因归本次执行；新执行处于 pending／running 且没有原因时，不继承上一执行的停止或失败原因。旧原因保留在原最近确认执行回执，沿原查询可读；当前真实 unknown、观察或执行错误仍须可见。UI 与 CLI 共用该事实，不按展示文案过滤，也不为此新增历史界面。动作绑定可审阅的内容、权限和原目标；旧结果不能悄悄对修改后的新目标执行，输出文本不能临时产生执行权限，失败或未知不能冒充成功或自动重试副作用。资源查询不授权清理、重启或停止健康 Agent。

手动执行与定时启用让用户能审阅内容、身份、范围和权限，未知权限不自动批准。应用关闭后的定时执行、Agent 完成与结果协议、在途工作修改 / 删除 / 停止、凭据与日志隐私在相应能力交付前明确边界，不预设新后台调度平台。查询余量、刷新鉴权、切换账号仅是用户工具示例，不成为厂商专用核心分支。视觉语言见密度 SSOT[《Toolkit 的入口、结果与配置》](../presentation/settings-and-observation.md#toolkit-的入口结果与配置)。

Toolkit 的 Desktop IPC 是原 Workbench 的本地用户通道。执行、配置、停止及声明后的展示求值均须绑定准确的原 WebContents 与主 WebFrame；名称来源记录、显示位置、可见性和相同标题不能授权，缺少发送者或 frame 保持未确认并拒绝本次调用。拒绝不关闭原工具执行或健康 Agent。公共 RPC／CLI 继续沿原 transport caller 与 Toolkit 执行授权合同，不由 IPC 的展示身份代签。

### TUI Toolkit

用户要求「配置一段脚本，然后 toolkit 加载的时候就直接 run 这个指令，打开的时候渲染出这个脚本的 TUI」。用户工具显式选择 TUI 模式，在保存的固定目录中通过 shell 执行命令；参数作为位置参数传给脚本，不把参数拼接成命令文本。TUI 命令留空或仅含空白时，表示打开准确执行 Host 的默认交互 shell，复用 Core 的普通终端选择能力，不固定为 bash 或要求用户手填 zsh；显式命令保持原执行语义。实际 shell 与包含执行环境在内的完整启动意图沿原准入捕获并私有持久保留；创建回执未知时沿原操作身份与完整原请求幂等核对，不从当前 Host 环境重算或更换请求 key，接回原 Run 不重新选择 shell。敏感启动环境不进入 Toolkit 公开配置、快照、诊断或日志。缺省仍为有限 JavaScript ESM 结果模式，本地扩展包沿既有 JavaScript 包合同。TUI 直接使用终端交互，不同时声明展示求值入口或结果动作，也不增加自动重启、调度或独立执行器配置。

设置中切换 Script 与 TUI 只改变当前草稿的模式及明确确认的相关字段；同一脚本文档继续呈现原草稿正文，不能因语言切换恢复缓存旧文本。Shell 编辑复用原代码编辑器的语言与主题能力，着色不执行、改写或校验命令是否可运行。TUI 的名称与图标沿现有用户工具配置和明确保存，图标编辑入口须可发现，不因 TUI 模式另设图标合同。后续输入、离开再进入与明确保存均消费该原草稿；切换或选图本身不保存、不执行，也不改变固定目标或已有 Run。

每个 TUI 可选择跟随全局 Terminal 配色，或显式选择共享终端目录中的某个配色项；未选择时跟随全局，其他工具与全局选择不被改写。配色项保持原主题合同，Workspace theme 与跟随全局 Terminal 选择是不同含义；不复制调色板或新增主题目录。选择配色只更新该工具的待保存草稿和设置内预览，不立即改写已保存偏好或运行终端；在工具编辑面明确保存后才应用，支持还原未保存选择，切换工具或设置页后返回保留本轮草稿。工具配置与配色共享明确保存入口，但配色单独变更不触发配置更新、执行或新的 revision；部分保存失败分别保留已确认结果与待保存内容，不把另一部分成功当作全部成功。配色及浮窗尺寸是按准确工具 ID 保存的客户端呈现偏好，沿既有持久保存边界保留，不进入工具执行 revision、捕获命令或 Run 事实。配色在原终端实例就地应用，保留 buffer、阅读位置、选区、输入与 Attachment；保存失败保留当前可用视图并说明未确认，不冒称已持久化。

用户明确调整浮窗尺寸后，同一工具再次打开及应用重启沿用该偏好；只有明确完成的调整更新保存值，关闭、普通显示和重渲染不重置。当前视口容不下时临时夹限到可用范围，不能把夹限后的尺寸反写为用户偏好；空间恢复后仍采用原偏好。尺寸恢复不修改固定执行目录、不创建或重启 Run，也不改变其他工具的偏好。

“加载”是 Host 启动时加载已启用的 TUI、创建已启用的 TUI，或把已禁用 TUI 重新启用。每次加载周期至多自动启动一次；创建或启用前须明确告知会运行保存的命令。已有准确 Run 仍健康时接回同一 Run，不再创建；同一加载周期内已确认退出后保留画面和终态，用户可明确运行一次，下一次 Host 加载或重新启用时才再次自动运行。打开、hover、关闭浮窗、重渲染、只读查询和保存已有脚本内容均不形成新的加载周期；保存修改只影响下次执行，不替换正在运行的命令。

Toolkit 沿现有执行 owner 持有工具身份、捕获的配置版本、固定目标、原创建操作与准确 Host／Run 绑定；Core 提供通用 Terminal Run API，ctxmux 继续拥有进程、PTY、历史与权威终态。客户端复用既有 Terminal 的附着、键盘、鼠标、粘贴、尺寸、回放与服务观察，不创建虚假 AgentSession、Tab 或 Region，也不维护另一套终端或执行状态机。TUI 终端持有焦点时，Escape 等原生键沿[Terminal 输入合同](terminal-reading.md)交给程序，关闭浮窗使用明确的宿主动作；仅 hover 未进入终端时保留原输入焦点。运行状态与本地输入焦点分别表达，交互说明不授予输入资格或替代原运行事实。调整浮窗大小只更新同一终端的尺寸，拖拽期间保持面板，保留 Run、Attachment、历史与阅读位置，不重新创建或连接终端。公开配置、发现、inspect、run、stop 与 watch 沿原 Toolkit 业务服务补齐模式和绑定；终端输入与观察沿原终端公共能力，不新增同义 Toolkit 输入命令。UI 和 CLI 读取同一回执与恢复事实。

关闭浮窗只释放该终端视图，Main 退出只释放本宿主观察，健康 TUI Run 继续由 Runtime 持有。首次显示、再次打开或 Main 重启后先核对并自动接回准确原 Run；可恢复的连接失败在同一视图沿[终端连接收敛合同](terminal-reading.md#connecting-与-redraw-必须收敛)自行收敛，未恢复时显式保留服务窗，不要求用户关闭再打开。观察失败、原创建回执不明或 Run 状态未知时保留原配置、准入、绑定和可用终端能力，持续说明失败步骤及原操作恢复入口，不自动重放创建或输入。缺少完整原启动意图时保持 unknown，不补造请求或另建 Run，仍保全健康 Run 与原工作面。已退出、丢失与暂不可观察分别表达，重新执行必须明确产生新执行，不能冒充接回。禁用只影响入口、加载和新准入，不停止健康 Run；Settings 仍可查看该工具并明确停止准确原执行。

TUI 的持续重绘走原终端字节与回放链，不累计为 Toolkit 文本结果，不套用有限结果的输出预算或机器结果通道。终端 Gap、读取失败或显示挂载失败不授权停止健康 Run。进程终局只认准确 Run 的权威状态和 exitCode，与终端历史完整性分别表达；自然退出或明确停止后保留最新 Run、执行回执和可读画面。下一次准入可回收已权威确认终态的旧 Run，清理或持久确认未知时保留原事实，不能误删运行中或状态未知的 Run。Toolkit 只在必要状态点保存绑定与回执，不重复保存终端字节；状态核对定位准确 Run，成本不随无关 Session 的历史或输出增长。

视图与进程分离采用成熟终端的边界：[tmux 的 detach／attach](https://man.openbsd.org/tmux.1)区分关闭客户端与原进程存续，[VS Code 的持久终端](https://code.visualstudio.com/docs/terminal/advanced)区分接回原进程与重新启动进程。AgentMux 沿自身 Runtime 的权威事实兑现该区分；这些参考不构成新进程已恢复原身份的证明。呈现沿[《TUI Toolkit 的配置与终端》](../presentation/settings-and-observation.md#tui-toolkit-的配置与终端)。

### Toolkit 展示时求值

inline 工具和本地包可选择声明独立、可重复求值的展示入口，普通工具默认不声明。声明及实际源码沿原配置／包 owner 可发现、可审阅；它不把普通主脚本或历史 action 变成自动执行，也不宣称平台强制只读或 sandbox。公开 evaluate 与显式选择 evaluateOnDisplay 的 watch 表达展示求值意图，CLI evaluate／watch --evaluate 与界面共用同一 owner；get／inspect 和默认 watch 始终只读，无展示入口的 watch --evaluate 仍为被动观察。官方入口继续守可信 local-user 权限，不能因展示升级 managed Agent 或远端设备权限。

同工具、准确目标和有效版本的可见消费者从零变为非零形成一个展示周期，包括 hover 真正展开、点击和键盘进入；展开前的 pointerenter 不求值。每周期自动求值一次，加入已有周期、重渲染或从 hover 转为点击不重复；多个消费者共享同一在途工作。用户明确刷新可再次请求展示求值，仍共享在途项。隐藏、关闭或销毁只释放本读者，不轮询、不停止普通动作或健康 Agent；下一周期或再次授权求值遇到在途／unknown 展示时接续原身份与原捕获内容，不堆新 Run。

展示求值复用原 Toolkit owner 的 Runtime 执行与恢复算法，分别保留展示与普通 run/action 的目标、版本、准入、执行身份、状态、时间及有限最近确认结果，不建立第二 Runtime、Renderer runner 或结果历史库。任何一边成功不结算另一边的 unknown，旧 action 未确认不阻挡独立展示，展示缺测也不封闭普通动作。求值期间或失败保留旧展示及原时间，版本／目标改变后旧值只作明确历史；必要在途身份、原快照与终局确认沿既有持久／恢复合同保全，不能因展示缓存被释放而遗失原 Run。

手机连接是 Performance 之后的第二个官方 Toolkit，在同一 Built-in 库中管理，默认显示在右下角工具区，并可保存启用及 icon／label 呈现配置。手机工具以随应用交付的 manifest、入口脚本、展示入口和具名动作注册为只读官方扩展，经公开 Toolkit 发现、脚本查询、原 Run 执行与通用结果显示消费原 Host device.ls/link。真正展开按通用展示合同读取当前设备事实与 offer URL，不创建邀请或改变授权；查看源码、保存配置和显示开关不求值。浮窗围绕“连接手机”组织扫码或复制与最近核实的设备状态，不嵌入设置管理表单；设置独立承担完整设备、撤销与活动管理。二维码、复制与完整原文的同次 URL 及回执边界沿[《手机版 Relay 连接》](public-control.md#手机版-relay-连接)，复制不重新求值。旧展示注明时间，不能冒充当前已核实；用户可明确刷新展示。关闭入口只结束当前观察，不撤销设备或停止健康 Run。手机 Toolkit 不持有第二份授权、活动账本或 Runtime，未配置和观察失败就地保留事实并提供设置入口。

原显式生成请求的执行结果 unknown 不代表手机断连，也不覆盖或阻挡独立展示的设备事实与当前链接；连接观察与操作结果分别保留来源、时间及未知范围。用户可明确继续原请求，资格、身份与可能执行的边界沿本节普通执行合同，不换新身份重做或清空准入。仅查看、hover、订阅或恢复工作面不得重放旧 action；原配置、目标、准入与已确认历史保全，新展示成功不为旧请求结算。持续说明实际未确认步骤和可用的核对／继续动作，不因执行观察缺口关闭健康 Agent 或原工作面。

### Toolkit 本地扩展包

Toolkit 包是独立本地扩展目录，manifest 声明名称、图标、脚本入口、可选展示入口和结果动作，目录可独立分发到其他仓库。安装后的业务源码以用户本地包文件为唯一来源；AppConfig 只记录安装位置和该工具的启用、显示、参数及固定执行目录，不保存一份源码副本。Auth 是预装可编辑的用户包，Performance 为系统维护的工具，同层展示，来源分组不成为不同执行平台。

查看源码、安装、启用或修改配置不运行包。修改包内文件后下次新运行或展示求值重新读取；公开 inspect、script、run、action 和 evaluate 都使用同一个真实包 owner；CLI `toolkit install <id> --path <directory>` 复用原创建业务。每次准入捕获配置及包内容身份，本次执行使用已捕获的不可变源码；文件改变使旧 expected 或旧结果动作明确冲突，不静默执行另一版本。unknown 回执仍保原执行身份，普通请求不自动重试，展示接续沿通用展示合同，不停止健康 Agent。已有用户创作脚本、工具 ID 和结果保留；删除的是错误的 Auth 模板前置流程，不能据此丢弃用户数据。

包 manifest 使用 `agentmux.toolkit.package.v1`，声明名称、既有具名图标、相对入口与结果动作；当前文件集有界为 128 个普通文件 / 1 MiB，保相对导入布局。每次运行的文件快照由本地 owner 持有，源码或配置改变产生新的有效版本；在途与 unknown 的快照保留，只有精确执行终局和 Run 清理已确认后才回收。外部命令、环境和动态查询仍属于当前用户环境，不承诺沙箱或全环境可复现。原 inline 脚本创作仍是有效能力，但包安装不把源码副本写入 AppConfig。

- **Performance 失败证据沿原 owner 读取**：原 Toolkit `inspect/watch` 返回失败发生阶段、原异常、原执行与已确认 Run；当前 Run 被正常清理后，失败引用仍归原执行。外层 LF/JSON、typed payload 与脚本内 CLI/RPC 是不同来源，不能从相同语法文案猜阶段。普通读取既不采原字节，也不返回已留存的原片段、stack 或任意诊断原错误文本（含诊断读写与 cleanup message）；安全投影以 `null` 表达未返回的原文，保留结构化阶段、来源、错误码和已知事实，既有执行 `reason` 语义保留。读取原材料须独立显式请求 `includeFailureEvidence`（CLI `--failure-evidence`），安全投影仍标明未取得、已留存但未返回或已返回。显式新观察的 `captureFailure` 可保有限片段、准确范围与缺段，已有观察不为取证被重启或停止，消费方核实际开启状态。只保原 Performance 最新失败，写盘最多一个在途和一个可替换待写项，被新材料替换的待写明确计数，不因慢盘无限积压。诊断写入/读取和 cleanup 问题与 primary 分开，保留原操作、错误码及确知的替换前后阶段，缺证为未知；运行事件保原来源、时刻及 Run，不猜 attach 因果。内存留证、当前写盘 ACK 与重启后实际读到的文件各自表达；留证失败不封闭健康能力。这不是任意 Run 原字节入口，也不改变 Runtime 权限。通用记录与跨领域读取边界沿 [Diagnostic Evidence 设计](../diagnostic-evidence.md)。

## 资源与 Activity 观测
Status Bar 的资源面板必须能把每个进程关联到项目/工作区、Provider 与当前 Agent 状态；空闲时显示可理解的 idle 时长。资源数值与 Agent 语义状态分开，缺失数据保持未知。Activity 展开行只补充能帮助定位的上下文，不重复左侧 Agents 入口。

## 验证进程的资源归属

- 用户内存有限，验证失败、超时或中断后不得留下 Electron、文件 observer 或测试 Runtime；runner 报告结束前必须确认本次进程已退出，不能把一条超时日志当作进程结束。一次验证未完成回收，不得再启动下一份 Electron 验证。
- 清理只针对本次验证的进程组、独立临时目录和 Runtime 身份，不影响正式应用和用户 Agent。观察失败必须明确报告，不能当作零残留；先回收进程，再删除它们依赖的临时目录。
- 文件 observer 属于创建它的应用进程；宿主异常退出也必须终止观察，不能成为长期存活的孤儿。此约束不改变 ctxmux 对用户 Run 的持有和恢复语义。

- 验证模式的启动落点只决定初始选择，不能持续覆盖用户或 probe 随后的 Workspace 切换；测试模式不得使项目切换失效。

- 文件树跨 Workspace 的验证事件必须按操作和 Workspace epoch 归属；挂载重建不许复用聚合 DOM 计数推断一次 mutation。Move 提交只产生一条权威 receipt，旧 epoch 的刷新明确记为 rejected，Stop 对已消失 Run 归入幂等终态。

- Tab 在 Tab Group 中的排序／移动与 Tab 内 Region 分割是不同动作，准确身份、方位和可行性统一遵循[《Tab、Tab Group 与 Region》](spaces-and-layout.md#tabtab-group-与-region)；本页不另设“Region 内排序 Tab”的模型。

## 全局通知与底部状态入口

通知中心收起时保留原通知 owner、未读状态、徽标与必要公告，完整列表和详情只为正在阅读的展示构造；再次打开仍读取同一原记录和当前事实。短标题与可访问名称遵守同一摘要预算，不为短预览完整物化诊断正文；完整原因、身份和复制内容保留在原记录及明确展开的详情中，不因摘要相同合并不同事件。行标题与公告均有短摘要预算，提供了 summary 也不旁路公告预算；关闭中心可重置行的临时展开与复制反馈，不重置原记录、阅读事实或重放复制。

- **统一通知入口。** 全局异常、环境或连接服务提醒、操作失败与 Agent 服务异常通知共用底层通知投影及固定系统通知入口，不各自追加常驻横条。状态栏只保留一个系统通知按钮，徽标唯一表示未读的原问题或事件数量，不同时叠加红点，也不承载滚动错误文本。打开入口的可访问名称说明未读与当前问题数量，两者不混成同一个计数；Focus 的待答数和 Dock 注意力徽标仍归各自原 owner。新提醒可短暂呈现不参与布局的轻量提示；关闭或提示结束后，原问题与可执行恢复入口仍能按需查看。已确认正常时保持安静，通知不阻断健康 Agent，不挤占终端阅读和工作面。
- **通知与权威事实分离。** 通知保存原来源、准确对象、失败步骤、已知状态、原因与恢复入口；Runtime、Provider、连接及操作 owner 继续持有业务事实。全局系统问题与单个 Agent 的作用域明确。读取失败保持未知，通知缺席、已读、关闭或清空历史都不证明问题解决、Run 终止或能力失效；通知文本不能授予输入、恢复或自动重试资格。 原 producer 尚在结算的持续提醒与新的普通事件分别保留；普通事件不得替换该 producer 的关联事实或取消原恢复观察，原 producer 结算也不得清除独立事件。
- **失败按原对象保留与结算。** 不同 Launcher Region 的启动失败、准确 Host／Session／Run 的恢复失败与原生身份确认失败分别保留，局部恢复服务窗和全局通知消费同一份原失败投影。后来的普通报错、其他对象失败、已读或历史清理不能撤掉原重试入口。成功回执只结算该次操作开始时捕获的原记录，不能清除后来一次失败；原生身份问题仍只由原 owner 的准确身份与持久确认事实结算。中心须能分辨同文案失败的原对象，保留完整归属；原位置不可确认时如实说明，不猜当前展示位置。
- **分类与等级分开。** 分类按来源分为系统、连接、Agent、操作，用于筛选和辨认职责；等级按原证据分为确认故障、流程降级、未知、信息。确认故障只用于原 owner 已证实目标能力或进程故障；流程降级表示流程某环节失败而原能力仍可用；未知表示当前事实不足；信息不假装成问题。分类与等级不能从报错文案、图标或颜色推断，不以未知冒充死亡，也不因分组改变恢复资格。中心保留原分类和等级，按确认故障、流程降级、未知、信息的顺序稳定排列，同级保留原有稳定顺序；选择筛选不修改原问题、未读或恢复状态。
- **当前问题与活动记录分开。** Current 只呈原 owner 尚未解除的当前问题；Activity 呈普通操作与事件记录，两者有独立数量和明确切换入口，默认先看 Current。按系统、连接、Agent、操作筛选同一投影，不建第二份业务 Store。首层按准确原对象组织，同一对象下的独立问题仍各自保留；缺少对象时明确来源或对象未记录，不把所有未知来源合并成同一对象。每项先表达主要影响、可辨认对象和一个真实下一步，完整身份、失败步骤、原因与原回执按需查看。分组数不冒充问题数，活动记录的存在不证明故障仍在发生。
- **CLI 沿诊断入口只读查询。** 通知查询复用原公共诊断入口及通知 client owner，提供有界列表和准确条目详情，与 GUI 消费同一来源、对象、分类、等级及阅读身份；面板收起不影响读取，不另建通知 Store、日志档案或顶层命令域。查询返回实际读取的 client／窗口范围，Current 与该 owner 当前保留的 Activity 分别表达，不声称涵盖全部 Host、窗口或持久历史。准确通知引用只用于复查原条目，不冒充 logId 或业务操作身份。默认安全投影、显式原文、读取预算与缺证语义沿[诊断协议](../../specs/diagnostic-evidence-protocol.md)，具体命令及字段归[公共能力源码入口](../../specs/public-capabilities.md)；不从展示文案推断业务事实。CLI 读取不标读、不清理、不打开面板或改变焦点，不探测、重试或恢复原业务。原 client owner 未提供当前投影、不可达或只取得部分来源时如实返回 unavailable／unknown／partial，空列表不能替代缺失观察，也不因此改变原通知、健康 Agent 或用户工作面。
- **按问题收敛。** 同一来源、准确对象与同一失败的重复观察更新原提醒，不追加通知、不重复弹出；只有原 owner 的明确关联才能合并跨对象问题，不能按展示文案正则猜同因。不同对象和独立失败保持可发现，聚合首层不丢原始原因及受影响范围。普通事件保留来源、准确目标及原事件或操作身份；缺少原身份时保留独立接收记录，不因正文相同吞掉另一对象或另一操作。重复次数仅在原 owner 明确确认重复观察时累积。发生时间沿原证据；只有客户端接收时间时标明接收，缺失时间不补造，观察刷新时间不冒充新事件时间。
- **已读、收起与解决独立。** 打开或关闭通知中心、切换分类以及滚动列表不批量标已读，面板打开期间到达的新项仍保持未读。显式展开某项详情或执行该项的标读动作，只确认这一准确问题当前版本的阅读；提供含义清楚的批量标读，范围为当前所选视图及分类中的条目，不包括隐藏的其他分类或另一个视图。局部与全局展示同一原问题时共享其稳定阅读身份，展开或收起局部提示不会要求用户在另一处再次确认同一版本；无法证实同一身份时不跨对象传播已读。内容有实质变化时重新标记未读，重启后同一已读问题不反复打扰。持续问题只能由原 owner 的明确恢复事实解除，事件历史可以单独清理。准确解除一条持续问题时同步解除该条阅读事实，之后同对象同原因重新发生的失败仍应未读；不借此清除其他问题或普通历史的已读事实。失败后的原 Session、请求、历史、草稿与可用能力保留。
- **触发以原问题变化为界。** 新的原问题、原原因或等级的实质变化，以及原 owner 明确解除后的再次发生，才形成新的未读提醒；时间、游标、探测次数、组件重挂载、临时空投影和反复读取不是新问题。重新展示或从局部跳到全局不重新触发提醒。窗口内被动服务提醒不自动升级为 OS 横幅；后台 Agent 的完成、待答、失败及 A2A 来信分别沿原注意力和来信 owner 的新事件规则，不对每次技术观察投递 OS 通知。
- **回执不复制诊断历史。** 窗口事件的已读身份采用固定长度的稳定摘要及阅读事实，完整规范输入仍区分原来源、准确对象、Run 和失败原因，不按裁剪后的展示标题合并。完整诊断只留在原问题与窗口事件详情，清理事件历史后不借已读回执永久重复保留正文。既有已读事实在当前阅读 owner 中统一规范，格式压缩不改变阅读结果；不为容量上限静默删除未读、当前问题或恢复事实。
- **局部恢复靠近对象。** 编辑草稿、权限请求、Browser 呈现恢复等需要就地动作的表面保留原入口，采用同一紧凑提醒语言并按需展开原因；不能用全局中心取代必需的局部恢复，也不能在全局和局部各铺一份完整错误。Focus 的全窗注意力明细、系统通知设置与原生 OS 投递仍消费原[跨会话注意力 owner](#跨会话注意力与系统通知)与设置 owner，不因窗口内统一而另建业务 Store。
- Working、Needs you、Error 的列表入口必须是清晰、一致、可键盘使用的同一类控件；跳转 Agent 与展开列表各自保持明确动作，空列表不提供无效入口。视觉约束见 surface-density 的同名条目。

## 设置页的信息架构

Browser 设置承载统一页面资源目录及自动闲置回收偏好，复用原设置模块、搜索、保存和作用范围表达；状态栏 Performance 提供直达同一管理面的入口。Performance 仍是只读观测工具，释放及恢复由原 Browser 公共 owner 执行，不能把观测脚本变成清理脚本。目录的真实存续、进程归属、保护与动作回执只见[《Browser 工作面》](browser-workface.md#browser-工作面-1)，配置保存不立即关闭健康页面或绕过保护判定。

用户要求研究并优化设置页面的整体结构。设置的层级按用户任务、对象和真实作用范围组织；单个轻量偏好与复杂资源编辑要有合适的轻重，不能按组件或配置键逐个增加一级页面。重组须保留全部既有入口、未保存草稿、原保存范围、对象直达与搜索；GUI 的导航结构不改变 CLI 的对象、配置键或唯一 owner。不把参考产品的作用域或插件平台自动变成 AgentMux 的运行时要求。

Overview 是 Settings 的普通入口，保留 AgentMux 品牌，并提供清楚的重点直达与完整设置目录；侧栏负责稳定、快速地到达分区，两者的层级与用途应可辨。重点直达来自原模块目录的明确产品编排，与全目录指向同一准确分区，不产生第二套页面、身份或配置；不借智能推荐、访问历史追踪或运行状态看板组织首页。完整目录、侧栏、搜索与窄窗分类消费同一模块贡献和稳定顺序；分组精炼不合并不同配置范围，不移除原入口或改变其操作资格。

侧栏分组默认全部展开，用户可明确收起或再次展开，各原分区在初次进入时直接可见。手动展开选择在同一设置工作面内保留；搜索临时展示命中组，不因筛选覆盖手动选择，原精确导航使目标组可见。收起组不关闭已访问编辑器或清空草稿，也不改变当前分区事实；当前入口不在可见区域时，选中材质不能停在其他入口上。窄窗分类继续沿原完整目录提供全部入口，展开不形成新的配置层或持久业务身份。

设置命名保持具体产品与对象含义，不用泛化词替代已有具体名称。Agent 配置与会话恢复的分组及具体入口见[分区、资源与配置生效](#分区资源与配置生效)；本机与 SSH 主机管理使用 Hosts，与其真实 Host 身份一致。Prompts、Survey、Mote Club 与 amux Protocols 保持原名称、用途和归属。导航命名与分类变化不修改原路由 ID、配置键、对象身份或保存 owner。

Survey 的图标与背景提供本地选图、替换和清除，URL 为可选入口；文件读取和预览失败保留原草稿与已保存设置，选图与预览不隐式保存。Mobile 直接提供扫码连接与复制链接，均消费同一原连接链接，不要求先复制才能发现二维码；读取未知保留原设备与恢复动作。Focus 与 Agent takeover 在窄窗和短屏允许就近查看当前草稿效果并返回原编辑控件，保留输入、草稿和阅读位置；预览不获取实际接管权、发消息或启动工作。

显式分区与对象直达不经 Overview，全部既有分区、原搜索与精确 Executor ID 保持可达；普通入口经 Overview 进入具体设置的额外点击不转嫁到对象直达，也不要求完成初始化或等待图像／动画。切换首页、分区或侧栏呈现不丢已访问草稿、阅读位置、原输入节点与焦点，键盘和窄窗操作继续完整可用；配置仍由原 owner 保存。入口摘要准确区分已保存值、资源数量、只读目录与用途说明，不以统一的已保存标签冒充不同事实，也不从摘要推导权限或运行健康。打开首页和切换导航不自动检测资源、启动或影响健康 Run。Settings 仍是辅助界面，原工作面、关闭方式和 status bar 的原操作归属保持，视觉密度引用密度 SSOT[《左下角导航与右下角工具组》](../presentation/spaces-and-layout.md#左下角导航与右下角工具组)。品牌、图像、阅读构图与动态保护归密度 SSOT[《Overview、品牌与阅读构图》](../presentation/settings-and-observation.md#overview品牌与阅读构图)，方案选择不能代替实际呈现评审。

**编译期模块贡献。** 用户在明确当前只是组件模块化、还没有 mod 贡献机制，并听取编译期模块注册的有限建议后，回复「优化」。本轮设置功能应通过编译期贡献组合：功能模块自持导航身份、所属组、标题与说明、搜索词与图标、已保存摘要、原编辑器及精确保存适配；设置壳、搜索和 Overview 消费同一目录，添加或调整小设置不要求在壳或概览另增功能分支。Renderer 与 Main 按各自环境静态组合；不把 React 实现塞入 Main/Core，不宣称同一文件可运行时热插拔。CLI 的既有 scalar 声明按功能领域组合，原统一 get/set 与 Main ConfigOwner 消费；公开读取列表按领域稳定聚拢，原键、默认值、合法值、作用范围、partial/prefix、无改动及持久提交语义保持，不把历史偶然交错顺序当合同。新 AppConfig 字段的类型、默认与持久化验证仍由领域作者明确接入，编译期贡献不替代它们；不新增热加载、第三方执行平台、第二 Store/配置 owner、任意路径 setter 或自动推导 schema/通用表单。全部已注册分区与 Overview 的入口、直接搜索、精确 Executor、已访问草稿/阅读位置、dirty/pending/失败反馈、未访问页不预挂、status bar 的密度引用密度 SSOT[《左下角导航与右下角工具组》](../presentation/spaces-and-layout.md#左下角导航与右下角工具组)，健康 Run 保护仍遵循本节既有合同。

设置页要像一个专业、紧凑的现代工作台：侧栏只负责快速定位稳定的设置分类，页内对象选择与详情表达当前配置任务，主区首屏明确当前设置对象、作用范围、当前值和主要操作。分类、对象选择、详情与保存的层级应清楚，不能靠反复切换不同目录才能理解正在编辑谁。复杂页按用户要作出的决定组织，常用选择先于高级参数；相关选项的前提、影响和相互关系在操作处用简短说明表达，完整语义与必要边界按需可查，不要求先通读协议或实现说明才能完成常用设置。可编辑内容与只读说明分层，重复说明收起到次级层。搜索、键盘导航、窄窗口和保存反馈必须保持可见且可恢复，切换分区不能丢弃未保存草稿。

当前字段的可编辑性、必要输入与生效范围应清楚可辨；本次保存所需条件未满足时，在相关字段或原保存区说明准确原因和补齐方式，不能只以灰色按钮让用户猜测。一个页面含多个保存 owner 时，每项动作标明所保存的对象或字段范围，原事务边界、expected 与保存期间后续输入保持，不为了界面简化合并提交。选择、编辑与校验反馈邻近原控件；已有外观或用途预览跟随同一草稿，明确区分示意、未保存效果与已确认结果。可视反馈不隐式保存，不执行预览所描述的真实业务，也不创建第二份配置或运行事实。

Provider / Executor 的设置采用上述层级，保留本产品的准确关系：Provider 是协议适配声明，一个 Provider 可被多个 Executor 引用，每个 Executor 是绑定一个 Provider 的独立启动配置，已保存的 Provider 身份不能因导航或分组而改变。Provider 上下文、所属 Executor 列表与当前详情应组成同一配置任务，不把二者机械做成互斥的资源页。全局模板与准确接收 Host 的配置清单分别保留原 owner、身份和保存动作，Host 的 Provider 默认与显式注册来源保持可辨；Host 注册成功只能确认本次提交的快照，不能清空回执前的后续输入；原回执版本只用于同一准确 Host 连接配置与 Executor ID 的下一次明确提交，目标改变不得沿用，失败或结果未知仍保留草稿且不自动重试。Provider 分组不把不同范围合并，也不把本机声明当作远端事实。参考界面的同名对象不改变本产品身份、配置范围和原保存语义；目录读取、检查与编辑状态分别表达，沿本节既有草稿、检查与保存合同，不把视觉重组扩大成新的配置或运行时能力。

### Browser use 与 Agent 操作呈现

Settings 为 Browser 提供独立的 **Browser use** 组，收拢原基础设置与 Agent 操作呈现。原自动化、应用链接选择、页面资源和外部连接等能力保留准确对象、配置键与作用范围；导航、搜索、Overview 和窄窗分类消费同一模块目录。分组不新建 Browser、配置或权限 owner，也不把管理动作变成外观开关。

- Agent 操作呈现可配置虚拟鼠标与讨论浮窗的显示、指针 tween、真实点击波纹，以及内发光的颜色、叠加、动画和宽度。合法值、默认与实际范围由同一字段源码和公开配置查询持有；修改这些偏好不取得或撤销控制权，不停止 Agent，不延长实际动作或改变任务结果。虚拟鼠标、波纹和执行反馈仍只消费原 Browser 的准确动作事实，位置未知不伪造。
- 显示偏好不是能力门禁。隐藏鼠标或讨论浮窗仍保留操作者与控制状态、可发现的消息和显式接管入口；关闭浮窗不清草稿或在途输入，用户可以明确重新打开。tween 关闭时保留真实静态目标，减少动态效果下保留可读身份与状态，不由配置强行恢复运动。输入隔离与本人批准仍只沿[Browser 控制合同](browser-workface.md#agent-操作可见性与输入隔离)。
- 编辑区内嵌实时模拟，用户调参即可比较当前草稿的效果。模拟与真实 Browser 消费同一配置解释和效果绘制原语，明确标为模拟；它不连接或创建 Browser／Agent／Run，不导航、发送消息、接管网页或读取实际网页内容。模拟自身的动作不作为真实操作回执，保存成功也不证明真实页面已经渲染该效果。
- 预览只表达未提交草稿，持久配置仍沿原明确保存、expected 合并、冲突与未知回执合同。原字段、保存期间后续编辑、已访问分区草稿、IME 和焦点保持；GUI 与原 `settings inspect`／`settings set` 消费同一 Main ConfigOwner，不另建预览配置 Store 或任意 CSS／脚本 setter。设置隐藏、关闭或 document 不可见时，模拟停止自身动画和监听，不增加无关 Browser／Session 的热路径工作。

本节定义用户已确认要求，不宣称当前源码或安装已支持；[呈现合同](../presentation/settings-and-observation.md#browser-use-与实时模拟)持有控件层级、预览密度与宽窄布局。

### 会话连续性设置

Agents 中的 Session recovery 模块编辑全局恢复偏好，侧栏、Overview、搜索和窄窗分类使用同一模块目录。恢复时机、等待、自动恢复活动时间窗、确证退出后原生 resume、同一操作的复查次数与间隔沿同一配置 owner 编辑；默认值与合法政策由 Core 的 [continuity policy](../../../packages/core/src/agent-session-recovery/continuity-contract.ts) 持有，恢复资格与执行语义仍归[Session 恢复](session-recovery.md)，设置页不另判 Run 或 Provider 状态。

Automation 提供“Provider 不支持中断识别时，使用退出前 active 状态”的独立开关，默认关闭，与恢复后续行同组。页面明确 Provider 已支持但本次 unknown 不使用该兜底，并展示准确中断的原生恢复成功后只发送一次固定 `<amux:continue />`；正常结束回合、健康接回和 unknown 不主动发送。该标记可能开启一个普通 User 回合，投递不代表模型已经完成任务。技术恢复信息留在操作回执与服务窗，不提供新的恢复提醒或自定义续行正文编辑；历史已冻结正文和未知输入受据保留。Session recovery 保留自动原生恢复的活动时间窗，覆盖退出前活动与已确认闲置，不能只将旧 working 作为不限时恢复资格。

保存只影响下一次准入的新恢复意图，不启动 Agent、不发消息、不修改原草稿或在途已冻结政策和正文。GUI 与 `settings inspect continuity`／已声明 `continuity.*` scalar 的 `settings set` 复用唯一 ConfigOwner，保留首次多字段并发 authored 合并、保存期间后续输入、原字段期望值与冲突；有效默认不回填未编辑字段。具体键和查询入口见[设置目录](../../settings-catalog.md)，不增加任意路径 setter 或第二配置 owner。

### Prompts 的指令库与编辑工作台

Prompts 应让用户先认出要用的正文、看懂到达方式和适用范围，再进入明确对象的专注编辑；同一页的资源列表与单对象编辑台承载这一流程，搜索、选择和窄窗往返保留全库草稿。当前对象不在筛选结果时继续具名可见，不自动切换、删除或覆盖编辑。新增后立即进入可编辑的新对象；普通设置的导航、搜索和直接访问沿本节原合同。

Prompt 是独立的指令资源，Provider 是可修改或解除的适用范围，状态选择与回复卡快捷回复是同一资源可同时具备的使用绑定；这些关系不等同于 Provider 与 Executor 的固定归属。Prompt 配置借鉴上下文筛选、纵向对象选择与单对象编辑的层级，但不因展示用途视图而拆库、复制正文、改变 ID，或新增持久类别与场景。Goals 常用操作继续按原 Prompt ID 引用同一指令库；筛选和视觉分组不改变既有引用、全库保存、发送与排队语义。

名称、关键词、正文、单个 Provider 范围与状态选择仍属于同一条用户 Prompt。新增、重命名、改正文、改范围或状态后，当前草稿有只读使用示意：`/keyword` 与裸词只展开草稿；状态绑定只说明何时出现正文按钮及单击的含义，沿[《按状态配置 Prompt 按钮》](conversation-input.md#按状态配置-prompt-按钮)的发送与 Queue 合同。没有状态绑定时明确只作草稿快捷展开；出现条件不能冒充当前发送能力，示意不执行、不连接 Run，也不提供实际发送动作。追加或暂未知的 Provider ID 保持其原值与明确范围，不被悄悄改成通用。

Prompts 的明确保存动作仍提交全库本次编辑，界面必须让用户看清跨条未保存和待删除的事实，不能把它画成只保存当前对象。关键词和正文必需、关键词在全库唯一，名称可沿关键词作为默认；错误具名到对象与字段，筛选外的错误也能找到原编辑。删除先是未提交的本地编辑，提交成功后才是持久删除，两个结果必须可辨。冲突、外部删除、保存失败或结果未知继续保留原草稿和编辑基线；保存期间的后续输入仍未提交，无关外部字段可刷新 clean 内容，同字段不能静默覆盖。保存与配置 owner、CLI 的完整回执及原工作面保护沿本节原合同。材质、排版与宽窄构图归密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)。

### 全分区一致性与相关消费者成本

同一窗口内关闭 Settings 后再打开，保留已访问分区的未保存编辑与原字段期望值；关闭不自动提交、不默认弹确认，也不把草稿复制成另一份配置事实。未访问分区仍按需进入；关闭期间不截获背景键盘，不保持隐藏弹层或运行可见期观测，焦点回原入口。显式新导航仍到准确分区，原保存、冲突与恢复沿原 owner；此编辑连续性不承诺未保存内容跨进程耐久。

所有真实设置分区都要具有一致的交互完成度，同时保留各页目的、原草稿、expected、保存范围、输入节点、焦点与 IME；视觉层级见密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)，不复制 Prompt 的工作流给无关设置。首页与侧栏整体优化的交付同时复查全部实际注册分区，逐页给出视觉与交互判断、具体问题和有依据的质量排序；核对主要对象与动作是否易认、分组与字段顺序是否符合任务、只读与可编辑内容是否可辨，以及宽窄窗口中的导航、键盘和保存反馈。首页截图、代表页或目录数量不能代签全部页面完成；判断明确实际操作范围，展示证据不代签外部认证、发布或后台业务完成。本次改动引入的问题在交付前修正并复验，原页面的独立改进按其证据确定优先级，不把全页复查扩大为无差别重做。

Settings 的工作量应随真正相关的消费者与事实增长。无关 Session、Host 或 timeline 更新不能持续放大可见设置或已访问隐藏分区的 render、draft reconcile、probe 和 observer 工作；隐藏保留草稿与必要配置基线同步，恢复可见时读取最新相关事实。自己拥有的视觉工作在静止、离场或 document 真正隐藏时收敛或停止；不能通过清空草稿、停止健康 Run、移除工作面或把未知当成功制造性能改善。Terminal 连续阅读与原工作面保留仍以本文件[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)的成本合同为准，不另建常驻 sampler 或 Runtime 事实。

卡顿原因未确认时保持 unknown。性能结论区分 Source、编译 Renderer 与实际加载包，绑定场景、资源规模、采样窗口及非空实际帧、commit、重排和 CPU 来源；CSS 参数、零计数、另一页通过或历史安装身份不能代签实际流畅。先用真正相关更新证明观察器连通，再核无关更新的工作量；不得因性能优化丢掉配置变化、后续输入或真实错误。

**设置与 Prompt 的连续切换。** 用户反馈：「Prompt 界面比较现代化了，可以再高级一点吗？设置界面的液态玻璃好像只是做了下样式，没有 liquid 那种切换和交互时流动效果，可以找找 github 上的高质量参考」。当前分区与 Prompt 对象的选中事实仍由原导航及指令库决定；连续反馈跟随本次明确选择，不能等动画结束才切换，也不能把 hover、反光、迟到动画或快速往返变成另一次选择。搜索、筛选或窗口重排后只表达仍真实存在的目标；目标不在当前可见列表时不画在邻居上，不冒充已经选择其他对象。动效不改变原点击、搜索、分类菜单、键盘与关闭语义。

Prompt 的当前对象、未提交修改与只读使用示意应在同一编辑工作台清楚可辨；对象修改事实来自原全库草稿及编辑基线，不另建“动画草稿”或另一套选中状态。切换和指针反馈保留原输入节点、已访问草稿、阅读位置与原焦点归属，不能为动画重挂编辑器、整页淡出或另建正文副本；新增与窄窗返回仍按原明确动作定位焦点。组合输入期间的反光、重排或动效不得抢焦点、打断组字或触发发送。全库明确 Save、删除与 Undo、原 expected、保存期间后续输入、外部提交与失败恢复沿本节既有合同；使用示意仍只读，不接入 Run。材质、流动与停止边界归密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)。

### 分区、资源与配置生效

远程管理的产品范围、拓扑、Host 连接配置与测试、来源核验和维护入口由 [Remote 管理 PRD](remote-management.md) 持有；本节只持有通用设置导航、草稿与保存，以及 Agent 配置和设备模块的相邻规则。

- 设置结构优化必须落到真实页面。日常 Preferences 在前（Appearance、Notifications、General），Browser 基础设置与 Agent 操作呈现归独立的 [Browser use](#browser-use-与-agent-操作呈现) 组，Message Tool 独立归组，其五个入口沿[本组职责](#message-tool-设置分组)，Agents 位于 Preferences 之后，分组内依次提供 Agent CLIs（安装与原启动配置）和 Session recovery（原会话恢复、复查与重试）；两页沿原分区身份和保存 owner，不再把 Agent 配置呈现为无标题的孤立入口。Hosts 工作台与 Mobile 设备管理归 Remote，Conversation Channels 提供 InApp、Lark 与 Discord 子项，分别面向 App 内对话模式及对应外部对话应用；原能力全部保留，Copied paths 在 General 内与本地数据／诊断分层，原单字段草稿、expected 和保存范围不扩大。统一底栏入口进入 Overview，项目管理沿 Hosts 的原项目入口进入；不新增第二齿轮，显式分区与 Executor ID 仍指向原精确对象；不保留独立 Copy Paths 页面或另造兼容路由。搜索仍能定位路径、`~`／absolute、字号、通知、日志、恢复、Provider 与设备接入。诊断或只读说明不进入偏好保存，不自动触发资源检测或更改健康 Run。

- 用户要求「继续，直到设置界面质量彻底满意」。设置作为辅助界面，第一眼必须是当前对象和动作；Workspace 与 Executor 可按名字、路径或身份检索，大量资源不靠逐条扫读。Executor 常用身份与外观优先，高级启动配置按需进入；已有 Provider 与 Executor ID 保持不可修改，新 Executor 创建后直接进入编辑。改变分组或检查结果不能丢失展开、输入或焦点。
- 设置保存仍经既有公开 API，启动配置的说明应明确针对后续启动，不能冒充已改变健康 Run。高级权限动作保持显式选择，不自动批准；所有分区保留原功能、草稿、错误反馈和 status bar。
- 启动参数的可编辑表示必须与实际 argv 可逆；追加或修改一个参数不能拆开其他参数中的空格、引号、反斜杠或空值。
- Executor 启动配置明确区分单一可执行文件与参数，二者相邻可编辑；可执行文件字段只保存目标 Host 的命令名或字面路径，不作为 shell 命令行解释，含空格的合法路径保留。提供随草稿更新的只读启动预览，清楚反映程序与每个参数的边界；参数未完成时原草稿保留并说明预览尚不可用，不自动拆分、执行或保存。全局模板与 Host 注册沿同一字段语义及原公开配置接口。
- 可执行文件缺失仅报告本次准确命令在目标 Host 未找到及修复方向，不能据此断言软件未安装。诊断保留实际命令、Host、原因和检查状态；GUI、启动错误、JSON-RPC 与 CLI 消费原 Core 事实，不能从空格或展示预览推断控制资格。
- 字体字号等数字设置必须允许清空、选中替换与逐位输入完整值；输入中的未完成值不能被立即钳位或舍入打断。明确保存时才验证有限整数和实际允许范围，非法输入保留草稿并说明原因，不改变已提交值；滑块选择保持合法，外部 CLI 提交、冲突与保存失败仍遵守同一草稿保留规则。
- 外观与终端主题的单选组遵守完整键盘行为：Tab 进入当前选择并能离组，方向键移动并选择相邻项、两端可回绕，Space 可选择焦点项；当前选择与键盘焦点都清楚可见。只给按钮标注 radio 角色而没有相应行为，不算键盘可达。
- Terminal palette 的小预览是静态配色示例，只帮助比较输出与输入的外观，不表示正在运行的 Terminal 或 Agent，也不因展示示例创建 Session、Run 或刷新循环。原选择、草稿、explicit Save 与 expected 合同保持；示例可读性与密度见密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)。
- Executor 与 Prompt 的 CLI 按稳定 ID 明确 list/get/add/update/remove，与界面共用原始编辑基线和配置事实。add 不覆盖已有对象，update 不默默创建；启动参数与环境整项替换并允许明确清空，正文逐字保留，支持的数据 key 不可在成功后静默丢失。外部提交仅刷新 clean 内容，保留 dirty 与保存期间后续编辑。Prompt 的 Provider 过滤可以更换或解除，删空 Prompt 库重启后仍为空；头像 Reset 不能复活旧装饰。
- Agents 已有的可用性刷新应在界面与 CLI 中检查明确的已保存 Executor 和 Host；CLI 不按焦点、显示名称或默认 Host 猜目标，列表汇总与一次精确检查分别表达。检查只说明准确目标 Host 上配置命令能否取得普通可执行文件；本地文件与已注册配置观察独立于 Runtime 连接，远端检查仍由已确认的准确远端 owner 执行，不冒充 args、env、登录或 Session 健康检查。Available 必须有本次普通文件与执行权限事实，可搜索目录或其他已确认非普通文件不能算可执行文件；这不承诺命令已实际运行或绕过 OS 启动检查。可用、已确认未取得普通可执行文件与检查未取得事实必须区分，已确认非普通文件说明类型原因，不把存在的路径写成不存在；未知文件检查失败保留实际原因，不写成未安装或一律空 PATH。任何后续候选实际可用应优先报告可用；没有可用候选时，未知不能被其他确定失败盖成 missing。结论绑定本次实际 Provider、命令和目标 Host owner；后改命令草稿、同 ID 并发替换或连接归属变化不能借用旧 Available 或 Checking。未保存的新命令如实尚未检查。Label 等未参与检查的编辑不扩大诊断范围。检查结果与原因由通用 Core 唯一事实提供，doctor 与启动拒绝说明不能另猜原因；既有非 available 不启动规则保留，不控制已有健康 Run。刷新不修改配置、草稿或工作面，不启动、停止、迁移或恢复 Agent，迟到结果不盖后来检查；连接或探测流程失败仅影响本次明确诊断，不挡健康 Input。
- **目标 Host 的执行器发现与全局模板分别表达。** Provider 声明协议适配，Executor 保存启动配置，可用性检查说明目标 Host 上本次命令解析事实，Session/Run 则代表真实执行。指定 Host 的可启动执行器清单沿该 Host 原已注册配置和受支持的发现机制取得，返回清楚的 Host 归属；设置、启动选择器、公开 API 与 CLI 消费同一来源，所选配置与最终进程必须属于同一目标 Host。全局模板清单继续表示保存模板，不冒充目标机器已安装或已授权的目录。未检测、available、missing、检查失败与连接未知分别保留，检查失败不能推断未安装或删除既有会话；文件可执行性仍不冒充登录或实际启动成功。
- **远端启动消费目标 Host 的准确配置。** 不将本机绝对命令路径、环境或凭据无条件套给远端；同名执行器在不同 Host 的路径和配置分别按原 owner 解析，不按名称猜同一配置。任意自定义 wrapper 不承诺自动发现，未被受支持机制发现时提供明确注册配置入口；不能默默安装、替换执行器或切换模型路由。发现元信息不返回环境秘密或凭据，启动与首句身份沿[远端恢复边界](session-recovery.md#联邦-runtime-与远端恢复边界)及[A2A owner](a2a-collaboration.md#a2a-身份信封与持久化全局消息队列)。
- 资源库与当前对象编辑遵守同一选择与草稿合同，适用于 Agent 配置及 Remote 的连接编辑：只有准确选中对象的字段挂载，未选对象与显式缺失目标不挂载编辑器。全库草稿仍由原 Pane 的原始基线 owner 持有，A→B→A、窄窗返回与隐藏分区不丢输入、保存期间后改或按对象持有的披露选择；输入中的改名不改变本次搜索命中集。新建进入准确新 ID 并聚焦名称，窄窗返回原准确列表项。重复相同 ID 的新导航请求仍由原导航 owner 定位，必要清除筛选；缺失目标明确不可用，不暗选其他对象。隐藏 Agents 不发起新的可用性检测，恢复可见与显式刷新沿原检测 owner，不停止健康 Run。
- Agents 工具行的响应式重排只改变原控件位置，不改变查找、Host 选择、已保存命令检查或显式刷新语义，不丢原编辑、展开、焦点与未保存草稿；排列约束归密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)。

- Executor 是启动模板，Session/Run 是独立对象。仍被 retained Session 或已准入启动引用的模板不能删除，界面与 CLI 都具名说明引用，配置不变且不停止、暂停或重建 Agent；引用范围不能只数可见格子或 connected 会话。引用事实读失败，只拒绝这一次危险删除或重绑并说明未知，普通设置和健康输入继续。已缺模板的同 ID 显式重建必须与现 Session 的 Provider 事实一致，只修改配置而不自动执行；冲突事实不能猜一个。已准入启动在完成前同样受引用完整性保护，不因尚未出现 Session 就被删掉依赖；不保存第二份模板或永久删除身份表来掩盖原 context 缺失。

- InApp 作为[App 内对话模式](conversation-mode.md#范围与唯一归属)的配置入口，说明原 Agent 输入工具栏的 Show Activity／Show Terminal 逐会话切换，并可进入原 Input & Mailbox、Appearance 与 Keyboard shortcuts。现有切换保持原 Session 的显示偏好与作用范围，不引入全局模式开关；共享输入、外观、快捷键、Prompts 与 Continuity 保留原配置和保存 owner，不复制表单或因归组整体迁入。只读快捷键和 amux Protocols 参考明确只读，入口不承诺新增可写字段。
- Remote 的 Mobile 沿原设备模块管理手机／浏览器接入与设备授权，仅在可见时读取；离开后结束界面观察，返回再读取当前事实。不以移动入口状态推断 Agent 或整体 App 是否可用。设备模块管理原 Host 的接入与授权，不冒充每个 SSH Host 的授权端点，也不因导航自动邀请、批准、撤销或扩大权限；撤销明确针对该设备原访问权限，范围不限于聊天。连接链接、设备身份与操作归属沿[《手机版 Relay 连接》](public-control.md#手机版-relay-连接)。
- 外部对话应用的首次接入、已有机器人配置与扫码原操作恢复见[外部对话应用接入](#外部对话应用接入)；环境、手机与机器人应用继续各有准确对象与授权边界。

- Survey 设置提供默认浏览器的系统选择入口；Survey 是 AgentMux 内的工作面，系统选择目标是具备真实 HTTP(S) 接收资格的 AgentMux 应用。当前默认处理程序由 Desktop 向操作系统分别读取 HTTP 与 HTTPS，区分已确认、部分匹配与未知；名字只用于展示，不推断默认资格。明确动作只请求系统选择，交接请求已发出与系统实际已选定分别表达，不保存应用内布尔值冒充系统事实，也不在启动、升级、进入设置或保存其他偏好时自动改默认。查询失败不拿走仍可用的设置入口，失败与未知保原工作面并可刷新观察。公开查询与打开系统设置沿同一 owner，不提供自动更改系统默认的 setter。

- Browser 的设置 CLI 沿当前 Unix 用户的本地配置管理权限；显式开启自动化要说明能力扩大，但不冒充真人批准，不因浏览器操作失败自动开启，也不绕过已有 Profile 批准、控制交还或原生应用链接选择。界面保存自动化和忘记链接选择时，保护编辑或点击时看到的字段/答案；CLI 的 forget 明确忘记命令处理时当前答案，由同一配置 owner 原子处理，不暗示先前列表的 CAS。forget 回到下次询问，不提供 allow/deny setter，也不覆盖其它链接选择或普通偏好。

- 添加项目在界面与 CLI 中登记明确的 Host、路径与可选名称；CLI 按给定路径字面登记，不自动展开或创建目录，比较同一位置时沿既有路径规则，保留原登记对象。重复添加返回原项目身份与名称，不重复写入或发布；并发登记同一位置只有一个身份，不同位置都保留。名称缺席或空白时沿既有默认命名。CLI 登记不自动切换工作面或启动 Agent；界面的明确选择与后续启动保持既有独立动作，原 Tab、Region、分割、焦点和未发送草稿均保留，重启恢复包含新增项目的完整工作面。
- General 的崩溃日志查询与显式文件管理器请求使用同一本机固定日志路径。查询清楚区分普通文件存在、文件不存在与检查未取得事实；只有明确不存在能说没有日志，检查失败保留原原因，目录等非普通文件不能当日志。CLI 查询成功表示取得诊断结论，不代表 Agent 或应用健康；显式显示失败如实报错，成功只说明请求已发出，不宣称文件管理器已可见。查询不读取日志正文、不上传、不更改配置或原工作面，也不影响健康 Agent；未取得事实不猜成无日志。系统 SSH 的说明须与当前远端能力一致，不能承诺尚未支持的远端运行。
- 设置搜索必须能用 General 已展示的 `Show crash log` 与 `Session recovery` 用语找到对应的静态目标，明确选择后看到原动作或说明；`crash`、`log`、`recovery` 同样可定位。查询与清除不改变诊断或恢复能力，不请求日志、不上传、不中断健康 Agent，也保留已访问分区的未保存草稿和原搜索输入焦点。
- 用户要求「所有设置项是否都可以通过 cli 完成，且 cli 设计的足够优雅清晰简单」。设置界面与 CLI 使用同一份配置事实和公开能力；可编辑设置都能从 CLI 读取和修改，命令明确对象、作用范围和生效时机；明确未提交的失败保留原值并给出可行动的原因。保存成功只在配置已持久保存并发布后确认。等待预算须容纳真实持久写入，并有明确上限；不能用“本地设置”假定写入立即完成。公开控制请求与回执都以协议定义的完整帧为准；缺结束边界的请求不得执行，未取得完整帧的回执不得认作成功。未收到完整回复时如实说明结果未确认，不把连接终止说成配置未写、JSON 内容损坏或 Agent 已坏，也不自动重试。已进入保存的动作由原所有者完成，不因回复连接断开而重放或伪装成未提交。随后读取只表示当前设置事实，不能冒充前一请求的完成回执。未知和失败保留未提交草稿、原工作面与健康 Run/Input。CLI 不另建配置系统，不用交互表象猜运行状态，也不自动扩大权限。只读系统事实通过诊断入口查询；纯粹的窗口动作不伪装成持久设置。

保存失败保留编辑与切换分区保留草稿是两种不同情形，前者通过不能替代后者。视觉约束只见密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)；文档整理不替实现或视觉评审宣布通过。

设置分区切换保留已访问分区的草稿与阅读位置；尚未访问的分区不为保留草稿而提前挂载。设置搜索由同一模块目录提供分区与具体字段、动作或只读说明的静态目标；结果清楚区分分区和目标，明确选择后才定位原编辑面并短暂强调对应位置，不自动编辑、保存、执行诊断或展开有副作用的资源。查找只消费贡献的名称、说明与搜索词，不读取用户值、密钥或隐藏编辑器正文，不为收集目标提前挂载未访问页或启动观测。清除或未被上层消费的非组字 Escape 结束本次搜索，返回开始查询前的分区与阅读位置，并聚焦原搜索输入；无匹配时同样可恢复。原编辑器实例、草稿、选区与保存反馈保持；显式外部导航结束旧搜索，不让旧查询或迟到定位覆盖新目标。分区菜单关闭时不得抢回用户已经转到搜索框或其他设置控件的焦点。已有资源优先于新增表单，新增入口明确且可收回；空资源时直接给出创建路径。保存动作在长内容中仍可达，结果在当前设置对象旁说明，保存失败保留编辑。设置区块同时显示已保存值和未提交控件草稿时，摘要必须明确它是已保存的值，不能让编辑中的勾选与已生效状态混为一谈；保存中或失败后仍保留原已保存事实与草稿，成功发布后才更新已保存摘要。Browser 自动化同样明确已保存权限与未提交选择，沿原显式保存及 Main owner，不因改变勾选而暗示权限已经扩大或收回。设置文案围绕作用范围、当前选择和生效时机；分区说明的分层与去重见密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)；底层包归属与实现术语退到诊断语境。现有 Provider/Executor 身份、权限与保存 API 保持稳定。

### 外部对话应用接入

已保存机器人身份显示准确 App ID、关联的 Mote，以及各自独立的初始化、启用和实时收发事实。关联来自原 Mote 偏好与原聊天配置，名称相同不合并身份；“自动同步暂停”不覆盖初始化未完成或未确认。没有原初始流程的手工应用不能据此判定失败。明确未完成初始化或被禁用的应用不作为新聊天的可选目标，读取缺口不能撤销原健康能力；原保存引用和继续设置入口保留。

用户可删除一个准确的本地已保存身份。确认面展示原应用及受影响的 Mote、群或私聊关联，删除沿当前修订和同一操作回执执行，不调用远端应用删除，不删除 Mote、原会话、历史绑定、凭据历史或未知请求。既有引用明确显示身份不可用，由原配置 owner 提供改选路径，不能静默改投另一应用；该身份的自动收发停止，独立机器人和健康 Agent 继续可用。结果未确认时保留原删除请求并提供查询，不用新 operation ID 重做。

Settings 的 Conversation Channels 提供 InApp、Lark 与 Discord；各项与 Remote 的 Mobile 分别沿[设置页的信息架构](#设置页的信息架构)定位，不以设备连接代替 App 内对话模式。Lark 与 Discord 各自管理对应平台的应用、机器人身份与群关系，页内保留准确平台及实际适配器能力。分组不建立统一 Channel Runtime 或第二份配置库：设备继续由原 Host Authority 持有，应用与凭据继续由原 Connection owner 持有。共用本地存储、各 Channel 自有资料缓存与共同 amux 声明沿[共同对话协议](conversation-mode.md#共同对话协议与外部交流入口)，设置不另存业务事实。产品入口变化保全已保存身份、原请求、现有接收与群绑定；打开设置或发现适配器不自动注册、建群、授权或启动 Agent。

外部对话自动同步总开关由准确托管 Host 的原 Connection 服务持有，与每个机器人应用的启用偏好分开。关闭后在原准入边界停止新的自动收发，Agent 菜单仍保留连接入口、已有群详情与设置路径，明确说明自动同步已关闭；进入或查看不自动开启服务，也不批量改写各应用配置。已保存机器人、凭据、群绑定、共享起点、成员授权、投递进度与未决原请求保留，已在途施效和回执按原操作核实，不能冒作已取消或未发送。重开只恢复仍满足原应用、Binding 与授权条件的能力，不误启原本暂停的机器人，不重建群或换 ID 重放未知操作。

平台能力开关也归同一 Connection 服务，以准确 adapterId 为独立策略范围；没有显式平台选择的服务操作仍是原全局范围。平台策略只决定该平台新的自动收发，与全局服务及单个机器人的启用值分别保存和确认；关闭一平台不改另一平台，也不批量改写 Bot 配置。新的接收、输入受理与群／私聊外发须同时满足全局、原平台、准确应用及原 Binding／成员授权；已由 Core 受理的输入和健康 Agent／Run 不因平台关闭而被取消。已有凭据、关系、默认关联、共享起点、授权和原进度保留，在途或未知效果不冒称未执行，恢复不重发原未知操作。平台关闭不是禁止管理、显式恢复或全部网络动作；原已明确授权的管理与生命周期通知仍沿各自合同。

平台策略的读取、保存与原 operation 查询沿同一公开服务及原认证 user／device 权限，保准确 Host／Runtime、独立修订与 CAS；新平台范围不改写全局原输入和历史回执，也不借显示名或当前执行 Host 选择 owner。平台自动收发策略不控制顶部入口。独立的“在 Agent 标题栏显示”由原 App ConfigOwner 持有，按准确 adapterId 保存展示偏好，默认显示；只有已保存的隐藏偏好才移除对应入口。隐藏不暂停消息，暂停消息也不自动隐藏入口；Host 未知、读取失败或跨范围结果均不改变展示偏好。隐藏不删除原关系或请求，不让该平台的 Binding／草稿经其他平台或 Other channels 再进入 header；原设置、管理、恢复与结果查询仍可达。保存选择、当前读取和原 ACK 分别表达，失联或丢 ACK 先查同一原操作，不默认换 Host、开新请求或扩大权限。

外部同步总开关不控制 App 内对话或第一方设备访问。总开关关闭时，设置中的身份管理、总开关恢复和原结果查询仍可达；已明确授权的管理与原操作恢复继续沿各自 owner，不因关闭同步被清空。总开关保存与当前读取分别表达，当前值不能冒作早先请求的 ACK；迟到读取不覆盖较新修订或后选。未知或读取失败不推断为关闭，不以观察缺口停止健康 Agent／Run 或删除原工作面；需要当前授权的新自动施效不能用缓存或文案补证，只限制那次未能核实的准入，并保留原请求和可用管理／查询路径。菜单的稳定入口与具名分组只见[Agent 群聊连接入口](../presentation/conversation-mode.md#agent-群聊连接入口)。

外部对话应用提供“创建并接入机器人”和“接入已有机器人”两个入口，首次接入以创建为主路径。创建路径在同一任务中完成准确平台的确认、应用创建与接入，不要求用户再抄取密钥；已有机器人路径保留凭证来源说明、准确应用身份、原草稿与显式保存。平台是否支持本次创建及其授权范围由实际能力和原回执确认；入口不能把其他产品的创建资格或已有建群能力冒作本产品已可创建应用。已有应用继续按名字和真实接入结论选择、查看与编辑，不因新增入口被重建、替换身份或改写群关系。

应用列表、创建能力与原申请结果分别读取。列表等待或读取失败时仍可进入接入已有机器人、原结果找回及有真实能力的创建任务；不以列表缺口推断没有已保存机器人，也不因刷新列表替换当前任务或新建申请。

账号登录、确认账号与创建应用分别表达。支持账号登录创建的平台，由原操作者先核对准确账号与企业，再明确创建；扫码或确认账号不自动创建应用。创建动作冻结本次明确选择的名称、简介与头像，Mote 发起时沿原公开资料快照，独立设置入口提供品牌默认头像。一次创建只授权原头像上传、当前平台明确支持的应用创建方式（含模板创建）、该应用凭据取得与本地保存，各环节分别保留原结果；结果未知时停在原环节，不补建应用或隐式改走另一创建方式。接入配置与发布沿各自明确授权和原结果，不由账号已确认推导。原申请的安全摘要与原操作者当前确认材料分开；旧申请保原身份、原字节与可达的本地恢复，不因新增创建方式自动切换流程。

首次创建沿已确认的原 Console 协议，由 Provider 将冻结名称、简介和原头像随首次上传与创建提交；Mote 使用原已保存资料及本次选定名称，空简介不以外部项目文案补齐。通用身份的默认文案与图像使用 AMUX 自有内容，由原产品创建 preset 持有，Provider 只执行原输入。应用连接和 Mote 默认引用的本地保存不再触发另一份官方资料同步来补写同一资料；显式更新已有应用统一沿同一 Console 管理授权及其原设置 owner，使用已确认账号更新准确应用，不改走机器人凭据的另一条资料写入路线。已派发的原资料 child、回执和未知写入保留可查，不因新创建流程收敛被删除、重放或补造成功。

Agent 可沿同一公共 CLI／RPC 完成已授权的机器人接入、配置和默认绑定；公开发现须给出可执行的动作、准确对象及原结果查询方式。Agent 使用原认证身份，只发现和续接自身创建的原接入操作；已配置连接须仍对应该原申请的准确应用。Mote 源资料限定原执行 Host 与 Workspace，群创建和绑定限定该 Agent 本身；本人或设备的既有私密操作不因 Agent 有能力票据而转移。全局连接策略、他人的连接和成员授权仍沿原可信本人或设备。平台扫码、账号企业确认及发布决定仍明确呈现。授权缺失只拒绝本次准确操作，并给出取得授权与继续原请求的入口，不关闭已有机器人或 Agent。

同一已保存应用集合承担机器人身份池；channel 设置以本次准确托管 Host 的机器人为管理主体，按准确平台、应用和 Connection 辨认、选择和管理，多条连接别名不冒充多个独立平台身份，也不静默合并其凭据。Connection 的本地名称与平台公开资料分别表达，初始化、当前接入观察和已确认的 Mote 用途分别可查。新群默认、私聊路由与原 Agent 的群 Binding 是不同关系；一项默认引用或平台页名称不表示 Mote 专属该 channel，也不表示其他 channel 已有独立配置。Mote 创建或关联在用户明确选择该用途时进入原 Mote 工作面，可选择全部已确认对象并继续原申请，不把所有未关联对象当作平台接入待办。原引用不可用、暂停与读取未知分别表达，不能按当前列表缺项归入未关联。只读取本次身份关联所需的原目录、偏好与选中对象公开资料，不扫描讨论历史或启动 Agent。默认引用、解绑与另建身份的行为唯一见[机器人身份与公开资料](motes-and-coordination.md#机器人身份与公开资料)，私聊沿同页的原私聊 owner；调整展示不迁移或改写这些关系与原操作。

Desktop 通过 `AGENTMUX_DESKTOP_USER_DATA` 显式选择独立 profile 时，原 Connection 数据库、原凭据记录、群绑定与操作回执归该 profile 的 user-data 目录；启动预热、自动收发和原操作恢复只消费该 profile 的连接库，不读取默认连接库或解析其中的凭据引用。未显式指定时继续使用原用户目录下的连接存储；不搬移、复制或清空既有数据，不另建 owner。该边界限定本地存储及引用归属；具体凭据存储与旧格式交接统一见[Host 常驻托管](conversation-mode.md#host-常驻托管)。已选 profile 的凭据访问仍沿原 Secrets owner、原授权与就绪事实，不因切换 profile 扩大读取范围。

打开或刷新身份目录及发现能力只读取非敏感元信息，不为探测凭据可用性读取私密存储；扫码、私密账号或凭据操作才沿原 Secrets owner 按需访问，正常自动收发所需的原凭据访问独立保留。

原凭据访问等待或失败不阻塞 Host、客户端公共服务与健康 Agent；原存储不可用时保留原始字节、凭据引用及操作身份，原结果查询仍可达，只拒绝本次尚未确认的凭据操作。

从具体 Mote 进入身份设置时保留该原 Mote、公开资料快照与默认关联意图，自动带入准确名字与当前头像，不用当前焦点推导来源。通用设置的全局添加入口创建独立身份，不要求先有 Mote，也不隐含默认关联。两条入口沿原创建、身份管理和保存 owner；切换入口不复用另一对象的草稿、私密材料或未决操作。Mote 的自动图标、已选图标、捏脸、图片与系列均是有效头像；系统从原外观只读取得所需静态图像，不要求用户重新准备或保存 PNG，不改原外观。读取或导出失败时保留原头像和身份，以准确原因提供刷新原资料的动作；不借品牌默认图冒充该 Mote。

新建机器人的名称在有准确 Mote 来源时默认采用该 Mote 已保存的名称，允许用户切换手动输入。手动模式首次进入时预填 `AMUX-<随机串>`，无 Mote 的通用入口直接使用该模式；随机串由平台随机源生成，不带时间、路径或其他对象信息。同一草稿的切换、刷新与异步检查保留已编辑的手动名称。明确开始原申请时冻结选定名称，之后的恢复、创建、资料同步和本地保存沿同一份原输入；不因 Mote 后续改名或切换焦点重写该申请，不修改 Mote 或已有机器人的名称。

首次创建以四步「资料 → 登录 → 创建 → 配置与发布」表达同一任务。登录步骤核对准确账号与企业；创建步骤以原账号和创建资料明确确认整次动作范围，配置与发布是必需的接入步骤，在创建已确认后由原 owner 自动续接，无需用户另点“继续配置”。自动续接只执行本次已明确授权、具备原协议资格的动作；待本人确认或企业审批时停在准确步骤，不能自动批准。应用创建、配置、发布回执与本地保存仍各自保留，局部未确认不撤销前步，也不自动重发未知写入。

创建与接入任务的资料准备、登录、创建与配置发布共用连续工作面；不因登录阶段完成而换成另一套流程。编号进度持续保留全部阶段，明确已确认完成、当前处理、等待本人或平台、结果未确认及尚未开始，不能只显示当前状态。当前任务说明准确对象、已经确认的结果和下一动作由谁完成：本人在此页或手机上操作、AgentMux 正在执行或读取、平台正在审核须可辨；单次查询结束不等于原业务完成。当前步骤的主动作直接说明其实际效果；没有可派发动作时说明等待对象或具名缺口，不制造一个无效的“继续”。已保存应用的管理入口展示原应用事实，不虚构本次创建步骤；原配置的子步骤沿真实观察与写入回执逐项说明。只有当前状态读取失败时保留前步已确认事实，并说明本次观察缺口。

原申请提供按发生顺序查看的脱敏请求轨迹，持有当前阶段、请求方法、来源限定的目标类别及 HTTP／原生状态事实；读取只涉及这次原申请。轨迹由原 Provider／操作 owner 提供，界面与公共调用者消费同一来源，不从展示文案反推状态。Cookie、密钥、二维码原文、完整跳转地址、查询参数值与个人资料不进入轨迹或复制诊断；轨迹可查不扩大查询、重试或发布资格。

创建、接入配置与资料管理的“复制诊断”一次取得同一原任务的当前结论、原 owner 已提供的失败或未确认原因、可用下一动作、安全观察摘要及完整有序轨迹，不要求用户分别收集数个折叠区。完整历史与本次观察分别标明来源类型、准确操作身份及观察修订；已由原任务明确关联的子操作保留各自身份，不跨任务拼接。摘要只选取阶段、状态、准确版本、动作种类及相关检查的能力、有限原因、问题和来源结果，不由请求成功推导当前检查通过；缺少原因或观察时明确未记录或未确认，不猜平台故障。摘要不包含账号、认证材料、二维码、凭据、原生响应或草稿正文。导出沿原游标取得全部可导出步骤，不受当前可见页或展开状态限制；读取失败说明完整性缺口，不冒作完整成功。取消、离开或切换目标后，迟到导出不再写入剪贴板。

扫码面明确正在接入哪个平台、需要用户在平台完成什么确认，以及返回后的下一步；本人身份与企业授权仍由平台持有。仅取得二维码、已扫码或页面返回，都不等于应用已创建、授权已完成或凭据已保存。创建所得凭据沿原安全凭据 owner 接入，密钥、token 和二维码背后的授权码不进入普通字段、日志或操作详情；二维码只在准确原确认面呈现，不作为历史详情展示。只能展示有来源的应用、企业与权限信息，不能用本地姓名或当前登录界面推断创建者身份。

一次创建意图及其准确目标必须在可能施效前保全。离开设置、关闭扫码面、切换入口、断线或重启后，用户仍能恢复查看这次原操作；重新打开不自动再建应用。二维码到期只说明原确认入口的有效性；平台取消按准确回执说明取消范围，本地关闭或停止等待只结束当前展示，不能据此推导应用未创建、已删除或授权已撤回。创建结果未知时保留原操作和已有应用事实，先查询原结果，不以换 ID、刷新二维码或“重新开始”发起另一创建；后续动作须依据原 owner 对同一请求的实际续接或明确重新开始资格，由用户显式执行。

返回同一 Mote、机器人或设置任务时，从既有 Mote／Enrollment／Setup 持久 owner 恢复当前 actor 有权查看的准确原请求、目标及已保存进度，不让画面切换抹去现场，也不只依赖 Renderer 回调或另存一份业务状态。多份原请求保持可辨认，不凭最新一项、显示名称或后来焦点替换原选择；来源或权限不可确认时保留安全定位与明确缺口，不打开另一 actor 的私密现场。公共 RPC／CLI 的发现须给出本 actor 可见的原操作及准确查询、续接入口，GUI 消费同一来源。恢复查询本身不创建、上传、改配置、提交发布或重放未知写入；不借旧界面快照复显已离场的二维码或账号材料；返回后的有效确认材料仍由原 owner 按当前 actor、原身份及有效性重新提供，必要确认继续沿原 owner。

原申请的进度检查是一项明确任务，由原 owner 的权威事实决定本次是查询、等待还是用户显式续接同一操作；入口须说明所查原申请与动作含义，不要求用户在数个含义相近的入口间猜测是否会再次创建。创建结果未知、平台明确失败、平台已创建但本地保存未确认须分别表达；本次查询失败只说明未取得新的确认，不能据此改写机器人创建结果或冒充平台拒绝。没有可用确认链接只说明当前缺少确认入口，不能据此将未知归为未开始、未创建或平台明确失败，也不承诺下一次检查一定补回链接或凭据。查看原结果或续接没有取得新事实时，也须就地反馈本次检查结果与未确认环节；原修订未变不能成为清空反馈的理由，显示反馈也不伪增领域修订。未知申请的动作说明实际查询或本地恢复，不承诺一定能继续平台创建；尚未到原轮询时机时，明确仍待确认，不提前轮询。原申请面直接保留接入已有机器人及打开另一独立申请的出口。独立申请不是重试或替换原申请，打开表单不创建、不轮询；创建需新的明确意图，原未确认请求分别可查。迟到反馈只归属原操作，不能覆盖后选、较新事实或另一份草稿。

原生登录交接入口与后续跳转使用同一准确目标范围，不能在前一步拒绝后一步已允许的合法交接。未确认结果保留实际失败的解析或后处理环节，并沿原操作及技术详情可查；有限诊断不包含令牌、Cookie、完整跳转地址、原始响应或个人资料，也不授予重放或创建资格。

登录链的传输目标与最终账号来源分别判定。Provider 只沿原流程允许的 HTTPS 来源继续标准重定向，不以中间或最终页面的路径、查询参数形状判断账号资格；URL fragment 不属于 HTTP 请求目标。最终账号仍须由准确应用来源的实际文档及原生稳定身份、企业和验证材料共同确认，中间登录页不授予账号或创建能力。每个新动作只推进一次请求，沿原私密状态保留 Cookie、来源与后续目标；有限跳转观察结束时保留原申请为未确认，不自动换码或重放。技术详情用有限原因区分缺少跳转目标、地址不合法、目标资格不符与观察上限，不输出原地址或从异常文案猜原因；历史原回执不因新增诊断被改写。

账号已在准确应用来源确认后，原创建、凭据取得与后续配置继续使用该最终来源及其 Cookie、验证材料与页面来源，不擅自换回初始入口。平台应用身份、准确账号及原申请绑定分别保持，传输来源变化不把原应用改成另一平台，也不扩大发布或共享授权。后续写请求不自动跟随重定向或重试；未知结果沿原动作保留并查询。

同源响应的单条 Cookie 不合格只拒收该 Cookie，不能抹去已取得的应用身份或平台回执。认证材料续接由原认证 owner 在原操作及准确账号内安全保存，与应用观察和施效结果分别确认；本地续接保存未完成时保留原结果及恢复入口，不重发平台动作，也不以迟到旧材料替换较新的认证。

准确原创建者发起的首次机器人版本，须由权威版本记录确认尚无版本，并明确选择仅创建者可见及机器人入口；这条操作只依赖其真正消费的来源，不以无关的当前受众、外部分享或通用管理资料读取作为门禁。适配器解释本次必要来源，原设置 owner 在公开 typed view 中给出所需读取主题，客户端、SDK 与 CLI 消费同一关系，不自行猜测发布模式。已有版本、版本未知及既有应用的范围更新继续保全原受众、排除范围、分享设置与原操作，不因信息缺口切换为首次发布。

原版本提交回执未知而准确版本身份已保存时，首层进度检查可直接查询该原版本的当前平台状态；原未知提交及其回执仍分别保留，不以查询结果补造旧确认或再次提交。没有准确版本身份时不猜列表首位。版本审核通过、已上线与实际可收发继续分别确认。

应用创建与本地连接保存分别确认。平台已创建而保存尚未确认时，继续处理同一个已创建应用及原保存，不退回创建起点；凭据不能安全恢复时明确缺少的环节，不以重建应用补偿。已有机器人保存结果未确认时同样保留原输入和操作，只查询原保存；需要继续时由用户明确续接原操作，不以未查到记录就另起保存。迟到结果只归属其原操作和应用，不覆盖后来选择或编辑中的草稿。

本次创建、必要的本地保存及配置与首次发布均由原操作确认完成后，任务直接说明已完成的准确范围，不再以只读进度检查充当必经的继续步骤。查看、刷新原结果和诊断继续可达，不能触发配置、发布或其他副作用。发布待审批、结果未知、已发布与实际消息收发分别表达；完成反馈不自动建群、绑定或发送消息。

Mote 创建使用原耐久接入操作，并保留其准确来源和之后默认引用保存的原请求。平台确认面可预填资料时，预填只是用户可改的候选，不证明最终名称、简介或头像一致；缺少可用头像来源不伪造已带入图片。创建、凭据保存、应用连接保存和 Mote 默认引用保存分别确认；其中后一步失败不撤销前面的真实结果，也不以新建应用补偿。原操作可在离开和重开后发现、查询和明确续接，不能只依赖当前 Renderer 回调记住属于哪位 Mote。

同步公开资料是针对准确应用的一次有限显式操作，与创建身份是不同任务。明确继续须沿原操作显示实际进度或真实停点，不能只结束加载或反复空转。资料读取、上传、写入与匹配读回只依赖各自真正消费的来源；发布阶段再核对准确版本、完整受众及其他必要来源，草稿不能成立时须说明原缺项，并保留资料已写入与待发布的分别事实。可推导的候选版本与可派发的发布草稿分别表达；来源缺失或仍待确认时，说明准确缺项并提供有限的显式刷新，不以无进展的重复读取表示继续。资料更新复用原管理登录、账号核对、读取、施效和发布回执；上传与资料写入只有这一条可执行路线，不在网络失败后切换协议或凭据。旧资料操作只保留原回执查询，不能以新管理授权重放。当前任务种类、目标与进度消费原操作及资料 owner 的有限事实；同步历史不因缺少创建申请或当前登录材料误显示待登录、待创建，新的管理任务则按原认证阶段说明所需登录。原操作冻结目标应用／Connection 修订、源资料和头像版本；上传图像、资料写入、提交发布、本次版本审核与在线资料观察分别保留准确回执。上传或写入未完成时具名说明原环节，结果未知保留原 operation，不自动重发写入。资料同步的原步骤和诊断沿原资料 owner 可查，完整导出及安全观察沿本节原任务的共同诊断合同。已有同步回执不因缺少创建轨迹被表达为尚无请求，未记录的 HTTP 细节保持未记录。资料写入接受不等于线上生效，发布受理不等于审核通过；读取今天的资料也不代签早先未知操作。资料同步可能影响使用同一应用的其他 Mote 和群，应先说明准确目标与影响范围；默认引用不授予独占或平台写权限。

资料管理任务的首层结论须由原 owner 的当前回执说明已完成部分、未完成阶段及准确下一动作，不要求用户解读请求表判断是否完成。资料已写入而发布未开始、发布检查待处理、版本已提交待审核、本次版本审核通过、线上已确认与结果未知分别表达；候选版本标明候选，不能冒作已创建或已发布。原账号、应用、完整原因与请求轨迹从属可查。对同一原操作查询时保留最后已确认结果和原任务，分别表达当前读取与原业务执行；读取失败或结果尚未返回不清空已有结论、不授予新动作，也不改变原 unknown。查询结束显示新观察或具名失败；离开或换目标后，迟到读取不替换后来对象或结束后来查询的反馈。查询、只读刷新、本地恢复和有副作用的继续仍消费原 owner 各自提供的动作，不用通用“继续”掩盖效果差异。

全量资料写入使用准确应用的可靠原资料，保留全部语言块、未改字段与已发布受众。本次明确更新名称时同步已有语言的名称；单一 Mote 简介只更新可靠主语言，其他翻译保持，明确空简介按清空处理。头像上传使用原已保存图像的准确字节及实际尺寸，不复制其他产品的品牌内容。写后读取、版本审核与线上资料分别观察，草稿资料吻合不代签线上生效。

平台不支持本次资料操作、创建来源或管理权限尚未确认时，保留原应用、已写入字段、来源快照和原操作，给出准确的未完成阶段与原平台继续入口，不把一次资料失败扩散成已有聊天或 Agent 不可用。不能静默公开托管本地头像、借其他机器人凭据或为同步资料改写其他能力与权限；没有准确版本范围和明确发布授权时，保资料已写入与待发布，不暗中发布其他待审变更。平台端点、来源限制与权限的可用性由实际合同和原回执确认，不由缺字段、模板或本地保存推导。

机器人应用的创建、凭据安全保存和接入检查应在同一设置任务内完成，不要求用户手工搬运创建所得密钥。平台支持的必要配置随本次明确接入意图处理，实际权限、订阅方式与发布生效沿准确应用的原合同和回执确认；待本人确认或企业审批时，就地说明需要谁做什么，不将申请受理或配置写入冒作已生效。已保存、应用鉴权、实时接入和群投递分别确认，保存成功不冒充已经能群聊，也不把多项技术检查平铺成首次上手流程。设置给出准确接入结论，并提供从原 Agent 菜单创建或连接群的下一步；群创建、成员可达、Binding、成员使用授权和共享范围仍独立确认。扫码不自动建群、不把扫码人视为已入群或已获 Agent 使用授权，也不扩大原共享范围。群关系与共享权限的唯一合同见[共同对话协议与外部交流入口](conversation-mode.md#共同对话协议与外部交流入口)。

同一机器人的接入默认呈现一项当前任务和一个明确下一步，消息、投递与权限仍可单独管理。下一步只由同一准确应用、API 来源及修订下的原安全观察与回执推导，不另存完成表或可用总分。用户明确检查后，可依次读取当前任务所需的有限应用事实，遇到首个需要用户决定或尚未确认的环节即就地说明；检查不自动改配置或提交发布，不轮询历史或无关机器人。平台结果已知而本地保存未完成时，优先恢复原结果；原施效未知时查看原请求，新的当前读取仍与原请求结论分开。较新选择、来源变化和迟到响应继续遵循原私密材料及草稿边界，不能借引导恢复旧动作资格。

从 Agent 菜单进入设置时，导航保留发起时的准确展示 Session 及其执行 Host、AgentSession 关系；返回动作只定位仍与这些原身份一致的 Agent，不改用后来焦点中的 Agent。缺少原来源或原对象已不可定位时，说明情况并提供既有 Agent 选择入口；不创建 Session、不代选群成员或共享范围。回到原 Agent 只改变展示选择，建群与绑定仍沿原 Agent 菜单、Mote 默认身份及明确授权。

已保存机器人的管理账号确认沿同一设置任务进行，明确展示本次账号、企业及用途，由用户确认准确账号；扫码与账号确认不授予应用管理权限，也不代表配置、发布或接入完成。实际可用的管理接入方式来自准确应用修订的实现发现，发现失败仍保留原连接检查和平台继续入口。自动推进只执行原 owner 给出的继续动作及其自身修订，未知结果停止推进；重新扫码、换账号和账号确认均须显式执行。

等待扫码与已扫码待手机确认沿同一原登录继续。平台明确返回的等待状态保持原二维码和原申请，按原轮询间隔自动检查，直至登录交接、明确过期或结果未知；不能把正常等待误判为失败，也不能每次检查重建二维码。同一次原登录的轮询请求尚未返回时，owner 保留该次仍有效的扫码材料；并发只读检查、请求派发和本地回执保存中的暂态不能让二维码消失。创建、管理和 Mote 资料更新消费同一合同；界面不另存一份二维码来覆盖明确交接、过期、续码或未知结果。原生协议各阶段只校验该阶段有来源的必要字段，等待轮询的状态字段不能成为已明确登录交接的额外前提；交接仍核对原签发方及目标，不等于账号已确认，也不授予应用创建资格。原生协议允许继续等待而账号交接尚未返回时，保留原申请和观察间隔继续检查；不把状态数值本身解释为扫码、账号或创建成功。读取已存进度仍是本地只读，不暗中开始新的平台请求；账号确认与应用创建保留各自明确动作。账号有效性由准确来源的稳定账号、企业身份及必要认证材料决定；可选显示名缺失或冲突、无关页面元数据和未执行的局部脚本不能撤销已确认身份。明确的二维码过期只更新原确认入口，不推导应用创建或业务取消。

机器人创建与本地保存均确认后，原操作者可从原结果明确继续同一机器人的设置，复用原创建中已确认账号的登录材料，无须为这次本地交接再次扫码。交接须关联原创建申请、认证尝试、账号与企业、准确应用、当前连接修订和稳定设置操作，并沿原安全凭据边界恢复；先显示账号核对，仍由用户明确确认本次管理账号。创建授权不延伸到配置或发布，保存的登录材料也不保证当前平台权限；后续平台读取仍须明确选择。创建、保存或交接结果未确认时，保留原请求与本地恢复，不自动补建应用、重新登录或换目标。

离开当前扫码或账号确认任务即停止展示私密材料与自动推进，包括在同一设置分区内切到已有机器人表单或应用列表；原设置任务保留每份已提交的安全输入，包括尚未出现在查询列表中的原请求。未查到记录不证明未受理，明确续接仍使用原输入与原身份；独立新申请不替换或阻断其他待查申请。私密响应与后续动作绑定准确 API 来源、应用及连接修订和本次选择；同身份的来源替换、后选目标或离开后的迟到响应均不能重新显示旧二维码、账号或继续执行动作。

已保存应用的通用管理同样保留用户明确选择的原申请身份。返回应用、重开管理或恢复设置后，从原 owner 在同一 actor 下只读查询该申请，不依赖当前历史第一页、创建能力或最近一笔请求猜测；导航恢复不派发继续、登录、配置或发布。保存的仅是准确应用下的原请求定位，私密账号、二维码、动作和阶段重新按原权限读取。申请暂不可读或修订已变化时保留原定位、具名缺口及恢复入口，不退成另一新申请。尚未选择申请与没有原请求分别表达；已选请求在读取中或读取失败后，仍能复制其可取得的安全诊断和具名缺失，不以空的界面选择状态宣称原轨迹为空。

事件接收方式与机器人消息能力是两个独立的明确配置项。用户先读取准确应用的当前事件接收方式；已是长连接只显示读取结果，不再写入，缺失或未知方式不得默认成可切换。切换前明确说明影响整个应用及其已有事件消费者，由用户明确确认后仅请求切为长连接；不连带增删订阅、回调、权限、可见范围、版本或发布。平台接受切换请求、之后读取到的当前方式、发布状态与实际收到消息分别成立。未确认的切换保留原操作与私有存储回执，可在原身份恢复；换账号、新设置任务或同应用别名不能换请求重发，后来的当前读取也不补签旧请求。这份未决结果只约束同一应用的该项切换，不能阻断独立的机器人消息能力开启、当前读取、平台继续入口或健康 Agent。

群消息接收在原事件投递设置中检查并明确添加。当前应用订阅与可用事件目录各保留原观察，适配器只认可实际接收器所需事件的唯一、准确应用身份项，不以名称、文档链接或另一身份桶代替；缺结构保持未知，已订阅不写入。添加前说明请求还会携带最近检查到的整个应用长连接方式，不能承诺方式不变或平台并发保护；仅添加该项，不暗中切换方式、配置权限、回调或发布。接收方式切换与消息添加都会使此前事件设置失去新写资格，只刷新目录不能补足。原方式请求未知时，只有重新读到长连接、准确事件确实缺失且原不可变方式意图一致，才可明确授权独立的添加；旧切换仍未知，不重试也不补签。未知添加跨账号、设置任务与同应用别名仍保留原请求，本地原回执优先恢复；不能阻断独立机器人消息、权限、平台入口或健康 Agent。请求接受、当前已配置、权限生效、发布与真实收到消息分别成立。

必要应用权限在同一设置任务内审查并明确申请。默认用途是 Agent 对话和创建、连接群聊；只有用户在本次申请中明确包含 Mote 身份同步，才增加更新应用自身名称、简介与头像所需权限，不由名称、图标或默认关联猜测，也不形成长期权限开关。用户的一次审查可依次读取可用目录与当前申请，二者分别保存原回执；部分成功保留，未知不重放已完成步骤。准确原生名称、应用身份和原 ID 决定缺失项，不猜别名、跨身份补全或把缺字段当空集合。仅向准确应用添加明确同意的缺失项；无缺项不请求平台。已接受的申请可在新的当前申请读取后明确补充另一有限用途；只刷新目录不能复用写入前的旧申请清单。平台接受、本地结果保存、当前已申请、生效授权与发布分别成立；需要额外数据范围配置时如实说明，不自动写范围、订阅或发布。未知添加跨用途、换账号、新设置任务或同应用别名仍保留原请求，不阻断独立消息能力、接收方式、已有群或健康 Agent。

账号确认后的应用观察与旧结果恢复分别成立。新的平台观察绑定当前明确确认的管理账号、准确应用与连接修订，一次原动作不因未知回执重发；平台报告的资料读取权限不冒充实际资料读取、应用所属企业、写权限或接入完成。换账号、修订或重开后，原主体仍可从同一申请中有界查找和选择旧观察，只恢复原私有结果的本地交接；这条恢复不要求重新登录或平台适配器仍在场，旧私密权限也不重新成为当前权限。旧结果不可恢复时保留未知，当前账号合格后的明确新观察仍可独立发起。查看历史、翻页与选择不请求平台或暗修回执，原机器人、平台继续入口与健康 Run 保持可用。

应用资料、当前事件设置、事件目录、当前回调、机器人设置、权限目录与当前权限申请按独立观察确认，每个原动作冻结准确主题并分别保留读取和安全保存回执；可选目录不代表当前已订阅内容，多项读取也不冒充完整或原子的配置快照。只投影有来源的安全资料及读取状态，原始配置与安全字段继续留在原凭据保护边界。未知主题不阻断另一明确读取，旧私密结果不带入后来账号或目标；机器人菜单默认值不代表能力启用，读取完成不代表已经可聊天、配置已修改或版本已发布。

发布前的待发布变更、准确版本列表、完整线上白黑范围、外部分享与应用特性分别读取，沿原观察日志和安全存储保留回执。准确版本详情须显式选择版本 ID，并贯穿原动作、读取目标、安全绑定与结果；不以列表首项、显示名称或审核状态猜测本次版本与当前线上版本。平台无需重复回显请求中的版本 ID，准确原请求承担目标身份；若回包明确给出冲突身份，则保留未知。部分读取成功时保留其原结果及具名缺项，创建版本资料不足不能封闭独立选择已有版本和查看原结果；多项读取不承诺平台原子快照或并发锁。

创建版本由用户明确填写版本和发布说明，审查准确应用的全部待发布变更、完整包含与排除范围、当前可用入口及外部分享设置；按原平台规则补充必要的审核理由。默认保全已检查的完整范围和有效入口，不能用空值、当前管理账号或首个候选覆盖；只有准确原创建者已确认时，才可明确选择仅该创建者可见。发布作用于整个应用，确认动作须说明其他待发布变更也会一并包含，不承诺只发布本次消息配置。草稿、来源或准确目标改变后，先重新审查，不沿用旧动作提交。已知同应用的提交发布可能改变线上范围与分享，后续创建须重新读取这些受影响事实；不为无关配置扩大失效或扫描范围。

创建版本与提交准确版本是两份独立意图和原回执。创建确认返回的准确版本 ID 可供用户继续审查，提交仍须另行明确确认；用户也可显式选择已有版本。创建结果未知不能凭相同名称或列表位置补签，亦不阻断另一份准确已有版本的独立审查与提交；未决创建和提交分别保留原身份，不经重开、换账号或应用别名重发。原平台结果已取得而本地保存未完成时，由原操作者沿原操作优先恢复安全回执，不要求再次平台登录或当前适配器仍可用，也不重新请求平台。平台受理、当前审核结果、准确线上版本和实际群消息接入分别确认；当前读取不能代签早先未知操作，配置待处理或发布局部失败不能关闭健康 Agent、现有机器人或群关系。

启用应用消息能力是对原明确应用的一次显式单项意图，不能由自动推进账号确认顺带执行。资格只消费当前准确账号与目标下最新已安全保存的原生关闭事实，不从缺省值、旧选中结果或稍后未知读取推导；动作冻结原来源与修订，平台接受和本地私有存储回执分别确认。旧未知意图不能经换账号、新设置任务或同一应用的另一引用换 ID 重发；同一执行 Host 内已有的原主体未决请求可准确找回。后来的开启／关闭观察都不代签旧请求，原本地回执恢复不要求当前登录、适配器或修订仍在场。该单项不连带菜单、投递模式、事件、权限、可用范围、默认入口或发布，不代表已经线上可用或可聊天；独立读取、原平台继续入口、已有机器人与健康 Agent 保持可用。

账号确认后的设置面直接提供准确机器人的当前消息设置检查，再按原 owner 给出的动作显式开启；本地动作发现与历史查询不请求平台。请求已接受、当前已开启、结果尚未确认与本地结果待保存分别表达，刷新当前设置不确认旧未知写入。原活动按需展开并沿准确子记录选择、翻页与恢复；当前已保存连接内的原操作可显式查看，不同连接只给安全定位与返回机器人库出口，不自动打开另一私密工作面。

未知申请默认恢复原对象；用户明确创建另一机器人时进入独立新意图，所有旧申请与尚未取得回执的原始请求仍可按准确身份找回。防重复提交只约束同一表单意图，不能因一个 begin 尚在等待而阻断另一个新意图。

创建或查询失败只影响本次应用接入。原已保存应用、未提交凭证草稿、Tab／Region、Composer、IME、Terminal 阅读与健康 Run 均保持；原始阶段、技术原因、准确操作身份与修订按需完整查看，收起详情不删除原事实，也不将当前读取冒作原请求回执。用户可以离开接入流程继续正常工作。

## 操作成本与当前卡顿

- 隐藏终端仍要接收和解析输出，保留原 Session 与 Runtime attachment；GPU 绘制资源只属于当前可见的终端。切换可见性不能重新启动 Agent、丢输出或换身份。
- 反复执行 Restart Session、替换 Run 或退出展示后，已退休消费者的回调、订阅与终端缓冲不能逐次累积；待执行回调由原调度窗口负责取消。按[原 Session 重启合同](session-recovery.md#显式重启会话)保全身份、工作面、草稿、仍在阅读的正文和未确认操作，不以关闭健康会话或删除历史降低占用。内存验收区分对象可回收、资源计数和进程占用，绑定实际消费者及重复操作条件；局部释放不冒称全局无泄漏。
- 浮层的共享宿主是唯一的窗口级 DOM 身份。解析它不能反复遍历终端、文件树或正文；工作面内容变多，不得增加这项固定窗口操作的成本。宿主被移除后仍能由原所有者重新建立，显式指定的容器保持原路由。

- 用户原话：「现在进程非常卡」「让系统成本只随真正相关的工作增长，先缩小范围再做重处理，不要让无关数据、历史和功能拖慢当前操作」。输入、切换与当前工作面的更新不能被无关 Session、历史或后台观察反复拖慢。
- 卡顿定位必须区分主进程、Renderer、Runtime、Agent CLI 和验证负载，结论绑定采样版本与操作；不能以一次体感或静态代码推测冒充根因。局部修复须证明原热点成本收敛并保留 ordered bytes、恢复与健康 Agent 的工作能力。
- 普通终端写入的成本也须可按原 Host、Session、Run、Region 和终端实例观察，区分 live、history、checkpoint 的写入次数、解析回调完成与实际 render 回调。二进制按字节、字符串按 code units 计量，不为诊断额外编码或混淆单位。累计量从原实例创建起算，销毁后不冒充当前实例；回调等待是墙钟时间，不能标为 CPU、实际显示或 Runtime ACK。复用当前 Performance 与公开 metrics 观察，不新增后台采样循环或保留输出正文。
- Session 事件的同步工作沿原协议类型提供固定有界分类，未知类型只累计为未知，不保留任意类型文本或事件正文。公开 metrics 和 Performance 消费同一记录，展开后可见记录器生命周期内的次数、同步总时长和峰值，与近期时段分开标明。该时长包含原处理函数及同步订阅中发生的工作，不覆盖之后另行调度的异步 React、布局或绘制，也不能拆出其中的原生 CPU 成本；嵌套调用可能重叠，不能相加为 CPU 份额。未进入该处理函数的终端输出仍由原终端成本观测负责，零计数不能解释为没有输出工作。
- 相同通知身份的派生只随相关源事实变化，历史条数、无关 Session 和父层刷新不能重复触发完整错误编码。同一组件消费同组事实时应复用一致快照，避免重复检查与分配；隐藏工作面的相关变化、输入和恢复能力仍然实时可用。
- 默认不保留过时实现的兼容层、legacy、fallback 或临时 workaround；这不授权丢失数据，也不撤销[Topic／Mote 已授权的目录搬迁](motes-and-coordination.md#topic-与-mote-的物理目录)或[笔记库搬迁](knowledge-workflows.md#笔记目录设置与搬迁)。复用当前依赖和平台能力，在权威事实的所属层修复，避免为探测、重试或性能增加竞争状态与中间层。P2/P3 的独立问题不能作为本轮 P0 交付的阻断门。


## Settings 分类的悬停与焦点

- Settings 窄窗分类入口同样遵守少点一步。鼠标悬停触发器、分类项，跨项和间隙到离开，全程只展示选项，不切换分类、不保存，也不夺正在编辑的输入与光标；自然收起或 hover Escape 保留原输入。鼠标明确选择不同分类后关闭；没有用户或动作已建立的新焦点时，焦点回到连接且可见的分类入口，键盘开启后的 Escape 同样返回该入口。外部点击或动作已经建立的新焦点不被拉回。分类切换保留已访问页的未保存草稿和阅读位置；禁用、搜索筛选及点击、键盘、触屏的完整操作仍成立。


## 跨会话注意力与系统通知

全窗 Agent 注意力汇总只在[Focus 入口](focus-context.md#focus-执行上下文项目泳道与底部时间音轨)出现，消费已有 Session 与 pending interaction 事实，不另建全宽汇总栏或第二份待办。Needs you、Error、Working 与实际结果分别表达，计数为零不伪造状态证据。明确跳转按准确 Session 定位；同类多个待办时优先 `status.observedAt` 最早者，辅助文本包含真实对象、数量与动作。

需要展开明细时复用同一全窗聚合与准确 Session 投影，关闭后释放该明细的展示消费；不为待答请求另建消息列表或状态机。明细以 needs-you、error、working 排序，同类按 `status.observedAt` 最早者在前；它与明确跳转使用同一来源和落点，不在状态栏另加入口。

- 名册的每一行显示该 Agent **启动时固定的授权范围**。它来自 Core Session 记录里已持久化的 launch-option 选择，经 DESCRIBE 半边（仅 choice id）跨 IPC，标签由 Renderer 用 Provider 自己的 catalog 声明解析——argv 仍然不出 Core。两条诚实规则：创建时未收窄任何一项则**什么也不显示**，绝不写"默认"（那是无人记录过的事实）；选择所对应的 option 或 choice 若 Provider 已不再声明，该项**丢弃**而非渲染裸 id（一个 `bypass-all` 当标签显示，会像一个已核实的授权，实际却无从解析）。行上最多一枚风险标记，取该行诸范围中最宽的那一档；Provider 未声明 tier 的选项不被补成 `safe`。

- **窗口外也能看到有几个 Agent 在等你**：macOS Dock 徽标持续显示已有全窗口 `needsYou` 汇总的当前数量，为零清除。窗口聚焦不等于请求已解决，前台也按真实数量更新；这不是未读消息或通知次数，不能另存一份待办。启动即投影当前事实，只在相关 Session 变化时更新，其他平台没有原生 Dock 时安静跳过。系统徽标更新失败通过已有非阻塞提醒说明，可在后续相关变化重试同一数量，不能影响 Agent 输入、状态和草稿。

- **通知要说清是谁、什么状态、在聊什么**。一句"Agent needs you"不足以让用户决定要不要放下手上的事——他需要知道是哪个 Agent、现在什么状态、Agent 最近说了什么、自己最近问的是什么。通知正文因此带上最近一轮对话的摘要（Agent 最近回复 + 用户最近提问），而不只是一个名字加一句泛化描述。内容从既有的 Session 投影与 Activity 时间线派生，不为通知另建一份对话记录；取不到时如实略去那一段，不填占位文字。

- **停留时长是一条滑轨，从关闭到"等待用户确认"**。用户看到通知时往往正在别处，一闪而过的提示等于没发。这条设置是一个连续的量级选择——`关闭` → 若干档停留时长 → `等待用户确认`（不自动消失，用户点过才走）——而不是一个"开/关"加一个隐藏的时长输入。默认档要足够长到用户能读完带对话摘要的正文。滑轨的取值只有一处定义，通知投递与设置界面共用它，不各写一份档位表。

- **设置明确投递范围。** Notifications 的停留时长与声音控制 OS 横幅，设置首层明确说明这个范围；Off 关闭 Agent 状态横幅，不清除窗口通知中心、原问题或阅读记录。A2A 的跟随／静默／提示继续沿原偏好；声音为两类横幅共享且始终可编辑，不因 Agent 状态横幅关闭而置灰仍有消费者的偏好。不把 OS 提醒当成 Inbox 已读、任务接受或业务完成。平台不支持或不能满足所选停留模式时，同一平台限制沿原投递结果作一次具名说明，不因注意力与 A2A 两种消费者重复报同一能力限制；点击横幅继续回到准确 Session，不改变原通知与请求的生命周期。

- **后台 Agent 主动出声**：完成、需要你、失败三类状态跃迁在用户看不到该 Session 时升起系统通知。原生通知能力只由 Desktop Main 持有并经 typed IPC 暴露，Renderer 不直接触达 OS，也不持有第二份通知状态；点击由 Main 聚焦窗口，去哪个 View/Region 仍由 Renderer 决定。"是否值得打扰"是一个**纯判定**，由通知、上卷与名册三面共用，绝不各自从状态字段重新推导：同一状态重复上报不算跃迁（Provider 会重播状态）；首次见到不算跃迁（否则挂载到一屏早已完成的 Agent 上会炸出一串通知，教会用户忽略这个通道）；用户正在看的那一个不打扰（点与 Activity 已经在讲了）。可见与否是**派生**的而非猜测——某 Session 占据某个 Tab Group 当前活动 Tab 的一个 Region 才算在屏上，因此窗口聚焦时仍会为背后 Tab 里的 Agent 发通知。投递结果是 typed 的：`shown` 与 `unsupported` 必须可区分，平台或用户系统设置拒绝时**明确降级并只报一次**（会拒绝的系统每次都会拒绝，重复上报会把一次诚实失败变成噪音），此时窗口内的点与 Board 仍照常承载该事实。关闭通知期间发生的跃迁只推进基线、不排队，重新打开不回放积压。


## Projects 状态与 Activity 菜单

- Projects 栏的 running/error 计数保持可见，但采用紧凑的图标与短标签，避免挤占目录树空间。

- Activity 的 Zone／Tab 组织、共享 Agent 行、hover 预览、准确选择、窄面返回及未知位置处理统一见[Activity 活跃入口与空间级联](focus-context.md#activity-活跃入口与空间级联)；本页不另定义工作线聚合或组级 Agent 选择策略。状态持续时间沿[Agent 已经这样多久了](agent-capabilities-and-messaging.md#agent-已经这样多久了)，不把最近活动时间冒成状态起点。

- Claude 与 Codex 的 Executor 设置提供一个明确的“一键 YOLO”操作；它写入该 Provider 已验证的无人值守启动参数，并立即保存。该操作只影响后续启动或恢复的 Run，不伪装成运行中进程的实时开关。

- 全局 transient `reportError` 不得固定在工作区底部遮挡内容。它应停靠在不覆盖主工作面的 notice 区，带清晰的关闭按钮和可访问名称；关闭只隐藏当前展示，不删除 Runtime/Session 事实，并保留从状态或诊断入口重新查看的路径。持久服务窗的事实保留、收起与复查统一沿[《我们的流程坏了，不等于 Agent 坏了》](session-recovery.md#我们的流程坏了不等于-agent-坏了)，不另设不可关闭的例外。

## 主题编辑与文件交换

Appearance 同时提供主题身份与 dark / light / system 明度选择，编辑、预览、恢复、保存自定义主题及本地上传/下载共用原设置 owner。预览明确是未保存状态，取消回到已保存主题；切换或退出设置不丢原编辑草稿、composer、Tab/Region、焦点、选择和健康 Run。保存失败保留主题草稿与已保存数据，给出失败阶段和可执行重试，不以失败关闭健康能力。

主题文件使用明确格式与版本，完整携带稳定身份、已支持视觉字段、完整双明度及语义图标资产。导入先校验并预览，不自动应用或覆盖；不支持/无效/超出单文件资源边界的输入须说明原因且不写盘。名称不是身份：重名可明确区分；同 ID 同内容可复用，同 ID 不同内容须显式另存副本或带当前期望值替换，取消不变更数据。导出后删除仅用于测试的自定义主题，再导入应用应还原相同视觉与图标。内置主题只读，修改另存自定义；删除当前自定义主题与返回默认主题在同一原 owner 事务完成，保原明度和显式 Terminal 配色。

图标编辑选择语义项，替换图形不改动作标签、可访问名称、状态或命中几何；资产为有界声明式数据，不执行主动内容或外部请求。完整可改范围与默认映射归[共享主题规范](../presentation/shared-rules.md#主题与样式-ssot-规范)。主题目录、选择及自定义资源的公开查询/修改复用 Settings 公共服务、严格解析和回执，GUI 与 CLI 共用校验与持久 owner；不能只闭合 GUI。

业务组件与原生适配按稳定语义名字消费图标，用户修改的是该含义的图形；共用默认字形的不同含义可分别替换。设置提供完整语义目录、用途和默认图形的发现、搜索及可视化选择，允许还原单项，并保留有校验反馈的声明式 paths 编辑。设置搜索按图标相关用词可定位 Appearance 的原主题设置，入口明确说明图标定制与真实控件预览的位置。预览、取消、保存及文件交换沿原主题 owner 完成；无效编辑保留原草稿，不覆盖已保存主题。公开主题查询同时提供同源语义目录及可用字形，公开修改继续使用完整主题资源，不另建图标配置或第二套保存路径。

Message Tool 下的 amux Protocols 是只读参考，查看本地随产品交付的全部可读格式、用途、精确 wire 示例与原消息卡片预览。目录、搜索定位和摘要直接派生自 Core 同一协议定义；协议格式与维护边界归 [amux 规范](../../specs/amux-protocol.md#通用命名协议与阅读目录)，不在设置复制类型清单、parser 或业务含义。新增原定义随编译自动出现，不要求修改导航壳、另写搜索项或维护文档副本。

目录不新建 AppConfig、Main scalar、RPC、运行时发现 Store 或操作入口；本地 Skill／help 使用同一公开定义提供发现，不连接 Runtime、不宣称所连远端或旧安装支持全部格式。预览只使用原共享阅读组件和明确样例，不读用户内容、不触发取信／发送／接续。设置现有搜索、窄窗菜单和信息定位机制继续适用。
