## 状态栏

- 状态栏是**整窗唯一**的跨 Session 汇总。每一项都必须是别处没有、且用户需要一直看见的事实；Tab 点、Board 列、Agents 工具各自有作用域，状态栏不重复它们。
- **活跃/待机计数按 Provider 分类展示**。「活跃」不是状态栏自己的定义——它就是 Board 的 working 列（`sessionBoardColumn`），其余一律算待机。同一个 `running` 的 Agent 绝不能 Board 判它在跑、状态栏判它待机；照抄一份 switch 正是这种分歧的来源，所以计数调用那一个函数而不是复述它。这与关注度汇总（`summarizeAgentAttention`：谁在等我）是刻意并存的两套口径，回答的是不同问题。零 Agent 的 Provider 不占位；全闲的 Provider 压低但仍在场——消失会让"这个 Provider 总共几个"失去出处。守护：`agent-status-bar.test.tsx`。
- **资源指标只在展开时采样**。折叠态不得触发任何进程扫描——一个常驻的全主机 `ps` 轮询会让空闲窗口持续耗电。展开后按固定周期采样，关闭即停。并发调用共享同一次进行中的采样（in-flight 去重），一次轮询风暴只产生一次子进程。
- **一次全主机扫描，按 pid 子树归并**。为每个 Agent 单独起一个采样进程，开销随 Agent 数线性增长；正确做法是一次扫描后按 run 的 pid 归并出各自子树，共享祖先按注册顺序只归第一个，避免重复计数。
- **只声明证据支持的口径**。输出字节速率就叫字节速率，不除以一个系数冒充 token/s——终端字节含 ANSI 转义与 TUI 重绘，与真实 token 数不成比例，一个无法验证的数字比没有这个数字更糟。
- **token 用量报累计量，永不报速率**。分子（token 数）必须由 Provider 自己报出：声明 `usage` 能力的 Provider 在 turn 收尾时由 hook 进程读一次自家 transcript 尾部，把这一 turn 的真实 token 数随既有回执带回（`AgentUsageCapability` / `AgentTurnUsage`，守护：`agent-usage-transcript.test.ts`、`agent-usage-capability.test.ts`；catalog 声明到 hook 环境那次注入由 `agent-usage-env-injection.test.ts` 守，断了它整条链会静默失效而其余全绿）。**而分母没有诚实的取法**：`tokens/s` 的分母（turn 墙钟时长）含用户思考、审批等待、工具执行、网络往返，是我们自己拼的、不可验证的数——真实分子除以编出来的分母，仍是编出来的数。所以接入之后也**不给任何速率**，只报「最近一个 turn」的累计量并在 UI 上明说是哪一段。这条口径的落点是**名册行**而不是状态栏：用量是每个 Agent 各自的事实，跨 Session 加总它没有意义（见上文"状态栏不重复有作用域的指标"）。三态各自不同且一态都不许塌成 0——报了用量、声明了但还没有一 turn（显示"不知道"）、根本不报用量（明说不报），守护：`agent-usage-display.test.ts`、`agent-roster.test.ts`。

## Settings 中的 Keyboard shortcuts

用户要求「快捷键设置也应该放进设置」。快捷键在同一 Settings 导航、搜索与 Overview 可发现；原快捷键入口与公开 `help.shortcuts` 指向同一实际 registry，命令、平台和弦与作用域不另维护一份列表。作用域、IME 与 Terminal 原生键消费仍沿既有快捷键合同。当前只读手册与可编辑配置必须清楚区分；未接入真实分发和唯一持久 owner 前，不能提供仅修改显示的录键或保存。后续可配置绑定须同时供实际分发、编辑器提示和 CLI 消费，冲突与保存不得另建假配置。

## Activity 工作线展开信息密度

- `Activity by work line` 折叠态保留工作线摘要和“选择一行打开”；展开箭头只在确实有额外可操作或诊断信息时出现。
- 展开项不得重复聚合行已经表达的名称、Provider 数量和状态。明细优先显示 Agent 图标、最近活动、状态原因、空闲/停止时长和可直接处理的动作；没有新增信息时保持折叠或隐藏展开控件。

## 通知关闭后的稳定性

- 用户关闭某条 transient error 后，同一错误由重复事件、轮询或恢复重放再次到达时不得重新弹出。只有新的错误内容，或用户主动选择重新查看，才能恢复提示。
- 原始错误事实继续保留在可重新打开入口；关闭的是当前展示，不是删除诊断记录。

## Status Bar 状态图标与 Activity 详情

- Status Bar 的 Agents、Needs You、Error 必须使用语义图标加紧凑数量，不能只用点或无来源的装饰形状；hover/辅助文本说明对象、数量和动作。
- Activity 展开应是诊断/处理面板，不重复聚合行已有信息；单 Agent 且无额外诊断时不显示展开箭头，多 Agent 或有原因/时长时才展开。

## Status Bar CPU/Memory 资源面板

- 用户要求「性能指标在右下角的观测面板看不出」「ctxmux 的泄漏管理应该也能看出来」。观测面板必须分清应用、Agent CLI 和 ctxmux：应用按 Main、Renderer、GPU、Browser/Utility 显示 CPU 与内存，Agent 按现有 Run 归属，Runtime 显示其公开合同提供的 Run、attachment、保留输出及回收事实。不能以应用内存总数代替卡顿来源，也不能从 RSS 高直接判为泄漏。
- 用户进一步反馈「有些 agent 的占用不太正常」「Storage 里面有的 agent 占用都有一个多 G 的内存」。Agent 行必须说明其数值是 CLI 本体还是含后代进程的 RSS，并能按同一 Run 的真实进程归属区分本体与子进程用量、数量；磁盘 Storage 不得被读成进程内存。同一 PID 不能重复归给不同 Agent，归属缺失或 PID 身份不能确认时明确未知。高占用复核绑定实际运行版本、采样时窗、活跃负载与进程树；协作子 Agent 或工具进程仍被活 CLI 持有，不等于无用孤儿，低 CPU、进程年龄与 RSS 高都不能单独授权清理。只有证实的无效保留才在原资源 owner 修复，不能停止、重启健康 Run、删除工作面或以改变用户负载制造改善数字。通用成本与连续阅读的验收条件仍以[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)为唯一来源。
- 进程指标、资源 owner 数量、保留历史容量与回收结果是不同事实；观察时间、CPU 聚合口径、未知/过期与失败原因必须可读。应用 CPU 的测量区间平均与 Agent 的平台 ps 平均读数必须分开说明；10 秒读数峰值不能冒充同一种瞬时 CPU。首次尚未形成 CPU 测量窗口不能冒充 0；Runtime 缺少公开指标时准确说缺少什么，不读写其私有数据库来补一个假完整面板。
- 资源观察只在有明确消费者期间工作：UI 展开、一次公开查询或一条公开观察流都属于消费；最后一个消费者离开后停止，慢观察不堆积。一次查询结束、期限到达、消费连接关闭、窗口或 owner 销毁时，属于该消费的监听与采样一起释放，建立尚未完成时离场也不能留下迟到消费。多个消费者共享同一 Main 采样，不按指标、消费者或采样 tick 另起采样或 CLI；Runtime 存储不随每秒 process 采样重读。在途读取即使无法取消，其迟到结果也不回写已结束或新的消费。局部指标失败不使其他指标消失，也不停止、删除或重启 Agent；既有孤儿目录回收与当前 Run 的历史回收分别显示，打开面板或查询不是删除历史的授权。
- 公开资源观察说明所在 Unix Host、Main 与窗口身份；本地进程读数只能归属该 Host 上身份已确认的 Run，远程 PID 或未确认归属不得当作本地真值。Renderer 计数属于具体 connected 窗口及其代次，缺席或旧代次不能冒充当前零值；计数 getter 未建立或读取失败保持未知，其他已确认计数仍保留。Runtime 没有公开 CPU/RSS 时保持 unavailable，不以看资源为由连接、恢复或停止 Run。
- 各来源保留其实际观察时间、最近成功时间与 pending、unavailable 或 stale 原因；process 新帧不刷新旧 Runtime、storage 或 Renderer 值的年龄。存储读取没有源时间时由实际读取 owner 记录本次观察时刻。公开 watch 只承诺有界最新观察，慢消费者不积压无界帧，停止后旧值只能明确作为历史，不能冒充新数据。
- Terminal 访问、切换、滚动与刷新卡顿的诊断须沿既有公开资源查询和观察取得同一 Renderer 代次的有界成本摘要，区分可见与隐藏消费者的检查、实际变化与渲染，以及终端输出处理与 Renderer 事件循环延迟；不能只报 owner 总数或依赖临时 DevTools 注入才取得这些事实。只输出聚合计数、时长、容量、必要归属与观察条件，不读取或导出终端、Prompt、历史正文及用户输入。采样工作量、耗时、保留量与输出量有明确边界，采样自身耗时及截断、缺测可辨；观测不能成为随无关 Session 或内容增长的重复全量遍历。Renderer 繁忙或未回应仍沿本节来源时效与局部失败合同表达，不延长查询至无界，也不干预健康 Run 或原工作面。 该摘要使用 Renderer 存续期间的有界轻量记录器：固定类别计数与最多 32 条慢事件不持有正文、不新增轮询；主线程长任务与 Event Timing 输入等待监听归 Renderer owner，离场即断开，支持性与失败明确。公开查询与 watch 的周期采样仍只在消费期间工作，不因轻量记录常开而常驻进程扫描。终端写入时长是等待解析回调的墙钟时间，展示投影可见、画布揭示、回放、输入 gate、在途写入及积压分别表达；展示投影可见不等于画布已经揭示或已响应，允许输入不等于输入已响应或已被 Runtime 确认。Event Timing 只统计浏览器实际提供、总事件时长至少 16 ms 的样本，等待时长使用 processingStart−startTime，不能以无样本冒充全部输入无延迟；长任务时长也不冒充输入延迟。
- 顶部已有页签的访问等待按实际呈现面与精确 Workspace／Group／Tab／Region 归因，沿同一公开摘要分别记录事件到 handler 的等待、选中、原 host 放置、终端当前揭示、本地帧与输入 gate 开放时点。缺测保持未知；Activity 等非终端模式明确不适用。已揭示的保留终端读取本次当前事实，不要求重新 attach；快切、重复呈现与旧代回调不能串成另一笔成功。只保留最近 16 次切换，不新增正文读取、全工作面扫描、轮询或输入门禁；本地帧不冒充 compositor 首帧，gate 开放不冒充输入响应。
- 关闭观测面板、切换页面、销毁窗口或替换订阅时，属于这次订阅的采样与生命周期监听必须一起释放；反复打开不能留下逐次增长的监听闭包。释放是同一订阅 owner 的幂等动作，不依赖下次打开或人工清理。
- 每个资源对象尽量显示所属 Project/Workspace、Agent/Provider 和最近活动/idle 时长；没有归属时明确显示 unknown。资源采样与 Agent 语义状态分开，不能把低 CPU 误判成 Agent idle。信息层级与紧凑布局归 Surface 密度合同。

## Toolkit 与官方 Performance 工具

用户要可自行扩展的 Toolkit：「配置一个工具和对应的图标」，包含脚本、Agent 任务、定时执行和交互按钮；hover 能看执行结果与动作，配置和操作也能通过 CLI 完成。用户随后明确：「toolkit 还是默认在 statusbar 从右往左排列吧，和左侧功能区区分」。用户最新纠正：「设置还是放左边」。Settings 的唯一普通入口回到左侧功能导航末端，使用同一设置导航 owner；打开或再次点击收起既有设置面，不改变当前工作面选中状态、原输入或工作面。Toolkit 仍与左侧功能区分开，位于右侧 utilities group，默认由右向左增长，Performance 位于右端工具位；快捷键帮助与状态提醒留在右侧、位于 Toolkit 左侧。Settings 不留第二个右侧入口；不把设置开合伪装成主工作面选中。摆放方向不改变文字方向、原焦点、原生 Tab / Shift+Tab 与输入语义，不新增排序配置、registry 或 RTL 文本。UI 与 CLI 使用同一配置、执行与结果 owner；查看、hover 或保存配置不隐含执行副作用或开启定时任务。未交付触发能力须明确其实际范围。

用户进一步确认「performance 就属于一种内置 toolkit」，要求所需查询信息开放 CLI，官方 Performance 通过脚本组合这些 CLI 完成。该脚本随产品发布，可查看但用户不可编辑、覆盖或替换其内置身份；展示内容、启停、样式与布局可配置。Performance 真实经过公开查询、官方脚本和通用 Toolkit 结果展示，不能在 UI 保留另一条绕过脚本的私有取数路径。官方代码只读不等于扩大执行权限；Performance 自身只查询观察。

用户再次强调「界面和 toolkit 的性能要好好优化」。性能取证覆盖同一条实际执行链的界面呈现、公开查询、脚本、结果解析与消费生命周期；各层只为相关可见消费者做必要工作，不能靠停止健康 Agent 或清空工作面减少成本。资源观察与释放只定义在[《Status Bar CPU/Memory 资源面板》](#status-bar-cpumemory-资源面板)，界面动态与隐藏工作沿《Settings 全分区完成度与相关消费者成本》，不建立另一套采样或性能账本。

用户继续明确「performance 界面的设计还是一塌糊涂」，要求真正 Toolkit 化、界面交互发挥全部设计水准。Performance 的第一层帮助用户读懂当前应用与 Agent 的资源占用、观察期间的变化及主要消耗对象；进程树、口径、owner 和 Runtime 存储在具名详情中可达。趋势只使用这次真实观察期间取得的有界样本，缺测或停观不能补假曲线；不同 CPU 口径不合成一个机器负载，RSS 不画成没有总容量事实的系统内存百分比。未知、过期、暖机和观察失败在对应来源就地表达，局部缺失不掩盖其余真实读数。

Performance 的观察、暂停、恢复、查看官方脚本及显示配置沿同一工具身份和执行结果；暂停只释放本消费者，绝不停止 Agent 或其他观察者。Hover 预览不夺走终端或编辑输入焦点与 selection；点击及键盘可稳定进入同一非模态操作内容，原生 Tab / Shift+Tab 可到动作和具名详情，焦点在浮窗内时不因指针离开而关闭。退出归还本次实际入口；仅 hover 后退出保留原输入焦点，指针移到浮窗操作不会意外关掉。仅 hover 且焦点仍在原 Terminal 输入时，Escape 关闭预览并原样传给终端；显式进入、浮窗内操作或 Settings 编辑输入时，Escape 只关闭最上层工具，不连带关闭 Settings 或丢失草稿。显示或布局配置保留未保存草稿与原字段期望，保存和执行分开，UI / CLI 同一 owner 的冲突与 unknown 事实不可被乐观成功掩盖。

Performance 原启用与 icon / label 默认、关闭入口不持续观察、手动观察理由与各消费者独立释放保持原合同。首个用户工具支持用户保存的本地 JavaScript ESM 脚本、固定目录和参数、名称与图标，普通 UI 与一条 toolkit CLI 使用同配置、执行及结果 owner。保存、显示启用、查看、hover 和订阅不执行用户脚本；只有显式 run/action 准入，关闭浮窗只释放阅读者，在途脚本到真实终局或明确 exact stop。源码可访问当前 Unix 用户本地文件、环境和网络，不承诺 sandbox、权限隔离、secret vault 或自动脱敏；定时、远程和 Agent 任务未交付前不显示成可用能力。

Toolkit 设置以同一层级的工具列表呈现内置与 Custom 工具，按来源分组。Auth / Account usage 是预装到用户本地配置中的普通 Custom 工具；预装的是独立本地扩展目录、可编辑源码与普通包引用，产品界面消费当前用户配置与本地 manifest，执行读取当前包文件，不在 Renderer 保留一份固定账户业务对象或以“采用模板”为进入它的前置。首次完成预装后，它直接出现在 Custom 分组，与 Performance 等内置工具平级；是否在 status bar 显示沿其本地显示配置。名称、图标、源码与动作在包文件中编辑，启用、显示、固定工作目录和运行参数沿同一配置 owner 保存；整个包可改为完全不同用途，编辑器、列表和结果明确其 Custom 身份。产品只持有通用 Toolkit 加载、配置、执行与结果，账号观测业务由用户脚本持有。后续用户编辑、删除与其他工具内容均完整保留，不能因启动或升级覆盖、重复添加或复活已删除配置；首次安装与已有用户的一次预装须沿同一配置 owner 明确处理，不从空列表猜删除或安装历史。检索词只帮助查找，不代表已取得或验证实时鉴权状态。查看、保存、hover 与订阅不执行用户查询，预装也不等于执行；目标未配置时在原工具处明确说明，不猜账户或伪造结果。显式工具目标仍精确直达，缺失目标不替换成另一个工具；切换保留未保存草稿，明确取消新建只撤回该工具草稿、不影响其他工具草稿，删除或取消末个用户工具回到自定义创建空态。官方 Performance 在内置分组清楚可达，保留原不可编辑身份与可写显示配置。

用户进一步明确：「这个不是写死的……完全是用户可以基于 toolkit 自行实现的一个 example」，示例工具可在与 AgentMux 无关的 GitHub 仓库独立开源和维护。AgentMux 只提供通用配置、执行、结果与动作消费；账号查询、额度／重置卡解释和外部工具适配属于示例源码，不进入 Core 或 Main 的业务分支。示例接入遵守公开 Toolkit 的脚本输入、结果和配置合同，无需注册产品专用身份或修改 AgentMux 源码；产品随附配置在新用户首次本地配置初始化时预装为普通用户工具；既有配置不因启动或版本变化被补回或覆盖，已有用户的明确预装沿原公开配置写入。预装不赋予额外权限，也不把独立仓库自动发现、安装或同步描述成已交付能力。

额度窗口的剩余量与自然重置时间、余额、可用重置权益及每项的发放／到期时间分别表达；数量、时间、状态、来源或时效缺失时如实未知，矛盾历史不伪称可信总数。执行完成时间与来源更新时间分开，绝对时间保留可辨时区，快照中的倒计时明确其观测时间；不把缓存成功说成 live 成功，不把卡片到期说成窗口自然重置。账户与查询范围来自保存的脚本和参数，不由 UI 当前焦点或显示名猜选；旧结果不暗换目标。预装脚本默认观察 codexL 全局当前账号，以该查询明确返回的 active_account_key 精确匹配；未返回该身份或匹配不唯一时说明未知，不选择第一个账户，不冒充任何 Agent Run 的账户。预装账号脚本只调用已有公开外部工具，适配位于用户可编辑源码；Core、Main 公共机制不增加厂商分支、第二份账户／凭据存储、registry 或 sampler。首版只提供手动观测，不预置续凭据、切号或用卡动作，不自动执行、后台刷新或定时启用；相应动作以后独立审阅真实公开协议与权限，不能从结果文本产生命令或授权。可权威确认的外部查询失败沿原工具 failed 结果表达，来源字段未知在本次有界文本中就地说明；观察、终局或持久确认未知保原确认事实及必要准入，健康工作面不受影响。恢复沿原配置、执行结果和工作面合同，不新增上一成功快照缓存或结果历史。

用户工具每次准入捕获不可变配置 revision、固定目标和明确 invocation；相同已保留 invocation 不重复执行，旧请求无保留事实时不猜重放，unknown 只限制该工具新准入，不停健康 Agent。修改只影响下一次，disable 影响显示与新准入；pending/running/unknown 工具删除沿 UI/CLI 同一持久提交与执行准入完整性拒绝，不以删除配置假装停止。动作仅来自已保存配置，绑定原结果 execution/config 和目标；配置、动作、目标或最新确认结果变化时旧按钮明确冲突，输出文本不能创造命令或权限。

用户点停止只针对原捕获的执行。Core 拒绝停止后不能留下“正在停止”或未被接受的 stopped 标记；脚本已自然结束时，只根据同一 Run 的公开终态、exitCode 与完整输出确认原结果并回收，不把后来一次停止请求改写成终止原因。停止回执与终态观察并发时也守同一事实边界；确认不足则保留原准入、旧确认结果与真实 unknown 原因，不猜测错误文案、不自动重放，不影响健康 Agent 的输入。

用户脚本结果是有界 PTY 合流文本，空结果可辨，不伪称独立 stdout，不执行 HTML/脚本。自然完成以 exact Core 终态/exitCode、authoritative 最终输出字节与完整连续接收事实为准，不以静默、观察退出或动画猜成功；Gap、损坏或终局不完整明确失败/unknown。工具 owner 保有限最新确认结果与必要在途准入，仅在关键点持久，不按输出片段写盘；准入先于执行持久确认，结果先于回收持久确认，保存失败保旧确认事实及必要准入，只限对应工具 unknown。普通退出只回收自己创建的 exact 工具 Run；异常重开保结果与准入，经 exact 公开 Core 状态/replay查证，事实不足不清工作面、不猜删或自动重放副作用，不增加 DB/WAL/daemon。

数据权威、Run 与 Agent 生命周期仍由原 owner 持有；指标、unknown、采样及释放只定义在[《Status Bar CPU/Memory 资源面板》](#status-bar-cpumemory-资源面板)，通用工作量与原工作面保护沿[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)。公开查询、脚本和 Toolkit 自身成本也计入，不能按指标或采样周期反复 spawn 多个 CLI、建立第二 sampler 或每工具常驻 loop。执行脚本与 Agent 任务复用现有 Runtime / Core 能力，不把长寿命 Agent 进程管理放进 Renderer。

结果保留真实执行身份、目标、配置版本、来源与时间；未执行、执行中、成功、失败、unknown、disabled 与过期可区分。动作绑定可审阅的内容、权限和原目标；旧结果不能悄悄对修改后的新目标执行，输出文本不能临时产生执行权限，失败或未知不能冒充成功或自动重试副作用。资源查询不授权清理、重启或停止健康 Agent。

手动执行与定时启用让用户能审阅内容、身份、范围和权限，未知权限不自动批准。应用关闭后的定时执行、Agent 完成与结果协议、在途工作修改 / 删除 / 停止、凭据与日志隐私在相应能力交付前明确边界，不预设新后台调度平台。查询余量、刷新鉴权、切换账号仅是用户工具示例，不成为厂商专用核心分支。Idea、使用旅程与尚未确认选择见 Toolkit idea（本机过程资料：`docs/ideas/toolkit.md`）；视觉语言见密度 SSOT[《Toolkit 的入口、结果与配置》](../presentation/settings-and-observation.md#toolkit-的入口结果与配置)。

手机连接是 Performance 之后的第二个官方 Toolkit，在同一 Built-in 库中管理，默认显示在右下角工具区，并可保存启用及 icon／label 呈现配置。查看、hover、打开设置和显示开关不生成链接或改变授权；手机工具以随应用交付的 manifest、入口脚本和具名动作注册为只读官方扩展，经公开 Toolkit 发现、脚本查询、原 Run 执行与通用结果显示消费原 Host device.ls/link。浮窗只显示快速连接和最近查询的设备状态，不嵌入设置管理表单；设置独立承担完整设备、撤销与活动管理。结果里的 URL 保留该次执行事实；普通 Custom 工具的 Copy link 复制原结果。声明复制时运行原 primary action 的工具，结果区复制沿同一动作获取新结果，不直接复制历史 URL。手机显式生成复制的当前链接与回执边界沿[《手机版 Relay 连接》](public-control.md#手机版-relay-连接)，手机打开链接即可使用。关闭入口只结束当前观察，不撤销设备或停止健康 Run。手机 Toolkit 不持有第二份授权、活动账本或 Runtime，未配置和观察失败就地保留事实并提供设置入口。

### Toolkit 本地扩展包

Toolkit 包是独立本地扩展目录，manifest 声明名称、图标、脚本入口和结果动作，目录可独立分发到其他仓库。安装后的业务源码以用户本地包文件为唯一来源；AppConfig 只记录安装位置和该工具的启用、显示、参数及固定执行目录，不保存一份源码副本。Auth 是预装可编辑的用户包，Performance 为系统维护的工具，同层展示，来源分组不成为不同执行平台。

查看、安装、启用或修改配置不运行包。修改包内文件后下次显式运行重新读取；公开 inspect、script、run 和 action 都使用同一个真实包 owner；CLI `toolkit install <id> --path <directory>` 复用原创建业务。每次准入捕获配置及包内容身份，本次执行使用已捕获的不可变源码；文件改变使旧 expected 或旧结果动作明确冲突，不静默执行另一版本。unknown 回执仍保原执行身份，不自动重试，不停止健康 Agent。已有用户创作脚本、工具 ID 和结果保留；删除的是错误的 Auth 模板前置流程，不能据此丢弃用户数据。

包 manifest 使用 `agentmux.toolkit.package.v1`，声明名称、既有具名图标、相对入口与结果动作；当前文件集有界为 128 个普通文件 / 1 MiB，保相对导入布局。每次运行的文件快照由本地 owner 持有，源码或配置改变产生新的有效版本；在途与 unknown 的快照保留，只有精确执行终局和 Run 清理已确认后才回收。外部命令、环境和动态查询仍属于当前用户环境，不承诺沙箱或全环境可复现。原 inline 脚本创作仍是有效能力，但包安装不把源码副本写入 AppConfig。

## 资源与 Activity 观测
Status Bar 的资源面板必须能把每个进程关联到项目/工作区、Provider 与当前 Agent 状态；空闲时显示可理解的 idle 时长。资源数值与 Agent 语义状态分开，缺失数据保持未知。Activity 展开行只补充能帮助定位的上下文，不重复左侧 Agents 入口。

## 验证进程的资源归属

- 用户内存有限，验证失败、超时或中断后不得留下 Electron、文件 observer 或测试 Runtime；runner 报告结束前必须确认本次进程已退出，不能把一条超时日志当作进程结束。一次验证未完成回收，不得再启动下一份 Electron 验证。
- 清理只针对本次验证的进程组、独立临时目录和 Runtime 身份，不影响正式应用和用户 Agent。观察失败必须明确报告，不能当作零残留；先回收进程，再删除它们依赖的临时目录。
- 文件 observer 属于创建它的应用进程；宿主异常退出也必须终止观察，不能成为长期存活的孤儿。此约束不改变 ctxmux 对用户 Run 的持有和恢复语义。

- 验证模式的启动落点只决定初始选择，不能持续覆盖用户或 probe 随后的 Workspace 切换；测试模式不得使项目切换失效。

- 文件树跨 Workspace 的验证事件必须按操作和 Workspace epoch 归属；挂载重建不许复用聚合 DOM 计数推断一次 mutation。Move 提交只产生一条权威 receipt，旧 epoch 的刷新明确记为 rejected，Stop 对已消失 Run 归入幂等终态。

- Tab 拖动默认表达同一 Region 内的排序；只有拖到明确的边缘/方位 drop zone 才表达拆分为新 Region。Split 按钮直接点击默认向右，hover 菜单复用统一方位组件，并按当前布局可行性置灰。

## 全局通知与底部状态入口

- 全局环境提醒也必须可以收起，不能在整个工作面最下面长期占据一整条不可关闭的空间。收起只表示用户已看过，不表示环境已修好；未解决的问题仍可从固定系统通知入口再次查看。问题内容变化时重新提示未读，重启后相同已读问题不反复打扰。
- 全局系统问题与单个 Agent 的消息作用域明确；通知保留失败步骤、当前实际运行方式与恢复动作。通知不阻断健康 Agent。
- Working、Needs you、Error 的列表入口必须是清晰、一致、可键盘使用的同一类控件；跳转 Agent 与展开列表各自保持明确动作，空列表不提供无效入口。视觉约束见 surface-density 的同名条目。

## 设置页的信息架构

用户新增要求：「对照下 `orca`、`paseo`、`deepseek-harness` 的设置界面研究下，整个设置页面结构可以更加优化」。设置的层级按用户任务、对象和真实作用范围组织；单个轻量偏好与复杂资源编辑要有合适的轻重，不能按组件或配置键逐个增加一级页面。重组须保留全部既有入口、未保存草稿、原保存范围、对象直达与搜索；GUI 的导航结构不改变 CLI 的对象、配置键或唯一 owner。对照结论和尚未实施的候选结构见 三项目设置结构研究（本机过程资料：`docs/reviews/settings-structure-references.md`），不把参考产品的作用域或插件平台自动变成 AgentMux 的运行时要求。

用户最新反馈：「现在优化怎么样了？还剩下哪些优化要做？」「当前的品牌感我觉得还是偏弱，是不是给设置一个入口页面？」「上面可以有一些 banner 之类的好看的图，然后有一些好看的视觉动效」。品牌入口页、图像与动效是本次反馈方向；本轮 Root 经有限方案评审选择 Overview 作为普通入口，承认普通字号路径多一次点击；这是实施判断，不伪称用户已回复可选偏好。显式分区与对象直达不经 Overview。具体页面构图与动效仍须实际呈现评审，不能以方案批准代替审美验收，决定见 Overview 实施评审（本机过程资料：`docs/reviews/settings-overview-plan-root-review.md`）。任何品牌入口都保留原八个分区的直接访问、原搜索与精确 Executor ID；不能让对象直达先经过宣传页、要求完成初始化或等待图像／动画。切换入口与分区不丢已访问草稿、阅读位置或焦点，配置仍由原 owner 保存；不自动检测资源、启动或影响健康 Run。Settings 仍是辅助界面，原工作面、关闭方式和 status bar 的原操作归属保持，视觉密度引用密度 SSOT[《左下角导航与右下角工具组》](../presentation/spaces-and-layout.md#左下角导航与右下角工具组)。品牌、图像与动态保护约束归密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)，具体提案见 品牌入口判断（本机过程资料：`docs/reviews/settings-brand-entry-intake.md`）。

**编译期模块贡献。** 用户在明确当前只是组件模块化、还没有 mod 贡献机制，并听取编译期模块注册的有限建议后，回复「优化」。本轮设置功能应通过编译期贡献组合：功能模块自持导航身份、所属组、标题与说明、搜索词与图标、已保存摘要、原编辑器及精确保存适配；设置壳、搜索和 Overview 消费同一目录，添加或调整小设置不要求在壳或概览另增功能分支。Renderer 与 Main 按各自环境静态组合；不把 React 实现塞入 Main/Core，不宣称同一文件可运行时热插拔。CLI 的既有 scalar 声明按功能领域组合，原统一 get/set 与 Main ConfigOwner 消费；公开读取列表按领域稳定聚拢，原键、默认值、合法值、作用范围、partial/prefix、无改动及持久提交语义保持，不把历史偶然交错顺序当合同。新 AppConfig 字段的类型、默认与持久化验证仍由领域作者明确接入，编译期贡献不替代它们；不新增热加载、第三方执行平台、第二 Store/配置 owner、任意路径 setter 或自动推导 schema/通用表单。原八页与 Overview 的入口、直接搜索、精确 Executor、已访问草稿/阅读位置、dirty/pending/失败反馈、未访问页不预挂、status bar 的密度引用密度 SSOT[《左下角导航与右下角工具组》](../presentation/spaces-and-layout.md#左下角导航与右下角工具组)，健康 Run 保护仍遵循本节既有合同。

设置页要像一个现代工作台：侧栏只负责快速定位，主区首屏明确当前设置对象、当前状态和唯一主操作；可编辑内容与只读说明分层，重复说明收起到次级层。搜索、键盘导航、窄窗口和保存反馈必须保持可见且可恢复，切换分区不能丢弃未保存草稿。

**Prompts 的指令库与编辑工作台。** 用户认为 Prompts 的交互差，希望它特别吸引人，并要求整体 review、优化设置设计规范。Prompts 应让用户先认出要用的正文、看懂到达方式和适用范围，再进入明确对象的专注编辑；同一页的资源列表与单对象编辑台承载这一流程，搜索、选择和窄窗往返保留全库草稿。当前对象不在筛选结果时继续具名可见，不自动切换、删除或覆盖编辑。新增后立即进入可编辑的新对象；普通设置的导航、搜索和直接访问沿本节原合同。

名称、关键词、正文、单个 Provider 范围与状态选择仍属于同一条用户 Prompt。新增、重命名、改正文、改范围或状态后，当前草稿有只读使用示意：`/keyword` 与裸词只展开草稿；状态绑定只说明何时出现正文按钮及单击的含义，沿[《按状态配置 Prompt 按钮》](conversation-input.md#按状态配置-prompt-按钮)的发送与 Queue 合同。没有状态绑定时明确只作草稿快捷展开；出现条件不能冒充当前发送能力，示意不执行、不连接 Run，也不提供实际发送动作。追加或暂未知的 Provider ID 保持其原值与明确范围，不被悄悄改成通用。

Prompts 的明确保存动作仍提交全库本次编辑，界面必须让用户看清跨条未保存和待删除的事实，不能把它画成只保存当前对象。关键词和正文必需、关键词在全库唯一，名称可沿关键词作为默认；错误具名到对象与字段，筛选外的错误也能找到原编辑。删除先是未提交的本地编辑，提交成功后才是持久删除，两个结果必须可辨。冲突、外部删除、保存失败或结果未知继续保留原草稿和编辑基线；保存期间的后续输入仍未提交，无关外部字段可刷新 clean 内容，同字段不能静默覆盖。保存与配置 owner、CLI 的完整回执及原工作面保护沿本节原合同。材质、排版与宽窄构图归密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)。

**Settings 全分区完成度与相关消费者成本。** 用户反馈「现在渲染感觉有点卡」「现在只有 prompt 页面比较现代化，其他是不是也都优化下」。所有真实设置分区都要具有一致的交互完成度，同时保留各页目的、原草稿、expected、保存范围、输入节点、焦点与 IME；视觉层级见密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)，不复制 Prompt 的工作流给无关设置。

Settings 的工作量应随真正相关的消费者与事实增长。无关 Session、Host 或 timeline 更新不能持续放大可见设置或已访问隐藏分区的 render、draft reconcile、probe 和 observer 工作；隐藏保留草稿与必要配置基线同步，恢复可见时读取最新相关事实。自己拥有的视觉工作在静止、离场或 document 真正隐藏时收敛或停止；不能通过清空草稿、停止健康 Run、移除工作面或把未知当成功制造性能改善。Terminal 连续阅读与原工作面保留仍以本文件[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)的成本合同为准，不另建常驻 sampler 或 Runtime 事实。

卡顿原因未确认时保持 unknown。性能结论区分 Source、编译 Renderer 与实际加载包，绑定场景、资源规模、采样窗口及非空实际帧、commit、重排和 CPU 来源；CSS 参数、零计数、另一页通过或历史安装身份不能代签实际流畅。先用真正相关更新证明观察器连通，再核无关更新的工作量；不得因性能优化丢掉配置变化、后续输入或真实错误。

**设置与 Prompt 的连续切换。** 用户反馈：「Prompt 界面比较现代化了，可以再高级一点吗？设置界面的液态玻璃好像只是做了下样式，没有 liquid 那种切换和交互时流动效果，可以找找 github 上的高质量参考」。当前分区与 Prompt 对象的选中事实仍由原导航及指令库决定；连续反馈跟随本次明确选择，不能等动画结束才切换，也不能把 hover、反光、迟到动画或快速往返变成另一次选择。搜索、筛选或窗口重排后只表达仍真实存在的目标；目标不在当前可见列表时不画在邻居上，不冒充已经选择其他对象。动效不改变原点击、搜索、分类菜单、键盘与关闭语义。

Prompt 的当前对象、未提交修改与只读使用示意应在同一编辑工作台清楚可辨；对象修改事实来自原全库草稿及编辑基线，不另建“动画草稿”或另一套选中状态。切换和指针反馈保留原输入节点、已访问草稿、阅读位置与原焦点归属，不能为动画重挂编辑器、整页淡出或另建正文副本；新增与窄窗返回仍按原明确动作定位焦点。组合输入期间的反光、重排或动效不得抢焦点、打断组字或触发发送。全库明确 Save、删除与 Undo、原 expected、保存期间后续输入、外部提交与失败恢复沿本节既有合同；使用示意仍只读，不接入 Run。材质、流动与停止边界归密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)。

- 设置结构优化必须落到真实页面。日常 Preferences 在前（Appearance、Notifications、Browser、General），资源配置随后（Agents、Prompts、Workspaces），环境连接与手机设备接入独立归入 Connections；原能力全部保留，Copied paths 在 General 内与本地数据／诊断分层，原单字段草稿、expected 和保存范围不扩大。统一底栏入口进入 Overview，Workspaces 从资源导航进入；不新增第二齿轮，显式分区与 Executor ID 仍指向原精确对象；不保留独立 Copy Paths 页面或另造兼容路由。搜索仍能定位路径、`~`／absolute、字号、通知、日志、恢复、Provider 与设备接入。诊断或只读说明不进入偏好保存，不自动触发资源检测或更改健康 Run。

- 用户要求「继续，直到设置界面质量彻底满意」。设置作为辅助界面，第一眼必须是当前对象和动作；Workspace 与 Executor 可按名字、路径或身份检索，大量资源不靠逐条扫读。Executor 常用身份与外观优先，高级启动配置按需进入；已有 Provider 与 Executor ID 保持不可修改，新 Executor 创建后直接进入编辑。改变分组或检查结果不能丢失展开、输入或焦点。
- 设置保存仍经既有公开 API，启动配置的说明应明确针对后续启动，不能冒充已改变健康 Run。高级权限动作保持显式选择，不自动批准；所有分区保留原功能、草稿、错误反馈和 status bar。
- 启动参数的可编辑表示必须与实际 argv 可逆；追加或修改一个参数不能拆开其他参数中的空格、引号、反斜杠或空值。
- 字体字号等数字设置必须允许清空、选中替换与逐位输入完整值；输入中的未完成值不能被立即钳位或舍入打断。明确保存时才验证有限整数和实际允许范围，非法输入保留草稿并说明原因，不改变已提交值；滑块选择保持合法，外部 CLI 提交、冲突与保存失败仍遵守同一草稿保留规则。
- 外观与终端主题的单选组遵守完整键盘行为：Tab 进入当前选择并能离组，方向键移动并选择相邻项、两端可回绕，Space 可选择焦点项；当前选择与键盘焦点都清楚可见。只给按钮标注 radio 角色而没有相应行为，不算键盘可达。
- Terminal palette 的小预览是静态配色示例，只帮助比较输出与输入的外观，不表示正在运行的 Terminal 或 Agent，也不因展示示例创建 Session、Run 或刷新循环。原选择、草稿、explicit Save 与 expected 合同保持；示例可读性与密度见密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)。
- Executor 与 Prompt 的 CLI 按稳定 ID 明确 list/get/add/update/remove，与界面共用原始编辑基线和配置事实。add 不覆盖已有对象，update 不默默创建；启动参数与环境整项替换并允许明确清空，正文逐字保留，支持的数据 key 不可在成功后静默丢失。外部提交仅刷新 clean 内容，保留 dirty 与保存期间后续编辑。Prompt 的 Provider 过滤可以更换或解除，删空 Prompt 库重启后仍为空；头像 Reset 不能复活旧装饰。
- Agents 已有的可用性刷新应在界面与 CLI 中检查明确的已保存 Executor 和 Host；CLI 不按焦点、显示名称或默认 Host 猜目标，列表汇总与一次精确检查分别表达。检查只说明本次连接上配置命令能否取得普通可执行文件，不冒充 args、env、登录或 Session 健康检查。Available 必须有本次普通文件与执行权限事实，可搜索目录或其他已确认非普通文件不能算可执行文件；这不承诺命令已实际运行或绕过 OS 启动检查。可用、已确认未取得普通可执行文件与检查未取得事实必须区分，已确认非普通文件说明类型原因，不把存在的路径写成不存在；未知文件检查失败保留实际原因，不写成未安装或一律空 PATH。任何后续候选实际可用应优先报告可用；没有可用候选时，未知不能被其他确定失败盖成 missing。结论绑定本次实际 Provider、命令和连接 owner；后改命令草稿、同 ID 并发替换或连接归属变化不能借用旧 Available 或 Checking。未保存的新命令如实尚未检查。Label 等未参与检查的编辑不扩大诊断范围。检查结果与原因由通用 Core 唯一事实提供，doctor 与启动拒绝说明不能另猜原因；既有非 available 不启动规则保留，不控制已有健康 Run。刷新不修改配置、草稿或工作面，不启动、停止、迁移或恢复 Agent，迟到结果不盖后来检查；连接或探测流程失败仅影响本次明确诊断，不挡健康 Input。
- **目标 Host 的执行器发现与全局模板分别表达。** Provider 声明协议适配，Executor 保存启动配置，可用性检查说明目标 Host 上本次命令解析事实，Session/Run 则代表真实执行。指定 Host 的可启动执行器清单沿该 Host 原已注册配置和受支持的发现机制取得，返回清楚的 Host 归属；设置、启动选择器、公开 API 与 CLI 消费同一来源，所选配置与最终进程必须属于同一目标 Host。全局模板清单继续表示保存模板，不冒充目标机器已安装或已授权的目录。未检测、available、missing、检查失败与连接未知分别保留，检查失败不能推断未安装或删除既有会话；文件可执行性仍不冒充登录或实际启动成功。
- **远端启动消费目标 Host 的准确配置。** 不将本机绝对命令路径、环境或凭据无条件套给远端；同名执行器在不同 Host 的路径和配置分别按原 owner 解析，不按名称猜同一配置。任意自定义 wrapper 不承诺自动发现，未被受支持机制发现时提供明确注册配置入口；不能默默安装、替换执行器或切换模型路由。发现元信息不返回环境秘密或凭据，启动与首句身份沿[远端恢复边界](session-recovery.md#联邦-runtime-与远端恢复边界)及[A2A owner](agent-capabilities-and-messaging.md#a2a-身份信封与持久化全局消息队列)。
- 大量 Agent 配置与远程连接采用可检索的资源库与当前对象编辑；只有准确选中对象的字段挂载，未选对象、Local 的 SSH 字段与显式缺失目标不挂载编辑器。全库草稿仍由原 Pane 的原始基线 owner 持有，A→B→A、窄窗返回与隐藏分区不丢输入、保存期间后改或按对象持有的披露选择；输入中的改名不改变本次搜索命中集。新建进入准确新 ID 并聚焦名称，窄窗返回原准确列表项。重复相同 ID 的新导航请求仍由原导航 owner 定位，必要清除筛选；缺失目标明确不可用，不暗选其他对象。隐藏 Agents 不发起新的可用性检测，恢复可见与显式刷新沿原检测 owner，不停止健康 Run。
- Agents 工具行的响应式重排只改变原控件位置，不改变查找、Host 选择、已保存命令检查或显式刷新语义，不丢原编辑、展开、焦点与未保存草稿；排列约束归密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)。

- Executor 是启动模板，Session/Run 是独立对象。仍被 retained Session 或已准入启动引用的模板不能删除，界面与 CLI 都具名说明引用，配置不变且不停止、暂停或重建 Agent；引用范围不能只数可见格子或 connected 会话。引用事实读失败，只拒绝这一次危险删除或重绑并说明未知，普通设置和健康输入继续。已缺模板的同 ID 显式重建必须与现 Session 的 Provider 事实一致，只修改配置而不自动执行；冲突事实不能猜一个。已准入启动在完成前同样受引用完整性保护，不因尚未出现 Session 就被删掉依赖；不保存第二份模板或永久删除身份表来掩盖原 context 缺失。
- Hosts 编辑同样保留原始字段基线与保存期间后续输入；无关 Host/字段提交只刷新 clean 内容，同字段冲突、准备失败与外部删除保留草稿，不用保存时的新快照消除冲突或静默重建。当前远端准备能力尚不可用时如实说明，不把受控准备条件下的保存成功冒充远端 Runtime 能力，也不打断无关本地健康 Run/Input。说明文字和 Test 反馈须与当前实际能力一致，不先承诺保存或测试可用、再在动作后否认；失败原因完整可读，草稿与健康输入保持。

- Hosts 的 CLI 读取已提交的连接记录；已保存连接按明确稳定身份取得当前已提交对象并测试，草稿才按明确输入测试，不猜默认 Host、焦点或显示名称；测试不改配置、工作面或健康会话。连接就绪、当前能力明确不支持与检查没有取得事实必须区分，不能把检查失败说成目标不可用，也不能把未知说成就绪。测试结果保留原始原因并绑定本次输入，CLI 回执与界面当前结论都不得把同 ID 的旧 Ready 用于后改或并发替换的连接值；新输入未测试时如实说明，不覆盖检查期间的后续编辑；远端尚不支持时如实说明，不用另一条启动路径绕过它。Host 删除、连接重绑与身份复用另有引用完整性合同，不能只凭可见会话或 connected Run 为空放行。

- SSH 连接的常用编辑为名称与 hostname／系统 SSH alias；用户、端口、密钥和服务覆盖按需展开，保留已有字面值与只读 Runtime binding，不扫描、展开或导入 SSH 配置，不自动部署服务。空覆盖沿系统 SSH 已有行为；保存连接不等于连接已就绪，Test 仍使用完整当前输入并显示真实结果。连接复用沿原 Workspace→Host 引用，展示选择不为全局 Executor 模板另存一份 Host 绑定；目标 Host 的注册配置与可用性沿上文原 owner 取得。Session 数只表达实际引用，不冒充运行中数量，原删除和保存保护不在布局调整中放松。
- Connections 中的环境库按稳定 Host ID 展开对象子菜单，分别查看连接配置与已登记项目。展开或关闭只改变导航；项目依据原 Workspace 的 `hostId` 投影，不以同名、同路径或当前焦点猜归属，不产生第二个项目编辑器。切换对象、子页和手机设备分区继续保留原全库草稿、按对象持有的高级展开选择、保存期间输入及冲突，窄窗返回准确当前子页入口。手机与设备是独立设置模块，沿原授权组件仅在可见时读取；离开后结束界面观察，返回再读取当前事实。它管理原 Mac 的接入与授权，不冒充每个 SSH Host 的授权端点，也不因导航自动邀请、批准、撤销或扩大权限。连接链接、设备数量与操作归属沿[《手机版 Relay 连接》](public-control.md#手机版-relay-连接)，原手输邀请并回 Mac 二次批准不再是目标连接流程。
- Hosts 的连接编辑区必须允许正常逐位输入 Hostname；首字符与后续内容变化不能自动折叠字段或移走输入焦点。展开/收起属于用户操作，同一 Host 的草稿、检查结果或无关配置更新不能改掉用户的展开选择；新 Host 可直接进入编辑。

- Browser 的设置 CLI 沿当前 Unix 用户的本地配置管理权限；显式开启自动化要说明能力扩大，但不冒充真人批准，不因浏览器操作失败自动开启，也不绕过已有 Profile 批准、控制交还或原生应用链接选择。界面保存自动化和忘记链接选择时，保护编辑或点击时看到的字段/答案；CLI 的 forget 明确忘记命令处理时当前答案，由同一配置 owner 原子处理，不暗示先前列表的 CAS。forget 回到下次询问，不提供 allow/deny setter，也不覆盖其它链接选择或普通偏好。

- 添加项目在界面与 CLI 中登记明确的 Host、路径与可选名称；CLI 按给定路径字面登记，不自动展开或创建目录，比较同一位置时沿既有路径规则，保留原登记对象。重复添加返回原项目身份与名称，不重复写入或发布；并发登记同一位置只有一个身份，不同位置都保留。名称缺席或空白时沿既有默认命名。CLI 登记不自动切换工作面或启动 Agent；界面的明确选择与后续启动保持既有独立动作，原 Tab、Region、分割、焦点和未发送草稿均保留，重启恢复包含新增项目的完整工作面。
- General 的崩溃日志查询与显式文件管理器请求使用同一本机固定日志路径。查询清楚区分普通文件存在、文件不存在与检查未取得事实；只有明确不存在能说没有日志，检查失败保留原原因，目录等非普通文件不能当日志。CLI 查询成功表示取得诊断结论，不代表 Agent 或应用健康；显式显示失败如实报错，成功只说明请求已发出，不宣称文件管理器已可见。查询不读取日志正文、不上传、不更改配置或原工作面，也不影响健康 Agent；未取得事实不猜成无日志。系统 SSH 的说明须与当前远端能力一致，不能承诺尚未支持的远端运行。
- 设置搜索必须能用 General 已展示的 `Show crash log` 与 `Session recovery` 用语找到原分区、看到原动作或说明；`crash`、`log`、`recovery` 同样可定位。搜索与清除不改变诊断或恢复能力，不请求日志、不上传、不中断健康 Agent，也保留已访问分区的未保存草稿和原搜索输入焦点。
- 用户要求「所有设置项是否都可以通过 cli 完成，且 cli 设计的足够优雅清晰简单」。设置界面与 CLI 使用同一份配置事实和公开能力；可编辑设置都能从 CLI 读取和修改，命令明确对象、作用范围和生效时机；明确未提交的失败保留原值并给出可行动的原因。保存成功只在配置已持久保存并发布后确认。等待预算须容纳真实持久写入，并有明确上限；不能用“本地设置”假定写入立即完成。公开控制请求与回执都以协议定义的完整帧为准；缺结束边界的请求不得执行，未取得完整帧的回执不得认作成功。未收到完整回复时如实说明结果未确认，不把连接终止说成配置未写、JSON 内容损坏或 Agent 已坏，也不自动重试。已进入保存的动作由原所有者完成，不因回复连接断开而重放或伪装成未提交。随后读取只表示当前设置事实，不能冒充前一请求的完成回执。未知和失败保留未提交草稿、原工作面与健康 Run/Input。CLI 不另建配置系统，不用交互表象猜运行状态，也不自动扩大权限。只读系统事实通过诊断入口查询；纯粹的窗口动作不伪装成持久设置。

 的「设置界面不酷」反馈与视觉约束归密度 SSOT 的「Settings 控制工作面」。设置页现代化的既有行为合同仍然有效；保存失败保留编辑与切换分区保留草稿是两种不同情形，前者通过不能替代后者。当前证据与需求状态见 设置界面视觉复核（本机过程资料：`docs/reviews/settings-visual-review.md`）。

设置分区切换保留已访问分区的草稿与阅读位置；尚未访问的分区不为保留草稿而提前挂载。搜索清除后焦点回到原搜索输入框，用户可以直接继续输入下一次查询；分区菜单关闭时不得抢回用户已经转到搜索框或其他设置控件的焦点；清除与搜索过滤保留已访问分区的未保存草稿。已有资源优先于新增表单，新增入口明确且可收回；空资源时直接给出创建路径。保存动作在长内容中仍可达，结果在当前设置对象旁说明，保存失败保留编辑。设置区块同时显示已保存值和未提交控件草稿时，摘要必须明确它是已保存的值，不能让编辑中的勾选与已生效状态混为一谈；保存中或失败后仍保留原已保存事实与草稿，成功发布后才更新已保存摘要。Browser 自动化同样明确已保存权限与未提交选择，沿原显式保存及 Main owner，不因改变勾选而暗示权限已经扩大或收回。设置文案围绕作用范围、当前选择和生效时机；分区说明的分层与去重见密度 SSOT[《Settings 控制工作面》](../presentation/settings-and-observation.md#settings-控制工作面)；底层包归属与实现术语退到诊断语境。现有 Provider/Executor 身份、权限与保存 API 保持稳定。

## 操作成本与当前卡顿

- 隐藏终端仍要接收和解析输出，保留原 Session 与 Runtime attachment；GPU 绘制资源只属于当前可见的终端。切换可见性不能重新启动 Agent、丢输出或换身份。
- 浮层的共享宿主是唯一的窗口级 DOM 身份。解析它不能反复遍历终端、文件树或正文；工作面内容变多，不得增加这项固定窗口操作的成本。宿主被移除后仍能由原所有者重新建立，显式指定的容器保持原路由。

- 用户原话：「现在进程非常卡」「让系统成本只随真正相关的工作增长，先缩小范围再做重处理，不要让无关数据、历史和功能拖慢当前操作」。输入、切换与当前工作面的更新不能被无关 Session、历史或后台观察反复拖慢。
- 卡顿定位必须区分主进程、Renderer、Runtime、Agent CLI 和验证负载，结论绑定采样版本与操作；不能以一次体感或静态代码推测冒充根因。局部修复须证明原热点成本收敛并保留 ordered bytes、恢复与健康 Agent 的工作能力。
- 默认不保留兼容层、legacy、fallback 或临时 workaround；不做 migration。复用当前依赖和平台能力，在权威事实的所属层修复，避免为探测、重试或性能增加竞争状态与中间层。P2/P3 的独立问题不能作为本轮 P0 交付的阻断门。
