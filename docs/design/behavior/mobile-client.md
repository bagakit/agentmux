## 导航、启动与返回

手机是适合移动使用的 AgentMux 第一方 client。连通后的一级导航从左到右为 Goals、Topics、Mote、Focus、Space，Mote 位于正中；原会话内也可切换主工作面。Survey、连接与设备设置及其他辅助能力收进菜单，不重复五个主入口。Mote 只列原协调对象；Space 沿原 Space→Zone→Tab→Region 绑定导航；Focus 按原 Core 执行状态与待处理交互组织，已有 Session 继续可达。目录不可读不按 cwd 或 Session ID 猜归属，原会话、草稿与阅读引用保留。

手机启动优先显示聊天：依次使用本设备最近访问的原对话、最近访问 Mote 的已保存主对话、原 owner 确认的主 Mote 的已保存主对话。最近访问是本设备的明确导航记录，不以 Agent 活动、名称、列表顺序或头像推断；元信息暂未读到不丢弃已保存的原对话。没有可确认引用时保留聊天起点、原对象与就近核对／设置入口，不自动新建替代 Session。原主工作面与资料编辑引用、草稿及未知操作继续保留并可返回；原设备存储未知不覆盖。既有主页偏好只作为退出聊天后的目录选择，用户可显式切换五个工作面。未连通且无保留工作面时显示接入页；重连、迟到目录和元信息不能抢走本次打开后用户选择的工作面，默认打开不自动恢复 Run 或重发输入。

手机返回一次只离开当前最上层呈现：面板、来源或详情、终端／结果、对话、目录逐层返回。非顶层工作面提供直接可达的返回动作，不能要求先打开菜单才能返回，也不以回到默认主页代替原上一层。网页和原生包装遵守同一语义；切换主入口、打开资料与返回保留挂载的 Composer、原草稿、阅读位置和未确认操作。本设备保存呈现引用，原 Host 或目录迟到不得替换用户后来选择的工作面。辅助菜单揭示侧栏并保留工作面；连接与设备设置位于侧栏，菜单不代替当前层的直接返回。

横屏与平板的 Agent 工作面在空间足够时并列显示 Focus 会话列表和原对话、终端或 Agent 工作。列表与正文各自滚动，列表选择仍沿原 Focus 的准确对象打开路径；宽窄变化、旋转和会话侧栏开合只改变呈现，不写业务主页、不改变 Mote／来源上下文，不新建或恢复 Run、不发送或重放输入。复用同一目录读取 owner 与已有注意事项去重；被保留的目录树、编辑器、草稿、附件、阅读位置和原身份继续保全。其他目录仍沿各自导航与返回，不由分栏补造第二套路由。返回仅改变原层级，不撤销宽屏外壳；Focus 根页沿同一目录 owner 保留唯一列表，其他根目录仍进入原工作面。几何与控件归[横屏与平板工作面](../presentation/mobile-client.md#横屏与平板工作面)。

五个主入口按实际可用宽度适配完整工作面：Goals 保留同一列表与原所选详情／编辑／讨论，Topics 保留同一分类／知识导航与原阅读／编辑，Space 保留同一空间树与原 Region 内容，宽态可并列、窄态沿原逐层呈现。Focus 根态重排原项目组，明确选择后仍打开原 Agent；Mote 主对话、Threads 与选择目录沿既有原对象路径。Topic 的 App 级来源栈也进入同一工作面右侧，不让嵌套笔记阅读器各自再分栏。并列导航中明确选择另一 Topic、知识或内容模式时离开当前外部来源，进入所选对象；当前来源本身为 Topic 且操作仍指向同一 Topic 时，切换讨论／知识、阅读与编辑保留该来源的返回层，逐层返回后才离开。分类展开、检索和刷新保留当前阅读，展开位置只随明确的分类选择改变，不因来源元信息读取而重置。宽窄只改呈现，不自动选择首项或写入业务上下文；同一目录、目标、编辑与内容 owner 保留原选中、展开、草稿和读取位置，真实可见的导航与内容各由原唯一 reader 观察。打开关联 Agent 继续原 openSession 与返回，不由这次排版引入新的跨页路由或来源状态。

每个功能工作面的导航由一个 owner 解释准确目标、来源层与返回。一次明确选择携带目标和用途，由同一转换完成位置变化；页面的数据或草稿引用回报只更新对应原对象，不借观测回报发起导航。各已访问范围的位置由该 owner 保留，交原 DeviceWorkface 的持久投影继续使用同一引用与合并责任，不在页面间维护相互回灌的位置副本。当前活动工作层为显示、可见读取域、返回和保存提供一致的解释；页内编辑、来源阅读与业务状态仍由原 owner 持有。

主工作面切换及当前面板、控件交互对已受理的本地意图立即给出可见反馈，不等待无关远端读取或昂贵的目录、历史组合；后续读取只更新对应范围，不阻塞已有可用操作。反馈只说明本地动作或等待，不冒充业务完成；隐藏工作面不因其他 Agent 的状态变化反复投影全部目录或历史，原已挂载编辑器、阅读位置、草稿与已接 Run 保留。

## 目录与呈现资料

手机目录完整消费原呈现 owner 的名称、项目、详情、状态与 recap，以及原 Mote 自定义头像。公共 carrier 保留这些 owner 的原展示值，不另加字段长度限制、再次截断摘要或截断正常数据；类型、准确身份、权限和既有整条传输容量边界仍成立，传输容量沿既有公共消息预算，不用更小的重复字段预算阻断原可用目录。正常中文与 emoji 展示数据不能使整份 Focus、Mote 目录不可读；验收包含原呈现生产者到实际公共 codec 的链路及原内容保真。

呈现资料沿只读 presentation catalog 取得。`space.ls`／`space.inspect` 的 `presentation: true`（CLI `amux space ls|inspect --presentation`）由 client 原呈现 owner 返回空间的 `catalog.appearance` 与有界 `agentPresentation` 事实：只传有界 glyph、parts、图片引用版本与已选空间的原 App 图片（PNG、JPEG、GIF、WebP、SVG 或图标格式）。Core 不解释头像外观，不保存新的身份。图片字节按选中 Space 的 inspect 读取，列表不批量传图片。手机导航与头像是这项只读能力的生产消费者。

Mote 外观沿原耐久身份 target 完整消费图片、图标、捏脸自定义及原动画；主 Mote 的默认身份不用于其他对象。Focus 的原显示名、项目、Executor 头像、recap、项目分组和状态由现有呈现 owner 返回，不用手动名称覆盖值代替显示名，也不在手机复制一份分类推断。缺少事实时沿服务窗说明，保留原可用会话。

## Focus、Mote、Topics 与 Space

手机 Focus 完整消费 App 原项目分组 owner 的准确 Host／Project、Topic／Mote 对象归属与待处理、执行中、近期工作的优先顺序；组内沿原 Agent 呈现 owner 保留名称、recap 与状态。每行同时展示已确认的项目、Agent 名称与语义状态：项目关系消费公共事实，不以 cwd 猜空间归属；显示名沿原名称解析链；事实不可读时标记未确认并保留原工作面。不以持久目录或 Session 创建顺序代替工作优先级，不按同名项目合并，不按 cwd 或显示文字推业务归属。近期活动、稳定次序及阅读保护沿[原 Focus 规则](focus-context.md#项目归属任务状态与恢复)，不从心跳、终端字节或打开视图推导活动。较早与未确认条目仍保留准确身份、原位置和可达入口；未知不冒充闲置、死亡或新结果。项目／对象图标和已完成、待输入、执行中等状态图标消费 App 同一外观与语义呈现来源，呈现未知不改变运行或输入资格。

手机 Mote 的日常入口围绕同一个原对象组织：进入原主对话、阅读进展、继续输入、回应事项与查看结果。主对话及合作资料消费原保存配置与业务 owner；主对话未确认时保留原对话候选和手动继续能力。同一 Session 在多处呈现时，入口保留此次 Space／Zone／Tab／Region 与 occurrence，不从 SID 的首个位置推导 Mote 身份。Mote 使用原保存头像及动画；会话顶部仅呈头像，身份与状态按需查看，不以不透明标题栏遮挡对话。头像揭示该对象的 Profile、当前工作和就近动作。

手机 Mote 用横排选择原对象，当前 Mote 的 Profile 是直接入口，与主对话及 Agents 平级，不作为需要逐层展开的树形子项；不枚举全部文件 Tab。Profile 沿[原搭档主页](motes-and-coordination.md#mote-快捷入口与当前协调上下文)提供已保存资料与按需文件编辑，Agents 只呈现原空间关系明确关联的 Agent 及其 recap；文件 Tab 和 Launcher 不冒充 Agent。选择已有 Agent 保留其准确 Session 与原展示位置，多 Region 或多处展示仍明确选择，不任取一个 Session。完整文件与其他工作面继续沿原 Space／资料入口可达，目录重排不删除或迁移内容。

当前选中 Mote 的主 Agent 入口就近常驻于对象标题处，不依赖展开目录、已有运行 Session 或已保存默认主会话。目录呈现、展开、资料读取、刷新和重连不额外启动或恢复 Agent；用户明确点击主入口后才进入该原 Mote 的主对话流程。已保存主会话沿[原默认会话与主对话恢复合同](motes-and-coordination.md#主对话的自动接回)核对原 Host、Session 与准确展示位置，健康会话直接继续，需恢复时通过原 Core 接回同一身份；配置确实未保存主会话时可进入该 Mote 的原创建表单，明确创建后沿原配置 owner 保存准确主会话绑定。组合由原公共／共享 Mote 机制承担，不另建手机主会话或生命周期 owner。配置、身份或原操作未知时保留入口、原引用、草稿与核对路径，不从第一个 SID、Launcher、名称或当前焦点猜主 Agent，不自动新建替代会话；既有独立的启动恢复时机仍由原恢复合同持有。

Space 等完整工作面目录中的 Launcher 提供可发现的创建 Agent 入口，沿[原工作起点](workface-launcher.md)进入既有创建流程，保留该入口的准确 Space／Zone／Tab／Region 来源，不按名称、当前焦点或首个位置改投。打开目录或创建表单不启动 Agent；用户明确确认后才沿原创建 owner 执行，并保留原操作及真实回执。原位置或绑定未确认时保留原工作面与输入，提供核对原目标的路径，不能只以“在 Mac 上查看”封住工作起点，也不能用未知回执自动重建。

手机 Topics 在同一目录中展开或收起 Category 下的原 Topic 子项，分类和成员由准确身份及原绑定确定；选择 Topic 仍进入原 Topic／Zone／Tab 工作面，讨论、知识及管理保持可达。对象和来源沿[《Topics 知识库的层级与沉淀》](spaces-and-layout.md#topics-知识库的层级与沉淀)，同屏展开只改变手机呈现，不另造分类或改写 Desktop 的导航范围。

手机 Space 与 Desktop 共用原项目分组和目录树的呈现规则，沿[《Project 与 Workspace》](spaces-and-layout.md#project-与-workspace)消费原 Project、手动分组与 Host 事实；目录派生分组只表达呈现。Zone／worktree、Tab 和 Region 的归属仍由原资源和绑定确认，不按路径猜 Session 的业务归属或执行资源。目录发现或呈现读取未确认时保留已知目录与原可用工作面，说明失败步骤和观察范围并提供原目标的读取／恢复；折叠说明和改变密度不判定健康、身份或操作资格。

手机消费原 Topic、Survey 与 Goals 的完整工作面及公共 owner，入口位置沿上文一级导航。Topic 保留 Category、Topic、Chat 和知识来源身份；Survey 只显示原明确收集的研究 Zone、原名称和准确 Tab／Region，不能把全量空间当研究或复制内容。Goals 沿原公共目标 owner 保留目标身份、状态、决策和操作回执，不维护手机独立目标系统；目标清单的完整范围与有界读取沿[Goal 的状态、筛选与路由队列](goals-and-demand.md#状态筛选与路由队列)。所选 File Region 以原目录元信息确定准确资源，通过既有 `file.read` 读取原内容与修订；列表不批量读取文件，不凭路径猜内容，不新增另一套文件读取接口。手机 Note 编辑和保存消费原共享 schema 与 revision-aware 文件写入 owner；冲突、未知写入和未保存草稿明确保全，未取得确认不冒充保存成功。正文写入若缺公共入口，在同一交付中暴露原 owner 的最小 RPC／CLI 能力并验证实际手机消费，不停留在只读占位。Browser 沿原 browserId 发现当前网页。原对话、Message Tools 与 Terminal 继续同源，自定义头像和动画保真，失败保留原对象和草稿。

## 对象身份与工作面

手机网页与 App 共享同一对象可达和业务能力：Mote、Topic、Space 里的原 Agent 即使尚未出现在手机 SDK 元信息目录，也保留原 SID、准确位置与打开／读取原会话入口，元信息未知就地说明，不把观察缺口当成未启动。明确新建 Agent 在已选原空间／Zone 中沿原 `agent.open` 完成 Executor、执行资源与展示目标选择，保留创建 operation、真实回执与查询原操作的恢复路径；不自动重放 unknown，不因打开目录或重连创建 Agent。

手机 Agent 列表项支持长按和可见的更多入口，打开同一原 SID 的操作菜单；短按仍继续原对话，滚动、取消触摸与多指操作不误开菜单或误导航。菜单就近提供复制原 Agent 身份链接、查看消耗与既有原会话恢复动作，复制沿[对象分享合同](public-control.md#对象地址分享与方向)，不另造名片格式。消耗仅消费原 Core／Provider 的原生 Session 累计、最近回复与上下文观测，明确范围及观察时间；未上报或读取失败保持未知并可刷新，不补零、不推算费用，不把名称或所在行当作执行身份。打开、关闭菜单及读取消耗不提交输入、恢复或更换 Run，不改变原导航和草稿。菜单响应本地打开动作，不等待远端读取；一级直接提供已确认的原生消耗摘要，异步核对保留准确原目标、观测范围与刷新路径，未上报与读取中不混同。远端迟到、失败或断连不妨碍关闭、复制原身份链接及其他已有可用动作；菜单开合的本地工作不随无关 Session 的历史或目录组合放大。

手机所有原 Agent 对话都可显式复制由原 SID 生成的 `amux://agent/<SID>` 身份地址；名称、Run 和展示位置不替代原身份。复制失败保留可选的完整链接。查看尚未恢复或状态未确认的 Agent 时，保留原历史和输入草稿，并可显式请求 Core 恢复原 Session。恢复绑定原 Runtime、设备记录、Session、Run 与 operation；目录元信息缺失时沿原 `agent.inspect` 点读，不冒充死亡。未知结果保留原恢复意图，只核对同一操作或明确继续该操作；重连、切页或刷新不自动重放，也不以新建或 Level A 重启代替语义恢复。复用 Hosted `ensureAgentContinuity`、公共 `agent.inspect` 与同 owner 的 `agent resume`，不新增同义 RPC／CLI。

## 提醒的收起与范围

手机的服务、故障和 unknown 提醒均提供显式收起或关闭；菜单固定保留「提醒与诊断」入口，可重看或恢复显示已收起的原提醒，并到达其原恢复动作。收起只改变本设备呈现，不确认健康、投递或操作结果，不删除原意图、回执和草稿，不重发请求，也不授予任何操作权限。新的原对象／原操作问题不能被另一对象的收起状态覆盖；需要权限或答复的原请求仍按其原合同保留。头像与项目图标的原外观读取异常也遵循这一边界：在对应原对象读取完整原因并明确重试，收起后仍能从固定入口恢复；同名对象、其他头像观察或资料读取不能代签原异常。

提醒绑定实际受影响的目录、对象与读取范围。仅属于某个 Session 的元信息问题，在离开该对话后不继续占据无关目录的常驻提示；返回该对象或打开「提醒与诊断」仍可查看原问题。目录问题提供就近的展开入口，列出受影响对象、失败步骤、具体原因和可行处理；准确身份与技术原文按需可读、可复制。明确刷新仅重读对应目录或对象的原公共事实，不自动恢复、创建、删除 Session 或重发未知操作；读取仍失败时保留原对象、已有内容和恢复路径，不把缺失元信息归为死亡或删掉条目。

## 对话、命令与输入

手机对话顶部直接提供命令行与对话切换，不要求打开更多菜单。Goal 和 History 以就近独立入口打开当前原 Session 的目标与输入／通信历史；复用原唯一面板与读取 owner，关闭回到原触发处，保留草稿、阅读位置和未确认输入。入口移动不发消息、不改变执行身份、恢复资格或授权。原生包装的撰写消息动作位于当前对话动作面板，用户明确选择后关闭面板并聚焦该原对话的编辑器；失败就地说明、保留草稿，不发送或切换会话。

手机 Agent 消息窗直接提供 Commands 入口，默认紧凑工具栏可达。Commands 同时消费原 Provider／Core composer 能力提供的命令与 Desktop 保存的自定义 Prompt，沿同一 Provider 绑定与插入语义，可搜索并插入当前草稿，不因选择命令自动发送、清空草稿或切换原目标。自定义配置只从原 Settings 资源 owner 读取，不另存手机配置或补回用户已删除的默认项。Commands 标明每项来自 Provider 命令还是自定义 Prompt；读取失败保留原命令、已读结果和健康输入，并提供重试及关闭。尚未列出命令时如实说明，原消息输入与终端能力保留，不凭展示文字编造命令资格。输入历史入口须直接可辨，复用[按 Agent 的输入历史](conversation-input.md#message-tool-按-agent-的输入历史)，搜索、复制或回填均不自动发送。

手机 Send／Cmd+Enter 的单条输入语义沿[《Composer 消息队列与紧凑状态》](conversation-input.md#composer-消息队列与紧凑状态)，消费原 Core 的显式输入能力；普通 Enter 保持原常规输入，重连与读取不生成发送授权。已取得 `admitted` 或 `terminal-confirmed` 回执的显式输入按原 typed 事实安静收敛，不在输入区下常驻故障诊断卡，也不把终端字节确认或 Native 接纳冒充为 Agent 任务完成；`waiting`、`stopped`、`not-applied`、`unknown` 与投递失败保留真实状态、原请求／Run／正文与手动恢复动作。收起或关闭内联投递说明只改变当前呈现，不删除原 attempt、不重置草稿、不改变输入资格且不重发；收起后可通过紧凑状态入口或通信记录重新查看同一原回执，刷新、切页或返回不使已收起旧框重新常驻或串成新操作。同一原输入已确认的准确回执优先于之后一次旧 Run 准入检查的错误；该错误只说明这次检查，不证明原输入从未投递，也不能覆盖或替代原回执。输入关联或结果未确认时继续查询同一原 operation，不凭错误码猜投递或重发。原 Run 权威确认终止且原 Session 具备恢复资格时，在对话就近提供显式恢复原 Session 的动作；恢复与原输入投递分别确认，仍沿原输入合同处理用户后续明确发送。提示与恢复动作在输入区外完整可读，不因长诊断挤压正文或编辑器。

手机问题与权限沿共同对话的[同步原请求与耐久答复回执](conversation-mode.md#同步原请求与耐久答复回执)及[原生异步问题与答复](conversation-mode.md#原生异步问题与答复)消费原公共方法。设备保全的答复 intent 冻结原操作、准确请求、Host／Runtime 与 Run，只供原操作核对，不恢复回答权限；重挂载、重连和当前 pending 不能补造丢失的原 intent。原请求完成或替换后，已保全原操作仍可只读查询；unknown 保留原答案与新草稿，不自动重投。较旧阅读窗接收原 reader 已接受的同源最近页答案事实，另一入口的准确答案可更新原问题的呈现，但不替换已读正文、选区或阅读位置；不同来源不继承答案资格。

手机 Skills 选择器按需消费公共 `skill.ls`（CLI：`amux skill ls --host ID --session ID`），由准确原 Session 的 Provider 目录与执行工作区发现，调用者不能替换 cwd。选择沿共享 Composer 插入可撤销引用，不执行 Skill、不授权发送；读取失败保留原草稿及已有输入能力，提供重试，切 Host／Session／工作面后的迟到结果不进入新草稿。Provider Commands、Agent 引用与 Posture 继续消费原 catalog 和输入 owner，不另建手机语义实现。

## 附件

手机附件入口在默认紧凑工具栏下直接可达，支持系统选择图片／普通文件或剪贴板粘贴图片，在原输入区就地预览、移除或明确上传；选择、粘贴、上传和网络重连都不授权发送消息。取消系统选择保持原草稿且不报故障，网页文件选择不因窗口焦点切换限时误判取消。长期无 UI Host 与 Desktop 共用同一私有附件存储 owner 服务公共 `file.upload` 与 `file.upload.inspect`，把附件字节送到准确原 Host／Session／Run；私有目的路径由 Host 决定，不接受调用者文件路径，也不覆盖已有操作。只有实际保存并读回、完整内容修订与原 operation 一致的回执，才沿共享 Composer 把文件引用加入原草稿；原 Send 再走 Core 单条输入。晚到回执不进入后来消息或另一会话，后来编辑的文字保留。未知回执保留原 intent，通过 `file.upload.inspect` 核对同一操作，不自动重传；切连接、切会话和重启设备后保有准确原目标及核对入口。设备只持久化原 intent／回执，不把文件字节塞入工作面备份；未上传的系统选择随本次设备选择保留，离线不禁用正文输入。支持格式（含 PNG、JPEG／JPG、GIF、WebP、HEIC／HEIF 及普通有界文件）、单文件与传输上限由公共 codec 定义，不扩大 Relay／Hosted 原消息预算；超限或不可读取只拒绝本次附件，健康 Agent 与原草稿保持可用。

系统选择或文件读取未返回时，用户可明确终止该次未完成的选择或读取，保留已完成的其他选择、正文和原上传；不能把窗口焦点或用户终止本页等待冒充系统取消。被终止动作的迟到结果不得添加附件、上传或修改草稿；其他选择与读取不被连带取消。仅在本页内存的完整文件逐项提供保全或明确移除入口；原上传已发起时，明确放弃本机副本不删除原上传记录或 Host 文件。文件导出是否实际落盘须如实表达，不能以发起下载代签保全；用户确认已另行保全或明确放弃该本机副本后，才解除对应内存字节对网页更新的限制。跨 Session 的附件按准确原身份提供返回或处理入口，不能让不可见的原附件成为无出口的阻断。

原上传意图已可靠保存，且原 `file.upload` 已实际发起或原 Host 对同一 operation 的权威观察明确确认存在时，用户可明确结束该次本页等待，保留原操作身份和 unknown 回执，通过原 `file.upload.inspect` 核对；此动作不撤销、重发或确认原上传。纯核对可由用户明确终止本页等待，不能把已发起的 `file.upload.inspect` 当作上传已派发或原操作存在的证据；本页仍有未发起的上传续做时须显式取消该续做，迟到结果不得继续上传。若该等待还会自动向草稿插入引用，必须同时显式终止该次插入续做，迟到结果不得修改当前或其他草稿；已有确认回执沿原对象保全。设备保存尚未确认或本机字节仍未保全时继续保留当前页，分别说明真实原因和可行恢复动作。

## 终端与内容读取

观看与控制可辨。手机终端默认沿原 Run 已确认网格显示，支持本地视觉缩放与正常触摸上下阅读历史，横向内容也可在本地平移查看；缩放、滚动、旋转或 viewport 变化不自动改变 PTY，也不生成输入。历史仍沿同一原 Run 的字节、reader 与 cursor，连续阅读和成本遵守[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)。用户明确进入控制并主动调整尺寸，才向原 owner 请求。被动阅读不 resize，不发鼠标输入或 DA/DSR/颜色查询回写，checkpoint/replay 不触发输入、通知或剪贴板，不伪造 ctxmux 排他 lease。

切页或连接变化取消了本次内容读取后，重新显示原内容时仍须按当前原资源继续读取；一次取消不能阻断以后对同一原文件的读取。旧读取的迟到结果不覆盖后来选择，已读正文与草稿保留。读取只随相关可见内容、连接和原资源变化发生，不轮询或因无关工作面变化重读。

当前对话的元信息由原Core的准确对象读取判定，不以Hosted缓存缺项判断会话终局或关闭已确认健康能力。退役事实只消费原历史描述或记录检查，历史读取与当前投递资格分别成立；刷新元信息须可重读该原对象，读取成功后只清对应来源的问题。打开或关闭状态详情不恢复、重开或发送任何请求，已有草稿与未确认意图保留。

## 设备工作面与未确认操作

设备工作面采用明确的持久来源和可导出保全记录。同源多个页面的草稿与意图按准确 key 更新，不能以旧页面快照覆盖其他会话或未知原请求；同 key 冲突保全原请求和双方正文，供用户核对与复制。导航、附件与目标意图和草稿共享原存储 owner 的跨页面原子更新，导入备份切换记录身份，迟到回执不能据旧页面状态改写新工作面。存储不可用时保留当前内存和导出能力，持续说明刷新保障不足，不因此关闭健康 Agent。重启与卸载后的存储条件分别说明，不假定密钥跨卸载必存。身份丢失后打开原 Mac 链接登记新设备，不创建替代 Host Session。

手机对原 Goal 的有限执行、分配、交接、删除及关联请求保留准确 Host／Runtime、Goal、操作身份和完整原参数；在途或未知结果不因页面刷新丢失。沿同一设备工作面保全，刷新后在固定的恢复入口仍可读取，即使原 Goal 已删除、目录不可达或当前连接不是原 Host；显示已收起只改变呈现。读取当前 Goal 是当前事实，不代签某次原操作的回执；没有权威结果时保持未知，不自动重发或替换。设备保存失败时当前请求和工作面保留并说明刷新保障不足，不因记账失败关闭健康 Goal 或 Agent 能力。

原请求已持久时，即使回执仍在途也可显式更新，恢复后保持未知。设备无法持久时，成功复制完整原请求及当时已知的回执状态且用户明确确认已另行保全，才允许取消该次尚未完成的写入并移除本页副本；复制失败或未确认不移除，取消后迟到写锁不得执行原写。原记录不可读或身份冲突时如实说明状态未知；该选择不写、不删除任何设备记录，回执未知须自行核对，不冒充原操作已完成。若请求已实际写入，保留设备原记录；已收到的回执也须沿原设备工作面准确保存后才更新。确认写锁持续故障时保留当前页并说明须恢复设备存储，不以不完整记录冒充安全载入。移除后如仍在原页收到迟到确认，恢复同一原请求的确认状态并按原记录身份保全；不能持久时重新提供确认状态的复制与明确保全。此选择不改变原 Goal，也不重发或确认操作结果；设备存储本身的刷新限制仍须独立解决。

## 首屏与按需加载

已保存准确对话引用的设备在原加密握手与控制身份确认后，即可读取该对话和恢复原草稿，不等整台 Host 的会话摘要完成；完整目录按[原 Hosted 观察边界](public-control.md#长期-host-的公开运行能力)并行准备。目录未确认与真正空目录必须可区分，目录局部失败保留原对话和准确输入路径，并在目录自身提供读取状态与恢复入口。没有原对话引用时，仍由原空间与 Mote owner 确认聊天起点，不猜目标或自动创建替代 Session。

普通启动的连接准备与产品工作面代码加载可并行进行，不以下载或执行整套工作面作为读取连接描述、原密钥和握手的前置。首屏持续区分页面代码与连接进展，局部模块失败保留原连接、设备记录及恢复入口；不能将模块加载成功称为连接完成。显式短链接的连接描述读取尚未完成时，可由用户取消该次观察并重新读取同一原来源，旧迟到结果不得改写后续连接；取消观察不撤销已连接的健康客户端或业务。网页更新仍须等实际模块可用后，在原设备写锁事务内完成真正的首次工作面读取与挂载，不能以 Suspense 占位已提交冒充工作面已在锁内恢复。

原Host在内容身份固定的namespace内提供脚本、样式等静态资源时，复用浏览器缓存并按客户端接受的编码压缩文本传输；页面入口、重定向和失败响应保持重新向原Host确认的语义，不能因缓存绕过已淘汰入口的恢复。压缩只改变传输编码，不改变解码后的原资源字节或构建身份；在途工作继续受原资源owner约束，不积累无界副本，不缓存动态业务事实。

手机沿Core通用summary投影接收当前会话元信息，不在首帧预载所有会话的历史恢复操作账本；当前恢复状态仍可读。明确核对恢复操作时沿原准确read／inspect取得完整账本和原操作，摘要缺项不代表原操作不存在，也不改变持久保存、恢复资格或未知回执。

手机首屏只等待当前工作面所需代码与事实；未访问的终端、目录和知识面板按需准备。进入后再切换仍保留原编辑器、阅读位置、草稿及未确认操作，不以卸载、重建 Session 或重发业务换取提速。模块加载失败仅影响对应面板，原聊天及导航保持可用，并提供明确返回和“保全并重新打开网页”的路径；不能把重建组件冒称资源已重新读取。明确返回、关闭或离开失败面板可撤回本次尚未导航的重开；不撤回原输入、上传或未知请求，也不拦截其他健康操作。当前版本或版本观察未知均可由用户发起重开，是否能离开沿下文[原网页保全与身份交接](#网页诊断与更新)核对；阻断时说明原原因，保留正文、图片、原操作及返回入口。加载性能须分别观察资源下载、脚本执行、连接建立和首段内容可读，局部菜单响应不能代签首次打开或真机网络结果。

## 网页诊断与更新

页面内容地址可用完整 SHA256 的可逆紧凑编码，去掉路径中重复的构建名与文件名；同一原资产 owner 按完整 digest 精确寻址，不增短码账本或指向 latest 的可变别名。已保留版本的原不可变地址仍返回原字节，原 buildId、namespaceDigest、更新检查与保全交接不变；禁止仅改地址栏到根路径掩盖文档版本。连接链接与首次信任沿[手机版 Relay 连接](public-control.md#手机版-relay-连接)。

手机网页已有的问题观察须能沿原公共诊断入口被 Agent 查询，准确区分认证设备、页面实例、来源、构建和原操作，减少截图转述。诊断沿[原证据机制](../diagnostic-evidence.md)，复用既有 client incident 档案与读取能力；原业务已经能查询的事实仍用原业务入口，不另造目录、Session 或错误状态 Store。原连接状态事件若携带可安全报送的有限协议错误码，诊断须保留该原码及事件边界；缺失或不属于允许范围时保持未知，不收集错误正文，不据此推断连接权限或操作结果。目录查询成功但原 Space 的 issue 字段存在也是需要保留的部分观察：只记录字段存在、原不透明 Space 引用、来源与数量，未知错误码保持未知，不读取或匹配提示文字推断原因、权限或健康；完整原因从原 Space 查询取得。

手机报送仅由真实认证 device principal 或保持该主体的原可信转发接收，设备身份不由业务 JSON 选择；Agent 查询不升级为设备管理，也不能代报自己是手机。原页面报告的构建、观察时间与接收方当时的构建、接收时间分别表达，不能用当前值回填旧事实。有限安全元数据、原文和缺证继续沿原诊断合同；未接入、未上报、离线、超界、被淘汰或原档案不可达不能冒充无问题，诊断失败不阻断原手机业务、输入或健康 Agent。

手机 Web 静态资源由同一原 Host 的资源 owner 接受完整候选、激活和查询原操作，静态更新不要求重启 Host、Session 或 Run。CLI 与 App 经默认公共入口到准确原 Host，Desktop 的反向调用保留原 caller、主体、参数和 Runtime fence；Host 不拥有该能力时明确不可用，不再回转 Desktop 形成循环，也不改连另一端点冒充成功。服务已提供新资源与准确原页面实际载入新构建分别确认，HTTP 成功、激活回执或当前 manifest 不能代签本页 loaded。

受管 Agent 的激活资格以原能力核验后得到的准确 Host、Session、Run 和执行 Workspace 为界；候选只接受该执行资源根下的字面相对构建路径，真实文件路径与完整性在原文件边界核对。异步校验后、实际交换前复核同一资格和执行资源；不能凭 Unix 连接、显示位置、名称或调用者自报的目录扩大权限，不能发布主机任意文件。资格、来源或资源范围未确认只拒绝这次激活，原 inspect、工作面和业务保持。原激活冻结候选与预期 active 修订，未知回执先查原操作，不自动改目标或重发。

候选、保留 namespace、在途 IO、载入观察与待报诊断均有明确的并发、总字节及数量边界，保留范围和超界结果可查询。旧资源仅在公布的有限范围内承诺可读，不能暗中淘汰却声称旧页始终可用；超界只影响本次准入或观察，保留当前有效服务并给出未施效、未保留或未知的准确结果与原恢复路径。没有必要的范围和资源预算时，不以排队或缓存无限积压代替处理。

手机浏览器重新访问符合原内容入口路径形状、当前未保留的页面入口时，原 Host 有当前有效发布则将该次 GET／HEAD 文档请求引向同源当前入口；仍保留的旧入口继续提供自身版本，旧脚本、样式和其他资源不能改指新版本。入口恢复保留原查询与浏览器持有的片段，不发送或回显片段中的连接资料；重定向不代表原设备身份已恢复或新页面已载入。没有有效发布或请求暂时不可服务时，按真实状态返回明确内容类型与可重试的可读页面，不能以缺少类型的空响应让页面变成文件下载。此机制只处理已经发起的访问，不因发布主动刷新存活页面，也不承诺保全浏览器未持久的内存内容；应用内选择更新仍沿下述原 owner 保全合同。Host 的候选准入要求原 build 身份可表达为单一且不会被标准 URL 归一化改变的路径段；无法表达的候选只拒绝本次激活，保留原候选资料、当前版本和健康 Agent。合法非 ASCII 或转义身份仍可用，HTTP build 观察头使用原身份的百分号编码，不把头值改写为另一身份。

手机网页在使用中主动核对准确原 Host 所提供的版本与本页真实载入版本；确认两者不同时就近提示有新版本，可关闭或收起，设置中的网页版本入口始终可发现并可主动查询和选择载入。页面恢复前台或重新连接后应能再次取得当前观察；查询应合并并限制成本，不因目录、消息或无关 Session 变化而重复请求。离线、读取失败、旧观察或来源无法确认时明确保留未知，不能宣称已是最新版或虚构待更新。关闭提示只影响本设备呈现，不改变版本事实，新的已确认版本仍可提示。

发布不自动重载或卸载原页面。用户明确选择载入时，先由原 owner 确认未提交文字、仅在本机的已选图片、工作面和在途或 unknown 原操作及意图已保全，再重新载入同一原入口；未知原操作不自动重放，重新载入后接回原身份并保留核对路径。保全缺证时继续原页并说明待载入和可行恢复动作，不用丢弃输入、猜无草稿或绕过未知请求换取更新成功。重新载入动作、服务资源已提供与新页面实际载入仍分别确认；重新载入失败保留或恢复可用的原工作面，不以点击动作代签载入成功。首次让旧进程取得新能力与后续静态资源更新分别交付，不声称源码更新已使旧 Host 热获新方法。本合同针对手机 Web，不新增 Native App OTA。

对话的发送准备、重试或停止尚未派发时，用户可在原消息附近明确取消该次意图；载入网页本身不代替取消，取消不发送正文、重试、停止或撤销原上传。原正文、选图、已发起的上传及原操作保留，迟到的准备结果不能继续派发；若设备保存仍未确认，保留当前页面并说明真实等待和恢复动作。同一原请求已实际派发、完整原意图已可靠保存且后续不再发起业务写时，可由用户明确载入；冷读保留原身份与 unknown，不自动重放。派发判断归原操作 owner 与实际调用事实，不从输入文字、显示状态或预先保存的意图推测。

新建 Agent 已由原回执确认并持久保全后，原已提交表单不再单独阻止网页更新；提交后的编辑仍须保留并单独确认，迟到回执不能清掉后来的输入。隐藏创建表单不复制或投影无关设备草稿与请求，保留原表单、意图和读取路径。

## 分版本交付与验收

手机版整体设计可分版本交付；每版须形成实际可用的完整流程，其他已有工作面与能力仍可达。各版的源码、真实 Renderer、公共调用链与物理手机体验分别验收，浏览器窄屏、编译或原生同步不代签真机。iPhone 与 Android 保留同能力范围，未执行真机验收不得据构建成功宣称两类设备验收通过。
