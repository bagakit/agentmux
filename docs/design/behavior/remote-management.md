# Remote 管理 PRD

本文是 AgentMux 远程管理的产品需求与行为 SSOT。它回答用户如何理解远端环境、找到正在工作的 Agent、判断观测缺口并完成准确的管理动作；Session 恢复、权限、消息和资源测量仍由各自原 owner 定义。当前源码入口见[公共能力与当前实现基线](#公共能力与当前实现基线)，源码存在不代签安装包或某台远端的运行能力。

## 已确认方向与方案范围

Remote 管理是独立、完整的产品主题；设置提供明确入口，以可探索的拓扑改善远端管理与监控的理解，实现时优先复用项目已有的无限画布依赖。用户提供的深色节点拓扑与右侧详情是构图参考，不授予第三方公网入口、代理服务或主动网络扫描资格。网络观察范围由本页的准确来源合同决定。

本文的观察层级、主流程和信息优先级是据此收敛的产品方案。分期是设计建议，不自动创建执行任务；新增采集、历史保存、通知策略、远端部署和控制能力须在对应 owner 明确合同后安排。已确认的管理范围包括完整管理工作台、所选 Host 的只读运行与网络观察、同身份路由修复，以及用户配置的应用授权同步；长期历史、主动告警、部署和批量运维仍按各自用户任务单独决策。本文定义目标合同，已落地能力另由下文实现基线核对。

#原工具绑定中的 `resourceHostId` 属于创建协调端的 Host 命名空间，不能直接当成当前 Desktop 的路由。Desktop 在原 Session 快照、事件、恢复候选与历史描述的投影边界，以原 `resourceRuntimeId` 对照已有认证绑定和缓存的稳定 Runtime 身份，派生当前设备下的 Agent／项目位置；不修改原绑定，不增加探测或持久事实库。模式标签和文件资源上下文消费同一投影。未映射或有歧义时项目 Host 保持未知，仅阻止本次依赖该准确地址的文件操作，保留原 Agent 的输入、控制与恢复入口。

## 远程 Agent 的能力方向

远程 Agent 必须支持 Agent 程序及其模型访问在一个 Host、项目文件与工具执行在另一个 Host，使用户能够使用另一环境的 Agent 能力处理原项目。两个 Host 的角色可互换，两个执行方向都须支持；具体方向由新 Session 的准确 Agent Host 与资源 Host／Workspace 绑定决定。已有的远端工作区模式仍将 Agent 与工作目录放在同一目标 Host，不能用现有 SSH 连接、远端 Session 管理或应用授权同步证明跨 Host 工具执行已经交付。先完成这一执行闭环，再推进其他候选能力；具体 Provider 与原生协议覆盖须由真实能力发现和端到端验证确认，跨账号范围仍独立决策。

方案必须分别表达原 AgentSession 的语义 owner、Agent Run 所在 Runtime，以及实际工具访问的 Host／Workspace。同一 Session 保持原双端绑定，恢复沿原对象进行，不随展示移动交换两端角色。展示位置沿原 Tab／Region，不能按当前焦点、本机同名路径或工具参数的自报身份选择执行目标。Provider 解释其原生工具协议与支持范围，Core 组合准确绑定、请求、权限和回执，Host 执行其授权资源操作；客户端仍消费同一公共能力，不复制 Provider 适配或 Runtime。通用分层沿[系统职责](../../architecture/system-ownership.md)，原生能力边界沿[Provider 能力对齐与移植边界](agent-capabilities-and-messaging.md#provider-能力对齐与移植边界)。

远端模型访问授权与项目资源访问授权分别成立。借用远端 Agent 不等于复制登录凭据、开放整台机器或授予对另一工作区的访问；两个方向的工具请求分别在各自资源 owner 上核对原主体、准确资源与本次操作。一个方向的连接或授权不授予反向访问权限，建立反向连接也不扩大已有授权。没有整目录同步也不代表内容不离开项目 Host：被读取的文件内容与工具结果可能进入远端 Agent 上下文，须如实说明数据路径。跨账号分享、资源池自动选机和主机间切换仍是独立范围，不因这一方向自动获得授权。

断联、观察超时、事件积压或前端退出不自行结束健康 Run；原操作未知时保留原身份与查询路径，不重放文件修改、命令或 Prompt。原生语义恢复失败不能以提示后改开空上下文完成 Level B 恢复。具体健康、持久工作面、故障隔离与恢复义务继续由[Durable Runtime 健康](session-recovery.md#durable-runtime-健康)和[联邦 Runtime 与远端恢复边界](session-recovery.md#联邦-runtime-与远端恢复边界)持有。

性能是这一执行能力的交付要求。正常工具往返应复用原连接与准确目标绑定，避免每次工具调用重建承载服务进程或传输连接、扫描所有 Session、复制整份历史或工作区。临时命令只消费其准确 Run 的终端事件；连接状态变化仍须通知受影响的命令，不能让无关 Run 的输出逐一访问全部并发命令。观察与大载荷传输须有背压和取消边界，慢 reader 或单个工具请求不能阻塞其他健康工作；空闲观察不以高频轮询换取可用性。成本只随相关请求、实际传输字节和消费者增长，优化不能改变权限、原操作回执或恢复语义。

新建分端执行时，在任何 helper Start 前先完成准确两端所需的原生准备；Agent 端同时确认本次必需的 Provider 工具接入贡献。所需合同不足或准备失败，应立即说明准确 Host、角色、步骤及原错误，并给出该 Host 的更新／配置入口。已知有更新仅为建议，未报告能力、观察失败与明确不支持分别表达；不以版本字符串、可选升级检查或全 Host 观察关闭既有健康 Agent。

Core 更新后，原失败请求可沿其准确 Coordinator、binding、Session 与创建操作显式继续。Coordinator 从自己保留的冻结意图推进，保留原 Runtime、Native Start 尝试及输入回执；不接受客户端以当前草稿重构输入，不换身份、不重发未知 Start 或初始 Prompt。工具 reader 重接、存储等待中的创建继续与分端原意图继续分别表达。当前环境与可执行动作随准确新观察更新，上次失败作为历史保留；更新成功本身不证明准备、创建或输入成功，也不自动触发继续。原工作面已被另一 Session 使用时，迟到回包不得覆盖它。

发现、创建时的执行选择、工具权限、操作结果与原身份恢复必须通过 Core 公共 API、JSON-RPC／CLI 及真实客户端同源消费，按[公共能力贡献约定](../../guides/public-capability-contributions.md)在同一计划中判断复用与扩展。真实双 Host 验收须分别覆盖两端角色互换后的执行方向，证明各方向准确的文件与命令落点、独立授权边界、错误资源拒绝、回包丢失不重放，以及重启后原身份与工作面恢复；通用机制另用不同原生协议或触发形态验证。性能证据须绑定候选与实际网络条件，分别记录冷启动、复用连接的工具往返、大载荷吞吐、并发干扰和空闲成本，不用本机环回或主观流畅代签真实跨主机性能。本节定义目标，不声明实现或验收已完成；具体方法沿[测试策略](../../testing/strategy.md#任务验收与假绿防护)。

## Tailcat 传输与本机接入

Remote 的同一 Host 可选择 SSH、SSH 优先且 Tailcat 备选、或仅 Tailcat。现有 Host 默认使用 SSH；关闭 Tailcat 不启动其 CLI，不改写 SSH 命令或删除配置。传输选择不改变 Host、Runtime、Session、Run 或工作面身份。备选只用于建立通道，在发送业务请求后失去回执时保留原 operation ID 和未知结果，不能自动改路重放。

Tailcat 通过官方 CLI 的双向 stdio 复用现有 JSON-RPC 和 Runtime 绑定。接收端必须已经安装并运行 AgentMux；本机接入开关只监听并将连接桥接到原 `amux system endpoint --stdio`，不安装远程核心。开关使用已保存的 server key（含 PSK 和固定 DERP region）及明确的非空 client public key allowlist；关闭只停止监听。发送端使用保存的 client key 和对方 `tc…` 地址。地址属于凭据，不进入日志、拓扑标签或公开示例。

CLI 缺失、启动失败和监听观察未知必须可见并可重新检查；进程启动不代签已连接。Tailcat 失败不能撤销健康 SSH、Agent 或 Run。现有 Linux x64 headless Core 升级范围保持不变，Tailcat 接入不授予 Mac 远程安装、主动扫描或绕过安全策略的权限。

### 在 App 中准备 Tailcat 接入

两台都已安装 AgentMux 的机器无需离开 App 运行 `tailcat genkey`。各机器上的人可让本机 Host 经官方 CLI 准备一份已保存密钥（未指定名称时使用固定的 AgentMux 默认名，只接受官方密钥目录中的名称，不接受路径）：接收端为带 PSK、固定 DERP region 的 server key，发起端为 client key，并返回其公开的 client public key 作为本机连接码。自定义名称沿官方 CLI 的原名称精确传递，不按自设字符集或固定长度拒绝，也不修剪或改名；文件系统是否合法由原 Host 与官方 CLI 判定。准备只在该名称的密钥缺失时生成，已存在即原样复用，绝不覆盖、删除或改写任何已有密钥；返回结果区分新生成与复用。私钥只留在原密钥文件，不进入结果、日志或配置；连接码是公钥，可以复制给对方。

准备动作写入本机凭据，只接受传输层认证的本机用户；托管 Agent 不能代为准备或借此取得授权。它只作用于发出请求的 Host 本机，不能替另一台机器生成密钥。CLI 缺失或执行失败如实说明并保留原配置、草稿与健康工作，给出安装与重试入口。

准备失败沿原结构化机器码区分准确服务未提供接口、CLI 明确缺失、已保存密钥不合适及执行尚未确认，不从文案猜测原因。服务接口不可用时说明原服务与下一步，不能用安装 Tailcat 冒充修复；只有原执行 owner 确认 CLI 缺失才提示该依赖未安装。服务未报告方法清单保持未知，不增加版本猜测或关闭健康能力；重新准备仍是人的明确动作。

准备不替人完成授权：发起端的连接码仍由接收端的人填入允许列表，监听开关与保存仍是接收端的明确动作；接收端的私有地址仍经原复制入口交给发起端，由发起端保存并测试同一 Host。两台机器之间只交换这两段文本，不新增无人确认的配对、网络协议或自动加入允许列表。GUI 与 `amux settings hosts tailcat-key` 共用同一 Host 能力。

### 接入失败时交给 Mote

Tailcat 依赖缺失、密钥准备或入站监听失败时，就地说明下一步并保留手动安装入口；用户可选择某个 Mote，交代依赖安装、环境诊断和配置填写准备。任务携带准确的本机执行目标、被配置 Host、接收／发起角色及非敏感字段是否已填写，不把私有地址、私钥或未经筛选的原始错误复制进任务。未保存草稿不能冒充已生效配置。

原失败步骤、已知机器码和所处设置入口以白名单字段加入同一任务上下文，供 Mote 直接消费已确认事实；缺失观察明确未知，不要求重新安装已确认可用的依赖，也不把窗口定位当成业务步骤。帮助入口可在诊断未知时继续使用，不新增求助状态库或借求助取得密钥、允许列表及保存权限。

求助复用原 Mote 目录、逻辑主对话和持久输入队列，沿原角色修订与准确操作回执投递，不按当前活动成员、显示名称或首个 Executor 猜执行者，也不新增专用修复 Agent 或任务状态库。主对话未确认时保原引用和设置草稿，让用户沿所选 Mote 的原开始／恢复入口继续。入队、输入确认、处理完成和连接成功分别表达；未知投递不自动重发。原客户端接入授权、密钥准备和保存权限继续由各自 owner 确认，求助本身不能代批允许列表。

### 当前通信方式

已配置 Remote 的实际通信方式在设备／Host 身份入口可发现，hover 与键盘聚焦可阅读同一事实。当前 SSH 或 Tailcat 只来自观察端维护的原 Host Runtime RPC 通道：真实建连确认、SSH 建连失败后选中 Tailcat、原通道关闭及路由正式采用分别由原传输 owner 提供。已保存偏好与实际采用方式分别标注；候选尚未采用不改变当前投影，断线后最后确认的方式不能继续标为当前已连接。尚未取得事实保持未知，其他独立命令通道、Agent 健康、Tailcat 直连或 DERP 中继路径不由这项观察代签。通道已建立但远端 Core 的 owner 协议明确早于当前合同，须明确提示协议更新要求，不能把它表述成 SSH 不通或 Agent 死亡，也不据此自动升级、重启或降级原 Runtime。

展示消费已有被动状态，不因 hover、focus、节点绘制或筛选发起新连接、探测、诊断／资源读取或轮询。事实附准确 Host／来源与确认时间，经原 SDK、Host inspect RPC／CLI 和 Desktop 状态投影复用；缺失／失败只影响本项观察，原 Host、Session、Run、工作面和恢复动作继续保留。正常提示仅含安全的方式、状态、是否采用备选及来源时间，不回显私有地址、key 路径、命令或原始标准错误。


## 产品目标与主要任务

Remote 管理首先帮助用户回答四个问题：我连接了哪些环境；哪台机器上有哪些项目和 Agent；现在确认了什么、哪里尚未确认；下一步能沿哪个原对象安全完成。

- **找到工作。** 从一台远端进入其已登记项目和原 Session；从一个有问题的 Session 返回其真实执行 Host、语义 Runtime 和具体观察来源。
- **判断影响。** 区分一项连接检查失败、一个 reader 失败、Runtime 身份不符与 Agent 本身故障，知道哪些工作仍可继续。
- **完成管理。** 在准确环境上编辑连接、测试、登记已有项目、查看执行器、核验来源信任或查询原维护操作，明确动作目标和真实回执。
- **减少记忆。** 图与详情共用同一对象选择，保留可读的名字、地址、执行归属和最后确认时间；无需对照多处设置或记住 Session ID 才能追踪问题。

管理台不取代终端、Focus、项目导航、Session 工作面或通用 Performance。它是这些原对象的管理入口与观察投影，不建立第二套执行 Runtime、Agent 名册状态或跨 Host 权限。

## 对象与唯一 Owner

| 对象 | 在管理台中的含义 | 事实归属与不可混同之处 |
| --- | --- | --- |
| 管理入口 / Endpoint | 本客户端正在消费的原业务服务及其能力范围 | 原公共服务与客户端连接事实；CLI 所在机器、接收 Core 的机器和执行机器不混同 |
| Host | 原 endpoint 范围内的本地或 SSH 稳定路由及连接配置 | 现配置 owner；名称、SSH alias 和地址可编辑，不是跨 endpoint 全局机器 ID，也不证明连接就绪 |
| Node / 组网节点 | 原 Core 向访问方发布的身份、资源与共享目录边界 | 原语义 Runtime 的持久身份与本机发布配置 owner；不是另一套 Runtime、物理机器 ID、路由或全网名册 |
| ExecutionHost | 该环境上的文件、shell 与目录访问能力 | 原 Host 执行服务；目录可读不代签 Agent Runtime 可用 |
| 语义 Runtime | 持有 Provider、AgentSession、权限与恢复语义的 Core 服务 | 原执行 Host 上的 Core；持久 Runtime 身份与当前服务进程代次分别表达 |
| ctxmux Runtime | 服务 PTY、Run、Attachment、ordered bytes、Replay 与 Gap 的运行时 | ctxmux；其身份、物理运行事实和资源读数不由 Desktop 猜测 |
| Project / Workspace | 已登记的准确 Host、目录与项目工作面引用 | 原配置与空间 owner；同名或同路径不证明跨机器同一目录 |
| AgentSession / Run | 持久 Agent 身份及某次执行实例 | 原 Core / ctxmux；Session 数、运行 Run 数和 Provider 工作状态是不同事实 |
| Tab / Region | 本地客户端展示原执行对象的位置 | Core 空间 owner 与客户端呈现；打开、选中、拖动拓扑节点不移动执行 cwd |
| Phone / Device | 被授权访问原宿主服务的客户端设备 | 原设备与授权 owner；与 SSH Host 不是同一类资源，不混算为远端服务器或跨 Host 授权端点 |

身份、绑定与恢复的完整合同唯一见[联邦 Runtime 与远端恢复边界](session-recovery.md#联邦-runtime-与远端恢复边界)、[Endpoint、Host 路由与源身份](public-control.md#endpointhost-路由与源身份)及[统一概念与空间寻址](spaces-and-layout.md#统一概念与空间寻址)。管理台消费这些事实，不能因需要画图或展示“健康度”增加自己的事实 Store。

## 本节点的发布与访问边界

Settings 的 **Node** 管“所管理节点对外提供什么”，**Hosts** 管“我连接谁、对方允许我看什么”，**Remote** 管“在哪里开始或继续工作”。连接、监控与浏览不以选择或登记项目为前提。Node 默认本机；显式选择已保存 Host 或从该 Host 进入 Node 设置后，页头、观察、草稿与保存均绑定其准确 Core／Runtime，不把远端节点冒充本机。

节点管理沿原 Core 的 owner 接口与真实 user principal 执行。可信 App 可借原配置路由和 Runtime fence 访问选定 Core；固定的目标范围只承接原 Node inspect／configure／owner-resources，不接任意 RPC，不在 Agent 请求被拒后剥离 caller 重试。同一 owner 已认证的 managed Agent 可以在原 user operator transport 下读取准确 Node 的完整 policy 与原操作；远端只沿已保存且由接收者确认 operator 资格的 carrier，并固定 Runtime／owner 实例，不传递本机 Agent capability 冒充远端身份。该有限只读不授予 publication 写入、私有 owner-resources、密钥或信任权限；device、guest、有限发布 scope 与 route delegation 不能借它升级资格。managed Agent、页面与名字不能取得发布管理权。当前操作者不能完成原用户动作时，保留准确目标、待确认操作与可达入口，不以对话授权冒充协议 principal。

切换目标只改变管理视图，保留各原 Runtime 的未保存内容和操作；迟到回复不能替另一节点保存、显示其策略或覆盖后续输入。远端不可用或缺少接口时给出准确维护入口，不回退为本机策略。入站 listener 仍由原设备自己的配置 owner 管理，远端发布页不得误挂本机 listener 表单。仅打开系统资源共享时，保留原目录授权；原完整 policy 保存会重新确认目录目标，不把它误报为毫无目录效果的窄开关。

发布配置由原 Core 在自己的持久 Runtime 范围持有，包含规范别名、是否共享系统资源、共享目录白名单、禁止访问的路径以及访客默认进入目录。Desktop 是该公共能力的客户端，不能在 Renderer 配置第二份策略或靠隐藏 UI 实施权限。保存沿准确预期版本与真实持久确认；未知回复先检查原操作，不重放。未保存表单、其原版本基线和待确认操作属于 Desktop 编辑意图，沿[原用户状态持久 owner](persistence.md)保全；恢复只读取原操作，不因重开页面或进程而重新发布，另一 Runtime 不能消费这份意图。发布项失败不关闭健康 Agent、已有连接或原工作面。

别名是便于人使用的可变定位名，不是凭证、全球唯一机器名或持久 Runtime 身份。别名规则只描述可用于 URI 的规范形式，不能拿任意 Host label、SSH alias 或地址替代发布事实。当前入口只在自己已配置且认证的 Host 范围解析发布方；同名、离线与未确认不猜首候选，不自动扫描或取得新信任。需要稳定指向原对象的分享保留发布方 Runtime 身份，不能因别名重新绑定而打开另一个 owner 的同名资源。链接格式归[对象链接协议](../../specs/amux-protocol.md#对象链接)。

共享资源通过原 Core 的窄发布接口读取；所有调用者遵守同一已提交发布策略。系统资源未共享时明确表示未共享，缺测与暂不可读分别说明，不用 0 或连接失败代替。默认进入目录是浏览起点，白名单与黑名单决定实际读取范围：目标须属于允许目录且不属于禁止范围，禁止项优先。共享目录在真实路径解析及底层读取边界执行，不信任客户端的路径、链接或 GUI 过滤，不允许符号链接、父目录和另一入口绕过。对外根引用不泄露未发布的绝对路径；没有发布目录时不猜 `~`、当前项目或整个磁盘。

上述策略约束 AgentMux 发布入口，不是 SSH 账号、独立系统工具或 Agent 任意命令的操作系统沙箱。已有同账号 SSH owner 权力、Device 配对、创建/消息来源信任和单次 Agent 权限继续由原 owner 管理；发布别名或打开 URI 不授予这些能力，也不为实施发布规则追溯撤销已有健康工作。发布接口不得在拒绝后退回宽权限文件、Git、shell 或 `runtime.invoke` 通路。

`amux://host/<别名>` 进入已确认节点的资源工作面；嵌套 Agent 和 Capsule 链接分别定位该发布方的原 Session 与原 Capsule，不创建替代对象。Agent 的当前展示位置、继续资格与权限沿原 owner。远端 Capsule 必须经准确 owner 的授权内容载体及原输入协议建立本机访问视图；不能把远端 loopback URL 当成本机地址，不能放开监听或以转发 HTML 的方式冒充完整交互与授权。

## 入口与观察范围

Remote 在 Settings 中有可发现的独立管理入口，搜索、Overview、Host 身份入口及原设置深链都能到达准确对象。原连接、项目和信任管理能力沿同一 Host owner 承接，不以增加 Remote 为由出现两套可编辑 Host 清单。Settings 的同一 Cluster 分组依次提供 Node、Hosts 和 Remote；节点发布、访问路由和工作能力的分工见[本节点的发布与访问边界](#本节点的发布与访问边界)。各页均能独立直达，Remote 不复制 Host 编辑器，Host 也不被归为某一种远程工作模式。Host 工作台保留原 `hosts` 对象与准确导航身份。Phone、外部对话应用和全局 Executor 模板继续由原 owner 管理。

同一 Host 工作台按总览与监控、项目、应用与访问、连接配置组织任务。切换任务仍持有同一个准确 Host、原草稿与已访问操作，不建立三套选择器、清单或配置副本。总览承接拓扑与分源观察；连接配置承接原编辑、Test 与 Core 维护；应用与访问承接该 Host 的真实执行器盘点及跨 Host 来源核验、真人批准。全局模板不冒充远端已安装应用。

应用账户凭证、来源 Core 信任、单次 Agent 权限和 Phone / Device 配对各有不同主体与授权 owner；应用与访问不暗示它们已统一同步。应用账户同步的准确来源、目标、最小材料与目标验真由[Remote 应用授权同步](remote-application-access.md)持有；不复制系统权限或整个用户目录，不以统一登录态代替具体应用协议。

进入后先显示已登记的环境和当前已有事实。查看拓扑不自动部署、升级、恢复全部 Session、运行任意 shell 或扫描网络；网络读取沿[所选 Host 的显式观察范围](#所选-host-的只读网络观察)，需要实际连接才能取得的事实由原服务按准确目标取得。离开页面只释放本页观察，不断开其他消费者或停止健康 Run。

“所有环境”必须说明它是已配置环境，不能冒充扫描发现的全部机器。筛选可按名称、地址、项目和明确的待处理状态收敛；筛选只改变可见范围，摘要说明过滤条件与观测覆盖，不把被过滤或读取失败的对象算成不存在。

设备也可从 Space 的名称入口直接进入其 [home 工作面](spaces-and-layout.md#设备主目录工作面)，无需先手动建立项目；Remote Agents 继续承接下面的双端资源选择。

## 独立 Remote execution 工作台

用户可见页面名为 **Remote**，稳定模块身份保持原 `remote-execution`。页面目的，是让用户明确“Agent 在哪里运行、项目与工具在哪里、怎样开始或继续这项工作”。它与 Hosts 同层参与 Settings 导航、Overview 和搜索；详情复用原 Host 的准确对象深链，不要求先进入某台 Host 才能找到执行入口。本节持有行为合同；设置、创建与观察的源码入口见[实现基线](#公共能力与当前实现基线)，源码入口不代签特定运行实例或 Provider 资格。

日常项目工作的模型是“哪个 Agent 在哪个 Space 的项目上工作”：先选择项目，再选择 Agent。尚未启动的 Launcher 以原项目 resource Workspace 为锚，默认 Agent 跟随项目设备；Outpost 表达使用另一设备的 Agent。项目在远端时也沿同一流程，不因查看者换了设备而交换项目和 Agent 的角色。

| 运行关系 | Agent 运行端 | 项目文件与工具端 |
| --- | --- | --- |
| 项目设备上的 Agent | 项目设备 | 原项目设备 |
| Outpost · 分端 Agent | 用户选择的另一准确设备 | 原项目设备 |

Remote 集中说明同机、分端及访问远端工作面的场景。Reach／Orbit 可作为访问场景说明，不是固定项目 Launcher 必须再选择的方向；客户端不必先判断相对查看者的四象限。查看远端工作面不代表只读 ACL、自动持续推进或新常驻服务。运行关系是原两端绑定的投影，不是持久模式、权限、连接状态或新的执行协议。

已运行 Session 始终以原工具资源与 Agent 绑定为准；移动到另一展示 Space 不改变其项目、Agent、cwd 或 Coordinator。原绑定中的局部 Host ID 不能直接当成查看设备的地址；缺少准确身份映射时保留未知。展示参照和品牌名称均不改变执行事实。

### 级联路径与工作模式

运行关系回答“项目和 Agent 在哪里”，执行路径回答“Agent 的工具怎样到达项目”，观察者访问路径回答“此客户端怎样查看它们”。三者分别具名，不能拿一条已连接 SSH 通道代签完整工具链。

例如 A 查看 B 项目，B 连接 C、C 连接 D。B 项目的 Launcher 默认选择 B 的 Agent；用户选择 Outpost 后，可选择沿已配置并获准的路线到达 D 的执行环境。项目仍为 B，Agent 仍为 D，C 只作中转，A 只作查看入口。用户的日常操作仍是选项目、选 Agent，不需要在 Launcher 手工重建级联链。

Remote 集中配置和观察准确路线。每一跳解释自己 owner 下已配置且获准的下一跳，保留终点 Runtime、逐跳身份及原 operation；业务参数不能携带任意 endpoint、凭据或自报 actor。B 有 C 的连接不自动授予任意 A 使用 C／D 的权限，相同 Unix UID 也不证明跨机器同一主体。沿原传输认证与明确逐跳委托执行；连接、配置、授权与实际采用分别表达。

路线发现从当前策略 owner 的安全已保存连接清单开始，显式选择一条连接后才读取实际对端签名身份。继续查看下一节点时，沿已保存且已获准的前缀逐次读取，不隐式保存草稿、递归导入配置或搜索全网。读取同时返回原来源限定的 actor，供准确展示和准备授权请求；此读取不授信，C 的接收策略仍由 C 的实际 owner 明确配置。缺少某一步权限时保留路线草稿、已确认路径和其他工作，只说明这次读取或保存的缺口。

完整路径和跳数由原路由 owner 的具名逻辑路径回执提供。跳数计该路径的转发边：同一已确认 Runtime 的项目与 Agent 为同机，明确一条边为直连，多于一条为级联。执行路径与客户端到两端的访问路径各有自己的跳数、来源、观察时间及完整／部分／未知状态。SSH ProxyJump 的配置、IP 路由器或界面求得的最短路不能充当当前执行跳数。中断、回执缺失和路由变化保留原请求，不改路重放业务操作。

**当前能力边界：**Core 已提供显式级联的公共调用、流、取消、逐跳授权及原分端执行入口；源 Space 的快照、变更和成员访问也沿其原业务身份提供。它们不等于完整桌面挂载、级联选择和每种输入方式已经交付。客户端仍须接通原消费者，保全原工作面与输入，并完成实际验收；A 不递归导入其他节点配置或自动发现全网。源码入口与仍缺的闭环沿[实现基线](#公共能力与当前实现基线)分别核对，不能用本节目标或示意图代签。

### 开始与继续工作

Remote 先展示已有工作及能力说明，明确选择“开始新工作”后才展开两端准备；访问页面、连接或浏览节点不要求项目。准备工作时说明目录用于这次任务的文件与命令，已有上下文准确带入，无项目时可选择准确设备已经确认的目录，不强制先登记业务项目。原“开始工作”与“已有工作”仍是两个明确任务面；切换保留原准备选择、所选 Session 和搜索，不运行准备、清除草稿或重绑。先明确准确的工作目录，再选择执行 Agent，检查同一处两端摘要后进入原 Launcher；模式与级联有集中说明和配置入口，不要求用户在每次创建前重学网络拓扑。品牌名不成为持久模式值、权限或连接事实。目录可来自当前上下文、已登记目录或准确 Host 的权威 home，不强制先登记项目。分端时默认 Agent 启动目录来自该 Host 的权威 home，按需选该 Host 的已登记目录；同 Host 原普通执行不强建工具 binding。准备不启动 Agent、不发送任务、不安装、升级或授信，不猜 `~` 或任意同名目录。准备失败保留原选择和草稿，迟到结果不能覆盖新对象、配置或后续输入。没有匹配目录时保留准确 Host 的原目录登记入口作为可选操作，不把未知清单当空列表。

日常项目工作沿 Space 中的[原 Launcher](workface-launcher.md#agent-运行端与项目工具端)开始，Settings 同时保留准备原 Launcher 与管理已有绑定的入口。操作正文唯一在[Core 使用指南](../../../packages/core/guides/actions/remote-execution.md)，由设置页和原 CLI 帮助同源消费。指南覆盖登记环境与目录、选择准确两端、显式启动和继续原工作，说明浏览一台机器与选定其项目是两个动作；不在本页或 UI 另写一套步骤及能力清单。

页面以当前客户端保存的非纯本地 AgentSession 为工作对象，包括显式双端绑定与无 binding 的普通远端同 Host 执行；同一 Host 可以承载多个绑定，绑定不等于 Host 连接、全局执行模板或新的常驻服务开关。列表沿当前管理入口可确认的 Session 与绑定引用组织，并标明观察范围；没有全域发现事实时不声称列出所有机器或全部工作。名称帮助阅读，准确 Agent Host、资源 Host／Workspace、Session 与 binding 身份负责定位。每个非纯本地 Agent 用同一紧凑关系标记表达项目端与 Agent 端，完整运行关系及路径按需展开；Region、Tab 对应 Agent 标记、Focus／Space 与恢复候选消费同一原绑定投影，不重复叠加机器名和长模式标签；多 Region Tab 不把活动 Agent 的 Host 冒充整张 Tab 的唯一归属。只有确认两端均本机时省略标记；缺失事实显式未知。名称、展示移动、观察失败与标签样式不改变 Session、Run、工具端或权限。工具桥接状态、Agent 运行状态与 Provider 分项能力分别呈现，`connected` 不能代签 Hooks、Skills、MCP 或 Agent control 全部可用。

| 用户任务 | 页面动作与完成信号 | 复用与边界 |
| --- | --- | --- |
| 理解并开始 | 一处双端用途说明与明确的开始入口；进入可编辑的原 Launcher 后再由用户启动 | 复用已登记 Workspace、准确 Host 的 Executor inventory 与原创建路径，保留项目侧文件引用、草稿与 warm shell；不在设置另造创建表单或自动提交首输入 |
| 找到原工作 | 按名字、两端环境或项目查找绑定，选择后可打开原 Session 工作面 | 复用原空间导航及 Session 投影；原 Tab／Region 存在时回到原位置，无法导航时保留准确引用与原因，不改开新 Session |
| 理解当前能力 | 所选绑定显示两端角色、工具观察及具名 Provider notices，并可刷新原观察 | 复用 Core inspection／订阅与持续服务窗；没有 notices 的空回执不推导所有功能受支持，未取得状态明确未知 |
| 修复准确环境 | 从所选绑定进入对应 Host、Executor 或来源信任管理，保留返回原绑定的路径 | 编辑、Test、审批和维护由原 owner 完成；页面不新增第二份 Host／Executor 配置，也不要求用户抄填凭据 |

开始入口必须区分新工作意图与已有工作。普通启动保持原行为；分离执行明确项目／工具 Workspace 和 Agent 运行 Workspace，两个方向使用同一角色模型。所选 Provider 或工作区模式尚不支持时，只说明该次新操作的资格与可用路径，保留草稿和普通工作能力；例如 Mote／Scratch 的上下文归属尚未具备跨 Host 合同时，不能把它作为普通项目静默送入此模式。进入、切页或刷新不创建 Agent、重启 helper、交换运行端或修改原 Session 绑定。

普通新共享请求的启动选项、原用户正文、独立平台说明和终端尺寸由同一公开合同传递；选项声明来自所选执行端的原 Provider，私有 argv／环境不随发现返回。调用方说明与 Source 自身上下文分别保留来源，仅由 Core 原出口组合，不改写用户正文或在 Host 静默覆盖说明。路由授权须绑定原输入贡献与实际创建输入，已有冻结请求不按当前设置重建。Source 的实际操作合同通过准确只读发现确认；不从包版本、可执行文件可用性或展示错误猜测。只在选中 Source、派发新共享请求前读取，未支持或未确认时在创建前说明本次缺口；原请求检查／续接、健康 Pane 和原单向 Reach 不新增这项门禁。

读取未完成、来源不可达和权威零集合分别表达。已有绑定的观察失败时保留最后确认事实及其来源、失败步骤、原工作面入口和刷新动作；未知不画成停止，刷新只更新观察，不重放命令、文件修改或 Prompt。原 Run 的重接、恢复与未决操作查询继续沿[恢复合同](session-recovery.md#联邦-runtime-与远端恢复边界)，本页不拥有新的恢复循环或手动停止全链路的按钮。

执行状态的主层以当前准确对象上的机器事实说明实际影响、已确认仍可用的能力和下一步；上次操作失败与当前观察分别具名。默认未配置、尚未核实与当前故障不能合成一个失败结论，完整 Provider 分项、原诊断、操作身份与原因按需展开并保留。没有当前运行或输入事实时明确未知，不能借“仍可用”文案代签 Agent 健康。收起、去重和措辞不改变原观察、显式动作资格或原请求；不解析给人看的错误字符串来判定状态、恢复条件或授权。

连接观察消费原 helper Run 的权威进程与 Attachment 事实：已确认退出与观察不可达分别说明，不能因没有新输出而沿用连接正常。连接状态、原生 generation 状态和局部工具操作诊断分开；某个请求被拒绝不关闭整条健康通道，未决操作沿准确 binding／generation／原 request ID 保留，不被后来的诊断覆盖。结算只由该原操作的持久结果／对应回执建立，任意成功帧或单纯重接不能清除其他未决结果。

“刷新观察”保持只读；原 reader 已中断时另提供明确的“重接原工具连接”，沿既有 `agent.execution.rejoin` 与原 user／device 权限执行。动作保留两个原 helper Run、Session 与持久桥接游标，可能继续结算同一个 recoverable Input claim；界面须说明此范围，不能称作无副作用读取，也不能新建 helper、改操作身份或重新提交未知 native 工具请求／Prompt。失败保留原引用、最后确认事实和继续工作的入口。相关公开 inspection 元数据、CLI 与第一方服务窗必须同源表达原因、范围与下一步。

Provider 可以使用原生执行服务，也可以将原生工具接口连接到资源侧 MCP；接法由 Provider 解释，Host／桥接／持久操作与恢复保持通用。采用工具替换时，运行端原生文件、命令与工作区副作用不得越过既定资源绑定；主 Agent、子 Agent 与 Skill 的工具约束均须成立。工具许可由原生权限流程或准确授权 owner 作出，不能把普通工具规则自动视为 MCP 同名工具的授权。Hooks、Skill、项目说明与用户配置须说明实际来源、执行端与已验范围；保留原会话身份和用户原配置，不能以空配置或关闭健康功能代签适配完成。 状态观察回调与会改变执行许可的自定义 Hook 按其真实合同分别判断；某种原工具名匹配在替代工具路径上的兼容差异，只说明该准确配置或调用的范围，不能由隔离反例推断用户已配置禁令，也不能据此关闭整个 Provider。尚未证明任意扩展完全等价，不构成扫描所有 Hook 缺席后才允许正常工作的前置条件。

页面只订阅当前相关对象；切换、隐藏或离开后释放自己的 reader，不断开其他消费者。列表摘要复用已有 Session 投影，详细 inspection 按需消费原绑定，不能为每帧更新枚举全部 Session 或重新连接所有 Host。临时读取状态与选择属于呈现层，双端绑定、能力资格和持久操作回执仍由 Core／Provider 原 owner 持有；若列表所需发现能力缺失，须在该公共 owner 补齐并供 GUI 与 CLI 同源消费，不在 Renderer 扫描持久文件或自建绑定数据库。

交付需验证从页面进入原创建流程、两个执行方向的准确角色、从原绑定打开持久工作面、未知观察时继续工作及离开后 reader 收敛。源码存在、工具往返或静态介绍均不能代签页面完成；真实调用链、变异、重启与独立视觉验收继续沿原规则。页面不自动扩展跨账号共享、自动选机、运行中切换、批量运维或能力探测范围。

## 拓扑及选择模型

### 真实关系优先

首层拓扑展示“本客户端 / 管理入口 → 原 endpoint 内 Host route → 已核验 Runtime”的逻辑关系。身份沿[Endpoint、Host 路由与源身份](public-control.md#endpointhost-路由与源身份)，不能把接收 Core 中的 `local` 一律画成 CLI 所在电脑；普通 Desktop 只有在原本机身份已确认时才显示 This Mac。Host 节点以原 endpoint 与 Host ID 定位，Runtime 有确认事实后再披露其准确绑定，不新增全局机器 ID。

边表示已保存或本次配置求值得到的逻辑关系，不承诺真实物理网络路由或正在保持的 socket。连接观测有来源时才在边上表达其结论与时间；没有当前观察时仍保留配置边，并明确其未确认性质。

节点邻近的网络信息消费原配置、准确输入上的检查及下节具名网络观察。未取得新观察时，hostname／SSH alias、用户、端口与 Runtime 绑定继续保持其原配置含义；未显式覆盖的值说明沿系统 SSH 配置，不补成已经解析或连接的网络端点。

系统 SSH 在本次读取明确给出的 ProxyJump 顺序可作为该路由的中转关系，标为配置路径；中转项只在原路由范围内辨认，不因此新增可管理 Host、Runtime、云区域或设备身份。SSH alias、内网 IP、相同名称或地理线索不能补出其他跳点；自定义代理只表示路径不透明，不解析命令猜中间设备。

同一 Host 的 Runtime、项目、执行器和 Session 关系放在选中详情或按需展开，不默认把所有资源铺成不可读的大图。多个 Host 是否属于同一物理设备，缺少权威身份就不合并；即使多个 route 已确认为同一 Runtime，也保留各自准确路由，不把连接别名统计成独立 Runtime。Host、Runtime 与会话聚合各保留自己的身份范围和去重口径。

拓扑内提供 Fleet map / Selected link 观察范围，与 Topology / List 呈现方式分开。Fleet map 沿原 Host 库展示环境关系；Selected link 只围绕当前所选 Host 投影同一网络观察中的配置中转与分源接口，不另设 Host 选择、草稿或事实 Store。范围切换不触发读取，不改变原焦点、保存、Session 或工作面；返回 Fleet map 保留原视口。

### 所选 Host 的只读网络观察

网络观察回答当前路由如何配置、原服务这次回应花了多久、各来源确认了哪些地址。GUI 与 CLI 经同一 Core 公共服务读取；准确 Host 配置、原客户端与 Runtime 身份仍由原 owner 持有，不在 Renderer 执行 shell 或新增网络事实 Store。

| 来源 | 提供的事实 | 必须保持的范围 |
| --- | --- | --- |
| 原 Host 配置 | 原 endpoint 内的 Host、hostname／alias 及显式覆盖 | 保存值不证明已连通，也不因只读观察被改写 |
| 系统 SSH 本次配置求值 | 目标 hostname、用户、端口、配置中转顺序与保活策略 | 复用原路由参数；当前求值不证明既有连接采用了相同配置。加密协议保活与 TCP 保活分开，策略不证明已收到保活响应 |
| 原 Owner 的新鲜公共调用 | 已确认 Runtime 身份、本次 Owner RPC 请求耗时及采样来源 | 单调时钟仅包裹这次公开调用；可能包含建连、排队与服务处理，不包含 SSH 配置解析或其他观察的总耗时，不称为纯网络 RTT、ICMP 延迟或逐跳时延 |
| 发起端与目标服务的网络接口 | 各自进程网络命名空间可见的接口名、地址族、地址、CIDR 与内部接口分类 | 两端各标实际进程来源，不将观察服务一概称为用户电脑；接口存在或名称不证明 VPN／隧道类型、连通性或当前出站接口。网卡地址不证明实际连接使用该 IP、NAT 出口或公网身份，不输出 MAC 或凭据 |
| 可选的发起端 DNS 读取 | 该观察端解析得到的地址候选 | 不要求首个闭环必须提供；候选不证明连接端点，也不代替跳板远端的解析结果 |

每次读取捕获准确已保存 Host 配置与原客户端，返回前复核两者仍相同；新鲜 Owner 结果通过原 Runtime 及服务代次核验后，才可关联请求耗时与目标接口。缓存身份不能代签这次网络回应。各来源分别带原采样或读取时间及局部失败，当前缺口与最后确认的旧值沿[状态、失败与恢复](#状态失败与恢复)表达，不把旧值刷新为当前正常或把缺测补零。

聚合查询先在原 endpoint 认证调用者；仅准确的网络只读叶借用所选 Host 的已授权传输，不把源端 Agent 凭据当成目标端身份，不放宽 Runtime 域的直接调用权限。无效调用者在网络观察前拒绝；合法 Agent 与用户经同一聚合能力取得具名来源结果。

GUI 只对可见的所选已保存 Host 显式读取或刷新网络，下述本机节点地址除外；CLI 沿同一准确 Host 公开查询，不以 GUI 可见为前置。节点渲染、缩放、筛选或选择全图不触发其他 Host 扫描，不另开定时探测与后台重连循环。SSH 配置求值可能执行用户已有的 Match exec，只在这次准确读取内进行。该求值仅返回上述网络字段，不将代理命令原文、完整命令输出、标准错误或额外私有路径加入观察结果及诊断，也不将解析值导入连接配置；用于原配置核验的 `configuration` 沿已保存 Host 配置合同返回，不属于 SSH 求值新增采集。正常请求可沿原传输的建连路径取得响应，不替换原消费者，不启动 Native、不枚举或恢复 Session，不重放输入；取消只结束本次观察，保留其他消费者和健康 Run。

已确认的本机 Host 节点例外地显示本机局域网地址，帮助用户告诉另一台设备“这台机器是谁”。来源是本机 Owner 在同一网络观察中给出的目标接口；Remote 页面可见时对本机读取一次，本机配置变化时重读，不轮询、不联网、不探测、不读取其他 Host。首选地址取非回环的 IPv4，有线与无线网卡优先，链路本地地址、VPN 与其他隧道接口靠后；其余地址按需展开。读取中、读取失败与本机确无局域网地址分别表达，不以空白或旧值冒充当前；接口地址不证明另一台设备可以到达这台机器。

物理路由器、网关、当前出站接口、实际 SSH 末跳 socket、完整物理路径、各级实际连接 IP、逐跳时延、丢包、公网出口与持续历史未有相应结构化来源时保持未知。链路与接口视图复用已有分源网络结果及原公共查询，不新增网关、socket、MTU 或接口类型采集；本范围不运行 traceroute、不访问外部 IP 服务、不修改保活策略，也不把配置中转节点画成已测得的物理网络。

### 连续理解与准确导航

拓扑节点和等价列表选择同一准确 Host，详情显示该对象当前可用事实与动作。缩放、平移、适配画布和筛选不改变配置、连接、焦点工作面或执行绑定；不提供拖线建立连接、拖拽迁移 Agent 等缺少真实业务合同的交互。

用户明确选择项目或 Session 后，沿原导航打开其准确工作面；现有工作面优先复用，远端暂不可用仍可查看原引用与恢复服务窗。导航未成立时保留设置与原选择，不把发起调用当作已打开工作面。选中节点本身不启动 Agent，不偷换当前执行环境。跨设备项目编组仅引用[原项目组织关系](spaces-and-layout.md#project-与-workspace)，不画成网络连接或一台虚拟 Host。

## 信息与监控层级

默认阅读顺序是环境身份、当前可确认结论、正在承载的工作、下一步；技术细节逐层披露。每一项动态事实均能追溯准确 Host / Runtime / Session / Run、来源与观察时间。最近成功与本次失败分别保留，不用刷新时间替旧值续期。

| 阅读层 | 应回答的问题 | 信息与边界 |
| --- | --- | --- |
| 环境总览 | 哪些环境值得我先看 | 已配置环境数、当前观察覆盖、明确需要处理的对象；不同事实不压成缺少依据的全局健康分数 |
| Host 节点 | 这是谁，现在知道什么 | 名称、连接类型、简短地址、具名观察状态、最近确认时间；可选项目与 Session 摘要明确是登记/引用还是当前运行口径 |
| Host 详情首层 | 这台环境正在承载哪些工作 | 准确 Host、语义 Runtime 绑定及身份确认结果；可定位的项目与原 Session；当前观察缺口和一项明确下一步 |
| 执行与能力 | 在这里能启动或恢复什么 | 原 Host 的执行器清单、Provider、配置来源、可用性、失败原因；全局模板不能冒充该 Host 已安装配置 |
| Runtime 详情 | Core 与物理 Runtime 各处于何种状态 | 当前可证明的 Runtime / owner / Native 身份、协议、平台与能力；serving 与 bundled 候选明确区分 |
| 资源详情 | 资源来自哪里，读数有多新 | 原 Runtime 已公开的 Run、Attachment 与保留输出等事实；CPU、内存、磁盘仅在有原 owner 的测量合同时展示 |
| 网络详情 | 路径、策略与地址分别确认到哪一步 | 沿[只读网络观察](#所选-host-的只读网络观察)分源披露配置路径、保活策略、Owner 请求耗时与接口地址，不压成链路健康分数 |
| 诊断与维护 | 失败在哪一步，原动作做到了哪里 | 准确来源、步骤、原因、原 operation 与阶段、下一步；观察当前状态与查询旧操作回执分别表达 |

Session 的工作、等待、权限请求、未知等状态沿[Core 语义与 Provider 事实](agent-capabilities-and-messaging.md)，不能从进程 running、终端文案、输出速率或最新活动时间猜出。离线、尚未测试和不支持必须可辨；没有当前读数时不补零，也不借用本机 CPU、内存或卷容量代替远端。

原 Runtime 资源采样、逻辑核口径、stale / pending / unavailable、共享采样及最后消费者释放沿[资源观察合同](settings-and-observation.md#status-bar-cpumemory-资源面板)。节点发布的整机 CPU、系统内存、磁盘卷与原 Core 进程的 CPU、RSS／heap、uptime 均由该服务实测并保留测量对象、单位、时刻与实例身份，不借用接收端读数。CPU 基于同源累计值的实际区间，首点不伪造百分比，重启后不跨代相减；保留终端输出 payload 不能冒充进程内存。

Service status 的首层面向当前准确 Host 的服务观察，区分服务进程与整机公开资源。本服务的 Core CPU／RSS／heap／uptime 只消费原 serving Core 的结构化测量；Native Run、Attachment 与 retained output 沿原 Runtime 口径，运行 Run 数不冒称 Agent 数，输出 payload 不冒充磁盘 I/O。已获原 owner 读取资格的 Desktop 可沿准确 Host／Runtime 的既有私有 owner 入口读取；这不修改 Node 的 Share，也不把普通发布访问者提升为 owner。公开资源被 withheld 时明确未共享；旧 Core 或来源缺失只使该读数未知，原 Session 与其它成功来源仍可用。

Agent 观察以原 Core 的 Session 记录为口径：Saved 是当前持久且未退役的原记录，Retired 是未被原 recordDeletion 事实删除的退役记录；Running saved 是同源 Native 当前 running Run 与这些记录的准确当前 Run 绑定交集。它不包含 Terminal、helper、退役 Run 或尚未确认持久化的创建，不表示 Provider 的工作／等待状态。Saved／Retired 与 Running 分别保留自己的观察时刻，不宣称跨 owner 原子快照或瞬时比例。计数在原 Store 聚合，Native 只提供原薄列表；不为监控导入历史、逐 Session hydrate、探测 Provider 或新增事实 Store。原 Native、记录计数与运行交集是独立读取，一项待定或失败不拖住另一已完成来源的交付。

Core I/O 消费原进程 resourceUsage 的累计读／写操作次数。Unix 的文件系统操作与 Windows 的进程 I/O 口径具名，均不冒充字节、磁盘或网络带宽及子进程工作；Native stream 是另一对象。区间速率只在同 Runtime／owner instance／PID／计数口径的两次成功样本间按真实 elapsed 派生，首点、缺测、回退和换代断开，不填零。原 Node private owner／public Share 与准确 Host 观察沿各自既有资格，新增缺失字段只使相应指标未知，不拿走旧来源能力。

本管理台复用当前展开 Host 的顺序读取循环，不因缩放、图布局或节点渲染扫描无关 Session。展开、当前页且文档可见才读，折叠或隐藏取消自己的观察；图表故障不阻断读数与健康工作。近期曲线仅保留本次可见读取所得的有界内存样本，明确窗口、来源、单位与断点；缺测不填零、不平滑跨断线、不重复标旧值为新。长期历史、告警与可用性统计仍须独立采集及留存合同，网络吞吐、温度与逐跳延迟无真实来源时不画图凑数。

## 连接配置与测试

Host 的公共配置链支持按稳定 ID 新增、读取、完整 expected/CAS 编辑与删除，并复用原 ConfigOwner、schema、持久确认与发布。登记未安装或暂不可达的 SSH Host 不要求远端 Core 已就绪；尚无已保存 Runtime 绑定、原已采用身份及本地 Session 投影的连接草案，修正或取消不以旧地址连接成功为前置，这不证明远端没有其他工作；已保存配置与当前连接事实分别表达。新增不能自报 Runtime 身份，已学习的 Runtime binding 不允许清空、改写或复用到另一 Host；已绑定的路由变化沿同身份修复核验。删除不能级联删除项目、Session、Run、草稿或工作面；已退休 Session 的原恢复与历史引用同样受保护，不能仅凭当前活动清单或 Run 为空移除原路由；仍被引用或无法确认可安全移除时保留原对象，给出准确引用与恢复动作。本机 Host 保持原唯一身份，不通过通用增删替换。公共操作沿原服务，不读写客户端私有配置文件；丢回执后先读取原保存事实，读取不能冒充原操作完成，不自动重放。

通用保存、冲突、搜索与草稿规则仍由[设置共同合同](settings-and-observation.md#设置页的信息架构)持有；本节持有 Host 专属要求，页面结构变化不授权另一份配置实现。

- SSH 连接的常用编辑为名称与 hostname／系统 SSH alias；用户、端口、密钥和服务覆盖按需展开，保留已有字面值与只读 Runtime binding；连接编辑不扫描或导入 SSH 配置，不自动部署服务，只读配置求值不回填覆盖字段。空覆盖沿系统 SSH 已有行为；保存连接不等于连接已就绪，Test 仍使用完整当前输入并显示真实结果。连接复用沿原 Workspace→Host 引用，展示选择不为全局 Executor 模板另存一份 Host 绑定；目标 Host 的注册配置与可用性沿[执行器设置 owner](settings-and-observation.md#设置页的信息架构)取得。Session 数只表达实际引用，不冒充运行中数量，原删除和保存保护不在布局调整中放松。 已确认本机 Host 不挂载 SSH 连接字段；其他对象的编辑挂载、精确选择、重复导航、新建聚焦、搜索命中与窄窗返回沿[设置共同合同](settings-and-observation.md#设置页的信息架构)。

- Hosts 的连接编辑区必须允许正常逐位输入 Hostname；首字符与后续内容变化不能自动折叠字段或移走输入焦点。展开/收起属于用户操作，同一 Host 的草稿、检查结果或无关配置更新不能改掉用户的展开选择；新 Host 可直接进入编辑。

- Hosts 编辑同样保留原始字段基线与保存期间后续输入；无关 Host/字段提交只刷新 clean 内容，同字段冲突、准备失败与外部删除保留草稿，不用保存时的新快照消除冲突或静默重建。当前远端准备能力尚不可用时如实说明，不把受控准备条件下的保存成功冒充远端 Runtime 能力，也不打断无关本地健康 Run/Input。说明文字和 Test 反馈须与当前实际能力一致，不先承诺保存或测试可用、再在动作后否认；失败原因完整可读，草稿与健康输入保持。

- Hosts 的 CLI 读取已提交的连接记录；已保存连接按明确稳定身份取得当前已提交对象并测试，草稿才按明确输入测试，不猜默认 Host、焦点或显示名称；测试不改配置、工作面或健康会话。连接就绪、当前能力明确不支持与检查没有取得事实必须区分，不能把检查失败说成目标不可用，也不能把未知说成就绪。测试结果保留原始原因并绑定本次输入，CLI 回执与界面当前结论都不得把同 ID 的旧 Ready 用于后改或并发替换的连接值；新输入未测试时如实说明，不覆盖检查期间的后续编辑；远端尚不支持时如实说明，不用另一条启动路径绕过它。Host 删除、连接重绑与身份复用另有引用完整性合同，不能只凭可见会话或 connected Run 为空放行。

- **同一 Runtime 可以修复接入路由。** 用户明确保存已绑定 SSH Host 的新地址、SSH 用户、端口、密钥或服务入口时，Host ID、类型与已提交的 Runtime 绑定保持不变。候选须经系统 SSH 认证并由新路线上的原 Core 公共身份协议确认；不能只相信表单中的 Runtime ID，不能因旧线路不可达而要求先停止任务。删除 Host、改变类型、未绑定连接或换到另一个 Runtime 不属于这项修复，仍沿原引用与身份合同。

- 路由修复沿原配置 owner 提交准确的预期版本与完整候选输入。候选确认期间保留原可用连接和输入，不预先关闭读者；配置持久保存成功后才采用新路线。保存失败、取消、身份不匹配或并发变更保留原配置与草稿并说明准确失败步骤。GUI、JSON-RPC 与 CLI 共用同一提交，不各自写配置文件；响应未知时先读回原已提交对象核对，不能重放任何运行操作。

- 修复连接不等于重建工作。原 Session、Run、消费者、附件、历史观察与字节游标的保全及恢复资格唯一见[同身份路由修复](session-recovery.md#同身份路由修复)。管理台分别表达“配置已保存”“原 Runtime 身份已确认”与“原读者已恢复”；身份确认不能代签当前 Run 或阅读恢复，局部观察失败不拖垮其他读者和健康环境。不暗中部署、升级、重新授权、自动故障转移或重发未知输入。

- Remote 中的环境库按稳定 Host ID 展开对象子菜单，分别查看连接配置与已登记项目。展开或关闭只改变导航；项目依据原 Workspace 的 `hostId` 投影，不以同名、同路径或当前焦点猜归属，不产生第二个项目编辑器。切换对象、子页和手机设备分区继续保留原全库草稿、按对象持有的高级展开选择、保存期间输入及冲突，窄窗返回准确当前子页入口。

- **首次跨 Host 来源信任由用户显式批准。** 已保存的目标环境在应用与访问中提供来源核验入口，显示本机来源与目标的 Runtime 身份、公钥指纹和目标已保存的信任事实；仅真实用户核验后明确批准，不自动信任、不替换已绑定公钥。连接、身份或公钥变化使旧核验失效，未知、冲突和保存失败保留真实原因及重新核验路径。该入口复用原 Host 的公开信任能力，Agent 不能借自报身份或界面输入替用户批准；身份与签名合同沿[A2A owner](a2a-collaboration.md#a2a-身份信封与持久化全局消息队列)。

- 消息来源信任在同一环境的 Agent 访问中按「本机到目标」与「目标到本机」分别展示和批准，明确双方 Runtime 与公钥指纹；两份批准只授予各自方向的消息目的。创建信任保持原范围，连接就绪或已接收任务都不能自动提升权限。审批回执未知时保留原核验事实，先读取准确目标的已存信任，不自动重批；缺少一方向信任不影响其他健康能力。确切签名与回信通路唯一见[跨 Runtime 原消息与回报](a2a-collaboration.md#跨-runtime-原消息与回报)。

## 诊断、维护与授权入口

本机Tailcat入站监听的开关、key引用与allowed clients由原ConfigOwner以准确listener slice CAS提供公共读取／配置入口，保传输认证的原用户与managed caller边界；不移除普通Host configure对local敏感字段的保护，也不把单次Core维护审核变成通用授权平台。key准备、配置保存、监听实际采用与网络可达分别成立；当前listener查询不重新启动进程，不因CLI或检查失败阻断显式禁用保存。远端路由、Node发布policy和同名另一机器的local不能代替这个准确入站对象；不读取／输送私钥，失败保原Core／Native／Run能力。

Agent 可为一个准确已保存 Host 提交单次 install 或 upgrade 请求，绑定原请求者 Session/已确认 Run、完整 Host 配置、维护 expected 与候选身份、原 operationId。申请和查询不执行维护，也不授予 standing 权限。只有传输认证的真人用户或设备且没有 managed Agent caller 可显式批准或拒绝；批准核对原请求摘要，再由原维护 owner 复核 Host、expected 和候选，持久记录审核主体与执行采用事实后施效。Agent 不能自批，也不能把请求 ID 当 bearer 授权；原直接真人维护命令保持可用。重启、记录失败、连接断开或未知执行回执保留原请求与查询路径，不重新批准或自动重放部署。审核范围不包括来源信任、凭据准备、远端清理或批量操作。 原接收 Core 与配置／维护 owner 分属进程时，公共申请、查询和审核沿原 client 转发接缝抵达唯一 owner，保留原认证主体；接收 Core 在转发前核验自己的 Runtime fence，目的端继续核验原主体与审核资格。不因本地未持有配置 owner 而阻断已提供的准确转发，也不另选 Core、降身份或自动重放。

应用账户同步由[Remote 应用授权同步](remote-application-access.md)唯一持有：用户配置准确来源、目标、应用账户和 scope，先比较差异，再显式传递最小材料并由目标验真。应用与访问页消费该能力，与 Agent 配置盘点、来源 Core 信任分区呈现；不把三者合成一个权限开关。

跨模块证据、关联、历史与采样机制统一由[Diagnostic Evidence 设计](../diagnostic-evidence.md)持有；Remote 消费其原对象与来源，不另建诊断 Store 或事件中心。诊断先解释失败边界和已有可用能力，再给沿原目标的动作。连接测试、资源刷新、执行器检查和维护检查分别说明范围；它们不互相代签，不将“重新测试”包装成自动升级或重启。只读摘要可提供安全的准确身份、版本依据、失败步骤和原操作引用用于复制，密钥、token、私有 Executor 环境及输入正文不进入普通诊断。

连接检查失败的总览给出进入同一准确 Host 连接配置的动作，保留本次检查输入与原原因；不按错误文案猜处理路径，也不阻断原 Session。Native 能力按原适配器声明逐项呈现，说明来源读取时间与当前或保留的证据；声明不代签某个 Run 的状态或授权。当前协议六项能力均为必需声明，不制造“不支持”的虚构分支；没有来源则未确认。

同一准确 Host 的 Core 维护使用一个摘要与当前主动作，安装与升级不并列为重复的检查卡片。主阅读层区分当前部署、当前 App 携带的候选、原维护操作和本机连接采用；当前版本、候选版本、来源与读取时间各取准确部署／制品，缺失字段保持未知，不把源码哈希或协议号当版本。Core owner 协议与 Native Runtime 协议分别具名。观测不到 Core 不等于未安装，只有原首次安装 owner 确认资格后才呈现安装审查。原操作固定其原候选，不能用当前 App 候选补写历史事实；旧未决操作不遮掉安全可读的当前信息。

当前候选组装不可用时，明确说明该缺口，仍独立呈现可读取的当前部署和原维护操作，并允许沿原 operation 查询；不能虚构候选或把旧候选当成本次候选。原结果查询或明确重连失败时，在首层说明本次动作未确认并保留原回执和可继续动作，详细原因按需展开。

普通 Core-only 更新先呈现准确 Host、当前与目标部署及「仅重启 Core，保留原 Native、Session 和运行进程」的影响。用户明确点击 Update 即授权这一份候选与 expected，经原升级 API 执行，不再重复要求同一影响的 Review／Confirm。若这次意图需要补读 expected，只做原目标与候选的只读核对；输入或候选改变、资格未确认、原操作未决时不提交升级，新的检查结果留待用户明确操作，不暗换目标或重放原操作。检查发现需要替换 Native 时转入下文原具名审查与影响确认，不能沿 Core-only 意图直接执行。打开、切换或检查 Host 本身不部署；自动部署、服务托管、批量重启、远端清理和批量信任不因拓扑管理台而获得授权。

部署状态只由原升级 owner 判定的部署结果改变。本机连接配置的采用未确认，不能把已完成的部署改成 unknown，也不成为另一个已具资格候选升级的额外门禁；未知的原部署沿原 operation 查询。原操作查询不停止、不启动、不重新部署；复查确认原升级已完成时，只补记该 Host 上已核实、供下次重启使用的当前发行，并收尾该操作的临时启动覆盖，两者与升级成功时提交的事实一致。只有新 Core 与原 Run 都核实后才记录当前发行，失败或未确认的升级不改变它。准确资格、原 Runtime 与 Native 保全规则只见[远端恢复与维护合同](session-recovery.md#联邦-runtime-与远端恢复边界)。

重新连接并采用原成功部署是独立的明确动作，保留原 operationId，不再次部署。连接采用的已确认或未确认回执由 Main 按原 operationId 与目标配置持久保存；App 重启后沿用原事实，不重置为待确认，也不要求再次重连。

原操作记录按准确事实呈现：受理前被拒的请求在维护 owner 处没有原操作记录，查询得到无记录即按「未开始」呈现拒绝原因并恢复版本检查，不冒充结果未知；无法读取的单条维护记录只以其 operationId 标为来源与结果未知，不重放，也不遮掉当前部署观测或阻断其他 Host。主阅读层呈现原回执的当前阶段及更新时间，不推算百分比、已完成步骤或预计耗时。未知回执保留原 operation，详情优先提供原结果查询；刷新当前连接不能变成重做升级。

原 Core 由 systemd 用户服务管理时，维护以该服务的准确 unit、MainPID 和进程归属为依据，保全 Native 的停止方式须已确认。升级仍由原服务启动候选；新 owner 核实并提交当前发行指针之后，移除本操作具名的临时启动覆盖。原操作复查可以仅收尾该覆盖并刷新服务定义，不启动或停止服务、不重复部署；未知时保留原操作与具名文件供后续核对。

Linux x64 的已保存、尚未绑定 Runtime 身份的 SSH Host 经原探测确认目标前缀没有已安装 Core、目标 socket 没有正在服务的 owner 时，可由用户显式在 App 中首次安装：Install → Review → Confirm，Test、连接、打开设置与普通检查都不安装。资格只来自 SSH 上的只读探测：平台与 glibc 满足本 App 携带的 Linux 产物、目标前缀下没有已安装的 Core、目标 socket 上没有正在服务的 owner；任一事实未确认就不提供安装，已有正在服务的 Core 只给升级入口。审查列出目标机器探测结果、安装位置与常驻方式，常驻方式由用户在两者中选择：仅写入启动脚本、机器重启后沿该脚本重新启动；或另外写入用户级 systemd 服务，开机自启是否成立以该机器 linger 的真实状态说明，不替用户开启或修改系统级配置。安装复用升级的同一便携 Core 制品、发行目录布局与当前发行指针，另带固定版本与摘要的 Linux Node，以后同一 App 可直接升级。安装沿一个 operationId 执行，回执阶段如实呈现；未知只读复查，不重放、不清理半装内容。成功后以新 owner 的公共身份写回该 Host 的服务入口、socket 与 Runtime 绑定，再按原连接流程确认；写回或连接确认失败保留已完成安装的事实与可继续动作。

需要连同 Native 冷替换的升级在主阅读层单独具名，说明原因是现运行 Native 的协议早于本 App 候选所需，而非连接失败或 Agent 损坏。审查先列将结束的运行中进程数量及其 Session，再列保留的 Runtime 身份、Session、历史与状态副本；没有运行中进程时如实说明无进程结束。确认动作写明结束进程的后果，与普通升级的确认分开，确认只针对审查过的那一份清单和候选。完成回执说明结束的 Run 所属 Session 沿原恢复规则继续，并给出原恢复入口；维护操作本身不额外恢复 Session。资格、保全与确认边界只见[远端恢复与维护合同](session-recovery.md#联邦-runtime-与远端恢复边界)，维护 owner 的具体步骤如下：

- **替包前取得原事实。** 维护 owner 沿原 producer 自身的严格公共读取器取得 owner、Session／Run 与停止回执，只保留部署所需的有限事实；仅换 Core 时先确认实际 Native 的进程出生身份、可执行文件与原产物归属。维护所需的物理 Run 状态来自同一 Native 实例的准确 Run 查询，不依赖 Provider 状态、输出文案或原生历史读取；源码声明不冒充 serving 源码已验证。
- **冷替换资格只来自原 Native 的公开事实。** 资格只来自原 Native 的公开 Hello（协议代际、随状态目录持久的 Runtime ID、必需能力）与同一实例经其自带 SDK 的准确 Run 查询；Runtime ID 不随状态目录持久、候选代际不高于现运行版本或 Run 清单读取未确认时，不提供冷替换。
- **执行顺序。** 执行沿原 `operationId`：原 Core 确认退出后，才向准确原 Native 进程发送停止信号，并按出生身份确认其退出；新 Native 启动前保存原状态目录的完整副本，副本归属该操作，不自动清理；新 Core 在同一状态目录、socket 与命名空间启动新 Native。原 Native 退出后仍存活、已无 Native owner 的原 Run 进程如实列入回执，不由维护操作按旧 PID 发送信号。
- **失败与回退。** 新 Core 启动前的已确认失败，用原发行与原启动参数拉起原 Core，由它在未改动的状态目录上启动原 Native，并如实说明原运行中 Run 已结束；启动后的不确定结果只读复查，不重放、不自动回滚。回退到旧 Native 只能使用该副本，新 Native 写过的现库不交还旧版本。

来源信任沿本页[连接配置与测试](#连接配置与测试)及其引用的 A2A owner；节点选择、Test 或展示不代签批准。Phone / Devices 仍沿[设备接入合同](public-control.md#手机版-relay-连接)，不把“可信来源能创建 Agent”混写成“此设备有所有远端管理权限”。

安装资格探测与升级 owner 检查使用目标机固定的 `/usr/bin/python3`，标准库调用兼容 Python 3.6；不暗中换用另一解释器或修改宿主 Python。解释器或只读探测不可用时如实保留未确认，不能冒充平台不支持；取得 glibc 等事实后，仍按 App 携带的完整 Linux 制品判定资格，不能仅以 Node 自身的要求代签 Native 也可运行。

## 状态、失败与恢复

每个 Host 同时可能有连接配置、最后成功观察、本次读取结论、若干仍健康的 Session 和一个未决维护操作。管理台保持这些维度独立，只在首层提出最需要用户处理的一项结论，完整原因可下钻；不发明一个覆盖全部维度的红绿总状态。

- 完整权威读取确认的零集合可以显示为空；pending、未测试、连接失败、来源未取得或局部失败都不能变为空集合。
- 配置修改后，旧检查仍属于旧输入；未提交草稿、已保存配置、当前检查与已完成业务操作分别显示。迟到结果不能覆盖后选 Host、较新配置或另一 Runtime 的事实。
- 观察失败保留上次已确认信息、来源和时间，并持续说明缺失步骤与恢复动作；最后确认的旧值不能当作当前正常。单项失败不遮掉其他已确认事实。
- 身份不匹配时保留原 Host / Runtime 绑定、引用和工作面，不自动信任新服务；本次不满足身份或授权的操作按原合同拒绝，已确认可用的无关能力继续可用。
- 服务不可达、reader 失败、未知 Session、未释放 lease 与空快照不授权删除节点对应的持久工作面。Session 终局、恢复与移除资格只由[原恢复合同](session-recovery.md#联邦-runtime-与远端恢复边界)判定。

全局通知与重复提醒继续消费[现通知 owner](settings-and-observation.md#全局通知与底部状态入口)；本管理台不因轮询、重进页面或节点重绘新增一份告警账本。新增跨 Host 告警、订阅通知和历史事件中心仍是待安排建议。

## 管理台的完成形态

管理台位于原 Settings 的环境管理入口，拓扑和列表共用原 Host 选择与草稿，没有另一套管理页或配置 owner。核心路径为“看全貌 → 选择准确远端 → 查看真实工作与观测 → 打开原工作面或完成准确管理动作”。项目、Session、执行器、连接、来源核验与维护均回到原业务服务，不能只有一张可拖动的图；完成信号是用户无需猜机器、状态和作用范围即可到达原工作或完成原管理动作。

运行监控只读取选定的已保存 Host，沿原公共服务提供分源的语义 owner、Native 身份、诊断与 Run／Attachment／保留输出等资源事实。查看状态不冷启动 Native、不自动恢复 Session；当前连接缺失或某个来源读取失败时保留其他事实与原工作能力。观察仅随准确可见消费者存续，切对象、隐藏或取消后收敛，迟到结果不串用。

运行观察复用已有 Runtime 只读方法；网络观察由准确 Host 的公共查询组合本页规定的来源，并接到实际 CLI 与 GUI 消费者，不在 Renderer 另跑 shell 或猜测展示文案。Core 继续与 UI 无关。接口的精确签名与接线由[公共能力源码入口](../../specs/public-capabilities.md)持有；源与回执、权限、恢复及性能边界仍沿本文引用的原 owner，不新增兼容层、旧版实现、迁移或独立监控事实库。

## 后续能力与交付判据

源码已有的范围见上文[公共能力与当前实现基线](#公共能力与当前实现基线)。只展示已有结构化事实；新增 Host 观察确有必要时补到原公共 owner。CPU、内存、磁盘或链路质量只有在相应 owner 的测量合同和实际消费链完整后纳入，不以一张静态监控卡先占位。

有界历史、变化诊断和主动通知仍是候选，须先决定用户任务、来源、留存、缺测、成本与通知 owner；自动运维、部署编排和批量控制独立评审，不顺带进入。列出候选不构成排期或实施承诺，工作台也不新增持久画布偏好；这些未决问题不能反过来阻断现有连接、Agent 和原工作面。

实施验收至少覆盖多个独立 Host 和相同名称/路径、从未测试与已确认正常、检查失败但健康 Agent 仍可用、部分读取与真实零值、配置换代的迟到结果、身份不匹配、原维护回执未知、按准确 Session 导航及返回。图和列表的选择/信息应一致，窄窗、键盘与主题沿[Remote 呈现](../presentation/settings-and-observation.md#remote-管理拓扑)。网络观察另核当前解析配置与既有通道的区别、Owner 请求计时范围、接口来源、配置改代与局部失败，不能拿解析候选证明实际连接路径。涉及布局或生命周期时仍按原合同验证真实重启与原工作面；涉及采样验证消费者离开后停止及无关 Session 不放大成本。测试、变异、实际公共链路和视觉评审按各原规则执行，纯文档整理不制造这些通过结论。
