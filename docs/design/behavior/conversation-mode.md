本文是对话视图及共同阅读的产品需求 SSOT，定义同一 AgentSession 的当前／历史记录、作者与来源、消息和过程、资源、问题答复及阅读动作。Desktop、Mobile、Focus 与 Mailbox 复用相同的阅读语义；各宿主持有自己的可见性、阅读位置和明确操作。

## 产品对象与辨识边界

| 对象或事实 | 产品含义与边界 |
| --- | --- |
| Session、Run 与 Region | 阅读归原 Session；执行和展示身份沿[空间与恢复合同](spaces-and-layout.md#统一概念与空间寻址)，切换视图不另建运行。 |
| 原记录、内容 part 与事件 | 原记录保原文和引用；part 表达其内容位置；事件聚合已确认的同一逻辑事实。同一事件可以有多个准确来源，来源数不等于发言数。精确身份与 MECE 归[统一协议](../../specs/conversation-protocol.md#unified-timeline-and-mece)。 |
| 工具调用、运行观察与发言 | 同一次调用的多来源观察不等于多次执行，也不把所属父消息合成同一发言；详见[共同记录顺序](#共同过程与消息的记录顺序)。 |
| 问题、已记录答案与答复操作 | 已读答案是原生阅读事实；某次操作是否应用，只消费该操作的原回执，详见[异步问题](#原生异步问题与答复)和[同步原请求](#同步原请求与耐久答复回执)。 |

## 连续统一的对话列表

共同语义流是 Core 的基础能力：多个来源保留各自原记录，由同一 Core 边界形成事件、关系及版本，再供所有客户端消费。节点已经可读不表示内容已经结束；内容结束、身份与作者确认、输入投递、原生采用及来源覆盖分别由各自原事实确认。迟到证据可以丰富原事件或明确修订关系，不能因等待超时将未知升级为确定；读取失败不撤销健康 Agent 的既有能力。机器合同归[统一协议](../../specs/conversation-protocol.md#unified-timeline-and-mece)。

对话模式整体呈现为一个完整、连续的消息列表。当前与历史消息、用户输入、Agent 回复和过程在同一阅读流中接续，随滚动沿原来源动态加载；允许用分隔、额外标签和就地状态说明历史边界、来源与记录差异，这些说明仍属于同一列表，不另开一套聊天或要求先进入总详情才能看到最新消息。

对话视图是 Agent Conversation 统一 timeline 的接入方，须消费 Core merge 模块给出的同一事件身份、顺序、内容与来源；底层聚合和 MECE（不重复、不遗漏）的准确合同见[统一 timeline 协议](../../specs/conversation-protocol.md#unified-timeline-and-mece)。同一逻辑事件在主列表只有一个呈现位置，正文、过程、交互卡和状态按该事件的内容关系呈现，不因信号来源或组件数量被算成多次发言。视图负责分组、折叠、资源展示和阅读状态，不另行拼接或推断一套事件身份与归并规则；原记录详情与来源继续独立可达。

同一消息的发送与实际进入原生对话属于同一消息实体的不同阶段，原提交、投递和原生记录分别保有事实与回执。中间层依据准确关系统一为实体，输入摘要、Agent 卡片预览、对话及邮箱等消费方直接读取该实体及其贡献，不从单来源记录重新拼接消息。准确采用后到时，实体的阶段和记录可以丰富，不能因为主来源或原记录 ID 改变再增加一次发言；固定预览保原阅读版本时也不能把同实体的后到记录追加为新消息。未知或有歧义的关联仍保独立原文和明确未知，不能用相同正文或接近时刻代替身份。

同一 Core 事件的已确认贡献来源在主卡共同可辨，原来源记录与内容详情分别可达。具有准确采用关联且同一消息的原生正文已可读时，原生发言作为主正文，发送贡献聚合为同一主卡内的可展开摘要，不再另占一条发言或重复铺出正文。摘要保留原发送时刻及准确进入对话的事实，多次提交保留各自身份与状态；原发送时刻不冒充原生接纳时刻，正文已可读也不能把原操作失败或结果未知改成成功。原作者、渠道／设备、完整内容和原回执仍沿详情可达。

尚未由 Core 聚合为原生主消息的 captured 提交保持自身发送记录身份与原位置，不显示成已附着到某条原生消息的补充。正式正文可读前，发送记录默认显示紧凑正文预览；准确同一消息的正式正文已可读后，默认进一步收为一行辅助摘要，呈现细节归[共同阅读密度](../presentation/conversation-mode.md#共同阅读密度)。原生不可读、合法空、目标未读或仅 captured 可读时，原完整输入、资源、Copy、Info 与准确引用仍须就地展开可达；失败和未确认状态常显，缺正文不能冒充后态。显式定位、已有展开选择与选区优先于默认密度变化，后到准确关联不能强制收起已展开或正在阅读的内容。发送信箱的共同入口与生命周期归[输入与邮箱](conversation-input.md#统一发送信箱与原生采用)。来源标签只表达记录来源，不证明作者、物理输入渠道、投递或原生采用；原生对话不能冒称已认证的终端直输。跨来源关系未确认时，保留独立记录及准确来源，并明确关系未确认，不把来源记录数冒称确定的新发言或执行次数。工具 trace 的多来源说明只消费 Core 给出的准确内容部件及原调用关系，不把整个父消息的来源扩散到无关部件；相同工具名、正文、时间或裸调用 ID 不建立关联。

Provider 处理层屏蔽原生历史、回调和输入受据的厂商差异；Conversation 协议及 Core 统一读取／聚合层持有准确来源、跨页贡献与事件更新。对话视图、飞书及其他 conversation connector 消费同一结果，不解析 Hook、不另做原生与提交的匹配。增加一路来源只扩充其适配，不要求每个接入方增加与其他来源两两组合的规则。具体机器边界仅定义在[统一协议](../../specs/conversation-protocol.md#unified-timeline-and-mece)。

Desktop 当前、History、退休会话阅读、Mobile 和 Focus 采用同一 Core 事件解释。各自可以按准确范围选择阅读窗或事件类型，但不能另造 captured 消息区、再按时间插入另一来源或重判谁是发言者。原记录搜索、阅读点、批注和资源仍指原记录；事件归并后须能回到所属事件及准确原详情，不能使既有引用失效。

近期显示窗与持久历史留存分开。读取须明确已接受范围、还有更早记录、已到来源起点、旧前缀未知及来源失败；存在继续或恢复路径时就地可达。仅局部读取、某来源为空或另一来源有内容，都不能冒称全量。未确认的新来源和后到关联不替换已读正文、草稿或选区；后到关联沿原记录关系更新，折叠与选区保护仍由客户端持有。 已挂载窗口的只读定位沿[公共客户端观察](public-control.md#对话消费者的只读观察)，不以诊断请求触发读取或改变原阅读。

所有消息与过程统一使用共同组件及阅读交互。同类正文、资源、过程披露、复制、选择、焦点与展开行为只有一个实现 owner；来源适配和宿主容器只提供原事实及必要能力，不分叉消息组件、样式或交互。按需展开 reasoning、工具载荷、来源与机器诊断仍在所属记录内完成，不割裂主对话阅读。

对话阅读面的首次加载、已有内容与合法空态，均以该面自身已经接受的完整读取帧判定。父级输入摘要或另一阅读面的先到结果不能提前结束本面的首次加载，留下短暂空白后再出现正文。自身已接受合法空帧或已有正文后，正常观察切点校准、后台变化读取及保留帧恢复不得再替成全屏首次加载；保原内容、空态、阅读位置、选区与草稿，真实来源改变、读取失败及明确新读取仍按原准确事实披露和恢复，不把保留帧当作当前来源已确认。Terminal／对话切换保持同一 Session、Run 和原工作面。

对话首次读取失败且没有已加载正文时，在原阅读区域完整说明失败的读取步骤、仍未知的事实、原 Session 与草稿的保留，以及可执行的只读恢复动作；不能只留下重复 Retry 横条和空白。已有正文时保留原阅读与选区，将同一阅读面的多路读取故障集中披露；各来源的原原因、等待和准确重试仍可达，不按错误文案相同合并业务事实，不重发未知输入，也不因读取失败改变健康 Agent 的能力。群分享观察另归原 Binding，不能冒称分享已关闭或 Agent 已失效。

连续体验不等于一次加载全部历史，也不证明来源已经完整。读取保持有界，已加载范围、真实缺口、未知与失败如实表达；每个来源的原序、身份、作者和回执独立保留，不按正文或时间拼出假连续、猜关联或去重。滚动接续、返回当前与锚点保持的具体边界沿[同一 History 阅读面](#history-使用共同对话阅读面)。

观察绑定与诊断只保留其准确身份、释放所需令牌和有限元数据，不额外持有已被替换的完整正文帧。当前已读、待接纳和暂停保留帧仍由原阅读 owner 按各自用途保留；缩小观察的持有范围不能清空正在阅读的内容、改变原观察修订或重建 Session。

## 共同对话与原生记录

持久会话历史在原 Session 的工作面内阅读，来源与终端回放明确区分；进入与退出阅读不能重建终端、发送应用按键或改变 Run。向上读取更早页保留正在阅读的项目及其位置，每次读取有界且只有一项在途；失败保留已读内容和输入，并提供重试。消息正文、交错的图片／音频／资源引用按来源保留，无法预览的引用如实显示；没有记录的时间和状态不得补造。Core 提供与 Provider 无关的分页接口，Provider 持有原生读取协议；Desktop 不解析厂商文件、不维护第二份历史账本。

当前原生来源核对、已保存历史来源与同观察资源内临时可读来源的边界仅见[《Provider 能力对齐与移植边界》](agent-capabilities-and-messaging.md#provider-能力对齐与移植边界)。共同阅读面消费 Core 确认的来源；核对或保存失败保留已读正文、选区、草稿与可用输入并显示原服务窗，不自行猜当前源或混用旧游标。

共同 Reader 对原窗口的较早游标扩窗可明确请求 `preserveCurrent`：本次补读只有在不驱逐任何原已接受贡献、保留版本及实时头时才能提交。Core 按原记录、保留版本／位置及 canonical 事件组装的真实记录与字节成本，在驱逐、发布候选帧或提交前核对既有窗口预算；超界返回 `AGENT_CONVERSATION_WINDOW_FULL`，保原帧、版本、较早游标、来源关联及实时观察可继续，不截掉一部分记录冒称成功。此策略只适用于原较早扩窗及其同次续传，不用于开启最新、重放当前帧、锚点、单条记录或较新导航；续传与重试不能借另一个策略复用在途帧。它不扩大预算，也不禁用原显式历史导航；没有请求保留的明确阅读仍按原有界淘汰与返程合同继续。客户端拒绝呈现已推进的帧不能代替 Core 的事务保证，窗口边界也不等于来源失败或 Agent 失效。

### 稳定记录引用

Core 的纯 `ConversationItemRef` 引用原 `ConversationRef`（Host／AgentSession）及准确记录 source：native 保 providerId、nativeSessionId、recordId，captured 保原 recordId。它适用于原输入、回复和系统发言，不把回复伪装成用户输入，也不把 captured 与 native 的同裸 ID／正文合并。`conversationItemRef(record)` 在记录缺权威 Host 时返回 null；原正文、来源与未知时间仍可读，不以当前焦点补身份。该引用只指向原记录，不持有正文、Reader、空间位置、Run 或新的对话生命周期。

### 命名会话阅读点

人可以对当前真实原记录显式建立、改名、移除阅读点，并在同一会话的阅读入口列出和返回；名字由人填写，不根据模型摘要、正文相似、时间或运行阶段推断章节。阅读点仅持有自己的稳定身份、用户名称和原 `ConversationItemRef`，由 Core 持久元数据 owner 保存；不复制会话正文，不建立第二个 Reader、Run、会话生命周期或 Note 文件。重开阅读面与重启后保留原引用，移动 Tab／Region 不改变目标。

创建只使用当前确知的 Host／AgentSession／source／record identity；缺少权威身份时保持原文可读，说明该次保存为何无法确认。查询、命名与删除沿同一业务 owner 的公共 RPC／CLI，显式 operation identity 与 revision 保护重试和并发；请求失败或回执未知时保留原名称草稿和原操作，不把未确认显示为已保存，也不盲目创建另一阅读点。

返回复用同一原记录定位与有界历史读取。原记录尚未加载、来源变化、原 Host 暂不可用与确知缺失分别如实说明，保留阅读点和原引用；不按同裸 ID、正文、当前焦点、后来 Session 或新 Run 代替目标，也不为查看阅读点重启或发送输入。导航只随本次明确选择，较晚的输入、滚动、焦点与来源切换优先；名字变化和列表刷新不抢阅读位置。UI 仅在需要读取列表时订阅或查询，不因无关 Session 输出扩大后台工作。

### 共同阅读组件与完整原生内容

原生会话协议与记录解释只有对应 Provider 一个 owner；已经存在的读取／解析能力应被复用，缺少完整对话读取能力时明确说明，不能把用量统计或实时事件解析当作完整历史。历史与实时对话中的同类消息使用同一消息组件；说话人、正文、资源、链接、复制与未知元数据的呈现只定义一次。组件的不足在这个共同 owner 上改进，历史入口只持有读取窗口与阅读位置，不能另造一套消息渲染、身份或时间事实。改进仍保持上述原工作面、终端行为与健康 Run 约束。

同类消息展示与共同阅读行为只有一个 owner；已有组件复用须沿真实产品调用核验，不能以两个入口导入同名组件就宣称体验一致。Provider 负责身份、内容和事件的真实解释，面板负责呈现、选择、复制、展开、滚动与交互状态；原生数据修复不能替代面板缺陷的独立复现、修复和实际操作验收。实时输入／权限交互与原生历史分页各自持有数据和生命周期，不为复用引入第二份事实或把历史读取变成控制活跃 Run。健康输入、原阅读位置、同 Session／Run 与重启后的原工作面仍须保留。

共同 Conversation／History 的产品质量须达到成熟产品的可比较阅读水平。回答是主要阅读面，reasoning 和工具按需展开，姓名、真实时间、状态与动作清楚但不抢正文；仅 trace／资源记录保持紧凑与身份可辨。输入的用户默认外观与跨 Agent 来源统一遵守下文《共同对话的用户默认外观与协作来源》；本会话 Agent 回答在左侧，不把缺 speaker 的机器事件右移。reasoning 默认收起且不挂载重正文，展开沿共同 Markdown 和原链接规则，保原 parts 顺序、记录身份、空／遮蔽与复制边界，不造思考内容、完成或时长。

已经记录的原生 reasoning、工具与回答 parts 必须可从对话阅读入口按需读到，复用共同专用 trace 呈现，不把 Hook 摘要或仅 user 投影称为完整原生对话。原生内容与 captured 观察的来源明确可辨，记录身份与 parts 顺序保持，不能按正文或时间猜两者对应并去重；若只展示原生 trace 子集，须明确范围且完整原生记录仍可达，不能隐去回答后冒充完整会话。原生阅读复用同身份已经读取并提交的有界页，不能为显示思考记录再建立第二份正文缓存、Reader、计时器或读取事实；遮蔽或未记录内容如实说明，不生成思考文本。隐藏后停止新增页并废弃迟到，保同身份已呈现正文、Range、展开、滚动和草稿；换身份不带入旧内容，无关 Session 输出不扩大读取工作。两入口的键盘、选区、复制、链接及原展开选择均须实际操作验证；同内容、宽窄与关键阅读操作须按成熟产品的阅读品质做有限匹配独立评审，不足则返修，缺比较不算完成。

共同对话时间尺必须保其已声明可见交互面积；身份轴与时间尺共用坐标盒时，纵向布局不能把时间尺压为零高度。宽窄均能按实际事件键盘读取，看得到但不可focus不算可用。

### 来源、回复快照与作者说明

记录来源、内容角色、作者及关联是四个独立事实，共同阅读不得以一个笼统的 Hook／unknown 标签代替说明。

| 说明 | 产品含义 |
| --- | --- |
| 原生对话 | 由 Provider 从原生会话记录读取的消息或过程。 |
| CLI 事件回报 | CLI 通过事件回调或通知上报的内容；具体回调、通知及安装方式只沿原始事实确认。 |
| 回复快照 | 事件回报附带的回复文本，不单独代表一次新的 Agent 发言，也不证明它与某条原生消息相同。 |
| 作者未记录 | 回复快照的原记录缺少准确作者字段；该说明不代表正文缺失、回复失败或当前 Agent 失效。 |

回复快照的详情保原来源类型、已记录的事件名、记录引用及缺作者原因；事件名缺失就不补造。所属 Session、显示名、正文或回调来源不单独认证正文作者，已知作者也不能被来源说明覆盖。明确用户输入的既有展示默认与 Mailbox 记录身份仍沿[共同对话的用户默认外观与协作来源](#共同对话的用户默认外观与协作来源)。

同一回复的原生正文与事件快照沿 Provider 给出的准确原消息关系进入 Core 合并，只保一个主要正文位置，快照作为原来源贡献按需展开。原生主体、回合及消息身份须各自有依据；同一回合可能有多条进度与回答，不能仅凭回合、最后位置或相同正文建立同一消息关系。缺少准确关联的旧快照继续独立可达，使用紧凑观察摘要，不因当前窗口已有原生回答而删除，也不默认再铺出整段回答。后到准确关系保原引用、展开、选区与阅读位置，不能把用户正在读的原文强制收起。

主 Agent 回复、子 Agent 回报与协作投递分别表达。Provider 从原生机器记录解释实际主体及发送者、接收者，Core 保留这些准确来源；客户端不从工具名称、路径标签或正文回填作者。已记录的协作回报在原位置可直接看清谁向谁汇报以及内容，完整载荷按需读取，不能只留下不具名的回复快照或藏成普通工具 JSON。未记录作者或接收者时保持未知，子主体不借用父 Session 的作者身份；来源回报不单独证明另一次发言、投递成功或任务完成。

跨来源排序不完整只描述当前窗口的顺序覆盖，不能直接标为某条记录的关联未确认。准确的未读目标、部件版本缺口、关系冲突及其他 Core 诊断仍在原来源／记录详情可查；不因删除误导提示而吞掉真实缺口，不因改名生成作者或归并事实。

### 原生 Subagent 回报的阅读

原生 Subagent 回报在原对话位置保有自己的消息和来源身份，默认提供紧凑、可反复展开与收起的正文预览。缩略态能辨认准确原生发送者路径及已记录的接收者、时间；没有可读预览且没有待读资源时只保留身份与展开入口，可读性说明在展开后提供，不为每条回报另占一行空正文提示。待读资源仍保明确的按需读取入口，不能当成空消息。展开后沿共同 Markdown、资源与阅读动作呈现完整可读内容；按[共同过程与消息的记录顺序](#共同过程与消息的记录顺序)穿插的回报在过程收起时仍独立可见，不藏入普通工具过程，也不默认铺满长原始载荷。每条回报仍独立可定位、复制和查原记录，不按相同路径归并或删除。后到记录和来源更新保已有展开选择、选区、阅读位置、焦点与草稿，原消息引用和详情继续可达。

Subagent 以明确的类别标签和原生路径区分主体，不重复所在主 Agent 的头像。类别图标只表达原生回报种类，不能把主 Agent 的姓名、SID、项目资料或权限当成子主体身份。路径只消费 Provider 已解释的原生字段；缺失或含糊时如实说明，不解析显示名、正文或路径外观建立父子关系，不将原生路径作为 AgentMux Session、执行 cwd 或可操作地址。独立 AgentMux Session 的协作消息仍沿原已核作者与头像合同，不因被称作 subagent 改变身份归属。

可读正文、原生封装与不可读载荷分别呈现。Provider 只按其明确原生结构解释正文及加密／遮蔽事实，客户端消费同一公共内容投影；不能用 UI 正则、关键词或长字符串外观判断密文、补作者或替换正文。已确认的封装和不可读机器载荷不成为正文预览或默认展开的可读答案；只有不可读内容时说明原记录未提供可读正文，不虚构摘要、成功、失败或隐藏推理。混合记录保可读 parts 与原位置，未知结构保留其完整原文和未知说明，不能为美观丢弃唯一内容。完整原记录及原始复制沿既有详情保留；若提供仅复制可读正文的动作，须与复制原始记录明确区分，不混入已确认的不可读载荷，缩略摘要不替代原文复制。此调整复用同一 Provider、Core 记录与共同消息组件，不新增来源台账、身份查询或读取循环。

### 共同过程与消息的记录顺序

对话阅读完整保留各已读取来源中的用户输入与 Agent 回复；首条、后续输入、恢复和重连后的独立记录均可达。一个来源的合法空页或暂不可用，不得隐藏另一来源已经读取的原消息；时间尺或身份标记不能代替正文。原生与 captured 的已读消息、回复与过程在同一列表按可核对的记录位置穿插，不将所有原生记录和所有发送记录前后分成两块，使中途发言与已记录的回复／过程失去阅读接续。同来源原记录顺序优先；跨来源可比较的 recorded time 只用于表达记录时间上的相对位置，不冒充执行、接纳、请求与回复的关联或两源对应。缺跨源位置保原记录、来源与未知说明，不补 now／0。Timeline 同步出现缺口时沿原 owner 重取权威快照，不静默只留下第一条。

中途用户及独立 AgentMux Session 的协作输入须清楚可见，过程不能跨这些输入聚成一段；原生 Subagent 回报的持续外显编排沿下文单独约束。Provider 按原格式解释真实发言与模型上下文：有正式 canonical 用户事件的格式，只将该事件作为该次原生发言，上下文副本保留在过程或详情；不能因缺少格式依据就删掉唯一原文，也不能从正文或邻接猜对应。原 raw 身份和文件保留，修正投影后版本如实变化，旧锚点或资源不能暗中替换成新正文。Provider 同一原生页沿其真实记录顺序连续阅读，user 输入在该来源内分隔 assistant／思考／工具过程；缺时间、逆序时间和同正文不同 ID 不破坏记录顺序，不把所有原生思考另堆在会话末尾。同一原生 rawID 在当前阅读窗口只挂一次，正文、reasoning、工具和资源保持原 parts 顺序、展开与完整记录可达；窗口有界和较早 History 仍明确。captured 提交回执与 Hook 观察是另一来源，保持完整独立可达的记录层和真实失败／未确认状态，不按正文或时间猜原生对应、去重或执行因果。现 captured 已明确记录时间的输入仍分隔该观察层的连续步骤组，不能为统一界面吞掉它。共同阅读不另设 Reader、正文账本或消息缓存；hidden／History 覆盖与返回保持原记录节点、Range、展开、滚动和草稿，无关输出不扩大读取。

混合阅读不能仅因跨来源机器观察的插入位置不同，就把本应共同披露的执行过程切碎并全部摊在正文；真实中途发言仍清楚可见，原步骤在其所属位置完整可达。运行观察携带的回复快照须按原观察事实可辨，不冒充一次额外的 Agent 发言；这不确认其与任何原生记录的对应关系，也不以原生页存在与否判定观察已被覆盖；原记录与缺源时的正文保全继续遵守[同一 History 阅读面](#history-使用共同对话阅读面)。

仅作为观察的快照，以及 Provider 已明确标记为原生协作消息的 Subagent 回报，不必在其前后拆出新的过程条；共同过程沿准确原序保留这些持续外显记录。过程收起只隐藏真实过程步骤，快照与 Subagent 回报仍在原位置独立可见和可展开，同一原记录只呈现一次，不在过程内外复制正文。此编排不改变原消息角色、作者、来源、关系或状态，也不把外显回报计作工具步骤；仅显示标签或正文自称 Subagent 的记录不获得这一资格。已知的不同原生来源／回合、真实用户及独立 AgentMux Session 输入、公开进度、正式回答和准确阅读分界仍分隔过程，不跨这些边界收拢。没有相邻真实过程时，回报仍独立展示，不凭回报建立空过程；后到记录不为减少过程条数合并两个已挂载父容器，原节点、展开选择、Range、焦点与阅读位置沿原保持合同。连续同作者消息只压缩重复的身份装饰，各条原消息、具体时间、来源、复制和详情仍可独立辨认；不同进度说明不能因含义近似被当作同一事件删除。

所有已接入 Provider 的原生会话阅读须对照成熟项目已有实现核验覆盖范围。记录来源、身份、内容及资源顺序由对应 Provider 解释，client 通过同一公开接口阅读；参考实现已经支持的能力不能因未接线而被报告为不存在。确实缺少读取途径或格式依据的 Provider 必须单列缺口，不用未核验的解析结果或静默降级补齐能力清单。

### 原记录文件的本地下载

共同对话中的文件沿同一精确记录资源 reader 显式下载，默认不预取文件 bytes。分页包装经原完整内容读取确认文件种类后，仍以原 source、record、turn、part 和 outer reference 请求文件表示，不以解包后的 URI、路径或展示名称授权。已授权的本地读取与外发资格分开；未知名称保持未知，可使用明确的通用下载名，不猜原格式或原名。

下载只将原文件 bytes 交给浏览器保存，不预览或执行文件，没有保存回执时不称已保存。读取失败保留原引用和就地重试；隐藏、换来源、关闭或卸载后的迟到结果不触发新下载，不承诺取消已交给浏览器的下载。原正文、Copy、来源、选区、草稿与健康 Run 保持，不新增文件资源账本或另一个保存服务。呈现见[原记录文件](../presentation/conversation-mode.md#原记录文件)。

### 原文与阅读范围

Provider 专有的完整外层输入包装由对应 Provider 解释为阅读范围；公开记录只保留一份完整原文，并附原文中的有界正文范围，共同投影与阅读组件复用同一纯解释能力。默认阅读不暴露已识别包装，完整 Copy 仍取原始文本；未识别、引用／代码内、残缺包装保原文，不据包装升级作者、渠道或设备事实，不增加第二解析器、Reader 或账本。原生记录缺发送渠道／设备时显示“原生 - 未知来源”；既有提交记录中的渠道与设备须完整穿过共同投影。没有明确记录关联时，不按正文或时间把提交来源补给原生记录。

### 原生异步问题与答复

用户在问题卡选择或填写后，可以直接点击“发送答案”，不要求先复制、切到终端、粘贴并确认。选择、默认预选和编辑只修改答案草稿；只有明确发送才提交。同一卡片当前未答问题须全部选择或填写后，一次发送这一批答案；不能先锁定一部分而使其余题目无法作答。Provider 声明并解释自己的原生异步答复协议，Core 核对同一 Session、原生来源、Run 与原问题记录及 questionId，复用既有输入 owner 发送；客户端不编码厂商协议、不解析终端 footer、编号、选中位置或假定键位。历史异步问题的答复输入与当前原生阻塞请求的 callback 分属各自原合同，不能互相冒充资格或完成。

问题卡分别表达草稿、发送中、已提交、结果未确认与原生已记录答案。直接发送不另起 Run、不改变原执行身份或工作面，不把输入提交回执冒充 Agent 已采用或完成。准确回复通道不可用时保留草稿、诊断、重试或查看原终端的动作；局部回复失败不关闭正常消息输入、终端或健康 Agent。用户显式打开原终端时，沿原工作面和 caret owner 把键盘输入交接到同一可用终端，确认可见且非 inert 后再消费该次焦点请求；导航不自动填入答案或提交按键，迟到交接不得夺取后来选择的焦点。

原答案指向的题目未读时，阅读缺口须保留原答案版本与准确问题关系；只有同源原问题实际被接受后才收敛，跨窗口的已读进度可续接，同文异题或后来改写答案不能补签。旧记录缺少原目标证据时保持未确认。问题已有原生答案与某次答复操作已送达是两件事。同题记录，甚至相同答案，都不能把旧 operation 的 unknown 改为 confirmed 或清掉原诊断；该操作只沿自己的权威输入回执核对。题目仍可独立显示已记录的答案，旧操作与新编辑草稿分别保留。

Provider 已识别的结构化问题回复，共同消息投影与卡片直接消费其答案，默认正文不裸露回复协议的 XML／JSON。 原生问题卡的回答确认只消费同一 Session、Provider 与原生来源已读到的结构化回答及准确 questionId；正文窗口之外的同源已读回答也须使原问题显示已有回答，原页已经呈现的记录回答保持优先。确认不替换正文窗、重挂节点或清除选区，不新增读取、轮询或重发，不以提交成功、声明正文、Hook 状态或另一来源记录代替回答；已读事实缺席时保留未确认及原阅读入口，不改变 Core 输入／交互结算和投递回执。该回复记录携带的问题文字可按需展开，属于记录内的上下文，不认证原问题或当前待答状态；opaque 问题引用、作者、渠道、设备与记录身份不变。答案只替换首个原始文本的阅读位置，同条记录的其他文本、资源和过程保原顺序；没有原始文本或问题文字也必须显示已记录的答案。完整 Copy 仍取原 contentParts；没有结构化回复事实的普通、引用、残缺或未识别标签保原文。不新增客户端协议解析器、跨页问题缓存或正文／时间关联，原页字节预算与发送合同保持。

已经创建的结构化异步问题答复操作由宿主持有原完整输入意图：准确 Session／来源／问题记录、答案、operationId、执行 Host／Run 及首次提交条件。第一次提交前保全，卡片重挂载、界面重载或设备工作面重新读取不重建该意图，也不自动重放。回执未知时保原答案与原条件，明确重试只续接同一原操作；首次或后来一次调用的单阶段未输入回执，均不能证明原逻辑操作整次未输入。结果未知期间不以新正文另起操作；Core 确认同原逻辑操作、同 Run 的整次输入完全未应用后，可由用户明确建立新的答复意图；整次未应用的权威判据与终局性仅见[《跨重启的 Prompt 投递凭据》](agent-capabilities-and-messaging.md#跨重启的-prompt-投递凭据)，不从后次调用失败推断；已读原生确认不因负向回执降级。同源准确 questionId 的已读原生回答仍按上文独立确认。新编辑的答案草稿与原在途／未知答复分存并可恢复，编辑不替换原正文或授予发送许可；未确认仅约束这次答复的重试，不封闭草稿编辑、原会话阅读、终端或正常消息输入。

### 共同对话的用户默认外观与协作来源

共同 Conversation／History 中，明确输入但未记录作者的消息按用户外观显示：右侧 You、用户头像与用户色，不再显示 Input／作者未记录；这是普通对话的展示默认；Mailbox 的记录身份模式仍沿其[单对象详情合同](conversation-input.md#统一对话阅读与简明操作)保留 Author unknown。Core 的 unknown 作者事实、记录身份、来源和受信提交凭据保持原样，不据默认外观伪造人类来源或写回数据。无 speaker 的机器事件不套用用户默认。

共同聊天识别对象还包括 AgentMux 系统自己发的消息，尤其首次启动的运行时引导和 Topic 上下文。系统内容在真实组装／发送来源处明确归属，沿现持久消息记录保留，显示为 AgentMux 系统消息，不能套右侧 You 或某 Agent 的身份；混有系统说明与用户／其他 Agent 请求时，各确定来源段分别表达，原请求、身份和投递事实保持。用户未记录作者的显示默认不覆盖已核系统来源。正文信封、第一条位置、时间或入口不升级来源；没有原生记录与系统提交的精确关联，不把旧混合首条拆成新的来源事实、不按正文去重，不宣称 captured 系统记录即原生已接受。无 speaker 机器事件仍用其机器呈现。

AgentMux 自身通过 User message 提供内容的范围、包装与组合约束只见[《AgentMux 注入上下文》](agent-capabilities-and-messaging.md#agentmux-注入上下文)；本节只定义原记录的阅读表达。

### 完整前导声明上下文的同记录阅读

输入开头完整的 `<amux>…</amux>` 声明上下文可收拢，让随后原请求连续可读。完整且边界明确的前导声明可以折叠、随时展开并选择原文；连续的完整前导声明保持其原次序，同一记录的真实尾文完整可读。没有普通尾文时保留声明和记录，不补写用户请求或捏造一段用户话。第一段普通正文以后不再寻找并隐藏声明；引用、blockquote、fenced／inline／缩进代码、非前导样例、不完整或结构含糊的前导序列保持全文可读。

完整、位于输入起始的连续 `<amux>…</amux>` 上下文之后，紧接的 `<amux:a2a from="SID" msg-id="MID">` 完整信封沿同一 Core 阅读语法组合呈现。协议与正文／reminder 定界只由 [amux 格式合同](../../specs/amux-protocol.md#阅读与原文)持有。各上下文和信封分段保留原始 source span，来源仍明确为声明，原始 unknown／已知 Agent 作者不变且可信作者优先；正文的开头换行、尾部与完整 Copy 保原始内容。未完成、结构含糊、引用或代码中的声明保原文可读；完整独立的未知命名协议按下节通用卡片展示，不按启动用途、发起工具或特定 Provider 分支。

Desktop、Mobile、Mailbox 单对象详情及大文本／资源全文展开消费同一 Core parser 与共享 ConversationMessage，不能各写标签正则或只修终端显示。sender 原文与平台 reminder 分层可读，reminder 不抢占正文；有界预览沿原已核正文边界取摘要，不为找信封尾段读取整篇。历史原记录保持原 wire、身份与可读性，不因协议更新被改写、删除或重新投递。

这只是原记录内的阅读分层，不创建新的消息或来源事实；声明即使来自用户原文也只叫声明，不认证 System、Agent 或人类，不改变原 unknown 作者、source、record ID、time、parts 或 native／captured 关联。已明确的 producer systemContext 仍以其原事实表达，不从这层声明投影反推系统记录。整条 Copy 保持完整原 wire，缩进、空格、引用及各 parts 不因折叠或展开而改写；原正文节点、Range、阅读位置、展开和草稿保持，查看不发送、导航、切 focus 或控制 Run。隐藏和无关 Session 输出不增加读取，不新增消息／身份账本、第二 Reader 或独立 parser。 声明收起后的尾文分隔与普通段落排版只见密度文档[《消息布局与身份密度》](../presentation/conversation-mode.md#消息布局与身份密度)中的“声明尾文的连续排版”。

已核 Agent 身份与当前对话 Session 均存在且身份不同，才是本对话中的其他 Agent。其他 Agent 在右侧使用独立轻气泡与可读 Agent 来源标记，姓名和头像仍绑定真实发送者；本会话执行 Agent 的回复也采用气泡，仍在左侧，与右侧用户／其他 Agent 输入沿真实身份和方向区分。气泡不改变正文、parts 或作者事实，不能只靠颜色区分，也不能把本会话回答当作协作输入。当前会话缺席、作者未核或资料缺席时不按正文、名称、时间或本地入口猜出其他 Agent。事实判定与展示默认各有一个共同 owner，两入口同类消息复用，不另造消息或作者缓存。正文、Markdown、trace 与资源顺序、记录 id、复制、划线便签、展开与阅读位置保持；新增来源标记不发送、不控制 Run。

### Capsule 页面成果

对话卡支持明确的 Capsule 页面内嵌，格式、准确对象、按可见性读取、原生隔离、隐藏释放及 HITL 资格沿 [Capsule 对话卡合同](local-page-hosting.md#对话卡中的页面成果)。普通链接保持行内引用；完整 Copy、消息身份、作者、来源与阅读位置不因内嵌改变。共享组件通过 host adapter 呈现，不自行访问端口或执行 HTML；只读、文档、代码与没有 adapter 的 client 保原地址。

### 时间轴视觉关键帧

对话时间轴为含贴图、静态图表或 Capsule 页面画面的原消息提供小型缓存缩略图，帮助定位视觉成果。缩略图只是原记录的呈现观察；作者、时间、记录身份、选择与点击定位仍归原消息和时间尺，不从画面判断权限、完成或页面状态。聚类保原计数与逐条记录，不用某条画面代表整簇。

缓存仅消费同一阅读面已实际可见且已解码的画面，绑定准确 Session、来源、原记录及正文版本；页面导航、图像来源或原文变化使旧缓存失效。一次可见观察、新画面解码或离开时可更新小图；无关消息或记录数组刷新复用仍有效的小图，不重复绘制和编码同一观察。不逐帧抓取、不因时间轴滚动加载未读正文、读取隐藏页面、额外启动 Browser、重读资源或重算图表。缓存只随当前已读记录保留，不持有原 DOM、大图或媒体流；换会话与卸载释放。缺缓存、解码或缓存失败保原气泡，不阻断正文和原操作；缩略图不冒充完整历史、当前实时画面或持久成果。

### amux 协议的共同卡片阅读

完整独立的 `amux:名称` 协议使用通用声明卡片，让类型、参数、可读正文与完整原文可达；已知常用格式沿 Core 同一阅读结果显示专用卡片。精确语法、保留名和原内容边界唯一见 [amux 格式合同](../../specs/amux-protocol.md#通用命名协议与阅读目录)。未知类型的可读展示不表示产品支持其业务含义；已知格式校验失败不伪装成另一种有效协议。

只读协议展示资格独立于作者和输入 Markdown 风格；人类、未知作者、其他 Agent、本 Session Agent 与系统记录均可阅读同一种纯协议，真实作者和来源保持。普通首个原文本 part 与显式打开的完整文本资源消费同一 reader；不跨 part 拼接、不扫描内层 A2A body、问题回答或普通正文中的示例。未展开资源不为找协议额外取全文。

通用卡、专用卡及设置预览共用同一阅读组件，不另造客户端 parser。声明卡片的展开、复制与预览均不发送、取信、确认消费、接续或导航；已核 A2A 通知的原信读取仅沿下节的准确范围与原 owner，业务动作仍由原 owner 按准确对象与授权处理。平台说明内已转义的标记保普通说明文字，不为专用样式递归解释。

### A2A 引用通知中的原信阅读

原 Core 已确认的 A2A 通知在其原对话阅读面可见时，按该记录的准确 Host、收件 AgentSession 和原 MID 只读取得 Inbox 原文。已核其他 Agent 的原信直接作为右侧消息卡片显示，真实发送者、原时间与完整正文承担主阅读，不要求先展开系统记录；作者与当前 Session 的关系仍沿共同消息方向合同。同一通知位置的多封原信逐项呈现；读取等待、失败或缺失保原引用、原因和准确重读入口，其他可读原信继续呈现。没有准确 Host 或原信读取能力时明确说明缺失，不借当前执行位置补出来源，不用机器命令代替正文。

原通知仍属于 AgentMux，是与原信分别保存的输入事实；原信的作者、时间与正文消费 journal 回执，不从引用的 from 声明认证。通知身份、完整协议、投递事实及 native／captured 原贡献在同一阅读位置按需可查，原贡献详情保完整原文与 JSON，不再次铺出聊天卡或重复读取原信。准确来源定位与已有展开选择仍可达，不能以减少重复阅读为由删除原记录、改通知作者或按相同正文猜关联。读取核对原 MID、发送者和收件 Session，单项失败不阻断其余原信或健康输入。

原信卡片直接说明原发送／创建时间、本次通知的时间及模式，使较早来信在后来出现时可解释。每个时刻必须具名对应其阶段：原信创建、入箱、本次通知准备、输入接纳与模型采用不能互称“收到”；没有相应阶段记录就说明未记录或未确认，不用前轮完成、原生记录出现、查询或页面渲染时刻补造。通知事实绑定该对话记录的准确原通知与所引用 MID，同一原信后来被再次通知不能改写早先卡片的通知时间和模式。原信正文与可变的通知结果分别保留；一次较早读取不能永久冻结待确认状态，同源显式核对须可达，核对等待或失败保原正文、原消息身份和重读路径，不自动重发或增加全局轮询。原通知模式与原发送意图分别保留：默认策略不冒充发送方显式选择，后来的人工立即通知不改写原发送方式。详情可核对完整日期、时区、已记录阶段与原通知身份；只有同一准确原信／通知关系、可比较时钟及两端时间均已确认时才展示经过时长，不能把该时长冒称模型处理耗时。缺少历史字段仍可完整阅读、复制原信和查原记录，时间或模式未知不阻断健康输入。

引用原文沿既有 message.read 公共能力读取，不产生新消息、投递、通知、批次 ack、模型采用或接单；原通知完整 Copy 在通知详情中保持 wire，原信正文沿消息卡独立复制。已解码正文不再解释其中的协议示例。只有已核通知和准确阅读范围取得此读取资格；普通用户正文、未核声明、只读设置预览与未打开文本资源保持被动展示。只解释首个原文本 part 或显式展开的完整文本资源，不为寻找引用预读资源。隐藏阅读面不额外取信，切换 Host／Session／MID 或 reader 后的迟到结果不能配到新引用。Desktop、Mobile 与 Focus 的共同阅读消费同一通知资格与原信组件，不另造 parser、消息账本或输入动作。

### 共同对话的紧凑消息、复合头像与按需详情

共同 Conversation／History 的用户输入、其他 Agent 输入和本会话执行 Agent 回复保持原方向与真实身份；当前名字沿同一既有 Agent 命名优先级，不能用项目、Zone 或 Tab 名取代 Agent 名。两类已核 Agent 的正文头像以其真实关联项目为主体、同一 Agent 为角标；缺项目、当前资料未确认或作者未核时如实显示已知身份，不借收件人、活动项目或声明补出项目头像。头像与辅助归属表示当前已知资料，不冒充消息发生时的项目／Zone／Tab。原记录顺序、中途输入、正文、reasoning／工具／资源 parts、复制、Range、展开、阅读位置和回复草稿保持。

消息卡中的 Agent 身份同时显示可用名字、头像和准确 Session ID，ID 不能只藏在详情里，并提供独立的一键复制；名字为首要阅读信息，ID 是可复制的准确寻址，不能用项目、Zone 或 Tab 名替代。已有唯一命名来源为这个 ID 保存了明确名字时，即使当前没有活跃 Session，仍显示该名字；缺失的 Provider、项目、生命周期和 Goals 保持未知，不借当前收件人补齐。名称后来改变沿同一当前资料来源反映，不改变原记录或 ID。

完整消息头中的准确 Agent ID 可作为声明引用，复用共同解析和唯一现有身份资料查询来显示它所引用对象的当前名字及头像；卡片清楚保留声明性质，不能因查到对象就将 unknown 作者升级为已认证 Agent，更不能画成人类用户。没有资料时保留可用声明名与准确 ID；没有 ID 时不补造。可信作者与声明冲突时以原可信作者为准，原文和完整 Copy 保持。只处理当前有界已读记录中的准确引用并去重；不新增查询、登记册、正文缓存、逐卡观察或轮询，不为卡头预读完整资料或 Goals。复制 ID 沿原平台 Clipboard 结果显示成功或就地失败；它不改变整条消息复制内容，也不发送、导航、切焦点或控制 Run。

共同消息气泡与已接入的 Workflow 过程须一起形成更精致紧凑的连续阅读面；收紧后仍能分辨用户、其他 Agent、本会话回答与真实过程状态，完整正文、失败与进行中、全部原步骤、按需展开及原选区均保持。仅调整共同呈现，不改变记录、来源、读取与原交互 owner；密度方式只见[《消息布局与身份密度》](../presentation/conversation-mode.md#消息布局与身份密度)。

消息详情使用有可读名称的图标按钮，鼠标与键盘均可进入和关闭；来源、记录／提交身份、作者事实、声明与当前 Sender／Project／显式 Goals 各自清楚，缺资料如实说明。收起详情不读取完整发送者资料或 Goals；打开只读该精确发送者的当前已有资料，关闭与查看不导航、不切 focus、不控制 Session／Run、不改原 Copy 内容。项目图形、头像与姓名不会新增消息或身份账本，隐藏阅读面和无关 Session 输出不扩大资料、历史读取或更新。紧凑度与控件视觉只见密度文档[《消息布局与身份密度》](../presentation/conversation-mode.md#消息布局与身份密度)。

共同输入卡的可读来源声明沿本页[《完整前导声明上下文的同记录阅读》](#完整前导声明上下文的同记录阅读)及唯一 Core parser 呈现；旧方括号来源头不再具有专门解析分支，历史原文仍完整可读与复制。完整新信封中的准确 Session ID 可以查询现有公开资料，查询所得明确称“按声明查询的当前资料”，不补造历史身份。未匹配或未知的声明不获得导航权；可信作者优先，标题、名称、正文或当前资料匹配均不升级为认证作者或投递事实。

完整、位于消息起始且边界明确的既有包装可成为轻量声明信息，正文按原语义阅读；未识别、不完整、嵌套未知结构或代码／引用中的相同标记保原文，不扫描正文猜包装。包内 name/type/time 只作声明，不认证作者、不升级权限，不替换原 recorded time 或表示送达；可信作者仍优先。原引用归因和内容保持，完整 Copy 仍为原始 wire 字节；包装处理复用唯一纯消息解析能力，Native user 与 captured 两入口同等采用，不引 UI／Node 依赖或第二 parser／身份账本。

输入卡区分“Provider 原生输入”及其 Provider 与“AgentMux 提交记录”，但来源不证明物理发送渠道，渠道未记录时如实说明，不能把所有原生输入叫作 Terminal。来源资料按用户显式查看才读取，关闭不新增读取；复用现项目图标、名称、Session 与目标事实，不增加第二注册表。可信引用或已匹配精确 ID 可以查看当前项目、标题与明确关联的主要目标，过去标题、历史项目或当时目标缺记录就未知，不把当前资料冒充当时。主要目标只来自已有显式 Session 关联；Session 创建时刻只叫生命周期开始，终止只用明确退休时刻，不用最近更新时间冒充结束。资料与来源动作保原选区、阅读位置和草稿，不触发消息投递或 Run 控制。

### Activity 记录时间的直接阅读

记录时间行内读具体起止，悬停与键盘详情读相对原点的偏移。Activity 单条机器事件直接显示已记录的具体时刻；步骤组保本组首条创建时刻至本组最大更新时间的记录范围和步骤数，紧凑过程的时间说明按需可读；具体呈现见[过程密度](../presentation/conversation-mode.md#可复用对话与-workflow-组件密度)。该范围只描述这些记录，不能称为 Session／进程的运行起止或完成事实；原步骤仍在进行的状态保持，不把最近更新冒充完成。相对已有原点的偏移进入悬停与键盘可读的时间说明；同日简短，跨日显示日期，不让相同钟表时间掩盖相隔日期。无时间事实如实未知，不补 now／0；原 ruler 时间／序数退化、原分组和折叠行为不变，不新增计时器、读取或时间事实。

### 用户消息从 Provider 原生会话取得

User Messages、Focus 时间轴和对话模式都须包含 Provider 原生会话已经记录的用户输入，覆盖 Terminal、Message Tool 及其他实际发送入口。原生会话中的用户输入不因发送入口或目标 Agent 不同而遗漏；内容与记录身份由对应 Provider 解释，三个表面消费同一公开 Core 事实，各自归属正确的 Session／Context，不把一条消息复制到不相关 Agent。Message Tool 的待发送、投递中与未确认记录继续如实可达，投递回执不冒充 Provider 已接收的会话消息。

同一原生记录重复读取只出现一次；同正文的不同输入仍是不同消息。同一次提交后来成为原生记录时，只有可核实的关联事实才合并其会话呈现与投递说明，不能靠相同正文、接近时间或终端回显猜对应关系。无法确认关联时明确区分已存在的原生消息和仍待核实的投递，不重发、不吞记录，也不把两份观察都宣称为已接受消息。原生 user 角色、内容来源、发送入口与作者身份分别表达；已知 Agent 作者仍按 Agent 归属，缺作者时原始作者事实仍保留 unknown；共同聊天的用户默认外观见《共同对话的用户默认外观与协作来源》，不将显示默认写回作者事实。缺少原生发生时间的消息仍可读，但不捏造 Focus 上的时间位置。缺原生身份、读取能力或服务暂不可达时保留已读消息、草稿、原工作面和健康输入，用既有服务窗说明缺口，不把“只有 Message Tool 记录”宣称为完整消息历史。

消息来源的更新与阅读有界，工作量只随真正相关的 Session、消费者与新事实增长；无关 Session 输出不能触发其他 Agent 的原生历史重读。 Terminal 直接输入也沿同一公开来源与共同消息事实进入对话、History 和 Focus；已读窗口不能一直停在首次读取而静默漏掉新输入。来源更新只基于已核相关原生事实或用户显式阅读，缺更新事实就说明当前窗口与刷新入口，不由任意输出、正文或时间猜新输入。Provider 已明确的 user 记录不因作者 unknown 或来自 Terminal 而丢弃；没有物理渠道事实仍只叫原生输入。已有明确提交凭据与原生记录只有精确关联才整合说明，重复正文不能当关联；读取范围之外或缺时间的输入仍明确可达，不捏造时间轴位置。收起、隐藏、切换 Context 与重启后的重新阅读保持同一记录身份、已知关联、原阅读位置及 Tab／Region／Session 恢复约束，不建第二份厂商解析、持久消息账本或 Runtime。终端连续阅读与输入性能仍按[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)验收。 对话原生输入是已读的有界窗口；正在读取、失败与仍有较早原生记录须就地可辨，不能把最近窗口没有输入画成整个会话没有输入。较早记录沿同一 Session、同一 Region 的已有 History 显式可达，按原游标继续阅读；游标不保证较早页有用户消息，失败可就地重试原读取。打开和返回保原正文、选区、阅读位置、草稿与健康输入，回到仍有效的原触发控件；读取说明与重试不重发消息、不控制 Run，不新增第二份历史或无界读取。

Focus 的最新记录入口停用且不交付结果时，不因同会话实时更新重复投影无人消费的记录；原阅读 owner 与已读窗口保持，重新启用按当前准确来源与身份追上最新事实。历史阅读期间保留原生快照和正在阅读的正文、选区与草稿，captured 已接收事实仍按原规则交付。已接受原生页或 captured 快照的空投影也交给同一轨道消费，不能丢成未读后重复投影；只有工作事实的分区不冒充已读对话，工作条带、在场与计数继续更新。

首次打开或显式刷新对话时，不能只因最近一页均为工具／活动就遗漏仍在既有有界阅读范围内的真实用户输入；已核原生来源发生相关变化后，新输入继续沿同一公开来源与共同消息组件可读。达到阅读边界仍未取得输入时，如实说明当前范围与较早记录入口，不能声称整个会话没有用户消息，也不能为寻找输入无界扫描、另建解析／缓存或干扰健康 Agent。原记录身份、parts 顺序、unknown 作者／时间、已有窗口与草稿保持。

健康原生 writer 保持记录文件打开时，已经落盘的相关新增记录也必须沿同一公开来源发出变化通知，不能依赖 writer 关闭文件才更新，也不能把观察注册成功当成后续变化已可观察。来源绑定失效或观察明确不可用时沿既有服务窗如实说明，保留旧窗与健康输入；更新后的阅读仍服从本节已有预算、原记录身份、选区保持、冻结与显式继续读取约束。

### 明确手动消息作者

Focus 时间轴须明确区分人类、其他 Agent 与未知作者。作者只消费明确事实：第一方 Message Tool 在手动提交或手动排队、首次创建消息意图时记录人类来源，沿原有队列、投递与 Core 回执保留，公共消息作者统一表达为人类、已核 Agent 或未知；已存在的 Agent 作者事实继续保留。共享发送函数、队列消费、控制命令、自动继续以及未归因本地 CLI 入口都不能凭缺少 Agent 字段变成人类；受信 Renderer 本身也不证明某条消息由人类发起。重试或重启后执行旧意图不改变原作者，未知记录保持未知，冲突声明不得升级成人类。原生 user 角色不等于人类，未核原生作者与未核投递关联仍按上述未知和分层规则表达，不从正文、时间或终端回显猜归属。Focus、User Messages 与共同对话呈现采用同一公开作者事实，Agent 标记、发送者导航、投递状态与已有阅读状态保持；作者事实暂缺不重发消息、不阻断健康输入，不增第二份账本。

Focus 时间轴标记、输入列表与消息来源说明表达原作者事实；固定阅读复用的共同正文外观沿《共同对话的用户默认外观与协作来源》。未知作者的正文默认外观不升级原记录、不改标记和来源说明，也不产生发送者导航或执行关联。

Focus 的固定消息正文也遵守《共同对话的紧凑消息、复合头像与按需详情》：原记录的来源、精确收件 Session 和共同说话人资料在正文中保持一致，已核其他 Agent 的方向、当前项目头像与按需详情不能因入口不同而丢失。来源详情仍可核未知作者的原生记录；只在明确打开详情时读取该精确发送者的当前资料及显式关联 Goals，轻量 hover 和收起状态不作完整资料读取。当前资料不冒充消息发生时的项目或发送 Run，未知项目不从收件人、活动项目或声明补出；既有 Sender Context、返回与未知 Run 说明保留。

### 共享消息投影的客户端边界

User Messages、Focus 时间轴、历史与对话模式在浏览器运行的客户端须消费 Core 公开、无 Node 运行时依赖的同一纯消息投影，正式生产构建可加载并呈现非空消息；消息的读取、进程与存储职责仍归原 owner。消费纯消息事实不能将文件、进程或 Runtime 依赖带入 Renderer，不能靠宿主 shim、别名、fallback 或复制投影修补接入；记录身份、作者、时间、来源与投递边界继续服从上述全来源消息合同。

Focus 的旧窗覆盖、显式继续、隐藏与正文预算由[Focus 有界消息阅读](focus-context.md#共同消息的有界阅读)定义；它消费上述同一公开来源与共同正文，不把局部窗口当完整会话。

Provider 的会话分析、对话模式与 trace 必须沿原生协议闭合到真实产品调用；内容顺序、主会话身份、恢复、长对话阅读和资源边界分别有真实验证。原生事件的同名不等于同义：依赖负载才能区分的收尾、取消、普通通知与子主体必须由 Provider 声明真实语义，不能把所有通知画成工作中，也不能让子主体覆盖主 Session。未知原生元数据如实缺席；不能靠猜测别名、默认成功、最近文件或额外运行时补齐。成熟度与竞品优越性是验收目标，只有绑定实际版本、同等任务与数据的比较证据才能报告为结论。

## History 使用共同对话阅读面

观察失败按准确来源与本次观察资源表达。另一来源的正常变化不能清除该失败，也不能证明原失败观察已经恢复。原 Retry 保留当前接受窗及其准确来源；只有观察失败时重接该窗，不改成无来源选择的最新读取。原历史锚点与版本保持不变。替换观察先取得并核对同范围的新观察，再释放旧观察；新观察仍不可用时保留原可用观察、正文及失败说明，不关闭健康 Agent 或其他来源的阅读能力。

读取失败时，“重试原读取”与“读取当前记录”是两个明确动作。前者保留该次操作、游标或 checkpoint，不能暗中改成 latest；后者由用户主动取得同一准确 Host／Session 的当前窗，即使旧窗仍位于尾部也可达。新窗仍经过原来源校验、选区、焦点与阅读保护；成功前保留原可读内容与失败说明。来源变化不引发自动换源、重放或后台轮询，也不取消健康输入与 Run。

显示窗中的正文版本、来源覆盖、历史状态与导航事实构成同一次阅读事务。选区保护延后替换时，这些显示事实一同保留；待呈现窗保其原操作与来源选择，解除保护后仍按该操作重新判定，不能统一冒作实时变化。选区判定与解除通知须归正文实际所在的 document；清除该选区后，即使已经停止跟随，也须重新判定原待呈现窗，不等待其他窗口的事件或强制回到最新。隐藏、宿主 document 更换或卸载时释放原监听，保留原阅读与输入。宿主在首次准入时固定显式 Earlier、Current 与自动覆盖等阅读意图；重放待呈现窗复用该意图，未形成新完整窗的失败导航不得覆盖它。各来源的阅读保护通过后，才推进跟随、锚点与历史占位等显示记账。本次准确读取失败仍沿既有服务窗立即披露，不因旧显示帧健康或选区保护而隐藏。准确原 ID 不变而正文版本变化同样须保护所选正文；版本只用于本地阅读替换判定，不认证消息关联或业务完成。新显式导航可以取代相关待呈现事务，但不得让迟到结果覆盖已接受的新选择。

首屏和仍在跟随当前尾部的阅读位置须持续显示同一准确来源的新记录与流式更新；程序性定位、锚点复位、视口／布局变化和历史预读本身不能冒充用户离开当前阅读，也不能关闭仍保留当前首页的实时尾部接入。是否仍包含当前来源首页沿原实际分页位置判定，与是否自动滚到底部分开；用户明确向上阅读后保原位置、正文节点、展开与选区，新记录不抢滚动。同源实时页与本地当前窗没有连续重叠时，仍沿原跟随意图停在最新尾部的用户不必反复点击“Show latest messages”：可见、同一 Session／source／binding、当前首页仍在窗且本阅读面没有非折叠选区时，沿唯一有界读取自动接回最新；这项许可不能只凭接近底部的几何推断，向上阅读与先前来源仍保原位置。自动读取因隐藏中止后，回到原尾部可恢复一次。读取失败保有其准确原操作与来源边界；补读较早时间范围达到本地有界窗口限制，只表示该范围尚未覆盖，不能因此关闭仍满足原许可的同源当前尾部接入。真实当前读取或来源校验失败仍保原窗和非阻塞原因／显式重试，不因普通重绘或无关变化反复尝试。阅读位置或选区保护仅延后本次窗口替换，独立于来源读取失败；相关选区解除或用户主动回到原尾部后，仍满足同一当前来源与跟随条件时可自动续接一次，不能被已解除的保护永久锁住。保留旧窗与选区期间不重复读页，真实失败仍由明确重试恢复。已裁出当前首页或用户正在阅读／选择原序无法连续接入的窗时保原内容，明确回到当前可达，不补造新消息数量。先前执行来源的窗口只读保留，不与当前执行来源混接；查看先前来源和回到当前来源均以明确动作和原 source／binding fence 区分，不能把换来源含糊标成普通较早阅读。

临时阅读窗回收与原来源变化分别处理。重新显示当前阅读面时，Core 若明确确认仅原临时窗已过期，可沿原准确来源重建一次有界当前窗；新窗完整来源范围校验通过后仍由原阅读位置和选区保护决定是否替换，不能借此切换原生来源、扩大 captured 范围或改变 Session／Run。历史窗与固定原版本不自动跳到最新，保原显示及明确的读取当前记录动作。真实来源变化、未知或重建失败继续保原内容和可达服务动作，不把同一个失效游标反复称为重试，也不新增后台轮询。

历史窗口末尾须就地提供返回当前尾部的定位动作，复用原当前页与选择保护；同一准确 Session／原生来源的已确认当前记录更新或窗口截断时，清楚提示当前记录仍可达。动作表达返回当前原线程尾部的阅读定位，正常新记录的观察、读取与接入不以按钮出现或点击为前置；最新窗尚未读入时仍沿原有界读取取得准确当前窗。同一已加载当前窗的入口显隐须核对完成布局后的实际阅读位置，与是否继续跟随的意图分开；实际已到尾部且没有待呈现内容时，先前离尾标记或暂停跟随本身不构成继续显示入口的理由。这个位置判断只约束定位入口，不修改跟随意图、不授予自动读取，也不取消历史窗、阅读保护及确有较新记录尚未呈现时的原返回／继续动作。更新不强行跳走历史正文、展开、选区或阅读锚点，不以缺当前记录、foreign 来源或未知状态猜新消息，也不补造消息数量。明确回到当前时沿原 generation fence 废弃被取代的更早读取，迟到结果不得覆盖已回到的当前窗口；隐藏时仍保原记录并停止读取。

Activity 是当前与较早会话记录的唯一阅读面；缺失的读取或交互能力在该面扩展，不额外提供 SessionHistoryView 或改名后的独立历史 Page。消息、过程、同步／异步问题、来源、头像、资源、批注与回复操作沿同一共同呈现；当前与较早记录只在同一线程的准确分界添加“以上是历史消息 (<时间>)”分割线；分界沿向前阅读前实际已呈现的同源原生窗首条原序记录身份冻结，原读取真正到达该身份后才呈现，并保原当前过程组、正文节点、展开与选区。缺少原当前锚点、来源不同或尚未到达时不猜分界；较新侧已移出局部窗口时不在旧窗末尾画暗示下方有正文的分割线；明确较新记录可继续向下读取，并保原返回当前入口。分界时间只取较早侧最后一条真实记录，缺失明确未记录，不把保留的当前正文或整段已加载冒为历史。

原生记录与 captured 记录在同一阅读面保持准确来源，可读用户正文、Agent 回复和过程不因来自 captured 而被藏进“投递与运行详情”一类总折叠。同类消息与过程消费共同呈现组件及一致的阅读层级；提交、投递、原生采用和运行观察分别表达原事实，机器回执及诊断沿所属原记录按需可达，不将未确认提交冒充 Agent 已接纳。没有准确关联时保两种原记录及来源，不能按正文、时间或裸 ID 猜关联删除，也不为统一外观伪造原生记录、状态或因果。回到最新与实时跟随须能到达当前实际可读消息的尾部；机器详情高度、展开或辅助滚动不能代替原生较早／较新分页边缘。主动阅读正文或过程详情保原锚点，不因另一来源更新推走；原生缺失或读取失败时仍可阅读、复制原 captured 正文及其真实失败／未确认说明。

一次 Earlier 读取包含请求等待、合法前缀逐页提交和后续布局稳定；在这些阶段中，仍存在的原可见正文与屏幕偏移持续保持，不能先跳走再在批次末尾拉回冒充稳定。用户选区、展开、焦点和草稿沿同一原记录保留；程序锚点恢复与浏览器布局响应不相互放大，也不由中途跳动触发另一批读取。

原唯一公开读取保有界页、opaque游标、来源／身份与分页锚点；在当前对话窗口向上阅读至共同对话原序的实际较早边缘且原来源还有更早游标时，沿同一读取 owner 加载更早记录，不要求先点 Earlier、切换历史状态或打开另一页。读取边缘属于共同记录流，不要求其中必须出现原生记录，也不由展开的机器详情或辅助滚动高度代替。

普通对话和 Header 历史入口先显示首个已核合法页，再异步沿同源原序页尽量补足所选时间范围，默认以最新已载真实原生时间为端点覆盖二十四小时。首次读取及时间范围补读每批最多顺序读取三页、每页显式最多一百条；主动阅读的方向性补足沿下方独立约束。初次批次包含首个合法当前页及最多两次较早页读取；明确扩大时间范围时，从已呈现窗开启一次最多三页的补读批次。一次原页操作的传输分片不另计页；范围、EOF、来源失败或阅读保护可以提早结束批次。批次结束后，实时变化、重绘或无关更新不重新开启它；原 Earlier 仍可沿原游标明确继续。剩余记录预算不足一页时只请求剩余数量并保留真实 limit；每个已核合法页先提交，后续慢页或失败不得撤走合法前缀。范围扩大从已呈现窗的较早游标追加，不重新读无游标首页、不裁掉当前正文或制造历史分界；缩小停止尚未发出的补页，保原已读记录。实际已载原生时间跨度达到目标、真实 EOF 或原记录／字节预算即停止；达到预算保原窗、覆盖事实与继续阅读入口，不冒完整时段，也不将正常有界终点当成读取失败；实际自动补读失败沿原较早入口说明原因并重试。原生时间全部缺失时保最多三页初窗和序数呈现，不借提交／观察时间猜原生覆盖；用户显式选全部时间可沿原游标继续有界补读。首次与时间范围补读需求仅来自首次读取、明确回到当前或时间范围选择；主动回翻的方向性补足另见下方渐进加载约束。正常重绘、无关数据和流式更新不复活已完成、取消或失败的需求。用户原向前／向后导航可取代在途后台补读；隐藏／换来源／换会话废弃迟到，并保原页及明确继续动作。局部导航消费同一个 Core 有界读取窗；原记录数量、序列化字节、页快照与组装上限只由[统一读取协议](../../specs/conversation-protocol.md#unified-reading-and-changes)定义，不在客户端另设一份语义窗口预算。预算包含固定首个快照页、可见正文与必要的不透明游标位置索引；同一原记录的不同已保留版本分别计费，同一对象不重复持有或计费。位置索引只记实际访问页的原 input cursor、limit 与原序边界；向下沿原游标直接重读相邻已访问页，核对 Session、source 与 raw 范围，不解码游标、不从最新页全量扫描，也不把无游标重读到的新尾当作原快照首页。进入历史阅读时固定的首快照含当时实际已看见的连续实时追加，不只是最初读入的百条；返程必须能找回这些已呈现记录。无游标首页保原已读取快照对象，返程不以新尾冒充原快照；这不增加 Reader、观察者或另一消息账本。正常当前阅读仍消费原共享观察的新消息与流式更新；持续追加需更新当前阅读窗时沿原有界分页读取，保原选区和阅读位置，失败保原窗与显式重试，不随每次流式更新反复重试，也不让固定当前快照耗尽历史滑动空间。连续原序没有重叠时保正在阅读或选中的窗，明确较新记录可返回当前，不拼接稀疏上下文伪装连续。

向上或向下接近对应边缘前一至两个视口即按真实阅读方向加载，触控板、键盘、滚动条与触摸阅读采用同一边缘行为，单次在途合并需求。边缘进出与主动阅读共同控制触发；单批内的继续补页沿下方方向性需求，批次结束后下一次真实同向阅读仍可继续，不要求先反向离开边缘才能解锁。程序定位、锚点复位、布局变化或内容追加不能独立发起读页，也不能在两边反复读取；每批只提交已核原序记录；读取期间在当前对话区域内提供持续可辨且非阻塞的真实等待反馈；反馈不改变已有消息、时间尺、输入区的位置或可用阅读高度，不抢焦点或拦截正文选择，具体呈现只见[共同阅读密度](../presentation/conversation-mode.md#共同阅读密度)。原较早／返回当前／Return／恢复动作在同一阅读面可达，不另设顶部历史工具栏；初次空窗同样可见，原错误与显式重试保持。时间尺的记录数量只表达已加载范围，不推断读取完成比例；未加载边缘只表示当前不透明游标后还有较早原序记录，不补历史起点、总量或时间比例，查看说明不读页，显式入口复用原继续读取。无更早游标即停止，失败保留正文、游标、选区和阅读锚点，并在原面给出可查原因与显式重试，不自动反复读取。

各展示位置只持必要的局部阅读窗口与位置，某一位置翻到过去不能改变 Focus、Mailbox 或另一位置的最近消息。当前与较早记录的切换、继续、返回保持同一会话的原Terminal实例、Session／Run、已保留正文节点、草稿、展开、选区与锚点；不能因窗口淘汰移除正在阅读或选中的记录；向上裁掉的较新页必须可沿向下滚动连续恢复，向下裁掉的较早页同理。达到实际记录或字节预算时保当前窗与返程定位，明确原因，不丢掉返程指针后假装仍可连续导航。隐藏暂停本位置新增页并废弃迟到，不清已读正文；来源变化留原窗，显式刷新才替换。明确回到最新只呈现该来源的最新连续原序；窗外保留的单侧输入不追加到主线程末尾冒成较新记录。较早完整记录沿原 Earlier 继续可读，较新缺口沿原 Current／Retry 取得；已读上下文、原输入历史与问题答复事实保持。无原生页或读取失败时保原可读内容，不因切窗清除选区或草稿。待恢复／退役记录沿权威Session读引用可读，不依赖Run或恢复、不创造第二身份／消息账本。Header入口、Return/Escape和原有效触发控件沿同一工作面，晚主动焦点优先；有合法读取能力的Activity位置不被引导到另一History界面。此结果不替代[真实活跃 Terminal 连续向上阅读 P0](terminal-reading.md#terminal-连续向上阅读历史)。

### 连续回翻的渐进加载

长对话的连续阅读同时保护数据接续与界面响应。首次合法内容先可读；用户主动向前／向后阅读或明确选择 Earlier／Newer，形成一份属于原 Host／Session／来源和方向的有限需求，接近边缘时提前准备相邻内容。一批合法页提交后，若原需求仍有效且前方可读储备不足，可沿同一游标继续补足，不要求每一页都等新的滚动事件。方向性补足以实际可读储备决定是否继续，不套用首次读取及时间范围补读的固定页数；每次补足仍须具有有限的相关读取工作量，并遵守 Core 原页、窗口与字节预算。达到储备、EOF、保护、真实预算或失败即结束本次补足；已提交合法内容保持可读，后续真实同向阅读仍可继续。几何不足、流式追加或重绘不能自行重置工作额度，也不能因为过程折叠得很短便不断遍历全部历史。

正常连续回翻以滚动自动接续，Earlier 保留为显式继续和原失败恢复入口，不成为每一段历史必经的操作。可读储备依据真实已载内容及当前阅读方向判断，以足够连续向前阅读数屏为补足目标；原记录条数、已读页数和时间跨度不代签可读屏数，折叠过程中的多条记录也不能冒充已准备多屏内容。共同流中的准确原记录及阅读锚点都可承接该需求，不要求当前可见内容必须含某一来源的记录。提前量可依据阅读速度及原读取耗时调整，但不增加用户必须配置的性能旋钮，也不从屏高推断历史总量或来源完整性。反向阅读、回到当前、隐藏、切来源和 Session 变化取代或取消原需求，迟到页不改变新位置；错误保原内容与明确重试，不能自动重试至成功。预取不能淘汰正在读或选择的原页，达到真实预算只停止本次补足，原明确导航与健康输入继续可用。有限局部窗口不能变成完整历史的不可越过终点；用户继续同向阅读时，在原呈现与选区保护成立的前提下沿原有界导航滑动窗口，反向返程仍连续可达，不能要求反复点击 Earlier 才能越过正常窗口边缘。

数据准备与重内容呈现分开：当前视口和邻近内容优先可读，尚未呈现的重 Markdown、代码与资源逐步呈现，新增数据不应形成一次不可中断的整窗 UI 工作。已呈现的原正文节点、选区、焦点、展开、草稿及双向返程仍按本节原合同保留；延后挂载与资源尺寸变化不推走正在阅读的原记录。实现边界、统一序列与呈现事务的关系见[客户端技术设计](../conversation-client-architecture.md#数据准备与渐进呈现)。这些是目标行为，不代表当前产品已实现自动补足或通过长会话性能验收。

智能连续列表同时约束读取、重内容处理和留存成本。默认折叠的过程、思考、工具载荷与原始详情，初次只准备准确身份、顺序、状态和可读摘要所需的有限内容；没有展开、完整复制或准确定位等真实需求时，不为其不可见正文预先执行完整载荷读取、重解析、高亮或资源解码。已经由原合法页提供的内容与仍须读取的资源如实区分，视觉折叠不作为节省数据或内存的证据。展开和完整取用沿原准确记录与公共内容 owner 完成，不以删原文、丢详情或另建客户端历史账本换成本。当前可读屏幕与邻近储备优先，单次工作和内存留存保持有限；连续回翻越久不能无界累积重正文与资源。已读内容的回收仍须满足原选区、焦点、展开、精确查找和双向返程保护，不因优化拿走已确认的阅读能力。

## Provider 系统记录

Provider 原生协议明确标记的运行时上下文、环境更新及系统指令，在公共历史中与用户消息、Agent 回复和过程活动区分，并以专门的只读系统卡片呈现。Provider 解释原生结构化来源，Core 传递通用分类；客户端不按正文标签、标题或 Provider 名字猜系统身份。未知或混合来源保持原文和已确认分类，不将用户粘贴的系统形状文本提升为系统事实。

卡片标明原 Provider 来源，保留准确记录身份、顺序、原文和资源引用，可展开、收起及复制完整原文；不冒称由 AgentMux 发送，不进入用户输入历史或提供用户消息的发送动作。历史系统分类只用于阅读，不授予指令优先级、权限或控制资格，也不改变原 Session、Run 和健康能力。

## 对话里的贴图

- 对话中的本地图片以缩略图显示，可复用路径引用到草稿。远程图片不自动请求，读取失败保留引用；沿用已有受控文件读取入口，不新增任意 URL 读取通道。
- 粘进对话的图片要**看得见**：渲染成缩略图，而不是一颗只显示路径的文件链接按钮。点击放大到灯箱。Provider 原生记录中已分类的图片资源也沿原 Session 的受控历史资源读取入口显示，核对原来源、记录与内容位置；当前对话和保留会话阅读共用这条边界，不能把内联图片编码铺成正文。
- 路径表示原样保留：Agent 要靠那个 `@path` 去读图，缩略图只是给人看的一层，不替换引用本身。
- 图片加载复用受控文件读取与原安全策略；具体 URI／CSP 形式属于当前实现，不成为永久产品约束。
- 本应用贴图路径的读取只访问同一可信贴图目录，路径与 symlink 解析不能逃出该目录读取外部字节；安全读取沿既有文件 owner。
- 起头的 `@` 是记号不是路径字符，解析路径时要剥掉，否则 `@src/foo.ts` 永远打不开。
- 缩略图的读取失败或仍在加载时必须保留原始路径引用；不能留下破图框，也不能因为展示失败把 Agent 可读的引用删掉。读取成功但浏览器解码失败同样回到原引用文字，移除失效缩略图与放大入口；已打开的灯箱解码失败须收起。已读取贴图的显示事实绑定同一 path 与 reader；读取目标或 reader 变更后的首呈现不能把旧图字节配新引用，失败与灯箱状态只作用于该精确贴图。迟到读取或旧图事件不能使当前图失效；正常可解码图片仍沿原缩略图与共享灯箱查看。非本应用贴图目录的图片路径继续走普通文件引用规则。
- 灯箱查看当前明确选择的原图，提供围绕光标的缩放、放大后的平移和适配视口；关闭后焦点回到触发缩略图。平移边界以原图和当前视口的真实几何确定，缩放与拖动只改变局部呈现，不改变原引用、草稿、消息或资源权限。
- 同一正文或草稿中实际呈现的贴图引用可在原灯箱中连续浏览。集合由原内容显式派生并沿用原 reader，不从 DOM、当前焦点、文件系统或其他 Session 发现图片。灯箱只额外读取当前选择的资源，不预读未选图，原缩略图的必要读取保持；切图复位缩放，读取失败保留该图原引用和重试，并允许继续浏览其他图。集合或 reader 改变后不将旧字节配到新目标；原生记录资源继续沿精确记录 reader 查看，不因图库绕过来源校验。
- 灯箱和图库不建立第二份附件、持久图片集合或图片字节事实。远程图片不因这条能力自动请求；复制、草稿持久化、撤销、删除和提交继续使用原引用。图片浏览只是已授权资源的本地呈现，不新增权限或 Runtime 状态。

## 对话正文中的 Agent 对象引用

对话正文中的合法 `amux://agent|region|tab|space|zone/<ID>` 裸引用与 Markdown 链接共用紧凑的行内对象呈现，原消息、链接地址及原始复制保持原文。引用严格解析为原 Core 类型与 ID；Agent 名称、Provider 图标与当前状态消费原 Session 事实，详情按悬停或键盘焦点读取。它表达被提及对象，不改变记录作者、来源、权限或消息时刻的事实；当前资料须与记录事实区分。未知或不可用时保留可辨的原引用与说明，不用同名对象、当前会话或替代 Session 补位。

共享阅读组件只负责识别与受控呈现，宿主持有对象事实、详情和打开动作；复用既有消息、头像、状态及导航能力，不为行内引用建立另一份 Session／位置事实。打开准确对象、位置歧义、输入保留与失败恢复沿[寻址与复制](public-control.md#对象地址分享与方向)，显示或展开详情不自动发送、启动或恢复 Agent。代码保持字面语义，只读预览保留无导航／资源读取边界，空间对象用类型图标、显式 Markdown 标签或原 ID 呈现，完整地址可查看和复制，不从 ID 内文字推断标题或用途。所有对象的打开沿原地址，非法 URI 保留可读原文。

同一原 SID 已由现有身份解析确认属于 Mote 时，沿原 Mote 名称、头像与表情呈现；普通 Agent 沿原显示名与 Provider 呈现。Mote 仍使用 Agent URI 与同一导航，不按前缀另立协议、持久身份或位置匹配。

状态更新只消费相关原 SID 的现有观察，不为每条历史引用独立轮询、订阅全量资料或预读详情。重复引用共享原事实；隐藏／离屏面停不必要动态。更新不替换正文阅读锚点、选区、展开意图或草稿。视觉与可访问呈现只见[真实对话与行内引用](../presentation/conversation-mode.md#真实对话与行内引用)。

## 可复用对话与 Workflow 表面组件

共同组件由 Gallery 与生产聊天直接消费，延续成熟实现，沿 Workflow 的低干扰语言表达真实工作过程。组件说明现在发生什么、原因与可执行动作；缺少事实不画空壳或示例状态。对象先于装饰，动作靠近事实；层次和动效保密度、键盘可达性、reduced-motion 与非颜色状态辨识。组件事实和数据适配归真实宿主，展示策略有唯一 owner，交互状态支持宿主控制；Gallery 可独立构建，不初始化 Desktop Store 或 Runtime。

开发 Gallery 的组件边界及可用宽度检查只持有当前示例视角，覆盖同一套原组件并保原交互状态；不写生产配置、读取 Runtime 或把示例值变成事实，也不另造生产组件副本。检查关闭或宽度恢复不替换原示例节点。

现有聊天和观察表面的视觉改版保留输入、权限、滚动、身份轴与服务窗的既有行为，不把 Workflow 假数据接入真实聊天。前端技术栈按当前依赖、实际问题与迁移成本评审，不以换框架代替设计工作。视觉规范的层级和唯一来源见[呈现入口](../agentmux-surface-density.md)。

- 参考页里的 Workflow 时间线不是一张只能复制的样稿，而是一组可以被不同 Client 消费的受控组件：普通 tool 行、Workflow 摘要头、阶段折叠、Agent 行、Agent 元信息、安静项折叠、旧 daemon 降级行、dock 压缩态和输入框上方提示条都必须有稳定的类型化输入与可访问状态。
- 对话过程实际消费现有 Workflow 组件：聊天 Activity 的真实步骤与状态消费这套共同观察语言，不停在 Gallery 示例。数据适配归宿主，组件不读 Store、不猜 Provider／Run 状态；Gallery 不成为聊天数据源。记录组不等于有阶段、工作流或多 Agent 的执行事实，没有真实阶段与统计不画虚构阶段、Agent 数、tokens 或进度；已有普通步骤仍完整可读，未知观察保持未知，真实失败与在途状态不能因视觉适配丢失。 长过程默认突出最近记录与真实失败，全部原始步骤仍由一个清楚入口展开；隐藏数按实际成员计算，展开沿原顺序，整组记录起止与总 steps 不随局部展示窗口改变。披露只保存用户意图与已呈现记录身份，不复制步骤事实；切换披露保已读正文、原选区、展开和草稿。
- 原生公开进度说明采用轻量、非正式的共同消息表面，按原 Source 顺序出现在对话中；正式回答、未记录阶段的消息与真实 reasoning 继续各有原含义，进度不能被当思考或归入尾部摘要。真实协作步骤进入同一 Workflow 观察呈现，原 sender／receivers、操作与目标最后记录状态按需可读；一条原生记录仍只是一条步骤，不把目标数量变成 steps、阶段或完整任务进度。无记录时间／状态不造时间或 Streaming；切换披露保原正文、Range、展开与草稿。原生事实归属仅见[《Provider 能力对齐与移植边界》](agent-capabilities-and-messaging.md#provider-能力对齐与移植边界)。
- 旧原生过程沿既有 History 公共读取与 opaque 游标继续可达，与当前对话复用相同阶段及过程呈现；现有有界附近页、原身份锚点、trace 披露和选区保护保持。较早记录不靠扩大 live Hook 窗口、重建旧 Hook 或拼接 captured 投递消息获取；局部窗口和未观察缺口仍诚实，不宣称完整会话或补造执行因果。
- 过程状态的动效与轻层次沿共同呈现组件：过程状态仍由已有真实观察事实决定，动效不补造进度、状态或新步骤；减少动态效果时保留可辨的静态图形与状态文字。过程的轻层次不改变原起止、数量、未知／失败、完整步骤、键盘开合、已读正文、选区和草稿，也不增加数据读取。图形与层次只见视觉合同[《可复用对话与 Workflow 组件密度》](../presentation/conversation-mode.md#可复用对话与-workflow-组件密度)。
- Workflow 组件只表达观察事实：`running`、`completed`、`failed`、`killed`、`paused`、`queued` 的视觉与中文文案一一对应；只有真实拥有阶段明细时才提供折叠箭头，旧 daemon 退化成普通 tool 行并持续说明“daemon 版本较旧，暂无阶段明细”，不留空壳。
- 折叠是统一的 disclosure 语义：按钮通过 `aria-expanded`/`aria-controls` 管理卡片、阶段和“还有 n 个”；Agent 行点击、Enter、Space 都能打开同一份元信息，失败行永不被安静折叠吞掉。运行中保持展开，终态默认摘要化；用户展开后状态更新不能把焦点或展开意图抹掉。
- Agent 分栏、窄屏字段收敛与 dock 的几何阈值只见[Workflow 组件密度](../presentation/conversation-mode.md#可复用对话与-workflow-组件密度)。真实失败不能进入安静项折叠，全部原始步骤仍可反复展开。

- 工作中的 Composer 使用[单一主操作](conversation-input.md#composer-静息形态与主操作)表达当前发送或中断；键盘发送、Queue 与明确 steer 的意图仍分别可用。steer 只补充输入，不改变 Run 生命周期；中断当前回复与 Stop Session 沿不同操作 owner。
- Activity 聚合行的状态只出现一次；等待、错误和阻塞等摘要不得再追加同义状态标签。路径与 Host 只作为次级元信息，不得把工作线行撑成多行卡片。
- 聊天页已有的 ConversationAxis、AgentMarkdown、AgentInteractionCard、ComposerTextarea、StatusDot 和 ServiceWindowNotice 是同一组件体系的既有成员；它们继续各自拥有身份轴、正文、请求回答、IME 输入、状态点和服务窗事实，不复制一份“聊天版”实现。Activity 内部的 Row/Run/Turn/Ruler 在后续接入时也沿用同一边界。
- 组件的可访问名称、键盘操作、焦点环、减少动画和非颜色状态提示是组件契约，不由 Gallery 或未来聊天宿主补丁式添加。颜色与侧边细条不得成为唯一选中/状态信号；状态必须同时有字形、文案或结构变化。

## 原生回合摘要与过程披露

共同 Conversation／History 对已有准确原生依据的回合提供摘要，在相应原生过程的阅读位置让回答、耗时、输出用量和完整过程各有清楚入口。回合摘要关联同一原生来源的准确 `turnId`；只有响应级数据时，摘要绑定原响应或记录 ID，明确是该响应，不补造回合。结束方式、耗时和用量由 Provider 在原生协议边界解释，经 Core 的既有公共历史页与持续变化记录传递。摘要是只读事实，不授予输入资格、不证明任务完成，也不改变 Session／Run 状态；没有来源或关联依据时保留原记录和未知，不按正文、最后一条回答、时间接近或 Hook 最近观测猜测。

耗时采用 Provider 明确报告的回合时长，或同一回合、同一来源时钟的明确开始和结束；它表示墙钟经过时间，不能冒称纯模型推理时间或生成速度。用量区分整轮累计、单次响应和会话累计，只把 Provider 明确归属该回合的整轮值称为本轮用量；最后一次模型请求的 token 不能代替整轮。输出、输入和合计各按原报告口径表达，缺失不补零，不由可见正文估算，不反推金额、上下文占用或 tokens/s。原生数值与计量范围可按需阅读；有真实零值时仍按该原值表达。

摘要复用共同过程的 disclosure，只折叠准确关联且已经加载的过程记录。正式回答、公开进度、中途用户或独立 AgentMux Session 发言、系统记录和真实失败继续沿原来源顺序阅读，不把公开进度当 reasoning，不以最后一条 prose 猜正式回答，不跨这些记录合并过程。原生 Subagent 回报与快照的持续外显编排只沿[共同过程与消息的记录顺序](#共同过程与消息的记录顺序)，不改变该记录身份或原生回合关联。进行中和边界未知不能因画面安静而自动变成完成；真实失败与在途信息沿原共同 Workflow 规则保持可见，用户已展开的过程不因后续状态更新强制收起。没有可展开记录时不提供空箭头。

有界页只代表已加载范围，局部过程数量和记录起止不能冒充整轮统计；缺页仍沿原历史游标继续可达。共同阅读面复用已提交的原页与变化记录，不为摘要增加第二 Reader、轮询、正文缓存、计时器或持久回合 Store。来源切换、分页、隐藏和恢复仍保原记录身份、正文节点、Range、展开、阅读位置与草稿，无关 Session 输出不扩大读取或重算工作。回合事实随现有 Core／JSON-RPC／CLI 历史消费链一致可读，不能仅在 GUI 另算一套。

Gallery 是[共同生产组件](#可复用对话与-workflow-表面组件)的隔离验收入口，生产聊天不读取 Gallery fixture。观察区替换只改变展示与交互编排，消息、Session、Agent 状态和 Runtime 事实继续由原 owner 提供。

Activity、Workflow、服务窗、权限卡与 Composer 沿[共同组件合同](#可复用对话与-workflow-表面组件)表达实际事实；此入口不另定义一套观察表面。

## 同步原请求与耐久答复回执

桌面对话、公共客户端与连接器在原 Provider 具备准确回复通道时，回答同一个 Core 待答请求；可回答资格与原终端出口沿[Provider 与人机交互合同](agent-capabilities-and-messaging.md#provider-与人机交互的分层收敛)，请求可读或意图已保存不代表通道存在。作答意图保留原 typed 请求的内容与 evidence、准确 Session／Run 和稳定 operationId；显示文案与焦点不授予响应资格。同一 operationId 不能换答案或目标，多个入口竞争由原请求 owner 只接受一个有效意图。问题完成、新题到达或 Run 更换后，原操作回执仍可按原身份读取，不把当前 pending 列表当作操作历史。

保存、派发未知、PTY 字节接受、Hook 原连接写入、ACP adapter 确认、原生采用和准确原请求完成分别报告；没有原生采用协议事实时保持未知。丢回执先查原操作，查询不发送输入，也不因返回空值证明其他操作未发生。用户明确重试同一操作与同一答案时，沿原 recoverable Input join；可能首次施效时仍由原 Provider 目标资格核对原请求与当前 Run，已经施效时消费原去重回执。不能自动重放未知动作、换 ID 绕过原意图或把旧卡答复应用于新题；Hook 回调未知不改投另一连接。

桌面请求卡保留已选答案与操作身份，传输回执丢失时查询原 owner；未知结果可就地再次检查。迟到答复与查询不得覆盖另一请求的卡片状态。原生终端、草稿、阅读位置和健康输入保持可用；同步待答请求与历史异步问题的读取和回答仍由各自原 owner 解释。公开接口及第一方接线见[公共能力来源](../../specs/public-capabilities.md)。

## 对话消息的阅读、复制与标注

当前阅读面提供一次收起本页已展开思考／工具详情的明确动作，只作用于当前已加载、属于本来源的过程实例；答案、人类消息、失败摘要、其他来源及未加载历史保持。动作不读取新页、不改变运行事实或复制回执，不默认批量展开重正文；无关新输出保持用户展开选择。收起保原阅读锚点与仍存在的正文选区，焦点不留在已卸载载荷中；单条展开仍沿原记录入口。

已提交的人类长消息可按需展开、收起；适用性消费原作者事实，不从原生user角色或声明推断人类。原全文、复制、引用、选择与定位保持，定位原消息或其内容时全文可达；短消息不增加多余披露。折叠只改变当前记录呈现，不删正文、资源或数据，不自动折叠Agent回答、未知作者、工具或reasoning。

工具详情对可无损呈现的原JSON提供按需可读格式和原文切换；无法安全转换的内容仍读原文，复制始终取原input/output字节。格式化不生成状态、权限、call/result配对或执行结果；来源变化不沿用另一记录的阅读选择或复制回执。

当前对话与Markdown阅读面提供局部查找，只搜索当前已加载、实际可读正文，并明确范围与命中数量。普通正文的延后挂载不改变其查找资格或命中总数，前后定位按原记录显露当前命中；当前首个命中尚未呈现时，首次向前定位先显露该项，不能计为第一项却直接跳到第二项，后续导航继续沿原顺序与环绕规则。用户主动收起的思考／工具详情不自动展开检索。查找不读取隐藏工作面、未加载历史或资源正文、输入草稿或另一个Session，也不要求同步挂载整窗重正文。查找与前后定位不改原内容、选区或记录身份，新内容到来不抢当前命中，关闭后焦点回原入口。Terminal、PDF、Editor与Focus历史搜索继续由各原owner持有，不冒充完整会话搜索或新增领域事实。

原 Markdown 代码与表格只按真实横向溢出提供剩余方向提示和可达的键盘滚动；保全文与复制字节，不掩去边缘文字，无溢出不额外占 Tab 停点。测量与监听只随相关可见阅读块存在，隐藏或离开即释放，不扩入 Terminal 或全局滚动热路径。

展开的思考／工具详情提供各自局部复制，复制完整原 reasoning、参数或结果，不混入标题、Call ID、Markdown展示标记，不拼配 call／result 或推断完成。redacted、空内容与缺少宿主复制能力时不提供伪内容操作；原折叠、顺序和按需 mount 保持。详情与普通代码块复用同一客户端 clipboard 回执机制；成功只来自真实确认，失败可重试，处理保焦并避免同次重复投递；反馈绑定原记录、原内容、宿主和本次动作，换源、折叠卸载及迟到回执不污染新内容。此呈现不新增 Core、JSON-RPC 或 CLI。

每条消息都须有可发现的完整原文复制动作，包含纯文本降级。消息方向、气泡和正文层级统一沿[用户默认外观与协作来源](#共同对话的用户默认外观与协作来源)及[呈现合同](../presentation/conversation-mode.md)；不另立一套早期卡片样式。

整条消息、Agent 身份与局部内容的复制反馈各自绑定原动作，不互相清空成功或失败状态。同一消息的后发复制意图使尚未进入 Clipboard 写入的旧全文读取失效，旧读取不能晚到覆盖用户新选的内容；已经发出的写入按原回执处理，不宣称撤销。异步完整原文、原宿主复制能力、失败重试与换源取消仍保留，不能以复制当前显示的摘要替代整条 Copy。

普通 Markdown 代码围栏提供独立的代码复制动作，复用宿主 clipboard 出口；复制当前代码的完整原内容，保留首尾空白、缩进和换行，不混入语言栏、按钮、行号或高亮标记。处理中、确认成功和失败可重试清楚可辨；没有 clipboard 成功回执不能显示成功。复制反馈绑定原代码、语言和宿主来源，换内容、往返切换或卸载后，迟到回执不能污染当前代码。图表分支、原高亮与可见性调度保持；只读预览和无宿主 adapter 的独立 Markdown 保留原无操作边界。该呈现复用现有客户端复制能力，不新增 Core、JSON-RPC 或 CLI。

对话选区留言统一称「批注」，避免与全局 Note 混淆。划词首先是阅读动作：在可编辑且非只读的当前对话阅读面选择正文，仅出现贴近真实选区的「批注／复制」工具条，不自动建立批注草稿或抢焦点。复制保留选区的完整文字；点击批注才打开留言浮窗并划线。跨控件、跨消息及非正文内容不拼成引用；没有有效选区不增加 chrome。

批注保留来源消息稳定 ID、真实引用文本及原 Range。浮窗跟随原范围，跨行、滚动、展开及宽窄变化保持所选位置；不能按重复文本首次命中重新定位、重排正文或改变阅读锚点。折叠、隐藏或原 DOM 离开时停止几何读取，失效定位暂隐，书写内容与原身份保留，返回后仅在原 Range 仍有效时恢复。新选区可以复制，但不能悄悄替换已有书写批注的引用目标。关闭／Escape 仅暂收，丢弃明确只丢此草稿；IME 不触发发送，回焦不夺走用户后来主动选择的控件。

批注可显式加入当前 Session 的回复草稿，沿原追加 owner 保留既有草稿；也可直接发送给所选 Agent。默认当前 Agent，推荐按本项目（包含新建）、Mote、其他排列；项目归属沿原执行 Workspace／Project，Mote 沿既有 owner，显示名称、头像与精确 Session 身份，不能按当前显示位置或名称猜关联。新建明确选择本项目执行 Workspace 与已有 Executor，通过原 agent.open 单次 initialPrompt 创建并交付批注，不再补发第二条输入。

直接发送沿原发送队列与公共输入合同；「已入队」不冒充 Agent 已收到或执行完成。入队前拒绝保留批注并可显式重试，入队后由原队列持有输入及失败／待确认状态。新建结果不确定时保原 requestId 核对该操作，不自动再建或重发。引用、留言及发送来源只定义一次，不新增标注账本、Reader、轮询或 Runtime。所有失败只影响本次动作，保留健康 Agent 的普通输入；选择、复制和模式切换保持响应。真实 Renderer 故障的恢复与退出见[《工作中界面崩溃的隔离、恢复与退出》](session-recovery.md#工作中界面崩溃的隔离恢复与退出)。视觉与密度唯一见[《对话消息的视觉语言》](../presentation/conversation-mode.md#对话消息的视觉语言)。

## 对话中用户消息的阅读方向

用户消息气泡整体靠右，用来表达对话轴上的发言归属；气泡内部正文、Markdown、列表和代码块统一居左对齐，长内容从左侧开始阅读。用户头像、时间和操作元数据可以继续沿右侧排列，但不能让正文跟着气泡方向右对齐。

仅用户显示的气泡随实际内容收敛，短消息不被撑成固定宽高，长正文与按需详情仍完整可读；当前会话 Agent 与其他已核 Agent 的气泡布局保持。既有作者事实、用户显示默认、来源详情、复制原文与原 DOM 选区边界保持，不凭气泡样式认证来源；视觉约束只见[《消息布局与身份密度》](../presentation/conversation-mode.md#消息布局与身份密度)。

## 共同对话协议与外部交流入口

群连接的观察与恢复复用原 Host 和 Binding owner：连接器已有的重连、原回执核对和等待处理自行收敛，客户端不另造发送队列或重试事实。展开当前群时自动读取有界原观察，读取不重放原输入或未知外部写入；查询失败保留原内容和已有能力。需要用户改变的明确设置采用就地、具名的一次操作，简单可逆动作不增加确认层；用户主动暂停、关闭及原成员授权不得由自动恢复改写。展示不得把历史缺口或一次查询失败升级为整条链不可用；首层信息组织见[群聊连接入口](../presentation/conversation-mode.md#agent-群聊连接入口)。

对话视图与飞书等外部聊天 connector 是同一 Agent Conversation 统一 timeline 的接入方，共同消费[底层 merge 与 MECE 合同](../../specs/conversation-protocol.md#unified-timeline-and-mece)：准确的原 Session、事件身份与顺序、带原来源的消息和内容更新、问题与权限请求、有限类型的动作及可查询原回执。原历史、输入与交互 owner 保持唯一；Core 不依赖客户端框架、不输出平台卡片布局，也不新增独立 Conversation Runtime 或第二份完整历史。客户端分别持有呈现、草稿与阅读状态，连接器持有外部认证、绑定及收发事实。

### Host 常驻托管

已启用的连接器由其准确托管 Host 常驻托管，App 只承担配置、确认和阅读；关闭窗口、退出 App 或最后一个客户端断开不停止连接器、清除绑定或撤销成员授权。本地与远端使用同一 Host 组合及收发 owner，远端 Core 经本机 App 代理执行不能代替远端独立托管。Core 仅消费通用连接、对话和授权端口；平台 SDK、卡片、凭据解析和缓存留在连接器与 Host，不能将 Electron、React 或具体平台依赖反向引入 Core。

Host 从原持久配置、授权、入站记录与 Outbox 恢复群收发及已配置的 Mote 私聊，原读取、会话选择、配额与 Agent 创建继续使用各自唯一 owner；不依赖某个窗口曾打开、预先解密留存内存或 Desktop 回调仍在线。Host 正常停止仅释放自己的接收、观察和存储资源，保留原 Agent、Run、消息和未决操作。局部凭据、平台或读取故障分别可见；凭据确实缺失、原私有存储读取不可用及原格式尚未交接分别投影为有限安全原因，不因未取到可用值就声称凭据不存在，也不透出凭据值或原异常。故障不能阻断其他连接或健康本地输入，也不把当前服务故障误作旧操作未执行。

SDK 客户端、认证缓存及其维护计时器归原连接器的活跃配置消费者持有，不随 Agent 数量复制。连接明确停用、删除、替换凭据或 Host 关闭时，释放已无消费者的缓存与 SDK 维护计时器；同一平台实例仍有其他消费者时保留共享客户端。资源回收不取消已经获准且在途的原请求，不改变已保存操作回执；迟到调用可以完成本次工作，但不得为已退出的消费者重建长期缓存。没有实际使用的平台适配器不因清理而加载，观察失败只影响本次缓存留存判断，不阻断原已获准调用。

连接器托管 Host 与绑定中的 Agent 执行 Host 是两种身份：既有本地连接器可以绑定远端 Agent，选择远端会话不把原连接器或凭据搬到远端。已有跨 Host 绑定保留原托管 owner、执行路由、身份、授权、读取起点与未决操作；原执行端点或授权确实不可达时保留引用并准确说明，不能猜测删除、自动重绑或用同名 Host 顶替。

跨 Host 入站在原记录和输入中保留准确托管 Runtime 与执行 Runtime 的来源关系；Host 别名只在各自配置内寻址，不充当跨 Host 身份。执行端沿已有认证连接回查原托管 owner 的原记录及当前授权，核对准确 Runtime、当前实例和本次原意图，再将原执行别名映射到自己的本地 Session。单向连接可用不证明反向授权读取可达；缺少准确路由、来源未确认或授权被撤回时，只影响相关外部输入，保留原请求、等待引用及健康本地输入。重开和继续使用原日志中的来源，不用新地址、当前同名 Host 或消息声明替换它，也不将原授权快照变成永久许可。

常驻 Host 读取自身已有的准确 Host 配置并持有相应认证连接，沿原配置 owner 接收更新，不另存一份路由清单。已确认 Runtime 的路由才能参与跨 Host 处理；首次身份确认仍由原配置管理入口完成。配置正常原子替换后，相关读取连接随之收敛；坏读、暂时不可达或观察失败保留已确认客户端与健康本地能力，并给出可恢复的有限原因。明确删除一个配置仅释放它的读取客户端，不停止其 Run；反向路由分别由各 Host 的原配置和认证成立。

设置中管理连接器时明确显示托管 Host；凭据、配置、原操作检查和资料读取沿同一准确目标。已经开始的保存、扫码或资料更新保留其原 Host、Runtime 身份、操作与输入；切换 Host 或重新打开页面不迁移请求、不清空草稿，也不将迟到结果用于另一目标。原 Host 暂不可达或同名端点更换身份时，只说明该操作未确认并保留原检查入口，不自动回到本机或另建操作。

配置、资料缓存、原绑定与收发回执属于准确托管 Host 的原连接存储；同机接管保留原路径和全部原身份，不建立 Desktop 与后台两份可编辑数据。远端管理明确目标 Host，不借本机路径、焦点或 Session 显示别名复制凭据或扩大权限。凭据直接保存于该 Host 的私有连接存储，复用原事务及操作回执，并用仅当前用户可访问的目录和文件权限保护（POSIX 目录 `0700`、文件 `0600`）；这是受权限保护的明文存储，不冒充静态加密。本地与服务器采用同一路线，不依赖 Electron、系统钥匙串、图形授权或另一个密钥服务。凭据仅由准确 Host 解析，专用写入入口使用原已认证的 Unix、SSH 或端到端加密通道及原用户／设备身份；普通配置、查询、诊断、审计、日志、命令行参数与环境变量不含凭据值。凭据故障只影响相关操作，不阻断健康 Agent。

旧凭据的格式交接只在用户明确授权后执行，由准确原私有解密 owner 沿原格式的原生提供方一次性完成；系统要求新进程授权时由用户完成，不绕过授权或自写解密。正常 Host 仍只读现行格式，不增加双格式解析、兼容 owner 或自动 fallback。交接前保全原数据库及其必要侧文件的可恢复备份，在同一原数据库、原 credentialRef 与 operationId 上原子转换，核对期间保留原密文和原请求；失败或提交确认未知时保原操作及可恢复数据，先核对原结果，不另造凭据或盲目重做。交接不改机器人、群、绑定、成员决策、读取起点或未知副作用，不要求用户手动导出或复制 AppSecret，也不生成单独的明文凭据导出文件。完成事实须由原转换回执、独立于原进程内存的同引用读取与可恢复备份验证共同确认，不要求为此重启现用 Host，也不以配置可见、新存储可用或新建合成数据代签。未获授权或交接尚未验证时保留原在用 owner 和现存连接的准确未完成说明，不能以不可读的新 owner 替换它，也不阻断独立实现与健康 Agent。

转换前的备份保留原加密字节；删除旧钥匙串项前还须保全并核验当前 codec 可读取、可恢复的转换后备份，两者均沿原私有权限保护，不作单独凭据导出。转换验证后，才可判断是否删除准确归属且已无依赖的连接器专属钥匙串项；不按应用名称猜归属或批量清理。Browser、其他持久数据或可恢复备份仍依赖该项时保留，依赖尚未确认也保留并说明原因。删除不得破坏原浏览器资料、身份或备份恢复路径；正常连接器收发不再依赖该旧项。转换、Host 接管和钥匙串清理分别报告实际结果，任何一步未知都不冒充全部完成。

群关系绑定准确 Host 与持久 AgentSession，不要求先打开 GUI Region；从 Region 发起时继续核对该原 Region 的准确 Session 关系。无展示的会话由同一 Core 核对真实 Session 与原对话起点，不能伪造空间对象、以裸显示名选目标或省略原授权与共享确认。

### 同步覆盖与原故障诊断

诊断须能在原权限内把准确原消息及版本、来源读取边界、共享资格、Outbox 操作与平台回执对应起来，分别说明未进入共享范围、来源不可读、尚未产生发送操作、发送中、已确认及原结果未知。来源读取失败与平台副作用状态分别保留，旧未知发送不得覆盖本次读取失败；没有待发项不能代签同步完整。原记录和读取边界的安全关联通过现有公共 diagnosis 提供，私有路径、正文、密钥、完整游标和任意异常文本不进入跨会话诊断；需要比较时使用原 owner 产生的有限机器事实与不泄露内容的稳定引用。

诊断的外发窗口从最近的原操作开始，按该绑定与版本内的耐久记录顺序有界读取，沿同一顺序的原游标查看更早回执；不按显示时间猜最新，也不为看最近几笔扫描整段历史。最近的成功不抹掉较早的未知操作或来源缺口，窗口为空不证明所有消息均已同步。

Mote 私聊提供针对准确原 Mote 目标的公共只读诊断，沿原 caller 认证、目标读取边界及托管 Host 核对保存开关、原路由 Connection、安全配置与服务／启动能力、最近有界 direct 入站、准备阶段和原 Core 输入回执。读取不到或窗口为空分别保持未知或未观察到，不把群正常、用户曾保存、配置开启、进程存在或字节确认代签私聊已受理、Agent 采用或处理完成。诊断只投影必要的安全身份引用、阶段与有限原因，不输出正文、人员或创建者身份、额度人员名单、私有路径、秘密或任意异常文本；不借诊断开放被拒的管理读取、私聊历史、配置、Agent 创建或重试权限。输入处于等待时，诊断沿原 Core 回执显示控制状态、观察归属以及有限的等待阶段、原因和唤醒条件；没有等待细节明确表示原回执未提供，不能从状态名推断正在处理或需要用户重发。准备步骤失败的有限类型错误码沿原入站／创建观察及 Core 等待回执保留，使执行器、资源、创建、待答交互、原输入占用及来源读取未确认可以区分，不因被接收器捕获就只剩通用检查失败；未分类错误仍给安全未知原因，不从文案猜类别。失败码仅解释原观察，不能代替当前权限、交互、Run 或投递回执授予恢复。 原目标校验失败时，同一有界诊断可沿原输入的准确 Session／Run 读取当前耐久目标是否仍匹配及原 Runtime 状态、类型化退出码；不以笼统错误码推断进程已结束或目标已变化。观测失败保持未知，不输出私有标识、终端正文或原生历史，不启动、接管或重试 Agent。恢复继续沿同一原消息、预留、Session 与输入核对，不重复计数、伪造来源、重放未知操作或停止健康 Agent；原私聊路由和额度语义仍归[Mote 飞书私聊](motes-and-coordination.md#飞书私聊与会话更新)。

终端写入确认之后，同一私聊诊断仍可读取冻结输入的原 Runtime 状态，以及所属原会话代次的有界回复来源、覆盖与投递观察。后者明确属于该代次，不能冒充某一条 query 已被采用或回答。仅投影安全阶段、类型化原因与数量，重复引用同一代次时复用本次读取；不开放原私聊标识或正文，也不以排障触发恢复、输入或发送。

专属 Mote 私聊的首次输入与回复来源就绪独立：准确原创建、Mote 上下文、当前输入授权及 Provider 输入条件成立后，原消息沿 Core 输入 owner 接收，不以尚未出现的原生历史阻塞健康 Agent。私聊创建 owner 明确记录该专属新会话从起点共享回复的意图；真实原生来源出现后，由 Core／Provider 提供准确起点并交给原 Publication owner 持久消费，不能拼造游标、取稍后的最新位置而丢失首回复，或将来源未出现误报为已同步。专属新会话的原生来源发现与首次起点建立须在原身份上自行收敛，不能要求先有原生起点才开放发现该来源的观察。原生起点暂不可读时，保留原 owner 的准确类型化失败原因；缺少起点不统一覆盖为身份未出现。来源读取恢复沿现有观察和恢复机制，不新建队列、轮询器或第二份会话事实。普通群仍只共享明确冻结起点之后的原范围；暂停、撤销、身份变化及未知副作用继续守各自原边界。

选定 Provider 同时负责原生对话的增量读取，历史页可读或观察已开启不代表回复发布能力已成立。私聊回复沿同一原 Provider 的对话增量公共能力与已保留原生起点消费，不暗中切换 Executor，不以捕获的终端输出替代原生消息。Mote 诊断区分原准备启动中冻结的 Provider 与当前默认配置；尚未准备时保持未知，不用当前选择冒充原会话事实。

临时断线和来源读取故障由该准确连接沿原读取、观察及耐久起点恢复，不依赖用户切换页面、再次发言或手工修改记录。恢复不替换冻结输入、重放未知副作用、扩大共享或用新快照成功补签旧缺口；来源真实变化与无法补齐的原范围明确保留，并继续处理具有独立来源和授权的内容。观察句柄存在与其原生来源监听可用分别成立；原生监听不可用时保留已可读来源及耐久进度，仅重接受影响的原观察，不能被一次成功历史读取改判正常。后台成本随活跃连接及其相关原记录增长，关闭或禁用本连接后释放相关观察与恢复工作，不扫描无关 Session。

### 共同来源与双向交付

外部消息采用共同原生 amux Channel 信封，声明准确平台应用、身份命名空间、发送者、原会话与原消息，可携带有来源的名字和头像资料；格式与原文边界沿[amux 协议](../../specs/amux-protocol.md)。Core、共同 client 和公共 RPC 不解释飞书或 Discord 字段。文本声明仅供阅读，真实作者、记录、输入和交互资格仍由原结构化 owner、Binding、Grant 与原请求确认。刷新资料不得改变 actor 身份、冻结输入、授权摘要或历史正文。

Channel 层沿原 Connection owner 提供共用本地持久存储机制，命名空间由准确原适配器和应用身份隔离；各 Channel 在自己的空间内持有用户、群等资料缓存及其结构、新鲜度和恢复策略。公共管理支持限定主体的本地查看、刷新与清理，不暴露私有存储或凭据，不另建配置、授权、Runtime 或完整对话历史。缓存缺失、过时和最新查询失败分别可见；资料故障只影响本次展示，不阻断已认证消息、原 ACK、健康输入、回复或其他连接，也不把瞬时错误固化为永久不存在。清理资料不丢弃原消息、Session、Binding／Grant、未知操作或其必要资源。

飞书和 Discord 各自实现共同协议的公开消息、进度、问题／答案、工具权限交互、生命周期与获准资源，按本平台原生能力采用可辨的卡片形式。原生布局、交互回调、上传及字符／资源限制归各 Channel；共同层只传递原事件、内容、动作和回执。卡片回调消费原请求、准确成员和独立 answer／permission 授权，不能作为本地人类直接提交。当前需要的公开交互不得以未实现占位或静默丢失代替；真实平台／Provider 边界保留原内容、未知事实和准确恢复路径，不能冒称等量支持。资料、群改名和其他元数据事件只更新对应原对象；群详情及关联入口联动呈现新名称，群 ID、绑定、授权及会话保持原身份，断线恢复和显式刷新仍可重新核对原对象。

公开回复中的 Markdown 图片与 Mermaid 图表属于原消息内容。连接器复用既有 Markdown 解析与准确原资源 owner，将平台不支持直接呈现的图片引用和 Mermaid 转为可查看的图片，保留原顺序、说明及源码查看方式；代码示例中的图片语法保持代码，不触发文件读取。自动读取仅限原 Provider 确认的助手公开正文；用户、工具和观察正文里的路径本身不授权本机文件读取，既有明确 typed resource 沿原读取合同。读取必须关联准确来源 Host、原记录及版本中的真实引用，不能让卡片正文或调用者另给的路径取得任意文件访问。图片解析、渲染、上传和消息投递分别沿原资源与 Outbox 保留结果；重开不重复上传或重发未知操作。转换不改写原对话正文或来源，不以摘要、裸本地路径或未经渲染的图表源码冒称图像已送达。局部失败保留正文、说明准确资源缺口及恢复入口，不阻塞无关消息。渲染在托管 Host 独立可用，不依赖 Desktop 窗口；平台布局与格式限制留在相应 Channel 内，通用资源读取不引入飞书分支。

普通群连接的唯一共享内容是完整正常对话，不提供仅同步回复的连接模式。一个 AgentSession 的 App 对话与所有已连接渠道组成同一共同对话。从各连接生效的共享边界起，任一端应连续看到该范围内完整的正常对话：App 用户发言同步到所有目标群；一个群的成员发言同步到 App 和其他目标群；Agent 的公开进度、回复、问题、答案及获准资源同步到所有目标群。平台可采用不同布局或分段，不能只广播 Agent 回复、漏掉用户发言或因来源是另一平台而静默缺失。明确 App 用户输入已被原 owner 保存但尚待执行时，也同步该发言并如实更新原状态，不用 Agent 回复或原生采用充当发言可见的前提。

记录同步与请求处理分别成立。成员授权和触发规则只决定是否将群消息提交给 Agent；没有触发处理的正常群发言仍进入共同记录并按已确认受众转发。每条发言保留准确原作者、来源渠道和原消息关系；原群已有的消息不再回送，转发副本和平台重投按原身份及投递关联去重，不因经过另一渠道生成新的用户发言或重复触发 Agent。同一群消息后来提交处理时沿准确原来源复用已有记录。进入共同记录或被转发均不授予输入、答案或权限资格，本 bot 的平台回声与连接状态卡不成为新的 Agent 输入。

连接确认明确列出同一 Agent 的全部已连接受众及新增目标，说明各群成员的发言会被其他已连接端看到；需要隔离时使用独立 Agent。完整共享沿原正常对话范围和生效起点判断，保留此前私有历史及内部内容边界。既有仅回复授权在原可信确认前保留原范围，但属于尚未完成的共同对话同步；界面直接说明用户消息尚未同步，并提供沿原 Binding 完成完整共享的明确动作。该动作沿用原身份、成员决定和原操作回执，按新确认边界接入较宽内容，不追溯外发旧私有历史；未确认前不能呈现为上下文已一致。网络中断按原耐久回执恢复；暂停、来源未知或平台不支持造成的缺口沿原诊断说明，不以静默丢弃或摘要代替完整正文。

入站状态分别说明原平台消息已接收、共同对话已收录、Core 输入是否建立与提交、实际等待或拒绝、原生采用及 Agent 回复。只有原消息收录确认时称「对话已收录」，不能用「提交已记录」使用户误以为已经提交或送给 Agent；没有原 Core 输入引用时不能显示已提交，有字节提交回执但无采用事实时仍明确 Agent 接收未确认。本次因成员未获输入权限而拒绝时，具名说明没有向 Agent 提交及准确原因，并保留原成员访问管理路径；不能为修正状态自动授权、扩大触发范围或补发消息。记录、等待、提交和采用分别消费准确原输入回执，不按 Agent 忙碌、页面气泡或平台 ACK 推断。

飞书群中面向 Agent 的原用户请求提供原消息上的 reaction 反馈，分别表示已收到、已开始处理与已完成处理。收到以原认证请求的耐久收录及准确目标为依据；开始处理须有该输入的原生采用／回合关联，排队或终端字节确认不能代替；完成须有同一原生来源、准确回合的完成事实，不以闲置、最终回复样式或平台送达回执推断。三项是原请求的处理里程碑，等待、拒绝、失败、中断或完成未知不能标成成功；缺失原生能力时保留可确认的阶段和准确诊断，健康输入仍继续。反应及其未知结果沿原投递 owner 保存和核对，断线、重开与平台重投不产生新 query，也不重放未知副作用；表情类型和平台接口留在飞书 Channel，其他 Channel 不被迫采用飞书的呈现。

当前群消息符合原 Binding、触发规则与准确成员输入授权时，交给 Agent 的输入还须包含：从目标 Agent 自己已记录的上一准确位置之后，到本次群消息之前，在同一授权对话范围内尚需提供的消息，按原顺序作为对话记录 quote；本次群消息保持独立的当前请求，不重复塞入引用。不能只挑曾触发处理或带 @的历史消息。原投递回执能准确关联到同一平台应用、群和消息，且原来源确认由当前接收者的原生对话产生或采用的内容，Agent 已经知道，不再重复引用；仅同一本地 Session 不足以排除已更换原生对话、尚未采用的代发或来源混合的消息。其他人的发言、其他 Agent／bot 的内容及来源未确认的消息仍保留，不能按名字、文案或一概过滤 bot 来去重。引用保留每条原消息的来源、身份关联、正文及资源关系；身份缺失保持未知，系统或内部私有上下文不因被引用而成为可分享内容。引用区与当前请求通过[amux Channel 对话记录引用](../../specs/amux-protocol.md#channel-对话记录引用)明确隔离，引用内的命令、提及、旧问题或权限文本不成为新请求，不取得输入、answer 或 permission 资格；当前请求仍由原 ingress 与 Core 输入 owner 核对。

上一位置须对应目标 Agent 的准确原记录及输入关联，不能用客户端已读、记录同步、外发读取位置、时间邻近或平台确认替代。一次输入准备后保留原区间、顺序、引用内容、当前请求与原操作身份；重试、重启和资料变化不向该输入追加新消息或重组已冻结 wire。位置推进必须沿原 owner 的准确回执核对，缺失回执、区间断档或完整内容不可取得时保留原位置与缺口，不声称已完整交给 Agent，也不通过重放已施效或未知输入补齐历史。引用服从原受众、共享起点与主动暂停的明确边界，不借补上下文追溯导出旧私有内容或触发暂停期积压请求；来源故障只约束本次引用完整性，不关闭健康 Agent 的其他输入、原消息阅读或恢复路径，不另建 Runtime、输入队列或完整历史。

普通群连接共享完整正常对话：已确认提交的人类消息、Agent 的公开回复与进度文字、问题、答案及这些对话内容中的获准资源；Terminal 正常提交的用户消息包含在内。进入当前共同对话的独立 AgentMux Session 原信也属于完整共享：沿准确原 Host、收件 Session、通知或直达输入的原消息 key 与 MID 只读核对原信及真实发送者，仅分享原信正文和身份，不转发引用通知、提醒包装或递归解释正文。原生子 Agent 的内部工具协作、工具原始输入输出、内部推理与系统私有上下文不属于该范围；内容形式与公开资格不能覆盖原语义用途。既有仅回复范围不自动扩大；较宽共享的内容语义收敛为正常对话，保留原身份、来源起点及已尝试请求的正文与回执，结果未知只核对原操作，未尝试且被排除的待投内容明确不再发送。

新建专用群默认让已授权成员的正常发言触发 Agent；连接已有群默认只由已授权成员的 @或回复机器人触发，用户可明确选择其他触发范围。默认来自本次连接意图，不随群人数、标题或成员变化暗改。平台确认的所选应用创建者在成员访问中默认预选发送请求、回答问题与工具权限决定三项，保存前均可调整，并明确工具权限会将原请求和工具上下文分享给该群。既有显式成员决定优先，不因默认值重新开启曾被撤销或关闭的能力；缺少准确创建者身份时不猜本人。其他成员由用户明确添加；预选、邀请或创建者身份本身不授予任何能力，只有明确保存及原授权回执生效。同一 Agent 的多个群共享上下文和已确认范围内的对话内容，确认时列出全部受众并说明跨群可见性；需要隔离时使用独立 Agent。

主动暂停与网络中断分别表达。断网恢复沿原请求和投递继续；主动暂停保留关系但停止该群的新记录同步、输入与外发，恢复以入站和出站的明确新边界继续，不自动补发暂停期间的聊天或触发积压任务。暂停前已开始或结果未知的请求保留原身份与核对路径，被跳过的未投内容明确为未交付。同一受众恢复时续接原成员授权，不要求逐人重授。准确应用、群、Agent Session、执行 Host／Runtime 与输入目标不变时，用户明确保存共享内容或消息触发方式的调整，只改变同步／触发规则，沿用原成员的能力与撤销决定，不要求重复授权。仅改变群消息触发方式时，同一完整共享关系沿用原发布起点、已读取位置和耐久投递操作；不能跳过未读或待投消息，也不能因配置修订重发未知请求。同一接收 Agent 的已采用前文位置与原引用区间也保持连续，不因切换触发方式重新引用全部历史。原已建立输入仍按准确旧请求及当前有效权限核对；尚未获准的入站不因连续关系自动取得输入资格，新消息按当前触发规则处理。更换上述授权对象时不转移原群授权；旧决定和原请求仍可查询。扩大共享仍须明确确认，不能借成员权限继承自动扩大受众或补发旧消息；解绑则终止该关系而非把暂停改名。

连接配置与管理统一归准确 Agent Session 标题栏的“对话同步”入口；Terminal 与 InApp 是同一段对话的不同视图，切换视图不改变 Host、Session、群关系或共享范围。各平台原浮层先说明准确群和原共享范围，再给出双向收发观察及可做动作。Message Tool 专注输入和原输入回执，不承担连接管理、平台发现、设置导航或常驻连接状态；共享关系不依附输入框。共享关系、自动同步、成员资格与实际递送仍各自消费原 owner，不能从群名、本地绑定或提示可见推定消息已同步；读取失败保原已知关系与准确缺口，不撤销健康输入、草稿或原恢复路径。可见工作面沿原标题栏服务观察同时读取准确托管 owner 的全局及平台同步配置，不要求先打开菜单才得到全局配置；未读与初次读取区别于真实读取失败。群资料的缓存过期不等于刷新失败，名称读取以原类型化观察结果区分缓存与不可用，不增加强制原生刷新、轮询或业务 Store。

飞书 connector 在已授权的受众、共享起点和范围内保全统一 timeline 的事件与内容，将同一事件的更新、重试和重连映射回原平台消息，而不是再次发布为新发言。平台长度或卡片限制可以使一个事件对应多段平台消息，映射须保留原事件身份、分段关系及原投递回执，不能把分段或投递次数算成新对话事件。接入方不得靠各自的正文去重、原生／captured 拼接或状态推断修补底层语义；不支持的内容、来源缺口与未知投递须明确可查，不静默跳过或冒称与原对话等量。平台差异只改变承载方式，不改变原事件、内容覆盖及权限边界。

原自含文件沿同资源读取与 Outbox 交付。原文件名缺失时保留缺失事实，使用明确的传输显示名；上传与群消息分别记账，上传未知不自动重传，只有群消息确认尚未尝试时才可由用户显式重试同一原文件，旧上传尝试仍保留未知。平台不支持编辑该消息类型时，沿同投递链记录原撤回与新建，保留版本、映射和回执；撤回失败可重试原操作，未知前驱不得越过。

读取进度与交付覆盖分别可查。无法公开或暂不能承载的事件／内容部件，须按准确原引用、版本和原因，在原耐久投递 owner 内记为未完成覆盖；该记录与本页已支持内容的投递意图一并确认后，读取位置才可前进。不能把此缺口当作成功跳过或完整交付；独立可支持内容继续沿原 Outbox 交付，补齐时核对原部件及原操作，不重放已确认或未知的副作用。

既有 Binding 的受众、共享范围、原来源起点和待投／未知操作在接入统一 timeline 后保持。新增来源或扩大共享沿原绑定 owner 明确确认，不自动补一个新 cut 掩盖未投内容。已有飞书输入只有在原 ingress 与 Core 准确输入引用提供权威对应时，才沿群里的原消息承载同一事件；这不是机器人外发成功回执，也不授予编辑真人消息的能力。迟到事件保原时间与语义顺序说明，不通过删除重发、倒填时间或假称平台可回插历史来伪造列表顺序。

当前状态读取、来源变化观察和实际副作用分别表达。界面可以刷新到最新状态；连接器必须凭原持久来源与自身耐久投递记录补读、核对，不能把临时通知、页面已更新或平台 ACK 当作原生采用、回答结算或任务完成。变化缺口与不可补读范围如实可查，未知不当作未执行，重试保同一原操作身份；此要求不把整个 Core 改成事件溯源，也不授权从终端展示文案猜控制事实。

外部来源声明跨进程传递时不携带授权资格。执行 Host 向原收件 owner 核对准确的原输入和当前授权，Core 在准入、实际派发及原等待重新加入时消费同一权威边界；不能用已保存的授权快照或调用者自报身份代替。收件 owner 的授权核对只读原收件、绑定和授权事实，不回调正在等待它的 Core 输入操作。原 owner 暂不可用时保留原操作与恢复入口，本地正常输入仍可使用。

外部富文本输入沿适配器的原生内容结构读取，保留标题、段落、正文空白及链接目标，作为原消息的一次完整输入，不按段拆成多次发言。提及资格只能来自同一可信事件的准确目标标识及其命名空间，不能从显示名、正文或渲染样式推断。多个语言版本缺少明确选择依据，或含尚不能完整承载的内容部件时，保留完整原消息并明确不支持，不静默选一份语言、删掉部件或把剩余文字冒称完整输入；同消息去重、当前授权与原群消息复用仍由既有收件 owner 持有。

外部接收器的认证、连接与已接收事实，分别沿原适配器和耐久收件 owner 表达。经认证的群消息按原生域、应用与群定位唯一的原 Binding，不按本地 Connection 别名或名称选会话；接收 Connection 保留原来源，目标 Connection、原 Binding、成员 grant 与准确 Session／Run 分别核验，不能借共用接收器转移授权。向 Core 派发或恢复检查失败只在原接收阶段与原记录上可查，不将健康接收器改报为认证或连接失败；另一次消息成功不抹掉尚未恢复的原故障。恢复沿同一仍待派发记录重新取得当前资格，已拒绝、已 claim 或结果未知的输入只核对原操作，不因配置或路由修复自动重发。

同一 Core Client 对同一原 Session、相同调用选项的原生历史观察共享底层 Provider watch，每个消费者独立取消与释放；最后一个消费者离开才释放共享观察。共享层只持活跃观察资源，不缓存页面、来源事实或控制资格。确证来源变化或观察终止后，新消费者重新取得原来源观察；资源终止只消费原 owner 的实际关闭事实，不从 unavailable 的错误码猜测。没有资源终止事实的观察未知保留已有 watch、已读内容与健康 Run，不扩散成其他消费者的取消。

设置的 Conversation Channels 组以 Lark 子项管理飞书与 Lark，以 Discord 子项管理 Discord；机器人与凭据管理沿[外部对话应用接入](settings-and-observation.md#外部对话应用接入)。属于同一 Mote 的每个 Agent，在原对象菜单提供稳定的「连接群聊」入口，进入同一准确 Agent 的任务面后明确选择已有群或创建专用群；选择方式本身不创建、绑定或扩大共享。每条关系绑定准确 Host／AgentSession；同一 Agent 的多处 Region 展示复用原群关系，Mote 与 Zone 组织这些入口。不同 Session 发起创建专用群时，分别保留各自的创建意图、原操作与平台群结果，不能因同 Mote、同一机器人或名称相同复用另一 Session 的群；明确选择已有群仍沿原绑定合同。原 Tab 层级与空间关系保持，群内线程默认组织同一原对话，不自动另建 Session。移动、分屏或重启保原身份、群关系与 cwd；Region 换成另一 Agent 不自动继承旧群，待投和未知操作继续守原目标及绑定修订。关闭展示不终止健康 Agent 或删除外部群，群名与位置不作为路由或授权依据。

创建或连接群时可明确选择已保存的机器人应用。原连接目录可投影准确 adapter 实现的群发现、建群及加入链接能力；这些实现事实不表示平台权限、凭据、可见性或实时接入已确认。明确未实现的新建动作给出准确不可用说明，能力来源缺失保持未知，已有群关系、本地输入及原未决请求的核对与续接不受影响。准确应用的设置导航回其所属平台页，自动同步设置消费同一通用服务。选择分别说明保存与启用偏好、当前鉴权和实时接入观察；已保存、已启用或被选中不表示平台能力、发布及群收发已确认。名称相同的应用仍以原平台域与应用身份区分，当前选择与提交守同一准确对象。确定禁用的应用不能成为新群操作的可选身份，凭据确定不可用也只约束相关新操作；观察未知保留原身份和核对入口，不由探测缺口撤销已有群关系或健康本地能力。已有群详情与已提交的创建、链接、绑定或重连意图始终保留其原 Connection、应用和受众；它们先于任何后来读取的默认值。尚未提交的新群表单先保本次用户明确选择，再以准确原 Mote 的默认机器人初始化；没有该偏好时沿已确认可选应用供用户选择。默认读取迟到、列表排序改变或 Mote 默认变更不能覆盖本次选择、输入或已冻结请求，不按 Session 名称、当前焦点或当前 cwd 猜原 Mote。

公开 Connection 仅以可选安全摘要投影同一原受管 Setup 日志里的未完成、曾确认完成或原完成未确认，不带私有申请定位、actor、账号或原输入。只读关联或观察失败不把手工应用伪造成受管对象；可信的原进度读取可用真实原回执补齐完成观察，不改原操作修订和冻结意图，也不重发。准确的受管初始流程未完成或其原完成事实尚未确认时，该已保存应用不进入尚未提交的新群提案的普通可用身份选项，原应用和继续原设置入口仍可见。初始流程曾确认完成由原 owner 的原应用、原输入与首次发布回执单调确认，不等同当前平台就绪；同应用的名称、凭据引用或本地配置修订变化不能抹掉历史完成，更换应用或 adapter 不能借用它。没有受管来源记录的手工应用保持初始化未确认并可显式选择，不按缺失关联判失败，不从名字、排序或历史扫描补配。既有群关系、已冻结请求、Mote 本地偏好保存及本地绑定不因此增加初始化或探测门禁，原未知写也不重发。

默认引用缺失、禁用、变为未知或与原应用身份不符时，显示原目标与本次无法使用的原因，保明确改选其他已保存应用及进入原设置管理的路径；不能悄悄换成第一项或别的 Mote 的机器人。该缺口只影响尚未提交的这次群操作，不阻断健康本地 Agent、已有准确群关系或独立接入另一身份。默认引用的原 owner 及保存事实唯一见[Mote 机器人身份](motes-and-coordination.md#机器人身份与公开资料)。

连接流程以群、共享、成员访问三个环节组织原事实和下一步，步骤位置从原群结果、Binding 与成员授权推导，不另存流程状态。用户可在同一任务面直接查看原群结果、共享范围、加入方式与成员访问，不必完成或重新执行前一动作才看到已有信息。创建成功后继续原群的共享确认；共享关系保存后明确说明已连接的范围，并提供该群的加入与成员授权入口，不能把创建、绑定或有一个已授权成员等同整群已可使用 Agent。原操作结果未知时停在准确未确认环节并保留查询入口，不为推进步骤而重发或跳过确认。

成员访问区分机器人应用默认与本群明确设置。应用规则属于准确托管 owner、适配器和原生应用，按该应用内的成员身份命名空间保存，作用于该应用现存和未来的有效群绑定；同一平台的另一机器人、另一 Host 或同名账号不继承。它不替代绑定、共享范围、触发规则、服务开关或原生输入资格，也不改变 Mote 私聊额度。设置可在尚无群绑定时管理，公共 API、CLI 和界面消费同一原授权 owner。

同一成员存在本群明确设置时，完整使用该决定，不逐项叠加应用权限：本群关闭某项就是未允许该项，撤销则不允许全部三项。只有没有本群决定或用户明确选择“使用机器人设置”时才继承应用规则。恢复继承保留原决定与操作历史，不能把撤销解释为继承或通过删除记录实现。旧决定与当前绑定修订不一致时保留准确差异及原结果，不自动复活旧允许，也不略过仍属同一授权对象的明确撤销。

生效权限带明确的本群／应用来源和原修订，不将应用规则复制为各群的授权，也不伪造本群保存回执。消息准入、问题回答与工具权限操作共用同一解析；实际执行前再次核对当前有效来源及准确原请求，本群后来新增限制立即约束尚未执行的应用授权操作。已被采用的输入不因此取消健康 Run，旧拒绝或未知操作不因规则修改自动重放。原结果未知只核对同一请求。

应用级工具权限的保存须明确说明：该应用所有现存与未来已绑定群可以接收作权限决定所需的原请求和有限工具上下文；它不是只向获准的那个人私密展示。只有具备对应有效权限的准确成员才能决定，仍核对原 Run、原请求与可用原生 responder。三项权限分别可选，预选不产生权限或分享；已确认创建者的新草稿沿本页的三项默认，已有明确决定优先。

成员访问以原 Host 保存的准确成员与能力为准，和未保存的表单草稿分别表达。同一成员切换选择、刷新、离开和重开保留未提交编辑；迟到读取或较早保存回执不覆盖后续编辑。草稿按原托管 owner、应用、群绑定及成员身份隔离，不能作为授权事实或自动提交依据；原授权对象改变时不沿用为新对象的同意。无改动时不创建新授权操作；原提交未确认时只核对原请求；已经明确拒绝的原操作保留回执，允许用户核对当前权限后显式修改，不把终态拒绝当作永远等待。暂停群说明当前不能新增或修改授权及恢复入口，保留已保存权限与草稿。

群绑定或解绑的权威操作确认应用后，连接器以机器人身份在准确原群发送连接关系开始或结束的说明卡；卡片说明原 Agent、共享范围及已确认的收发限制，不将本地绑定保存宣布为双向收发已可用。卡片投递与绑定结果分别可查，同一原操作不因重投产生多份通知，结果未知不能假报成功。解绑只结束该群的同步关系，保留原 Agent；结束卡失败不阻挡或撤销解绑。结束通知限定本次原操作的准确群和机器人身份，恢复投递不得重新开启绑定、全局同步或旧成员授权。

创建群须明确本次受众、邀请成员和共享范围，使用本次明确选择的已配置应用。创建、成员加入和绑定的确认分别可查；创建成功而绑定失败时保留原群并继续原绑定步骤，不能重复建群。创建结果未知时查询原操作；平台没有足够查询证据时保留未知，不按群名猜测成功或换 operation ID 自动重试。启用 Connector、打开菜单和检查配置不创建群、不发消息，也不启动或重建 Agent。平台应用配置、账户授权与群创建互相独立；本地正常对话在外部配置或创建失败时仍可使用。

群选择与详情优先使用执行 Host 对准确应用和群身份读取到的当前平台群名，名称只用于辨认。尚未取得平台群名时，原创建请求中的名称只能作为标明来源的暂存描述；已有平台名称的读取失败保留最后确认值并说明观察缺口，不把创建名称改报为当前平台名称。已知群 ID 始终来自原群结果并作为次级准确标识，缺名不改变原群或绑定身份。创建专用群默认邀请已确认的原创建账号，在确认为当前本人时明确标示：由原接入 owner 确认该账号与所选应用下可邀请成员的准确关联，再将其作为本次可见的默认邀请成员。开发者后台账号、应用可见受众与群成员标识不能仅因文本相同互相代换。创建者的平台身份、邀请结果、实际加入、群访问、Binding 与聊天授权分别核对；邀请不授予聊天或远程权限。只有机器人在群、机器人已入群或 Binding 成功，不代表本地用户已入群或能够发言。缺本人关联、目录权限或成员确认时保留准确状态与可达动作，不猜本地用户对应哪个平台账号，也不展示没有真实数据源的群或成员选择。

Agent Conversation 的共同标题栏为当前已接入的外部 channel contributions 分别提供紧凑入口，不以已有 Binding 为显示前提；平台自动收发与独立入口显示只沿[原平台设置合同](settings-and-observation.md#外部对话应用接入)，不把 contribution 当作启用配置。已保存群关系与原创建意图按所属 channel 保留，全局自动同步关闭、Binding 暂停或观察未知不隐藏管理与核对入口。只有准确托管 owner 对当前 Session 的关系读取已确认且无绑定时，才表达未绑定；读取失败、缺 owner 或原结果未知不当作没有群。原进度继续沿准确 Host／Session、Connection 与原 operation 核对，已绑定时直接查看原群和加入路径。同一 channel 有多条原关系或待续接请求时明确选择，不按首项猜目标。新 channel 的默认选择仅作用于没有原引用的新入口，原草稿、应用、绑定与未知申请保准确归属；切换 channel 不把一份草稿套给另一平台、覆盖输入或派发第二笔原操作。点击只恢复原上下文，不重新建群、重放未知操作、自动启用服务、保存共享、生成入群链接或授予权限；不因新入口换掉原 owner。入口复用原贡献、意图与事实 owner，不在 header 新建配置或状态 Store，也不从图标推导启用事实。

标题栏仅给紧凑图标与有限异常提示，完整状态和长错误留在原展开面，不占据 Agent 标题或输入空间。状态类别由准确原配置与有界诊断的类型化事实推导，区分未绑定、同步关闭、共享暂停、观察未知以及来源或投递需要核对；不能把不同缺口都压成一个 Needs attention，也不能从展示文字反推类别或控制资格。类别仅用于呈现，不新增健康状态或业务事实。原面板首层说明当前 channel 的准确群关系、独立的收发观察和可做动作；未绑定时以选择或连接群为当前任务，原 owner 未确认时说明缺口并保留原核对／设置路径，不能用一个泛化失败或笼统“已连接”替代这些事实。状态摘要复用准确原 Session／Binding 的既有有界只读诊断，区分绑定和同步配置、当前来源读取与平台投递、共同对话收录与 Core 提交及原生采用。群名、图标、配置开启或 transport ready 不能单独说明双向收发正常；本次来源缺口与旧未知投递分别可查，空窗口不推断断线。状态是一次检查快照，明确最近检查时刻及其成功、部分或失败结果，并保留手动刷新；该时刻不冒作最后收发或采用时间。初次可见、打开原菜单和明确检查仅核对当前可见准确目标，复用原失效与刷新入口，不增加全局轮询、后台健康 Store 或可写 ready 标记。读取失败保留同一原群、名字／准确标识、早先已知结果及可用动作并说明当前未确认；换目标、来源或修订后，迟到检查不污染另一关系。检查不改授权、共享范围或服务配置，不重放未知操作。

标题栏、展开摘要与群详情沿同一准确群关系逐层展开。群详情先辨认原群、原 Session 与机器人身份，再分别说明“对话 → 群”和“群 → Agent”的范围、检查结果与下一步；配置与成员资格不冒作任一方向的收发回执。成员访问、共享和加入各有直接可达的原动作，已有信息不以完成前一步为查看门禁；长诊断和原回执按需展开。全局自动同步、机器人启用、成员发请求授权及原消息回执仍消费各自 owner，各区直接说明已确认事实、未知与准确下一步。创建群、加入群、关系保存、配置打开与真实消息送达互不代签，不能以一个“已连接”或完成步骤让用户推断整条链可用。没有查到当前绑定时，保留原群与请求并提供原绑定的确认或核对入口，不猜另一 Session、不重建群、不把有界空窗口当作全历史未执行。

成员数量只按实际读取范围说明，不把局部成员页或已授权人数当作群成员总数，也不从邀请对象或登录账号猜本人。Binding 的 active 只表达原范围内的本地共享授权，不能单独成为已经可群聊的结论；本次尚待绑定、加入、启用同步、授权或核对的动作在原任务面就地可达。

全局同步开关复用设置中的同一 Connection 服务业务和原操作回执；群详情中的明确开启动作先说明影响所有外部机器人，由用户选择并确认，不因进详情或完成绑定自动打开。机器人启用、共享确认和具体成员的发请求授权仍是各自准确操作，不能由一个按钮静默串联。保存只更新对应已确认事实；输入与外发继续依原回执核实，未知沿同一 operation 查询。

原接收、Core 输入和平台外发分别按原记录确认，空的投递读取窗口不证明全历史没有消息或平台可用；没有新获准内容时不自动发送测试消息。原群、共享起点、成员授权与未知操作在查询失败、离开和重开后保留，不为补齐状态重新建群、替换身份或重放。

群诊断默认以收、发结果和必要下一步说明，技术回执按需展开。复制只包含准确应用、群与 Binding 修订的有限只读观察，明确窗口、后续页和未取得的事实；正文、成员身份、凭据与原生载荷不进入诊断。一次复制不是原子历史签收，离开、换目标或取消后不交付迟到结果；检查和复制不重试任何收发。面向准确 Host／Session、可选原 Binding 的公共只读诊断与界面复制共用 Core 的脱敏投影；托管调用保留原身份，只开放这项有限观察，不扩大原配置、私有安装或成员授权的读写资格。各区独立说明服务、接收器、绑定范围及授权计数、原投递与 Core 输入状态；读取失败不伪造空集合或完成。入站按准确原生应用和群读取有界最新窗口，保留原游标与更早页说明，并区分接收 Connection 与输入目标 Binding；不能被本地别名或未 claim 记录遮蔽。Core 等待原因仅来自原输入回执，正文、原生载荷、凭据、成员身份及任意错误文本均不进入投影。原管理接口因创建者权限过滤的空列表，不作为目标没有群的证据。

在明确的受众、共享起点和范围内，amux 原对话与飞书群保留同等的对话信息，由系统可靠交付，不要求模型记得调用发送工具。用户在原 Agent Terminal、对话输入区或其他已支持入口提交的消息，以及 Agent 回复、问题、回答与共享范围内的对话资源，均按同一 Core 对话投影对应呈现，不能只转发 Agent 回复。平台可用分段、卡片、展开或准确原资源承载，正文和语义不能静默截断；尚未支持的内容与观察缺口明确可查，不冒称两端已经等量。旧私有历史不默认追溯导出，范围外内容和原权限边界继续保留；外发过滤不等同模型上下文隔离。

外发正文资格独立于对话中的呈现角色。Provider 按原生协议解释模型输入副本、生成上下文、系统指令与程序生成的错误诊断的来源与用途，Core 传递该事实；保留为过程、详情或系统卡片，不使这些内容成为可共享发言。没有准确公开区段的原生用户输入继续保持资格未确认，不能按标题、正文、相邻记录或时间补配。原记录和完整本地阅读保持；原投递 owner 在实际外发前守该边界，明确受影响原部件的覆盖缺口，独立获准的内容继续交付，未知副作用只查询原操作。

用户在 AgentMux 输入区提交的公开消息，由系统以独立的用户卡片同步到已授权群，明确原用户来源与「通过 amux 发送」，保留相同正文及原记录关联；卡片与 Agent 进度、最终回复清楚区分。原平台消息仍对应平台已有的那条发言，不生成回声副本。机器人凭证、原生 user 角色、显示名称或正文声明不能代签本人身份与授权，也不能把代发卡片冒作平台本人发言或 Agent 回复。缺失作者关联时保持未知并补齐原 owner 的关联证明，不能猜身份填满页面。

Core 已保存、仍在等待处理的公开用户输入也属于同一共享对话。原 Input owner 提供原提交、作者、公开正文和实际等待状态；进入群的卡片明确「等待处理」，后续采用或完成沿同一原记录更新，不重复发表用户消息。保存、原生采用、Agent 回复和外部送达分别有准确回执；改变等待状态不使共享起点之前的旧输入获得新的外发资格，私有生成上下文不进入卡片。

扩大共享类型须由原绑定 owner 明确确认新的范围与修订，旧绑定的原范围、共享起点和待投／未知操作继续保留。代码升级或界面说明变化不自动取得用户消息、媒体等新增类型的外发授权，不能用新呈现文案替代准确共享事实。

两端的对应关系复用准确原消息、来源和耐久投递映射。已从飞书进入原会话的消息对应群里的原消息，不再回群生成重复副本；相同正文的不同消息仍是不同记录。重连、更新和原操作查询保同一身份，不以文案、显示名、时间邻近或正文哈希推断作者、同一消息或执行因果，也不新增第二份对话历史、观察器或输入队列。

一笔外发结果未知，只阻塞确实依赖该原操作结果或平台消息映射的后续更新、撤回与资源操作；其他已获准且无依赖的用户消息、进度和最终回复继续交付。选择与原子 claim 采用同一依赖边界，保留原来源顺序和独立消息的实际送达结果，不把后发成功说成旧消息已经确认。未知操作保留原身份、请求与查询路径，不删除、改判成功或另建请求重发；诊断持续说明未确认的准确操作及影响范围。

桌面与外部入口操作同一原问题，原 owner 核准确请求和当前权限，不能按卡片状态或普通文本猜答案、权限决定或完成。机器人聊天授权、平台本人发言、账户工具与远程权限批准分别成立。既有私有上下文接入群须明确分享授权，本地正常对话不依赖外部授权和投递是否可用。

Provider 已声明可直接回答的异步原生问题，外部原生表单沿同一个 Core question reply 入口，保全原 source、record、question IDs、Run、前驱输入及完整答案。当前每问按原协议单选或自填，多问在一次明确提交中交付；协议未声明多选时不自行扩张。准确 actor／应用／群与当前 Binding 修订的 answer grant 独立于 input 和 permission，平台按钮或回调不自行授权，不能伪装成本地 human 输入。原 action、授权与问题输入回执分别保留；“已提交”不代签原生采用或完成，未知只查询原操作，不重发或重开待答表单。原请求没有可寻址 responder 时，外部与本地保持同一真实能力边界，保留完整原问题、选项、准确不可用原因与原 Agent 入口，不展示无效回答按钮。

已具备准确开放 responder 的原权限请求可独立接入外部决策，不能冒称已支持原生 question。permission 的预选、明确保存、应用默认与本群覆盖沿本节成员访问合同；实际决定仍绑定准确 actor／应用／群、当前 Binding 和有效授权来源修订。input／answer grant、入群、接入或普通 publication scope 不授予此能力；未获上下文分享授权、原回调已关闭或平台映射未确认时保只读及准确本地入口。完整 expectedRequest、原 actor、授权来源修订与 operation 在原 owner 保全，跨进程仅沿原 authority seam 核原 claim，并在真正 Hook／ACP effect 前复核当前权限；未知仅查同原操作，不转 prompt 或重放 Hook。真实平台、原生采用与 question 资格分别验收，不由另一项能力的成功代签。

以上定义已确认的产品方向与边界，不代表任一 Provider 已支持全部结构化语义、连接器已接入或相关回执已完成验收。现有阅读沿[共同原生记录](#共同对话与原生记录)与[同一 History 阅读面](#history-使用共同对话阅读面)，呈现沿[对话呈现 SSOT](../presentation/conversation-mode.md)，原人机交互资格见[分层收敛](agent-capabilities-and-messaging.md#provider-与人机交互的分层收敛)。

## 产品验收导航

下表组织可观测结果及对应要求，不维护第二套测试流程或发布门禁。优先级按实际影响沿[共同原则](shared-rules.md)、[红线](../../../RED-LINES.md)与原专题判断；不能把所有边界差异一律升级为发布阻断。验证方法归[测试策略](../../testing/strategy.md#任务验收与假绿防护)与[视觉验收](../../guides/agent-visual-e2e-review.md)。

| 条件 | 应看到的结果与保护边界 | 需求与影响 |
| --- | --- | --- |
| 同一逻辑消息有准确的多来源对应 | 主列表只有一条消息，标签说明各真实来源，原记录和完整内容分别可达；未确认对应保持未知，不按正文或时间删记录。 | [统一列表](#连续统一的对话列表)；消息遗漏或重复通常按 P1 的实际阅读影响判断。 |
| 直接在终端输入，或一轮有消息、reasoning、工具和资源 | 声明范围内原输入、回答和全部 parts 均可读，按原序接续；过程默认披露层级不改变原内容和作者。 | [原生输入](#用户消息从-provider-原生会话取得)、[过程披露](#原生回合摘要与过程披露)；遗漏影响按 P1，纯层次瑕疵按 P3。 |
| 到达最新、主动读历史或选中文字后又有更新 | 最新可持续接入；历史、选区、展开和草稿保留；定位动作不暗示点击后才加载，已到尾且无待呈现内容时收起。较早／较新记录仍可沿准确原窗继续。 | [History](#history-使用共同对话阅读面)；定位入口等非致命表达问题按 P2，实际正文不可达按其信息影响判断。 |
| 操作 Question、Permission，或答复回执丢失 | 题目和已有答案可读；只有准确可寻址原请求及资格才执行；草稿、发送、原生已答和某次操作 unknown 可区分，unknown 保原操作，不自动重复副作用。 | [异步问题](#原生异步问题与答复)、[同步原请求](#同步原请求与耐久答复回执)；不可逆重复副作用沿 P0，关键交互不可达沿 P1。 |
| Session 未恢复、恢复中、失败、已结束或观察未知 | 原权威状态一眼可辨，不把未恢复画成仍在继续；原工作面、身份、已读正文和可用健康输入保留。 | [Session 恢复](session-recovery.md)、[Terminal 连续阅读](terminal-reading.md#terminal-连续向上阅读历史)；原身份／工作面恢复和活跃终端阅读按 P0。 |
| 切到另一第一方位置或已授权外部群 | 相同已接受范围的身份、内容与来源解释一致，局部窗口和平台分段可不同；缺口、未知投递和不支持的内容可查，旧共享边界和原操作不变。 | [客户端边界](#共享消息投影的客户端边界)、[外部交流入口](#共同对话协议与外部交流入口)；按信息、身份和副作用的实际影响判断。 |
| 原文仍可达而来源、窗口、版本或轻微视觉表达有差异 | 准确记录问题及适用条件；P2 表达差异与 P3 轻微样式问题不自动阻断无关发布，也不能冒称已完成全部 MECE。 | 本文相应需求、[呈现 SSOT](../presentation/conversation-mode.md)；不另加验收流程。 |
