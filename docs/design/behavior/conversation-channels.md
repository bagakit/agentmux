## 统一 timeline 的外部接入方

对话视图与飞书等外部聊天 connector 是同一 Agent Conversation 统一 timeline 的接入方，共同消费[底层 merge 与 MECE 合同](../../specs/conversation-protocol.md#unified-timeline-and-mece)：准确的原 Session、事件身份与顺序、带原来源的消息和内容更新、问题与权限请求、有限类型的动作及可查询原回执。原历史、输入与交互 owner 保持唯一；Core 不依赖客户端框架、不输出平台卡片布局，也不新增独立 Conversation Runtime 或第二份完整历史。客户端分别持有呈现、草稿与阅读状态，连接器持有外部认证、绑定及收发事实。

外部消息采用共同原生 amux Channel 信封，声明准确平台应用、身份命名空间、发送者、原会话与原消息，可携带有来源的名字和头像资料；格式与原文边界沿[amux 协议](../../specs/amux-protocol.md)。Core、共同 client 和公共 RPC 不解释飞书或 Discord 字段。文本声明仅供阅读，真实作者、记录、输入和交互资格仍由原结构化 owner、Binding、Grant 与原请求确认。刷新资料不得改变 actor 身份、冻结输入、授权摘要或历史正文。

外部 connector 在已授权的受众、共享起点和范围内保全统一 timeline 的事件与内容，将同一事件的更新、重试和重连映射回原平台消息，而不是再次发布为新发言。平台长度或卡片限制可以使一个事件对应多段平台消息，映射须保留原事件身份、分段关系及原投递回执，不能把分段或投递次数算成新对话事件。接入方不得靠各自的正文去重、原生／captured 拼接或状态推断修补底层语义；不支持的内容、来源缺口与未知投递须明确可查，不静默跳过或冒称与原对话等量。平台差异只改变承载方式，不改变原事件、内容覆盖及权限边界。 用户图文消息保留原内容顺序；图片先于文字、真实署名及原输入状态更新，不改变已获准内容的发送资格。状态属于整条原输入，各片段共用准确的同版状态；状态更新可更新文字呈现，不重发已保留的图片或改写已尝试的原请求与回执。

既有 Binding 的受众、共享范围、原来源起点和待投／未知操作在接入统一 timeline 后保持。新增来源或扩大共享沿原绑定 owner 明确确认，不自动补一个新 cut 掩盖未投内容。已有飞书输入只有在原 ingress 与 Core 准确输入引用提供权威对应时，才沿群里的原消息承载同一事件；这不是机器人外发成功回执，也不授予编辑真人消息的能力。迟到事件保原时间与语义顺序说明，不通过删除重发、倒填时间或假称平台可回插历史来伪造列表顺序。

覆盖判定遵守原 Binding 已确认的来源范围。仅共享原生回复的范围不因缺少范围之外的 captured 起点而记为不完整；原 owner 若曾据此生成缺口，只能核对原 Binding、版本和准确派生记录后将其标为已解决，保留原记录。完整共享范围中真实缺失的 captured 起点、原内容与资源缺口仍如实保留；不能为修正诊断扩大范围、补造 cut 或重放原投递。

当前状态读取、来源变化观察和实际副作用分别表达。界面可以刷新到最新状态；连接器必须凭原持久来源与自身耐久投递记录补读、核对，不能把临时通知、页面已更新或平台 ACK 当作原生采用、回答结算或任务完成。变化缺口与不可补读范围如实可查，未知不当作未执行，重试保同一原操作身份；此要求不把整个 Core 改成事件溯源，也不授权从终端展示文案猜控制事实。

## 绑定身份与原生 OpenAPI

平台原生应用或账号 ID 保持原值；原协议将其限定在服务实例时，应用身份同时保留经认证确认的原实例。同一平台、账号 ID、群和消息 ID 出现在不同实例时，绑定、成员授权、游标、缓存、入站与外发回执仍分别属于原实例。缺少或读不懂实例来源时保持原身份及未知，不按显示名称补全，不借用无实例范围的历史授权；准确受众的读取成本也不随其他实例的历史增长。

Agent 绑定一个连接器身份后，应能在同一任务上下文中按需调用该平台已支持的原生 OpenAPI，组合尚未由连接器逐项封装的功能。身份来自准确托管 Host 上、属于该 Agent 的原绑定；多个身份须明确选择，不从默认工具应用、同名显示或消息正文推断，也不自动换为用户代发。身份发现只返回绑定、应用、平台与实现能力，不返回凭据，也不将“支持原生调用”冒作平台权限已经生效。

该身份也是 Agent 主动操作关联群的默认执行身份。Agent 在选择平台 CLI 或 OpenAPI 前，应能从原系统指引发现绑定身份与原生请求入口；第三方 CLI 的当前账号、默认应用或“以 bot 执行”选项不证明它属于原绑定。CLI 只有明确消费同一绑定身份和原 Host 执行边界时才能代表该身份；否则沿已有公共原生请求入口完成可支持的操作。缺少平台能力或权限时说明准确缺口，不静默借另一 Agent 的 bot、工具默认账号或用户身份发送。用户明确选择其他身份的操作保留该明确选择，不能将自动同步身份与另外获准的业务身份混为一谈。

原生请求由原 Host 借用该身份已有的有效平台权限执行。平台 origin、路径语义、认证、SDK 与业务错误归适配器；Core 提供通用身份、请求、授权和原回执，不能将原生协议扩成逐 API 白名单或任意带凭据的 URL 代理。Agent 不取得 AppSecret、Bot token、派生访问令牌、Cookie 或可替代它们的请求头；这些值不进入参数、环境、普通日志、诊断、原操作查询或返回结果。重定向、认证交换与凭据管理不能变成业务接口的凭据导出旁路；普通业务结果保留有用错误与脱敏说明，不以缺少封装或一次失败关闭健康 Agent。

自动同步与按需身份操作分别成立。暂停消息同步不当然撤销该身份；解绑、明确停用或准确身份被替换后，不再用旧绑定发起新的原生调用。已在途的原请求保留原身份及结果，历史查询不触发网络、借用另一个当前身份或重新发起业务。绑定身份不将群成员的发请求、回答问题或工具批准权限合并；Agent 的动作继续服从原授权和确认合同，不使外部成员直接获得凭据或 Host 管理权。

原生调用有明确的原 operationId、请求内容与调用者，查到同一原操作只返回原结果；同 ID 改目标或改正文明确冲突。HTTP 响应、平台业务成功、已记录回执与副作用是否发生分别表达。超时、断线或 Host 中止后保留原未知结果，不自动换 ID、重放或向用户申请无关 OAuth。公开 RPC、CLI、独立 Host 与远端路由消费同一 owner；支持的请求／响应格式与缺失能力要如实可发现，不以 JSON 接口测试冒充文件、流或全部原生 API 都已覆盖。

## 机器人应用的创建与接入

机器人应用的创建、凭据保存、接入配置、版本发布与资料同步，是把一个平台应用变成可用连接的设置任务。登录方式、创建方式、可配置项、版本与审核规则等平台差异由平台 adapter 声明，下文提到的具体平台概念只作例子。Settings 的 Conversation Channels 只承载这些流程的入口、已保存身份与开关的字段语义，见[外部对话应用接入](settings-and-observation.md#外部对话应用接入)；方法、动作与回执字段见[Connection 公共协议：管理认证、应用接入与资料](../../specs/connection-protocol.md#管理认证应用接入与资料)，适配器实现见[连接器包说明](../../../packages/connectors/README.md)。

### 账号确认、创建与首次接入

账号登录、确认账号与创建应用分别表达。支持账号登录创建的平台，由原操作者先核对准确账号与企业，再明确创建；扫码或确认账号不自动创建应用。创建动作冻结本次明确选择的名称、简介与头像，Mote 发起时沿原公开资料快照，独立设置入口提供品牌默认头像。一次创建只授权原头像上传、当前平台明确支持的应用创建方式（含模板创建）、该应用凭据取得与本地保存，各环节分别保留原结果；结果未知时停在原环节，不补建应用或隐式改走另一创建方式。接入配置与发布沿各自明确授权和原结果，不由账号已确认推导。原申请的安全摘要与原操作者当前确认材料分开；旧申请保原身份、原字节与可达的本地恢复，不因新增创建方式自动切换流程。

首次创建沿平台 adapter 声明的已确认原管理控制台协议，由 adapter 将冻结名称、简介和原头像随首次上传与创建提交；Mote 使用原已保存资料及本次选定名称，空简介不以外部项目文案补齐。通用身份的默认文案与图像使用 AMUX 自有内容，由原产品创建 preset 持有，adapter 只执行原输入。应用连接和 Mote 默认引用的本地保存不再触发另一份官方资料同步来补写同一资料；显式更新已有应用统一沿同一管理控制台授权及其原设置 owner，使用已确认账号更新准确应用，不改走机器人凭据的另一条资料写入路线。已派发的原资料 child、回执和未知写入保留可查，不因新创建流程收敛被删除、重放或补造成功。

首次创建以四步「资料 → 登录 → 创建 → 配置与发布」表达同一任务。登录步骤核对准确账号与企业；创建步骤以原账号和创建资料明确确认整次动作范围，配置与发布是必需的接入步骤，在创建已确认后由原 owner 自动续接，无需用户另点“继续配置”。自动续接只执行本次已明确授权、具备原协议资格的动作；待本人确认或企业审批时停在准确步骤，不能自动批准。应用创建、配置、发布回执与本地保存仍各自保留，局部未确认不撤销前步，也不自动重发未知写入。

创建与接入任务的资料准备、登录、创建与配置发布共用连续工作面；不因登录阶段完成而换成另一套流程。编号进度持续保留全部阶段，明确已确认完成、当前处理、等待本人或平台、结果未确认及尚未开始，不能只显示当前状态。当前任务说明准确对象、已经确认的结果和下一动作由谁完成：本人在此页或手机上操作、AgentMux 正在执行或读取、平台正在审核须可辨；单次查询结束不等于原业务完成。当前步骤的主动作直接说明其实际效果；没有可派发动作时说明等待对象或具名缺口，不制造一个无效的“继续”。已保存应用的管理入口展示原应用事实，不虚构本次创建步骤；原配置的子步骤沿真实观察与写入回执逐项说明。只有当前状态读取失败时保留前步已确认事实，并说明本次观察缺口。

扫码面明确正在接入哪个平台、需要用户在平台完成什么确认，以及返回后的下一步；本人身份与企业授权仍由平台持有。仅取得二维码、已扫码或页面返回，都不等于应用已创建、授权已完成或凭据已保存。创建所得凭据沿原安全凭据 owner 接入，密钥、token 和二维码背后的授权码不进入普通字段、日志或操作详情；二维码只在准确原确认面呈现，不作为历史详情展示。只能展示有来源的应用、企业与权限信息，不能用本地姓名或当前登录界面推断创建者身份。

一次创建意图及其准确目标必须在可能施效前保全。离开设置、关闭扫码面、切换入口、断线或重启后，用户仍能恢复查看这次原操作；重新打开不自动再建应用。二维码到期只说明原确认入口的有效性；平台取消按准确回执说明取消范围，本地关闭或停止等待只结束当前展示，不能据此推导应用未创建、已删除或授权已撤回。创建结果未知时保留原操作和已有应用事实，先查询原结果，不以换 ID、刷新二维码或“重新开始”发起另一创建；后续动作须依据原 owner 对同一请求的实际续接或明确重新开始资格，由用户显式执行。

应用创建与本地连接保存分别确认。平台已创建而保存尚未确认时，继续处理同一个已创建应用及原保存，不退回创建起点；凭据不能安全恢复时明确缺少的环节，不以重建应用补偿。已有机器人保存结果未确认时同样保留原输入和操作，只查询原保存；需要继续时由用户明确续接原操作，不以未查到记录就另起保存。迟到结果只归属其原操作和应用，不覆盖后来选择或编辑中的草稿。

本次创建、必要的本地保存及配置与首次发布均由原操作确认完成后，任务直接说明已完成的准确范围，不再以只读进度检查充当必经的继续步骤。查看、刷新原结果和诊断继续可达，不能触发配置、发布或其他副作用。发布待审批、结果未知、已发布与实际消息收发分别表达；完成反馈不自动建群、绑定或发送消息。

Mote 创建使用原耐久接入操作，并保留其准确来源和之后默认引用保存的原请求。平台确认面可预填资料时，预填只是用户可改的候选，不证明最终名称、简介或头像一致；缺少可用头像来源不伪造已带入图片。创建、凭据保存、应用连接保存和 Mote 默认引用保存分别确认；其中后一步失败不撤销前面的真实结果，也不以新建应用补偿。原操作可在离开和重开后发现、查询和明确续接，不能只依赖当前 Renderer 回调记住属于哪位 Mote。

机器人创建与本地保存均确认后，原操作者可从原结果明确继续同一机器人的设置，复用原创建中已确认账号的登录材料，无须为这次本地交接再次扫码。交接须关联原创建申请、认证尝试、账号与企业、准确应用、当前连接修订和稳定设置操作，并沿原安全凭据边界恢复；先显示账号核对，仍由用户明确确认本次管理账号。创建授权不延伸到配置或发布，保存的登录材料也不保证当前平台权限；后续平台读取仍须明确选择。创建、保存或交接结果未确认时，保留原请求与本地恢复，不自动补建应用、重新登录或换目标。

未知申请默认恢复原对象；用户明确创建另一机器人时进入独立新意图，所有旧申请与尚未取得回执的原始请求仍可按准确身份找回。防重复提交只约束同一表单意图，不能因一个 begin 尚在等待而阻断另一个新意图。

### 原申请的恢复与进度检查

返回同一 Mote、机器人或设置任务时，从既有 Mote／Enrollment／Setup 持久 owner 恢复当前 actor 有权查看的准确原请求、目标及已保存进度，不让画面切换抹去现场，也不只依赖 Renderer 回调或另存一份业务状态。多份原请求保持可辨认，不凭最新一项、显示名称或后来焦点替换原选择；来源或权限不可确认时保留安全定位与明确缺口，不打开另一 actor 的私密现场。公共 RPC／CLI 的发现须给出本 actor 可见的原操作及准确查询、续接入口，GUI 消费同一来源。恢复查询本身不创建、上传、改配置、提交发布或重放未知写入；不借旧界面快照复显已离场的二维码或账号材料；返回后的有效确认材料仍由原 owner 按当前 actor、原身份及有效性重新提供，必要确认继续沿原 owner。

原申请的进度检查是一项明确任务，由原 owner 的权威事实决定本次是查询、等待还是用户显式续接同一操作；入口须说明所查原申请与动作含义，不要求用户在数个含义相近的入口间猜测是否会再次创建。创建结果未知、平台明确失败、平台已创建但本地保存未确认须分别表达；本次查询失败只说明未取得新的确认，不能据此改写机器人创建结果或冒充平台拒绝。没有可用确认链接只说明当前缺少确认入口，不能据此将未知归为未开始、未创建或平台明确失败，也不承诺下一次检查一定补回链接或凭据。查看原结果或续接没有取得新事实时，也须就地反馈本次检查结果与未确认环节；原修订未变不能成为清空反馈的理由，显示反馈也不伪增领域修订。未知申请的动作说明实际查询或本地恢复，不承诺一定能继续平台创建；尚未到原轮询时机时，明确仍待确认，不提前轮询。原申请面直接保留接入已有机器人及打开另一独立申请的出口。独立申请不是重试或替换原申请，打开表单不创建、不轮询；创建需新的明确意图，原未确认请求分别可查。迟到反馈只归属原操作，不能覆盖后选、较新事实或另一份草稿。

离开当前扫码或账号确认任务即停止展示私密材料与自动推进，包括在同一设置分区内切到已有机器人表单或应用列表；原设置任务保留每份已提交的安全输入，包括尚未出现在查询列表中的原请求。未查到记录不证明未受理，明确续接仍使用原输入与原身份；独立新申请不替换或阻断其他待查申请。私密响应与后续动作绑定准确 API 来源、应用及连接修订和本次选择；同身份的来源替换、后选目标或离开后的迟到响应均不能重新显示旧二维码、账号或继续执行动作。

已保存应用的通用管理同样保留用户明确选择的原申请身份。返回应用、重开管理或恢复设置后，从原 owner 在同一 actor 下只读查询该申请，不依赖当前历史第一页、创建能力或最近一笔请求猜测；导航恢复不派发继续、登录、配置或发布。保存的仅是准确应用下的原请求定位，私密账号、二维码、动作和阶段重新按原权限读取。申请暂不可读或修订已变化时保留原定位、具名缺口及恢复入口，不退成另一新申请。尚未选择申请与没有原请求分别表达；已选请求在读取中或读取失败后，仍能复制其可取得的安全诊断和具名缺失，不以空的界面选择状态宣称原轨迹为空。

### 登录交接与认证材料

原生登录交接入口与后续跳转使用同一准确目标范围，不能在前一步拒绝后一步已允许的合法交接。未确认结果保留实际失败的解析或后处理环节，并沿原操作及技术详情可查；有限诊断不包含令牌、Cookie、完整跳转地址、原始响应或个人资料，也不授予重放或创建资格。

登录链的传输目标与最终账号来源分别判定。平台 adapter 只沿原流程允许的 HTTPS 来源继续标准重定向，不以中间或最终页面的路径、查询参数形状判断账号资格；URL fragment 不属于 HTTP 请求目标。最终账号仍须由准确应用来源的实际文档及原生稳定身份、企业和验证材料共同确认，中间登录页不授予账号或创建能力。每个新动作只推进一次请求，沿原私密状态保留 Cookie、来源与后续目标；有限跳转观察结束时保留原申请为未确认，不自动换码或重放。技术详情用有限原因区分缺少跳转目标、地址不合法、目标资格不符与观察上限，不输出原地址或从异常文案猜原因；历史原回执不因新增诊断被改写。

账号已在准确应用来源确认后，原创建、凭据取得与后续配置继续使用该最终来源及其 Cookie、验证材料与页面来源，不擅自换回初始入口。平台应用身份、准确账号及原申请绑定分别保持，传输来源变化不把原应用改成另一平台，也不扩大发布或共享授权。后续写请求不自动跟随重定向或重试；未知结果沿原动作保留并查询。

同源响应的单条 Cookie 不合格只拒收该 Cookie，不能抹去已取得的应用身份或平台回执。认证材料续接由原认证 owner 在原操作及准确账号内安全保存，与应用观察和施效结果分别确认；本地续接保存未完成时保留原结果及恢复入口，不重发平台动作，也不以迟到旧材料替换较新的认证。

已保存机器人的管理账号确认沿同一设置任务进行，明确展示本次账号、企业及用途，由用户确认准确账号；扫码与账号确认不授予应用管理权限，也不代表配置、发布或接入完成。实际可用的管理接入方式来自准确应用修订的实现发现，发现失败仍保留原连接检查和平台继续入口。自动推进只执行原 owner 给出的继续动作及其自身修订，未知结果停止推进；重新扫码、换账号和账号确认均须显式执行。

等待扫码与已扫码待手机确认沿同一原登录继续。平台明确返回的等待状态保持原二维码和原申请，按原轮询间隔自动检查，直至登录交接、明确过期或结果未知；不能把正常等待误判为失败，也不能每次检查重建二维码。同一次原登录的轮询请求尚未返回时，owner 保留该次仍有效的扫码材料；并发只读检查、请求派发和本地回执保存中的暂态不能让二维码消失。创建、管理和 Mote 资料更新消费同一合同；界面不另存一份二维码来覆盖明确交接、过期、续码或未知结果。原生协议各阶段只校验该阶段有来源的必要字段，等待轮询的状态字段不能成为已明确登录交接的额外前提；交接仍核对原签发方及目标，不等于账号已确认，也不授予应用创建资格。原生协议允许继续等待而账号交接尚未返回时，保留原申请和观察间隔继续检查；不把状态数值本身解释为扫码、账号或创建成功。读取已存进度仍是本地只读，不暗中开始新的平台请求；账号确认与应用创建保留各自明确动作。账号有效性由准确来源的稳定账号、企业身份及必要认证材料决定；可选显示名缺失或冲突、无关页面元数据和未执行的局部脚本不能撤销已确认身份。明确的二维码过期只更新原确认入口，不推导应用创建或业务取消。

### 请求轨迹与复制诊断

原申请提供按发生顺序查看的脱敏请求轨迹，持有当前阶段、请求方法、来源限定的目标类别及 HTTP／原生状态事实；读取只涉及这次原申请。轨迹由原平台 adapter／操作 owner 提供，界面与公共调用者消费同一来源，不从展示文案反推状态。Cookie、密钥、二维码原文、完整跳转地址、查询参数值与个人资料不进入轨迹或复制诊断；轨迹可查不扩大查询、重试或发布资格。

创建、接入配置与资料管理的“复制诊断”一次取得同一原任务的当前结论、原 owner 已提供的失败或未确认原因、可用下一动作、安全观察摘要及完整有序轨迹，不要求用户分别收集数个折叠区。完整历史与本次观察分别标明来源类型、准确操作身份及观察修订；已由原任务明确关联的子操作保留各自身份，不跨任务拼接。摘要只选取阶段、状态、准确版本、动作种类及相关检查的能力、有限原因、问题和来源结果，不由请求成功推导当前检查通过；缺少原因或观察时明确未记录或未确认，不猜平台故障。摘要不包含账号、认证材料、二维码、凭据、原生响应或草稿正文。导出沿原游标取得全部可导出步骤，不受当前可见页或展开状态限制；读取失败说明完整性缺口，不冒作完整成功。取消、离开或切换目标后，迟到导出不再写入剪贴板。

### 接收方式、消息能力与权限配置

机器人应用的创建、凭据安全保存和接入检查应在同一设置任务内完成，不要求用户手工搬运创建所得密钥。平台支持的必要配置随本次明确接入意图处理；新建机器人和绑定已有机器人的初始权限申请、已保存机器人的缺项补齐，共用按适配器真实消费者定义的默认权限；其中包含人物姓名、头像读取所需的接口及字段权限，沿同一接入用途审阅准确原应用的缺失项，不将接口可调用当作字段已获许可。实际权限、订阅方式与发布生效沿准确应用的原合同和回执确认；待本人确认或企业审批时，就地说明需要谁做什么，不将申请受理或配置写入冒作已生效。已保存、应用鉴权、实时接入和群投递分别确认，保存成功不冒充已经能群聊，也不把多项技术检查平铺成首次上手流程。设置给出准确接入结论，并提供从原 Agent 菜单创建或连接群的下一步；群创建、成员可达、Binding、成员使用授权和共享范围仍独立确认。扫码不自动建群、不把扫码人视为已入群或已获 Agent 使用授权，也不扩大原共享范围。群关系与共享权限的唯一合同见[群入口与成员访问](#群入口与成员访问)与[完整共享与输入状态](#完整共享与输入状态)。

同一机器人的接入默认呈现一项当前任务和一个明确下一步，消息、投递与权限仍可单独管理。下一步只由同一准确应用、API 来源及修订下的原安全观察与回执推导，不另存完成表或可用总分。用户明确检查后，可依次读取当前任务所需的有限应用事实，遇到首个需要用户决定或尚未确认的环节即就地说明；检查不自动改配置或提交发布，不轮询历史或无关机器人。平台结果已知而本地保存未完成时，优先恢复原结果；原施效未知时查看原请求，新的当前读取仍与原请求结论分开。较新选择、来源变化和迟到响应继续遵循原私密材料及草稿边界，不能借引导恢复旧动作资格。

事件接收方式与机器人消息能力是两个独立的明确配置项。下文的“长连接”指平台 adapter 声明的、由 Host 持续保持的事件接收连接。用户先读取准确应用的当前事件接收方式；已是长连接只显示读取结果，不再写入，缺失或未知方式不得默认成可切换。切换前明确说明影响整个应用及其已有事件消费者，由用户明确确认后仅请求切为长连接；不连带增删订阅、回调、权限、可见范围、版本或发布。平台接受切换请求、之后读取到的当前方式、发布状态与实际收到消息分别成立。未确认的切换保留原操作与私有存储回执，可在原身份恢复；换账号、新设置任务或同应用别名不能换请求重发，后来的当前读取也不补签旧请求。这份未决结果只约束同一应用的该项切换，不能阻断独立的机器人消息能力开启、当前读取、平台继续入口或健康 Agent。

群消息接收在原事件投递设置中检查并明确添加。当前应用订阅与可用事件目录各保留原观察，适配器只认可实际接收器所需事件的唯一、准确应用身份项，不以名称、文档链接或另一身份桶代替；缺结构保持未知，已订阅不写入。添加前说明请求还会携带最近检查到的整个应用长连接方式，不能承诺方式不变或平台并发保护；仅添加该项，不暗中切换方式、配置权限、回调或发布。接收方式切换与消息添加都会使此前事件设置失去新写资格，只刷新目录不能补足。原方式请求未知时，只有重新读到长连接、准确事件确实缺失且原不可变方式意图一致，才可明确授权独立的添加；旧切换仍未知，不重试也不补签。未知添加跨账号、设置任务与同应用别名仍保留原请求，本地原回执优先恢复；不能阻断独立机器人消息、权限、平台入口或健康 Agent。请求接受、当前已配置、权限生效、发布与真实收到消息分别成立。

必要应用权限在同一设置任务内审查并明确申请。默认用途是 Agent 对话和创建、连接群聊；只有用户在本次申请中明确包含 Mote 身份同步，才增加更新应用自身名称、简介与头像所需权限，不由名称、图标或默认关联猜测，也不形成长期权限开关。用户的一次审查可依次读取可用目录与当前申请，二者分别保存原回执；部分成功保留，未知不重放已完成步骤。准确原生名称、应用身份和原 ID 决定缺失项，不猜别名、跨身份补全或把缺字段当空集合。仅向准确应用添加明确同意的缺失项；无缺项不请求平台。已接受的申请可在新的当前申请读取后明确补充另一有限用途；只刷新目录不能复用写入前的旧申请清单。平台接受、本地结果保存、当前已申请、生效授权与发布分别成立；需要额外数据范围配置时如实说明，不自动写范围、订阅或发布。未知添加跨用途、换账号、新设置任务或同应用别名仍保留原请求，不阻断独立消息能力、接收方式、已有群或健康 Agent。

账号确认后的应用观察与旧结果恢复分别成立。新的平台观察绑定当前明确确认的管理账号、准确应用与连接修订，一次原动作不因未知回执重发；平台报告的资料读取权限不冒充实际资料读取、应用所属企业、写权限或接入完成。换账号、修订或重开后，原主体仍可从同一申请中有界查找和选择旧观察，只恢复原私有结果的本地交接；这条恢复不要求重新登录或平台适配器仍在场，旧私密权限也不重新成为当前权限。旧结果不可恢复时保留未知，当前账号合格后的明确新观察仍可独立发起。查看历史、翻页与选择不请求平台或暗修回执，原机器人、平台继续入口与健康 Run 保持可用。

应用资料、当前事件设置、事件目录、当前回调、机器人设置、权限目录与当前权限申请按独立观察确认，每个原动作冻结准确主题并分别保留读取和安全保存回执；可选目录不代表当前已订阅内容，多项读取也不冒充完整或原子的配置快照。只投影有来源的安全资料及读取状态，原始配置与安全字段继续留在原凭据保护边界。未知主题不阻断另一明确读取，旧私密结果不带入后来账号或目标；机器人菜单默认值不代表能力启用，读取完成不代表已经可聊天、配置已修改或版本已发布。

启用应用消息能力是对原明确应用的一次显式单项意图，不能由自动推进账号确认顺带执行。资格只消费当前准确账号与目标下最新已安全保存的原生关闭事实，不从缺省值、旧选中结果或稍后未知读取推导；动作冻结原来源与修订，平台接受和本地私有存储回执分别确认。旧未知意图不能经换账号、新设置任务或同一应用的另一引用换 ID 重发；同一执行 Host 内已有的原主体未决请求可准确找回。后来的开启／关闭观察都不代签旧请求，原本地回执恢复不要求当前登录、适配器或修订仍在场。该单项不连带菜单、投递模式、事件、权限、可用范围、默认入口或发布，不代表已经线上可用或可聊天；独立读取、原平台继续入口、已有机器人与健康 Agent 保持可用。

账号确认后的设置面直接提供准确机器人的当前消息设置检查，再按原 owner 给出的动作显式开启；本地动作发现与历史查询不请求平台。请求已接受、当前已开启、结果尚未确认与本地结果待保存分别表达，刷新当前设置不确认旧未知写入。原活动按需展开并沿准确子记录选择、翻页与恢复；当前已保存连接内的原操作可显式查看，不同连接只给安全定位与返回机器人库出口，不自动打开另一私密工作面。

### 版本创建与发布

准确原创建者发起的首次机器人版本，须由权威版本记录确认尚无版本，并明确选择仅创建者可见及机器人入口；这条操作只依赖其真正消费的来源，不以无关的当前受众、外部分享或通用管理资料读取作为门禁。适配器解释本次必要来源，原设置 owner 在公开 typed view 中给出所需读取主题，客户端、SDK 与 CLI 消费同一关系，不自行猜测发布模式。已有版本、版本未知及既有应用的范围更新继续保全原受众、排除范围、分享设置与原操作，不因信息缺口切换为首次发布。

原版本提交回执未知而准确版本身份已保存时，首层进度检查可直接查询该原版本的当前平台状态；原未知提交及其回执仍分别保留，不以查询结果补造旧确认或再次提交。没有准确版本身份时不猜列表首位。版本审核通过、已上线与实际可收发继续分别确认。

发布前的待发布变更、准确版本列表、完整线上可见与排除范围、外部分享与应用特性分别读取，沿原观察日志和安全存储保留回执。准确版本详情须显式选择版本 ID，并贯穿原动作、读取目标、安全绑定与结果；不以列表首项、显示名称或审核状态猜测本次版本与当前线上版本。平台无需重复回显请求中的版本 ID，准确原请求承担目标身份；若回包明确给出冲突身份，则保留未知。部分读取成功时保留其原结果及具名缺项，创建版本资料不足不能封闭独立选择已有版本和查看原结果；多项读取不承诺平台原子快照或并发锁。

创建版本由用户明确填写版本和发布说明，审查准确应用的全部待发布变更、完整包含与排除范围、当前可用入口及外部分享设置；按原平台规则补充必要的审核理由。默认保全已检查的完整范围和有效入口，不能用空值、当前管理账号或首个候选覆盖；只有准确原创建者已确认时，才可明确选择仅该创建者可见。发布作用于整个应用，确认动作须说明其他待发布变更也会一并包含，不承诺只发布本次消息配置。草稿、来源或准确目标改变后，先重新审查，不沿用旧动作提交。已知同应用的提交发布可能改变线上范围与分享，后续创建须重新读取这些受影响事实；不为无关配置扩大失效或扫描范围。

创建版本与提交准确版本是两份独立意图和原回执。创建确认返回的准确版本 ID 可供用户继续审查，提交仍须另行明确确认；用户也可显式选择已有版本。创建结果未知不能凭相同名称或列表位置补签，亦不阻断另一份准确已有版本的独立审查与提交；未决创建和提交分别保留原身份，不经重开、换账号或应用别名重发。原平台结果已取得而本地保存未完成时，由原操作者沿原操作优先恢复安全回执，不要求再次平台登录或当前适配器仍可用，也不重新请求平台。平台受理、当前审核结果、准确线上版本和实际群消息接入分别确认；当前读取不能代签早先未知操作，配置待处理或发布局部失败不能关闭健康 Agent、现有机器人或群关系。

### 应用资料同步

同步公开资料是针对准确应用的一次有限显式操作，与创建身份是不同任务。明确继续须沿原操作显示实际进度或真实停点，不能只结束加载或反复空转。资料读取、上传、写入与匹配读回只依赖各自真正消费的来源；发布阶段再核对准确版本、完整受众及其他必要来源，草稿不能成立时须说明原缺项，并保留资料已写入与待发布的分别事实。可推导的候选版本与可派发的发布草稿分别表达；来源缺失或仍待确认时，说明准确缺项并提供有限的显式刷新，不以无进展的重复读取表示继续。资料更新复用原管理登录、账号核对、读取、施效和发布回执；上传与资料写入只有这一条可执行路线，不在网络失败后切换协议或凭据。旧资料操作只保留原回执查询，不能以新管理授权重放。当前任务种类、目标与进度消费原操作及资料 owner 的有限事实；同步历史不因缺少创建申请或当前登录材料误显示待登录、待创建，新的管理任务则按原认证阶段说明所需登录。原操作冻结目标应用／Connection 修订、源资料和头像版本；上传图像、资料写入、提交发布、本次版本审核与在线资料观察分别保留准确回执。上传或写入未完成时具名说明原环节，结果未知保留原 operation，不自动重发写入。资料同步的原步骤和诊断沿原资料 owner 可查，完整导出及安全观察沿本节原任务的共同诊断合同。已有同步回执不因缺少创建轨迹被表达为尚无请求，未记录的 HTTP 细节保持未记录。资料写入接受不等于线上生效，发布受理不等于审核通过；读取今天的资料也不代签早先未知操作。资料同步可能影响使用同一应用的其他 Mote 和群，应先说明准确目标与影响范围；默认引用不授予独占或平台写权限。

资料管理任务的首层结论须由原 owner 的当前回执说明已完成部分、未完成阶段及准确下一动作，不要求用户解读请求表判断是否完成。资料已写入而发布未开始、发布检查待处理、版本已提交待审核、本次版本审核通过、线上已确认与结果未知分别表达；候选版本标明候选，不能冒作已创建或已发布。原账号、应用、完整原因与请求轨迹从属可查。对同一原操作查询时保留最后已确认结果和原任务，分别表达当前读取与原业务执行；读取失败或结果尚未返回不清空已有结论、不授予新动作，也不改变原 unknown。查询结束显示新观察或具名失败；离开或换目标后，迟到读取不替换后来对象或结束后来查询的反馈。查询、只读刷新、本地恢复和有副作用的继续仍消费原 owner 各自提供的动作，不用通用“继续”掩盖效果差异。

全量资料写入使用准确应用的可靠原资料，保留全部语言块、未改字段与已发布受众。本次明确更新名称时同步已有语言的名称；单一 Mote 简介只更新可靠主语言，其他翻译保持，明确空简介按清空处理。头像上传使用原已保存图像的准确字节及实际尺寸，不复制其他产品的品牌内容。写后读取、版本审核与线上资料分别观察，草稿资料吻合不代签线上生效。

平台不支持本次资料操作、创建来源或管理权限尚未确认时，保留原应用、已写入字段、来源快照和原操作，给出准确的未完成阶段与原平台继续入口，不把一次资料失败扩散成已有聊天或 Agent 不可用。不能静默公开托管本地头像、借其他机器人凭据或为同步资料改写其他能力与权限；没有准确版本范围和明确发布授权时，保资料已写入与待发布，不暗中发布其他待审变更。平台端点、来源限制与权限的可用性由实际合同和原回执确认，不由缺字段、模板或本地保存推导。

### Agent 发起的接入与设置导航

Agent 可沿同一公共 CLI／RPC 完成已授权的机器人接入、配置和默认绑定；公开发现须给出可执行的动作、准确对象及原结果查询方式。Agent 使用原认证身份，只发现和续接自身创建的原接入操作；已配置连接须仍对应该原申请的准确应用。Mote 源资料限定原执行 Host 与 Workspace，群创建和绑定限定该 Agent 本身；本人或设备的既有私密操作不因 Agent 有能力票据而转移。全局连接策略、他人的连接和成员授权仍沿原可信本人或设备。平台扫码、账号企业确认及发布决定仍明确呈现。授权缺失只拒绝本次准确操作，并给出取得授权与继续原请求的入口，不关闭已有机器人或 Agent。

从 Agent 菜单进入设置时，导航保留发起时的准确展示 Session 及其执行 Host、AgentSession 关系；返回动作只定位仍与这些原身份一致的 Agent，不改用后来焦点中的 Agent。缺少原来源或原对象已不可定位时，说明情况并提供既有 Agent 选择入口；不创建 Session、不代选群成员或共享范围。回到原 Agent 只改变展示选择，建群与绑定仍沿原 Agent 菜单、Mote 默认身份及明确授权。
## 群入口与成员访问

机器人与凭据在 Settings 的 Conversation Channels 中按平台管理，入口与分组只见[外部对话应用接入](settings-and-observation.md#外部对话应用接入)。属于同一 Mote 的每个 Agent，在原对象菜单提供稳定的「连接群聊」入口，进入同一准确 Agent 的任务面后明确选择已有群或创建专用群；选择方式本身不创建、绑定或扩大共享。每条关系绑定准确 Host／AgentSession；同一 Agent 的多处 Region 展示复用原群关系，Mote 与 Zone 组织这些入口。不同 Session 发起创建专用群时，分别保留各自的创建意图、原操作与平台群结果，不能因同 Mote、同一机器人或名称相同复用另一 Session 的群；明确选择已有群仍沿原绑定合同。原 Tab 层级与空间关系保持，群内线程默认组织同一原对话，不自动另建 Session。移动、分屏或重启保原身份、群关系与 cwd；Region 换成另一 Agent 不自动继承旧群，待投和未知操作继续守原目标及绑定修订。关闭展示不终止健康 Agent 或删除外部群，群名与位置不作为路由或授权依据。

创建或连接群时可明确选择已保存的机器人应用。原连接目录可投影准确 adapter 实现的群发现、建群及加入链接能力；这些实现事实不表示平台权限、凭据、可见性或实时接入已确认。明确未实现的新建动作给出准确不可用说明，能力来源缺失保持未知，已有群关系、本地输入及原未决请求的核对与续接不受影响。准确应用的设置导航回其所属平台页，自动同步设置消费同一通用服务。选择分别说明保存与启用偏好、当前鉴权和实时接入观察；已保存、已启用或被选中不表示平台能力、发布及群收发已确认。名称相同的应用仍以原平台域与应用身份区分，当前选择与提交守同一准确对象。确定禁用的应用不能成为新群操作的可选身份，凭据确定不可用也只约束相关新操作；观察未知保留原身份和核对入口，不由探测缺口撤销已有群关系或健康本地能力。已有群详情与已提交的创建、链接、绑定或重连意图始终保留其原 Connection、应用和受众；它们先于任何后来读取的默认值。尚未提交的新群表单先保本次用户明确选择，再以准确原 Mote 的默认机器人初始化；没有该偏好时沿已确认可选应用供用户选择。默认读取迟到、列表排序改变或 Mote 默认变更不能覆盖本次选择、输入或已冻结请求，不按 Session 名称、当前焦点或当前 cwd 猜原 Mote。

公开 Connection 仅以可选安全摘要投影同一原受管 Setup 日志里的未完成、曾确认完成或原完成未确认，不带私有申请定位、actor、账号或原输入。只读关联或观察失败不把手工应用伪造成受管对象；可信的原进度读取可用真实原回执补齐完成观察，不改原操作修订和冻结意图，也不重发。准确的受管初始流程未完成或其原完成事实尚未确认时，该已保存应用不进入尚未提交的新群提案的普通可用身份选项，原应用和继续原设置入口仍可见。初始流程曾确认完成由原 owner 的原应用、原输入与首次发布回执单调确认，不等同当前平台就绪；同应用的名称、凭据引用或本地配置修订变化不能抹掉历史完成，更换应用或 adapter 不能借用它。没有受管来源记录的手工应用保持初始化未确认并可显式选择，不按缺失关联判失败，不从名字、排序或历史扫描补配。既有群关系、已冻结请求、Mote 本地偏好保存及本地绑定不因此增加初始化或探测门禁，原未知写也不重发。

默认引用缺失、禁用、变为未知或与原应用身份不符时，显示原目标与本次无法使用的原因，保明确改选其他已保存应用及进入原设置管理的路径；不能悄悄换成第一项或别的 Mote 的机器人。该缺口只影响尚未提交的这次群操作，不阻断健康本地 Agent、已有准确群关系或独立接入另一身份。默认引用的原 owner 及保存事实唯一见[Mote 机器人身份](motes-and-coordination.md#机器人身份与公开资料)。

连接流程以群、共享、成员访问三个环节组织原事实和下一步，步骤位置从原群结果、Binding 与成员授权推导，不另存流程状态。用户可在同一任务面直接查看原群结果、共享范围、加入方式与成员访问，不必完成或重新执行前一动作才看到已有信息。创建成功后继续原群的共享确认；共享关系保存后明确说明已连接的范围，并提供该群的加入与成员授权入口，不能把创建、绑定或有一个已授权成员等同整群已可使用 Agent。原操作结果未知时停在准确未确认环节并保留查询入口，不为推进步骤而重发或跳过确认。

群关系绑定准确 Host 与持久 AgentSession，不要求先打开 GUI Region；从 Region 发起时继续核对该原 Region 的准确 Session 关系。无展示的会话由同一 Core 核对真实 Session 与原对话起点，不能伪造空间对象、以裸显示名选目标或省略原授权与共享确认。

创建群须明确本次受众、邀请成员和共享范围，使用本次明确选择的已配置应用。创建、成员加入和绑定的确认分别可查；创建成功而绑定失败时保留原群并继续原绑定步骤，不能重复建群。创建结果未知时查询原操作；平台没有足够查询证据时保留未知，不按群名猜测成功或换 operation ID 自动重试。启用 Connector、打开菜单和检查配置不创建群、不发消息，也不启动或重建 Agent。平台应用配置、账户授权与群创建互相独立；本地正常对话在外部配置或创建失败时仍可使用。

群绑定或解绑的权威操作确认应用后，连接器以机器人身份在准确原群发送连接关系开始或结束的说明卡；卡片说明原 Agent、共享范围及已确认的收发限制，不将本地绑定保存宣布为双向收发已可用。卡片投递与绑定结果分别可查，同一原操作不因重投产生多份通知，结果未知不能假报成功。解绑只结束该群的同步关系，保留原 Agent；结束卡失败不阻挡或撤销解绑。结束通知限定本次原操作的准确群和机器人身份，恢复投递不得重新开启绑定、全局同步或旧成员授权。

连接已有群未完成时，原绑定操作提供已拒绝、待继续或结果未知的准确事实，并说明受影响的原群、Agent 及当前可执行下一步；确认拒绝不写成泛化的“变更未确认”。关系冲突的说明只使用原 owner 已确认的对象和原因，尚未取得的关联明确待核对，不从错误文字、名称或当前焦点猜另一个绑定。机器人认证、实时接入、群资料和全局同步配置分别说明自身范围，不能代签或遮蔽本次绑定结果。检查只读取原操作；改选、继续或结束本次设置沿明确动作与其原回执，保留已确认关系、成员权限及原请求，不自动解除已有关系、转移授权或重放未知操作。

群选择与详情优先使用执行 Host 对准确应用和群身份读取到的当前平台群名，名称只用于辨认。尚未取得平台群名时，原创建请求中的名称只能作为标明来源的暂存描述；已有平台名称的读取失败保留最后确认值并说明观察缺口，不把创建名称改报为当前平台名称。已知群 ID 始终来自原群结果并作为次级准确标识，缺名不改变原群或绑定身份。创建专用群默认邀请已确认的原创建账号，在确认为当前本人时明确标示：由原接入 owner 确认该账号与所选应用下可邀请成员的准确关联，再将其作为本次可见的默认邀请成员。开发者后台账号、应用可见受众与群成员标识不能仅因文本相同互相代换。创建者的平台身份、邀请结果、实际加入、群访问、Binding 与聊天授权分别核对；邀请不授予聊天或远程权限。只有机器人在群、机器人已入群或 Binding 成功，不代表本地用户已入群或能够发言。缺本人关联、目录权限或成员确认时保留准确状态与可达动作，不猜本地用户对应哪个平台账号，也不展示没有真实数据源的群或成员选择。

成员访问区分机器人应用默认与本群明确设置。应用规则属于准确托管 owner、适配器和原生应用，按该应用内的成员身份命名空间保存，作用于该应用现存和未来的有效群绑定；同一平台的另一机器人、另一 Host 或同名账号不继承。它不替代绑定、共享范围、触发规则、服务开关或原生输入资格，也不改变 Mote 私聊额度。设置可在尚无群绑定时管理，公共 API、CLI 和界面消费同一原授权 owner。

同一成员存在本群明确设置时，完整使用该决定，不逐项叠加应用权限：本群关闭某项就是未允许该项，撤销则不允许全部三项。只有没有本群决定或用户明确选择“使用机器人设置”时才继承应用规则。恢复继承保留原决定与操作历史，不能把撤销解释为继承或通过删除记录实现。切换为本群设置时，先带入当前有效选择形成未保存草稿；切回继承须明确保存，旧的本群决定仍可查。旧决定与当前绑定修订不一致时保留准确差异及原结果，不自动复活旧允许，也不略过仍属同一授权对象的明确撤销。

生效权限带明确的本群／应用来源和原修订，不将应用规则复制为各群的授权，也不伪造本群保存回执。消息准入、问题回答与工具权限操作共用同一解析；实际执行前再次核对当前有效来源及准确原请求，本群后来新增限制立即约束尚未执行的应用授权操作。已被采用的输入不因此取消健康 Run，旧拒绝或未知操作不因规则修改自动重放。原结果未知只核对同一请求。

应用级工具权限的保存须明确说明：该应用所有现存与未来已绑定群可以接收作权限决定所需的原请求和有限工具上下文；它不是只向获准的那个人私密展示。只有具备对应有效权限的准确成员才能决定，仍核对原 Run、原请求与可用原生 responder。三项权限分别可选，预选不产生权限或分享；已确认创建者的新草稿沿本页的三项默认，已有明确决定优先。

成员访问以原 Host 保存的准确成员与能力为准，和未保存的表单草稿分别表达。同一成员切换选择、刷新、离开和重开保留未提交编辑；迟到读取或较早保存回执不覆盖后续编辑。草稿按原托管 owner、应用、群绑定及成员身份隔离，不能作为授权事实或自动提交依据；原授权对象改变时不沿用为新对象的同意。无改动时不创建新授权操作；原提交未确认时只核对原请求；已经明确拒绝的原操作保留回执，允许用户核对当前权限后显式修改，不把终态拒绝当作永远等待。暂停群说明当前不能新增或修改授权及恢复入口，保留已保存权限与草稿。

## 群触发与同步配置

新建专用群默认让已授权成员的正常发言触发 Agent；连接已有群默认只由已授权成员的 @或回复机器人触发，用户可明确选择其他触发范围。默认来自本次连接意图，不随群人数、标题或成员变化暗改。平台确认的所选应用创建者在成员访问中默认预选发送请求、回答问题与工具权限决定三项，保存前均可调整，并明确工具权限会将原请求和工具上下文分享给该群。既有显式成员决定优先，不因默认值重新开启曾被撤销或关闭的能力；缺少准确创建者身份时不猜本人。其他成员由用户明确添加；预选、邀请或创建者身份本身不授予任何能力，只有明确保存及原授权回执生效。同一 Agent 的多个群共享上下文和已确认范围内的对话内容，确认时列出全部受众并说明跨群可见性；需要隔离时使用独立 Agent。

主动暂停与网络中断分别表达。断网恢复沿原请求和投递继续；主动暂停保留关系但停止该群的新记录同步、输入与外发，恢复以入站和出站的明确新边界继续，不自动补发暂停期间的聊天或触发积压任务。暂停前已开始或结果未知的请求保留原身份与核对路径，被跳过的未投内容明确为未交付。同一受众恢复时续接原成员授权，不要求逐人重授。准确应用、群、Agent Session、执行 Host／Runtime 与输入目标不变时，用户明确保存共享内容或消息触发方式的调整，只改变同步／触发规则，沿用原成员的能力与撤销决定，不要求重复授权。仅改变群消息触发方式时，同一完整共享关系沿用原发布起点、已读取位置和耐久投递操作；不能跳过未读或待投消息，也不能因配置修订重发未知请求。同一接收 Agent 的已采用前文位置与原引用区间也保持连续，不因切换触发方式重新引用全部历史。原已建立输入仍按准确旧请求及当前有效权限核对；尚未获准的入站不因连续关系自动取得输入资格，新消息按当前触发规则处理。更换上述授权对象时不转移原群授权；旧决定和原请求仍可查询。扩大共享仍须明确确认，不能借成员权限继承自动扩大受众或补发旧消息；解绑则终止该关系而非把暂停改名。

连接配置与管理统一归准确 Agent Session 标题栏的“对话同步”入口；Terminal 与 InApp 是同一段对话的不同视图，切换视图不改变 Host、Session、群关系或共享范围。各平台原浮层先说明准确群和原共享范围，再给出双向收发观察及可做动作。Message Tool 专注输入和原输入回执，不承担连接管理、平台发现、设置导航或常驻连接状态；共享关系不依附输入框。共享关系、自动同步、成员资格与实际递送仍各自消费原 owner，不能从群名、本地绑定或提示可见推定消息已同步；读取失败保原已知关系与准确缺口，不撤销健康输入、草稿或原恢复路径。可见工作面沿原标题栏服务观察同时读取准确托管 owner 的全局及平台同步配置，不要求先打开菜单才得到全局配置；未读与初次读取区别于真实读取失败。群资料的缓存过期不等于刷新失败，名称读取以原类型化观察结果区分缓存与不可用，不增加强制原生刷新、轮询或业务 Store。

## 完整共享与输入状态

普通群连接的唯一共享内容是完整正常对话，不提供仅同步回复的连接模式。一个 AgentSession 的 App 对话与所有已连接渠道组成同一共同对话。从各连接生效的共享边界起，任一端应连续看到该范围内完整的正常对话：App、Terminal 或其他已支持入口的用户发言由系统同步到所有目标群，不要求模型另调发送工具；一个群的成员发言同步到 App 和其他目标群；Agent 的公开进度、回复、问题、答案及获准资源同步到所有目标群。平台可采用不同布局或分段，不能只广播 Agent 回复、漏掉用户发言或因来源是另一平台而静默缺失。明确 App 用户输入已被原 owner 保存但尚待执行时，也同步该发言并如实更新原状态，不用 Agent 回复或原生采用充当发言可见的前提。

记录同步与请求处理分别成立。原群消息已耐久收到但共同记录暂不可用时，沿同一准确共享关系恢复原话的收录；仅调整触发方式不能使原记录永久失去收录资格，恢复收录也不授予旧消息输入资格。成员授权和触发规则只决定是否将群消息提交给 Agent；没有触发处理的正常群发言仍进入共同记录并按已确认受众转发。每条发言保留准确原作者、来源渠道和原消息关系；原群已有的消息不再回送，转发副本和平台重投按原身份及投递关联去重，不因经过另一渠道生成新的用户发言或重复触发 Agent。同一群消息后来提交处理时沿准确原来源复用已有记录。进入共同记录或被转发均不授予输入、答案或权限资格，本 bot 的平台回声与连接状态卡不成为新的 Agent 输入。

连接确认明确列出同一 Agent 的全部已连接受众及新增目标，说明各群成员的发言会被其他已连接端看到；需要隔离时使用独立 Agent。完整共享沿原正常对话范围和生效起点判断，保留此前私有历史及内部内容边界。既有仅回复授权在原可信确认前保留原范围，但属于尚未完成的共同对话同步；界面直接说明用户消息尚未同步，并提供沿原 Binding 完成完整共享的明确动作。该动作沿用原身份、成员决定和原操作回执，按新确认边界接入较宽内容，不追溯外发旧私有历史；未确认前不能呈现为上下文已一致。网络中断按原耐久回执恢复；暂停、来源未知或平台不支持造成的缺口沿原诊断说明，不以静默丢弃或摘要代替完整正文。

进入当前共同对话的独立 AgentMux Session 原信也属于完整共享：沿准确原 Host、收件 Session、通知或直达输入的原消息 key 与 MID 只读核对原信及真实发送者，仅分享原信正文和身份，不转发引用通知、提醒包装或递归解释正文。原生子 Agent 的内部工具协作、工具原始输入输出、内部推理与系统私有上下文不属于该范围；内容形式与公开资格不能覆盖原语义用途。既有仅回复范围不自动扩大；较宽共享的内容语义收敛为正常对话，保留原身份、来源起点及已尝试请求的正文与回执，结果未知只核对原操作，未尝试且被排除的待投内容明确不再发送。

入站状态分别说明原平台消息已接收、共同对话已收录、Core 输入是否建立与提交、实际等待或拒绝、原生采用及 Agent 回复。只有原消息收录确认时称「对话已收录」，不能用「提交已记录」使用户误以为已经提交或送给 Agent；没有原 Core 输入引用时不能显示已提交，有字节提交回执但无采用事实时仍明确 Agent 接收未确认。本次因成员未获输入权限而拒绝时，具名说明没有向 Agent 提交及准确原因，并保留原成员访问管理路径；不能为修正状态自动授权、扩大触发范围或补发消息。记录、等待、提交和采用分别消费准确原输入回执，不按 Agent 忙碌、页面气泡或平台 ACK 推断。

### 入站认证、收件与恢复

首次接入会返回已有积压的平台，适配器先沿原生协议建立该消息流的初始接收边界；边界未确认的原事件仍在原收件 owner 耐久保管，但不因后来新建 Binding 或成员授权取得输入和共同对话共享资格。原生空队列等准确边界回执、当前实时接收与正常重连分别成立，不能要求活跃群先保持沉默，也不能按本机时间或消息正文猜起点。重连继续原已确认边界和耐久游标，既有拒绝不因后来就绪或重复投递被升级；初始流边界不冒充后续新授权的历史资格。

外部来源声明跨进程传递时不携带授权资格。执行 Host 向原收件 owner 核对准确的原输入和当前授权，Core 在准入、实际派发及原等待重新加入时消费同一权威边界；不能用已保存的授权快照或调用者自报身份代替。收件 owner 的授权核对只读原收件、绑定和授权事实，不回调正在等待它的 Core 输入操作。原 owner 暂不可用时保留原操作与恢复入口，本地正常输入仍可使用。

外部富文本输入沿适配器的原生内容结构读取，保留标题、段落、正文空白及链接目标，作为原消息的一次输入，不按段拆成多次发言。提及资格只能来自同一可信事件的准确目标标识及其命名空间，不能从显示名、正文或渲染样式推断。混合内容沿[公开语义覆盖合同](../../specs/conversation-protocol.md#public-channel-representation-and-action-coverage)保留各部分：图片或文件尚未读取时，在其原位置说明准确资源缺口，独立可读文字仍正常交付，不能冒称附件内容已送达或整条输入已完整读取。多个语言版本缺少明确选择依据时保留完整原消息并明确不支持，不静默选一份语言；同消息去重、当前授权与原群消息复用仍由既有收件 owner 持有。

外部接收器的认证、连接与已接收事实，分别沿原适配器和耐久收件 owner 表达。经认证的群消息按原生域、应用与群定位唯一的原 Binding，不按本地 Connection 别名或名称选会话；接收 Connection 保留原来源，目标 Connection、原 Binding、成员 grant 与准确 Session／Run 分别核验，不能借共用接收器转移授权。向 Core 派发或恢复检查失败只在原接收阶段与原记录上可查，不将健康接收器改报为认证或连接失败；另一次消息成功不抹掉尚未恢复的原故障。

原生入站 ACK 只确认原收件 owner 已耐久保管完整事件与正文；Core 首次保存仍确认完整冻结的输入表示。原收件已经冻结 operation／MID、正文、quote、作者和准确目标而 Core 回执未取得时，沿同原完整请求确保接收，由 Core 的原 operation 事务核对已存意图及历史 claim；不能从 null、网络恢复或当前 Run 正常推定未施效。已存输入先按既有读取权限返回原事实，当前授权或反向来源暂不可用只限制新的推进，不把已保存事实改成不存在；缺原来源的旧记录不补资格，既有未知效果不重放。Run 已变且尚无 Core 意图时，只能依据原 Core 的准确语义恢复链和原执行来源核对同目标；缺失保持原未知，不以今天的 native 身份改写原请求。

收件记录的恢复动作另有稳定的 operationId，并绑定只读检查给出的该收件 owner 准确来源；动作身份只在原托管 Runtime 的这一条收件记录内有效，其他收件记录不参与查重。重复同一动作只读取或接回原结果，旧来源不能影响后来的准备代次。收件 owner 只管理“已接收”、交给 Core 首次保存的交接及自身准确观察；已有 Core 输入引用时只返回该引用与当前推进观察，重试、重新启用和派发控制仍归原输入 owner。正常的确保接收或自动唤醒，不能因同一输入引用后来被确认为未应用就升级成后继尝试，也不复活已停止的输入；这项限制不妨碍同一个已经取得原派发资格的首次效果继续。动作身份或来源引用不授予读取正文、授权或跨 Runtime 控制的权限。

受托管的接收 Agent（原消息冻结的 Host、Session、Binding 与受众已满足原收件授权）可以对同一请求执行确保接收，不要求先完成机器人登记（bot enrollment）；核验时保留它的真实 Agent 身份与当前 Runtime，实际的 Core 首次保存与执行效果仍由 Core 重新核对原外部作者、成员授权和目标。没有冻结目标、或只能读取同群未分配动作的旁观者，不因此取得输入资格；取消前文观察另按实际动作核对资格，见[上下文与输入承载](#上下文与输入承载)。

原收件 owner 已获准且仍待处理的消息，不因原 Agent 未连接而永久停在未确认：沿[会话连续性](session-recovery.md#会话连续性策略与输入)自动尝试恢复准确原 Session，并在准确恢复后重新取得当前资格，按[原输入队列](conversation-input.md#composer-消息队列与紧凑状态)的顺序继续原请求，不要求用户重新发言。恢复、授权或输入观察失败分别留在同一原记录，等待超时只结束本次观察；后续相关原事实到达仍能继续核对，不丢弃旧 pending、不把另一条新消息成功当旧请求已处理。

原物理 operation 已确认的拒绝回执保持稳定，不把它扩成整条逻辑输入永久不可继续。已有 claim 但整条输入已权威确认完全未应用时，沿[原输入 owner 的唯一后继尝试](agent-capabilities-and-messaging.md#跨重启的-prompt-投递凭据)合同继续，保留前序 operation 与回执；Provider 已接受、partial 或结果未知的输入只核对原操作，不因恢复成功自动重发。首次及后继派发都须满足原意图、当前授权与准确派发条件，错误目标或授权拒绝不能借恢复绕过；不能从提示文案、缺少当前回执或配置／路由修复推断可以重发。自动继续保留原消息、operation、冻结内容和当前授权，不复活已停止、取消、暂停、解绑或撤权的原请求，不另建连接器消息队列。

### 上下文与输入承载

当前群消息符合原 Binding、触发规则与准确成员输入授权时，原消息保留本次请求，以及从目标 Agent 自己已记录的上一准确位置之后、到本次群消息之前，在同一授权对话范围内尚需提供的消息；前文按原顺序作为对话记录 quote，本次请求独立保留，不重复塞入引用。不能只挑曾触发处理或带 @的历史消息。原投递回执能准确关联到同一平台应用、群和消息，且原来源确认由当前接收者的原生对话产生或采用的内容，Agent 已经知道，不再重复引用；仅同一本地 Session 不足以排除已更换原生对话、尚未采用的代发或来源混合的消息。其他人的发言、其他 Agent／bot 的内容及来源未确认的消息仍保留，不能按名字、文案或一概过滤 bot 来去重。引用保留每条原消息的来源、身份关联、正文及资源关系；身份缺失保持未知，系统或内部私有上下文不因被引用而成为可分享内容。引用区与当前请求通过[amux Channel 对话记录引用](../../specs/amux-protocol.md#channel-对话记录引用)明确隔离，引用内的命令、提及、旧问题或权限文本不成为新请求，不取得输入、answer 或 permission 资格；当前请求仍由原 ingress 与 Core 输入 owner 核对。

输入承载按实际编码规模分别选择当前正文与前文：短正文直接注入，前文过大时仅提供原 MID 上该 quote 的读取入口，不把短请求一起藏到信箱；正文自身过大时也可只提供其原 MID 读取入口。原正文、完整 quote、来源与范围继续由原消息 journal 保存，不截断、摘要替换或另存一份信箱正文。Agent 按需沿原公共消息读取能力选择正文或前文，并以有界分片取得完整原内容；未选择的前文不随正文读取返回。阈值只决定新输入的表示，不拒绝健康输入、不改变原 immediate／idle 意图、输入 key、作者、权限或通知时机，不把外部作者伪装为 A2A 作者，也不将外部消息加入仅面向 Agent 间交流的列表。承载预算沿[输入环境判定与复用边界](agent-capabilities-and-messaging.md#输入环境判定与复用边界)，已经冻结的原输入不因后续预算策略、指引或群记录变化重新组装。

引用及 reaction 操作指引属于与原请求分开的平台说明。指引让 Agent 发现准确原 MID 的读取方式和原绑定身份的原生请求入口，不要求发送固定的开始或完成表情。适配器给出原会话是私聊还是群聊时，新外部输入的同一平台说明再写明来源类型（群聊提醒所有人都能读到回复）和一份共用的聊天回复规范：先给结论或一个直接问题、简短、不发纯进度、细节放可打开的文档、不经平台 API 重发已共享的回复；该规范与 connection 模块指引同源。类型只选择这段说明，不进入原消息信封、作者、权限或输入资格；适配器未给出类型时不加说明，已冻结的输入不重新组装。规范只指导写作，连接器不截断、摘要或扣留 Agent 的回复。公共读取保留原 Host／收件 Session 的 caller 边界与原字段范围，读取仍不 ACK 信箱、不接受任务、不自动发送 reaction。所选输入即使只含引用，托管交付标记仍仅沿该原输入回执表达交付，不升级为正文已读或开始处理。

上一位置须对应目标 Agent 的准确原记录及输入关联，不能用客户端已读、记录同步、外发读取位置、时间邻近或平台确认替代。一次输入准备后保留原区间、顺序、引用内容、当前请求与原操作身份；重试、重启和资料变化不向该输入追加新消息或重组已冻结 wire。位置推进必须同时确认原冻结 wire 实际携带该完整 quote，以及原 owner 对这条输入的准确回执；仅交付 quote 的读取引用或随后只读原 MID，均不推进完整前文已提供的位置。保留原位置时，后续超长前文继续用短引用，不重新内联巨大历史，也不为推进位置新增阅读回执。缺失回执、区间断档或完整内容不可取得时保留原位置与缺口，不声称已完整交给 Agent，也不通过重放已施效或未知输入补齐历史。引用服从原受众、共享起点与主动暂停的明确边界，不借补上下文追溯导出旧私有内容或触发暂停期积压请求；来源故障只约束本次引用完整性，不关闭健康 Agent 的其他输入、原消息阅读或恢复路径，不另建 Runtime、输入队列或完整历史。

可选前文是弱读取：每次准确的只读资源各自使用独立的有界观察窗，包括前文位置的原回执读取、仅用于 quote 的凭据等待、原生锚点、每页历史及必要的 token／HTTP 交换；不为整段区间设总截止或页数上限。观察窗的当前时长见[接收反馈与读取观察窗](../../architecture/conversation.md#接收反馈与读取观察窗)。正常的慢页，以及累计超过一个观察窗的完整范围，仍按原顺序保全。观察窗到期或取消只结束这一次观察，保留原请求、已确认前缀、准确范围与具名缺口；前文位置读取失败时使用最后确认的位置或原保留基线，不推进未确认的位置。回复资格、当前作者与成员授权以及准确目标是强前提：它们失败只阻断这条输入，不能改记成 quote 缺口后放行。弱读取不持有整个 Host 的消息 journal 锁，也不关闭健康输入。

每次前文观察（context observer）由原收件记录持久标识，连同其修订与冻结来源。准确的原收件 Agent 可以在原消息冻结的 Host／Session／Binding／受众范围内结束自己的这次弱观察，核验时保留真实身份、当前 Runtime 与原输入授权；不要求机器人登记，但同群旁观读取或仅持有来源引用不授予取消资格。取消先针对准确的原来源，并保留原动作结果；已经耐久完成的本地回执不再等待后续的目标验证、Core 首次保存或 Core 读取，未取到的 Core 观察明确标为未知或不可用。较早一次观察的动作或迟到读取，不能取消、覆盖或清除后来的一次观察；缺少耐久前缀时如实保留缺口。Core 首次保存仍持有完整冻结的输入表示，后来的 quote 读取成功不改已冻结内容，也不再提交第二条输入。

### 接收反馈与自主 reaction

面向 Agent 的原用户请求，连接器自动托管的 reaction 只表达接收等待与输入交付，不代 Agent 表达处理过程或结果。原认证请求已耐久收录且准确目标成立后可显示等待；真实进入队列仍须由原输入 owner 确认完整原输入的成员关系，已保存字段本身不代签。收到与已入队共用同一个托管等待标记，细阶段及各自真实回执保留在投递详情，不为同一等待表情重复创建会互相撤销的效果。只有准确原终端或原生输入通道确认本次获准输入已交付，才替换为交付标记；输入若是原信箱引用的通知，该标记也只证明通知已交付，不证明 Agent 已读取正文。获准尝试、平台已收消息或等待标记成功均不代替输入交付。快速交付不补演未经观察的排队阶段，各里程碑不依赖前一个表情的网络结果。等待、拒绝、未应用或未知不能标成已交付；原已确认交付事实也不被后续处理失败撤销。具体表情和平台接口留在各 Channel，卡片布局变化不改变原 reaction 的目标或含义。

输入交付后，是否、何时以及用何种 reaction 表达处理过程或结果由 Agent 自己决定，沿[原绑定身份能力](#绑定身份与原生-openapi)和当前授权执行；连接器不因原生采用或回合结果自动新建开始、完成、失败或中断 reaction。Agent 的表达与托管交付回执分别成立，均不能被反向读取为控制事实。原生采用／开始仍须有该输入的准确采用与回合关联，完成仍须有同一原生来源、准确回合的类型化结果（typed outcome）；终端字节确认、原生输入通道接收、表情、闲置、最终回复样式、耗时或平台回执都不能代签。缺失原生能力时保留未知及准确诊断，健康输入仍继续。此处只收窄自动外部表达，不改变原输入队列、作者、权限、采用记录或完成事实。

同一请求的自动托管标记只在等待与已交付之间替换，迟到的等待事实或回执不使交付呈现倒退。替换只管理同一原应用、原消息和原请求下，由本反馈链路持有准确平台映射的托管表情；Agent 自主表达、其他操作者和同一机器人其他用途的表情均不随自动阶段清理。添加新标记与删除旧标记各按原投递 owner 的独立操作和回执确认，不抹去旧回执或把任一步的未知写成整个替换成功；旧标记清理失败不阻塞新标记、正文或健康输入。平台只提供分步操作时允许短暂并存，恢复沿原未决操作核对，不重放原 query，也不扫描无关历史或批量清空原消息表情。旧阶段已冻结的请求及 wire 保留原身份、参数与只读核对能力；收窄新操作的生成范围不授权改写、重发或补签旧效果。共同层复用原请求、输入事实、投递 journal 与映射，不另建反馈事实 Store；具体表情、添加／移除和核对能力由各 Channel 提供，未提供该能力的平台保留准确诊断。

Mote 飞书私聊在原专属会话准备就绪、准确原接收决定与当前授权仍成立后，也在原用户消息上显示同一托管等待标记。反馈沿该消息已保存的原代次与应用、会话、发送者关联，不能用当前最新代次或同名 Mote 改投目标。初次准备尚未就绪时保留原入站及准备状态，不冒称即时反馈；准备就绪后的等待标记不等待原生历史、输入采用或回复出现，也不代表已入队、已交付 Agent、开始或完成。反馈在正常输入认领前进入原 Outbox，随后重开仅核对或继续该原效果，不因私聊缺少捕获来源而扫描历史补发。反馈的持久化或平台故障不阻断健康输入；尚未保存的反馈与结果未知的原效果须准确区分，不能把输入已认领当作表情已送达，也不重放未知效果。私聊与群聊共用同一交付判据和 Agent 自主表达边界；原私聊输入只有准确终端交付回执而无原生采用关联时，采用／完成仍保持未知。未来输入启用原生能力须沿同一原 Session 和准确原生来源确认，保全原代次、旧 Binding 与已冻结输入；观察缺失不撤回健康终端输入能力，另一 Provider 的接线也不代签该原会话的能力。

后续托管交付反馈沿该请求已确认的原接收目标、原输入及当前授权核对，不借当前最新代次或其他群的接收目标。恢复反馈的工作范围只含该准确受众中尚需核对的原请求，成本不随已完成历史和无关 Session 增长；没有未完成请求时不为表情轮询。等待表情的外发成功不终结输入观察；准确交付后不为自动处理表情继续观察原生采用或完成，也不以原生未知促使持续点查终端回执。用户取消、停止观察、输入明确未执行和待重新加入分别沿原输入 owner 解释；以后显式恢复同一逻辑输入时保原请求并核对新的等待代次，不以旧停止事实或旧事件补签新进展。取消与恢复均发生在连接器离线期间时，沿[原输入增量变化发现](conversation-input.md#统一发送信箱与原生采用)重新定位准确请求，不能因为曾移出待核对集合就永久漏报，也不补造离线期间未经证实的历史阶段。反馈工作索引只选择待核对对象，不拥有输入状态、采用或完成事实，不决定健康 Agent 是否可继续工作。

### 消息对应与独立交付

共享受众、起点与正常对话范围沿[完整共享与输入状态](#完整共享与输入状态)。平台可用分段、卡片、展开或准确原资源承载，正文和语义不能静默截断；尚未支持的内容与观察缺口明确可查，不冒称两端已经等量。外发过滤不等同模型上下文隔离。

外发正文资格独立于对话中的呈现角色。Provider 按原生协议解释模型输入副本、生成上下文、系统指令与程序生成的错误诊断的来源与用途，Core 传递该事实；保留为过程、详情或系统卡片，不使这些内容成为可共享发言。没有准确公开区段的原生用户输入继续保持资格未确认，不能按标题、正文、相邻记录或时间补配。原记录和完整本地阅读保持；原投递 owner 在实际外发前守该边界，明确受影响原部件的覆盖缺口，独立获准的内容继续交付，未知副作用只查询原操作。

用户在 AgentMux 输入区提交的公开消息，由系统以独立的用户卡片同步到已授权群，明确原用户来源与「通过 amux 发送」，保留相同正文及原记录关联；卡片与 Agent 进度、最终回复清楚区分。原平台消息仍对应平台已有的那条发言，不生成回声副本。机器人凭证、原生 user 角色、显示名称或正文声明不能代签本人身份与授权，也不能把代发卡片冒作平台本人发言或 Agent 回复。缺失作者关联时保持未知并补齐原 owner 的关联证明，不能猜身份填满页面。

等待输入的共享资格沿[完整共享与输入状态](#完整共享与输入状态)，原 Input owner 提供原提交、作者、公开正文和实际等待状态；进入群的卡片明确「等待处理」，后续采用或完成沿同一原记录更新，不重复发表用户消息。保存、原生采用、Agent 回复和外部送达分别有准确回执；改变等待状态不使共享起点之前的旧输入获得新的外发资格，私有生成上下文不进入卡片。

扩大共享类型须由原绑定 owner 明确确认新的范围与修订，旧绑定的原范围、共享起点和待投／未知操作继续保留。代码升级或界面说明变化不自动取得用户消息、媒体等新增类型的外发授权，不能用新呈现文案替代准确共享事实。

无回声规则沿[完整共享与输入状态](#完整共享与输入状态)，对应关系复用准确原消息、来源和耐久投递映射；相同正文的不同消息仍是不同记录。重连、更新和原操作查询保同一身份，不以文案、显示名、时间邻近或正文哈希推断作者、同一消息或执行因果，也不新增第二份对话历史、观察器或输入队列。

一笔外发结果未知，只阻塞确实依赖该原操作结果或平台消息映射的后续更新、撤回与资源操作；其他已获准且无依赖的用户消息、进度和最终回复继续交付。选择与原子 claim 采用同一依赖边界，保留原来源顺序和独立消息的实际送达结果，不把后发成功说成旧消息已经确认。未知操作保留原身份、请求与查询路径，不删除、改判成功或另建请求重发；诊断持续说明未确认的准确操作及影响范围。

原自含文件沿同资源读取与 Outbox 交付。原文件名缺失时保留缺失事实，使用明确的传输显示名；上传与群消息分别记账。显式接续携带原投递 owner 给出的准确效果种类与真实尝试来源，每个来源只接受一次；接受后即耐久保留该接续，丢回复、并发或重开仍核对同一来源，不因下一次尝试又失败而再次排队。只有原消息已权威确认未应用，或原上传未知且群消息确实从未准备、从未尝试时，才可按当前准确授权继续同一原操作；未知消息不重放，旧尝试及回执保持。迟到的旧上传未知不能撤销已接受的接续；下一上传认领前到达的准确成功可复用原资源，已有后继认领或消息冻结后只结算旧尝试，不换资源、正文或投递事实。接续已接受、当前队列去向和平台效果分别表达，取消、撤权或已结束操作不因重复旧来源复活。平台不支持编辑该消息类型时，沿同投递链记录原撤回与新建，保留版本、映射和回执；撤回失败可重试原操作，未知前驱不得越过。

读取进度与交付覆盖分别可查。无法公开或暂不能承载的事件／内容部件，须按准确原引用、版本和原因，在原耐久投递 owner 内记为未完成覆盖；该记录与本页已支持内容的投递意图一并确认后，读取位置才可前进。不能把此缺口当作成功跳过或完整交付；独立可支持内容继续沿原 Outbox 交付，补齐时核对原部件及原操作，不重放已确认或未知的副作用。

平台已权威确认原消息完全未施效且只是暂时限流时，原发布 owner 可在准确原失败来源上自动继续，仍与显式重试竞争同一接续权。平台等待建议按准确原生资源范围共用，未提供有效建议时采用明确、实测正常延迟的本地策略；两者都在原效果 claim 事务重核，提前接受显式动作或产生同范围新消息不能绕过尚有效的窗口。其他群、API、独立投影及健康 Agent 正常推进，未知、取消、撤权或被取代的消息不因此重放或复活。等待沿原投递类型化事实表达来源与最早时间，不代签未来授权、成功或全局配额；到期后仍可能收到新的限流事实，沿原 owner 核对，不以零再次限流为由增加全局调度器或每消息计时器。

### 消息图片与文件

公开回复中的 Markdown 图片与 Mermaid 图表属于原消息内容。连接器复用既有 Markdown 解析与准确原资源 owner，将平台不支持直接呈现的图片引用和 Mermaid 转为可查看的图片，保留原顺序、说明及源码查看方式；代码示例中的图片语法保持代码，不触发文件读取。自动读取仅限原 Provider 确认的助手公开正文；用户、工具和观察正文里的路径本身不授权本机文件读取，既有明确 typed resource 沿原读取合同。读取必须关联准确来源 Host、原记录及版本中的真实引用，不能让卡片正文或调用者另给的路径取得任意文件访问。图片解析、渲染、上传和消息投递分别沿原资源与 Outbox 保留结果；重开不重复上传或重发未知操作。转换不改写原对话正文或来源，不以摘要、裸本地路径或未经渲染的图表源码冒称图像已送达。局部失败保留正文、说明准确资源缺口及恢复入口，不阻塞无关消息。渲染在托管 Host 独立可用，不依赖 Desktop 窗口；平台布局与格式限制留在相应 Channel 内，通用资源读取不引入飞书分支。

App 用户消息中的截图与粘贴图片同属原消息内容，不能只同步附件引用的本机绝对路径。真实附件来源及其与原正文位置、原输入和资源版本的关联，由可信输入与原资源 owner 记录；正文路径、文件名或图片节点的显示形状不能建立该关联或授权读取任意文件。连接器沿原关联读取获准的图片，复用已有上传和耐久投递，按原顺序传递图片与用户文字；外发正文、卡片摘要及附件提示不带附件的本机目录。App 原文、草稿引用与 Agent 实际输入保持，外部呈现适配不改写它们。资源缺失、变化、不可读或平台不支持时，外部端明确显示对应附件尚未送达及可用的原对话入口，保留其他正文和独立资源；不以裸路径替代图片，不扩大原共享范围，不为补图重放未知请求。

### 回复页脚

外部最终回复的页脚提供原回合状态、准确归属的原生耗时与 token 用量。事实复用[原生回合摘要与过程披露](conversation-mode.md#原生回合摘要与过程披露)，只关联这条回复的原来源与回合或响应，保留原计量范围；响应级数据不能称为本轮统计。token 优先显示 Provider 原报合计，缺合计时依次采用明确标注的输出或输入量，不自行相加或用输出冒称总量。状态来自准确回合结果，最终回复的 phase 不等于回合完成；不能借用 Session 最新状态、其他回合或正文推断，回合结束不代签用户任务完成。缺失读数省略，真实零值保留，首字与速度没有准确原生依据时不显示；飞书 reply 页脚不提供打开原对话的动作。正文不等待可选摘要；新准备且具备安全更新能力的回复，在准确同回合或响应事实跨记录或分页后到时，沿原消息与既有投递回执补齐页脚，不产生第二份正文。页脚只补充呈现，不修改原正文、作者或共享范围，不改写旧冻结请求，也不因后到事实重发未知原投递。

### 平台资料与头像

Channel 层沿原 Connection owner 提供共用本地持久存储机制，命名空间由准确原适配器和应用身份隔离；各 Channel 在自己的空间内持有用户、群等资料缓存及其结构、新鲜度和恢复策略。公共管理支持限定主体的本地查看、刷新与清理，不暴露私有存储或凭据，不另建配置、授权、Runtime 或完整对话历史。缓存缺失、过时和最新查询失败分别可见；资料故障只影响本次展示，不阻断已认证消息、原 ACK、健康输入、回复或其他连接，也不把瞬时错误固化为永久不存在。清理资料不丢弃原消息、Session、Binding／Grant、未知操作或其必要资源。

原群读取与成员发现已取得的名字、头像沿同一准确主体资料缓存复用，不要求该群或成员先发消息才可呈现。当前可见主体首次缺少资料时，沿同一 owner 有界按需读取；群详情、成员访问、Mote 人员与应用成员入口共用资料读取、刷新、变化订阅和取消语义，不能只复用头像外观。群详情的显式刷新同时更新当前所呈现主体的资料；未在当前面板呈现的成员和历史授权不扩大本次读取，普通重绘不逐次触发平台查询。本次原生响应未观察到某字段时保留先前确认的值及其原新鲜度，不把本次改名当成旧头像重新确认；平台明确移除字段则沿该原生事实更新。原生查询成功但未返回姓名或头像，不代表资料已取得或当前有效；没有已观察字段时明确未取得，只有先前真实资料时保留原值并说明本次更新未确认。接口可调用与资料字段许可分别成立，缺字段本身不冒充已确证的权限拒绝。头像始终属于其原人物或群，不能用上级群体的图标冒充当前会话头像。客户端须能实际加载合同允许的头像资源；资料未读取、查询失败与图片解码失败分别成立，图片失败不改判身份、授权或 Agent 能力。

### 公开作者资料与头像

公开作者资料投影与媒体上传／回执复用各自沿同一公共 owner。人类、Agent、A2A、过程、回复与 Question 消费相同的原作者资料和资源关系，卡片只布局，不各自读取资料、上传头像或维护缓存。已确认人类作者的公开显示名与头像只在准确原输入的可信准备边界进入，随该输入保存；其他作者沿其原 owner 解析，不用当前个人配置、收件 Agent 或机器人创建者覆盖原作者。资料用于呈现，不认证本人或授予权限，不公开个人简介，也不改变既有给 Agent 的资料共享选择；通用资料机制不归 Agent Provider 输入语义，不另建身份库、配置副本或第二资源库。已确认的同应用媒体结果可复用，在途上传由相关需求共用；可再生成头像的一次未确认不能成为永久缺图缓存，后来的真实展示需求可有界按需尝试，但不重放或回退原正文副作用，不扫描历史或新增全局定时器。可选资料和媒体故障不阻断健康输入及正文交付。

可选作者资料是展示弱依赖：有界等待只结束当前展示观察，不能撤销已确认的作者、公开资格或正文交付能力，也不能冒充底层读取完成。相同准确作者的相关需求复用真实在途读取直到其结束；一个观察者取消不取消其他相关消费者。迟到的资料与资源读取结果沿准确原作者、输入及资源版本继续进入既有媒体上传、结果复用与安全补齐能力，不重写已冻结请求；宿主释放时结束其拥有的观察，不新增资料轮询、永久缺失缓存或独立恢复队列。

对新建且已确认具备安全局部更新能力的卡片，原头像稍晚确认后应沿同一原消息补齐，首张或唯一一张消息不依赖下一次发言。已声明的准确头像资源仍在真实读取或上传时，可在正文准备前沿既有可选实体准备保留局部更新能力；没有声明头像或已确认资源不可用时不为此创建实体。头像补齐只改变准确作者的身份元素，和后续正文共用平台可验证的更新顺序；头像结果未知不挡正文，也不能使较新的正文或作者回退。头像、可选卡片实体、相应权限或准备结果不可用时保留原正文交付能力，不能为等头像额外延长正文等待。消息发送方式在原请求准备时确定，迟到实体回执不改写已准备或已发送的消息；已发旧卡、未具备局部更新能力的卡和过期实体保原消息，不迁移或重发。实体及头像的准备、确认、不可用和未知在原投递详情可查，与正文已送达分别表达；原不确定写入不重放。恢复只沿同一 Binding、消息、作者和资源的原回执与相关变化推进，不扫描历史或建立第二份队列；已有头像可直接呈现时不为可选补齐另行创建实体。

飞书和 Discord 各自实现共同协议的公开消息、进度、问题／答案、工具权限交互、生命周期与获准资源，按本平台原生能力采用可辨的卡片形式。原生布局、交互回调、上传及字符／资源限制归各 Channel；共同层只传递原事件、内容、动作和回执。卡片回调消费原请求、准确成员和独立 answer／permission 授权，不能作为本地人类直接提交。当前需要的公开交互不得以未实现占位或静默丢失代替；真实平台／Provider 边界保留原内容、未知事实和准确恢复路径，不能冒称等量支持。资料、群改名和其他元数据事件只更新对应原对象；群详情及关联入口联动呈现新名称，群 ID、绑定、授权及会话保持原身份，断线恢复和显式刷新仍可重新核对原对象。

### 外部问题与权限决定

桌面与外部入口操作同一原问题，原 owner 核准确请求和当前权限，不能按卡片状态或普通文本猜答案、权限决定或完成。机器人聊天授权、平台本人发言、账户工具与远程权限批准分别成立。既有私有上下文接入群须明确分享授权，本地正常对话不依赖外部授权和投递是否可用。

Provider 已声明可直接回答的异步原生问题，外部原生表单沿同一个 Core question reply 入口，保全原 source、record、question IDs、Run、前驱输入及完整答案。当前每问按原协议单选或自填，多问在一次明确提交中交付；协议未声明多选时不自行扩张。已定位到原问题但答案缺项或无效时，原入站回执明确为答案校验未通过，并在原交互处提示纠正；不能误报不支持或权限变化。尚未 claim 的有效原卡片保持可填写，纠正后的新明确提交沿原身份处理，旧拒绝事件不自动重放。校验提示不授予回答资格，也不能重开已 claim 或结果未知的表单。准确 actor／应用／群与当前 Binding 修订的 answer grant 独立于 input 和 permission，平台按钮或回调不自行授权，不能伪装成本地 human 输入。原 action、授权与问题输入回执分别保留；“已提交”不代签原生采用或完成，未知只查询原操作，不重发或重开待答表单。原请求没有可寻址 responder 时，外部与本地保持同一真实能力边界，保留完整原问题、选项、准确不可用原因与原 Agent 入口，不展示无效回答按钮。

已具备准确开放 responder 的原权限请求可独立接入外部决策，不能冒称已支持原生 question。permission 的预选、明确保存、应用默认与本群覆盖沿[群入口与成员访问](#群入口与成员访问)；实际决定仍绑定准确 actor／应用／群、当前 Binding 和有效授权来源修订。input／answer grant、入群、接入或普通 publication scope 不授予此能力；未获上下文分享授权、原回调已关闭或平台映射未确认时保只读及准确本地入口。完整 expectedRequest、原 actor、授权来源修订与 operation 在原 owner 保全，跨进程仅沿原 authority seam 核原 claim，并在真正 Hook／ACP effect 前复核当前权限；未知仅查同原操作，不转 prompt 或重放 Hook。真实平台、原生采用与 question 资格分别验收，不由另一项能力的成功代签。

外部权限与问题卡响应沿原托管 Host 冻结的准确执行 Runtime、绑定、成员授权和原动作身份核对。托管端与执行端分离时，执行端回查原托管 authority，不能改查自己的本地入站或信任调用者声明。原 claim 与执行回执分别成立；恢复候选只指向需核对的原动作，只有准确原执行 owner 确认尚未开始且原授权仍当前，才接续原操作；未知副作用保持查询，不换身份、请求或执行端重放。

## Host 常驻托管

已启用的连接器由其准确托管 Host 常驻托管，App 只承担配置、确认和阅读；关闭窗口、退出 App 或最后一个客户端断开不停止连接器、清除绑定或撤销成员授权。本地与远端使用同一 Host 组合及收发 owner，远端 Core 经本机 App 代理执行不能代替远端独立托管。Core 仅消费通用连接、对话和授权端口；平台 SDK、卡片、凭据解析和缓存留在连接器与 Host，不能将 Electron、React 或具体平台依赖反向引入 Core。

接收连接、事件耐久保全、Core 输入与平台外发是四种独立事实。接收器沿准确托管 Runtime、原 Connection 与配置修订维护寿命；SDK 正在原生重连时，Host 接续同一恢复，不竞争重开健康连接。SDK 明确结束后，原 Host owner 承接可恢复的接收寿命；原平台拒绝仅说明那次尝试，不改写授权或成为永久门禁。后续明确恢复可沿同身份重新核验平台已修正的条件，不要求先修改本地配置修订。接收恢复不重放未知输入或平台写入，不启动、停止或替换 Agent。

接收观察保留原 owner 产生的接收器引用、当前阶段、有限原因及原协议已排定的下一尝试；它与原消息接收、采用及投递回执分别表达。没有业务消息不能判断失联；物理连接 OPEN、HTTP 认证正常或旧消息成功不代签当前长连接活性。原 SDK 没有提供的最后心跳时间不补造。单次握手与心跳回应预算仅约束准确物理接收器的原协议观察，超期驱动同身份连接恢复或保留未确认，不判定 Agent 死亡，不扩为 Core 输入或整批消息总时限。启动前必要的只读认证与接收身份 HTTP 观察也须沿原读取 owner 可取消地结束等待，每个准确资源独立取得观察窗口，不给整个启动或重连寿命套总时限。取消只释放该次启动观察，由原接收 owner 沿同配置重新核验；迟到结果不得继续旧启动、替换后来接收器或取消其他消费者的读取。观察失败保留原身份及已有健康能力；原生错误只沿准确协议事实分类，不解析任意异常文案。

原用户／设备可沿准确托管 Runtime 的既有管理权限明确恢复原接收器；Agent 的消息回执读取资格或知道接收器引用不授管理权。动作在原操作日志先冻结 Connection、配置修订、原接收器引用、操作者与 operationId；重复同一操作只查或加入原恢复，旧引用不关闭后来健康的代次。健康连接无需旋转，SDK 正在恢复时加入同一恢复；尚在凭据或初始 HTTP 观察、没有可确认原引用时，只能加入该观察或保持未确认，不能猜测已可重建。原操作结果与当前接收观察分别可查，取消查询不取消已获准的恢复；服务关闭、配置替换或托管 Runtime 不匹配只拒绝本次不准确动作，不自动启用服务、改用本机或改变 Agent／绑定。原平台拒绝后，新明确操作可在同配置修订上重新核验原身份；旧操作重查不发第二次核验。

Host 从原持久配置、授权、入站记录与 Outbox 恢复群收发及已配置的 Mote 私聊，原读取、会话选择、配额与 Agent 创建继续使用各自唯一 owner；不依赖某个窗口曾打开、预先解密留存内存或 Desktop 回调仍在线。Host 正常停止仅释放自己的接收、观察和存储资源，保留原 Agent、Run、消息和未决操作。局部凭据、平台或读取故障分别可见；凭据确实缺失、原私有存储读取不可用及原格式尚未交接分别投影为有限安全原因，不因未取到可用值就声称凭据不存在，也不透出凭据值或原异常。故障不能阻断其他连接或健康本地输入，也不把当前服务故障误作旧操作未执行。

SDK 客户端、认证缓存及其维护计时器归原连接器的活跃配置消费者持有，不随 Agent 数量复制。连接明确停用、删除、替换凭据或 Host 关闭时，释放已无消费者的缓存与 SDK 维护计时器；同一平台实例仍有其他消费者时保留共享客户端。资源回收不取消已经获准且在途的原请求，不改变已保存操作回执；迟到调用可以完成本次工作，但不得为已退出的消费者重建长期缓存。没有实际使用的平台适配器不因清理而加载，观察失败只影响本次缓存留存判断，不阻断原已获准调用。

连接器托管 Host 与绑定中的 Agent 执行 Host 是两种身份：既有本地连接器可以绑定远端 Agent，选择远端会话不把原连接器或凭据搬到远端。已有跨 Host 绑定保留原托管 owner、执行路由、身份、授权、读取起点与未决操作；原执行端点或授权确实不可达时保留引用并准确说明，不能猜测删除、自动重绑或用同名 Host 顶替。

跨 Host 入站在原记录和输入中保留准确托管 Runtime 与执行 Runtime 的来源关系；Host 别名只在各自配置内寻址，不充当跨 Host 身份。执行端沿已有认证连接回查原托管 owner 的原记录及当前授权，核对准确 Runtime、当前实例和本次原意图，再将原执行别名映射到自己的本地 Session。单向连接可用不证明反向授权读取可达；缺少准确路由、来源未确认或授权被撤回时，只影响相关外部输入，保留原请求、等待引用及健康本地输入。重开和继续使用原日志中的来源，不用新地址、当前同名 Host 或消息声明替换它，也不将原授权快照变成永久许可。

常驻 Host 读取自身已有的准确 Host 配置并持有相应认证连接，沿原配置 owner 接收更新，不另存一份路由清单。已确认 Runtime 的路由才能参与跨 Host 处理；首次身份确认仍由原配置管理入口完成。配置正常原子替换后，相关读取连接随之收敛；坏读、暂时不可达或观察失败保留已确认客户端与健康本地能力，并给出可恢复的有限原因。明确删除一个配置仅释放它的读取客户端，不停止其 Run；反向路由分别由各 Host 的原配置和认证成立。

设置中管理连接器时明确显示托管 Host；凭据、配置、原操作检查和资料读取沿同一准确目标。已经开始的保存、扫码或资料更新保留其原 Host、Runtime 身份、操作与输入；切换 Host 或重新打开页面不迁移请求、不清空草稿，也不将迟到结果用于另一目标。原 Host 暂不可达或同名端点更换身份时，只说明该操作未确认并保留原检查入口，不自动回到本机或另建操作。

## 凭据存储与格式交接

配置、资料缓存、原绑定与收发回执属于准确托管 Host 的原连接存储；同机接管保留原路径和全部原身份，不建立 Desktop 与后台两份可编辑数据。远端管理明确目标 Host，不借本机路径、焦点或 Session 显示别名复制凭据或扩大权限。凭据直接保存于该 Host 的私有连接存储，复用原事务及操作回执，并用仅当前用户可访问的目录和文件权限保护（具体权限见[Host 凭据存储](../../../apps/host/credential-storage.md)）；这是受权限保护的明文存储，不冒充静态加密。本地与服务器采用同一路线，不依赖 Electron、系统钥匙串、图形授权或另一个密钥服务。凭据仅由准确 Host 解析，专用写入入口使用原已认证的 Unix、SSH 或端到端加密通道及原用户／设备身份；普通配置、查询、诊断、审计、日志、命令行参数与环境变量不含凭据值。凭据故障只影响相关操作，不阻断健康 Agent。

旧凭据的格式交接只在用户明确授权后执行，由准确原私有解密 owner 沿原格式的原生提供方一次性完成；系统要求新进程授权时由用户完成，不绕过授权或自写解密。正常 Host 仍只读现行格式，不增加双格式解析、兼容 owner 或自动 fallback。交接前保全原数据库及其必要侧文件的可恢复备份，在同一原数据库、原 credentialRef 与 operationId 上原子转换，核对期间保留原密文和原请求；失败或提交确认未知时保原操作及可恢复数据，先核对原结果，不另造凭据或盲目重做。交接不改机器人、群、绑定、成员决策、读取起点或未知副作用，不要求用户手动导出或复制 AppSecret，也不生成单独的明文凭据导出文件。完成事实须由原转换回执、独立于原进程内存的同引用读取与可恢复备份验证共同确认，不要求为此重启现用 Host，也不以配置可见、新存储可用或新建合成数据代签。未获授权或交接尚未验证时保留原在用 owner 和现存连接的准确未完成说明，不能以不可读的新 owner 替换它，也不阻断独立实现与健康 Agent。

转换前的备份保留原加密字节；删除旧钥匙串项前还须保全并核验当前 codec 可读取、可恢复的转换后备份，两者均沿原私有权限保护，不作单独凭据导出。转换验证后，才可判断是否删除准确归属且已无依赖的连接器专属钥匙串项；不按应用名称猜归属或批量清理。Browser、其他持久数据或可恢复备份仍依赖该项时保留，依赖尚未确认也保留并说明原因。删除不得破坏原浏览器资料、身份或备份恢复路径；正常连接器收发不再依赖该旧项。转换、Host 接管和钥匙串清理分别报告实际结果，任何一步未知都不冒充全部完成。

Desktop 通过 `AGENTMUX_DESKTOP_USER_DATA` 显式选择独立 profile 时，原 Connection 数据库、原凭据记录、群绑定与操作回执归该 profile 的 user-data 目录；启动预热、自动收发和原操作恢复只消费该 profile 的连接库，不读取默认连接库或解析其中的凭据引用。未显式指定时继续使用原用户目录下的连接存储；不搬移、复制或清空既有数据，不另建 owner。该边界限定本地存储及引用归属；具体凭据存储与旧格式交接见本节上文。已选 profile 的凭据访问仍沿原 Secrets owner、原授权与就绪事实，不因切换 profile 扩大读取范围。

打开或刷新身份目录及发现能力只读取非敏感元信息，不为探测凭据可用性读取私密存储；扫码、私密账号或凭据操作才沿原 Secrets owner 按需访问，正常自动收发所需的原凭据访问独立保留。

原凭据访问等待或失败不阻塞 Host、客户端公共服务与健康 Agent；原存储不可用时保留原始字节、凭据引用及操作身份，原结果查询仍可达，只拒绝本次尚未确认的凭据操作。

## 群状态、诊断与恢复

群连接的观察与恢复复用原 Host 和 Binding owner：连接器已有的重连、原回执核对和等待处理自行收敛，客户端不另造发送队列或重试事实。展开当前群时自动读取有界原观察，读取不重放原输入或未知外部写入；查询失败保留原内容和已有能力。需要用户改变的明确设置采用就地、具名的一次操作，简单可逆动作不增加确认层；用户主动暂停、关闭及原成员授权不得由自动恢复改写。展示不得把历史缺口或一次查询失败升级为整条链不可用；首层信息组织见[群聊连接入口](../presentation/conversation-mode.md#agent-群聊连接入口)。

### 群状态与成员活动

平台标题浮窗是准确绑定群的状态阅读面。首层说明当前连到哪个群、原接收连接状态，以及最近原入站、出站的时间和结果；收到、输入交付、原生采用、平台递送与处理完成仍沿各自回执区分。时间只消费准确原消息或操作的记录，检查时刻与缓存更新时间不代替最近收发；本地落盘的原平台回执观察时刻标为“确认于”，只有平台原记录确有发送时刻时才称“发送于”，后续核对不刷新原确认时刻。没有取得记录说明未取得，不推断从未发生或断线。正常状态不要求用户手动检查才看见这些基本信息，确有故障时沿原 owner 提供准确恢复或设置入口。

成员身份、平台群角色、Agent 请求／答题／权限决定授权分别消费原成员、资料与授权 owner；群管理员不自动获得 Agent 权限，已观察发言人也不冒充完整群成员名单。每人发言数绑定原群、来源和明确统计范围，有限已读窗口不能冒充全历史总数，未知不能显示为零。成员列表与统计缺口保各自范围，失败不遮住已确认的其他信息。轻浮窗与群详情共享原观察和组件，按可见工作面读取；不因增添时间、人数或分区另建正文镜像、统计账本、逐行轮询或权限判定。

原群详情与紧凑摘要消费同一接收观察：当前接收器或 intake 缺口优先于此前已成功的消息，原 Core 输入仍在等待或未确认时保留其独立原动作；接收器健康不能代签输入采用。明确恢复冻结同一观察中的配置修订、接收器引用及原托管目标，未知回执先查原 operation，明确续接仍用相同完整输入与 ID，不因重开详情或默认 Host 变化换目标。客户端关联保存失败不新增管理权限门禁，保内存原请求并说明关联未耐久、可复制原请求；不得承诺本地写入失败后进程死亡仍能自动找回未知 ID。

群活动的原因、观察缺口与原动作沿[同步覆盖与原故障诊断](#同步覆盖与原故障诊断)消费，不另解释恢复资格。

### 标题栏与群详情

Agent Conversation 的共同标题栏为当前已接入的外部 channel contributions 分别提供紧凑入口，不以已有 Binding 为显示前提；平台自动收发与独立入口显示只沿[原平台设置合同](settings-and-observation.md#外部对话应用接入)，不把 contribution 当作启用配置。已保存群关系与原创建意图按所属 channel 保留，全局自动同步关闭、Binding 暂停或观察未知不隐藏管理与核对入口。只有准确托管 owner 对当前 Session 的关系读取已确认且无绑定时，才表达未绑定；读取失败、缺 owner 或原结果未知不当作没有群。原进度继续沿准确 Host／Session、Connection 与原 operation 核对，已绑定时直接查看原群和加入路径。同一 channel 有多条原关系或待续接请求时明确选择，不按首项猜目标。新 channel 的默认选择仅作用于没有原引用的新入口，原草稿、应用、绑定与未知申请保准确归属；切换 channel 不把一份草稿套给另一平台、覆盖输入或派发第二笔原操作。点击只恢复原上下文，不重新建群、重放未知操作、自动启用服务、保存共享、生成入群链接或授予权限；不因新入口换掉原 owner。入口复用原贡献、意图与事实 owner，不在 header 新建配置或状态 Store，也不从图标推导启用事实。

标题栏仅给紧凑图标与有限异常提示，完整状态和长错误留在原展开面，不占据 Agent 标题或输入空间。状态类别由准确原配置与有界诊断的类型化事实推导，区分未绑定、同步关闭、共享暂停、观察未知以及来源或投递需要核对；不能把不同缺口都压成一个 Needs attention，也不能从展示文字反推类别或控制资格。类别仅用于呈现，不新增健康状态或业务事实。原面板首层说明当前 channel 的准确群关系、独立的收发观察和可做动作；未绑定时以选择或连接群为当前任务，原 owner 未确认时说明缺口并保留原核对／设置路径，不能用一个泛化失败或笼统“已连接”替代这些事实。状态摘要复用准确原 Session／Binding 的既有有界只读诊断，区分绑定和同步配置、当前来源读取与平台投递、共同对话收录与 Core 提交及原生采用。群名、图标、配置开启或 transport ready 不能单独说明双向收发正常；本次来源缺口与旧未知投递分别可查，空窗口不推断断线。状态是一次检查快照，明确最近检查时刻及其成功、部分或失败结果，并保留手动刷新；该时刻不冒作最后收发或采用时间。初次可见、打开原菜单和明确检查仅核对当前可见准确目标，复用原失效与刷新入口，不增加全局轮询、后台健康 Store 或可写 ready 标记。读取失败保留同一原群、名字／准确标识、早先已知结果及可用动作并说明当前未确认；换目标、来源或修订后，迟到检查不污染另一关系。检查不改授权、共享范围或服务配置，不重放未知操作。

标题栏、展开摘要与群详情沿同一准确群关系逐层展开。群详情先辨认原群、原 Session 与机器人身份，再分别说明“对话 → 群”和“群 → Agent”的范围、检查结果与下一步；配置与成员资格不冒作任一方向的收发回执。成员访问、共享和加入各有直接可达的原动作，已有信息不以完成前一步为查看门禁；长诊断和原回执按需展开。全局自动同步、机器人启用、成员发请求授权及原消息回执仍消费各自 owner，各区直接说明已确认事实、未知与准确下一步。创建群、加入群、关系保存、配置打开与真实消息送达互不代签，不能以一个“已连接”或完成步骤让用户推断整条链可用。没有查到当前绑定时，保留原群与请求并提供原绑定的确认或核对入口，不猜另一 Session、不重建群、不把有界空窗口当作全历史未执行。

群详情首层的主动作只消费原接收器 owner 提供的准确能力：接收连接真正已结束且原控制允许时，主动作沿原接收器重连；已有自动恢复或准确排期时只检查进度；结果未知时只读检查；接收在线而来源暂忙时，沿原发布 owner 提供的准确恢复能力接续。仍需人处理的准确输入等待，检查原回执后沿原控制继续。

成员数量只按实际读取范围说明，不把局部成员页或已授权人数当作群成员总数，也不从邀请对象或登录账号猜本人。Binding 的 active 只表达原范围内的本地共享授权，不能单独成为已经可群聊的结论；本次尚待绑定、加入、启用同步、授权或核对的动作在原任务面就地可达。

全局同步开关复用设置中的同一 Connection 服务业务和原操作回执；群详情中的明确开启动作先说明影响所有外部机器人，由用户选择并确认，不因进详情或完成绑定自动打开。机器人启用、共享确认和具体成员的发请求授权仍是各自准确操作，不能由一个按钮静默串联。保存只更新对应已确认事实；输入与外发继续依原回执核实，未知沿同一 operation 查询。

原接收、Core 输入和平台外发分别按原记录确认，空的投递读取窗口不证明全历史没有消息或平台可用；没有新获准内容时不自动发送测试消息。原群、共享起点、成员授权与未知操作在查询失败、离开和重开后保留，不为补齐状态重新建群、替换身份或重放。

### 同步覆盖与原故障诊断

来源读取的显式恢复沿同一 Publication owner、当前授权与原发布范围，唤醒或加入已有的发布工作，不把只读检查称为恢复。输入触发规则修订后仍解析到原发布边界，保留原耐久切点；不能唤醒同名但已改变共享范围的后继关系。请求只表达准确的 Connection／Binding 修订，不以诊断指纹或逐个游标增设门禁。恢复回执区分三种结果：加入已有工作、发起新的唤醒、因停用或当前范围不再授权而不执行（回执值见[Connection 公共协议：投递](../../specs/connection-protocol.md#投递)）；这些回执不表示来源已就绪或平台效果已确认。恢复不另建持久状态、队列、计时器，不重建 receiver、不取消其他 Provider 读取，也不重发可能已施效的消息。本人准确 Session 的托管调用与原 Host 操作者复用现有范围和当前 Runtime 授权，不以机器人创建者身份另设门槛。

诊断须能在原权限内把准确原消息及版本、来源读取边界、共享资格、Outbox 操作与平台回执对应起来，分别说明未进入共享范围、来源不可读、尚未产生发送操作、发送中、已确认及原结果未知。来源读取失败与平台副作用状态分别保留，旧未知发送不得覆盖本次读取失败；没有待发项不能代签同步完整。原记录和读取边界的安全关联通过现有公共 diagnosis 提供，私有路径、正文、密钥、完整游标和任意异常文本不进入跨会话诊断；需要比较时使用原 owner 产生的有限机器事实与不泄露内容的稳定引用。

原来源读取断点沿既有投递列表的显式证据查询取得，权限仍归准确托管 Host、原 Binding 与受众的既有只读授权。Publication 在记录来源观察时配对保留当时的 checkpoint；查询返回该原观察及与其 checkpointKey 一致的 opaque checkpoint，缺少原配对则返回未知，不能事后读取当前 frontier、借历史内容 anchor 或建立新起点补造。默认列表、恢复接纳回执与跨会话脱敏诊断不增加断点披露；证据查询不推进读取、不恢复来源、不重放效果、不扩大共享或权限。证据只说明原 owner 已记录的观察；重启或尚无相关读取时保持未知，不以这份诊断观察冒充跨重启耐久历史。

诊断的外发窗口从最近的原操作开始，按该绑定与版本内的耐久记录顺序有界读取，沿同一顺序的原游标查看更早回执；不按显示时间猜最新，也不为看最近几笔扫描整段历史。最近的成功不抹掉较早的未知操作或来源缺口，窗口为空不证明所有消息均已同步。

第一方投递详情沿准确原记录的完整公开回执消费 owner 给出的可续接来源，不从诊断摘要、队列状态或原因文案重建资格。详情使用与本次原记录读取同次匹配的类型化来源；回复丢失时仍沿同一来源续接，客户端不另做资格检测或轮询。明确动作冻结原托管 Runtime、Binding／受众、operationId 及准确效果种类与尝试来源；丢回复、重开及当前来源变化不改写已提交输入，只有新明确点击才选择新的失败来源。只读核对说明当前原投递及可确认的最近接纳边，未匹配原来源不证明该边未接纳；明确继续仍重复完整原输入，由原 owner 查询或加入同一接续。读取只针对当前选中原记录，不为每行另开观察；离开或取消只释放本次观察，不取消已接纳业务。关联保存失败保内存原输入与可复制请求，不新增管理权限门禁；接纳、队列与平台效果仍分别表达。

来源同步故障的诊断位置须直接提供原发布 owner 的准确恢复操作，并与概览共用同一动作及未决反馈；恢复不依赖用户先暂停再恢复共享，不改变原共享范围、耐久读取起点或未知投递。刷新诊断只更新观察，不能代称恢复；恢复请求接纳或加入当前工作不代签读取恢复或平台送达。

发布续读的诊断须保留 Core 已分类的读取繁忙、字节预算不足与临时窗口失效等安全错误码，分别说明本次来源观察，不能只剩无法区分的来源缺口。同一原来源的临时阅读窗修订或续传策略冲突沿窗口／游标原因表达，不冒充来源身份改变。恢复沿原读取位置和完整窗口的续传合同进行；临时失败不跳到最新、不漏掉尚未共享的公开进度与回答。读取预算只约束本次工作量，不能让同一合法原消息在没有恢复动作的情况下永久停留；窗口完成与平台送达仍分别确认。 群诊断须沿这些有限类型说明准确影响范围与原动作，不能据来源观察判定长连接断开或 Agent 死亡。机器人级 intake 检查缺口可能来自其他群或较早事件，不覆盖本群已确认的原输入结果。未记录更细原因、公共诊断未提供该原因、本次读取失败与保留的较早观察分别表达，不从文案补造权限、格式、作者或失败原因。原输入写入终端仍不等于原生采纳；较早效果聚合未知且当前窗口没有对应请求时，沿原游标和准确 operation 检查，不自动扫描或重发。原内容缺口不授予补发权，明确续接仍只消费原 owner 的 source／ref 与当前授权。

群诊断默认以收、发结果和必要下一步说明，技术回执按需展开。复制只包含准确应用、群与 Binding 修订的有限只读观察，明确窗口、后续页和未取得的事实；正文、成员身份、凭据与原生载荷不进入诊断。一次复制不是原子历史签收，离开、换目标或取消后不交付迟到结果；检查和复制不重试任何收发。面向准确 Host／Session、可选原 Binding 的公共只读诊断与界面复制共用 Core 的脱敏投影；托管调用保留原身份，诊断不扩大原配置、私有安装或成员授权的读写资格。Agent 还可通过既有 delivery 列表与详情读取准确本人 Host／Session 原绑定的无正文投递回执，不要求本人创建机器人或绑定；读取核对不可变的原 Binding 修订、Connection、应用和群，历史回执不依赖当前绑定头或当前共享开关。读后仍核验原调用身份与 Runtime owner；这项只读资格不授予跨 Session 查询、私有 Mote 记录或管理写入。本人 Agent 的明确重试复用同一原绑定身份核验，不要求由本人创建机器人或绑定；重试保留原 operationId、身份和受众，提交前再次核验原调用者与 Runtime owner，由原发布 owner 判断当前绑定仍授权且原消息明确未施效。资源上传未知而消息尚未尝试可沿原操作明确恢复；消息可能已施效时仍只查询原结果，不重放。各区独立说明服务、接收器、绑定范围及授权计数、原投递与 Core 输入状态；读取失败不伪造空集合或完成。入站按准确原生应用和群读取有界最新窗口，保留原游标与更早页说明，并区分接收 Connection 与输入目标 Binding；不能被本地别名或未 claim 记录遮蔽。Core 等待原因仅来自原输入回执，正文、原生载荷、凭据、成员身份及任意错误文本均不进入投影。原管理接口因创建者权限过滤的空列表，不作为目标没有群的证据。

托管 Agent 可从上述有界诊断取得准确 ingressId，再沿既有入站详情读取本人原接收事实和原 Core 回执，不要求本人创建机器人或绑定。已有输入或群接收目标的冻结 Host／Session／Binding 关联优先，只有准确本人原关联可读取相应回执；明确属于其他 Session 的记录不因同一应用或群变为可读。尚未归属的 action 可按本人当前未解除绑定的准确原生应用与群受众读取其已有类型化事实，包括未 claim、拒绝或未知的记录；这份受众读取资格不生成输入目标、Session 归属或回答资格。读取先核准确原记录的范围，再观察其 Core 回执，读后保原调用身份与 Runtime owner 核验。找不到准确关联或受众时保留未知及原记录，不扫描全群历史猜所属、不把接收 Connection 别名当作受众，也不因共享暂停或服务关闭删除本人已有读取资格。该路径不扩大一般入站列表、authority／record-authority 或管理操作的资格；列表仍表达其原接收 Connection 与冻结绑定过滤合同。入站详情保现有类型化事实，不输出原生载荷或凭据；actionRef／answers 缺项不说明是选择还是提交，不能从显示文案补造原生动作。

临时断线和来源读取故障由该准确连接沿原读取、观察及耐久起点恢复，不依赖用户切换页面、再次发言或手工修改记录。恢复不替换冻结输入、重放未知副作用、扩大共享或用新快照成功补签旧缺口；来源真实变化与无法补齐的原范围明确保留，并继续处理具有独立来源和授权的内容。观察句柄存在与其原生来源监听可用分别成立；原生监听不可用时保留已可读来源及耐久进度，仅重接受影响的原观察，不能被一次成功历史读取改判正常。 观察器关闭、读取繁忙和原生来源／边界变化分别表达；关闭事件保留已知原故障类别，没有原来源核验事实时不得改报来源变化。恢复继续使用原已接受来源与耐久读取起点，新的尾部读取成功不补签原共享范围完整。后台成本随活跃连接及其相关原记录增长，关闭或禁用本连接后释放相关观察与恢复工作，不扫描无关 Session。 待答问题刷新沿原发布日志定位候选问题，并核对同一绑定版本、同一投影是否已有后继；已回答或撤销的后继仍遮蔽旧待答记录。结果条数有界不能代替底层扫描有界，不因无关普通消息历史增长而每轮重做全历史分组；保留候选历史本身的实际成本，不另建问题状态账本。

### 原生来源被原地重写时的接续

同一原生来源被 Provider 原地重写，与换文件、换开头或换成另一来源，是两种不同的事实，分别表达；对应错误码归[对话协议](../../specs/conversation-protocol.md)。发布（Publication）不等用户操作，沿原 Binding 与耐久切点自动尝试接续，但只有原消费边界有足够的来源证据时才能继续。记录 ID、内容摘要或孤立位置相同，都不能证明中间没有新增记录；短样本校验、物理位置和由位置派生的记录 ID，也不构成完整前缀或已消费身份的恢复证明。

接续不靠按孤立记录锚点跳读来恢复。自动补齐由 Core／Provider 保留与共享起点同次观测的原范围证据，先固定本次完整读取范围，再核对原 Publication／Outbox 的完整效果身份与关联。已知的重写不能把共享起点之前的记录移进获准范围；核验按有界页进行并耐久推进，重启后继续同一范围，不持有整段同步事务。

能够证实原范围与旧效果的关系时，自动补发当前获准范围中尚未产生公共效果的公开记录。缺少旧范围证据时，提供精确冻结范围的审阅，只有原用户／设备可以另行明确授权；这份范围授权不解除旧的未知效果被重复的风险。审阅固定原 Provider 与原生 Session，按页展示候选公开记录与资源、被排除的内容及旧效果的身份缺口；确认绑定同一原身份、修订与范围摘要，确认回复结果未知时沿同一原操作查询。一次历史范围授权与后续共享起点分别保留：后续起点只能从同一份封存观测的范围终点建立，不能把一次从零审阅历史变成对未来重写历史的无限授权。

恢复重放不重排已有的回复指标与结果事实，不降低已确认消息的元数据；新回复可以沿其自身的直接来源补充指标。接续只覆盖原授权范围内的后续记录：已投递的平台消息不重发、不撤回、不改写；因重写而消失的已接纳记录保持原回执，不冒充新投递。独立的 captured 来源中可确认的进度与已准入的 Outbox，不因原生来源缺口而停止。

缺少可核实的完整原边界、无法证明边界或来源已被替换时，保留原切点、原身份与来源缺口，明确展示原因及可达的恢复入口；不自动换源，也不从最新位置补签缺口。原切点的普通读取按相关来源有界地重新观察，原来源重新可核实时即可恢复；这不执行锚点搜索、整段扫描或外发重放。暂时读取失败仍可重试，显式恢复也只重新读取同一原切点。接续不得重播未知效果、影响健康输入或扩大共享。

正常同步读取不因接续证据变慢；接续的读取与验证成本随相关事实有界增长，不因无关 Session 放大，也不占用读取资源阻碍健康输入。

### Mote 私聊的接收与诊断

Mote 私聊提供针对准确原 Mote 目标的公共只读诊断，沿原 caller 认证、目标读取边界及托管 Host 核对保存开关、原路由 Connection、安全配置与服务／启动能力、最近有界 direct 入站、准备阶段和原 Core 输入回执。读取不到或窗口为空分别保持未知或未观察到，不把群正常、用户曾保存、配置开启、进程存在或字节确认代签私聊已受理、Agent 采用或处理完成。诊断只投影必要的安全身份引用、阶段与有限原因，不输出正文、人员或创建者身份、额度人员名单、私有路径、秘密或任意异常文本；不借诊断开放被拒的管理读取、私聊历史、配置、Agent 创建或重试权限。输入处于等待时，诊断沿原 Core 回执显示控制状态、观察归属以及有限的等待阶段、原因和唤醒条件；没有等待细节明确表示原回执未提供，不能从状态名推断正在处理或需要用户重发。准备步骤失败的有限类型错误码沿原入站／创建观察及 Core 等待回执保留，使执行器、资源、创建、待答交互、原输入占用及来源读取未确认可以区分，不因被接收器捕获就只剩通用检查失败；未分类错误仍给安全未知原因，不从文案猜类别。失败码仅解释原观察，不能代替当前权限、交互、Run 或投递回执授予恢复。 原目标校验失败时，同一有界诊断可沿原输入的准确 Session／Run 读取当前耐久目标是否仍匹配及原 Runtime 状态、类型化退出码；不以笼统错误码推断进程已结束或目标已变化。观测失败保持未知，不输出私有标识、终端正文或原生历史，不启动、接管或重试 Agent。恢复继续沿同一原消息、预留、Session 与输入核对，不重复计数、伪造来源、重放未知操作或停止健康 Agent；原私聊路由和额度语义仍归[Mote 外部私聊](motes-and-coordination.md#外部私聊与会话更新)。

终端写入确认之后，同一私聊诊断仍可读取冻结输入的原 Runtime 状态，以及所属原会话代次的有界回复来源、覆盖与投递观察。后者明确属于该代次，不能冒充某一条 query 已被采用或回答。仅投影安全阶段、类型化原因与数量，重复引用同一代次时复用本次读取；不开放原私聊标识或正文，也不以排障触发恢复、输入或发送。 输入终端确认、原生采用、正式回答产生与平台送达分别沿其原权威事实说明；缺少准确原输入或回合关联时，不能拿同一代次内的旧回答或已确认投递补签当前请求。已建立原生起点与本次原生来源可读分别成立：当前页的原生覆盖失败、来源变化或读取超时必须如实反映，不因捕获页可读、空页返回或已有游标而标成来源就绪。当前来源恢复与历史未补齐的缺口、未知副作用分别保留。

专属 Mote 私聊的首次输入与回复来源就绪独立：准确原创建、Mote 上下文、当前输入授权及 Provider 输入条件成立后，原消息沿 Core 输入 owner 接收，不以尚未出现的原生历史阻塞健康 Agent。私聊创建 owner 明确记录该专属新会话从起点共享回复的意图；真实原生来源出现后，由 Core／Provider 提供准确起点并交给原 Publication owner 持久消费，不能拼造游标、取稍后的最新位置而丢失首回复，或将来源未出现误报为已同步。专属新会话的原生来源发现与首次起点建立须在原身份上自行收敛，不能要求先有原生起点才开放发现该来源的观察。原生起点暂不可读时，保留原 owner 的准确类型化失败原因；缺少起点不统一覆盖为身份未出现。来源读取恢复沿现有观察和恢复机制，不新建队列、轮询器或第二份会话事实。普通群仍只共享明确冻结起点之后的原范围；暂停、撤销、身份变化及未知副作用继续守各自原边界。

选定 Provider 同时负责原生对话的增量读取，历史页可读或观察已开启不代表回复发布能力已成立。私聊回复沿同一原 Provider 的对话增量公共能力与已保留原生起点消费，不暗中切换 Executor，不以捕获的终端输出替代原生消息。Mote 诊断区分原准备启动中冻结的 Provider 与当前默认配置；尚未准备时保持未知，不用当前选择冒充原会话事实。

## 读取与恢复的成本边界

同一进程内消费不可变原对话页时，可复用 Core 已完成的内容校验；受控路由仅改写外层寻址、仍持有原内容和相同来源范围时，沿原读取 owner 保留这份校验结果，不重复复制正文。每个读取与提交边界仍核对当前请求的准确来源、范围、版本、读取意图和预算；路由包装先按原预算完成收敛。普通复制、传输后的数据及跨页组装的独立单位不能借用另一对象的校验结果；校验归属不延长页面寿命，不改变公开数据形状，不授予发布权限。

内容恢复扫描的工作量随准确 Binding 修订中符合原恢复条件的候选增长。缺少可读原对象的诊断 gap 继续保留在覆盖与历史中，但不扩大恢复候选扫描；原恢复顺序、分页位置、授权及未知回执保持不变。

连接器的卡片准备恢复只读取准确 Binding 与修订内仍处于 dispatching 的原准备；已确认、未知、明确未执行的回执和无关历史不扩大该查询工作。查询索引仅缩小候选范围，不改变原准备的状态权威：真实在途项保留，已无在途执行者的原准备只转为未知，不自动重发。

独立公开发言与资源读取按原内容部分分开推进。来源窗口已可读时，准确未解析部分作为可恢复缺口保留，不能因单条图片、文件或 Markdown 资源较慢阻塞同群其他文本和既有准备。恢复沿原 part、版本、受众及操作进行，观察并发预算限制当次工作量，不限制合法历史总量；停止观察不取消已开始的业务写入。逐条提交只查询相关未决部分，不因无关历史缺口增长而全量重扫。

Core 临时阅读面保留输入采用的必要轻量身份与冲突证据；正文窗口淘汰不抹掉已观察反证。证据按当前相关输入增量查询，正常历史增长不能触发全局、永久的采用未知，也不能把一个原输入的未确认扩散到同页其他准确输入。完整窗口未交付前不推进其接受事实；关闭原阅读面释放本面证据。公开事件只携带与本事件有关的原证据，连接器沿该作用范围生成反馈与原输入关联，不另建采用账本。

同一 Core Client 对同一 Session、相同调用选项的原生历史观察共享底层 Provider 观察（watch），每个消费者独立取消与释放；最后一个消费者离开才释放共享观察。共享层只持有活跃的观察资源，不缓存页面、来源事实或控制资格。确证来源变化或观察终止后，新消费者重新取得该来源的观察；资源终止只消费原 owner 的实际关闭事实，不从“不可用”错误码猜测。没有资源终止事实时，观察未知保留已有观察、已读内容与健康 Run，不扩散成其他消费者的取消。
