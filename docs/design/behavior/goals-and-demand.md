## Goals 的 Grill 与 Grounding

Goals 首先让人看懂要达到什么、还有什么关键取舍、接下来该对齐目标还是核验结果；持续 Goal 与执行 Session／Run 的身份保持分离。

用户不应先学习 Grill、Grounding、Mote 或版本协议，才能使用目标工作面；这些方法和身份继续支撑行为，主界面用普通语言回答目标是什么、怎样算成功、还有什么待决定、已有结果怎样以及接下来可以做什么。

每个阶段必须有可找到的真实入口，并让人预期点击后会打开原讨论、发送整理/核验请求，还是确认/接受所读内容；不能只替换方法名而仍让用户寻找入口。目标已确认而尚无结果时，原讨论是可继续推进的明确入口，已有的关联工作面也可达；结果检查留作有实际结果后主动请求的次级动作，不伪装成开始执行。

### 从探索开始

常用起步操作、目标清单与详情各有清楚主次。探索入口不要求先有 Goal、Project 或具体点子；起步不自动创建占位实体。

常用操作点击一次就发送所见完整请求并进入原对话，不附问卷或第二次提交。准备、入队和实际送达分别表达；一次在途点击不重复创建或投递。失败与未知保留原请求、已建立的工作面、健康 Run、执行焦点和布局；探索与显式 New Goal 的草稿创建分别成立。

默认请求限下述三句；角色候选未成为当前要求，不建立学生／工程师档案或角色配置。

默认常用操作为「我还不知道能做什么，可以了解我并给我建议吗？」「我有一些点子，我们开始尝试一个项目」「根据最近的项目情况，建议我下一步应该做什么」三个入口，学生、工程师入口移出本轮范围，不要求角色档案或角色配置。首两条不要求已有 Goal、Project 或具体点子；第三条只在可靠 Project 上下文存在时可用，点击前可见准确项目名，所发送上下文与之为同一对象。只有 current 来源时明确称当前项目，不假称最近。可见完整句子就是首发消息，点击一次即发出请求并进入真实对话，不在短标签后藏另一套问卷或多阶段指令。了解用户从轻量对话开始，不先要求填写兴趣、技能或身份字段；后续目标讨论继续由原对话 owner 承担。一次在途请求、失败与未知保留、原健康 Run/焦点/布局以及不先造空 Goal/Project 继续沿上述合同；不扩大为角色系统。

常用操作的完整请求、可靠项目条件、原对话、保存冲突与失败恢复沿本节；排版、宽窄密度和图形角色唯一见[《Goals 的目标正文与对齐密度》](../presentation/goals-and-demand.md#goals-的目标正文与对齐密度)。

常用操作支持持续整理：保留上述默认完整请求与可靠项目条件，支持用户以一句指令新增、引用已有指令、修改正文、排序、移出常用及收起更多操作。自定义正文仍由原 Settings Prompts 指令实体唯一持有，常用操作只持引用与排列/显隐；修改同一正文会影响其他使用入口，应清楚说明，移出常用不等于删除指令库内容。新增只需正文，名称可辅助生成，高级属性按需；管理编辑与排序不能发起 Agent。已展开或准备执行的完整正文在发送前可读，名称不能代替真实请求；一次点击发送所见正文并进入原对话，不暗附问卷、第二次提交或多阶段流程。适用 Agent 与实际匹配执行者必须诚实可见，实际执行者先沿本节主 Mote 原 bot 的已确认归属，符合指令适用范围时复用其真实配置；没有已知原 bot 时才沿既有启动选择规则，并明确显示实际名称；不匹配不静默代换。没有可用匹配执行者时管理仍可用、请求保持而不猜选。更多操作与模块本身可收起，返回、取消、移除及重排保留明确焦点，增加数量不能吞掉连续目标清单；不自动恢复已移除项或复活被删正文。视觉与图形角色唯一见 surface-density[《Goals 的目标正文与对齐密度》](../presentation/goals-and-demand.md#goals-的目标正文与对齐密度)，原 Mote、保存冲突、服务窗及健康工作面继续由既有 owner 承担。

### Mote 协调与已有授权

Mote 默认承担协调职责：意图或授权未明确时继续轻量讨论，不早建空项目/需求、不强制每轮创建；当一个可检验尝试、实际位置与授权足够时，先检查并复用已有项目和 Agent，需要新项目时建立真实目录及最小初始指令，通过原公开 owner 注册项目、建立或绑定 Demand，并把包含原意、真实上下文、交付与证据标准的任务实际投递给可用执行 Agent、记录同一真实 Session 关联。细设计和实现默认由执行 Agent 承担，Mote 继续讨论、组织、跟进与取证；用户明确要求亲自执行时按该授权。通用协调职责由 Mote 原署名启动 Notes 的单一 owner 持有，不能暗改可见 CTA 原句、只为某个按钮补隐藏流程、覆盖用户 SOUL/Wiki，或把普通 Topic/执行 Agent 改成协调者。项目注册不冒充目录/指令已创建，指派/记录/进程退出不冒充任务已送达或目标达成；用户仍决定目标与关键取舍，Grill/Grounding 的提案、人的确认及结果证据沿下述合同。能力、保存或投递未确认时保留讨论、实体及健康工作面，如实说明步骤，不能猜 API、身份或成功，也不能用直接配置写入代替未确认的公开能力。

协调职责在新讨论与复用已有 Goal 会话的实际请求中都可用，沿同一应用署名指令 owner，不只留在新会话启动时或要求用户重建 Mote。用户显式 New Goal 已保存的待定义实例应持续更新同一 Demand 的标题、原意与目标提案，不因「探索不早建空需求」拒绝该已存实例或另造一份。意图、实际位置和既有授权足够时，Mote 持续讨论并推进真实项目位置及初始指令、注册或复用、同一 Demand 绑定与其他执行 Agent 的实际任务；仅一轮 Grill 提案或自己包办细设计不算协调交付。公开帮助和实际请求应说明已支持的更新与发现、绑定、派发和回读入口，并按真实执行 owner 区分会启动/投递的 Desktop demand start 与仅写领域元数据的命令；一次未确认结果先读原回执与实体，不重复 create、start 或发送。用户的明确新建/实施授权与目标确认、结果接受仍是分别可读的事实，不借后两者反复索取已给的有限授权，也不替人认可。

公开帮助必须完整说明现有 Project 身份、需求写入的风险与授权参数及回执含义，不能让 Agent 按帮助仍无法完成已授权的项目/需求绑定。项目注册返回的 workspace 身份不能冒充 Project 身份，所绑定的 Project 必须来自当前公开发现事实；未知风险、待确认授权与用户已经给出的授权要清楚区分。补齐帮助不得放宽原风险/授权判据、替用户确认目标或接受结果，也不得靠隐藏 CTA 指令、直接配置写入或临时绕路弥补公开能力说明缺口。

### 清单、详情与当前下一步

用户进入页面、打开一个目标及返回清单时，都能沿同一目标读懂当前事实、下一步和动作结果：清单结论在详情里有对应的正文与实际入口，打开目标、继续讨论、发出对齐/核验请求和人的认可各有清楚语义。当前工作状态、目标确认与结果接受仍沿下述同一 owner 和边界，既有未知、差距、旧报告与恢复动作继续可读。已有目标的阅读与探索入口保持主次，进入详情后的临时收纳与返回不改变用户常用目录、未保存正文、搜索/筛选、目标身份与原健康工作面；收纳后出现的新在途、未保存、失败或回执不明事实仍有可见摘要，并可回到保留原草稿的同一入口。确认前成功标准与真实未决问题保持展开可读，不能让人认可未读内容；关键决定尚未解决与可确认保持互斥的真实状态。产品语义、视觉和交互分别按实际观察范围核对；评分是设计判断，不代签安装、模型行为或未观察场景。视觉约束唯一归 surface-density[《Goals 的目标正文与对齐密度》](../presentation/goals-and-demand.md#goals-的目标正文与对齐密度)。

常用起步操作、目标扫描与正在阅读的正文各有明确主次，不因装饰、重复说明或固定空栏牺牲可见的目标与结果。保留三句原始一击即发请求及其可靠项目条件、同一常用操作指令与未保存草稿、搜索筛选和原目标选择；排列变化不增加提交、不自动发送、确认或接受，也不重建讨论、工作面或健康 Run。成功标准、重要未决问题、结果依据、差距、未知和认可回执不明仍沿本节真实人类确认边界可读可操作。具体密度、对齐与图形角色唯一见 surface-density[《Goals 的目标正文与对齐密度》](../presentation/goals-and-demand.md#goals-的目标正文与对齐密度)。

- **Project 关系沿同一真实身份**。Goals 的项目筛选、属性选择与明确创建/修改使用同一公开 Project 身份，不能把内部 Workspace 身份当成 Project。一个项目及其 worktree 只形成一个项目选项，跨 host 的同名路径保持不同身份。已绑定但当前无法找到的 Project 保留原 ID、已有名称及关系，并清楚说明暂不可用，不自动换绑、清空或显示成未分配；用户仍可明确改选或清除。结果的本地证据沿所绑定项目的真实 Workspace 与原文件打开入口定位，不解码 Project ID 猜目录、不越过原路径边界，也不改动已有执行 Session、确认/接受及健康工作面。Project/Workspace 分层与分组真值继续归[《Project 与 Workspace》](spaces-and-layout.md#project-与-workspace)。

### 显式新建与专属讨论

- **显式新建直接开始目标讨论**。New Goal 一次明确点击就保存真实待定义的 Goal 草稿并进入它的专属 PMO，不再事前要求填写意图表单。草稿不虚构意图、完成标准或人的确认，以当前明确选择的真实 Project 作上下文，没有选择就保持未分配；普通常用探索 CTA 仍不先造 Goal/Project。讨论只整理和更新这同一个 Goal，不再创建第二个实例或项目，不启动目标的执行 Run。一次在途新建、短暂离开/返回及保存回执不明都保留原创建身份，不能重复造目标；只在 owner 已确认保存后进入 PMO，未知先读取同一目标。保存或 PMO 准备/投递失败就地说明实际失败步骤、已保留事实及恢复动作；已有 Goal、已建立的专属 Tab/launcher 和原请求保持，再试仍指向它们，不误称尚未建立的 Tab 已存在，也不停止健康 Run。优先级、日期、标签、批次、执行者与 Session 仍不是创建必填项。Agent 整理真实目标和标准，不虚构用户未表达的要求或查证不到的 Context，人工确认与结果接受继续沿原合同。

Goals 的 Work 导航归属、跨上下文打开和无唯一已知关联时不猜 Goal，只见[Work、Survey、Recall 与 Mote 的导航上下文](spaces-and-layout.md#worksurveyrecall-与-mote-的导航上下文)；下述专属讨论定义实体关系，不合并 Goals 与左下 Mote 面板的选择。

- **Goal 在主 Mote 中有专属 Tab**。主 Mote 的固定默认身份唯一见[《Mote 头像与主 Mote》](motes-and-coordination.md#mote-头像与主-mote)；New Goal 在这同一个主 Mote 内建立该 Goal 的专属讨论 Tab，各 Goal 保持各自独立的 Agent 上下文，不能把新 Tab、Region 或 AgentSession 说成新 Mote。原主 Mote 名称、目录、SOUL、头像、Wiki 与资料保留，不按 Goal 或 Project 复制 Mote 实体或人格；Goal 所关联 Project 只提供该目标的真实上下文，不决定另一个主 Mote 身份。已有 Goal 继续指向原专属 Tab，重入、重试与重启先保留并恢复同一 Goal/Tab/Region/Session 关系，恢复未知沿原服务窗说明，不借其他 Goal 的讨论冒充恢复。 同一个 Mote 目录不足以证明已经复用主 bot。常用探索、New Goal 与已有 Goal 的讨论都归原主 Mote：探索只在其中建立独立讨论 Tab，不新建 Mote，不提前造空 Goal/Project；New Goal 和已有 Goal 沿各自专属 Tab 与同一 Goal ID。新讨论沿原明确目标及已知 bot 的真实 Executor/Provider 配置，保原名称、SOUL、Wiki 和资料，不因配置顺序、产品名或活动项目静默换一个 bot；既有专属 Tab 映射的 Session 继续原上下文，不以复用 bot 为由暗中合并或更换这些会话。同一个真实提需或 PMO 对话可以创建、参与多个 Goal；默认 Supervisor 直接引用该准确来源 Session，不因此新建专属会话。专属讨论与默认指派是不同关系。明确指令的适用 Provider 限制仍成立，不匹配须可见，不另建每 Mote 偏好或身份名册。

已知主 bot 的事实尚未确认时，原主 Mote 的 launcher 内明确说明原 bot 未确认、请求未发送、完整草稿仍在同一 Region，以及手动选择 Agent 后启动的下一步。不能只把说明留在浮窗后，也不能把另一配置的默认选中态说成已复用原 bot；没有既有 bot 的首次选择和非主 Mote 的普通 launcher 沿各自原用途。已在运行的 Session 继续原上下文，不受新讨论的配置选择阻断。

同一浮窗内的主 Mote 卡片也沿已经保留的 Agent Region 表达事实：原 Agent 引用仍在、快照尚未确认时显示状态待确认，不能一边保原上下文、一边写「No Agent yet」。只有真正没有原 Agent 引用的冷启动才表示尚无 Agent；这条呈现不改变任何 Session、Run 或恢复动作。

PMO 请求必须使用所关联的真实 Project 与具体 Workspace 的身份、Host 和路径；Project 身份、Workspace 身份和 PMO 自身运行目录不能混称。所见项目与发出的上下文一致，未知、已删除或来源含糊时如实说明，不猜另一项目；用户原文保持。尚未分配 Project 是正常目标状态，不冒充关联失败或要求重试；项目相对文件引用保持原文，不借 Scratch 或活动项目代替其根。已经分配但被删除、失效或含糊的实际 Project 关联仍诚实说明。项目文件引用按原宿主、路径及项目根边界解析，`~/` 只有获得该 Host 的真实 home 才能展开，本机 home 不代替远程事实。没有既有变量 owner 时不许诺通用模板替换，也不对正文盲目替换 home 字符串；具体用户坏链接仍需按实际原句核验，不把尚未查证的原因写成已修复。

### 目标确认与结果接受

- **Grill 对齐目标**。一个目标的当前 Grill 结果是可阅读的目标摘要、稳定身份的成功标准与少量真正影响选择的未决问题；用户看过当前内容后明确确认，不能用完整 transcript、空模板或系统属性替代目标协议。Agent 可以从对话提出和更新方案；用户只提供意图、关键取舍和确认，不承担整理成表单的工作。来源对话仍可追溯，当前目标正文不重复堆历史聊天。没有标准或尚有关键未决问题时，如实说明尚未对齐，仍可继续讨论和使用原执行工作面。
- **Grounding 对齐结果**。每条当前成功标准都能对照真实结果、可打开或定位的证据与差距。Agent 自报完成、命令成功、Session/Run 退出、已有 done 状态与证据数量都不等于目标达成。缺项、未知、失效版本和没有依据各自如实呈现；未知不画成通过。普通「接受结果」只面向当前已确认且非空的标准、完整的当前检查和有依据的结果。已核实的差距可以由用户明确选择「接受结果，保留差距」；差距保留为差距，不改写成全部达成。缺项、unknown、空标准或无依据不能用这条动作绕过核验。旧目标已有 done 但没有对齐或证据时，保留旧实体与状态，同时明示缺失事实，不能伪装成已经接受。
- **确认绑定用户看过的内容**。目标内容或标准发生语义变化后，旧确认失效，旧 Grounding 标明针对旧目标；结果提案变化后旧接受失效。同内容重报不产生新版本或清除有效确认。确认与接受必须核对当前目标版本及结果身份；并发替换后不得认可用户没看过的新提案。只有显式用户动作记录确认/接受；Agent 身份的通用更新及 CLI 调用只能提交提案，不能自填认可时间或版本来冒充人已确认。已认证的人或设备通过原 `goal.confirm`／`goal.accept` 提交明确确认，仍核对同一准确版本和结果。认可时间与版本身份由 Demand owner 生成。
- **认可回执不明时先读当前事实**。确认或接受的保存回执不明时，唯一主要恢复入口是读取持久 owner 的当前提案；不能同时让正常确认、接受、保留差距接受或重试认可成为可操作捷径。清单与详情的当前下一步都指向读取当前提案；点击清单整行仍只打开 Goal，不直接读取或认可。读回后仍由用户看过当前内容再明确选择，不自动认可或读后重试。其他阶段动作不与恢复争抢主强调，讨论、核查请求与原工作面继续可用；目标、草稿和失败说明保留。回执不明不能被说成保存已失败或 Agent 已坏，也不依据错误文案猜分类。
- **少噪音、可收敛**。默认扫描当前目标的连续列表；可切换同一数据与筛选的横向看板，看板不能把状态列折成两层巨大空格。完成与取消按需查看，筛选可清除，选择和详情身份不因投影变化丢失。列表或卡片优先呈现目标、当前对齐事实和下一步；Project、执行状态等只表达真实次级事实。不保留一份左侧 Branch Board 清单再复制中心目标列表。
- **正文优先、属性渐进**。详情首屏是目标标题、意图/目标正文和 Grill/Grounding 的当前结论与明确动作。优先级、Project、负责人、标签、日期、父子关系、批次和关联 Session 继续可查看/编辑，但低频属性按需展开，空字段不制造填写义务；执行拓扑、活动和决策在相应区域可达，不挤成首屏系统字段墙。详情的视觉层级与密度只定义在密度 SSOT[《Goals 的目标正文与对齐密度》](../presentation/goals-and-demand.md#goals-的目标正文与对齐密度)。
- **普通语言说明当前事实与动作**。目标、成功标准、待决定事项和结果使用直接可懂的名称；Grill/Grounding 是整理与核验的方法，不作为阅读或操作的前置知识。尚无目标提案时，用户原始意图与一个澄清入口即可说明下一步，不把尚无提案、尚无结果画成两块失败区域；已有报告即使目标提案缺失仍可阅读材料，并明确无法按当前目标接受。目标已确认但尚无结果报告时，说明目标已达成共识、仍可继续当前工作，有实际结果后再对照标准核验；不能从确认推断工作已经完成，也不能把结果未提交说成失败。工作状态已是 done 但没有报告时，无论目标是否已确认都明确结果尚未核验。已有结果的差距、未知、缺项和旧版事实保持直接可见。
- **工作状态、人的认可与执行事实各有名称**。Backlog/Todo/Done 等是可编辑的工作状态，不代表当前目标已确认或结果已接受；默认清单优先一个当前待办或结论，工作状态在看板、筛选与属性中明确可达。正常阅读不要求比对版本号；只有目标变化、并发拒绝或查看历史时才需要解释版本所影响的内容。版本和结果身份仍由原 owner 持有，确认与接受仍精确绑定用户看过的内容。打开已有讨论与发送澄清/核验请求必须明确区分；简化文案不能把未投递说成已执行，也不能把澄清动作包装成开始执行。
- **对话入口必须真实送达目标上下文**。Grill 与 Grounding 都复用该 Goal 专属 Mote/PMO 工作面，携带当前意图、目标版本、标准及相关结果。已有 Agent 时也必须通过既有公开输入/队列入口提交本次真实指令；只打开旧 Tab 或改按钮文案不算进入对齐流程。没有收到、正在等待或投递未知时明示事实，不虚构 Agent 已整理。跨面切换、Mote 打开/关闭和重启继续沿既有 durable Tab/Region/Session 恢复约束。

默认 Goals 扫描和详情的工作量随当前可见目标、实际关联 Session 和相关新事实增长；不为每张目标挂载完整终端/拓扑，不因无关 Run 输出重算全部目标或重挂载原工作面。相关消费者成本与连续阅读的 P0 边界继续归[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)，本轮只验证新增表面的放大边界。

Grill/Grounding 的领域事实属于独立 Demand 文件系统包，同一份公开 API/CLI、Main 与 Renderer 投影可读；UI 只持有草稿和展示状态。Provider 与 Core/ctxmux 的生命周期事实保持原 owner，Goals 不新增第二套 Runtime、流程引擎或转录库。本轮不扩展复杂任务依赖、自定义字段、甘特图、自动审批或自动结果验收。

## Goals、Focus 与执行工作面

公开导航为 Mote；Work（Space、Focus、Goals）；Know（Survey、Recall），入口和独立选择只见[空间导航合同](spaces-and-layout.md#左下角导航space-与-goals)。Goals 的清单／看板是同一 Goal 集合的投影；Board 只是历史名称或实现用语，不再定义 Branch／Topic × Agent 状态矩阵，也不是另一全局产品入口。Agent 注意力、请求和结果查看唯一归[Focus](focus-context.md#focus-执行上下文项目泳道与底部时间音轨)，具体 Session 的输入、回复和恢复沿原工作面完成。

选中 Goal 只更新该目标的同屏详情；没有详情时保持清单全宽，不留空右栏或用方向性重排冒充分屏。关联执行上下文、文件、Diff、Activity、决策、评论和对话在同一目标下可达，明确“进入原工作面”才导航。切换、键盘返回和重启保原选择及阅读位置；先恢复 durable Tab／Group／Region／布局和焦点，Session 恢复时机引用[冷启动合同](session-recovery.md#冷启动按需恢复p0-末位)。探测、握手或快照未知保原目标与关联，不以新实体代替恢复。

## Demand 文件事实与独立包

Goal 是长期产品目标，沿底层 Demand 身份持久化；它不属于 Core Runtime，也不是 Desktop Store 的临时 UI 状态。[Demand 包](../../../packages/demand/package.json)与 Core 平行，提供宿主无关 TypeScript API 和文件系统 CLI，唯一持有领域文件、索引、锁、原子写入与损坏恢复。Mote、GUI 与公共业务服务消费同一事实，不在 Mote 目录或 Renderer 另存任务账本。

Core 持有 Provider、AgentSession、语义恢复及持久空间身份／关系；ctxmux 持有 Run、PTY、ordered bytes 与 Runtime 生命周期。Demand 包只持领域关系，不启动或管理 Agent 进程。Demand 与 Project／Session／Attempt 的关联保存稳定 ID 与可验证引用；历史关联、当前执行和 unknown 分别表达，不存在的观察不能伪成 running。

### 公开名称与接口来源

公开 GUI 单项为 Goal，Desktop RPC／CLI 使用现有 `goal.*`／`amux goal`；底层类型、文件和包保留 Demand 身份及领域名，独立文件工具是 `agentmux-demand`。这些是不同入口对同一领域事实的访问，不按改名重发身份，也不为旧 `task.*` 建同义兼容层。准确语法、参数、权限与回执只见[公共能力来源](../../specs/public-capabilities.md#cli-与服务的当前来源)、[公共 CLI parser](../../../packages/core/src/agentmux-cli-commands.ts)和[Demand CLI](../../../packages/demand/src/cli.ts)，本页不另手抄命令词典。

## Demand 的完整业务闭环

1. **提出目标**：显式 New Goal 保存一个待定义实例并进入其专属 Mote 讨论；探索从原对话开始，不先造 Goal／Project。目标确认与结果接受沿[前述合同](#goals-的-grill-与-grounding)。
2. **分配执行**：从真实 Project、Agent Session 与 Mote 发现事实选择准确对象。负责人是一个或多个实际 Agent Session，Executor 只用于新 Agent 创建配置；相关会话保留讨论与历史，不冒充负责人。可以未分配、只分配不启动、明确开始或重新分配；`backlog` 表示暂不启动，改变状态或负责人不隐式开始、停止既有 Session。具体关系与恢复见[负责人、相关会话与当前推进](#负责人相关会话与当前推进)。
3. **管理推进**：详情可编辑标题、描述、状态、优先级、Project、负责人、标签、计划起止日期、父目标／推进批次与 Session 关联。父子状态各自成立，批次解释一批子目标；活动、决策、评论、执行记录保来源及时间，不互相冒充。每次执行、失败、重试或取消沿原工作记录与 Session／Run 留事实；退出、报错、Needs you 或旧 done 都不推断目标完成。
4. **恢复审计**：跨进程读取后，同一目标、正文、关系、状态与 receipt 保持。文件或 Runtime 查询失败保已读内容、选择、草稿与服务窗；关联暂不可见保原 ID，区分尚未恢复与从未关联。取消保历史；删除是准确、显式、确认的危险动作，不连带删除 Project、Session 或健康 Run。

### 负责人、相关会话与当前推进

提需参与事实独立记录实际创建、讨论与补充要求的 Agent/PMO/Mote：准确身份、参与时 Session、原来源和时间由真实调用/身份 owner 确认，元信息沿原身份读取，不复制聊天全文。参与不同于负责人、相关会话、Supervisor 或当前执行；Session 退出不删除参与历史，缺少来源不能从关联、名称、焦点或历史末项猜作者。选择器先推荐与该 Goal 相关且可选的 Agent，再排该 Project 的可用 Agent；其他 Mote/Agent 沿原选择规则。不可选的历史参与仍可读、可定位，不伪装成可立即执行。Supervisor 相邻提供有可辨头像/姓名的准确推荐和明确一键指派，推荐不是已经指派。

Goals 的原 Settings owner 保存「让提需 Agent 默认担任 Supervisor」偏好，有效默认开启，GUI 与公开 settings inspect/set 同源。仅新需求首次默认指派沿实际创建/提需链确认的原 PMO/Agent Session；开启时在同 Demand 一次纳入 Supervisor、负责人和相关会话，关闭仍保参与事实及推荐、等待明确指派。该默认不追改旧需求、后来的提需补充、已有人工选择或运行中的 loop；每个 Goal 仍可显式清空/更换。保存绑定不启动 Loop。缺少准确提需 Session 时保选择入口，不猜默认主会话或当前焦点；延后取得新 Goal 原始来源时仍核首次资格及未被人工覆盖。默认绑定直接用真实提需 Session，与手选 Mote 新建 Session 的意图分开。PMO/主对话可以复用服务多个 Goal，不能由当前一目标一新 Session 的实现习惯推断身份；每次操作保明确 Goal/来源及原回执。

负责人、相关会话和 Loop Supervisor 都引用准确的原 Agent Session。负责人可多选，承担该 Goal 的推进；相关会话承担讨论与历史关联，两种职责分别编辑，在同一区域共用 Agent 选择入口。旧 Session 关联及原 Executor 配置保留，不能从 Executor 或历史关联自动推断负责人。负责人同时属于保留的相关 Session 集合，增加负责人原子加入该集合；移出负责人不删除历史。Supervisor 非空时必须属于负责人，移出当前 Supervisor 时明确清空或指定替代，并以同 Goal 的 expectedUpdatedAt 一次保存，冲突先读原记录。旧公开 Executor 负责人写入及所有客户端消费一并撤换，不保留两套负责人权威。Supervisor 由负责人中明确选择一个；保存 Supervisor 不启动循环，更换负责人或 Supervisor 不静默重绑旧 loop、不停止原 Run 或重放未知输入。原 loop 的目标、Session、Run、版本与 operation 独立保留，可检查并控制原操作。Supervisor 资格只约束新 loop；检查或重读原开始先找到同 operation 的冻结 loop，再核原目标，不以新选择拒绝旧回执。旧 loop 未显式停止前不能为该 Goal 另起指向新 Supervisor 的 loop。

选择器可搜索名称、Project 和准确身份，呈现头像、名称、项目与权威可用状态。相关且可选 Agent 优先之后，未绑定 Project 时 Mote 优先；绑定后该项目的可用 Agent 优先，working 不是唯一可选状态。未知、尚未恢复及已保留引用诚实可见，不因列表缺席清空关系。选择 Mote 为该 Goal 建新的 Session，沿该 Mote 原身份与 launch owner；支持启动新的 Agent 作为负责人，Executor 是创建参数。未明确执行位置时选择真实 Project/目录，不从 PMO cwd、显示 Space 或名称猜测。创建、关联及任务投递分别报告；稳定 operation 与原 Session 的检查入口保留，回执未知先检查，不重复创建或发送。

原 Goal 显式开始 owner 在同 Demand 中保存结构化业务 dispatch 记录：准确 Session、稳定 operation、原时间、prepared/submitted/confirmed/unknown 投递阶段及原回执引用；只记录业务提交，不持 Runtime 生命周期。该记录只能由实际开始 owner 建立，普通活动类别不能冒充执行。confirmed 依据才称正在推进，unknown 保留最后事实与原检查入口；多个无法唯一确定的当前依据表达歧义，不猜最近条目。原 Goal 显式开始及其实际任务提交持有当前推进依据；负责人、历史关联、Run 活跃或 loop tick 本身不足以证明正在推进。Agent Region 可呈现具有准确执行关系依据的当前 Goal 并导航其详情，多个依据或尚未恢复时明确表达相应事实。导航保持 Agent/Goal 身份、输入草稿和健康 Run，不改 Session/Tab 名称、执行 cwd，不发送 Grill 或隐式消息。关系随原领域事实恢复，未知不冒充完成或终局。

关键过程记录沿原 Demand activities owner，公共 Core/RPC/对象式 CLI 可追加并检查准确 operation。原 Session 作者由调用认证取得，业务正文不能冒充另一作者；稳定操作重读不重复写，同操作不同内容明确冲突。需求变化、进展、评审/测试证据、main SHA、发布版本、缺口和接手入口分类可读，证据保存路径/SHA 引用，不复制聊天全文或工具逐行输出。GUI 与 CLI 消费同条原活动，工作实现、main 集成、发布安装与人的成果接受分别成立。

### 状态、筛选与路由队列

工作状态 Backlog、Todo、In progress、In review、Blocked、Done、Cancelled 由明确操作维护，与 Agent 状态、人的目标确认和结果接受各自成立。没有显式关联的 Session 不自动生成 `session:*` 目标卡；Focus 和原工作面继续负责这些 Session。

路由队列可恢复地发现无 Project、无负责人、未确认或需要人处理的目标，队列不改变生命周期状态。搜索与状态、Project、负责人、优先级、标签、日期、Session／Agent 及归档筛选作用于同一集合；清除、复制或公共接口重放保持语义。清单、看板、表格不各存数据。卡片只保足够扫描和路由的 ID、目标、状态及次级关系摘要，完整正文和危险动作在准确详情内可达；字段的默认展开与视觉密度引用[呈现 owner](../presentation/goals-and-demand.md#goals-的目标正文与对齐密度)。

## 委派回报与责任接续

Goal 的委派沿 Core 原通信 dispatch 和实际独立 AgentSession，保存原 source message、operation、Host、owner／worker、Run、冻结任务正文及资料来源；Goal 持有业务关联和逐成功标准的报告，Core 持有通信、投递与回复事实。委派不更换 Supervisor，只有显式交接修改责任。Mote 的执行 cwd 与 Goal Project 分别成立，准确发现目标，不从名称、正文或显示位置推定执行身份。

未交付的执行 Agent 退出时，原 Goal、委派、负责人和工作面保留，明确需要原身份接续或处理阻塞。已有真实报告时显示报告待回收，并让 Supervisor 沿原回复核对证据、差距与未知，提交同一 Goal 的结果；回收后显示待人核验或接受。进程退出、idle、投递、ack、worker_done 和报告自称完成均不代签业务完成或人类接受。仅观测未知时说明失败步骤与恢复动作，保健康 Agent 可用，不盲重投。

委派意图、通信提交和报告回收分别沿原 owner 持久化与对账；回执丢失和重启后保持同一 operation／message、冻结正文和原责任。逐标准报告有准确作者、原 reply、证据位置与目标提案版本，重复或迟到回复不制造新工作、不覆盖已回收报告或人的接受。原 Mote 和 Goal 工作入口提供查看来源、回答提问／处理阻塞、回收报告及原 Session 接续的真实动作；不要求用户靠追问发现未收尾。

## Goal 详情中的 Session 观察投影

执行拓扑按需表达准确 Project／资源 Workspace、Topic／Branch、已有 Tab、Region 与 AgentSession；多处合法绑定可辨，不以 Session 数量、当前焦点、最近顺序或终端标题猜位置。没有 Tab、Region 或当前 Agent 时诚实说明。共用原空间与 Session 投影组件，不为每张目标常驻完整终端或另建拓扑账本。

选中目标后，可用原 arrangement 为一个或多个准确 Session 建观察投影；它是详情的临时呈现，不修改原持久工作面的分割，不创建 Session 或第二个进程。Region 复用同一 Session／Run、ordered bytes、Replay、Gap 和 Attachment owner；新观察 lease 不成为 Runtime 真相或另一份缓冲。返回 Goals 保原目标、详情位置与筛选。

观察投影只读状态、输出、Activity 与待处理事实；禁止 PTY 输入、composer 发送、生命周期修改与主动尺寸控制，只禁 resize 不算观察模式。需要输入、编辑、停止 Agent 或调整终端尺寸时，明确进入准确原工作面；已授权的控制仍归原 owner。将来允许投影接管须显式转移唯一输入／尺寸 owner，不能由多 Region 争抢。跳转失败、位置歧义或恢复未知保目标事实、原引用与恢复入口，不清详情。

## Demand 的专属 PMO Tab

New Goal 与已有 Goal 的讨论关系只定义于[显式新建与专属讨论](#显式新建与专属讨论)：同一个主 Mote 内，每个 Goal 有独立讨论 Tab 与 Agent 上下文；不创建新 Mote，不共享别的目标讨论，也不启动目标执行 Run。Demand 文件保领域事实，准确 Tab／Region、拓扑及绑定持久化归 Core 空间 owner；Client 保呈现与真实输入焦点。

“打开 PMO／继续讨论”定位原 Goal 的准确讨论 Tab；读取、握手或恢复未知不证明 Tab 已关闭，更不授权替换 Session。保原 Goal／Tab／Region／Session 与服务窗，沿同一操作读取或恢复；只有权威确认原 Tab 已明确关闭后，本次显式打开／新建讨论意图才可为该 Goal 建立新专属上下文，保旧关联历史，不另加一次确认。浮窗有明确目标时等待并展示该目标，Agent 尚未挂上不先展示旧 PMO，也不回退另一个 Goal。

请求携带稳定 Goal／Demand ID、当前标题、原意／描述、真实 Project／Workspace／Host 及路由事实；Mote 只整理、组织与跟进，执行分工和既有授权沿[协调合同](motes-and-coordination.md#pmo-teams-topic-名称与职责)。原目标保存未知先读同一对象，准备或投递未知先核原操作，不重复 create／start／发送。

### Goal 与原持续推进的连接

确认的 Goal 可以由明确指定的单一 Loop Supervisor 持续推进；该准确 Session 必须属于负责人。未指定 Supervisor 时详情引导选择，Continue 的启动操作在准确 Supervisor 明确后可用；原 loop 的检查和控制不被新的选择状态遮蔽。原 `goal.start` 通过可选 continuation 授权绑定已确认 alignment revision 与同一业务 operationId；未提供 continuation 仍是原有限开始。原 `goal.inspect` 按该 Goal 投影原续跑 Manager 的准确目标、状态与原操作回执，读不创建调度或复制 Goal 账本。原 `goal.continuation-action` 以准确 Goal/loop、预期 revision 与业务 operationId 沿同一 Manager 执行暂停、恢复、停止或检查；普通日历 `schedule.*` 不承载 interval 续跑。RPC/CLI/GUI 与连接设备对同一操作、版本和结果使用一致语义。

有限 Goal 开始把已确认的任务正常提交给明确的执行 Session；Provider 具备立即打断能力不等于这次目标开始获得抢占授权。提交方式与同一业务操作在首次入队时保存，重试沿原方式和原回执；已经选择立即打断或方式尚未确认的旧操作，不能被新的有限开始静默改成普通提交。忙碌、待权限、错误 Run 和投递未知仍由原 Core 判定并保留原任务、草稿与健康工作面，不在失败后换方式或换身份重发。用户的显式立即发送与原持续推进保留各自原合同。

Goal 完成/取消仅停止相应 loop；blocked、待决定、确认失效或读取未知暂停自动动作并保留健康 Agent。loop 与 Goal grounding 的人类接受各自成立，自动推进不替用户确认目标、接受成果或宣告成功。交互与 Mote 入口唯一见[《目标、持续推进与成果回报》](motes-and-coordination.md#目标持续推进与成果回报)。
