# 用户数据与本地持久化

本文定义保存承诺、唯一持久来源与跨进程恢复的共同边界。[Session 恢复](session-recovery.md)定义原身份和工作面的具体恢复行为；各存储 owner 的当前机制由架构文档说明，不能以设计合同代签实现完成。

## 数据按语义归属

| 数据 | 唯一事实 owner | 持久责任 |
| --- | --- | --- |
| Run、生命周期、ordered bytes、Replay、Gap、Attachment | ctxmux | 原 Runtime 的持久记录与事务 |
| AgentSession、Provider-native 身份、权限、已接收输入与语义恢复 | Core | 原语义对象及原操作的持久 Store |
| Space、Zone、Tab、Group、Region、拓扑与绑定 | Core Spatial | 与前端无关的原空间图 |
| Desktop 草稿、待发送意图、未保存编辑内容、选择与界面偏好 | Desktop 宿主 | 本地持久文件或数据库；Renderer 负责编辑、投影与保存请求 |
| 可从上述原事实重新构造的索引、DOM 与渲染缓存 | 对应消费者 | 可丢弃缓存，不承诺作为唯一恢复来源 |

草稿、队列和未保存编辑内容属于用户数据；用户尚未点击发送或保存文件，不代表可以丢弃其工作。客户端意图不冒充 Core 已接受输入，恢复该意图也不授权投递。通用 Core 不依赖 Desktop 的数据结构、Electron 或 Renderer。

## 保存合同

凡承诺跨重启保全的数据，都须明确唯一持久 owner、稳定存储根、保存触发、确认结果、重启读取入口与失败后的可执行动作。新数据类型与新工作面在同一竖切中完成保存和恢复消费。

正式持久副本经本地文件或数据库 owner 保存。Renderer 内存和 Web Storage 不承担关键用户数据的唯一保管责任；缓存不与权威副本双写竞争，也不在原来源读取失败时回退成空值或旧副本。保全已有数据的导入只在确认目标来源缺席时执行，确认保存前保留原内容；目标已存在时沿目标 owner 读取，不能以另一副本覆盖它。

保存请求、已应用替换、持久确认与下一进程读回分别表达。目录存在、内存中值最新、调用 `setItem` 返回以及平台 void flush 请求都不能代签持久成功。文件替换需要文件和目录同步结果；数据库沿其原事务合同确认。结果未知保留原内容及原请求，不假称未发生，不重放消息或执行动作。

运行期真实用户变更按相关数据聚合保存，不能只依赖正常退出。持续输入不无限推迟第一次保存；后续输入不能被迟到确认覆盖。相同持久值、普通读取、无关 Session 状态及输出事件不制造保存工作。保存失败在原工作面持续说明未确认范围和重试动作，保留最新内容及健康 Agent 能力。

## 退出、更新与恢复

显式保存、退出和受控重载通过原 owner 提交当前工作面及待保存用户数据，确认覆盖本次捕获的内容，不能把空待提交队列当作当前状态已保存。等待期间的新编辑、owner 更换及并发修改分别核对；不能用旧快照覆盖后来工作。需要保存而确认失败时保留原工作面与可达重试，不以停止健康 Run 解除本地记账。

启动先读取同一持久根及原 owner，保留准确身份、布局和用户内容。读取失败、损坏、unknown 与真正不存在分别处理；不能用默认空壳覆盖原文件，也不能从 Session inventory 擅自补建明确关闭的展示。原恢复身份和未知输入遵循 [Session 恢复](session-recovery.md)。

## 验收与诊断

每项保存能力必须有真实产品消费者、定向变异及跨进程读回证据。真实隔离正常退出和异常终止覆盖原 Tab／Group／Region、焦点、分割、草稿、队列和编辑内容；不能由测试额外写盘、重新种数据或另起空 Session 代签。热路径成本核对无关 Session 事件不放大用户状态保存。

保存异常沿原 owner 留存有界诊断，包含阶段、来源、确认状态和必要的对象／revision 引用，不记录草稿、消息正文或凭据。恢复后能核查失败发生在哪一步；告示消失、目录存在或进程仍活着不证明历史保存成功。诊断不能成为健康能力的新门禁。
