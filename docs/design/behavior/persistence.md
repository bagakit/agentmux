# 用户数据与本地持久化

FileDocument 的可选 readIdentity 仅保该份正文的原 Native 读取来源，不是路径变更回执、保存确认或权限账本。旧记录缺来源仍保正文、草稿和原工作面；written 不能继承旧 inode 来源，重新读取与采用边界归 [Files 的保存合同](files-and-git.md#revision-aware-保存与外部冲突)。

本文定义保存承诺、唯一持久来源与跨进程恢复的共同边界。[Session 恢复](session-recovery.md)定义原身份和工作面的具体恢复行为；各存储 owner 的当前机制由架构文档说明，不能以设计合同代签实现完成。

## 数据按语义归属

| 数据 | 唯一事实 owner | 持久责任 |
| --- | --- | --- |
| Run、生命周期、ordered bytes、Replay、Gap、Attachment | ctxmux | 原 Runtime 的持久记录与事务 |
| AgentSession、Provider-native 身份、权限、已接收输入与语义恢复 | Core | 原语义对象及原操作的持久 Store |
| 初始 raw Terminal 创建 admission 与既有 recovery 意图 | Core 原 Terminal recovery owner | 私有原 preparation、Runtime 与同 key 耐久 admission；Native Run 事实仍归 ctxmux，行为沿[Session 恢复](session-recovery.md#重启后的-tabregion-与-session-恢复) |
| Space、Zone、Tab、Group、Region、拓扑与绑定 | Core Spatial | 与前端无关的原空间图 |
| Desktop 草稿、待发送意图、未保存编辑内容、选择与界面偏好 | Desktop 宿主 | 本地持久文件或数据库；Renderer 负责编辑、投影与保存请求 |
| 可从上述原事实重新构造的索引、DOM 与渲染缓存 | 对应消费者 | 可丢弃缓存，不承诺作为唯一恢复来源 |

草稿、队列和未保存编辑内容属于用户数据；用户尚未点击发送或保存文件，不代表可以丢弃其工作。客户端意图不冒充 Core 已接受输入，恢复该意图也不授权投递。通用 Core 不依赖 Desktop 的数据结构、Electron 或 Renderer。

Host 连接编辑与当前 Host 选择属于 Desktop 原用户文档：保留普通 SSH 与 Tailcat 尚未保存的字段、字面输入及其原配置基线，包括新建但未保存的连接。当前 Host 选择只恢复窗口内的管理上下文，不改变连接或维护资格；入站编辑仍沿原 Tailcat 范围。恢复字段不创建密钥、不启用连接、不授权访问或重放保存；原 Host／Node 配置 owner 仍执行显式保存和冲突判定。原目标被删除、复用或改接另一 Runtime／路由时，保留原编辑供阅读，不能把它静默套到新目标；未知格式也保留原文。私密地址只进入原私有编辑数据，不进入诊断、共享业务状态或 Mote 求助。

Agent 卡片[异步操作反馈](session-recovery.md#agent-卡片的异步操作反馈)的未收口引用属于 Desktop 意图：准确原操作、来源／目标及接手的原命名意图随既有用户投影保存，由同一持久入口恢复。最后观察不代替 Core 业务状态；重启后沿原操作核对，不重放。成功装饰无需作为未解决事项持久化，部分完成、失败及未确认的原引用仍须保全；保存失败沿既有用户数据服务窗说明，不因反馈面收起丢掉恢复入口。

已关闭或删除 AgentMux 记录后，独立本机输入仍须可发现、复制；准确关联、未知旧 key 与删除范围沿[《已关闭 Session 的 AgentMux 记录》](session-recovery.md#已关闭-session-的-agentmux-记录)，不另建历史 Store 或将副本搬入 Core。

电子书阅读位置属于原 durable Region 及准确 Host／Workspace／文件资源上的 Desktop 展示偏好，由既有 Desktop 用户状态 owner 按视图独立持久化；Core 继续持有空间身份、布局与绑定。保存阅读进度不能遍历无关 Session、重写完整空间图或重新编码无关草稿。资源变化须隔开迟到写入；偏好读写失败保留健康 File 与当前内存位置，并提供准确恢复入口。

初始 Terminal 的 admission marker 与可替换成员由同一原 owner 保存；冷进程不能因成员缺失重建派发资格。未收口 opaque preparation 保持私有，交出引用后的成员可薄化，原 key 与目标摘要继续保留；不复制到空间图、Renderer 或公共结果，不在输入、输出或普通布局保存扫描历史创建。失败的保存确认与已取得的 Native ACK 分别保管；冷读不能恢复上一个 writer 的目录同步确认。

## 保存合同

凡承诺跨重启保全的数据，都须明确唯一持久 owner、稳定存储根、保存触发、确认结果、重启读取入口与失败后的可执行动作。新数据类型与新工作面在同一竖切中完成保存和恢复消费。

正式持久副本经本地文件或数据库 owner 保存。Renderer 内存和 Web Storage 不承担关键用户数据的唯一保管责任；缓存不与权威副本双写竞争，也不在原来源读取失败时回退成空值或旧副本。保全已有数据的导入只在确认目标来源缺席时执行，确认保存前保留原内容；目标已存在时沿目标 owner 读取，不能以另一副本覆盖它。

客户端输入入口收敛为共享 Message Tool 时，旧请求只在原执行 Runtime、Session、Run、创建或关联及原操作身份完整时接入同一队列，原正文、投递事实与回执一起保留；当前工作面不能补齐旧请求缺失的身份或授权。共享副本持久确认后，才可清理仍与原快照一致的旧请求。冲突、不可解析材料与仅有位置的旧草稿保持可读、可复制；填入当前草稿须由用户明确编辑，不自动猜归属或重发。数据接管和保存失败不以 Native 观察成功为前提，也不阻塞健康 Agent 的独立新输入；历史材料不占用新消息的在途额度。

保存请求、已应用替换、持久确认与下一进程读回分别表达。目录存在、内存中值最新、调用 `setItem` 返回以及平台 void flush 请求都不能代签持久成功。文件替换需要文件和目录同步结果；数据库沿其原事务合同确认。结果未知保留原内容及原请求，不假称未发生，不重放消息或执行动作。

Core 的 Hook 回执确认与辅助工作历史投影分别表达。合并保存不得让可选历史失败抹掉有效回执；必需回执保存的失败或未知沿原 owner 保留准确身份、确认状态与恢复入口。历史投影的准备尚未确认时，不能把本次回执说成写入结果未知，也不授权重放原生输入或历史贡献。

原输入的不可变 claim、Run、冻结计划与各阶段回执由原输入 owner 保全。清理当前终端 readiness、切换 Run、普通 Session 保存及退休不能删除或削弱独立历史中的已确认 ACK；缺少当前投影不代表原回执被撤销。准确原 claim 下新增证据与真实冲突分别处理，不用通用状态排名覆盖不同协议结果。历史回执的显式恢复只消费已核来源并更新准确原记录，不重开退休身份、不把旧输入搬回当前槽位、不重发输入，也不绕过明确删除的终局事实。

运行期真实用户变更按相关数据聚合保存，不能只依赖正常退出。持续输入不无限推迟第一次保存；后续输入不能被迟到确认覆盖。相同持久值、普通读取、无关 Session 状态及输出事件不制造保存工作；Agent 状态、时间线等运行时投影变化不改变持久输入时，不重新投影和序列化全部 Tab、Region、布局及草稿。保存失败在原工作面持续说明未确认范围和重试动作，保留最新内容及健康 Agent 能力。

保存合并从首个待写更新起算有界期限，后续输入只替换待写的最新不可变投影，不推迟该期限；编码与实际存储写入在同一批次完成，不在每次键入时编码整份状态。相同投影不重复编码，内容撤回为已保存值时不重复写入。期限是事件循环的调度时点，不能把忙碌进程说成硬实时落盘保证。启动写闸、恢复、删除、退出补写和写入失败由同一持久化 owner 处理，不另建字段清单、历史账本或后台轮询。进程在保存期限之后突然中断、未执行退出补写时，已到期的工作面和草稿仍须在新进程恢复。

客户端保留的输入回执不复制未被消费的 admission 作者资料与头像；原始作者事实仍由 Core 输入记录保管。新观察与已保存的客户端回执经过同一投影入口，保留原输入身份、等待代次、投递结果、冲突判定及队列正文，不因缩减展示副本而重发输入或丢弃草稿。

屏幕上已出现的工作面位置，要么已由原持久 owner 确认，要么在用户继续工作期间就可见地标为未保存；不能等到退出、更新或重启才暴露。具体是：

- **后台保存有界可见。** 变更超过有界时间仍未确认，无论是保存失败还是请求一直不应答，都给出持续告示，并在后台自动退避重试，不依赖用户下一次编辑。迟迟不应答的请求按回执丢失处理，不能让之后的保存都排在它后面。
- **冲突只隔离冲突项。** 同一项被另一写入方改成不同值时，该项保留已确认的那个值，并在告示里点名这一项；其余无关变更照常提交，冲突不能让之后的新工作面停在内存里。合并不能让已打开的 Tab 失去展示位置，也不能合出持久 owner 会拒绝的图。
- **创建即确认位置。** 由创建 owner 确认的新对象，其位置随创建回执由持久 owner 记录，不只依赖客户端后台补存。
- **失败可追溯。** 保存停滞及其恢复沿原 owner 留存跨重启可查的有界记录，见下文《验收与诊断》。

## 退出、更新与恢复

显式保存、退出和受控重载通过原 owner 提交当前工作面及待保存用户数据，确认覆盖本次捕获的内容，不能把空待提交队列当作当前状态已保存。只关闭工作台窗口而应用继续运行（macOS）时，窗口在同一检查点确认保存后才关闭；保存未确认则保留窗口并给出说明，用户再次关闭时按其意愿关闭。各持久 owner 的检查点相互独立：空间保存失败不跳过用户文档与 Main 落盘，调用方仍得到该失败。等待期间的新编辑、owner 更换及并发修改分别核对；不能用旧快照覆盖后来工作。需要保存而确认失败时保留原工作面与可达重试，不以停止健康 Run 解除本地记账。

启动先读取同一持久根及原 owner，保留准确身份、布局和用户内容。读取失败、损坏、unknown 与真正不存在分别处理；不能用默认空壳覆盖原文件，也不能从 Session inventory 擅自补建明确关闭的展示。原恢复身份和未知输入遵循 [Session 恢复](session-recovery.md)。

首次初始化与已使用 namespace 的部分来源缺失分别判断。已有原数据库、签名材料、身份记录或确认的恢复来源时，缺少其中单项不能自动生成另一 Runtime 身份、签名密钥或确认新空库。原材料不一致时保持准确未知与恢复入口，不用新身份追认原授权；关键身份及已确认窗口操作须取得文件和目录的持久确认，替换已应用而同步未确认不能伪装未写或成功。

## 备份与正式还原

承诺可恢复的用户数据须有经过实际还原验证的独立恢复来源。原持久 owner 提供一致快照、准确 namespace／身份、覆盖 revision 或字节范围及恢复依赖；备份覆盖原 Session、独立输入与 ACK、私有创建材料、退休事实、空间与展示关闭、用户草稿队列和可取得的 Provider 原生上下文。缺失或暂不可取的来源逐项表达，不能用空内容补齐或把部分覆盖称为完整。跨 owner 分别取得的快照不冒充全局原子事务，原 Run／当前进程和原生业务效果仍由各自 owner 确认。

自动备份沿真实持久变更聚合，有界保留已验证版本；新版本未验证并持久发布前，最后可还原的原版本不得删除。只读、输出热路径和无关 Session 事件不重复复制全部用户状态或原生历史。后台失败保留健康能力和最后可用备份，持续表达最近恢复点、缺失范围及重试动作；同盘副本不承诺抵御整盘损坏。

正式还原先在原 owner 预检准确来源、目标身份、当前基线及覆盖，再以同一操作应用并给出分阶段可重读回执。已有数据不能被旧快照静默覆盖，后来的退休／关闭、输入确认及新编辑必须保全；缺失目标的恢复和当前原记录的证据补全分别处理。恢复与原 writer／读者生命周期协调，不以裸 copy／rename 代替在线事务。还原未知时先核对原操作，不重复替换；恢复元数据或待发送意图不授权 Start、业务输入或自动重放，也不把原生上下文缺失降为新建空会话。Core、公开 RPC／CLI 与 Desktop 消费同一恢复事实和操作合同，不另设旁路事实库。

控制材料从较旧恢复点还原时，原输入 owner 先耐久确认本次恢复代次，再发布候选材料。原输入、首句、消息通知和持续安排保留原正文、身份与未知结果，不能自动重放；旧版本也不能将缺少恢复资格的材料当作新的执行授权。只补全准确历史 ACK 不改变当前输入代次、当前槽位或退休事实。已完成操作的回执是原结果，重读它不再发布旧快照；发布结果未知且目标后来改变或再次丢失时，保持未知，不能将再次复制视为同一次恢复。

真正新建的输入或创建意图在首次产生时，沿准确原 Source／执行 Runtime 的只读资格入口冻结恢复代次，随后随原请求、队列、调度和回执传递。接收端不能因为本地找不到旧 operation 就读取新代次替旧请求续授资格；最终输入和 Start owner 仍核对原请求。观察失败不把缺值改为“从未恢复”，也不能拿走健康 Agent 已有的阅读、停止和无输入原上下文续接能力。旧安排的执行资格未确认时保留原安排及服务窗；新的明确安排保留独立身份，不复用旧未知输入 key。

正常语义启动因原身份或数据库缺失而不能继续时，仍提供受信的纯数据维护入口，由原持久 owner 核对来源并恢复，不构造替代 Session、签名身份或 Runtime。空间、草稿和窗口在默认初始化之前由各自原 owner 恢复；已有文档和内存中尚未保存的编辑优先保全。只有具备准确恢复依赖和 writer 协调的成员可应用，其他成员逐项列为不可确认，不以文件存在或备份列表可读代签可恢复。 原跨 owner 的创建／消息授权文件仅作为历史原件保留，缺失不证明仍被批准；不从备份自动重新授予权限。准确身份可单独恢复，新的跨 owner 授权仍由既有 trust owner 显式批准。

## 验收与诊断

每项保存能力必须有真实产品消费者、定向变异及跨进程读回证据。真实隔离正常退出和异常终止覆盖原 Tab／Group／Region、焦点、分割、草稿、队列和编辑内容；不能由测试额外写盘、重新种数据或另起空 Session 代签。热路径成本核对无关 Session 事件不放大用户状态保存。

保存异常沿原 owner 留存有界诊断，包含阶段、来源、确认状态和必要的对象／revision 引用，不记录草稿、消息正文或凭据。恢复后能核查失败发生在哪一步；告示消失、目录存在或进程仍活着不证明历史保存成功。诊断不能成为健康能力的新门禁。

显式初始创建退休沿同一 Terminal recovery owner 保存薄单调 witness：原 per-key 短锁负责协调，另一个 O_EXCL 文件在原 fd 写入、同步并确认父目录；不 rename 正在 flock 的稳定 inode。首次独占且确认的创建者才可派发一次 retirement；空、残缺或已存在 witness 不重新授予施效资格。Agent key 角色不保存在此 witness 中，而是从原 Agent Store 精确核对；共享空锁只串行本次准入，不复制生命周期账本。

原 Agent Store 的私有机器创建 key集合与完整性标记归原 Session/reservation/退休顶层，随其生命周期交出；不进入公开 history或cloneSession投影，不新增角色catalog、表或历史迁移。canonical事实在普通更新保留，调用者incoming不得自签新增key或升级完整性；无原完整事实及unbound Run来源保持unknown。
