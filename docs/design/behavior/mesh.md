# Mesh 网络与接入

本文是 AgentMux 组网的行为 SSOT，持有网络域、节点与网关角色、连接与路径、节点发布、网络观察和配置要求。远程工作、项目与 Agent、运行观察和维护沿 [Remote 管理](remote-management.md)；Session、权限、空间和持久化仍由各自原 owner 定义。本文定义目标合同，当前源码基础见[公共能力与当前基线](#公共能力与当前基线)，不代签实现、安装或真实远端可达。

[交互合同入口](../agentmux-desktop-interaction.md) · [Mesh 呈现](../presentation/settings-and-observation.md#mesh-网络工作面) · [设置共同合同](settings-and-observation.md#设置页的信息架构)

## 目标与范围

Settings 的 Hosts 升级为 Mesh 网络工作面，统一理解和管理已配置节点、网关、连接与路径，同时保留原 Host 对象和已有管理能力。网络能力包括多个网关间的拓扑传播和多跳选路，不只改变页面名称或展示手工连线；不要求所有节点直接互连。无法被入站 SSH 访问的机器可以主动接入可达且获准的网关，由访问方沿原 Core 的身份和授权访问。

Mesh 的网络域是明确的成员、连接和传播范围，不是全局用户、业务权限域或共同本机。网络入网不复制登录材料、不共享 Session，也不选举替代业务 owner。组网组件可以独立发布和运行，Core 也可直接引用形成网关；独立进程不能成为 Core 嵌入的必需中间服务。新增网络能力先接同一公共服务与实际 CLI，再由第一方界面消费。

## 对象、身份与唯一 Owner

| 对象或关系 | 含义与事实来源 | 必须保留的边界 |
| --- | --- | --- |
| Endpoint | 正在消费的原公共业务服务及其命名空间 | 接收 Core、CLI 所在机器与实际执行机器分别表达；定义归[公共身份合同](public-control.md#endpointhost-路由与源身份) |
| Host | 原 endpoint 范围内的稳定路由及连接配置 | 原配置 owner；名称、SSH alias 和地址可编辑，不是跨 endpoint 全局机器 ID，也不证明连接就绪 |
| Node | 原 Core 对外发布的身份、资源与共享目录边界 | 原语义 Runtime 的持久身份与发布 owner；不是物理机器 ID、另一套 Runtime 或全网名册 |
| 网络 peer | 参与网关拓扑与转发的已授权网络身份 | 与 Runtime、Device、daemon E2EE key 和 Core 业务签名者分开；纯 relay 进程不伪造执行 Runtime |
| gateway／edge | 接入、主动出站或转发的组合角色 | 可以由 Core 或独立网络组件承担，不固定为机器身份或唯一中心 |
| 网络路径与 circuit | 到准确 publisher 的传输路径及已采用的连接 | 由网络 producer 提供；候选、配置、当前采用与最后确认分别表达，不当作物理 IP 路径 |
| Core 业务路线 | 原 `adoptedRoute` 的显式签名委托链 | 原 actor、接收者授权、有限调用范围和冻结执行 binding 不随网络选路改变 |

多个 Host、peer 或 Node 是否关联，由各自原身份事实确认；同名、同 IP、同机器外观或同路径都不构成合并依据。即使多条路由已确认到同一 Runtime，也保留各自准确命名空间、配置与操作目标，不因画图建立新的机器／Session Store。

Core 持有唯一 Mesh 持久配置、网络身份、启动代次和原操作回执，Desktop 与 Headless 消费同一 owner；已有 SSH／Host 配置继续由其原 writer 保存。独立 relay 进程由自己的装配 owner 保管网络私钥与启动代次。共享网络包只持有当前连接、拓扑、选路和 circuit，不写 Core、AppConfig、Session 或业务权限事实。

## 多网关拓扑与多跳选路

### 准入与拓扑来源

成员资格使用明确的网络域与公钥 pin。直接邻接在双方认证准确 peer 后成立，地址只是连接目标，不授予身份；重放旧握手、换网络、换 key 或冒称来源不能建立邻接。网络身份的持久 key 与单调启动代次由原 owner 保存；保存未知或原数据不可读时保留原字节和请求，不能按时钟猜新代次或生成替代身份。

每个来源只声明自己确认的邻接、已准入且当前连接的 publisher 及明确发布的入口。拓扑记录由原来源签名，携带可比较的启动代次与修订；接收方核对来源 pin、网络范围和新旧，再有界传播。节点可转发另一来源的已签记录，不能替它改变内容或把间接宣告冒充自己实测。只有双方记录一致确认的有效邻接进入选路，本机首跳还须有真实认证连接；断开、撤销和 publisher 退出沿原来源撤回其事实。

拓扑宣告不证明远端 Native／Agent 健康或每一跳此刻仍可达。实际开流须逐跳核对当前邻接、连接代次和终点的准确 publisher；旧宣告至多使本次连接失败，不得转往另一个主体或扩大权限。传播与索引工作随获准成员、实际连接和新修订增长，握手、控制帧与在途工作有明确资源界限，不随 Session 数或累计历史增长。

### 路径与连接寿命

网络按跳数、具名且稳定的 RTT 口径和确定性 peer 顺序选择到准确 publisher 的候选路径；未测 RTT 与真实读数分开，测量噪声不触发反复切换或持续拓扑洪泛。一次 circuit 固定完整的不重复 peer 路径、终点／publisher 代次及沿途连接身份；逐跳核对当前位置、前后邻接和目标，防止循环、跨 circuit 串线或错投。路径长度受明确成员范围约束，不能无限递归。

拓扑改善只影响新建 circuit，健康的已采用路径继续使用。确需建立替代连接时，先确认准确原目标与可用通道，再释放原消费者；建立失败、观察缺失或排序变化不能关闭原健康工作。端到端加密载荷一旦可能发送，断线或改路不能重开并重放旧载荷；原未知操作、输入 ID、查询与 reader cursor 保留。连接迁移、业务完成和恢复不是选路成功的同义词。

peer 控制与数据承载须适应一方只能主动出站的网络条件，不要求对方另有反向 TCP／SSH 入站。控制与各 circuit 的流控、取消及资源归属分开，单个慢 reader 不阻塞拓扑或其他健康 publisher。重复连接确定性收敛，不挤掉健康身份或顺带释放无关数据连接。撤销成员／peer 只收敛其相关连接与路由；停止或移除自己的监听处理器不关闭借用的宿主 HTTP、其他 WebSocket handler 或原 Native Run。

### 网络权限与业务委托

publisher 准入、peer 准入、终点 client 准入与每次资源操作各有准确主体和 owner，一层通过不代签另一层。网络只转发原 V2 端到端加密载荷，不解密业务内容、不代理成 Unix 用户，也不将 device 洗成本地 user 或 managed Agent。网关不持有 AgentSession、业务操作、设备审批或恢复的权威。

网络跳点不增加或减少 `adoptedRoute` 的逻辑 hops，不改变原 actor、签名参数、逐接收者授权和冻结的执行路线。现有 Core 显式多跳委托已由[公共路线类型](../../../packages/core/src/host-route.ts)、[原路线 owner](../../../packages/core/src/host-route-gateway.ts)及[路线指南](../../../packages/core/guides/modules/route.md)持有；发现可达路径不自动保存业务路线、导入 Host、批准资源访问或重放原调用。网络组网不复制业务 primary、成员停服或共享凭据策略。

## Mesh 工作面与配置

Cluster 依次提供 Mesh、Node、Quick。默认打开 Mesh，以同页地图、网关／路径、已保存设备和机器资源回答当前实例如何参与网络及已确认的网络事实。Node 默认管理本机身份、权限和发布，Gateway、Tailcat、SSH 各有自己的设置入口。原已保存 Host 的连接、项目与维护沿准确 Host 进入。Quick 按用户任务组织首次接入、允许另一设备访问、打开设备、开始与继续工作。多个入口可以定位同一设置，编辑和保存仍沿唯一原 owner。仅盲转发的 peer 不取得工作委托或 Session 所有权。

Mesh 首页提供“连接 Relay Gateway”和“使用另一台设备”两个工作入口，注明当前从哪个 Core 观察。连接已有 Relay Gateway 依次提供选择与预览、确认连接和查看结果。材料与双方准入齐备时一次确认即可连接。尚需网关批准、本机身份恢复或网络检查时，在同一流程保留选定网关、输入和当前进度，说明缺少的条件与对应动作。已连接取自准确双方的认证事实。

接入确认只应用当前所选网关及其必要的成员、拨号和参与状态变更。以原 Core 最新已保存配置计算，保留高级设置的未保存字段、原基线和原编辑入口；无关草稿或其整表冲突不阻断接入。保存前版本变化时刷新原 Core，重新复核最新目标，网关身份、网络域与启动网关的约束保持有效。提交结果不明时查询原操作，展示正在检查的原连接；如果其他待确认的配置写入涉及同一 Core，先核对其回执。认证尚未观察到时提供检查连接与复制双边配对材料，批准是否缺失只按已有回执表达。接入完成可直接打开设备访问或返回原总览。

加入方可主动拨号，网关管理方确认网络成员，目标端点的管理方另行批准访问设备。公开配对码在 App 与无界面 CLI 使用同一编解码，预览网络名、准确 peer 和公布入口后再保存。提供网关和添加上游可以同时进行；只有明确停止提供入口才撤下监听与公布地址。访问链接由有路径且已监听的原网关生成，入口可从它明确公布的地址中选择。访问方在 App 取得自己的设备公钥并打开准确链接，复用获准工作入口读取原 PTY 并提交任务。连接草稿、保存、认证、授权和任务回执各有可见状态。

已管理网关的操作员可粘贴设备码并在同一处批准该设备，按最新的原网关配置只保存本次成员变更。内联反馈确认保存，实际认证由原观察确认。访问端可粘贴访问链接并预览目标设备和网关，再打开准确工作区；打开后的设备授权在其原窗口确认。链接保存与打开分开报告，重试保存不再次打开工作区。

节点的接入方式由其原配置 owner 明确持有，可使用域名、公网或局域网地址，也可经节点之外的网关到达。同一节点可以有多个接入入口；增删入口不改变原 Runtime、Session 或设备身份。配置须分别表达实际监听、主动连接的目标和向访问方发布的入口；外部网关、域名与端口映射不能从监听地址或网卡自动推定。设备详情可就近进入其接入配置，但不复制 Mesh 网络配置或 Node 资源发布策略。

常见局域网、公司内网和网关接入提供简明引导、合理默认值或明确的一键准备动作，高级地址和监听配置按需展开。默认值只是候选配置；准备、持久保存、实际采用、可达和设备获准分别确认。Relay 接入不要求 SSH，部署或维护使用 SSH 不成为其他设备的入网条件；一键准备也不隐含新增成员或资源授权。

macOS 的本地网络隐私授权归系统管理。首次接入局域网时，桌面包声明用途，安装注册的后台 Host 归属同一个应用。用户可在系统设置的「隐私与安全性 → 本地网络」管理 AgentMux 的许可。系统尚未授权或局域网不可达时保留已保存的配置、原 Core 和现有工作。

配置读取失败、网络观察失败和真实空网络分别表达。配置不可用时说明当前受影响的配置读取、可检查的原 Core 与显式重读入口；原错误可展开核对，不直接将内部 owner 术语当成引导。独立可用的网络观察和原已保存连接仍可访问，不因配置观察失败显示虚构空拓扑、永久加载或要求停止健康 Run。保留原草稿与未知操作，已有设置可读时局部错误不折叠正在编辑的字段。

本机配置读取因原 Runtime 身份缺失受阻时，接入页在网关输入前提供 App 内恢复入口。有原备份时二次确认后进入文件选择，验证后接回原身份。另建身份沿[原 Runtime 身份恢复](persistence.md#原-runtime-身份恢复)隔离后台，向导留在当前页。连接、地图以及本机网关编辑消费相同选择及准确 Runtime，显式选择的远端仍沿原路由。身份待确认期间只暂缓依赖该身份的任务，已保存设备与独立观察按各自能力继续可达。重读保留网关码、原草稿及待确认写入。

Mesh 配置经原 Core 公共 owner 完整 CAS 保存，保留 expected revision 和原 operation ID；原 managed caller 的认证与准确 Runtime／owner fence 在持久写入前仍须成立。复用原 Node operator 资格；Device、guest、有限发布访问或 route delegation 不因此取得配置管理权。未知保存先查询原操作，不能用读到相同值伪造历史持久 ACK，不能换 ID 重发。 显式管理已保存远端 Core 时，入口验证原本地 caller，冻结准确 Host／预期 Runtime 与原 operator carrier；接收 Core 独立核原 operator 权限和 Runtime／instance，不把入口 Agent 当作远端 Session。该有限路由复用原 Node operator 选择边界，不提供任意 RPC 转发；原配置和确认回执写入后，保存直接返回本次修订与操作回执。后续配置读取或路由观察独立报告结果。

持久保存与当前应用分开表达：期望配置、已采用修订、应用中／失败、监听和当前网络观察各自可核对。热更新保留未改变的 peer、健康 circuit 和原对象；新配置、监听或应用失败保留原可用路径与健康 Core，不以关闭整个 Runtime 或强制重启应用配置。运行网络与监听器的寿命分开，允许仅主动出站的参与者；借用 listener 时只释放自己的资源。

同一对象的未保存草稿、原基线、保存期间后续输入、冲突、展开与准确选择均沿[设置共同合同](settings-and-observation.md#设置页的信息架构)和[持久化合同](persistence.md)保全。切换目标、页签或分组不能把迟到结果用到另一 Runtime，也不清空原 Host／Workspace／Session 引用。网络和原业务状态分别显示，图／列表／详情消费同一事实；布局、选中、缩放与筛选只改变视图，不执行扫描、连接、授权或保存。

### 网络总览与集群主机状态

在 macOS 的地图位置编辑器中，用户可为本机主动读取系统位置。Desktop 在当前前台窗口请求系统授权，读取一次并将返回坐标填入本机地图草稿。保存沿原本机标注入口。系统定位状态、设备地理位置和原节点发布各自由原来源确认。用户可在原节点发布入口单独决定分享的位置。定位拒绝或未取得读数时保留草稿和手动标注能力。用户改写坐标、切换设备或离开编辑器后，迟到的结果不能覆盖其内容。

地理图打开时，如本机没有地图标注与可用的节点位置，Desktop 向 GeoJS 查询本机公网出口所在的大致地区。估算结果只用于本机地图，无需系统定位。用户仍可用系统定位或手动校正提高准确性。本机标注的编辑与远端位置读取彼此独立。同一来源暂缺本机回执时，地图保留上次已确认的本机位置。收到本机回执后，以新位置或明确缺测为准。

Mesh 默认首页按当前网络与路径、网关、已保存机器路由的顺序提供观察。网关显示本机原监听与原记录公布的网关入口，公布入口与认证邻接分别表达。机器首层同时呈原连接和资源观察，每条已保存路由均有行，资源未知时仍可准确管理。Mesh 左栏提供网关管理、已保存设备与机器状态，窄窗使用同一 Settings 导航。逐项按准确 Host 打开原编辑面，返回总览保留原选择和编辑草稿。专用子面不启动隐藏网络或连接编辑观察；网络 peer／endpoint 和已保存 Host 仅按权威关联联动，不以同名、IP 或排列位置推定对应关系。

Mesh 总览的连接图同时呈现已保存的 Host 路由、已保存的设备访问链接和已观测的 Mesh Relay 邻接。保存关系保持原配置来源，通信状态复用原 Host 的通道观察和已完成测试；Relay 邻接取自原网络 producer。由桌面经原本机 Core 直接观察时，保存连接的发起端与该 Core 明确报告的自身 Relay peer 共享一个本机图形锚点；两种连接及其各自的原始身份和观察在锚点上仍可辨。远端对象仅以权威身份关联合并。没有 Relay 对端时已保存连接继续可见，本机 Relay 状态只解释该来源。读取失败保留已有的最后确认结果和来源，已确认缺失时保留其他仍存在的关系。显式专注已知路径以突出该路径并压低其余关系的方式改变阅读重点，原有连接保留在图上。绘图不发起额外探测、配对或连接；设备选择可打开准确原 Host 的连接编辑。

网络路径共用同一 producer 快照，区分 peer、原 endpoint、候选 route 和已采用 circuit。选择、范围、搜索、图／列表和详情只改变阅读位置。刷新和首次网络回执都保留用户已调整的节点、视口和选择。两个已确认来源之间发生 Runtime、owner 代次或网络变化时，观察与拓扑选择按来源隔离。原网络及 Host 深链继续到达准确观察或编辑对象，`mesh-paths` 的发现目标落总览地图。地理图、连接图与列表共用同一份设备选择和观察数据。地理图始终提供真实底图。两端均有位置时在地理图画出连接；未定位的设备列于底图外，可切到连接图查看它的链路。保存的设备访问链接按端点标识和加密公钥归组，保留各自的入口。设备与转发它的网关分别呈现。已打开且获准的设备工作面可提供原节点的位置观察，浏览地图不会为每条访问链接启动工作面。本机地图可为准确 Host 或网络域内的 peer 单独标注，保留原有 Host 标注。远端地理信息来自节点自愿发布的位置，或有依据的站点登记。节点显式启用发布出口估算时，由该节点发起查询，仅发布带来源的粗略区域；VPN 和网关出口可能位于别处。私网只有匹配到有权维护的站点资料才可定位。用户在本机的校正优先，同名 Host、IP、入口和中转 peer 不构成身份关联。地图按需读取，地理观察失败仅使地点未知。节点和位置的变更不触发业务授权、任务重建或整网实时同步。线宽只在有相应来源时才表达流量。

总览和 Machines 共用当前已保存 Host 路由的资源观察，提供整机 CPU、内存、卷容量、uptime 与已有服务读数，保留当前／最后确认、采样时间、权限范围及局部缺口。Host 路由不等于物理机器身份，不按名称／IP 合并或相加当作物理集群总容量。
进入这个具名总览是读取当前已配置Host资源的明确范围；使用原公共owner和已获准传输，初次可见时读取，提供单Host与全范围显式刷新，不默认开启常驻轮询。排队和在途读取可取消，慢或失败Host不阻塞其他卡片；离开总览与 Machines、隐藏文档或配置改变取消自己的观察，不停止／重连其他消费者。已获原owner私有读取资格时具名显示，私有不可用仍可尝试原独立的发布资源读取；未共享、未观测与读取失败各自表达，不补零或改变原发布策略。原已知Runtime与路由配置在返回前核对；异源结果不能覆盖旧目标，代次重启不能跨源计算CPU区间。

### 原 Host 工作台的入口与范围

Mesh、Node 与 Quick 在设置目录、搜索和原深链均可独立到达。Mesh 的已保存设备和机器观察进入准确 Host 的 Node 设置，项目和信任继续沿该 Host 的原工作台。Quick 的连接入口返回同一向导。原 Host 对象、稳定模块、Host、Runtime、field 与草稿身份保持。其他设备和 Executor 模板沿原管理面。

同一 Host 工作台按总览与监控、项目、应用与访问、连接配置组织任务。切换任务仍持有同一个准确 Host、原草稿与已访问操作，不建立三套选择器、清单或配置副本。总览承接拓扑与分源观察；连接配置承接原编辑、Test 与 Core 维护；应用与访问承接该 Host 的真实执行器盘点及跨 Host 来源核验、真人批准。全局模板不冒充远端已安装应用。

进入后先显示已登记的环境和当前已有事实。查看拓扑不自动部署、升级、恢复全部 Session、运行任意 shell 或扫描网络；网络读取沿[所选 Host 的显式观察范围](#所选-host-的只读网络观察)，需要实际连接才能取得的事实由原服务按准确目标取得。离开页面只释放本页观察，不断开其他消费者或停止健康 Run。

“所有环境”必须说明它是已配置环境，不能冒充扫描发现的全部机器。筛选可按名称、地址、项目和明确的待处理状态收敛；筛选只改变可见范围，摘要说明过滤条件与观测覆盖，不把被过滤或读取失败的对象算成不存在。

## 主动接入与可组合网关

无法被入站连接访问的设备可主动向已配置网关建立加密双向通道，访问方经该网关到达设备原 Core。设备的出站可达性与网关接入授权分别确认，不以 SSH 可用为前提；配对明确准确网关和接入设备，通道标识不替代原 Host／Runtime 身份。网关只持有连接、接入资格和转发状态，AgentSession、Run、项目、资源权限与恢复仍由原 owner 持有。建立连接不授予访问方额外资源权限，不把网关当成所有接入机器的共同本机。

连接组件按网络能力命名并可独立发布；网关、主动接入与边缘转发是组合角色，不固化为机器身份或固定中心拓扑。Core 可直接引用组件形成网关，轻量边缘单元也可独立运行同一组件。独立进程只是其启动装配，不能成为 Core 网关的必需中间服务；两者共用转发、准入和流控机制，借用宿主监听器时仅释放自己的连接与处理器，不关闭宿主服务。转发保持原目标及授权；多网关传播和选路遵循本文的来源与路径合同，不能从节点角色推导无限发现或业务授权。

第一方客户端和 CLI 通过原公共 RPC 消费同一原业务能力。连接配置、发现、当前观察、停止本次接入与恢复入口均须可操作；组件监听、准确设备已接入、目标 RPC 可用与原业务完成分别表达，未连接、身份未知与明确拒绝分别表达。通道中断保留原工作面、Session、未决操作与最后确认事实；重连只恢复传输，不自动重放未知请求或创建替代 Session。单个设备的中断和积压不关闭其他设备或本机健康能力。

人在原 Host 上保存 participant 配置后，该 Host 沿同一网关 runtime 自动发布自己的原 Core endpoint，不再要求另行填写未公开的出站文件。复用原 serverId、daemon key、DeviceAuthority 与已认证 framed dispatcher；网络成员公钥只批准 peer，原用户还须明确批准 endpoint 的 client 公钥，先核对允许列表再进入原设备登记。两种 key 和原 Runtime 身份分别呈现，入网不自动批准设备或提升为本地用户。

原 endpoint 的设备身份、daemon key 与授权由 Core 唯一拥有；持久化 headless 入口和 Host 共用这套实现、原 schema 与原 File Store 旁的文件，不另造身份或权限。端点通过惰性、可取消的端口提供，内部 publisher 使用自有的私有 loopback attachment，不开放公网 Core RPC。网络配置与转发不等待可选端点初始化；端点身份损坏或仍未取得时，持续报告端点未知／不可用，原 Unix、已可用 Mesh 转发和健康 Native Run 保持可用。停止和撤销只释放相关载体与观察，不停止 Native Run；迟到初始化不能重建已停止资源，停止不能无限等待可选初始化。显式传入的端点仍沿其原 owner；内存 Store 或未提供端点的独立控制服务如实报告 endpoint 未提供，不伪造持久身份。headless 不伪造手机网页，以原 Mesh offer 和所选网关的显式 ingress 供访问。原已公开的独立出站组件继续保持自己的明确用途，不作为 Mesh 设置的隐藏前提。

## Tailcat 传输与本机接入

同一 Host 可选择 SSH、SSH 优先且 Tailcat 备选、或仅 Tailcat。现有 Host 默认使用 SSH；关闭 Tailcat 不启动其 CLI，不改写 SSH 命令或删除配置。传输选择不改变 Host、Runtime、Session、Run 或工作面身份。备选只用于建立通道，在发送业务请求后失去回执时保留原 operation ID 和未知结果，不能自动改路重放。

Tailcat 通过官方 CLI 的双向 stdio 复用现有 JSON-RPC 和 Runtime 绑定。接收端必须已经安装并运行 AgentMux；本机接入开关只监听并将连接桥接到原 `amux system endpoint --stdio`，不安装远程核心。开关使用已保存的 server key（含 PSK 和固定 DERP region）及明确的非空 client public key allowlist；关闭只停止监听。发送端使用保存的 client key 和对方 `tc…` 地址。地址属于凭据，不进入日志、拓扑标签或公开示例。

本机 listener 位于 **Node > Tailcat** 的 `incoming` 字段；远端 client 在准确 Host 的连接编辑页。App 与 Settings 使用同一导航解析，将原入口规范到 Node。未指定 Host 时只解析唯一配置的本机；显式缺失／远端目标不得替换为本机。原 Host 的 `resources` 进入该 Host 的 Overview；公开 `app focus --settings-section hosts --host` 保持稳定地址和准确 Host 回执，界面在 Node 呈现同一 Overview。

CLI 缺失、启动失败和监听观察未知必须可见并可重新检查；进程启动不代签已连接。Tailcat 失败不能撤销健康 SSH、Agent 或 Run。现有 Linux x64 headless Core 升级范围保持不变，Tailcat 接入不授予 Mac 远程安装、主动扫描或绕过安全策略的权限。

### 在 App 中准备 Tailcat 接入

两台都已安装 AgentMux 的机器无需离开 App 运行 `tailcat genkey`。各机器上的人可让本机 Host 经官方 CLI 准备一份已保存密钥（未指定名称时使用固定的 AgentMux 默认名，只接受官方密钥目录中的名称，不接受路径）：接收端为带 PSK、固定 DERP region 的 server key，发起端为 client key，并返回其公开的 client public key 作为本机连接码。自定义名称沿官方 CLI 的原名称精确传递，不按自设字符集或固定长度拒绝，也不修剪或改名；文件系统是否合法由原 Host 与官方 CLI 判定。准备只在该名称的密钥缺失时生成，已存在即原样复用，绝不覆盖、删除或改写任何已有密钥；返回结果区分新生成与复用。私钥只留在原密钥文件，不进入结果、日志或配置；连接码是公钥，可以复制给对方。

准备动作写入本机凭据，只接受传输层认证的本机用户；托管 Agent 不能代为准备或借此取得授权。它只作用于发出请求的 Host 本机，不能替另一台机器生成密钥。CLI 缺失或执行失败如实说明并保留原配置、草稿与健康工作，给出安装与重试入口。

准备失败沿原结构化机器码区分准确服务未提供接口、CLI 明确缺失、已保存密钥不合适及执行尚未确认，不从文案猜测原因。服务接口不可用时说明原服务与下一步，不能用安装 Tailcat 冒充修复；只有原执行 owner 确认 CLI 缺失才提示该依赖未安装。服务未报告方法清单保持未知，不增加版本猜测或关闭健康能力；重新准备仍是人的明确动作。

准备不替人完成授权：发起端的连接码仍由接收端的人填入允许列表，监听开关与保存仍是接收端的明确动作；接收端的私有地址仍经原复制入口交给发起端，由发起端保存并测试同一 Host。两台机器之间只交换这两段文本，不新增无人确认的配对、网络协议或自动加入允许列表。GUI 与 `amux settings hosts tailcat-key` 共用同一 Host 能力。

### 接入失败时交给 Mote

Tailcat 依赖缺失、密钥准备或入站监听失败时，就地说明下一步并保留手动安装入口；用户可选择某个 Mote，交代依赖安装、环境诊断和配置填写准备。任务携带准确的本机执行目标、被配置 Host、接收／发起角色及非敏感字段是否已填写，不把私有地址、私钥或未经筛选的原始错误复制进任务。未保存草稿不能冒充已生效配置。

原失败步骤、已知机器码和所处设置入口以白名单字段加入同一任务上下文，供 Mote 直接消费已确认事实；接收端 help 的 `settingsTarget` 是 `{section:'hosts',hostId:<原 local Host ID>,item:'incoming'}`，client 仍是各远端 Host 的 `connection`。缺失观察明确未知，不要求重新安装已确认可用的依赖，也不把窗口定位当成业务步骤。帮助入口可在诊断未知时继续使用，不新增求助状态库或借求助取得密钥、允许列表及保存权限。

求助复用原 Mote 目录、逻辑主对话和持久输入队列，沿原角色修订与准确操作回执投递，不按当前活动成员、显示名称或首个 Executor 猜执行者，也不新增专用修复 Agent 或任务状态库。主对话未确认时保原引用和设置草稿，让用户沿所选 Mote 的原开始／恢复入口继续。入队、输入确认、处理完成和连接成功分别表达；未知投递不自动重发。原客户端接入授权、密钥准备和保存权限继续由各自 owner 确认，求助本身不能代批允许列表。

### 当前通信方式

已配置 Host 的实际通信方式在设备／Host 身份入口可发现，hover 与键盘聚焦可阅读同一事实。当前 SSH 或 Tailcat 只来自观察端维护的原 Host Runtime RPC 通道：真实建连确认、SSH 建连失败后选中 Tailcat、原通道关闭及路由正式采用分别由原传输 owner 提供。已保存偏好与实际采用方式分别标注；候选尚未采用不改变当前投影，断线后最后确认的方式不能继续标为当前已连接。尚未取得事实保持未知，其他独立命令通道、Agent 健康、Tailcat 直连或 DERP 中继路径不由这项观察代签。通道已建立但远端 Core 的 owner 协议明确早于当前合同，须明确提示协议更新要求，不能把它表述成 SSH 不通或 Agent 死亡，也不据此自动升级、重启或降级原 Runtime。

展示消费已有被动状态，不因 hover、focus、节点绘制或筛选发起新连接、探测、诊断／资源读取或轮询。事实附准确 Host／来源与确认时间，经原 SDK、Host inspect RPC／CLI 和 Desktop 状态投影复用；缺失／失败只影响本项观察，原 Host、Session、Run、工作面和恢复动作继续保留。正常提示仅含安全的方式、状态、是否采用备选及来源时间，不回显私有地址、key 路径、命令或原始标准错误。

## 本节点的发布与访问边界

Node 的显式已保存 Host 设置始终在页内标明准确目标。该 Host 的观察、草稿和写入均沿其原 Core／Runtime。机器观察及设备访问不以选择或登记项目为前提。独立 Mesh 身份的 Gateway 配置继续沿该身份的准确后台 owner。

节点管理沿原 Core 的 owner 接口与传输认证的原 user operator 资格执行。同一 owner 已认证的 managed Agent 可在该原用户管理通道上执行用户授权的准确 Node inspect／configure，入口保留真实 Agent 认证；目标 Core 独立认证原 operator carrier。现有 Node 保存回执记录策略与操作，不另造审核主体。远端只借用已保存且由接收者确认 operator 资格的 carrier，固定 Runtime 与 owner 实例；来源 caller 先在原 Core 认证，其 capability 不成为目标 Core 的本机 Agent 身份。configure 保留完整策略、expectedRevision 和原 operationId，回执未知沿同一操作读取。device、guest、有限发布 scope 与 route delegation 不因 Agent 在场而取得 owner 资格；私有 owner-resources、密钥和来源信任仍按各自权限合同执行。不得剥离 caller 后重试被拒请求，也不把对话文字当作传输 principal。

切换目标只改变管理视图，保留各原 Runtime 的未保存内容和操作；迟到回复不能替另一节点保存、显示其策略或覆盖后续输入。远端不可用或缺少接口时给出准确维护入口，不回退为本机策略。入站 listener 仍由原设备自己的配置 owner 管理，远端发布页不得误挂本机 listener 表单。仅打开系统资源共享时，保留原目录授权；原完整 policy 保存会重新确认目录目标，不把它误报为毫无目录效果的窄开关。

发布配置由原 Core 在自己的持久 Runtime 范围持有，包含规范别名、是否共享系统资源、共享目录白名单、禁止访问的路径以及访客默认进入目录。Desktop 是该公共能力的客户端，不能在 Renderer 配置第二份策略或靠隐藏 UI 实施权限。保存沿准确预期版本与真实持久确认；未知回复先检查原操作，不重放。未保存表单、其原版本基线和待确认操作属于 Desktop 编辑意图，沿[原用户状态持久 owner](persistence.md)保全；恢复只读取原操作，不因重开页面或进程而重新发布，另一 Runtime 不能消费这份意图。发布项失败不关闭健康 Agent、已有连接或原工作面。

别名是便于人使用的可变定位名，不是凭证、全球唯一机器名或持久 Runtime 身份。别名规则只描述可用于 URI 的规范形式，不能拿任意 Host label、SSH alias 或地址替代发布事实。当前入口只在自己已配置且认证的 Host 范围解析发布方；同名、离线与未确认不猜首候选，不自动扫描或取得新信任。需要稳定指向原对象的分享保留发布方 Runtime 身份，不能因别名重新绑定而打开另一个 owner 的同名资源。链接格式归[对象链接协议](../../specs/amux-protocol.md#对象链接)。

共享资源通过原 Core 的窄发布接口读取；所有调用者遵守同一已提交发布策略。系统资源未共享时明确表示未共享，缺测与暂不可读分别说明，不用 0 或连接失败代替。默认进入目录是浏览起点，白名单与黑名单决定实际读取范围：目标须属于允许目录且不属于禁止范围，禁止项优先。共享目录在真实路径解析及底层读取边界执行，不信任客户端的路径、链接或 GUI 过滤，不允许符号链接、父目录和另一入口绕过。对外根引用不泄露未发布的绝对路径；没有发布目录时不猜 `~`、当前项目或整个磁盘。

上述策略约束 AgentMux 发布入口，不是 SSH 账号、独立系统工具或 Agent 任意命令的操作系统沙箱。已有同账号 SSH owner 权力、Device 配对、创建/消息来源信任和单次 Agent 权限继续由原 owner 管理；发布别名或打开 URI 不授予这些能力，也不为实施发布规则追溯撤销已有健康工作。发布接口不得在拒绝后退回宽权限文件、Git、shell 或 `runtime.invoke` 通路。

`amux://host/<别名>` 进入已确认节点的资源工作面；嵌套 Agent 和 Capsule 链接分别定位该发布方的原 Session 与原 Capsule，不创建替代对象。Agent 的当前展示位置、继续资格与权限沿原 owner。远端 Capsule 必须经准确 owner 的授权内容载体及原输入协议建立本机访问视图；不能把远端 loopback URL 当成本机地址，不能放开监听或以转发 HTML 的方式冒充完整交互与授权。

## Host 路由视图与真实关系

原 Host 路由视图展示“本客户端 / 管理入口 → 原 endpoint 内 Host route → 已核验 Runtime”的逻辑关系。身份沿[Endpoint、Host 路由与源身份](public-control.md#endpointhost-路由与源身份)，不能把接收 Core 中的 `local` 一律画成 CLI 所在电脑；普通 Desktop 只有在原本机身份已确认时才显示 This Mac。Host 节点以原 endpoint 与 Host ID 定位，Runtime 有确认事实后再披露其准确绑定，不新增全局机器 ID。

边表示已保存或本次配置求值得到的逻辑关系，不承诺真实物理网络路由或正在保持的 socket。连接观测有来源时才在边上表达其结论与时间；没有当前观察时仍保留配置边，并明确其未确认性质。

节点邻近的网络信息消费原配置、准确输入上的检查及下节具名网络观察。未取得新观察时，hostname／SSH alias、用户、端口与 Runtime 绑定继续保持其原配置含义；未显式覆盖的值说明沿系统 SSH 配置，不补成已经解析或连接的网络端点。

系统 SSH 在本次读取明确给出的 ProxyJump 顺序可作为该路由的中转关系，标为配置路径；中转项只在原路由范围内辨认，不因此新增可管理 Host、Runtime、云区域或设备身份。SSH alias、内网 IP、相同名称或地理线索不能补出其他跳点；自定义代理只表示路径不透明，不解析命令猜中间设备。

同一 Host 的 Runtime、项目、执行器和 Session 关系放在选中详情或按需展开，不默认把所有资源铺成不可读的大图。多个 Host 是否属于同一物理设备，缺少权威身份就不合并；即使多个 route 已确认为同一 Runtime，也保留各自准确路由，不把连接别名统计成独立 Runtime。Host、Runtime 与会话聚合各保留自己的身份范围和去重口径。

拓扑内提供 Fleet map / Selected link 观察范围，与 Topology / List 呈现方式分开。Fleet map 沿原 Host 库展示环境关系；Selected link 只围绕当前所选 Host 投影同一 Host 网络观察中的配置中转与分源接口，不另设 Host 选择、草稿或事实 Store。范围切换不触发读取，不改变原焦点、保存、Session 或工作面；返回 Fleet map 保留原视口。

## 所选 Host 的只读网络观察

网络观察回答当前路由如何配置、原服务这次回应花了多久、各来源确认了哪些地址。GUI 与 CLI 经同一 Core 公共服务读取；准确 Host 配置、原客户端与 Runtime 身份仍由原 owner 持有，不在 Renderer 执行 shell 或新增网络事实 Store。

| 来源 | 提供的事实 | 必须保持的范围 |
| --- | --- | --- |
| 原 Host 配置 | 原 endpoint 内的 Host、hostname／alias 及显式覆盖 | 保存值不证明已连通，也不因只读观察被改写 |
| 系统 SSH 本次配置求值 | 目标 hostname、用户、端口、配置中转顺序与保活策略 | 复用原路由参数；当前求值不证明既有连接采用了相同配置。加密协议保活与 TCP 保活分开，策略不证明已收到保活响应 |
| 原 Owner 的新鲜公共调用 | 已确认 Runtime 身份、本次 Owner RPC 请求耗时及采样来源 | 单调时钟仅包裹这次公开调用；可能包含建连、排队与服务处理，不包含 SSH 配置解析或其他观察的总耗时，不称为纯网络 RTT、ICMP 延迟或逐跳时延 |
| 发起端与目标服务的网络接口 | 各自进程网络命名空间可见的接口名、地址族、地址、CIDR 与内部接口分类 | 两端各标实际进程来源，不将观察服务一概称为用户电脑；接口存在或名称不证明 VPN／隧道类型、连通性或当前出站接口。网卡地址不证明实际连接使用该 IP、NAT 出口或公网身份，不输出 MAC 或凭据 |
| 可选的发起端 DNS 读取 | 该观察端解析得到的地址候选 | 不要求首个闭环必须提供；候选不证明连接端点，也不代替跳板远端的解析结果 |

每次读取捕获准确已保存 Host 配置与原客户端，返回前复核两者仍相同；新鲜 Owner 结果通过原 Runtime 及服务代次核验后，才可关联请求耗时与目标接口。缓存身份不能代签这次网络回应。各来源分别带原采样或读取时间及局部失败，当前缺口与最后确认的旧值沿[状态、失败与恢复](remote-management.md#状态失败与恢复)表达，不把旧值刷新为当前正常或把缺测补零。

聚合查询先在原 endpoint 认证调用者；仅准确的网络只读叶借用所选 Host 的已授权传输，不把源端 Agent 凭据当成目标端身份，不放宽 Runtime 域的直接调用权限。无效调用者在网络观察前拒绝；合法 Agent 与用户经同一聚合能力取得具名来源结果。

GUI 只对可见的所选已保存 Host 显式读取或刷新网络，下述本机节点地址除外；CLI 沿同一准确 Host 公开查询，不以 GUI 可见为前置。节点渲染、缩放、筛选或选择全图不触发其他 Host 扫描，不另开定时探测与后台重连循环。SSH 配置求值可能执行用户已有的 Match exec，只在这次准确读取内进行。该求值仅返回上述网络字段，不将代理命令原文、完整命令输出、标准错误或额外私有路径加入观察结果及诊断，也不将解析值导入连接配置；用于原配置核验的 `configuration` 沿已保存 Host 配置合同返回，不属于 SSH 求值新增采集。正常请求可沿原传输的建连路径取得响应，不替换原消费者，不启动 Native、不枚举或恢复 Session，不重放输入；取消只结束本次观察，保留其他消费者和健康 Run。

已确认的本机 Host 节点例外地显示本机局域网地址，帮助用户告诉另一台设备“这台机器是谁”。来源是本机 Owner 在同一网络观察中给出的目标接口；Mesh 中本机 Host 页面可见时对本机读取一次，本机配置变化时重读，不轮询、不联网、不探测、不读取其他 Host。首选地址取非回环的 IPv4，有线与无线网卡优先，链路本地地址、VPN 与其他隧道接口靠后；其余地址按需展开。读取中、读取失败与本机确无局域网地址分别表达，不以空白或旧值冒充当前；接口地址不证明另一台设备可以到达这台机器。

物理路由器、网关、当前出站接口、实际 SSH 末跳 socket、完整物理路径、各级实际连接 IP、逐跳时延、丢包、公网出口与持续历史未有相应结构化来源时保持未知。链路与接口视图复用已有分源网络结果及原公共查询，不新增网关、socket、MTU 或接口类型采集；本范围不运行 traceroute、不访问外部 IP 服务、不修改保活策略，也不把配置中转节点画成已测得的物理网络。

## 连接配置与测试

Host 的公共配置链支持按稳定 ID 新增、读取、完整 expected/CAS 编辑与删除，并复用原 ConfigOwner、schema、持久确认与发布。登记未安装或暂不可达的 SSH Host 不要求远端 Core 已就绪；尚无已保存 Runtime 绑定、原已采用身份及本地 Session 投影的连接草案，修正或取消不以旧地址连接成功为前置，这不证明远端没有其他工作；已保存配置与当前连接事实分别表达。新增不能自报 Runtime 身份，已学习的 Runtime binding 不允许清空、改写或复用到另一 Host；已绑定的路由变化沿同身份修复核验。删除不能级联删除项目、Session、Run、草稿或工作面；已退休 Session 的原恢复与历史引用同样受保护，不能仅凭当前活动清单或 Run 为空移除原路由；仍被引用或无法确认可安全移除时保留原对象，给出准确引用与恢复动作。本机 Host 保持原唯一身份，不通过通用增删替换。公共操作沿原服务，不读写客户端私有配置文件；丢回执后先读取原保存事实，读取不能冒充原操作完成，不自动重放。

通用保存、冲突、搜索与草稿规则仍由[设置共同合同](settings-and-observation.md#设置页的信息架构)持有；本节持有 Host 专属要求，页面结构变化不授权另一份配置实现。

- SSH 连接的常用编辑为名称与 hostname／系统 SSH alias；用户、端口、密钥和服务覆盖按需展开，保留已有字面值与只读 Runtime binding；连接编辑不扫描或导入 SSH 配置，不自动部署服务，只读配置求值不回填覆盖字段。空覆盖沿系统 SSH 已有行为；保存连接不等于连接已就绪，Test 仍使用完整当前输入并显示真实结果。连接复用沿原 Workspace→Host 引用，展示选择不为全局 Executor 模板另存一份 Host 绑定；目标 Host 的注册配置与可用性沿[执行器设置 owner](settings-and-observation.md#设置页的信息架构)取得。Session 数只表达实际引用，不冒充运行中数量，原删除和保存保护不在布局调整中放松。 已确认本机 Host 不挂载 SSH 连接字段；其他对象的编辑挂载、精确选择、重复导航、新建聚焦、搜索命中与窄窗返回沿[设置共同合同](settings-and-observation.md#设置页的信息架构)。

- Mesh 的 Host 连接编辑区必须允许正常逐位输入 Hostname；首字符与后续内容变化不能自动折叠字段或移走输入焦点。展开/收起属于用户操作，同一 Host 的草稿、检查结果或无关配置更新不能改掉用户的展开选择；新 Host 可直接进入编辑。

- Mesh 的 Host 编辑同样保留原始字段基线与保存期间后续输入；无关 Host/字段提交只刷新 clean 内容，同字段冲突、准备失败与外部删除保留草稿，不用保存时的新快照消除冲突或静默重建。当前远端准备能力尚不可用时如实说明，不把受控准备条件下的保存成功冒充远端 Runtime 能力，也不打断无关本地健康 Run/Input。说明文字和 Test 反馈须与当前实际能力一致，不先承诺保存或测试可用、再在动作后否认；失败原因完整可读，草稿与健康输入保持。

- Host 的 CLI 读取已提交的连接记录；已保存连接按明确稳定身份取得当前已提交对象并测试，草稿才按明确输入测试，不猜默认 Host、焦点或显示名称；测试不改配置、工作面或健康会话。连接就绪、当前能力明确不支持与检查没有取得事实必须区分，不能把检查失败说成目标不可用，也不能把未知说成就绪。测试结果保留原始原因并绑定本次输入，CLI 回执与界面当前结论都不得把同 ID 的旧 Ready 用于后改或并发替换的连接值；新输入未测试时如实说明，不覆盖检查期间的后续编辑；远端尚不支持时如实说明，不用另一条启动路径绕过它。Host 删除、连接重绑与身份复用另有引用完整性合同，不能只凭可见会话或 connected Run 为空放行。

- **同一 Runtime 可以修复接入路由。** 用户明确保存已绑定 SSH Host 的新地址、SSH 用户、端口、密钥或服务入口时，Host ID、类型与已提交的 Runtime 绑定保持不变。候选须经系统 SSH 认证并由新路线上的原 Core 公共身份协议确认；不能只相信表单中的 Runtime ID，不能因旧线路不可达而要求先停止任务。删除 Host、改变类型、未绑定连接或换到另一个 Runtime 不属于这项修复，仍沿原引用与身份合同。

- 路由修复沿原配置 owner 提交准确的预期版本与完整候选输入。候选确认期间保留原可用连接和输入，不预先关闭读者；配置持久保存成功后才采用新路线。保存失败、取消、身份不匹配或并发变更保留原配置与草稿并说明准确失败步骤。GUI、JSON-RPC 与 CLI 共用同一提交，不各自写配置文件；响应未知时先读回原已提交对象核对，不能重放任何运行操作。

- 修复连接不等于重建工作。原 Session、Run、消费者、附件、历史观察与字节游标的保全及恢复资格唯一见[同身份路由修复](session-recovery.md#同身份路由修复)。管理台分别表达“配置已保存”“原 Runtime 身份已确认”与“原读者已恢复”；身份确认不能代签当前 Run 或阅读恢复，局部观察失败不拖垮其他读者和健康环境。不暗中部署、升级、重新授权、自动故障转移或重发未知输入。

- 从 Mesh 或 Quick 进入已保存环境时，原 Host 工作台按稳定 Host ID 展开连接、项目和维护。项目依据原 Workspace 的 `hostId` 投影；对象、子页和窗口尺寸切换继续保留原全库草稿、对象级展开选择、保存期间输入及冲突。

## 公共能力与当前基线

`settings.mesh.inspect` 读取配置和原保存回执，`settings.mesh.configure` 按原修订完整保存，`mesh.inspect` 读取当前网络观察。App 和 CLI 从设置读取结果取得原节点的公开配对码，并在保存前使用同一解码规则预览。CLI 入口为 `amux mesh code` 和 `amux mesh code read`。读取和预览不改变成员资格。`mesh.link` 经选定网关的已公布入口为原端点生成访问链接，端点仍按自己的设备授权处理访问。精确参数、权限、支持版本与命令见[公共能力来源](../../specs/public-capabilities.md)及[Mesh 操作指南](../../../packages/core/guides/modules/mesh.md)。

`mesh.inspect` 被动读取网络 producer 的准确当前快照，分开表达期望／采用修订、监听、peer 认证、拓扑、候选路径、时间、覆盖与局部失败；不因查看而建连、保存或铸造身份。`mesh.link` 只将完整原 ConnectionOffer 的 carrier 转为本 owner 已确认的网络路径与明确发布的 ingress，保留原 serverId 和 daemon E2EE public key；不从拓扑猜 key、不接受客户端任意替换 endpoint，不把监听地址或 peer 私有拨号地址冒充公网入口。路径或入口未知只拒本次转换，保留原 offer；返回链接仍由原终点认证和授权，不证明外网可达或业务完成。

现有源码已提供独立 `@agentmux/relay`、原 V2 E2EE、显式单网关出站和 Core 嵌入；这与既有 Core 显式业务多跳是两个层次。多网关拓扑与 Mesh 工作面按本文目标交付，是否已被当前构建和服务提供须另核，不能由单网关测试或页面名称代签。

## 状态与交付判据

配置已保存、网关正在监听、peer 已认证、拓扑已知、路径已采用、原 Core 已响应和业务完成分别表达。未测试、unknown、unavailable、stale 与真实零值保持可辨，当前失败与最后确认的旧事实各带来源和时间。观察缺口不能移除原工作面、重建 Session、关闭健康 Agent 或拿走其他已确认能力；恢复沿[原 Session 合同](session-recovery.md#联邦-runtime-与远端恢复边界)，通用提示和草稿继续沿设置 owner。

交付须验证实际多网关拓扑传播和必须经过中间网关的加密数据流，而非 mock 图或可直接到达目标的旁路。独立包、嵌入 Core、公开 CLI／设备 SDK 和 Mesh UI 各自形成实际消费；错误来源／key、旧修订、不一致邻接、循环、错目标、撤销与单路积压均有有意义的反例。新路径、断线与重启保留原 Runtime、Session、Run、key、未决操作和输入，不能自动重放；一个 publisher 失败时另一健康路径仍可使用。

公共配置和观察须覆盖 CAS 冲突、未知保存读回、持久确认与应用失败分离、原 caller／fence、热更新保全和停止释放。实现验收沿[测试策略](../../testing/strategy.md#任务验收与假绿防护)完成实际加载的变异与产品调用链；真实图形交付另做[独立看图评审](../../guides/agent-visual-e2e-review.md)，布局或生命周期变化沿原工作面与真实重启合同。纯文档整理只核来源、链接、冲突与语义保全，不制造实现通过；本地证据不代签远端部署、npm 发布或安装。
