## Mote 快捷入口与当前协调上下文

### 搭档界面与共享工作面

Mote 浮窗与 Space 交流面围绕同一位持久搭档组织：准确 Mote 身份、当前事情／讨论、原消息与输入、真实状态及下一步动作。Mote 可拥有多个讨论；讨论仍由原 Tab 承载，内部 Region／Session 的精确归属沿 Core 空间关系，不因一个名字或一种布局简化成一位 Agent。

Mote 使用自己的交流呈现，复用原空间模型、内容 owner、共享 Conversation／Composer、输入投递和 Core 生命周期。复用这些能力不要求原样嵌入通用 IDE 外壳，也不授权另建讨论目录、会话日志、输入通路或执行状态。交流面上的事情选择映射原 Tab／Group／Region；完整工作面与文件、编辑、终端、分屏和原全部成员按需可达，原布局、草稿、阅读位置、健康 Run 和执行 cwd 保留。多 Region 中选取交流对象必须沿原准确选择，未知时保引用，不猜首个 Agent。

同一对象的服务状态在一个持续可见的呈现层组织。短说明指明受影响能力与当前可用／未知事实；详情保每个原失败步骤、准确目标、原受据和已有恢复动作。摘要只组织显示，不建立新的健康 owner、不改变 action admission；可收拢但未解决事实持续可发现，不因关闭详情、发出重试或后来的无关成功清除。原权限／问题与确实未应用的操作仍有贴近该动作的明确反馈，健康原生输入、其他讨论和可用内容保持。视觉、密度与一致语言唯一见[同主题呈现](../presentation/motes-and-coordination.md#mote-快捷入口与当前协调上下文)。

常驻 Mote 按钮是稳定的功能锚点，使用固定品牌标识；当前已选 Mote 的名称、头像与真实状态在打开面和可访问描述中准确表达。功能入口品牌不作为当前对象的头像存储，也不替换主 Mote 或自定义 Mote 已保存外观。各处“召唤 Mote”按触发处明确目标或原已选目标进入同一个快捷面，各导航上下文保自己的选择；键盘召唤在原快捷键入口可发现，其组合、应用内或系统级范围与冲突由宿主快捷键 owner 明确，不以 hover 或导航替代发送授权。入口与面内动作的视觉状态见呈现合同。

### Space 中的协作者名册

Space 的同一 Mote 名册支持协作者视图与常规列表，显示选择及名册头像尺寸由原 Settings/config owner 保存。用户明确要求缺省头像尺寸为 45；同一个有界尺寸设置同时作用于协作者视图与常规列表，列表行随头像高度调整并保紧凑文字和对象动作。设置提供按实际尺寸显示的头像剪影预设，点击选择后仍可沿原滑块微调；两者编辑同一设置草稿，明确保存后生效。浮窗和名片的头像尺寸各沿原合同；缺省值调整不覆盖用户已保存的尺寸。协作者视图突出可辨头像和名字，列表适合紧凑扫描；两者消费同一文件事实、身份、搜索、固定/排序、当前选择和对象菜单，切换或调整尺寸不重建 Mote、Tab/Region、资料、未发送草稿或 Session/Run。未保存设置保持原已确认呈现；保存冲突或失败保选择草稿和原可用工作面。缺省选择协作者视图，读取不写回配置。

选择打开准确原 Mote，改名、头像、行为设定、新讨论、资料、固定与归档/恢复沿原对象动作。归档筛选用同一图标与已确认数量，保可访问名称、开关状态和原焦点恢复，不把归档或未知当执行终局，不影响主 Mote 保护。完整 Profile/Ideas/文件仍沿共享 Space 框架；浮窗保同一搭档交流面与准确原资料、完整工作面入口。

显示偏好作为 Desktop 的 `moteDirectoryView` 标量复用原 `settings inspect/set` JSON-RPC／CLI 与耐久 config owner，合法值为 `collaborators`、`list`；名册头像尺寸沿同一入口保存为有界数值显示偏好，公开设置的缺省值与此处用户确认一致，范围由该设置的公共合同定义。两项偏好不属于 Core 空间身份、执行事实或用户 SOUL，不新增 Mote 管理协议或运行时。

左下产品入口称为 Mote，按钮、快捷面和实际协调上下文保持一致，原 Mote 持久身份不变。用户应该在点击前后都知道入口会打开哪一段工作、现在是哪位 Agent 在处理，以及怎样进入同一完整工作面。

快捷入口保持贴近按钮、全部对象可达和原交流层级。快捷入口采用同一个可操作面：悬停临时呈现，明确交互固定；所有 Mote 与原工作面在这个面内可达，不再另叠一块只说明用途的 tooltip。

窗口内 Mote 对象位于左侧，在宽卡片与仅头像两态间明确切换，面板边界与背后工作面可辨。对象导航与事情导航分层，仍是原来的同一个可操作快捷面。

左下 Mote 面板与 Work 中 Mote 实体的导航边界只见[Work、Survey、Recall 与 Mote 的导航上下文](spaces-and-layout.md#worksurveyrecall-与-mote-的导航上下文)，本节继续定义原协调对象与快捷面的行为。Mote 与 Topic 的文件树使用同一公共能力；Mote 文件区固定浏览该 Mote 的原真实根，不提供展开整个共享目录的“Show all files”或面向普通知识 Topic 的收集入口，普通文件及知识能力从各自原场景可达，不借 Mote 顶部改变范围或把引用收集叫文件保存。二级内容按对象表达：知识库 Category 展开具体 Topic，Topic 显示自身讨论、知识与资料，Mote 呈现同一持久对象的自我设定、名片与点子，让用户理解这位搭档和怎样继续合作。知识层级只见[《Topics 知识库的层级与沉淀》](spaces-and-layout.md#topics-知识库的层级与沉淀)。自我设定与名片沿原名称、头像、SOUL 等事实，点子沿已有持久笔记与资料能力，不另造人格、Memory 引擎、记忆存储或强制资料分类。菜单文案与具体分组数量不由本条规定；框架与共同工作面只见[《Space 的统一工作面框架》](spaces-and-layout.md#space-的统一工作面框架)。Mote 主选择器只列 Mote，跨对象浏览仍由 Space 中分开的 Motes 与 Topics 分区承担。同一 Mote 可以有多个自己的 Tab/Group，这些事情标签不表示多个 Topic；Mote 与 Zone 不合并身份，也不改变既有实体多处展示绑定。共用文件树不改变原文件资源归属，导航分类与物理存储仍是不同事实；目录分离与已授权迁移统一遵守[《Topic 与 Mote 的物理目录》](#topic-与-mote-的物理目录)。

Mote 在 Space 中的二级对象内容以 Profile 为首屏，Ideas 承载原笔记与点子；原 SOUL／自我设定直接呈现在 Profile，沿明确文件编辑动作进入右侧原 Editor，不另设 Persona 切换。对象内容仍在共同框架内，保同一原 Zone 工作面与公共文件能力，不另造 Zone 导航、文件树、Editor 或 Tab/Region 管理；切换与原工作面的保护统一遵守前述 Space 框架，普通 Topic 保持自己的内容。 名片首屏以准确身份、已保存的合作方式和当前事项为主；`topic.md` 的原摘要收在注明文件来源的按需展开处，与原 `SOUL.md` 分开辨认，并可沿原 Editor 编辑。展示调整不按文案猜测哪些内容是默认模板，也不删除已保存摘要；没有事项或点子时保原创建／查看动作，读取尚未确认或失败时仍保可读说明与原恢复动作。

**对象范围与成员完整隔离。** 从树、快捷面、恢复、来源 Session 或公开导航打开 Mote，都建立同一准确 Mote 与其原 Zone/Tab/Region 展示引用。其工作面只枚举原空间关系明确关联的成员，不因共用 Scratch、旧 `topicId`、cwd、标题或相邻 Tab 把其他 Topic／未绑定 Topic 的 Tab 纳入；经原关系明确绑定的外来 Zone、Tab 与合法跨 Workspace 展示继续可达，隔离不是删除共享内容。该对象内切 Group/Tab/Region、编辑文件、输入或新建工作面保持 Mote 范围，局部落焦不能清掉对象选择后跳回 Topics。只有明确的跨对象导航才切换对象；外来文件的资源归属不自行改写当前 Mote 的选择。成员或位置未知时保原引用、已确认成员和当前工作，给出持续恢复说明，不退回整份 Scratch、猜邻居或自动创建替代 Session。未绑定 Topic 的原 Zone/Tab 仍在明确的全局入口可找到。名片、文件动作和讨论导航使用同一范围，进程重启先恢复该对象与工作面，健康 Run、草稿、布局及执行 cwd 保留。

Mote 浮窗是原交流工作面的快捷入口，文件与编辑等完整工具能力在同一 Space 内继续可达；浮窗的身份与事情区可用一个 Profile 动作按需开关同一名片，复用原自我设定、快捷配置、事项和点子动作，默认保交流工作面。名片开合与窄面切换保原工作台、对话输入、草稿、准确展示引用与 Session；关闭或隐藏的名片不新增资料读取，不另建文件树或 Editor。进入完整 Space 的 `Open in Space` 动作与当前准确对象和讨论相邻；空 Mote 沿原空态顶部保留同一动作，不为了提供入口新建 Tab 或 Session。导航沿当前已选 Mote 与已确认的完整 Tab／Group／Region 引用接手原工作，保原草稿、模式与健康 Session／Run；位置未确认时仍按本节原目标保护与恢复说明处理，不猜另一个位置，也不关闭可用正文。此分工不取消 Space 的原文件、编辑、人格和资料能力。空 Mote 的文件或目录终端动作由用户在已确认的同一 Space 明确发起，沿它当前实际呈现的活动 Pane 放置；先核原资源、Space 绑定和可见 Group，不借背景项目或未知保存地址，不先造讨论。

- **名片和自我设定能操作原对象。** 用户能查看已确认的名称、头像、真实摘要与原 SOUL；名片头像本身是该名片唯一更换头像的入口，姓名旁的改名动作沿原耐久名称 owner，不新增外观或改名机制。编辑绑定打开时的明确原 Mote 和所属 Workspace；资源重绑不自动更换原目标或清空未保存草稿，错误保存由原资源 owner 明确拒绝，不借邻居作目标。关闭编辑面只在原触发控件仍可用、当前仍属同一资源且没有后来外部焦点时返回它。自我设定按前述 Profile 首屏分工呈现，不重复提供功能组跳转链接；未确认的摘要不以模板介绍代替。合作方式与知识检查沿原内容 owner 按需进入，保存、生效、冲突和未确认继续由该 owner 负责，不借此改写运行中的 Session。头像编辑与改名的保存／取消／失败保全分别遵守本专题原头像与耐久名称合同，真实运行状态、SOUL、笔记和原工作面保持。
- **点子能查看、编辑和继续。** 点子沿当前 Mote 的持久笔记与资料查看，用户可明确通过原文件／笔记动作创建或编辑，打开已有来源讨论与成果，再沿原讨论动作继续交流。Profile 只展示有限若干原笔记标题，近期顺序沿原文件系统已确认的修改时间；时间缺失或读取未确认时如实说明，不用列表顺序、刷新计数或当前时间伪造近期。点击标题切到 Ideas 并定位同一准确原笔记，不借邻居 Mote、重读整份目录正文或维护另一份笔记缓存。条目引用原内容与已记录的来源，不复制正文、聊天或进度；来源和范围未记录时如实说明，不从邻居 Session 推断。没有笔记时保原文件访问和明确创建入口；读取失败保原引用、草稿与服务窗。知识组织仍自主，不强制固定点子文件、资料分类、Memory 引擎或新的 Goal／Task 账本。

Mote 的交流面支持与多位搭档合作，以及同一 Mote 下的多个原讨论与会话。Mote 浮窗与 Space 中打开的 Mote 工作面遵守同一对象与会话层级：多个 Mote 是持久对象选择，所选 Mote 下的多个 Session 与承载事情的 Tab/Group、实际 Region 各有准确归属，不能把会话数量画成 Mote 数量或把普通 Topic 默认变成该 Mote 的成员。Mote 工作面围绕交流与原正文输入呈现，在前述共同 Space 框架内继续复用原 Zone/Tab/Region、文件与 Core 生命周期；普通 Topic 保持自己的知识内容。交流参考用于对象、事情、消息与输入的层级；呈现导航映射原 Tab／Group／Region，不生成第二套空间、Session 或讨论事实。进入、切换和往返保原 Tab、Region、健康 Session/Run、非空草稿、执行历史与恢复，不复制聊天或重启 Agent。文件访问沿同一公共文件树与明确资源目标，原 Mote 的耐久资料及全局浏览仍可达；知识组织由 Mote 自主，不强制分类或搬目录。身份通过对象导航及一个清楚的搭档身份区持续可读，当前事情和实际执行者分别表达；完整工作面与模式能力沿原 owner 可达，不叠加重复操作或另存模式。具体视觉稿与真实正常/窄窗/失败场景须独立评审，不能只以复用组件或采图成功冒称达到该交流体验。

Mote 的事情导航使用 `Discussions`／`New discussion` 等用户可懂措辞并映射原 Tab；讨论承载原 Tab，内部可以有多个真实 Region／Session，不把改文案变成新会话或让 Tab 与 Session 同义。发言显示准确作者：只有实际 Session 的 Host、运行目录与原 Mote 耐久身份明确相符时，才用该 Mote 的持久名称与同一头像；同处当前工作面、同名标题或表面关联不构成归属，外来或未知作者保原真实身份。正文、历史、输入与操作继续由原内容 owner 承担，不复制另一份聊天记录；原消息与讨论导航在宽窄工作面中的可读性唯一见 surface-density 同名章节。资料读取慢或迟到时仍保原文件 owner 的结果，但不因返回时又选中同一 Mote 就抢回旧选择；同一 Mote 下较晚选择的讨论／Region、A→B→A 往返后的新意图、后来输入与焦点始终优先，失效请求不重新选择旧文件、讨论或工作面，也不收起后来打开的资料栏。

名称和常用对象动作在原对象入口可发现。Mote 的改名与常用对象动作在原名册／Space 对象菜单中可发现，鼠标与键盘均可达；改的是同一耐久 Mote 的语义名称，不是某一个 Session 的显示名，不改目录身份、SOUL、头像、已有 Tab/Region、执行绑定或健康 Run。保存／取消／失败及迟到结果保原对象与草稿，浮窗即使在 Settings、Focus 等背景上也绑定原 Mote 和所属 Workspace，不能借当前背景项目误投。头像、人格、资料／完整 Space、pin 与归档／恢复沿已有能力和主身份保护组织，常用动作足够合理且主次可读；对象管理与当前 Session 的关闭、分屏、输入附件、模式动作分别指向真实原目标，不把菜单扩充变成新增执行能力。系统层级与弹层命中只引用[《浮层让位默认成立，而不是逐个接线》](browser-workface.md#浮层让位与输入层级)本次反馈合同。

尚未启动 Agent／睡眠的 Mote 工作面也围绕当前 Mote 自身：原启动面标题显示已确认的这个 Mote 名称，不把 Topics/Scratch 收纳容器当作当前对象。对象名称与实际运行环境分开，Host、工作目录和启动参数仍是原资源事实；名称尚未确认时保原工作面并如实说明，不借默认或邻居 Mote。普通 Topic、Folder 与空 Group 沿原环境身份。此要求不合并 Mote、Zone、Tab 或 Session，不改变多处展示绑定或物理目录。

- **面板内同一个当前目标**。左下入口的无障碍描述、快捷面选择与当前状态都指向该面板已选的同一个 Mote、实际 Tab 与当前 Region；「Open in Space」明确将这个准确目标一次带入 Work，此后两边各自保留选择，沿前述导航上下文合同。Mote 表达持久协调对象，Tab 名表达当前事情，Provider/Executor 和 Session 表达实际执行者，不能相互冒充。Goal 的专属讨论仍是自己的 Tab，入口必须能读出该 Goal 的上下文，不能只用泛称 Mote 掩盖正在打开另一件事。自定义 Mote 的投影、准备与完整 Space 都指向它自身的持久对象与准确原空间关系，不借默认 Mote 的工作面。
- **可进入的悬停面**。鼠标悬停入口即显示原可操作面，允许越过按钮与面板间的小间隙进入、滚动、选择和输入；未固定时离开两者后自然收起。悬停本身不改变 DOM 焦点、光标或组字，不选择另一个 Mote/Tab/Region，不持久化打开状态、不写视图模式、不启动 Session/Run、不发送或入队输入。键盘与触控有等效的明确打开入口；Escape 收起预览，不抢走输入法或另一块已打开浮层拥有的按键，也不把未移动过的焦点拉回入口。
- **不同工作面同样可操作**。用户反馈在 Mote 工作面 hover 后可移入操作，切到设置页却只能看到窗口、无法操作。Settings、Space、Focus、Goals、Survey 等窗口内容切换不改变同一个 Mote 快捷面的可进入性；面板及原投影不能继承被设置遮住的背景工作面的 inert/隐藏归属。移入、明确固定、选择与输入仍沿原 owner，悬停不关闭设置、不移动原焦点、不写 Agent 模式；被设置遮住的背景继续不接收输入，健康 Run 和原 Tab/Region/草稿保留。
- **全部 Mote 可选**。快捷面呈现既有默认 Mote 和文件系统已确认含 SOUL 的全部 Mote 对象，每个对象有紧凑可选行、可读身份与它实际目标的状态；多个 Tab 或 Session 不冒充多个 Mote，普通 Topic 不混入名册。超出可用空间时仍能滚动到全部对象，不只取默认或当前一个。目录、快捷选择与焦点分类共享同一份文件快照事实及修订边界，不新增 Mote id 名册、不在 Tab/Session 上复制身份布尔，也不把分类另行持久化；目录读取失败保留已有事实与已选原引用，说明未知和失败步骤。 冷读也按独立事实处理：原目录 owner 已确认的完整身份、实际地址及 Mote 类型不依赖协作者牌、介绍正文或 Wiki 同时读成功；局部失败随原对象说明，不能把已确认 Mote 从名册拿走。身份或类型证据本身未确认时保未知，不凭所在目录、名称或邻居推断。原 list/read 与共同文件快照承载这些事实，不另设持久名册。
- **Mote 与 Tab 分层**。全部对象沿快捷面左侧导航排列，右侧以搭档身份、当前讨论、原正文与输入呈现所选 Mote，讨论和完整工作面仍映射原 Tab／Group／Region；不再把对象列表叠在 Tab 上方。明确且可访问的开关在宽卡片与仅头像两种呈现间切换，初始为宽态；两态都有同一组对象、同一精确选中与真实状态，完整名称和状态在头像态通过 hover、键盘焦点及无障碍描述可读。对象多时左侧有界纵向滚动，收起与呈现切换清楚组织，进入完整 Space 与准确对象／讨论相邻；搭档身份区表达当前对象，不叠加重复操作入口。
- **导航呈现偏好独立**。宽卡片/仅头像只是快捷面的单一呈现偏好，由原浮层 UI owner 保存，关开与普通 UI 状态恢复后保持；窄窗可收紧宽态名称空间，不能静默替用户改成头像态或让开关语义与实际呈现不一致。从临时面操作开关仍沿既有明确交互固定语义；切换自身不选择别的 Mote/Topic/Tab/Region，不改原 Agent 模式、执行焦点与历史、草稿、消息队列或 Run，不重建右侧原输入和工作面，不增加逐 Mote 偏好账本或另一份目录事实。
- **范围内拖拽尺寸并记忆**。用户要求 Mote 浮窗「要支持下一定范围内拖拽改变大小(并记忆)」。临时与固定面仍贴原左下入口锚点和小间距，允许从可辨的边缘／角部拖拽改变宽高，保持入口与面板的联系，不成为自由移动窗口。两种左栏呈现都支持，尺寸偏好由同一个原 floating UI owner 保存，关开和普通 Renderer 重载后读回，不另存逐 Mote 尺寸账本，也不改变所选目标、原 Tab/Region、草稿、输入模式或 Session/Run。可用下限让当前卡片／头像导航、必要动作与右侧原正文输入仍可操作；上限由当前 viewport 的实际可用空间决定，收窄或变矮时重新夹紧，视口小于通常下限时仍以当前可见可操作空间为界，不能把浮窗或动作挤到屏幕外。暂时收窄只改变有效尺寸，不改写用户偏好的大尺寸。拖拽越过边界仍能完成或取消，pointercancel、Escape 和失焦（blur）终止均取消未提交手势并回到拖拽前尺寸；结束、取消和关闭后不留下指针捕获、resize cursor 或阻碍输入的遮挡。首次未调整时沿当前默认尺寸，偏好读写失败保留可用浮窗和原工作并说明未保存或未知。
- **明确重新打开先对话，自然固定延续所见面**。用户要求「Mote 窗口打开时默认显示为对话模式」，并明确选择每次重新打开先显示对话、打开后仍可切终端。点击入口或从既有显式上下文入口重新打开准确 Mote 时，当前实际 Agent 的原工作面先显示对话；先 hover 再点击入口仍是明确打开，不能绕过。开着时用户仍可手动切 Terminal；同一已打开目标的重复打开请求不重置其后来选择，显式转到另一准确目标则按新打开先对话。单纯 hover 不写模式；在可见面内选择 Mote/Tab/Region、聚焦、操作或自然固定仍延续同一个所见正文和草稿，不借此翻转模式；尺寸和左栏呈现切换同样不重置。只有当前已确认存在的目标 Agent 承担这次模式请求，不改邻居或其他 Session 的模式；没有真实 Agent、空态或恢复未知保留原引用与现有告示，不猜替代目标、不启动。原 Session 仍持有同一份模式事实，其已有其他显示位置消费同一模式；不另存 Mote 或逐投影模式，不复制原 Runtime。重新载入已固定面不是新的人类打开，沿原保存模式恢复。本条替换旧「关开仍优先保留显式 Terminal」的要求，hover 无写入与面内自然固定的保护不变。明确打开和面内操作沿原固定语义，离开鼠标后仍可继续输入；已经固定的面不因再次经过按钮生成第二块面或抢焦点。两种显示都贴同一入口锚点并适配视口，不提供自由移动、最大化或独立位置记忆；有界尺寸拖拽与记忆遵守本节对应条目。原准确目标、Tab/Region/Session/Run、草稿与队列、执行历史和背后导航选择保持。
- **目标状态来自目标本身**。入口及各 Mote 行表达各自实际目标 Region 所引用 Agent 的真实状态，不把邻居 Session 的 Working、Needs you 或错误当作当前目标状态。已保存目标尚在恢复、尚无 Agent、当前 Region 是其他工作面以及状态未知分别按事实说明；读不到状态不能猜空闲或错误，也不因无关 Session 更新改变当前反馈。收起态只消费当前目标，展开后只增加所示 Mote 与原工作面需要的 Session、名称和事实消费者；目录读取只随所属修订更新，不订阅整份 Timeline 或逐 Session 反复扫描全部 Tab，不让无关 Run 输出放大入口工作。成本底线继续归[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)。
- **协调焦点不污染执行历史**。默认和文件事实确认的自定义 Mote，其协调 Session 都使用既有独立协调焦点；选择 Region/Session、切模式、明确输入与初始化恢复遵守同一语义归属，不能只在浮窗补一个特判后仍把自定义 Mote 的协调 Session 写入执行 Agent 的历史。Mote 在 Space 中的导航选择可更新 Work 的准确对象／位置引用，不反向改写面板目标，也不把协调 Session 重新分类为执行 Agent。已知普通 Topic 和执行 Agent 继续沿原执行焦点。Scratch 身份暂时未知时保留原 lane、选择与历史，给出旁边的服务窗；不猜成普通执行对象，也不等待目录检查完成才允许运行。
- **开合保留上下文**。关闭只收起快捷面，保留已选 Mote/Tab/Region及原 SessionId 或 launcher RegionId 草稿；重新打开回到同一工作。已固定开合与目标沿原 UI owner 持久化，临时悬停不在重启后伪装成用户固定。显式 Goal/Focus 入口仍按前述跨上下文合同选择其精确目标；用户在快捷面主动选择其他 Mote/Tab/Region 只更新面板选择。各处名称、身份、内容与运行状态消费原同源事实，不据此同步导航选择。背景工作面切换、Session 列表顺序、迟到目录读取或恢复事实不擅自更换已选目标。打开完整 Space 是明确进入同一准确目标的一次 Work 导航；收起面板后背景继续所属导航上下文的当前选择，不能恢复旧快照覆盖后来选择，也不停止 Run、不新建 Session、不改写执行 Agent 的独立焦点与历史；只有明确 Send/Queue/Launch 沿原输入 owner 消费原文字。
- **逐 Mote 记住最近访问的 Agent**。每个 Mote 记住最后一次明确访问的原 Agent 及其 Host、Session、Tab、Region 和展示位置。Space 与快捷面的真实 Tab/Region 访问更新同一个 client 展示偏好；名字、文件访问、自动补位置、关闭邻接、目录与运行观测、单纯 hover 不冒充 Agent 访问。展开快捷面或切回该 Mote 时优先回到它，原草稿、输入与身份延续，不先显示 Choose a discussion 中间页。显式 Goal/Focus 的准确目标仍遵守这次人类意图；当前打开的面不随背景访问或迟到事实跳走。配置的主对话仍是独立持久配置与固定首位规则，只在没有最近访问和原保留目标时作为首次入口；旧 Mote 也可沿其已确认的原活动 Tab/Region 直接进入，不按数组第一项或别的对象猜地址。最近 Agent 观察或位置未知时保原完整引用、成员及服务窗，不借主对话冒恢复；已确认原 Tab 删除才消费关闭事实并保留其他原工作面，多处位置仍存不清实体。真正没有任何原 Tab 且事实已确认时才显示新建引导。最近访问仅是导航偏好，不复制分类名册、Runtime、Session、模式或另一套持久空间引擎，沿原 client 偏好持久化，普通 UI 重载可恢复。
- **关闭 Tab 按明确意图继续**。用户反馈关掉 Mote 的 Tab 后仍显示“Original Tab retained”并要求回 Space 恢复。收起快捷面与关闭其中的 Tab 是不同意图：经既有确认已实际删除当前 Tab 后，同一 Mote 有其他原 Tab 就继续其原工作面，没有剩余 Tab 就保留该 Mote 的可操作空态，允许用户明确新建；入口、正文、状态与完整 Space 指向同一结果。关闭后沿原 Group 已提交的剩余选择继续，剩一张与多张同样成立；仍有该 Mote 的原 Tab 时完整保留公共 Tab 导航，不能把没有当前选择、保存的空选择或位置未确认当成零 Tab 而隐藏全部成员。保存的空选择只说明当时没有当前讨论，后来已有 Tab 时恢复原讨论导航。确实零 Tab 且目录和成员已确认时才显示新建引导；目录或成员未知仍保原引用与服务窗，不冒称空对象。取消或失败而仍保留原 Tab 时保留原目标；只移除一处位置而 Tab 仍有其他合法位置时保留原对象，不冒称实体或 Session/Run 终局。已关闭事实与后置清理失败分别表达，原错误告示保留，不能继续引用已删除 Tab。不借其他 Mote，也不为清理失效目标停止 Session/Run、悄悄新建或重开已关闭 Tab；空态打开完整 Space 仍展示同一 Mote 的空态，新建只由用户明确 New Tab/+ 消费。已确认存在的选中 Mote 没有任何原 Tab 且成员事实已确认时，统一呈现此可操作空态；切到其他 Mote 再回来仍为空，目录确认不自动补 launcher，不另存逐 Mote 的关闭历史。保存的精确未知 Tab 引用不因没有已放置 Tab 被清成空态。仅因原目标暂未恢复、位置未知、恢复超时或读取失败时，仍按“恢复未知仍有原目标”保留原引用；明确关闭的结果和空态跨普通重启保持。
- **恢复未知仍有原目标**。目标 Tab/Region 或 Session 暂未恢复时，保留原引用与工作面投影，原草稿不交给其他 Agent；在同一快捷面说明等待或失败步骤、当前可用或未知事实及已有恢复动作。不能跳到另一个可用 Agent 来伪装恢复成功，不能为流程失败清空原目标或停止健康 Run。跨真实进程重启仍先恢复工作面与本入口的已选目标，再沿既有公开能力尝试 reattach/resume。
- **恢复说明旁仍能继续原工作**。用户实际反馈 Mote 浮窗正文全空，只剩原 Tab 位置不可用并要求回 Space 的说明，也追问 Space 中点 Mote 是否还没有专属页面。身份已确认的 Mote 在浮窗与 Space 都通过共同框架呈现同一交流体验，自己的原讨论、实际 Region／Session 与资料入口仍可辨，不另造第二套页面。保存的精确 Tab／Region 暂未恢复或当前位置未确认时，保原引用与可行动的服务窗；说明不能拿走整个讨论导航和正文操作面，同一 Mote 已确认的其他原讨论仍可枚举并由用户明确选择。恢复动作指向准确原对象，不能仅让用户凭技术字符串猜去哪里操作；已确认原目标可恢复时继续其原正文，暂不可确认则如实说明。快照、Tabs 或当前 Group 中缺席不等于明确删除、retired 或 unknown 终局，不从另一个 Topic 的 active Group、别的 Mote 或第一个健康 Agent 猜恢复；实际明确关闭仍只按前述关闭合同处理。原草稿、布局、Session／Run 与后来选择保留，不为修空白自动新建、重开已关闭 Tab 或停止健康执行。
- **投影只承担自己的上下文**。窗口工作面 owner 绘制全局导航 chrome；快捷面等 workbench projection 保留准确 Tab／Region 引用、原操作与自己的交流呈现，不复制背后 Goals、Focus 或其他主工作面的全局标题。快捷面内和背后的 Browser 都保持原内容与可操作区域。没有真实显示 bounds 变化时，悬停不触发 Terminal fit/Runtime resize；所选 Mote 的原 View 真正转入快捷面时，相关显示尺寸可由原 fit/Runtime owner 适配，收起仍恢复原 Tab/Region、阅读与工作面。背景、无关 Terminal 和隐藏 slot 不因浮层开合产生尺寸写入或工作放大。原生层级与尺寸统一沿[《Browser 任务能力与可复用资产》](browser-workface.md#browser-任务能力与可复用资产)及[《Hover 提示不改变 Terminal 几何》](terminal-reading.md#hover-提示不改变-terminal-几何)，只依赖通用 overlay 与实际 Region 事实，不为 Mote 或具体站点写特例。

按钮展开、左侧对象导航两态、状态、动作与窗口外缘的视觉分工唯一见 surface-density[《Mote 快捷入口与当前协调上下文》](../presentation/motes-and-coordination.md#mote-快捷入口与当前协调上下文)。跨 Mote 选择复用既有对象目录、Tab、Region、焦点、命名与状态 owner，不增加默认 Tab 或逐 Mote 记忆注册表、第二份消息投递通路或 Runtime/Session 生命周期。

## Mote 的日常合作

Mote 提供可理解、可纠正、接得上工作的长期合作体验。合作方式、记忆检查、安排、点子和成果在原 Space 对象内容及原对话里可达；浮窗仍只作同一交流工作面的快捷入口。它们消费原文件、目标、Session 与调度事实，不产生第二份文件树、记忆数据库、任务账本或 Runtime。外部连接器采用通用连接结构；设置启用后，每个 Mote 内 Agent 的创建／绑定群入口及原 Session 关系沿[共同对话协议与外部交流入口](conversation-mode.md#共同对话协议与外部交流入口)。外部应用、准确受众与每次操作仍需实际授权，不因 Mote 身份授予账户工具或远程权限。

- **每个 Mote 的快捷模式。** 原目录中的 `MOTE.md` 以有版本的 YAML 保存默认 Executor 和默认会话的原 Session／Host、Tab／Region 及准确展示位置；正文可保用户备注，不存绝对路径，也不在 SOUL 中复制可写配置。Profile 展示已保存选择，重新打开编辑选中同一事实；新旧 Mote 均可直接配置，不迁移身份或覆盖原资料。界面称「Executor for new chat」，默认 Executor 只为该 Mote 的新 Launcher／明确启动预选，用户仍可改选，不改共享 Workspace 偏好、已有 Agent 或权限。默认会话沿原 catalog 和公共 Workbench 验证，进入而未指定另一准确目标时打开原会话，在本 Mote 的原 Tab 行排在首位并保持常开；取消默认选择后沿正常关闭行为。显式导航、后来选择与输入优先，保存不启动／停止 Run、不发送消息、不另建替代 Session；进入时的原会话恢复只遵循本节[《主对话的自动接回》](#主对话的自动接回)，其他位置和成员保留。无效、未知或尚未恢复的保存引用仍可检查和修正，不能任取其他位置、丢弃原工作或以观察失败关闭健康 Agent。配置沿原 Files／Editor 的版本保存与未知恢复 owner，并可由既有公共 Files、空间与 Agent／Executor 发现和操作能力读取、编辑和消费，不另建配置数据库或生命周期。
- **认识与行为方式。** 首次建立关系可以跳过，已有对话和用户当前输入优先。Profile 展示该 Mote 已确认保存的行为摘要；再次打开设定时选中同一保存事实，不能把表单草稿称为已保存。行为方式设定采用与头像设定一致的可操作编辑体验：四组具体行为偏好及自定义文字可选择、预览和撤回。四组分别对应交流朝向、获取信息、权衡建议和推进节奏；完整、明确的选择导出 E/I、S/N、T/F、J/P 四字母 MBTI 风格标签。它只概括用户选择的合作偏好，不把任意 SOUL、头像、运行状态或模型回复当作人格测评依据；未确认的设定不猜标签。独立 `BEHAVIOR.md` 是已保存行为的单一权威，以有版本的 YAML frontmatter 表达结构配置，以 Markdown 正文保用户补充，`SOUL.md` 以相对引用关联。文件仍沿原文件与 Editor owner 可读、可编辑和耐久保存；未知格式、读取失败、冲突及保存未确认保原内容与草稿，只拒绝无法确认目标或内容的那次保存，不拿走健康会话。新文件确认不存在时，唯一完整的旧 SOUL 应用行为块可作为明确标识的待导入来源；只经用户明确 Save 建立新文件并将该精确块换为相对引用，块外原文保留。已存在的新文件不被旧块覆盖，两文件尚未全部确认时说明实际未完成步骤，保可恢复原文件与请求的选择；首次主动改风格不冒充外部冲突，也不留两份可写行为权威。原新对象初始化可 create-only 提供默认文件，read/list 与 Cancel 不改盘。跨对象、迟到读取或后来编辑不能覆盖当前目标和输入。用户可用自己的问题沿原 Launcher 在明确的新 Session 试聊，实际 Agent／模型、生成状态与失败可辨，不把规则预览或预写台词冒充回复，不替换正在工作的 Run。新 Session 和明确合作准备实际读取已保存行为文件与原 SOUL，并保本次来源、版本和未知；已有会话的原上下文不热改，临时指令仍优先于已记偏好。行为偏好和标签不新增工具权限、自动输入、外部授权或主动跟进开关。
- **检查与更正记忆。** 用户能从 Profile 按需展开该 Mote 原 `MEMORY.md` 短索引，查看原保存正文、准确文件与版本，并回同一原 Editor 更正或撤回；相关资料沿原文件链接和文件树组织。收起或隐藏不读正文，重新展开读取当前原版本；读取失败保本对象最后确认的内容与准确引用，并提供重试。未保存的 Editor 草稿与原保存正文分别可辨，后者不冒充已包含草稿。没有记录来源或使用事实时表达未知；目录中的普通点子不能自动被称作已记住的事实。保存、读回、冲突和未确认沿原编辑 owner，保原草稿及正确资源，不盲重写。原索引读取和展示不证明模型实际使用；新讨论继续沿原 `prepareAgent` 加载启动时的原文件，不重复注入准备时的旧MEMORY正文。资料组织自主，不强制额外记忆文件或分类，不吞入全部聊天；改变记忆不删除原历史，也不扩大执行授权。
- **耐久知识与凭据边界。** 短入口保有来源、日期与范围的偏好、决定、纠正和原证据索引，过程流水与历史观察沿原记录留存；整理前保全原文与链接基础，当前 Goal、Runtime 和安装事实仍回原 owner 核对，不把旧状态反复追加成当前事实。凭据不写入会自动加载的 SOUL、AGENTS、MEMORY、topic 或 Wiki；普通知识只保不含秘密值的用途、范围和定位。需要保管的敏感值交给原 Host 凭据 owner 或系统凭据服务，授权操作时按需取用。迁出前确认安全保存与读回，未确认不丢弃原值或冒称修复；更改原文件不声称已擦除既有模型历史。
- **日历安排。** 用户能表达一次、每日、每周、每月与每年的当地时刻，明确时区，查看下一次触发、原目标、原正文及状态，暂停、继续或取消。安排经原持久调度与 Core 输入执行，持久安排和投递确认分开；错过的周期不集中补发，忙碌、用户输入、权限等待、重复操作和未知回执沿原保护。明确当前保证的宿主在线范围，不将独立 Run 存活、关 App、睡眠或离线猜成提醒仍能兑现；未确认的投递保原操作供检查，不自动重发。重启恢复原安排、状态与操作身份，不创建替代 Session。
- **有分寸的跟进。** 主动问候由用户明确开启，可暂停，遵守当地安静时段、最小间隔和预算；没有明确相关目标或真实对话就不编关心话题。上一条主动问题未获用户答复时不叠问；用户正在输入、Agent 忙碌或等授权时不插话。内容简短、针对已确认上下文，并明确来源，不假称后台完成工作。同一实体在多个位置显示仍只消费一份安排与原投递身份，隐藏或打开 Profile 不新增后台循环。
- **点子与继续讨论。** 用户能明确请求基于已确认资料、目标和最近对话的少量具体建议，看到相关理由及实际使用的来源。资料稀少时承认，来源未核时不伪称已核；喜欢或不喜欢的显式反馈影响后续生成。建议仍沿原笔记与文件能力保存、编辑及引用，选择点子形成原讨论草稿，由用户决定启动；生成点子只授权所需读取，不授权外发、安排、购买或修改外部资源。
- **把成果交到手边。** 原对话能呈现实际文件成果，保可辨名称／类型与原打开动作，并回到原消息或工具事实。文件与回复的关系来自已确认的原引用，不仅凭时间邻近推定权威来源；文件失效或结果未确认保原引用及说明。原 Markdown、文件预览、Git／Result Review 继续使用同一资源与身份，不另建成果存储或读取无关 Session。隐藏展示不做新的文件扫描或预览加载。

用户可检查的安排、偏好和生成动作按[公共能力贡献约定](../../guides/public-capability-contributions.md)评估并消费同一业务 owner 的公共接口；发现、配置或读取不隐含启动、投递或外部授权。上述行为要求不以提示词在场、保存请求成功或单个模型样本代替实际链路资格。

### 长期合作的八项评估

Mote 的长期合作质量按以下 8P 问题检查。具体行为与授权边界仍归对应章节；此表用于串联产品要求，不表示八项已全部实现或通过体验验证。

| 原则 | 用户应能判断的问题 | 具体行为归属 |
| --- | --- | --- |
| personable · 像人 | 能否认出同一位搭档，并形成稳定、可调节的合作方式？ | [持久人格](#mote-预制与持久人格)及日常合作的“认识与行为方式” |
| proximate · 触手可及 | 能否从实际支持的桌面和设备入口直接找到原搭档与工作？ | [快捷入口](#mote-快捷入口与当前协调上下文)、[连接设备](public-control.md#手机版-relay-连接) |
| persistent · 一直在 | 隔一段时间或重启后，原身份、资料、工作面与安排能否接续，在线范围是否说清楚？ | [主对话接回](#主对话的自动接回)、[持久工作面](session-recovery.md#工作面持久恢复与启动边界)及日常合作的“日历安排” |
| personalized · 个性化 | 偏好能否保存、检查、更正和撤回，后来是否真正使用？ | 日常合作的“检查与更正记忆”、[原文件记忆](#会话入口与原文件记忆) |
| proactive · 主动 | 是否围绕已确认目标提供相关、适时、可继续行动的帮助？ | [主动点子](#自然认识可纠正资料与主动点子)、[持续推进](#目标持续推进与成果回报) |
| prudent · 克制 | 是否尊重当前输入、授权、静默与暂停，避免叠催和无依据承诺？ | 日常合作的“有分寸的跟进”及[持续推进](#目标持续推进与成果回报) |
| productive · 能干活、能闭环 | 是否交到实际成果、准确阻塞或待决定事项，并保留原验收与人类接受？ | 日常合作的“把成果交到手边”、[持续推进](#目标持续推进与成果回报)、[Goals 与 Demand](goals-and-demand.md) |
| private · 保护隐私 | 是否说清本地留存、设备传输、所选 Provider 处理及撤回各自的数据边界？ | [设备传输](public-control.md#手机版-relay-连接)、[资料加载与撤回](#会话入口与原文件记忆)及日常合作的外部授权边界 |

本地保存与设备端到端加密不能单独证明模型仅在本地处理；原文件更正或撤回的效果沿原文件记忆合同说明。入口可达、身份持久、定时触发、输入送达和文件存在，也分别只证明自身事实，不能替代长期合作的实际结果。

### 连接设备编辑快捷配置

已连接设备按准确 Mote 内容身份读取 Quick 配置；读取不要求该对象已在 Desktop 某处展示。保存继续交给原 Files／Editor owner，使用发现返回的准确原展示位置或明确的空 Group；只有一个合法候选时可自动绑定，多处展示由用户按可读位置选择，不借当前活动页或第一项猜测。读取、选择和保存均不启动会话、不发输入，未知引用仍保完整原值。

Desktop 本地表单仍以原表单生命周期和后来编辑取消未完成保存。外部设备的明确 Save 在原 owner 准入后使用已冻结的完整配置、原文、资源和修订完成；Desktop 不声称观察到了远端后来输入，也不以恒真条件绕过原导航或资源守卫。远端后来表单、原未知请求与完整原因保在原设备工作面，迟到回执只能结算其原请求。核对当前文件不是旧保存 ACK；没有权威原 writer 回执或操作账本时保持未确认，用户明确采用当前原修订后才能提交新的保存，不自动重放。

### 主对话的自动接回

快捷模式的原目录配置同时记录主对话恢复时机。Main Mote 固定启动时恢复；其他 Mote 缺省打开时，并可选择启动时。Profile 明确呈现保存的时机，Main 的必选状态直接说明；保存不发送消息，不因保存即时启动会话。恢复的准确身份、原工作面保全、普通闲置门槛的例外与失败/退休边界只定义于 [Session 恢复的显式固定主对话合同](session-recovery.md#冷启动按需恢复p0-末位)。没有准确主对话时仍保原选择入口，不任取成员。浮窗只有真正打开可触发打开时恢复，单纯 hover 预览、隐藏/后台的挂载与历史阅读不触发。

### 目标、持续推进与成果回报

Mote 的主动推进沿原 Goal、准确执行 Session 与原续跑调度成立。用户可以在当前 Mote 的真实讨论中交代一个目标，确认原 Goal 的成功条件，并明确选择关联的执行者；“持续推进”是单独授权，默认不打开。此后同一目标的当前进展、需要用户决定的事项、下一次检查与成果入口就地可达，不要求用户先填写脚本目录或另建执行清单。探索性聊天与初次认识不自动创建空 Goal。Goal 的定义、确认和成果接受唯一见[《Goals 与 Demand》](goals-and-demand.md)。

授权绑定原 Goal ID、已确认 alignment revision 与准确 Host/Session/Provider/cwd。多个执行者必须明确选择，不能借最后关联项、背景 Space、名称或当前目录猜执行者。原定时推进与日历消息共用既有调度和 Core 输入事务，各自保留业务语义；Goal 生命周期由原 Goal owner 解释，Core 的续跑 source/scheduler 不新增 Mote、Demand 或 UI 依赖，也不解释 Goal 生命周期。一次开始的业务 operationId 与后续 tick 各自准确留存，丢失回执按原操作核对；未确认不得重复发送或创建替代 Session。

阻塞、待决定、原目标确认失效或原 source 不可读时，自动推进暂停并说明；完成或取消只停止该目标的自动推进，不停止健康 Run、不删除原工作面、不冒充成果已接受。改名或无关目标变化不停止当前目标。原版本已失效的 loop 仍可检查或停止，不能恢复旧授权。新确认版本由用户明确停止旧 loop、以新的开始操作授权，不自动重绑或改写旧未知事务。继续执行须重新确认当前版本、目标和原输入条件；手动输入、权限请求、运行繁忙和未知 delivery 保留原 Core 的保护与可用能力。应用或连接恢复保原目标、同一 loop、待核操作与讨论，不追补一串过期 tick。

回访摘要从原 Goal 的活动、决定、实际 grounding 与原 loop 状态取事实，以“做了什么 / 卡在哪里 / 需要你决定什么 / 成果”组织；接受输入、空闲状态与计时器触发均不算成果。成果沿原文件引用和 Goal 逐项证据，保 met/gap/unknown、人类接受与版本。暂停、恢复、停止在当前内容旁可达，不能以新表单、第二文件树或第二任务数据库承载。

### 自然认识、可纠正资料与主动点子

第一次合作可从一个真实问题开始，介绍与偏好设定均可跳过；行为与 MBTI 是前述原 `BEHAVIOR.md` 的可编辑偏好，SOUL 相对引用同一文件，不能要求先完成性格测验才能工作。跨讨论资料从该 Mote 的原 SOUL、行为文件与原资料按需读取，按需显示本次真实读回或带入的文件与版本，并沿原 Editor 修改；模型实际应用资料须有真实工具/回答见证，准备提示不等于使用证明。保存失败或未确认保留草稿与服务说明；已有 Session 的上下文不冒称实时热更。下一次新讨论读取新资料，另一 Mote 不借同目录邻居或背景对象获得资料。

主动点子由用户为准确执行者明确开启原安排；频率、静默/暂停及来源范围可读。普通目标续跑、定时消息与轻量问候各自说明用途，问候不能伪装成后台工作。建议应少而相关，解释为何值得做并按需给出实际资料来源，不以定时写一条消息充当有价值点子。安排保存准确资料 locator 与原意图；创建时摘要只称最后确认，执行时须由实际 Agent 重读当前文件并说明未知，不重写同操作的投递内容。用户接受后沿原 Goal 或原讨论继续，反馈沿原 SOUL/文件保存并在后续新讨论中真实消费，不另建 Feed 或 Memory 引擎。

持续执行以原 Host 在线、Agent 可用和准确输入条件为前提；关闭当前面板或换设备不改变原执行身份。设备/连接不可达时显示最后已确认事实与未知状态，不宣称云端全天候保证。公共 API、CLI 与已连接设备消费同一 Goal/loop 回执、暂停和成果事实；飞书/Lark 连接留待通用连接结构讨论，不在本批加入厂商分支。

### 资料刷新与当前工作摘要

名册复用原文件系统观察；无关普通文件修改不重读全名册。已确认对象的设定、归档或正文变化只重读该对象，目录成员或身份记录变化才重新发现成员。较早的扫描不覆盖在途期间已确认的新对象；局部成功不抹掉其他对象或目录发现仍未知的事实。读取失败保原身份与可用工作面，按原范围提供重试。

准备问题或点子只核对用户选中的原资料，以及准确资源、展示引用和用户后来输入。无关对象的保存不取消准备；选中资料确实改变、资源或页面改变过、用户改了输入时，迟到结果不得替用户创建讨论或安排。读完最后一次核对仍须检查当前输入与原目标，保原草稿。

Profile 的当前工作以原 Goal 状态、验收和记录为准，缺省最多显示三项摘要，优先提示阻塞和待确认的工作。数量及完整记录入口清楚可达；已结束的历史仍可查，展开与返回不改变原 Goal、讨论、草稿、Session 或 Run。行为设定与最近点子继续是 Profile 中可达的对象内容。

## Topic 与 Mote 的物理目录

普通 Topic 的 canonical 文件目录在 `~/.agentmux/topics`，Mote 在 `~/.agentmux/motes`。用户明确要求分离并迁移已有对象，原目录保留对应软链接，以后再删；本轮不删除这些链接。这是明确授权的数据迁移与临时旧地址，不由一般“不留 migration／fallback”的实现规则否定，也不扩展为任意目录迁移。归类沿已有文件事实：主 Mote 与已确认含 SOUL 的对象是 Mote，已归档对象同样迁移；分类读取失败保持未知，不当普通 Topic 猜着搬。内容组织仍自主，不改写用户知识文件或强制分类。

- **Mote 使用稳定的物理短名。** Mote 的 canonical 路径为 `~/.agentmux/motes/<持久 Mote ID 的短哈希>`，从完整、已确认的内容 ID 导出，不使用 Topic／Launcher 技术前缀，不随改名、关闭或新建讨论、切换 Agent Session 改变。短名只用于目录索引，不能代替完整对象 ID；同名目标必须核对同一对象，碰撞、未知记录或别的对象不能被覆盖或冒认。新对象直接使用自己的 canonical 短目录身份；现有对象改物理名时保各自准确原身份、资料、头像、归档、全部展示绑定及执行 cwd，精确旧地址仍通向同一对象。完整内容 ID 与相对原根的身份定位由原 app-owned 目录元数据保存，不能写绝对路径、另建身份名册或从短哈希反造 ID。发现与公开查询只读；记录缺失、损坏或未确认时保已确认对象和工作面并说明恢复动作，不能以当前物理地址重铸身份。具体摘要算法与长度由实现负责，不作为其他对象的通用命名限制。

- **展示身份与物理地址分开。** `__scratch__` Workspace 保留原 Scratch 逻辑容器地址与 ID；物理目录迁移本身保既有 Topic/Mote 内容身份、空间实体、选择、草稿、文件逻辑引用与执行绑定。普通 Topic 到 Category→Topic 的空间层级承接是另一个明确动作，旧普通 Topic Space 节点转换与原内容 ID 保留只见[《Topics 知识库的层级与沉淀》](spaces-and-layout.md#topics-知识库的层级与沉淀)，不据旧文件 alias 保留永久旧空间 owner。Snapshot 明确给出实际物理目录，真实 IO、新启动 cwd 与公开查询的对象 path 消费该地址；公开查询只投影原协议字段，不泄漏内部路径元数据；原相对文件地址仍由同一受限文件 owner 解析，不按背景项目或显示位置猜对象。新对象直接写入对应 canonical 根，不先创建旧实体再搬。
- **迁移保留原对象。** 已确认的旧目录在同盘以不覆盖目标的同一次原子 exchange 保留原 inode 与完整内容，同时把精确旧地址变为对应软链接，不留下旧路径不可用的间隙；`topic.md`、SOUL、Wiki、`.agents`、`.agentmux`、头像资产、归档和任意用户文件不重建、不清洗、不丢弃。旧目录身份由对象内 app-owned `.agentmux/directory-identity.json` 保持，文件中不写绝对路径；只保存相对于原逻辑容器的已校验对象定位及该原逻辑身份的核对依据，由原 Workspace 的登记地址解析为同一个既有目录身份，保原头像与 Space/Zone 地址，即使将来删除旧链接也不重发身份。原逻辑根、目标目录名与记录必须一致，不能改用当前物理地址、另一根目录或同名对象重铸身份；记录须在 canonical 对象暴露前耐久保存。已保存的旧绝对路径记录只在原目录 owner 严格确认原根、原对象及原记录后无损重编码，失败、冲突或保存未确认保原记录、内容与工作面，不以删除记录或重建对象完成升级；公开读取和目录发现保持只读，不暗中改写文件。记录承载完整内容 ID 及该对象的目录身份，不成为 Session/Run 或第二份工作面事实，损坏或未知不得退回物理地址重铸身份。新对象使用自己的 canonical 目录身份。冲突、失败或无法确认的步骤如实可恢复，不能覆盖已有目标、将部分结果称为完成、跳过对象不说明，或删除未确认的原数据。
- **记录维护的确认与恢复。** 升级中的原记录保留为这次操作的待确认见证，不成为第二份身份表；并发替换、中断或耐久保存未确认时保留实际原字节，不能覆盖后来出现的记录。即使新格式已可读取，只要本次操作仍未确认，冷读取与公开观察仍保原可确认身份和持续说明；没有准确见证时沿原工作面绑定保未知，不借当前物理地址重发身份。恢复沿同一原目录维护入口核对实际记录、原对象及耐久保存后解除说明，公开查询不执行修复。
- **旧执行与新启动各用真实地址。** 已有 Session/Run 的保存 cwd 与身份原样，迁移不停止、重启或改写健康执行；旧地址仍连到同一对象，活跃进程继续读写原 inode。新启动使用 canonical cwd，经 Core 原公共能力创建。真实进程重启后恢复原工作面、引用与状态，旧 Session 继续沿自己的原地址恢复，不借迁移造替代 Session 或把 unknown 当终局。
- **旧 alias 不放宽文件边界。** ScratchTopics 与通用文件入口共用 Main 的受限目录解析，只接受已确认身份、精确旧直系目录与相应 canonical 目标的映射；读取仍遵守原已允许的 explicit 只读链接能力；任意链接不因此获得变更权限或新增可访问范围，被替换的根/目标及逃逸继续按原权限与路径规则拒绝。主 Mote 的删除／移动保护、头像资产范围及原保存冲突检查仍成立；失败只拒绝这次错误目标的动作，不拿走健康 Agent 与原工作面。

## Mote 头像与主 Mote

用户明确保存的头像来源与选择在应用换包、重启后仍可读回，不以 Renderer 的临时环境作为唯一保存依据。重开编辑器选中同一已保存图片、图标、捏脸或自动来源；进入编辑器本身不切到预制脸、不覆盖选择。原耐久配置持有选中事实，目录资产仍由原文件 owner 持有；旧已保存选择的保全转接不能复活用户后来清除的值。读取或保存未确认时保已确认外观与编辑草稿，给出原目标的恢复说明。

用户要求：“MOTE也支持下更换头像吧，调研下DOT和Muse的能力，也看下discord的体验，对mote做下优化”，并明确参考 OpenAI dot、Meta Muse 或 Grok Bot。用户可以为同一 Mote 更换本地图片头像、预览最终圆形显示、明确保存或取消，并恢复默认外观。头像属于原耐久 Mote 身份，卡片/头像两态左栏、交流身份区、Space 树与完整 Space 的对象头像槽使用同一已选外观；图像、名称、类型、真实执行状态和展开/选中状态各自表达，不把 Session/Provider 头像当成 Mote 身份。选择沿既有外观 owner 持有，原图标、图片和捏脸外观是同一互斥选择，图像资产属于同一 Mote 耐久目录，不新增身份名册、第二份当前选择或 SOUL 人格字段。编辑和异步保存绑定明确原对象；未保存草稿不改变其它入口，取消不写入，读取/保存失败保原已确认头像和待保存选择，说明未确认与重试动作，不阻挡原工作面或健康 Agent。换头像不启动/停止 Run，不改原目标、Tab/Region、执行历史、草稿、SOUL/Wiki 或授权；本条不扩展联网生成或另一套人格系统，状态表情遵守下述约束。

主 Mote 未自定义及恢复默认时使用项目的原龙图标，不按名称或运行状态替换主身份；已保存的用户图片、图标或捏脸选择优先，主 Mote 也可以明确捏脸或上传。Mote 的原头像编辑入口提供可预见的部件编辑和同一保存/取消/默认语义；普通 Project、Folder、Topic 不出现 Mote 捏脸。捏脸提供更多可辨的五官、轮廓或配饰选择，沿同一外观选择保存；新增选项保留所有已保存的部件组合，不要求用户重新编辑或把旧脸换成默认脸。部件外观与短暂表情分开，动画不改写保存的脸型或五官选择，切状态后仍能认出同一位 Mote。

用户最新要求 Mote 的 avatar change／创建图标默认首选 `Make a face`，旁边可切换到 `Icon or image`；后者是对之前仅提上传 image 的细化。默认的是编辑面的首选方式，不自动保存或改掉原已确认外观，主 Mote 的未自定义与恢复自动仍使用原龙。已有捏脸选择作为 Face 草稿保留，图片或图标用户可切回 `Icon or image`，各方式保留自己的本地草稿；默认 Face 方式有明确所见预览，Save 保存当前所见外观，不增加第二个确认动作。打开、取消或仅切换方式均不写持久外观。用户同时反馈：「Change Avatar 这个界面本身的质量目前还是太低了一点，应该要再高一点。至少要使用上设置界面里头那种液态玻璃的切换按钮效果吧？」编辑面需清楚呈现当前方式、单一中心预览、对应的五官调整或图片／图标选择和保存／取消，沿原外观 owner、对象异步边界与失败保全。玻璃切换及控件视觉唯一见 surface-density[《Mote 头像与主 Mote》](../presentation/motes-and-coordination.md#mote-头像与主-mote)。

Mote 头像「平时也要偶尔活动」：实际可见的日常身份头像不要求鼠标靠近或 Agent 正在工作才有局部动作，Make a face 沿原五官关节表达短暂神态，原龙、上传图片与默认／手选图形可有不损害辨识的轻微姿态，不推断图片五官或改写保存外观。待机动作与运行事实分开，不借活动伪装 Working、工具调用、在线或恢复成功；睡态仍可辨为睡态，待回复与未知只用中性短动作并保原眉嘴及说明，不能被好奇或笑脸覆盖；错误和已停止不叠加日常动作并保持可辨。已确认没有 Agent 的初始 launcher/空态呈现睡觉，已结束的进程仍明确说明“已停止”；保存目标或 Session 暂未恢复不当作未启动。Working 呈现思考；当前准确 Agent 的真实在途工具事件可联动表情，工具完成或失败后不继续伪装仍在调用。历史工具、另一位 Agent、旧 Run、迟到事件或缺失出处不能冒充当前调用；无可确认工具事实时仍表达原真实运行状态。Starting、待用户处理、Blocked、Error、Disconnected、恢复未知及进程运行但语义未知分别可辨，不把未知猜成 Idle、睡觉或成功；表情和颜色不替代原状态说明及请求/服务窗。动作强度与日常节奏只见 surface-density[《Mote 头像与主 Mote》](../presentation/motes-and-coordination.md#mote-头像与主-mote)。

`Icon or image` 的图库提供 low-poly 角色图片候选，与本地图片、原图标选择同处一个方式；它们仍沿原图片／外观 owner 和明确保存动作成为同一 Mote 的外观，不增加头像身份、人格字段或独立保存机制。现有二维 `Make a face` 继续可选，保留原可组合部件与保存、取消、默认语义；新的角色系列可以同时提供图像和可捏脸外观，具体形态和材质沿[同主题呈现](../presentation/motes-and-coordination.md#mote-头像与主-mote)。新增角色、系列或调整捏脸风格保留已保存图片、图标、脸型、配色和全部部件组合；编辑时准确读回原选择，任何候选都要由用户明确保存后才替换外观。图库图片与可组合脸分别消费各自已有动态能力，静态角色图片不冒充五官骨骼动画。主 Mote 的未自定义与恢复默认继续使用原项目龙。

头像系列从本 Host 的 `~/.agentmux/avatars/<series>/` 专用素材根发现，以子目录表达系列；用户或 Agent 放入的一组正规 PNG／JPEG 头像可以作为可选来源，只有图片的目录无需声明文件。同一系列可通过受限纯数据声明提供图片、现有二维捏脸预设与成熟 GLB 的可编辑外观，后续系列与 user mods 沿同一数据边界扩展。可编辑资格只取准确资产的原生部件或 morph／材质参数及已实现解析／渲染能力，显示名称、缩略图和文案不授予该资格；缺失能力不编造控制项，不执行来源中的任意代码。发现只读，不创建 Mote、AgentSession 或 Run，不按系列名重铸身份，也不自动保存或替换外观。准确头像选择仍由原外观 owner 持有，目录、素材或可选声明暂不可读时保已保存选择与草稿，明确受影响的准确来源及恢复动作，其他可用来源与原工作面继续可用。具体声明字段、格式与支持的原生参数由[公开数据合同](../../specs/mote-avatar-series.md)定义，不由素材授予权限、运行状态或执行能力。

保存系列外观时，原外观选择同时保留准确来源与内容版本、原可编辑参数及已保存图像；PNG 沿原对象图片 owner 保存，选择沿原耐久配置 owner 发布，不增加第二份当前选择。删除、替换或暂缺 mod 不改变已保存图像或原参数；原来源不可确认时继续显示原保存头像，明确可编辑来源未确认或不可用，恢复的是同一准确版本而非同名新素材。切系列、预览与取消均不写入；未确认保存保留原已确认外观、原请求与草稿，通过同一原对象和操作核对，不以重新生成默认头像、换操作身份或另建 Session 完成恢复。公开发现、预览、保存与读取消费同一原 owner，图像写成、当前选择观察、原操作回执与磁盘耐久确认分别表达。

用户可从系列选择面明确添加自定义系列。添加面说明专用素材目录、普通图片与混合系列的用法，并提供创建目录及初始示例的动作；创建只发生在原 Host 的头像素材根下一个准确的新子目录，不覆盖已有目录或文件。完成后刷新并选中该系列，用户仍须明确保存头像才改变原 Mote 外观。取消教程不写素材；写入或打开目录失败时保留已写内容、编辑草稿和其他可用系列，准确说明该步骤及原路径。目录创建与示例内容由公开头像素材 owner 提供，图形界面和 Agent 消费同一边界；打开目录是独立的明确动作，不创建工作区、Mote、Session 或 Run。

默认主 Mote 的原龙与自定义图片沿同一原头像动态 owner 支持轻微待机动作和指针附近的朝向响应；响应仅改变临时呈现，不推断图片五官、改写保存外观或把睡态／未知表达成醒来与正常运行。普通 Topic 图标不因这项能力加入头像动态。

仅实际可见的对象头像槽消费其准确目标状态与必要工具事实，常驻品牌入口沿本专题入口／对象的分工；隐藏实例、头像滚出可见范围、页面隐藏或减少动态偏好下停止动态并保留可辨静态状态，可见的左下品牌入口可保不代称目标执行事实的轻姿态，不因浮窗收起而强制隐藏。消息历史中的作者头像继续保原色与静态身份，不因本条为每条历史消息新增动画或 Session 消费。动画不增加全局轮询、逐头像 JavaScript 帧循环、整份 Timeline 订阅或无关 Session 的工作放大，不触发 fit/Runtime resize、不改变输入焦点、草稿、授权或生命周期。视觉、动画强度与控件密度唯一见 surface-density[《Mote 头像与主 Mote》](../presentation/motes-and-coordination.md#mote-头像与主-mote)。

用户补充此前要求：「如果是 make face 的情况下，它实际上应该是骨骼动画。平时它可能会有一些表情、神态的变化。如果我的鼠标离它很近，它还会看向我的鼠标。这种灵动的效也要有。」捏脸采用内部五官可组合的骨骼／关节式连续变化，平时的表情神态和靠近时的视线响应仍能认出保存的同一张脸；不能整图帧替换、整头旋转或遮脸装饰伪装成该能力。鼠标靠近只使附近准确可见的捏脸实例局部响应，视线与真实运行状态的临时表情组合而不覆盖待处理、错误或未知提示；不把鼠标互动伪造为 Agent 工作或工具事实。隐藏、离屏、页面不可见与 reduced-motion 停止动态，退出附近恢复原状态；不为无关隐藏实例增加 pointer listener、rAF、轮询或 Timeline 消费，沿前述相关成本与输入／生命周期保全。图片与图标仍沿原语义，不硬贴捏脸五官或改变原图片。

用户进一步要求：“应该要有主mote设计，就是不可被用户删除的一个mote，默认就有”。主 Mote 使用原默认 Mote 的固定身份，由既有目录 owner 在普通启动时幂等提供，同一对象仍在创建时重复请求等待原结果，结束后不缓存过时快照；失败保原内容并可明确重试，不能把尚未完成的创建误报为外来对象，不按名称、列表首项、Session 或是否正在运行猜主身份，也不另建数据库。新环境默认有主 Mote；已有目录的 SOUL、头像、Wiki、资料和原工作面保留，目录缺失、读取失败或恢复状态未知需沿服务窗明确实际步骤，不把未知当成新环境覆盖用户内容或宣称原内容已经恢复。应用内删除主 Mote 目录、删除包含它的祖先，或通过移动/改路径/覆盖令该身份消失都不可执行；保护落在原唯一目录变更服务，精确地址及其合法别名同等受保护。标题改名、内部用户文件正常操作、头像更换/恢复默认、关闭主 Mote 的 Tab、收起浮窗仍合法；其他自定义 Mote 沿原管理行为，不因主身份保护锁住 Session/Run 或重建健康 Agent。控件与密度只见 surface-density[《Mote 头像与主 Mote》](../presentation/motes-and-coordination.md#mote-头像与主-mote)。

## Mote 归档与恢复

用户反馈：“现在好像没有合理的 archive mote 的机制”。自定义 Mote 可以明确归档、在原 Mote 管理面发现已归档对象并恢复；恢复的是同一个耐久目录身份，不是复制或重新创建。归档把它从常用 Mote 列表和新目标推荐中收起，原 Space 的 Motes 区始终有可发现的“显示已归档”与恢复路径。普通 Topic 不因这条需求获得归档行为，关 Tab、收起浮窗、删除目录与归档各有独立含义。

归档状态由原 Mote 目录 owner 持有；目录、头像、SOUL、Wiki、资料、固定/排序偏好与完整身份快照保留。已打开或明确选择的同一 Mote、Tab/Region、其他已有位置、执行历史、未发送草稿与健康 Session/Run 保持；当前归档对象仍可辨其状态、继续原工作面并恢复，不因它退出常用列表而判为丢失、自动切换目标、重新创建或停止 Agent。新选择不主动推荐已归档对象，已有明确目标及在途请求不被另一位 Mote 替换。

归档/恢复只有原对象的持久写入和读取确认后才表达成功；未确认时保原已确认状态与可用工作面。读取失败、状态未知、保存失败或迟到结果需说明实际步骤、当前已确认/未知事实与重试动作，不能把未知当未归档、把未知读取当恢复成功，或让旧请求覆盖后来已确认的状态。重新载入仍能读回归档事实、发现并恢复原对象；不另建身份名册、第二份归档选择或复制执行状态。

主 Mote 继续沿[《Mote 头像与主 Mote》](#mote-头像与主-mote)的固定默认身份存在。本次设计判断是主 Mote 不能被归档后隐去，以保留默认可达入口；这不是用户关于归档的原话，也不限制关闭其 Tab、收起浮窗、换头像、修改标题或正常内部文件操作。应用服务最终边界同样保护主身份，不能只隐藏菜单。控件语言、Space 最小宽度下的名称／归档状态与次要动作入口见 surface-density[《Mote 归档与恢复》](../presentation/motes-and-coordination.md#mote-归档与恢复)。

## 主 Mote 与 Goals 协作

主 Mote 保原 `launcher:leader` 耐久身份、目录、SOUL、Wiki、头像与资料；历史 Leader Topic／PMO teams topic 只表示同一协调对象的旧称。主 Mote 可以读取全局 Project、Goal 与 Agent 事实，不因背景 Scratch、活动项目或名称变化改目标；其中 Agent 仍是经 Core 公共能力运行的正常 AgentSession，不另建隐藏 Runtime。

用户可直接与 Mote 讨论，意图与授权未足够时轻量澄清，不先造空 Goal／Project。显式 New Goal 则先保存真实待定义 Goal，再进入同一主 Mote 内该 Goal 的专属讨论 Tab；两条创建边界、真实 bot 配置、Project 上下文及未知恢复唯一见[Goals 的显式新建与专属讨论](goals-and-demand.md#显式新建与专属讨论)。Mote 讨论的创建／更新结果、准确 Project、分析依据与关联 Session 在对话和目标详情可追踪，不把任务分派变成不可见副作用。

Goals 的主实体为 Goal，底层沿 Demand 身份；它不再以 Branch／Topic × Agent 状态矩阵组织，也不属于另一 Agents／Session／Board 全局导航。目标摘要、数量和空态只消费持久 Demand：零目标不把 `main` 或任意 Branch 当需求行；状态、筛选、路由队列和执行观察投影只由[Goals](goals-and-demand.md#demand-的完整业务闭环)定义。Mote 快捷面不是 Goals 总览的替代。

## PMO teams topic 名称与职责

Mote 默认与人讨论需求、组织执行 Agent、分配工作并持续跟进结果；PMO 是协调角色，普通 Topic 不继承它。Mote 保自己的 Space，普通 Topic 是 Category 中的 Zone；复用文件、公共能力或 Scratch 不改变身份和成员归属。

Mote 先发现准确 Project、Executor、Session、Tab／Region 和已有能力，再提出可检查的分工。范围、位置、风险或授权缺失且影响下一步时才追问；用户已经明确授权的有限创建、分配与推进直接执行，目标确认与结果接受各自成立，不反复索取原授权，也不替人认可。默认细设计和实现交给执行 Agent，Mote 继续讨论、组织、跟进和取证；只有用户明确要求 Mote 亲自实现时才承担该项实现。未知能力、身份、投递或结果保原工作面与健康 Agent，不猜成功、不用直接配置写入绕过公共 owner。

真实项目目录及最小初始指令、项目注册、同一 Demand 绑定、执行 Session 创建／复用、首任务投递与结果核验分别留下实际事实。项目注册不证明目录已建，记录指派不证明送达，Session／Run 退出不证明目标达成。一次未知 create／start／发送先读原操作和实体，不自动重放；准确上下文与通用职责在新讨论和复用原会话的请求中都可用，具体闭环引用[Goals 的协调合同](goals-and-demand.md#mote-协调与已有授权)。

初始协调消息须明确沿原 Demand 推进到交付与收尾的责任。执行已获授权时，Mote 持续组织实施、处理提问或阻塞、核验逐标准证据、回收原报告并提交同一 Goal 的待验收结果；不能以完成分派、退出、idle、投递回执或 worker_done 收尾。确有阻塞时保留准确责任人、阻点与下一步。仅讨论或澄清的请求保持当前授权范围；人的目标确认与结果接受仍由原 Goal owner 持有。

初始消息同时要求为本次讨论、本次明确交给 Mote 负责的无名 Session 及其新建执行 Session 取简短、可辨的主题／职责名。先读取准确目标、原名称来源与 revision，再沿原命名能力写入并核对回执；应用生成及 Agent 自主命名使用派生来源，保护用户手改、手动清除与启动指定名。主题明确后可细化仍为派生的临时名，不按每轮进度反复改名、不批量修改历史会话。Mote 本体、Session 与 Tab 各守原身份；优先级、并发与恢复唯一见[显示名与身份](spaces-and-layout.md#显示名与身份)。命名未知或失败只影响该步骤，保原工作面与健康执行，不换 Session、不重发任务。

### 需求写入授权与决策记录

需求写入策略可配置为“按风险确认”（默认）、“全部确认”或“默认直接创建”，保存后在原入口可见。明确且低风险的单项目请求按已给授权创建并产生可追踪 receipt；跨项目路由、目标不明、不可逆或高影响动作展示来源、候选 Project、风险及缺少的确认，不静默写入。“默认直接创建”不绕过准确目标、既有权限与必要的风险授权；后续动作也不把过去授权扩大到新对象。

用户确认、改变目标 Project、接受／拒绝风险判断或撤销 Demand，作为结构化决策进入原知识／决策 owner，保原请求、候选与最终 Project、风险、用户选择、Demand／operationId、时间和来源 Session。完整聊天转储不冒充可检索决策；建议和排序可消费历史，不能绕过当前设置、确认闸门或权威事实，证据不足仍表达未知。通用版本化公共能力提供原记录的读写、检索与增量观察，Provider 不拥有这些语义，不新建第二份任务或记忆账本；未核实能力如实列缺口。

### Wiki 与应用协调指令

应用署名的通用协调职责由单一 Notes owner 持有，当前源码入口为 [MOTE_COORDINATION_ROLE](../../../apps/desktop/src/shared/scratch-topics.ts)。它适用于 Mote 的实际新讨论与复用请求，不靠改 CTA 原句、复制配置或重建 Mote 生效，也不覆盖用户 SOUL／Wiki。普通 Topic 与执行 Agent 不因复用组件获得协调角色。

通用合作原则、Mote 专业职责和本次 Goal 职责分别沿原 owner 提供。专业职责在保存的 SOUL 中明确领域、判断方法与交付标准，不只靠名称或四维行为偏好表达，也不扩大原执行授权与默认 PMO 分工。基础 AGENTS 保核心协作边界和模块发现入口，Goal 的完整管理／执行职责在实际 Goal 操作中按原身份、意图与回执注入。精简应用上下文须分别核对新讨论和复用请求的实际输入生产链，保完整原草稿与后来启动能力，不通过匹配显示文案或删改用户自写文本去重。模板变化不自动覆盖已保存资料，也不使活跃 Session 热更新。

Topic 与 Mote 各自已保存的 Wiki 仍是对应原内容对象的可编辑知识，启用、内容版本和更新时间可见并可恢复；禁用不注入，恢复不重建 Topic／Mote／Session。准备会话时明示实际读取来源与版本；平台安全、当前用户指令、权限及权威 Project／Goal／Session／Run 事实优先于默认建议和历史推断。冲突或读取未知说明具体事实，不伪造状态、不静默覆盖文件或扩大授权。

主 Mote 的默认 Wiki 是可查看、可编辑的初始内容，帮助理解公共 Project／Workspace、空间、Goal／Demand、Session／Attempt 和 ctxmux 能力，包含路由、合并／拆分目标及风险确认建议；已有用户 Wiki 不因默认变化被改写。真实职责与权限不依赖 Wiki 中一句旧角色描述，源码中的初始内容也不代签现存文件或运行会话已更新。

## 快捷工作面的打开与恢复

快捷面按本专题的搭档界面组合已选 Mote 的原 Tab／Region 引用、Session、消息、输出与 Composer，保背后原工作面；导航、对象选择、尺寸与入口动作唯一见[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)。各入口共用这一个搭档交流面与原消息能力，不另建 Session、PTY、自由位置或第二份开合状态。“收起”不移除常驻入口，入口在 Settings、窄窗、无活动 Tab 或分屏时仍可见且可键盘进入；身份头像不冒充真实 Agent 工作状态。

明确打开后在同一入口内显示可见、可聚焦的搭档交流面、准确原讨论／Region 与可用输入。准备过程按原 owner 说明阶段并完成后进入内容；已有可用身份、导航、历史和输入保持，恢复未知进入持续状态层，不用全幅加载遮住健康原工作面或留空浮层。失败保入口和原面，持续说明失败步骤、当前可用／未知状态与恢复动作。默认显式打开使用 Activity，对已见模式、hover／固定和重启的优先级沿原快捷面合同，不以恢复再触发新的人类打开。

固定目标和开合沿原 UI 偏好恢复，Core 持久空间 owner 先恢复原 Tab／Region、布局与引用；原主对话的自动接回时机只遵循[主对话合同](#主对话的自动接回)及[Session 恢复](session-recovery.md#冷启动按需恢复p0-末位)。hover、隐藏挂载和历史阅读不成为恢复授权。快照、握手或渲染未知不清布局，不换 Session、不自动重发旧输入。快捷面与 Work 保独立导航和真实输入焦点；可见性进入同一终端泊车、预算与通知事实，不能显示时回收内容或为隐藏引用新增消费。

## Mote 预制与持久人格

Mote 是带预制的持久协作对象，复用共同 Space 管理能力；人格与产品角色不等同 Provider／Executor 或某次 Session。

- PMO 等特殊 Agent 以带预制的持久 Mote 组织，复用耐久目录、Wiki、资料、产出与铭牌，以及共同的 Space 管理能力。预制负责特殊身份、默认上下文与产品入口，Mote 保原 Space，普通 Topic 沿知识库 Zone 层级；不建立另一套 Space、Topic、Agent 或 Run 生命周期。
- 特殊 Agent 的入口、Space 树条目与已有工作面必须指向同一个持久 Space；打开、收起、恢复或切换入口不创建第二个 Topic 或 Session。现有 PMO 的身份、职责和执行焦点约束继续见[《PMO teams topic 名称与职责》](motes-and-coordination.md#pmo-teams-topic-名称与职责)与[《执行 Agent 焦点历史与 PMO 上下文隔离》](focus-context.md#执行-agent-焦点历史与-pmo-上下文隔离)。
- 普通 Topic 不继承特殊预制的角色。特殊身份属于产品预制，与执行它的 Provider/Executor 区分；实际 Agent Session 仍通过 Core 的公开能力启动与恢复。
- Mote 的持久产品身份使用独立矢量标记；新建、技能和权限动作各按含义表达，不全换成Mote身份。Provider 官方标识与真实运行状态继续沿原 owner；具体字形、尺寸与替换范围只定义在密度 SSOT[《控件语言》](../presentation/shared-rules.md#控件语言)。
- 这一类带持久人格的产品对象具有跨 Folder/Topic 全局负责的能力；其职责不被自身 Topic 目录或当前选中 Space 限定。产品身份与 Session 分离：产品身份在没有运行 Session、Session 结束、更换或恢复时仍然存在，不能用某一次 Session 的身份代替持久角色身份。

Mote 可复用 Topic 的知识管理、协作者和内容能力；这不表示 Mote 收纳全部普通 Topic，或两者占据相同知识导航层级。Agent Space 保留这些能力，创建时额外带有具体可读、可编辑的 `SOUL.md` 等特殊预制。`SOUL.md` 表达这位 Agent 的持久人格、价值取向、沟通方式与行为边界，和当前执行它的 Session、Run、Provider/Executor 身份区分；更换或恢复执行会话不能把这些耐久内容丢掉，也不能用模板覆盖用户已经编辑的内容。

普通 Topic 沿用已有知识管理结构；这类持久角色自行决定如何组织和维护自己的知识。产品提供可读、可编辑的预制入口，不强制迁移已有资料或统一知识分类。`SOUL.md` 仍承载持久人格；已有 Wiki、资料、产出、铭牌和用户编辑内容继续保全，Session/Run 的权威事实仍由原 owner 持有。

PMO Team 是这种 Agent Space 的已有产品实例，继续复用原固定 Topic、Wiki、角色说明与工作面。`SOUL.md` 属于耐久上下文，不能覆盖用户当前指令、既有授权与 Core/ctxmux 的权威事实，也不能把设定了长期职责伪装成已经启动或完成了后台执行。文件存在与执行会话实际加载是两件事：启动、恢复和文件编辑后的生效情况必须按真实执行能力表达，不能仅因预制了文件就声称已加载，也不能为一个 Space 修改其他 Agent 的全局人格。加载方式与更新时机遵守本节下文的新会话与恢复约束。

Mote 的默认人格与知识维护约束：新建或补缺失的 Mote SOUL 默认先读相关已有资料，记录有来源、时间和作用域的确认偏好与决定，区分事实、推测、提案、承诺和完成；更正只更新相关耐久知识，保存后读回才声称记住。换 Session 通过原资料接续，不假称继承未见对话或运行工具；不知道、未读、写入未确认都如实说明。知识组织继续自主；默认短记忆入口遵循下节，不要求其他 MEMORY 文件集、统一分类、scheduler 或第二份 Goal/Task 状态。详细执行协调沿 app-owned MOTE_COORDINATION_ROLE 单一职责；主 Mote 的新默认或用户明确恢复默认 Wiki 只提供短知识／协作指南，不重复整段角色流程，非主 Mote／普通 Topic 的默认 Wiki 不改。已有磁盘 SOUL、Wiki 与用户资料原样保留，不做 migration、自动清洗或截取用户文本去重；仅新的 Session 按原人格加载合同生效，恢复不热替换。实际模板交付与模型是否执行、读写成功分别验证，不能用提示词内容承诺每轮遵守或自动长期记忆。

### 会话入口与原文件记忆

- Mote 和普通 Topic 在原目录补缺失的 `AGENTS.md`，说明真实 `amux` 发现与使用入口、当前指令和权限优先、原文件用途及协作者检查。普通 Topic 必读 `topic.md`；Mote 另读 `SOUL.md`、存在的 `BEHAVIOR.md` / `MOTE.md`、`MEMORY.md` 和相关原资料。已有 AGENTS 与用户人格逐字保留；预制不会把普通 Topic 变成 PMO。指令文件不授予新权限，也不是 Runtime 状态。
- 新 Session 由原 `prepareAgent` 路径实际读取该对象的 AGENTS；Mote 另读取原 `MEMORY.md`，带版本进入原 Core 初始上下文，不依赖某家 Provider 自动发现文件。读取只限准确原目录的有界普通文件；读取失败、文件变化、非法编码或超限均明确说明未加载，保留原输入、Session 和资料。恢复已有 Session 继续原上下文，不热替换、不重启；文件编辑后下次新 Session 使用新版本。
- `MEMORY.md` 是新建或补缺失时的简短默认索引，正文仍只有原文件一份，允许链接既有资料、保留自主组织方式。默认内容为空，不将旧聊天自动当作确认知识。原文件树和 Editor 负责查看与编辑；AGENTS / MEMORY 属于核心上下文，不混入 Recent ideas。
- 原 Agent 在正常协作回合中按 AGENTS 评估值得长期保留的确认偏好、决定、更正、承诺与证据链接，写清来源、日期和适用范围，区分提案与确认。通过原 Files 的准确资源、revision/CAS 保存后实际读回，才说“已记住”；未知结果先检查，不盲重写。无需新增时可记录带来源的 Agent 自报维护说明；自报记录、旧文件 marker、Run 结束或回答文字都不证明本轮实际完成语义提取或保存。
- 用户可在原 Editor 改正或移除条目。撤回可保留无原正文的最小 source 标记，指导后续 Agent 不从旧材料重新吸收；原 CAS 拒绝旧 revision，但不保证模型读最新版后永不重新提出旧内容，也不声称已擦除 Provider 历史或当前活跃模型上下文。
- 本机制自动完成的是新 Session 的原文件加载。正常回合的评估与写入仍由该 Agent 执行，未执行不能称为已保存；不另起后台 Agent、额外独立模型回合或无限追问。系统逐轮强制评估、逐 operation 冻结上下文与可信 assessment 回执尚属独立未实现能力，不能用本节提示词或模板交付代签。
- 公共能力复用 `whoami`、`--skill`、准确空间发现及 `file.read/create/write`；模板与原文件加载不新增 Memory RPC 或第二存储。GUI、Agent 和 CLI 均检查同一原文件与 Files 回执，记忆不代替 Goal/Task、权限和 Session/Run 权威事实。

固定底部 Mote 快捷入口指向已有协调对象，不随当前 Space 自动换对象；打开、展开、收起与进入完整 Space 都复用同一耐久身份和原工作面。

有稳定身份、SOUL.md 和全局负责能力的持久产品对象统一称为 **Mote**；Space 树、创建与固定快捷入口使用同一含义，PMO 仅为初始化默认角色之一。命名不改变耐久目录、Core Session、ctxmux Run 与布局身份。

Topic 自动发现只读取原收纳目录的直接 Topic 子目录，不扫描无关项目或全盘；内容和工作面身份连续。

- Space 的顶部通用创建保留跨类型菜单；分区 `+` 沿[对象发现与创建](spaces-and-layout.md#对象发现与创建)创建 Mote、Category 或打开 Folder，Category 页创建具体 Topic。从任意当前 Space 创建 Topic/Mote 都进入其持久目录，不要求先切到默认 Topics。
- Mote 创建时提供可编辑的 SOUL.md 和默认 PMO 角色；普通 Topic 不继承人格。一个目录中的 SOUL.md 是该目录具有持久人格的文件事实，和有没有运行 Session 分开。Topic 的知识基础继续保留，Mote 自行组织后续知识。
- 左下角默认 Mote 仍打开已有协调对象的快捷面；入口的展开状态独立于 Working / Needs you 等真实 Session 状态，无障碍名称与描述可辨；树条目进入该对象的完整工作面。快捷面可打开完整 Space，完整面可编辑同一 SOUL.md。两条入口复用既有 Tab/Region/Session，不因面板开合新建对象；关闭快捷面沿[独立导航上下文](spaces-and-layout.md#worksurveyrecall-与-mote-的导航上下文)继续背景当前目标与原执行上下文，不能恢复打开时的旧选择；进入完整 Space 保留明确选择的新目标。同一 Mote 有多个会话时，快捷面与重启恢复保留已有目标 Tab 和 Mote 焦点，不能仅因它排在列表前面就换到另一个会话；浮层的目标选择不改写原主工作面的选中。
- 新 Mote 从没有运行 Session 的可用启动面开始，不凭打开或创建预制启动额外 Terminal。普通 Topic 的首次 Terminal 规则继续成立。
- SOUL.md 的内容在新执行会话启动时作为该 Mote 的人格上下文实际传入 Core；恢复已有会话保留其原上下文和持久目录。正在运行的会话不因文件保存而声称已热更新；文件编辑入口明确说明新会话使用更新后的内容。读取失败应给出可见原因，原目录、工作面和健康 Session 保留。
- Topic 升级成角色和复制尚未确认为产品要求；Mote 归档与恢复见[《Mote 归档与恢复》](motes-and-coordination.md#mote-归档与恢复)。
