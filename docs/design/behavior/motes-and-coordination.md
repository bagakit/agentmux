## Mote 快捷入口与当前协调上下文

### Space 中的协作者名册

Space 的同一 Mote 名册支持协作者视图与常规列表，显示选择及名册头像尺寸由原 Settings/config owner 保存。用户明确要求缺省头像尺寸为 45；同一个有界尺寸设置同时作用于协作者视图与常规列表，列表行随头像高度调整并保紧凑文字和对象动作。设置提供按实际尺寸显示的头像剪影预设，点击选择后仍可沿原滑块微调；两者编辑同一设置草稿，明确保存后生效。浮窗和名片的头像尺寸各沿原合同；缺省值调整不覆盖用户已保存的尺寸。协作者视图突出可辨头像和名字，列表适合紧凑扫描；两者消费同一文件事实、身份、搜索、固定/排序、当前选择和对象菜单，切换或调整尺寸不重建 Mote、Tab/Region、资料、未发送草稿或 Session/Run。未保存设置保持原已确认呈现；保存冲突或失败保选择草稿和原可用工作面。缺省选择协作者视图，读取不写回配置。

选择打开准确原 Mote，改名、头像、行为设定、新讨论、资料、固定与归档/恢复沿原对象动作。归档筛选用同一图标与已确认数量，保可访问名称、开关状态和原焦点恢复，不把归档或未知当执行终局，不影响主 Mote 保护。完整 Profile/Ideas/文件仍沿共享 Space 框架；浮窗保交流与原 Tab 行快捷入口。

显示偏好作为 Desktop 的 `moteDirectoryView` 标量复用原 `settings inspect/set` JSON-RPC／CLI 与耐久 config owner，合法值为 `collaborators`、`list`；名册头像尺寸沿同一入口保存为有界数值显示偏好，公开设置的缺省值与此处用户确认一致，范围由该设置的公共合同定义。两项偏好不属于 Core 空间身份、执行事实或用户 SOUL，不新增 Mote 管理协议或运行时。

用户反馈：「现在左下角的 Mode 按钮和实际的 Mode 配合得似乎不是特别好，相互关联不上」，要求「整体地 review 和重新设计」。当前该位置的产品入口称为 Mote；本轮针对其按钮、快捷面和实际协调上下文的一致性，不改变 Mote 的持久身份。用户应该在点击前后都知道入口会打开哪一段工作、现在是哪位 Agent 在处理，以及怎样进入同一完整工作面。

用户进一步希望 hover 时直接显示，认为当前面板离按钮太远、信息冗余且整合不好，title 行没有必要，多个 Mote 却只显示一个。快捷入口采用同一个可操作面：悬停临时呈现，明确交互固定；所有 Mote 与原工作面在这个面内可达，不再另叠一块只说明用途的 tooltip。

用户继续要求把窗口内的 Mote 对象放到左侧，避免与 Tab 叠在一起；可以在宽卡片与仅头像两态切换，「类似 Discord」；窗口边缘更明显，与背后工作面区分。对象导航与事情导航分层，仍是原来的同一个可操作快捷面。

左下 Mote 面板与 Work 中 Mote 实体的导航边界只见[Work、Survey 与 Mote 的导航上下文](spaces-and-layout.md#worksurvey-与-mote-的导航上下文)，本节继续定义原协调对象与快捷面的行为。Mote 与 Topic 的文件树使用同一公共能力；Mote 文件区固定浏览该 Mote 的原真实根，不提供展开整个共享目录的“Show all files”或面向普通知识 Topic 的收集入口，普通文件及知识能力从各自原场景可达，不借 Mote 顶部改变范围或把引用收集叫文件保存。二级内容按对象表达：知识库 Category 展开具体 Topic，Topic 显示自身讨论、知识与资料，Mote 呈现同一持久对象的自我设定、名片与点子，让用户理解这位搭档和怎样继续合作。知识层级只见[《Topics 知识库的层级与沉淀》](spaces-and-layout.md#topics-知识库的层级与沉淀)。自我设定与名片沿原名称、头像、SOUL 等事实，点子沿已有持久笔记与资料能力，不另造人格、Memory 引擎、记忆存储或强制资料分类。菜单文案与具体分组数量不由本条规定；框架与共同工作面只见[《Space 的统一工作面框架》](spaces-and-layout.md#space-的统一工作面框架)。Mote 主选择器只列 Mote，跨对象浏览仍由 Space 中分开的 Motes 与 Topics 分区承担。同一 Mote 可以有多个自己的 Tab/Group，这些事情标签不表示多个 Topic；Mote 与 Zone 不合并身份，也不改变既有实体多处展示绑定。共用文件树不改变原文件资源归属，导航分类与物理存储仍是不同事实；目录分离与已授权迁移统一遵守[《Topic 与 Mote 的物理目录》](#topic-与-mote-的物理目录)。

Mote 在 Space 中的二级对象内容以 Profile 为首屏，Ideas 承载原笔记与点子；原 SOUL／自我设定直接呈现在 Profile，沿明确文件编辑动作进入右侧原 Editor，不另设 Persona 切换。对象内容仍在共同框架内，保同一原 Zone 工作面与公共文件能力，不另造 Zone 导航、文件树、Editor 或 Tab/Region 管理；切换与原工作面的保护统一遵守前述 Space 框架，普通 Topic 保持自己的内容。 名片首屏以准确身份、已保存的合作方式和当前事项为主；`topic.md` 的原摘要收在注明文件来源的按需展开处，与原 `SOUL.md` 分开辨认，并可沿原 Editor 编辑。展示调整不按文案猜测哪些内容是默认模板，也不删除已保存摘要；没有事项或点子时保原创建／查看动作，读取尚未确认或失败时仍保可读说明与原恢复动作。

**对象范围与成员完整隔离。** 从树、快捷面、恢复、来源 Session 或公开导航打开 Mote，都建立同一准确 Mote 与其原 Zone/Tab/Region 展示引用。其工作面只枚举原空间关系明确关联的成员，不因共用 Scratch、旧 `topicId`、cwd、标题或相邻 Tab 把其他 Topic／未绑定 Topic 的 Tab 纳入；经原关系明确绑定的外来 Zone、Tab 与合法跨 Workspace 展示继续可达，隔离不是删除共享内容。该对象内切 Group/Tab/Region、编辑文件、输入或新建工作面保持 Mote 范围，局部落焦不能清掉对象选择后跳回 Topics。只有明确的跨对象导航才切换对象；外来文件的资源归属不自行改写当前 Mote 的选择。成员或位置未知时保原引用、已确认成员和当前工作，给出持续恢复说明，不退回整份 Scratch、猜邻居或自动创建替代 Session。未绑定 Topic 的原 Zone/Tab 仍在明确的全局入口可找到。名片、文件动作和讨论导航使用同一范围，进程重启先恢复该对象与工作面，健康 Run、草稿、布局及执行 cwd 保留。

Mote 浮窗是原交流工作面的快捷入口，文件、编辑及名片／自我设定／点子等完整对象内容在同一 Space 内继续可达，浮窗不再重复承载这些工具面。进入完整 Space 的动作放在原公共 Tab 行的 `Open in Space` 快捷图标；空 Mote 沿原空态顶部保留同一动作，不为了提供入口新建 Tab 或 Session。导航沿当前已选 Mote 与已确认的完整 Tab／Group／Region 引用接手原工作，保原草稿、模式与健康 Session／Run；位置未确认时仍按本节原目标保护与恢复说明处理，不猜另一个位置，也不关闭可用正文。此分工不取消 Space 的原文件、编辑、人格和资料能力。空 Mote 的文件或目录终端动作由用户在已确认的同一 Space 明确发起，沿它当前实际呈现的活动 Pane 放置；先核原资源、Space 绑定和可见 Group，不借背景项目或未知保存地址，不先造讨论。

- **名片和自我设定能操作原对象。** 用户能查看已确认的名称、头像、真实摘要与原 SOUL；名片头像本身是该名片唯一更换头像的入口，姓名旁的改名动作沿原耐久名称 owner，不新增外观或改名机制。编辑绑定打开时的明确原 Mote 和所属 Workspace；资源重绑不自动更换原目标或清空未保存草稿，错误保存由原资源 owner 明确拒绝，不借邻居作目标。关闭编辑面只在原触发控件仍可用、当前仍属同一资源且没有后来外部焦点时返回它。自我设定按前述 Profile 首屏分工呈现，不重复提供功能组跳转链接；未确认的摘要不以模板介绍代替。合作方式与知识检查沿原内容 owner 按需进入，保存、生效、冲突和未确认继续由该 owner 负责，不借此改写运行中的 Session。头像编辑与改名的保存／取消／失败保全分别遵守本专题原头像与耐久名称合同，真实运行状态、SOUL、笔记和原工作面保持。
- **点子能查看、编辑和继续。** 点子沿当前 Mote 的持久笔记与资料查看，用户可明确通过原文件／笔记动作创建或编辑，打开已有来源讨论与成果，再沿原讨论动作继续交流。Profile 只展示有限若干原笔记标题，近期顺序沿原文件系统已确认的修改时间；时间缺失或读取未确认时如实说明，不用列表顺序、刷新计数或当前时间伪造近期。点击标题切到 Ideas 并定位同一准确原笔记，不借邻居 Mote、重读整份目录正文或维护另一份笔记缓存。条目引用原内容与已记录的来源，不复制正文、聊天或进度；来源和范围未记录时如实说明，不从邻居 Session 推断。没有笔记时保原文件访问和明确创建入口；读取失败保原引用、草稿与服务窗。知识组织仍自主，不强制固定点子文件、资料分类、Memory 引擎或新的 Goal／Task 账本。

用户随后明确批准实施：「你的建议挺好的，就这么改吧。注意设计方面，交互设计方面要发挥你的最高水平」，并希望整个弹出面板呈现类似 Discord「和很多 Agent 交流的效果」，强调「只是一个 Agent 可以启动多个会话 Session」，提出 Mote 在 Space 打开时也采用这样的聊天画面。Mote 浮窗与 Space 中打开的 Mote 工作面遵守同一对象与会话层级：多个 Mote 是持久对象选择，所选 Mote 下的多个 Session 与承载事情的 Tab/Group、实际 Region 各有准确归属，不能把会话数量画成 Mote 数量或把普通 Topic 默认变成该 Mote 的成员。Mote 工作面围绕交流与原正文输入呈现，在前述共同 Space 框架内继续复用原 Zone/Tab/Region、文件与 Core 生命周期；普通 Topic 保持自己的知识内容。Discord 的交流参考不授权另造 Tab 导航或工作面。进入、切换和往返保原 Tab、Region、健康 Session/Run、非空草稿、执行历史与恢复，不复制聊天或重启 Agent。文件访问沿同一公共文件树与明确资源目标，原 Mote 的耐久资料及全局浏览仍可达；知识组织由 Mote 自主，不强制分类或搬目录。身份通过对象导航与原必要上下文持续可读，不恢复已取消的独立 title 行、重复标题或第二套模式栏。具体视觉稿与真实正常/窄窗/失败场景须独立评审，不能只以复用组件或采图成功冒称达到该交流体验。

Mote 的事情导航沿原 Tab 控件使用 `Discussions`／`New discussion` 等用户可懂措辞；讨论承载原 Tab，内部可以有多个真实 Region／Session，不把改文案变成新会话或让 Tab 与 Session 同义。发言显示准确作者：只有实际 Session 的 Host、运行目录与原 Mote 耐久身份明确相符时，才用该 Mote 的持久名称与同一头像；同处当前工作面、同名标题或表面关联不构成归属，外来或未知作者保原真实身份。正文、历史、输入与操作继续由原内容 owner 承担，不复制另一份聊天记录；平面紧凑消息与公共 Tab/Region 导航在宽窄工作面中的可读性唯一见 surface-density 同名章节。资料读取慢或迟到时仍保原文件 owner 的结果，但不因返回时又选中同一 Mote 就抢回旧选择；同一 Mote 下较晚选择的讨论／Region、A→B→A 往返后的新意图、后来输入与焦点始终优先，失效请求不重新选择旧文件、讨论或工作面，也不收起后来打开的资料栏。

用户进一步要求支持修改 Mote 名字，但找不到入口，并认为 Mote 右键菜单功能太少，希望参考 Muse。Mote 的改名与常用对象动作在原名册／Space 对象菜单中可发现，鼠标与键盘均可达；改的是同一耐久 Mote 的语义名称，不是某一个 Session 的显示名，不改目录身份、SOUL、头像、已有 Tab/Region、执行绑定或健康 Run。保存／取消／失败及迟到结果保原对象与草稿，浮窗即使在 Settings、Focus 等背景上也绑定原 Mote 和所属 Workspace，不能借当前背景项目误投。头像、人格、资料／完整 Space、pin 与归档／恢复沿已有能力和主身份保护组织，常用动作足够合理且主次可读；对象管理与当前 Session 的关闭、分屏、输入附件、模式动作分别指向真实原目标，不把菜单扩充变成新增执行能力。系统层级与弹层命中只引用[《浮层让位默认成立，而不是逐个接线》](spaces-and-layout.md#浮层让位默认成立而不是逐个接线)本次反馈合同。

尚未启动 Agent／睡眠的 Mote 工作面也围绕当前 Mote 自身：原启动面标题显示已确认的这个 Mote 名称，不把 Topics/Scratch 收纳容器当作当前对象。对象名称与实际运行环境分开，Host、工作目录和启动参数仍是原资源事实；名称尚未确认时保原工作面并如实说明，不借默认或邻居 Mote。普通 Topic、Folder 与空 Group 沿原环境身份。此要求不合并 Mote、Zone、Tab 或 Session，不改变多处展示绑定或物理目录。

- **面板内同一个当前目标**。左下入口的无障碍描述、快捷面选择与当前状态都指向该面板已选的同一个 Mote、实际 Tab 与当前 Region；「Open in Space」明确将这个准确目标一次带入 Work，此后两边各自保留选择，沿前述导航上下文合同。Mote 表达持久协调对象，Tab 名表达当前事情，Provider/Executor 和 Session 表达实际执行者，不能相互冒充。Goal 的专属讨论仍是自己的 Tab，入口必须能读出该 Goal 的上下文，不能只用泛称 Mote 掩盖正在打开另一件事。自定义 Mote 的投影、准备与完整 Space 都指向它自身的持久对象与准确原空间关系，不借默认 Mote 的工作面。
- **可进入的悬停面**。鼠标悬停入口即显示原可操作面，允许越过按钮与面板间的小间隙进入、滚动、选择和输入；未固定时离开两者后自然收起。悬停本身不改变 DOM 焦点、光标或组字，不选择另一个 Mote/Tab/Region，不持久化打开状态、不写视图模式、不启动 Session/Run、不发送或入队输入。键盘与触控有等效的明确打开入口；Escape 收起预览，不抢走输入法或另一块已打开浮层拥有的按键，也不把未移动过的焦点拉回入口。
- **不同工作面同样可操作**。用户反馈在 Mote 工作面 hover 后可移入操作，切到设置页却只能看到窗口、无法操作。Settings、Space、Focus、Goals、Survey 等窗口内容切换不改变同一个 Mote 快捷面的可进入性；面板及原投影不能继承被设置遮住的背景工作面的 inert/隐藏归属。移入、明确固定、选择与输入仍沿原 owner，悬停不关闭设置、不移动原焦点、不写 Agent 模式；被设置遮住的背景继续不接收输入，健康 Run 和原 Tab/Region/草稿保留。
- **全部 Mote 可选**。快捷面呈现既有默认 Mote 和文件系统已确认含 SOUL 的全部 Mote 对象，每个对象有紧凑可选行、可读身份与它实际目标的状态；多个 Tab 或 Session 不冒充多个 Mote，普通 Topic 不混入名册。超出可用空间时仍能滚动到全部对象，不只取默认或当前一个。目录、快捷选择与焦点分类共享同一份文件快照事实及修订边界，不新增 Mote id 名册、不在 Tab/Session 上复制身份布尔，也不把分类另行持久化；目录读取失败保留已有事实与已选原引用，说明未知和失败步骤。 冷读也按独立事实处理：原目录 owner 已确认的完整身份、实际地址及 Mote 类型不依赖协作者牌、介绍正文或 Wiki 同时读成功；局部失败随原对象说明，不能把已确认 Mote 从名册拿走。身份或类型证据本身未确认时保未知，不凭所在目录、名称或邻居推断。原 list/read 与共同文件快照承载这些事实，不另设持久名册。
- **Mote 与 Tab 分层**。全部对象沿快捷面左侧导航排列，右侧保留所选 Mote 的原 Tab/Region、说明、正文与输入；不再把对象列表叠在 Tab 上方。明确且可访问的开关在宽卡片与仅头像两种呈现间切换，初始为宽态；两态都有同一组对象、同一精确选中与真实状态，完整名称和状态在头像态通过 hover、键盘焦点及无障碍描述可读。对象多时左侧有界纵向滚动，收起与呈现切换合为一处精简控制，进入完整 Space 沿原 Tab 行动作，不恢复独立 title 行或重复入口。
- **导航呈现偏好独立**。宽卡片/仅头像只是快捷面的单一呈现偏好，由原浮层 UI owner 保存，关开与普通 UI 状态恢复后保持；窄窗可收紧宽态名称空间，不能静默替用户改成头像态或让开关语义与实际呈现不一致。从临时面操作开关仍沿既有明确交互固定语义；切换自身不选择别的 Mote/Topic/Tab/Region，不改原 Agent 模式、执行焦点与历史、草稿、消息队列或 Run，不重建右侧原输入和工作面，不增加逐 Mote 偏好账本或另一份目录事实。
- **范围内拖拽尺寸并记忆**。用户要求 Mote 浮窗「要支持下一定范围内拖拽改变大小(并记忆)」。临时与固定面仍贴原左下入口锚点和小间距，允许从可辨的边缘／角部拖拽改变宽高，保持入口与面板的联系，不成为自由移动窗口。两种左栏呈现都支持，尺寸偏好由同一个原 floating UI owner 保存，关开和普通 Renderer 重载后读回，不另存逐 Mote 尺寸账本，也不改变所选目标、原 Tab/Region、草稿、输入模式或 Session/Run。可用下限让当前卡片／头像导航、必要动作与右侧原正文输入仍可操作；上限由当前 viewport 的实际可用空间决定，收窄或变矮时重新夹紧，视口小于通常下限时仍以当前可见可操作空间为界，不能把浮窗或动作挤到屏幕外。暂时收窄只改变有效尺寸，不改写用户偏好的大尺寸。拖拽越过边界仍能完成或取消，pointercancel、Escape 和失焦（blur）终止均取消未提交手势并回到拖拽前尺寸；结束、取消和关闭后不留下指针捕获、resize cursor 或阻碍输入的遮挡。首次未调整时沿当前默认尺寸，偏好读写失败保留可用浮窗和原工作并说明未保存或未知。
- **明确重新打开先对话，自然固定延续所见面**。用户要求「Mote 窗口打开时默认显示为对话模式」，并明确选择每次重新打开先显示对话、打开后仍可切终端。点击入口或从既有显式上下文入口重新打开准确 Mote 时，当前实际 Agent 的原工作面先显示对话；先 hover 再点击入口仍是明确打开，不能绕过。开着时用户仍可手动切 Terminal；同一已打开目标的重复打开请求不重置其后来选择，显式转到另一准确目标则按新打开先对话。单纯 hover 不写模式；在可见面内选择 Mote/Tab/Region、聚焦、操作或自然固定仍延续同一个所见正文和草稿，不借此翻转模式；尺寸和左栏呈现切换同样不重置。只有当前已确认存在的目标 Agent 承担这次模式请求，不改邻居或其他 Session 的模式；没有真实 Agent、空态或恢复未知保留原引用与现有告示，不猜替代目标、不启动。原 Session 仍持有同一份模式事实，其已有其他显示位置消费同一模式；不另存 Mote 或逐投影模式，不复制原 Runtime。重新载入已固定面不是新的人类打开，沿原保存模式恢复。本条替换旧「关开仍优先保留显式 Terminal」的要求，hover 无写入与面内自然固定的保护不变。明确打开和面内操作沿原固定语义，离开鼠标后仍可继续输入；已经固定的面不因再次经过按钮生成第二块面或抢焦点。两种显示都贴同一入口锚点并适配视口，不提供自由移动、最大化或独立位置记忆；有界尺寸拖拽与记忆遵守本节对应条目。原准确目标、Tab/Region/Session/Run、草稿与队列、执行历史和背后导航选择保持。
- **目标状态来自目标本身**。入口及各 Mote 行表达各自实际目标 Region 所引用 Agent 的真实状态，不把邻居 Session 的 Working、Needs you 或错误当作当前目标状态。已保存目标尚在恢复、尚无 Agent、当前 Region 是其他工作面以及状态未知分别按事实说明；读不到状态不能猜空闲或错误，也不因无关 Session 更新改变当前反馈。收起态只消费当前目标，展开后只增加所示 Mote 与原工作面需要的 Session、名称和事实消费者；目录读取只随所属修订更新，不订阅整份 Timeline 或逐 Session 反复扫描全部 Tab，不让无关 Run 输出放大入口工作。成本底线继续归[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)。
- **协调焦点不污染执行历史**。默认和文件事实确认的自定义 Mote，其协调 Session 都使用既有独立协调焦点；选择 Region/Session、切模式、明确输入与初始化恢复遵守同一语义归属，不能只在浮窗补一个特判后仍把自定义 Mote 的协调 Session 写入执行 Agent 的历史。Mote 在 Space 中的导航选择可更新 Work 的准确对象／位置引用，不反向改写面板目标，也不把协调 Session 重新分类为执行 Agent。已知普通 Topic 和执行 Agent 继续沿原执行焦点。Scratch 身份暂时未知时保留原 lane、选择与历史，给出旁边的服务窗；不猜成普通执行对象，也不等待目录检查完成才允许运行。
- **开合保留上下文**。关闭只收起快捷面，保留已选 Mote/Tab/Region及原 SessionId 或 launcher RegionId 草稿；重新打开回到同一工作。已固定开合与目标沿原 UI owner 持久化，临时悬停不在重启后伪装成用户固定。显式 Goal/Focus 入口仍按前述跨上下文合同选择其精确目标；用户在快捷面主动选择其他 Mote/Tab/Region 只更新面板选择。各处名称、身份、内容与运行状态消费原同源事实，不据此同步导航选择。背景工作面切换、Session 列表顺序、迟到目录读取或恢复事实不擅自更换已选目标。打开完整 Space 是明确进入同一准确目标的一次 Work 导航；收起面板后背景继续所属导航上下文的当前选择，不能恢复旧快照覆盖后来选择，也不停止 Run、不新建 Session、不改写执行 Agent 的独立焦点与历史；只有明确 Send/Queue/Launch 沿原输入 owner 消费原文字。
- **关闭 Tab 按明确意图继续**。用户反馈关掉 Mote 的 Tab 后仍显示“Original Tab retained”并要求回 Space 恢复。收起快捷面与关闭其中的 Tab 是不同意图：经既有确认已实际删除当前 Tab 后，同一 Mote 有其他原 Tab 就继续其原工作面，没有剩余 Tab 就保留该 Mote 的可操作空态，允许用户明确新建；入口、正文、状态与完整 Space 指向同一结果。取消或失败而仍保留原 Tab 时保留原目标；只移除一处位置而 Tab 仍有其他合法位置时保留原对象，不冒称实体或 Session/Run 终局。已关闭事实与后置清理失败分别表达，原错误告示保留，不能继续引用已删除 Tab。不借其他 Mote，也不为清理失效目标停止 Session/Run、悄悄新建或重开已关闭 Tab；空态打开完整 Space 仍展示同一 Mote 的空态，新建只由用户明确 New Tab/+ 消费。已确认存在的选中 Mote 没有已放置的原 Tab 时，统一呈现此可操作空态；切到其他 Mote 再回来仍为空，目录确认不自动补 launcher，不另存逐 Mote 的关闭历史。保存的精确未知 Tab 引用不因没有已放置 Tab 被清成空态。仅因原目标暂未恢复、位置未知、恢复超时或读取失败时，仍按“恢复未知仍有原目标”保留原引用；明确关闭的结果和空态跨普通重启保持。
- **恢复未知仍有原目标**。目标 Tab/Region 或 Session 暂未恢复时，保留原引用与工作面投影，原草稿不交给其他 Agent；在同一快捷面说明等待或失败步骤、当前可用或未知事实及已有恢复动作。不能跳到另一个可用 Agent 来伪装恢复成功，不能为流程失败清空原目标或停止健康 Run。跨真实进程重启仍先恢复工作面与本入口的已选目标，再沿既有公开能力尝试 reattach/resume。
- **恢复说明旁仍能继续原工作**。用户实际反馈 Mote 浮窗正文全空，只剩原 Tab 位置不可用并要求回 Space 的说明，也追问 Space 中点 Mote 是否还没有专属页面。身份已确认的 Mote 在浮窗与 Space 都通过共同框架呈现同一交流体验，自己的原讨论、实际 Region／Session 与资料入口仍可辨，不另造第二套页面。保存的精确 Tab／Region 暂未恢复或当前位置未确认时，保原引用与可行动的服务窗；说明不能拿走整个讨论导航和正文操作面，同一 Mote 已确认的其他原讨论仍可枚举并由用户明确选择。恢复动作指向准确原对象，不能仅让用户凭技术字符串猜去哪里操作；已确认原目标可恢复时继续其原正文，暂不可确认则如实说明。快照、Tabs 或当前 Group 中缺席不等于明确删除、retired 或 unknown 终局，不从另一个 Topic 的 active Group、别的 Mote 或第一个健康 Agent 猜恢复；实际明确关闭仍只按前述关闭合同处理。原草稿、布局、Session／Run 与后来选择保留，不为修空白自动新建、重开已关闭 Tab 或停止健康执行。
- **投影只承担自己的上下文**。窗口工作面 owner 绘制全局导航 chrome；快捷面等 workbench projection 保留自己的 Tab/Region 与操作，不复制背后 Goals、Focus 或其他主工作面的全局标题。快捷面内和背后的 Browser 都保持原内容与可操作区域。没有真实显示 bounds 变化时，悬停不触发 Terminal fit/Runtime resize；所选 Mote 的原 View 真正转入快捷面时，相关显示尺寸可由原 fit/Runtime owner 适配，收起仍恢复原 Tab/Region、阅读与工作面。背景、无关 Terminal 和隐藏 slot 不因浮层开合产生尺寸写入或工作放大。原生层级与尺寸统一沿[《Browser 任务能力与可复用资产》](browser-workface.md#browser-任务能力与可复用资产)及[《Hover 提示不改变 Terminal 几何》](terminal-reading.md#hover-提示不改变-terminal-几何)，只依赖通用 overlay 与实际 Region 事实，不为 Mote 或具体站点写特例。

按钮展开、左侧对象导航两态、状态、动作与窗口外缘的视觉分工唯一见 surface-density[《Mote 快捷入口与当前协调上下文》](../presentation/motes-and-coordination.md#mote-快捷入口与当前协调上下文)。跨 Mote 选择复用既有对象目录、Tab、Region、焦点、命名与状态 owner，不增加默认 Tab 或逐 Mote 记忆注册表、第二份消息投递通路或 Runtime/Session 生命周期。

## Mote 的日常合作

Mote 提供可理解、可纠正、接得上工作的长期合作体验。合作方式、记忆检查、安排、点子和成果在原 Space 对象内容及原对话里可达；浮窗仍只作同一交流工作面的快捷入口。它们消费原文件、目标、Session 与调度事实，不产生第二份文件树、记忆数据库、任务账本或 Runtime。外部连接器应采用通用连接结构，其具体授权与接入仍需独立讨论，不因本节授权某一厂商登录或外发。

- **认识与行为方式。** 首次建立关系可以跳过，已有对话和用户当前输入优先。Profile 展示该 Mote 已确认的行为摘要，行为方式设定采用与头像设定一致的可操作编辑体验：四组具体行为偏好及自定义文字可选择、预览和撤回。四组分别对应交流朝向、获取信息、权衡建议和推进节奏；完整、明确的选择导出 E/I、S/N、T/F、J/P 四字母 MBTI 风格标签。它只概括用户选择的合作偏好，不把任意 SOUL、头像、运行状态或模型回复当作人格测评依据；未确认的设定不猜标签。偏好继续沿原 SOUL 可读、可编辑和耐久保存，原自定义内容、未保存草稿、文件冲突及保存未知保留；准备设定草稿与实际保存分开表达，仅替换已确认的应用行为块，不改任意原文与旧合作／反馈要求，不建第二份人格事实。取消不改原文件，跨对象、迟到读取或后来编辑不能覆盖当前目标和输入。用户可用自己的问题沿原 Launcher 在明确的新 Session 试聊，实际 Agent／模型、生成状态与失败可辨，不把规则预览或预写台词冒充回复，不替换正在工作的 Run。编辑处说明已保存设定对新 Session 生效；已有会话的原上下文不热改，临时指令仍优先于已记偏好。行为偏好和标签不新增工具权限、自动输入、外部授权或主动跟进开关。
- **检查与更正记忆。** 用户能从 Profile 抵达该 Mote 原资料，查看保存内容、实际记录的来源与范围，并沿原文件能力更正或撤回。没有记录来源或使用事实时表达未知；目录中的普通点子不能自动被称作已记住的事实。保存、读回、冲突和未确认沿原编辑 owner，保原草稿及正确资源，不盲重写。资料组织自主，不强制固定记忆文件或吞入全部聊天；改变记忆不删除原历史，也不扩大执行授权。
- **日历安排。** 用户能表达一次、每日、每周、每月与每年的当地时刻，明确时区，查看下一次触发、原目标、原正文及状态，暂停、继续或取消。安排经原持久调度与 Core 输入执行，持久安排和投递确认分开；错过的周期不集中补发，忙碌、用户输入、权限等待、重复操作和未知回执沿原保护。明确当前保证的宿主在线范围，不将独立 Run 存活、关 App、睡眠或离线猜成提醒仍能兑现；未确认的投递保原操作供检查，不自动重发。重启恢复原安排、状态与操作身份，不创建替代 Session。
- **有分寸的跟进。** 主动问候由用户明确开启，可暂停，遵守当地安静时段、最小间隔和预算；没有明确相关目标或真实对话就不编关心话题。上一条主动问题未获用户答复时不叠问；用户正在输入、Agent 忙碌或等授权时不插话。内容简短、针对已确认上下文，并明确来源，不假称后台完成工作。同一实体在多个位置显示仍只消费一份安排与原投递身份，隐藏或打开 Profile 不新增后台循环。
- **点子与继续讨论。** 用户能明确请求基于已确认资料、目标和最近对话的少量具体建议，看到相关理由及实际使用的来源。资料稀少时承认，来源未核时不伪称已核；喜欢或不喜欢的显式反馈影响后续生成。建议仍沿原笔记与文件能力保存、编辑及引用，选择点子形成原讨论草稿，由用户决定启动；生成点子只授权所需读取，不授权外发、安排、购买或修改外部资源。
- **把成果交到手边。** 原对话能呈现实际文件成果，保可辨名称／类型与原打开动作，并回到原消息或工具事实。文件与回复的关系来自已确认的原引用，不仅凭时间邻近推定权威来源；文件失效或结果未确认保原引用及说明。原 Markdown、文件预览、Git／Result Review 继续使用同一资源与身份，不另建成果存储或读取无关 Session。隐藏展示不做新的文件扫描或预览加载。

用户可检查的安排、偏好和生成动作按[公共能力贡献约定](../../guides/public-capability-contributions.md)评估并消费同一业务 owner 的公共接口；发现、配置或读取不隐含启动、投递或外部授权。上述行为要求不以提示词在场、保存请求成功或单个模型样本代替实际链路资格。

### 目标、持续推进与成果回报

Mote 的主动推进沿原 Goal、准确执行 Session 与原续跑调度成立。用户可以在当前 Mote 的真实讨论中交代一个目标，确认原 Goal 的成功条件，并明确选择关联的执行者；“持续推进”是单独授权，默认不打开。此后同一目标的当前进展、需要用户决定的事项、下一次检查与成果入口就地可达，不要求用户先填写脚本目录或另建执行清单。探索性聊天与初次认识不自动创建空 Goal。Goal 的定义、确认和成果接受唯一见[《Goals 与 Demand》](goals-and-demand.md)。

授权绑定原 Goal ID、已确认 alignment revision 与准确 Host/Session/Provider/cwd。多个执行者必须明确选择，不能借最后关联项、背景 Space、名称或当前目录猜执行者。原定时推进与日历消息共用既有调度和 Core 输入事务，各自保留业务语义；Goal 生命周期由原 Goal owner 解释，Core 的续跑 source/scheduler 不新增 Mote、Demand 或 UI 依赖，也不解释 Goal 生命周期。一次开始的业务 operationId 与后续 tick 各自准确留存，丢失回执按原操作核对；未确认不得重复发送或创建替代 Session。

阻塞、待决定、原目标确认失效或原 source 不可读时，自动推进暂停并说明；完成或取消只停止该目标的自动推进，不停止健康 Run、不删除原工作面、不冒充成果已接受。改名或无关目标变化不停止当前目标。原版本已失效的 loop 仍可检查或停止，不能恢复旧授权。新确认版本由用户明确停止旧 loop、以新的开始操作授权，不自动重绑或改写旧未知事务。继续执行须重新确认当前版本、目标和原输入条件；手动输入、权限请求、运行繁忙和未知 delivery 保留原 Core 的保护与可用能力。应用或连接恢复保原目标、同一 loop、待核操作与讨论，不追补一串过期 tick。

回访摘要从原 Goal 的活动、决定、实际 grounding 与原 loop 状态取事实，以“做了什么 / 卡在哪里 / 需要你决定什么 / 成果”组织；接受输入、空闲状态与计时器触发均不算成果。成果沿原文件引用和 Goal 逐项证据，保 met/gap/unknown、人类接受与版本。暂停、恢复、停止在当前内容旁可达，不能以新表单、第二文件树或第二任务数据库承载。

### 自然认识、可纠正资料与主动点子

第一次合作可从一个真实问题开始，介绍与偏好设定均可跳过；行为与 MBTI 仍是原 SOUL 的可编辑偏好，不能要求先完成性格测验才能工作。跨讨论资料从该 Mote 的原 SOUL 与原文件读取，按需显示本次真实读回或带入的文件与版本，并沿原 Editor 修改；模型实际应用资料须有真实工具/回答见证，准备提示不等于使用证明。保存失败或未确认保留草稿与服务说明；已有 Session 的上下文不冒称实时热更。下一次新讨论读取新资料，另一 Mote 不借同目录邻居或背景对象获得资料。

主动点子由用户为准确执行者明确开启原安排；频率、静默/暂停及来源范围可读。普通目标续跑、定时消息与轻量问候各自说明用途，问候不能伪装成后台工作。建议应少而相关，解释为何值得做并按需给出实际资料来源，不以定时写一条消息充当有价值点子。安排保存准确资料 locator 与原意图；创建时摘要只称最后确认，执行时须由实际 Agent 重读当前文件并说明未知，不重写同操作的投递内容。用户接受后沿原 Goal 或原讨论继续，反馈沿原 SOUL/文件保存并在后续新讨论中真实消费，不另建 Feed 或 Memory 引擎。

持续执行以原 Host 在线、Agent 可用和准确输入条件为前提；关闭当前面板或换设备不改变原执行身份。设备/连接不可达时显示最后已确认事实与未知状态，不宣称云端全天候保证。公共 API、CLI 与已连接设备消费同一 Goal/loop 回执、暂停和成果事实；飞书/Lark 连接留待通用连接结构讨论，不在本批加入厂商分支。

### 资料刷新与当前工作摘要

名册复用原文件系统观察；无关普通文件修改不重读全名册。已确认对象的设定、归档或正文变化只重读该对象，目录成员或身份记录变化才重新发现成员。较早的扫描不覆盖在途期间已确认的新对象；局部成功不抹掉其他对象或目录发现仍未知的事实。读取失败保原身份与可用工作面，按原范围提供重试。

准备问题或点子只核对用户选中的原资料，以及准确资源、展示引用和用户后来输入。无关对象的保存不取消准备；选中资料确实改变、资源或页面改变过、用户改了输入时，迟到结果不得替用户创建讨论或安排。读完最后一次核对仍须检查当前输入与原目标，保原草稿。

Profile 的当前工作以原 Goal 状态、验收和记录为准，缺省最多显示三项摘要，优先提示阻塞和待确认的工作。数量及完整记录入口清楚可达；已结束的历史仍可查，展开与返回不改变原 Goal、讨论、草稿、Session 或 Run。行为设定与最近点子继续是 Profile 中可达的对象内容。

## Topic 与 Mote 的物理目录

普通 Topic 的 canonical 文件目录在 `~/.agentmux/topics`，Mote 在 `~/.agentmux/motes`。用户明确要求分离并迁移已有对象，原目录保留对应软链接，以后再删；本轮不删除这些链接。这是明确授权的数据迁移与临时旧地址，不由一般“不留 migration／fallback”的实现规则否定，也不扩展为任意目录迁移。归类沿已有文件事实：主 Mote 与已确认含 SOUL 的对象是 Mote，已归档对象同样迁移；分类读取失败保持未知，不当普通 Topic 猜着搬。内容组织仍自主，不改写用户知识文件或强制分类。

- **Mote 使用稳定的物理短名。** Mote 的 canonical 路径为 `~/.agentmux/motes/<持久 Mote ID 的短哈希>`，从完整、已确认的内容 ID 导出，不使用 Topic／Launcher 技术前缀，不随改名、关闭或新建讨论、切换 Agent Session 改变。短名只用于目录索引，不能代替完整对象 ID；同名目标必须核对同一对象，碰撞、未知记录或别的对象不能被覆盖或冒认。新对象直接使用自己的 canonical 短目录身份；现有对象改物理名时保各自准确原身份、资料、头像、归档、全部展示绑定及执行 cwd，精确旧地址仍通向同一对象。完整内容 ID 与相对原根的身份定位由原 app-owned 目录元数据保存，不能写绝对路径、另建身份名册或从短哈希反造 ID。发现与公开查询只读；记录缺失、损坏或未确认时保已确认对象和工作面并说明恢复动作，不能以当前物理地址重铸身份。具体摘要算法与长度由实现负责，不作为其他对象的通用命名限制。

- **展示身份与物理地址分开。** `__scratch__` Workspace 保留原 Scratch 逻辑容器地址与 ID；物理目录迁移本身保既有 Topic/Mote 内容身份、空间实体、选择、草稿、文件逻辑引用与执行绑定。普通 Topic 到 Category→Topic 的空间层级承接是另一个明确动作，旧普通 Topic Space 节点转换与原内容 ID 保留只见[《Topics 知识库的层级与沉淀》](spaces-and-layout.md#topics-知识库的层级与沉淀)，不据旧文件 alias 保留永久旧空间 owner。Snapshot 明确给出实际物理目录，真实 IO、新启动 cwd 与公开查询的对象 path 消费该地址；公开查询只投影原协议字段，不泄漏内部路径元数据；原相对文件地址仍由同一受限文件 owner 解析，不按背景项目或显示位置猜对象。新对象直接写入对应 canonical 根，不先创建旧实体再搬。
- **迁移保留原对象。** 已确认的旧目录在同盘以不覆盖目标的同一次原子 exchange 保留原 inode 与完整内容，同时把精确旧地址变为对应软链接，不留下旧路径不可用的间隙；`topic.md`、SOUL、Wiki、`.agents`、`.agentmux`、头像资产、归档和任意用户文件不重建、不清洗、不丢弃。旧目录身份由对象内 app-owned `.agentmux/directory-identity.json` 保持，文件中不写绝对路径；只保存相对于原逻辑容器的已校验对象定位及该原逻辑身份的核对依据，由原 Workspace 的登记地址解析为同一个既有目录身份，保原头像与 Space/Zone 地址，即使将来删除旧链接也不重发身份。原逻辑根、目标目录名与记录必须一致，不能改用当前物理地址、另一根目录或同名对象重铸身份；记录须在 canonical 对象暴露前耐久保存。已保存的旧绝对路径记录只在原目录 owner 严格确认原根、原对象及原记录后无损重编码，失败、冲突或保存未确认保原记录、内容与工作面，不以删除记录或重建对象完成升级；公开读取和目录发现保持只读，不暗中改写文件。记录承载完整内容 ID 及该对象的目录身份，不成为 Session/Run 或第二份工作面事实，损坏或未知不得退回物理地址重铸身份。新对象使用自己的 canonical 目录身份。冲突、失败或无法确认的步骤如实可恢复，不能覆盖已有目标、将部分结果称为完成、跳过对象不说明，或删除未确认的原数据。
- **记录维护的确认与恢复。** 升级中的原记录保留为这次操作的待确认见证，不成为第二份身份表；并发替换、中断或耐久保存未确认时保留实际原字节，不能覆盖后来出现的记录。即使新格式已可读取，只要本次操作仍未确认，冷读取与公开观察仍保原可确认身份和持续说明；没有准确见证时沿原工作面绑定保未知，不借当前物理地址重发身份。恢复沿同一原目录维护入口核对实际记录、原对象及耐久保存后解除说明，公开查询不执行修复。
- **旧执行与新启动各用真实地址。** 已有 Session/Run 的保存 cwd 与身份原样，迁移不停止、重启或改写健康执行；旧地址仍连到同一对象，活跃进程继续读写原 inode。新启动使用 canonical cwd，经 Core 原公共能力创建。真实进程重启后恢复原工作面、引用与状态，旧 Session 继续沿自己的原地址恢复，不借迁移造替代 Session 或把 unknown 当终局。
- **旧 alias 不放宽文件边界。** ScratchTopics 与通用文件入口共用 Main 的受限目录解析，只接受已确认身份、精确旧直系目录与相应 canonical 目标的映射；读取仍遵守原已允许的 explicit 只读链接能力；任意链接不因此获得变更权限或新增可访问范围，被替换的根/目标及逃逸继续按原权限与路径规则拒绝。主 Mote 的删除／移动保护、头像资产范围及原保存冲突检查仍成立；失败只拒绝这次错误目标的动作，不拿走健康 Agent 与原工作面。

Mote 头像「平时也要偶尔活动」：实际可见的日常身份头像不要求鼠标靠近或 Agent 正在工作才有局部动作，Make a face 沿原五官关节表达短暂神态，原龙、上传图片与默认／手选图形可有不损害辨识的轻微姿态，不推断图片五官或改写保存外观。待机动作与运行事实分开，不借活动伪装 Working、工具调用、在线或恢复成功；睡态仍可辨为睡态，待回复与未知只用中性短动作并保原眉嘴及说明，不能被好奇或笑脸覆盖；错误和已停止不叠加日常动作并保持可辨。已确认没有 Agent 的初始 launcher/空态呈现睡觉，已结束的进程仍明确说明“已停止”；保存目标或 Session 暂未恢复不当作未启动。Working 呈现思考；当前准确 Agent 的真实在途工具事件可联动表情，工具完成或失败后不继续伪装仍在调用。历史工具、另一位 Agent、旧 Run、迟到事件或缺失出处不能冒充当前调用；无可确认工具事实时仍表达原真实运行状态。Starting、待用户处理、Blocked、Error、Disconnected、恢复未知及进程运行但语义未知分别可辨，不把未知猜成 Idle、睡觉或成功；表情和颜色不替代原状态说明及请求/服务窗。动作强度与日常节奏只见 surface-density[《Mote 头像与主 Mote》](../presentation/motes-and-coordination.md#mote-头像与主-mote)。

默认主 Mote 的原龙与自定义图片沿同一原头像动态 owner 支持轻微待机动作和指针附近的朝向响应；响应仅改变临时呈现，不推断图片五官、改写保存外观或把睡态／未知表达成醒来与正常运行。普通 Topic 图标不因这项能力加入头像动态。

仅实际可见的入口与名册身份头像消费其准确目标状态与必要工具事实；隐藏实例、头像滚出可见范围、页面隐藏或减少动态偏好下停止动态并保留可辨静态状态，可见的左下入口不因浮窗收起而停止自己的日常动作。消息历史中的作者头像继续保原色与静态身份，不因本条为每条历史消息新增动画或 Session 消费。动画不增加全局轮询、逐头像 JavaScript 帧循环、整份 Timeline 订阅或无关 Session 的工作放大，不触发 fit/Runtime resize、不改变输入焦点、草稿、授权或生命周期。视觉、动画强度与控件密度唯一见 surface-density[《Mote 头像与主 Mote》](../presentation/motes-and-coordination.md#mote-头像与主-mote)。

用户补充此前要求：「如果是 make face 的情况下，它实际上应该是骨骼动画。平时它可能会有一些表情、神态的变化。如果我的鼠标离它很近，它还会看向我的鼠标。这种灵动的效也要有。」捏脸采用内部五官可组合的骨骼／关节式连续变化，平时的表情神态和靠近时的视线响应仍能认出保存的同一张脸；不能整图帧替换、整头旋转或遮脸装饰伪装成该能力。鼠标靠近只使附近准确可见的捏脸实例局部响应，视线与真实运行状态的临时表情组合而不覆盖待处理、错误或未知提示；不把鼠标互动伪造为 Agent 工作或工具事实。隐藏、离屏、页面不可见与 reduced-motion 停止动态，退出附近恢复原状态；不为无关隐藏实例增加 pointer listener、rAF、轮询或 Timeline 消费，沿前述相关成本与输入／生命周期保全。图片与图标仍沿原语义，不硬贴捏脸五官或改变原图片。

用户进一步要求：“应该要有主mote设计，就是不可被用户删除的一个mote，默认就有”。主 Mote 使用原默认 Mote 的固定身份，由既有目录 owner 在普通启动时幂等提供，同一对象仍在创建时重复请求等待原结果，结束后不缓存过时快照；失败保原内容并可明确重试，不能把尚未完成的创建误报为外来对象，不按名称、列表首项、Session 或是否正在运行猜主身份，也不另建数据库。新环境默认有主 Mote；已有目录的 SOUL、头像、Wiki、资料和原工作面保留，目录缺失、读取失败或恢复状态未知需沿服务窗明确实际步骤，不把未知当成新环境覆盖用户内容或宣称原内容已经恢复。应用内删除主 Mote 目录、删除包含它的祖先，或通过移动/改路径/覆盖令该身份消失都不可执行；保护落在原唯一目录变更服务，精确地址及其合法别名同等受保护。标题改名、内部用户文件正常操作、头像更换/恢复默认、关闭主 Mote 的 Tab、收起浮窗仍合法；其他自定义 Mote 沿原管理行为，不因主身份保护锁住 Session/Run 或重建健康 Agent。控件与密度只见 surface-density[《Mote 头像与主 Mote》](../presentation/motes-and-coordination.md#mote-头像与主-mote)。

## Mote 归档与恢复

用户反馈：“现在好像没有合理的 archive mote 的机制”。自定义 Mote 可以明确归档、在原 Mote 管理面发现已归档对象并恢复；恢复的是同一个耐久目录身份，不是复制或重新创建。归档把它从常用 Mote 列表和新目标推荐中收起，原 Space 的 Motes 区始终有可发现的“显示已归档”与恢复路径。普通 Topic 不因这条需求获得归档行为，关 Tab、收起浮窗、删除目录与归档各有独立含义。

归档状态由原 Mote 目录 owner 持有；目录、头像、SOUL、Wiki、资料、固定/排序偏好与完整身份快照保留。已打开或明确选择的同一 Mote、Tab/Region、其他已有位置、执行历史、未发送草稿与健康 Session/Run 保持；当前归档对象仍可辨其状态、继续原工作面并恢复，不因它退出常用列表而判为丢失、自动切换目标、重新创建或停止 Agent。新选择不主动推荐已归档对象，已有明确目标及在途请求不被另一位 Mote 替换。

归档/恢复只有原对象的持久写入和读取确认后才表达成功；未确认时保原已确认状态与可用工作面。读取失败、状态未知、保存失败或迟到结果需说明实际步骤、当前已确认/未知事实与重试动作，不能把未知当未归档、把未知读取当恢复成功，或让旧请求覆盖后来已确认的状态。重新载入仍能读回归档事实、发现并恢复原对象；不另建身份名册、第二份归档选择或复制执行状态。

主 Mote 继续沿[《Mote 头像与主 Mote》](#mote-头像与主-mote)的固定默认身份存在。本次设计判断是主 Mote 不能被归档后隐去，以保留默认可达入口；这不是用户关于归档的原话，也不限制关闭其 Tab、收起浮窗、换头像、修改标题或正常内部文件操作。应用服务最终边界同样保护主身份，不能只隐藏菜单。控件语言、Space 最小宽度下的名称／归档状态与次要动作入口见 surface-density[《Mote 归档与恢复》](../presentation/motes-and-coordination.md#mote-归档与恢复)。

## 全局 Board 与固定 Leader Topic

用户确认：Board 不作为 Agents 的默认主视图。Board 是全局任务面，跨 Project、Workspace、Branch、Topic 可见；它承载任务卡、任务状态、目标项目和与 Agent 执行的关联，不再以当前 Workspace 的 Branch/Topic × Agent 状态矩阵作为产品模型。任务状态与 Agent/Attempt/Session 状态是不同事实，不能用同一个列或状态字段互相替代。

Agents 提供一个常驻 Mote 快捷入口，其全部对象选择与当前目标遵守[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)。默认对象保原 Leader Topic 的耐久内容身份，当前产品对象是主 Mote；其中 Session 是正常 AgentSession，必须通过 Core 公开能力运行，不建立隐藏 Runtime。它可以读取全局项目目录与 Board，不借背景当前 Scratch 选择替换已选协调上下文。

用户可以直接与默认 Session 讨论需求。Session 分析后可以在全局 Board 创建任务，并为任务标记应执行的 Project；创建结果、目标 Project、分析依据和关联 Session 必须在对话与任务卡上可追踪，不能把跨项目的创建变成不可见的副作用。无法确定目标 Project 时保留待确认状态，不猜测归属，也不阻断 Session 继续对话。

Board 的“New Demand”直接在窗口中央打开固定 Leader Topic 浮窗，并注入本次需求讨论的提示词，让 Leader Agent 开始和人澄清目标及项目归属。入口携带当前 Project 筛选上下文，不创建空白 Demand；后续 Demand 写入遵守既有确认策略。

入口只负责进入原 Mote 工作面，不代替 Board 的全局浏览入口。恢复状态未知时，入口仍保留并打开原恢复提示；不能因启动握手或读取快照失败清空全局 Board。当前对象、开合与定位唯一见[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)，视觉见密度 SSOT 同名节。

点击 Leader 头像后必须在同一个入口内呈现可见的 Leader Topic 工作面：头像打开的是已经准备好的固定 Topic 浮窗，浮窗必须有可见的 Workbench、Tab/Region 和可输入的 Composer；若 Topic 准备仍在进行，先显示全幅恢复/加载表面，准备完成后自动切换到内容，不能留下空白浮层或只更新隐藏状态。准备失败时保留浮窗并在其中显示服务窗式失败说明与重试动作。

点击 Leader 头像后必须在同一个入口内呈现可见的 Leader Topic 工作面：头像打开的是已经准备好的固定 Topic 浮窗，浮窗必须有可见的 Workbench、Tab/Region 和可输入的 Composer；若 Topic 准备仍在进行，先显示全幅恢复/加载表面，准备完成后自动切换到内容，不能留下空白浮层或只更新隐藏状态。准备失败时保留浮窗并在其中显示服务窗式失败说明与重试动作。

## Leader Topic 入口的浮动与收纳

“收起”只关闭当前 Mote 快捷面，不移除 footer 的常驻入口；不再切换浮动/紧凑入口形态。入口保持独立助手图标与命中区，不代替任何主工作面导航。临时悬停、明确固定、全部对象选择、邻近定位与重启恢复唯一遵守[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)。

入口属于全局 chrome，不依赖是否正在浏览 Board；切到 Workbench、Settings 或窄窗口仍可见、可键盘进入，不能因没有活动 Tab 或分屏而消失。通知栏、Agents roster 和入口不得各自复制未读事实，统一消费原注意力 owner。

## Leader Topic 入口头像

Leader Topic 的当前产品身份与字形沿[《Space、Folder 与 Topic》](spaces-and-layout.md#spacefolder-与-topic)及密度 SSOT[《控件语言》](../presentation/shared-rules.md#控件语言)，入口头像只表达持久 Mote 身份，不代替真实 Agent 状态。头像、快捷面与收起动作的可见联系统一归[《Mote 快捷入口与当前协调上下文》](../presentation/motes-and-coordination.md#mote-快捷入口与当前协调上下文)，不另留浮动态头像、三个点、自由位置或另一份开合状态；打开和收起不创建第二个 Topic 或 Session。

默认 Session 使用的宿主能力必须是通用的 CUI/JSON 协议：读取全局 Project 目录和 Board、搜索任务、创建/更新任务、绑定目标 Project、关联 Attempt/Session、读取事件增量。Provider 只提供 Agent 对话与生命周期，不把 Board 命令塞进某个 Provider 配置；协议失败属于流程状态，必须在入口或对话中说明并保留已有任务。

`agentmux` CLI 必须能让 Agent 查到当前所有已注册项目，以及各项目中的其他活跃 Agent；返回稳定 Project/Workspace/Session ID、路径、Provider/Executor 和真实状态。未打开 Tab 的活跃 Agent 仍可发现，未知或查询失败不能伪装成空列表。

## Leader Topic 与任务写入确认

项目调度 Agent 的持久协调对象是主 Mote，历史称为 Leader Topic。它持续承载全局项目目录、Board 需求、路由分析、用户确认和结果回执，保原耐久内容及固定 `launcher:leader` 身份；实际执行仍是正常 AgentSession，不把 Mote 当成普通知识库 Topic 或某次 Session。其文件系统真相和重启恢复继续由原 owner 持有，不进入普通 Topic 的默认成员，也不随着用户当前 Scratch Topic 改变。

Task 写入策略必须是用户可配置的开关，默认值为“按风险确认”。明确且低风险的单项目请求可以直接创建，并在对话和 Board 中产生可追踪的 Task receipt；涉及跨项目路由、目标不明确、不可逆或高影响动作时，先展示来源与依据、候选 Project、风险和待确认项，不能静默写入。用户也可以切换为“全部确认”或“默认直接创建”，设置的改变必须持久化并在入口可见。

每次用户确认、修改目标 Project、接受/拒绝风险判断或撤销 Task，都要作为该主 Mote 的结构化决策记录进入原全局知识库。记录至少包含原始请求、候选与最终 Project、风险判断、用户选择、Task/operationId、时间和来源 Session；不能把完整聊天转储冒充可检索知识。主 Mote 可以根据这些记录学习风险与路由建议，但学习只改变建议和默认排序，不能绕过用户当前设置、确认闸门或既有事实；当证据不足时仍显示“无法确定”，让用户决定。

该知识库的读取、写入、检索和增量订阅必须通过通用版本化 CUI/JSON 能力暴露给调度 Agent；Provider 不拥有知识库语义，也不能通过 Provider 配置暗中改变 Board 的写入规则。

## 默认 Session 的浮动工作面

默认 Session 和全部 Mote 的快捷打开形态统一遵守[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)：保留背后原工作面，不用跳转 Scratch 主路由冒充快捷面。内容是已选 Mote 的原 Tab、Region、Agent 身份、输出和 composer，只是附着投影，不创建第二个 Session、PTY 或聊天产品；Board、Focus 等入口明确打开准确目标时复用这一个快捷面，不另维护一份 Mote；一次跨上下文带入与后续独立选择只见[导航上下文合同](spaces-and-layout.md#worksurvey-与-mote-的导航上下文)。

固定开合与目标属于持久 UI 状态。重启先恢复原面与 Tab/Region，再尝试 reattach/resume；恢复握手、探测或渲染失败时保留入口和持久工作面，在服务窗说明失败步骤，不清空布局。

快捷面与主工作面分别拥有自己的导航焦点；面内新建、关闭、文件与快捷键必须按该 Mote 的明确身份与原空间关系执行。当前 Mote 工作面的可见性也必须进入现有终端泊车、内存预算与通知判定，不能一边显示一边回收。定位与开合统一遵守[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)，关闭只收起。旧的“跳到 Scratch 主路由”实现不能作为此行为的替代。

## Leader 对话浮窗的清晰度

Leader 浮窗默认以已有 Agent 对话模式打开，用户仍可切换终端；悬停与固定的模式优先级统一遵守[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)。外缘在复杂工作面上清晰可辨，选择区与内容是一体的紧凑表面，不保留独立身份标题行。固定 Mote 的原内容、Session、收纳和重启恢复保持同一事实。

## Leader Topic 的身份与职责

- `launcher:leader` 是 AgentMux 的协调者 Topic，不是普通 Project Agent 的替身。它的默认职责是理解需求、澄清缺口、提出 Project/Topic/Session 分配方案、记录 Demand 决策并跟踪进展。
- Leader 默认先对话后执行：没有用户明确确认和目标 Agent 分配时，不自行修改业务文件、不替用户完成编码任务、不把“帮我推进”默认为“自己直接实现”。它可以读取全局 Project、Tab、Region、Session 和 Agent 摘要，用于做出可检查的分配建议。
- Leader 的身份必须同时写入固定 Topic 的默认 Wiki 和启动时的 AgentMux context；用户消息、Runtime、权限、Session 与 Project 事实优先于 Wiki。普通 Topic 继续使用通用 Topic Wiki，不得误把 Leader 角色传播给其他 Topic。
- Leader 需要实际执行工作时，先把目标、承担者、Project、Session、风险和验收写成待确认方案；用户确认后再通过公开 Demand/CUI 能力分配或触发工作。确认前的工具调用只能用于观察、澄清和准备，不得产生不可逆业务写入。

## PMO teams topic 名称与职责

固定协调对象的产品类型与快捷入口统一称为 Mote，原 `PMO teams topic` / `PMO teams` 是历史名称；PMO 作为默认角色之一，约束见[《Space、Folder 与 Topic》](spaces-and-layout.md#spacefolder-与-topic)。现有协调职责是和人讨论需求、组织执行 Agent、分配工作并持续跟进结果；底层仍是同一个耐久内容对象，改名不创建新对象，不改变已存在的 Session、对话、文件目录和布局身份。Mote 保原 Space，普通 Topic 对应 Category 中的 Zone，两者不会因复用文件能力而合并归属。用户已明确授权的分配与推进直接执行，不重复索要确认；默认把项目实现交给执行 Agent，只有用户明确要求 PMO 亲自实现时才承担该项实现。普通 Topic 不继承 PMO 身份。

- PMO 快捷面的边界与焦点清楚，选择区与控件不挤压对话首屏。展开、收起和窗口重启继续复用同一份状态，不能生成第二个 Topic 或 Session。
- Board 左侧工具面板只展示持久化 Demand 的摘要、数量和明确空态。Demand 为零时不得把 `main` 或任意 Branch 名称当成需求行；Branch/Project 上下文只在真正需要展示归属时出现，不能冒充 Board 主实体。
- Board 工具顶栏只保留一组不重叠的工作面控制和 Board 身份。Project Rail 被 Board 遮挡时，不得用固定宽度的侧栏 chrome 挤压或覆盖 Board 图标；控件必须在窄宽度下仍保持可见、可点击和可读。
- Demand 有两条创建入口：用户直接在 PMO Teams Topic 对话时，PMO 先澄清需求并在确认后决定是否公开创建；用户点击 Board 的“新建”按钮时，界面先创建一条可见 Demand，再以该 Demand 的上下文打开同一个 PMO Teams Topic 浮窗。两条入口都不能创建第二个 Topic 或把 Demand 偷换成 Session。

## PMO Teams 快捷面与工作面外壳

Mote 选择、入口锚点、连续工作面与持久边界只见[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)。通用 Workbench 的 Tab/Region 能力复用原 owner，不保留重复身份标题、自由移动、最大化或独立位置状态；有界尺寸拖拽与记忆仅由同名 Mote 条目定义，不叠加窗口 chrome、空态装饰与另一份 Mote 标识。
