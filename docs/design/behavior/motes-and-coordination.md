# Mote 与 PMO 协调

本文定义 Mote 的持久身份、资料与合作方式，以及快捷工作面、主对话恢复和协调职责。Mote 以具有人格的团队承载长期合作，是自己的 Space，可绑定多处内容；内部实际做事的 Agent、一次 AgentSession／Run、展示位置及普通知识库 Topic 各有准确身份。伙伴的两条来源与 Topic 晋升需求见[《伙伴从哪里来》](companions-from-work.md)。Mote 是与 Work、Know 并列的独立导航入口，不属于 Know；普通 Topic 属于 Space 的 Topics 分区。导航分组只见[空间合同](spaces-and-layout.md#左下角导航space-与-goals)。本文要求不代签实现或安装验收。

## Mote 快捷入口与当前协调上下文

### 搭档界面与共享工作面

Mote 浮窗与 Space 交流面围绕同一位持久搭档组织：准确 Mote 身份、当前事情／讨论、原消息与输入、真实状态及下一步动作。每个 Mote 只有一个持续的逻辑主对话，当前承接 Agent 可更换；额外工作由 Threads 集中呈现为同源事件与工作 thread，具体合同见[主对话、工作 thread 与事件历史](#主对话工作-thread-与事件历史)。原 Tab／Region／Session 仍按 Core 空间关系保存，不能用对话呈现合并执行身份。

当前 Mote 身份已确认时，可见交流面持续呈现其原持久头像与名称；主对话读取、欢迎、当前与历史阅读、原 Run 已退出、主角色来源未确认及编辑／发送输入期间，身份不随正文分支消失，名册中的头像不能替代这处身份。已确认 Mote 的主角色或执行观察未知时，保留该 Mote 的原外观，分别说明受影响的 Agent、历史或输入事实；头像不代称当前执行者或恢复成功。头像读取与保存继续沿[原外观 owner](#mote-头像与主-mote)，身份本身未确认则保原引用和可辨的未知说明，不借另一位 Mote 补位。

Mote 日常交流以主对话及工作 thread 为主；进入原工作面后，直接复用公共 Zone／Tab／Region 组成与选择逻辑，每个真实 Tab Group 只显示一排原 Tab。日常进入沿本节的主 Agent 入口规则，明确打开原成员则保准确 Tab／Region 选择；保存的空选择不能让已有成员全部失去可达入口。确实没有成员且目录已确认时显示公共初始页。工作面选择不自行确立主 Agent，保存的精确未知引用仍按原恢复合同保留。

Mote 使用自己的交流呈现，复用原空间模型、内容 owner、共享 Conversation／Composer、输入投递和 Core 生命周期。复用这些能力不要求原样嵌入通用 IDE 外壳，也不授权另建讨论目录、会话日志、输入通路或执行状态。交流面上的事情选择映射原 Tab／Group／Region；完整工作面与文件、编辑、终端、分屏和原全部成员按需可达，原布局、草稿、阅读位置、健康 Run 和执行 cwd 保留。多 Region 中选取交流对象必须沿原准确选择，未知时保引用，不猜首个 Agent。

同一对象的服务状态在一个持续可见的呈现层组织。短说明指明受影响能力与当前可用／未知事实；详情保每个原失败步骤、准确目标、原受据和已有恢复动作。摘要只组织显示，不建立新的健康 owner、不改变 action admission；可收拢但未解决事实持续可发现，不因关闭详情、发出重试或后来的无关成功清除。原权限／问题与确实未应用的操作仍有贴近该动作的明确反馈，健康原生输入、其他讨论和可用内容保持。视觉、密度与一致语言唯一见[同主题呈现](../presentation/motes-and-coordination.md#mote-快捷入口与当前协调上下文)。

消息的原作者、来源范围、输入阶段与操作回执可按需收拢，但各自事实、准确引用、原文复制、Trace 和恢复动作仍由原 owner 完整提供；正在等待、未应用与送达未知不能因收拢而消失或被合并成成功。身份与证据层级调整不重建原 Conversation／Composer，不清草稿、阅读位置、选区或已展开的原记录，不改变 Session／Run、输入资格或成员访问。

常驻 Mote 按钮是稳定的功能锚点，使用固定品牌标识；当前已选 Mote 的名称、头像与真实状态在打开面和可访问描述中准确表达，入口的展开状态与 Working、Needs you 等真实 Session 状态分开表达。功能入口品牌不作为当前对象的头像存储，也不替换主 Mote 或自定义 Mote 已保存外观。各处“召唤 Mote”按触发处明确目标或原已选目标进入同一个快捷面，各导航上下文保自己的选择；键盘召唤在原快捷键入口可发现，其组合、应用内或系统级范围与冲突由宿主快捷键 owner 明确，不以 hover 或导航替代发送授权。入口与面内动作的视觉状态见呈现合同。

### Space 中的协作者名册

每个 Mote 团队在产品中称 Mote Club，承载其持久身份与逻辑主对话；全局伙伴名册称 Clubs。左下 Mote 快捷面与 Space 的 Motes 分区共用这一份名册。Space 中的名册支持协作者视图与常规列表，显示选择及名册头像尺寸由原 Settings/config owner 保存。缺省头像尺寸为 45px；同一个有界尺寸设置同时作用于协作者视图与常规列表，列表行随头像高度调整并保紧凑文字和对象动作。设置提供按实际尺寸显示的头像剪影预设，点击选择后仍可沿原滑块微调；两者编辑同一设置草稿，明确保存后生效。浮窗和名片的头像尺寸各沿原合同；缺省值调整不覆盖用户已保存的尺寸。协作者视图突出可辨头像和名字，列表适合紧凑扫描；两者消费同一文件事实、身份、搜索、固定/排序、当前选择和对象菜单，切换或调整尺寸不重建 Mote、Tab/Region、资料、未发送草稿或 Session/Run。未保存设置保持原已确认呈现；保存冲突或失败保选择草稿和原可用工作面。缺省选择协作者视图，读取不写回配置。

选择打开准确原 Mote，改名、头像、行为设定、新讨论、资料、固定与归档/恢复沿原对象动作。归档筛选用同一图标与已确认数量，保可访问名称、开关状态和原焦点恢复，不把归档或未知当执行终局，不影响主 Mote 保护。完整 Profile/Ideas/文件仍沿共享 Space 框架；浮窗保同一搭档交流面与准确原资料、完整工作面入口。

显示偏好作为 Desktop 的 `moteDirectoryView` 标量复用原 `settings inspect/set` JSON-RPC／CLI 与耐久 config owner，合法值为 `collaborators`、`list`；名册头像尺寸沿同一入口保存为有界数值显示偏好（代码名 `moteDirectoryAvatarSize`），公开设置的缺省值与此处一致，范围由该设置的公共合同定义。两项偏好不属于 Core 空间身份、执行事实或用户 SOUL，不新增 Mote 管理协议或运行时。

左下产品入口称为 Mote，按钮、快捷面和实际协调上下文保持一致，原 Mote 持久身份不变。用户应该在点击前后都知道入口会打开哪一段工作、现在是哪位 Agent 在处理，以及怎样进入同一完整工作面。

快捷入口保持贴近按钮、全部对象可达和原交流层级。快捷入口采用同一个可操作面：悬停临时呈现，明确交互固定；所有 Mote 与原工作面在这个面内可达，不再另叠一块只说明用途的 tooltip。

窗口内 Mote 对象位于左侧，在宽卡片与仅头像两态间明确切换，面板边界与背后工作面可辨。对象导航与事情导航分层，仍是原来的同一个可操作快捷面。

左下 Mote 面板与 Work 中 Mote 实体的导航边界只见[Work、Survey、Recall 与 Mote 的导航上下文](spaces-and-layout.md#worksurveyrecall-与-mote-的导航上下文)，本节继续定义原协调对象与快捷面的行为。Mote 与 Topic 的文件树使用同一公共能力；Mote 文件区固定浏览该 Mote 的原真实根，不提供展开整个共享目录的“Show all files”或面向普通知识 Topic 的收集入口，普通文件及知识能力从各自原场景可达，不借 Mote 顶部改变范围或把引用收集叫文件保存。

Space 二级菜单的内容按对象表达：知识库 Category 展开具体 Topic，Topic 显示自身讨论、知识与资料，Mote 呈现同一持久对象的自我设定、名片与点子，让用户理解这位搭档和怎样继续合作。知识层级只见[《Topics 知识库的层级与沉淀》](spaces-and-layout.md#topics-知识库的层级与沉淀)。自我设定与名片沿原名称、头像、SOUL 等事实，点子沿已有持久笔记与资料能力，不另造人格、Memory 引擎、记忆存储或强制资料分类。菜单文案与具体分组数量不由本条规定；框架与共同工作面只见[《Space 的统一工作面框架》](spaces-and-layout.md#space-的统一工作面框架)。

Mote 主选择器只列 Mote，跨对象浏览仍由 Space 中分开的 Motes 与 Topics 分区承担。同一 Mote 可以有多个自己的 Tab/Group，这些事情标签不表示多个 Topic；Mote 与 Zone 不合并身份，也不改变既有实体多处展示绑定。共用文件树不改变原文件资源归属，导航分类与物理存储仍是不同事实；目录分离与已授权迁移统一遵守[《Topic 与 Mote 的物理目录》](#topic-与-mote-的物理目录)。

Mote 在 Space 中的日常入口默认显露主 Agent 的原交流工作面；明确打开 Profile 时，搭档主页在共同内容工作面取得完整阅读面积。Profile、Ideas、Calendar 和原成员工作面之间的明确导航保其原位置与输入，不创建替代 Session、不改原持久布局。主页和快捷名片复用同一内容组件，连接偏好、原记忆、点子和日历仍各由原业务 owner 持有；近期安排摘要消费同一范围查询与原记录，隐藏主页暂停自动观察。明确新建讨论仍进入原 Launcher 草稿，与交给主 Agent 或继续已有成员讨论的动作明确区分。Profile／Ideas 返回保各自阅读位置及原选中内容。Ideas 承载原笔记与点子；原 SOUL／自我设定直接呈现在 Profile，沿明确文件编辑动作进入右侧原 Editor，不另设 Persona 切换。对象内容仍在共同框架内，保同一原 Zone 工作面与公共文件能力，不另造 Zone 导航、文件树、Editor 或 Tab/Region 管理；切换与原工作面的保护统一遵守前述 Space 框架，普通 Topic 保持自己的内容。 名片首屏以准确身份、已保存的合作方式和当前事项为主；已保存简介沿 `topic.md` 的原摘要呈现，长文可按需展开，准确来源与原 Editor 更正入口可达，与原 `SOUL.md` 分开辨认。展示调整不按文案猜测哪些内容是默认模板，也不删除已保存摘要；没有事项或点子时保原创建／查看动作，读取尚未确认或失败时仍保可读说明与原恢复动作。

**对象范围与成员完整隔离。** 从树、快捷面、恢复、来源 Session 或公开导航打开 Mote，都建立同一准确 Mote 与其原 Zone/Tab/Region 展示引用。其工作面只枚举原空间关系明确关联的成员，不因共用 Scratch、旧 `topicId`、cwd、标题或相邻 Tab 把其他 Topic／未绑定 Topic 的 Tab 纳入；经原关系明确绑定的外来 Zone、Tab 与合法跨 Workspace 展示继续可达，隔离不是删除共享内容。该对象内切 Group/Tab/Region、编辑文件、输入或新建工作面保持 Mote 范围，局部落焦不能清掉对象选择后跳回 Topics。只有明确的跨对象导航才切换对象；外来文件的资源归属不自行改写当前 Mote 的选择。成员或位置未知时保原引用、已确认成员和当前工作，给出持续恢复说明，不退回整份 Scratch、猜邻居或自动创建替代 Session。未绑定 Topic 的原 Zone/Tab 仍在明确的全局入口可找到。名片、文件动作和讨论导航使用同一范围，进程重启先恢复该对象与工作面，健康 Run、草稿、布局及执行 cwd 保留。

Mote 浮窗是原交流工作面的快捷入口，文件与编辑等完整工具能力在同一 Space 内继续可达；浮窗的身份与事情区可用一个 Profile 动作按需开关同一名片，复用原自我设定、快捷配置、事项和点子动作，默认保交流工作面。名片开合与窄面切换保原工作台、对话输入、草稿、准确展示引用与 Session；关闭或隐藏的名片不新增资料读取，不另建文件树或 Editor。进入完整 Space 的 `Open in Space` 动作与当前准确对象和讨论相邻；空 Mote 沿原空态顶部保留同一动作，不为了提供入口新建 Tab 或 Session。导航沿当前已选 Mote 与已确认的完整 Tab／Group／Region 引用接手原工作，保原草稿、模式与健康 Session／Run；位置未确认时仍按本节原目标保护与恢复说明处理，不猜另一个位置，也不关闭可用正文。此分工不取消 Space 的原文件、编辑、人格和资料能力。空 Mote 的文件或目录终端动作由用户在已确认的同一 Space 明确发起，沿它当前实际呈现的活动 Pane 放置；先核原资源、Space 绑定和可见 Group，不借背景项目或未知保存地址，不先造讨论。

Goal 巡查明确指定原 Supervisor 对话时，可复用这个左下交流浮窗呈现准确原 Agent；单项／全局的到达、输入与恢复边界唯一见[巡查合同](goal-execution-and-supervision.md#执行责任停滞告警与-pmo-巡查)及[全局巡查](goal-execution-and-supervision.md#全局巡查)。复用浮窗不把普通 Agent 纳入 Mote 名册或改变原成员归属，不以主 Mote 身份冒称外来的实际执行者；原 Mote 对象导航与准确 Agent 目标分别保留。

- **名片和自我设定能操作原对象。** 用户能查看已确认的名称、头像、真实摘要与原 SOUL；名片头像本身是该名片唯一更换头像的入口，姓名旁的改名动作沿原耐久名称 owner，不新增外观或改名机制。编辑绑定打开时的明确原 Mote 和所属 Workspace；资源重绑不自动更换原目标或清空未保存草稿，错误保存由原资源 owner 明确拒绝，不借邻居作目标。关闭编辑面只在原触发控件仍可用、当前仍属同一资源且没有后来外部焦点时返回它。自我设定按前述 Profile 首屏分工呈现，不重复提供功能组跳转链接；未确认的摘要不以模板介绍代替。合作方式与知识检查沿原内容 owner 按需进入，保存、生效、冲突和未确认继续由该 owner 负责，不借此改写运行中的 Session。头像编辑与改名的保存／取消／失败保全分别遵守本专题原头像与耐久名称合同，真实运行状态、SOUL、笔记和原工作面保持。
- **点子能查看、编辑和继续。** 点子沿当前 Mote 的持久笔记与资料查看，用户可明确通过原文件／笔记动作创建或编辑，打开已有来源讨论与成果，再沿原讨论动作继续交流。Profile 只展示有限若干原笔记标题，近期顺序沿原文件系统已确认的修改时间；时间缺失或读取未确认时如实说明，不用列表顺序、刷新计数或当前时间伪造近期。点击标题切到 Ideas 并定位同一准确原笔记，不借邻居 Mote、重读整份目录正文或维护另一份笔记缓存。条目引用原内容与已记录的来源，不复制正文、聊天或进度；来源和范围未记录时如实说明，不从邻居 Session 推断。没有笔记时保原文件访问和明确创建入口；读取失败保原引用、草稿与服务窗。点子列表和所选正文沿同一准确原 Mote Zone 和 Files 资源读取；共享 Workspace 的其他目录选择或在途文件请求不改变这份读取的资源。完整目录确认后才显示空列表。知识组织仍自主，不强制固定点子文件、资料分类、Memory 引擎或新的 Goal／Task 账本。

Mote 的交流面支持与多位搭档合作；同一 Mote 的多个原执行会话归属于一个主对话及其工作 thread，未建立准确关联的原工作面仍可独立进入。Mote 浮窗与 Space 中打开的 Mote 工作面遵守同一对象与会话层级：多个 Mote 是持久对象选择，所选 Mote 下的多个 Session 与承载事情的 Tab/Group、实际 Region 各有准确归属，不能把会话数量画成 Mote 数量或把普通 Topic 默认变成该 Mote 的成员。Mote 工作面围绕交流与原正文输入呈现，在前述共同 Space 框架内继续复用原 Zone/Tab/Region、文件与 Core 生命周期；普通 Topic 保持自己的知识内容。交流参考用于对象、事情、消息与输入的层级；呈现导航映射原 Tab／Group／Region，不生成第二套空间、Session 或讨论事实。进入、切换和往返保原 Tab、Region、健康 Session/Run、非空草稿、执行历史与恢复，不复制聊天或重启 Agent。文件访问沿同一公共文件树与明确资源目标，原 Mote 的耐久资料及全局浏览仍可达；知识组织由 Mote 自主，不强制分类或搬目录。身份通过对象导航及一个清楚的搭档身份区持续可读，当前事情和实际执行者分别表达；完整工作面与模式能力沿原 owner 可达，不叠加重复操作或另存模式。具体视觉稿与真实正常/窄窗/失败场景须独立评审，不能只以复用组件或采图成功冒称达到该交流体验。

日常主对话与工作 thread 的导航按下述逻辑对话合同组织；原工作面中的讨论导航仍准确映射原 Tab，其内部可以有多个真实 Region／Session。新建执行工作面不自动成为第二条主对话，也不因改文案获得事件关联。发言显示准确作者：主对话关联 owner 已准确确认的主角色来源可以使用该 Mote 的持久名称与同一头像，仍保原 Session 作者与来源；其他实际 Session 只有 Host、运行目录与原 Mote 耐久身份明确相符时才这样呈现。同处当前工作面、同名标题或表面关联不构成归属，外来或未知作者保原真实身份。正文、历史、输入与操作继续由原内容 owner 承担，不复制另一份聊天记录；原消息与讨论导航在宽窄工作面中的可读性唯一见 surface-density 同名章节。资料读取慢或迟到时仍保原文件 owner 的结果，但不因返回时又选中同一 Mote 就抢回旧选择；同一 Mote 下较晚选择的讨论／Region、A→B→A 往返后的新意图、后来输入与焦点始终优先，失效请求不重新选择旧文件、讨论或工作面，也不收起后来打开的资料栏。

名称和常用对象动作在原对象入口可发现。Mote 的改名与常用对象动作在原名册／Space 对象菜单中可发现，鼠标与键盘均可达；改的是同一耐久 Mote 的语义名称，不是某一个 Session 的显示名，不改目录身份、SOUL、头像、已有 Tab/Region、执行绑定或健康 Run。保存／取消／失败及迟到结果保原对象与草稿，浮窗即使在 Settings、Focus 等背景上也绑定原 Mote 和所属 Workspace，不能借当前背景项目误投。头像、人格、资料／完整 Space、pin 与归档／恢复沿已有能力和主身份保护组织，常用动作足够合理且主次可读；对象管理与当前 Session 的关闭、分屏、输入附件、模式动作分别指向真实原目标，不把菜单扩充变成新增执行能力。系统层级与弹层命中只沿[《浮层让位与输入层级》](browser-workface.md#浮层让位与输入层级)。

尚未启动 Agent／睡眠的 Mote 工作面也围绕当前 Mote 自身：原启动面标题显示已确认的这个 Mote 名称，不把 Topics/Scratch 收纳容器当作当前对象。对象名称与实际运行环境分开，Host、工作目录和启动参数仍是原资源事实；名称尚未确认时保原工作面并如实说明，不借默认或邻居 Mote。普通 Topic、Folder 与空 Group 沿原环境身份。此要求不合并 Mote、Zone、Tab 或 Session，不改变多处展示绑定或物理目录。

- **面板内同一个当前目标**。左下入口的无障碍描述、快捷面选择与当前状态都指向该面板已选的同一个 Mote、实际 Tab 与当前 Region；「Open in Space」明确将这个准确目标一次带入 Work，此后两边各自保留选择，沿前述导航上下文合同。Mote 表达持久协调对象，Tab 名表达当前事情，Provider/Executor 和 Session 表达实际执行者，不能相互冒充。Goal 的专属讨论仍是自己的 Tab，入口必须能读出该 Goal 的上下文，不能只用泛称 Mote 掩盖正在打开另一件事。自定义 Mote 的投影、准备与完整 Space 都指向它自身的持久对象与准确原空间关系，不借默认 Mote 的工作面。
- **可进入的悬停面**。鼠标悬停入口即显示原可操作面，允许越过按钮与面板间的小间隙进入、滚动、选择和输入；未固定时离开两者后自然收起。悬停本身不改变 DOM 焦点、光标或组字，不选择另一个 Mote/Tab/Region，不持久化打开状态、不写视图模式、不启动 Session/Run、不发送或入队输入。键盘与触控有等效的明确打开入口；Escape 收起预览，不抢走输入法或另一块已打开浮层拥有的按键，也不把未移动过的焦点拉回入口。
- **不同工作面同样可操作**。Settings、Space、Focus、Goals、Survey 等窗口内容切换不改变同一个 Mote 快捷面的可进入性；面板及原投影不能继承被设置遮住的背景工作面的 inert/隐藏归属。移入、明确固定、选择与输入仍沿原 owner，悬停不关闭设置、不移动原焦点、不写 Agent 模式；被设置遮住的背景继续不接收输入，健康 Run 和原 Tab/Region/草稿保留。
- **全部 Mote 可选**。快捷面呈现既有默认 Mote 和文件系统已确认含 SOUL 的全部 Mote 对象，每个对象有紧凑可选行、可读身份与它实际目标的状态；多个 Tab 或 Session 不冒充多个 Mote，普通 Topic 不混入名册。超出可用空间时仍能滚动到全部对象，不只取默认或当前一个。目录、快捷选择与焦点分类共享同一份文件快照事实及修订边界，不新增 Mote id 名册、不在 Tab/Session 上复制身份布尔，也不把分类另行持久化；目录读取失败保留已有事实与已选原引用，说明未知和失败步骤。 冷读也按独立事实处理：原目录 owner 已确认的完整身份、实际地址及 Mote 类型不依赖协作者牌、介绍正文或 Wiki 同时读成功；局部失败随原对象说明，不能把已确认 Mote 从名册拿走。身份或类型证据本身未确认时保未知，不凭所在目录、名称或邻居推断。原 list/read 与共同文件快照承载这些事实，不另设持久名册。
- **Mote 与 Tab 分层**。全部对象沿快捷面左侧导航排列，右侧以搭档身份、当前讨论、原正文与输入呈现所选 Mote，讨论和完整工作面仍映射原 Tab／Group／Region；不再把对象列表叠在 Tab 上方。明确且可访问的开关在宽卡片与仅头像两种呈现间切换，初始为宽态；两态都有同一组对象、同一精确选中与真实状态，完整名称和状态在头像态通过 hover、键盘焦点及无障碍描述可读。对象多时左侧有界纵向滚动，收起与呈现切换清楚组织，进入完整 Space 与准确对象／讨论相邻；搭档身份区表达当前对象，不叠加重复操作入口。 宽态按原消息次序读取准确原主对话最近一条已确认的可见消息，预览正文并可显示该条记录的原 `recordedAt`。缺少可信记录时间时保留正文预览。当前被读的其他成员、未送出的草稿、工具过程和状态变化不作为消息。只在可见名册行上有界观察原来源，未知和已确认无记录分别表达，旧预览只能保留在同一原会话上。Needs you 只在同一 Host 上唯一匹配的原主 Session 具有已观测的活跃 Run，且原 Session 的注意状态确认为待人处理时出现。原消息和注意状态更新时维持既有目录顺序。会话项沿原主对话入口，头像沿准确 Mote 的同一 Profile 入口。悬停与聚焦可发现头像动作，明确激活后才打开 Profile。查看与关闭保持当前对话、背景导航和草稿。仅头像态也保留可分别执行的会话和资料动作。
- **导航呈现偏好独立**。宽卡片/仅头像只是快捷面的单一呈现偏好，由原浮层 UI owner 保存，关开与普通 UI 状态恢复后保持；窄窗可收紧宽态名称空间，不能静默替用户改成头像态或让开关语义与实际呈现不一致。从临时面操作开关仍沿既有明确交互固定语义；切换自身不选择别的 Mote/Topic/Tab/Region，不改原 Agent 模式、执行焦点与历史、草稿、消息队列或 Run，不重建右侧原输入和工作面，不增加逐 Mote 偏好账本或另一份目录事实。
- **范围内拖拽尺寸并记忆**。Mote 浮窗支持在有界范围内拖拽改变大小，并记住尺寸。临时与固定面仍贴原左下入口锚点和小间距，允许从可辨的边缘／角部拖拽改变宽高，保持入口与面板的联系，不成为自由移动窗口。两种左栏呈现都支持，尺寸偏好由同一个原 floating UI owner 保存，关开和普通 Renderer 重载后读回，不另存逐 Mote 尺寸账本，也不改变所选目标、原 Tab/Region、草稿、输入模式或 Session/Run。可用下限让当前卡片／头像导航、必要动作与右侧原正文输入仍可操作；上限由当前 viewport 的实际可用空间决定，收窄或变矮时重新夹紧，视口小于通常下限时仍以当前可见可操作空间为界，不能把浮窗或动作挤到屏幕外。暂时收窄只改变有效尺寸，不改写用户偏好的大尺寸。拖拽越过边界仍能完成或取消，pointercancel、Escape 和失焦（blur）终止均取消未提交手势并回到拖拽前尺寸；结束、取消和关闭后不留下指针捕获、resize cursor 或阻碍输入的遮挡。拖拽中的几何更新由同一窗口定位 owner 合并到实际呈现帧，松手立即呈现最终尺寸，不以隐藏整块浮窗或重新读取对话等待刷新；尺寸观察不形成重复定位反馈。首次未调整时沿当前默认尺寸，偏好读写失败保留可用浮窗和原工作并说明未保存或未知。
- **明确重新打开先显示对话，面内操作延续所见面**。每次明确打开准确 Mote（点击入口，或从既有的显式上下文入口进入），当前实际 Agent 的原工作面先显示对话视图（代码名 `activity` 模式）；先悬停再点击仍算明确打开。打开后用户可以手动切到终端，此后：
  - 对同一已打开目标的重复打开请求不重置用户后来的选择；明确转到另一准确目标算新的打开，同样先显示对话。
  - 单纯悬停不写模式。在可见面内选择 Mote／Tab／Region、聚焦、操作或自然固定，都延续同一所见正文与草稿，不翻转模式；尺寸调整和左栏呈现切换同样不重置。
  - 重新载入已固定的面不算新的人类打开，按原保存的模式恢复。

  这次模式请求只由当前已确认存在的目标 Agent 承担，不改邻居或其他 Session 的模式；没有真实 Agent、处于空态或恢复未知时，保留原引用与现有告示，不猜替代目标，也不启动。模式事实只由原 Session 持有一份，该 Session 的其他显示位置消费同一模式；不另存 Mote 级或逐投影的模式，也不复制原 Runtime。明确打开和面内操作沿原固定语义：鼠标离开后仍可继续输入，已固定的面再次经过按钮时不生成第二块面，也不抢焦点。临时面与固定面都贴同一入口锚点并适配视口，不提供自由移动、最大化或独立位置记忆；有界尺寸拖拽见上一条。原准确目标、Tab／Region／Session／Run、草稿与队列、执行历史和背后的导航选择都保持不变。
- **目标状态来自目标本身**。入口及各 Mote 行表达各自实际目标 Region 所引用 Agent 的真实状态，不把邻居 Session 的 Working、Needs you 或错误当作当前目标状态。已保存目标尚在恢复、尚无 Agent、当前 Region 是其他工作面以及状态未知分别按事实说明；读不到状态不能猜空闲或错误，也不因无关 Session 更新改变当前反馈。收起态只消费当前目标，展开后只增加所示 Mote 与原工作面需要的 Session、名称和事实消费者；目录读取只随所属修订更新，不订阅整份 Timeline 或逐 Session 反复扫描全部 Tab，不让无关 Run 输出放大入口工作。成本底线继续归[《Terminal 连续向上阅读历史》](terminal-reading.md#terminal-连续向上阅读历史)。
- **协调焦点不污染执行历史**。默认和文件事实确认的自定义 Mote，其协调 Session 都使用既有独立协调焦点；选择 Region/Session、切模式、明确输入与初始化恢复遵守同一语义归属，不能只在浮窗补一个特判后仍把自定义 Mote 的协调 Session 写入执行 Agent 的历史。Mote 在 Space 中的导航选择可更新 Work 的准确对象／位置引用，不反向改写面板目标，也不把协调 Session 重新分类为执行 Agent。已知普通 Topic 和执行 Agent 继续沿原执行焦点。Scratch 身份暂时未知时保留原 lane、选择与历史，给出旁边的服务窗；不猜成普通执行对象，也不等待目录检查完成才允许运行。
- **开合保留上下文**。关闭只收起快捷面，保留各原 Tab／Region、SessionId、Launcher 草稿与输入；再次日常打开按下条主 Agent 规则选择入口，不销毁上次成员工作。已固定开合与原位置沿 UI owner 持久化，普通 UI 重载或进程恢复继续原选择，不冒充一次新的人类打开；临时悬停不在重启后伪装成用户固定。显式 Goal／Focus、来源或成员入口仍按跨上下文合同选择精确目标，面内手动选择只更新该面。背景工作面切换、Session 列表顺序、迟到读取或恢复事实不擅自更换已选目标。打开完整 Space 是进入当前准确目标的一次 Work 导航；收起后背景保持后来选择，不覆盖新输入、不停止 Run、不新建 Session，也不改写执行 Agent 的独立焦点与历史；只有明确 Send／Queue／Launch 沿原输入 owner 消费原文字。
- **日常回到主 Agent，手动位置继续保留**。无明确成员目标地打开快捷面、从对象名册进入 Mote 或切换到另一个 Mote 时，默认进入该 Mote 已确认的主 Agent 原对话，不以最近访问的成员替换它；主 Agent 的职责与确立见[主 Agent 与内部工作](#主-agent-与内部工作)。显式 Goal／Focus、来源、讨论或成员导航仍优先，面内手动切换后保持其准确 Host、Session、Tab、Region、展示位置和草稿；同一已打开目标的重复请求、后台更新与迟到事实不抢回主对话。最近访问仍是 client 导航偏好，可用于明确继续原工作，不成为主 Agent 绑定或默认入口。主 Agent 引用或位置未知时保原引用与恢复说明，其他已确认成员仍可明确打开，不任取首个或最近 Agent 冒充主 Agent。确实未配置主 Agent 与原引用恢复未知分开表达；只有目录和成员均确认且确实没有原 Tab 时才呈现新建引导。明确关闭只消费原关闭事实，多处合法位置、其他工作面及原 Session／Run 继续保留。
- **关闭 Tab 按明确意图继续**。收起快捷面与关闭其中的 Tab 是不同意图；明确关闭 Tab 后，不能继续显示“原 Tab 仍保留”的恢复说明并要求用户回 Space 恢复：经既有确认已实际删除当前 Tab 后，同一 Mote 有其他原 Tab 就继续其原工作面，没有剩余 Tab 就保留该 Mote 的可操作空态，允许用户明确新建；入口、正文、状态与完整 Space 指向同一结果。关闭后沿原 Group 已提交的剩余选择继续，剩一张与多张同样成立；仍有该 Mote 的原 Tab 时完整保留公共 Tab 导航，不能把没有当前选择、保存的空选择或位置未确认当成零 Tab 而隐藏全部成员。保存的空选择只说明当时没有当前讨论，后来已有 Tab 时恢复原讨论导航。确实零 Tab 且目录和成员已确认时才显示新建引导；目录或成员未知仍保原引用与服务窗，不冒称空对象。取消或失败而仍保留原 Tab 时保留原目标；只移除一处位置而 Tab 仍有其他合法位置时保留原对象，不冒称实体或 Session/Run 终局。已关闭事实与后置清理失败分别表达，原错误告示保留，不能继续引用已删除 Tab。不借其他 Mote，也不为清理失效目标停止 Session/Run、悄悄新建或重开已关闭 Tab；空态打开完整 Space 仍展示同一 Mote 的空态，新建只由用户明确 New Tab/+ 消费。已确认存在的选中 Mote 没有任何原 Tab 且成员事实已确认时，统一呈现此可操作空态；切到其他 Mote 再回来仍为空，目录确认不自动补 launcher，不另存逐 Mote 的关闭历史。保存的精确未知 Tab 引用不因没有已放置 Tab 被清成空态。仅因原目标暂未恢复、位置未知、恢复超时或读取失败时，仍按“恢复未知仍有原目标”保留原引用；明确关闭的结果和空态跨普通重启保持。
- **恢复未知仍有原目标**。目标 Tab/Region 或 Session 暂未恢复时，保留原引用与工作面投影，原草稿不交给其他 Agent；在同一快捷面说明等待或失败步骤、当前可用或未知事实及已有恢复动作。不能跳到另一个可用 Agent 来伪装恢复成功，不能为流程失败清空原目标或停止健康 Run。跨真实进程重启仍先恢复工作面与本入口的已选目标，再沿既有公开能力尝试 reattach/resume。
- **恢复说明旁仍能继续原工作**。浮窗正文不能只剩一条“原 Tab 位置不可用、请回 Space”的说明。身份已确认的 Mote 在浮窗与 Space 都通过共同框架呈现同一交流体验，自己的原讨论、实际 Region／Session 与资料入口仍可辨，不另造第二套页面。保存的精确 Tab／Region 暂未恢复或当前位置未确认时，保原引用与可行动的服务窗；说明不能拿走整个讨论导航和正文操作面，同一 Mote 已确认的其他原讨论仍可枚举并由用户明确选择。恢复动作指向准确原对象，不能仅让用户凭技术字符串猜去哪里操作；已确认原目标可恢复时继续其原正文，暂不可确认则如实说明。快照、Tabs 或当前 Group 中缺席不等于明确删除、retired 或 unknown 终局，不从另一个 Topic 的 active Group、别的 Mote 或第一个健康 Agent 猜恢复；实际明确关闭仍只按前述关闭合同处理。原草稿、布局、Session／Run 与后来选择保留，不为修空白自动新建、重开已关闭 Tab 或停止健康执行。
- **投影只承担自己的上下文**。窗口工作面 owner 绘制全局导航 chrome；快捷面等 workbench projection 保留准确 Tab／Region 引用、原操作与自己的交流呈现，不复制背后 Goals、Focus 或其他主工作面的全局标题。快捷面内和背后的 Browser 都保持原内容与可操作区域。没有真实显示 bounds 变化时，悬停不触发 Terminal fit/Runtime resize；所选 Mote 的原 View 真正转入快捷面时，相关显示尺寸可由原 fit/Runtime owner 适配，收起仍恢复原 Tab/Region、阅读与工作面。背景、无关 Terminal 和隐藏 slot 不因浮层开合产生尺寸写入或工作放大。原生层级与尺寸统一沿[《原生 Browser 与浮层的交叠、对位和点击》](browser-workface.md#原生-browser-与浮层的交叠对位和点击)及[《Hover 提示不改变 Terminal 几何》](terminal-reading.md#hover-提示不改变-terminal-几何)，只依赖通用 overlay 与实际 Region 事实，不为 Mote 或具体站点写特例。

按钮展开、左侧对象导航两态、状态、动作与窗口外缘的视觉分工唯一见 surface-density[《Mote 快捷入口与当前协调上下文》](../presentation/motes-and-coordination.md#mote-快捷入口与当前协调上下文)。跨 Mote 选择复用既有对象目录、Tab、Region、焦点、命名与状态 owner，不增加默认 Tab 或逐 Mote 记忆注册表、第二份消息投递通路或 Runtime/Session 生命周期。

## Mote 的日常合作

空白安装的默认 Mote 无需先填写人格、合作偏好或知识库即可从用户当下的真实问题开始。默认合作方式先给有用的回应或可检查的小步，只询问会改变下一步的缺失信息，不以认识用户为由先做问卷。专业判断按本次任务和实际能力展开，名称或维护者的私人角色不成为新用户预设。偏好、决定和纠正在正常合作中沿原文件按来源与范围积累；空 MEMORY 只说明该索引尚未记录，不代表原目录没有其他知识。默认可用性与真实 Agent CLI、供应商认证各自可辨，不把模板或配置存在称作模型已可工作。

Mote 提供可理解、可纠正、接得上工作的长期合作体验。合作方式、记忆检查、安排、点子和成果在原 Space 对象内容及原对话里可达；浮窗仍只作同一交流工作面的快捷入口。它们消费原文件、目标、Session 与调度事实，不产生第二份文件树、记忆数据库、任务账本或 Runtime。外部连接器采用通用连接结构；设置启用后，每个 Mote 内 Agent 的创建／绑定群入口及原 Session 关系沿[共同对话协议与外部交流入口](conversation-mode.md#共同对话协议与外部交流入口)。外部应用、准确受众与每次操作仍需实际授权，不因 Mote 身份授予账户工具或远程权限。

### 主对话、工作 thread 与事件历史

Mote 在内置群里的工作视角从 Threads 的「群聊」入口进入，沿[内置群聊与 Mote 群内视角](#内置群聊与-mote-群内视角)关联同一个群与该 Mote 的群内 Thread Agent。

Promotion 与成员导航中的 Mote Thread 表达一个 Club 内准确 Agent 的对话与长期工作承载，沿原 Session、来源和可恢复工作面关联；它不是团队人格或逻辑 Main。原 Dispatch 的消息 thread 与事情 event 继续表达各自派工通信，同一 Agent 可参与多个原工作 thread，不能用 Agent SID 替换它们。导航和成员读取不创建会话；用户明确提交晋升或其他流转时，沿原 Takeover 建立独立新 Agent，保留原 Session、位置和工作来源。晋升、两级建 Club 与转岗的动作合同见[伙伴从哪里来](companions-from-work.md#club-与-thread-的晋升层级)。

浮窗和完整 Space 的“工作／私聊／成员”在顶栏直接可选，沿同一个内容选择与原来源切换，不要求先找 Threads 图标；主对话始终直接可回。三个入口的数量只来自各自原 owner：工作按已关联 event 身份去重，私聊按原 conversation generation 去重，成员按准确 Host／Session 去重。仅已载入的范围不能冒称完整总数，分页、尚未读取、读取失败及未知身份分别可辨；数字不暗示未读、待答或任务完成。切换不创建、恢复、发送或改投输入。

主对话提供一处紧凑的工作快跳入口，展开后直接定位同一 Mote 的准确原工作事件。正在工作依据关联执行者的 Core 语义事实，不能从进程存在、派工尚无回报、标题或历史问题推定；同一执行者关联多个历史事件时，分别保留原事件，并明确表达“关联 Agent 正在工作”，不能宣称每项历史任务正在执行。主角色轮转不抹去原关联工作；读取缺口保持未知，快跳保留原正文、选区、阅读位置、输入草稿和返回主对话的入口。

Mote 对象链接使用原持久 Space 身份，主链接打开唯一逻辑主对话，工作引用打开同一 Mote 的原事件 thread；准确编码只见[对象链接格式](../../specs/amux-protocol.md#对象链接)。主 Agent 轮转不改变 Mote 链接，thread 不以一个 Agent SID 充当身份。打开沿同一 Mote 导航与原事件读取，不建立替代 Session 或复制聊天；未知成员、来源或位置保留原引用与可恢复说明，不按名称、cwd 或首候选补位。链接可达范围沿原服务的空间发现，不宣称跨设备全局寻址。

浮窗与完整 Space 的交流面提供同源的当前对话切换入口。用户在当前成员工作中可直接选择另一原成员，不必先退回 Threads 列表；主对话有直接返回动作。主对话入口明确表达逻辑 Main 意图，成员入口明确表达原成员意图，两者不能因为此刻指向同一 Session 就混用；后来角色变化不改写原选择。切换只导航准确原位置，不发送、创建、停止或重放输入，双方草稿、阅读位置与原 Reader／Composer 保留。多个原位置由用户明确选择，查找无结果与成员来源未确认分别表达，读取失败不拿走已确认工作。完整工作区仍沿同一原位置可达。

Mote 的持久身份与任务一致性是底层运行原则。主对话稳定键复用原 Mote ID；当前主角色与版本沿原 `MOTE.md` 和 Files CAS 保存，事件关联只持有原来源引用，由 Core 的公共关联 owner 统一读写。一个 Mote 同时只有一个逻辑主对话，用户始终是在与同一位 Mote 合作；当前承接它的主 Agent 是准确、可更换的执行角色，不是 Mote 人格或逻辑对话本身。主角色切换保留已确认目标、范围、约束、决定、未完成承诺及原输入、授权和成果来源。主对话的原记录保各自作者、Host／Session／Run 和记录引用，跨 Agent 连续阅读不改写 Provider 历史，不将新 Session 冒称原 Session 的恢复。

Discussion 只呈现唯一逻辑主对话：当前及曾承接主角色的原对话来源连续可读，成员对话和运行事件不另插入正文。Threads 集中呈现额外 Agent 承接的工作、原事件与其 thread；主 Agent 的回复可引用同一工作事件。Mote 派出成员处理的工作各有自己的 thread。事件关联原派工／创建操作、主对话的准确来源位置、承接成员与后续结果；同一工作可以有多个原执行来源，不能以成员数量当事件数量。Threads 中的工作列表、展开的 thread 和按时间浏览的事件历史共用同一事件身份与原来源，只投影需要判断的进度、成果和决定，不另存一份聊天日志、任务状态或人工维护的历史账本。没有准确来源位置、时间或归属时说明缺口，不从相邻消息、标题、cwd 或刷新时刻拼出关联；未关联的旧工作面保其原入口，不能伪装成已归档事件。

主对话可在正文末尾提供相关工作 Threads 的紧凑折叠入口，展开与独立 Threads 使用同一原工作事件及派工回复；关联仅取原工作 owner 确认的主对话 Host／Session，不按消息时间、标题或相邻位置推造消息级锚点。缺少准确关联的工作仍从独立 Threads／原成员入口进入。Threads 按已读取的工作标题和执行者查找，并按原派工问题记录、执行者回报和读取未确认事实筛选；不将已回报称为已验收，也不将存在历史问题称为当前待答。当前读取范围和更早未载入范围可辨，查询、折叠和往返不改变主／成员输入对象。

Threads 同时提供该 Mote 原外部私聊的直接阅读入口，工作、私聊与成员按来源区分。原外部私聊按准确人及原 conversation generation 发现，选择整行即沿原 Host／Session 的公共 Conversation reader 读取原输入与回复，并保留原输入回执和工作面入口；不能只有接收输入列表或要求先进入 Profile 配置才能找到对话。此入口复用原聊天配置、people／history 与 Conversation owners，不另造工作 event、聊天日志或 Session 目录，不扫描全部 Agent。新创建者输入仍沿唯一逻辑 Main，旧独立私聊保原身份；分页、切换、折叠和历史读取不创建、恢复、发送或改投输入，来源读取失败保原引用及已读内容。不同人的原受众和读取权限保持，展示归属不授予 Agent 新读取权限。

成员与私聊的宽面均以左侧原来源列表、右侧所选原对话同时呈现；选择整行直接切换正文，初次进入可默认展示首条已确认来源供阅读，不据此选择输入或主角色。窄面一次选择进入正文并直接返回原列表。已选原来源、阅读位置和草稿在切换及读取失败时保留；继续原工作沿原准确位置进入，多处位置仍明确选择，不为阅读创建 Region 或恢复 Run。

Main Agent 是可轮转的执行角色，Mote 保持同一身份与逻辑主对话。已确认未绑定时，先提供[欢迎输入](#欢迎输入与主对话流转)，用户提交首个问题等明确开始交流的意图沿原创建 owner 使用已配置的默认 Executor 建立独立主 Agent；没有已配置默认 Executor 时提供配置入口，不硬编码或猜测首个可用执行器，也不选任意成员代主角色。已绑定时另有明确“新建主 Agent／更换主 Agent”动作；新建、原 Session 恢复和选择已有承接者各保真实含义，未知恢复不触发替代创建。新主以原创建回执和 MOTE CAS 确认绑定后才承接之后的新操作；旧主、旧主对话来源、在途／未知请求及健康 Run 保留，不因轮转删除或停止。未知创建／绑定沿同一原操作核对，双客户端与迟到结果不产生重复创建、改投或抢回后来选择。

更换 Mote 已保存的默认 Executor 后，下一条新的逻辑 Main 消息触发执行角色轮转；同一 Provider 下不同 Executor ID 仍是不同选择。保存设置不立即创建、绑定或停止 Agent，此条件独立于按空闲流转的策略。Core 核对当前承接者的原 Executor 与已保存选择，沿同一原创建、接替、MOTE CAS 和输入回执链执行；已经录入、在途或结果未知的旧消息不因设置变化改投或重发，旧主的历史、草稿与健康 Run 保留。执行器来源或原角色尚未确认时，保原请求及具体恢复入口，不把 Provider 默认目录冒充用户保存的 Executor 清单。

用户从 Threads 进入原成员工作后可继续原工作并回到 Discussion，双方原草稿、阅读位置和当前角色保持。Discussion 沿已确认当前主引用定位，不能把当前任意成员或文件 Tab 当主对话；Threads 的显式成员输入保原成员，不因它后来成为主角色改写该次意图。主角色已确认换人而仍在阅读旧主，或新输入所需原角色来源暂未确认时，原正文、草稿和未知旧操作保留，新的逻辑主输入不能静默降为原 Agent 的普通输入；用户可返回当前主对话，或从 Threads 明确选择原 Agent 继续。完整 Group、Tab、Region、分屏、文件与终端从具体工作相邻的“在工作区打开”动作进入，不独占一条“原工作面”横栏。选择 thread、浏览事件历史及切换 Agent 的展示不自动发输入或重做原指令。切换当前主 Agent 只影响之后明确面向新角色的操作；在途及未知的输入、通知、权限、安排和恢复仍冻结原目标与原操作身份，不能转发或补发到新 Agent。交接可带原来源的有界上下文，但历史摘要不成为新授权。不同外部私聊的受众、隔离及原 generation 不因同属 Mote 合并，也不向其他受众广播内部事件。

被展示的原对话、输入和主角色动作必须共用该准确 Mote 的上下文与原角色读取；浮窗借用原 View、主界面位于 Focus、其他工作区或另一 Mote 时，背景工作面的上下文不参与当前操作判定。明确进入主对话时，自动定位并显露原主对话；未在背景展开或尚未完成界面接线不能成为健康原 Agent 的输入门禁。定位保留原 DOM、草稿和阅读位置，后来输入及选择优先；真实来源未确认时沿同一原读取取得事实并给出就地恢复动作，不重发未知输入、不以普通成员输入绕过逻辑主角色核对。

原主 Agent 恢复失败时，Mote 主对话必须保留清楚、可达的继续路径，不把阅读重试当作恢复进度，也不让用户反复发送来尝试恢复。沿准确原 Session／Run 和原恢复回执区分正在恢复、结果未确认及 Core 已确认无法恢复；没有原生恢复来源时说明无法原样恢复，保留历史、草稿和原输入。是否切换承接会话由本节已保存的自动流转策略与原 Core／Host owner 决定，界面不要求用户先理解 Session、接管或分析；未开启自动时保留必要的明确人工继续入口，换主设置及原工作面按需可达。新创建与绑定仍核对准确 Mote、原角色和配置；主来源未知时保留核对及设置入口，不猜另一成员替代。独立换主意图不以旧恢复成功、历史读取成功或旧输入结算为前提。创建与主角色绑定已确认、仅旧首条输入仍待观察时，不再视为创建未确认，不阻断独立的新问题或其已保存策略；真正未确认的创建继续沿原操作核对。换主只承接之后的新操作：旧未知输入、恢复及创建仍按原操作核对，不迁移、不自动重发。原生终端保为按需诊断方式，不成为普通用户唯一出口。

### 欢迎输入与主对话流转

Mote 主交流输入从读取首帧到欢迎、创建或恢复、主对话可读始终保留同一个通用 Composer 和编辑实例；确认会话只改变准确目标的发送适配与正文，不因消息、角色或 metadata 加载重挂编辑器、换草稿来源、清空正文、改变光标／选区、打断中文合成或丢失撤销历史。草稿沿同一准确 Mote 的原持久 owner；Runtime 等执行信息的迟到确认不改变草稿身份，本设备保留其准确原地址，跨连接或页面恢复不重算为另一份输入。既有 Session／成员的独立草稿保留，不自动覆盖或拼接；切换不同 Mote 时隔离输入法事务与撤销历史。加载、历史读取失败与输入资格分别成立；已由 Core 接纳的操作保原身份，读取中仅本设备保留的问题仍遵循本节的打开寿命，切对象或关闭不授权迟到发送。

原主角色 owner 已确认没有当前承接会话时，Mote 工作面提供直接开始交流的欢迎体验；首个问题直接从文字输入开始，无需先理解 Executor、Session 或建立流程。输入草稿从首帧即可编辑，读取配置和角色来源不清空已输入内容。角色来源读取中按发送只在本设备保留这一条消息，不创建、不绑定、不投递：读取确认当前主角色后，在进入的原主对话里以同一提交路径发出一次；确认没有当前主角色时作为欢迎页的首条消息发出；来源未确认时不发送，原文留在草稿。每个 Mote 同时只保留一条：保留后原文移出输入框，同一句话只出现一次，用户可以明确撤回；撤回或投递被拒绝时原文回到同一草稿。这一保留只属于发起它的这次打开：关闭、切走或重开后不再自动发出，原文回到可再发的草稿，不重复投递；同一 Mote 的其他展示（隐藏的 Space 工作面、另一块面板）只显示草稿，不发出或释放不是自己保留的消息。读取、滚动或在本 Mote 内输入不取消这次进入；只有明确改选其他对象、切换页面或关闭才取消。已有当前主角色时继续原主对话；来源未读取、彼此不一致或暂不可用保持未确认，不能当作没有主会话、自动新建或选一个成员替代。

首个问题与该次开始意图保留准确 Mote、原草稿和操作身份。创建、主角色绑定与首条输入分别以原公共 owner 的准确回执成立；尚未配置 Executor 时，输入旁明确说明缺少配置并提供可直接打开配置的动作，保留可编辑原草稿；配置中的新对话 Executor 候选与保存核对消费同一原 Host 的配置来源，读取未知不冒充无配置。配置保存本身不创建或发送；未提交的草稿回到原问题继续编辑，已保留的原开始意图仍沿同一原操作接续。绑定确认后沿逻辑主输入 owner 投递，不把创建成功当首条消息已送达。未知创建、绑定或投递只核对原操作，不能因刷新、切端、超时或迟到结果重复创建和重发。

迟到的流转判定和开始结果不替代用户较晚的展示选择。用户已明确进入成员 thread 时，即使它与原 Main 引用同一 Host／Session，也仍是成员意图，不自动切回主对话。触发流转的原问题与原操作继续由原输入 owner 保留，并提供明确接续原请求的入口；展示入口接纳不等于创建、绑定或输入已完成。不属于当前准确 Mote 的流转请求只拒绝本次入口接纳，不能因此消费原请求或令其后续入口消失；回到所属 Mote 后仍可沿同一原请求接续。既有角色资格与未知回执边界保持，不能把原问题改作普通成员输入、重复发送或另建 Agent。

主对话、工作 thread 以及成员／私聊原对话的过程披露、跟随、主动向上阅读和重新打开的位置保持统一沿[同一 History 阅读面](conversation-mode.md#history-使用共同对话阅读面)，流转和呈现切换不另立滚动规则。

曾承接主角色的对话自然进入同一 Mote 的历史列表，用户可读原正文并返回当前交流。每段历史的起止区间与流转原因取自原主角色 owner 的 typed 事实，区分自然到期流转、用户主动接替、仍在承接与来源未确认；未记录的时间或原因保持未知。前端 wall clock、最后消息、Session 创建时间、关联写入时间、退出或一段安静都不能自行宣告主角色到期、补出任期或触发新主。历史保原作者、Host／Session／Run、消息与来源范围，不把整段 Session 的记录猜切成角色任期。

每个 Mote 可设置自己的自动对话流转策略，由原 `MOTE.md` 配置及 CAS、Core／Host 原主角色与输入 owner 共同执行，Desktop、手机及公共 API 消费同一保存事实。策略提供保持当前对话，或开启自动切换；自动开启时，达到已设置的对话空闲条件，或准确原主会话已由 Core 确认无法原样恢复，在下一次明确的新输入时由原策略决定流转。可配置条件、当前生效策略与待保存编辑清楚可辨。未配置自动策略的旧 Mote 保持原承接和恢复，不因新增设置静默换身份。空闲到期判断使用原 owner 确认的主对话活动；无法恢复的判断只使用准确原 Session／Run 的终局恢复回执，不能以离线、读取失败、缺测或展示文案代替。两者均核对已保存策略修订、准确角色及本条新输入；未知活动／旧输入、配置冲突或在途创建保持原事实与恢复入口，不以观察失败推造到期或重放旧请求。实际流转保留触发条件、原策略与新旧任期的准确回执；心跳频率、通用自动恢复闲置窗和外部私聊的会话更新时间仍各守原范围，不作为 Main 的隐含到期值。保存策略与流转是不同动作，界面挂载、阅读和刷新不自行创建 Agent。

发送触发的原主会话恢复已有明确结论时，客户端保留准确原因和阶段。原 Run 已结束且续接标识尚未确认时，说明恢复卡点并保留原输入；Provider 历史是否存在依据其原记录，主角色流转仍沿原策略。

主动切换沿公共接替、原创建与主角色绑定能力完成，接替上下文由同一 Core／公共输入 owner 承接准确旧来源及 Mote 身份、任务一致性指引；客户端不另拼生命周期、另存主角色事实或仅靠 prompt 宣告绑定成功。原 Session、Run、历史、未发送草稿与未知旧操作保留；接替不停止旧健康工作、不重放旧指令，也不把摘要转成新授权。相关一致性要求沿[环境理解与身份、任务一致性](#环境理解与身份任务一致性)。

语音与全双工是已确认的后续方向，当前没有采集或识别引擎；在真实能力接入前，不展示可用的麦克风来冒充支持。后续方向是支持语音能力插件及 BYOK，由真实能力提供方承担识别／转写或实时语音，用户可选择服务及自己的凭据；不把特定服务、密钥或语音实现绑定进 Mote 身份。届时麦克风授权、采集、取消和失败路径均有准确事实，形成的明确输入仍沿同一原 Mote 输入 owner 与回执，文字输入继续可用。未授权或未真实采集不能表达为正在听。全双工延续同一身份、输入与取消语义，采集、用户发言、模型响应及中断状态各守真实能力事实；本方向不授予麦克风或外部服务权限。

### 环境理解与身份、任务一致性

公开 Mote skill 与每次 Mote 启动的应用注入 prompt 共同要求：先核对自己的执行身份、可用能力、执行 cwd、Mote 原资料与准确空间／主角色绑定，区分执行环境、展示位置和当前任务资源。复用已确认的相关环境，仅在绑定变化或操作需要时重核，不逐轮全局扫描，不以可选观察失败阻断健康工作。

穿梭任务、切换 thread、上下文交接、更换承接 Agent 和心跳时，始终接续用户的真实目标、已确认约束与决定、未完成承诺及原操作／权限／来源。按需读取原 Goal／Task、输入与知识来源，保全用户后来的有效修正和每项授权范围；不能因换任务重设人格、丢掉旧承诺、把成员转述变成人类授权，或把轮次结束报成任务完成。详细运行指引由公开 Mote skill 唯一定义，应用总注入段保短原则与发现入口；用户已有 SOUL／AGENTS 原文不被默认更新覆盖。新上下文送达、既有 Session 的指引发现、模型实际读用和行为效果分别验收，不以改文件声称全部会话已更新。

### 主 Agent 与内部工作

主对话督办围绕本 Mote 已关联的原工作来源展开。`space mote dialogue supervision read` 按原关联分页读取 Dispatch 的通信事实、报告引用及正式 Goal 委派引用；只读观察不发送、不恢复，也不新建任务账本。每项读取缺口分别保留未知和原引用，不因一项不可用丢弃其余已知结果，不扫描无关 Session。角色轮转不转移旧 Dispatch 的参与者权限；新主需沿原授权交接，不能借 Mote 身份读取其他 Agent 的工作。

主 Agent 保持用户目标、约束、决定与未完成承诺，收到原消息或实际安排的心跳时读取同一督办入口，核查需要处理的结果、问题和缺口。普通进度无需额外打扰用户。成员回报、通信结束、Goal 回收、独立核查及人类接受分别成立；当前标准、负责人和操作资格始终经原 Goal owner 核对，Main 身份不授予 Goal Supervisor 权限。后续处理复用原消息、Goal 与输入操作，未知回执只核对原操作，不重放或改投。新指导经平台上下文与同一手册提供，保留原用户文本、人格资料及已冻结输入。

每个 Mote 由一个已确认的主 Agent 默认承接日常交流、任务安排和结果汇总。Mote 持有持久身份，主 Agent 是当前承接唯一主对话、负责沟通与协调的成员，其他 Agent 在工作 thread 中承担具体工作；Tab 是原工作面，Session／Run 是实际执行身份。每个 Mote 的主 Agent 与全局 Main Mote 分开辨认，不能以当前焦点、名字、头像或第一个成员推断主 Agent。

日常交流入口同时让用户辨认正在阅读的主 Agent 或具体成员，并按需查看本 Mote 的成员工作与需要自己处理的事项。成员范围来自原空间绑定，执行状态与原生请求来自准确 Host／Session 的公开观察，工作和责任来自原 Goal；不把全局待办、未知成员或应由协调者处理的事项混入人的请求。待处理条目进入同一成员的原请求或工作记录，回答、授权与验收仍由原 owner 完成。展开摘要或切换成员不启动执行、不自动回答、不重发输入，也不把运行中或轮次结束称作任务完成。原身份、成员入口与已确认信息在局部观察失败时保留，未知范围单独说明。

用户交代事情后，主 Agent 负责保留目标、决定和待交付结果，并按需安排成员及其原工作面。短交流可以直接完成；需要长时间执行或并行推进的工作由成员承担，使主 Agent 仍能接住新的问题与方向调整。后台建立、更新或完成内部工作不切换用户当前 Tab／Region、不抢输入，不要求用户逐项管理成员或跟着查看过程。创建、输入、消息、状态与恢复沿原 Core 公共能力和真实回执，不另建执行 Runtime。

用户可以随时进入任何已确认的成员工作面，直接交流、编辑或继续原工作，无需切换一个全局“接管模式”。与本 Mote 当前协作有关的已发送人类指令变更、关键结果和需要决策的问题，应沿原消息／任务回报能力回流准确主 Agent，保原作者、目标、操作与来源引用，主 Agent 据此更新安排。阅读、选择、未发送草稿、按键和原始过程流不当作新决定；回流不重复执行原指令，不把成员转述升级为人类授权，也不复制全部聊天历史。用户已发送的修正仍直接作用于其原任务，不能依赖主 Agent 先回应才允许成员继续；待投递、未确认与已接受分别可查，未知结果不自动重发。

自动回流的范围必须由原输入与准确回执证明。已有成员从已确认 Mote 工作面提交的明确人类输入，由 Host 核对原 MOTE.md 与成员绑定，并固定本次原主 Agent；后来更换主 Agent 不改投已发生的输入或通知。新建／打开 Agent 的首条创建输入、原生终端直接输入不据此宣称已自动同步，仍沿原派工／dispatch 或明确授权的消息完成交接。平台回流是带来源的观察，不新增权限；输入被接受、原生轮次结束、任务完成和人类验收分别保留原语义。实际操作指引唯一见 Core 的 [Mote 手册](../../../packages/core/guides/modules/mote.md)，随 Mote 提供的短工作指南只负责引导发现，不把每个成员都设成协调者，也不因更新指引声称既有 Session 已读用。

一次通知被原输入 owner 明确证明整次未应用后，仍保留原观察与该次通知回执；原主 Agent 出现新的权威 Run／空闲机会时可重新判定通知资格，每次尝试保独立操作身份。同一机会不反复投递，未知回执只核对原操作，不能按累计拒绝次数永久放弃原协作。成员回复与轮次结束分批到达或进程重启时，完整准确回复引用仍可从原观察读取；通知可只携带观察入口与结果摘要，不以裁剪引用满足通知大小。既有持久观察的发现索引可以从原日志事实修复，不能用索引缺口丢掉原决定、改投主 Agent 或重放成员指令。桌面和手机的明确成员输入共用此合同，来源随原操作保存，后来的导航不改变该次来源。

主对话中的平台回流通知以可读事件说明原成员、本次输入或轮次结果，原协议与完整观察按需读取。只对原对话 owner 已资格化的系统通知使用此呈现，普通消息中的相同 JSON 不获得平台身份。终端字节确认、原生输入采用、轮次结束和任务验收使用各自准确含义；详情始终绑定通知的原 Host、成员和观察，不跟随当前导航改投，不从展示内容取得控制权限。

新建 Mote Agent 的原启动上下文提供主／成员职责的发现入口；既有 Session 在用户下一次从准确 Mote 工作面明确提交输入时，由该次原输入的平台段提示发现同一指引，已读者可复用当前上下文中的指引。提示不改变用户原文，不自授主身份，不新增后台输入或强制重启；主身份仍以原 MOTE.md 准确绑定、实际 Host／Session 与空间事实核对。保存的旧 AGENTS.md 和既有 Session 原上下文保留；提示送达、实际读用及协调行为分别观察，不宣称自动更新全部旧会话。

主 Agent 绑定沿本节快捷模式的原持久配置。已有准确主对话继续使用原身份；确实未配置时，用户可沿原成员选择或明确新建轻量确立，不能因进入、浏览或读取失败自动指定一个成员。新建 Mote 的首次明确 Agent 启动可同时建立主绑定，只有准确创建与保存回执确认后才称已建立；原请求未确认时保原引用和继续核对路径。已有 Mote 和晋升 Topic 均保原成员、工作面、资料与草稿，不把确立主 Agent 变成晋升的额外表单。

主 Agent 失败或观察未知时，在其原入口说明受影响职责及恢复动作；其他健康成员、原输入与工作面继续可用。恢复或明确更换主 Agent 保留原任务与决定来源，不用空白新 Session 冒充原对接者。主角色的驻留与内部心跳按下述明确持久安排执行；它不自动开启普通日历安排、外部消息或更大权限，这些动作仍沿各自授权和原 owner。

主 Agent 创建后，主对话来源关联与 `MOTE.md` 的 CAS 绑定由公共 `space.mote.dialogue.setup.inspect`／`advance` 这一个 owner 组合完成，Desktop、Mobile、Hosted SDK 与 CLI 消费同一入口。

- 参数与目标：两个方法只接收原完整 target 与创建回执 `{hostId, operationId}`；其中 creation Host 准确指向原空间 admission owner，不从 MOTE 资源 Host 或 Agent 执行 Host 推断。
- 谁能推进：两个方法都只接受原来的人或设备，Agent 调用者被拒绝，不能借此读取或指定常驻主 Agent。inspect 只读；advance 只用于明确推进这次初建的后续步骤。两者都不新建、恢复或停止 Agent，不接受临时追加的 Query，也不接受客户端自报的“文件已保存”。
- 冻结的输入：原创建意图中已冻结的首条 Query 与接替输入，在绑定确认后按[欢迎与流转合同](#欢迎输入与主对话流转)交给同一原主输入 owner；每条输入的资格与回执独立核对。
- 分别反馈：创建、旧主对话来源、绑定与输入各自反馈；文件写入回执与 writer 角色／source journal 的观察证据分开表达。
- 对账而不重放：普通 `preferences.save` 只有在 bind operation、完整 target、baseline、角色与 occurrence 全部相符时，它的实际写入结果才能完成这次初建绑定；另一 owner 已完成的保存可在同一 setup 中明确对账，阶段未知时不重放。

### 合作资料与工作入口

Mote 的 Space 以 Profile、Discussion、Threads、Ideas 和 Calendar 同级入口组织日常合作，共用同一导航与当前选择表达。Profile 是同一持久搭档的资料主页，让用户查看已保存介绍与合作方式，并能回到主 Agent 继续交代真实问题、查看当前工作；Discussion 承接唯一主对话及相关工作引用，Threads 承担工作 thread 查找与同源事件历史；准确原工作面及全部成员仍沿原 Tab／Group／Region 选择与恢复可达，不复制对话或创建替代 Session；Ideas 浏览原笔记与所选正文，再沿原来源准备讨论、安排或反馈；Calendar 查看和控制原安排。档案只展示原名称、头像、保存介绍、行为偏好及准确原对象的资料，不从任意文本或运行表现推导职位、组织关系、技能资格或绩效。合作偏好、快捷配置、机器人身份、记忆与原文件仍可达，不能以新的浏览层级删除原能力，也不要求先补全资料才能工作。切换入口、查找或筛选只改变呈现，保留准确 Mote、原讨论与资料引用、未发送草稿和已授权在途操作，不启动后台工作或改写执行身份。

Profile 展示有限若干原讨论，供用户直接接回已有工作，完整清单仍由 Discussion 的原工作面承担。条目使用原 Tab 标题、准确展示引用与可确认的状态，近期顺序只消费原 owner 已记录的访问或活动事实；缺少近期依据时按原成员顺序呈现并说明范围，不用数组位置、刷新时刻或邻居 Session 推造“最近”。点击条目沿同一精确打开能力进入原 Tab／Group／Region；未确认的原位置保留引用与恢复路径，不猜另一个 Agent。该列表是原成员的有界投影，不新增持久讨论目录、访问账本或重复消息读取。

完整 Mote Space 的共同页面都可沿共同入口回到该 Mote 的主 Agent，日常问题由主 Agent 原 Composer 承接，不要求用户先选择执行成员或新建讨论。用户仍可在原工作面明确新建讨论；原 Launcher 草稿、准备操作、来源和结果继续由其原 owner 保存，不改投主 Agent，也不因导航自动发送或启动。页面切换保原输入及在途操作，后来编辑、切换对象或准确引用仍优先，迟到结果不能抢回页面、覆盖新输入或借其他 Mote 完成。

打开与切页先呈现已确认的准确身份、共同导航和可用输入，资料及相关状态由各自 owner 独立补齐。与本次打开或导航无关的文件正文、偏好、连接、记忆、工作和安排读取不阻塞原工作面或入口；需要核对的真实目标与权限仍沿原合同确认。切换保留已有页面状态、阅读位置、草稿与已授权请求，复用原读取 owner 的确认结果和在途读取，不因呈现切换从头重建或无谓重读；源修订、准确对象变化、实际失效与明确刷新仍读取当前事实。局部慢读或失败在对应内容表达并保原已确认结果与恢复动作，不把未读取当空白，不以取消原请求、替代对象或另建事实缓存换取快速外观。

完整 Space 的文件浏览与 Files／Agents 工作工具选择按[Profile 与完整 Space](../presentation/motes-and-coordination.md#profile-与完整-space)归属 Discussion。切换页面只改变呈现，保留同一资源范围、文件树展开、选中、查找、滚动与未完成文件操作；不重置文件树偏好，不改变原讨论和 Editor，也不拿走原 Agents 能力。Profile、Ideas 与 Calendar 中的显式文件动作仍沿原 Files 与精确 Editor 入口回到 Discussion 工作面，打开后保原文件、草稿及讨论引用；后来选择与输入继续优先。Ideas 新建笔记仍沿原创建能力进入可操作的文件工作面，不能把创建输入留在隐藏页面，也不新建第二份文件树或写入通路。

Mote 对象菜单的人格与资料编辑绑定被操作 Mote 的准确 Host、资源 Workspace 和原文件，展示目的地沿该次动作已确认的原 Space／Zone／Group／Tab／Region，遵循[对象选择与原展示绑定](spaces-and-layout.md#topic-导航与成员范围)。文件资源归属与展示位置分别确认：复用原文件、Document 或已打开 Editor，不等于选择该文件的其他 Topic 展示；已有 Tab／Region 的归属与合法展示继续保留，不以后台选中项、首个 File Tab、共用 Scratch 或执行 cwd 覆盖本次 Mote 目标。菜单、显式原文件编辑与后续落焦使用同一准确目的地，异步读取或准备完成不能抢回后来选择；位置未确认时保原文件、草稿和引用，沿原候选或空工作面恢复路径处理，不任取无关 Topic 或创建替代 Agent。文件打开、保存及未知结果继续由[原 Files／Editor owner](files-and-git.md#explorer-与-editor)承担。

- **每个 Mote 的快捷模式。** 原目录中的 `MOTE.md` 以有版本的 YAML 保存默认 Executor、当前主 Agent 的准确 Session／Host、Tab／Region 展示位置及驻留／心跳偏好；逻辑主对话不以当前 Session ID 充当身份，主 Agent 复用准确角色绑定，正文可保用户备注，不存绝对路径，不在 SOUL 中复制可写配置。Profile 展示已保存选择，重新打开编辑选中同一事实；新旧 Mote 均可沿原编辑入口修正，不迁移身份或覆盖原资料。界面明确区分“主 Agent”与“Executor for new chat”，后者只为新 Launcher／明确启动预选，用户仍可改选，不改共享 Workspace 偏好、已有 Agent 或权限。主 Agent 沿原 catalog 和公共 Workbench 验证，日常交流默认回到唯一主对话；原工作面中的主角色可辨，取消绑定不关闭原健康 Agent，其他成员与原工作保留。进入优先级见本节“日常回到主 Agent，手动位置继续保留”，恢复时机沿[主对话的自动接回](#主对话的自动接回)。保存绑定通过原文件 CAS 发布准确配置／意图，不自行启动／停止 Run 或发送消息；Host 因有效驻留安排维护新角色时，沿独立的生命周期及心跳操作取得回执，不创建替代原 Session；无效、未知或尚未恢复的保存引用仍可检查、修正与按原身份恢复。配置沿原 Files／Editor 的版本保存与未知恢复 owner，GUI 和既有公共 Files、空间、Agent／Executor 能力消费同一事实，不另建配置数据库或生命周期。新建 Mote 在首次保存设置前没有 `MOTE.md`。Files owner 确认文件不存在时，主对话、驻留、快捷与连接设置一致读作默认状态：主对话就绪但尚无主 Agent，驻留未绑定，不报读取失败；读取出错或结果未知仍为未确认。
- **初始化与资料编辑。** 快捷配置的 Executor 选择、校验与首次主对话启动消费同一原 Host 的实际启动配置；没有主 Agent 时仍可保存新对话偏好，保存后提供进入首次对话的明确动作，不能要求先手工建立讨论再回来选择。心跳的入口与实际状态保持可发现，轮转等高级设置按需展开，不成为开始交流的必填步骤。Profile 的 Edit profile 打开当前 Mote 原资料的就地表单，读取、取消与保存不切换到 Discussion；保留完整原资料及未保存编辑，只有明确保存才沿原 Files／Editor 的版本检查修改。原资料不可读或保存未知时就地保留表单、错误和核对入口，不覆盖文件或替换 Session。
- **认识与行为方式。** 首次建立关系可以跳过，已有对话和用户当前输入优先。
  - 设定与展示：Profile 展示该 Mote 已确认保存的行为摘要；再次打开设定时选中同一保存事实，不能把表单草稿称为已保存。行为方式设定采用与头像设定一致的可操作编辑体验：四组具体行为偏好及自定义文字可选择、预览和撤回。四组分别对应交流朝向、获取信息、权衡建议和推进节奏；完整、明确的选择导出 E/I、S/N、T/F、J/P 四字母 MBTI 风格标签。标签只概括用户选择的合作偏好，不把任意 SOUL、头像、运行状态或模型回复当作人格测评依据；未确认的设定不猜标签。
  - 文件与保存：独立 `BEHAVIOR.md` 是已保存行为的单一权威，以有版本的 YAML frontmatter 表达结构配置，以 Markdown 正文保用户补充，`SOUL.md` 以相对引用关联。文件仍沿原文件与 Editor owner 可读、可编辑和耐久保存；未知格式、读取失败、冲突及保存未确认保原内容与草稿，只拒绝无法确认目标或内容的那次保存，不拿走健康会话。
  - 旧行为块导入：`BEHAVIOR.md` 确认不存在时，旧 `SOUL.md` 中唯一完整的应用行为块可作为明确标识的待导入来源；只经用户明确 Save 建立新文件并将该精确块换为相对引用，块外原文保留。已存在的新文件不被旧块覆盖，两文件尚未全部确认时说明实际未完成步骤，保可恢复原文件与请求的选择；首次主动改风格不冒充外部冲突，也不留两份可写行为权威。原新对象初始化可 create-only 提供默认文件，read/list 与 Cancel 不改盘。跨对象、迟到读取或后来编辑不能覆盖当前目标和输入。
  - 试聊与生效：用户可用自己的问题沿原 Launcher 在明确的新 Session 试聊，实际 Agent／模型、生成状态与失败可辨，不把规则预览或预写台词冒充回复，不替换正在工作的 Run。新 Session 和明确合作准备实际读取已保存行为文件与原 SOUL，并保本次来源、版本和未知；已有会话的原上下文不热改，临时指令仍优先于已记偏好。行为偏好和标签不新增工具权限、自动输入、外部授权或主动跟进开关。
- **检查与更正记忆。** 用户能从 Profile 按需展开该 Mote 原 `MEMORY.md` 短索引，查看原保存正文、准确文件与版本，并回同一原 Editor 更正或撤回；相关资料沿原文件链接和文件树组织。收起或隐藏不读正文，重新展开读取当前原版本；读取失败保本对象最后确认的内容与准确引用，并提供重试。未保存的 Editor 草稿与原保存正文分别可辨，后者不冒充已包含草稿。没有记录来源或使用事实时表达未知；目录中的普通点子不能自动被称作已记住的事实。保存、读回、冲突和未确认沿原编辑 owner，保原草稿及正确资源，不盲重写。原索引读取和展示不证明模型实际使用；新讨论继续沿原 `prepareAgent` 加载启动时的原文件，不重复注入准备时的旧MEMORY正文。资料组织自主，不强制额外记忆文件或分类，不吞入全部聊天；改变记忆不删除原历史，也不扩大执行授权。
- **从纠正中改进方法。** Mote 先修正当前任务，在用户纠正、重复低效或有价值结果出现时评估是否值得保留方法；没有可复用结论就不增加记录。在原相关笔记中写清来源、日期、适用条件、具体做法与失败或不适用条件；单次经验保留其证据范围。沿原 Files 读取当前资源和版本、保存并读回，只有有后续价值的短链接进入 MEMORY。后续相关工作按需读取链接的当前方法，依据实际结果或反例修订、收窄或撤回同一原结论，不堆叠互相冲突的总结。已授权知识维护不逐条重复求准；它不授权重写人格、行为设定、全局 skill 或权限，不新增每轮反思模型、后台循环或强制记录。保存、上下文送达、实际读用与效果改善分别以各自证据说明，不互相代签。
- **耐久知识与凭据边界。** 短入口保有来源、日期与范围的偏好、决定、纠正和原证据索引，过程流水与历史观察沿原记录留存；整理前保全原文与链接基础，当前 Goal、Runtime 和安装事实仍回原 owner 核对，不把旧状态反复追加成当前事实。凭据不写入会自动加载的 SOUL、AGENTS、MEMORY，也不放入 topic、Wiki 等普通资料；普通知识只保不含秘密值的用途、范围和定位。需要保管的敏感值交给原 Host 凭据 owner 或系统凭据服务，授权操作时按需取用。迁出前确认安全保存与读回，未确认不丢弃原值或冒称修复；更改原文件不声称已擦除既有模型历史。
- **日历安排、间隔重复与一次倒计时。** 用户能表达一次、每日、每周、每月与每年的当地时刻并明确时区，也可安排分钟级间隔重复或一次相对倒计时。各形式共用原持久调度、准确 Session 目标和 Core 输入事务。一次倒计时的相对时长只在首次保存原操作时换算为绝对到期时间，重复请求、暂停后继续或重启恢复不重新计时；一次确认投递后结束，不变成周期续跑。间隔重复保留原安排的时间锚点与发生项，确认一次输入后继续按原规则安排下一次。暂停是停止投递而非冻结时钟；一次倒计时恢复时仍处理原到期项，周期安排错过多次时只处理最新到期项。取消或一次完成后为终态，不能由暂停、继续、迟到请求或保存失败复活；已终止的暂停或继续请求明确拒绝，沿原安排查询当前状态，不伪造历史成功回执。原安排可查询准确到期、正文、状态及暂停、继续、取消；这些控制不停止健康 Agent。忙碌、权限等待、重复操作和未知回执沿原输入保护。人工输入占用期间按[自动推进的输入保护合同](agent-capabilities-and-messaging.md#自动推进的触发暂停与认领)让路。错过的周期不集中补发，未确认的投递保原操作供检查，不自动重发。调度只保证已确认的宿主在线范围，关 App、睡眠或离线不承诺准时触发；重启恢复同一安排、状态及操作身份，不创建替代 Session。Mote 为完成已授权工作可给准确自身 Session 安排有明确用途和期限的有限检查，说明安排并保可检查及取消入口；这不授权周期问候、外发、额外后台反思或扩大任务范围。
- **有分寸的跟进。** 主动问候由用户明确开启，可暂停，遵守当地安静时段、最小间隔和预算；没有明确相关目标或真实对话就不编关心话题。上一条主动问题未获用户答复时不叠问；用户正在输入、Agent 忙碌或等授权时不插话。内容简短、针对已确认上下文，并明确来源，不假称后台完成工作。同一实体在多个位置显示仍只消费一份安排与原投递身份，隐藏或打开 Profile 不新增后台循环。
- **点子与继续讨论。** Mote 基于当前方向、相关已确认资料和真实讨论提出少量有理由、来源、适用范围与下一步的建议，区分提案与已确认决定。资料稀少或来源未核时如实说明；喜欢或不喜欢的显式反馈在原范围影响后续建议。保存点子复用原笔记与 Files，在已授权知识维护范围内更新相关原笔记，必要时创建普通 Markdown 点子并保存读回，不要求新 Idea 实体、固定分类或先打开界面。只有有后续价值的入口才进入短 MEMORY 索引；保原来源、用户正文和可更正／撤回。已注册的 Note 沿原 Notebook owner 保目录和关系，正文仍由原 Files 持有。选择点子形成原讨论草稿，实际执行仍沿当前授权；生成或留存点子不自动确认 Goal，也不授权外发、安排、购买或修改外部资源。
- **把成果交到手边。** 原对话能呈现实际文件成果，保可辨名称／类型与原打开动作，并回到原消息或工具事实。文件与回复的关系来自已确认的原引用，不仅凭时间邻近推定权威来源；文件失效或结果未确认保原引用及说明。原 Markdown、文件预览、Git／Result Review 继续使用同一资源与身份，不另建成果存储或读取无关 Session。隐藏展示不做新的文件扫描或预览加载。

用户可检查的安排、偏好和生成动作按[公共能力贡献约定](../../guides/public-capability-contributions.md)评估并消费同一业务 owner 的公共接口；发现、配置或读取不隐含启动、投递或外部授权。上述行为要求不以提示词在场、保存请求成功或单个模型样本代替实际链路资格。

### Mote 安排日历

完整 Space 和左下浮窗共用 Mote 页签的呈现与选择语义。浮窗选择 Calendar 后在原浮窗内使用整块正文浏览同一 Mote 的日历；日历可按安排名称、指令或原讨论搜索，按安排状态筛选，一键隐藏原来源确认的心跳。筛选同时作用于格子、时段详情和 Upcoming，只改变阅读范围。返回原对话保留原选择和输入。页面切换属于当前工作面。

同一持久 Mote 提供直接可发现的 Calendar，统一查看自己的日历提醒、一次倒计时和定时点子。范围沿原目录 owner 确认的准确 Host 与 home 地址，包含已确认的原地址及其中不同执行 Session 的安排；切换当前讨论不改变这份对象范围，不以 scratch 容器、标题或路径前缀猜归属。Calendar 与原会话的 Arrangements 消费同一 schedule owner，原安排、修订、目标、权限和请求身份保持，不另存日历事件或为打开视图新建安排、发送输入、启动 Agent。

日历提供 Day、3 Days、Week、Month 和 Upcoming，默认 Month；切换视图带着原所选日期继续浏览。月视图按日显示重复安排和预计次数，其他日期网格按小时合并；只在选择某一小时后按页显示该时段的具体时刻。一分钟或两分钟周期的数量由可见窗口上的压缩投影推得，不能为每个预计触发生成日历对象。Upcoming 按原截止时间列原安排。管理安排时每条规则只列一次，分别标注上次已接收与下次计划，完整指令和控制按需打开。安排是发生时间点，不凭视觉格子赋予时长或未经原 owner 支持的拖拽改期能力。

浏览时区只改变呈现。民用时间复用 Core 的原规则和可见窗口，分钟周期复用原截止时间定锚。预计次数、原到期和最近一次已接受输入分别表达；暂停、结束或投递待核实的安排不推演未来，倒计时仍保最初的绝对到期。只有原记录可证明最近一次输入已被接受，不把空时段、过去周期或推算冒充完整历史、模型已开始工作或业务完成。投影不推进原截止时间，也不授予投递或控制资格。

每条安排保原讨论目标，民用时间安排保规则时区，提供准确的检查、暂停／继续／取消及返回原对话入口。创建沿已确认的原讨论，目标未知时仍可查看原安排并选择讨论，不猜首个会话或自动启动。写入未知保草稿、原 operation 和检查／同操作重试入口，不自动重放；结束终态继续沿本节原调度合同。查看失败保最后确认条目和可达重试，空日期、尚无安排与读取未知分别表达；隐藏只停止新增观察和展示计时，不撤销已授权的在途写入或丢失原请求。日历不附带读取知识树或笔记正文。

选择日期或时段时，同一日历按时间呈现该范围内各原安排的发生项与计划。沿原调度 Host 的 `schedule.history` 按页读取已确认的准确 Session 和已发布规则。已经发生的项是只读事实，使用原到期时刻、原身份和发生时的上下文；编辑、暂停或取消安排只影响后续计划。原回执后续可补全状态。点开具体事件查看原指令、已确认结果并返回原对话。入队、投递、原生回合结束与任务成果各自独立；来源或回执不完整时保留已确认结果，就地提供重试。画布按可见窗口读取，格子和展开明细使用同一来源、发生时间和状态；部分读取明示范围，不能当作零次或最终总数。高频计划保持压缩，已发生事件按需分页，无历史轮询，不写第二份记录。新建草稿沿所选日期／时段及浏览时区准备；打开已有草稿保留原内容、时刻和操作身份，改到所选时段由用户明确选择。

公共能力复用 schedule list/inspect/create/pause/resume/cancel；跨会话查询使用通用准确目录 scope，控制仍针对原完整对象。民用时间及只读发生项投影由 Core 同一可复用算法持有，宿主和客户端共用，不在 Renderer 重写 DST、月末或倒计时规则。会议、个人日程同步及正向秒表不因这一日历入口自动加入；呈现与窄面规则见[同主题日历呈现](../presentation/motes-and-coordination.md#mote-安排日历)。

### 长期合作的八项评估

Mote 的长期合作质量按以下 8P 问题检查。具体行为与授权边界仍归对应章节；此表用于串联产品要求，不表示八项已全部实现或通过体验验证。

| 原则 | 用户应能判断的问题 | 具体行为归属 |
| --- | --- | --- |
| personable · 像人 | 能否认出同一位搭档，并形成稳定、可调节的合作方式？ | [持久人格](#mote-预制与持久人格)及日常合作的“认识与行为方式” |
| proximate · 触手可及 | 能否从实际支持的桌面和设备入口直接找到原搭档与工作？ | [快捷入口](#mote-快捷入口与当前协调上下文)、[连接设备](public-control.md#手机版-relay-连接) |
| persistent · 一直在 | 隔一段时间或重启后，原身份、资料、工作面与安排能否接续，在线范围是否说清楚？ | [主对话接回](#主对话的自动接回)、[持久工作面](session-recovery.md#工作面持久恢复与启动边界)及日常合作的“日历安排” |
| personalized · 个性化 | 偏好能否保存、检查、更正和撤回，后来是否真正使用？ | 日常合作的“检查与更正记忆”、[原文件记忆](#会话入口与原文件记忆) |
| proactive · 主动 | 是否围绕已确认目标提供相关、适时、可继续行动的帮助？ | [主动点子](#自然认识可纠正资料与主动点子)、[持续推进](#目标持续推进与成果回报) |
| prudent · 克制 | 是否尊重当前输入、授权、静默与暂停，避免叠催和无依据承诺？ | 日常合作的“有分寸的跟进”及[持续推进](#目标持续推进与成果回报) |
| productive · 能干活、能闭环 | 是否交到实际成果、准确阻塞或待决定事项，并保留原验收与人类接受？ | 日常合作的“把成果交到手边”、[持续推进](#目标持续推进与成果回报)、[Goals 与 Demand](goals.md) |
| private · 保护隐私 | 是否说清本地留存、设备传输、所选 Provider 处理及撤回各自的数据边界？ | [设备传输](public-control.md#手机版-relay-连接)、[资料加载与撤回](#会话入口与原文件记忆)及日常合作的外部授权边界 |

本地保存与设备端到端加密不能单独证明模型仅在本地处理；原文件更正或撤回的效果沿原文件记忆合同说明。入口可达、身份持久、定时触发、输入送达和文件存在，也分别只证明自身事实，不能替代长期合作的实际结果。

### 连接设备编辑快捷配置

原文件配置、候选发现和实际运行分别报告。准确资源及原文件已确认时，展示目录或 Executor 候选读取失败不把整份配置改为未确认，不阻断未修改相应选择的偏好保存；已保存的原选择与草稿保留，失败候选不冒充空清单。更换 Executor 或主角色时，仍只以对应原 owner 的已确认候选校验这次选择，缺失事实拒绝该次更换并给出原来源的核对入口。候选发现不成为无关保存的等待前置。

已连接设备按准确 Mote 内容身份读取 Quick 配置；读取不要求该对象已在 Desktop 某处展示。未改动主角色的心跳、后续会话 Executor 和轮转偏好保存，继续由原 Files／Editor owner 核对准确资源、原文、配置与修订；原展示位置缺失或恢复中不阻断这类保存，原主角色引用与代际保持不变，不借保存恢复暂停安排。首次绑定或更换主角色等需要展示关系的动作，才使用发现返回的准确原展示位置或明确的空 Group；只有一个合法候选时可自动绑定，多处展示由用户按可读位置选择，不借当前活动页或第一项猜测。读取、选择和保存均不启动会话、不发输入，未知引用仍保完整原值；原资源、修订或主角色变化仍拒绝该次不再适用的保存并保留完整草稿。

Desktop 本地表单仍以原表单生命周期和后来编辑取消未完成保存。外部设备的明确 Save 在原 owner 准入后使用已冻结的完整配置、原文、资源和修订完成；Desktop 不声称观察到了远端后来输入，也不以恒真条件绕过原导航或资源守卫。远端后来表单、原未知请求与完整原因保在原设备工作面，迟到回执只能结算其原请求。核对当前文件不是旧保存 ACK；没有权威原 writer 回执或操作账本时保持未确认，用户明确采用当前原修订后才能提交新的保存，不自动重放。

### 主对话的自动接回

每个 Mote 的主角色缺省保持可用，并自动触发内部心跳，缺省间隔为 30 分钟，用户可以设置。可用包括已确认的空闲承接状态，无需持续输出。连接的 Host 消费原 Mote 配置和准确当前角色，复用 Core 公共生命周期与原持久调度。机器或 Host 重启后，已开启的原安排在原 Host 再次在线时自动接续，用户无需打开 Mote、先发消息或手动恢复安排。客户端共用原状态与控制入口，心跳由 Host 定时。无在线 Host 时不承诺执行。

**心跳到期，先恢复原主会话，再继续本次到期事项。** Host 核对原安排、准确当前角色与授权后，按 Core 报告的当前事实推进。同一个到期事项可以跨恢复等待保留，恢复和心跳投递仍分别沿原 owner 取得回执。

| 到期时的事实 | 系统要做什么 |
| --- | --- |
| 原 Run 健康，活动可核对 | 接回原 Run。Provider 确认当前有可接纳的机会后，由 Core 最终准入；忙碌、人的输入或原生待答沿原占用规则等待或顺延。 |
| 原 Run 仍在运行，但当前活动观测缺失、失效或无法确认 | 先沿 Core／Provider 恢复准确原 Run 的观测，保留可用的进程、终端、对话和手动输入。观察未知不能作为空闲、忙碌或进程终局，也不触发停止或换主。 |
| Runtime 确认原 Run 已结束或丢失，原驻留意图仍允许恢复 | Host 按原意图发起或接回 Core 的恢复操作，由原 Provider 续接同一 Session 和原生对话。Core 确认新 Run 的原生来源和输入资格后继续；恢复后若已有权威的初始空闲机会，无需等用户发第一条消息或等本 Run 先完成一轮。 |
| 原 Host／来源暂不可用，或恢复尚在进行 | 保持安排开启，保留最新可执行的原到期事项。沿原连接或恢复操作重查，按可用变化和逐次加长的等待续接；不以空转检查结算本次到期。 |
| 需要原生信任、登录等人类操作，或 Core 确认原上下文无法续接 | 在原主对话和心跳入口说明准确原因与下一步。用户完成已确认的原生待答后自动核对并接续；原上下文无法续接时保原对话和恢复入口，更换主 Agent 沿已保存的[主对话流转策略](#欢迎输入与主对话流转)。 |

恢复原可接纳状态后，Host 在同一处理链重新核对角色、安排、人的输入与原操作，投递仍到期的事项，无需再等一个完整间隔。错过多个周期只处理最新仍有资格的一次。原 owner 确认未交出输入时，观测失败和本次等待取消只记为未发送；持续未知时要保留等待原因、下次核对条件及可执行入口，不能每次只报跳过。用户明确暂停／停止、撤销、退休、换主、采用新版指导及可能已写出的输入仍遵守下文约束。恢复使用的权威依据和准入边界归 [Session 恢复](session-recovery.md#冷启动按需恢复p0-末位)。

心跳的可观察结果须来自同一持久安排及准确输入记录：区分偏好已保存、安排已建立、到期已检查、输入已接受、原生已开始处理和本轮已结束。最近检查时间、最近实际投递、下次到期或重查机会、未执行原因及恢复动作可公开读取；没有原生处理或结束依据时保持未确认，不能用 `active`、计时器触发或终端字节 ACK 补成“已经检查了工作”。一次检查没有需汇报的变化可以不发聊天消息，但用户仍能核对该次真实结果。GUI、SDK／RPC／CLI 消费同一原 owner 的事实，不另设客户端心跳、活动推断或结果账本。

实际输入引用在原安排 owner 认领时固定原操作、Run、维护来源与到期事项，投递结算、后续跳过检查、间隔调整和主角色变化不把它改指当前输入。原输入的投递、原生采用、同轮原生结果、Agent 的工作报告与 Goal 验收分别表达；原生已返回空闲不等于该输入已被消费或业务已完成。Provider 未提供逐输入关联时，明确显示同原 Run 的观察及关联未支持／未确认，不从时间、相邻轮次、正文或最新回答补因果。公开摘要只投影原 owner 核对属于该 Mote 自动安排的最小状态和引用，不能接受任意私有输入键，也不透传原提示、完整 claim、环境或控制资格；原私有输入参与者权限保持。旧记录缺引用时保持未知，读取不重写历史、不触发恢复或输入。

一个 Mote 的配置、主角色、恢复或 Host 查询缓慢，只影响该对象；其他到期安排和健康输入继续处理。后台检查、恢复、来源资格核对与实际输入均需有取消和阶段反馈，不能在全局串行等待中饿死无关对象。相关成本随活跃原角色和实际到期事项增长，不因无关历史 Session 扩大。

驻留与心跳的当前意图、间隔、暂停及当前主角色绑定须可公开检查和设置；配置保存、安排建立、进程恢复、心跳输入已接受与实际完成分别取得原回执。主绑定未确认时保原成员与选择入口，不猜首个成员；需要首次创建时沿已确认 Executor 与原创建操作取得唯一主绑定，创建未知不再开第二位。明确暂停驻留／心跳、取消、停止或退休仍由原 owner 承认，后台不能以“始终在线”复活用户刚停下的执行。

心跳检查当前目标、成员 thread、待处理决定和未完成承诺，在原授权范围内继续有价值工作。每轮从本 Mote 原关联来源有界读取具体事项、报告与当前责任，保留分页覆盖和各项未确认；原链接页为空、链接水位未变或 Agent 空闲不能代称全部工作无变化。准确 Goal 的当前标准与管理权仍归原 Goal owner，不按同名或相同 ID 借用另一 owner 的事实，不因 Main 身份代签验收。

每轮接续相关原报告和事项的当前事实，选出一件有价值的已授权下一步，沿原 owner 执行并核对结果；已有结果不重复做，仍待满足的条件说明在等什么、由谁负责及相关的后续触发。报告用原 summary、动作和引用交代相较上轮的有用变化、结果及下一步或明确等待，不复制任务状态或另建进度账本。局部来源读不到只影响对应事项，其余可读工作继续；没有真实增量时如实安静结束。

没有新的需行动事项时，同一心跳回合可以围绕原目标、承诺和已有相关资料做轻量回顾。有值得保留的改进、实验或待验证想法时，沿本 Mote 原 Ideas 笔记和 Files／Editor owner 读取相关原文、补充同题内容或明确缺失后创建，并保修订、草稿及原保存回执；不另建 Idea Store。新想法保其依据、假设和提案性质，不自动变成执行任务、用户决定或额外授权。没有有用增量可以零写入并安静结束，不要求每拍造 idea 或记空日志，不把有界查找当作全库无同题的证明，也不逐次问候、重复汇报或另启反思 Agent。普通回顾和 Ideas 维护不额外打扰用户；需要处理的变化和风险沿原消息、交互、Goal 责任及通知 owner 表达，不以模型正文、无变化标签或已读状态消除真实异常。

内置心跳的单拍提示只携带本次动作、原对象与督办入口，完整工作手册在原指南按需读取。用户编辑的安排保留原文。心跳指导和原安排采用的策略分别确认。更新默认指导不代签既有安排或既有模型上下文已采用；既有安排升级沿原配置／调度 owner 的明确操作和回执，只影响未认领的未来事项，保留原身份、暂停选择、间隔和原未知输入。采用时尚未到期的原下一拍保持不变，不能因替换指导额外跳过一个间隔；已经到期的事项按原节奏取下一次未来机会。已冻结的用户正文、平台段、操作和条件保持原文，不能在投递时追加事实或换提示后冒称同一原请求。当前事实优先在同一心跳回合沿原只读能力取得，不为注入上下文重复复制任务真相。

采用回执未确认时，原操作须仍可核对。普通备注正文变化不能阻断已发布操作的结算；原身份、配置、角色、操作与请求仍须准确一致，不把当前文件改写成旧请求。后来明确的暂停、恢复或间隔调整独立有效，旧采用只按原意图与当前控制状态的准确读回结算，不借旧授权激活或覆盖后来操作。持续持久化失败保原操作、定义与未知阶段，不误报尚未写入；已确认终态的重复读取不要求再次写盘。尚未发布的准备可由新的明确请求在确认原准备意图已停用后取代，原记录仍保留；已发布未知不能用另起操作掩盖。

忙碌和原生待答等待原准入恢复，安排保持开启。人的输入意图把到期顺延到这次输入之后一个完整间隔，输入操作回执单独列出被顺延的心跳。原 owner 确认尚未交出的暂时失败按上文保留到期并继续核对；可能已写出的心跳保留为未知并暂停核对该原输入，其他恢复成功不能代签它的投递。一个逻辑角色只有一份当前有效安排。更换主 Agent 后撤销旧角色的后续自动动作，新角色由新明确绑定承接；原 pending／unknown 仍归原操作，不迁移、不重放。

心跳间隔不决定会话寿命。长离线不产生替换主 Agent 的资格；轮转只沿[欢迎输入与主对话流转](#欢迎输入与主对话流转)的已保存策略、原生活动与原输入准入发生。满足既有轮转条件的承接仍沿原创建、交接和绑定 owner，保留原承诺、授权及未决操作，迟到的旧 Run 结果不能重新任命旧主。心跳自身不生成触发轮转所需的人类新输入。

暂停原因要保留可操作的结构化依据：人的明确暂停／停止、当前角色已被替换、发送前的暂时失败、可能已发生的未知写入分别处理，不从历史错误文案猜授权。来源恢复后，已证实未发送的到期按原安排继续核对；可能写出的同一输入先核原操作，不因重连、重启、改间隔或重新打开页面自动重发。明确暂停与取消保持有效，修复观察流程不能代人重新授权；历史上被流程误停的安排要有就地检查原回执和明确恢复入口，不悄悄激活全部旧记录。安排的创建尚未确认时，仅在原权威记录确认主角色未变、无人暂停或取消、从未检查或投递的条件下，Host 才能沿原操作继续同一个幂等创建；这不允许恢复真正暂停的安排或重发未知输入。

临时写盘失败时，已读取的原安排仍可查询。认领写入失败且尚未交出输入时，保留原安排与已到期事项，存储可写后逐项继续；可能已交出的输入由调度器向 Core 核对原回执，确认已接纳时只结算，明确未应用时沿原输入 owner 的重试资格继续，仍未知时保持原键和可见原因。保存准备后重启时，先核对原认领。原 Run 已确认终局，且 Core 在同一持久切口确认原键无认领、原意图未消耗该轮时，可撤掉旧准备，让原安排按当前准入继续。查不到回执、换过 Run 或原生会话都不单独授权重发。恢复只消费原持续意图和当前角色资格，不覆盖后来明确的暂停或取消。需要跨轮工作的巡检按已完成的批次继续，拉取或保存一批源消息不推进已处理进度。

恢复准确原 Session 与建立新承接 Agent 是两种操作。驻留安排如何进入 Core 自动恢复、原活动证据时间窗、明确停止和退休保护只定义于 [Session 恢复的显式固定主对话合同](session-recovery.md#冷启动按需恢复p0-末位)。驻留授权不由普通挂载、hover 或历史阅读产生，主角色以外的成员继续遵守普通按需恢复。用户从入口明确打开准确 Mote 的 Discussion 时，先接回已确认当前主对话与原历史；确需恢复的当前主 Agent 可由这一次明确打开形成无输入的原 Core 恢复意图，保原 Session、Provider native identity 与操作回执，不另建承接者代恢复。该意图只属于这次明确打开，不由 hover、后台重载、刷新、切 Threads 或历史阅读补造；同一打开不重复创建恢复操作，后来换对象、改选、关闭与输入优先。主绑定未确认、明确暂停／停止／退休和旧恢复结果 unknown 各沿原事实处理，不猜首个成员，不覆盖停止，不重放输入或未知 Start。仅因输入或持久保存未确认而暂停心跳时，仍可按用户原驻留授权或明确打开意图恢复原主对话。恢复不发送输入，也不改变原安排的暂停及待核对回执。原历史读取不以 CLI 在线为前提；未绑定主角色时明确显示建立／选择入口，不伪装成原主对话已恢复。

Mote 的日常入口与主对话持续提供自动照看状态，读取原安排而非最近回复推断。暂停由原调度 owner 在真实状态迁移时保留类型化原因、事件身份与已知时间，经同一公开安排读回；用户暂停、配置关闭、角色替换、未知投递及旧记录原因未确认分别表达。旧记录不补造暂停时间，最近检查不能当作暂停起点。需要核对的同一未决事件进入原通知／服务入口且只提醒一次；已读或关闭提示只改变提醒呈现，不恢复安排、不清除原事件。提醒绑定其原安排、事件与输入，后来更换主角色或同一安排的新一拍不能替换核查目标；旧提醒只读核查原输入，当前配置与恢复仍在当前准确安排中操作。正常忙碌和用户明确关闭不报警，读取失败不宣布 Agent 死亡；核对与恢复复用原操作，不能借提醒重发未知输入。

### 透明启动与需要用户继续的步骤

Mote 首次创建、轮转承接和原 Session 恢复都可能经过 Provider 的目录信任、登录、迁移或其他原生初始化。原 Provider 解释自己已确认的启动阶段、准确待答请求与输入资格，Core 组合原操作和恢复身份，Mote 消费同一结果。已发起创建、进程 running、信任预置成功或曾经收到 Hook 均不能单独代签本次输入已可接纳；首问和心跳是否可投递沿[输入环境判定](agent-capabilities-and-messaging.md#输入环境判定与复用边界)。

透明操作不能在用户看不到的确认面永久等待。主对话在原启动／恢复消息附近持续说明实际阶段、已保留的输入和一个明确下一步：确证需要目录确认时说明准确目录与影响，确证登录时进入原登录流程，观察不足时明确“启动状态待确认”。Provider 支持结构化原生答复时，在主对话中完成绑定准确 Host／Session／Run／请求的确认，过期答复只拒绝该次动作；不支持时如实说明，提供按需查看同一原进程的终端及继续核对入口，不把终端设为普通用户默认首屏，也不模拟一个不存在的通用“允许”按钮。

自有目录的免打扰准备沿[Topic 与 Mote 的物理目录](#topic-与-mote-的物理目录)，不把任意 Project、家目录子树或外来仓库自动设为信任。准备失败保留已可用的启动、终端和恢复通路，原服务状态持续可见，不以增加等待时间、盲发回车、发送问题代答确认，或新建 Agent 掩盖阻塞。本次读取观察的超时与取消只结束观察；原创建、输入与可能已执行的答复继续沿原操作核对，用户晚输入和焦点不被迟到结果覆盖。

### 后台合作的底层验收

可靠性验收从实际 Host 组装、Core 公共生命周期、唯一调度、Provider 输入及原回执闭合到 Mote 消费者；控件可点、安排 `active`、模型提示词或模拟计时通过均不代替这条链。按受影响 Provider 分别核真实可执行文件与启动形式，新建、原身份恢复与已有健康 Run 分开；不支持或未验证的能力具名说明。针对某个 Mote 修复心跳时，以当前安装产品的原主角色和原安排取得新到期、准确原输入的投递及原生结果，并保留下次安排；不能用普通 Agent 测试消息代替，也不能把只更新界面当作 Core／Host 修复已经加载。原恢复仍需人／设备动作时，保留这一未完成项和原位恢复入口，不代签实际已通。

| 场景 | 必须取得的证据 |
| --- | --- |
| 到期与安静完成 | 至少一拍真实到期经过原调度与 Core 输入，核准确角色／Run、唯一输入键及可观察处理结果；没有变化不刷聊天，手动输入仍可用。 |
| 活动观测中断，原 Run 仍在线 | 实际到期保留，恢复准确原生来源的观测，其他健康能力继续可用；确认可接纳后按原到期事项投递一次。原 Run 始终保留，持续未恢复时可见准确原因及可执行入口。 |
| 长离线、睡眠、重连及已结束的 Run | 在原持久数据上接回原 Run 或续接同一 Session，核准确原生来源和输入资格。在没有用户打开、手工触发或先发消息的情况下消费最新到期事项一次，保留原问题和承诺。 |
| 忙碌、用户输入与原生待答 | 保留或顺延到期，人的输入优先，确认后沿同一意图继续；首问与心跳不落入信任／登录确认面，普通原生终端仍可操作。 |
| 丢受据、存储失败与进程重启 | 分别在认领前、可能写出及确认后注入故障，重启后保原安排和输入键；未知不重发，确认成功不重复，未发生的暂时失败有恢复机会。 |
| 换主、轮转与迟到结果 | 原来源资格与承接 CAS 经并发和崩溃验证，旧角色后续自动动作失效；原 pending／unknown 不迁移，交接不丢目标、约束、承诺、来源与授权。 |
| 隔离与免打扰信任 | 阻塞一位 Mote 的来源读取不阻塞另一位到期；准确家目录与合法别名可用，嵌套外来仓库和链接逃逸不获预置信任。 |

这些场景随对应实现取得生产变异、真实消费者与跨重启证据，具体方法沿[测试策略](../../testing/strategy.md#任务验收与假绿防护)。需要真实厂商 CLI 的范围不能用受控 Provider fixture 代签；需求写入不代表既有或本轮实现已经通过。

### 目标、持续推进与成果回报

Main 接续工作时，同时核对原关联工作和准确执行 Session 自己已保存的安排；两者覆盖范围分别说明，关联页为空不代表没有已授权事项。读取复用原调度与工作 owner，按准确目标限定范围，自己的驻留心跳按原来源身份排除；不靠标题、工作目录或承诺文案生成另一份任务事实。一个来源不可读时保留其他来源与原能力，具名说明未知。机制升级通过原产品入口和原指导采用生效，不依赖开发 Agent 反复给旧 Main 补业务指令。普通恢复继续保持无新增输入；用户明确要求重启时沿原 Core 操作保原 Session 与原生对话，重启本身不作为新指导已采用或工作已完成的证据。

Mote 中的主动推进沿原 Goal、该 Goal 的 Loop Supervisor 与原续跑调度成立。用户可以在当前 Mote 的真实讨论中交代一个目标，确认原 Goal 的成功条件，从负责人中明确选择 Supervisor，再单独授权持续推进（默认不开启）。此后同一目标的当前进展、需要用户决定的事项、下一次检查与成果入口在 Mote 中就地可达，不要求用户先填写脚本目录或另建执行清单。探索性聊天与初次认识不自动创建空 Goal。Goal 的定义、确认和成果接受见[《Goals 与 Demand》](goals.md)；loop 的授权绑定、暂停与停止条件、版本失效和恢复只见[《Goal 与原持续推进的连接》](goal-execution-and-supervision.md#goal-与原持续推进的连接)，Mote 不另行定义。

回访摘要从原 Goal 的活动、决定、实际 grounding 与原 loop 状态取事实，以“做了什么 / 卡在哪里 / 需要你决定什么 / 成果”组织；接受输入、空闲状态与计时器触发均不算成果。成果沿原文件引用和 Goal 逐项证据，保 met/gap/unknown、人类接受与版本。暂停、恢复、停止在当前内容旁可达，不能以新表单、第二文件树或第二任务数据库承载。

### 自然认识、可纠正资料与主动点子

第一次合作可从一个真实问题开始，介绍与偏好设定均可跳过；行为与 MBTI 是前述原 `BEHAVIOR.md` 的可编辑偏好，SOUL 相对引用同一文件，不能要求先完成性格测验才能工作。跨讨论资料从该 Mote 的原 SOUL、行为文件与原资料按需读取，按需显示本次真实读回或带入的文件与版本，并沿原 Editor 修改；模型实际应用资料须有真实工具/回答见证，准备提示不等于使用证明。保存失败或未确认保留草稿与服务说明；已有 Session 的上下文不冒称实时热更。下一次新讨论读取新资料，另一 Mote 不借同目录邻居或背景对象获得资料。

主动点子由用户为准确执行者明确开启原安排；频率、静默/暂停及来源范围可读。普通目标续跑、定时消息与轻量问候各自说明用途，问候不能伪装成后台工作。建议应少而相关，解释为何值得做并按需给出实际资料来源，不以定时写一条消息充当有价值点子。安排保存准确资料 locator 与原意图；创建时摘要只称最后确认，执行时须由实际 Agent 重读当前文件并说明未知，不重写同操作的投递内容。用户接受后沿原 Goal 或原讨论继续，反馈沿原 SOUL/文件保存并在后续新讨论中真实消费，不另建 Feed 或 Memory 引擎。

主动点子安排与 Goal 续跑都以原 Host 在线、Agent 可用和准确输入条件为前提；关闭当前面板或换设备不改变原执行身份，设备或连接不可达时显示最后已确认事实与未知状态，不宣称云端全天候保证（Goal 续跑见[《Goal 与原持续推进的连接》](goal-execution-and-supervision.md#goal-与原持续推进的连接)，安排见上文“日历安排”）。公共 API、CLI 与已连接设备消费同一 Goal／loop 回执、暂停和成果事实。外部平台是否接收 Goal／loop 回执与成果仍待讨论；接入时沿通用连接结构，不加厂商分支。

### 资料刷新与当前工作摘要

名册复用原文件系统观察；无关普通文件修改不重读全名册。已确认对象的设定、归档或正文变化只重读该对象，目录成员或身份记录变化才重新发现成员。较早的扫描不覆盖在途期间已确认的新对象；局部成功不抹掉其他对象或目录发现仍未知的事实。读取失败保原身份与可用工作面，按原范围提供重试。

准备问题或点子只核对用户选中的原资料，以及准确资源、展示引用和用户后来输入。无关对象的保存不取消准备；选中资料确实改变、资源或页面改变过、用户改了输入时，迟到结果不得替用户创建讨论或安排。读完最后一次核对仍须检查当前输入与原目标，保原草稿。

Profile 的当前工作以原 Goal 状态、验收和记录为准，缺省最多显示三项摘要，优先提示阻塞和待确认的工作。数量及完整记录入口清楚可达；已结束的历史仍可查，展开与返回不改变原 Goal、讨论、草稿、Session 或 Run。行为设定与最近点子继续是 Profile 中可达的对象内容。

### 机器人身份与公开资料

Mote 可选择原连接设置中已保存的机器人身份，也可明确创建对应的机器人，并将其设为该 Mote 后续连群的默认身份。面向搭档的机器人身份卡以原 Mote 为对象，不另建 Bot 实体或第二份默认关系。身份池、凭据、平台应用与健康由原 Connection owner 管理；Mote 只在原持久偏好中保存原 Connection 服务上下文中的精确引用及对应应用身份，不复制凭证或建立另一份机器人名册。跨 Desktop 或原服务无法解析该引用时明确不可用，保原目标与明确改选路径，不借执行 Host 或其他服务猜凭据归属。默认引用不是执行 Session、Region、人格或运行状态，不表示该 Mote 独占应用或已取得平台管理权限。

创建和同步使用该 Mote 原已保存的名称、简介和头像。客户端先读取原 topic.md 的准确公开投影及原保存外观的真实静态图像，准备本次明确发布的资料；SOUL、行为设定、Wiki、记忆、其他资料或未保存草稿不自动成为公开简介。准备时读回的文件与头像版本随准确 Mote 来源一起冻结，作为这份资料的准备溯源，不冒充 Host 对当前 App 外观的核对或权限。公共客户端显式提交自备资料而未读取原来源时如实不提供版本，不编造来源观察。来源未知、无保存图像或读取失败时如实说明缺失字段，不借模板、邻居 Mote、当前 Session、屏幕截图或重绘结果填充；手动名称仍沿原创建意图。修改 Mote 本地资料不自动修改平台应用。

Host 校验准确原 Mote 目标、当前操作者及本次资料和真实 PNG，冻结同一份名称、简介、图片与子操作；后续创建、同步及默认保存只消费这份原输入，不重新读取客户端外观或因资料后来改变而替换内容。默认引用保存继续由准确原 File owner 核对原资源与原 baseline，并保真实写入回执。新管理动作的准备失败不影响已配置群收发、私聊或健康 Agent。旧操作保原输入与已冻结子步骤，沿原查询和续接恢复；旧客户端请求是否已派发未确认时保留它并检查原结果，不因新输入合同而删除、补写资料或自动重发。

资料面与原对象入口提供创建机器人、同步公开资料和选择默认身份，并可进入原连接设置管理身份池；设置与 Mote 原入口消费同一身份关系和原操作。动作绑定打开时准确 Mote 与原资源；切换对象、关闭资料面或迟到响应不改绑到后来 Mote，不覆盖后续默认选择或草稿。已创建应用而默认引用保存尚未确认时，继续关联同一原应用与原保存请求，不重复创建。保存、未知及恢复沿原 Mote 偏好和文件／Editor owner，不要求修改默认机器人先选择讨论位置、启动或恢复 Agent。

解绑只清除该 Mote 的默认引用，不删除远端应用、原身份池记录或凭据，也不变更已有群。为已有默认身份的 Mote 重新创建时，明确这是另一个身份及本次默认关联意图，保留旧身份和旧默认，不先解绑；只有新应用创建与本地连接保存均确认后，才沿该原意图更新本 Mote 的默认引用。默认已被后来操作改动时不覆盖，关联结果未知不补建应用，原新身份与原保存请求仍可查看并明确选择。

更改默认身份只影响之后尚未提交的新群提案，不重定向已有 Binding、已提交原意图、grant、平台成员身份或消息。默认引用失效时保原目标与明确改选、管理入口，不静默借另一只机器人；失败不拿走健康 Agent、原资料或工作面。新群选择的精确优先级唯一见[共同对话协议与外部交流入口](conversation-mode.md#共同对话协议与外部交流入口)，应用创建、资料同步及发布的回执边界见[外部对话应用接入](settings-and-observation.md#外部对话应用接入)。

### 外部私聊与会话更新

Mote 的 Profile 提供外部私聊开关、原连接设置中已保存的准确机器人选择、访客会话闲置更新时长与新访客额度。这些策略归同一个持久聊天路由 owner；Executor 复用 Mote 的同一保存偏好，原 `MOTE.md` 中供新群使用的默认机器人与主对话心跳各守原用途。界面明确说明不同设置的适用对象，不复制连接器全局身份、凭据、传输或同步开关。已配置连接器的原生接收、回复、资料和恢复能力分别如实呈现，缺少某项能力不冒称全部可用。读取页面、保存配置和后台查询不启动 Agent，开启私聊也不代签消息已接收、Agent 已采用或回复已送达；全局同步关闭时提供原设置入口。

Profile 明确显示当前私聊配置的托管来源，并允许人明确选择已配置的 Host；读取原公共身份端口确认准确 Runtime 后，配置、身份确认、人员、诊断与连接器管理共用同一来源。已经确认的当前来源不跟随全局设置中最近查看的 Host、平台标签或焦点改变；本机暂时不可读也不封闭明确选择其他已配置来源的读取。切换来源不迁移原请求、未提交编辑或较晚草稿，迟到结果只作用于自己的原来源；缺少原托管记录保持未知，不扫描所有 Host 或借当前默认冒充历史路由。该选择是本次界面的读取上下文，不另建 Mote 到 Host 的业务事实 Store。

政策与个人额度的未提交编辑、明确拒绝后的原稿及较晚修改归客户端同一草稿 owner；关闭资料、切换 Mote 与重新启动后的保全沿[本地持久化合同](persistence.md#保存合同)。请求效果与草稿分别确认，不能把已知拒绝当作未知效果来保留编辑内容。

私聊以原 Mote、原生应用、准确私聊与用户身份确定路由，不因同名机器人、连接别名或当前焦点混合对话。已确认主动消息的准确回复先沿其原作者路由；准确创建者的新普通私聊进入该 Mote 的同一逻辑主对话，先按原主角色 owner 资格化并保留准确角色版本与 Host／Session，在原 Session 合法恢复后、首次 Core claim 时冻结 Run 与原外部输入键，保真实外部作者，不伪装为 App 人工 prompt。主角色后来变化不改投已准入输入；旧私聊 admission 和未知操作仍沿原 generation 续核。主角色未确认或尚未建立时保原入站与建立／恢复入口，不用独立私聊 Agent 补位。其他人的私聊继续按下述独立 lane 工作。一个原生应用同时只有一个启用的 Mote 私聊路由。首次获准消息懒加载新 Agent；距上次真实会话活动不超过配置时长时复用同一 Agent，超过时由下一条消息启动新 Agent。查询、握手、改名与元数据刷新不算聊天活动。新对话使用原 Mote 的保存资料和既有 Core 创建、输入与恢复能力，保留此前 Agent、Run、桌面主对话及原工作面。

复用的 Session 需要恢复时，新的获准私聊在冻结输入目标之前，沿 Core 的原生语义恢复继续同一 Session；不能仅凭原绑定存在就向已中断的 Run 提交，也不能以新建空对话替代恢复。恢复沿本次原入站和原恢复操作重入，不重复扣减额度。健康 Agent 保持可用；明确停止、撤权、目标变化或原生恢复未确认时保留原消息与准确原因。已冻结的旧输入仍守自己的原 Run 和回执，不随这次恢复自动改投或重发。恢复操作只准备原对话，不替外部用户发送额外的继续提示；当前原消息仍由原外部输入 owner 处理。

新 Agent 的首条必需系统上下文列出同一私聊用户此前最近三个对话的准确 Host／AgentSession 引用，以及查询更多历史的公共命令。清单只引用原对话，不复制全部历史正文，不放进可被预算省略的可选上下文，也不混入外部用户的原始消息。历史按该路由和用户分页，原文继续通过原对话读取能力按需取得；陌生人不能借清单取得其他人的私聊。

Profile 提供原私聊记录入口，按人查看已有对话及最后活动，并能进入准确 Host 上的原 Agent。记录已创建或准备完成不表示进程正在运行、消息已提交或已经回复。页面就地解释最近入站停在接收、准备、等待 Agent 还是已接收；配置开启与真实投递状态分开。读取按需分页，保留已知记录和失败原因，不因打开、刷新或选择记录启动新 Agent、恢复旧 Run、改变桌面主对话或重放消息。

原输入记录中尚在等待的请求可由具备权限的用户明确停止该次等待。动作始终使用原 Host、输入和等待代；停止前未派发、只停止观察、已处理或等待代已变化分别按原回执呈现，不能都显示为已取消。该动作不停止 Agent，不删除消息，也不把旧输入转投新的 Run；操作结果未确认时保留原操作供核对。新的私聊消息与旧输入各自遵循原恢复和授权合同。

原生应用范围内已确认的创建者进入同一逻辑主对话并享有无限聊天额度；创建者证明只资格化这两项能力。创建者未知时就地说明，所有外部用户仍按访客策略核对，不因此阻断已明确授权的访客私聊，也不从输入权限、首个发信人、凭据持有人、扫码账号、显示名或其他应用的用户 ID 推定创建者或 Main 关系。默认新访客额度为 0 时不准入，正数作为新来访客的初始个人总额度；可信人／设备也可为已观察到的准确个人明确分配总额度。名单按原配置中的当前创建者证明资格化准确个人，保留已用计数及既有会话；更改默认额度不覆盖已有个人分配。计数按获准进入聊天的唯一原始用户消息持久去重，平台重投、Agent 回复和会话分代不重复扣减或重置。额度的最后一条获准消息仍可完成输入和回答，额度用尽只限制后来的新消息；明确关闭或撤权仍按准确当前政策生效。创建者额外观察失败不清除同一原生应用已确认的事实，应用变化则不借用旧应用的身份。既有 admission、原 Main、会话代次及未知效果继续沿原身份和原操作核对。 原访客后来得到准确创建者证明时，保留已用计数并按创建者无限额度处理。原应用确认了另一位创建者时，旧创建者按访客处理；其当前个人总额度为无限时，以当前明确保存的新访客额度形成有限总额度，保留已用计数并据此计算剩余额度，默认 0 不准入新消息。原有有限个人额度不因默认值改变而覆盖。名单、准入和个人分配沿同一当前资格化规则，既有分配操作、admission、grant 和会话不改写；创建者补充观察未知不触发降格。

聊天政策的普通保存只消费原资源、准确 Connection、管理权限与修订，不在线读取创建者资料；同一应用沿用已确认的创建者证明，切换应用后保持未确认。人或可信设备可沿同一配置 owner 明确请求刷新原生创建者资格，本次必须取得准确应用与修订下的证明；未确认时只拒绝这次刷新意图，保原配置、已确认身份与原操作，不用旧证明冒称本次刷新成功。该明确请求可以包含同一授权范围内的政策修改；界面的独立身份动作使用已保存政策，保留另有的编辑草稿。身份刷新与政策保存各保原请求；尚未确认的刷新不封闭独立政策保存，较新政策已写入时，旧刷新沿原 CAS 拒绝，不自动换修订重放，也不在后台悄悄改变权限。

聊天配置、额度、创建预留、各代 Session 和未知结果均沿原操作持久保留。并发首条消息只创建一个 Agent，创建或投递回执未知时继续核对同一原请求，不另建身份。旧代输入和迟到回复使用各自冻结的 binding、grant 和目标，不因新代成为当前入口而改投或丢失；收发继续复用原持久 ingress、Core 输入队列与 publication，不另造消息流水或 Runtime。关闭聊天保留配置、额度、历史和健康 Agent，失败只作用于本次准确操作并给出可恢复原因。

本人私聊的回复显式关联原入站：原准确收件 Agent 沿公共 reply 能力向原应用、原会话、原作者回复，唯一发布 owner 保存操作与效果回执，未知时只核对原操作。可信输入上下文提供准确原入站引用与能力入口，引用不代替调用者与原 claim 校验。仅有已保管的 claim 不能授权外发，原 Core 输入回执须确认该准确输入已投递；原回复操作与每个发布片段分别保留回执，错误受众、原入站、Host／Session、binding 或片段序号／总数不能被当作该原回复的结果。

新显式回复的发布记录同时保留已认证的原 Agent 作者与执行 Host／Session，每个片段沿同一作者呈现。名称、头像是可选的原资料观察，读取失败保原作者及正常回复能力，不从后来 Main 或正文填补；原保存、prepared 或未知效果保持原快照，不因资料更新补写或重发。

Main 跨语义 Host 时，普通私聊仍沿原 Core 与原入站 authority 输入，不因缺少回复回程而阻断健康 Main。当前执行端点未确认到原连接器 owner 的回复路由时，可信上下文只保原引用，事件与诊断的当前 `noticeCode` 说明 `MOTE_CHAT_REPLY_ROUTE_UNCONFIRMED`，不覆盖原入站 `code` 或已确认的输入回执；这不是输入失败或 Main 停止，也不允许猜另一个 Host、会话或收件人。跨 Host 自动选择原连接器端点的回程尚未接通；显式到达原 hosting 端点的调用可复用其现有认证，核原收件 Session capability、合法恢复、原入站与原 Core 投递回执后，向原人回复。默认执行端点回程未确认不撤销这条准确显式调用的资格；双向读取入站 authority 本身仍不等于外发授权。

Main 的 App 输入、心跳、其他输入、工具过程和无关后续回复不会因这条本人路由自动发往私聊；本人路由不建立普通全会话发布关系，也不撤销 Main 的内部感知与协调能力。原连接器 owner 中若已有该准确 Main 的普通外发关系（包括可恢复的 paused 关系或旧私聊 lane），新私聊保原消息并说明 `MOTE_CHAT_MAIN_EXTERNAL_AUDIENCE`，在准入事务与 Core 原输入／重入授权处复核；不自动解除关系、停止 Run 或更换 Agent。用户沿原 Mote 主对话详情取得 Main 的原 Host／Session，再在原 hosting 端点用 `connection binding ls --session SID` 列出本 owner 各 Host 路由的同 SID 关系，inspect 准确关系及已保存的 `executionRuntimeId`；不同 Host 别名若确认同 Runtime／Session，仍属于同一发布来源。用户明确处理后重试原入站。这个资格检查只陈述本原 owner 的事实，不是全局保密隔离；其他 owner 之前或之后经原人／device 明确授权的独立导出仍归其原授权。本次新输入资格不撤销此前合法保存的原人显式 reply intent 或读取旧回执的资格。不同 Provider 消费同一边界，缺少原生采用／回复关联时不用正文、时间或相邻回合猜测归属。

### 主动感知与外部沟通

Mote 是主动的协作者，不是被叫到才回答的机器人。它从自己所在的会话和本地环境感知发生的事，串联相关上下文，借 AgentMux 的能力把需要做的事转成任务，并在合适的时机经连接器找人沟通。例如，一件事在一个群里讨论过，另一个平台的社群又有人反馈同一问题；Mote 把两者联系起来，并在代码托管上发现一个已提交、合入后就能解决的变更，于是主动向用户说明情况，同时安排成员审阅这个变更，用户确认后再执行合入。

感知来源有三类：Mote 机器人所在的私聊和群里平台实际投递给它的消息（平台未授予机器人读取群内全部消息时，只有 @ 它的消息）；该 Mote 执行身份在本地环境中可用的账户、命令行工具与权限，由 Agent 按需主动查询；以及成员结果、Goal 与安排等原有回流。连接器消息沿原持久入站记录形成 Mote 的事件读取：范围是该 Mote 聊天路由的原生应用收到的全部会话，按收到顺序分页，每条带会话（私聊或群及其准确 ID）、作者、正文、寻址（@、回复或普通消息）、被回复的消息、原平台消息引用，以及原处理目标 Agent 引用；目标引用本身不是已投递回执。它是原记录的只读投影，不复制消息、不另建事件库；读取不启动、恢复或输入任何 Agent。消息分页与计数的工作量随本页增长；成员资格沿原空间 owner 查询，稳定空间文件不重复解码或遍历全图，原文件变化后重新核对，不复用旧权限。

事件读取只对用户本人和该 Mote 的主 Agent 与成员开放；服务外部受众的 Agent 不能读取其他会话的事件。服务外部受众的 Agent 包括私聊与群对话 Agent，也包括有未解除普通群关系的 Agent：它之后的回复会发布到那个群，暂停的关系恢复后同样如此。因群关系拒绝时指出是哪个关系，并说明可以解除该关系，或改由没有群关系的成员读取。事件正文是外部内容，不构成指令、授权或已确认知识：外部消息里的要求只是线索，需要行动时仍沿原授权。一个会话的内容默认只向创建者汇报；带进另一个会话（另一个群或其他人的私聊）须创建者明确同意。

Mote 保存一份单调前进的“已查看”进度，主 Agent 看完一批事件后明确推进，用户在 Profile 可见进度和之后的新事件。主 Agent 的内部心跳检查目标与承诺时一并查看未查看的事件，没有新事件就保持安静；感知不另开计时器，也不逐条消息唤醒 Agent。需要持续关注的具体事情，主 Agent 沿原调度给自己安排有明确用途和期限的回看。

判断需要行动时，主 Agent 沿原能力把事情转成任务：建立或更新 Goal、派成员（例如审阅 Agent）、给自己安排回看，成员结果沿原回流。合入、发布、对外发言、删除或付款等有外部后果的动作，先向创建者说明依据和影响并取得明确确认；外部事件、成员转述或以往的默认都不能代替这次确认。

需要告诉创建者时，主 Agent 与成员可通过该 Mote 的机器人给创建者发私聊消息，说明发生了什么、已经做了什么、需要创建者决定什么；这是向创建者本人汇报，不是对外发言，也不扩大心跳或安排的授权。每条消息沿原操作持久保存作者 Agent、正文、平台消息与投递结果；投递结果未确认时只核对原操作，不重发。创建者尚未与该机器人私聊过时如实说明无法送达，不改用其他会话或身份。创建者回复这条消息时，回复以创建者本人的身份作为输入交给发出它的原 Agent，不进入私聊会话 Agent，也不把该 Agent 的其他回复转发到私聊；不是回复的新消息仍按私聊路由。主动消息遵循“有分寸的跟进”：有具体事实才发，不叠问、不刷屏，同一决定不在多处重复催问。服务外部受众的 Agent（范围同上）不能使用这项能力。

### 群聊中的独立协作者

Mote 的原机器人被拉进群后，在群里作为独立协作者工作：群消息首先是上节的感知事件；有人在群里直接找它时，它在该群就地回应，需要时把事情转给主 Agent 与成员，并在有结果或需要确认时回到原群说明。

群对话与私聊共用同一持久聊天路由 owner，以原 Mote、原生应用与准确群确定。每个群一段持续对话：首条获准请求懒建 Agent，之后的群消息复用同一 Agent，不按私聊的“会话更新时间”分代；原 Agent 被明确结束后，后续获准请求启动新 Agent，并在其首条系统上下文中引用此前的群对话。群与群、群与私聊、群与桌面主对话不共享对话历史；Mote 身份与 SOUL、行为设定、MEMORY 等耐久资料仍是同一份，新 Agent 按[会话入口与原文件记忆](#会话入口与原文件记忆)读取。用户已明确连接到某个 Agent 的群（任一状态的普通群关系）继续归原关系，Mote 群对话不接管、不并存；之后明确建立的群关系同样优先。群内话题暂不另分对话。

入站确认路径只做本地索引查找；创建 Agent 和恢复原 Run 发生在确认之后，且只为获准请求执行。无关群消息不启动、不恢复 Agent，一个群的消息量不放大其他 Mote、群或私聊的工作量。

Profile 的聊天设置提供“群聊”开关，随该 Mote 的聊天路由保存；默认开启，只对下述获准的人生效。关闭只停止该路由的群请求，保留已有群对话、Agent 与记录，重新开启后原群对话继续可用。

能让它做事的人是已确认的应用创建者，以及在该机器人应用成员访问中明确获准“发送请求”的成员；获准成员 @ 机器人或回复机器人消息时形成请求。其他成员的发言和未寻址的消息只进入该群的共同记录，在之后的请求中作为前文引用，不取得输入、回答或权限资格，也不触发群对话 Agent。陌生人额度只用于私聊。

群对话的正常回复共享到该群；它为本群请求安排的成员工作、自己设定的回看与结果回报都回到同一群对话，再由它在群里说明。回看沿原调度能力，只服务本群交给它的事，不定时群发或逐次汇报。

回复对群里所有成员可见。群消息、引用的前文和其他成员的说法不是已确认知识，没有创建者在群里确认时不写入 MEMORY 或 Wiki；除非创建者在该群明确要求，不在群里披露创建者的私有资料、文件或其他对话。逐场合的回写控制及其在真实写入路径上的执行尚未实现，当前不能以提示词代签“已强制只读”。

Profile 的聊天记录另列群对话，显示群名、最后活动和准确 Host／Agent，并能进入原 Agent；群对话不计入发起人的私聊记录。读取与私聊记录同样按需分页，不因打开记录启动 Agent、恢复旧 Run 或重放消息。

以下方向尚未实现：同一 Mote 同时使用多个平台应用的机器人（每个原生应用一条聊天路由，感知与沟通跨应用串联）；主动在群里发言；`@所有人` 的通用广播寻址（适配器给出原生提及事实，单独配置，默认不响应）；群里关注全部消息并只在相关时回复（需要明确的“不回复”机器协议，且与 Core 原输入、队列和回执合同一致）；逐场合回写控制（在独立工作目录与 Provider 写入限制上真实生效，不支持强制的 Provider 如实说明）；群内话题分对话，以及入群时的自我介绍。

### 内置群聊与 Mote 群内视角

内置群聊是有自己身份、成员与公开历史的独立会话。创建时选择参与的 Mote 并保存群与成员关系。即使群成员完全相同，也能创建各有历史的群。主持、分工和谁参与一条消息由用户决定。

- **群聊视角。** 会话列表按群显示一行，带群名与最近一条公开消息。点行打开群，点群头像查看群资料与成员。用户在群里发送时使用自己的身份，在自己的阅读视图中署名「我」。Mote 的公开回复以该 Mote 的身份署名，保留原执行来源以供核对。每条公开消息由同一个群保存一次，引用或切换视角沿原消息身份读取。
- **Mote 视角。** 同一个群与一个 Mote 对应一个可持续的群内 Thread Agent。Mote 实际参与时建立或接回原会话。Mote 的 Threads 按群提供入口，用户可查该 Mote 实际收到的群消息、它在群里的工作过程，以及哪些回复已公开发回群。已确认的发回结果可直接定位原群消息。单纯打开群或切换视角只阅读，原群草稿与个人阅读位置各自保留。
- **上下文与接续。** 群内 Thread 使用本群获准读取的消息与该 Mote 获准使用的资料。群、其他群及 Mote 主对话各有独立会话历史与受众。原输入引用、公开回复与实际执行分别核对。原群历史按需可读，需要继续执行时接回已绑定的原 Session。某个成员的执行缺口只影响该成员，公共历史与其他成员各自可用。
- **本次投递与公开回执。** 发送前可确认本次发送邀请哪些成员参与。原操作保存群、作者、正文与本次选中的成员，成员后续变化不改投原操作。共享消息确认保存后可独立读回，各成员的准备、实际接纳、处理与公开回复各保原会话和回执。成员暂不可用时保留原消息，并在准确成员处说明进度或未确认结果。公开回复一次，Thread 中的回复可回到原群消息。重启和重试沿原群、成员 Session 与操作身份核对，已确认的公开消息只读回，未知投递持续核对原回执。Desktop、Mobile 与公共 RPC／CLI 读取同一群与成员事实，公共入口保留准确对象、原操作及回访路径。
- **群头像、公告与邀请。** 建群时可保留默认群标记，或指定一至四位成员，以其真实 Mote 头像组成统一群头像。群保存头像配置和当前公告。公告更新以系统身份在原公开历史记录一次通知。邀请准确 Mote 入群时，原邀请携带该次确认的当前公告与群引用，经 AMUX Note 落入该 Mote 的原逻辑收件箱。邀请、公告和消息公开各保原操作及读回依据，读取或查看收件状态不启动 Agent。
- **群管理与 Topic 文件。** 原用户和明确配置的群管理 Mote 可邀请成员或移除其他成员。管理 Mote 的操作由当前准确群内 Thread 证明身份和授权，每位 Mote 可从自己的原 Thread 退出。离开后原成员身份和公开历史保留，停止新的群输入并收回群操作和文件授权，保留已接纳的原操作回执和健康 Run。群可绑定已经存在的原 Topic，群文件沿绑定对象的准确范围、Files owner 和原授权读写。绑定和成员操作经同一群 owner 保存，Desktop、Mobile、公共 CLI 和随部署的 Agent 使用指南消费相同管理权限和原回执。

## Topic 与 Mote 的物理目录

Scratch 逻辑容器的原 Host 与根不由普通 Folder 重新绑定或通用配置编辑改写；目录读取失败时保留准确原根与工作面，不能把某个 Mote 的 home 选成容器根来修复观察。已有不一致分别核对原目录身份、原请求与实际保存结果，不按当前嵌套目录猜着修复。

普通 Topic 的 canonical 文件目录在 `~/.agentmux/topics`，Mote 在 `~/.agentmux/motes`，两者与 Scratch 逻辑容器的原物理根 `~/.agentmux/scratch` 并列。已有对象的目录分离和 Mote 历史软链接的撤除已获用户明确授权。撤除前须确认同一 Mote 的资料、工作面、原会话恢复和日程在旧链接缺失时仍可用；有未确认依赖的链接继续保留，独立对象可各自完成。该授权限于这批 Mote 旧链接。目录身份记录、原子交换与记录升级的当前机制见架构文档[《空间状态与导航机制》](../../architecture/spatial-state.md)，本节只定义必须成立的结果。归类沿已有文件事实：主 Mote 与已确认含 SOUL 的对象是 Mote，已归档对象同样迁移；分类读取失败保持未知，不当普通 Topic 猜着搬。内容组织仍自主，不改写用户知识文件或强制分类。

- **Mote 使用稳定的物理短名。** Mote 的 canonical 路径为 `~/.agentmux/motes/<持久 Mote ID 的短哈希>`，从完整、已确认的内容 ID 导出，不使用 Topic／Launcher 技术前缀，不随改名、关闭或新建讨论、切换 Agent Session 改变。短名只用于目录索引，不能代替完整对象 ID；同名目标必须核对同一对象，碰撞、未知记录或别的对象不能被覆盖或冒认。新对象直接使用自己的 canonical 短目录身份；现有对象改物理名时保各自准确原身份、资料、头像、归档、全部展示绑定及历史执行 cwd。完整内容 ID 与相对原根的身份定位由原 app-owned 目录元数据保存，不能写绝对路径、另建身份名册或从短哈希反造 ID。发现与公开查询只读；记录缺失、损坏或未确认时保已确认对象和工作面并说明恢复动作，不能以当前物理地址重铸身份。具体摘要算法与长度由实现负责，不作为其他对象的通用命名限制。

- **展示身份与物理地址分开。** `__scratch__` Workspace 保留原 Scratch 逻辑容器地址与 ID；物理目录迁移本身保既有 Topic/Mote 内容身份、空间实体、选择、草稿、文件逻辑引用与执行绑定。普通 Topic 到 Category→Topic 的空间层级承接是另一个明确动作，旧普通 Topic Space 节点转换与原内容 ID 保留只见[《Topics 知识库的层级与沉淀》](spaces-and-layout.md#topics-知识库的层级与沉淀)，不据旧文件 alias 保留永久旧空间 owner。Snapshot 明确给出实际物理目录，真实 IO、新启动 cwd 与公开查询的对象 path 消费该地址；公开查询只投影原协议字段，不泄漏内部路径元数据；原相对文件地址仍由同一受限文件 owner 解析，不按背景项目或显示位置猜对象。新对象直接写入对应 canonical 根，不先创建旧实体再搬。
- **迁移保留原对象。** 迁移已确认的旧目录时保留原对象本身（同一 inode 与完整内容），不覆盖已有目标。需要暂留旧入口时，在同一次原子交换中将已有物理地址直接连到 canonical 地址，避免制造中间路径；`topic.md`、SOUL、Wiki、`.agents`、`.agentmux`、头像资产、归档和任意用户文件不重建、不清洗、不丢弃。当前平台不能原子完成这一步时，迁移拒绝执行并保留原有工作能力。
- **目录身份记录。** 对象的目录身份由对象内的一份 app-owned 记录保持。记录不写绝对路径，只保存完整内容 ID、相对于原逻辑容器的已校验定位及核对依据，由原 Workspace 的登记地址解析回同一个既有目录身份，保原头像与 Space／Zone 地址；即使将来删除旧链接也不重发身份。原逻辑根、目标目录名与记录必须一致，不能改用当前物理地址、另一根目录或同名对象重铸身份；记录须在 canonical 对象暴露前耐久保存。旧格式中保存绝对路径的记录，只在原目录 owner 严格确认原根、原对象及原记录后无损重编码；失败、冲突或保存未确认时保原记录、内容与工作面，不以删除记录或重建对象完成升级。公开读取和目录发现保持只读，不暗中改写文件。记录不成为 Session／Run 或第二份工作面事实，损坏或未知时不得退回物理地址重铸身份。新对象直接使用自己的 canonical 目录身份。冲突、失败或无法确认的步骤如实可恢复，不能覆盖已有目标、将部分结果称为完成、跳过对象不说明，或删除未确认的原数据。
- **记录维护的确认与恢复。** 升级中的原记录保留为这次操作的待确认见证，不成为第二份身份表；并发替换、中断或耐久保存未确认时保留实际原字节，不能覆盖后来出现的记录。即使新格式已可读取，只要本次操作仍未确认，冷读取与公开观察仍保原可确认身份和持续说明；没有准确见证时沿原工作面绑定保未知，不借当前物理地址重发身份。恢复沿同一原目录维护入口核对实际记录、原对象及耐久保存后解除说明，公开查询不执行修复。
- **历史执行与恢复分别保全。** 已有 Run 的执行 cwd 与输入按原记录保全，迁移不停止、重启或改写健康执行。新启动使用 canonical cwd，经 Core 原公共能力创建。撤除旧链接前，由 Core 核对原 Session 和 Provider 原生来源能否在实体目录续接，保留原 Session、工作面、日程和未知操作的身份。撤除检查包含经另一软链接间接使用该地址的入口；只删已核准的链接本身。
- **旧 alias 不放宽文件边界。** ScratchTopics 与通用文件入口共用 Main 的受限目录解析，只接受已确认身份、精确旧直系目录与相应 canonical 目标的映射；读取仍遵守原已允许的 explicit 只读链接能力；任意链接不因此获得变更权限或新增可访问范围，被替换的根/目标及逃逸继续按原权限与路径规则拒绝。主 Mote 的删除／移动保护、头像资产范围及原保存冲突检查仍成立；失败只拒绝这次错误目标的动作，不拿走健康 Agent 与原工作面。
- **自有目录预置原生信任。** Mote 与 Topic 的家目录由 AgentMux 创建和持有；在其中启动会询问目录信任的 Provider 时，Core 在启动前经该 Provider 的原生信任记录预先认可 Host 按自己的目录身份确认的那一个家目录（按解析软链接后的真实路径记录），效果等同于人在信任提示中选择信任。只有确认的家目录本身才预置：Scratch 根目录本身、根下未被确认为家目录的仓库、用户 Project 目录、家目录内嵌套的外来仓库、经软链接逃出家目录的路径都不预置，保留原生提示。预置只写 Provider 自己的那一条信任记录、沿其原生写锁并保留其余配置。家目录资格以 Host 确认的准确对象和真实路径为准，合法原别名不失去资格；字符串路径前缀不能把家目录内的外来仓库或链接逃逸扩成自有目录。读取、加锁或写入未确认时保留原启动与健康能力，将未确认步骤交给[透明启动的就地服务说明](#透明启动与需要用户继续的步骤)，不以必须操作终端作为普通用户唯一的继续方式。

## Mote 头像与主 Mote

用户明确保存的头像来源与选择在应用换包、重启后仍可读回，不以 Renderer 的临时环境作为唯一保存依据。重开编辑器选中同一已保存图片、图标、捏脸或自动来源；进入编辑器本身不切到预制脸、不覆盖选择。原耐久配置持有选中事实，目录资产仍由原文件 owner 持有；旧已保存选择的保全转接不能复活用户后来清除的值。读取或保存未确认时保已确认外观与编辑草稿，给出原目标的恢复说明。

用户可以为同一 Mote 更换本地图片头像、预览最终圆形显示、明确保存或取消，并恢复默认外观。头像属于原耐久 Mote 身份，卡片/头像两态左栏、交流身份区、Space 树与完整 Space 的对象头像槽使用同一已选外观；图像、名称、类型、真实执行状态和展开/选中状态各自表达，不把 Session/Provider 头像当成 Mote 身份。选择沿既有外观 owner 持有，原图标、图片和捏脸外观是同一互斥选择，图像资产属于同一 Mote 耐久目录，不新增身份名册、第二份当前选择或 SOUL 人格字段。编辑和异步保存绑定明确原对象；未保存草稿不改变其它入口，取消不写入，读取/保存失败保原已确认头像和待保存选择，说明未确认与重试动作，不阻挡原工作面或健康 Agent。换头像不启动/停止 Run，不改原目标、Tab/Region、执行历史、草稿、SOUL/Wiki 或授权；本条不扩展联网生成或另一套人格系统，状态表情遵守下述约束。

`Icon or image` 提供一组与默认 Mote 同一身份家族的内置静态图像，风格清单与构成只见[同主题呈现](../presentation/motes-and-coordination.md#mote-头像与主-mote)；默认图形自身不变。直接点击候选进入原图像预览与裁剪，只有明确保存才写入该 Mote 的原耐久图像与外观选择；取消、读取失败及切换候选不替换原已确认头像。候选来自现有头像源目录与预览能力，不要求先配置系列，不新增外观注册表。

主 Mote 未自定义及恢复自动时使用[共同默认身份规范](../presentation/shared-rules.md#mote-默认身份与装饰徽标)，不按名称或运行状态替换主身份；已保存的用户图片、图标或捏脸选择优先，主 Mote 也可以明确捏脸或上传。Mote 的原头像编辑入口提供可预见的部件编辑和同一保存/取消/默认语义；普通 Project、Folder、Topic 不出现 Mote 捏脸。捏脸提供更多可辨的五官、轮廓或配饰选择，沿同一外观选择保存；新增选项保留所有已保存的部件组合，不要求用户重新编辑或把旧脸换成默认脸。部件外观与短暂表情分开，动画不改写保存的脸型或五官选择，切状态后仍能认出同一位 Mote。

头像编辑（Change Avatar）提供 `Icon or image`、`Make a face`、`Series` 三种方式，排列与切换样式见呈现合同。重开编辑器按已保存来源进入对应方式：已保存捏脸进入 `Make a face`，已保存系列进入 `Series`，自动默认、已保存图标或图片进入 `Icon or image`；各方式保留自己的本地草稿，切换到 `Make a face` 时呈现明确所见的 Face 草稿，`Save face` 保存当前所见外观，不增加第二个确认动作。点击 `Restore automatic` 将草稿重置为自动默认外观，保持当前所在方式页签不强制跳转。打开、取消或仅切换方式均不写持久外观；保存沿原外观 owner、对象异步边界与失败保全。编辑面布局、切换效果与控件视觉唯一见 surface-density[《Mote 头像与主 Mote》](../presentation/motes-and-coordination.md#mote-头像与主-mote)。

Mote 头像平时也会偶尔活动：实际可见的日常身份头像不要求鼠标靠近或 Agent 正在工作才有局部动作，Make a face 沿原五官关节表达短暂神态，已保存角色、上传图片与手选图形可有不损害辨识的轻微姿态，不推断图片五官或改写保存外观。待机动作与运行事实分开，不借活动伪装 Working、工具调用、在线或恢复成功；睡态仍可辨为睡态，待回复与未知只用中性短动作并保原眉嘴及说明，不能被好奇或笑脸覆盖；错误和已停止不叠加日常动作并保持可辨。已确认没有 Agent 的初始 launcher/空态呈现睡觉，已结束的进程仍明确说明“已停止”；保存目标或 Session 暂未恢复不当作未启动。Working 呈现思考；当前准确 Agent 的真实在途工具事件可联动表情，工具完成或失败后不继续伪装仍在调用。历史工具、另一位 Agent、旧 Run、迟到事件或缺失出处不能冒充当前调用；无可确认工具事实时仍表达原真实运行状态。Starting、待用户处理、Blocked、Error、Disconnected、恢复未知及进程运行但语义未知分别可辨，不把未知猜成 Idle、睡觉或成功；表情和颜色不替代原状态说明及请求/服务窗。动作强度与日常节奏只见 surface-density[《Mote 头像与主 Mote》](../presentation/motes-and-coordination.md#mote-头像与主-mote)。

`Icon or image` 的图库提供 low-poly 角色图片候选，与本地图片、原图标选择同处一个方式；它们仍沿原图片／外观 owner 和明确保存动作成为同一 Mote 的外观，不增加头像身份、人格字段或独立保存机制。现有二维 `Make a face` 继续可选，保留原可组合部件与保存、取消、默认语义；新的角色系列可以同时提供图像和可捏脸外观，具体形态和材质沿[同主题呈现](../presentation/motes-and-coordination.md#mote-头像与主-mote)。新增角色、系列或调整捏脸风格保留已保存图片、图标、脸型、配色和全部部件组合；编辑时准确读回原选择，任何候选都要由用户明确保存后才替换外观。图库图片与可组合脸分别消费各自已有动态能力，静态角色图片不冒充五官骨骼动画。恢复自动仍沿本节同一默认规则，不替换任何尚未清除的显式外观。

头像系列从本 Host 的 `~/.agentmux/avatars/<series>/` 专用素材根发现，以子目录表达系列；用户或 Agent 放入的一组正规 PNG／JPEG 头像可以作为可选来源，只有图片的目录无需声明文件。同一系列可通过受限纯数据声明提供图片、现有二维捏脸预设与成熟 GLB 的可编辑外观，后续系列与 user mods 沿同一数据边界扩展。可编辑资格只取准确资产的原生部件或 morph／材质参数及已实现解析／渲染能力，显示名称、缩略图和文案不授予该资格；缺失能力不编造控制项，不执行来源中的任意代码。发现只读，不创建 Mote、AgentSession 或 Run，不按系列名重铸身份，也不自动保存或替换外观。准确头像选择仍由原外观 owner 持有，目录、素材或可选声明暂不可读时保已保存选择与草稿，明确受影响的准确来源及恢复动作，其他可用来源与原工作面继续可用。具体声明字段、格式与支持的原生参数由[公开数据合同](../../specs/mote-avatar-series.md)定义，不由素材授予权限、运行状态或执行能力。

保存系列外观时，原外观选择同时保留准确来源与内容版本、原可编辑参数及已保存图像；PNG 沿原对象图片 owner 保存，选择沿原耐久配置 owner 发布，不增加第二份当前选择。删除、替换或暂缺 mod 不改变已保存图像或原参数；原来源不可确认时继续显示原保存头像，明确可编辑来源未确认或不可用，恢复的是同一准确版本而非同名新素材。切系列、预览与取消均不写入；未确认保存保留原已确认外观、原请求与草稿，通过同一原对象和操作核对，不以重新生成默认头像、换操作身份或另建 Session 完成恢复。公开发现、预览、保存与读取消费同一原 owner，图像写成、当前选择观察、原操作回执与磁盘耐久确认分别表达。

用户可从系列选择面明确添加自定义系列。添加面说明专用素材目录、普通图片与混合系列的用法，并提供创建目录及初始示例的动作；创建只发生在原 Host 的头像素材根下一个准确的新子目录，不覆盖已有目录或文件。完成后刷新并选中该系列，用户仍须明确保存头像才改变原 Mote 外观。取消教程不写素材；写入或打开目录失败时保留已写内容、编辑草稿和其他可用系列，准确说明该步骤及原路径。目录创建与示例内容由公开头像素材 owner 提供，图形界面和 Agent 消费同一边界；打开目录是独立的明确动作，不创建工作区、Mote、Session 或 Run。

Mote 的手选图形与自定义图片沿同一原头像动态 owner 支持轻微待机动作和指针附近的朝向响应；响应仅改变临时呈现，不推断图片五官、改写保存外观或把睡态／未知表达成醒来与正常运行。普通 Topic 图标不因这项能力加入头像动态。

仅实际可见的对象头像槽消费其准确目标状态与必要工具事实，常驻品牌入口沿本专题入口／对象的分工；隐藏实例、头像滚出可见范围、页面隐藏或减少动态偏好下停止动态并保留可辨静态状态，可见的左下品牌入口可保不代称目标执行事实的轻姿态，不因浮窗收起而强制隐藏。消息历史中的作者头像继续保原色与静态身份，不因本条为每条历史消息新增动画或 Session 消费。动画不增加全局轮询、逐头像 JavaScript 帧循环、整份 Timeline 订阅或无关 Session 的工作放大，不触发 fit/Runtime resize、不改变输入焦点、草稿、授权或生命周期。视觉、动画强度与控件密度唯一见 surface-density[《Mote 头像与主 Mote》](../presentation/motes-and-coordination.md#mote-头像与主-mote)。

捏脸（Make a face）的头像采用内部五官可组合的骨骼／关节式连续变化：平时有表情和神态变化，鼠标靠近时视线会看向指针，变化中仍能认出保存的同一张脸；不能用整图帧替换、整头旋转或遮脸装饰冒充这种能力。鼠标靠近只使附近准确可见的捏脸实例局部响应，视线与真实运行状态的临时表情组合而不覆盖待处理、错误或未知提示；不把鼠标互动伪造为 Agent 工作或工具事实。隐藏、离屏、页面不可见与 reduced-motion 停止动态，退出附近恢复原状态；不为无关隐藏实例增加 pointer listener、rAF、轮询或 Timeline 消费，沿前述相关成本与输入／生命周期保全。图片与图标仍沿原语义，不硬贴捏脸五官或改变原图片。

### 主 Mote

主 Mote 是默认就有、用户不可删除的 Mote。它使用原默认 Mote 的固定身份（代码名 `launcher:leader`），由既有目录 owner 在普通启动时幂等提供，同一对象仍在创建时重复请求等待原结果，结束后不缓存过时快照；失败保原内容并可明确重试，不能把尚未完成的创建误报为外来对象，不按名称、列表首项、Session 或是否正在运行猜主身份，也不另建数据库。新环境默认有主 Mote；已有目录的 SOUL、头像、Wiki、资料和原工作面保留，目录缺失、读取失败或恢复状态未知需沿服务窗明确实际步骤，不把未知当成新环境覆盖用户内容或宣称原内容已经恢复。应用内删除主 Mote 目录、删除包含它的祖先，或通过移动/改路径/覆盖令该身份消失都不可执行；保护落在原唯一目录变更服务，精确地址及其合法别名同等受保护。标题改名、内部用户文件正常操作、头像更换/恢复默认、关闭主 Mote 的 Tab、收起浮窗仍合法；其他自定义 Mote 沿原管理行为，不因主身份保护锁住 Session/Run 或重建健康 Agent。控件与密度只见 surface-density[《Mote 头像与主 Mote》](../presentation/motes-and-coordination.md#mote-头像与主-mote)。

## Mote 归档与恢复

自定义 Mote 可以明确归档、在原 Mote 管理面发现已归档对象并恢复；恢复的是同一个耐久目录身份，不是复制或重新创建。归档把它从常用 Mote 列表和新目标推荐中收起，原 Space 的 Motes 区始终有可发现的“显示已归档”与恢复路径。普通 Topic 不因这条需求获得归档行为，关 Tab、收起浮窗、删除目录与归档各有独立含义。

归档状态由原 Mote 目录 owner 持有；目录、头像、SOUL、Wiki、资料、固定/排序偏好与完整身份快照保留。已打开或明确选择的同一 Mote、Tab/Region、其他已有位置、执行历史、未发送草稿与健康 Session/Run 保持；当前归档对象仍可辨其状态、继续原工作面并恢复，不因它退出常用列表而判为丢失、自动切换目标、重新创建或停止 Agent。新选择不主动推荐已归档对象，已有明确目标及在途请求不被另一位 Mote 替换。

归档/恢复只有原对象的持久写入和读取确认后才表达成功；未确认时保原已确认状态与可用工作面。读取失败、状态未知、保存失败或迟到结果需说明实际步骤、当前已确认/未知事实与重试动作，不能把未知当未归档、把未知读取当恢复成功，或让旧请求覆盖后来已确认的状态。重新载入仍能读回归档事实、发现并恢复原对象；不另建身份名册、第二份归档选择或复制执行状态。

主 Mote 继续沿[《主 Mote》](#主-mote)的固定默认身份存在，不能被归档后隐去，以保留默认可达入口。这是设计判断，不是用户关于归档的原话。这一限制不影响关闭其 Tab、收起浮窗、换头像、修改标题或正常内部文件操作。应用服务最终边界同样保护主身份，不能只隐藏菜单。控件语言、Space 最小宽度下的名称／归档状态与次要动作入口见 surface-density[《Mote 归档与恢复》](../presentation/motes-and-coordination.md#mote-归档与恢复)。

## 主 Mote 与 Goals 协作

主 Mote 保原 `launcher:leader` 耐久身份、目录、SOUL、Wiki、头像与资料；历史 Leader Topic／PMO teams topic 只表示同一协调对象的旧称。主 Mote 可以读取全局 Project、Goal 与 Agent 事实，不因背景 Scratch、活动项目或名称变化改目标；其中 Agent 仍是经 Core 公共能力运行的正常 AgentSession，不另建隐藏 Runtime。

用户可直接与 Mote 讨论，意图与授权未足够时轻量澄清，不先造空 Goal／Project。显式 New Goal 则先保存真实待定义 Goal，再进入同一主 Mote 内该 Goal 的专属讨论 Tab；两条创建边界、真实 bot 配置、Project 上下文及未知恢复唯一见[Goals 的显式新建与专属讨论](goals.md#显式新建与专属讨论)。Mote 讨论的创建／更新结果、准确 Project、分析依据与关联 Session 在对话和目标详情可追踪，不把任务分派变成不可见副作用。

Goals 的主实体为 Goal，底层沿 Demand 身份；它不再以 Branch／Topic × Agent 状态矩阵组织，也不属于另一 Agents／Session／Board 全局导航。目标摘要、数量和空态只消费持久 Demand：零目标不把 `main` 或任意 Branch 当需求行；状态、筛选与路由队列见[Goals](goals.md#状态筛选与路由队列)，执行观察见[Goal 执行与监督](goal-execution-and-supervision.md#goal-详情中的-session-观察投影)。Mote 快捷面不是 Goals 总览的替代。

## PMO teams topic 名称与职责

Mote 的主 Agent 默认与人讨论需求、组织执行 Agent、分配工作并持续跟进结果；PMO 是协调角色，其他成员保各自实际职责，普通 Topic 不继承它。Mote 保自己的 Space，普通 Topic 是 Category 中的 Zone；复用文件、公共能力或 Scratch 不改变身份和成员归属。

主 Agent 先发现准确 Project、Executor、Session、Tab／Region 和已有能力，再提出可检查的分工。范围、位置、风险或授权缺失且影响下一步时才追问；用户已经明确授权的有限创建、分配与推进直接执行，目标确认与结果接受各自成立，不反复索取原授权，也不替人认可。默认细设计和实现交给执行成员，主 Agent 继续讨论、组织、跟进和取证；只有用户明确要求主 Agent 亲自实现时才由其承担该项实现。未知能力、身份、投递或结果保原工作面与健康 Agent，不猜成功、不用直接配置写入绕过公共 owner。

真实项目目录及最小初始指令、项目注册、同一 Demand 绑定、执行 Session 创建／复用、首任务投递与结果核验分别留下实际事实。项目注册不证明目录已建，记录指派不证明送达，Session／Run 退出不证明目标达成。一次未知 create／start／发送先读原操作和实体，不自动重放；准确上下文与通用职责在新讨论和复用原会话的请求中都可用，具体闭环引用[Goals 的协调合同](goals.md#mote-协调与已有授权)。

初始协调消息须明确沿原 Demand 推进到交付与收尾的责任。执行已获授权时，Mote 持续组织实施、处理提问或阻塞、核验逐标准证据、回收原报告并提交同一 Goal 的待验收结果；不能以完成分派、退出、idle、投递回执或 worker_done 收尾。确有阻塞时保留准确责任人、阻点与下一步。仅讨论或澄清的请求保持当前授权范围；目标确认与结果接受只由人做出，经 Goal 领域 owner 记录，Mote 不代签。

初始消息同时要求为本次讨论、本次明确交给 Mote 负责的无名 Session 及其新建执行 Session 取简短、可辨的主题／职责名。先读取准确目标、原名称来源与 revision，再沿原命名能力写入并核对回执；应用生成及 Agent 自主命名使用派生来源，保护用户手改、手动清除与启动指定名。主题明确后可细化仍为派生的临时名，不按每轮进度反复改名、不批量修改历史会话。Mote 本体、Session 与 Tab 各守原身份；优先级、并发与恢复唯一见[显示名与身份](spaces-and-layout.md#显示名与身份)。命名未知或失败只影响该步骤，保原工作面与健康执行，不换 Session、不重发任务。

### 需求写入授权与决策记录

本节定义 Mote 代用户写入 Demand（创建或改变 Goal 记录）时的授权策略；Mote 何时进入写入由[《Mote 协调与已有授权》](goals.md#mote-协调与已有授权)定义。这里的“确认”是对这次写入的授权，不是 Goal 的目标确认或结果接受：那两项只由人通过 `goal.confirm`／`goal.accept` 完成，见[《目标确认与结果接受》](goals.md#目标确认与结果接受)。

需求写入策略可配置为“按风险确认”（默认）、“全部确认”或“默认直接创建”，保存后在原入口可见。明确且低风险的单项目请求按已给授权创建并产生可追踪 receipt；跨项目路由、目标不明、不可逆或高影响动作展示来源、候选 Project、风险及缺少的确认，不静默写入。“默认直接创建”不绕过准确目标、既有权限与必要的风险授权；后续动作也不把过去授权扩大到新对象。

用户确认、改变目标 Project、接受／拒绝风险判断或撤销 Demand，作为结构化决策进入原知识／决策 owner，保原请求、候选与最终 Project、风险、用户选择、Demand／operationId、时间和来源 Session。完整聊天转储不冒充可检索决策；建议和排序可消费历史，不能绕过当前设置、确认闸门或权威事实，证据不足仍表达未知。通用版本化公共能力提供原记录的读写、检索与增量观察，Provider 不拥有这些语义，不新建第二份任务或记忆账本；未核实能力如实列缺口。

### Wiki 与应用协调指令

通用协调职责由应用署名的启动指令这一个 owner 持有，当前源码入口为 [`MOTE_COORDINATION_ROLE`](../../../apps/host/src/mote-topic-model.ts)。它适用于 Mote 的实际新讨论与复用请求，不靠改 CTA 原句、复制配置或重建 Mote 生效，也不覆盖用户 SOUL／Wiki。普通 Topic 与执行 Agent 不因复用组件获得协调角色。

初始上下文只保通用身份、必要边界、模块路由和重要决定／纠正／结果后的维护责任，日常合作与原文件记忆方法由 `amux mote --skill` 提供，PMO 的发现、派工、命名、跟进与交付方法由原 `amux mote playbook pmo` 按需提供，不在每次启动重复整套规程。普通 Topic 的方法路由由应用按已确认对象类型独立提供，不受旧自定义 AGENTS 或 Wiki 开关影响；完整方法仍归 `amux topic --skill`。这些手册沿公共 CLI 本地只读生成，读取不依赖在线服务，不启动任务或改变用户资料。专业职责在保存的 SOUL 中明确领域、判断方法与交付标准，不只靠名称或四维行为偏好表达，也不扩大原执行授权与默认 PMO 分工。基础 AGENTS 保原文件和模块入口，Goal 的完整管理／执行职责在实际 Goal 操作中按原身份、意图与回执注入；完整合同继续归 Goal owner。精简须分别核对新讨论和复用请求的真实消费链，保完整原草稿与后来启动能力，不通过匹配显示文案或删改用户自写文本去重。模板变化不自动覆盖已保存资料，也不使活跃 Session 热更新。

Topic 与 Mote 各自已保存的 Wiki 仍是对应原内容对象的可编辑知识，启用、内容版本和更新时间可见并可恢复；禁用不注入，恢复不重建 Topic／Mote／Session。准备会话时明示实际读取来源与版本；平台安全、当前用户指令、权限及权威 Project／Goal／Session／Run 事实优先于默认建议和历史推断。冲突或读取未知说明具体事实，不伪造状态、不静默覆盖文件或扩大授权。

主 Mote 的默认 Wiki 是可查看、可编辑的初始内容，帮助理解公共 Project／Workspace、空间、Goal／Demand、Session／Attempt 和 ctxmux 能力，包含路由、合并／拆分目标及风险确认建议；已有用户 Wiki 不因默认变化被改写。真实职责与权限不依赖 Wiki 中一句旧角色描述，源码中的初始内容也不代签现存文件或运行会话已更新。

## 快捷工作面的打开与恢复

快捷面按本专题的搭档界面组合已选 Mote 的原 Tab／Region 引用、Session、消息、输出与 Composer，保背后原工作面；导航、对象选择、尺寸与入口动作唯一见[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)。各入口共用这一个搭档交流面与原消息能力，不另建 Session、PTY、自由位置或第二份开合状态。“收起”不移除常驻入口，入口在 Settings、窄窗、无活动 Tab 或分屏时仍可见且可键盘进入；身份头像不冒充真实 Agent 工作状态。

明确打开后在同一入口内显示可见、可聚焦的搭档交流面、准确原讨论／Region 与可用输入。准备过程按原 owner 说明阶段并完成后进入内容；已有可用身份、导航、历史和输入保持，恢复未知进入持续状态层，不用全幅加载遮住健康原工作面或留空浮层。失败保入口和原面，持续说明失败步骤、当前可用／未知状态与恢复动作。明确打开默认先显示对话视图；已见模式、hover／固定和重启的优先级沿[《明确重新打开先显示对话》](#mote-快捷入口与当前协调上下文)条目，恢复不被当作新的人类打开。

固定目标和开合沿原 UI 偏好恢复，Core 持久空间 owner 先恢复原 Tab／Region、布局与引用；原主对话的自动接回时机只遵循[主对话合同](#主对话的自动接回)及[Session 恢复](session-recovery.md#冷启动按需恢复p0-末位)。hover、隐藏挂载和历史阅读不成为恢复授权。快照、握手或渲染未知不清布局，不换 Session、不自动重发旧输入。快捷面与 Work 保独立导航和真实输入焦点；可见性进入同一终端泊车、预算与通知事实，不能显示时回收内容或为隐藏引用新增消费。

## Mote 预制与持久人格

Mote 是具有人格的持久协作团队，复用共同 Space 管理能力；人格与产品角色不等同 Provider／Executor 或某次 Session。有稳定身份、`SOUL.md` 和全局负责能力的持久产品对象统一称为 Mote；Space 树、创建入口与固定快捷入口使用同一含义，PMO 只是初始化的默认角色之一。命名不改变耐久目录、Core Session、ctxmux Run 与布局身份。Mote 可以按预设专家画像建立，也可以从已经持续工作的 Topic 晋升而来；两条来源与晋升连续性由[《伙伴从哪里来》](companions-from-work.md)定义。

Topic／Mote 是组织工作的层次，Agent 是其中承担具体任务的成员层次。Topic 可以承载一个专业岗位或工作方向，保留知识积累和低门槛讨论的原用途；Mote 为长期承担的工作建立团队人格与职责。两者都可以有实际 Agent，成员关系沿原准确空间与协作事实表达，不以对象头像、同名目录、当前展示或 Session 数量猜测。Agent 从具体任务中积累经验，可能逐渐承担领域专家或协调管理职责；这些变化须有原工作和明确职责支撑，不新增固定职级、绩效分数或自动人事资格。组织晋升与成员成长分别表达，单一对外人格不能遮蔽实际执行者；具体成员、Session／Run 与原空间关系仍沿各自 owner。

- PMO 等预设角色以带预制的持久 Mote 组织，复用耐久目录、Wiki、资料、产出与铭牌，以及共同的 Space 管理能力。预制负责特殊身份、默认上下文与产品入口，Mote 保原 Space，普通 Topic 沿知识库 Zone 层级；不建立另一套 Space、Topic、Agent 或 Run 生命周期。
- 预设 Mote 的入口、Space 树条目与已有工作面必须指向同一个持久 Space；打开、收起、恢复或切换入口不创建第二个 Topic 或 Session。现有 PMO 的身份、职责和执行焦点约束继续见[《PMO teams topic 名称与职责》](motes-and-coordination.md#pmo-teams-topic-名称与职责)与[《执行 Agent 焦点历史与 PMO 上下文隔离》](focus-context.md#执行-agent-焦点历史与-pmo-上下文隔离)。
- 普通 Topic 不继承特殊预制的角色。特殊身份属于产品预制，与执行它的 Provider/Executor 区分；实际 Agent Session 仍通过 Core 的公开能力启动与恢复。
- 从画像新建的 Mote 从没有运行 Session 的可用启动面开始，打开或创建预制不额外启动 Terminal；从 Topic 晋升的 Mote 保留原有成员与工作面。普通 Topic 的首次 Terminal 规则继续成立。
- Mote 的持久产品身份使用独立矢量标记；新建、技能和权限动作各按含义表达，不全换成Mote身份。Provider 官方标识与真实运行状态继续沿原 owner；具体字形、尺寸与替换范围只定义在密度 SSOT[《控件语言》](../presentation/shared-rules.md#控件语言)。
- 这一类带持久人格的产品对象具有跨 Folder/Topic 全局负责的能力；其职责不被自身 Topic 目录或当前选中 Space 限定。产品身份与 Session 分离：产品身份在没有运行 Session、Session 结束、更换或恢复时仍然存在，不能用某一次 Session 的身份代替持久角色身份。

Mote 可复用 Topic 的知识管理、协作者和内容能力；这不表示 Mote 收纳全部普通 Topic，或两者占据相同知识导航层级。Mote Space 保留这些能力，建立人格时提供具体可读、可编辑的 `SOUL.md` 等资料。`SOUL.md` 表达该 Mote 团队的持久人格、价值取向、沟通方式与行为边界，与实际成员及其 Session、Run、Provider/Executor 身份区分；一个目录中的 `SOUL.md` 是该目录具有持久人格的文件事实，和有没有运行 Session 无关；更换或恢复执行会话不能把这些耐久内容丢掉，也不能用模板覆盖用户已经编辑的内容。原会话何时实际读取这些资料，继续沿下节加载合同。

普通 Topic 沿用已有知识管理结构；这类持久角色自行决定如何组织和维护自己的知识。产品提供可读、可编辑的预制入口，不强制迁移已有资料或统一知识分类。`SOUL.md` 仍承载持久人格；已有 Wiki、资料、产出、铭牌和用户编辑内容继续保全，Session/Run 的权威事实仍由原 owner 持有。

主 Mote（历史名 PMO Team）是这种 Mote 的已有产品实例，继续复用原固定身份、Wiki、角色说明与工作面。`SOUL.md` 属于耐久上下文，不能覆盖用户当前指令、既有授权与 Core/ctxmux 的权威事实，也不能把设定了长期职责伪装成已经启动或完成了后台执行。文件存在与执行会话实际加载是两件事：启动、恢复和文件编辑后的生效情况必须按真实执行能力表达，不能仅因预制了文件就声称已加载，也不能为一个 Space 修改其他 Agent 的全局人格。加载方式与更新时机遵守本节下文的新会话与恢复约束。

Mote 的默认人格与知识维护约束：新建或补缺失的 Mote SOUL 默认先读相关已有资料，记录有来源、时间和作用域的确认偏好与决定，区分事实、推测、提案、承诺和完成；更正只更新相关耐久知识，保存后读回才声称记住。换 Session 通过原资料接续，不假称继承未见对话或运行工具；不知道、未读、写入未确认都如实说明。知识组织继续自主；默认短记忆入口遵循下节，不要求其他 MEMORY 文件集、统一分类、scheduler 或第二份 Goal/Task 状态。详细执行协调沿 app-owned MOTE_COORDINATION_ROLE 单一职责；主 Mote 的新默认或用户明确恢复默认 Wiki 只提供短知识／协作指南，不重复整段角色流程，非主 Mote／普通 Topic 的默认 Wiki 不改。已有磁盘 SOUL、Wiki 与用户资料原样保留，不做 migration、自动清洗或截取用户文本去重；仅新的 Session 按原人格加载合同生效，恢复不热替换。实际模板交付与模型是否执行、读写成功分别验证，不能用提示词内容承诺每轮遵守或自动长期记忆。

### 会话入口与原文件记忆

基于当前 Mote 开展的协作，用户能控制哪些只使用已有上下文、哪些还允许向该 Mote 的长期记忆等耐久知识回写。使用已有 Mote 知识不自动包含回写许可，共用身份或响应其他成员也不扩大原知识维护范围。原会话历史、草稿及执行记录的保全独立于长期记忆回写，不能因关闭回写而丢弃原对话或恢复资料。

- Mote 和普通 Topic 在原目录补缺失的 `AGENTS.md`，说明真实 `amux` 发现与使用入口、当前指令和权限优先、原文件用途及协作者检查。普通 Topic 必读 `topic.md`；Mote 另读 `SOUL.md`、存在的 `BEHAVIOR.md` / `MOTE.md`、`MEMORY.md` 和相关原资料。当前知识使用与维护方法对新建和已有对象均须可发现，不能因对象创建较早或保留旧 AGENTS 而缺少入口，也不要求用户重建对象或 Session。已有 AGENTS 与用户人格逐字保留，原知识及自主组织方式保全；当前方法沿各自原模块 owner 提供，Mote 的详细方法继续复用原 `amux mote --skill`。预制不会把普通 Topic 变成 PMO。指令文件不授予新权限，也不是 Runtime 状态。
- 新 Session 由原 `prepareAgent` 路径实际读取该对象的 AGENTS；Mote 另读取原 `SOUL.md`、`BEHAVIOR.md` 与 `MEMORY.md`，各自带版本作为人格与知识上下文进入原 Core 初始上下文，不依赖某家 Provider 自动发现文件。读取只限准确原目录的有界普通文件；读取失败、文件变化、非法编码或超限均明确说明未加载并给出可见原因，保留原输入、Session、目录与资料。恢复已有 Session 继续原上下文，不热替换、不重启；正在运行的会话不因文件保存声称已热更新，文件编辑入口明确说明之后的新 Session 才使用新版本。原文件保存、当前方法可发现、上下文实际送入某个 Session 与该 Agent 采用方法分别表达，不能从模板或文件更新推定现有 Session 已采用。
- 可选原文件正文按 Core 最终出站消息的同一预算装载，计入引导、作者／派生上下文、封装转义和未加载说明；单文件读成功不等于已送入。放得下时带全文及原版本，放不下时明确未带入及准确原路径，保留原文件、必需职责／权限边界和用户原文，不截断或改写。首次创建冻结实际结果；原操作重试与恢复沿已冻结内容，不因后来的文件或引导版本重选。固定必需内容自身超限仍如实拒绝本次输入，健康工作面和原资料可继续使用。
- `MEMORY.md` 是新建或补缺失时的简短默认索引，正文仍只有原文件一份，允许链接既有资料、保留自主组织方式。默认内容为空，不将旧聊天自动当作确认知识。原文件树和 Editor 负责查看与编辑；AGENTS / MEMORY 属于核心上下文，不混入 Recent ideas。
- 原 Agent 先理解用户要达成的结果，做事时留意可复用的改进，以未来工作能否用上判断是否更新方法和记忆。为用户安排稍后执行的工作时，在原提醒 prompt 简短保留该结果，提醒自己完成后按同一标准更新。已授权的知识维护沿本对象的方法入口，写清确认偏好、决定、更正、承诺与证据的来源、日期和适用范围，区分提案与确认。通过原 Files 的准确资源、revision/CAS 保存后实际读回，才说“已记住”；未知结果先检查，不盲重写。无需新增时可记录带来源的 Agent 自报维护说明；自报记录、旧文件 marker、Run 结束或回答文字都不证明本轮实际完成语义提取或保存。
- 用户可在原 Editor 改正或移除条目。撤回可保留无原正文的最小 source 标记，指导后续 Agent 不从旧材料重新吸收；原 CAS 拒绝旧 revision，但不保证模型读最新版后永不重新提出旧内容，也不声称已擦除 Provider 历史或当前活跃模型上下文。
- 本机制自动完成的是新 Session 的原文件加载。正常回合的评估与写入仍由该 Agent 执行，未执行不能称为已保存；不另起后台 Agent、额外独立模型回合或无限追问。系统逐轮强制评估、逐 operation 冻结上下文与可信 assessment 回执尚属独立未实现能力，不能用本节提示词或模板交付代签。
- 公共能力复用 `whoami`、`--skill`、准确空间发现及 `file.read/create/write`；模板与原文件加载不新增 Memory RPC 或第二存储。GUI、Agent 和 CLI 均检查同一原文件与 Files 回执，记忆不代替 Goal/Task、权限和 Session/Run 权威事实。
