## 注意力与审查密度

- 行为、请求处理顺序和恢复边界只由 [交互合同](../behavior/agent-capabilities-and-messaging.md#注意力处理与结果审查闭环) 定义；本节只规定呈现。
- 全局 Needs you 入口和 Session 内交互卡使用同一套状态颜色、图标和文案；列表行优先显示 Agent/Session 身份、请求类型和摘要，数量放在聚合入口。
- 选中的请求复用现有交互卡和动作语言；提交中、失败、请求已过期与列表已空均有独立可读状态，不能只靠颜色表达。键盘焦点在下一项或入口按钮上可见。 入口收起后的焦点归还与较晚操作优先级遵循上述交互合同，不新增可见控件。
- Diff、Browser preview 和继续对话使用结果附近的一组紧凑动作；展开内容才占用详情或 Region，静息时不制造空右栏。
- Context、Usage、Needs you 和 Error 保持不同语义表达；既有未知值保持中性 unavailable/unknown，不能用绿色或 0% 代替未知。本节不新增 Usage 数据源或仪表盘。
- 预览和审查入口沿用当前 Surface、Region 和服务窗语言；窄屏时可以收进动作菜单，但不能依赖 hover 才能使用。

## Agents、队列与语义 token 密度

- Agents 菜单默认一行对象 + 一行最近动作；Provider/配置/路径降为次级信息，只有事实不足时才显示状态词。
- running 使用稳定静态 glyph，working 使用带节奏的动态 glyph；两者不能只靠颜色区分。只换提示文字、只换颜色，或两者都静态，都不满足这条；减少动态效果时动势退化为静态，但 running 与 working 的字形差异必须保留。本条适用于 Agents 菜单行，以及 Project Rail／Space 行尾的状态槽；头像与 Executor 身份图上的状态标记另沿下文[状态标记与 Executor 叠加密度](#状态标记与-executor-叠加密度)，普通 running 不加常驻标记。
- 队列默认显示短消息、状态 glyph 和数量；展开后提供明确的删除/立即发送动作，失败项使用 warning/error surface，不自动反复闪烁。
- Message Tools 的 token 使用短名和下划线，不把完整 URL/引用文本直接塞进正文；不同 token 类型用形状/前缀/辅助色区分，完整引用只在 hover/详情中出现。
- 识别词命中沿用**同一套下划线语汇**，不新造第二种视觉：它与已插入的语义 token 的区别在于它仍是可编辑正文（尚未替换），故不取 token 的实心/前缀形态，只加下划线提示「这个词可以展开」。提示条与候选菜单复用 Message Tool 的既有浮层与紧凑菜单，不占用输入区的常驻行高。

## 共享 Agent 菜单的动作层级

原来源未确认时，身份头部仍以准确对象为主，首层以短状态和直接可达的检查动作说明缺口，完整诊断收入有界、可选择的详情；不将原始错误当作无样式大标题塞在菜单顶部。尚未取得当前观察、暂不可读与准确来源变化分别说明，只有已有原确认事实才使用“原来源不再匹配”等变化表述。未知执行身份不推断 Run 已结束，工作面、草稿与已读内容持续保留；能力与恢复路径沿[共享菜单行为](../behavior/agent-capabilities-and-messaging.md#共享-agent-菜单)。

Focus 卡片、Agents 列表与 Agent Region 的右键／More 沿同一共享 Agent 菜单的名称、动作和控件语言呈现；入口特有内容通过扩展位进入同一层级，不另画菜单外观。打开位置沿各自手势避让，名称确认准确 Agent。身份头部左侧的紧凑名称与必要 Host 信息保稳定边距和对齐，Host 保低强调；Executor 不再以独立文字重复占标题空间，而在右侧 `Copy Agent Link` 旁使用共享 Executor 头像，点击复制对应原生 Session ID。头像、对象链接图标与名称形成同一紧凑头部，基线与垂直位置协调，不另起一行。对象链接继续直接提供本次已确认的 `Copy Agent Link`／`Copy Region Link`，Agent 链接在 Region 链接前；各复制入口仍是一级可达的动作。长名称先有界省略并可按需读全，不能挤掉头像、复制图标及完整命中区。复制组不再另占带 `Copy link` 短标题的一行，但保稳定分组名称、各项完整可访问名称及真正的 hover／键盘说明，不只依赖原生 title。头像的提示清楚区分 Executor 身份与“复制原生 Session ID”，不能让用户把头像复制误认成 amux 链接或打开设置；完整 Executor 名称与身份仍在按需说明及详情中可读。头部共用菜单边距，不分别叠加上下留白；原生 ID 的来源、未知与失败边界只见[共享菜单行为](../behavior/agent-capabilities-and-messaging.md#共享-agent-菜单)。

Conversation history 与 Session details 相邻；其后先是派生动作组（Take over、Fork current conversation、Pass on experience，再按保存顺序列用户动作，末尾以低强调的 Customize… 进入设置），再是会话生命周期组（Restart Session、Stop Agent），Stop 位于该组末项并保留原确认与后果说明。官方动作各用自己的语义图标，用户动作共用自定义派生图标；两组之间仅一条分隔。首层优先常用动作，长说明、连接设置与维护等低频内容按需收纳，不为每项扩展增加常驻组头或把菜单拉成整页资料。分组之间仅作必要分隔，不为实现片段插入横线或叠加分隔线两侧与组内的重复留白；原始 ID、目录与原生来源不支配首层宽度和高度。具体能力与扩展边界只见[共享菜单行为](../behavior/agent-capabilities-and-messaging.md#共享-agent-菜单)。Focus 顶栏的 Tab 操作入口沿[Focus 操作栏](focus-context.md#操作栏与原工作面)表达不同作用域。

终端正文右键先呈现紧凑的 Copy、Paste、Select all、Find 等正文工具，命中的路径、选区提示与输出操作就近可读，再衔接相关 Agent／Region 动作；常用复制与原生上下文的视觉优先级高于会话维护，不机械复刻 More 的整份顺序与内容密度。双列正文工具保每格自己的图标与文字，首列图标沿普通菜单项的图标列起排，文字基线、行距与后续菜单一致；不为工具块另设一套左右内边距，也不把双列文字工具强行改成无文字图标行。共享能力不依靠另一个终端菜单覆盖，终端专属工具也不常驻到 More。身份摘要、组名与分隔保持克制，不把正文右键变成第二份 Agent 管理面。实际目标、只读与未知资格及原动作后果沿[行为合同](../behavior/spaces-and-layout.md#agent-region-关闭与身份入口)。

分屏与排列直接在一级菜单呈现下节的 `New region`、`Layout` 共享两行控件与说明，不再经过 `Split and layout` 子菜单。复制对象链接同样留在一级，用一行紧凑图标动作表达准确的 `Copy Agent Link`、`Copy Region Link`，复用共享行的对齐、命中区、hover／键盘说明和完整可访问名称；它们复制既有 amux 对象链接，不另造 ID 格式或用显示名替代身份。常用动作尽量扁平，可变多目标选择、低频资料、连接设置与维护通过清楚入口按需展开；Check native source、Refresh observation 及其检查状态与失败提示在原维护入口可读可操作，不常驻铺开长说明。详情面保留完整 Session、Host、cwd、原生来源、观察原因、候选与原确认，字段可换行阅读；来源异常继续在原 Header 明确可辨。候选审阅、取消或确认替换详情行时，键盘焦点留在原详情子菜单，继续可选择下一动作。主菜单和子菜单受实际窗口约束，鼠标路径连续，键盘、触控及返回焦点沿原菜单协议；以共享紧凑工具行和按需内容控制首层高度，不用长列表、多层嵌套或裁切换密度。业务与身份边界见[Agent Region 关闭与身份入口](../behavior/spaces-and-layout.md#agent-region-关闭与身份入口)。

Session details 的原生来源区将「AgentMux 已采用的对话目标」与「终端当前所选对话」分开表达。多主对话候选沿原菜单逐项选择，完整身份可换行；已保留目标同样可选择，确认区展示原目标、拟采用目标及动作范围。已明确采用目标时 Header 用简短目标状态，前台选择未知留在相邻详情，不伪称全部已确认，也不继续把目标显示成一概不可用。候选核验、原操作核对与输入边界只见[同一 Run 内的原生会话切换](../behavior/agent-capabilities-and-messaging.md#同一-run-内的原生会话切换)。

## Region 菜单的分组图标行

Region 右键、Agent Header 的 More、分屏方向与 Browser More 中的同类动作采用一致的紧凑分组：`New region` 一行表达左、右、上、下，`Layout` 一行表达原有布局预设与排列。短组名只出现一次，动作以方向、格局与排列的语义图标区分；布局预设与排列之间只在两组都有动作时保留细分隔。没有动作的组自然缺席，可用项沿原动作模型，不为凑齐图标补出当前表面不支持的操作。分屏主按钮仍是原默认动作，方向选择留在原展开面。

这组默认图形在菜单实际的 16px 尺寸下仍应清楚可辨、视觉尺度与留白协调：四个分割方向指出新区域所在侧，四个预设忠实表达实际列数、格数与排列，两种重排分别表达均分与当前区域优先，不与新增 Region 混淆。不以装饰细节或颜色替代方向和格局，也不要求为成套而重画已有合适图形。图形沿原语义身份与[共享图标规则](shared-rules.md#语义图标密度与性能)维护，用户明确保存的主题选择继续有效；本组默认图形调整不改变原名称、命中区和动作回调。

布局控制面与同一 Agent 菜单中的 `Output` 工具行形成连续、安静的平面，短标签共用列宽，动作共用起点与图标步长，文字沿普通菜单项的基线与行距；`New region` 与 `Layout` 不因分组不同另起列线。对象链接复制在[身份头部](#共享-agent-菜单的动作层级)沿原图标组直接呈现，不为了服从工具行标签列再次独占一行。宽度由短标签与实际动作所需的内容决定，并受宿主可用宽度约束；不为了铺满更宽菜单而把图标推到右端、拉大标签与动作间的空隙。紧凑与版式纪律来自共同网格、一致光学尺度和清楚层级，成组留白紧凑而有节奏；普通图标文字项、双列正文工具与这些图标行仍保各自可辨形态，不为统一强行复制一种布局。压缩无效行间与块内空间，不以缩小原图标、命中区或焦点轮廓换密度。材质克制并融入原菜单，只在必要处轻微界定层次；不为每行、每组或每个图标叠卡片、边框、阴影和装饰标题，也不为高级感增加行数或占用正文。

布局控制面只保两组动作，不设常驻底部说明行。每行短组名始终提供稳定的可访问分组名称；hover 与键盘 focus 的动作说明在原组名槽同位轻量显示，槽位与图标起点不随文案移动，结束后恢复短组名；已有键盘焦点时保持其动作说明，不让指针经过另一项覆盖。当前动作的完整名称和已有快捷键必须可读：较长名称沿共享浮层与实际宿主避让规则就近展开，不能只靠截断文字、图标或鼠标原生 title；键盘焦点同样可达，触控不依赖不存在的 hover。每项自身的完整可访问名称保持不变，视觉说明不改分组身份；指针经过不抢走编辑或终端焦点。布局命令的常态与 hover 沿统一的中性面和前景层次表达，按压短促克制、没有位移；键盘焦点保独立完整的焦点轮廓，不用泛绿或整组发亮冒充命令已选中。菜单其它动作原有的等级色与禁用语义不受该局部样式改变。动作命令不伪装成单选状态；确有当前值时，其非颜色标记与临时键盘高亮分别表达，不用上次点击猜当前布局。

交换 Region 使用一个 `Swap Region…` 子菜单入口；候选保留原目标名称与同名区分，不压成难以辨认的图标。复制、移到新 Tab 与独立窗口保持一级可达；连接项沿本次明确动作的范围呈现，需要选择可变目标或读取低频资料时才继续展开。Tab 移到新 Group 可以复用紧凑方向行，但组名明确表达移动，不能混成新建 Region。动作作用域与准确目标只由[Agent Region 关闭与身份入口](../behavior/spaces-and-layout.md#agent-region-关闭与身份入口)及[Region 移位入口](../behavior/spaces-and-layout.md#region-移位入口)定义。

正常宽度以两行动作为目标；空间不足时，预设和排列各自成组换行，避免单个排列动作孤落新排，仍保细指针与粗指针的完整命中区和焦点轮廓，不缩小图标或裁掉末项来硬凑行数。长目标名可以有界换行、滚读，原完整名称仍可读；菜单及子菜单沿实际宿主窗口避让，不越出视口或断开触发器到候选的指针路径。

每项沿原菜单项语义，保留上下、Home／End、名称查找、Enter／Space 执行及 Escape 退出；同排左右键只在该图标行内移动焦点，不改成第二个嵌套工具栏，不接管输入法事件；仅同排有邻项时处理左右键，行端不截断事件，子菜单的进入与行端返回仍沿原菜单规则。就近说明随当前 hover／focus 更新，离开、退出与关闭时沿原菜单浮层规则收束，焦点恢复仍归原菜单；菜单呈现不改变原工作面的输入、布局、身份或生命周期。

## Executor 身份一致性

具体 Agent 的图标在各处保留同一 Executor 颜色／角标与默认底图，密度变化只调整尺寸，不丢身份定制。标识编辑控件嵌入该 Executor 配置，不归全局外观；行为归属见交互 SSOT 同名条目。

### 对话身份色与语义色

对话与参与者轨复用[共同消息头像](conversation-mode.md#消息布局与身份密度)：已核 Agent 使用真实项目图与 Agent 角标，Mote 使用原对象头像，人类与系统沿原作者呈现。身份解析、显示名与 Provider 资料各沿原事实 owner，不从事件 kind、消息声明或颜色认证作者；机器事件 glyph 仍可表达事件类型。

派生说话人色只提供辅助分组，不能独自区分身份或表达执行状态。同 Provider 的不同 Agent 可能共享品牌图形，也可能色相相近；接线方须提供可分辨的真实名字，名字、hover／focus 与可访问名称才是稳定判别入口。手选图形、Provider 品牌与 Mote 所选图片保原色，不把派生色重涂其图案。

自动派生的 Agent 说话人色相让开现有语义色：amber 的待处理、red 的错误、green 的成功，以及人类说话人的 blue。以各语义色相为中心保留半宽 **22°** 的弧，先按色相环合并跨 0° 与相交禁区，再从补集均匀取值；不能先散列再把命中禁区的值推到边缘，否则会人为聚簇。色相使用整数度，禁止为了增加可用色域任意缩小避让弧。可用区间随实际语义 token 推导，不把某次 palette 测得的区间数量或角度总量写成另一份固定色表。名字与非颜色状态信号始终保留，身份色不冒充运行、等待、成功或错误。

## 状态标记与 Executor 叠加密度

Tab、树、Session、Board 与 Browser rail 的普通身份图按提醒价值显示角标：工作中的 Agent 使用小型活动字形，避免用一个小绿点承担“正在产出”的含义；idle／普通 running 不添加常驻标记。Message Tools 接收者头像同时承担状态与关联动作入口，其 running／working 呈现只见[《Message Tools 右侧操作整体》](conversation-input.md#message-tools-右侧操作整体)。等待、阻塞、断联和错误只在确有提醒价值时显示右上角标记。Executor 角标缩小到 Provider 图标内部的叠加层，保留一圈很窄的底色隔离，不向外扩张，不和 Provider 身份图分开排布。活动详情菜单使用有限宽度、可换行和最大高度滚动，原因文本与时间、Project 元数据仍能同时读到。

### Agent 头像簇的可见判别

多个同 Provider 的 Agent 并排时，有不依赖颜色的判别器：原 Provider 图标回答执行来源，显示名的首个完整字素表达具体 Agent，二者同时可辨。字素使用与 Tab 相同的原名称优先级链，改名同步；不能使用最低档 Session label 或 Executor label 代替显示名，tooltip 与可访问名同样消费该链。

字母牌不要求把现有身份槽整体放大；字号沿原 `--fs-micro`，低于 10px 的原具名例外保持冻结的 7px 且实际绘字，不将字母混入豁免。叠压时右缘被邻座覆盖，注意力、归并计数、自定义徽标与字母不得抢同一可见角，也不把字母登记在实际被遮住的角；角位及换载体裁决沿[共享密度合同](shared-rules.md)，不新增第五角标。每枚 hover／focus 可完整阅读，用户自定义徽标继续保留。

Provider 官方品牌色与自动说话人色的分工唯一见[《对话身份色与语义色》](#对话身份色与语义色)，不使用正片叠底、品牌重染或另一调色板。Topic topology 的 Region 地图将 Agent 头像嵌入准确格子，不另列重复身份；该地图的 working／running 状态描边与其他状态的中性层级沿原事实，不能推广成所有身份头像的 running 角标。普通导航身份的标记范围只见上文[状态标记与 Executor 叠加密度](#状态标记与-executor-叠加密度)，hover 名称、真实状态与准确定位保持。

## 头像旁的阶段与动作提示

- 在既有 Agent 身份附近，用一个紧凑动作 glyph 与短气泡／标签表达当前已确认阶段，沿原字体、状态图形和头像语言；不新增 AI 工具栏、第二头像条或常驻大卡片。身份、控制归属、当前动作与记录仍各有层次，颜色只作辅助；完整名称、来源与动作可在原详情按需读到。
- 统一视觉词汇围绕动作本身：观察／读取用眼睛或文档，实际脚本用小型执行器，协议／语义不足的工具用通用调用图形，点击用指针与一次局部波纹，输入用键盘，滚动用方向，导航用页面方向图形，等待与需要本人使用原等待／请求图形。图形配简短动作词，不以工具品牌、符号或动画认证状态；思考气泡只在[当前阶段行为合同](../behavior/agent-capabilities-and-messaging.md#agent-当前阶段与动作的可见表达)允许时出现，不写编造的推理正文。
- 同一身份的提示有有限视觉预算：首层保一个可辨的当前动作，真实并发可用紧凑标记通向原详情，不堆多个相互遮挡的气泡；只有已确认的活动集合才能显示数量。步骤、并发关系与未知在详情保全，不让摘要把其他动作说成结束。提示避让当前目标、讨论框、主要阅读内容及接管入口，不截取命中、抢焦点或移动系统鼠标；窄／短工作面优先缩减长文，不藏控制出口。
- 动态只服务真实活动的感知，限当前可见对象上的局部反馈；结束、接管、来源失效、隐藏时停止旧执行循环。完成提示只作短暂一次反馈，不延续 busy 或反复庆祝。未知保持中性和可读原因，不无限播放“思考中”；减少动态时保静态图形、文字和真实位置，不能靠动画承担唯一事实，也不为观感延迟真实动作或常驻扫描无关 Agent。
- 聚合的 Provider 头像若没有独立定位目标，只表达身份与状态，不伪装成可点击按钮；有会话目标的头像才独立可操作。列表行动作不嵌套原生按钮，键盘与指针的动作含义一致。
- Browser、Agent 身份入口与共同过程使用同一状态／动作词汇，但不重复铺同一个提示。Browser 中的页面目标与原生层级继续沿 [Browser 就地呈现](browser-workface.md#browser-控制权提示)，通用提示不另建终端／Browser 绘制面；原生阶段能力与输入资格只由同主题行为 owner 决定。

## 状态、Browser 与 Scratch / Topic 密度

- Project 树的 idle、running/working、error 统一为同一宽度的“小图标 + 数字”状态槽；只换 glyph 和语义色，不换控件结构。完整状态名称进入 tooltip/无障碍名称，避免长文案破坏树的列对齐。停止/退出态使用中性颜色，error 只使用于明确故障事实。
- working 与 idle 的计数口径归交互合同[《Agent 全局状态：唯一事实与投影》](../behavior/agent-capabilities-and-messaging.md#agent-全局状态唯一事实与投影)，本层只定义它们的视觉层级。
- Browser 页面优先于控制提示；操作、接管与交还的状态密度统一见[《Browser 任务工具与证据的紧凑呈现》](browser-workface.md#browser-任务工具与证据的紧凑呈现)，不另规定占用一行的控制条。
- Space 的 Topics 分类与成员沿[《Project Rail 与 Topic 行密度》](spaces-and-layout.md#project-rail-与-topic-行密度)共用当前导航节奏，不再显示另一个 Scratch 父行或伪造 Folder 层级。标题允许省略但操作和选中态完整；hover 与完整行选中 Surface 可辨。Topic 行的打开状态、更新时间或 Agent presence 用低对比度辅助信息表达，新增和空列表用明确但紧凑的引导；原 Topics 总览保持独立的已 polish 密度。

## Executor identity 的统一密度

- Executor identity 组件在 Tab、树、Session、Board 和 Browser rail 中共享同一图标盒、状态点尺寸、珐琅外轮廓和 hover/focus 信息面板；调用方只提供尺寸上下文，不重写内部间距。此处适用普通导航／观察身份，Message Tools 的状态入口按上节引用呈现。
- 自定义 Executor 图标的叠加位置与状态标记的出现条件只见上文[状态标记与 Executor 叠加密度](#状态标记与-executor-叠加密度)。
- 信息面板使用现有 tooltip 的 micro/compact 字号和边距，首层以紧凑身份头、工作状态和原生会话摘要组织；当前模型、套餐与额度余量优先可扫读，额度按原窗口显示余量及重置信息，上下文与计费用量不混成一个百分比。设置仍是一个小型动作，进入 Executor 模板设置，不把 Appearance 的控件复制进面板。
- Agent 信息的来源、观察时间、进程、输入资格和诊断按需展开，不重复铺开状态词、相同时间戳及通用输入说明。正常、待处理、部分未知和读取失败保持清楚层级；没有来源的字段用简短未提供说明，不用空白、假零值或成功色伪装齐全。长名称和模型名可读，宽窄与矮工作面都保留主要信息、刷新和原操作出口；指针与键盘使用同一面板，不因刷新或开合抢走草稿焦点。数据与控制边界归[信息面板行为](../behavior/agent-capabilities-and-messaging.md#executor-身份组件与信息面板)。
- 既有头像的保留和 Reset 语义见设置的呈现[《Executor 启动配置阅读》](settings-and-observation.md#executor-启动配置阅读)；所有尺寸下的设置预览与实际身份图保持一致。

## 原生会话变化的就地提示

行为、原生来源资格与人工确认沿 [同一 Run 内的原生会话切换](../behavior/agent-capabilities-and-messaging.md#同一-run-内的原生会话切换)。该 Region 右上 Agent 信息入口用紧凑文字与轻量标记表达「来源变化」或「来源未确认」，不能只用颜色，也不将健康进程画成终局错误。完整旧／候选 ID、依据和确认范围放进原信息面，主工作面不堆机器字段或第二份身份卡。

核对与采用准确候选的动作和原因成组，鼠标及键盘均可达；失败保留选择和服务说明，取消不写入。存在多个主候选时，在原信息面逐项选择，再核对采用范围；已选语义目标与尚未确认的前台选择分开标明，不能把采用成功显示成前台已切换。窄 Region 下文字可换行、长 ID 可按需完整读取和复制，操作命中区不能被挤出或遮住。提示不抢输入、不遮挡终端连续阅读，不因无关刷新自动消失；正常完全确认后保持安静。候选实际宽窄画面与确认／失败动作沿既有独立看图评审验收，采图或源码字段存在不能代签。

## Claude Prompt 的提交反馈

发送动作保持与其它 Provider 同一枚主按钮和命中区。提交状态只呈现行为合同[《Claude Prompt 提交》](../behavior/agent-capabilities-and-messaging.md#claude-prompt-提交)给出的 Provider 回执，不以终端回显、输入框变化或按钮瞬时禁用判断提交完成。原生提交尚未确认时，Message Tool 保留文字并显示正在提交或需要重试的状态，避免用户误以为任务已开始而继续操作。

## Hook 隔离提示的密度

- 主会话与下属记录的归属以交互合同[《Hook 配置隔离与非 AgentMux 会话》](../behavior/agent-capabilities-and-messaging.md#hook-配置隔离与非-agentmux-会话)为准；不能在恢复或历史入口中把下属记录显示成主会话的完整记录。正常下属生命周期事件不增加主工作面的错误噪声。

- Hook 未安装、来源未关联、共享配置冲突或探测失败使用靠近受影响 Agent 的一行 warning/info 服务窗；文案说明步骤、当前降级能力和恢复动作，不展示 Provider 共享配置的内部路径作为常驻产品信息。
- Doctor 的逐 Provider 策略、磁盘安装与加载确认按交互文档[《Hook 配置隔离与非 AgentMux 会话》](../behavior/agent-capabilities-and-messaging.md#hook-配置隔离与非-agentmux-会话)区分表达，不用一个“已安装”标签代替不同事实；未知沿现有一行服务窗说明，不增加状态灯或阻断输入的提示。
- 磁盘检查沿用 Doctor 的逐 Provider 诊断呈现，状态、检查范围和行动紧邻；不增加常驻安装灯、全局汇总标签或另一套 Settings 状态缓存。只读点时检查与正常连接后修复的行为归同一交互合同。
- 非 AgentMux 会话被识别为无关联事件时只保留低干扰诊断，不弹出阻塞对话框、不禁用 Composer，也不把健康 Agent 标成错误终局。
- Hook 的 AgentMux 关联身份属于低频元信息，放入 tooltip、详情或诊断收据；主工作面只显示当前能力和可执行恢复入口。

## A2A 消息队列与身份信息密度

- 非历史 CLI 当前回执与无关原生读取依赖边界归交互合同[《持久消息的显式消费与派发等待》](../behavior/a2a-collaboration.md#持久消息的显式消费与派发等待)，不另造提示或输出协议。
- 显式消费沿现有 CLI 结构化回执与可读信封表达批次、Run、消息身份和真实投递状态，不增加常驻界面入口或第二种已读徽章；通信语义唯一来源见交互合同[《持久消息的显式消费与派发等待》](../behavior/a2a-collaboration.md#持久消息的显式消费与派发等待)。
- 跨 Session 消息来源沿既有一行来源与正文呈现，不新增视觉层或认证徽章；原信、启动／技能与随信提醒的使用要求只引用交互合同[《A2A 身份信封与持久化全局消息队列》](../behavior/a2a-collaboration.md#a2a-身份信封与持久化全局消息队列)，`whoami` 的身份事实不承载另一份通信指南。

- 发送回执与收件侧信封必须能对应同一条消息：首层明确显示已入队、已投递或失败，详情能核对稳定 `messageId` 和 Core 核验的双方 Session/Run；重试不得像一条新消息，队列暂不可写时不得出现虚假的“已送达”。交互行为以[《A2A 身份信封与持久化全局消息队列》](../behavior/a2a-collaboration.md#a2a-身份信封与持久化全局消息队列)为准。
- 收件来源显示 Core 已解析的参与者身份；Region、Tab 和其他视觉位置不能冒充发送者或接收者。实际可读来源与机器消息字段的归属只见上述 A2A 交互合同，可读属性只沿新信封合同表达，不替代结构化事实。
- Message Tools 的首层只显示发送者、接收者、当前投递状态和必要的失败/重试动作；`messageId`、receipt、generation、thread/correlation 和 workspace/session/run 关联进入详情或审计入口，不占用 Composer 主输入区。
- 队列重启、replay、背压或 Store 降级使用现有 Agent/Session 服务窗的一行状态提示，说明事实、当前能力和恢复动作；不清空消息列表、不覆盖 Composer，也不把健康 Agent 画成终局错误。
- 读取和审计入口支持按 thread、recipient、session 或 receipt 收窄范围；默认列表按 durable sequence 排序，不能用当前 Region 或视觉位置替代消息身份。

## Message Tool 的等待与失败说明

Desktop 的发送等待与失败提醒 dock 在所属 Message Tool 的右侧，复用 SessionMailbox 的 Notices／User Messages 作为唯一处理面；入口随原邮箱对齐，提醒不覆盖工具行、不在输入编辑区重复铺大错误块。主提醒最多两行：简洁的原消息状态／短原因与紧凑的可用操作；窄面仍保留可辨操作，不以多行原错误、嵌套 JSON、常驻大横幅或缩字补空间。失败、结果未知和暂时等待可区分；通知到达不偷焦点、不撑高 Composer、不遮住原工作面，关闭或披露后保原草稿、选择与输入位置。

同一条原输入的标题、处理动作与完整诊断消费同一 Core 等待／接纳回执。Core 已确认保存且仍在等待时，不仅因底层观察携带 `AbortError` 而改称发送失败或结果未知；真正 unknown、部分输入及已派发事实仍优先保留，不能从错误名称、等待阶段或零字节提示补造未派发。完整复制保原 key、等待代次、当前控制与接纳事实及原错误，首层仍保持紧凑。

默认“复制诊断”生成紧凑摘要：状态、准确原输入引用与等待代次、当前等待位置、原错误原因和已有 logid 各表达一次，不铺开重复 stack 或嵌套 JSON。摘要明确缺失与未知，不把观察位置冒称根因，不从相同文案合并不同来源。

完整原错误、stack、结构化 JSON、Host、Session／Run、messageId、operation 和 logid 留在同一处理面的默认折叠详情中，通过独立的“复制完整资料”动作按需完整取得。导出保留实际收到的错误、Core 输入回执与日志各自来源，不再将回执内容扩写进错误，也不按多种标题反复展开同一材料；首层摘要不得裁掉存储原文或重建一份诊断事实。复制沿原 Clipboard 回执显示准确的成功、失败或未确认反馈，不能只用 tooltip 告知。原 owner 已确认上下文整理时才表达“正在整理上下文，稍后重试”；有限自动尝试的次数、下一次等待与停止动作在同一处理面按需查看。等待、重试、停止等待与投递资格继续消费[输入环境与原消息合同](../behavior/agent-capabilities-and-messaging.md#输入环境判定与复用边界)，呈现位置与行数不授予或取消这些资格，也不新增队列或 notice 事实 Store。

Desktop 的 dock 位置由宿主持有；共用的错误、详情与复制组件保留各 client 的呈现入口，Mobile 不套用 Desktop 的右侧 dock。正常／窄分屏、长草稿及完整长诊断须沿[独立 Agent 看图评审](../../guides/agent-visual-e2e-review.md)在实际产品工作面操作、采图并复审，确认短因、原动作、展开／完整复制与键盘访问可达；图片或纯样式检查不能代签审美通过。
