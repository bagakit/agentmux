## 消息布局与身份密度

### 消息方向与气泡

用户和其他已核 Agent 的输入气泡在右侧，当前会话执行 Agent 的回复使用左侧轻气泡；所有正文保持左对齐，停靠不改变段落、列表、表格和代码的阅读起点。其他 Agent 使用轻量来源卡、真实头像、姓名与 Agent 来源标记，当前会话 Agent 回答不使用左侧竖线。作者事实与用户显示默认只见[《共同对话的用户默认外观与协作来源》](../behavior/conversation-mode.md#共同对话的用户默认外观与协作来源)和[《对话中用户消息的阅读方向》](../behavior/conversation-mode.md#对话中用户消息的阅读方向)。

只有人类用户默认显示的气泡加强与 Agent 的视觉区别：宽高顺随内容，短消息呈自然紧凑的气泡，长消息在可用阅读宽度内换行并保持内容完整。使用现有安静色阶、克制边缘和圆角形成区别，各作者共用协调的正文阅读字号，不依靠身份不同而缩小正文、固定大宽高或裁掉元信息换取区别。宽窗和332px中长姓名、声明、Markdown／代码、复制、详情与键盘焦点可读可达。作者事实、默认显示与阅读保持只引用交互合同[《对话中用户消息的阅读方向》](../behavior/conversation-mode.md#对话中用户消息的阅读方向)。

### 身份行与按需详情

共同消息卡先分标题行、小字说明行与正文，再布局内部元素。标题行有独立身份槽与固定的时间／复制／Info 操作槽，长姓名与 ID 只在身份槽内换行；来源、项目与声明进入独立小字行，不竞争标题位置。辅助项横向连续排列，仅空间不足时自然换行；声明标签按内容宽度，不拉满整行。长项目与来源沿自身项的原省略／完整披露规则，不能扩大卡片宽度。Info 始终在标题行且可键盘操作，详情沿原披露展开在标题下方；正文与续接独立，宽窄均不因说明变长而把按钮挤到第二行，不用绝对定位掩盖布局。触屏的完整命中范围与视觉尺寸分开：44px 操作区域不能放大头像、图标或时间字号，也不能把图标动作变成占据整行的散列列项；窄屏中时间、复制、Info 与作者头像沿同一紧凑基线，必要的身份或来源说明另起一行，正文与消息头之间不预留空操作栏。

消息主卡与 trace 的已确认来源使用[来源、回复快照与作者说明](../behavior/conversation-mode.md#来源回复快照与作者说明)中定义的同一组紧凑短标签，置于原辅助说明层，自然换行，不挤占姓名、时间、Copy／Info 或正文。同一卡的多来源可直接扫读，准确原记录、版本及未确认关系沿既有详情披露；宽窄、键盘及明暗保持可读，不新增来源工具栏或重复标签墙。来源与关联的事实边界只见[连续统一的对话列表](../behavior/conversation-mode.md#连续统一的对话列表)。

准确聚合的发送贡献留在正式主卡顶部，尚未聚合的提交沿自身原位置呈现；两者复用[共同阅读密度](#共同阅读密度)中的发送记录与原文披露，不增加第二张提交卡、重复正文或来源工具栏。原作者、渠道／设备、完整内容和准确引用沿展开详情可达，多次提交分别可辨；只使用原事实中的发送时间，不补造接纳时间。显式 Focus／搜索详情直接阅读原文，不再套第二层默认折叠。关联、真实状态与阅读保持只沿[行为合同](../behavior/conversation-mode.md#连续统一的对话列表)。

共同气泡的姓名与原始时间组成紧邻的轻量元信息组，姓名字号低于正文、字重更克制，时间进一步弱化，操作沿原按需入口靠后；不以拉开姓名和时间形成空标题带。头像跨消息文本行对齐，不单独撑高标题；保留原 32px 项目／Agent 复合身份与 20px 用户标记。表面使用安静填色、克制内边缘与协调圆角，用户色阶区别清楚但不压正文；长内容、窄窗、明暗和真实键盘操作沿本节原约束。

已核其他 Agent 与执行 Agent 的头像以真实项目图形为主体，Agent 图形在角上可辨，不把正文挤成窄条；缺项目的已知 Agent 保其身份图形。Agent 名字是首要扫描信息，时间与 Project／Zone／Tab 是安静辅助，长名字可读，辅助信息在窄窗可收敛且完整内容按需可达。Message details 使用紧凑图标入口，title／可访问名称与焦点可辨；详情按来源、作者和当前资料分组为少量紧凑行，不堆重复姓名、长空字段墙或常驻文字按钮。宽窗与 332px 中完整正文、代码、长姓名、头像角标、展开详情、失败动作与键盘均须可读可达；来源声明、未知状态、生命周期与当前资料边界只见[《共同对话的紧凑消息、复合头像与按需详情》](../behavior/conversation-mode.md#共同对话的紧凑消息复合头像与按需详情)。

Agent 消息的头像、名字和 Session ID 组成同一个紧凑身份组，不新增身份 toolbar 或第二块卡片；名字保持主层级，准确 ID 用较弱但清晰的文字常显，可选择，并以有明确 tooltip／可访问名称的邻近图标复制。窄面允许身份组自然换行，不把名字或 ID 压成纵列、藏到详情或挤窄正文；头像沿原复合身份和稳定尺寸，不用用户头像表示声明 Agent 引用。声明性质以克制短标签可辨，项目／Zone／Tab 继续辅助。复制反馈在原命中处即时可见、不移动卡片或改变高度；减少动态时保静态反馈，失败仍可读和重试。名字、ID、声明与复制原文的事实边界只见交互合同[《共同对话的紧凑消息、复合头像与按需详情》](../behavior/conversation-mode.md#共同对话的紧凑消息复合头像与按需详情)。

同一已确认作者的连续公开进度使用轻量续接行，避免每条重复大头像、项目与来源说明；组首、作者变化、正式回答及显式定位的原记录保完整身份。续接消息仍显示准确姓名、SID 与具体时间，SID 保原常显及邻近复制入口，Copy／Info 和完整身份沿该条可达，正文不改写、不缩小或截断。仅过程／观察插入不制造另一位发言者，真实用户或协作输入则重新建立清楚的身份起点；不得按相同显示名归组。

### 操作来源设备

用户消息与对话交互操作在既有作者、时间元信息旁以紧凑设备图标与名称展示来源，例如“来自 iPhone”；完整设备身份与操作详情按需展开，不增加独立大卡片或改变作者标记。Desktop 与手机共用此呈现，历史未知来源明确显示未知，不把 Agent 回复标成设备操作。认证归属及记录保全沿[《手机版 Relay 连接》](../behavior/public-control.md#手机版-relay-连接)。

### 共同阅读密度

整体布局遵守[连续统一的对话列表](../behavior/conversation-mode.md#连续统一的对话列表)。历史分隔、来源标签、加载与状态说明嵌在同一列表层级内，使用克制的辅助视觉；消息和过程沿共同对齐、间距与披露语言连续排列，不因标签或数据来源形成第二块聊天面、重复标题墙或独立操作区。

Session 的恢复状态及原动作沿[Session 重启恢复状态](session-recovery.md#session-重启恢复状态)呈现，与本页的消息读页等待、来源和阅读位置说明分别表达。

共同气泡与已接入 Workflow 过程使用一致的轻量容器语言，优先减少外间距、容器内留白和外层读页的重复 padding；短消息不因容器空白被撑高，过程头部、摘要和步骤行的留白保持连贯。名字、主要正文与必要过程状态先可扫读，辅助资料沿原入口完整可达；消息与过程的边缘、缩进和展开层级连贯。共同聊天正文与周边界面采用协调的阅读尺度，Activity 与 History 共用同一正文、Markdown 和代码基线，不保留明显放大的聊天正文，也不把元信息压到密度下限以下来换紧凑。32px 身份图形与必要命中区保持，触屏操作保有足够命中区；宽窗和 332px 中的中文、长名字、代码、展开内容、复制反馈与键盘焦点清楚可读。调整限共同阅读作用域，不改变全局 UI、Editor 或 Terminal 字号，不得以裁内容、压窄正文或隐藏身份、失败、原步骤换紧凑。行为与保持边界只引用[《History 使用共同对话阅读面》](../behavior/conversation-mode.md#history-使用共同对话阅读面)。

Outbox、Focus 时间轴与对话模式的同类消息沿既有消息行、紧凑标记和按需说明呈现，不另造消息样式。输入来源、当前窗口与缺时间说明采用轻量来源语言，不新增常驻来源工具栏；读取范围与失败用消息面内的短说明和就地 History／Retry 动作表达，空态和窄窗仍可操作。首窗被后续工具／活动占满时，输入继续沿同一读取说明与较早记录入口可达，不新增控件或消息样式；原生新增记录的来源通知、作者、时间、投递和返回边界只见[用户消息来源](../behavior/conversation-mode.md#用户消息从-provider-原生会话取得)。

发送记录与所属用户消息采用相同的右侧对齐和有界阅读宽度。准确同一消息的正式正文尚不可读时，默认首行显示「消息发送＋原发送时间＋真实状态」，下一行用小字显示正文预览，折叠态最多两行并提供展开入口；发送者、渠道和设备等已有事实放入详情。只有与这条消息相关的发送或同来源原读取确实在途，才复用共享行内 SVG 活动信号；准确目标尚未读到不单独授予忙碌状态，失败、结果未知或来源不可用不维持无真实在途动作的动画。

准确同一消息的正式正文已可读后，发送贡献默认收为「消息发送＋原发送时间＋已进入对话＋正文前缀」的一行可展开摘要，使用清楚可读的辅助色阶，停止活动信号，由正式正文承担主要阅读权重。Core 已聚合的发送贡献在同一正式主卡内呈现该摘要，不另保第二条发言；失败和结果未知仍明确可辨，不能以「已进入对话」覆盖原操作状态。长正文前缀沿可用宽度省略，时间、状态与展开控件保持可读可达；展开后沿原全文、资源及 Copy／Info，不受预览行数限制。已有展开、选区、显式定位和键盘焦点优先于默认收拢，后到记录不能强制折叠正在阅读的原内容。两阶段只消费[行为合同](../behavior/conversation-mode.md#连续统一的对话列表)中的准确关系与实际可读事实，不以相同正文、相邻时间或任意原生卡片建立对应。

可读正文和过程使用同一共同消息区，不因原生、Hook 或 captured 来源分出第二套聊天外观，也不把最新正文藏入含计数的“投递与运行详情”总折叠。同类过程使用相同紧凑层级、披露与载荷组件；不同来源的适配只供原事实，不自造平行 payload、样式或状态解释。提交／未确认／失败就地贴近所属消息，机器回执与诊断保持轻量、按需可读；共享外观不抹平事实差别或按正文猜两源关联。明确属于运行观察的回复快照保留原正文预览，按[来源、回复快照与作者说明](../behavior/conversation-mode.md#来源回复快照与作者说明)使用与原生对话同层级的普通标签；角色、采集入口和缺作者说明分别可辨，原事件名及解释在详情可读，不叠加高亮标题或重复的 Hook／采集说明。普通标签不改变其观察角色，也不表示已经确认原生对应。说明只消费 Core 已接受的准确关系与缺口：已有未读目标时说明对应原始记录尚未读到，关系循环等冲突沿原诊断表达；本窗口没有记录整条回复的 same-event／observes 关系时，主线保简短采集来源说明，准确关系边界留在原详情，不推断全历史没有关系或必有一条原生对应消息。跨来源排序为 partial 不构成关系事实，具体 part 的 same-invocation 也不等于整条回复关系；已有准确关系时不固定标未知。完整原文与所属动作按需展开，不画成第二段默认全铺的 Agent 回答。阅读保持与原身份规则只见[同一 History 阅读面](../behavior/conversation-mode.md#history-使用共同对话阅读面)。

回复快照的正文和折叠预览使用正常正文阅读色，保留有价值信息的清晰度；不因其来源为运行观察而整体置灰。来源、时间、事件和未确认关系仍用原辅助层级说明，正文颜色不授予作者、关联或投递事实。

快照默认是一行可展开的观察入口：角色、真实时间及短正文摘要在同一行，正文按 Markdown 的阅读文字形成摘要并沿可用宽度省略，不把固定字符上限当作足够紧凑，也不将列表、强调及代码标记直接拼成第二份全文。展开后显示完整原文和原来源详情，原 Copy 不取摘要。已经准确合入主消息的快照仅在该主卡的来源贡献内可达；未关联观察保自己的位置及未知边界。子 Agent 回报的头像、路径与折叠沿下文[Subagent 回报的紧凑呈现](#subagent-回报的紧凑呈现)，正式协作消息仍使用准确发送者→接收者的轻量上下文。

观察入口在相邻过程内保持原序可达，不重复撑出多条等权的过程容器；未展开的过程只给一份紧凑记录数及实际可用状态，缺状态在按需说明中明确，不反复铺“状态未记录”。真实失败和在途仍常显，用户／协作输入与公开发言不收进过程。相关语义与阅读保持沿[共同记录顺序](../behavior/conversation-mode.md#共同过程与消息的记录顺序)。

返回当前尾部使用同一个紧凑入口，文案为“滚动到最新”，含义沿[同一 History 阅读面](../behavior/conversation-mode.md#history-使用共同对话阅读面)，不同时出现 Current、Show latest 与 Jump to latest 三套同义按钮。入口只在实际需要离开原阅读位置返回当前尾部时浮在所属阅读面底部，回到尾部且没有待呈现内容后收起，不增加正文行高或挤动输入区；普通流式更新、重绘或布局测量不能让入口反复闪现、闪烁或暗示必须点击才会加载新消息。等待、失败、阅读保留及键盘焦点在原入口附近清楚可辨。阅读位置或选区保留用短说明表达，不把正常阅读保护铺成大段错误横条；真实读取失败仍保完整原因与明确重试。较早／较新的相邻页继续读取与返回原入口保持各自含义，不以统一按钮取消历史、选区或原游标。

对话读页等待服从原阅读层级：已有内容时在时间尺记录读数旁以小尺寸活动图形及可访问说明表达，保留原读数，不铺居中大胶囊、重复横条或伪进度。等待的出现与消退不改变时间尺、正文和输入区几何；读取更早消息复用原动作的等待反馈，同一阅读面不叠两套提示。首次无记录且原读取在途时，沿[共享 Region 加载表面](session-recovery.md#全页加载大屏)形成整个可用对话阅读区的动态阅读场景，复用现有构图、材质与动效边界。配色沿项目 Graphite／Mint 的中性表面和主题强调色派生，保持柔和但明确的明暗层次，不把高亮色铺成主背景或另造色盘；动态具有清楚的空间组织、主次、行进方向与连续节奏，以柔光和表面变化形成纵深，避免等权重线框交叉、机械往返或多组图形同时争夺注意。状态文字保持稳定、简短并有持续净空。动势属于全幅装饰场域，覆盖可用阅读面；原工具、来源说明与动作留在自然布局，不随场景移动，不画假消息、身份、记录数或进度。宽窄与明暗主题均保持完整构图，减少动态时保静态场景，隐藏面停止不必要动画。已有失败且没有可读正文时使用静态的阅读中断说明，保原完整原因和原重试入口，不继续播放加载动画；已确认空记录与 Agent 工作状态分别表达。正文到达立即可读，不为动效延迟、重排或给每次切换、消息更新添加入场动画；仅沿既有动效 token 使用 opacity／transform。读取、选区和原工作面保持沿行为 owner，不由动效或展示文字授予控制事实。

自动补读达到原有界阅读窗时，不显示时间范围超限的错误横条或伪重试；已载范围与较早入口继续表达原覆盖。“只保留近期记录”“还有更早记录”等正常范围说明归已有较早入口的按需说明和原覆盖详情，不另占提示行、增加第二个入口或冒充完整历史。真正的自动补读失败，其完整原因、等待及重试归同一个较早读取按钮，鼠标与键盘都可读可操作，不另占一条横栏或增加第二个 Retry。初次读取及其他来源失败仍保自己的原说明，不因收拢自动补读反馈而消失。

### Subagent 回报的紧凑呈现

Subagent 回报沿共同消息的轻量表面和左侧阅读起点，默认收为清楚的身份行与短正文预览，不做满屏原始日志或厚标题卡。头像直接复用所在主 Agent 的既有图形；紧邻的「Subagent」与准确原生路径构成身份组，不再重复一行巨大路径标题或以普通观察圆点代替头像。接收者和记录时间保持辅助层级，Copy／Info 与开合沿原消息动作语言，窄面仍可达。长路径允许自然换行或视觉省略，完整路径可查看、选择和复制，不把路径挤成纵列，也不借父 Agent 的 SID 填满身份行。身份事实及独立 Session 的适用边界只见[原生 Subagent 回报的阅读](../behavior/conversation-mode.md#原生-subagent-回报的阅读)。

折叠预览取已有可读正文的阅读文字，保持正常正文色并沿宽度收敛，不把 Markdown 标记、封装字段或已确认的密文拼进摘要。没有预览且没有待读资源时收为一条安静的身份行，不另画占位正文或空摘要按钮；头像随身份行收紧，仍沿用主 Agent 的原图形。展开显示共同 Markdown 与资源，原封装及不可读载荷置于明确命名的原始详情，避免正文套一层又一层同等权重的卡片。仅有不可读内容时在展开后用一句中性说明交代可读性，保原始详情入口，不画错误态、虚构摘要或装饰性的成功标记。

开合控件始终可辨，鼠标、Enter／Space 与触屏操作一致；展开和收起保原消息节点、焦点与阅读连续性，原 Copy 不取截断预览。正常宽度、332px、明暗主题下，长路径、中文、混合资源、仅不可读记录、完整详情和复制反馈都须清楚可读；减少动态时仍保明确开合，不以动画、头像或摘要推导消息状态。阅读保持与来源边界沿行为 owner，具体行高和留白复用共同消息 token。

### 声明与系统来源

Channel 输入沿共同消息卡呈现名字、头像、平台与原会话，正文为主，准确原身份与资料观察按需可读；已核作者与包内声明不混为同一认证。头像不可读或资料过时保留可辨的原主体、旧观察与刷新动作，不闪空正文或要求重新发消息。资料缓存的限定查看、刷新和清理归原 Channel 详情／设置，等待、失败和保留结果的视觉语言复用原控件。平台群改名后，标题栏、群详情及选择入口显示同一原群的新名称；不因改名跳转焦点或改变关系。行为只见[共同协议](../behavior/conversation-mode.md#共同对话协议与外部交流入口)。

飞书与 Discord 原生消息面分别围绕普通对话、进度、问题／答案、权限和资源采用可辨形态；操作贴近原问题，显示准确对象、可选项、等待、已处理或待核对结果。原生控件不被适配器外的通用大卡片模板取代，长内容和平台分段保留原事件与完整阅读／复制路径，不能用同一个成功标签掩盖不同回执。

消息包装沿同一来源卡表达：真实作者为主，包内声明安静且按需可辨，裸协议标签不占正文首尾；来源标签、正文和按需动作层级清楚，不为声明再套厚标题墙、重复头像／边框或常驻工具栏。资料详情采用现项目图标与文字，正文保持主要阅读面。长声明、引用、正文与动作在 332px 仍完整可读；未知或不完整包装保原文，声明与 Copy 的事实边界只见[《共同对话的用户默认外观与协作来源》](../behavior/conversation-mode.md#共同对话的用户默认外观与协作来源)。

A2A 的协作提醒沿同一轻量披露语言置于原正文之后，默认收起、字号和颜色次于正文；展开可完整阅读，键盘焦点与开合明确，不作为新的来源或授权证明。

已核 A2A 引用通知以原信的右侧 Agent 消息卡承担主阅读，沿共同头像、姓名、准确 Session ID、原时间与 Copy／Info 布局，正文使用正常阅读尺度。主卡不再套系统记录外壳，平台通知、完整协议与 native／captured 原贡献收进按需详情；打开来源只读原文和 JSON，不重复铺完整聊天卡。多封原信沿原顺序排列，逐项读取等待或失败贴近原引用，保清楚的重读入口，不用机器命令代替正文，也不叠加多层等权大卡。宽窄、明暗与键盘操作保持可读可达，已有选区、展开与焦点沿原阅读保护。读取资格、身份和复制边界只见[原信阅读行为](../behavior/conversation-mode.md#a2a-引用通知中的原信阅读)。

完整前导声明上下文沿共同消息的轻量披露语言收起为紧凑声明行；原尾文是主要阅读面，声明摘要不堆头像、重标题或独立大气泡。展开的原上下文可选择、滚动和完整读取，折叠入口有清楚的声明名称、开合与键盘焦点；宽窗和332px中尾文、引用、缩进代码、整条 Copy 与必要动作仍可读可达。连续声明与无尾文不制造用户正文；已核系统与未认证声明的事实边界唯一遵守[《完整前导声明上下文的同记录阅读》](../behavior/conversation-mode.md#完整前导声明上下文的同记录阅读)。

**声明尾文的连续排版**。收起声明后的普通尾文沿既有段落节奏紧接阅读，不因声明与尾文的分隔换行或普通段落默认外边距撑成大片空白。仅已识别声明之后至多两个完整前导 LF／CRLF 可作为阅读分隔不占空行；更多换行、空格、tab、正文内部换行、代码缩进和行末空格保持其阅读语义。普通用户文本及未识别声明不应用这项分隔处理，普通文本与 Markdown 段落复用共同段落间距。原记录、作者、声明与完整 Copy 的事实边界仍只见[《完整前导声明上下文的同记录阅读》](../behavior/conversation-mode.md#完整前导声明上下文的同记录阅读)。

已核 AgentMux 系统内容复用共同消息面，使用可读 AgentMux／System 来源和中性轻量样式，与右侧用户和其他 Agent 输入气泡及左侧当前会话回答区分，不只靠颜色。长上下文完整可读、可展开和可复制，不压倒真实请求、不另造常驻工具栏。身份与未知默认只引用[《共同对话的用户默认外观与协作来源》](../behavior/conversation-mode.md#共同对话的用户默认外观与协作来源)。

Provider 系统记录复用共同对话已有的轻量系统卡片：紧凑标题、来源与单行摘要，默认收起长正文，展开后沿原文本与资源阅读组件完整呈现。视觉不冒充人工消息气泡或 Agent 回复，不用警告色暗示故障；窄分屏、明暗主题与键盘焦点保持清楚可读，复制结果沿原反馈。来源与语义边界唯一见[Provider 系统记录](../behavior/conversation-mode.md#provider-系统记录)。

## 对话消息的视觉语言

### 正文与 Markdown

正文中的静态图表复用文件与 Note 的[图表预览与放大阅读](files-and-git.md#图表预览与放大阅读)，保持有界、等比完整预览与同结果大图，不在消息卡片中铺开无上限的长图。

用户及其他 Agent 输入的 Markdown 复用共同语法与阅读组件，完整呈现列表、引用、链接、代码和表格。正文、各级标题、列表、引用、表格与代码使用一致的正文尺度，以字重、协调留白和局部滚动建立层级，不以多级标题放大字号。ATX 标题保留原始 `#` 标记并加粗，嵌套层级也不增大字号；Setext 标题不捏造标记，代码／转义中的 `#` 保字面内容。执行 Agent 回复与文件文档的原有标题／outline 语义保持，原始复制与批注选区不改。

Activity、History 及其他共同阅读入口共用同一正文、Markdown、代码与资源的 tokens、间距和阅读基线；窄窗不裁正文、元信息、动作或焦点。展开、复制与实际质量验证只见[《对话消息的阅读、复制与标注》](../behavior/conversation-mode.md#对话消息的阅读复制与标注)，宿主不维护另一份消息外观。

已记录的问题答复沿原输入正文呈现答案，关联问题与原始记录使用紧凑的按需披露，默认不露协议包装；正常与窄窗、明暗和键盘焦点保持可读，整条复制沿原消息反馈。语义与原文边界唯一见[对话消息的阅读、复制与标注](../behavior/conversation-mode.md#对话消息的阅读复制与标注)。

### 长内容、代码与局部查找

长人类消息的全文入口与折叠状态清楚，原消息尾部与附件操作在展开后完整可达；宽窄保持原正文基线、自然比例和可见焦点，不用遮罩隐藏可聚焦操作。

长代码与宽表格在真实横向溢出时，以轻量边界提示表明尚可阅读的方向，端点撤下；沿原字体、主题与滚动表面，不通过裁字、遮字或大面积渐隐获得提示。键盘焦点清楚，正常不溢出的块保持原静息密度。

普通代码围栏的语言标识与复制动作放在同一条轻量工具栏，正文代码仍是主要阅读面；沿既有 surface、字体、图标和焦点 token，不叠加装饰卡片。长语言标识可视觉省略，复制动作与状态仍清楚可读；窄 Region 中工具栏保持在代码横向滚动之外，不将整个消息撑宽。明暗主题、键盘焦点、复制处理中／成功／失败均可辨；复制内容与迟到回执边界只见交互合同[《对话消息的阅读、复制与标注》](../behavior/conversation-mode.md#对话消息的阅读复制与标注)。

局部查找收起时以放大镜图标融入当前阅读面的既有操作区，不独占一整行或保留工具栏空位；名称、快捷键与键盘焦点清楚可达。打开后在原阅读面内显示有界的轻量浮动查找框，输入、命中数量、前后及关闭动作保持紧凑，窄面与触屏不溢出或裁动作；不推动时间尺、正文或输入区。明确当前已加载范围，命中强调与当前命中可辨；仅用户定位时滚动，新内容保选择与阅读位置。

### 复制、批注与阅读反馈

本页过程收起使用既有阅读动作区的低干扰入口，与查找、单条披露和消息动作保持主次；必要时可在窄面收纳，名称与键盘焦点仍完整可达，不另占常驻大工具栏。只收起过程载荷，原答案与失败摘要的视觉层级保持；范围和阅读保持只见[对话阅读合同](../behavior/conversation-mode.md#对话消息的阅读复制与标注)。

阅读点沿原消息动作区与共同阅读工具的轻量层级：在准确原记录旁显式命名，列表显示用户名称及可辨来源，改名、移除和返回含义分开；不增加占据正文的大章节卡片或常驻第二侧栏。命名输入、空列表、保存中、失败／未知与返回结果就地可读，键盘和窄工作面完整可达；长名称可换行或省略但保完整可读入口，操作不被挤出。行为与持久边界唯一见[命名会话阅读点](../behavior/conversation-mode.md#命名会话阅读点)。

复制、标注等动作默认安静，hover／focus 时在原消息操作区出现，失败状态仍可达；消息停靠、作者与密度见[《消息布局与身份密度》](#消息布局与身份密度)。

从当前消息继续到新会话的动作及其语义标示沿[续聊入口的呈现](session-recovery.md#从消息继续到新会话)，与原消息操作保持同一轻量层级。

思考／工具展开与真实复制成功可有短而可中断的局部反馈，关闭后不保留重 Markdown 挂载，不用持续光效或全消息入场动画。减少动效时直接呈现最终态，反馈仍依真实操作回执，不能以动画或计时宣称成功。

选区首先显示轻量浮动操作条，以 SVG 和短文字提供「批注／复制」，不弹出大表单。明确批注后才出现细划线和紧凑浮窗；宽窄均在所属阅读面及视口内夹紧，空间不足时翻转／移位，不撑固定空列或在末尾铺表单。引用默认单行摘要，可展开全文；留言沿 Message Tool 输入语言按内容增高。目标选择默认当前 Agent，以头像和名称表达身份，展开后按本项目（含新建）、Mote、其他分组，长名称收敛且完整身份可达。发送是明确主动作，加入当前回复草稿为次动作；关闭、丢弃、复制不混用。克制阴影、轻边界、紧凑字号建立浮起层次，失败和待确认就地清楚，不堆重复元信息或满宽按钮。原 Range、隐藏、只读、焦点和输入所有权唯一见[《对话消息的阅读、复制与标注》](../behavior/conversation-mode.md#对话消息的阅读复制与标注)。

固定协调对象使用 Mote，入口与原对话面唯一见[《Mote 快捷入口与当前协调上下文》](motes-and-coordination.md#mote-快捷入口与当前协调上下文)。名称与职责归[《Space、Folder 与 Topic》](../behavior/spaces-and-layout.md#spacefolder-与-topic)，不在对话正文再列身份标题、角色说明或模式栏。

首次对话读取失败的空白工作面沿共用 Region 全页状态组件，采用恢复页相同的 Graphite／Mint 材质、开放阅读构图、语义图标和动作语言。标题说明阅读未完成，简短说明交代影响与保留内容，原始诊断按需展开，主动作就地重试准确读取；不在全页状态上方再叠多条同类错误横栏。已有正文时使用单一紧凑服务窗入口，按需查看各来源与其恢复动作；分享观察提示归原 Composer 的轻量状态入口，完整原错误和只读刷新可达。正常、窄分屏、明暗主题与减少动态下，正文、草稿和键盘焦点保持。

## 真实对话与行内引用

引用短名在输入正文中原位呈现，下划线提供可操作暗示，类型由字形和名称共同表达；焦点可见，窄窗不横向撑宽。功能与恢复约束见[输入与语义引用](../behavior/conversation-input.md#对话接入新组件与输入引用闭环)。

对话正文中的 Agent applink 呈现为与文字基线协调的紧凑行内名片，复用现有身份图形（普通 Agent 的 Provider 图标与珐琅质感、Mote 的原头像）及真实状态标记，名称仍是主要判别器；轻量材质、边缘与克制动势形成精致感，不为每个引用插入大卡片或撑高整段。hover 与键盘焦点打开同一份有界详情，完整名称、原 SID 与未知说明可读，点击和披露命中清楚且不嵌套交互控件。正常／窄分屏、明暗、长名称和重复引用下不横溢出，减少动态时保静态状态与焦点提示；隐藏面停不必要动画。原引用、当前资料、身份与导航边界只见[对话正文中的 Agent 对象引用](../behavior/conversation-mode.md#对话正文中的-agent-对象引用)。

行内对象引用的补充密度：Region／Tab／Space／Zone 与 Agent 使用同一轻量材质、基线和圆角语言；空间类型用清楚的小 SVG，不伪装 Agent 头像。显式标签优先，未知名称时用原 ID 而非猜名字；过长 ID 只视觉省略，完整原地址可查看和复制。打开与复制为相邻独立命中区，键盘可达，不嵌套按钮、不因 hover 出现操作而挤动正文。交互事实只见[对话正文中的 Agent 对象引用](../behavior/conversation-mode.md#对话正文中的-agent-对象引用)。

## 原记录文件

原记录文件在所属消息中使用轻量文件行：原文件名为主，未知原名明确可辨，已知 MIME 与大小作为安静补充；下载是唯一主动作，原引用按需复制。复用现主题、语义文件／下载图标、轻操作与焦点语言，不叠厚卡片、重复标题或说明墙，不把 data URI 或 base64 铺成正文。

长名称、准备中、读取失败和重试在窄工作面完整可达，动作自然换行，不缩字、裁内容或挤出焦点。下载交付不显示未经确认的“已保存”；读取、迟到和原授权边界只见[原记录文件的本地下载](../behavior/conversation-mode.md#原记录文件的本地下载)。

## 时间轴视觉关键帧

消息气泡保原作者图形、选择与焦点，有缓存时在上沿叠一枚很小的等比缩略图。缩略图保持在本轴的局部高度与原标记宽度内，不遮前后文字、时间轨或相邻标记；宽窄均沿原碰撞聚类。聚类继续以数量为主，菜单逐条给出对应小图与原摘要，不能用一条图代表整簇。无图保持原消息标记，不用加载动画或空槽制造持续等待；行为和缓存来源只见[时间轴视觉关键帧](../behavior/conversation-mode.md#时间轴视觉关键帧)。

## 对话贴图缩略图与灯箱

本地贴图与 Provider 原生记录中已分类的图片资源复用同一缩略图与灯箱语言。缩略图沿正文流排列，保持图片比例与可辨认的内容边界，保留引用复用入口，不把完整路径撑成一行按钮。内联图片编码不铺成正文。加载中或失败时沿原始引用的可读文字呈现，避免空白占位、破图图标与失效灯箱；读取和解码的唯一行为合同见交互文档[《对话里的贴图》](../behavior/conversation-mode.md#对话里的贴图)。缩略图点击后在共享 Overlay 中放大，灯箱不改变消息高度；关闭动作回到原缩略图，键盘 Escape 与遮罩关闭保持同一语义。

图片查看以图像为主体，名称与关闭动作位于紧凑顶部，缩放、适配、前后浏览与当前序号位于不遮挡原图的工具行。控件共用语义图标、主题、焦点和密度 token；窄窗保留可发现且可键盘操作的核心动作，不缩小图像阅读空间来容纳长路径。放大、平移与切图即时反馈，减少动画偏好继续生效；失败说明和重试属于当前准确图片，不能覆盖其他可用图片或伪装读取成功。

图库导航与缩放操作按实际可用宽度成组换行，触屏较大的点击区同样适用；不以裁掉操作或缩小命中区维持单行。原图适配区、标题与关闭动作始终留在灯箱内，换行不改变组内顺序、键盘访问或原资源读取。

## 可复用对话与 Workflow 组件密度

同类过程在 Desktop、Mobile 与其他阅读位置复用完整的记录呈现和披露语言；宿主密度、文件／链接动作与锚点可不同，已有摘要、原载荷、差异阅读、准确定位、键盘访问和复制能力不能因收敛组件而丢失。普通发言、协作回报、系统记录可使用不同薄外壳，正文和来源详情保持共用，紧凑模式可与各类外壳组合。职责、来源适配与完整 Copy 的技术边界见[共同过程、正文与卡片外壳](../conversation-client-architecture.md#共同过程正文与卡片外壳)，不以现有某一端组件的功能子集定义统一后的体验。

### 过程层级与详情

聊天观察区采用 Workflow 的“时间线 + 分层 surface + 状态轨道”语言，但保留对话正文、权限请求和 Composer 各自的内容密度。

视觉品质来自层次、对比、细微动势和状态反馈，不来自大面积渐变、过重阴影或装饰性卡片堆叠。

过程摘要与 trace-only 保持紧凑，不把每一步套成大气泡、厚 header、重复头像或标题墙；失败、进行中与全部原步骤仍清楚可达。

原工具详情的可读格式／原文选择沿轻工具行语言，不叠卡片，长键值与原文本均可完整阅读。

通用工具记录按原生结构中的调用／结果种类使用独立语义图标，不能一律借用终端轮廓或从工具名猜工具类型。调用与结果采用同族模块及输入／输出方向，小尺寸仍清楚；结果图形不带成功勾选，明确失败仍使用原失败标记和原因。记录默认静止，已出现调用或结果不构成当前执行事实。保留原文、Call ID、次序、未知状态与按需展开、复制，不在呈现层配对记录或补推执行结果。

思考／工具详情的局部复制放在展开载荷的轻量操作行，沿普通代码块复制的图标、状态和焦点语言；原折叠摘要保持主次，不在折叠行常驻额外工具，也不叠装饰卡片。长 Call ID 可完整换行，复制动作不被挤出窄栏；处理、已复制及失败重试清楚可辨，明暗和触屏保持可用。原文和回执边界只见交互合同[《对话消息的阅读、复制与标注》](../behavior/conversation-mode.md#对话消息的阅读复制与标注)。

### Workflow 行、数字与变体

平铺机器行沿既有 24px 行高、20px 节点槽、56px 等宽时间槽和 12px 横向 padding；展开内容与自身标题左缘对齐。记录型过程使用共同 compact 行及层级缩进，原生与 captured 不各造布局；详情沿同一过程载荷层级，缺时间不占空时间沟。时间线沿既有 hairline spine，节点填充光晕，不叠装饰环。

- Workflow 时间线沿用聊天 Activity 的低干扰行语言：普通 tool 行与 Workflow 卡片共用时间线缩进和折叠箭头，不额外套一层装饰性外框；只有输入框上方 dock 作为独立浮层保留 surface、圆角与内部滚动。
- 对话中已接入的记录型过程使用更轻的层次，正文与真实状态先于整圈框线；折叠、展开与焦点仍清楚可辨，不用重边框、卡片套卡片或更小字号建立层次。Streaming／进行中采用精致、克制的 animated SVG 状态图形，线条与既有小图标尺度一致，动作安静且不引起文字或数字位移；减少动态效果时静态仍可辨。状态事实与阅读保持只引用交互合同[《可复用对话与 Workflow 表面组件》](../behavior/conversation-mode.md#可复用对话与-workflow-表面组件)。
- 公开进度说明沿共同正文的轻量紧凑类别，完整文字仍可选、复制和标注，弱化 chrome而不缩小正文字号或截掉内容；正式回答的主阅读层级保持。协作记录的摘要、sender→receiver与最后记录状态先于原载荷详情，无实际阶段／统计不画空字段或 progress rail。阶段、来源、顺序和旧历史行为只引用[《可复用对话与 Workflow 表面组件》](../behavior/conversation-mode.md#可复用对话与-workflow-表面组件)，不在密度合同重复定义。
- 组件密度固定在 `--fs-micro` / `--fs-meta` / `--fs-body` 三档与 2/4/6/8/12/16px 间距刻度内。状态徽标、模型短名、最近工具、耗时、token 和调用次数使用 `tabular-nums`，数字不因状态切换跳位。
- Workflow 头部的 progress rail 是结构性进度，不是选中指示；选中阶段或 Agent 使用整行轻量 surface、`aria-expanded` 和焦点环表达，不使用重复的单边竖条。状态颜色只承担语义，失败/终止/暂停仍需字形或文案。
- Agent 行默认一行：状态字形、label、模型短名、最近工具、耗时、token；打开后才显示阶段、尝试、排队/开始/最近活动、工具调用等新增信息。展开面板用两列 `dl`，不重复标题和状态。
- 超过 8 个 Agent 才进入双列 grid；超过 12 行且尾部连续安静项才显示“还有 n 个”。失败项与当前运行项始终优先可见。≤560px 隐藏模型与最近工具，头部数字换行到第二行；触屏控件最小命中区 44px。
- 同一 Workflow 组件通过 `dock` 变体复用结构，仅收紧模型和行高并限制 `max-height: 220px`；不得为 dock 维护另一套状态投影。旧 daemon 用 flat tool 行样式，无箭头、无空卡片。

### 时刻与时长读数

时刻采用补零的二十四小时 `HH:MM:SS`，不以 locale 的上午／下午格式改变时间沟宽度；跨日范围带日期，同日用短钟表。时刻、时长和偏移沿同一既有格式化能力，使用 mono 与 `tabular-nums`；不能靠截取偏移字符串的符号拼出时长。

时长从最高非零位起报，如 `3h04m03s`、`4m03s`、`3.2s`、`840ms`；低位补零，高位为零省略，不在分钟封顶。分档依据实际显示精度取整后判定：秒档显示到十分之一秒，分钟及小时交界不产生 `60.0s` 或 `59m60s`。该格式同样用于偏移、标尺跨度、已记录范围及可访问说明，不各造一份格式器。

标尺给真实起止与已加载数量，偏移及范围说明按需读；消息和单条机器行保已记录的具体时刻。紧凑过程摘要保步骤数与真实状态，具体记录起止与偏移由同一头部的悬停／键盘说明可达，不再叠一行重复统计；普通过程变体可沿原头部直接显示范围。较长范围自然换行，不挤工具名或扩宽固定时间沟。无时间事实保持未知，不显示假跨度；同刻的记录范围不硬报 `0s`。范围的来源与执行时长的区别只见[Activity 记录时间](../behavior/conversation-mode.md#activity-记录时间的直接阅读)。

### 开发观察与真实消费者

Gallery 是共同组件的集中开发观察表面，可切换 light／dark／system，展示 running／completed／failed／killed／paused、窄屏和旧 daemon。它使用最终生产组件、真实公开 props 与全部关键状态，页面结构与聊天页一一对应；展示数据是静态 fixture，不引入 Runtime 或 Chat Store。生产聊天观察区与 Gallery 共用同一消息组件、Workflow surface、密度和状态表达，不复制另一套视觉实现；聊天页适配层只把真实 Activity／Run／Agent 事实映射到公开 props，缺失或未知事实保持未知，不用示例值补齐。

开发 Gallery 可显式查看原组件轮廓并调整示例容器的可用宽度；控制组紧凑且键盘可达，示例仍用原字号、组件及公开 props，不以整页缩放冒窄宽适配。关闭轮廓回到正常呈现，设置只留本地示例，不污染生产偏好。

## 原生回合摘要

原生回合摘要沿共同 Conversation／History 与 Workflow 的轻量过程语言，使用一行安静的耗时、输出用量和实际过程披露入口，回答保持主要阅读面。复用现有字体、颜色、间距、语义图标与时长格式，不另套头像、大卡片、边框墙或常驻统计栏；数字采用等宽读数，输出 tokens 的含义通过短文字和可访问名称表达，不仅靠向下箭头辨认。输入、合计和计量范围可按需披露，避免三套数字争抢正文。

有可读过程时，整行披露的 hover、键盘焦点、开合与命中清楚；只读摘要不画空箭头。窄 Region 允许辅助读数自然换行，保持原字号、有效命中区和完整内容，不挤窄正文或隐藏失败。状态只表达真实已报告的结束、失败、中断或未知，正常摘要保持中性；数值和经过时间不驱动伪进度、呼吸动画或成功色。原过程开合、复制、Range、滚动与草稿沿共同阅读组件保持，明暗、宽窄和键盘访问须在真实消费者中核对。

回合归属、整轮与响应口径、缺值和有界过程的唯一行为规则见[原生回合摘要与过程披露](../behavior/conversation-mode.md#原生回合摘要与过程披露)。

## 分层人机交互的呈现

交互行为以 [Provider 与人机交互的分层收敛](../behavior/agent-capabilities-and-messaging.md#provider-与人机交互的分层收敛) 为唯一约束来源。输入结果、待答请求、服务窗和注意力摘要复用现有控件语言：紧凑图标、对象、原因和可执行动作；只在有信息时展开详情。持续问题不遮住可用终端或占据重复全局弹窗；提示与原对象可互相定位，并保留键盘操作、IME 和无障碍名称。

回答失败在原卡片内使用低干扰、可换行的原因提示，保留原选项。需要原生确认的未知请求默认收为紧凑、安静的对象摘要与现有“Open terminal”动作；完整问题、工具输入、回执与原因按需展开，不把长原始 JSON、重复状态标题和来源提示堆成常驻大卡片，也不遮住可用终端。确认处理后的当前请求卡片消退，不留已处理占位或继续挂“Needs you”；完成与未知的事实边界只见上述交互合同。全局告示沿用既有服务窗与紧凑定位按钮，显示所属 Session，不增加第二套通知外壳；宽窗和窄分屏中的摘要、终端入口、详情与键盘焦点清楚可达。

对话中的当前 Permission/Question 沿共同聊天的身份与内容层级呈现，问题与选项构成一块紧凑可读内容，显示文字“需要你回答”及克制的等待图标；不能仅以颜色表示交互。真实长选项和说明在窄窗自然换行，键盘焦点和完整命中区可辨。提交中、只读、需要原生处理与失败各有对应文字，失败仍在原请求附近；没有请求不增加常驻卡片、空槽或状态栏。行为与请求/响应事实只见交互 SSOT[《Provider 与人机交互的分层收敛》](../behavior/agent-capabilities-and-messaging.md#provider-与人机交互的分层收敛)；不另定义 Provider 特有气泡或第二套控件。

历史异步问题沿[原生异步问题与答复](../behavior/conversation-mode.md#原生异步问题与答复)呈现为“已记录的问题”，不能因当前阅读窗没有答案显示成当前待答。答案可在原卡片选择或填写，主动作是“发送答案”；当前未答题均完成后启用，默认预选不触发发送。草稿、发送中、已提交、结果未确认与已记录答案分别表达，成功以真实回执为依据。结果未确认时显示原答案及“继续原发送”入口，后续编辑草稿独立保留。只有准确回复通道不可用时才就地说明原因并提供“打开原终端”；复制仍可用于取用答案，不成为正常发送的前置步骤。宽窄、明暗和键盘操作保持原焦点与披露语言，事实与恢复边界只见上述行为合同。

## Agent 群聊连接入口

所用机器人应用以原选择控件保持紧凑、准确和可改选；列表与当前选择用短说明区分已保存、原初始化待继续、暂停、接入未确认及准确失败；同名应用在选项和选中摘要中直接显示平台域与可区分的应用身份，不仅藏在悬浮提示里。确定禁用的应用明确显示暂停与不可用于新群，旧关系仍显示其原应用；原初始化待继续的对象与普通新群可用选项分开，保留具名的原设置入口，原应用身份和核对／管理入口可达，不用同样的正常外观把保存当成已能收发。新提案采用 Mote 默认时给轻量来源说明，不把“默认”画成已绑定或有权限。已有关系和原未决请求仍显示原应用；默认失效时保留原身份及简短原因，提供明确选择其他身份／进入原设置的路径，不用空白选择器或整页置灰代替。应用读取与选择不改变 Agent↔群关系的主视觉，长名和应用身份在窄窗自然换行，完整识别信息可按需读取。

Mote 内每个 Agent 的原对象菜单，以单一「连接群聊」主入口、已有群详情和相关设置组成稳定的具名组；自动同步关闭或读取未知时保留入口，并用准确短说明引导查看或设置，不留孤立标题和分隔线。Region 右键与 Agent 更多菜单复用同一分组，标题安静、组内动作紧凑，沿既有菜单的图标、键盘与焦点语言，不另套子导航或重复平台组。总开关的准入与恢复仅依[原 Connector 总开关行为](../behavior/settings-and-observation.md#外部对话应用接入)，不从空列表或观察失败猜关闭。

Terminal 右上小标题栏按当前已接入的外部 channel contributions 各显示一个紧凑平台图标，与 Agent 自身 Provider 图标区分；不再放单一 Connections 文字条、常驻群名或长状态文案。平台字形与状态角标共同适配实际低矮信息带的字形高度，不因按钮命中区较大而放大绘制；缩绘制不缩原动作命中区或键盘可达性。hover 不另叠按钮背景盒，沿原安静信息带以字形反馈；焦点保持清楚可辨，hover、焦点和展开不增加按钮或标题行高度、挤动相邻标题与动作。平台字形从初始态起均为灰度，hover／焦点只增强可见性，不在查询后才从品牌色切回灰色；原类别角标继续表达准确状态，不以品牌色推断已连接。相邻平台入口与展开面压缩重复留白，保留原透明命中区、焦点和可读的动作分区。已确认未绑定时只显示灰色小图标；未知、关闭、暂停及需核对的类别用一致语义图标与从属标记辨认，并提供 hover／键盘可达的短说明，不能只靠颜色区分类别或把未知画成未绑定。平台名称、准确群名和简短观察在 tooltip 及展开面首层可达；长错误与技术原因只在面板内说明，不用常驻错误文字、旋转符或数量摘要挤占原 Agent 标题。全局或平台自动同步关闭仍保留图标和恢复路径；只有独立的“在 Agent 标题栏显示”偏好已保存为隐藏时，才隐藏对应平台入口。未知或读取失败不改变显示偏好。该平台的原关系或草稿不通过其他平台及 Other channels 重新露出顶部入口，原设置、管理与恢复路径仍可达；两个设置分别由[原配置及 Connection 服务合同](../behavior/settings-and-observation.md#外部对话应用接入)持有，不把 catalog 贡献变成另一份启用状态。同一 channel 的多条关系和待续接任务在展开面逐条列出，准确应用与群身份用于区分同名对象，不按名字合并。群名读取失败保原确认名或准确群标识及简短缺口，不用创建草稿冒充当前平台名称。

展开面贴近原平台图标，以当前群名为主体；正常与窄窗都保留原命中区、hover 路径、键盘焦点和终端位置。首层用两条紧凑方向摘要回答“对话发到群了吗”“群消息交给 Agent 了吗”，成功、等待与需要操作分别具名；最近已送达的消息不因另一笔历史回执未确认而染成警告。群名下不铺应用与群的技术 ID，同名对象仍有可辨来源。当前需要处理的问题只出现一次，紧邻一个具体动作，例如“恢复此群同步”或“管理成员访问”；其他设置和完整证据按需进入。成员、平台与全局动作在原位置说明实际范围，不用笼统 Needs attention、重复警告列表或多个近义入口让用户猜下一步。

展开期间自动刷新当前群的原观察，关闭或离开可见工作面后停止；查询保留现有内容，用安静的局部反馈表达，不闪空、不用持续旋转冒充后台正在执行。底层已有自动恢复时不要求用户反复点检查；用户主动关闭或暂停仍通过明确动作恢复。详情保留最近检查时刻、保留快照的说明、来源缺口、原请求与技术身份，无法确认的历史不被隐藏成成功；只有确实需要用户处理的事实成为首层警告。状态与恢复的权威边界沿[原状态行为](../behavior/conversation-mode.md#共同对话协议与外部交流入口)。

菜单直接提供每条准确关系的详情与加入路径，以及当前实际支持的平台连接、同步设置动作；Connect a conversation 进入对应 channel 的原选择面，所选应用与已有关系用所属平台的准确名称和图标辨认。存在尚未按 channel 确认归属的原进度时，入口使用 Open channel setup；原选择面再明确展示可续接的原申请，不能声称每个 channel 都有待续接任务。原托管连接读取失败且未取得群关系时，主动作使用 Check bot hosting 核对原目标。Channel settings 到达对应平台的设置页；当前群的全局同步关闭时，通过具名动作直接到原群内的自动同步控件，并明确其影响全部外部机器人，不重复陈列近义设置入口。平台呈现与准确设置目的地来自原 Settings contribution，通用菜单不另维护平台名单，也不陈列尚未交付的平台能力。选中后沿原菜单焦点交接进入准确 Host／Session 的详情或设置，不因后来焦点变化换目标。自动同步关闭时，原设置动作仍可见并说明作用范围，不能让用户从 Sync off 猜测恢复入口；首层同步控件的布局见[设置页现代化密度](settings-and-observation.md#设置页现代化密度)。完整群名称与轻量来源在详情首层可见，查看群、暂停、重新连接与投递问题集中呈现；正文和 Composer 保留阅读及草稿空间，不新增常驻连接工具栏或顶层聊天导航。

Message Tool 的共享提示沿输入上方的轻量上下文呈现，与输入框保持相同侧边距，不另占一行标题。每个受众以小平台图标、准确共享范围与群名组成紧凑行；长群名在自身空间内省略，完整名字和准确身份按需可读，窄窗不把范围、名字和长状态散排成文字墙。每个受众至多一个从属短状态，明确暂停、关闭、初次检查或读取不可用；普通缓存过期不常驻错误提示，资料检查细节从属于准确原群。共享提示不复用标题栏的连接按钮、设置菜单或群详情弹窗；无关系时整段缺席，仅共享 Agent 回复时不能写成用户正文也会外发。提示不抢输入焦点、草稿、光标或主操作；原关系、提示与递送的事实边界只见[共同协议行为合同](../behavior/conversation-mode.md#共同对话协议与外部交流入口)。

群聊连接面是当前 Agent 的轻量任务面，以 Agent 与目标群的关系为主体；创建时群名称是主要编辑对象，创建后以当前平台群名为主标题，准确群 ID 为次级说明。仅有原创建名称时明确标为创建时的名称，平台名读取中或不可用就地说明，不将暂存名称呈现成当前平台事实。所选应用属于准确可辨的次级来源，配置与技术凭据按需进入，不能用等权字段堆叠代替任务组织。复用 Mote 与 Settings 既有的石墨／Mint 功能材质、表单和动作语言；创建、邀请、共享确认与步骤反馈围绕同一关系就地呈现，已确认步骤、未知和成员访问分别可辨，不因布局整合混成一个成功标记。控件比例、行基线、分组节奏和主次动作在原工作面正常与窄窗中须达到同项目成熟表面的完成度。完整构图由[独立看图](shared-rules.md#agent-主观审美的判断边界)判断，统一控件、深色 Token、文案或折叠本身不代称现代化品质。

同一连接对话框先提供清楚、等同可达的已有群／新建群选择，当前选择与准确 Agent 在首层可辨。「群 → 共享 → 成员访问」以紧凑步骤保持位置感，当前环节拥有一个明确主动作，已确认结果保留可见摘要；步骤不作为隐藏已有信息或常用动作的门禁，各分区仍按当前任务保持主次。创建结果确认后直接呈现原群与共享的下一步，连接确认后说明共享范围及尚需谁加入、谁获授权。等待保留当前内容并在动作附近连续反馈，不闪空或用忙碌样式掩盖未知。

创建面以群名称、准确成员／受众和共享范围为主，当前 Agent 与所选应用在同一面可辨。已确认的创建账号以“创建账号”及可辨身份呈现为默认邀请成员，仅在当前本人关联已确认时标示“本人”；关联未确认时就地说明缺口和准确加入动作，不要求用户从技术 ID 猜本人。创建中、已创建待绑定、绑定失败和结果未知就地呈现并保留原输入；未知给出检查原操作入口。正常与窄窗保留主动作和完整错误说明，成功标记只对应已经确认的步骤。身份、授权与恢复边界唯一见[共同协议行为合同](../behavior/conversation-mode.md#共同对话协议与外部交流入口)。

群详情以当前平台群名和准确 Agent／机器人身份构成清楚的顶部主体，群 ID 与技术来源从属；当前最相关的动作紧邻对应事实。概览以两个方向的状态卡分别呈现“对话 → 群”和“群 → Agent”，范围、短状态、检查时间与必要下一步主次分明，不把配置开启画成递送成功。成员访问、Sharing、Join 采用带语义图标的分区入口与一致内容层级，原授权、共享、加入操作在对应分区直接可达；不要求完成前一步或展开技术诊断才找到常用动作。最近消息结果、全局同步、机器人接入与成员发请求资格分别具名；关系已保存、同步关闭、成员待授权和观察未确认不混成一排完成勾或笼统“已连接”。长诊断、技术身份和原回执集中按需展开，不在各区反复平铺。正常与窄窗均保留群身份、方向状态、主动作及关闭／返回，局部分区可自然堆叠，不裁掉成员动作或挤成连续说明长文。

共享区直接回答“同步哪些对话”“群里怎样让 Agent 回复”，将正常对话的双向可见与触发处理分开。新建专用群、连接已有群的默认触发选择在提交前可见并可改；正常对话范围直接说明包含 Terminal 已提交消息、排除工具原始输出与内部上下文。准确创建者显示创建账号标记及三项能力的默认预选，工具审批范围在保存前清楚可见；本人关联未确认时不标为本人。未保存预选与已保存授权分别呈现，既有明确关闭或撤销不被默认勾回。多群共享列出全部受众及跨群可见性，保持单一准确 Agent 上下文。

最近消息分方向说明结果：入站显示已记录以及当前是否提交给 Agent，等待、原生采用或回复关联只有原回执支持时才展示；出站显示发送中、已送达、待核对或未交付。暂停、恢复和解绑采用不同具名动作，恢复说明从新消息继续并保留原成员范围；已保存群关系、全局服务、机器人状态与实际消息结果保持分区，故障按真实影响范围说明。局部查询保留内容，在对应动作处持续反馈，不闪空、不用不断旋转暗示未知操作仍在执行。

群内连接说明卡以“此群已绑定”或“此群同步已结束”等关系事实为标题，标明准确 Agent、群和共享范围；同步关闭或未确认时就地说明。结束卡明确 Agent 继续存在，避免让成员以为整个 Agent 已结束。卡片沿同一产品的轻量层级与 bot 身份语言，技术回执从属；重复读取不产生新卡，卡片投递失败在原关系详情可见并保留准确恢复入口，不把卡片失败画成解绑失败。

当前缺口旁保留一个明确就地动作，其他独立分区和已有结果仍可读。全局同步在原群任务面复用设置的同一控件语言和原请求反馈，操作前清楚说明影响所有外部机器人，避免为打开同步往返寻找设置；它不夹带机器人启用、绑定或成员授权。

未取得的信息就地说明，不能用空分区或推测填满页面；本地共享已启用、后台读取就绪和已送达采用不同的具名说明，不能让单一 Sharing on 或 ready 暗示整条链已可用。入群路径或成员使用权仍待确认时，原下一动作保持可见。有效官方入群链接可直接显示二维码，并保留打开、复制及有效期；缺失、过期和原结果未知分别显示原链接动作或查询入口，二维码不画成已入群或已授权。刷新保留原群、已有结果与局部连续等待；消息收发结果与必要下一步保持可见，仅完整技术身份、原操作回执及诊断轨迹按需折叠，读取范围的关键缺口就地说明。保存与可用资格的唯一边界见[共同协议行为合同](../behavior/conversation-mode.md#共同对话协议与外部交流入口)。

群详情的 Member access 以成员列表为主体，每人只出现一个可辨身份与权限摘要，直接在该成员行编辑，不同时堆叠选人列表、已授权列表和重复表单。无成员可发请求时在群概览明确提示并直达成员分区；有授权时显示具名已保存结果。编辑处明确标示未保存、保存中、已保存或原结果待核对，主动作紧邻对应成员，无改动时不要求重复保存。创建账号沿准确来源具名，技术身份按需查看；暂停时就地解释不可保存的原因与恢复动作。聊天与远程权限沿紧凑表单与 Mint 动作表达两种独立授权。除准确创建者的三项预选外，其他成员的远程权限默认关闭；具名成员保存前说明该群会接收作决定所需的原权限上下文，并提供明确撤销；不以危险色铺满正常表单，也不把长平台身份作为主标题。提交、未知与查询反馈归准确成员及原操作，重开仍可恢复。平台权限卡以原请求和选项为主体，只在具备真实 responder、分享授权与准确映射时提供动作；否则保清楚的只读原因和原本地入口，不能展示貌似可点击的假按钮。

机器人设置提供“所有群的成员访问”，以准确机器人应用和托管 Host 为范围；无需先建群才能配置。群详情的每个成员显示“使用机器人设置”或“仅本群”，就地显示实际三项能力及来源。切换为本群设置先带入当前有效选择形成未保存草稿；切回继承须明确保存，旧本群决定仍可查。应用规则更新不覆盖本群特例，应用名单不冒充当前群成员名单。

保存动作明确作用范围：本群编辑只保存本群，机器人设置保存到此应用的现存及未来群。应用级工具权限的上下文分享范围在保存处就地说明，不能藏进技术回执。创建者三项默认在未保存时明确标成建议，其他人不默认获准；已有撤销、限制、未决操作及用户编辑都不被迟到资料或默认值覆盖。原结果待核对与真正保存中分别显示，不靠旋转动画制造仍在执行的错觉。

创建与绑定已有群保持同样的对象关系和设计品质，绑定面不能退回技术标识与配置字段的堆叠。amux 与群聊可采用适合各端的版式，但同一共享对话的信息和原记录关联完整可达。AgentMux 用户发言采用独立用户卡片，以原正文为主体，轻量标明真实来源与「通过 amux 发送」，与 Agent 进度和最终回复形成清楚层级；不把机器人头像当作原作者。等待处理的原输入就地标明等待，后续状态沿同一条卡片变化，不能用旋转动画暗示结果未知的原发送仍在执行。正文、附件、问题与回答的阅读层次沿共同对话语言，平台限制通过分段或准确资源入口表达，不用省略内容换取整洁。身份、共享资格和结果隔离的唯一合同仍见同主题行为，呈现不猜控制或授权事实。

飞书 Channel 的 Agent 过程消息采用无标题行的紧凑原生卡片：正文用小一档的备注字号，收紧内边距和组件间距；连续过程不反复占用“Agent progress”标题行。原正文、换行与字面内容完整保留，文字在正常与手机宽度下仍清楚可读。消息列表摘要取自真实过程内容；最终回复、用户发言、问题与权限卡保留各自可辨层级。仅改变新准备卡片的呈现，不改写原冻结请求或把未知投递当作重发理由。

群内原用户 query 用飞书原生 `Get`、`OnIt`、`DONE` reaction 分别标记收到、已开始处理、完成处理；直接附在原消息上，不为这三个反馈另刷消息卡。标记表达已经发生的里程碑，不把 `OnIt` 当作持续在线指示；完成标记只消费[原处理事实](../behavior/conversation-mode.md#共同来源与双向交付)，不因看到回复就补勾。等待、失败或未知仍沿原诊断与对话状态说明，不使用成功表情掩盖。

飞书最终回复以正文为主体，采用无重复标题栏的原生富文本卡片，正常字号和清楚的段落、列表、强调、代码及表格层次。普通回复在平台实际编码预算内保持一张卡；确实超过限制时沿内容块分段，不能在表格半行或代码围栏中硬切。大表格分段保留对应表头与完整行，代码分段保留语言和围栏；完整内容可读，不以截断换取整洁。原生 Markdown、表格和大小预算由飞书 Channel 持有，最终回复的 feed 用途仍明确为 Agent reply；用户发言、问题和权限保持各自身份与交互。旧冻结卡片保持原请求和核对路径，不因新样式改写或重投。

回复中的图片按原正文位置显示为可预览的真实图片，保留替代文本或说明；Mermaid 图表显示为清晰可读的渲染图，并保留源码查看方式。图片与图表沿正文节奏排列，手机宽度下保比例并可放大，不把裸本地路径、图片 Markdown 标记或整段图表代码当成正常视觉结果。读取、渲染或上传失败时就地说明该资源尚未送达，正文仍完整可读；相关来源、权限及投递行为只见[共同来源与双向交付](../behavior/conversation-mode.md#共同来源与双向交付)。

普通协作发言卡片以角色身份和正文组织，不重复显示宽大的 Conversation message 标题栏。使用原协议确认的 Agent／Mote 头像与名称，小尺寸身份区配轻量用途标记，正文保持清楚的阅读层级；角色感来自真实身份和布局，不增加虚构等级、奖励或状态。技术来源、读取状态及未知原因在诊断详情查看，不作为正文前缀。身份尚未确认时保持诚实标识，不能根据内容猜作者；头像读取与共享沿原资源合同，缺失头像不阻塞正文。

飞书 Channel 的所有对话卡片统一提供消息列表摘要，顺序为“短时间 · 来源或用途 · 正文摘要”。短时间来自原消息或原投递操作已经记录的时间；缺失时省略时间，不以查询或重试时刻补造。来源或用途区分用户发言、Agent 过程、最终回复、问题、权限及连接状态；正文只取原卡片真实内容，在平台预算内收敛，完整正文保持可读。新操作在原 Outbox 首次记录时固定时间，恢复和查询不改摘要或原冻结请求。

## 共同工作面的品质与保持

共同呈现须在真实消费者的完整代表图中由独立 Agent 审阅；修正后复拍复验至明确可交付。Gallery、截图采集或 CSS／像素断言不能代替实际工作面的审美与交互结论。正常与窄面、明暗主题、长内容、失败状态、键盘焦点、触屏及减少动态偏好纳入适用场景；原 Range、阅读位置、焦点、IME、草稿、编辑节点与 Terminal 几何的保持仍沿行为 owner，不因视觉收纳新增读取、观察或持久事实。

## amux 协议卡片

协议卡在原消息正文内部形成紧凑、可辨的阅读层级：短类型标题、必要声明参数、正文和默认收起的完整原文。通用卡用安静中性表面；常用平台说明、Browser 场景、A2A 原信／引用、接续与快捷回复沿同一控件、主题和字号形成可辨样式，不以颜色暗示来源已认证或动作已执行。普通正文不因卡片变成技术日志，reminder 保次级 disclosure。

长类型、属性、SID／MID、正文及原始 wire 可换行、选择并完整展开，332px 与手机宽度下不挤掉原消息身份、时间、复制和 Info。键盘可开合，焦点与展开状态可辨；原复制行为不从卡片重组内容。设置的协议样例复用真实消息组件，类型清单按原设置行与 disclosure 组织，不平铺一面等权大卡，也不增加品牌横幅。
