## 消息布局与身份密度

### 消息方向与气泡

用户和其他已核 Agent 的输入气泡在右侧，当前会话执行 Agent 的回复使用左侧轻气泡；所有正文保持左对齐，停靠不改变段落、列表、表格和代码的阅读起点。其他 Agent 使用轻量来源卡、真实头像、姓名与 Agent 来源标记，当前会话 Agent 回答不使用左侧竖线。作者事实与用户显示默认只见[《共同对话的用户默认外观与协作来源》](../behavior/conversation-mode.md#共同对话的用户默认外观与协作来源)和[《对话中用户消息的阅读方向》](../behavior/conversation-mode.md#对话中用户消息的阅读方向)。

只有人类用户默认显示的气泡加强与 Agent 的视觉区别：宽高顺随内容，短消息呈自然紧凑的气泡，长消息在可用阅读宽度内换行并保持内容完整。使用现有安静色阶、克制边缘和圆角形成区别，各作者共用协调的正文阅读字号，不依靠身份不同而缩小正文、固定大宽高或裁掉元信息换取区别。宽窗和332px中长姓名、声明、Markdown／代码、复制、详情与键盘焦点可读可达。作者事实、默认显示与阅读保持只引用交互合同[《对话中用户消息的阅读方向》](../behavior/conversation-mode.md#对话中用户消息的阅读方向)。

### 身份行与按需详情

共同消息卡先分标题行、小字说明行与正文，再布局内部元素。标题行有独立身份槽与固定的时间／复制／Info 操作槽，长姓名与 ID 只在身份槽内换行；来源、项目与声明进入独立小字行，不竞争标题位置。辅助项横向连续排列，仅空间不足时自然换行；声明标签按内容宽度，不拉满整行。长项目与来源沿自身项的原省略／完整披露规则，不能扩大卡片宽度。Info 始终在标题行且可键盘操作，详情沿原披露展开在标题下方；正文与续接独立，宽窄均不因说明变长而把按钮挤到第二行，不用绝对定位掩盖布局。

共同气泡的姓名与原始时间组成紧邻的轻量元信息组，姓名字号低于正文、字重更克制，时间进一步弱化，操作沿原按需入口靠后；不以拉开姓名和时间形成空标题带。头像跨消息文本行对齐，不单独撑高标题；保留原 32px 项目／Agent 复合身份与 20px 用户标记。表面使用安静填色、克制内边缘与协调圆角，用户色阶区别清楚但不压正文；长内容、窄窗、明暗和真实键盘操作沿本节原约束。

已核其他 Agent 与执行 Agent 的头像以真实项目图形为主体，Agent 图形在角上可辨，不把正文挤成窄条；缺项目的已知 Agent 保其身份图形。Agent 名字是首要扫描信息，时间与 Project／Zone／Tab 是安静辅助，长名字可读，辅助信息在窄窗可收敛且完整内容按需可达。Message details 使用紧凑图标入口，title／可访问名称与焦点可辨；详情按来源、作者和当前资料分组为少量紧凑行，不堆重复姓名、长空字段墙或常驻文字按钮。宽窗与 332px 中完整正文、代码、长姓名、头像角标、展开详情、失败动作与键盘均须可读可达；来源声明、未知状态、生命周期与当前资料边界只见[《共同对话的紧凑消息、复合头像与按需详情》](../behavior/conversation-mode.md#共同对话的紧凑消息复合头像与按需详情)。

Agent 消息的头像、名字和 Session ID 组成同一个紧凑身份组，不新增身份 toolbar 或第二块卡片；名字保持主层级，准确 ID 用较弱但清晰的文字常显，可选择，并以有明确 tooltip／可访问名称的邻近图标复制。窄面允许身份组自然换行，不把名字或 ID 压成纵列、藏到详情或挤窄正文；头像沿原复合身份和稳定尺寸，不用用户头像表示声明 Agent 引用。声明性质以克制短标签可辨，项目／Zone／Tab 继续辅助。复制反馈在原命中处即时可见、不移动卡片或改变高度；减少动态时保静态反馈，失败仍可读和重试。名字、ID、声明与复制原文的事实边界只见交互合同[《共同对话的紧凑消息、复合头像与按需详情》](../behavior/conversation-mode.md#共同对话的紧凑消息复合头像与按需详情)。

### 操作来源设备

用户消息与对话交互操作在既有作者、时间元信息旁以紧凑设备图标与名称展示来源，例如“来自 iPhone”；完整设备身份与操作详情按需展开，不增加独立大卡片或改变作者标记。Desktop 与手机共用此呈现，历史未知来源明确显示未知，不把 Agent 回复标成设备操作。认证归属及记录保全沿[《手机版 Relay 连接》](../behavior/public-control.md#手机版-relay-连接)。

### 共同阅读密度

共同气泡与已接入 Workflow 过程使用一致的轻量容器语言，优先减少外间距、容器内留白和外层读页的重复 padding；短消息不因容器空白被撑高，过程头部、摘要和步骤行的留白保持连贯。名字、主要正文与必要过程状态先可扫读，辅助资料沿原入口完整可达；消息与过程的边缘、缩进和展开层级连贯。共同聊天正文与周边界面采用协调的阅读尺度，Activity 与 History 共用同一正文、Markdown 和代码基线，不保留明显放大的聊天正文，也不把元信息压到密度下限以下来换紧凑。32px 身份图形与必要命中区保持，触屏操作保有足够命中区；宽窗和 332px 中的中文、长名字、代码、展开内容、复制反馈与键盘焦点清楚可读。调整限共同阅读作用域，不改变全局 UI、Editor 或 Terminal 字号，不得以裁内容、压窄正文或隐藏身份、失败、原步骤换紧凑。行为与保持边界只引用[《History 使用共同对话阅读面》](../behavior/conversation-mode.md#history-使用共同对话阅读面)。

Outbox、Focus 时间轴与对话模式的同类消息沿既有消息行、紧凑标记和按需说明呈现，不另造消息样式。输入来源、当前窗口与缺时间说明采用轻量来源语言，不新增常驻来源工具栏；读取范围与失败用消息面内的短说明和就地 History／Retry 动作表达，空态和窄窗仍可操作。首窗被后续工具／活动占满时，输入继续沿同一读取说明与较早记录入口可达，不新增控件或消息样式；原生新增记录的来源通知、作者、时间、投递和返回边界只见[用户消息来源](../behavior/conversation-mode.md#用户消息从-provider-原生会话取得)。

### 声明与系统来源

消息包装沿同一来源卡表达：真实作者为主，包内声明安静且按需可辨，裸协议标签不占正文首尾；来源标签、正文和按需动作层级清楚，不为声明再套厚标题墙、重复头像／边框或常驻工具栏。资料详情采用现项目图标与文字，正文保持主要阅读面。长声明、引用、正文与动作在 332px 仍完整可读；未知或不完整包装保原文，声明与 Copy 的事实边界只见[《共同对话的用户默认外观与协作来源》](../behavior/conversation-mode.md#共同对话的用户默认外观与协作来源)。

完整前导声明上下文沿共同消息的轻量披露语言收起为紧凑声明行；原尾文是主要阅读面，声明摘要不堆头像、重标题或独立大气泡。展开的原上下文可选择、滚动和完整读取，折叠入口有清楚的声明名称、开合与键盘焦点；宽窗和332px中尾文、引用、缩进代码、整条 Copy 与必要动作仍可读可达。连续声明与无尾文不制造用户正文；已核系统与未认证声明的事实边界唯一遵守[《完整前导声明上下文的同记录阅读》](../behavior/conversation-mode.md#完整前导声明上下文的同记录阅读)。

**声明尾文的连续排版**。收起声明后的普通尾文沿既有段落节奏紧接阅读，不因声明与尾文的分隔换行或普通段落默认外边距撑成大片空白。仅已识别声明之后至多两个完整前导 LF／CRLF 可作为阅读分隔不占空行；更多换行、空格、tab、正文内部换行、代码缩进和行末空格保持其阅读语义。普通用户文本及未识别声明不应用这项分隔处理，普通文本与 Markdown 段落复用共同段落间距。原记录、作者、声明与完整 Copy 的事实边界仍只见[《完整前导声明上下文的同记录阅读》](../behavior/conversation-mode.md#完整前导声明上下文的同记录阅读)。

已核 AgentMux 系统内容复用共同消息面，使用可读 AgentMux／System 来源和中性轻量样式，与右侧用户和其他 Agent 输入气泡及左侧当前会话回答区分，不只靠颜色。长上下文完整可读、可展开和可复制，不压倒真实请求、不另造常驻工具栏。身份与未知默认只引用[《共同对话的用户默认外观与协作来源》](../behavior/conversation-mode.md#共同对话的用户默认外观与协作来源)。

Provider 系统记录复用共同对话已有的轻量系统卡片：紧凑标题、来源与单行摘要，默认收起长正文，展开后沿原文本与资源阅读组件完整呈现。视觉不冒充人工消息气泡或 Agent 回复，不用警告色暗示故障；窄分屏、明暗主题与键盘焦点保持清楚可读，复制结果沿原反馈。来源与语义边界唯一见[Provider 系统记录](../behavior/conversation-mode.md#provider-系统记录)。

## 对话消息的视觉语言

### 正文与 Markdown

用户及其他 Agent 输入的 Markdown 复用共同语法与阅读组件，完整呈现列表、引用、链接、代码和表格。正文、各级标题、列表、引用、表格与代码使用一致的正文尺度，以字重、协调留白和局部滚动建立层级，不以多级标题放大字号。ATX 标题保留原始 `#` 标记并加粗，嵌套层级也不增大字号；Setext 标题不捏造标记，代码／转义中的 `#` 保字面内容。执行 Agent 回复与文件文档的原有标题／outline 语义保持，原始复制与批注选区不改。

Activity、History 及其他共同阅读入口共用同一正文、Markdown、代码与资源的 tokens、间距和阅读基线；窄窗不裁正文、元信息、动作或焦点。展开、复制与实际质量验证只见[《对话消息的阅读、复制与标注》](../behavior/conversation-mode.md#对话消息的阅读复制与标注)，宿主不维护另一份消息外观。

已记录的问题答复沿原输入正文呈现答案，关联问题与原始记录使用紧凑的按需披露，默认不露协议包装；正常与窄窗、明暗和键盘焦点保持可读，整条复制沿原消息反馈。语义与原文边界唯一见[对话消息的阅读、复制与标注](../behavior/conversation-mode.md#对话消息的阅读复制与标注)。

### 长内容、代码与局部查找

长人类消息的全文入口与折叠状态清楚，原消息尾部与附件操作在展开后完整可达；宽窄保持原正文基线、自然比例和可见焦点，不用遮罩隐藏可聚焦操作。

长代码与宽表格在真实横向溢出时，以轻量边界提示表明尚可阅读的方向，端点撤下；沿原字体、主题与滚动表面，不通过裁字、遮字或大面积渐隐获得提示。键盘焦点清楚，正常不溢出的块保持原静息密度。

普通代码围栏的语言标识与复制动作放在同一条轻量工具栏，正文代码仍是主要阅读面；沿既有 surface、字体、图标和焦点 token，不叠加装饰卡片。长语言标识可视觉省略，复制动作与状态仍清楚可读；窄 Region 中工具栏保持在代码横向滚动之外，不将整个消息撑宽。明暗主题、键盘焦点、复制处理中／成功／失败均可辨；复制内容与迟到回执边界只见交互合同[《对话消息的阅读、复制与标注》](../behavior/conversation-mode.md#对话消息的阅读复制与标注)。

局部查找使用紧凑的输入、命中数量、前后及关闭动作，明确当前已加载范围，命中强调与当前命中可辨；仅用户定位时滚动，新内容保选择与阅读位置。

### 复制、批注与阅读反馈

复制、标注等动作默认安静，hover／focus 时在原消息操作区出现，失败状态仍可达；消息停靠、作者与密度见[《消息布局与身份密度》](#消息布局与身份密度)。

从当前消息继续到新会话的动作及其语义标示沿[续聊入口的呈现](session-recovery.md#从消息继续到新会话)，与原消息操作保持同一轻量层级。

思考／工具展开与真实复制成功可有短而可中断的局部反馈，关闭后不保留重 Markdown 挂载，不用持续光效或全消息入场动画。减少动效时直接呈现最终态，反馈仍依真实操作回执，不能以动画或计时宣称成功。

选区首先显示轻量浮动操作条，以 SVG 和短文字提供「批注／复制」，不弹出大表单。明确批注后才出现细划线和紧凑浮窗；宽窄均在所属阅读面及视口内夹紧，空间不足时翻转／移位，不撑固定空列或在末尾铺表单。引用默认单行摘要，可展开全文；留言沿 Message Tool 输入语言按内容增高。目标选择默认当前 Agent，以头像和名称表达身份，展开后按本项目（含新建）、Mote、其他分组，长名称收敛且完整身份可达。发送是明确主动作，加入当前回复草稿为次动作；关闭、丢弃、复制不混用。克制阴影、轻边界、紧凑字号建立浮起层次，失败和待确认就地清楚，不堆重复元信息或满宽按钮。原 Range、隐藏、只读、焦点和输入所有权唯一见[《对话消息的阅读、复制与标注》](../behavior/conversation-mode.md#对话消息的阅读复制与标注)。

固定协调对象使用 Mote，入口与原对话面唯一见[《Mote 快捷入口与当前协调上下文》](motes-and-coordination.md#mote-快捷入口与当前协调上下文)。名称与职责归[《Space、Folder 与 Topic》](../behavior/spaces-and-layout.md#spacefolder-与-topic)，不在对话正文再列身份标题、角色说明或模式栏。

## 真实对话与行内引用

引用短名在输入正文中原位呈现，下划线提供可操作暗示，类型由字形和名称共同表达；焦点可见，窄窗不横向撑宽。功能与恢复约束见[输入与语义引用](../behavior/conversation-input.md#对话接入新组件与输入引用闭环)。

对话正文中的 Agent applink 呈现为与文字基线协调的紧凑行内名片，复用现有身份图形（普通 Agent 的 Provider 图标与珐琅质感、Mote 的原头像）及真实状态标记，名称仍是主要判别器；轻量材质、边缘与克制动势形成精致感，不为每个引用插入大卡片或撑高整段。hover 与键盘焦点打开同一份有界详情，完整名称、原 SID 与未知说明可读，点击和披露命中清楚且不嵌套交互控件。正常／窄分屏、明暗、长名称和重复引用下不横溢出，减少动态时保静态状态与焦点提示；隐藏面停不必要动画。原引用、当前资料、身份与导航边界只见[对话正文中的 Agent 对象引用](../behavior/conversation-mode.md#对话正文中的-agent-对象引用)。

行内对象引用的补充密度：Region／Tab／Space／Zone 与 Agent 使用同一轻量材质、基线和圆角语言；空间类型用清楚的小 SVG，不伪装 Agent 头像。显式标签优先，未知名称时用原 ID 而非猜名字；过长 ID 只视觉省略，完整原地址可查看和复制。打开与复制为相邻独立命中区，键盘可达，不嵌套按钮、不因 hover 出现操作而挤动正文。交互事实只见[对话正文中的 Agent 对象引用](../behavior/conversation-mode.md#对话正文中的-agent-对象引用)。

## 对话贴图缩略图与灯箱

本地贴图与 Provider 原生记录中已分类的图片资源复用同一缩略图与灯箱语言。缩略图沿正文流排列，保持图片比例与可辨认的内容边界，保留引用复用入口，不把完整路径撑成一行按钮。内联图片编码不铺成正文。加载中或失败时沿原始引用的可读文字呈现，避免空白占位、破图图标与失效灯箱；读取和解码的唯一行为合同见交互文档[《对话里的贴图》](../behavior/conversation-mode.md#对话里的贴图)。缩略图点击后在共享 Overlay 中放大，灯箱不改变消息高度；关闭动作回到原缩略图，键盘 Escape 与遮罩关闭保持同一语义。

图片查看以图像为主体，名称与关闭动作位于紧凑顶部，缩放、适配、前后浏览与当前序号位于不遮挡原图的工具行。控件共用语义图标、主题、焦点和密度 token；窄窗保留可发现且可键盘操作的核心动作，不缩小图像阅读空间来容纳长路径。放大、平移与切图即时反馈，减少动画偏好继续生效；失败说明和重试属于当前准确图片，不能覆盖其他可用图片或伪装读取成功。

图库导航与缩放操作按实际可用宽度成组换行，触屏较大的点击区同样适用；不以裁掉操作或缩小命中区维持单行。原图适配区、标题与关闭动作始终留在灯箱内，换行不改变组内顺序、键盘访问或原资源读取。

## 可复用对话与 Workflow 组件密度

### 过程层级与详情

聊天观察区采用 Workflow 的“时间线 + 分层 surface + 状态轨道”语言，但保留对话正文、权限请求和 Composer 各自的内容密度。

视觉品质来自层次、对比、细微动势和状态反馈，不来自大面积渐变、过重阴影或装饰性卡片堆叠。

过程摘要与 trace-only 保持紧凑，不把每一步套成大气泡、厚 header、重复头像或标题墙；失败、进行中与全部原步骤仍清楚可达。

原工具详情的可读格式／原文选择沿轻工具行语言，不叠卡片，长键值与原文本均可完整阅读。

思考／工具详情的局部复制放在展开载荷的轻量操作行，沿普通代码块复制的图标、状态和焦点语言；原折叠摘要保持主次，不在折叠行常驻额外工具，也不叠装饰卡片。长 Call ID 可完整换行，复制动作不被挤出窄栏；处理、已复制及失败重试清楚可辨，明暗和触屏保持可用。原文和回执边界只见交互合同[《对话消息的阅读、复制与标注》](../behavior/conversation-mode.md#对话消息的阅读复制与标注)。

### Workflow 行、数字与变体

- Workflow 时间线沿用聊天 Activity 的低干扰行语言：普通 tool 行与 Workflow 卡片共用时间线缩进和折叠箭头，不额外套一层装饰性外框；只有输入框上方 dock 作为独立浮层保留 surface、圆角与内部滚动。
- 对话中已接入的记录型过程使用更轻的层次，正文与真实状态先于整圈框线；折叠、展开与焦点仍清楚可辨，不用重边框、卡片套卡片或更小字号建立层次。Streaming／进行中采用精致、克制的 animated SVG 状态图形，线条与既有小图标尺度一致，动作安静且不引起文字或数字位移；减少动态效果时静态仍可辨。状态事实与阅读保持只引用交互合同[《可复用对话与 Workflow 表面组件》](../behavior/conversation-mode.md#可复用对话与-workflow-表面组件)。
- 公开进度说明沿共同正文的轻量紧凑类别，完整文字仍可选、复制和标注，弱化 chrome而不缩小正文字号或截掉内容；正式回答的主阅读层级保持。协作记录的摘要、sender→receiver与最后记录状态先于原载荷详情，无实际阶段／统计不画空字段或 progress rail。阶段、来源、顺序和旧历史行为只引用[《可复用对话与 Workflow 表面组件》](../behavior/conversation-mode.md#可复用对话与-workflow-表面组件)，不在密度合同重复定义。
- 组件密度固定在 `--fs-micro` / `--fs-meta` / `--fs-body` 三档与 2/4/6/8/12/16px 间距刻度内。状态徽标、模型短名、最近工具、耗时、token 和调用次数使用 `tabular-nums`，数字不因状态切换跳位。
- Workflow 头部的 progress rail 是结构性进度，不是选中指示；选中阶段或 Agent 使用整行轻量 surface、`aria-expanded` 和焦点环表达，不使用重复的单边竖条。状态颜色只承担语义，失败/终止/暂停仍需字形或文案。
- Agent 行默认一行：状态字形、label、模型短名、最近工具、耗时、token；打开后才显示阶段、尝试、排队/开始/最近活动、工具调用等新增信息。展开面板用两列 `dl`，不重复标题和状态。
- 超过 8 个 Agent 才进入双列 grid；超过 12 行且尾部连续安静项才显示“还有 n 个”。失败项与当前运行项始终优先可见。≤560px 隐藏模型与最近工具，头部数字换行到第二行；触屏控件最小命中区 44px。
- 同一 Workflow 组件通过 `dock` 变体复用结构，仅收紧模型和行高并限制 `max-height: 220px`；不得为 dock 维护另一套状态投影。旧 daemon 用 flat tool 行样式，无箭头、无空卡片。

### 开发观察与真实消费者

Gallery 是共同组件的集中开发观察表面，可切换 light／dark／system，展示 running／completed／failed／killed／paused、窄屏和旧 daemon。它使用最终生产组件、真实公开 props 与全部关键状态，页面结构与聊天页一一对应；展示数据是静态 fixture，不引入 Runtime 或 Chat Store。生产聊天观察区与 Gallery 共用同一消息组件、Workflow surface、密度和状态表达，不复制另一套视觉实现；聊天页适配层只把真实 Activity／Run／Agent 事实映射到公开 props，缺失或未知事实保持未知，不用示例值补齐。

开发 Gallery 可显式查看原组件轮廓并调整示例容器的可用宽度；控制组紧凑且键盘可达，示例仍用原字号、组件及公开 props，不以整页缩放冒窄宽适配。关闭轮廓回到正常呈现，设置只留本地示例，不污染生产偏好。

## 原生回合摘要

原生回合摘要沿共同 Conversation／History 与 Workflow 的轻量过程语言，使用一行安静的耗时、输出用量和实际过程披露入口，回答保持主要阅读面。复用现有字体、颜色、间距、语义图标与时长格式，不另套头像、大卡片、边框墙或常驻统计栏；数字采用等宽读数，输出 tokens 的含义通过短文字和可访问名称表达，不仅靠向下箭头辨认。输入、合计和计量范围可按需披露，避免三套数字争抢正文。

有可读过程时，整行披露的 hover、键盘焦点、开合与命中清楚；只读摘要不画空箭头。窄 Region 允许辅助读数自然换行，保持原字号、有效命中区和完整内容，不挤窄正文或隐藏失败。状态只表达真实已报告的结束、失败、中断或未知，正常摘要保持中性；数值和经过时间不驱动伪进度、呼吸动画或成功色。原过程开合、复制、Range、滚动与草稿沿共同阅读组件保持，明暗、宽窄和键盘访问须在真实消费者中核对。

回合归属、整轮与响应口径、缺值和有界过程的唯一行为规则见[原生回合摘要与过程披露](../behavior/conversation-mode.md#原生回合摘要与过程披露)。

## 分层人机交互的呈现

交互行为以 [Provider 与人机交互的分层收敛](../behavior/agent-capabilities-and-messaging.md#provider-与人机交互的分层收敛) 为唯一约束来源。输入结果、待答请求、服务窗和注意力摘要复用现有控件语言：紧凑图标、对象、原因和可执行动作；只在有信息时展开详情。持续问题不遮住可用终端或占据重复全局弹窗；提示与原对象可互相定位，并保留键盘操作、IME 和无障碍名称。

回答失败在原卡片内使用低干扰、可换行的原因提示，保留原选项。需要原生确认的未知请求默认收为紧凑、安静的对象摘要与现有“Open terminal”动作；完整问题、工具输入、回执与原因按需展开，不把长原始 JSON、重复状态标题和来源提示堆成常驻大卡片，也不遮住可用终端。确认处理后的当前请求卡片消退，不留已处理占位或继续挂“Needs you”；完成与未知的事实边界只见上述交互合同。全局告示沿用既有服务窗与紧凑定位按钮，显示所属 Session，不增加第二套通知外壳；宽窗和窄分屏中的摘要、终端入口、详情与键盘焦点清楚可达。

对话中的当前 Permission/Question 沿共同聊天的身份与内容层级呈现，问题与选项构成一块紧凑可读内容，显示文字“需要你回答”及克制的等待图标；不能仅以颜色表示交互。真实长选项和说明在窄窗自然换行，键盘焦点和完整命中区可辨。提交中、只读、需要原生处理与失败各有对应文字，失败仍在原请求附近；没有请求不增加常驻卡片、空槽或状态栏。行为与请求/响应事实只见交互 SSOT[《Provider 与人机交互的分层收敛》](../behavior/agent-capabilities-and-messaging.md#provider-与人机交互的分层收敛)；不另定义 Provider 特有气泡或第二套控件。

## Agent 群聊连接入口

Mote 内每个 Agent 的原对象菜单，在 Connector 启用后提供具名的「创建群聊」和「绑定已有群聊」，沿既有菜单的图标、键盘与焦点语言。连接后以群名称和轻量来源提示保持可发现，查看群、暂停、重新连接与投递问题集中在按需详情；正文和 Composer 保留阅读及草稿空间，不新增常驻连接工具栏或顶层聊天导航。

群聊连接面是当前 Agent 的轻量任务面，以 Agent 与目标群的关系为主体，群名称是主要编辑对象；所选应用属于准确可辨的次级来源，配置与技术凭据按需进入，不能用等权字段堆叠代替任务组织。复用 Mote 与 Settings 既有的石墨／Mint 功能材质、表单和动作语言；创建、邀请、共享确认与步骤反馈围绕同一关系就地呈现，已确认步骤、未知和成员访问分别可辨，不因布局整合混成一个成功标记。控件比例、行基线、分组节奏和主次动作在原工作面正常与窄窗中须达到同项目成熟表面的完成度。完整构图由[独立看图](shared-rules.md#agent-主观审美的判断边界)判断，统一控件、深色 Token、文案或折叠本身不代称现代化品质。

创建面以群名称、准确成员／受众和共享范围为主，当前 Agent 与所选应用在同一面可辨。创建中、已创建待绑定、绑定失败和结果未知就地呈现并保留原输入；未知给出检查原操作入口。正常与窄窗保留主动作和完整错误说明，成功标记只对应已经确认的步骤。身份、授权与恢复边界唯一见[共同协议行为合同](../behavior/conversation-mode.md#共同对话协议与外部交流入口)。

创建与绑定已有群保持同样的对象关系和设计品质，绑定面不能退回技术标识与配置字段的堆叠。amux 与群聊可采用适合各端的版式，但同一共享对话的信息和原记录关联完整可达。用户本人发送与系统代发清楚区分：代发卡片以原用户消息为主体，轻量标明真实来源与「通过 amux 发送」，不把机器人头像当作原作者；正文、附件、问题与回答的阅读层次沿共同对话语言，平台限制通过分段或准确资源入口表达，不用省略内容换取整洁。身份与信息对等的唯一合同仍见同主题行为，呈现不猜控制或授权事实。

## 共同工作面的品质与保持

共同呈现须在真实消费者的完整代表图中由独立 Agent 审阅；修正后复拍复验至明确可交付。Gallery、截图采集或 CSS／像素断言不能代替实际工作面的审美与交互结论。正常与窄面、明暗主题、长内容、失败状态、键盘焦点、触屏及减少动态偏好纳入适用场景；原 Range、阅读位置、焦点、IME、草稿、编辑节点与 Terminal 几何的保持仍沿行为 owner，不因视觉收纳新增读取、观察或持久事实。
