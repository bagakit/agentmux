# Capsule 的设置、页面与工具结果呈现

本文定义 AgentMux Capsule 的视觉、密度和交互层次；身份、模式、权限、保存与恢复只见[Capsule PRD](../behavior/local-page-hosting.md)。这是待实现和真实看图验证的设计合同，不代签界面或功能已经交付。

## 设计目标与阅读顺序

Capsule 是可认出、可再次打开的页面成果。界面首先回答“哪一页、现在能做什么、是否需要我回答”，再展开内容路径、服务端点、权限与工具执行证据。设置帮助用户决定后续页面怎样创建，页面本身承担阅读与交互，Toolkit 结果负责把人带到准确成果；三处不重复画页面管理台或另套预览。

本机与远程来源在准确对象附近可辨，内容根明确属于执行 Host；服务停止、运行结果未知、客户端未连接与页面未展示分别表达，不把关闭 App／工具当成停止独立服务，生命周期仅消费 [PRD](../behavior/local-page-hosting.md#生命周期内容与重启恢复) 的原 owner。

沿既有 Graphite／Mint、主题语义角色、字号、间距、图标和控件。整体采用专业工具的紧凑行与稳定对齐，主要内容有充分阅读面积，分组用段距与轻分隔；不以大标题、彩色数字卡、连续圆角面板、重复摘要或装饰阴影代替层级。选中用完整 Surface 与明确非颜色信号，键盘焦点独立可辨，不用单侧细线表达唯一状态。

## Settings 中的 Capsule 模块

Capsule 在既有 Settings 模块目录、搜索与窄窗分类中同层可发现。入口标题为 **Capsule**，固定摘要简述“持久页面、隔离与交互”；摘要不显示从 AppConfig 猜出的动态数量、当前根或服务状态。进入后由 Capsule 领域 owner 提供实际配置，配置读取、编辑草稿与真实页面资源分别表达。

正文按“独立服务 → 新建默认 → 受管位置 → 已有页面”组织为一个连续工作面，保留原设置侧栏和导航，不另造 Capsule 全屏应用壳。服务用紧凑行显示原 Core 的状态、准确身份与明确启停；停止或未知时保留已有页面、配置与编辑草稿，未知命令仅核对原操作，不能因进入 Settings 自动撤销已保存的 stopped 意图。首屏先有当前值和明确用途，说明贴近字段且只出现一次。

| 区域 | 呈现与动作 |
| --- | --- |
| 新建默认 | 紧凑字段行提供内容管理、运行模式及主题跟随；每项当前值直接可读。隔离／注入使用清楚的文字选择，短提示说明能力差别，不画成风险仪表盘 |
| 受管位置 | 显示真实绝对目录及具名选择入口；长路径可换行、选择和复制，次级说明明确“用于新页面，已有页面保留原位置”。未知路径显示未确认，不用示意路径冒充实际值 |
| 领域保存 | 独立保存这一份 Capsule 配置，原位显示未保存、保存中、冲突、失败与待核对；不借 Settings 总保存或整体 Saved 标签代签。保存区不盖住字段或页面列表 |
| 已有页面 | 紧凑列表／表格直接认出名称、当前模式、真实状态、待答事实与主要动作；内容来源作次级文字，完整 ID、绝对资源、服务端点和原操作按需展开 |

默认值区域明确标记只影响新建。主题跟随与 HITL 权限分开表达；隔离页面不会因全局主题选项开启而暗示已注入能力。根目录选择保留字段编辑和原配置范围，不出现“迁移全部页面”的默认动作，也不增加 Capsule 总启用开关。

页面列表每行只突出一个实际主动作：可打开时打开，已有展示可准确定位，失败时给适用于原事实的恢复动作；复制链接和完整详情保持次级。页面状态、模式和待答不是同一维度，不把“Injected”画成运行成功，不把“未展示”画成页面故障。零页面时仅给简短用途与 CLI／skill 发现入口，不铺空卡、假页面或演示计数。

页面级配置在选中准确页面的详情中编辑，名称、原 ID 和作用范围保持可见。页面的实际模式、主题策略与创建时默认来源可辨，不把“来自创建时默认”误称为仍动态继承。更改模式时能力差异与保留的原请求在动作附近可读，普通查看不打开 Browser、重建容器或发送输入；权限及保存事实只消费 PRD 的原 owner。

## Browser 中的页面身份与交互

页面内容占主阅读面。Capsule 身份融入现有 Browser chrome：紧凑图形、页面名称与实际模式足以辨认对象，完整 ID、内容来源、`amux://capsule/<ID>`、真实端点和来源工具在具名详情中可达。地址编辑、复制、More、Close 和原控制权入口继续可用，不叠第二条 Capsule 工具栏或永久运行 banner。

原页面尚未恢复或当前服务失败时，沿现有 Browser 恢复面显示原名称、准确目标、简短状态及原身份恢复动作。旧内容或旧截图只表示历史，不冒称当前可操作；不铺空白、假封面或技术 ID 墙。打开和定位保原 Browser／Region 与人的输入，后台恢复不自动聚焦。

注入模式的主题投影与页面自有内容协调，不能把宿主的整个设置面或通用工具栏复制进页面。授权状态在可信宿主表面可辨；页面自行绘制的 App 风格按钮不能冒充宿主批准入口。宿主确认人工提交的入口显示准确原请求与接收 Agent，页面表单与宿主信任标记各有用途，不以重复发送按钮或两套问题卡让人猜哪一个生效。

## 待答、答案与未知状态

需要人回答时，以原问题和可操作答案为主，准确 Agent 接收者及来源作为紧凑上下文，宿主待答入口就近揭示同一请求。问题在页面中已完整可读时，Browser chrome 仅保可发现的待答标记与定位，不再复制一张同内容卡片；详情和答案编辑不遮原页面主要内容。

| 事实 | 表达重点 |
| --- | --- |
| 等待回答 | 显示“需要你回答”与实际问题，原选项或输入清楚可用；不以服务 busy 暗示 Agent 故障 |
| 编辑、已保存草稿 | 原答案和保存状态就地可见，选择与保存不显示为已发送 |
| 提交中 | 同一原答复的真实阶段，避免重复投递；其他页面阅读和正常输入仍可用 |
| 已确认投递 | 明确表示送到原准确 Agent；只有更后的原协议事实存在时，才显示已采用或已处理 |
| 结果未知 | 简短“结果待核对”与原操作查询动作，保原问题和答案；不换成“重发”或清空输入 |
| 已确认完成、失效或切模式 | 分别说明实际结局和仍可做的动作；旧答复保原记录，不把另一新请求当作原请求继续 |

等待、未知和失败只在准确页面和请求附近表达一次；不用全页遮罩、成排状态标签或循环动画放大局部问题。主题、服务和投递分别失败时按相关事实提供可展开说明，主内容与可用动作保持；颜色配文字／图形，完成态安静，历史不冒正在执行。

## 对话卡中的有界页面

明确内嵌在原正文位置呈现紧凑成果面。页面身份用一层清楚的标题行组织，实际模式是与标题分开的安静元信息；长标题与模式、动作之间保留稳定间距和对齐，不贴连成一串正文。Hide／Show、Expand／Compact 和 Open in Browser 形成次级阅读工具区，就近可达。原引用及准确 Browser 身份在具名详情中可选择、复制。默认页面区约 300 CSS px，随视口收缩，展开可使用较大正文区域；页面在独立原生容器阅读，不把卡片拖成无限长正文。

可见时直接回接既有原生页面；首次创建需要原服务可用，不叠第二次“加载页面”确认。离开阅读窗口暂停昂贵呈现，回到原位置恢复准确消费者；展开增大卡片阅读区，完整打开沿原 Browser 工作面，两种动作分别可辨。页面信息刷新失败、服务停止与未知在原卡片提供简短准确状态、Retry original page 与完整打开，不把仍可用的原页说成故障，原消息继续可读。

注入模式的待答入口沿原可信宿主控件，与页面自身按钮可辨。入口紧凑揭示待答事实，不与卡片标题、展开标题重复整套页面名称和模式。用户展开待答后，问题与答案是主阅读内容，接收 Agent 是就近可核对的上下文；完整 Host／Session 标识、页面来源与原操作采用次级层级，始终清楚可达。确认当前答案是待答区的主动作，保存草稿、刷新与读取状态作为次级控件和反馈；不把所有工具画成等权大按钮。精致感来自一致的字阶、段距、边界与对齐，沿 App 共享 token。答案与未知仍沿[待答呈现](#待答答案与未知状态)，呈现收敛不改变原开合、草稿保全、接收目标或人工确认资格。

暗／亮主题、窄窗、键盘动作与长标题使用同一呈现语言，完整页面内容和待答区各有清楚边界。Toolkit 轻量成果行保持下节范围，不因对话支持内嵌而自动加载页面。

## Toolkit Library 的成果入口

沿现有 **Toolkit Library** 和工具结果浮窗语言，在原结果内用一个轻量成果行呈现 Capsule：页面名称为主、实际状态与必要来源为次、打开／定位为明确动作，复制 Capsule 对象链接为次级动作。真实 `toolId`、`executionId`、结果时刻和 Capsule ID 收在执行／来源详情中；不要求用户阅读 UUID、JSON 或端口才理解成果。

成果行与普通外部链接可辨，但不以大卡片、iframe、网页缩略预览或第二个服务重复展示页面。工具执行状态、页面发布状态和实际 Browser 展示保持各自含义；失败和未确认在原动作附近可读，不把工具 succeeded 的绿色延伸为页面已可用。新执行结果到来不改变正在编辑或阅读的原页面，不抢选择或焦点。

TUI custom kit 薄封装同一管理 CLI，保留原工具终端和执行身份，服务 Run 与工具 Run 在详情中各归其原对象，不另造 Capsule 终端或保活控制台。

hover 只阅读已确认结果；点击或键盘触发准确打开、定位或复制，沿原非模态工具浮窗保持焦点返回和 Escape 语义。来源缺失、旧执行或引用不可读时保可读原结果和准确诊断，不猜当前工具、扫描终端文本或把普通 URL 升格为 Capsule；完整来源与动作资格只见[联动行为合同](../behavior/local-page-hosting.md#browser-与-toolkit-library-联动)。

## 自适应、可访问性与验收

正常、窄分屏、短窗口与缩放后都能读到当前对象、实际模式、主要动作、待答与未知。字段窄时按原阅读顺序纵排，名称／路径换行不挤掉动作；长结果在自己的有界区域阅读，不让外层层层滚动或固定栏遮住底部。深浅主题沿原语义 token，不缩字或缩命中区换密度；原生键盘选择、可见焦点、IME、可访问名称与减少动态效果完整保持。

验收以实际 Settings Capsule 模块、真实 Toolkit 结果入口和同一 Browser 中的真实页面闭环采图，包含空／非空列表、长路径、页级覆盖、模式切换、待答、保存冲突／未知与恢复。对话卡从正式 Desktop 样式入口消费原 owning 样式，验收入口不能额外补齐正式消费者缺失的规则来代签产品呈现。按[独立看图规则](../../guides/agent-visual-e2e-review.md)评审正常和窄窗、深浅主题与真实原生页面层级，修正后复采；静态原型、gallery、链接存在或一次截图成功不能代签设计质量。
