## 动手前先读

改手机界面前先回答四个问题，答不上来就读对应链接：

| 问题 | 去哪里找 |
| --- | --- |
| 这个界面在手机上应该怎样呈现 | 本页对应章节 |
| 它的行为、权限、连接或恢复边界 | [手机版 Relay 连接](../behavior/public-control.md#手机版-relay-连接)、[手机对象身份与工作面](../behavior/public-control.md#手机对象身份与工作面)、[手机网页诊断与更新](../behavior/public-control.md#手机网页诊断与更新) |
| 它是否消费共享组件（`packages/client-ui`） | [共同视觉与样式](shared-rules.md)；对话、输入、终端分别见[共同阅读密度](conversation-mode.md#共同阅读密度)、[Composer 密度](conversation-input.md#composer-状态与队列密度)、[终端阅读](terminal-reading.md) |
| 改完怎样证明好看且可用 | 本页[验收](#验收采图与看图) |

手机样式写在 `apps/mobile/src` 的手机 CSS 与组件里。修改 `packages/client-ui` 的共享组件或样式会同时改变 Desktop，必须在同一改动中核对 Desktop 消费者；只为手机调整时，用 `.mobile-app` 作用域的选择器或组件的呈现参数，不改共享默认。被延迟加载的工作面（目录、Topics、Goals 等）自带样式表时，首屏组件（应用外壳、连接页、底部面板、新建 Agent）使用的规则不能只放在延迟加载的样式表里，否则这些规则在延迟模块到达前不存在。

## 产品标准

手机是 AgentMux 的第一方 client。目标是达到成熟手机应用（系统消息、主流 AI 对话与协作工具的手机版）的完成度：安静、紧凑、即时响应、一眼看懂。工具属性不是粗糙的理由。

判断一个画面是否达标，依次问：

1. **主次一眼可辨。** 正文、当前对象和主动作先被看到；元信息、技术身份和诊断退到次级或按需展开。
2. **没有无信息的元素。** 已确认的正常状态不写成文字；没有数据时不铺空表；同一事实在同一屏只出现一处。
3. **几何干净。** 对齐、留白和字号来自同一套刻度；层级靠填充、明度和字重，不靠描边和卡片套卡片。
4. **触屏可用。** 每个动作的命中范围至少 44px，按下即时反馈，不被软键盘、安全区或其他浮层遮挡。
5. **真实状态诚实。** 故障与未知持续可发现、可展开、可恢复，只是默认收成一行；从不把未知画成成功。

“同一屏”指同一时刻可见的画面：底部面板或侧边菜单打开时，面板与其下方可见的工作面各算一屏；不同面板之间可以各自呈现同一事实的入口，但每一屏只有一处主要说明，其余只放跳转入口。

## 尺度与 token

手机的尺度变量在 `apps/mobile/src/mobile.css` 的 `:root` 重新定义，**有意**与 Desktop 的[字号阶梯](shared-rules.md#字号阶梯)不同：触屏阅读距离更远，正文和标题比 Desktop 大一档。颜色、表面、高光、阴影与动效曲线来自共享 [palette 与样式 SSOT](shared-rules.md#主题与样式-ssot-规范)。新样式写变量，不写字面像素或毫秒；只有几何专用值（安全区、44px 命中、绘制面）可以写字面值。

| 用途 | 手机值 | 变量 |
| --- | --- | --- |
| 页面标题、对话顶栏名称 | 17px，字重 600 | `--fs-title` |
| 正文、列表名称、按钮 | 13px | `--fs-body` |
| 元信息、次级说明、分组标题 | 11px | `--fs-meta` |
| 最小字号（底栏标签、角标、计数） | 10px | `--fs-micro` |
| 可编辑字段 | 16px，防止 iOS 聚焦缩放 | 不缩小 |
| 等宽长值（ID、路径） | 跟随所在位置的档位，配 `--font-mono` | 不另设档 |
| 内容左右留白 | 12px | `--sp-5` |
| 间距 | 2 / 4 / 6 / 8 / 12 / 16 / 24px | `--sp-1` … `--sp-7` |
| 控件绘制面 | 32px（命中范围另算 44px） | `--mobile-control-surface` |
| 圆角 | 6 / 9 / 12px | `--radius-sm` / `--radius` / `--radius-lg` |
| 按压、着色 | 120ms | `--dur-fast` |
| 面板、菜单入场 | 手机自定义的入场时长与曲线 | `--dur-enter` / `--ease-enter` |

紧凑感来自一致比例、清楚对齐和克制表面，不来自整体缩放、缩小编辑字号或删掉动作。视觉尺寸与命中范围分开：图标只画 16–18px，但所在按钮的命中范围仍是 44px；命中范围不当作视觉留白，也不放大头像或图标。

此前已确认的本表面细则继续有效：

目录、对话、资料与结果的卡片、底部面板及服务说明共享[原主题与语义 token](shared-rules.md#主题与样式-ssot-规范)，保留 Amux 原可配置的字体、圆角、层次阴影与语义图标表现；触屏几何沿本页适配，不用手机固定绘制值盖过原样式选择，也不为这些表面另造偏色材质。状态色与主动作只表达各自语义。资料标签与恢复动作使用普通工作用语，原始配置名、技术身份及诊断全文按需可读。

比原手机外壳缩小标题、正文、元信息与段落留白：标题约17px、正文13px、元信息11px，内容横向留白12px，行和章节优先用轻分隔表达结构，避免每段都套卡片。标题、身份槽和底栏不靠大面积空白表达重要性；搜索、筛选与新建沿紧凑工具布局，Goals 刷新使用有准确可访问名的轻图标动作，主次清楚。搜索、筛选、服务摘要和目录行的绘制面应轻薄，避免把完整触摸范围都铺成连续的大块实心圆角底板；压缩重复的品牌／页面标题层次和容器内留白，让名称与内容先于外框。目录与正文不以逐项描边、层层线框或装饰阴影组织内容；优先用对齐、字重、段距和必要表面层次表达关系，输入边界、当前选择、键盘焦点及服务未知仍清晰。现代紧凑感由一致比例、清楚对齐和克制表面形成，不以整体缩放取得，也不以竞品材质或布局取代自身主题。视觉尺寸与点击范围分开，主要触摸目标至少44px；编辑字段保持16px以避免iOS聚焦自动缩放。五入口在320px宽度仍完整可读，菜单、长名称、未知回执和软键盘不挤掉编辑器或关键操作；减少重复身份标题和终端切换按钮。安全区、键盘收起底栏与矮视口滚动沿原viewport owner。

## 控件语言

手机沿[共同控件语言](shared-rules.md#控件语言)的档位，复用共享原生按钮组件 `Button`、`IconButton` 的具名、焦点、按压与禁用语义，只调触屏几何。

| 档位 | 手机上的样子 | 手机落地类 | 用在哪里 |
| --- | --- | --- | --- |
| Primary | 实心品牌绿、深色文字、顶部高光 | `.mobile-primary`，或共享 `Button variant="primary"` | 一屏最多一个主动作，如“创建 Agent”“接受并结束目标” |
| Secondary | 干净 Surface 填充、软高光，**无描边** | `.mobile-secondary` | 次级确认、行内动作 |
| Ghost / Icon | 透明底，按下时出现 Surface | `IconButton` + `.mobile-icon-button` | 页头、工具栏、行尾图标动作 |
| 文字动作 | 品牌绿文字，无底无框 | `.mobile-text-button` | 提醒里的“重试”“详情”等短动作 |
| Danger | 实心红色变体 | 共享 `Button variant="danger"` | 删除、撤销等破坏性主操作 |

规则：

- **描边不是控件的主要视觉手段。** 按钮、行、卡片、表单字段都不用常驻描边区分层级；描边只留给输入框聚焦、键盘焦点和需要强调的危险或未知状态。不要在某个工作面用通配选择器给所有 `button` 加边框。
- **选中只用一个信号。** 当前项用 Surface 填充加字重或图标强调；不叠描边、左侧竖条或多重底色，也不用品牌绿文字表示“已展开”。
- 一组里的同类动作使用同一档位；不在同一组混用描边按钮和图标按钮。
- 页头与工具栏动作优先用语义图标并保留可访问名称；只有图标说不清时才用短文字。
- 键盘焦点统一使用 `--focus-line` 的 2px 外框；只有绘制面小于命中范围的控件（图标按钮、搜索框）用内缩偏移，使焦点框贴着可见面。
- 分组列表或表单用一块 `--surface-2`（或 `--surface-1`）填充面、`--radius-lg` 圆角和 `--hl` 高光承载，组内行之间用细分隔，组外不加描边。可导航的行在尾部放 `navigation.submenu` 图标。

此前已确认的本表面细则继续有效：

手机图标动作复用共同原生按钮组件及其具名、焦点、按压和禁用语义，只在手机呈现边界适配触摸几何；不另造同义按钮状态或借装饰组件重写操作资格。完整点击范围与可见绘制面分开，静止时保持轻量，按压即时反馈，键盘焦点始终可辨。底栏当前入口以轻量完整表面和字重共同表达，不能只在小图标上加底色；短动效仅说明状态变化，沿原主题时长并尊重减弱动态偏好，不延后动作或用动画冒充加载完成。

## 文案

默认视图使用普通工作用语，写给正在用手机的人，不写给调试代码的人。

| 默认视图里不出现 | 换成 |
| --- | --- |
| 作为前缀泛用的“原”（原资料、原 Agent、刷新原研究） | 画面里只有一个这类对象时直接省略：资料、这个 Agent、刷新 |
| Host、Session、Run、PTY、operation、回执、unknown、观测、样本等实现词 | Mac、对话、终端、操作、确认、未确认、数据 |
| 原始英文异常、错误码、`undefined`、CLI 命令 | 一句中文说明发生了什么、还能做什么；原文进“技术信息” |
| UUID、hostId、executorId、绝对路径、内部枚举值 | 产品名称（如 Codex）；准确身份进详情，可复制 |
| 对已确认正常状态的说明（“原展示位置已确认”） | 不写 |

规则：

- 同一台电脑统一叫 **Mac**。同一动作在全应用只用一个说法：返回、重试、刷新、收起、完成、取消。返回写出目的地，例如“‹ 目标”；退出编辑器用“完成”或“取消”。
- 需要区分两个版本时，用具体对比词：“这台手机上的草稿 / Mac 上的版本”“之前未送出的消息”，不用“原”。
- 同一组状态在所有页面使用同一份词表，例如 Goal 状态、检查结果在 Goals 页和对话目标页一致；Agent 自己的报告写“Agent 报告已达成”，只有人接受后才写“已验收”。
- 共享组件里的英文默认文案（如 “You”“Needs your answer”“Cancel”）在手机上显示中文。
- 中文与英文、数字之间加一个空格；中文句内不用半角空格；完整句子在一处生成，不用字符串拼接拼出半句。
- 时间按距离显示：今天写时分，今年写月日与时分，更早带年份，都不带秒；缺失、非正数或 Date 无法表示的时间不显示具体值。
- 技术身份与诊断不删除：放在同一提醒或详情的“技术信息”折叠里，完整可读、可复制。缺失的字段写“未记录”，不显示 `undefined`。

## 状态、提醒与未知

状态呈现分三层，越靠后越安静：

| 事实 | 默认呈现 |
| --- | --- |
| 已确认正常 | 不显示说明；必要时只用状态图形 |
| 在途、等待 | 就地一行短说明或行内忙碌图标，不占整块区域 |
| 故障、未知 | 一行摘要 + 展开入口 + 收起按钮；展开后依次是说明、恢复动作、技术信息 |

规则：

- **摘要先说结论和还能做什么**，例如“自动任务未确认暂停 · 你可以继续输入”。原始错误、操作 ID、CLI 命令不进摘要。摘要用状态色图标加 11–13px 次级文字，不用整段正文色段落。
- **展开后的固定顺序**：一句人话解释 → 恢复动作 → “技术信息”折叠（操作 ID、Mac 实例、原始错误、日志状态）。矮屏上解释和动作先出现，不在详情里重复印出输入框里已有的草稿。
- 每个提醒都可收起，收起后从菜单固定的“提醒与诊断”恢复；收起只改变本设备呈现，不确认结果、不删除原意图或草稿。行为边界见[手机对象身份与工作面](../behavior/public-control.md#手机对象身份与工作面)。
- 同一事实在同一屏只有一处主要说明，贴近受影响的对象。连接中断与消息未确认送达是两件事，分别说明；离线时依赖连接的提醒归到同一条连接状态下。
- 输入框下方的提醒合计不能挤掉阅读区：多条同时存在时只显示最重要的一条加“还有 N 项”，其余在面板中查看。
- 没有数据的读数折成一行（如“用量 · 暂无数据”），有数据才展开成表；未知读数仍可辨，不补零、不推算。
- 头像或项目图标读取失败时，用该对象的默认身份图形（语义图标或首字母）加一个可点的小标记，不显示空白方块；多个对象的同类失败合成一条摘要，不在页面底部为每个对象常驻一条横幅。点小标记或摘要能读到原因并重试。
- 加载占位按将要出现的内容画出骨架（标题行、几行列表），文字状态作为 `role="status"` 保留；不只显示一行“正在加载…”。底部面板里的加载状态不再放第二个“返回”，面板自带关闭。
- 空状态用一个语义图标、一行 13px 说明和至多一个次级动作，不用裸句子。

此前已确认的本表面细则继续有效：

Commands 在手机消息窗的默认紧凑工具栏就近可达，搜索与原命令选择沿同一输入控件语言；不要求先发现工具条展开开关。所有 warning 提醒都有明确的收起／关闭入口，完整触摸范围至少 44px；菜单中「提醒与诊断」位置固定，收起后仍能发现存在的提醒并恢复原显示及恢复动作。默认呈现可收敛，原因和原恢复路径不丢失；头像与项目图标旁的小状态标记不能是触屏上读取原异常的唯一入口，应以完整触控目标发现原原因及恢复动作。成功反馈与工作状态不冒充故障提醒。

同一连接或目录观察事实在当前画面只保留一处主要说明，相关能力与恢复动作贴近受影响对象，不在标题、正文和输入区重复铺告示。目录发现未确认等服务说明默认收成一句可理解的摘要和就地展开入口，先说明哪里未确认以及仍可用的原能力；展开后完整失败步骤、观察范围、原诊断与准确恢复动作可读，不让全页长诊断抢占目录首屏。连接中断与消息投递未知是不同事实，仍分别说明准确状态、原请求和恢复入口；短屏也保留草稿、编辑区与关键操作。输入区下方的投递与操作说明只在等待、停止、未接纳、未知或失败时显示紧凑单行摘要，提供 44px 触控可达的收起／关闭与重看入口，并在收起后保留紧凑状态提示及通信记录入口；不把已确认输入常驻渲染为故障卡，不在共享 `MessageDeliveryFailure` 外再堆叠第二份原消息详情折叠块，也不以父级通配按钮样式破坏其紧凑排版。默认紧凑工具栏下附件／图片上传按钮与展开工具开关同排可达，不因工具条收起而隐藏附件入口。

## 动效与按压反馈

动效只说明状态变化：出现、消失、展开、切换、跟随手指。节奏用 token，并在 `prefers-reduced-motion: reduce` 下去掉位移，只保留淡入淡出或直接切换。动效不延后动作、不冒充加载完成，也不是状态的唯一载体。

- **底部面板**：打开时从底部上移并淡入，背景同步淡入；关闭时反向退出。位移用独立的 `translate` 属性，不覆盖定位用的 `transform` 和 `bottom`。Radix 受管节点的入场动画限定在 `[data-state='open']`，退出用不同的动画名与有限时长，见[共同验收](shared-rules.md#验收)。
- **侧边菜单**：作为覆盖层从左侧滑入，背景淡入；不整体平移或缩放应用外壳。
- **按压**：行、图标按钮、底栏入口与 Mote 切换在手指按下时立即出现 Surface 底色，抬起后在 `--dur-fast` 内淡出；hover 规则不能是触屏上唯一的反馈。
- **折叠**：箭头旋转与内容出现同步；不对大块内容做高度动画。
- **刷新图标**只在用户主动刷新或首次读取时旋转，后台定时读取不让图标自己转。

## 页头、返回与底栏

- 每个工作面只有一层约 44px 的页头：左侧是返回（图标加目的地名，窄屏可只留图标）或页面标题，中间是当前对象名称，右侧是图标动作组并贴齐内容右缘。下钻页面的标题是当前对象（目标名、Topic 名、研究名），不继续显示所在目录名。
- 正文里不再放第二个返回按钮；Topics 分类在当前树里展开或收起，只用箭头表示，不切换成带返回的页头。
- 底栏五个主入口等宽，Mote 居中作为身份锚点，不做浮起的创建按钮；当前入口用 Surface 填充加字重共同表达。所有入口图标占同样高度的槽位，标签共享基线；菜单按钮与入口分开。五个入口在 320px 宽仍完整可读。

此前已确认的本表面细则继续有效：

手机整体沿 AgentMux 的安静、紧凑工具语言。底栏五个主入口等宽，Mote 正中作为身份锚点，不做浮起的创建按钮；选中态同时用表面填色、图标或文字强调以及可访问的当前页面事实。辅助菜单与返回动作分开、就近可达，五主入口组完整保留；辅助能力沿原菜单揭示，原工作面保持挂载。

非顶层工作面的返回入口直接出现在当前上下文，名称或来源提示说明返回哪里，与菜单动作清楚区分。终端以原内容为阅读主面，本地缩放与触摸滚动可发现且不中断历史；本地阅读比例与会改变原 Run 网格的 PTY 尺寸控制明确分开，完整当前值、焦点与 unknown 恢复保持可达。

## 对话

对话以正文和输入为主：

- 顶栏一层：返回、当前对象（Mote 显示头像与名称）、Goal / 历史 / 终端切换与“更多”。名称用 `--fs-title`，单行省略，极窄时最多两行。相邻图标必须能区分（历史用 `object.history`），状态小点只在需要关注时出现。
- 内容不足一屏时消息贴近输入框，不在中间留大片空白；内容超过一屏后行为不变。
- 消息身份、时间、复制与详情的密度沿[共同阅读密度](conversation-mode.md#共同阅读密度)。
- 阅读范围只在真实缺口或未知时显示一行工作用语；仅仅“没有从开头读起”时并入“更早消息”。
- 输入框与工具栏沿 [Composer 密度](conversation-input.md#composer-状态与队列密度)。有内容可发送时发送键是实心品牌绿的圆形（绘制 32px、命中 44px），空草稿时退为低对比填充。附件与工具开关同排可达。
- 输入框下方只在等待、停止、未接纳、未确认或失败时显示一行摘要，按[状态与提醒](#状态提醒与未知)分层；已确认的发送不常驻说明。

此前已确认的本表面细则继续有效：

对话以正文和输入为主，当前对象与返回只占一层紧凑顶栏，常用工具就近，更多动作按需揭示；消除重复品牌/标题/身份、无信息常驻诊断和无意义容器间距。正常已确认状态安静收敛，真实故障/unknown 仍能持续发现和展开完整原因；压缩视觉体积不以缩小编辑字体、遮挡正文、折断工具或移除恢复动作实现。普通记录来源徽标可收进原消息详情；作者身份、投递与操作控件、关联来源未读提示仍在原上下文可见，收起不改变消息关系、投递资格或读取事实。

手机对话顶栏常驻紧凑命令行切换图标，清楚标明返回对话或查看终端。Goal 与 History 作为当前对话顶栏的轻量语义图标靠近终端与更多动作，默认不加底板、边框或阴影，视觉小而各自保留完整触控范围；不增加工具行，正文和输入保持完整宽度。窄屏可收起返回文字，但普通对话的当前会话名称仍在顶栏可辨；极窄或原生头部可在既有顶栏高度内使用最多两行名称以保留更多有效字符，过长时可收敛，原完整名称和项目仍能按需读取；图标避开安全区、软键盘和其他操作，焦点与按压状态清楚可辨。原生包装的撰写消息沿当前对话动作面板就近可达，不另占常驻顶栏按钮。打开后原面板有明确关闭，焦点可回到原图标；收起不增加读页、重复订阅或复制历史实例。

同一原答复的状态与查询只保留一处：问题卡仍在时就在卡内呈现，卡片退出后保留原操作的查询入口。重挂与状态更新不另建答复，也不覆盖当前草稿；主说明使用工作用语，技术诊断按需展开。

## 目录：Focus、Space、Topics、Survey

- 列表行左对齐：身份图形、名称（13px）、一行次级信息（11px）、尾部状态或动作靠右。命中至少 44px，不逐项套卡片或描边。Survey、Goal 关联会话里的 Agent 行与 Focus 行同一结构。
- 尾部状态只显示状态图形与状态词；Provider 名称、多处位置等次要信息进行尾“更多”菜单或次级行，用产品名称（Codex）而不是小写 id。
- 分组标题 11px 次级色，带计数；层级用缩进和 disclosure 表达，折叠控件保留可访问名与 `aria-expanded`，无子项的行不留空箭头槽。
- 不用 hostId、绝对路径或 UUID 作为行或分组标题。只有一台 Mac 时不显示主机分组；本机文件夹分组写“文件夹”；路径只在同名分组需要区分时作为一行 11px 中间省略的次级信息。
- 搜索框统一为前置放大镜图标的轻填充字段（绘制 32px、命中 44px），回车即搜索，不另配“搜索”按钮；刷新、新建放在页头图标动作组。
- 状态图标与文字按紧凑列表比例协调，已完成有清楚图标及文字；长状态不挤掉名称。
- Focus 按原项目分组，组内按待回应、执行、结果组织；Space 的单 Region Tab 直接以内容名称呈现，Launcher 用同行的“创建 Agent”动作；Topics 的分类与 Topic、Space 的项目与后代共用紧凑树行。层级与行为见[手机对象身份与工作面](../behavior/public-control.md#手机对象身份与工作面)，对象树语言见[对象树与知识层级](spaces-and-layout.md#对象树与知识层级)。
- 没有已确认的关联内容时，不为空集合单独起一个带标题的区块。

此前已确认的本表面细则继续有效：

手机以 App 已有成熟设计为基准：Focus 项目分组、项目与对象外观、Agent 状态形状保持同源，已完成状态有清楚图标及文字，不能仅用微弱颜色或小字区分。状态图标以紧凑列表中的文字和身份图为比例基准，长状态保留可辨与完整读取入口，同时给名称与摘要合理阅读空间；不同状态不能因图标或文字撑大行高。界面按触屏和窄屏重排，保留主题配置及完整触控目标，不重复设计同义图标、首字母替身或状态词表。

Topics 的 Category 与 Topic 子项、Space 的原项目分组及目录后代共用紧凑连续树行；名称为主扫描轨道，原 recap 为次，层级用缩进和明确 disclosure 表达，不逐项套大卡片或放大头像。当前行、hover、展开与键盘焦点分别可辨，折叠控制保完整可访问名与 `aria-expanded`；无子项的行不留空箭头槽。手机层级沿[同主题行为](../behavior/public-control.md#手机对象身份与工作面)，对象与分组语言引用[《对象树与知识层级》](spaces-and-layout.md#对象树与知识层级)，不照搬 Desktop 三栏宽度。目录标题、搜索与尾部操作对齐，“更多”不拆成单字换行；原完整名称和详情按需可读。

Space 等完整工作面展开后的 Agent、文件、Browser 与 Launcher 资源行统一左对齐，图标、名称和次级信息沿各自层级的固定左缘连续排列，尾部动作靠右；不居中资源正文或用大片左空白分配行宽。单 Region Tab 直接以原内容名称与动作呈现，不为每项再占一行重复“未命名 Tab”等技术占位标题；多个 Region 的 Tab 仍保留可辨分组，已有有效 Tab 名称与内容不同时按需保留。省略标题只收敛呈现，原 Tab／Region tuple、来源、导航与创建目标仍完整保留。Launcher 用与其他资源同行的具名“创建 Agent”动作表达可执行工作起点，不以仅含 Mac 不可用说明的静态行代替；行为与授权沿[手机对象身份与工作面](../behavior/public-control.md#手机对象身份与工作面)。

## Mote、Profile 与 Goals

- Mote 用可横向滚动的头像与名称条切换，当前项用 Surface 填充表达选中；Profile 是当前 Mote 的直接入口，不嵌进目录子行。
- Profile 分“当前工作”与“资料”两组，每组一块填充面；资料行以可读标签为主（合作方式、自我设定），文件路径作为次级信息，可导航的行带尾部箭头。执行器显示产品名称；刷新是图标按钮；不常驻“资料来自已保存文件”之类说明。阅读资料原文时，返回、标题、刷新、编辑合成一行页头。
- Goals 详情是一个详情页，不是文档转储：页头标题是目标名；下方一行元信息（状态、项目、更新时间）；然后是目标正文、成功标准清单（每条一个状态图标、标准文字、检查说明与证据行）、结果与验收。工作状态与属性、活动与决策、协作与高级动作收进折叠。
- 一屏只有一个 Primary：未确认时是“确认目标”，有当前结果时是“接受并结束目标”；其余动作用 Secondary 或文字动作。
- 对话里的目标结果页，已有结果时“成果与验收”排在“持续推进”之前；持续推进未开始时收成一行，展开后再填写间隔。
- 证据显示为文件行（文件图标、名称、来源说明、尾部复制），不使用默认圆点列表，说明与按钮分行。

此前已确认的本表面细则继续有效：

Mote 对话是日常工作中心；顶部原头像揭示 Profile，并直接显示当前 Mote 名称，让用户无需凭图标猜测对话对象；窄屏保留可辨名称和完整名称读取入口。结果、终端及其他当前对话动作在同一上下文中就近可达。Profile 用原资料、当前工作和相关对象分层，身份与进展不重复堆进标题栏。Focus 按原项目分组，在组内用待回应、执行和结果的原状态组织可扫读行；页面标题靠左、新建与刷新动作组靠右对齐内容边缘，保留完整触控范围；进入后当前对象及返回来源清楚。对话正文、交互请求、投递反馈和输入区形成连续信息流，长诊断完整可读且不挤掉编辑器。目录、对话、资料和结果共用导航、字号、间距与控件语言；以完整实际画面和操作序列评审。

Mote 以可横向滚动的紧凑头像与名称条切换，当前对象清楚选中；Profile 就近作为当前 Mote 的直接图标／具名入口，不嵌进目录子行。主对话入口与 Agents 列表位于当前对象下，未启动或未配置时仍可发现；窄屏长名称可完整披露，头像不撑高整页。聊天首屏和 Mote 切换共用原身份、主题及至少 44px 触控范围，横排不伪装为新的空间层级。主 Agent 的真实状态、打开／设置和未知来源按行为合同表达，资料里的文件与技术身份按需展开。

## 底部面板、菜单与表单

- 面板顶部是拖动条、标题（15–17px）与关闭；标题与关闭吸顶，内容在一个有界区域内滚动。面板用填充与阴影、顶部高光区分层次，不画外圈描边。
- 面板首屏放最常用的信息与动作，不放空表或长说明；次要信息按需展开。
- 动作列表用分组填充面中的 44px 行（图标、名称、可选尾部信息）；相同图标不表示不同动作，例如“恢复这个 Agent”与“刷新用量”用不同图标。
- 表单字段作为分组填充面中的行：左侧 13px 标签，右侧当前值与展开图标，整行是原生选择的命中区；文本输入保持 16px。不给每个字段同时画填充和描边。主提交按钮是 Primary，贴近表单末尾。
- 关闭后焦点回到触发的控件；打开不重排或重读无关目录。

此前已确认的本表面细则继续有效：

Agent 行的更多动作用轻量语义图标就近揭示，与长按打开同一底部菜单；保留完整触摸目标及明确的关闭路径，不挤断名称或把整行变成操作栏。消耗按原生 Session、最近回复、上下文分清层级，未知与数值可辨。一级面板以紧凑的身份行、可直接扫读的消耗摘要和短操作组组织，不要求先展开二级才能看到常用读数，不逐项重复说明或用整行大卡分隔。先呈现本地已有内容与明确读取状态；远端回执只更新对应读数，不推迟整个面板显露，也不使操作位置反复跳动。Mote 自定义头像的所有绘制与动画图层随原槽位等比缩放，在 iPhone Safari 及其他支持的浏览器不溢出遮住邻行；保持原配色、部件、表情、动态与减弱动态偏好，不以裁切或替换掩盖缩放问题。

## 终端

手机终端把主要空间留给输出：观看与控制方式可辨，模式说明和长说明归信息入口；阅读比例、复制、刷新等次要动作共享一个紧凑操作组。默认视图用“只读查看 · 终端大小跟随 Mac”这类工作用语，不写 PTY、Run。完整规则见[终端阅读的呈现](terminal-reading.md#terminal-信息与恢复画面的视觉品质)。

## 连接、设备与网页更新

- 未连接且没有保留工作面时显示接入页：龙品牌图、一句操作说明与连接详情；连通后工作面不常驻品牌或连接教程，连接与默认主页配置归菜单。
- 确认有新版本时给出轻量、可关闭的一行提示，不遮住对话与输入；菜单固定的“提醒与诊断”提供网页版本与诊断，默认紧凑，设备、页面、构建与原操作按需展开。更新受内容保全约束时就地说明并保留继续使用。行为见[手机网页诊断与更新](../behavior/public-control.md#手机网页诊断与更新)。
- Mac 端的设备设置与手机连接 Toolkit 的呈现见[手机连接与设备活动](settings-and-observation.md#手机连接与设备活动)。

此前已确认的本表面细则继续有效：

确认新版本时，在手机当前工作面主动给出轻量、可关闭的提示，提供进入更新的明确动作；不遮住对话、输入与必要操作。菜单固定的「提醒与诊断」入口提供网页版本，紧凑呈现当前页面、Host 提供和待载入状态，并可明确选择载入；详细设备、页面、来源、构建与原操作按需展开，不把版本差异常驻成巨大故障面板。诊断不可达、未上报和旧观察明确可辨，原因及原查询路径仍可到达。应用更新受原内容保全约束时，在原位置说明待载入并保留返回、收起与继续使用；不强制清空编辑器、附件或未知请求。行为与权限唯一见[手机网页诊断与更新](../behavior/public-control.md#手机网页诊断与更新)。

手机有限 Goal 操作的在途和未知原请求可从菜单固定的「提醒与诊断」进入；默认紧凑显示准确 Goal、动作和未确认状态，完整原 Host、操作及请求按需展开并可复制。原 Goal 已删除或暂不可读时，原记录仍在该入口；关闭或收起不移除记录、不冒充原回执，也不妨碍其他健康操作。身份与保全沿[手机版 Relay 连接](../behavior/public-control.md#手机版-relay-连接)。

未确认持久的请求可复制完整原请求及当前已知回执状态；复制成功后才提供明确确认已另行保全并移除本页副本的出口。原记录不可读或身份冲突时明确提示状态未知，回执未知须自行核对；此选择不写、不删除设备记录，不代表存储恢复或操作完成。若请求已写入而已收到的回执尚未保存，说明原记录保留、需要恢复设备存储并重试保存回执；留页时迟到确认须重新显示并保全。说明该动作不会改变原 Goal 或重发及确认原操作。

## 验收：采图与看图

手机界面改动按以下顺序验收。测试全绿或采图成功都不能代替看图结论。

1. **采图**：从仓库根目录运行 `node apps/mobile/scripts/fixtures/mobile-product-redesign/capture-ui.mjs`。它在受控 Chromium 中操作真实 `MobileApp`，覆盖 390×844、320 窄屏、短屏与浅色主题，在 `.tmp/mobile-product-redesign/renderer-*/` 下输出完整截图、`receipt.json` 与 `review.md`。对话密度、浮动工具、Focus 状态、网页更新等专项场景的参数与模拟边界见同目录 [scenario.md](../../../apps/mobile/scripts/fixtures/mobile-product-redesign/scenario.md)。改动影响哪个场景就运行哪个；改共享选择器时，复拍所有消费该选择器的场景。
2. **看图**：由未参与实现的 Agent 先读本页相关章节，再逐张打开完整截图，判断主次、紧凑、对齐、留白、文案、控件清晰与操作可达，写出具体位置的问题和建议。做法见[独立 Agent 看图评审](../../guides/agent-visual-e2e-review.md)。
3. **修正并复拍**：按意见修改后重新采图，直到看图结论明确可交付；旧图与旧意见保留在本机证据中。
4. **行为不退化**：涉及状态、提醒或动作的改动，在真实 `MobileApp` 消费者测试中证明未知仍可见、恢复动作仍可达、命中范围不小于 44px；几何与样式断言可以用采图脚本的 `--mutation=` 变体证明改坏会红。

受控 Chromium 不等于真机：iOS/Android 输入法、系统键盘、安全区、前后台和 Safari 绘制须另行在设备上确认，结论里写明边界。

行为、分层、连接、工作面与恢复唯一见交互 SSOT[《手机版 Relay 连接》](../behavior/public-control.md#手机版-relay-连接)。手机独立外壳适配触摸、软键盘和窄/矮视口，共用原对话组成与终端阅读语言；身份、输入能力、请求与unknown清楚可达，不仅缩小Desktop。真实操作采图与独立审美沿既有视觉E2E，查看受影响手机尺寸的完整页面及切换、面板、输入和错误状态操作过程，判断密度、对齐、遮挡与操作可达；局部截图或采图成功不代表全页审美通过。
