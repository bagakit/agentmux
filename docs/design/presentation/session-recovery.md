## 启动大屏的进度层级

- 启动预热沿用同一张全页加载大屏：主标题表示当前阶段，次级文字说明正在处理的对象或下一步；阶段状态以文字呈现，不只靠动画或颜色。进度记录保持简短，避免刷屏和伪精确的百分比。何时显示、降级和让出工作面按交互合同[《全页加载与启动大屏》](../behavior/session-recovery.md#全页加载与启动大屏)执行。

新建 Agent 与 resume 的 P00 可用性、空 Session 列表与未知的区分只定义在交互合同[《P00：新建 Agent 与 resume 必须可用》](../behavior/session-recovery.md#p00新建-agent-与-resume-必须可用)。失败沿已有启动反馈与 Session 服务窗呈现，具体步骤和原地重试清楚可见；不增加常驻诊断栏，不以空态或遮挡原 Terminal 的全页错误替代仍可工作的原 Region。恢复后的输入提示与动作一致性沿同一合同，复用原输入框提示，不增加恢复横幅或为更新文案重建编辑表面。

## 全页加载大屏

- 启动、恢复、停泊、全页导航和大块数据加载共用一个 `FullPageLoadingSurface` 组件；当前图像、层次、动态和主题合同只见[《Terminal 信息与恢复画面的视觉品质》](terminal-reading.md#terminal-信息与恢复画面的视觉品质)。调用方不重复实现全屏 spinner 或品牌 splash。
- 前景只承载品牌、真实阶段标题、短说明和当前可用动作，保持稳定可读。loading、recovering、parked 和 failed 共用几何与密度预算，停泊不显示忙碌信号。真实工作面出现后加载层卸载，不留下空的 chrome 行。
- Terminal 内的 Region 舞台限制在原内容面，加载图形与标题不另占一行或挤掉原终端与服务窗；终端网格、状态切换与尺寸事实只按交互 SSOT[《Connecting 与 Terminal 恢复页的全页状态舞台》](../behavior/session-recovery.md#connecting-与-terminal-恢复页的全页状态舞台)执行。
- 「不重复实现」是**屏幕上只有一份**，不是「调用方自觉不写第二份」。调用方把自己的内容交给
  `FullPageLoadingSurface` 之后，就不再自带第二份背景、品牌层、活动信号或阶段标签——同一张面上
  出现两组品牌/信号、两行阶段文案即为违反。这条是  真实发生过的回归：Connecting 面搬进共享
  组件时把自己那套舞台一起带了进去，而圈着旧舞台的 `:not(.full-page-loading)` 因为两个类落在
  同一个元素上而全部失效，于是旧的那份既没被样式藏起来、也没被删掉，两份同时显形。约束按
  「这张面上有几组」验收，不按「代码里写没写」验收。
- 所有大屏必须提供可访问的 live 文本和不会因动画变化而重复播报的标签；减少动态与隐藏面的约束只见[《Terminal 信息与恢复画面的视觉品质》](terminal-reading.md#terminal-信息与恢复画面的视觉品质)。

## 重启恢复告示
- 重启期间保留原 Tab/Region 的空间骨架与焦点位置；连接中状态使用 Region 内低干扰短标签，不用空白面或新建 Tab 代替。
- Runtime 尚未完成 attach 时，告示必须明确“布局已恢复，正在连接既有 Session”，不得显示“在其他应用打开”这类会诱导用户重复 resume 的文案。
- 恢复回放的几何与未知状态遵循交互合同的 resume/attach 约束；尺寸不可确认或同步失败复用原 Region 的服务窗，不新增常驻尺寸控件。
- 已解决启动告示的收束与未解决、收起及后来错误的保留，唯一见交互合同[《重启后的 Tab/Region 与 Session 恢复》](../behavior/session-recovery.md#重启后的-tabregion-与-session-恢复)；复用原告示呈现，不新增通知层、成功徽章或常驻状态行。

## Session 重启恢复状态

- 重启恢复由共享入口的循环标识和 Progress 页内的短状态表达（`恢复检查中`、`已恢复`、`需处理`），不复用 `working`/`error` 造成矛盾语义。
- 展开面板明确列出当前 Run、旧回执是否可用、恢复检查时间和下一步动作；旧 Run 活动不覆盖新 Run 的最近活动。

## Session 加载与 Terminal 恢复的构图

构图和动效的当前要求统一见[《启动与恢复的分量分开》](#启动与恢复的分量分开)。Connecting 保留真实 Executor 与完整初始 Prompt，内容稳定、可选择、可复制；窄分屏可滚动读完整内容。恢复只占原 Region，Titlebar、Tab、Project Rail、Tool Dock 与分屏边界仍可见，已有终端内容优先保留。

## 启动错误与 Executor 命名的表面

启动错误使用现有服务窗／错误面语言：短标题先说明失败阶段，正文给出当前事实和下一步，复制诊断是一个紧邻的次级动作。不能把 JSON schema 路径、堆栈或内部字段名直接铺成主标题，也不能用无尽 loading 代替解析失败。配置仍安全保留时，提示保持可读且不遮住已经恢复的工作面。
创建已成功而显示读取尚未确认时，沿用上述低噪声服务窗，不将原工作面切回 launcher、替换成失败全屏或展示持续的启动转圈；行为和未知事实边界只定义在交互 SSOT[《我们的流程坏了，不等于 Agent 坏了》](../behavior/session-recovery.md#我们的流程坏了不等于-agent-坏了)的“创建成功不能被显示读取失败撤销”。
CLI 提前退出的具体启动原因沿用现有说明与详情层，不把堆栈或完整终端输出铺成主标题；恢复回退后的身份与输入边界只归交互 SSOT[《启动配置错误与诊断》](../behavior/session-recovery.md#启动配置错误与诊断)，原失败工作面保留可读说明。


Executor 的主标签优先使用用户可读名称；内部 ID 只在详情、复制诊断和 CLI 精确操作中出现。多个同 Provider Executor 以名称、稳定身份色和角标区分，序号后缀不承担产品语义。启动恢复或配置修复时，身份标记保持一致，不因为字段清理而换成新的随机标识。

## 真实重启恢复的表面密度

分隔条两侧的实际尺寸沿交互 SSOT[《Tab、Tab Group 与 Region》](../behavior/spaces-and-layout.md#tabtab-group-与-region)的同一比例显示；比例更新不制造重挂、白屏或额外工具行。

真实重启后的第一帧先显示原有 Tab、Region 和焦点所属工作面；Runtime/Provider 恢复中的服务窗贴在受影响 Region 的边缘，不用全屏 loading 覆盖工作面。服务窗短标题说明失败阶段，正文说明当前保留的事实和恢复动作；恢复成功后收敛为轻量状态，不制造第二套恢复面板。验收证据必须来自不同的真实 Electron 进程和同一持久化根目录，不能用组件重挂载或静态启动标记代替。

完整产品私有验收的非空输入与正常写入时序沿交互 SSOT[《重启后的 Tab/Region 与 Session 恢复》](../behavior/session-recovery.md#重启后的-tabregion-与-session-恢复)，不能用 hydrate 后补写的工作面替代第一帧恢复事实。

## 全局加载表面

Browser restoring、Agent Terminal attach 和 Terminal restoring 共用同一套 Region 级动画与阶段文案，不能各自再造局部 loading 卡片；真实 surface 出现后统一卸载。

应用级和 Region 级加载只保留一套 graphite grid / sweep / registration mark 语言。首次装载显示全幅动画；局部刷新保留已有事实，只在原位显示轻量忙碌信号。任何新的等待态先复用 `FullPageLoadingSurface`，再决定是否需要额外上下文，不另起一套 spinner 视觉。

## 安装后 Renderer 版本边界

安装包启动时只能显示当前内置 Renderer 或同一内置版本下的有效热更新；上一安装包留下的热更新页面不能混入新包。版本边界失败时显示内置页面并保留工作面事实，不用空白或旧版 UI 占据首屏。

## Session 恢复服务窗与单目标 attach

恢复中的服务窗保持紧凑的一行提示，不覆盖终端和 Agent 输入，也不把健康 Session 画成全屏错误。提示应说明失败发生在连接、Replay、屏幕证据或 Provider 流程的哪一步，并保留可达的恢复动作。成功取得目标 Attachment 后，服务窗收敛，当前输出和输入区域继续使用原 Region 的边界。

单目标 attach、刷新和恢复的视觉更新只依赖目标 Attachment 或精确 Subject 的 Run/尺寸/Gap 事实，不等待全局 Session 列表刷新；全量 Runtime projection 属于启动或管理表面，不得让一个 Region 的首次画面等待历史 Run 的批量状态查询。

## 联邦 Runtime 的状态与身份密度

- 本机与远端 Runtime 共享同一套状态语汇：`live`、`unverified`、`historical/interrupted` 和 `retired` 必须可区分，不能把远端不可达或探测超时压成绿色的运行中，也不能用空白工作面代替未知状态。
- 远端 endpoint、Host 和可信身份属于低频元信息，放进既有 tooltip、context menu、服务窗或详情面，不新增一条常驻 Remote bar、第二套 Tab chrome 或重复的 Session/Run 标签。布局、Agent 名称和状态仍由原有工作面承担。
- 远端 Runtime 使用现有紧凑服务窗表达连接、握手、能力探测和恢复阶段；告示说明失败步骤、当前保留的事实和可执行动作，不覆盖终端、输入区或焦点。恢复成功后收敛为轻量状态，不留下第二个恢复面板。
- Linux headless Runtime 不引入桌面专属视觉组件。Desktop 只渲染统一的 Runtime/Session 投影，远端服务的 Provider、Hook、权限和 semantic resume 细节不在工作面复制一份。

## 断电恢复中的状态与附着反馈

断电后保留原 Tab/Region 的视觉骨架。旧 Run 不存在时，终端区域使用轻量恢复状态承载重试动作；不把红色“Attach failed”作为最终态。恢复成功后原位置直接显示新的实时 Run，避免用户手动重新打开 Tab。状态文案区分“旧 Run 已消失，正在恢复”“Provider 暂不可用”和“Session 已明确结束”，不以相同错误密度混在一起。

## Prompt 恢复服务窗

- Prompt 投递恢复中的“旧凭据已接管”“正在等待已送达投递”与“证据链降级”使用现有 Session 服务窗承载；提示必须靠近受影响的 Agent、持续可见且不抢输入焦点。
- 服务窗只说明当前事实、影响范围和可执行动作，不把流程探测失败绘成 Agent 已退出，也不为了隐藏提示清空 Tab、Region 或 Session。健康 Agent 的输入面保持可用时，提示不能变成禁用遮罩。
- 回合边界无法确认时，显式发送与原投递重试使用既有 Message Tools 的动作语言，不再增加第二个 Continue 按钮；风险说明停在服务窗，保持正文、焦点和排队条目可见。行为归交互合同[《跨重启的 Prompt 投递凭据》](../behavior/agent-capabilities-and-messaging.md#跨重启的-prompt-投递凭据)；六项 P0 的交付范围见[《P0 的共同交付边界》](../behavior/agent-capabilities-and-messaging.md#p0-的共同交付边界)。
- 终局后的临时 readiness 与持久交付受据沿上述交互合同区分；临时投影清除不改变已确认交付的表达，本层不新增状态或控件。
- Message Tool 长运行后复发的 mailbox／直接发送失败沿交互合同[《跨重启的 Prompt 投递凭据》](../behavior/agent-capabilities-and-messaging.md#跨重启的-prompt-投递凭据)表达；复用原条目与 Session 服务窗，保留可见正文和健康 Terminal 输入，不增另一套故障面或发送动作。
- 卡顿期间使用现有工作面与服务窗表达已确认的失败阶段，不增加全局遮罩或第二套运行状态。采样、相关工作成本与修复边界见交互合同[《操作成本与当前卡顿》](../behavior/settings-and-observation.md#操作成本与当前卡顿)。

## 运行期保存告示

工作面保存未确认沿用现有服务窗的错误与恢复语言，不新增状态灯、保存队列面板或常驻控件。提交与恢复行为统一见交互 SSOT《运行期保存也必须经过宿主持久化边界》。

实际持久化归属缺失、新空数据库与旧备份恢复的事实边界统一见交互 SSOT[《Tab、Tab Group 与 Region》](../behavior/spaces-and-layout.md#tabtab-group-与-region)；沿同一保存／恢复服务窗表达，不把空白首页或欢迎面当作原工作面已经恢复。

## 确认与任务弹层的统一品质

用户认为 Stop Agent Session 弹窗「太土」，希望类似界面都更加现代、精致、简洁、紧凑。操作与状态真源仅见交互 SSOT[《Stop Agent Session 与同类弹窗的统一品质》](../behavior/session-recovery.md#stop-agent-session-与同类弹窗的统一品质)。

- 弹层沿 Graphite / Mint 与现有 Settings 功能材质：单一高不透明内容底、细微中性高光与柔和阴影，遮罩保留原工作面的空间关系。明暗两主题均以文字和操作清晰度为先，不使用夸张彩色光圈、厚边框、警告图标独立卡或卡片套卡片来制造层次。
- 小型确认以一行短标题、可读的真实对象和简短后果说明形成层级。风险可用标题旁的小型 glyph 与危险动作颜色表示，不常驻大警告块；对象是正文的一部分，长名称 / 路径可换行、选择、完整读取，不靠单行省略隐藏作用域。说明使用正文可读档，避免微字号长段解释。
- 取消、保留 Session 与停止 / 删除按主次排列；只有实际停止 / 删除使用危险语义。按钮同高度、紧凑、尺寸在 hover / focus / busy 不跳动，窄窗长按钮自然换行且均可达，不铺厚重 footer 或重复确认说明。
- 表单与选择弹层共用上述材质、标题档、动作区和静态焦点语言；创建 / fan-out / 讨论的小图标融入标题，取消大图标底座、装饰性大标题与粗分隔。输入与列表仍有清楚 affordance，实际错误 / 未确认事实原位可读，不为减少视觉噪音隐藏它们。快速切换与快捷键保留任务特有布局。
- 动效仅是短促渐显与轻微位移，不缩放文字、改变布局或反复呼吸；减少动态效果偏好下静态完整。小窗与矮窗弹层有界，必要时内部滚动，对象、正文、输入与所有动作都能到达。


## 启动与恢复的分量分开

用户确认「新版当前启动页不错，就是要更好一点」，希望保留其构图并增加鼠标交互；restore 需「另一种简约的酷法」，避免既与启动页相同又「过于素了」。加载与恢复面的排版要有分量，减少不重要的冗余信息；阶段、事实、信息资格与 owner 仅见交互 SSOT[《启动与 restoring 的不同重量》](../behavior/session-recovery.md#启动与-restoring-的不同重量)。

- 应用启动是一张完整品牌面：清晰构图、中性高光、设置页同一功能材质、Graphite / Mint 与精确文字比例形成现代高级感。允许鼠标引发轻微光照/景深变化，内容和控件不跟着移动；指针离开回归平稳，触摸无需 hover 才可读，不靠来回扫线、呼吸或自动循环放大图像制造“正在加载”。真实阶段文案负责说明进度，失败保留原因与入口。
- Region 恢复／停泊采用开放、安静的左对齐阅读构图，充分使用面宽；正文舞台随实际 Region 流动，在宽面形成约 560px 的阅读上限，窄面沿原 spacing token 收紧内边距，不挤成悬浮的小图标卡或居中的微型栏目。沿用 `--fs-display` 与 `--fs-prose` 的标题／正文档，以空间、行长和对齐建立分量，不另起字号系统。允许低对比、局部静态光影与精细的行内状态 glyph，不能退化成纯平背景加几行孤立文字，也不使用横幅大图、品牌 hero、全屏扫线或厚重卡片；展开详情的材质与焦点反馈细微、稳定。
- 每张面只有一份清楚的主状态，原可用动作紧邻状态且先于 recap；去掉重复 eyebrow、孤立图标底座、泛化保留说明与空反馈块。标题和有信息量的短说明形成同一组，只有实际操作反馈占用空间。关键失败、未知和当前可用能力保持首层可读；完整身份、技术元数据与低层诊断进入原详情，不能用折叠减轻它们的真实严重性。普通退出与保留的合并资格只沿上述交互合同。
- recap 以一条安静分隔和有呼吸的间距形成次级阅读层，不另套卡片或重复状态；来源简短可辨，完整来源可按需核对。其唯一内容与密度边界见[《Terminal resume 的 recap 密度》](terminal-reading.md#terminal-resume-的-recap-密度)。正常、窄／短、长 Prompt／摘录及真实失败／未知下，主状态和原动作先可见，长正文有界滚动且完整阅读／复制／诊断入口可达；短面不靠裁切控件维持留白。
- 忙碌、失败与未知按真实阶段使用既有语义，不画虚构进度、不持续呼吸或旋转，内容和控件不随装饰移动。app 的已有品牌面也采用精炼的状态／动作层次，保留图像与鼠标反馈的原边界；Region 的开放阅读构图不能靠缩小 app 大屏得到。
- 公共组件仍共享 token、阶段语义与材质；app 和 region 是明确不同构图，不能用大屏缩小冒充轻量恢复。减少动态时交互位移静止，隐藏窗口与 retained inert 面不运行装饰动画；鼠标效果仅局限 app 启动面，不给每个 Region 增加全局监听或热路径成本。
