## 启动大屏的进度层级

- 启动检测沿用同一张全页加载大屏：主标题表示当前阶段，次级文字说明正在处理的对象或下一步；并行检查以紧凑文字呈现各自的真实过程与状态，不把同时进行的工作画成尚未开始的串行步骤。Agent 可用性检查可辨，存在准确总量时显示已完成项与总数；等待、可用、确认缺失和检查失败不能都压成同一个问号。进度记录保持简短，避免刷屏和伪精确的百分比，不只靠动画或颜色表达状态。检查范围与进入工作面的时机只见交互合同[《全页加载与启动大屏》](../behavior/session-recovery.md#全页加载与启动大屏)。
- 应用启动保留当前 Realm 的原品牌大图与右侧构图，只优化左侧阅读栏：一份 `AgentMux` 品牌字标、真实阶段标题、短说明、共享活动信号和当前活动组成清楚层级，不新增卡片、装饰线框、微缩工作面或第二套加载外壳。并行 endpoint 观察按原 `step` 的首次出现顺序分组，显示各组准确 endpoint 数量及该组去重后的原 `message`；不得从展示文案推断完成、健康或串行先后。过程条目使用面向阅读的状态符号、正文排版与留白，不做成命令行输出。`Connection details` 先按 endpoint 汇总为紧凑、可扫描的列表，单个 endpoint 展开后才呈现其原 step、code 与 recovery；不得打开总详情就把全部原始诊断铺成日志墙。每个原 host、step、code 与 recovery 仍完整可读，状态说明与详情入口保持清楚对比，不能为了安静而把未确认事实弱化成不可读脚注。启动与详情开合用短距分层入场、光影过渡和微弱活动呼吸提供连续反馈，动效不冒充进度；减少动态效果时所有层级与条目直接可读。纯呈现复用原 `RuntimeEndpointWarning` 与启动消费者，不增加 JSON-RPC、CLI、Store 或生命周期事实。
- 必要持久投影读取完成后直接进入工作面；Agent 可用性检查在后台继续，其过程与失败沿原检测入口和服务窗呈现，正常、窄窗和短窗均清楚可见且能键盘到达，不遮回已进入的工作面。不提供放行按钮或启动等待设置，不新增独立启动配置面板、常驻诊断栏或第二套加载外壳。
- Runtime 尚未连接和 Renderer 尚未确认的等待表面沿同一阶段、文字与低干扰加载动效；动效表达正在等待或核实，不声称已连接。长等待的继续等待、退出与诊断动作在原表面就地可见，正常、窄窗和短窗均能键盘到达，焦点清楚，减少动态效果下阶段与动作仍完整可读。退出须有明确确认语义，避免默认焦点误触；探测、退出与恢复行为只引用交互合同[《全页加载与启动大屏》](../behavior/session-recovery.md#全页加载与启动大屏)，不增加第二套全局告警外壳。

新建 Agent 与 resume 的 P00 可用性、空 Session 列表与未知的区分只定义在交互合同[《P00：新建 Agent 与 resume 必须可用》](../behavior/session-recovery.md#p00新建-agent-与-resume-必须可用)。失败沿已有启动反馈与 Session 服务窗呈现，具体步骤和原地重试清楚可见；不增加常驻诊断栏，不以空态或遮挡原 Terminal 的全页错误替代仍可工作的原 Region。恢复后的输入提示与动作一致性沿同一合同，复用原输入框提示，不增加恢复横幅或为更新文案重建编辑表面。

## 工作中界面崩溃的恢复告示

- Renderer 真实退出后的说明与动作由仍活着的 Main 使用系统原生告示呈现，短标题说明界面故障，正文交代原数据、健康 Run 与最后未确认改动的边界；提供清楚的重新加载和退出动作，不依赖白屏中的控件。恢复和退出语义仅见交互 SSOT[《工作中界面崩溃的隔离、恢复与退出》](../behavior/session-recovery.md#工作中界面崩溃的隔离恢复与退出)，不新增第二套全局错误外壳或堆栈主阅读区。

## 全页加载大屏

- 启动、恢复、停泊、全页导航和大块数据加载复用 `FullPageLoadingSurface` 的公共阶段、token、活动信号与材质；应用启动和 Region 恢复分别采用[《启动与恢复的分量分开》](#启动与恢复的分量分开)的构图，不把品牌大屏缩小到 Region。调用方不另造 spinner 或重复品牌层。
- 每张面只承载一份真实阶段标题、短说明、活动信号和当前可用动作；品牌主体限于应用启动面。loading、recovering、parked 和 failed 保持各自容器的稳定几何，停泊不显示忙碌信号。真实工作面出现后加载层卸载，不留下空的 chrome 行。
- 很快完成的加载不闪现：以 loading 进入的 Region 面经短暂停顿后才淡入，减少动态时停顿后直接出现；停顿只作用于呈现，不推迟读取、动作或状态播报。进入节奏只在面出现时决定一次，同一张面切换阶段不重播，已显示的内容不因此消失再淡入。恢复、停泊与失败面承载原身份与恢复事实，进入即呈现；应用启动面沿自己的入场。
- Terminal 内的 Region 舞台限制在原内容面，加载图形与标题不另占一行或挤掉原终端与服务窗；终端网格、状态切换与尺寸事实只按交互 SSOT[《Connecting 与 Terminal 恢复页的全页状态舞台》](../behavior/session-recovery.md#connecting-与-terminal-恢复页的全页状态舞台)执行。
- 共享组件接收调用方的真实内容后，屏幕上仍只有一份背景、主状态与活动信号；调用方不再叠同级舞台、重复阶段标签或第二份品牌层。以实际画面核对单份呈现，不能只凭代码复用关系判断。
- 所有大屏必须提供可访问的 live 文本和不会因动画变化而重复播报的标签；减少动态与隐藏面的约束只见[《Terminal 信息与恢复画面的视觉品质》](terminal-reading.md#terminal-信息与恢复画面的视觉品质)。

## 重启恢复告示
- 重启期间保留原 Tab/Region 的空间骨架与焦点位置；连接中状态使用 Region 内低干扰短标签，不用空白面或新建 Tab 代替。
- Runtime 尚未完成 attach 时，告示必须明确“布局已恢复，正在连接既有 Session”，不得显示“在其他应用打开”这类会诱导用户重复 resume 的文案。
- 告示区分旧 owner 仍存活与租约可回收两种情况；重启后遗留的过期租约（stale lease）不呈现为健康 Session 被其他进程占用。归属核验只见交互合同[《工作面持久恢复与启动边界》](../behavior/session-recovery.md#工作面持久恢复与启动边界)的「恢复须核验原 lifecycle owner」。
- 恢复回放的几何与未知状态遵循交互合同[《恢复与多 View 的终端尺寸》](../behavior/terminal-reading.md#恢复与多-view-的终端尺寸)；尺寸不可确认或同步失败复用原 Region 的服务窗，不新增常驻尺寸控件。
- 已解决启动告示的收束与未解决、收起及后来错误的保留，唯一见交互合同[《重启后的 Tab/Region 与 Session 恢复》](../behavior/session-recovery.md#重启后的-tabregion-与-session-恢复)；复用原告示呈现，不新增通知层、成功徽章或常驻状态行。

## Session 重启恢复状态

- 受管前台退出后的原页面沿[前台退出的一键继续约束](../behavior/session-recovery.md#sessionrun-与-view)显示短状态、必要后台说明和就近的 Resume 主动作；保留原终端输出与对话阅读，不让用户只面对原生退出文案或命令。后台可用、已结束和未确认分别说明，不用红色崩溃面代替正常前台断开；底层接回或语义恢复的选择由原 owner 处理，不让用户先选择恢复技术路径。点击后的真实阶段与失败原位可见，成功后收起对应告示。
- 重启恢复由共享入口的循环标识和 Progress 页内的短状态表达（`恢复检查中`、`已恢复`、`需处理`），不复用 `working`/`error` 造成矛盾语义。
- 展开面板明确列出当前 Run、旧回执是否可用、恢复检查时间和下一步动作；旧 Run 活动不覆盖新 Run 的最近活动。
- 退出提示与 Attention 摘要先说清准确阶段。已取得退出码时直接呈现该事实，不能仍称“没有详情”；只有原恢复回执明确关联当前 Run，才说明“恢复进程退出”，普通退出、原 Run 中断和当前恢复观察分别表达。退出码只解释进程结果，缺少具体原因时明确原因尚未确认，不据文案猜测 Provider 故障或重试资格。
- 原恢复回执已提供的阶段、尝试次数和具体失败原因须在原服务窗可读：首层保持短状态与下一步，完整错误及所属 Run／operation 沿已有详情展开，不让具体原因被通用退出说明覆盖。旧尝试的失败不得冒充当前 Run 的原因，健康 Run 不因历史失败持续显示恢复失败；没有取得的阶段、次数或原因不补造。恢复观察与动作资格只见[持续推进恢复](../behavior/session-recovery.md#session-重启后的持续推进恢复)及[启动配置错误与诊断](../behavior/session-recovery.md#启动配置错误与诊断)。
- 当前对话阅读面的原 Session 区域直接承载清楚的恢复短状态、必要原因与原动作，不让用户切到 Terminal 才发现待恢复或恢复问题。复用已有服务窗与恢复入口，已有正文仍是主要阅读面；恢复中与消息读页等待分别表达，待恢复、失败、结束和未知不使用“工作中”文案或忙碌动画。宽窄、空态和保留旧正文时均可读可操作，不另造恢复面板或常驻成功徽章；状态资格与健康能力保持见[冷启动工作面与按需执行](../behavior/session-recovery.md#冷启动工作面与按需执行)。
- 没有可续接原生对话的已结束 Session，原位用一句平实说明讲清 Core 确认的事实（AgentMux 没有这条 Session 可续接的原生对话），不推测 Provider 是否保存过、何时结束，不用红色失败面，不叠第二块同义告示；首层只留一个能走通的实心主动作（在这里开始新对话：沿用原 Executor 与执行目录，在原 Tab 旁新开 Tab，不发送任何内容），不保留注定失败的重读或恢复按钮，接手与分析仍在原次级位置，原 Tab 保持可读。输入框提示不说“发送以恢复”，按下发送也只保留草稿并指向主动作，不自动带入新会话。行为边界见[没有可续接原生上下文时如实说明并给出可走通的路](../behavior/session-recovery.md#agent-session-启动与恢复的统一阶段)。

## Session 加载与 Terminal 恢复的构图

构图和动效的当前要求统一见[《启动与恢复的分量分开》](#启动与恢复的分量分开)。Connecting 保留真实 Executor 与完整初始 Prompt，内容稳定、可选择、可复制；窄分屏可滚动读完整内容。恢复只占原 Region，Titlebar、Tab、Project Rail、Tool Dock 与分屏边界仍可见，已有终端内容优先保留。

原来源 Session 未确认且没有可显示的当前画面时，同样沿上述共享 Region 状态舞台呈现：短标题先讲当前目标与实际状态，一段正文说明保留的原工作和下一步，真实可用动作就近排列；不把“Core 未返回 Session”这样的协议判断、反复身份说明及空白私有草稿框铺成主页面。原身份、技术原因与最后确认事实收进同一按需详情；已有草稿作为次级保留内容可继续编辑，空草稿收起。长任务名、远端名称与错误在窄分屏可完整读到，明暗主题、键盘焦点和减少动态均沿现共享舞台。只有真实在途连接／读取／恢复使用等待标识；尚未确认、目录缺席及不可用使用稳定静态状态，不能靠循环动效暗示已经重连。状态与动作资格只见[同主题行为](../behavior/session-recovery.md#connecting-与-terminal-恢复页的全页状态舞台)，不从视觉阶段推导生命周期。

## 启动错误与 Executor 命名的表面

启动错误使用现有服务窗／错误面语言：短标题先说明失败阶段，正文给出当前事实和下一步，复制诊断是一个紧邻的次级动作。不能把 JSON schema 路径、堆栈或内部字段名直接铺成主标题，也不能用无尽 loading 代替解析失败。配置仍安全保留时，提示保持可读且不遮住已经恢复的工作面。
启动等待、观察未确认与失败提示采用同一清楚的阅读顺序：当前状态标题、为何出现及已知影响的一段短说明、就近的原检查／恢复动作。按钮附近说明该动作检查或继续什么，不能只留泛化失败标题和一个含义不明的 Resume；准确运行事实与保留边界仍首层可读，完整错误、操作身份和技术字段放入已有详情，未知原因不补造。状态与动作资格仅见[Session 加载页的可恢复信息](../behavior/session-recovery.md#session-加载页的可恢复信息)。
Source Launcher 的保留请求采用同一紧凑服务窗：主层只给一个清楚的状态、必要原因与原操作，创建失败和当前观察不互相覆盖；准确完整技术原因、机器 code、角色／Host／步骤与原 JSON 收进一处具名详情。复用现有字号、间距与按钮主次，不继承 Launcher 叙述大字把调试字段铺满主面；窄、短窗口仍能看到并编辑保留草稿，详情使用独立有界滚动。紧邻的“复制诊断”复制当前准确原对象的诊断，并确认实际复制结果；它不重读、继续或发送。状态事实不因折叠隐藏或视觉分组而改变。
待创建请求因存储受限而自动继续时，原 Region 的等待舞台只呈现一份主状态、短原因与下一步，不在通用“正在启动”标题下叠另一整块同义告示。首层保留一个与原操作资格相符的主动作：可立即继续时明确其继续原请求，结果未确认时明确其只检查原结果；自动继续的说明持续可读，不要求用户逐项检查才能等待恢复。完整原诊断、原结果检查及接手／分析等其他路径收在一处具名、可发现且键盘可达的展开入口，各自动作含义可辨；展开不自动派发，收拢不清除故障。动作进行中保留原内容与反馈位置，同一等待更新不反复展开详情、抢焦点或逐次播报技术错误；准确结果恢复后收回对应等待，不新增成功面。真实等待与结果未知沿原阶段分别呈现，不能用活动信号、文案或经过时间授予继续资格；原操作边界仍见同主题交互合同，健康终端与已读内容保全沿[Session 恢复服务窗与单目标 attach](#session-恢复服务窗与单目标-attach)。
沿既有语义图标与公共动效策略使用轻量 SVG，形成精细、稳定的状态提示；不引入 GIF、重型动效依赖、第二套动画舞台或装饰性流程图。只有真实等待使用持续活动信号，未确认停泊与已确认失败使用静态状态表达，不能用动画解释不存在的进度；减少动态效果下完整静态可读，隐藏／停泊面停止循环。构图、色彩、活动信号的分量与动态成本边界继续归[启动与恢复的分量分开](#启动与恢复的分量分开)。
创建已成功而显示读取尚未确认时，沿用上述低噪声服务窗，不将原工作面切回 launcher、替换成失败全屏或展示持续的启动转圈；行为和未知事实边界只定义在交互 SSOT[《我们的流程坏了，不等于 Agent 坏了》](../behavior/session-recovery.md#我们的流程坏了不等于-agent-坏了)的“创建成功不能被显示读取失败撤销”。
CLI 提前退出的具体启动原因沿用现有说明与详情层，不把堆栈或完整终端输出铺成主标题；恢复回退后的身份与输入边界只归交互 SSOT[《启动配置错误与诊断》](../behavior/session-recovery.md#启动配置错误与诊断)，原失败工作面保留可读说明。


Executor 的主标签优先使用用户可读名称；内部 ID 只在详情、复制诊断和 CLI 精确操作中出现。多个同 Provider Executor 以名称、稳定身份色和角标区分，序号后缀不承担产品语义。启动恢复或配置修复时，身份标记保持一致，不因为字段清理而换成新的随机标识。

## 真实重启恢复的表面密度

分隔条两侧的实际尺寸沿交互 SSOT[《Tab、Tab Group 与 Region》](../behavior/spaces-and-layout.md#tabtab-group-与-region)的同一比例显示；比例更新不制造重挂、白屏或额外工具行。

真实重启后的第一帧先显示原有 Tab、Region 和焦点所属工作面；Runtime/Provider 恢复中的服务窗贴在受影响 Region 的边缘，不用全屏 loading 覆盖工作面。服务窗短标题说明失败阶段，正文说明当前保留的事实和恢复动作；恢复成功后收敛为轻量状态，不制造第二套恢复面板。验收证据必须来自不同的真实 Electron 进程和同一持久化根目录，不能用组件重挂载或静态启动标记代替。

完整产品私有验收的非空输入与正常写入时序沿交互 SSOT[《重启后的 Tab/Region 与 Session 恢复》](../behavior/session-recovery.md#重启后的-tabregion-与-session-恢复)，不能用 hydrate 后补写的工作面替代第一帧恢复事实。

## 全局加载表面

Browser restoring、Agent Terminal attach 和 Terminal restoring 共享 Region 级状态语言，构图、动态与停泊／失败区分唯一见[《启动与恢复的分量分开》](#启动与恢复的分量分开)。首次加载沿对应容器呈现完整阶段与原动作；局部刷新保留已有事实，只在原位显示轻量忙碌信号。真实 surface 出现后等待层卸载，不另造局部 loading 卡片或第二套 spinner。

## 安装后 Renderer 版本边界

安装包启动时只能显示当前内置 Renderer 或同一内置版本下的有效热更新；上一安装包留下的热更新页面不能混入新包。版本边界失败时显示内置页面并保留工作面事实，不用空白或旧版 UI 占据首屏。

应用 client 与实际 Runtime 的协议错位沿原启动阶段和服务窗说明真实失败步骤、当前可用或未确认范围与恢复动作，保原工作面，不把健康 Agent 绘成已停止或用全局白屏替代可见状态。整套已验证版本选择、实际服务资格与健康 Run 保全只见交互 SSOT[《分层更新与回切》](../behavior/session-recovery.md#分层更新与回切)，本层不新增错误外壳或版本状态账本。

主进程启动依赖缺失沿既有启动阶段与可见服务说明表达；不为构建／发布故障新增常驻诊断区、另一层错误外壳或健康 Agent 的停止状态。安装依赖闭包、真实加载事实与原工作面／Run 保全只定义在交互 SSOT[《打包、安装与启动事实》](../behavior/session-recovery.md#打包安装与启动事实)的“主进程启动依赖必须在安装包内闭合”约束。

## Session 恢复服务窗与单目标 attach

恢复中的服务窗保持紧凑、低占用，不作为固定的一行挤占终端，不覆盖终端和 Agent 输入，也不把健康 Session 画成全屏错误。提示应说明失败发生在连接、Replay、屏幕证据或 Provider 流程的哪一步，并保留可达的恢复动作。成功取得目标 Attachment 后，服务窗收敛，当前输出和输入区域继续使用原 Region 的边界。

单目标 attach、刷新和恢复的视觉更新只依赖目标 Attachment 或精确 Subject 的 Run/尺寸/Gap 事实，不等待全局 Session 列表刷新；全量 Runtime projection 属于启动或管理表面，不得让一个 Region 的首次画面等待历史 Run 的批量状态查询。

## Durable Runtime、Gap 与失败提醒的告示密度

- Durable Runtime 的异常使用同一套紧凑服务窗语言。瞬态 WAL busy 的重试不占据 Terminal 内容区，也不显示永久 loading；只有重试耗尽、磁盘不足或完整性失败，才在原 Region 旁显示一条简短的分类告示与下一步。状态库达到容量上限时，标题说明“状态库已满／启动未完成”这一阶段，保留已恢复的工作面，不把 readiness 超时写成 Agent 故障。WAL 增长超出预算与真实数据损坏分开呈现。退出清理中的 attach 门禁只在原 Region 旁短暂告示，清理完成后自动收敛，不使用永久的全局遮罩。状态、Owner 边界与默认持久位置和实际绑定的区分归交互合同[《Durable Runtime 健康》](../behavior/session-recovery.md#durable-runtime-健康)；本层不复制错误码，不另造控件、常驻路径指示、常驻指标或诊断轮询，也不把候选地址显示为恢复成功。
- 失败提醒沿交互合同[《我们的流程坏了，不等于 Agent 坏了》](../behavior/session-recovery.md#我们的流程坏了不等于-agent-坏了)。新建入口与 resume 所属 Session 使用既有局部反馈或服务窗，紧凑说明失败步骤、当前可用或未知的能力与可执行动作，原始原因可查看。未知与流程失败沿同一轻声提醒分类；一条底层错误不同时堆叠局部与全局告警，不抢焦点，不遮住仍能工作的 Terminal。Prompt 投递与 Store 读取未确认时沿用现有紧凑服务窗，不建立第二份错误码清单。
- 本机身份恢复复用原入口的服务窗。首层说明本机后台受影响的功能与仍可继续的工作。需要原备份时，「从备份恢复」是主动作，仍可用的入口留在次级位置，技术原因收进详情。恢复后的变化在原位呈现，恢复记录可在诊断中核对。恢复条件见[原 Runtime 身份恢复](../behavior/persistence.md#原-runtime-身份恢复)。
- 输出 Gap 与 Gap 复发沿交互合同[《完成与 error 判定可信度》](../behavior/session-recovery.md#完成与-error-判定可信度)。现有告示详情能定位原 Session；默认主文只保留范围与 Gap 说明，观察字段、可核游标与完整原文放进可展开的 Details，长范围或窄面不能让展开的诊断挤占原恢复控件。不新增监控栏、监控面板、常驻计数器、错误登记表、遮罩或重复告警，也不以告示推测进程死亡。

## 联邦 Runtime 的状态与身份密度

远端管理页面与拓扑范围见 [Remote 管理 PRD](../behavior/remote-management.md)，多 endpoint 失败隔离、生命周期与真实恢复验收见交互 SSOT[《联邦 Runtime 与远端恢复边界》](../behavior/session-recovery.md#联邦-runtime-与远端恢复边界)。本机与远端复用原工作面和服务窗语言，单 endpoint 失败不升级为整窗空态、loading 或阻断；本节只定义 Session 工作面的呈现，不另立部署面板、Remote bar、终端 chrome 或第二份行为／RPC 合同。

- 本机与远端 Runtime 共享同一套状态语汇：`live`、`unverified`、`historical/interrupted` 和 `retired` 必须可区分，不能把远端不可达或探测超时压成绿色的运行中，也不能用空白工作面代替未知状态。
- 远端 endpoint、Host 和可信身份属于低频元信息，放进既有 tooltip、context menu、服务窗或详情面，不新增一条常驻 Remote bar、第二套 Tab chrome 或重复的 Session/Run 标签。布局、Agent 名称和状态仍由原有工作面承担。
- 远端 Runtime 使用现有紧凑服务窗表达连接、握手、能力探测和恢复阶段；告示说明失败步骤、当前保留的事实和可执行动作，不覆盖终端、输入区或焦点。恢复成功后收敛为轻量状态，不留下第二个恢复面板。
- Linux headless Runtime 不引入桌面专属视觉组件。Desktop 只渲染统一的 Runtime/Session 投影，远端服务的 Provider、Hook、权限和 semantic resume 细节不在工作面复制一份。

远程工具 binding 的资格沿原 Session 服务窗持续呈现。连接正常仍可显示 Provider 明确报告的 Hooks、Skills、MCP 或 Agent control 分项限制；展开才显示失败步骤、保留能力和恢复动作。未知观察保留原 binding 与已读资格，刷新只重读该对象，不重放工具调用或关闭健康 Agent。没有待处理事项时收敛，不增加常驻远端状态条。

## 断电恢复中的状态与附着反馈

断电后保留原 Tab/Region 的视觉骨架。旧 Run 不存在时，终端区域使用轻量恢复状态承载重试动作；不把红色“Attach failed”作为最终态。恢复成功后原位置直接显示新的实时 Run，避免用户手动重新打开 Tab。状态文案区分“旧 Run 已消失，正在恢复”“Provider 暂不可用”和“Session 已明确结束”，不以相同错误密度混在一起。

## Prompt 恢复服务窗

- Prompt 投递恢复中的“旧凭据已接管”“正在等待已送达投递”与“证据链降级”使用现有 Session 服务窗承载；提示必须靠近受影响的 Agent、持续可见且不抢输入焦点。
- 服务窗只说明当前事实、影响范围和可执行动作，不把流程探测失败绘成 Agent 已退出，也不为了隐藏提示清空 Tab、Region 或 Session。健康 Agent 的输入面保持可用时，提示不能变成禁用遮罩。
- 回合边界无法确认时，显式发送与原投递重试使用既有 Message Tools 的动作语言，不再增加第二个 Continue 按钮；风险说明停在服务窗，保持正文、焦点和排队条目可见。行为归交互合同[《跨重启的 Prompt 投递凭据》](../behavior/agent-capabilities-and-messaging.md#跨重启的-prompt-投递凭据)；六项 P0 的交付范围见[《P0 的共同交付边界》](../behavior/agent-capabilities-and-messaging.md#p0-的共同交付边界)。
- 终局后的临时 readiness 与持久交付受据沿上述交互合同区分；临时投影清除不改变已确认交付的表达，本层不新增状态或控件。
- Message Tool 长运行后复发的 mailbox／直接发送失败沿交互合同[《跨重启的 Prompt 投递凭据》](../behavior/agent-capabilities-and-messaging.md#跨重启的-prompt-投递凭据)表达；复用原条目与 Session 服务窗，保留可见正文和健康 Terminal 输入，不增另一套故障面或发送动作。
- 卡顿期间使用现有工作面与服务窗表达已确认的失败阶段，不增加全局遮罩或第二套运行状态。采样、相关工作成本与修复边界见交互合同[《操作成本与当前卡顿》](../behavior/settings-and-observation.md#操作成本与当前卡顿)。

## 运行期保存告示

工作面保存未确认沿用现有服务窗的错误与恢复语言，不新增状态灯、保存队列面板或常驻控件。提交与恢复行为统一见[《保存合同》](../behavior/persistence.md#保存合同)。

实际持久化归属缺失、新空数据库与旧备份恢复的事实边界统一见交互 SSOT[《工作面持久恢复与启动边界》](../behavior/session-recovery.md#工作面持久恢复与启动边界)；沿同一保存／恢复服务窗表达，不把空白首页或欢迎面当作原工作面已经恢复。

## 接手的中央 Agent 选择

接手在准确来源 Region 的当前画面中央呈现初始 Launcher 共用的 Agent 选择区域，保留原内容作工作上下文，不使用独立 Dialog、全局遮罩或 captured / native 来源下拉框。Focus 卡片有唯一已确认位置时先导航到该 Region 再就地展开；无位置或多位置时同一区域覆盖 Focus 工作区一侧，并在其中显式选择目的地。用户的新 Agent 派生动作复用同一区域：标题为动作名，起点行显示「原 Agent → 动作名」，指令以三行内的引用块预览，悬停可读全文，默认 Agent 排在候选首位并获初始焦点。身份、材料与提交保护只见[《接手原会话的工作》](../behavior/session-recovery.md#接手原会话的工作)；候选的头像、名称、选中反馈与可用性表达沿[《初始 Launcher 的现代工作台密度》](spaces-and-layout.md#初始-launcher-的现代工作台密度)，不另画一套普通 Executor select。

同一 Takeover 选择区域显示准确来源与明确新去向，并以紧凑文字标注 Promotion、Handson、转岗或普通接手；性质与未知资格沿[流转合同](../behavior/session-recovery.md#takeover-的流转性质与派生关系)，不用外形、名称或位置推断。Promotion 优先呈现已有 Clubs，另建 Club 清楚说明团队与 Thread 两级结果；确定去向后复用共用 Agent 选择，不另开一套接手弹窗、Executor 选择或上下文来源表单。来源和目标的同名对象以必要的原归属消歧，未知结果固定原请求并提供检查，原位置与输入持续保留。

目的地首层呈现资源选择，默认准确目标直接展示其可用 Agent；展示 Workspace／Group 放在按需展开的 `Show in` 中，切换展示位置保留已选资源。两组菜单各自可搜索、浏览与退出，不把全部资源与展示位置组合成一张长菜单。默认与明确选择的资格沿[接手行为合同](../behavior/session-recovery.md#接手原会话的工作)。

Agent 详情在原 Source 阅读面呈现接手来源、性质和去向：先读得懂谁从哪里承接到哪里，再按需展开准确身份和原操作；多去向有界分页，未记录、未读取、未知与已创建后关闭分别表达。链接沿原准确对象导航，不暗示点击会创建或恢复 Agent，也不把来源、去向和真实认证创建者混成同一关系。

选择区域以短促有限的进入与退出回应 Take over，内容与可点击目标稳定，减少动态时直接呈现完整静态状态，输入、取消与提交不等待动画完成。沿共享动态 token 和控件呈现实际选择，不画假加载或循环装饰。宽窄、明暗和短 Region 中，长名称、完整候选、选中标记、键盘焦点、取消及真实失败均清楚可达；局部关闭返回原入口，不抢旁侧健康工作面的焦点。动效中间帧与静态终态均需独立实际看图。

已创建后关闭的接手目标在原选择区域明确显示“已创建，后已关闭”，并提供再次选择接手 Agent 的动作。打开选择区域时 Core 已确认同一来源的上一次接手已关闭，则在标题说明下以一句非阻断文案告知，候选保持可选，用户此刻的选择即再次选择；选择在呈现之后才发生的关闭，仍按前句先显示关闭事实。未知结果继续提供检查原请求；关闭事实与检查失败不能混成同一种失败标题。再次选择沿原共享候选布局，取消仍回到原工作面。

## Region fork 的位置选择

从当前 Agent 的原信息／操作入口发起 fork，位置选择复用已有分屏与新 Tab 的方向几何、焦点和键盘语言。只呈现本次可用目的地，不借用浏览器 URL 或系统浏览器动作。原会话与新会话的关系在完成反馈中可辨；未确认和局部失败沿原服务窗提供核对动作，保持原工作面可读可用。能力、起点、新身份与提醒的行为只见[《从 Region 显式 fork 到新工作面》](../behavior/session-recovery.md#从-region-显式-fork-到新工作面)。

## 确认与任务弹层的统一品质

“Restart Session…”作为 Agent 原操作菜单中的明确动作，与 Resume 区分。复用现有确认面，说明会中断当前工作、恢复同一会话且不重发旧输入；取消不产生生命周期动作。未收口的原重启显示真实反馈，提供检查原操作，只有 Core 明确允许时才重试同一请求，不因对话框关闭、页面重开或回执丢失创建另一次重启。准确目标、操作身份与恢复义务仅见[显式重启会话](../behavior/session-recovery.md#显式重启会话)。

Stop Agent Session 与同类弹层采用现代、精致、简洁、紧凑的风格。操作与状态真源仅见交互 SSOT[《Stop Agent Session 与同类弹窗的统一品质》](../behavior/session-recovery.md#stop-agent-session-与同类弹窗的统一品质)。

- 弹层沿 Graphite / Mint 与共享[《弹层作用域与层级》](shared-rules.md#弹层作用域与层级)的实色内容材质、细微中性高光与柔和阴影，遮罩保留原工作面的空间关系。明暗两主题均以文字和操作清晰度为先，不使用夸张彩色光圈、厚边框、警告图标独立卡或卡片套卡片来制造层次。
- 小型确认以一行短标题、可读的真实对象和简短后果说明形成层级。风险可用标题旁的小型 glyph 与危险动作颜色表示，不常驻大警告块；对象是正文的一部分，长名称 / 路径可换行、选择、完整读取，不靠单行省略隐藏作用域。说明使用正文可读档，避免微字号长段解释。
- Restart Session 的对象行按结构化事实分别呈现 Executor 与项目：Executor 复用共享 Provider 图形及 Executor 配置名，项目复用共享 folder 图形及 Workspace 名；两者保留可读文字，不从展示名称拆分或猜测事实。项目未确认时保留原对象文本，不把 Session 名冒充项目。
- 取消、保留 Session 与停止 / 删除按主次排列；只有实际停止 / 删除使用危险语义。按钮同高度、紧凑、尺寸在 hover / focus / busy 不跳动，窄窗长按钮自然换行且均可达，不铺厚重 footer 或重复确认说明。
- 表单与选择弹层共用上述材质、标题档、动作区和静态焦点语言；创建 / fan-out / 讨论的小图标融入标题，取消大图标底座、装饰性大标题与粗分隔。输入与列表仍有清楚 affordance，实际错误 / 未确认事实原位可读，不为减少视觉噪音隐藏它们。快速切换与快捷键保留任务特有布局。
- 动效仅是短促渐显与轻微位移，不缩放文字、改变布局或反复呼吸；减少动态效果偏好下静态完整。小窗与矮窗弹层有界，必要时内部滚动，对象、正文、输入与所有动作都能到达。


## Agent 卡片的操作动效

停止中、接手中与 Fork 中采用同一套卡片操作动效，形成可辨、精致且适合连续操作的反馈。状态、准确对象、非模态承接及成功资格只见[异步操作反馈](../behavior/session-recovery.md#agent-卡片的异步操作反馈)；本节不以视觉状态授予业务能力。

- **未确认反馈先讲状态与选择。** 卡片与 Region 入口共用“短状态 → 一句当前事实 → 动作 → 按需详情”的层级；原操作 ID、Session／Run 等技术信息收入具名的“操作详情”，详情在有界浮层中完整可读、可选取和复制；展开不改变卡片行高。必要的准确来源、去向与已知创建结果先用人可读的对象说明，同名时消歧；首次失败与当前核对结果在详情中分别可辨，不以通用“原操作已保留”取代已知原因。
- **卡片显示确认的接手去向。** 原 Agent 卡下方用一条轻量关系提示呈现。一个目标显示共享头像、真实显示名和短句；多个目标复用共享头像组，列出可达的具名目标，有限空间的剩余项从数字入口打开。点击头像或名字打开对应 Agent 的已确认位置，键盘能逐个访问。确认首条交接才写「继续了这份工作」；仅确认创建时说明新 Agent 已创建，仍待核对的步骤与历史查阅沿原入口。

- **接手取消与收起分开呈现。** 对沿[接手行为](../behavior/session-recovery.md#接手原会话的工作)可表达取消的未完成操作，首层直接可见“检查结果”和“取消接手”，用同一轻量行内动作和可读状态承接。“继续接手”进入详情，与只读检查可辨。点击后立刻在当前操作上显示提交或检查。提交前失败仅显示一次短状态，紧接具体失败步骤和下一步，完整错误留在详情。仅支持检查的旧记录收入原 Agent 信息来源页的“旧接手记录”。详情先显示简短结果和“检查结果”，明确有证据的提交阶段。技术信息默认折叠，原错误与检查分项显示，原操作编号保留复制入口。详情以具名收起入口回到同一记录，不在首层增设业务取消按钮。取消在途、取消未确认与已取消各用稳定短文字表达；检查原取消仍未完成时提供明确的“继续取消”，已观察生效但原保存回执未知时另用非阻断短说明表达，已创建时显示真实结果及查看／停止准确新 Agent 的入口，确认保存的取消复用同一有限落定反馈并退场；保存待确认继续原位可读。消失或动画不代替取消回执。仅查看技术详情不触发检查、继续或取消。
- **窄面保留可用动作。** 采用轻边界、低对比状态标记、清晰字重与紧凑留白，沿现有主题 token、语义图标及共享控件，不套另一套面板皮肤。已确认创建的 Focus 卡片提示在行内动作末尾使用具名关闭图标。动作在窄卡片内有序换行，文字和命中区域保持可读、可点击；卡片与紧凑入口打开的详情都支持键盘展开、关闭和焦点返回。检查与取消等待只反馈本次动作，不抢焦点、遮住原工作面或禁用原 Agent；未知态保持静态，不循环扫光假装仍在执行。
- **原卡片内的轻量连续对象。** 反馈贴近准确操作，以中性薄表面、克制内轮廓和名称／状态／动作的清楚层级表达，不另包整卡强调色边框、重竖线、外晕、霓虹环、整面扫光或警戒纹理。原名称、正文、选择和可用动作保持稳定；状态色只辅助小图形与短文字，不替代原 Agent 活动态。Stop、Takeover、Fork 沿同一[动效 token](shared-rules.md#动效)和呈现 owner，不分别造另一套卡片。
- **提交、在途与落定分工。** 真实提交可有一次短促按下回应，准确在途才在原短状态文字／小标记内使用低对比的局部柔扫光，配「停止中」「接手中」「Fork 中」等稳定短状态，文字在整个周期中持续可读；不循环改变整卡表面，不用环绕位置、圈数、倒计时或假百分比表示进展。正文几何与状态图形可分别过渡，已确认事实立即可读，不等待过渡完成。多项并行各自可辨，不同步闪动或重排卡片。
- **收口只消费真实结果。** 原 owner 确认成功后，在同一位置用静态结果与一次有限落定反馈收敛；装饰结束不签业务完成，关闭动画也不使状态停在在途。卡片是否退场沿原行为合同，接手和 Fork 不借完成消掉来源 Agent；已有展开、选区与键盘阅读优先，不为默认收拢移走正在阅读的原操作。
- **未解决结果保原恢复。** 部分完成、失败、未确认与已退役分别使用静态、清楚的短状态及原核对／明确继续入口，保已知结果、准确对象与原操作。观察失败不改成业务失败或撤销已确认完成，显示方式、停动画与收起装饰不触发自动重试或替代请求；原动作资格只沿行为 owner。
- **详情与焦点连续。** 原 operation、来源／目标、准确回执和原因按需展开，主卡与紧凑入口共用同一阅读层次。开合几何与正文可读分开编排，关闭开始即不可聚焦或命中，焦点只在仍属于关闭内容时回原触发器；后来的主动焦点优先。关闭过渡、结果到达与某处装饰退出不能截断另一处正在展开的同一原操作。
- **动态服从可见性与原偏好。** 可见、准确在途与宿主已有的有效动效许可共同决定运动；减少动态或适用的显式关闭直接保同一静态信息与动作，隐藏／离屏停止额外工作，返回不重播过期提交或旧成功。Map 专属设置不因视觉复用暗中扩成 List 的全局配置。共享呈现不新建逐卡 timer、React 帧循环、全表测量或 Session 轮询；相关可见操作以外的留存增量不能放大逐帧成本。真实过渡、静态终态与动态成本分别取证，静态采图只证明对应帧。

## 启动与恢复的分量分开

已确认的终端前端非零退出沿同一 Region 全页失败构图，标题、后台状态、原身份保留与恢复动作形成清楚主次；原 Provider 已提供的启动／终端诊断在原服务窗首层有界显示一次，不要求先展开详情；长诊断可滚动、选择和完整读取，机器标识保留在按需详情，原始输出仍沿原入口。不能让裸露的故障终端加小横幅成为默认失败提醒。未知原生会话身份明确可读，不用“原会话可直接接回”代替未确认事实；正常与窄面继续保持原输入、查看输出与返回动作。

应用启动页保留已确认的构图，并加入鼠标交互；restore 面采用与启动页不同的简约风格，既不复制启动页，也不过于素淡。加载与恢复面的排版要舒展、有分量，减少不重要的冗余信息；进行中的可见活动与长等待说明必须清楚，不能让静态画面使用户难以判断仍在等待还是已失败。阶段、事实、信息资格与 owner 仅见交互 SSOT[《启动与 restoring 的不同重量》](../behavior/session-recovery.md#启动与-restoring-的不同重量)。

- 应用启动是一张完整品牌面：清晰构图、中性高光、设置页同一功能材质、Graphite / Mint 与精确文字比例形成现代高级感。启动图沿用已确认的主体与构图，提高源分辨率与 Retina 大窗清晰度；清晰度以相同显示倍率下宽窄、明暗 Retina 的实际呈现为准，保留构图、色彩、材质与前景可读性，像素尺寸或插值放大不等于新增细节。素材的生成与增强方式归[品牌素材清单](../../../packages/client-ui/brand/README.md)。允许鼠标引发轻微光照/景深变化，内容和控件不跟着移动；指针离开回归平稳，触摸无需 hover 才可读，不靠来回扫线、呼吸或自动循环放大图像制造“正在加载”。真实阶段文案负责说明进度，失败保留原因与入口。
- Region 恢复／停泊采用开放的左对齐阅读构图，充分使用面宽与上下留白；舞台随实际 Region 流动，宽面不把主状态、长摘录和诊断压进固定窄栏。主状态与工作回顾分别有清楚的空间预算，标题、短说明、活动信号和原动作先形成完整阅读起点，次级内容与它保持明显间距；正文行长仍有界，窄面沿原 spacing token 收紧内边距，不挤成悬浮的小图标卡或居中的微型栏目。沿用 `--fs-display` 与 `--fs-prose` 的标题／正文档，以空间、行长和对齐建立分量，不另起字号系统。允许低对比、局部静态光影与精细的行内状态 glyph，不能退化成纯平背景加几行孤立文字，也不使用横幅大图、品牌 hero、全屏扫线或厚重卡片；展开详情的材质与焦点反馈细微、稳定。
- 每张面只有一份清楚的主状态，原可用动作紧邻状态且先于 recap；去掉重复 eyebrow、孤立图标底座、泛化保留说明与空反馈块。标题和有信息量的短说明形成同一组，只有实际操作反馈占用空间。关键失败、未知和当前可用能力保持首层可读；完整身份与技术元数据进入原详情；首层原诊断不能因折叠而失去可见原因。普通退出与保留的合并资格只沿上述交互合同。
- 已有 Session 的 Connect 与 Restore 复用同一公共会话上下文层：准确会话、当前状态和原动作形成阅读起点，上次活动与带单位／范围的历史规模组成紧凑、可换行的次级摘要，recap 承接真实工作内容。时间、数量和内容有明确短标签，不堆成难读的灰字、重复技术行或三张独立指标卡；完整时间、来源和覆盖范围按需可核对。未知与读取失败沿事实轻量表达，缺内容不铺空白摘要盒，不以虚构数字增加完整感。正常、窄／短面都保原动作与正文可达，长摘录有界阅读，不能靠缩小文字或裁掉控件换取留白；事实资格和读取边界唯一见交互 SSOT[《Connecting 与 Terminal 恢复页的全页状态舞台》](../behavior/session-recovery.md#connecting-与-terminal-恢复页的全页状态舞台)。
- recap 以一条安静分隔和有呼吸的间距形成次级阅读层，不另套卡片或重复状态；来源简短可辨，完整来源可按需核对。其唯一内容与密度边界见[《Terminal resume 的 recap 密度》](terminal-reading.md#terminal-resume-的-recap-密度)。正常、窄／短、长 Prompt／摘录及真实失败／未知下，主状态和原动作先可见，长正文有界滚动且完整阅读／复制／诊断入口可达；短面不靠裁切控件维持留白。
- loading／recovering 使用一份持续、克制而可辨的活动信号，与稳定的当前阶段文字相邻；不能只有首次进入的短动画或看似忙碌的静态 glyph。动效只表达界面仍在等待，不证明 Runtime／Provider 已取得进展，不画虚构百分比、倒计时或不断变化的伪步骤。parked／failed 不显示忙碌动效；未知状态仍按真实可确认的等待或失败事实表达，不能由耗时或动画推断 Agent 健康、死亡或恢复成功。内容和控件不随装饰移动，不用全屏扫线、反复缩放文字或大面积呼吸制造活动感。长等待的事实说明与原恢复动作保持就地可读，语义归交互合同，不把用户留在无解释的无限循环里。app 的已有品牌面也采用精炼的状态／动作层次，保留图像与鼠标反馈的原边界；Region 的开放阅读构图不能靠缩小 app 大屏得到。
- 公共组件仍共享 token、阶段语义、活动信号与材质；应用启动、Session 连接、Terminal／Browser 恢复及共享大块数据加载均遵守同一层级和等待／停泊／失败区分，保留各消费者的原标题、真实内容及原动作。app 和 region 是明确不同构图，不能用大屏缩小冒充轻量恢复。减少动态时活动信号和交互位移静止，但阶段、等待说明与动作仍完整可读；隐藏窗口与 retained 隐藏／停泊面不运行循环动画，活动信号不驱动逐帧状态播报。鼠标效果仅局限 app 启动面，不给每个 Region 增加全局监听、Runtime 轮询或热路径成本。

## 从消息继续到新会话

消息上的继续动作保持低调，明确标为“可见对话上下文续聊”，不冒充 Provider 原生 fork；具体行为、上下文范围与新会话归属只见[从所选消息继续](../behavior/session-recovery.md#从所选消息继续到新会话)。图片缩略图、引用与失败说明只见[对话资源呈现](conversation-mode.md#对话贴图缩略图与灯箱)。
