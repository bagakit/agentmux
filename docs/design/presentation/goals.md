## Goals 的清单、看板与详情

### Goals 的列表与看板

Goals 属于 Work；导航分组只见[《左下角导航、Space 与 Goals》](../behavior/spaces-and-layout.md#左下角导航space-与-goals)，Goals 与 Focus、执行工作面的分工见[《Goals、Focus 与执行工作面》](../behavior/goals.md#goalsfocus-与执行工作面)。Goals 的清单与看板是同一目标集合的投影，Board 是历史或实现用语，不保另一套 Agents／Session／Board 主导航或 Branch × 状态矩阵。

列表、看板和详情的当前视觉规则唯一见[《Goals 的目标正文与对齐密度》](#goals-的目标正文与对齐密度)。卡片先读目标标题、当前结论和目标 Project，稳定 Goal／Demand ID、工作状态、Attempt／Agent 活动及路由依据居次层或按需展开；不把卡片堆成信息表。选中用完整 Surface 与非颜色信号，状态色只补语义，动态仅回应真实事实变化与明确阅读操作，不用发光装饰。搜索、筛选和唯一创建入口共用低高度工具带；来源与依据只在真实存在时按需阅读。

总览卡片使用稳定标题、紧凑当前结论与低占用事实页脚；执行与巡查的完整诊断、准确技术来源和次级操作按需展开，展开只改变阅读，不打开另一个Goal或发送输入。关键未知、需处理数量及通往原恢复动作的具名入口在折叠时仍可辨。看板优先将横向空间用于非空状态列，空状态集中为紧凑的零计数摘要，完整状态筛选仍可达；长诊断不把单张卡默认撑成整列面板。

总览与详情的动效延续同一阅读关系：摘要与属性披露沿内容的自然高度平滑展开、收起，并配合克制的淡入与箭头转动；阅读导航的选中标识连续跟随实际段落，列表与看板切换只在内容区做轻量过渡。动效不替换原编辑实例，不等待动画结束才允许原操作，也不改变状态、完成、权限或恢复事实。快速反向操作应从当前画面连续收敛；减少动态效果时直接呈现最终状态，键盘焦点、风险摘要与恢复入口始终准确可达。

Goals 的概况 banner 与常用操作合为同一个起始区域：概况、Review 与 New Goal 在主行，原常用操作在下方紧凑排列，沿同一底色和留白阅读，不再叠一个独立大标题或重复装饰。完整请求、准确目标与原设置／收起入口仍可读可达；详情打开时保留原紧凑返回与失败反馈；窄窗可收起普通起始内容，但准备中、保存中、失败或未确认的原服务窗及返回入口仍须完整可见，不能随共同祖先隐藏或被起始区高度限制裁掉。窄窗自然换行且不挤走目标列表。

目标卡片以共用头像组呈现当前 Supervisor 与负责人，最多先显示三个，超出部分用准确的 `+N`，保留可读成员与角色说明。相同的准确身份只计一次，跨来源同名或同 ID 不合并；未确认的身份使用明确的未知呈现，不借头像暗示正在工作。历史关联会话不冒充当前团队，原执行与责任告警仍独立表达。头像组使用原头像组件和有界的重叠间距，成员变化可短暂淡入，不持续跳动或为每卡拉取独立 Runtime。 Agents、各头像与 `+N` 都有可辨的 hover、按下与键盘焦点；团队菜单保完整名称、角色和来源，准确头像复用原 Agent 详情浮层，不以浏览器 title 代替。悬停不抢焦点，点击进入阅读，退出回到原触发点；浮层沿共用动效与减少动态偏好，不另造一套弹层。

正常宽度的同屏详情使用连续侧栏，不用弹窗遮住目标列表；没有选中 Goal 时不画空详情栏或占位边框，不使用“从右到左”的方向性动画；窄窗沿可返回的详情面保正文可读，不强留三个不可读窄列。详情、文件、变更、Activity、决策与讨论使用同一容器及原 Tab 语言，精确导航到原工作面才改变空间选择。Mote 快捷面优先对话连续性，执行观察面优先真实状态、Attempt 与下一步；共享身份、状态和项目语汇，不复制同一消息。

Activity 的决策摘要先读原决定，问题、依据与作者在该行轻量展开，使用现有正文、次级标签和分隔语汇；长内容可换行、选择和复制，宽窄与两种主题保持可读，不叠新模态或另造路由图。原数据及阅读身份边界见[行为合同](../behavior/goals.md#goalsfocus-与执行工作面)。

### 活跃 Ticket

Goals 的 **Tickets** 入口沿同一工具带搜索 Ticket 和原 Goal，可按 Project 缩小范围。列表按当前推进状态分组，每行先显示 Ticket 标题，再给出原 Goal 与已知 Project。选中行打开同一 Ticket 的详情，交付、执行和历史沿原入口阅读。读取失败在原列表内说明并可重试，保留最近一次确认的列表。工作范围和状态含义见 [活跃任务与认领](../behavior/goal-plans-and-tickets.md#活跃任务与认领)。

### Goal 的共识身份与局部反馈

Goal 的图形表达双方围绕同一方向形成目标约定，采用对话框中的旗帜：对话框表达讨论，旗帜表达共同约定的方向；小尺寸保持清晰完整，不以靶心、完成勾或抽象握合折线代替共识含义。导航、列表、关联记录与历史默认静止；实际选中导航实例可沿[共享选择反馈](shared-rules.md#ui-现代化的独立评估边界)做短动作，和下述业务确认反馈分开。图形本身不宣称已经确认或工作完成。

原确认面可以在准确所见 revision 的确认回执后，让内部旗面沿旗杆轻轻展开一次，对话框与旗杆固定，随后回完整静止态。只消费原 Goal owner 的本次确认结果，确认与结果验收仍按[行为合同](../behavior/goals.md#goals-的-grill-与-grounding)分别表达；发送请求、Agent 回复、目标 Done、读回旧确认或重新挂载不触发成功反馈。保原失败说明与当前稿，不增加业务状态或自动动作。共享作者、用户资产和减少动态规则沿[语义图标合同](shared-rules.md#语义图标密度与性能)。

### 当前结论与明确动作

「确认目标并让该 Agent 继续」在按钮上显示准确接收 Agent 的头像，悬停可读名称、角色和当前状态。操作只从原按钮触发。直达计划或 Ticket 时，若当前需要用户确认，固定工具条可引到同一份目标标准和确认入口。已有计划时，单次执行放入次级入口。当前 Ticket 和 Goal 验收使用各自的实际回执，已结束的 Ticket 仍可在历史中查看。

同一 Goal 的当前阅读重点由原下一步事实统一决定，子区块消费同一重点建立主次，次要操作继续可达。当前版本的成功标准在当前阅读面只呈现一份，逐项连接对应检查与证据；未确认目标的标准仍先于确认动作，旧报告、额外报告项、缺项和未知分别完整保留。正常尚未提交报告以紧凑状态与原核查入口表达，已标 Done 却无报告的待核验事实仍突出。空计划保留真实 Goal 起点及原规划动作，用轻量上下文承接；真实 DAG、依赖、评审与证据不因空态收敛而缩水。展开、确认和切换后保留当前阅读、焦点与草稿，复用既有自然展开和减少动态规则。

清单优先呈现当前结果结论，历史开始或委派提示不盖住已接受的当前成果。Done 但尚未验收的目标继续可扫描，明确所缺核验；已接受并结束的目标进入历史后，原详情仍呈现结果和结束状态，不突然清空。

详情的唯一主入口沿[当前阶段的呈现规则](#goals-的目标正文与对齐密度)，原讨论、执行与认可资格归[行为 owner](../behavior/goals.md#goals-的-grill-与-grounding)；差距保持明确。已确认标准可收起阅读，确认前标准和未决问题保持展开。持续跟进、讨论变更和结果核查使用次级强调，原在途及未知操作的检查优先于新动作。

证据同时呈现可辨文件名及来源 Host／Workspace，完整资源和报告版本按需查看；原文引用与可打开的准确文件来源有清楚区别。版本变化就近说明并提供明确查看当前文件的动作，未绑定本地引用保持可读可复制。长路径、长 Agent 名、窄窗与明暗主题可换行，不靠 tooltip 才知道接收者或重要缺口。

讨论、核查和监督入口将实际接收者放在动作附近；有原绑定时显示准确 Agent 身份，没有或待确认时说清当前事实。用途与接收者沿[行为 owner](../behavior/goals.md#目标确认与结果接受)，不新增身份 Store、状态色或第二套控制面。

## Goal 详情中的 Session Region 投影

Goal 详情的观察投影复用原 Region、arrangement 与身份组件。清单卡片只显示可扫描的 Agent 拓扑摘要；准确 Project／资源 Workspace、Topic／Branch、Tab／Region 与 Session 层级在详情内可展开，完整显示路径不由当前焦点推断；详情中的“进入原工作面”与观察内容有独立命中区，不覆盖正文。多位置绑定沿原空间事实表达，不把一个 Session 强制等同唯一 Region。

观察密度保真实输出、状态、最近活动与进度，输入工具、生命周期操作与主动尺寸控制均由[行为 owner](../behavior/goal-execution-and-supervision.md#goal-详情中的-session-观察投影)裁决；窄面不把多个 Region 压成细条，可用原排列／披露入口阅读。零 Session 使用一句就地说明；工作拓扑与排列按钮只在有可观察的执行内容时出现。详情返回保原选择与位置，未知与尚未恢复的事实占用与已知事实相同的稳定槽位并附服务说明，不用空白或跳动布局掩盖缺口，也不清空正文。

## Goals 工作区的 Surface

顶部 Review、New Goal 和常用操作均在实际内容命中区内，保留鼠标 hover、按下和键盘焦点；窗口拖动区域及原生嵌入视图不能覆盖这些可见动作。不能用正常业务按钮置灰或吞事件掩盖宿主命中问题。

详情的首屏层级、计划工作区和窄窗顺序见[Goal 详情工作台](#goal-详情工作台)。窄窗中的动作自然换行，保留原字号。原执行按准确记录渐进阅读，当前关键未知、待处理数量与原恢复入口仍明确可达；没有当前动作时不铺空工作块。Team 复用原 Agent 卡，属性继续次层展开。

关系与可编辑属性使用稳定标题，完整字段和历史技术依据按需披露。组件可借鉴既有参考库的摘要、展开和反馈节奏，状态、完成、权限与恢复仍只消费本产品原业务owner。

工具栏用一条紧凑路径显示当前阅读位置。点击当前位置展开文内目录，包含计划、目标正文以及已有的活动记录；手动滚动时同步当前位置。目录从触发点短距离展开，底板从第一帧就遮住背后的正文。选择章节后焦点落到原文，减少动态效果时直接就位。窄面工具栏单独开合 Supervisor，返回保留原阅读位置。Goal 的复制入口归入目标操作，计划链接留在计划旁。跳转保留编辑器、节点选择和草稿。计划位置真实显露原图并保留返回原正文的入口，横向空间优先让真实依赖与阅读内容可用，不用空白画布或装饰状态填宽。目标确认和结果接受前仍完整呈现原标准、证据与差距。

工作面、目标卡与观察 Region 共享[原 Surface token](shared-rules.md#主题与样式-ssot-规范)：工作底、卡片／chrome 与 hover／选中各有主次。区域以留白和 hairline 分隔，边框只表达真实列间、Tab／Region 或输入边界。目标详情是一张连续正文面，不连套“详情卡 → 执行卡 → terminal 卡”；新增边界、阴影或颜色须表达真实交互事实。

## Goal 与 Demand 的命名和投影

公开单项称 Goal，底层 Demand 领域身份、文件和包沿原 owner 保存；执行 Task／Attempt 不与目标同义。GUI 名称、公开 RPC／CLI 和独立文件工具的准确边界只见[《公开名称与接口来源》](../behavior/goals.md#公开名称与接口来源)，本页不要求所有 parser、DOM 或领域类型机械改名。

Goals 与 Mote 消费同一[Demand 文件事实](../behavior/goals.md#demand-文件事实与独立包)。卡片不复制 Session 状态机，Agent 行不冒充目标。CLI／API、文件读取或 Runtime 查询失败沿原服务窗说明，保已读目标、选择、草稿与关联，不用空列表覆盖工作面。关联 Session 以稳定身份和 Agent／Project 摘要可达，添加、移除与进入原工作面各有明确动作；删除只在准确目标的危险菜单中确认。

## Goal 专属 PMO Tab 的表面

New Goal 与已有目标讨论的实体关系和恢复资格唯一见[《Demand 的专属 PMO Tab》](../behavior/goal-execution-and-supervision.md#goal-的专属-pmo-tab)。目标卡保一个紧凑讨论入口，详情在 Goal overview 标题右侧放同一讨论入口，同族讨论插画与文字置于同一低高度控件。造型按实际尺寸保人物辨识，焦点与按下沿共享按钮，原接收者仍由真实名称与入口文字交代。打开后显示主 Mote 中该 Goal 的准确专属 Tab；原 Mote 名／头像、目标标题和执行者各有层级，不能把 Tab 画成新 Mote，也不能暗中合并或更换原 Tab／Session 映射。PMO／主对话的复用关系遵循上述行为合同。当前下一步沿下节呈现，不重复整段对话。

Core 空间 owner 持久化准确 Tab／Region、拓扑与绑定，Client 只呈现原目标。读取或恢复未知时保原 Goal／Tab／Region／Session 与服务窗，不自行新建替代上下文；原 Tab 已权威确认关闭后的显式新讨论按行为 owner 处理。等待目标 Agent 挂载时沿同一 Tab 的真实状态，不先闪回别的目标或旧 PMO。

常用探索、New Goal 与已有 Goal 的讨论都在原主 Mote 中打开，呈现同一归属：主 Mote 的既有名称／头像与本次 Goal 或探索正文各有清楚角色，不新增并列身份卡或重复人格说明；实际承接的主 bot 以真实可读名称和身份与正文相邻，不能只靠 Mote 图标掩盖换了执行者。已知适用范围冲突、准备／投递未知和真实保留的请求用原低占用服务窗说明，仍保完整正文与健康输入；不新增流程卡、系统字段墙或重复确认入口。执行者选择与协调行为只见交互合同[《显式新建与专属讨论》](../behavior/goals.md#显式新建与专属讨论)，主 Mote 的外观沿[《Mote 头像与主 Mote》](../behavior/motes-and-coordination.md#mote-头像与主-mote)。

## Goals 的目标正文与对齐密度

Goals 是人每天打开、三秒内读出「什么在等我、哪些由 Agent 推进、点哪里推进」的目标工作面，紧凑可连续阅读，并以低高度品牌页头建立主视觉；行为与事实边界统一见交互 SSOT[《Goals 的 Grill 与 Grounding》](../behavior/goals.md#goals-的-grill-与-grounding)。参考 Multica 的正文/讨论优先与渐进属性，不复制其 Web chrome 或复杂字段面。

整体采用安静、克制的现代工作界面：用清楚的字体层级、连续网格与适度留白引导阅读，中性色承载普通身份、历史与辅助材料，警示色只突出实际需要处理的事实；减少硬边框、套层卡片、重复状态和并列按钮。当前原操作及其真正下一步先读，执行图仍有完整构图；技术身份和来源渐进读取，重要未知、差距与恢复动作持续可见。编辑状态预留稳定预算，保存回执到达不移动正在操作的按钮；阅读密度不以点击目标跳动换取。

当前事实与动作使用普通语言，行为归上述交互章节。阅读层级先用目标、成功标准、待决定事项和结果；方法名、版本号与系统身份降为按需解释，不靠增加教程、步骤器或状态卡补救理解。

当前阶段的动作资格归交互 SSOT。每阶段唯一主入口必须能在当前正文或既有工具带直接找到；已确认且尚无结果时，强调原讨论入口，并以短说明指向原讨论/关联工作面继续推进，把发送结果核验请求留作次级；报告可核验时突出「接受并结束目标」，「只接受结果」为相邻次级选择。只换名称、同时保留多枚同等强调按钮或只说可以继续而不给入口，都不满足可理解性。

起步 CTA 的点击与探索请求行为唯一归交互 SSOT。紧凑起步区让零门槛探索先可发现，有可信项目时再呈现带项目名的条件入口；既有 New Goal 保留独立的次级创建语义。完整请求句子直接可读，长句在窄窗可换行且仍可操作，不把标签截短后藏另一份首发消息。等待、未知与原地恢复沿既有服务窗，不以大型教程、三张阶段卡、无依据计数或多个同等强调按钮替代起手。入口范围归行为 owner，精确陈列须通过实际图审。

常用请求、项目条件、轻量对话与角色入口范围唯一见交互 SSOT[《Goals 的 Grill 与 Grounding》](../behavior/goals.md#goals-的-grill-与-grounding)。首屏沿既有紧凑起步区与连续清单组织，不出现角色选择墙或角色资料表；项目名与所作用的条件入口相邻可读，不能让人猜本次建议针对哪个项目。不将已被替代的角色候选混入入口。

主 bot 待确认与未分配 Project 的行为边界见同一交互章节。主 Mote 的未知请求说明在其 launcher 内就地可读，原请求、未发送事实与明确选择动作保持清楚层级；不以另一 Agent 的绿色默认选中态代替原身份。正常未分配项目不铺大号恢复告示，已有关联的真实失败仍可读。

主 Mote 卡片与上述 launcher 说明保持同一事实，保留引用但状态未知的读法见交互章节；不能在同一个浮窗里同时宣称原 Agent 待确认和「No Agent yet」。

起步区的视觉完成度以当前[《Settings 控制工作面》](settings-and-observation.md#settings-控制工作面)为本产品对照：完整请求是主要阅读对象，准确项目名是相邻次层，进入对话的动作明确可辨；用稳定阅读宽度、字重、留白、轻分隔和统一 Surface 边界形成层次。宽窗不能把短请求拉成横跨整页的空槽，窄窗不能靠缩字、截句或偶然挤排维持布局，也不能留下孤立的句尾或让项目说明挤压请求。起步区与目标清单的低高度管理带分工清楚，保留连续阅读空间。

起步请求形成一个克制的功能组，各动作的命中面、hover、按下与键盘焦点清楚；材质沿既有石墨、薄高光和中性边界，不为每个请求另叠玻璃、装饰渐变、阶段卡或重复图标。完整句子可用语义重点建立字重层次，不能另造短标签替代所见请求。准备中保持原句和作用项目可读，同时有真实文字反馈，不能只把全组变灰或把准备称为已送达；失败与未知的服务窗就地、持续且不遮挡原内容。两种主题以及已知减少动态、透明度或增强对比偏好下仍清楚可用，装饰不订阅无关 Session／Terminal 热路径。三句范围、点击、状态事实与恢复行为只引用 interaction[《Goals 的 Grill 与 Grounding》](../behavior/goals.md#goals-的-grill-与-grounding)。看图评审覆盖宽窄初始页、真实项目、操作状态与清单同框的候选，方法见[独立 Agent 看图评审](../../guides/agent-visual-e2e-review.md)；旧入口曾通过的图片不能代签起步区的品质改进。

常用操作支持自定义与持续收敛，正文与行为唯一归交互 SSOT[《Goals 的 Grill 与 Grounding》](../behavior/goals.md#goals-的-grill-与-grounding)。低高度图文起点以完整请求为主，语义插画辅助用途辨认，可信项目与适用 Agent 是相邻次层，常用操作的整理与扩展入口集中到 Settings → Goals，正文与原 Prompts 库保持同一实体；Goals 使用页只留使用与显隐控制，配置导航明确到 Goals 分区。参考 Settings 的功能分组和图文节奏；品牌只落在页头与起步区这一处，不在列表与详情中重复标识；正文阅读上限不固定整页扫描区为居中窄栏，装饰不吞掉连续目标列表，图形失效仍保文字与动作可用。图文品质按同一看图评审判断，旧控件图片、换边框或重复图标不能代签。

常用操作的配置入口沿 Settings 导航进入 Goals 分区，正文编辑沿同一原指令库，Goals 使用面不展开配置编辑；进入对话的箭头跟随正文首行，不在正文与项目元信息之间漂移。正常首批操作自然完整呈现；真实长正文或更多操作展开时才共享有界阅读预算，全文仍可键盘滚读且滚动不误发；Settings 中的窄管理使用库与编辑两种状态，返回同一稳定引用，而非把整库堆在编辑正文之前。Goals 中的正常执行与 Settings 中的配置、正文编辑各有清楚状态：新增以一句正文为主，修改同一指令及移出引用有不同语义；完整请求在宽窄窗口发前均可读取，不以截句、短名称或 tooltip 替代。更多操作采用有界渐进展开，展开、收起、Settings 管理返回与排序移除的焦点可追踪；数量增加仍保留 Goals 连续阅读空间。看图评审覆盖两主题、窄窗长正文／长项目名和真实操作状态的整页候选，旧图片、token 一致或仅采图成功不能替代判断；图形不增加无关 Session/Terminal 热路径工作。

常用操作的后续 Mote 建立项目、需求绑定与执行指派行为唯一归 interaction[《Goals 的 Grill 与 Grounding》](../behavior/goals.md#goals-的-grill-与-grounding)；起步图文区不把这些职责画成必经阶段卡、角色入口或额外提交，原可见完整请求和连续目标阅读保持。

常用 CTA 的插画沿[共同美术语言](brand-identity.md#共同美术语言)，由同族 3D 角色姿态、局部动作或抽象场景辅助辨认了解用户并给建议、把想法推进成项目、结合当前／最近项目建议下一步；造型、非写实光影与铬金属材质和 Mote 角色系统协调。静态 CTA 可使用同一场景的预渲染素材，实际小槽位仍看清动作与形体。插画表达请求用途，不充当第二个 Mote 头像；有可信项目时才呈现项目下一步入口的行为仍归交互 owner。自定义指令使用中性构图，完整正文说明用途。插画贴近原完整请求，正文仍是主层，低高度起步区与连续目标列表保持阅读空间，原管理、更多、项目与 Agent 事实完整；页头与起步区可以合成一条低高度品牌起点（同族 3D 角色、标题、真实摘要与 New Goal），不在其他位置另加宣传带、重复图标或独立点击目标。需求详情的聊天澄清入口可有同族的小型讨论意象，与原动作和正文协调；发送澄清、打开已有讨论与人的确认仍由原标签和相邻正文区分，插画不暗示目标已确认或结果已接受，不扩大为阶段插画、空报告或第二层身份卡。

### 整页阅读与视觉验收

目标与行为合同唯一归[《Goals 的 Grill 与 Grounding》](../behavior/goals.md#goals-的-grill-与-grounding)。初始、清单和详情共享可辨的阅读边线、文字层次和控件语言；参考 Settings 的明确功能分组、真实当前值、紧凑行与可辨入口，让人沿完整页面读懂目标和结果。常用操作的品牌起点与正在阅读的目标形成明确主次；详情保留可辨的返回入口，宽窄均沿同一阅读节奏。目标对齐与结果核验各由其真实正文标题、当前事实和相邻动作辨认，成功标准、当前结果、证据及重要差距保持连续对照。清单结论的形态表达当前事实，打开目标的命中与方向可辨，讨论/请求/认可的操作反馈各有落点。属性与技术身份继续渐进展开，标题、正文、控件、服务窗及完整焦点在两主题宽窄下均可读。整页评分须依据可定位的当前候选观察；改进须在真实初始页、混合事实清单及关键目标/结果详情上独立实际看图复核，保留具体修正和原图身份。

### 常用操作的空间与连续列表

常用区优先减少无意义占位，相邻列表与详情只调整相关对齐／边距。行为保留边界只归 interaction[《Goals 的 Grill 与 Grounding》](../behavior/goals.md#goals-的-grill-与-grounding)。常用操作是低高度功能起点：各常见 CTA 以完整请求为主，协调且克制的语义插画辅助辨认，自定义指令保持中性，品牌图只出现在页头品牌起点和空态，不在常用区标题里再贴一次，不铺满整屏宣传画面，重复的起步 slogan 与空态说明合并。宽窗利用可用宽度让完整请求并列，窄窗按自然阅读顺序换行；正常首批真实请求无需滚过装饰或嵌套滚区才能看全，也不靠默认收起功能冒充省高。更多／长内容才按真实阅读需要有界展开。配置导航、收起和未保存／未知反馈仍有清楚落点，不能靠缩字、截原句、隐藏真实项目或改正文 owner 换密度。

清单不再固定在居中的窄栏内，新增宽度应增加可扫描的目标。宽窗清单以标题和相邻 Project／执行事实为主格，真实当前结论为对齐的次格；较窄导航与窄窗自然回到两行，不强制每条目标永远堆成三层，也不把结论变成行内执行按钮。详情页头保留同组的队列位置和下一条入口。返回总览时恢复原选中位置与 Board 或 List 偏好。正文从分界附近与原工具带同边线起读；详情及执行画布使用可用宽度，长篇正文单独保合理阅读上限，不用固定整张详情宽度留下大块闲置；Team/属性与主工作簇相邻并有共同网格；正文行宽限制不得把剩余宽度变成两栏之间的空白断带。标题、标准、结果、证据、重要差距和未知保留原字号与完整阅读，不用默认折叠关键信息或缩小全局文字冒充紧凑。空目标用 Goals 概念插画配一句指向上方起步入口与 New Goal 的事实，不重复品牌口号或铺空占位卡；真实零匹配仍保完整原因与原地恢复动作。看图评审覆盖两主题宽窄下的初始页、混合清单、详情和原管理／草稿返回的真实 Renderer 完整图；几何测量只证明空间反例已关闭，不能替代品位判断。

- 首屏顶部是一条低高度页头：页面标题与 Goal 标识、由同一分组真实计数组成的一行摘要（如「2 need you · 1 with agents」；无待人处理时明说），以及全局巡查与唯一实心主按钮 New Goal。计数只来自下述分组，不做统计卡、不铺 hero；打开详情时页头收紧为标题与动作一行、摘要换到下一行。
- 首屏保持紧凑起步入口与连续列表；搜索、筛选和视图管理使用一条低高度工具带，不再让七状态、四个宽选择框、重复 Branch Board 导航与空列占满画面。唯一 New Goal 是独立创建入口，不与探索发起混称；筛选收为一个可展开入口，已生效条件才显示紧凑可清除标签。列表/看板切换使用一个克制的图标或 segmented 控件；全局工作面标题不在多个 chrome 重复。工具带保持单行、单一网格：路由队列是可切换的同级筛选态，不额外制造一块高大的独立卡片；筛选结果、列计数和空状态在同一视觉节奏中，批量动作只在确有选中项时出现；侧栏不可见时不留空 chrome，侧栏开关与 Goals 动作各有独立命中区。
- 默认列表按「轮到谁」分组。各组成员、当前下一步文案与历史收纳的判定只见交互合同[《清单、详情与当前下一步》](../behavior/goals.md#清单详情与当前下一步)；本页只定义呈现：空组不出现，筛选、搜索和看板不另存数据。每组标题带阶段字形和计数，每行带同一阶段字形；各阶段字形彼此不同，颜色只作补充，「需要你」与「需要处理」的下一步用对应语义色强调。详情阶段行右侧以「n of m」显示本组位置，并在后面还有目标时给一个次级「Next」；换组提示是一次约 900ms 的薄荷色细环，不循环、不发光。正常路径的说明只讲下一步与真实后果（如「Accept and finish also closes the goal.」），不写「不会做什么」的安抚句；失败、未知、旧报告、回执不明与不可撤销操作的说明保持完整。
- 关联 Session 的普通状态只描述关联对象，不与本 Goal 的当前推进结论混排；清单可给准确关联人数与未确认提示，完整 Agent 状态按需查看。已有该 Goal 准确执行、报告与关键未知仍就近表达。
- 列表与看板沿同一顺序阅读：阶段标记与标题同排，标题旁或下一行给出当前结论，计划进度、Project 与团队在次行各呈现一次。普通历史关联在详情读取，关系未知与需要处理的执行观察仍在条目上可见。长标题换行，整行命中与团队入口互不争抢；待澄清、待决定、待确认、目标已确认、待查看结果或已接受以一条普通短文案表达，未知明确可读。工作状态不与这条结论并列冒充同一种进展；在看板、筛选与属性中保留明确入口。整行点击表示打开目标，当前结论不伪装成直接执行动作；不把 PMO、Grill、Grounding、Open Session 排成一串 CTA。选中使用整行中性 Surface、字重或可辨焦点，不能只靠单边色条。没有 Goal 时用 Goals 概念插画配一句指向起步入口与 New Goal 的可操作空态，不重复品牌口号；同一 Goal 的执行缺席只在详情中说明，不逐行重复；已完成/取消的历史按需展开。
- 可选看板采用单条横向轨道，列在同一水平阅读顺序中，窄窗水平滚动；不允许列换行成上下矩阵。显式筛选某一工作状态时只呈现该状态列，让匹配目标直接可读；清除筛选后恢复原列序。列宽应保证真实标题可读，空列只保留列头、轻量空态和必要命中，不制造高大的 Nothing here 区域。默认不为完成/取消保留整列空白。
- 选中 Goal 后的正文、分工与 Supervisor 沿[详情工作台](#goal-详情工作台)组织。
- 成功标准与结果采用对齐的短行/正文块：先读标准，再读结果结论和证据入口；met/gap/unknown 同时有文字或字形，颜色仅作补充。证据只显示可辨名称与定位入口，完整路径按需读取，长内容可展开；没有证据时显示缺少依据。服务窗紧邻相关失败步骤，以低占用、持续可见的说明和恢复动作表达，不覆盖正文与健康输入。
- 认可回执不明的行为归交互 SSOT《认可回执不明时先读当前事实》。该服务窗只突出一个读取当前提案的恢复动作；清单行的唯一下一步与详情恢复入口使用同一文案，不再添加一枚行内恢复按钮。正常确认/接受与重试不堆成竞争按钮，其他阶段入口收为次级而仍可达。读回失败的原因和保留内容就地可读，不制造遮罩、错误状态卡或让人选择三条相冲突的路径。
- 属性是一组紧凑行内项（行内 picker／紧凑输入）和命名明确的「更多属性」展开面，保留已有字段编辑能力；标签、日期和批次放在「更多属性」，负责人和相关会话只在侧栏的负责人区编辑，不重复放进属性表单。空值不画大输入槽，不为默认 Normal、Global 或 0 Sessions 重复制造徽章；窄窗允许属性换行，控件保持可读标签和键盘焦点。执行上下文与活动按需读取，当前相关 Session 可直接进入原工作面，不默认把全部 Tab/Region 树摊满详情首屏。活动与决策按时间线分组并可展开，历史记录可折叠。删除、取消、停止和重试使用统一的危险／次级动作语言，不把运行状态画成第二套卡片。
- 稳定 Goal／Demand ID、优先级、标签、日期、子目标和执行摘要按需可达；超长字段可省略，完整值经 tooltip 与无障碍名称取得。接收者、重要差距与未知不在此列，仍按前述规则直接可读。
- New Goal 不再出现事前意图表单，点击后真实 Goal 与同目标专属讨论可辨；创建与恢复行为唯一归交互 SSOT。入口以低占用的短说明让人提前知道会创建待定义目标并打开专属讨论，不把创建讨论表述成开始执行。细虚线表达该目标尚待定义，来自真实目标提案缺席事实，不能靠标题词或新增影子状态判断；已有意图、结果材料及恢复事实仍完整可读，目标提案出现后回到普通边界。必要的 Project 上下文轻量可见，不把草稿画成高大的空占位卡或默认填满标准。正文、控件使用现有 Surface、文字与焦点 token；hairline 只分割真实区域，hover/focus 才显编辑边界。选中 Goal 时进入专注详情，返回清单可回读原筛选和布局。新建后的完整宽窄工作面同样按看图评审验收，修正后复拍至明确可交付。打开后的讨论表面见[《Demand 专属 PMO Tab 的表面》](#goal-专属-pmo-tab-的表面)。

看板让人沿目标的当前处理环节读到下一步。流程图示从现有工作分组读取计数，点选或键盘激活可以定位对应目标，筛选生效与清除有可见反馈；观察未知、需要处理等情况保持独立可辨。列标题明确工作状态，利用工作面宽度，空列入口轻量呈现。卡片保留标题、当前结论、真实分工或待确认关系，变化只做短促反馈，减少动态效果时保留静态选中。

## Goal 详情工作台

详情正文按推进计划、目标、执行记录、活动的顺序阅读。目标说明、标准和验收在同一区连续呈现，目录上共享一个入口。工作台服务于[人和 Agent 共同使用的 Goal](../behavior/goals.md)。页头概括要达成的结果与当前结论，原确认回执的异常及恢复紧随页头，标准和报告留在原阅读区。计划区呈现任务之间的关系和分工。页顶的当前位置菜单可直接进入各已出现的分区，选择后把焦点交给对应分区。进入一项任务后，就地对照该项的标准、交付和证据。Supervisor 栏说明当前由谁协调、有什么待办；执行时间轴回答工作何时发生，协调记录回答谁在何时作了什么决定。正文标题和内容沿同一左边线，区与区用间距和标题层级分组。图与时间轴共用一块工作区底色，辅助栏以轻底色区分。正文区不叠全宽边线，图标用于状态、导航、展开和无标签控件。动作靠近所作用的对象。

可编辑标题与真实当前结论建立阅读起点，工作状态、Project 等元信息合为紧凑一行。当前阶段只突出一个主动作，确认与接受贴近所作用的正文；未知、差距和旧结果保持可读。意图以渲染后的 Markdown 阅读，显式编辑进入原文并保留未提交的草稿。详情首屏从推进区起读。页头并排呈现标题、当前结论、已确证的待评审数与计划进度，并以一个「查看交付」进入原报告。推进区先铺开[计划图](#goal-计划图)，每个工作节点就地显示分工。已有多个任务时从计划标题栏打开分工索引，索引在画布前展开；选中节点后就地读该任务的正文。未拆分时从唯一节点读取分工。窄面复用有依赖说明的纵向节点列表。图旁的交接摘要显示当前工作或选中原尝试的双方与交接方向。准备和派发关联从任务负责人指向执行者，执行者提交回报时方向反转。按原记录确定双方及角色，缺少交接记录时省去摘要。

单节点且尚无排期或尝试时，首屏以紧凑路径呈现工作节点，时间轴在一行内说明记录缺席。原 Goal 正文紧随计划，已有的范围与标准可直接用来整理提案。已标完成却缺报告时，标题旁同时交代完成标记与核验缺口；有可读报告才提供读取报告的入口，下一步按原提案与确认状态给出。

当前结论带有原工作时，就近提供直接读取该记录的次级入口。记录所在的操作区继续持有主动作。分工只显示用于扫读的任务和执行者，进入节点可读执行位置与原证据。协调时间线优先显示作者名字，原身份从该记录读取。次层执行历史收起时呈现任务与可证实的结论，多个记录时才汇总数量。刷新随展开的记录呈现，读取异常时紧贴异常提供同一重读入口。另起一次任务是独立动作，保留明确的执行者选择。展开一次执行时先读按 Markdown 排版的原请求，正文有稳定行宽，用户可切换到逐字原文或同次执行的技术详情。打开记录即可看到原异常与恢复动作。

计划图沿真实依赖排列并行分支。指向或键盘聚焦任务时就地显出它的依赖与后续，选中任务后可继续对照其路径。路径使用对比与短过渡；静止的任务不产生运行暗示。减少动态效果时仍保留完整关系和选中信号。

Start 和 Finish 在图的两端用比工作节点更轻的标记，未拆分的 Goal 也看到完整路径。结束标记读原结论，等待时保留中性形态。窄面在纵向图中保留首尾和真实依赖。

「执行时间轴」紧接工作台下方，有排期、执行或多项任务时显示任务行和时间区。同一时间坐标上，排期用虚线轮廓，已证实的执行区间用填色横管，单次事件用带时间提示的点。横管按原时间坐标取宽，空间足够时条内直读已观测时长。短条保持原宽，在横管或行标题悬停可查看时长及起止，键盘聚焦该行可读同一时长。单项原回执用紧凑纵向事件列，发生时间与事件对齐，连线只连接同组已记录事件。尚无时间资料的单节点使用一行摘要，其他任务保留可定位的轨道，窄面可在时间图区横向滚读。分工、DAG、交付和执行时间轴共享选中位置。点击右侧的准确协调记录可定位同次尝试，返回时焦点回到原入口。

已有整体验收报告时，先读当前状态、结论预览、合计和当前动作。长报告和逐项检查经「查看标准和证据」进入。每项先看结论与说明，证据在该项下展开；文件路径不铺在首屏。目标定义、等待确认、接受结果和旧版本仍使用对应原事实与动作。

宽屏共用一整行目标页头，计划图与 Supervisor 栏从下一行的同一高度起读。Supervisor 栏先读身份、指派或更换、当前待办及巡查准备、回执与恢复，接着处理编排请求、打开原会话或设置持续推进，按需读取原来源及协调时间线。计划图保留通往右栏编排的导航；无记录时不铺历史空块。记录显示真实作者及原操作，二级关系和属性按需展开。窄面切换工作区和 Supervisor 时，保持同一 Goal、节点选择、草稿和原工作入口。人的确认和结果接受保留在原标准与结果正文。有原活动或决定时，Activity 从同一详情读取。各视图消费[同一原记录](../behavior/goal-plans-and-tickets.md#详情工作台的原记录)。

Agent 与 Mote 选择复用共享的搜索、分段切换、选择字段和身份符号。名称、工作位置与状态按不同字级排列，整行选择反馈兼顾键盘与减动。创建、发送和原回执沿原操作。头像组、选择字段、通用动作和导航选中底面沿[共享组件](../../../packages/client-ui/README.md#choose-a-control-for-the-task)，工作台决定阅读落点。长记录按原入口展开，保留读者的位置和键盘焦点。

## 协作关系与持续推进的呈现

Goal 详情的 Agent 直接复用 Focus／Space 的同一真实卡片与身份、状态、摘要、菜单和进入原工作面的交互；不能只复用头像后另造一套关系按钮。准确身份只显示一次，Supervisor、执行者与相关讨论以可辨角色附着于该卡，角色编辑仍沿原 Goal 关系 owner。历史及未解析引用也保清楚统一的关联视觉单元，已知旧名/来源/角色可读，稳定 ID 与技术依据居次层；确认身份、生命周期结束和运行未知分别表达。已确认 Actor 复用原卡片交互，只有历史元信息或多候选时保原引用、原因与准确读取/关系检查入口，不伪造当前 control、活动状态或菜单目标。卡片的相关事实订阅和热路径预算沿既有 owner。

Goal 列表的成员头像和「Agents」浮层按当前分工呈现。确认的名字与分工优先，只有准确引用的成员显示角色与短 Session 标识。当前工作面未知单独显示一次，完整 Session 与来源位置按需展开。悬停只预览，点击固定阅读或打开已确认的原 Agent Reader；经过浮层边缘时保持可读，离开和键盘关闭沿应用已有浮层规则。

已有实际执行关联时，先呈现每位执行者的原责任、报告摘要与当前下一步，报告回收或结果核验是该任务的主动作；原 Agent 和任务 owner 是次级入口。Supervisor 保持明确可辨，负责人和历史相关会话的重复配置按需展开，未指派时保留直接选择。已收到提醒的详情降到次层，待处理或未知提醒仍就地可读；逐标准证据和原来源可展开，不让配置和回执说明挤掉实际执行责任。

工作记录与负责人区在详情中的位置沿[详情的阅读顺序](#常用操作的空间与连续列表)。负责人和相关会话在同一区域、分别命名；共用有头像、完整名称、Project 和文字状态的可搜索列表，不用系统 select 承载 Agent 列表。多选的已选状态同时有字形/文字及中性 Surface，保留未知身份和准确进入原工作面的入口。列表先将相关且可选的 Agent 按行为 owner 优先，再按项目/Mote 规则排序；新建入口在列表内清楚命名，创建配置与已存在的 Session 不混成同一种选项。

关系编辑有明确编辑含义，不伪装成分类 tab；阶段主动作、原对话导航、原操作检查和新请求分别强调。新持续推进的频率配置渐进展开，尚不适用时用短说明指向真实下一步；已有 Loop 和原未决/失败记录仍可读可控。系统术语、语言、按钮和状态色一致，技术保全说明与完整原标识按需阅读，关键未知及恢复动作仍就地可见。

Supervisor 从负责人中明确单选；旁边用原身份头像与完整姓名呈现准确推荐，明确的「设为 Supervisor」一键动作与已保存身份分开，不把默认选中颜色当作推荐或成功。实际提需来源保低占用的参与摘要/按需明细，与负责人和历史分别命名。Goals 设置的默认勾选项说明仅影响新需求首次绑定、不自动开始 Loop，沿既有设置组与草稿/保存反馈。尚未指定时用一个低占用的图文 banner 说明「指定一位负责人持续跟进」，以选择 Supervisor 为唯一主入口；小型轨道/协作意象辅助辨认，不铺 hero、不叠卡片、不挤正文。指定后显示原 Agent 的准确身份与 Continue 控制，已有 loop 始终按原事实可读和可控。未知创建/关联/投递有各自就地、持续的服务窗和原操作检查，不能只显示 spinner 或重做按钮。

更多属性按计划/分类/关系等实际用途紧凑分组，复用应用 SelectionField、弹层、焦点及主题 token；标题、正文与常用项不再重复填表。宽窄、明暗、搜索、键盘返回、长名称、空值、未知引用和保存反馈均保持可读，完整焦点与原草稿可追踪。活动分类让要求变更与阶段证据可区分，长引用按需读取；main、发布及人接受不混成一枚完成标识。

Agent Region 的当前 Goal 标记与原 Agent 身份/状态相邻，标题可辨且点击命中清楚，进入准确详情保留原输入。历史关联不铺为当前工作，长标题不挤掉 Agent 状态与既有 chrome。订阅只消费相关领域事实，不跟随无关 Session 的终端输出重算。看图评审覆盖整页、选择器、未设／已设 Supervisor 与 Region 导航，修正后复拍至明确可交付。行为唯一见[负责人、相关会话与当前推进](../behavior/goal-execution-and-supervision.md#负责人相关会话与当前推进)。

## 执行者、责任告警与巡查反馈

Goal 列表/看板与详情就近显示有来源的执行 Agent、管理者、业务阶段及下一步负责人；头像、完整名称与文字状态共同可辨。紧凑摘要先读目标、执行状态、准确下一责任与原动作，详细身份、状态起点、最近进展和原证据按需展开。目标阶段、Run 状态与巡查请求回执分别命名，保存、投递、实际巡查和人的接受不压成同一完成标记；必要异常原因、重要差距与可用恢复入口仍就近可读，不能只靠 hover 或藏进原始详情。执行关联与历史相关会话分开，无确认执行、后台执行、多个依据、未知和不可用均有诚实的紧凑表达。Agent 工作面保留当前 Goal 的准确回到入口，导航沿原工作面，不改变执行或草稿。

待处理责任在原 Goal 行/卡及详情可见，不要求先打开终端或逐条翻 Activity。告警用简短原因、实际执行者/管理者及下一动作解释哪里停滞，严重程度沿原事实与共同状态语言，颜色不单独承担含义。正常等待验收或已说明的外部等待显示相应阶段；观察未知提供非阻塞服务窗，健康工作面继续可用。行为及责任判据唯一见[执行责任、停滞告警与 PMO 巡查](../behavior/goal-execution-and-supervision.md#执行责任停滞告警与-pmo-巡查)。

告警附近提供明确的「PMO 巡查」主动作，点击后左下快捷交流浮窗可见，并呈现该 Goal 准确原 Supervisor Agent 的对应对话。原目标、管理者与所读对话有可辨身份，不能只打开旧 PMO、另一 Goal 的讨论或把普通 Agent 冒称主 Mote；原实体归属与导航行为沿[单项巡查合同](../behavior/goal-execution-and-supervision.md#执行责任停滞告警与-pmo-巡查)。原输入准备、排队／投递、真实工作状态和实际巡查结论分别呈现，不用展开动画、Working 文案或 loading 图形假造执行。目标准备或恢复未知时仍显示准确目标窗口、具体原因与可达的接续／选择入口，不留空白、不闪旧会话。

原在途请求保可读并防重复，用户仍可继续其他工作；仅打开管理者的次级导航动作与发起巡查有清楚区别。巡查结论、更新后的进度、剩余缺口和下一责任人回到同一 Goal，未解决原因继续可见，不能用 Toast 成功或按钮消失冒充处理闭环。背景 Goals 的选择、搜索／筛选、正文和原输入保持；浮窗关闭只收起呈现，不取消原巡查或恢复旧背景选择。

原目的地尚未确认与首次发送使用不同文案：未有准确原输入目标时，原对话入口保留未确认呈现，不借当前同名 Agent 补成旧目的地。原 owner 允许从未尝试的请求首次发送时，入口明确说明这次会首次交给当前已确认的 Supervisor，并就近显示其准确 Host；Run 等技术依据按需读取。这个显式动作与核对原回执、打开原对话分别可辨，不把候选画成已经保存的原接收者，也不因目的地未知拿走已有的首次发送能力；资格与回执仍归[单项巡查合同](../behavior/goal-execution-and-supervision.md#执行责任停滞告警与-pmo-巡查)。

宽窄窗口、明暗主题、键盘/触摸与长名称下，执行摘要、告警、巡查动作和处理反馈保持可读可操作，复用原 Goal、Agent 身份与状态组件。详情切换、重连和重启保原选择、草稿、执行关联与巡查反馈；告警和巡查不新增另一份任务清单或通知事实库。

### 全局巡查入口与汇总对话

Goals 总览提供低占用、明确标为「全局巡查」的入口，与单项 Goal 的「PMO 巡查」有可辨范围，不隐藏在某一目标里或被当前筛选伪装成仅检查可见行。入口沿原紧凑工具带，不新铺统计大卡或挤占连续目标阅读。点击后左下浮窗显示主 PMO Mote 内这次全局巡查的新独立 Tab，标题与相邻短说明可辨全部 Demand 的检查范围；不把新 Tab 画成新 Mote 或新 Goal。准备、投递、实际工作及读取缺口有各自低占用反馈，行为只归[全局巡查](../behavior/goal-execution-and-supervision.md#全局巡查)。

汇总留在本次对话，先说明总体情况和未核对范围，再用能定位原 Goal 的结构列出需处理事项、来源／未知及建议下一步。可直接处理的建议显示准确操作及影响，用户明确选择并确认后才执行；不可直接处理的事项将问题和待决定内容摆在一起，方便同一对话讨论。不把全部目标全文堆成卡片墙，不以一枚总成功标识掩盖部分失败，也不把建议样式画成已经执行。原 Goal、证据与实际操作回执按需可达；窄窗、明暗和长目标名称下，汇总、讨论输入、确认范围与未知说明保持完整可读。

## 委派与回报的阅读

委派、报告回收与责任沿[同主题行为](../behavior/goal-execution-and-supervision.md#委派回报与责任接续)。原 Goal 的协作区和 Mote 当前工作摘要先显示需要谁做什么：待回应、提问或阻塞、报告待回收、未交付待接续、观测未知、结果待人接受。准确作者和下一步紧邻正文，原 source／reply、Host／Session／Run、资料版本和逐标准证据按需展开。原 Session、报告回收和结果核验动作可操作，宽窄布局保主要正文与入口，不以大段技术标识、状态色或静态卡片代替实际回收。

待复核工作在计划上方提供到当前交付的入口，显示节点名与真实状态；详情的 Plan 阅读导航直达该区域。待复核条目使用整行命中，展开项以文字、方向图标和 Surface 标出当前位置。标题在窄栏换行。报告阅读只在切换时短促进入，减少动态效果时立即就位；返回优先还给打开本次阅读的控件，该控件消失后还给同一计划节点。交付优先显示当前报告、该节点的检查、对这次交付的结论与原讨论。历史尝试按需读，记录仍归原委派。选择节点与返回使用同一阅读区，保留正确焦点。单次直接执行继续从 Goal 的结果区读取。

## Goal 计划图

计划图是 Goal 详情首屏的视觉中心，在标题与当前结论之后展开。计划工具栏、路径和时间轴共享同一石墨工作台。静态光面与首尾的金属轮廓源于[工坊](brand-identity.md#共用工坊)，状态色仍对应真实状态，阅读与焦点不依赖材质。未拆分时原 Goal 占第一列的唯一节点，和拆分后的任务共用画布、分工索引、节点卡片和正文。单节点也有完整构图，视线从起点经工作节点到达终点，节点、连线与四周留白的比例随画布宽度协调。多节点时，分支、依赖与汇合构成主要阅读线。整页图审同时看单节点宽屏和有真实依赖的多节点计划，核对两者的工作节点与路径在分工、工具和时间轴同屏时都清晰突出。

甘特图的标题与执行条通向同一 Ticket 或尝试。时间点的命中区独立，位置重叠时垂直错开，时间坐标保持对齐。预览贴近触发点，持续阅读的详情和原记录动作在窄窗也完整可达。悬停、键盘焦点和当前选择可辨。交互约束见[详情工作台的原记录](../behavior/goal-plans-and-tickets.md#详情工作台的原记录)。

节点显示原目标标题、当前结论和分工，选中后可读原目标与成功标准。保留当前原工作与结果的阅读顺序。图的修订号和进度沿原 owner 提供的拆分计划显示。

拆分入口由计划标题栏导航到 Supervisor 工作台，原准备、发起、对话、失败核对和明确接续均在该工作台呈现。无 Supervisor 时沿原关系入口选择，之后一次明确点击才发送。点击已有 Supervisor 的制定入口立即打开其浮窗对话并显示准备状态；新计划请求、旧讨论请求和只读打开讨论分别可辨。回到原 Goal 时仍显示原请求反馈。原 owner 保存拆分后在同一图内呈现真实节点与依赖。

原计划请求的首次发送同样遵循[原目的地与首次发送的区分](#执行者责任告警与巡查反馈)，保留原请求与明确动作，不把当前候选说成原目标。

计划图按依赖从左到右分层：没有依赖的节点在第一列，每个节点放在其最晚依赖的下一列；同一列内按计划中的顺序排列。依赖用细曲线从前一节点右缘连到后一节点左缘，已完成的依赖线用中性色，通向可开工节点的线用品牌薄荷色。宽画布将真实依赖列分配到可用宽度，节点保合理阅读上限，不把整组挤在左侧留下大块空面；列多时仍可横向滚读而不缩小字号；分叉与合流给不同连线留出可辨的端点和间距。窄栏按真实依赖深度分组，用紧凑的同级排列呈现可并行的分支，节点保留准确的前置任务名称。深度只表达拓扑关系。

节点以阶段字形和任务名为首行。下方将当前状态与执行者放在同一信息层，空间不足时自然换行。节点展开后可读完整分工与已知的执行位置（本机、远端 Host 或远端项目），已有评审时能读到评审方与结论。阶段字形与配色沿清单的阶段标记：可开工与要求修改用强调，执行中与待评审用中性加进度，已完成退为低对比并保留可读，未知用琥珀色说明。唯一可开工的下一步用实心薄荷填充高亮；其余节点不另加描边或阴影竞争注意力。

每个工作节点常驻一行分工。当前委派已确认时显示该次执行 Agent；只有计划指派或认领时显示负责 Agent 与待派工状态。未拆分 Goal 仅有团队关系时按关系显示，执行者待确认。可认领的空缺节点显露待认领身份。人在具体节点查看、开放或指派，Agent 从同一计划发现可认领工作。首尾标记只承载路径语义。身份名称与执行、评审阶段可分别辨认。

整张工作节点支持点击，键盘使用同一入口。任务名、状态和执行者各有稳定的阅读位置。选择节点后在图旁读取该任务的分工、委派、报告与评审证据。窄面把显式选中的节点和正文连成一张卡，只显示一次任务标题，返回时焦点落回原入口。原 thread 按需读取，读取失败保原引用与已确认记录，提供同一来源的重读入口。Agent 导航保准确 Host 与 Session，Agent 所在 Host 与远端工具资源分别表达，位置未观察时明确未知。标准已变或缺失时，旧评审标为原尝试的结论，不让「通过」冒充当前完成。节点状态变化时只有一次短促的颜色与位置过渡，遵循减少动态效果偏好。清单行在计划存在时显示一条细进度和「已完成／节点总数」，与阶段标记并列，不另起统计卡。

拆分节点所在列与节点状态消费行为合同定义的同一份计划推导，与 CLI 读到的结果一致。单节点直接复用 Goal 的当前结论。图只随该 Goal 的相关事实变化重算。

Goal owner 返回计划却未附推导时，呈现层同样不补算：节点按计划顺序排成一列铺满正文宽度的清单，每张卡片写明依赖并标「状态不可用」，不高亮下一步，不画进度条或进度环；段内说明计划本身未变，并指出更新该 Host 即可看到节点状态。
