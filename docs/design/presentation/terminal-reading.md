## Terminal resume 的 recap 密度

- recap 放在原标题、步骤说明与原活动信号之后、诊断详情之前的次级信息层，使用原恢复舞台的正文、弱化来源与 Surface 语汇；一张面只呈现一份摘录，不另加品牌、重复标题、工具栏或自动展开的卡片。真实性、来源及读取边界只见交互 SSOT[《Terminal resume 画面中的 recap》](../behavior/terminal-reading.md#terminal-resume-画面中的-recap)。
- 正常与窄／短 Region 都先看清阶段、失败说明和原动作，摘录以有界可读高度呈现；长正文不把动作挤出当前面，完整记录沿已有详情／历史入口可达。没有可用内容时采用原有轻量说明，不铺空白摘要盒、不以 recap 的独立 loading 遮住原恢复状态。减少动态时正文与来源仍可读，不随动画重复播报整段摘录。

## Terminal 内容层与输入层的清晰边界

- Terminal 输出是第一视觉层，保持连续的等宽字形、明确的行高和稳定的 cell 几何；恢复与停泊的视觉分量归[《启动与恢复的分量分开》](session-recovery.md#启动与恢复的分量分开)，装饰不能透进已有文本或 Composer。
- xterm 容器必须由唯一的尺寸 owner 测量，宽高、margin 和可见性不能互相叠加出第二个画布；冷停/恢复时的旧 canvas 要么隐藏并不接收指针，要么完整释放，不能留下半透明残影。
- Composer 是独立的输入 surface，使用自己的背景、边框和最小高度；它与 Terminal 之间保留一条可见分隔，不把输入占位、工具按钮或动画混入终端滚动区。
- 窄栏和 reduced-motion 下仍保留输出、光标与服务窗的可读层级；恢复成功后移除状态层，不留下空白 chrome 或无意义的装饰纹理。
- 恢复内容至少在 320px 和 420px 窄分屏保持可读：真实说明按纵向流动，Prompt 可滚动，复制与恢复控件保持命中区；宽格不额外增加注册标记或装饰。
- 减少动态效果时，真实步骤、身份、Prompt 与动作仍完整可读；具体动效与鼠标边界只见[《启动与恢复的分量分开》](session-recovery.md#启动与恢复的分量分开)。
- 真实 attach 或恢复事实到达后，过渡短而克制；不能把视觉完成冒充 Runtime 完成。

## Agent 终端颜色的能力一致性

- Terminal surface 对每个 Provider 使用同一套 ANSI/truecolor 能力基线，颜色由 PTY 字节和 xterm palette 共同决定；Provider 名称不能成为颜色是否可见的隐式开关。
- 启动和恢复时过滤宿主注入的禁色环境变量，避免 Claude 这类会严格遵循 `NO_COLOR`/`CLICOLOR=0` 的 CLI 变成单色。过滤只作用于宿主的意外继承，不改变用户为当前 Run 明确选择的其它环境语义。

- 终端颜色密度由 ANSI 16 色和 256 色共同构成。Claude 的橙色、绿色和灰阶等索引色要在普通消息、提示、工具输出和 diff 之外都保持原有层次；不能只让代码 diff 看起来有颜色。WebGL 和 DOM 回退的颜色表必须一致，终端主题的基础色定义不能覆盖或禁用 xterm 的扩展索引色。

- Resume 后的颜色保持、正常新建 Agent 复用长寿命 Runtime 时的颜色环境、用户在  要求完成实际修复的验收边界与无色来源区分只定义在交互合同[《Agent 终端 256 色显示》](../behavior/terminal-reading.md#agent-终端-256-色显示)的「Resume 后颜色保持」；沿用原 Terminal palette 与服务窗，不增加 Provider 专属色表、诊断栏或遮挡工作面的提示。

## Terminal 历史阅读的呈现

安装后仍滚不动的反馈沿原终端内容面处理；诊断与恢复说明不能遮住内容或制造另一个滚动面。结果与未知事实的约束统一见交互合同[《Terminal 连续向上阅读历史》](../behavior/terminal-reading.md#terminal-连续向上阅读历史)。

界面更新时历史工作面与当前健康 Run 的保留判据只引用上述交互合同的《第一方界面与 Native 更新分别提交》，不增设历史引用清理或另一套阻断提醒。

跨 Client 输入后的游标与拒绝／未知结果沿同一交互合同表达，继续使用原终端及紧凑服务窗，不增加游标控件、重试入口或第二个输入面。

触控板滚动沿同一 Terminal 内容面操作；说明与控件保持紧凑，滚动手势、悬停提示与失败提醒保持原终端网格尺寸稳定。当前保留内容与 TUI 距离的行为、实际滚动验收见交互合同[《Terminal 连续向上阅读历史》](../behavior/terminal-reading.md#terminal-连续向上阅读历史)。

向上阅读与回到最新输出使用原终端的滚动面；保留原视口，不加第二个常驻输入区。真实历史边界与全屏应用的说明放在紧凑的服务提醒，不写进终端正文、不遮住终端和输入。连续滚动、跟随与 Runtime 历史的行为约束归交互合同的「Terminal 连续向上阅读历史」。

历史提醒要让人分清「终端缓存到头」「Runtime 字节已淘汰」和「持久会话记录仍可读」。已有记录的阅读入口沿用会话工作面，不以红色错误或全屏遮罩阻挡健康 Agent；不能用一个笼统的 History gap 表达所有内容都已丢失。来源、完整性和重连模式的约束只定义在上述交互合同中。

会话历史融入原 Region 的内联内容面，保持原工作面、输入区与紧凑来源说明；不得在一次普通上滑时出现独立 History 遮罩、整屏工具栏跳变或要求用户先退回另一页才能操作。终端与持久内容使用一致的字体、字号、行距、背景、宽度、选择和滚动语言，不因来源变化突然变成另一套聊天卡片／Markdown页面；来源与完整性保持可辨。长期待恢复的工作面直接呈现可读记录和就近恢复状态，读取更早内容与失败重试仍可达；图片／音频等引用无法预览时显示引用与原因，不增加第二个输入区。活跃与待恢复的行为判定、分页位置和终端保留只归上述交互合同及《冷启动按需恢复》。

历史与实时对话沿用同一消息组件及其控件语言；原工作面的字体和颜色可以由宿主继承，不为历史另写头像、消息头、正文、资源引用与复制控件。组件复用、Provider 解析和缺失元数据的事实归上述交互合同。

共享消息投影的浏览器接入沿用上述既有消息呈现，不新增视觉层、控件或常驻状态；客户端与宿主边界只引用交互合同《共享消息投影的客户端边界》。

取消后的输入和状态沿同一 composer 与服务窗表达；可开始下一轮不额外显示成功徽章。边界事实归交互合同[《Provider 能力对齐与移植边界》](../behavior/agent-capabilities-and-messaging.md#provider-能力对齐与移植边界)。

用户要求 Provider 完善后的体验「高级、优雅、简约」。正文保持主要阅读层级，推理与工具细节按需展开，失败只由真实状态强调；消息身份、资源和复制沿用共享控件，不增加按厂商分支的工具条、状态灯或重复面板。实际交互和性能验收归交互合同[《Provider 能力对齐与移植边界》](../behavior/agent-capabilities-and-messaging.md#provider-能力对齐与移植边界)。

历史入口沿用会话工作面的固定操作位；历史边界提醒留在紧凑服务窗，不在终端上方再堆一份相同操作。按需恢复的工作面沿用原布局和正文语言，以轻量状态及就近进度说明当前可读、待恢复或恢复中，避免大屏遮住已有内容；闲置门槛与执行触发只定义在交互合同《冷启动按需恢复》。

终端持续输出的队列与批次成本同样归[《Terminal 连续向上阅读历史》](../behavior/terminal-reading.md#terminal-连续向上阅读历史)，不增加控件、诊断轮询或另一份输出投影。 Runtime 写盘合批沿同一成本合同，观测仍使用现有资源面板，不另加常驻指标或状态。Terminal 与 Message Tool 同时停住时的 Runtime 事实与未知边界也引用该合同；提醒复用既有紧凑服务窗，不遮住原终端或增加第二套监控面板。 多 Session 的共享故障、派生状态与原始服务的区分及整段交付也只引用同一交互合同；不增加第二组状态灯或诊断栏。

输出安静后的耐久化与相关 Run 补写成本也引用上述交互合同；不增加常驻诊断控件、全会话轮询或第二份输出状态。

界面与 Native 更新的分别提交、实际服务身份与进程归属、冷安装的恢复核对缺口及失败结果，唯一行为来源见交互合同[《Terminal 连续向上阅读历史》](../behavior/terminal-reading.md#terminal-连续向上阅读历史)的对应约束；沿用现有紧凑服务窗与诊断呈现，不增加第二套版本条或运行状态。 活 Runtime 升级归属的当下事实与陈旧 receipt 的诊断边界引用同章《活 Runtime 的升级归属使用当下事实》；不把账本缺口画成 Agent 故障或新增阻断输入的提醒。完整后台库存与原界面投影、候选版本未回应的边界引用同章《安装的后台保全与界面恢复分别核对》，不将未展示的 Run 画成界面恢复故障，不另建告警组件。 共享可执行文件的外部 Node 客户端与 GUI 自有 Node worker 的归属/原出生保护引用同章《应用进程归属与 Node 辅助执行分开》，未确认分类沿现服务窗说明，不另建模式或健康账本。 观察途中新增候选的模式缺口沿同一归属约束说明，未确认不呈现为应用故障。 归属失败的点时身份、阶段与未知边界沿同一交互约束在安装诊断面说明，不新增常驻状态条或全机日志。

旧 listener 的明确冷态与候选默认状态位置的边界亦沿上述交互合同表达；默认位置差异、实际状态 authority 与未确认的历史恢复分别说明，不将冷安装放行绘成迁移成功或健康 Run 保留，不另加配置控件。

活动历史内部处理的成本约束归同一交互合同；性能优化不增加观测轮询、状态控件或第二套历史投影。 窗口壳与资源回收的订阅边界同样归[《Terminal 连续向上阅读历史》](../behavior/terminal-reading.md#terminal-连续向上阅读历史)；收窄更新不增加任何常驻诊断 UI。 AgentSession 快照的无新事实通知与相关项更新边界同样只引用该交互合同，不增加指标、轮询或控件。

字节传输不增加工作面控件；正常字符和控制序列由原 Terminal 显示。公开 API 和 CLI 的字节完整性约束归交互合同的「ordered bytes 的公开传输边界」。

Region 持续故障告示与手动观察刷新只引用交互合同[《Terminal 连续向上阅读历史》](../behavior/terminal-reading.md#terminal-连续向上阅读历史)的对应约束。刷新就近沿用既有紧凑服务窗控件，原终端网格与阅读面稳定，不遮住终端或输入，不增加状态灯、诊断栏或监控面板；观察刷新与输入重试使用可区分的标签和动作。

## Terminal 链接读出与目的地面

点击后的浮层以当前目标为单一信息头，打开动作有清楚分组、可辨短名称与方向；系统浏览器和工作台内的目的地关系一眼可读，不让用户只凭无文字的小图标猜动作。沿原目的地 owner 与 Settings 共享控件刻度、轻材质和焦点语言，宽窄面保持统一命中区与稳定文字，减少空槽、重复 URL 和装饰留白；长目标可按需核对完整内容。目的地集合、键盘 / 手势、碰撞边界与保全行为唯一见交互 SSOT[《Terminal 链接读出与目的地面的信息归属》](../behavior/terminal-reading.md#terminal-链接读出与目的地面的信息归属)。真实宽窄 / 边缘浮层的新图须独立看图，无 must-fix；采图成功或仅 CSS 在场不能代称完成。

## Hover 提示与终端尺寸

提示沿用窗口浮层语言，不参与工作面排版，不撑高工具条或压缩 Terminal。几何、Runtime resize 与阅读位置约束只定义在交互合同的「Hover 提示不改变 Terminal 几何」。

链接下划线沿既有终端链接语言呈现，不另加标记、背景块或诊断栏；准确的文字单元格、命中、软换行／滚动、打开归属与成本边界唯一见交互合同[《Terminal 链接 hover 范围与单元格》](../behavior/terminal-reading.md#terminal-链接-hover-范围与单元格)。实际中文、emoji、组合字符及窄区场景须能看清文字与下划线的对应关系，采图成功不能代替独立看图。

被动读出的避字落点、无空白则收起及 live／scroll／resize 后的保全行为，只见交互合同[《Terminal 链接 hover 范围与单元格》](../behavior/terminal-reading.md#terminal-链接-hover-范围与单元格)；沿原读出控件语言，不增加预留行或另一层提示。



## Terminal 信息与恢复画面的视觉品质

交互、事实、输入与唯一入口只见 interaction[《Terminal 信息入口与恢复画面品质》](../behavior/terminal-reading.md#terminal-信息入口与恢复画面品质)。用户要求精致、现代、简约、紧凑；右上局部信息组的基线、字形底色与交互轮廓协调，hover/focus/open 不突然扩张背景或命中区，不把小角标变成一条工具栏。名字与必要动作仍可读，正常和窄分屏的终端首行、正文和输入保持清晰。

Terminal 被动服务提醒以邻近操作区的低占用入口呈现，不作为纵向布局里的固定一行，不在中间再叠 Full-screen history 横幅。未解决/未知与已收起仍可辨，完整原说明、关闭/复查和恢复动作按需可达；轻量不是把故障静默藏掉。

启动与恢复的构图、分量、鼠标反馈与动效统一见[《启动与恢复的分量分开》](session-recovery.md#启动与恢复的分量分开)。本段保留 Graphite/Mint、明暗/窄/矮格及真实说明/动作可读性的要求，不再规定 Region 使用应用启动的大图。
