## Terminal resume 的 recap 密度

- recap 放在原标题、步骤说明与原活动信号之后、诊断详情之前的次级信息层，使用原恢复舞台的正文、弱化来源与 Surface 语汇；一张面只呈现一份摘录，不另加品牌、重复标题、工具栏或自动展开的卡片。真实性、来源及读取边界只见交互 SSOT[《Terminal resume 画面中的 recap》](../behavior/terminal-reading.md#terminal-resume-画面中的-recap)。
- 正常与窄／短 Region 都先看清阶段、失败说明和原动作；摘录与主状态保持明显间距，以有界可读高度呈现，正文密度低于主状态。长正文、代码与路径合理换行，不让完整 Last reply 的长度决定舞台首屏，也不把动作挤出当前面；完整内容、原复制和详情／历史入口仍可达，不靠缩小字号或不可读裁切制造留白。没有可用内容时采用原有轻量说明，不铺空白摘要盒、不以 recap 的独立 loading 遮住原恢复状态。减少动态时正文与来源仍可读，不随动画重复播报整段摘录。

## Terminal 内容层与输入层的清晰边界

- Terminal 输出是第一视觉层，保持连续的等宽字形、明确的行高和稳定的 cell 几何；恢复与停泊的视觉分量归[《启动与恢复的分量分开》](session-recovery.md#启动与恢复的分量分开)，装饰不能透进已有文本或 Composer。
- xterm 容器必须由唯一的尺寸 owner 测量，宽高、margin 和可见性不能互相叠加出第二个画布；冷停/恢复时的旧 canvas 要么隐藏并不接收指针，要么完整释放，不能留下半透明残影。
- Composer 是独立的输入 surface，材质与无常驻描边的焦点语言沿[Composer 表面 owner](spaces-and-layout.md#工作面与注意力密度)，保留原最小高度及与 Terminal 输出的可见分隔；不把输入占位、工具按钮或动画混入终端滚动区。
- 窄栏和 reduced-motion 下仍保留输出、光标与服务窗的可读层级；恢复成功后移除状态层，不留下空白 chrome 或无意义的装饰纹理。
- 恢复内容至少在 320px 和 420px 窄分屏保持可读：真实说明按纵向流动，Prompt 可滚动，复制与恢复控件保持命中区；宽格不额外增加注册标记或装饰。
- 减少动态效果时，真实步骤、身份、Prompt 与动作仍完整可读；具体动效与鼠标边界只见[《启动与恢复的分量分开》](session-recovery.md#启动与恢复的分量分开)。
- 真实 attach 或恢复事实到达后，过渡短而克制；不能把视觉完成冒充 Runtime 完成。

## Agent 终端颜色的能力一致性

Terminal 对所有 Provider 使用同一 ANSI／truecolor 与扩展索引色呈现基线，字节、palette 与 WebGL／DOM 回退保持同一颜色语义；不能只让 diff 有颜色，普通消息、提示、工具输出与灰阶层次也须可读。启动／Resume 的环境、用户显式选择与无色来源边界唯一见[《Agent 终端颜色与 Provider 环境》](../behavior/terminal-reading.md#agent-终端颜色与-provider-环境)和[《Agent 终端 256 色显示》](../behavior/terminal-reading.md#agent-终端-256-色显示)。失败沿原 Terminal palette 与服务窗说明，不增 Provider 专属色表、诊断栏或遮挡工作面的提示。对话身份的派生色与非状态色边界见[《对话身份色与语义色》](agent-capabilities-and-messaging.md#对话身份色与语义色)，不混入 Terminal 调色板。

## Terminal 历史阅读的呈现

### 原位阅读与原工作面

向上阅读与回到最新输出使用原 Terminal 的滚动面，保留原视口、网格、输入区和工作面。普通上滑不出现独立 History 遮罩、整屏工具栏跳变或第二个常驻输入区，也不要求先退回另一页。诊断、恢复与服务说明不能遮住内容、改变几何或制造另一滚动面。触控板、连续滚动、跟随与实际活跃会话验收只见[《Terminal 连续向上阅读历史》](../behavior/terminal-reading.md#terminal-连续向上阅读历史)。

待恢复面在原 Region 内直接呈现可读记录和就近恢复状态，较早内容、完整阅读与失败重试可达；不用大屏遮住已有内容。按需恢复的执行资格、闲置门槛与未知保护只见[冷启动行为 owner](../behavior/session-recovery.md#冷启动按需恢复p0-末位)。跨 Client 输入、游标拒绝／未知和取消后的输入沿原 Composer／服务窗说明，不另加游标、输入或成功徽章。

### 来源、缺口与共同阅读

历史提醒区分终端缓存到头、Runtime 字节已淘汰和持久会话记录仍可读；来源、完整性、读取范围与失败各有简短说明和原位 History／Retry 动作。不能用笼统 History gap 暗示全部丢失，不能把未知画成故障、空态或成功。历史入口沿会话原固定操作位，紧凑服务窗不与它重复占位；输出缺口不写进终端正文或挡住健康 Agent。

历史与实时对话复用[共同消息呈现](conversation-input.md#用户消息气泡的内文密度)，正文、头像、来源、资源与复制只有一份语言。原工作面可由宿主继承字体与颜色，终端历史衔接保持协调的字号、行距、背景、阅读宽度、选择与滚动，不因来源变化突变成另一套聊天卡片。推理、工具和过程细节沿共同阅读按需展开，失败只由真实状态强调；图片／音频不能预览时保引用与原因。Provider 解析、缺失元数据、浏览器客户端接入与宿主能力边界归同一[历史行为合同](../behavior/terminal-reading.md#terminal-连续向上阅读历史)及[Provider 能力 owner](../behavior/agent-capabilities-and-messaging.md#provider-能力对齐与移植边界)，不按厂商新增工具条、状态灯或诊断面。

### 故障说明、更新与成本

Region 持续故障和手动观察刷新沿原紧凑服务窗；观察刷新与输入重试的标签和动作可分，不能清空原终端、遮挡健康输入或另建监控面板。OSC 8 在快照后缺失的语义沿同一说明表达，可用链接保持既有下划线与目的地提示，不在正文加诊断标记。

输出队列、批次、写盘合批、安静后的耐久化、相关 Run 补写、历史内部处理、窗口壳订阅与资源回收均沿[历史与相关消费者成本合同](../behavior/terminal-reading.md#terminal-连续向上阅读历史)；呈现不增加轮询、全会话观察、状态缓存或另一份输出／历史投影。Terminal 与 Message Tool 同停、多 Session 共享故障及观察未知仍说明准确影响范围，保原工作面与健康 Run，不制造第二组状态灯。

界面／Native 更新、后台库存、实际服务与进程归属、候选未回应、外部 Node 与 GUI worker、冷安装及旧 listener 的事实边界同归上述行为 owner；需要说明时沿安装诊断面与既有服务窗，区分已保全、未展示和未确认。不能把账本或归属检查缺口画成 Agent 故障、迁移成功或界面已恢复，不加永久版本条、全机日志或输入阻断。

[ordered bytes 的公开传输](../behavior/terminal-reading.md#ordered-bytes-的公开传输边界)不增加工作面控件；正常字符与控制序列由原 Terminal 显示。共享故障、来源与成本的详细判断只在行为 owner 定义，本页只保其就地、低干扰且持续可达的呈现。

## Terminal 链接读出与目的地面

点击后的浮层以当前目标为单一信息头，打开动作有清楚分组、可辨短名称与方向；系统浏览器和工作台内的目的地关系一眼可读，不让用户只凭无文字的小图标猜动作。沿原目的地 owner 与 Settings 共享控件刻度、轻材质和焦点语言，宽窄面保持统一命中区与稳定文字，减少空槽、重复 URL 和装饰留白；长目标可按需核对完整内容。目的地集合、键盘 / 手势、碰撞边界与保全行为唯一见交互 SSOT[《Terminal 链接读出与目的地面的信息归属》](../behavior/terminal-reading.md#terminal-链接读出与目的地面的信息归属)。真实宽窄 / 边缘浮层的新图须独立看图，无 must-fix；采图成功或仅 CSS 在场不能代称完成。

## Hover 提示与终端尺寸

提示沿用窗口浮层语言，不参与工作面排版，不撑高工具条或压缩 Terminal。几何、Runtime resize 与阅读位置约束只定义在交互合同的「Hover 提示不改变 Terminal 几何」。

链接下划线沿既有终端链接语言呈现，不另加标记、背景块或诊断栏；准确的文字单元格、命中、软换行／滚动、打开归属与成本边界唯一见交互合同[《Terminal 链接 hover 范围与单元格》](../behavior/terminal-reading.md#terminal-链接-hover-范围与单元格)。实际中文、emoji、组合字符及窄区场景须能看清文字与下划线的对应关系，采图成功不能代替独立看图。

被动读出的避字落点、无空白则收起及 live／scroll／resize 后的保全行为，只见交互合同[《Terminal 链接 hover 范围与单元格》](../behavior/terminal-reading.md#terminal-链接-hover-范围与单元格)；沿原读出控件语言，不增加预留行或另一层提示。



## Terminal 信息与恢复画面的视觉品质

交互、事实、输入与唯一入口只见 interaction[《Terminal 信息入口与恢复画面品质》](../behavior/terminal-reading.md#terminal-信息入口与恢复画面品质)。用户要求精致、现代、简约、紧凑；右上局部信息组的基线、字形底色与交互轮廓协调，hover/focus/open 不突然扩张背景或命中区，不把小角标变成一条工具栏。名字与必要动作仍可读，正常和窄分屏的终端首行、正文和输入保持清晰。

Terminal 被动服务提醒以邻近操作区的低占用入口呈现，不作为纵向布局里的固定一行，不在中间再叠 Full-screen history 横幅。未解决/未知与已收起仍可辨，完整原说明、关闭/复查和恢复动作按需可达；轻量不是把故障静默藏掉。

手机终端将主要可用空间留给原输出，当前观看／控制方式保持可辨，模式说明、正常确认和缓冲区长说明归原信息入口；详情收起时不留一大块固定说明区。阅读比例、复制、刷新与次要动作共享紧凑操作组，按当前任务揭示，不把每类工具各铺成一排常驻栏。先收紧标题、工具和说明占位，保持终端文字清楚，不以继续缩小字号或大块空白中的缩略画面替代可读的输出面。操作组与详情沿[手机呈现 owner](public-control.md#手机版-relay-连接的呈现)消费 Amux 原主题及可配置样式；触摸范围与视觉体积分开，真实 cell、网格与观看授权沿行为 owner，不因密度调整另造终端尺寸或事实。

启动与恢复的构图、分量、鼠标反馈与动效统一见[《启动与恢复的分量分开》](session-recovery.md#启动与恢复的分量分开)。本段保留 Graphite/Mint、明暗/窄/矮格及真实说明/动作可读性的要求，不再规定 Region 使用应用启动的大图。
