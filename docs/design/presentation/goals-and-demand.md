## Goals 的清单、看板与详情

公开导航与工作面归[《Goals、Focus 与执行工作面》](../behavior/goals-and-demand.md#goalsfocus-与执行工作面)：Mote；Work（Space、Focus、Goals）；Know（Survey、Recall）。Goals 的清单与看板是同一目标集合的投影，Board 是历史或实现用语，不保另一套 Agents／Session／Board 主导航或 Branch × 状态矩阵。

列表、看板和详情的当前视觉规则唯一见[《Goals 的目标正文与对齐密度》](#goals-的目标正文与对齐密度)。卡片先读目标标题、当前结论和目标 Project，稳定 Goal／Demand ID、工作状态、Attempt／Agent 活动及路由依据居次层或按需展开；不把卡片堆成信息表。选中用完整 Surface 与非颜色信号，状态色只补语义，动态仅回应真实执行变化，不用发光装饰。搜索、筛选和唯一创建入口共用低高度工具带；来源与依据只在真实存在时按需阅读。

正常宽度的同屏详情使用连续侧栏，不用弹窗遮住目标列表；窄窗沿可返回的详情面保正文可读，不强留三个不可读窄列。详情、文件、变更、Activity、决策与讨论使用同一容器及原 Tab 语言，精确导航到原工作面才改变空间选择。Mote 快捷面优先对话连续性，执行观察面优先真实状态、Attempt 与下一步；共享身份、状态和项目语汇，不复制同一消息。

## Goal 详情中的 Session Region 投影

Goal 详情的观察投影复用原 Region、arrangement 与身份组件。准确 Project／资源 Workspace、Topic／Branch、Tab／Region 与 Session 层级可展开，完整显示路径不由当前焦点推断；详情中的“进入原工作面”与观察内容有独立命中区，不覆盖正文。多位置绑定沿原空间事实表达，不把一个 Session 强制等同唯一 Region。

观察密度保真实输出、状态、最近活动与进度，输入工具、生命周期操作与主动尺寸控制均由[行为 owner](../behavior/goals-and-demand.md#goal-详情中的-session-观察投影)裁决；窄面不把多个 Region 压成细条，可用原排列／披露入口阅读。详情返回保原选择与位置，未知与尚未恢复使用稳定槽及服务说明，不清空正文。

## Goals 工作区的 Surface

工作面、目标卡与观察 Region 共享[原 Surface token](shared-rules.md#主题与样式-ssot-规范)：工作底、卡片／chrome 与 hover／选中各有主次。区域以留白和 hairline 分隔，边框只表达真实列间、Tab／Region 或输入边界。目标详情是一张连续正文面，不连套“详情卡 → 执行卡 → terminal 卡”；新增边界、阴影或颜色须表达真实交互事实。

## Goal 与 Demand 的命名和投影

公开单项称 Goal，底层 Demand 领域身份、文件和包沿原 owner 保存；执行 Task／Attempt 不与目标同义。GUI 名称、公开 RPC／CLI 和独立文件工具的准确边界只见[《公开名称与接口来源》](../behavior/goals-and-demand.md#公开名称与接口来源)，本页不要求所有 parser、DOM 或领域类型机械改名。

Goals 与 Mote 消费同一[Demand 文件事实](../behavior/goals-and-demand.md#demand-文件事实与独立包)。卡片不复制 Session 状态机，Agent 行不冒充目标。CLI／API、文件读取或 Runtime 查询失败沿原服务窗说明，保已读目标、选择、草稿与关联，不用空列表覆盖工作面。关联 Session 以稳定身份和 Agent／Project 摘要可达，添加、移除与进入原工作面各有明确动作；删除只在准确目标的危险菜单中确认。

## Demand 专属 PMO Tab 的表面

New Goal 与已有目标讨论的实体关系和恢复资格唯一见[《Demand 的专属 PMO Tab》](../behavior/goals-and-demand.md#demand-的专属-pmo-tab)。目标卡与详情保一个紧凑讨论入口，打开后显示主 Mote 中该 Goal 的准确专属 Tab；原 Mote 名／头像、目标标题和执行者各有层级，不能把 Tab 画成新 Mote，也不能暗中合并或更换原 Tab／Session 映射。PMO／主对话的复用关系遵循上述行为合同。当前下一步沿下节呈现，不重复整段对话。

Core 空间 owner 持久化准确 Tab／Region、拓扑与绑定，Client 只呈现原目标。读取或恢复未知时保原 Goal／Tab／Region／Session 与服务窗，不自行新建替代上下文；原 Tab 已权威确认关闭后的显式新讨论按行为 owner 处理。等待目标 Agent 挂载时沿同一 Tab 的真实状态，不先闪回别的目标或旧 PMO。

## Goals 的目标正文与对齐密度

Goals 是安静、紧凑、可连续阅读的目标工作面；行为与事实边界统一见交互 SSOT[《Goals 的 Grill 与 Grounding》](../behavior/goals-and-demand.md#goals-的-grill-与-grounding)。参考 Multica 的正文/讨论优先与渐进属性，不复制其 Web chrome 或复杂字段面。

当前事实与动作使用普通语言，行为归上述交互章节。阅读层级先用目标、成功标准、待决定事项和结果；方法名、版本号与系统身份降为按需解释，不靠增加教程、步骤器或状态卡补救理解。

当前阶段的动作资格归交互 SSOT。每阶段唯一主入口必须能在当前正文或既有工具带直接找到；已确认且尚无结果时，强调原讨论入口，并以短说明指向原讨论/关联工作面继续推进，把发送结果核验请求留作次级。只换名称、同时保留多枚同等强调按钮或只说可以继续而不给入口，都不满足可理解性。

起步 CTA 的点击与探索请求行为唯一归交互 SSOT。紧凑起步区让零门槛探索先可发现，有可信项目时再呈现带项目名的条件入口；既有 New Goal 保留独立的次级创建语义。完整请求句子直接可读，长句在窄窗可换行且仍可操作，不把标签截短后藏另一份首发消息。等待、未知与原地恢复沿既有服务窗，不以大型教程、三张阶段卡、无依据计数或多个同等强调按钮替代起手。入口范围归行为 owner，精确陈列须通过实际图审。

常用请求、项目条件、轻量对话与角色入口范围唯一见交互 SSOT[《Goals 的 Grill 与 Grounding》](../behavior/goals-and-demand.md#goals-的-grill-与-grounding)。首屏沿既有紧凑起步区与连续清单组织，不出现角色选择墙或角色资料表；项目名与所作用的条件入口相邻可读，不能让人猜本次建议针对哪个项目。不将已被替代的角色候选混入入口。

主 bot 待确认与未分配 Project 的行为边界见同一交互章节。主 Mote 的未知请求说明在其 launcher 内就地可读，原请求、未发送事实与明确选择动作保持清楚层级；不以另一 Agent 的绿色默认选中态代替原身份。正常未分配项目不铺大号恢复告示，已有关联的真实失败仍可读。

主 Mote 卡片与上述 launcher 说明保持同一事实，保留引用但状态未知的读法见交互章节；不能在同一个浮窗里同时宣称原 Agent 待确认和「No Agent yet」。

起步区的视觉完成度以当前[《Settings 控制工作面》](settings-and-observation.md#settings-控制工作面)为本产品对照：完整请求是主要阅读对象，准确项目名是相邻次层，进入对话的动作明确可辨；用稳定阅读宽度、字重、留白、轻分隔和统一 Surface 边界形成层次。宽窗不能把短请求拉成横跨整页的空槽，窄窗不能靠缩字、截句或偶然挤排维持布局，也不能留下孤立的句尾或让项目说明挤压请求。起步区与目标清单的低高度管理带分工清楚，保留连续阅读空间。

起步请求形成一个克制的功能组，各动作的命中面、hover、按下与键盘焦点清楚；材质沿既有石墨、薄高光和中性边界，不为每个请求另叠玻璃、装饰渐变、阶段卡或重复图标。完整句子可用语义重点建立字重层次，不能另造短标签替代所见请求。准备中保持原句和作用项目可读，同时有真实文字反馈，不能只把全组变灰或把准备称为已送达；失败与未知的服务窗就地、持续且不遮挡原内容。两种主题以及已知减少动态、透明度或增强对比偏好下仍清楚可用，装饰不订阅无关 Session／Terminal 热路径。三句范围、点击、状态事实与恢复行为只引用 interaction[《Goals 的 Grill 与 Grounding》](../behavior/goals-and-demand.md#goals-的-grill-与-grounding)。实际宽窄初始页、真实项目、操作状态与清单同框的候选须独立逐图审美，修正后重拍；旧入口曾通过的图片不能代签此次品质改进。

常用操作支持自定义与持续收敛，正文与行为唯一归交互 SSOT[《Goals 的 Grill 与 Grounding》](../behavior/goals-and-demand.md#goals-的-grill-与-grounding)。低高度图文起点以完整请求为主，语义插画辅助用途辨认，可信项目与适用 Agent 是相邻次层，管理与收起不争主操作。参考 Settings 的功能分组和图文节奏，不复制品牌 hero 或重复标识；正文阅读上限不固定整页扫描区为居中窄栏，装饰不吞掉连续目标列表，图形失效仍保文字与动作可用。图文品质须由本批实际候选独立审美，旧控件图片、换边框或重复图标不能代签。

新增与管理的控件必须处于图外清楚可读的区域，不遮住品牌主体；进入对话的箭头跟随正文首行，不在正文与项目元信息之间漂移。正常首批操作自然完整呈现；真实长正文或更多操作展开时才共享有界阅读预算，全文仍可键盘滚读且滚动不误发；窄管理使用库与编辑两种状态，返回同一稳定引用，而非把整库堆在编辑正文之前。常用区的正常执行、明确管理和正文编辑三种状态需可辨：新增以一句正文为主，修改同一指令及移出引用有不同语义；完整请求在宽窄窗口发前均可读取，不以截句、短名称或 tooltip 替代。更多操作采用有界渐进展开，展开、收起、管理关闭与排序移除的焦点可追踪；数量增加仍保留 Goals 连续阅读空间。两主题、窄窗长正文/长项目名和真实操作状态都须以本批 Source 的实际整页候选独立审美，旧图片、token 一致或仅采图成功不能替代判断；图形不增加无关 Session/Terminal 热路径工作。

常用操作的后续 Mote 建立项目、需求绑定与执行指派行为唯一归 interaction[《Goals 的 Grill 与 Grounding》](../behavior/goals-and-demand.md#goals-的-grill-与-grounding)；起步图文区不把这些职责画成必经阶段卡、角色入口或额外提交，原可见完整请求和连续目标阅读保持。

常用 CTA 的插画沿[共同美术语言](shared-rules.md#ui-现代化的独立评估边界)，以同族角色姿态、局部动作或抽象意象辅助辨认了解用户并给建议、把想法推进成项目、结合当前／最近项目建议下一步；构图与材质和 Mote 角色系统协调。插画表达请求用途，不充当第二个 Mote 头像；有可信项目时才呈现项目下一步入口的行为仍归交互 owner。自定义指令使用中性构图，完整正文说明用途。插画贴近原完整请求，正文仍是主层，低高度起步区和原管理、更多、项目与 Agent 事实保持，不另加品牌宣传带、重复图标或独立点击目标。需求详情的聊天澄清入口可有同族的小型讨论意象，与原动作和正文协调；发送澄清、打开已有讨论与人的确认仍由原标签和相邻正文区分，插画不暗示目标已确认或结果已接受，不扩大为阶段插画、空报告或第二层身份卡。

### 整页阅读与视觉验收

目标与行为合同唯一归[《Goals 的 Grill 与 Grounding》](../behavior/goals-and-demand.md#goals-的-grill-与-grounding)。初始、清单和详情共享可辨的阅读边线、文字层次和控件语言；参考 Settings 的明确功能分组、真实当前值、紧凑行与可辨入口，让人沿完整页面读懂目标和结果。常用操作的品牌起点与正在阅读的目标形成明确主次；宽窗详情保留足够可扫描的目标导航，窄窗正文与返回沿同一节奏。目标对齐与结果核验各由其真实正文标题、当前事实和相邻动作辨认，成功标准、当前结果、证据及重要差距保持连续对照。清单结论的形态表达当前事实，打开目标的命中与方向可辨，讨论/请求/认可的操作反馈各有落点。属性与技术身份继续渐进展开，标题、正文、控件、服务窗及完整焦点在两主题宽窄下均可读。整页评分须依据可定位的当前候选观察；改进须在真实初始页、混合事实清单及关键目标/结果详情上独立实际看图复核，保留具体修正和原图身份。

### 常用操作的空间与连续列表

常用区优先减少无意义占位，相邻列表与详情只调整相关对齐／边距。行为保留边界只归 interaction[《Goals 的 Grill 与 Grounding》](../behavior/goals-and-demand.md#goals-的-grill-与-grounding)。常用操作是低高度功能起点：各常见 CTA 以完整请求为主，协调且克制的语义插画辅助辨认，自定义指令保持中性，标题不再重复贴品牌图，不独立占据一整块宣传画面，重复的起步 slogan 与空态说明合并。宽窗利用可用宽度让完整请求并列，窄窗按自然阅读顺序换行；正常首批真实请求无需滚过装饰或嵌套滚区才能看全，也不靠默认收起功能冒充省高。更多／长内容才按真实阅读需要有界展开。管理、收起和未保存／未知反馈仍有清楚落点，不能靠缩字、截原句、隐藏真实项目或改正文 owner 换密度。

清单不再固定在居中的窄栏内，新增宽度应增加可扫描的目标。宽窗以标题和相邻 Project／执行事实为主格，真实当前结论为对齐的次格；较窄导航与窄窗自然回到两行，不强制每条目标永远堆成三层，也不把结论变成行内执行按钮。详情导航只占辨认与选择所需宽度，正文从分界附近与原工具带同边线起读，并保合理阅读上限；右侧可以保留阅读留白，不在分界与正文之间制造第二条宽空栏。标题、标准、结果、证据、重要差距和未知保留原字号与完整阅读，不用默认折叠关键信息或缩小全局文字冒充紧凑。空目标仅用一条就地事实指向上方可用起步入口，不重复品牌口号或铺大空卡；真实零匹配仍保完整原因与原地恢复动作。两主题宽窄的初始、混合清单、详情和原管理／草稿返回必须以本批真实 Renderer 完整图独立评审；几何测量只证明空间反例已关闭，不能替代品位判断。

- 首屏保持紧凑起步入口与连续列表；搜索、筛选和视图管理使用一条低高度工具带，不再让七状态、四个宽选择框、重复 Branch Board 导航与空列占满画面。唯一 New Goal 是独立创建入口，不与探索发起混称；筛选收为一个可展开入口，已生效条件才显示紧凑可清除标签。列表/看板切换使用一个克制的图标或 segmented 控件；全局工作面标题不在多个 chrome 重复。
- 默认列表以一条 Goal 为一个阅读单位：可读标题占主层，Project、真实执行摘要与更新事实占次层；待澄清、待决定、待确认、目标已确认、待查看结果或已接受以一条普通短文案表达，未知明确可读。工作状态不与这条结论并列冒充同一种进展；在看板、筛选与属性中保留明确入口。整行点击表示打开目标，当前结论不伪装成直接执行动作；不把 PMO、Grill、Grounding、Open Session 排成一串 CTA。选中使用整行中性 Surface、字重或可辨焦点，不能只靠单边色条。没有 Goal 时只留一句可操作空态；已完成/取消的历史按需展开。
- 可选看板采用单条横向轨道，列在同一水平阅读顺序中，窄窗水平滚动；不允许列换行成上下矩阵。显式筛选某一工作状态时只呈现该状态列，让匹配目标直接可读；清除筛选后恢复原列序。列宽应保证真实标题可读，空列只保留列头、轻量空态和必要命中，不制造高大的 Nothing here 区域。默认不为完成/取消保留整列空白。
- 详情是一张连续正文面，而不是控件卡片集合。标题本身可编辑，用户原话与目标正文保持阅读宽度；目标、成功标准、待决定事项与逐标准结果使用直接的标题，不让 Grill/Grounding 与副标题竞争阅读。正常确认状态直接说明人的认可，版本号不占主要标题行。尚无提案时只呈现意图、简短说明和澄清动作；尚无结果时用低占用说明交代何时核验，不铺出空报告。已有旧版报告和未知/差距保持可见。当前阶段最多一个主动作，确认/接受贴近所作用的正文；打开已有讨论是次级入口，发送澄清或检查请求按其实际作用命名。避免大号步骤器、状态统计卡与套娃边框；其余区域可以按需展开，但重要差距与未知不能藏进菜单。
- 成功标准与结果采用对齐的短行/正文块：先读标准，再读结果结论和证据入口；met/gap/unknown 同时有文字或字形，颜色仅作补充。证据只显示可辨名称与定位入口，完整路径按需读取，长内容可展开；没有证据时显示缺少依据。服务窗紧邻相关失败步骤，以低占用、持续可见的说明和恢复动作表达，不覆盖正文与健康输入。
- 认可回执不明的行为归交互 SSOT《认可回执不明时先读当前事实》。该服务窗只突出一个读取当前提案的恢复动作；清单行的唯一下一步与详情恢复入口使用同一文案，不再添加一枚行内恢复按钮。正常确认/接受与重试不堆成竞争按钮，其他阶段入口收为次级而仍可达。读回失败的原因和保留内容就地可读，不制造遮罩、错误状态卡或让人选择三条相冲突的路径。
- 属性是一组紧凑行内项和命名明确的「更多属性」展开面，保留已有字段编辑能力；空值不画大输入槽，不为默认 Normal、Global 或 0 Sessions 重复制造徽章。执行上下文与活动按需读取，当前相关 Session 可直接进入原工作面，不默认把全部 Tab/Region 树摊满详情首屏。
- New Goal 不再出现事前意图表单，点击后真实 Goal 与同目标专属讨论可辨；创建与恢复行为唯一归交互 SSOT。入口以低占用的短说明让人提前知道会创建待定义目标并打开专属讨论，不把创建讨论表述成开始执行。细虚线表达该目标尚待定义，来自真实目标提案缺席事实，不能靠标题词或新增影子状态判断；已有意图、结果材料及恢复事实仍完整可读，目标提案出现后回到普通边界。必要的 Project 上下文轻量可见，不把草稿画成高大的空占位卡或默认填满标准。正文、控件使用现有 Surface、文字与焦点 token；hairline 只分割真实区域，hover/focus 才显编辑边界。宽窗列表与正文并置，窄窗详情保留返回入口并优先保证正文与动作可读，不把两栏同时压到不可用。新建后的完整宽窄工作面同样执行独立最高审美看图与修正直到满意的既有约束。

- New Goal 打开后的讨论表面须让人辨认「主 Mote 中的该 Goal 专属 Tab」：主 Mote 的既有名称/头像与 Goal 标题各有清楚角色，不把每个 Goal 的讨论 Tab 画成另一个 Mote 对象，不新增并列身份卡或重复人格说明。身份与恢复行为只归 interaction[《Goals 的 Grill 与 Grounding》](../behavior/goals-and-demand.md#goals-的-grill-与-grounding)的「Goal 在主 Mote 中有专属 Tab」，主 Mote 的外观规则沿[《Mote 头像与主 Mote》](../behavior/motes-and-coordination.md#mote-头像与主-mote)。 同一归属覆盖常用探索、New Goal 和已有讨论；主 bot 的真实可读名称/身份与本次 Goal 或探索正文相邻，不能只靠 Mote 图标掩盖换了执行者。已知适用范围冲突、准备/投递未知和真实保留请求用原低占用服务窗说明，仍保完整正文与健康输入；不新增流程卡、系统字段墙或重复确认入口。执行者选择和协调行为唯一归交互 SSOT。

## 协作关系与持续推进的呈现

详情沿同一连续正文面组织：标题及状态、优先级、Project 的紧凑常用属性，目标正文与当前阶段动作，协作关系、Continue，最后是渐进属性与过程记录。负责人和相关会话在同一区域、分别命名；共用有头像、完整名称、Project 和文字状态的可搜索列表，不用系统 select 承载 Agent 列表。多选的已选状态同时有字形/文字及中性 Surface，保留未知身份和准确进入原工作面的入口。列表先将相关且可选的 Agent 按行为 owner 优先，再按项目/Mote 规则排序；新建入口在列表内清楚命名，创建配置与已存在的 Session 不混成同一种选项。

Supervisor 从负责人中明确单选；旁边用原身份头像与完整姓名呈现准确推荐，明确的「设为 Supervisor」一键动作与已保存身份分开，不把默认选中颜色当作推荐或成功。实际提需来源保低占用的参与摘要/按需明细，与负责人和历史分别命名。Goals 设置的默认勾选项说明仅影响新需求首次绑定、不自动开始 Loop，沿既有设置组与草稿/保存反馈。尚未指定时用一个低占用的图文 banner 说明「指定一位负责人持续跟进」，以选择 Supervisor 为唯一主入口；小型轨道/协作意象辅助辨认，不铺 hero、不叠卡片、不挤正文。指定后显示原 Agent 的准确身份与 Continue 控制，已有 loop 始终按原事实可读和可控。未知创建/关联/投递有各自就地、持续的服务窗和原操作检查，不能只显示 spinner 或重做按钮。

更多属性按计划/分类/关系等实际用途紧凑分组，复用应用 SelectionField、弹层、焦点及主题 token；标题、正文与常用项不再重复填表。宽窄、明暗、搜索、键盘返回、长名称、空值、未知引用和保存反馈均保持可读，完整焦点与原草稿可追踪。活动分类让要求变更与阶段证据可区分，长引用按需读取；main、发布及人接受不混成一枚完成标识。

Agent Region 的当前 Goal 标记与原 Agent 身份/状态相邻，标题可辨且点击命中清楚，进入准确详情保留原输入。历史关联不铺为当前工作，长标题不挤掉 Agent 状态与既有 chrome。订阅只消费相关领域事实，不跟随无关 Session 的终端输出重算。实际整页、选择器、未设/已设 Supervisor 与 Region 导航须由独立 Agent 看本批完整图，修正复拍至明确可交付。行为唯一见[负责人、相关会话与当前推进](../behavior/goals-and-demand.md#负责人相关会话与当前推进)。

## Goal 卡片与详情密度

Goals 当前列表、看板和详情密度统一归[《Goals 的目标正文与对齐密度》](#goals-的目标正文与对齐密度)。稳定 Demand ID、优先级、标签、日期、子 Demand 和执行摘要仍按需可达，字段超长省略并保留完整 tooltip/无障碍名称。

Goals 顶部使用一条低高度工具带承载搜索、状态/Project/负责人/标签/日期筛选、视图切换和唯一的新建入口；路由队列作为可切换的同级筛选态，不额外制造一块高大的独立卡片。筛选结果、列计数和空状态在同一条视觉节奏中，批量动作只在确有选中项时出现。

Goal 详情是连续的右侧 surface：标题和状态在短 header 中，属性编辑使用行内 picker/紧凑输入，描述和评论保持阅读宽度；活动与决策收在可展开的时间线分组，进行中的 Goal 工作记录和 Session 固定在上方，历史记录可折叠。删除、取消、停止和重试使用统一危险/次级动作语言，不把运行状态画成第二套卡片。

右侧 Goal 首屏以需求标题、描述和路由属性建立阅读顺序，不重复显示一个静态大标题和一格同文案的 Title 输入框。标题编辑控件呈现为标题本身，描述默认是可直接编辑的正文面；输入框边界仅在 hover/focus 时出现。状态、优先级、Project 排成可换行的紧凑常用属性组；负责人和相关会话统一沿[协作关系与持续推进的呈现](#协作关系与持续推进的呈现)，不重复放进属性表单。标签、日期和批次放在明确命名的可展开“更多属性”区，空值不占据首屏。Session 区紧随需求正文；零 Session 使用短的就地说明，工作拓扑和排列按钮只在有可观察执行内容时出现。窄窗允许属性换行，控件仍保持可读标签和键盘焦点。

多 Session 投影继续复用现有 Region arrangement。卡片只显示可扫描的 Agent topology 摘要，完整 Topic/Branch/Tab/Region 层级在详情内可展开；unknown 或尚未恢复的事实占用同样的稳定槽位，不用空白或跳动布局掩盖缺口。
> 命名更新：历史 “Leader Topic” 与 “PMO Teams Topic” 现称 **Mote**；视觉与密度约束继续有效，当前产品身份由交互 SSOT[《Space、Folder 与 Topic》](../behavior/spaces-and-layout.md#spacefolder-与-topic)定义。
