## Agent 输入行密度

- Agent 输入区采用紧凑文本区和一排具名快捷工具；文件、截屏、技能、指令可直接辨认。主按钮与生命周期动作的区分沿[《Message Tools 主按钮密度》](#message-tools-主按钮密度)；收起后保留轻量恢复入口与草稿提示。行为见[《可收起的 Agent 快捷输入区》](../behavior/conversation-input.md#可收起的-agent-快捷输入区)。
- 展开/收起按钮与快捷工具同排并置于最左端，避免为单一开关增加独立占高；按钮保持与同排工具一致的尺度、焦点和 tooltip 语言。

- Agent 身份的来源与行为按交互合同[《Agent Region 关闭与身份入口》](../behavior/spaces-and-layout.md#agent-region-关闭与身份入口)，顶栏呈现只按[《Agent Region 的关闭与动作密度》](spaces-and-layout.md#agent-region-的关闭与动作密度)执行；输入区仅保留原输入模式与动作密度，不重复名字或补一条身份 toolbar。
- Terminal/Activity 视图切换使用一个 28px 左右的图标按钮，不使用常驻的双按钮分段控件；图标只表达下一步动作，焦点环和 tooltip 保留可发现性。

## Message Tool 输入历史列表

历史查询沿现有 Message Tool 的历史区展开，保留待发列表和历史阅读的清楚分工，不在输入区增加常驻第二套消息列表。列表顶部以一行查询输入与明确搜索动作起步，正文优先；来源与记录时间是紧凑的次级信息，缺失事实用短说明，不堆叠原生标识和技术详情。

每行可读正文摘要、真实来源和清楚的回填动作；长正文及资源沿原阅读组件展开，复制与填入草稿分开，不能让点击阅读暗中发送。查询中、部分范围、可继续读取、不可用与确实无匹配就地呈现，已有结果仍可使用。正常与窄工作面保留查询、结果及原草稿的可读空间，键盘焦点与关闭返回路径明确；行为边界唯一见[按 Agent 的输入历史](../behavior/conversation-input.md#message-tool-按-agent-的输入历史)。

## System Reminder 的默认与本次控件

两层选择的行为唯一见交互 SSOT《[System Reminder 的默认与单次选择](../behavior/conversation-input.md#system-reminder-的默认与单次选择)》。Settings 与 Launch 复用各自既有表单的轻量 checkbox、标签与键盘焦点语言，明确区分「默认开启」和「本次会话开启」，继承说明只出现一次；不为一个布尔选择新增设置页、独立状态条或装饰卡片。宽窄窗口的名称、当前选择和必要说明均可读，原固定关闭／保存动作与输入工作面保持。提醒语义尚未确认时，本段只记录已确认的控件约束，不宣称产品已提供开关或提醒能力。

## 输入区 Context 监控

- Agent 名册与工作区 Agents 列表复用紧凑行内数字徽章，两档压力可区分，不给每行增加完整监控条；数值来源、阈值和未知边界只在交互合同「当前 Agent 的上下文余量与输入焦点」定义。

- 上下文余量使用工具行内低干扰的短标签，悬停以原详情浮层说明容量、已用／剩余量与采样时刻；浮层可移入阅读，点击／键盘／触屏可明确固定。宽窄与明暗保持完整数字、单位和焦点，详情不被输入框或窗口边缘裁切；未知明确显示，不为监控单独增加一整行。行为见交互合同「当前 Agent 的上下文余量与输入焦点」。

## Composer 状态与队列密度
- 三态入口固定在左侧：一行态与输入同排，展开态在工具行起点；工具行与大输入框的入口位置一致。大输入框给出受视口约束的实际编辑高度，空内容也可辨；展开/收起图形表达下一动作，仍沿用无边框、低干扰控件语言。行为唯一来源见交互合同 Message Tools 三态约束。
- Context 使用紧凑徽标，不在输入区占据独立大行；hover 提供精确 token 与更新时间。
- Send 与 Interrupt 继续表达发送和中断当轮两个不同意图；待发摘要、数量与对应的显式发送按下节[《输入框外的待发提示》](#输入框外的待发提示)呈现，不在输入工具行另叠一组常驻按钮。外部队列动作不能冒充提交当前草稿或中断当轮。
- 待发内容在输入编辑区外以短摘要、数量与真实状态可辨，完整内容、顺序、失败原因和原操作仍在同一 Outbox；移动与入队时间保持紧凑次层，不另建展开面板或常驻大行。行为约束只见[《Composer 消息队列与紧凑状态》](../behavior/conversation-input.md#composer-消息队列与紧凑状态)。

- **工具行必须能在窄宽度下收窄，而不是折成多行。** 窄到放不下时按「先丢文字、后丢控件」降级为图标态（tooltip 与可访问名保留全文），常态行高不因窄宽度而增加。Composer 所在的 Region 可被分屏拖窄，故这里量的是**该组件自己的可用宽度**，不是窗口宽度——用窗口断点会在窄分屏里完全不触发。折行是本条要禁止的形态：工具行折行会把主动作挤到第三行，也会让任何依赖「工具行只有一行」的避让一起错位。

### 输入框外的待发提示

有待发内容时，紧凑卡片真正浮于所属 Message Tool 上方，贴近所属工具并保留短而可辨的真实间隙，不能隔着大块无内容空档。卡堆的右下角同时是定位锚点与 3D 旋转中心，对准 Message Tool 本体的右上角，与终端工作面的右边缘统一对齐；原生终端刷新、滚动、工具高度变化和布局移动后仍保持这个位置，不漂到终端上部。可见原生输入行的必要避让只形成贴近工具的安全间隙，不将整堆卡片推远。宽度随内容收缩并设上限，长摘要截断，窄分屏按组件可用宽度收窄，不占满正常宽度的整行。浮层没有承载整条提示的横向背景，不与底部工具本体连成一块，也不在正常布局中占高。每条卡片的摘要、当前状态与右侧操作共处紧凑单行，不因状态另起第二行；正文优先，状态仍可辨，完整原因按需读全。右侧按钮简洁、同尺度且主次清楚，次级操作可按需披露，不用宽重按钮簇挤掉正文；发送、复制、编辑及原更多操作仍可达。真实数量独立可辨，不把排队表现为发送动画。无内容不画空条、不留空槽，不增加常驻工具栏。完整队列继续在共享 Outbox，未知与等待原因可读，不靠红色大横幅说明。

排队通过真实消息卡片的 3D 叠加表达：未悬停的排队静息态即有清楚可辨的深度与高度层次，不能用几条细边缘或单张卡片的阴影代替。露出的卡片部分能辨认并成为逐条悬停的入口；悬停与键盘聚焦使对应卡片成为可读主层，其原文、状态与动作清楚可辨。每条待发卡片均可发现，长队列沿有界空间提供清楚的遍历入口和当前位置，不以总数替代剩余条目；整体呈现高度有界，不随队列数量无止境长成纵向列表。真实数量仍准确可读，单条不伪造排队叠层。 多卡滚动延续同一 3D 空间：进入、经过与离开可读前层的卡片随视口位置改变纵深与倾斜，不能把长队列退成平面的上下滑动；运动连续且克制，不自动发送、更换消息身份或抢焦点。悬停与键盘焦点仍把准确卡片抬成可读主层，动作可达；减少动态时保留静态深度、逐条遍历与原操作。卡片保持紧凑、简约、精致，减少动态效果时保留静态空间层次与聚焦反馈。

窄分屏按所属组件的可用宽度收窄摘要，发送、复制、编辑与更多动作均有稳定命中和完整可访问名称；卡片保持单行摘要，全文披露与编辑区在浮层内有界滚动，保存与取消含义明确，不把长消息、编辑区或操作组挤出工作面。全文披露沿[行为合同同名小节](../behavior/conversation-input.md#输入框外的待发提示)，复制反馈沿[《统一对话阅读与简明操作》](#统一对话阅读与简明操作)。出现、退出和聚焦均保留原输入区与终端几何，贴近工具也不能遮原生终端输入、编辑文字或 IME 候选，不妨碍终端连续阅读，不抢焦点、替换编辑节点或丢草稿。静息默认优先显示准确在途条目；没有在途条目时才展示下条可投递消息，逐条查看仍保持各卡片原身份与真实状态。实际几何、可辨的 3D 层次、逐条操作及明暗宽窄完整代表图须独立评审，采图成功不代表可交付；发送与状态事实唯一遵守[行为合同同名小节](../behavior/conversation-input.md#输入框外的待发提示)。

## 持续推进观察界面

- 持续推进复用邮箱这一枚常驻入口，收进浮层内有明确标题的 Progress 独立页；Composer 不再增加独立 summary 行或另一枚循环按钮。邮箱图形、Inbox 未读数字、Notices 提示与循环状态标识各有自己的含义，不相加或重叠，入口语义及密度沿[《入口提示的清楚含义》](#入口提示的清楚含义)；未启用保持安静，active、paused、unknown 用形状与完整可访问说明区分，不能仅靠颜色。现有 Agent 卡片的低干扰循环标记仍属其原观察位置。
- 展开轻量面板呈现已有的精确目标、可选任务来源、分别标注的 Agent／循环状态、实际最近／下次检查和最近决定；完整原因与未知事实可读。没有来源的时间／决定不补造活动、回执或事件列表；不为展示新增事件历史。时间与状态的行为边界只见交互合同[《持续推进与邮箱共享入口》](../behavior/conversation-input.md#持续推进与邮箱共享入口)。
- 邮件分区与 Progress 页使用同一浮层边界和紧凑短标签，正常与窄分屏都能识别并进入各页；标签与必要计数不得挤出视口或强迫用户横向寻找入口。内容在浮层内有界滚动，原正文与操作组不因页切换被推高；Progress 标题表达持续推进而不冒充来信，完整目标、状态与原因仍可读。选择、焦点与关闭沿现有控件语言，不堆叠第二层 tabs、标题栏或卡片。
- 展开设置沿同一紧凑表单语言：分钟数字、续行文案和来源字段有清楚的标签、内距、边界与焦点；只有编辑字段随可用宽度伸展。来源绑定的复选框保留自身尺寸，与标签共享一行，不漂到行中央或与说明分离；正常和窄分屏都保持可读、可点击，不靠缩小字号过关。
- 暂停、恢复、停止循环、立即检查、设置和任务记录保持可达；停止循环与中断 Agent 的标签必须区分。错误有对象、原因和可操作入口，不出现无解释的空白面板。
- 草稿或队列占用、输入栅栏变动与观察未知的暂停原因进入同一 Progress 页的循环详情，不另建输入状态面。续行提示沿原编辑控件的组字语言，组字与只读占用边界只定义在交互合同[《内置任务持续推进》](../behavior/conversation-input.md#内置任务持续推进aftertime-使用需求)。
- 可选任务来源在现展开面板显示绑定身份和最近核验结果；显式 root、Feature ID、公开脚本沿同一设置面输入，不新增任务看板。完成与未知语言、任务来源合同唯一见[内置任务持续推进](../behavior/conversation-input.md#内置任务持续推进aftertime-使用需求)。
- 调度、投递与完成规则只由 [Desktop interaction](../behavior/conversation-input.md#内置任务持续推进aftertime-使用需求) 定义；共享入口、页切换、未读与表单保留只见其[《持续推进与邮箱共享入口》](../behavior/conversation-input.md#持续推进与邮箱共享入口)。

用户进一步要求 Progress「重新设计」「现代化一点，至少有『设置』界面的水准」。该页沿当前 Settings 的轻分组、对齐字段、可读实色控件与焦点语言：一次阅读只呈现配置或当前循环这个主对象，不复制整屏 Settings 导航、Overview 大标题或卡片套卡片。基础字段与操作沿 `--fs-body`，说明用 `--fs-meta`，精确标识可用次级等宽字；不靠缩字号或降低对比获得紧凑。

- 未启用首屏突出周期（明确 minutes 单位）、续行主编辑区和唯一启用动作；只读任务来源作为有明确标签与说明的可选组，原复选框保持固有尺寸和整行标签，绑定后同组展开三个字段。字段边界、内距、字形、focus／disabled 与当前 Settings 同一 token 家族，正常宽度对齐，窄栏转为清楚纵向阅读而不把复选框拉满。
- 启用首屏突出已确认的循环状态、分别标注的 Agent 状态及真实下一检查；Pause／Resume、Check now 与 Stop loop 用紧凑有文字控件，主次可辨，只有真实语义使用状态色。最近决定是可读正文，原周期／续行／来源以同面的只读配置披露，不与可编辑表单混淆。精确目标以可发现的原生 details 展开，长路径与标识可换行、选取和读全，不把它们固定铺在主操作之前。
- unconfirmed／错误优先用完整状态与原因表达，已知旧循环事实退为有说明的次级信息；不重复画 Agent 灯、假时间计量或无解释空卡。沿现有有界浮层及固定邮箱导航／关闭入口；320 窄栏与矮面可滚到字段、完整决定和全部实际动作，正文不裁原因，操作组不横向溢出，原 24px 工具带、草稿与 Terminal 几何保持。切页／关闭／披露的表单保留与控制边界只见交互同名小节。

## Message Tools 快捷语法

- 工具行提供统一入口；`@`、`/`、`$` 的补全面板使用与 Session Composer 相同的紧凑菜单和来源标识。不可用能力显示原因，不占用单独常驻行。
- 初始页与已连接 Session 的工具视觉语言一致，差异只体现在项目上下文或 Provider 能力尚未就绪。

## 输入错误与浏览器选中态

- Message Tools 的等待与失败提醒及完整诊断沿[《Message Tool 的等待与失败说明》](agent-capabilities-and-messaging.md#message-tool-的等待与失败说明)的右侧 SessionMailbox 处理面呈现，输入编辑区与工具行保持原阅读和操作空间。
- Browser Region 选中态使用与其他 Region 相同的低对比边框/标题强调，点击内容后保持可见，不增加额外装饰。

## Message Tool candidate density
候选菜单统一复用 Message Tool 的浮层，不改变工具栏高度；菜单有边界和内部滚动，方向键与 Enter/Escape 操作一致。候选项以紧凑的图标、名称和一行辅助信息呈现。

按来源分段时，段标题沿用本仓已有的**分段标题语汇**（micro 字号、大写、字距、次级文字色），不新造第二种标题形态；标题在滚动时吸顶，使长列表里当前段的归属始终可见。**只有确实存在两个以上来源时才出现标题**——单一来源加标题等于给一份列表起个多余的名字。段序由候选自身的拼装顺序决定，不另立一张优先级表。

候选项重名时必须能看出**是哪一个**：同名但来自不同来源的两条（例如不同插件各带一个 `configure`）要带上足以区分的来源标记；而**同一条** skill 被同一来源重复收进来若干次（安装缓存与市场副本并存、镜像目录各算一遍）不是"需要区分"，是不该出现第二条——前者靠标注解决，后者靠去重解决，两者不是同一个问题。

## Composer 静息密度与主操作
初始形态沿行为合同[《Composer 静息形态与主操作》](../behavior/conversation-input.md#composer-静息形态与主操作)选择，默认**一行**；设置中的“两行”表达输入行加工具行。两种初始形态复用原有档位的尺寸与控件，不引入新的视觉状态。一行态是最安静的形态，其控件密度也必须最低——切换键在一行态同高但更安静、不带重边框；两行与大输入框档位才允许更强的存在感。发送与中断在同一主按钮格内按真实状态切换，图形与材质唯一见[《Message Tools 主按钮密度》](#message-tools-主按钮密度)；结束 Session 等生命周期破坏性操作使用危险语义，不把中断当前回复表达成会话销毁。

**一行态里那一行文字垂直居中，不下沉贴底。** 用户原话：「message tool 只有一行时，文字下对齐会导致视觉不均衡」。一行态是网格布局，行高由较高的工具列决定；那一行文字必须在这个行高里垂直居中，不能沉到底部留出上方空档。工具与主操作控件仍锚在底部（编辑区涨到多行时它们留在下缘才对），这与文字居中不矛盾。

**一行态左侧工具列按实际内容宽度撑，不预留固定的空档。** 用户原话：「Message tool 的输入框，如果是一行的模式下，输入位置到前面的 padding 很大」。一行态左侧固定放三态入口与视图切换键这一簇，是设计既定的位置。但这一簇的宽度必须**按其实际内容撑**，不是被一条固定最大值的轨道反手撑到那个最大值——那样在弹性布局中会在图标与编辑区之间留出可见的空档。轨道仍保有一个宽度上限用于抵御未来工具集变宽，只是"上限"和"预留"必须分开：内容窄时轨道就窄，只有内容真会更宽时才夹到上限。

 用户再次反馈：「比如 message tool 的一行模式，现在 input 离左边的 icon 建立很远，这个是修过的」。一行输入文字与左侧图标簇之间不得重新出现无内容的宽空档；这项已修过的密度约束在并行集成、构建与实际安装后仍须成立。已交付优化的保留与取证边界见交互 SSOT[《已交付优化的保留与取证》](../behavior/conversation-input.md#已交付优化的保留与取证)。


## Message Tools 身份与切换稳定性

- 身份在右侧，仅保留 Agent 头像，不与左侧功能按钮混排；全名与状态进入提示和可访问名称。行为以交互合同的 Message Tools 身份约束为准。

Control／CLI 的发送语义沿交互 SSOT[《Composer 静息形态与主操作》](../behavior/conversation-input.md#composer-静息形态与主操作)中的直接 steer 规则统一定义，不增加控件或第二套授权状态。
- 用户反馈「换左下角切换图标的时候，高度好像不一致，导致高度在抖」。三态共用等高的工具命中区和纵向对齐；一行态的低干扰只通过视觉权重表达，不再靠缩短按钮制造高度差。仅编辑区按三态改变高度，工具行不能因换图标、隐藏文字或切换状态额外跳动。

## Message Tools 邮箱

协作列表首屏优先呈现查找、已加载范围和原记录；通用用途与完成边界说明以有文字的原生披露按需阅读，不在结果前重复铺多段说明。查询范围、未知、失败与恢复动作仍就地可见，详情中的业务状态不因视觉收纳而隐藏；开合不触发读取、投递或切换所选记录。

邮箱使用直观的信封图标，与右侧 Agent 头像组成一个紧凑入口；位置不受左侧工具展开／折叠影响，不再散成两个独立小图标。入口 Inbox 数字和 Notices 提示按下节[《入口提示的清楚含义》](#入口提示的清楚含义)分别呈现，旧的红色总未读角标和入口 pending 数字不继续保留。Inbox、Outbox、Notices 共用一个有界内容面，阅读层次见本节[《内部信息流与完整阅读》](#内部信息流与完整阅读)；Progress 页与循环标识只见[《持续推进观察界面》](#持续推进观察界面)。会话入口与其他控件等高，一行态也不消失；通知到达和阅读不能撑高输入框。行为约束只见[行为合同同名小节](../behavior/conversation-input.md#message-tools-邮箱)。

悬停预览与显式打开沿同一邮箱内容面，不增加第二个预览卡片或常驻入口；待发队列与发件历史分段清楚，时间未记录的告示说明保持低干扰且可读。悬停、已读、最近顺序与待发队列边界只定义在交互 SSOT 的《Message Tools 邮箱／悬停访问与最近顺序》。

紧凑消息卡片与展开邮箱沿所属 Message Tool 的同一右侧锚点交接：先保持两态合法终点一致，再以原短时长、自然减速曲线平滑展开与收回。保留原 DOM、字号和交互 owner，不以整体缩字、复制可操作层或延迟消息状态制造过渡。快速反向、Region 调整、目标变化、隐藏及卸载时接续或取消到当前合法终点，不留旧层命中、迟到动作或常驻逐帧观察；减少动态时即时切换。过渡保护原 IME、焦点、编辑节点、草稿、Terminal 与相邻工作面，不通过动画输入框高度让 PTY 逐帧适配。当前生产消费者的中间帧、端点与操作必须经独立 Agent 实际看图确认。

用户此前反馈「现在 mailbox 上的红点感觉太大了」，留下的约束是提示轻量、数字保持现有10px下限与完整可读，不能缩字、裁字、整体缩放或降低不透明度；原 Range 可读性容差不放宽。旧红底10px／11px及左上数字的位置约定已由下节的新入口含义替代。24px工具带高度、Progress独立标识、相邻头像与原草稿／Terminal几何保持；新入口的完整代表图仍须确认提示清楚且不显得都是错误，局部尺寸断言不替代视觉结论。

### 入口提示的清楚含义

邮箱信封右侧的小数字沿用户认可的轻巧旁置阅读感，只表示 Inbox 未读；使用现有中性文字／主题 accent，不用红色告警底或同时再画红点。数字字形使用现有10px下限和清楚对比，1／两位／99+完整可读；零未读时不渲染数字或预留空槽，信封到 Agent 头像之间不留下无含义的空白；有未读数字时才保留容纳99+的固定数字宽度，位数变化不挤字。入口仅随真实可见提示内容伸缩，原编辑节点、草稿与焦点保留。该区属于邮箱入口自身，不进入右侧头像状态角；24px是原工具命中高度，不把它误当固定24px宽或借改提示放大控件。

Notices 与 Progress 使用同一邮箱按钮内居中对齐的独立小图形，与信封、数字和右侧 Agent 状态各自可辨；不把铃铛浮到工具带上沿或叠在信封角上，不重叠或预留缺席提示的空位。Notices 沿现有 amber 表示需要阅读的告示，零未读时整枚缺席；不沿用总未读红色胶囊，不把普通 Inbox 来信染成错误。提示形状与 tooltip／准确可访问说明共同表达，不只靠颜色。入口不再旁置 pending 数字；Outbox 标签仍显示实际正数 pending，并给出准确含义。数字／告示／待发的事实与已读边界只定义在[行为合同同名小节](../behavior/conversation-input.md#入口提示的清楚含义)。

正常640／窄320、明暗、长草稿及三种输入形态中，0／1／两位／99+、Inbox-only／Notices-only／同时出现和阅读归零保持工具带高度、Composer编辑节点／草稿／焦点和Terminal rows／光标／输入；入口宽度只随真实可见提示伸缩；未读数字、告示提示、Progress及相邻头像均完整可辨。告示不闪烁、不新增动画／第二状态灯或整条告警色。独立 Agent 在真实完整图里须确认数字含义易懂、普通来信不像错误、告示又能被发现；采图成功或CSS值扫描不能代替看图结论。

### 内部信息流与完整阅读

标题／关闭与分类导航在长列表、长正文和矮面内保持固定且可达，只有当前页内容滚动；单条详情沿同一层内容面，有明确返回入口，不叠第二个 popover。正常与窄分屏先能扫到真实记录的对象、短正文预览、来源／状态及紧凑原始时间；时间完整表达可达，未知不因压缩而消失。预览只摘取原文可见开头，不生成摘要事实，长内容有清楚的完整阅读入口；详情正文不缩字、不截断、不借整条长卡把导航或其它记录推出可读范围。

Outbox 的 Pending 与 History 有轻量分段和不同次序的可辨关系；空 Pending 不以长说明占据首屏，分页／读取问题在 History 内可发现，重复流程说明不挤掉实际消息与对应可用动作。System 摘要中的问题、影响与恢复动作有主次，完整原文仍可滚读；Progress 当前状态与配置属于该页自己的结构，不套成消息卡或混入 History。选择态用现有整面填充／文字与非颜色信号，不用单侧细线或告警色假装选中。

同一阅读规则覆盖 Inbox、Outbox 与 System，正文 DOM 只挂当前页有界原文摘要与显式打开的单对象全文，隐藏页不常驻整批长正文；Progress 的原常驻表单与单一观察是按其合同保留的例外，不新增观察。原字体／密度 token、24px 工具带和入口命中区保持。长草稿、计数变化、阅读展开／返回不重排 Composer 或 Terminal；明暗、正常640与窄320、短矮面里至少一条真实摘要／动作与关闭入口可达，正文可读到末尾。分类、详情身份、已读、时间、投递与动作边界只见交互 SSOT 的同名小节。


### 统一对话阅读与简明操作

Collaboration 沿同层邮箱导航，清楚注明仅原 Dispatch 监督链；首层看原双方与通信等待，消息正文、投递与监督分别可读，长身份及原证据按需展开。读取失败就地保记录及重读入口，空列表不声称没有普通 A2A 消息；不添无依据计数、通用成功绿点或新任务图，事实边界只见[协作合同](../behavior/agent-capabilities-and-messaging.md#交出去与派出去)。

协作查找沿原紧凑输入与选择控件，名称／通信状态是列表主层，原身份为次层；查找范围、匹配数量与清除入口就近可见，不加常驻说明大卡。选中详情保独立阅读，返回原列表仍保原查询和位置。证据复制置于所选记录的轻量动作带，与返回和刷新有清楚分工；保复制反馈、可访问名称与键盘焦点。正常、窄320和短矮面中输入、过滤、关闭、原正文末尾与必要动作均可达，不缩原正文字号，不重排 Composer／Terminal。

用户要求完整 Mailbox「选项清楚、不要到处都是字、现代化」，以现有 Settings 的轻分组、对齐控件、清楚文字与 focus 完成度为直接参照。采用紧凑中性内容面：头部只必要 Mailbox 标题／当前目标和关闭；Inbox、Outbox、Notices 是一致 icon＋短 label＋正数行动 badge 的同层阅读导航，Progress 用有文字的独立工具入口可发现，不混成第四种邮件、不另加模式条。所选页以整面轻填充／字重及 aria-selected 表明，不靠单侧细 rail；导航数字语义只见[行为合同同名小节](../behavior/conversation-input.md#统一对话阅读与简明操作)。

列表按头像／作者身份与紧凑真实时间、两行正文开头组织；两行摘要与原240字符预算不变，协议头到正文的有界投影只依[行为合同同名小节](../behavior/conversation-input.md#统一对话阅读与简明操作)，不为每条 parse 全文或重复操作口号。使用同族 avatar 和现有字体／间距 token，让正文是主要扫描对象；已知正常记录不逐行堆来源、成功状态或 Read full message。异常使用短可见状态而不整卡告警色。Notices 先问题，类型／时间为辅助；Pending 与 History 用短分段标题和必要本区数量，不卡片套卡片。空态是一枚有识别性的图标、一句对象标题、最多一条必要提示。

同层单对象详情呈现各 client 共用的 ConversationMessage 紧凑阅读：头像／作者、正文 Markdown、紧凑时间和共享 Copy 有清楚主次，来源／完整时间／投递事实通过可发现 disclosure 读全。紧凑呈现是同一共享阅读层的明确选项，正文与阅读控件沿其统一样式；宿主负责邮箱容器、主题与真实身份材质，不另维护对话阅读外观副本。共享阅读层与宿主能力的职责只见[行为合同同名小节](../behavior/conversation-input.md#统一对话阅读与简明操作)。正文不缩字、不裁尾，不堆多套身份栏或复制按钮；紧凑模式不能改普通对话外观或事实。Pending 的 Send 是可见文字主按钮，移动／复制／移除为中性低层级 icon 动作，保持现有命中与 focus，并有 tooltip／可访问名称；说明只随真实风险就近出现。按钮、色彩和材质沿现 Settings／Conversation token，不引入新 palette、玻璃大卡、装饰 banner 或动效噪声。

待发卡片的复制动作在点击处有即时交互反馈，真实成功后出现可见的成功标记和克制短动效，不能只改 tooltip／title 让用户看不到结果；反馈不挪动原命中区或改变卡片高度。减少动态效果时保留清楚的静态成功反馈。成功、失败与未确认的事实唯一沿[行为合同同名小节](../behavior/conversation-input.md#统一对话阅读与简明操作)的原 Clipboard 结果，不在呈现层抢先宣布复制成功。

标题／关闭、同层导航及详情 Back 在长正文与矮面内保持固定可达，只有当前内容区滚动；Back 回原列表阅读位置。各页切换不卸载 Progress 表单或增加无关观察。正常640与窄320、明暗、短矮面、长草稿中至少一条真实摘要／当前动作及关闭入口可读；正文／长路径／代码可完整滚读，整面不横溢出、不以缩字换空间。原24px工具带与入口、[新数字／告示提示](#入口提示的清楚含义)、Progress及相邻头像、Composer及Terminal实例／rows／光标几何不变；pending提示保在Outbox标签。

独立 Agent 须在真实产品组合的完整代表图中判断导航含义、对象优先、文案节制、Markdown详情、主次动作与 Settings 同族完成度，修正后重拍；采图成功／像素断言不替代审美通过。已读、作者／投递／时间、原始复制、来源打开及队列 owner 只定义在[行为合同同名小节](../behavior/conversation-input.md#统一对话阅读与简明操作)；本节定义邮箱列表与详情的视觉层次，其他阅读节引用本节，不另列行为定义。

### 邮箱记录一键定位对话

“在对话中查看”是记录的次级阅读动作，在 Inbox／Outbox 记录列表和共享 ConversationMessage 的单对象详情中可直接发现；沿同族紧凑按钮／图标与可见短文字，不用无名称图标或藏在多层菜单中。列表的正文阅读命中与定位按钮并列且独立，详情沿共享阅读层的动作区，不复制卡片或挤掉唯一 Send。正常与窄栏可键盘到达、焦点明确、有准确可访问名称；24px 工具带、原字号、草稿与 Terminal 几何不因入口出现而变化。

准确记录进入对话可读视口后，用短暂整面轻填充和非颜色提示标明“已定位此消息”；不以单侧细 rail、告警色或永久选中灯代替位置反馈，不改变作者／投递状态。减少动态效果偏好下不强制平滑滚动或动画。投递状态与位置说明各自简短可辨；未加载、未找到、来源变化或读取失败的说明贴近该记录，能继续读原文／复制，不盖过输入、正常消息与健康 Terminal。详细身份、读取、迟到与 Run 边界只定义在[行为合同同名小节](../behavior/conversation-input.md#邮箱记录一键定位对话)。完整代表图须同时可辨卡片定位入口、准确对话位置与原草稿／邻面，不以采图成功或像素断言替代独立看图结论。

### 当前查看位置与路径

Mailbox 已有记录的单对象详情用一行紧凑的“当前对话位置”概要呈现已确认的资源项目／Space 名、Tab 显示名与 Region 标识，让用户辨认将在哪个工作面查看；它独立于身份头栏，位于原详情内容中，不添常驻 toolbar、位置卡片或列表逐条路径。名字保持可读宽度，长值可省略显示但完整值可访问；Region 短标识不代替完整地址。队列条目的定位概要是否存在只沿[《邮箱记录一键定位对话》](../behavior/conversation-input.md#邮箱记录一键定位对话)，Info 继续读取所属 Session 当前执行资料。当前位置、资源项目与执行目录的事实归[行为合同同名小节](../behavior/conversation-input.md#当前查看位置与路径)。

完整资料进入现有 Info 的轻量披露：当前显示 Workspace／Group／Tab／Region 的完整身份、已确认资源 Project 的名称及项目根目录、Workspace／worktree 目录和分支、Session 执行 Host 与 cwd 各有明确标签。与现有 Current sender 分开阅读，不用一条无标签路径混合查看位置、执行目录或发件人资料。未确认或未记录的值使用短文字说明，不留伪地址、空装饰行或假的项目图标；已知值仍可读全与选择。

概要、Info、原文 Copy、定位与 Pending 原动作沿现共享详情层级，命中与键盘焦点独立且清楚。640 与 320 的明暗完整工作面中，长项目名、Tab 名、路径和 ID 可读、可展开或换行，身份与正文不被挤成纵列；投递与位置说明、Send、Copy、返回与关闭可发现。仍用原字号、token 与有界内容滚动，不抬高 24px 工具带、不横溢出、不挤占草稿或原 Terminal。新增概要与展开 Info 的真实完整代表图须由独立 Agent 实际审阅，采图或尺寸断言不代替审美通过。

## 显式文件引用

显式选择的普通文件沿原行内引用的图标、字号和表面显示简短文件名，准确完整路径按需阅读；详情不遮住相邻输入，长路径自然换行。小移除动作主次清楚，细指针 hover／focus 显露，无 hover 可见；名称／路径阅读与移除命中分开，键盘可达，原正文、草稿和图片行高保持。行为见交互合同[《显式选择的文件引用》](../behavior/conversation-input.md#显式选择的文件引用)。

## 输入框图片

草稿图片的移除动作以小型语义叉号叠在缩略图右上角，不再在旁边占一列或比行内缩略图更醒目；其命中与预览独立，不嵌套按钮。细指针悬停图片或动作、键盘焦点进入该图片时显露，无悬停／触屏环境保持可见并保留易点中的透明命中范围；不能让仅 hover 的显示方式拿走键盘或触屏操作。失败或加载中的原引用仍有准确且不遮文字的移除动作。沿原行高、图片比例和语义图标，窄窗不撑宽输入，焦点清楚；事务和资源保全只见交互合同[《输入框截图缩略图》](../behavior/conversation-input.md#输入框截图缩略图)。

截图授权、取消与失败反馈留在原 Message Tools 的局部处理面，密度与披露沿[《Message Tool 的等待与失败说明》](agent-capabilities-and-messaging.md#message-tool-的等待与失败说明)；不能用重复模态授权提醒打断输入或遮挡健康终端。恢复说明准确指出当前运行副本，不把「已在设置中授权但当前副本不可用」画成用户没有授权。行为真源见交互 SSOT[《Message Tools 失败反馈与 Browser Region 选中态》](../behavior/conversation-input.md#message-tools-失败反馈与-browser-region-选中态)。

截图/粘贴图片在输入文本流中显示等高缩略图；一行态保持原行高，展开编辑时缩略图随内容流排列。图片比例保持，点击可放大，不能用长路径挤占输入区。读取失败仍显示引用文字。行为见交互 SSOT 的“输入框截图缩略图”。

成功加载后的预览框随实际缩略图收紧宽度，不按原图固有宽度或竖图的行高预留空白；横图、竖图、方图及重复引用保持自然比例，关闭角标仍贴着所属图片。仅为读取中或失败的文字引用保留可读空间，不能让占位宽度继续撑开已解码的图片。

## Message Tools 右侧操作整体

无悬停或粗指针输入下，紧凑工具的实际点击区须易用且彼此独立，包含发送、邮箱、上下文与展开入口；可采用独立触屏尺寸或安全命中扩展，但不得覆盖相邻动作、正文或编辑器。触屏适配沿原按组件宽度的收纳与重排规则，窄区可使用既有双行，保持原输入可用且不以透明命中覆盖草稿；细指针仍保24px视觉密度与原工具排列。

用量、主操作、邮箱和头像读作一条紧凑操作组，共用连续底色与圆角边界。细指针下点击区 24px 等高、图形视觉等距，触屏命中沿本节前述约束；静息不各自画色块，hover、键盘焦点和展开态保持可辨。

主按钮和行内图片的预算唯一见[《Message Tools 主按钮密度》](#message-tools-主按钮密度)，本节只定义整组对齐与身份角标。

头像中央 Provider、左上自定义角标、右上状态、右下数量互不挤占；描边沿图形透明轮廓，不画外接矩形。运行状态不改变中央身份色。作为状态与关联动作入口，此处 running 用安静蓝色空心标记，working 用绿色活动标记，颜色和形状同时可辨；正常结束保持中性，真实错误才红色。该入口角标不同于普通导航身份的提醒预算，后者见[《状态标记与 Executor 叠加密度》](agent-capabilities-and-messaging.md#状态标记与-executor-叠加密度)。邮箱提示归独立信封，含义沿[《入口提示的清楚含义》](#入口提示的清楚含义)。行为与执行器设置范围见交互 SSOT 同名小节。
已保存的 Executor 头像沿用同一套尺寸、角标和珐琅规则，设置入口移动不改变其显示；旧 Appearance 记录仍以原 ID 显示，不伪装成新 Executor。

## Message Tools 主按钮密度

主按钮保持同一固定点击格：空闲显示上箭头，执行中显示实心方形，后者使用中性平面样式与 hover 反馈。tooltip 与可访问名称明确表达发送或中断当前回复；停止 Session 的危险动作仍在原生命周期入口，不由方形图案推断会话销毁。行内截图保留比例，高度沿正文行高，不强制方框。行为见[《Message Tools 单一主按钮与行内图片》](../behavior/conversation-input.md#message-tools-单一主按钮与行内图片)。

## Message Tool 内的 Agent 视图切换

Terminal / Activity 切换从 Pane 顶栏移到 Message Tool 的工具带，和 Skills、Commands、Capture 共用紧凑按钮语言。顶栏保留 Tab、Workspace、Agent 生命周期和分屏动作；切换按钮必须在窄栏仍可发现，当前模式用 selected/focus 语义表达，不用额外大标题。

## Session 归属与 Message Tools 的自适应密度

- Fork / Resume 的 Tab 入口沿用目标 Session 的工作面归属，不能从当前焦点 Region 借用位置。新 Tab 的插入点只由目标 Tab 的布局事实决定，不能用“当前 Agent 右侧”这种无法解释的空间捷径。
- Message Tools 的 composer 采用“左右稳定、中间弹性”的布局：宽度足够的紧凑态保持一行；窄工作面让原编辑区独占完整一行，原工具与发送控件在下面保持同一单排，不把草稿挤成两三个字一行，也不丢动作或改掉所选输入模式。输入超过可读宽度时扩展为 2–4 行；超出最大高度后才在编辑区内部滚动。文本始终左对齐，不能用固定窄宽度和居中布局牺牲输入面积；编辑器、草稿与模式边界只见交互 SSOT[《Agents、队列与 Message Tools》](../behavior/agent-capabilities-and-messaging.md#agents队列与-message-tools)的一行态约束。
- Message Tools 的“滑动到底部”入口贴在编辑区内部的边缘，沿用 24px 级别的紧凑命中区和现有 focus ring；它只在滚动位置离开底部时出现，回到底部立即隐藏。入口不改变编辑区宽度、不新增外层滚动条、不改变左右控件的对齐。

## Result ready 的紧凑层级

小 Region 的完成提示采用低占用的紧凑状态表达：完成状态与结果查看入口清楚可辨，结果摘要和关闭入口按需可达。展开内容使用有上限的列表或树状分组表达文件与预览链接，名称可截断、完整值在可访问名称中保留；不使用十行平铺按钮，不把解释性长句与每个目标并列占据首层。信息控件的共同视觉约束见[《服务提醒与结果信息的轻量控件》](settings-and-observation.md#服务提醒与结果信息的轻量控件)；行为约束见[《Result ready 在小 Region 中的可用性》](../behavior/conversation-input.md#result-ready-在小-region-中的可用性)。

## 按状态配置 Prompt 按钮

行为、持久化、发送与 Permission / Question 边界统一见交互 SSOT[《按状态配置 Prompt 按钮》](../behavior/conversation-input.md#按状态配置-prompt-按钮)。用户要求这些状态条更现代、按钮不再厚重：用户自定义 Prompt 沿 Message Tool 与信息条的紧凑、安静控件语言，名称简短可读，正文按需查看；不采用宽大的主按钮、厚重描边、重复装饰图标或另一块常驻卡片。

状态动作没有当前内容时零占用，不保留空行、固定高度或隐形槽。状态匹配、唯一接收者入口、Review 与请求分工及焦点行为只定义在 interaction 同名小节。常态仅保留现有头像与同一语义角标：沿既有工具带尺寸与身份图，不抬高 Composer；hover／focus／open 不外扩、不另加状态背景条、常驻文字或按钮计数。用户指令与结果动作进入这个入口的同一内容面，替换此前状态 Prompt 全部常态平铺与横滚轨道的视觉要求；稳定工具带不以牺牲长草稿宽度或原终端末行换取动作同时露出。

展开内容沿 Graphite／Mint 的高不透明功能材质、原中性细边与一层柔和阴影；一行身份和简短真实状态建立主次，用户 Prompt 用可读名称与短正文预览，Send／Queue 作为动作意义可辨，不重复图标、彩色 pills、卡片套卡片或大主按钮。Prompt 名称与正文可换行，完整内容、禁用原因、键盘焦点和全部动作可达；多项通过有界内容滚动。正常高度下状态摘要与操作头固定；极矮时身份、关闭与返回保持固定，摘要可随正文滚动，沿交互同名小节的可达性约束。Review 在同一面内使用原详情层级，不叠第二浮层。

有当前匹配动作的紧凑展开面，首屏必须能发现至少一条实际 Prompt 名称及其 Send／Queue；实际 320×430、长草稿与待答卡并存时也成立，不能打开后只见状态和“用户指令”等分类标题、看起来没有按钮。身份、关闭与返回仍固定可达，重复分类标题不能占掉唯一可见动作的空间；完整正文与其余内容继续按原可读字号滚动阅读，不缩字或截掉说明。该首屏优先级仍须保护完整 Composer 与原生终端末行，不通过增高输入区或遮挡输入换取动作可见。

正常与窄 Region 的展开面均锚定原头像并夹在工作面／窗口可用范围内；完整 Composer、原生末行保护带、上下避让区选择与临时覆盖请求卡的退出保持只见交互同名小节。矮窗选用更可用的避让区并收敛内部滚动区，而不撑高工具带或遮住关闭入口；正文可见高度至少容纳一行完整可读文字，不以极薄滚动缝冒充可达。输入、正文与长状态说明使用现有可读字号，元数据只居次层，不能靠全局缩字伪造紧凑。已发送、待发、不可提交、未知和恢复状态都有文字或语义字形；动效限于短促淡入与材质反馈，减少动态效果时完整静态。Settings 的状态选择与使用示意仍沿原单对象编辑台与全库保存反馈，不另造配置页面；状态说明与绑定意义以交互 SSOT 为准。

### 回复卡片的 reaction 快捷回复

沿[交互约束](../behavior/conversation-input.md#回复卡片的-reaction-快捷回复)，SVG 图标少而明确，短名称和完整含义可读，键盘可操作，并清楚显示发送中、已接受、失败或结果未知；不把点击显示成点赞数量或可撤销的已赞状态。图标在悬停、键盘聚焦或点击时可有轻微动画，平时安静，遵守减少动态效果偏好。

含义提示跟随原消息所在的可见工作面；原位置隐藏或不可交互时收起并释放定位观察，不留下窗口级提示。原消息、草稿与快捷回复保留，回到原位置仍可显式打开和使用。
