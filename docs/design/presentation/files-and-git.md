## 本地文件查看与编辑表面

- Agent 的文件打开、Session 展示偏好、File Region 模式与 Region 交换沿已有紧凑控件语言；作用范围、默认保输入、真实格式及失败／恢复边界只在交互文档[《Agent 通过 CLI 打开文件与控制原工作面》](../behavior/public-control.md#agent-通过-cli-打开文件与控制原工作面)定义，不增加一条永久 chrome 或第二套模式按钮。
- 网页、图片与文本的展示应符合各自内容类型，沿用工作台已有控件语言；行为和范围见[《本地文件预览与按格式编辑》](../behavior/files-and-git.md#本地文件预览与按格式编辑)。具体工具栏与编辑能力在成熟产品调研后评审。
- Terminal 本机临时产物沿现 Browser chrome 呈现真实文件内容及可辨本地目标，不增加假项目卡、第二预览窗或常驻说明；目标边界、点击校验、失效与恢复唯一见交互 SSOT[《Terminal 本机临时产物预览》](../behavior/files-and-git.md#terminal-本机临时产物预览)。
- 用户要求本地 PNG 链接能直接预览并补齐相关缺失。图片用内容优先的安静查看面，紧凑工具行提供 Fit、1:1、缩放与必要尺寸信息；真实图片是主层，透明背景可辨，浅 / 深色与窄 / 矮 Region 保持完整可达的阅读和操作，不用大空卡、重复路径或满屏说明替代内容。
- 文件查看 / 源码工具栏须给同 Region 的关闭按钮留出位置；窄 / 矮分屏中，关闭、重读、系统打开、Reveal、模式切换与保存互不遮挡，所有可用按钮都能实际点击。沿用既有 Region chrome，不增加一条永久标题带。
- 保存结果未确认沿原 Editor 状态槽持续说明并提供紧凑的“核对已保存文件”动作，核对失败保原草稿与动作，不另开遮挡正文的弹层。正常与窄 Region 中核对、关闭和原正文仍可操作；状态与恢复条件唯一见交互文档[《Revision-aware 保存与外部冲突》](../behavior/files-and-git.md#revision-aware-保存与外部冲突)。
- 音视频沿原生播放控件；Editor 中可编辑且支持渲染的文件，包括 HTML，源码与预览沿同 File 的紧凑模式切换，在原正文区域呈现内容，回源码与保存状态保持可辨可达。HTML 沿既有网页内容呈现语言，不为就地预览另开窗口、增加地址栏或叠加第二条永久标题带；当前正文的就地预览与显式已保存文件预览须准确区分，未保存源码状态保持可辨。未知二进制或预览失败呈现一条准确原因及系统打开 / Reveal 动作，避免假编辑器、空白成功态和层叠警告。格式支持、读取与恢复，以及显式 Markdown 图片／文件链接的目标边界，唯一见交互文档[《本地链接的真实格式预览与二进制保全》](../behavior/files-and-git.md#本地链接的真实格式预览与二进制保全)；沿原正文与图片的直接打开入口，不加重复链接卡或常驻提示。
- 文件树目录的“Open as Project”只出现在目录右键菜单中，和 New Folder / Open in Terminal 同一菜单密度；文件行不留禁用占位。动作成功后由 Project Rail 的既有选中态表达结果，失败使用既有错误面，不在菜单里增加第二种确认卡。

- 结构化数据、图、Notebook与构建产物沿同一File正文呈现：表格与记录分页，图提供适合视口与必要缩放，Notebook按cell阅读，编译日志与产物状态紧凑可辨。只为当前格式显示实际可用动作；正常、窄／矮Region中源码返回、格式化、取消与失败恢复均可达，不增加第二条永久标题带或以空卡代替内容。格式能力、性能与副作用边界唯一见[格式能力与按需扩展](../behavior/files-and-git.md#格式能力与按需扩展)。
- **Terminal 文件动作保持轻量且可扫读。** 右键中的系统文件动作放在路径动作分组，使用平台对应的短文案与统一 14px 图标；没有路径命中时整组缺席，不留空分隔线。菜单不能因长路径把动作裁掉，动作文本允许单行省略并保留完整 title/可访问名称。

## Branches 行的状态标记

Branches 行以分支名和必要 worktree 路径为主层；当前分支、已绑定 worktree 与未绑定分支用可辨的小图标表达，保留悬停说明和无障碍名称，不用每行重复的文字胶囊占据名称空间。分组标题与计数清楚表达 Worktrees 和纯 Branches，长列表中仍可找到另一组；无单位的裸数字不能成为唯一说明。比较分支与扇出 prompt 是不同动作，工具图形须可辨，不能只靠悬停区分两个相同图标。

状态槽无填充、无边框，沿既有语义色与共享行对齐；正常与窄侧栏、深浅色中都不得与 Agent 在场簇、同步计数或 pin 操作重叠。同类身份与状态避免无信息增量的重复图形，但相同 Provider 图标不抹去不同 executor 的真实身份；Agent 角标与同步计数要能分别辨义。选中态与当前分支事实分别表达，图标不改变原打开、创建 worktree 或 Git 行为。

分支名优先占据主阅读宽度，worktree 路径摘要沿[交互合同](../behavior/files-and-git.md#git-源码控制与-pr)相对仓库根显示，避免反复呈现相同的 home／项目根前缀；完整目标仍可按原路径偏好读取。名称、路径和末端动作均在各自范围内布局，空间不足时有明确省略及完整读取入口，不靠缩小字号或叠压头像换宽度。

## Changes 文件名与目录摘要

Changes 的单行密度、状态和动作边界沿[《Explorer 与快捷输入区》](#explorer-与-editor-的共用头和列表)。计数带明确文件单位，每行以文件名为主层、目录为次层；正常栏利用可用空间读出名称，窄栏让目录摘要收敛或缺席，把空间优先给主文件名，避免重复目录占宽后把不同名称全压成同一前缀，确需省略的完整路径保留原 tooltip。原分组与事务行为沿[交互合同](../behavior/files-and-git.md#git-源码控制与-pr)。

## Git 工作面与渐进详情

窄侧栏保留工作线定位、状态摘要与 History 快览，搜索与筛选使用既有紧凑输入、选择和菜单语言，结果数量、当前范围和清除入口可辨；不堆多排 chips 或重复路径挤压名称。仓库历史使用可发现的“查看仓库历史”文字入口，与具体提交标题的打开动作区分；动作随当前准确对象按需呈现，鼠标与键盘入口共享语义，不能靠无说明的图标猜对象或让输入字符触发 Git 写入。

具体提交详情以提交标题、固定 OID 和准确仓库为阅读目标，呈现完整消息、parent、引用与改动文件，不在其旁重复铺完整 History。“在历史中定位”作为清楚的次要动作；持续详情不能只靠 hover 维持，hover 摘要与明确打开的详情在重量和关闭方式上可辨。读取、空结果、缺对象与失败沿原状态语汇，不用空白面代签成功；加载和更新不让已读正文反复跳动。

完整仓库历史工作面以仓库及当前范围为主层，一份 History 与当前提交详情、所选文件 Diff 联动阅读；选择和 Diff 的反馈留在当前审阅面，显式另开动作保持可达。完整历史在主区呈现时，侧栏对同一次阅读提供紧凑状态／返回入口，不并排重复另一份完整列表；不把 Branches／Changes 导航改成跳转后的被动选择。较宽空间用于联动阅读，窄／矮 Region 中按当前阅读内容收敛列数，保留目标、正文和返回入口，不强塞三列或永久占满侧栏。目的地与阅读位置交接规则唯一见[Git 源码控制与 PR](../behavior/files-and-git.md#git-源码控制与-pr)。

独立 Git 工作面复用既有 Region chrome、只读 Diff、工具行与菜单密度；由已有 Review 或分支入口进入时不增第二套结果卡、编辑器或常驻侧栏。准确资源、固定 OID、只读资格及恢复边界唯一见[Git 源码控制与 PR](../behavior/files-and-git.md#git-源码控制与-pr)；具体列数和停靠位置按可用宽度适配，不成为另一套 Git 事实。

## Git History 行内图宽与标签

每个提交行按自身节点、经过本行的轨道以及进出连线确定图形所需宽度，并把本行余下宽度给提交标题和引用标签；不能让整页最宽一行替所有行预留空白，也不能以固定窄图槽裁掉真实分叉／合并。相邻行仍在同一轨道坐标下连续连接，节点与标题按原行中心对齐，不能为了缩窄某一行移动或省掉真实 parent；宽关系的必要阅读空间要实际可达。

引用标签利用本行实际剩余空间，单个标签不得仍按多个标签的预留份额二次缩窄。提交标题保持主层，标签、省略计数与短 hash 不互相覆盖；正常栏有空白时用于阅读，窄栏必要省略后仍经原详情完整读取。每提交一行、字号、颜色、平滑连线与详情浮层唯一沿[《Explorer 提交历史的密度、分支颜色与连线》](#explorer-提交历史的密度分支颜色与连线)，真实范围、分页与信息读取边界沿[交互合同](../behavior/files-and-git.md#git-源码控制与-pr)。

常规向下阅读在到达已读边界前获得下一页；边界计数与加载反馈保持紧凑，手动继续和失败重试入口可达，不把底部按钮变成阅读必经步骤。追加页不推动正在阅读的行或遮住原正文；提前量、去重与失败重试的读取约束唯一沿上述交互合同。

## Branch Pin 的层级与操作位

固定分支的标题左缘在所属 Project 之下增加一层真实缩进，统一遵守[《Project Rail 与 Topic 行密度》](spaces-and-layout.md#project-rail-与-topic-行密度)；不靠空折叠槽或空图标槽凑层级，也不退到父级左边。Pin 按钮缩小内边距，未悬停或聚焦时不占操作位，悬停或键盘聚焦后才为按钮留空间；已固定状态保留安静的视觉提示，不用常驻大按钮挤压名称。行为约束见[《Branch Pin 的层级与操作位》](../behavior/files-and-git.md#branch-pin-的层级与操作位)。

## Worktree 移除确认与 Git 卫生提示

移除 worktree 的确认框保持单一主动作和紧凑正文：第一段说明签出目录会消失、分支仍在；探针得到的分支留存事实作为同一段正文的尾句接入，不另起一张提示卡，也不把未知状态画成成功或安全。探针失败时只显示“无法核实”这类服务窗式提醒，不改变确认按钮的可达性。

未提交改动触发的二次确认继续使用危险动作语义，并且只表达“丢弃未提交产出”；它与“分支仍保留但有独有提交”共用容器密度，不共用措辞。fan-out 创建后的仓库卫生属于后台 Git 事实，不在 Branch 行常驻增加徽章或第二行元信息；只有真实 `git status` 变脏时才进入错误面。

## 两条分支比较

复用 Branches 与现有列表、选择控件、只读 Diff 工作面；A/B 与比较方向并列且明确，结果列表按文件呈现，不增加第二套编辑器、浮动 Review 卡或常驻新侧栏。行为与身份统一见交互 SSOT[《Git 源码控制与 PR》](../behavior/files-and-git.md#git-源码控制与-pr)。

## Explorer 与 Editor 的共用头和列表

- 用户要求项目标题与 Explorer 标题合并、去重项目路径，并让 Branches／Changes 符合已有液态玻璃。Explorer 只保留一条紧凑项目／工具共用头，原收起入口与新建、刷新动作在同一层，收起文件树后仍可展开；下部 Branches／Changes／History 只保留一个明确的选择层，不叠同名面板标题、仓库路径和工具标签。项目路径按需读取，只有确实不同的 worktree／Host 上下文才占次级信息位，长名称与路径可完整读取；正文与 hover 的表示沿交互文档[《路径显示与复制》](../behavior/spaces-and-layout.md#路径显示与复制)。
- 玻璃沿现有 `material-control-*` 与成熟原控件，集中在共用头、选择面和必要操作面，以透明层次、发丝线及静态高光形成深度；下方 Branches／Changes／History 切换复用设置界面既有的液态玻璃选中语言，保持紧凑及原字号、命中区和键盘焦点，正常与窄栏、明暗及减少动态／高对比条件均可辨；文件、分支、改动和提交列表维持稳定文字底，不做卡片墙、每行透镜或持续动画。选中、键盘焦点、hover 与危险操作彼此可辨，减少动态和隐藏面停不必要动画；颜色不独占选中或 Git 状态语义。
- 文件名称在非编辑态保明确可点击的指针、轻量 hover 与独立选中／焦点反馈，I-beam 只出现在真正输入态；名称与行内改名是主命中区，移除右侧重复 Edit／Delete 图标后仍能发现菜单与键盘动作。通用行内名称控件与行基线对齐，名称、选区、等待及错误在正常／窄栏、明暗主题可读，不用突兀重边框、按钮墙或改变行高表达编辑；目录 disclosure、文件打开、名称编辑、多选与拖拽的命中边界清楚。沿现有 Explorer／Branch Header 和 Tool Dock 密度预算，正常与窄栏、明暗主题均保清楚的主名称、完整操作及可滚动内容，不靠缩字、额外标题带或遮住工作面换取紧凑。
- Editor 顶栏保持极简：正常 Saved 是低存在感的轻状态，不画成粗重禁用动作；必要 Save、预览／Diff 与 More 入口沿现有紧凑图标、tooltip 和焦点语言。More 菜单复用现有玻璃浮层材质、层级与碰撞边界，键盘项、勾选与危险／恢复动作清楚，正常与窄编辑区不遮主文件名、正文或状态原因。Monaco 正文字号继承／override 与保存语义只见[《Explorer 与 Editor》](../behavior/files-and-git.md#explorer-与-editor)，样式不另写固定正文字号。
- Changes 沿成熟 SCM 单行列表：文件名占明确可收缩的主区域，长名称省略并可完整读取；状态用紧凑非色标记，完整状态和冲突细节按需可读。名称、状态与必要暂存／丢弃动作各有边界，窄栏、hover、键盘焦点、忙态和危险确认均不得互相覆盖或挤成多行；普通态动作克制，聚焦／hover 可发现，危险确认不随指针移开而消失。
- History 用提交主文、引用标签与克制的 parent 连接表达真实拓扑；分叉／merge、当前范围和继续读取边界可辨，颜色仅辅助连接，未知／失败有原位原因与可执行恢复。正常／窄栏与明暗图审必须在完整真实工作面确认层级、连接和文字可读，不用装饰图线冒充全部历史。范围与快照唯一见交互文档[《Git 源码控制与 PR》](../behavior/files-and-git.md#git-源码控制与-pr)。

- 键盘入口与底部设置按钮相邻并保持相同控件尺度。Explorer 忽略项弱化但可读；链接以文件／文件夹图标叠加链接标记呈现，失效链接有可访问的说明，不显示 `link` 文字徽章。行为见[《Explorer 的真实文件与快捷键入口》](../behavior/files-and-git.md#explorer-的真实文件与快捷键入口)。

## Explorer 提交历史的密度、分支颜色与连线

用户要求 Git History 进一步紧凑，「每个提交只占一行」。提交标题、分支标记与短 hash 在同一行，正常与窄栏均不换行；标题占主要阅读空间，分支标记保持克制，空间不足时短 hash 可收进既有 hover。行内省略的信息沿交互 SSOT[《Git 源码控制与 PR》](../behavior/files-and-git.md#git-源码控制与-pr)通过 hover／键盘焦点的同一短暂信息面按需可读、可选择复制，不常驻第二条元信息行，不靠缩小既有正文字号换密度；信息面沿现有窗口浮层边界定位，正常与窄栏、明暗主题均保长标题、OID 与引用名称可读，必要时面内滚动，不盖住焦点入口或挤变提交行。graph 节点与对应提交行的中心对齐，连线沿同一行距保持真实拓扑与连续性。

不同活动分支的引用、节点及对应轨道使用可辨的稳定色相；颜色不能取自当前行号或 lane 序号，分页、收起展开及相同分支的刷新不应换色。真实合流处可展示两种来路的颜色，分支名称和真实 parent 关系仍是非色语义依据，不能只靠颜色区分。线条为清楚、平滑的连续轨道，跨 lane 的移动、分叉与合并有一致的圆角/曲线，节点与连线交界可辨；不能用视觉优化连起无关系的提交、压掉 merge parent 或把未读边界画成已知关系。深浅主题与正常/窄栏均需实际独立看图通过。行为事实沿交互 SSOT[《Git 源码控制与 PR》](../behavior/files-and-git.md#git-源码控制与-pr)。
