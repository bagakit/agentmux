## 本地文件查看与编辑表面

- 各类支持文件以正文为主层，沿同 File 的紧凑 chrome：Markdown 的标题、段落、表格、代码、引用与图片有清楚的阅读层级；结构数据保类型和横向阅读；PDF 保分页/缩放与可选择文本；图片、音视频保真实尺寸与原生播放操作。格式之间复用路径、状态和控件语言，不用重复标题、空大卡或常驻说明替代内容。
- 明暗主题和窄/矮 Region 中，正文、目录层级与选中态仍清楚，关闭、模式切换、保存、重试和内容操作实际可达。目录窗口化保连续行密度、完整命名与焦点反馈，不以数据窗口边缘表现为目录终点。
- 全项目 quick-open 沿已有紧凑查找与选择面呈现，当前项目范围、文件名和区分重名的相对路径可辨；键盘选中态、加载、无匹配、截断与失败沿同一结果面表达，不另铺搜索说明卡。文件树 hidden / ignored 显隐和 Collapse All 归现有头部或菜单动作，状态可发现，不给每行重复增加操作槽；保留树的连续行密度。
- Markdown TOC 使用安静的标题层级与紧凑展开入口，正文保持主层。宽 Region 中目录不把短文切成空大列，窄／矮 Region 中可收起或在按需面中访问，跳转目标及键盘焦点清楚；长标题可读，重复标题不以截断后的同名外观掩盖位置。无标题时不展示空侧栏或常驻说明。
- minimap 是源码边缘的辅助导航，沿 Editor 的原设置／More 语言表达开关，正常态不增加永久标题带。开启后明暗主题和窄 Region 中正文、滚动条、关闭与保存仍可达，不能让小地图成为正文的主视觉；范围与位置保全要求只在[同主题交互](../behavior/files-and-git.md#本地文件预览与按格式编辑)定义。

- Agent 的文件打开、Session 展示偏好、File Region 模式与 Region 交换沿已有紧凑控件语言；作用范围、默认保输入、真实格式及失败／恢复边界只在交互文档[《Agent 通过 CLI 打开文件与控制原工作面》](../behavior/public-control.md#agent-通过-cli-打开文件与控制原工作面)定义，不增加一条永久 chrome 或第二套模式按钮。
- Terminal 本机临时产物沿现 Browser chrome 呈现真实文件内容及可辨本地目标，不增加假项目卡、第二预览窗或常驻说明；目标边界、点击校验、失效与恢复唯一见交互 SSOT[《Terminal 本机临时产物预览》](../behavior/files-and-git.md#terminal-本机临时产物预览)。
- 用户要求本地 PNG 链接能直接预览并补齐相关缺失。图片用内容优先的安静查看面，紧凑工具行提供 Fit、1:1、缩放与必要尺寸信息；真实图片是主层，透明背景可辨，浅 / 深色与窄 / 矮 Region 保持完整可达的阅读和操作，不用大空卡、重复路径或满屏说明替代内容。
- 文件查看 / 源码工具栏须给同 Region 的关闭按钮留出位置；窄 / 矮分屏中，关闭、重读、系统打开、Reveal、模式切换与保存互不遮挡，所有可用按钮都能实际点击。沿用既有 Region chrome，不增加一条永久标题带。
- 保存结果未确认沿原 Editor 状态槽持续说明并提供紧凑的“核对已保存文件”动作，核对失败保原草稿与动作，不另开遮挡正文的弹层。正常与窄 Region 中核对、关闭和原正文仍可操作；状态与恢复条件唯一见交互文档[《Revision-aware 保存与外部冲突》](../behavior/files-and-git.md#revision-aware-保存与外部冲突)。
- 音视频沿原生播放控件，Markdown / SVG 源码与预览使用同 File 的紧凑模式切换，HTML 沿既有 Browser chrome；不为每种格式创建另一套窗口语言。未知二进制或预览失败呈现一条准确原因及系统打开 / Reveal 动作，避免假编辑器、空白成功态和层叠警告。格式支持、读取与恢复，以及显式 Markdown 图片／文件链接的目标边界，唯一见交互文档[《本地链接的真实格式预览与二进制保全》](../behavior/files-and-git.md#本地链接的真实格式预览与二进制保全)；沿原正文与图片的直接打开入口，不加重复链接卡或常驻提示。
- 文件树目录的“Open as Project”只出现在目录右键菜单中，和 New Folder / Open in Terminal 同一菜单密度；文件行不留禁用占位。动作成功后由 Project Rail 的既有选中态表达结果，失败使用既有错误面，不在菜单里增加第二种确认卡。

## Branch Pin 的层级与操作位

固定分支的标题左缘在所属 Project 之下增加一层真实缩进，统一遵守[《Project Rail 与 Topic 行密度》](spaces-and-layout.md#project-rail-与-topic-行密度)；不靠空折叠槽或空图标槽凑层级，也不退到父级左边。Pin 按钮缩小内边距，未悬停或聚焦时不占操作位，悬停或键盘聚焦后才为按钮留空间；已固定状态保留安静的视觉提示，不用常驻大按钮挤压名称。行为约束见交互合同[《Branch Pin 的层级与操作位》](../behavior/files-and-git.md#branch-pin-的层级与操作位)。

## Worktree 移除确认与 Git 卫生提示

移除 worktree 的确认框保持单一主动作和紧凑正文：第一段说明签出目录会消失、分支仍在；探针得到的分支留存事实作为同一段正文的尾句接入，不另起一张提示卡，也不把未知状态画成成功或安全。探针失败时只显示“无法核实”这类服务窗式提醒，不改变确认按钮的可达性。

未提交改动触发的二次确认继续使用危险动作语义，并且只表达“丢弃未提交产出”；它与“分支仍保留但有独有提交”共用容器密度，不共用措辞。fan-out 创建后的仓库卫生属于后台 Git 事实，不在 Branch 行常驻增加徽章或第二行元信息；只有真实 `git status` 变脏时才进入错误面。

复用 Branches 与现有列表、选择控件、只读 Diff 工作面；A/B 与比较方向并列且明确，结果列表按文件呈现，不增加第二套编辑器、浮动 Review 卡或常驻新侧栏。行为与身份统一见交互 SSOT[《Git 源码控制与 PR》](../behavior/files-and-git.md#git-源码控制与-pr)。
