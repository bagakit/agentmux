## 本地文件查看与编辑表面

- Agent 的文件打开、Session 展示偏好、File Region 模式与 Region 交换沿已有紧凑控件语言；作用范围、默认保输入、真实格式及失败／恢复边界只在交互文档[《Agent 通过 CLI 打开文件与控制原工作面》](../behavior/public-control.md#agent-通过-cli-打开文件与控制原工作面)定义，不增加一条永久 chrome 或第二套模式按钮。
- 网页、图片与文本的展示应符合各自内容类型，沿用工作台已有控件语言；行为和范围见 [Desktop interaction](../agentmux-desktop-interaction.md)“本地文件预览与按格式编辑”。具体工具栏与编辑能力在成熟产品调研后评审。
- Terminal 本机临时产物沿现 Browser chrome 呈现真实文件内容及可辨本地目标，不增加假项目卡、第二预览窗或常驻说明；目标边界、点击校验、失效与恢复唯一见交互 SSOT[《Terminal 本机临时产物预览》](../behavior/files-and-git.md#terminal-本机临时产物预览)。
- 用户要求本地 PNG 链接能直接预览并补齐相关缺失。图片用内容优先的安静查看面，紧凑工具行提供 Fit、1:1、缩放与必要尺寸信息；真实图片是主层，透明背景可辨，浅 / 深色与窄 / 矮 Region 保持完整可达的阅读和操作，不用大空卡、重复路径或满屏说明替代内容。
- 文件查看 / 源码工具栏须给同 Region 的关闭按钮留出位置；窄 / 矮分屏中，关闭、重读、系统打开、Reveal、模式切换与保存互不遮挡，所有可用按钮都能实际点击。沿用既有 Region chrome，不增加一条永久标题带。
- 保存结果未确认沿原 Editor 状态槽持续说明并提供紧凑的“核对已保存文件”动作，核对失败保原草稿与动作，不另开遮挡正文的弹层。正常与窄 Region 中核对、关闭和原正文仍可操作；状态与恢复条件唯一见交互文档[《Revision-aware 保存与外部冲突》](../behavior/files-and-git.md#revision-aware-保存与外部冲突)。
- 音视频沿原生播放控件；Editor 中可编辑且支持渲染的文件，包括 HTML，源码与预览沿同 File 的紧凑模式切换，在原正文区域呈现内容，回源码与保存状态保持可辨可达。HTML 沿既有网页内容呈现语言，不为就地预览另开窗口、增加地址栏或叠加第二条永久标题带；当前正文的就地预览与显式已保存文件预览须准确区分，未保存源码状态保持可辨。未知二进制或预览失败呈现一条准确原因及系统打开 / Reveal 动作，避免假编辑器、空白成功态和层叠警告。格式支持、读取与恢复，以及显式 Markdown 图片／文件链接的目标边界，唯一见交互文档[《本地链接的真实格式预览与二进制保全》](../behavior/files-and-git.md#本地链接的真实格式预览与二进制保全)；沿原正文与图片的直接打开入口，不加重复链接卡或常驻提示。
- 文件树目录的“Open as Project”只出现在目录右键菜单中，和 New Folder / Open in Terminal 同一菜单密度；文件行不留禁用占位。动作成功后由 Project Rail 的既有选中态表达结果，失败使用既有错误面，不在菜单里增加第二种确认卡。

## Branches 行的状态标记

Branches 行以分支名和必要 worktree 路径为主层；当前分支、已绑定 worktree 与未绑定分支用可辨的小图标表达，保留悬停说明和无障碍名称，不用每行重复的文字胶囊占据名称空间。分组标题与计数清楚表达 Worktrees 和纯 Branches，长列表中仍可找到另一组；无单位的裸数字不能成为唯一说明。比较分支与扇出 prompt 是不同动作，工具图形须可辨，不能只靠悬停区分两个相同图标。

状态槽无填充、无边框，沿既有语义色与共享行对齐；正常与窄侧栏、深浅色中都不得与 Agent 在场簇、同步计数或 pin 操作重叠。同类身份与状态避免无信息增量的重复图形，但相同 Provider 图标不抹去不同 executor 的真实身份；Agent 角标与同步计数要能分别辨义。选中态与当前分支事实分别表达，图标不改变原打开、创建 worktree 或 Git 行为。

分支名优先占据主阅读宽度，项目内路径摘要沿[交互合同](../behavior/files-and-git.md#git-源码控制与-pr)相对仓库根显示，避免反复呈现相同的 home／项目根前缀；完整目标仍可按原路径偏好读取。名称、路径和末端动作均在各自范围内布局，空间不足时有明确省略及完整读取入口，不靠缩小字号或叠压头像换宽度。

## Changes 文件名与目录摘要

Changes 的单行密度、状态和动作边界沿[《Explorer 与快捷输入区》](conversation-input.md#explorer-与快捷输入区)。计数带明确文件单位，每行以文件名为主层、目录为次层；正常栏利用可用空间读出名称，窄栏让目录摘要收敛或缺席，把空间优先给主文件名，避免重复目录占宽后把不同名称全压成同一前缀，确需省略的完整路径保留原 tooltip。原分组与事务行为沿[交互合同](../behavior/files-and-git.md#git-源码控制与-pr)。

## Git History 行内图宽与标签

每个提交行按自身节点、经过本行的轨道以及进出连线确定图形所需宽度，并把本行余下宽度给提交标题和引用标签；不能让整页最宽一行替所有行预留空白，也不能以固定窄图槽裁掉真实分叉／合并。相邻行仍在同一轨道坐标下连续连接，节点与标题按原行中心对齐，不能为了缩窄某一行移动或省掉真实 parent；宽关系的必要阅读空间要实际可达。

引用标签利用本行实际剩余空间，单个标签不得仍按多个标签的预留份额二次缩窄。提交标题保持主层，标签、省略计数与短 hash 不互相覆盖；正常栏有空白时用于阅读，窄栏必要省略后仍经原详情完整读取。每提交一行、字号、颜色、平滑连线与详情浮层唯一沿[《Explorer 提交历史的密度、分支颜色与连线》](conversation-input.md#explorer-提交历史的密度分支颜色与连线)，真实范围、分页与信息读取边界沿[交互合同](../behavior/files-and-git.md#git-源码控制与-pr)。

## Branch Pin 的层级与操作位

固定分支的标题左缘在所属 Project 之下增加一层真实缩进，统一遵守[《Project Rail 与 Topic 行密度》](spaces-and-layout.md#project-rail-与-topic-行密度)；不靠空折叠槽或空图标槽凑层级，也不退到父级左边。Pin 按钮缩小内边距，未悬停或聚焦时不占操作位，悬停或键盘聚焦后才为按钮留空间；已固定状态保留安静的视觉提示，不用常驻大按钮挤压名称。行为约束见 desktop-interaction 的同名小节。

## Worktree 移除确认与 Git 卫生提示

移除 worktree 的确认框保持单一主动作和紧凑正文：第一段说明签出目录会消失、分支仍在；探针得到的分支留存事实作为同一段正文的尾句接入，不另起一张提示卡，也不把未知状态画成成功或安全。探针失败时只显示“无法核实”这类服务窗式提醒，不改变确认按钮的可达性。

未提交改动触发的二次确认继续使用危险动作语义，并且只表达“丢弃未提交产出”；它与“分支仍保留但有独有提交”共用容器密度，不共用措辞。fan-out 创建后的仓库卫生属于后台 Git 事实，不在 Branch 行常驻增加徽章或第二行元信息；只有真实 `git status` 变脏时才进入错误面。

## 两条分支比较

复用 Branches 与现有列表、选择控件、只读 Diff 工作面；A/B 与比较方向并列且明确，结果列表按文件呈现，不增加第二套编辑器、浮动 Review 卡或常驻新侧栏。行为与身份统一见交互 SSOT[《Git 源码控制与 PR》](../behavior/files-and-git.md#git-源码控制与-pr)。
