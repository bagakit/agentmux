## Mote 快捷入口与当前协调上下文

用户认为左下按钮和实际工作「相互关联不上」。对象、当前目标、状态来源、开合和恢复行为只见 interaction 的同名章节；本节只定义其可见联系，沿现有 Graphite / Mint 与[《左下角导航与右下角工具组》](spaces-and-layout.md#左下角导航与右下角工具组)的低条、独立龙头像入口，不另造一套导航或在交流正文重复角色介绍。
- Mote 二级面在共同 Space 框架内呈现自我设定、名片与点子；名片是当前原 Mote 的按需二级内容，不在交流首屏再叠一份身份标题或角色介绍。共同框架只见交互 SSOT[《Space 的统一工作面框架》](../behavior/spaces-and-layout.md#space-的统一工作面框架)，文件树与二级内容归属只见同主题交互章节；不以另一套文件面板、Tab 导航或跨对象 `Topics` 分类标签包装当前 Mote。Motes 与普通 Topics 在 Space 的既有分区语言中可辨。未启动工作面的当前 Mote 身份沿原启动面标题呈现，名称与运行环境的边界见同主题交互章节，不增加浮窗 title 行或头像栏。

- Space 中的 Mote 以顶部二级切换表达功能组，默认组继续展示原公共 Zone／Tab／Region 工作面与文件能力；名片、自我设定和点子的可操作内容与当前对象清楚关联，沿原紧凑控件语言呈现。名片保必要身份与原编辑动作，不重复交流首屏标题；点子先让人读出原笔记内容与已有来源，再进入原编辑或讨论，不以装饰卡片、假成果或第二文件面板填充页面。功能组的行为和内容归属只见[同主题交互](../behavior/motes-and-coordination.md#mote-快捷入口与当前协调上下文)，区域层级只见[Space 的统一工作面框架](../behavior/spaces-and-layout.md#space-的统一工作面框架)；不由本条固定菜单英语名、分组数量或新的 Tab 排布。 Profile 首屏让真实头像与名称形成清楚的身份重心，合作方式、真实事项和最近点子沿连续、紧凑的信息流向下排列；空区只保一行原动作，问题输入轻而可达，不把缺少数据写成大段说明或铺成表单。原文件内容按需展开且来源可辨，已保存内容、非空事项和未知／失败说明不能为视觉精简被隐藏；窄面仍保身份、操作与键盘焦点完整。

- 按浮窗内部实际可用宽度安排公共资料面与工作面，不以主窗口宽度冒充正文预算。横排会把原分屏正文与输入挤窄时，资料面沿同一宿主纵向排列并可滚动；保原全部 Group、分割比例与对象导航偏好，不自动收掉它们来掩盖宽度不足。首次打开文件的准确位置选择独立占用资料面上方的控件行，公共文件与对象内容使用完整列和可操作的余高，不能把选择框与名片挤成并排窄列，也不能让名片、自我设定与点子的切换项被位置选择挤到不可见。

- 用户现已批准 Mote 浮窗与 Space Mote 工作面形成同一套聊天交流体验：先读出持久 Mote 对象，再读出所选 Mote 的事情/会话层级与原对话输入，参考其提出的 Discord 交流组织。对象身份、Session/Tab/Region 归属、共同文件能力和普通 Topic 边界唯一见交互 SSOT 同名章节；Discord 的交流参考不规定另一套 Tab 排列。本次设计稿与正常、窄窗、失败/未知真实截图须共同证明层级易懂、交流为主、资料按需；沿下文已取消独立 title 与重复模式栏的约束，不用额外角色介绍、标题带或卡片墙代替清晰层级。

- 讨论导航沿原 Tab 控件使用 `Discussions`／`New discussion`，正文沿原作者、时间与内容层级呈现平面紧凑消息；准确原 Mote 的发言用同一持久名／头像可辨，不把每条消息包成浮起卡片、重复请求标题或额外身份栏。公共 Tab/Region 导航在正常与窄窗中为正文保留真实宽度，不盖住作者头像或截断消息；二级内容按需进入，不以新的列表排布改变原 Tab 导航。其它作者与未知来源的真实表达继续保留。讨论、Session 与作者资格、原正文 owner 和慢资料读取不抢晚焦点的行为唯一见交互 SSOT 同名章节。

- 用户继续反馈弹窗被浮窗遮挡、常用功能按键不生效及改名入口难找。通用层级、命中、焦点／Escape 与准确原目标合同只见交互 SSOT[《浮层让位默认成立，而不是逐个接线》](../behavior/browser-workface.md#浮层让位与输入层级)和本节 Mote 合同；视觉需亲看实际前后景完整画面及真实控件命中，不能用抬 z-index、截图命令成功或扩大菜单堆满动作冒称完成。对象菜单与局部改名沿原紧凑控件语言，名称、动作和失败提示可读，不新增独立 Mote title。


- 用户进一步认为 hover 面板「离按钮太远」、信息冗余、整合不好，title 行没必要，多个 Mote 却只看到一个。临时面直接贴近 footer 按钮上方，以一档小间距建立关系；靠边时在视口内夹紧，不把原保存浮窗的远处坐标当作 hover 锚点，不另显示重复 tooltip。
- 收起、临时悬停、键盘焦点与固定展开分别可辨。出现时入口保留轻而清楚的完整轮廓/Surface 与 `aria-expanded`，固定状态静止后也可认出；不靠短暂烟火、眼睛粒子、扫屏或单边色条传达状态。真实 Agent 状态沿既有小型状态图形和可读文字表达，与展开边界分开，不让绿色头像冒充 Working 或在线。
- Profile 的快捷模式沿身份、合作方式和当前工作的信息流紧凑呈现默认 Agent 与默认会话，显示实际名称与必要状态，用原图标编辑动作进入设置；缺省只保简短可达的配置入口，不铺常驻表单。设置选择沿原控件清楚区分已保存与草稿；默认会话在原 Tab 行用克制的固定图标可辨，不增加第二条导航或新卡片。其身份、关闭资格及未知保护只见[同主题行为合同](../behavior/motes-and-coordination.md#mote-快捷入口与当前协调上下文)。
- Profile 中的需求关联、原执行 Agent 和快捷默认值选择共用[单选控件语言](shared-rules.md#控件语言)，保原选择、未知说明与原领域动作；选择不自动关联或开始执行。
- 用户继续要求 Mote 放左侧、不要和 Tab 叠，宽卡片与仅头像可切换，「类似 Discord」。快捷面采用左侧对象导航、右侧原 Tab/Region 与正文输入：常规宽态约168–176px，以紧凑宽卡片呈现头像、名称与真实短状态；头像态约52–56px，保留同一头像、状态形状与完整命中区。头像不是另一个对象，切换不让右侧再出现一份内容或 title。窄窗收紧宽态可收缩名称列，仍维持用户所选宽卡片或头像态和右侧原输入可用；原草稿不能被挤成每行仅2–3个字符的竖排。头像和截断名称的全文提示必须在原工作面上方真实可读，不能被正文或相邻 Surface 遮住；完整名与状态在 hover/focus 及无障碍描述中可读。
- 删除独立 Mote title 行：对象导航、两态开关、打开同一完整 Space 和收起合为一处精简控制。全部对象沿左侧有界纵向滚动，长名称只在名称列省略；不加角色介绍、重复标题或数量摘要。宽卡片只有必要身份与短状态，不形成逐对象浮起卡片墙。两态选中均用完整 Surface/轮廓和形状或其他非颜色线索与可访问语义，不能只用颜色或单边细线；键盘焦点与真实状态分开表达。
- Mote 对象名、当前事情的 Tab 与实际执行者分别只承担自己的层级。长 Mote/Goal 名只在可收缩名称区域省略，完整名按需和无障碍描述可读；状态与 24px 级动作命中区保持固定，不被长名挤掉。Provider、Session、技术 ID、用途说明与打开提示不再成段重复铺在选择区。
- 左侧导航与右侧原 Tab/Region chrome、说明、正文和输入读作一块连续紧凑工作面。窗口使用主题自适应的整圈清楚细边界、克制阴影与左右轻微 Surface 差，让外缘在背后同色工作面上仍可辨；不靠粗绿边、发光或遮挡主窗的 scrim 建立边界，不增加嵌套内容外框。不复写背后 Goals/Focus 的全局标题，不叠加角色说明、欢迎语或第二套工作面。打开完整 Space 的明确目标与后续独立导航只见[Work、Survey、Recall 与 Mote 的导航上下文](../behavior/spaces-and-layout.md#worksurveyrecall-与-mote-的导航上下文)，面内自然固定不切换正文模式；用户明确重新打开先对话、开着仍可切终端的行为边界只见交互 SSOT 同名 Mote 章节，沿现有对话正文与模式动作呈现，不增加第二条模式栏或重复说明。
- 明确关闭 Tab 后的原剩余工作面与可操作空态，只见交互合同同名章节“关闭 Tab 按明确意图继续”；空态复用原 Tab/Region 的紧凑 New Tab/+ 动作与可读说明，不额外叠恢复告示、第二工具栏或欢迎面。
- 尺寸拖拽只在浮窗边缘／角部提供轻且可辨、正面积的 resize 命中，pointer cursor、悬停与键盘焦点清楚；不增加独立 title 行、尺寸工具栏、位置输入或自由移动把手。正常与窄窗、宽卡片与头像态、最小可用和贴视口上限时，左侧对象／动作与右侧原正文输入仍完整可读可达，resize 命中不覆盖它们。范围、锚点、记忆、视口夹紧和取消语义只见交互 SSOT 同名 Mote 章节。
- 临时与固定面共用同一入口锚点并适配视口，不增加自由移动把手、最大化动作或独立位置控件；范围内尺寸拖拽与记忆见交互 SSOT 同名章节；正常、窄窗、长名、两个以上 Mote 和恢复状态下入口、全部对象、动作与键盘焦点完整。等待恢复、尚无 Agent、目录读取失败与未知使用克制且可读的原说明/服务窗，不用动画声称已接通。悬停立即显示，浮窗本体静止后无装饰性动画，减少动态偏好下也即时出现；头像表情只遵守[《Mote 头像与主 Mote》](#mote-头像与主-mote)，不带动浮窗几何。

## 全局 Board 与 Leader Topic 浮动入口

Mote 常驻入口与快捷面统一遵守[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)，与全局通知入口分开，不用状态颜色替代身份，也不因打开 Topic 改写背后布局。正文复用原 Session 工作面，实际 Executor、状态与恢复提示继续可见，不另保留可拖动的浮动入口。

全局 Board 的任务卡以任务标题和目标 Project 为第一层信息，任务状态、最近 Attempt/Agent 和 Session 上下文为第二层；不要把同一 Session 复制成多条 Agent 行。跨项目上下文用简短的 Project/Workspace/Branch/Topic 路径表达，窄窗优先保留任务标题、状态和目标 Project。行为约束见 desktop-interaction 的“全局 Board 与可配置默认 Session”。

Goals 的 `New Goal` 使用紧凑文字图标按钮，直接进入真实待定义目标与专属讨论，再沿[《Goals 的目标正文与对齐密度》](goals-and-demand.md#goals-的目标正文与对齐密度)呈现；入口行为归交互 SSOT，不增加事前空卡表单。

## Leader Topic 入口的浮动与收纳

Mote 入口保持与主工作面导航独立的命中区，收起不移动或移除该入口；临时/固定面的锚点、选择区与动作唯一遵守[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)。窄窗保留图标与真实注意力提示，不用叠加图标同时承担 Board 和 Mote。

未读/需要处理提示使用原共享静态状态图形或数字，不使用持续动画；与系统通知、Agents roster 共用颜色和形状语义。行为约束见交互 SSOT[《Mote 快捷入口与当前协调上下文》](../behavior/motes-and-coordination.md#mote-快捷入口与当前协调上下文)。

## 默认 Topic 与确认开关

默认 Topic 的表面要让用户看见它正在积累“项目路由与确认依据”，但不把知识库画成第二个聊天窗口。浮窗中使用一个紧凑的确认策略控件，显示当前模式：`按风险确认`（默认）、`全部确认` 或 `默认直接创建`；控件与 Task 草案的 `needs confirmation` 状态相邻，不能藏在通用设置深处。

Task 草案的视觉顺序固定为：原始请求摘要 → 候选 Project 与路由理由 → 风险/待确认项 → 创建策略 → 确认或创建动作。用户确认后显示短 receipt 和“已记录到默认 Topic”的可追踪提示；知识库条目在来源与依据抽屉中以紧凑记录出现，包含时间、决策和关联 Task，不能重复铺开整段对话。学习到的风险/Project 建议使用“建议”标签和依据数量，不用高亮或动画暗示它已经是真相。

## 默认 Session 入口的原生复用

Mote 入口使用原 tab／region／composer 的密度与身份表达，当前全部对象、锚点、临时/固定开合唯一遵守[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)。常驻紧凑助手按钮保持可键盘进入及真实注意力提示，Session chrome 不再额外画重复内联入口，不持久化自由坐标或 floating/compact 形态，也不展开第二套聊天控件。

## Leader Topic 的浮动工作面

Mote 快捷面的对象选择、合并动作与单一轻边界唯一遵守[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)，正文直接放已选 Topic 的原 Tab/Region 与现有 composer。不保留独立可拖动标题栏、最小化控件、浮动态助手按钮、客服式消息卡或重复聊天 header。

Leader Topic 的头像沿用项目资源中的绿色 low-poly 龙图标。入口形态、局部提升与完整可见边界唯一遵循[《左下角导航与右下角工具组》](spaces-and-layout.md#左下角导航与右下角工具组)，内部龙头像保持清晰、完整和不变形。不得用新生成的角色头像、纯色字母或通用 Provider glyph 取代项目龙头像。

浮窗关闭后只变为不可见并交还焦点，不能卸载或清空其 Topic/Region；再次打开应保留原 Tab、输出和滚动位置。悬浮头像普通点击后必须呈现可见、可聚焦、可输入的浮窗，拖动阈值内的点击不能被吞掉；入口可切换为与底部三项同组的 compact 形态；Board footer、Session chrome 和 Agents surface 不再各画一套内联菜单。

头像与展开面板的可见关系、必要动作和无独立 title 的边界唯一遵循[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)。悬停、固定和收起行为沿交互 SSOT 的同名 Mote 合同，不保留三个点或另一份开合状态；不增加第二枚关闭头像或远距离的重复切换按钮。

不显示三个点操作按钮；入口形态与密度统一遵循[《左下角导航与右下角工具组》](spaces-and-layout.md#左下角导航与右下角工具组)。打开、固定和收起沿[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)，不增加独立浮动态收纳按钮。头像外层沿当前入口合同的表面、圆形轮廓与焦点语言，不画绿色描边；绿色只作为品牌图形和注意力语义。面板锚点和视口适配唯一遵循[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)，保持入口与面板的视觉连接。

## Leader 一体式对话面

Leader 浮窗使用清晰中性细边框、外阴影与实色内容底，标题和内容同底色。标题区收紧至 36px，头像融入同一行，不显示内部 Topic ID，不重复放最小化和关闭这两个相同动作。展开头像缩至适配标题行的尺寸；毛玻璃保留在独立悬浮入口，不牺牲正文可读性。默认对话模式的行为归交互 SSOT。

Leader 内容区的身份提示采用一条短的职责说明和一个明确的“先澄清、再分配、经确认才写入”状态槽，不增加高大的客服式欢迎卡。对话内容、Composer 和工作区事实仍沿用普通 Topic 的密度；职责约束由固定 Leader Wiki 提供，普通 Topic 不显示这条额外提示。

## PMO 浮窗与 Board 工具栏的紧凑度

本轮 Space 迭代同时重新审视左下角 PMO Teams 头像的交互与表面，范围和命名约束见 interaction[《Space、Folder 与 Topic》](../behavior/spaces-and-layout.md#spacefolder-与-topic)。头像、Space 树条目与完整工作面使用可辨认的一致身份语言；实例名称、产品类型、运行状态与展开状态各自清楚，不让一个装饰效果代替这些不同事实。底部头像保持固定快捷入口；快捷面标题栏提供打开完整 Space 与收起，SOUL.md 编辑位于同一 Space 的树条目。沿用既有密度、减少动态效果与焦点语言，不添加重复的入口或角色说明栏。

PMO 展开面使用一体式短标题行：标题字号服从正文元信息档，头像与标题行接合，边框和阴影清楚但不靠高大的留白制造层级。标题行高度不应成为对话首屏的主要占用；完整名称放在 tooltip/无障碍名称中。Board 工具栏采用单行、单网格负责人布局；Project Rail 被遮挡时不保留 180px 的空 chrome，也不让侧栏按钮与 Board 图标落在同一格互相覆盖。

Mote 的入口位置与独立尺寸见[《左下角导航与右下角工具组》](spaces-and-layout.md#左下角导航与右下角工具组)，页面内不再保留第二个浮动头像。当前目标、展开边界与动效唯一遵守[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)。

## Mote 归档与恢复

行为唯一见 interaction[《Mote 归档与恢复》](../behavior/motes-and-coordination.md#mote-归档与恢复)。沿原 Mote 行菜单提供可辨的 Archive/Restore 动作，Space 的 Motes 区用一处紧凑“显示已归档”控件发现原对象；已归档标识使用次级文字，不借颜色伪装执行状态，不另加管理页或重复状态栏。当前归档 Mote 的原工作面保留紧凑状态与恢复动作，主身份的不可归档说明紧邻原动作。宽窄窗口、cards/avatars 两态与长名称下，菜单、恢复、显示已归档及原正文输入/Tab 控件可命中、可键盘操作并保持返回焦点；未确认/失败用原次级服务窗说明，不能遮住原输入或占据主要正文。

Space 侧栏缩到支持的最小 180px 时，Mote 名称仍须可辨、Archived 完整可读，Restore 和真实状态入口仍可操作；不能抬高最小宽度或让名称被挤成零宽。空间不足时，固定／取消固定与编辑 SOUL 等次要动作收进该 Mote 原有的上下文菜单，鼠标和键盘均可到达；宽侧栏保留原行内操作，普通 Topic 和 Folder 不因这条约束改变。长名称可在名称列省略，完整名沿原 tooltip／无障碍名称可读，不另设窄栏菜单引擎或丢失原对象的动作。

## Mote 头像与主 Mote

头像编辑、同一外观与默认不可删主身份的行为唯一见 interaction[《Mote 头像与主 Mote》](../behavior/motes-and-coordination.md#mote-头像与主-mote)。本地图片在现有圆入口、cards/avatars 两态左栏与 Space 的原身份槽内使用统一比例与可预见裁剪，不为照片放大导航、挤占状态或重复加身份标题。选择、真实状态及主身份说明有各自可读信号；头像图案/色相不承担运行或选中事实。沿既有局部编辑面，用一处预览、明确保存/取消/恢复默认与紧凑次级失败提示；宽窄窗口中图片选择、缩放和原必要控件可命中、可键盘操作。主身份的保护说明紧邻原管理动作，避免将“不能删除对象”画成整位 Mote 的动作全部禁用。

用户要求「左下角 Mote 图标直接彩色，不要灰」。Mote 的入口、已打开浮窗名册、Space 与正文中同一身份头像保持所选图片或 Make a face 的原色，不因未选中、睡眠、恢复未知或工作面位置统一降饱和、灰化或降低头像不透明度；手动 icon 保其原所选图形与配色，不虚构彩色图案。没有图片或 Face 而使用默认／seed 或手选图形的对象头像，也以既有主题 accent／身份色保持稳定可辨，不新增随机色或身份注册表。这里的原色约束限于对象身份头像；普通类型标记与菜单／工具动作 glyph 仍沿[《控件语言》](shared-rules.md#控件语言)中 Mote 类型标记的文字颜色规则，不能把全部 MoteIcon 调用染色。原选中标记、真实状态文字／角标和键盘焦点继续承担选择与状态，颜色不冒充运行事实；不扩大到无关工具图标或改变 Folder 的活动新近度呈现。行为与外观存储仍只见 interaction[《Mote 头像与主 Mote》](../behavior/motes-and-coordination.md#mote-头像与主-mote)。

用户要求 Mote 图标“讲究一下”：主身份的项目龙保持原轮廓与辨识度，二维捏脸有清楚的部件预览与选中反馈，不沿普通项目/Topic 的小图标网格表达整张脸。捏脸面沿原局部头像编辑器，少量部件分类、单一脸部预览和保存/取消/恢复默认保持主次；宽窄窗口与键盘均能完整操作，不添加人格页、重复身份标题或另一处常驻头像。日常活动大部分时间保持安静，低频发生短小、平顺收束的眨眼、视线或轻姿态，动作间有清楚停顿，不持续循环摇摆，也不让多个头像整齐同步。五官状态变化保持所选外观，睡觉、思考与真实工具联动仍用小幅表情表达；不使用整颗头像持续旋转、闪烁、粒子或遮住脸的工具徽章代替五官动画。原龙、上传图片与图形的轻姿态保持原色和清楚轮廓，不被虚构成另一张脸。小尺寸优先保脸与必要状态信号，动静切换不改命中区、按钮几何或相邻正文。减少动态及隐藏条件下保持静态可辨表情和原非颜色状态提示。日常活动的对象范围、真实状态、事件出处、停止动态与成本边界只见 interaction[《Mote 头像与主 Mote》](../behavior/motes-and-coordination.md#mote-头像与主-mote)；交付图审至少亲看正常、窄窗和真实失败/未知完整画面，并核对动态过程，不以截图或采集成功代替动画品位通过。

用户要求 Change Avatar 的面板质量更高，至少采用设置界面同样的液态玻璃切换效果。`Make a face` 与 `Icon or image` 并排且选中可辨，默认进入方式与保存语义只见 interaction 本节；优先复用 Settings 已有 `LiquidSelectionSurface` 与原生选择/焦点机制。面板以一处居中、足够看清部件和表情的大预览为视觉重心，方式切换、五官调整或图片/图标选择、保存/取消具有清楚主次；不用普通小图标网格和拥挤按钮承担整张脸的编辑。正常与窄窗保预览、必要动作和键盘焦点完整，动态玻璃尊重 reduced-motion，失败提示不遮挡预览或待保存选择。

骨骼／关节式五官动效保持小幅、连续、可组合的姿态，视线回应附近鼠标而不突然跳整张脸；眉、眼、嘴与原真实状态能同时读懂。头像小尺寸中仍看得出视线和表情，中心预览可看清变化；不能靠旋转、闪烁、粒子或整图帧更换充数。明确的正常、鼠标近/远、工作/待处理/未知及减少动态过程需独立亲看，静态截图不能证明连续运动。实例作用域、停止条件、事件出处、图片/icon边界和相关成本只见 interaction[《Mote 头像与主 Mote》](../behavior/motes-and-coordination.md#mote-头像与主-mote)。

Board 左侧清单的视觉单位是 Demand 卡片。零 Demand 只显示一条可操作的空态和创建提示，不能显示 Branch 名、`main` 或其它技术上下文作为占位行。创建按钮保持和工具带同一低高度，创建后再展开 PMO 对话，避免先弹出一个空的大面板。

## PMO Teams 快捷面的定位与密度

临时和固定面统一沿[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)贴近入口并适配视口，不保留自由移动、最大化或独立位置控件；有界尺寸拖拽与记忆只见交互 SSOT 同名 Mote 条目。对象选择、动作与单一内容边界共用原工作面语言，不为定位恢复独立身份标题带。

## PMO Teams 浮窗的参考驱动简约规则

- 参考成熟桌面浮动工作面的紧凑工具区：单行目标 32–36px，横向 padding 8–12px；头像/身份图标 18–20px；关闭、新建、分屏等动作使用 24px 命中区。对象选择、必要状态与动作沿[《Mote 快捷入口与当前协调上下文》](#mote-快捷入口与当前协调上下文)，不再保留独立身份标题带。
- 完整职责与 Session 信息进入按需详情、无障碍名称或原工作面，不常驻副标题、内部 Topic ID 或欢迎语。Mote、Tab、实际执行者各自只说明自己的事实。
- 顶部优先放真实对象选择与 Tab/Region 操作，不和嵌入 Workbench 的 Tabbar 形成“标题栏 + 第二标题栏”的两层大 chrome。
- 快捷面只使用一个内容边界和一个阴影层；外层负责入口锚点与视口适配，内层工作面负责内容。不要给同一层级连续套边框、胶囊和卡片背景。打开后的首屏内容应尽可能从第一行工具条下开始。
- 简约性是可验证约束：删除某个标题、分组或装饰后，如果信息仍由图标、Tab、状态和 hover 提供，则该元素必须删除；新增视觉元素必须说明它表达了哪一个用户可操作事实。

### 名册密度与读取提示

Space 协作者名册的名字使用小字号、单行直接截断，宽度不超过头像；完整名字保留在 hover/focus 提示及无障碍名称中。列数随可用名册宽度与用户保存的头像尺寸自然变化，不缩小用户头像设置来凑固定列数。单个 Mote 的资料读取失败提示跨名册行清楚呈现，保留同一头像与入口，不把长错误挤进头像格、遮挡相邻对象或已有输入。
