# Note 编辑与文件会话的实现

本文说明 Desktop 与 Mobile 编辑 Note 时的当前源码机制：远端新稿怎样合入正在编辑的草稿、怎样映射到富文本编辑器，以及保存结果怎样对账。文件格式与公共写入回执见 [Note Markdown 与元数据](../specs/note-markdown.md)，用户可感知的编辑约束见[人和 Agent 协同编辑](../design/behavior/knowledge-workflows.md#note-中-agent-与人的协同编辑)。源码机制不代表某个安装或运行实例已通过验收。

## 文件会话

Desktop 的 Note 与 Source 视图共用同一个 `FileDocument`、文件监听、保存队列与持久草稿；Mobile 的 Note 编辑使用自己的编辑状态。一个文件会话分别保留三类事实：已保存的基线、之后的本地输入、已经发出的保存意图。

远端原文与本地草稿的合并使用同一个精确 diff3 与稳定块身份检查：

- [`mergeLiveNote`](../../packages/client-ui/src/note/note-live-merge.ts) 把富文本校验与 diff3 放进 browser Worker（`note-live-merge.worker.ts`）执行，不占用输入线程；Worker 失败时结果为 `unavailable`，输入与目标保留，并提供重试入口。
- 不能确认安全合入时，保留基线、当前、提议三份正文；观察失败不能冒充对方没有修改。

## 远端新稿映射到编辑器

富文本编辑器收到新快照时，[`NoteSnapshotSync`](../../packages/client-ui/src/note/note-snapshot-sync.ts) 在 Worker（`note-snapshot.worker.ts`）中按稳定结构与实际内容差异生成多个 ProseMirror Step；只有 ProseMirror 的纯模型字段跨越 Worker 边界，DOM、渲染与插件代码留在编辑器 owner。[note-snapshot-transaction.ts](../../packages/client-ui/src/note/note-snapshot-transaction.ts) 把这些 Step 应用为一个设置了 `addToHistory: false` 的事务：选区与已有撤销历史随之映射，远端事务不进入本地撤销组。快照 Worker 失败时保留编辑器、输入与同一目标快照，并报告显示稿与新稿；编辑器内容仍是失败前的同一份时，`NoteSnapshotSync.retry` 以原观察到的快照重试。

- 等待快照映射期间可以继续输入。每次变化都携带该事务实际编辑前的内容，文件会话把这段输入映射到自己的最新草稿。
- 尚未映射完成的基线、目标与输入随草稿持久保存。同一编辑链的连续输入可以聚合；来自不同实际基线的输入按各自的增量依次映射，保存等待映射结果。
- 输入法组合进行时（编辑器 `view.composing` 或宿主报告的组合状态），快照映射暂停；组合结束后先发布最终输入，再接收待映射的内容。
- 段落重排或匿名结构变化无法确认位置映射时，保留编辑器与撤销上下文，可只读比较显示稿与新稿；用户明确选择继续编辑显示稿时，先把新稿存入保留稿，再切换当前草稿。这一过程不自动写文件、不重置编辑器，也不补造块身份。
- 任一阶段出现重叠时，保留最新的显示稿与各份原稿；用户可以展开、选择保留稿，并检查结果未知的请求。选择正文不会重放或删除原请求，也不能用旧编辑器的全文覆盖已接收的新稿。

## 保存结果的对账

- `written` 与 canonical 内容是否可用分开处理。内联内容明确不可用时，保留已写的 revision、历史事件与原意图，读取同一 revision 的原文或已提交的事件后再确认内容；不能用提交稿补成 canonical。
- `unknown` 不因当前字节相同而被追认为已提交，也不自动重发原请求。
- Source 视图暂时写坏身份头或显式重建文件时，仍保留同一文件的尝试，身份不明则保持未知，不回到「字节匹配即确认」的路径。用户可以明确采用当前文件继续编辑，同时保留旧草稿与原请求，旧请求的结果仍为未知。
- 共享编辑器的本机草稿持久化失败时，原保存基线、请求与输入继续留在本工作面。其他工作面的更新保存为另一份稿；只有同一事件的已确认回执才按原提交稿对账，不能把保留下来的旧全文配上另一份稿的新 revision 再保存。

## 版本窗口、恢复与撤销

Note 的版本窗口只在展开且当前可见时读取历史元数据，按真实活动分组、续页；选定一个事件后才读取原始的前后内容，并用现有的只读 diff 编辑器比较。整篇恢复与批次撤销通过原文档的保存队列调用公共动作（`file.restore`、`file.undo`，合同见 [Note Markdown《整篇恢复与批次撤销》](../specs/note-markdown.md#整篇恢复与批次撤销)）；本地草稿与之后的输入保留，重叠时交回原文档的冲突处理。
