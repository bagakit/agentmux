# AgentMux 桌面端导航与会话栏需求

这份文档只写已经确认的产品结果。跨界面对象模型和 Owner 边界由桌面交互设计合同统一说明，不在这里重复。

## 目标

- 左侧项目栏、工作区工具栏和主工作区各做一件事，开关互不影响。
- 减少重复标题和空白栏，把更多空间留给终端、Agent 和文件内容。
- 同一条信息只在最合适的位置显示一次。
- 布局和操作采用成熟桌面应用的稳定模式，同时保留 AgentMux 自己的功能边界和视觉主题。

## 左侧项目栏

- Scratch（临时工作区）固定在最上方。星形图标和置顶位置用来区分它，行高、间距、文字和选中样式与普通项目一致，不画成带边框的卡片。配置顺序变化时，它的位置不变。
- Scratch 下方才是普通项目列表。项目过多时，只滚动这部分。
- Scratch 和普通项目都要清楚显示选中、悬停和键盘聚焦状态，并显示当前会话数量。
- 项目栏可以收起。收起只改变界面，不删除或重建工作区、标签、会话和分屏。
- 展开时，底部只放设置和主机两个图标按钮。底栏高 32px，按钮为 24px，不显示 “Settings & hosts” 文字。
- 设置按钮打开设置面板并落在第一个可操作的分区（Workspaces），主机按钮直接打开主机设置。两个按钮都要有说明文字和键盘聚焦状态。
- 收起后，整条项目栏消失，只在左下角保留一个 28px 的设置入口。它贴近角落，不使用重阴影或模糊背景，也不能挡住终端输入和滚动条。

## 顶部导航

- macOS 红绿灯后固定放两个按钮：第一个开关项目栏，第二个开关工作区工具栏。
- 两个按钮始终保持相同的顺序和位置。任一面板开关时，按钮都不能移动、重叠或消失。
- 项目栏使用侧栏图标，工作区工具栏使用双面板图标。图标方向保持不变，用按钮底色表示开关状态。
- 项目图标、品牌图标和文字不放进这组功能按钮，避免看起来像第三个开关。
- macOS 左侧先为红绿灯保留 80px，两个按钮的中心分别位于窗口左侧 94px 和 124px。
- 项目栏展开时，顶部区域跟随项目栏宽度。项目栏收起后，顶部区域缩到 180px，但不能完全缩进主工作区。
- 项目栏和工作区工具栏分别控制自己的面板。四种开关组合都要正常工作。

## Tab、分区和 Tab 内分屏

- 一个 Tab 代表用户认知里的一张完整视图。Tab 的名称、关闭、切换和恢复都以这张视图为单位。
- “Tab 分区”和“Tab 内分屏”是两个不同的功能，不能共用一套状态或用同一个结果冒充。
- Tab 分区用来整理整张视图。用户可以把 Tab 拖到不同分区、调整分区位置，或者把整个 Tab 移到新的分区。每个分区有自己的标签栏；移动前后 Tab 数量不变，Tab 内的内容布局也不变。
- Tab 内分屏只切分当前 Tab 的内容区域。分屏后顶部仍然只有原来的一个 Tab，名称和身份不变；新增的是这个 Tab 里面的内容区域，不是新 Tab，也不是新的 Tab 分区。
- 当前 Tab 内的每个内容区域可以获得焦点并独立调整大小。关闭一个内容区域只改变当前 Tab 的内部布局；关闭整个 Tab 才关闭这张完整视图。
- `Split` 明确表示“拆分当前 Tab 的内容”。`Move Tab to New Group`、拖到分区边缘等操作明确表示“移动整张 Tab”。两套入口的名称、图标、预览和结果都要能一眼区分。
- 不能用“创建一个空 Tab 分区并显示 New Tab”代替 Tab 内分屏。两种布局分别保存：工作区保存 Tab 分区布局，每个 Tab 保存自己的内部内容布局。刷新 Renderer 或重启 App 后也必须按原来的 Tab、Region 方向和比例恢复，不能把一个分屏 View 炸回多个独立 Tab。

- 每个 Agent（如 Codex、Claude）或终端窗格只保留一行标签栏，标签永远不能折成两行。名称过长时显示省略号。
- 只有一个窗格时，窗口顶栏和标签共用一条 36px 高的顶行。分屏后，窗口控制保留在 36px 顶行。每个窗格使用自己的 31px 标签栏。
- 终端或 Agent 内容紧接在标签栏下方，不再增加第二条会话信息栏。
- Agent 标签显示 Agent 图标、会话名称、状态点和关闭按钮。终端标签使用 Terminal 图标，不再用状态点冒充内容身份；名称、关闭和运行控制仍留在同一行。
- 选中的标签使用轻微底色和底部 2px 横线，不使用顶部亮线或整圈描边。
- 正在运行的会话在同一行显示 24px 的停止按钮。已经结束的会话不显示该按钮。
- 从标签栏点击停止按钮前必须确认，并继续使用统一的 Run 停止流程。关闭 Tab 内的单个 Region
  只改变内容布局；关闭承载最后一个 Terminal Region 的完整 Tab 时直接停止 Run；关闭承载最后
  一个 Agent Region 的完整 Tab 时弹出确认，默认停止并关闭，同时允许明确选择保留 Session
  后仅关闭 Tab，或取消。
- 当前 Tab 的工具区直接显示 `Split` 按钮。点击后选择左、右、上、下，在同一个 Tab 内新建内容区域；Tab 数量和 Tab 分区数量都不变。
- Tab 被移动到较窄的分区后，标签不能被压成一排难读的小块。每个标签保持稳定的可读宽度，名称始终单行显示，太长就省略。
- 一个窗格放不下所有标签时，只在这个窗格的标签栏里横向滚动，并显示左右导航。鼠标滚轮、触控板横移都能浏览；新建或切换标签时，当前标签会自动滚到可见位置。
- 调整 Tab 分区宽度只改变“现在能看到几个标签”，不会缩字体、把标签折成两行、自动搬动标签或重新分配标签。
- Tab 分区树、Tab 内部分屏树、焦点和尺寸只由 Desktop App 保存；Core 提供与具体 Agent 无关的空间操作语义，ctxmux 只持有 Run、PTY 和进程，不保存界面布局。
- Agent/Terminal Run 的持久化仍由 Core/ctxmux 负责；Desktop 只持久化“这些 Session 在哪张 Tab 的哪个 Region”这一层展示关系，不复制 PTY、Replay 或 Agent 状态。
- 默认创建页可以提前启动一个可复用 Terminal，让用户直接输入命令，也可以一键把它变成正式 Tab。用户认领前，它不属于任何 Tab；Desktop 必须准确记住这个未认领 Session 的 ID。下次启动只清理这些明确记录的 Session，并在恢复布局时排除它们，不能让它们冒成新 Tab，也不能切走当前 View。用户认领后，它就按普通 Terminal 恢复。

## 会话信息放在哪里

- 会话名称和运行状态直接放在标签上。
- 鼠标停在标签上时，可以查看主机、开始时间和最近活动时间。
- 完整会话 ID 从标签的右键菜单复制，不常驻占用一行空间。
- 最近一条消息只在活动记录（Activity）视图显示，不放在终端上方。
- 这些调整只减少重复显示，不删除会话和运行状态数据。

## 设置面板结构

- 设置导航按本项目规模收敛成两个清楚的分组，不增加无内容的分类。
- 左侧导航按 `Setup / Preferences` 两个分组标题排列，同组内的分区列在标题下方。
  - `Setup`：`Workspaces / Hosts / Agents`——用户需要注册和配置的资源。
  - `Preferences`：`Appearance / General`——外观和只读说明。
- 分区顺序按“可操作性”排：能配置的资源在前，静态说明的 General 在最后。不再让只读的 General、只有主题开关的 Appearance 排在最前。
- 打开设置默认落在第一个可操作分区 `Workspaces`，不再落在只有只读说明卡片的 General（那是一个每次打开都空转的死页）。
- 内容区顶部的 eyebrow 显示当前分区所属的分组名（Setup / Preferences），不再显示固定的 “Configuration” 占位标题。
- 搜索过滤仍然有效：整组没有命中就整组不渲染，全部没有命中时显示无结果提示。
- 这次不新增设置项、第二套状态或占位页；General 在补上真实设置之前保持在最后。

## 验收标准

- Scratch 始终固定在普通项目之前，项目列表可独立滚动。
- 展开态底栏为 32px，只有设置和主机两个图标按钮。收起态左下角只有一个 28px 设置入口。
- 项目栏和工作区工具栏分别开关时，顶部两个按钮的位置不变，内容和标签没有遮挡。
- 看板（Board）、普通工作区、单窗格和分屏状态下，顶部导航都不会重复、错位或叠在一起。
- Agent 和终端窗格只有一行标签栏，终端内容直接从下一行开始。
- 当前 Tab 可以从自己的 `Split` 按钮向四个方向拆分内容；操作前后仍是同一个 Tab，不新增 Tab 或 Tab 分区。
- 多标签分区变窄后，标签仍保持单行和可读宽度；放不下的标签通过该分区自己的左右按钮、鼠标滚轮或触控板横向浏览，当前标签始终可见。
- 标签右键菜单和拖拽可以把整张 Tab 移到其他分区或新分区；它们与 Tab 内分屏是两套清楚、独立的操作，任何一步都不能产生含义含混的 `New Tab`。
- 运行中的会话可以从标签栏停止，结束后的会话不显示停止按钮。所有图标按钮都有鼠标提示、供读屏软件识别的名称和可见的键盘聚焦状态。
- 设置面板左侧导航按 `Setup / Preferences` 两组显示；打开设置默认落在 `Workspaces`，内容区 eyebrow 显示所属分组名而不是固定的 “Configuration”。
- 项目规定的自动检查、桌面端代码检查、正式版构建和界面测试全部通过。

## 本次不做

- 不增加任务、自动化、搜索、通知、帮助或反馈入口。
- 不改变 Scratch 的目录、名称和启动方式。
- 不增加项目栏宽度拖动、自动隐藏或悬浮抽屉。
- 不把左侧项目栏和工作区内的文件、分支工具栏合并。
- 不为这次改动增加新的配置项、第二套状态、兼容代码或占位功能。
