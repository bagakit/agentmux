# 历史清理改坏引用与候选代码

## 定性

**P0 级红线行为，已确认的故障发生在候选生成和验证阶段。** 历史整形把隐私扫描命中当成改写业务值的授权，误伤对象引用，并生成不能解析的候选代码。这违反了“控制事实不得依赖展示文案或假定”的边界：字符串的外观不能决定对象身份、引用类型或执行语义。责任在本次清理工具和验收判断，不在原功能作者。

用户明确将本次事件定性为违反红线导致的故障。现有证据没有证明这些错误候选进入实际运行的应用，也没有证明原 Session 丢失、健康 Run 被停止或用户数据被删除；不能把红线定性扩大成没有证据的线上后果。红线判据见 [AGENTS](../../AGENTS.md#通用机制与-provider-适配) 和 [RED-LINES](../../RED-LINES.md)。

## 用户可见症状

> “历史整形中的路径、时间清理误改语义，导致验证失败”

> “以最近几次修正的 case 为例”

以下案例属于同一次整形，但不是同一个运行错误：

| 案例 | 错误行为与实际信号 | 级别与修正 |
| --- | --- | --- |
| 引用被误识别 | 子串替换进入 Agent URI、相对材料引用和 skill 引用。旧 helper 恰好返回相同字节，掩盖了错误分类；换成真正派生根后，这种表达式会改变引用目标。独立语义审查拒收候选。 | P0：保留三类引用的原始字面量和目标，不交给文件路径替换。 |
| JSX 被拼坏 | 清理 Gallery 草稿里的混合模板表达式时，转换器拼接了错误的表达式结构。保留的失败候选能直接复现一条 TypeScript 解析诊断，错误码为 `1005`。 | P1：按表达式边界生成修改，重新解析完整文件，再导入和渲染真实 Gallery。 |
| 固定根藏进 helper | 一批普通模拟路径改成 helper 调用，但 helper 仍从文件系统根拼接固定目录。静态字面量消失，实际根没有随模块位置变化。审查拒绝把字节相等当作动态化完成。 | P1：逐版本改用实际模块派生根，配对所有输入、配置和预期；真实临时目录用途另行判断。 |

第一例是错误授权，第二例是生成代码损坏，第三例是验收依据失效。三者不能用一次“扫描无命中”或“文件能解析”共同代签。

## 影响面

受影响的是历史转换器产生的引用表达式、Gallery 候选源码和部分测试路径。故障使候选无法通过解析或语义审查，并使原有通过结果不足以证明新版本有效。已确认的普通路径修正覆盖二十五个历史版本；另八个版本的实际临时目录、短连接路径和系统接口用途单独保留，没有按整个文件豁免。

**以下不受影响：**本次证据不支持原 Session、Run、持久工作面被破坏的结论。原始提交与未保存工作先行保全；错误候选留在本机验证范围，最终主干消费的是修正后的整树投影。原始引用在最终 [Markdown fixture](../../apps/desktop/scripts/fixtures/markdown-parse-reuse/entry.tsx)、[材料准备测试](../../apps/desktop/test/goal-delegation-materials.test.ts) 和 [Gallery](../../apps/desktop/src/renderer/src/components/ObservationSurfaceGallery.tsx) 中保留。实际系统目录、协议身份、计数和未观测哨兵没有因为外观相似被统一替换。

## 止血措施

停止对应转换器继续写入，保留原始 blob、失败候选和未保存内容；从原始版本重新生成有明确语义边界的候选。不要通过删除用例、改掉预期、放宽阈值或清空原工作面取得通过。

本次已纠正引用分类、模板生成和普通模拟路径的根派生，补验真实消费者后再切换主干。对仍在使用原 Session 的用户，不需要为了清理候选而停止、替换或删除原 Session。

## 根因分析

直接原因是替换器没有守住字符串 token、引用类型、JSX 表达式和生成代码的边界。带斜杠的片段被归入文件路径；展示文本的拼接改动也进入可执行表达式。把数值改写成 helper 时，外层源码、嵌套生成源码及模块执行方式同样需要分别判断。

根因是**隐私清理流程把“扫描器认为可疑”升级成了“可以改写该值”**，并用不承重的证据证明完成：没有字面量不等于没有固定根，解析成功不等于引用目标正确，整树忠实应用映射不等于映射合理。这种过度防御扩大了授权范围，反而损害被要求保全的内容。

已有规则存在但没有绑定住转换步骤。规则要求身份与控制目标由原 owner、协议和实际回执确认，流程却先依赖词形猜用途，再让测试适应转换结果。早期检查偏重命中数量、解析和数值等价，缺少引用回调、不同模块根和实际打包消费的独立判据。只有把原始引用、输入与预期的关系作为不变量，才能发现“输出看似干净，含义已经变了”。

## 改进措施

1. **收窄改写授权，先分类再生成。**
   - 是否足够 root：覆盖本次三类误识别引用及二十五个普通路径版本；八个真实系统用途版本逐项保留，不宣称全仓从此没有误分类。
   - 能否彻底避免：正确的 token 与语义分类本可阻止这些误改；扫描本身只能发现候选，不能单独保证分类正确。
   - 是否降低系统熵：删除宽泛子串改写，复用现有引用与路径机制，不增加各文件自己的例外开关。

2. **验证实际表达式和消费者，而非 helper 名称。**
   - 是否足够 root：覆盖一个已确认损坏的 Gallery 候选、三类引用和二十五个模块根版本；补查两份嵌套生成源码、四个字段，以及七份 CommonJS harness 的实际 bundle。
   - 能否彻底避免：解析和消费者检查能在合入前发现同类回归，不能阻止作者再次写错转换器；嵌套生成源码的逐字节比较只能证明对应受控消费者。
   - 是否降低系统熵：沿已有 parser、组件和打包链验证；模块专用 helper 增加少量表面，但避免把依赖模块元信息的实现塞进不支持该语义的执行环境。更简单的统一导入方案因此不能直接使用。

3. **证据绑定精确版本，变化后只补验真正受影响的范围。**
   - 是否足够 root：最终覆盖三百零三个原提交的整树投影；旧客户端资格中两份已变化的加载对象由实际消费者补验，十五个旧材料用例被新执行替代。
   - 能否彻底避免：版本绑定能阻止拿旧通过结果批准新 blob，不能替代业务语义判断，也不能证明尚未运行的产品场景。
   - 是否降低系统熵：消费同一份精确映射与回执，保留原失败，不再创建平行的“清理通过”口径。

## 验证

- 措施一：最终引用见 Markdown fixture 的 `show`、材料测试的 `target`、Gallery 的 `ObservationSurfaceGallery`。真实 Markdown 入口的六条动作回调与原版逐字相同；路径 helper 在不同模块位置求值，普通根随模块位置变化。源码：[共享 fixture](../../test/fixture-values.mjs)。
- 措施二：失败的 Gallery 候选被重新解析，确有错误码 `1005`；最终版本实际导入并渲染。新增客户端对照两侧各八十四项通过。嵌套生成源码前后逐字节一致、可解析；字段偏移变异被检测。七份 CommonJS harness 实际打包后没有残留模块元信息依赖；这不代替启动 Native Runtime 的验证。
- 措施三：最终三百零三个整树检查点、四百六十六个单亲提交与原始输入逐一匹配。客户端有效覆盖每侧三百九十六项，三百四十五项通过、五十一项既有失败；复用了未变化的加载版本，没有声称全量重跑或全绿。三个失败诊断仅原侧多出清理错误，原文单独保留。

本报告是纯文档整理。上述数字来自对应版本的实际回执，本次没有重新运行实现测试、编造新的变异结果或宣称应用安装验证完成。原始后像、失败候选、完整诊断、命令、变异和加载对象记录按[过程资料边界](../process-directories.md)留本机；不复制其中的环境信息到仓库。资料缺席时应标记缺证，不把正文当作可重新执行的通过凭据。
