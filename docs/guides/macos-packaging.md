# macOS 打包与安装

本页面向并行开发中的一次打包交付。成本与验收范围由 [AGENTS](../../AGENTS.md#并行协作与交付) 定义；构建、更新路由及进程机制见 [Desktop 更新架构](../architecture/desktop-updates.md)，数据与恢复要求见 [Session 恢复](../design/behavior/session-recovery.md#更新安装与恢复验收)。本页不增加发布门禁，也不把某轮临时安装脚本当成正式入口。

## 最短交付路径

1. **锁定开包时最新的 committed main。** 记录 commit 与 tree；共享工作区有并行修改时，在该提交的独立干净 worktree 构建。保留他人的修改，不用 stash、切分支或清场换取干净目录。构建中 main 继续前进不触发自动重打；交付时说明本包锁定提交，不能称其包含开包后的提交。
2. **准备锁定依赖，选择一个入口。** 缓存齐全时可用 `pnpm install --offline --frozen-lockfile`；缓存缺项则由正常锁定依赖安装补齐。只出包用 `pnpm package:mac`，同时安装用 `pnpm package:mac:install`。打包入口本身已执行依赖构建、组包、签名和产物检查，外层不再先跑一遍完整 build、typecheck 或测试套件。已有签名候选的安装续做不重新调用整条打包命令。
3. **复用同一候选与已有结果。** App、DMG 和安装副本来自同次构建；按已完成阶段核对准确身份，复用功能任务已有验收。DMG 压缩和 App 复制会争用磁盘，不默认同时启动多个重 I/O 任务；同机其他 Agent 正在工作时优先控制并发和重复副本。只在阶段转换或具体失败时读取相关日志，不高频扫描全局进程、目录、工作面或重算整包散列。
4. **安装后核对实际加载，再清理。** 从 `~/Applications/AgentMux.app` 正常启动，核对实际 Main、Renderer、必要持久保存、原工作面和相关 Runtime／Run 事实；磁盘身份或版本号不能代替已加载身份。然后清理本次不用的中间产物与 worktree，保留在用映像、未保存工作和必要原始回执。清理不能成为安装前置条件。

## 必要核对与触发式补查

| 阶段 | 本次应消费的证据 | 何时才补查 |
| --- | --- | --- |
| 源码与构建 | 锁定的 commit／tree、准确构建结果 | 源码身份漂移或具体编译失败 |
| 候选与 DMG | 原入口产生的签名、来源身份、组装结果 | 候选字节变化、签名失败或容器身份不符 |
| 安装与重启 | 原安装动作结果、实际加载的包和 Renderer、工作面及相关 Runtime 事实 | 退出、加载或保全出现具体失败／差异 |
| 清理 | 本次准确目录的提交、未保存内容与占用事实 | 目录存在独有工作、在用引用或归属未知 |

这不是让操作者再手工执行一遍同名检查。入口已有准确结果时直接复用；缺口只补该项。安装不重新证明全部功能、打开隐藏 Browser 页面、等待所有页面联网或要求同事停止开发。候选未变时不在原流程外重复全量回归、图审、深度签名核验、全文件比对或全仓资源盘点；原安装入口对新复制目标的签名与身份核对仍有自己的范围。

## 失败后从准确阶段续做

- **先保留原 operation 与结果。** 区分未开始、暂存完成、已替换、已启动和观察未知。确认原进程及实际副作用后再决定下一步；未知不自动重放，后续成功不覆盖原失败。只修复失败阶段，复用仍有效的构建、签名候选和暂存副本。
- **复制慢不等于 App 故障。** 不给额外包装器随意套一个比真实复制更短的总超时；原安装入口的复制并未使用 GUI 就绪时窗。超时后先确认复制进程已结束、canonical App 是否变化，再处理该次不完整暂存目录。不要因复制失败重编译或重签未变化的候选，也不要改大 GUI／Runtime 时窗来处理磁盘复制问题。
- **启动烟测等待原消费者的真实就绪。** Hosted consumer 初次连接尚未确认时，保留原诊断并等待其既有后台重连；恢复通知只唤醒同一消费者的完整 bootstrap 确认，不直接代签 ready。父级原总时窗继续约束烟测，不另加重连循环、预算或 Runtime；准确终局与取消仍释放本次观察。
- **Host 身份与 UI 读取不另套固定子进程总时窗。** 续做原安装时，消费原 fenced bootstrap／`app.inspect` 的真实回复或失败，不提前杀掉仍可完成的查询。保留原 UI activation 的轮次等待范围，不把它宣称为已实现的在途取消。原 Runtime、PID、UID、出生时间与映像归属核对继续有效；观察未知不授权停止未知进程，也不要求重构未变化的已签候选。
- **GUI 与 Node 模式分开。** GUI 启动沿原入口从环境副本移除 `ELECTRON_RUN_AS_NODE`；CLI 和 semantic Host 的有意 Node 模式保留。这里只调整 Electron 启动模式，不移除、改写或伪造 Agent 凭据与权限身份。
- **退出检查只判断真实当前对象。** 进程 `admissions` 是历史，当前 `serving` 与准确 UID/PID/birth 才参与当前归属判断。历史条目仍在不等于进程仍活；未知模式也不能猜成 GUI 或后台。semantic namespace、GUI worker 和独立 Run 的范围沿原机制确认，不能从脚本名或命令行外观猜测后强杀。旧 GUI 在切换前重开时，刷新它的准确保存／退出观察，复用已准备好的候选。
- **接口拒绝只解释该次操作。** Core `runtime.*` 的身份拒绝不等于 macOS 文件安装也被拒绝；但不能通过去掉凭据、换终端或代按确认来重做同一个被拒操作。依据用户已有安装授权和准确操作范围继续可执行步骤，不额外制造人工确认门。仅完成 App／Renderer 替换、保留旧 semantic Host 时，应分别报告这些结果，不能宣称 Core 服务已重载或 Native 已升级；正式安装器的 Host reload 路径仍以实际源码与回执为准。

## 记录耗时，不把经验变成额外验收

使用现有阶段时间、失败回执和必要日志区分编译、签名、复制、容器压缩、退出观察与清理。签名和复制本身可能耗时，不能据此虚构“校验很多”；重复构建、过短超时导致的重复制、把历史当存活进程而循环等待，则属于应消除的操作负担。没有具体异常时不另跑资源 benchmark 或全局采样来证明打包足够轻。

本轮原始时间线、具体提交、PID、临时脚本与重试证据只留本机过程目录；后续可复用做法保留在本页，不能从文档更新推断打包工具已获得新的实现能力。
