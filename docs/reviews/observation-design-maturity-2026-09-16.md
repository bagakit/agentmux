# Workflow 架构与观察视觉成熟度

## 已批准范围

用户在 2026-09-16 明确要求创建 tracker 并实现：Workflow 技术向原有成熟组件靠拢；现有聊天及观察表面向 Workflow 视觉语言靠拢；梳理设计规范；review 前端技术栈是否有更好选择。该讨论是本计划的批准依据，不代表批准远端发布、运行时架构迁移或更换技术栈。

设计约束只在 `docs/design/agentmux-desktop-interaction.md` 和 `docs/design/agentmux-surface-density.md`。本文件记录执行边界与证据，不另立设计规则。

## 执行边界

先建立独立 Gallery 构建作为最小可观察路径。之后 Workflow 架构、现有观察视觉、规范与前端技术栈评审三支独立执行，汇合后在 Farm 验证实际组件。Workflow 仍不接入真实聊天事实；样式改版作用于现有 Activity、输入、权限与服务窗组件。

Workflow 保持纯展示输入；展示策略独立，数字与时间有明确单位；折叠默认策略随状态变更但保留用户意图；Dock 由宿主管理可见性；详情和无详情用可区分类型。无需新增全局状态管理器、通用组件框架或 Runtime。

## 依赖评审

- T-001 是独立浏览器入口与构建合同的 spine；后续分支消费该可见基线。
- T-002 只拥有 workflow 组件、模型、fixture 和其 Gallery 宿主；T-003 只拥有现有表面样式及对应真实组件预览；T-004 只拥有规范、栈评审和文档/依赖漂移检查。共享 Gallery 根由 T-002 管，T-003 用独立 `ConversationComponentGallery` 并由 T-002 接线。
- T-005 消费三个分支的同一候选，完成 build/typecheck/交互、视觉和变异验证。最终证据必须依赖已汇合代码；浏览器环境准备可提前。
- 不创建 Git restore tag：本轮不 commit，用户工作树与现有 Git 历史保留，精确 diff 为回退边界。

## 验收证据

执行后记录：独立构建依赖和体积、交互测试、定向回归、块级变异、排除定义文件的真实调用者、Farm 浏览器证据和规范漂移检测。尚未执行的验证不宣称通过。
