# Common conversation protocol

Core owns source-qualified conversation semantics. Clients retain presentation, drafts and reading state; Providers retain native interpretation; the original history, input and interaction owners retain their durable facts. Product requirements belong to [the conversation behavior SSOT](../design/behavior/conversation-mode.md); current consumer wiring is described in [the mechanism map](../architecture/conversation.md).

## Unified timeline and MECE

Agent Conversation must provide one clear, unified timeline for an exact conversation and requested scope. Its Core merge module aggregates actual speech and runtime observation signals after Provider interpretation; clients consume the same resulting event identities, ordering, content and provenance. The merge module reuses the original history, input and interaction owners, without creating a second transcript, Reader, Session or Runtime. Desktop conversation views and the Feishu connector are consumers of this contract, not independent owners of conversation reconstruction.

Provider processing interprets vendor history, callbacks and native input receipts into source-qualified facts. These are distinct observations of the original protocol, not separate client conversation models. Core alone integrates those facts with its original input and interaction facts. A new source contributes through that boundary; neither a view nor a connector adds source-pair association rules. Core owns accepted source pages, cuts and contribution accumulation in its bounded reading view; clients retain the resulting presentation and their scroll, selection, expansion and drafts. The current implementation and any unclosed reading paths remain identified in the [mechanism map](../architecture/conversation.md).

MECE (mutually exclusive, collectively exhaustive) applies to logical conversation events and their content within that scope:

- **No duplication:** one logical event has one timeline identity and one occurrence. Signals authoritatively tied to that event enrich or update it rather than creating another utterance. Its text, process parts, interaction and status belong to that event; signal, revision, render-fragment and delivery-attempt counts are not additional message or execution counts. Distinct original records remain independently traceable.
- **No omission:** every original input, reply, process, interaction and resource in scope must have an accounted-for place in the timeline or its original event details. Mixed records preserve all content parts and their order. Pagination, folding, reconnects and a missing source cannot silently remove content from another source. Unread ranges, gaps and unsupported or unavailable content remain explicit and reachable for continuation or recovery; a partial read cannot certify complete coverage.
- **Evidence-based association:** only authoritative identities and explicit source relationships can establish that signals describe the same event. Equal text, nearby timestamps, display names and body hashes do not establish a join. Unassociated runtime snapshots remain explicit observations with their original content and provenance, rather than being promoted into another Agent utterance or discarded as a duplicate.
- **One semantic order:** preserve original source order and confirmed relationships. Missing time, association or coverage stays unknown; merging does not invent timestamps, causality, authorship, input adoption or operation completion. Presentation and platform mapping retain these semantics.

These are required protocol invariants. The contract below defines the unified target; separate source reads do not by themselves prove its implementation or verification across consumers. Consumer obligations belong to [the conversation view](../design/behavior/conversation-mode.md#连续统一的对话列表) and [external conversation integration](../design/behavior/conversation-mode.md#共同对话协议与外部交流入口). Current wiring belongs to the [mechanism map](../architecture/conversation.md).

### Records, events and content ownership

Source-shaped adapters establish original records once. Semantic normalization consumes those accepted records directly, retaining their identity, revision and order witnesses; reading windows do not reconstruct records from presentation or recompute original versions to establish identity. An event revision describes its current contributing facts and does not establish input adoption, completion or authorization.

A source record retains its source-qualified identity, original item, revision and source-order witness. Native items and captured items keep their own shapes. The timeline accounts for every captured kind, including process, permission, lifecycle and system records. A browser-safe Core projection is the only owner of event role, recorded author, cross-source association and ordering policy; input projections reuse the same author interpretation.

A Provider interprets the declared original history format before projecting roles. When that format defines a canonical user event and separate model-context records, only the canonical event represents that native utterance; the context records retain their original content as process or detail. The original source metadata establishes the format; copied later metadata cannot redefine it. Missing or unknown format facts cannot justify discarding the only known speech. Corrected normalization keeps original raw identities and bytes while producing an accurate new revision; an old exact anchor or resource cannot silently resolve to a different current representation.

An event has a source-qualified anchor, a Core-produced revision token, a role (`message`, `process`, `observation`, `interaction` or `notice`), its contributing record IDs, and ordered content references. Original bodies occur only in the source records; content references identify a native part or an existing captured field together with the original record revision. Mixed message text, reasoning, tools and resources retain their original positions and remain reachable. Source records, events, messages, observations, revisions and transport fragments are distinct counting units. Execution counts require an accurately scoped invocation identity.

A native content part may carry Provider-owned `contentEligibility`: `public`, `private` or `unconfirmed`; absence is unconfirmed. This describes the original part's purpose at its record revision, independently of display role and author, and grants no audience or sending authority. Mixed records retain separate part facts. Normalization, strict wire reads and deferred resource wrappers preserve them; resolving a resource cannot upgrade the original selected part. External sharing consumes these facts under the [original sharing boundary](../design/behavior/conversation-mode.md#共同对话协议与外部交流入口).

Only an explicit `same-event` relation coalesces event identity. Invocation membership, `answers` and `observes` retain their distinct meanings. An invocation membership binds one exact original content part and revision to its complete source-qualified invocation identity, including a singleton member. It is not a pairwise edge requiring another record in the same read batch. Equal authoritative invocation identities describe one invocation; they neither coalesce parent messages nor assert that unread member content has been read. Core defines that identity once, and consumers only present the accepted memberships. Membership facts and the event revisions that include them must be independent of page size, fragments or unrelated intervening records. Providers and the original Core producers supply the typed references and their actual uniqueness scope; clients cannot manufacture them from opaque IDs, text, timestamps or display. A later authoritative association is an explicit coalescence/update, preserving every original record reference and unresolved operation. It does not append another utterance or create an alias Store.

Each original typed answer declares an `answers` relation to the semantic question identity: original source Host, managed Session, Provider/native source and the whole opaque question ID. This identity does not invent an unread request record or turn. Every answer record retains its own relation, including multiple answers to one question. `answers` and `observes` belong only to the event containing their originating accepted record; reading the target does not add an incoming relation to its event or change its version. Unread targets retain accurate coverage gaps. The strict unit codec checks the complete local answer and observation facts against the originals; a recomputed event hash cannot authorize a missing, duplicated or forged relation.

Explicit recorded Agent, external or human authors take precedence over generic captured roles. An unattributed Hook reply snapshot is an observation of a reply, not an additional utterance. Missing native data never removes that observation's original body. Missing Host identity permits reading but yields no navigable `ConversationItemRef`; it cannot be filled from current focus. Public reads always require the exact Host and Session.

Native collaboration messages retain their original record ID, turn, content parts and a `collaboration` value with `kind: 'message'`, the exact native `source`, and optional original `sender` and `recipient` actor strings. These actors belong to that Provider conversation namespace; they are not AgentMux Session IDs, executable directories or input authorization. Core presents the report as a message boundary without assigning the parent Session as its author or projecting it as a user input or parent assistant result. Missing attribution remains unknown; malformed optional attribution preserves the original content with a readable diagnostic. Conflicting native source attribution cannot confer a foreign identity. Existing history, context and unified conversation reads carry the same facts without a separate collaboration reader.

Within a same-event group, consistent explicit captured authors take precedence over an absent or default canonical author. Conflicting explicit authors retain `unknown` and an accurate source gap. This reading attribution does not change the primary record's role, public-content boundary, permissions or operation authority.

The original Core input writer may attach `inputRef` to its captured user message, reusing the original `AgentPromptInputKey`: the submission kind, Session, expected Run and message or submission identity. Its Host namespace remains the original captured record's namespace. This reference links the record to that input; it does not prove native adoption, Terminal authorship or an external delivery receipt. An external origin representation must match the original durable ingress claim's exact input reference and authenticated connection, room, binding and grant facts. Author and body equality alone cannot establish that relation. Older records without the reference retain their original content and an explicit unresolved publication gap; consumers cannot recover it by decoding opaque record IDs or matching text.

An explicit `native-conversation` input intent freezes its exact Provider/native source, expected Run and optional expected turn in the original input journal and admission. Ordinary terminal input keeps its existing target. Before native dispatch, Core freezes a fresh correlation containing the complete original input key in that input's durable `PromptSubmissionRecord`; later inputs cannot replace it. The Provider sends that value as the native client-message correlation through the same qualified Run actor. An admission response or matching client correlation is not by itself native adoption, a physical record locator, public-content authority or replay permission. Unknown outcomes retain their original claim and are inspected without redispatch.

The Provider may preserve the canonical native user item's original client correlation, semantic item identity, turn and exact native source. Core confirms `adoptedInput` only by reading that input's original durable claim and checking its complete frozen correlation, input key, Run, source and actor plan; Provider-supplied confirmation is discarded. The physical record locator remains independent of the native semantic item identity. One shared Core relation rule associates the captured user record's exact `inputRef` with the confirmed native record, making the native utterance primary and preserving every original submission as a contribution. This association does not change captured versions or grant publication of native context; qualified captured public content remains independently eligible under its original authorization and cut.

Adoption is qualified against the accepted reading inventory and its known counterevidence, not a claim of whole-Session uniqueness. Different original native items for the same input retain their separate utterances and an explicit ambiguity gap. The existing temporary reading view retains bounded identity/version witnesses when originals leave the window; it holds no second transcript or durable adoption Store. A canonical candidate whose original claim is not confirmed supplies no input key or adoption authority. Its exact source, turn and complete client correlation remain available as counterevidence when another item is later confirmed for that same tuple; temporary claim-read failure cannot erase an already accepted candidate. Ordinary native client IDs and different tokens or turns cannot borrow that confirmation. Witness overflow, or an accepted original version that no longer confirms its retained witness, leaves adoption coverage unknown without blocking ordinary reading or input. Full-window assembly validates the same relation rule across units; transport fragments do not create independent semantic evidence. Unread originals remain unread, and reading never settles or replays an unknown input or external delivery.

A Room Binding may select a native input source only in an explicit new bind/relink through `inputTarget`; this long-lived choice carries no turn ID. The original ingress claim freezes that target with the exact Run, and Core checks the frozen target alongside its original author authority. Publication source cuts confer no input authority. Existing bindings without this choice keep ordinary terminal delivery, and historical claims without a frozen intent are not upgraded.

### Ordering and coverage

Each source's original order and each record's part order are hard constraints. A native page index is only an order witness within that accepted page; it is not a global sequence number. The original Provider page operation and its continuation establish adjacency across pages; page hashes identify those operations without ordering them. Core applies one stable tail K-way policy to the accepted source sequences, then reverses that traversal for presentation. A frozen replacement window is newest-first regardless of its wire fragment sizes. Earlier page contributions extend the accepted source sequences; changes replace original versions at their retained source positions. Recorded times may rank otherwise unrelated tail candidates, while missing, equal or conflicting times retain an explicit partial cross-source order. A stable tie-break does not establish causality, authorship or input adoption. Clients consume the complete resulting window without their own timestamp insertion or page-union rules. Changes remain event updates rather than additional utterances.

Every source reports its accepted extent, continuation and coverage: earlier records may be available, exhausted or unknown; the current cut may be read, partial, unavailable or unsupported. Missing relationship targets are explicit unread references. A bounded or empty recent snapshot cannot certify the whole Session. Source failure does not erase another source's accepted records, and cancellation releases only the relevant reader.

When the original Session identifies a Provider but has no accepted native Session ID, scope and coverage use an explicit `{kind:'native-unavailable',providerId}` slot. It identifies the unresolved source, not a native record, invocation, anchor, continuation or cut. Provider capability absence is `unsupported`; inability to locate an otherwise supported source is `unavailable`. A later native identity requires a new explicit scope and checkpoint, without expanding a previous frontier. Captured records remain readable independently.

A durable frontier carries its frozen `scope.sources` as well as the successful source cuts. The enclosing result and frontier must agree on that scope. Native cuts retain their original exact source and opaque cursor; captured cuts retain epoch and committed sequence. Whole-request identity, integrity, scope and accepted-view/frontier mismatches reject the operation before source dispatch. Within that accurately selected scope, a source primitive's rejection of its original cut is a failure of that source: retain its old cut and records, expose the exact failure in its unavailable coverage, and allow another valid source to advance independently. A future captured sequence or mismatched captured epoch is not an empty successful read or permission to establish a new epoch; that source cannot advance until its original qualification is restored or the user explicitly selects a new scope. Validate each source's result before admitting any of its rows or next cut. Cancellation still cancels the original request. Ordinary source unavailability follows the same isolation boundary. A known question ID without its accepted request record produces a gap scoped to the original answer contribution; it does not manufacture a request record reference. An accurate typed reference to an unread canonical or observed target remains an explicit unread locator, with the accepted contribution's content intact.

Captured history remains owned by the original Session store. Its current/recent window is a query, never a retention limit. The original Session SQLite database holds captured stream identity, immutable record versions and latest-record/order pointers; native history is not copied into it. Updates preserve the record's first position, while durable change sequence counts committed versions. Pages and writes use the exact Session's indexes and bounded results, without loading cumulative history or scanning unrelated Sessions.

Existing captured JSONL is handed over once through the original writer, transaction, source-generation and durability boundaries. The handover preserves all existing complete records and the original file, confirms the same source witness, and leaves one active fact owner without dual writes or a fallback reader. An uncertain acknowledgement is reconciled against that original transaction. An incomplete trailing record retains its bytes and diagnostic; earlier complete history is preserved. Corruption is never skipped as successful coverage. A retained old snapshot has an unknown earlier prefix; previously compacted-away data cannot be declared recovered. Epoch and committed sequence survive restart, and an actual source replacement is reported rather than silently recut.

### Unified reading and changes

The existing Conversation operations carry the unified contract. Raw source inspection remains under `agent.history`; the Conversation API does not retain a second raw-output mode.

| Operation | Input and result |
| --- | --- |
| `agent.conversation.inspect` | Exact `hostId`, `agentSessionId`, optional `limit`, `cursor`, `view`, `maxBytes`, an exact retained `nativeSource: {providerId,nativeSessionId}`, or an exact versioned original-record anchor; returns the scope, per-source coverage, order witness, bounded items, `nextCursor`, byte budget and `window`. |
| `agent.conversation.checkpoint` | Exact Host/Session and authorized source scope; returns a frontier vector containing original native cuts and the captured epoch/committed sequence. It does not export earlier content or authorize sharing. |
| `agent.conversation.changes` | The exact original frontier, optional accepted `view`, bounded limit/budget and fragment continuation; returns the full replacement window, explicit coalescences and coverage with the next frontier. It is not a list of new utterances. |
| `agent.conversation.watch` | Relevant original-source invalidation or unavailability in the exact scope; optional `view` retains that temporary resource for this observation. Notifications wake durable catch-up and are not a message log or publishing receipt. |
| `agent.conversation.release` | Exact Host/Session and opaque `view`; releases only that temporary Reader view and returns its identity and release result. It does not change durable originals, the Session or its Run. |

A bounded item contains one semantic unit: an event and its contributing original records. Oversized units use the existing exact JSON UTF-8 fragment fields (`itemId`, encoding, digest, offset, total and base64 bytes). The entire unit, including relation and question metadata, is within that fragmentation boundary; no unbounded outer event array bypasses the budget. `window` names the original view, frozen revision, total unit inventory, completion, opaque view/replay tokens, exact checkpoint and versioned boundaries outside the retained window. `consumeConversationWindowPage` verifies byte fragments, original scope and inventory, rejecting duplicate event or record identities. It yields a complete replacement snapshot only after `window.complete`; clients then replace their displayed semantic snapshot. An unfinished window cannot advance the durable frontier or partially replace previously accepted content. Its `replay` repeats the same frozen response frame, including when a routed envelope requires a smaller byte budget.

The original backend Reader retains the accepted contributions, original source-page adjacency and cuts in temporary view state. A view bounds retained originals to 1,200 records and 32 MiB of serialized rows, and bounds its projected complete window to the existing 32 MiB assembly limit. It retains at most three frozen response snapshots for retries. Crossing a retained-window bound removes complete prior event groups from that view, never the original owners: `outside.older` and `outside.newer` retain exact original-record/version boundaries for anchored reading. The incoming exact contribution remains accounted for; an individually oversized event returns an explicit budget failure with its original read intent intact. This resource bound is not a history retention limit.

An original request actively producing or replaying a view is not a parked view. Initial reads, changes and each fragment request hold that exact view while their operation is in flight and release that qualification on completion, failure or cancellation. Completion refreshes the recency of the still-owned view before parked reclamation; explicit release or owner disposal cannot resurrect it. The interval between separate fragment requests remains subject to the ordinary bounded parking policy. This qualification adds no durable lease, observer, Session or Run.

Producer, strict unit parsing and complete-window assembly use the same retained-original record capacity. A single event may account for any number of original contributions that fits that existing whole-window record and byte budget; a smaller independent codec count cannot reject a valid producer unit. Assembly counts actual original record identities across all units, not only event count or declared metadata. Fragmentation preserves one event and every exact contribution; it does not split the event into extra messages or bypass the retained record and byte bounds.

An exact watch keeps its view active; unrelated reads cannot reclaim it. Disposing a bound observation removes only its observation pin and performs no source read. The accepted view remains parked; `inspect` with its `view` repeats the current accepted frame without opening a new source head. Explicit `release` or Client disposal releases the temporary resource. Unobserved views have a bounded sixteen-view parking area in the original Client and may expire; explicit release and Client disposal also reclaim them. Expiration rejects only that temporary continuation and retains displayed originals, exact anchors and durable cuts for a new read. `window.navigation.older` and `.newer` are opaque Core inspect positions in the original accepted page sequence. They remain available after changes; a changes `nextCursor` only continues that changes operation. An inspect `nextCursor` continues unfinished wire assembly, or names the older history position after a complete frame. A client commits at `window.complete`, then chooses a navigation intent separately. Empty examined Provider pages advance or terminate according to their original continuation; they are not missing or evicted records. A native Provider may supply `replayCursor` for the exact page snapshot and start position; Core never converts or decodes its changes cursor to seek history. Without a repeatable native head, that original head remains inside the same view and counts against its record and byte budget. A view token is not a durable checkpoint, input permission or proof that an Agent has stopped. Scope and original Host/Session checks precede revision checks.

An inspect source failure retains that source's unread position rather than declaring EOF. The next accepted navigation cursor keeps the same view and scope, the failed source position, and any independently accepted progress from other sources. Explicit continuation can therefore retry the failed source without rereading an exhausted healthy source. Only a successful source page may advance its position or establish EOF; a rejected page cannot enter the retained native head or replace its changes cut. Successful recovery clears only that source's failure. These semantics use the existing inspect, navigation and CLI continuation contract without adding a retry API.

A missing temporary view returns `AGENT_CONVERSATION_VIEW_EXPIRED`; a wrong original Host, Session or source scope remains a source-validation failure. Expiration does not confirm the availability of the underlying sources. A returning current reader may reopen one temporary view pinned to its accepted native source, then accept it only after the complete original source scope is verified. The previous frame and reading protections remain until that acceptance. A historical or anchored reader does not silently move to the current head; it retains its originals and offers an explicit current read. Failure to rebuild remains observable and retryable without a polling loop.

The original native page may carry an opaque `changesCursor` issued from the same physical read snapshot. Claude and Codex saved-history adapters obtain it from their shared native JSONL reader. Core carries that cut unchanged into the accepted window; a separately observed pre-page checkpoint cannot certify the page's version. A Provider page without this fact remains readable and reports that its history-to-changes join is unknown. Core never decodes or compares opaque source positions to invent that join.

The requested `hostId` is the selected client route; it is distinct from `sourceHostId`, the original Core namespace. Read/checkpoint/watch results retain both. Complete units, record references, source frontiers and resource references retain their original source Host even when that namespace is `local` on a remote machine. A complete reading identity includes the selected route, source namespace, Session and accepted source scope; a bare `local` record ID is not a cross-Host comparison or authorization key. No public Hosted option can rename the source namespace.

The actual Core read owner also supplies `sourceHostId` on native pages, captured snapshots and raw byte pages from its already accepted Session descriptor; a Provider or client does not invent it. Pure projection uses that original namespace while a presentation adapter may carry the selected route separately. Conflicting original source Host receipts retain every known per-record reference and body, report the conflict and confer no cross-Host join. A missing original namespace preserves readable content without filling it from current focus or a route alias.

`checkpoint` is a route-scoped envelope `{hostId, agentSessionId, sourceHostId, frontier}`. Its `frontier` contains the unchanged original source Host, Session, scope and cuts. An anchor's `frontier` field carries this same envelope alongside its original record and revision. Changes and anchors must match the original route and Session before dispatch; the selected semantic owner then checks the original source namespace and cuts. A routed continuation wraps the original opaque cursor with an integrity-protected route/Session/source binding. Forwarding unwraps only that matching route and never edits inner fragment bytes or source references. The complete final result, including these envelopes and gap continuations, must fit the requested byte budget; an insufficient budget preserves the original input and reports a budget error.

An exact retry locator retains the original `ConversationItemRef`, record revision, content selector and source-cut frontier. Inspection by anchor reads that exact retained record version at that cut; a returned fragment cursor remains bound to the same anchor. A different anchor cannot reuse it. The returned `window.anchor` retains this exact intent through wire assembly and parked-view reads. It is a single-record inspection, not a surrounding history window: null navigation does not identify the live head, source coverage does not claim the whole source was read, and changes cannot advance that fixed version. Clients retain it on later invalidation and may explicitly open history again. Captured versions come from their original durable owner; native reads revalidate the original source and revision. An unavailable or changed native version remains a gap instead of being replaced by latest content. Event revision tokens summarize accepted source revisions and relationships; they verify updates and never establish identity or authorize sharing.

Inspection with `record: ConversationItemRef` instead reads the currently retained version of that exact original record through the same owner. It cannot be combined with `anchor`, `view` or `nativeSource`. Its continuation remains bound to the same record, and a nonempty window carries the resulting exact `window.anchor`, including during fragment assembly. An unavailable record remains explicit; this mode does not weaken an existing versioned anchor or open a surrounding history window. The selected route and original source namespace retain their separate meanings.

The local SDK, Hosted contract, RPC parsers, discovery and CLI consume this same owner and result. CLI inspection accepts ordinary `--host`, `--session`, `--limit`, `--cursor`, `--view`, `--max-bytes` and optional `--process-details deferred`, or `--input FILE|-` for the exact typed request including an anchor or a current-record reference. Watch accepts the view it retains; release is an explicit separate operation. Exact-source `--source` inspection belongs to `agent.history`. Native source checkpoint/change readers remain primitives of the original history owner, explicitly distinct from the unified frontier. Existing source cuts are retained verbatim; no client cursor or snapshot revision substitutes for a durable publication frontier.

### Deferred process details

List inspection and changes can opt into `processDetails: 'deferred'` through the same SDK, Hosted, JSON-RPC and CLI operations. The representation is bound to the original temporary view and its signed continuations; it cannot change midway through a view. Omitting the option retains complete records. Exact `anchor` and `record` inspections always return complete originals and reject the option. No separate detail endpoint or transcript owner is introduced.

Only a whole semantic unit whose event role is `process` can carry deferred records. The explicit `original.kind: 'deferred'` variant contains typed native or captured headers and a separate `summaryRevision`; the original record reference, revision, order, event role, recorded author, invocation membership, relations, content positions and source-cut frontier retain their original meanings. Headers carry no text, tool input or tool output. They identify unread content slots without claiming that an empty body is the original. Strict parsing validates header integrity and the event facts against those typed slots; mixed complete/deferred contributions in one unit and unrequested deferred records are rejected. Full-record revision calculation remains unchanged. Speech and interactions retain complete original content.

A source can defer process bodies only when its existing owner supports exact retrieval. Captured details use the original immutable record-version store. Native details require the original Provider's declared `readSessionHistoryRecord` capability; Providers without it retain their complete native records. An unavailable native Provider does not remove healthy captured reading. Opening details uses the accepted record reference, original revision and original frontier as an exact anchor. A changed or missing version remains an explicit retryable detail failure; neither an empty exact result nor latest content replaces the requested original. Failure of another source does not reject a healthy exact target.

`projectConversationWindow` keeps deferred records and their exact references in the accepted presentation inventory. Compatibility projections containing complete native/captured originals remain complete-record subsets; they do not contain fabricated empty originals. Counts, boundaries, location and empty-state decisions over the accepted window use the full semantic inventory, including deferred records. A mounted detail request retains its original anchor across unrelated window updates. After the first explicit expansion, clients may retain that exact body and DOM through folding to preserve selection and formatting state. This representation reduces wire payload and unviewed Renderer body work; the existing source scan, signature validation and captured record parsing still occur in the original read owner.

## Reading and projection

`@agentmux/core/conversation` is browser-safe. `projectConversationRecords` projects an already accepted native history page and/or captured timeline. Each record preserves its original source and item, ordered content parts, recorded author facts and source-qualified identity. Equal text in different records remains distinct. Reading does not infer a human author, input adoption, interaction completion or task success.

The shared UI consumes this projection and adds speaker presentation. The projection creates no reader, cache, Session or Runtime. Source IO and pagination remain in the original Core history owner.

### Readable AgentMux envelopes

Exact readable formats belong to the [amux protocol](amux-protocol.md). Conversation consumers use the same Core reading result for original wire and explicitly opened complete text resources; an already decoded journal or producer body remains authored content and is not parsed again as wire. Preserve original declaration spans, body and separate reminder presentation. Parsed declarations confer no author or permission facts. Full Copy reads original parts or resources, independently of the reading projection. Invalid, quoted, incomplete or ambiguous text stays readable. The [shared Core reader](../../packages/core/src/agent-message-render.ts) supplies that interpretation; actual client wiring belongs to the [mechanism map](../architecture/conversation.md#可读信封与原输入).

A2A references remain references in the reading projection. Their discovery hint does not prefetch the body, submit input or acknowledge consumption. Opening an original message uses its existing authorized lookup; a user's view does not attest that the executing Agent read or accepted it. Container and shorthand forms preserve their original wire for Copy and share the interpretation defined by the format owner. Actual producer and consumer verification remains separate from format recognition.

An original captured platform notification retains `a2aNotificationId` and its exact prompt `inputRef` under the AgentMux system source. A native user-message contributes the same platform purpose only after Core confirms its original input claim, native source, correlation and complete wire; `adoptedInput.purpose: 'a2a-notification'` records that qualification. The common projection can then coalesce the original same-Host contributions as one system notice. These inputs are absent from User Messages, while their raw native records and complete parts remain readable. Matching authored tags or text alone never supply purpose, attribution or a join.

`projectConversationReading` and `projectConversationWindow` expose `inputs` as `ConversationInputEntity` values over the accepted events. Each entity carries its canonical route-qualified event identity, event revision, recorded event author and all original contributing records. Its primary source, raw record ID, body, resource targets and content-boundary qualification still identify that original contribution; another contribution's confirmed public content does not qualify the native body. `record.input` and raw `agent.history` user-message results remain source-record projections. Input consumers use `inputs` instead of reconstructing entities from those raw projections. A canonical representative may change through an explicit `coalesces` edge; a retained preview can use `retainConversationInputs` to admit additional entities without appending that already represented event again. Only exact same-scope identities and current coalescence edges extend a retained selection; equal bodies, times or arbitrary overlapping contributions do not establish an entity relationship. Retention keeps the selected original reading version, not a second semantic accumulation or a claim that a withdrawn association remains current.

An original user-message projection can carry `sourceRecord: { record, revision }`, using the existing `ConversationWindowBoundary`: the exact original Host, Session and source record reference, and that record's version. Native query versions use the qualified original item's `conversationRevision`; accepted Conversation adapters pass their existing source record version through. Captured versions come from the original stream position revision; an unversioned live snapshot does not manufacture one. A raw user-message can also carry the original confirmed `inputRef` and the small typed `conversation.sameEvent`, `nativeInput` and `adoptedInput` facts. Wire readers validate the source boundary, input key and strict provenance structure. Structurally valid original provenance that cannot establish a same-source relationship stays readable; the common matcher rejects its association without rejecting the original history page. Absence remains unconfirmed. This read metadata does not change a raw native author's `unknown` value or grant authority; a fingerprint alone is no entity relationship.

Typed user-message reads expose `publicContent` independently of the recorded author and source. `confirmed` means the original input writer retained the exact `userContent` separately from generated `systemContext`; it establishes a content boundary, not sharing authorization, content safety, delivery or personal identity. Unmarked captured records and native records without a qualified content-boundary producer remain `unknown`. Original text, parts and Copy remain complete. Updating a captured body without that producer clears its boundary fact; a status-only update does not.

Use the existing `agent.history --host HOST --session SESSION --source captured|native --kind user-message` query for the same bounded observation through public RPC and the CLI. The original conversation projection and first-party message details consume that result. Plain conversation reads retain the original records and fragments; no native-reference association is invented. Sharing still requires the original audience, binding and authorization scope.

Raw `agent.history` reads reuse that owner's bounded read envelope. Required fields are `hostId`, `agentSessionId` and `source` (`native` or `captured`); `limit`, `cursor` and `maxBytes` retain the original history contract. The envelope keeps the original source identity, revision, ordering, items and opaque continuation. These are the source primitives of the unified Conversation reader, not an alternative Conversation output mode.

```sh
amux agent history --host HOST --session SESSION --source native
```

A complete item retains the original record. An oversized item remains a sequence of exact JSON UTF-8 byte fragments with contiguous offsets and a SHA-256 digest. Reconstruct and verify the complete record before projecting it; a fragment is not a partial semantic message. A missing native source does not erase captured work. Cancelling a read releases only that reader.

## Recorded resources and content fragments

`AgentMuxClient.sessionHistoryResource(agentSessionId, request)` and public `agent.history.resource` read one exact native content part at its original Host. The public request adds `hostId` and `agentSessionId` to `AgentSessionHistoryResourceRequest`: `source {providerId, nativeSessionId}`, `recordId`, zero-based `partIndex`, and `expectedReference` are required; retain `turnId` when recorded. `maxBytes` reduces the read budget, and `offsetBytes` continues a deferred text-content read. Types are defined in [`types.ts`](../../packages/core/src/types.ts); request and response validation lives in [`session-history-resource.ts`](../../packages/core/src/session-history-resource.ts).

```sh
amux agent history resource --input RESOURCE_REQUEST.json
```

The caller copies identity and reference from the accepted original native page. These fields constrain a comparison; they do not authorize an arbitrary path. Core checks the native binding, locates or revalidates the original record and exact part, and confirms the binding again around the read. Public routing requires the exact retained Host and Session. The result retains that scope, source, record, optional turn, part index and reference. Hosted SDK replies omit the transport `hostId` and validate the original Session and resource before presentation.

There are two independent fragmentation layers:

| Layer | Bytes and continuation | Semantic boundary |
| --- | --- | --- |
| History read-envelope fragment | An entire original record serialized as JSON UTF-8; continue the original bounded history envelope with its opaque cursor. | Reassemble contiguous bytes and verify the record digest before parsing or projecting that record. |
| Deferred content-part resource | A page contains `resourceType: 'text'` and `content {encoding: 'json-utf8', kind, byteLength, sha256}`; resource reads continue that exact serialized part with `offsetBytes`. | Preserve the metadata and ordered part position; verify the complete extent, digest and original semantic `kind` before using the part as complete text, reasoning, tool or resource content. |

A resource result is one of `read` (supported raster MIME, canonical base64 bytes, byte length, and `width`/`height` verified from the original raster header), `file` (explicit self-contained document bytes and recorded metadata), `fragment` (exact offset/total/digest/next offset), or `unavailable` (code and readable reason). Set `representation: 'image'` to request raster bytes explicitly from the same original resource, including a signed deferred image part. Keep its outer `expectedReference`; the Core owner verifies and reconstructs its exact serialized part before decoding the image internally. This purpose cannot be combined with `offsetBytes`. Omitting it preserves the original JSON fragment semantics, including an image wrapper’s complete original JSON. The signed envelope is bounded before accumulation by the decoded byte budget’s base64 expansion plus a finite metadata allowance; oversized envelopes remain unavailable for this representation while their default JSON reads remain available. Decoded image bytes retain their separate budget. Local resource reading does not require public sharing eligibility; the publication owner checks that eligibility and scope separately before requesting bytes. Current image formats and budgets are enforced by `imageBytes` in the resource validator; opaque or HTTP image references return unavailable without network fetching. This endpoint does not fetch arbitrary file paths or URLs, provide generic audio downloading or perform image OCR. A text fragment may return `continuationReference` when the original Provider has revalidated and renewed the same read extent; use it as the next `expectedReference`, keeping all source/record/part and content metadata unchanged. [`readSessionHistoryTextResource`](../../packages/core/src/session-history-content.ts) implements complete part reconstruction for browser-safe consumers.

Set `representation: 'file'` for self-contained bytes from an exact original `resourceType: 'file'` part, including its signed deferred JSON wrapper. It returns `status: 'file'`, canonical `dataBase64`, `byteLength`, recorded `mimeType` and optional original file-part `label`. The outer identity/reference stays unchanged; a wrapper label is not substituted for the original file label. MIME and label are recorded metadata, not verified file format, author or sharing permission; existing Provider MIME defaults do not establish an explicit upstream declaration. Missing names remain missing. This purpose also rejects `offsetBytes`, retains the 16 MiB decoded cap and finite encoded/envelope budget, and leaves default JSON fragments unchanged. Paths, HTTP and opaque file references remain unavailable without filesystem or network reads. Local private/unconfirmed reads retain their existing qualification; future external publication must independently authorize the original part and audience. Droid exact-record reads reuse its original JSONL source/header checks and converter; they do not imply durable changes or native discovery support.

Saved paginated Codex MCP completion records can supply a file from an original typed resource's `blob` and declared `mimeType`. The Provider checks the original thread, turn and call identity and uses the same converter for page, exact-record and durable changes reads. Each extracted file payload appears once in that record; the remaining original metadata and content retain their reading representation without another copy of the extracted blob. The model-output record remains independently readable and is never parsed back into a second file. Its matching call identity describes invocation membership, not event coalescence. File extraction establishes local byte access only; publication eligibility is determined separately from the original content purpose and binding scope. Text previews, resource links and missing MIME declarations do not supply file bytes. Producer-side result truncation is not an additional local read limit.

Malformed resource requests fail validation; a changed native source, missing exact record, changed part/reference or mismatched response fails at its original binding/lookup/parser boundary. Preview unavailability remains a typed result where supported, including unsupported exact-record lookup, image format, byte/decode budget or unavailable file bytes. Callers retain the original record, reference and continuation and expose the specific failure; they cannot substitute another source, guess a path or treat missing bytes as empty content. Resource failure and cancellation affect this read, not the original Session, ordinary input or Run. The exact owner is [`AgentMuxClient.sessionHistoryResource`](../../packages/core/src/client.ts); reply identity is validated by `parseSessionHistoryResourceResult` / `parseSessionHistoryResourceReadResult`.

Client adapters must carry this resource reader to the actual shared message consumer. A pasted-file preview reader is a separate host capability and cannot resolve a Provider-native resource by itself. Reading and thumbnail display do not submit input or prove delivery. The protected reading behavior is defined by [the common record contract](../design/behavior/conversation-mode.md#共同对话与原生记录) and [recorded images](../design/behavior/conversation-mode.md#对话里的贴图).

## Relevant observation and durable changes

`agent.conversation.watch` observes the exact scope through the original Provider observation pool and relevant captured commits. Notifications are source invalidations or unavailable observations, never a message log or delivery receipt. Desktop, Hosted clients and public readers share the original source observations. Cancelling one reader leaves the others and the Run intact.

```sh
amux agent conversation watch --host HOST --session SESSION
amux agent conversation checkpoint --host HOST --session SESSION
amux agent conversation changes --input CHECKPOINT_REQUEST.json
```

The checkpoint result contains `hostId`, `agentSessionId`, `sourceHostId`, the exact scope and a route-scoped source-cut envelope in `checkpoint`. The next changes request carries its original `hostId`, `agentSessionId` and `checkpoint`, plus optional limit, budget or continuation. SDK consumers use `conversationCheckpoint` and `readConversationChanges`. Each bounded result retains the scope, original records, semantic units, per-source coverage, next checkpoint and `more` flag. A fragment continuation is completed before acknowledging the corresponding next frontier. Empty source bookkeeping pages may advance their original cut without inventing an event.

Each first source cut follows the last complete committed record; existing history is excluded. A partial append is not consumed before its delimiter arrives. Catch-up resumes in original source order after reader or Host restart, independently of notification loss and UI reading cursors. Saved Claude and Codex sources reuse their original physical reader and Provider converter; captured changes reuse the original Session store's committed versions. Providers without durable catch-up report that source's capability as unsupported while retaining history, other available sources, input and the original Run.

A checkpoint is a read continuation, never sharing or input authority. It contains no transcript path. Source replacement, truncation, changed identity or changed saved boundary reports the exact source failure and retains the original continuation. A connector must inspect and authorize a new source cut before publishing from it. Constituent cuts stay independent within the vector; only the common Core projection supplies cross-source ordering and its uncertainty.

## Asynchronous question references

`projectConversationQuestions` projects already accepted native pages and same-source answer context. Every question reference retains the managed Session, Provider source, record, recorded turn and opaque question ID; an execution Host is included only when supplied by the caller. Missing turn identity stays missing. Each recorded answer retains its original user record and source, independently of the question's own turn.

`recordedQuestionAnswerFacts` queries only those accepted facts. A same-source answer outside the displayed window can confirm the card without rereading history, replacing the reading window or retaining a separate answer cache. Both pages must retain the same known original `sourceHostId`, Session and Provider/native source; a caller's current route cannot supply an unknown source Host. Unknown or different sources retain their original records without contributing a matched answer. The card's displayed-page precedence does not remove other original answer records or their relations. `questionReplyReceiptMatches` checks the original submission receipt; native answer evidence does not prove which operation delivered it, and a submitted receipt does not prove that a native answer was recorded.

The original `agent.history` and `agent.context` expose typed question and answer records. `agent.question.reply` remains the original exact reply owner, including its stable operation, Run and predecessor. Historical asynchronous questions are readable facts rather than synchronous pending requests. Client draft, in-flight and unknown reply intent remain with the existing client owner under [the original question and reading contract](../design/behavior/conversation-mode.md#原生异步问题与答复); refreshing or projecting a question does not submit it.

## Mailbox consumption

All applicable local and authorized connector submissions enter the original Core sending mailbox, with one stable input identity and the original admission, attempt and receipt owner. An ingress acknowledgement, queue acceptance, wait generation, transport write and native adoption are different facts. A notification invalidates the authoritative bounded mailbox read; it does not create a client-owned input. Older inputs lacking a recorded fact keep their original records and an explicit coverage gap rather than fabricated history. Connector publication Outbox remains the separate platform-delivery owner.

`AgentMuxClient.readAgentInputMailbox` and `agent.input.ls` read the original journal through the existing recipient/intent-sequence index. The opaque continuation fixes original queue incarnation, recipient, accepted membership cut and descending order. Controlled entries retain their original intent and waiting receipt; a read-only submission entry refers to its original admission without inventing a waiting generation or control eligibility. Each control/admission is a current observation, independent of that membership cut. An unavailable observation retains its original item and exact failure while other entries remain readable. New exact claims are recorded only after their first successful admission CAS; a fresh typed launch is recorded at its original lifecycle acceptance. Rejoining old claims or reconciling an unknown old launch does not manufacture rows. Historical recording coverage remains explicitly unconfirmed.

Mailbox pages reuse `JsonReadEntry` and the existing complete JSON byte assembler. Page and item observations retain the exact queue/cut/recipient scope; a changed observation invalidates its incomplete bytes rather than splicing latest content. The selected route encloses the original source cursor and queue, and does not relabel input keys. Reading, cancellation, fragment assembly and journal-visibility failures never dispatch input or revoke an accepted claim.

An exact native adoption fact associates the original input with its source-qualified native item. It cannot be inferred from a Hook turn, accepted PTY bytes, equal text or time. After that association the native utterance is the primary logical message and original submission facts are supplementary contributions, not another utterance. Every attempt, original record and unknown operation remains inspectable. Native client correlation is not an idempotency guarantee; an unknown effect retains its original identity and cannot be automatically replayed.

The default semantic message path can choose native transport only for an unclaimed message key with its original exact condition and a confirmed durable Core Session source on the same Run. Manual terminal intent is unchanged. The first native claim freezes the original condition, source, actor, plan and complete correlation before dispatch; read-only preparation does not grant an effect or permit terminal substitution. Native planning and adoption share the same source identity tuple. Adoption checks the complete original native claim for either an explicit native target or this default message path; the reader does not choose transport or repair old claims.

`projectSessionInputs` is the shared pure SDK projection for bounded Inputs queries and journal pages. It reuses Core same-event and adoption rules with complete original Host, Session, Run, key kind and ID. Current accepted entities contribute relationships and ambiguity witnesses, never unmatched query bodies; a current source revision differing from a queried original invalidates that old proof while retaining the queried text. Query records outside the current window can use their own qualified source facts. Missing original Host keeps journal and history separate. Groups retain every original object and receipt, exposing a native-first queried primary and recorded author consensus. The pure `sessionInputMailboxAuthor` projection supplies the same recorded journal author facts to both this grouping and the original journal presentation. Equal text, timing and a route Host do not establish membership. Desktop and Mobile show one main row per confirmed group, with independently readable original details and actions; the journal retains its own receipt and controls. Source continuations, coverage and unknown failures remain unchanged. This uses the existing `agent.history` and `agent.input.ls` RPC/CLI operations; no new read or delivery command is introduced.

The original Desktop Mailbox consumes Core input projection and `conversationItemRef` for the same Host, Session and native or captured record. Its mapper retains the original object and existing row/read-marker keys; known Agent authors and delivery status come from Core rather than another timeline interpretation. Typed native question answers retain their opaque IDs and original input-record reference. Missing original question pages do not manufacture a question target or acquire another reader. An unknown Host or incomplete source leaves the record readable without inventing a complete reference.

The required Message Tool pages are [A2A Inbox, A2A Outbox and User Messages](../design/behavior/conversation-input.md#message-tools-邮箱). The first two read the original Core A2A journal for the current Agent's received and sent messages; User Messages retains original user drafts, pending inputs and recorded input history. Notices, Progress and existing Dispatch reading retain their owners. These page requirements do not assert current UI completion. Saved or dispatched input receipts, recorded native input, local human read markers and Agent consumption remain independent facts; browsing a message never dispatches it or advances the Core Agent-consumption acknowledgement. The original `message.pending.*` and `agent.history` paths retain their queue/history responsibilities; connector publication Outbox is a separate owner and is not inserted into user Pending or A2A Outbox.

## External input attribution and admission

An external author is a structured Core fact with its original application, actor ID type, conversation, platform message and binding/grant references. The original envelope, input journal, captured record and user-message projection preserve it. The Desktop reader presents this source separately from a local human or Agent. Visible headers are reading aids and never authorize an input.

The optional executing-Host [durable intake owner](../../packages/connectors/README.md#durable-external-intake) authenticates through its registered adapter, saves the complete event before ACK, and freezes the original Host, Session, Core Run and operation/message IDs before a possible Core call. Core accepts external attribution only with the live in-process Host author context. That owner compares the actual input with its original claim and checks current authorization at possible admission and explicit rejoin; a persisted grant snapshot cannot supply that authority.

For Hosted clients, the wire carries the original envelope alone. The semantic Host installs `AgentExternalInputAuthorityPort` and builds the Core context locally; functions and caller-supplied authentication flags are not serialized. The original executing-Host intake owner supplies current authority for the exact claim. Rejoin obtains attribution from the original Core message journal, while ordinary human input does not consult the connector port. A missing or unavailable port leaves external authority unconfirmed without replacing the original input or disabling ordinary input. The protected boundary is defined by [the shared conversation behavior](../design/behavior/conversation-mode.md#共同对话协议与外部交流入口).

`connection.ingress.ls` and `connection.ingress.inspect` expose bounded original intake facts and the original Core receipt without submitting. An absent receipt or unavailable read keeps a claimed operation unknown. Further dispatch and restart do not replace its IDs, target or body. Existing `agent.history` and input inspection retain their original owners; `agent.send` does not accept caller-supplied external authorship. No second Agent queue, observation or Runtime is introduced.

## State, change and delivery

External publication is required to preserve [shared conversation parity and accurate authorship](../design/behavior/conversation-mode.md#共同对话协议与外部交流入口), including original human input from the Agent Terminal. This is a required product contract, not a claim that current publication adapters already cover every record or platform identity. The original conversation projection and input attribution remain authoritative; platform presentation and delivery reuse the original connector Outbox and mappings.

New ordinary group bind and relink requests use `future-shared-conversation` for the complete normal conversation. The original `RoomBinding.scope.publication` still records narrower `future-native-user-facing` grants and dedicated private-chat reply origins accurately; an existing narrow group grant is an incomplete shared conversation until its trusted operator explicitly confirms whole-conversation sharing. A new scope goes through `connection.binding.relink` with the exact expected revision and a fresh source cut; another `connection.bind` cannot silently broaden an existing binding. Original pending and unknown publications retain their own scope and revision. Consent does not establish a qualified public-content boundary, authorship, platform identity or complete adapter coverage.

Within that shared cut, the original captured writer's `publicContent=confirmed` user input may carry `ConnectionDelivery.relay`: the application sender and each exact content reference with its original typed author. Unknown authors remain unknown. The same delivery methods expose this safe attribution without message bodies or prepared requests. Relay attribution is not platform personal-send authority, does not qualify native gaps, and does not change an existing narrow grant.

For broader sharing, an unqualified original native user record or an unsupported complete image/file resource produces the public delivery observation `unavailable` / `content-unconfirmed`. The original publication owner retains an unresolved event/part decision with its exact versioned retry locator. Only a transaction that durably accounts for all required supported intents and gaps may advance the read frontier; a failed gap write leaves the original cut unchanged. The delivery coverage remains incomplete, never a successful skip or empty substitute. Worker restart reads the same durable gap, and other supported content continues through its original lane. This observation concerns external publication only and does not revoke ordinary Agent input, replace its Session or resolve an older unknown platform operation. Inspecting or settling an older effect cannot hide the source-content gap; the older delivery remains independently inspectable.

Self-contained public file parts use the same resource API and publication Outbox as recorded images. Public delivery `resourceUpload.kind` distinguishes `image` and `file`; its original part, attempt and upload state expose no asset key or bytes. An adapter with a separate upload protocol retains its confirmed upload key privately before freezing the chat-message request. A native direct-resource adapter freezes a multipart payload and generic descriptors (original operation resource identity, hash, byte length, transfer name and MIME); only the effect context of that same claimed Outbox operation can read and verify its retained bytes. These bytes are independent of display metadata cache management. Direct multipart has one message effect and does not manufacture an upload key or upload receipt. Upload uncertainty does not establish chat-message application or non-application: no automatic reupload occurs, but an explicit retry of the same authorized operation may create another upload attempt when its chat message was never attempted. Earlier upload attempts keep their own uncertain receipts. A possibly applied chat message remains inspect-only with its original prepared request and key. File-message replacements that cannot be edited use ordered withdrawal and creation operations in this same Outbox; a failed withdrawal remains the retryable predecessor, and an unknown predecessor cannot be bypassed. Missing original names remain absent metadata even when a neutral transfer filename is required by the adapter.

When a native interaction card cannot display its complete original text, the same operation may carry an explicit `public-interaction-text` resource source. Its bytes derive deterministically from that operation's frozen public question body and recorded answers, or its shared permission title, context and option labels. Private fields, action references and generated transport or availability metadata do not become attachment text. The descriptor retains the same original operation identity, exact hash, byte length, transfer name and MIME; its claimed effect context rejects a different operation or descriptor. No second blob store or cache copy is created. The short card states that the complete original text is attached and preserves the original action and exact local Agent entry. The attachment changes presentation only, never question semantics, grants or response ownership. Unknown multipart effects keep the same inspect-only recovery boundary.

A successful read proves what was observed in its stated range. It does not prove that a message was delivered, an input was adopted or a task completed. UI snapshots and observation cursors are not durable publishing checkpoints. External delivery must retain its own operation identity and confirmed platform mapping, and reconcile unknown effects through the original operation.

The source model and protected behavior are defined by [the conversation contract](../design/behavior/conversation-mode.md#共同对话协议与外部交流入口). This page defines the unified target together with the original reading, resource, question and external-input contracts. Actual implementation belongs to the [mechanism map](../architecture/conversation.md); interface availability does not establish that every client has supplied all adapters or passed product validation.

It defines the accepted representation and original action boundary; it does not certify that a particular adapter, Provider or live platform has implemented or verified each row. Native card layouts, limits, uploads and callback decoding belong to the adapter. A missing native capability retains the complete original content and the exact local action entry with an explicit limitation; it cannot be reported as successful delivery, answering or permission approval.

A missing or unsupported image or file does not erase independently readable text; each part retains its original order, resource relationship and explicit coverage gap. Preserving a resource ID or raw payload alone does not mean that its content reached the Agent. The adapter interprets native alternate content representations according to their declared precedence, retaining the original payload rather than requiring differently encoded representations to be identical. Partial reading does not certify complete input, change its authority or authorize replay of an already applied input.

## Named original-record reading points

[`ConversationLandmark`](../../packages/core/src/conversation-landmarks.ts) stores only a stable point ID, an explicit name, the original `ConversationItemRef` and, when the catalog route differs from that source namespace, `routeHostId`. The outer query/write Host remains the catalog route; the point keeps its source reference unchanged. Queries, creates, renames and removals validate that route and Session together. Existing points and recorded write intents without `routeHostId` retain their original single-namespace context and exact intent; adding route context to a new point does not rewrite or replay an older operation. The same module owns strict query/write/result parsing. `agent.conversation.landmark.ls` lists one exact Host/Session scope and optionally its original `recordedOperation`; `agent.conversation.landmark.apply` creates, renames or removes one point with `expectedRevision` and an immutable `operationId` intent. The page revision is current metadata state, while `recordedOperation.revision` describes that original acknowledged change; a later rename or removal does not rewrite the old receipt.

The [original public service](../../packages/core/src/public-rpc-service.ts) and [object CLI](../../packages/core/src/agentmux-cli-commands.ts) consume the same [durable owner](../../packages/core/src/conversation-landmark-store.ts). A metadata receipt does not confirm record reachability or native adoption. An unavailable execution Host does not invalidate saved metadata; returning to a record still uses its original bounded conversation reader. No body, generated chapter, Run or input capability is retained in a point. Unknown saves keep their original intent and query the same operation before any new action. A client may retain only that unresolved write input in its existing workbench intent persistence; it is not an acknowledged Core operation or a second metadata catalog. Reopening restores the same operation and exact reference, and acknowledgement removes only the matching client intent.
