# 公共能力来源导航

本文按当前已提交源码帮助包消费者、CLI 维护者与客户端开发者定位公共入口、类型定义和消费链。它是一张来源地图：准确签名、参数、错误和导出范围由源码与 package exports 持有，行为约束由各 owning 设计持有，本页不维护第二份 API、命令词典或行为条款。源码合同、工作树、安装与运行事实分别核对；系统分工先读[系统分层与事实归属](../architecture/system-ownership.md)。

新增功能的作者先按[公共能力贡献约定](../guides/public-capability-contributions.md)判断 RPC／CLI 影响，再用本页找到定义与实际消费入口。

[Core package exports](../../packages/core/package.json) 决定可导入的子路径，[index.ts](../../packages/core/src/index.ts) 决定包根重导出。出现在 exports 中只证明当前包入口，不单独证明接口成熟度、稳定性或运行验收。包内实现文件的链接用于阅读源码，不授权消费者绕开公共入口深入导入。

`client-ui` 的 [exports](../../packages/client-ui/package.json) 为浏览器 bundler 提供源 TS，为 Node import 提供 ESM 产物；宿主按包说明加载样式及主题。Main 只需图片规则或路径识别时，使用 `pasted-images`、`terminal-path-link` 等纯叶入口，避免加载 React、Tiptap 或 DOM。UI 包消费 Core 的类型与纯公开子路径，Core 不增加 UI 依赖；共享组件不持有 Agent 或 Run 事实。

### 文件资源的读取、修改与发现

Note 使用同一组 `file.read/write/create`，经共享的 [NoteFileWriter](../../apps/host/src/note-file-writer.ts) 读写 `.note.md`。正文、稳定块／引用和可信作者的边界见 [Note Markdown](note-markdown.md)。`notebook.inspect --content` 与 GUI 的 `notebook:content` 经 [NotebookObservationOwner](../../apps/host/src/notebook-observation-owner.ts) 观察同一已保存正文与修订绑定的元数据，`notebook.graph/resolve` 从正文派生关系。[NotebookStore](../../packages/core/src/notebook-store.ts) 以笔记库本地文件持有目录、关注、操作历史和块归因，存储机制见 [Note Markdown](note-markdown.md#元数据与公共消费)。`notebook.inspect` 同时公开 NotesStorage 的 `resourceChanges` 与 `conversionIssues`，供消费者确认同一 Note 的位置与部分转换问题。

Zone 文件的已保存正文与修订保存由[文件类型与严格 codec](../../packages/core/src/public-rpc-files.ts)公开。`file read`／`file write` CLI → 公共服务 → Host 注入的 [FileReadOwner](../../apps/host/src/file-read-owner.ts) 解析 Zone 与资源，再委托[普通文件 IO](../../apps/host/src/ordinary-files.ts)；Desktop 的 [WorkspaceFiles](../../apps/desktop/src/main/workspace-files.ts) 消费同一受限本地实现并提供宿主适配。结果保留完整的 revision、Host／Workspace／Zone 与读取状态；观察未知不冒充文件不存在，也不另建内存存储。

- `file.write` 只保存已有的文本文件，要求完整 revision。结果为 `written`、`conflict`、`error` 或 `unknown`；未知时先读同一文件核对，不自动再写。
- `file.create`（CLI `file create --input FILE|-`）创建缺失的目标：先由 `file.read` 确认目标映射，再提交完整资源、Zone 相对路径、正文与明确的 `expectedRevision:null`。内容 owner 确认映射后委托 Files IO 的排他创建，不覆盖已存在的文件；普通文本和 Note 使用同一通用能力。结果的四种状态与 `file.write` 相同，未知时先读同一目标对账，不自动换名或重发。
- Note 首次保留的内容共享由 [Files 共享合同](../../packages/core/src/public-rpc-file-share.ts) 提供 `file.share`／`file.share.undo`／`file.share.inspect`（CLI `file share [undo|inspect] --input FILE|-`）。GUI 与 CLI 共用[共享 owner](../../apps/host/src/note-shared-block-owner.ts)、[撤销 owner](../../apps/host/src/note-shared-undo-owner.ts)、Note writer、lease、CAS 和可信历史，分别回执共享文件创建、原位置替换、目标保存与条件回收，不冒称跨文件原子提交。一次目标保存可以同时移除旧使用并新增共享；检查可读取保留的提取／撤销请求或一个共享文件。恢复范围、受管并发边界以及 Markdown 身份与关系见 [Note 格式](note-markdown.md#共享-markdown-文件)。
- 项目文件名发现：`file ls` CLI → `file.list` → `WorkspaceFiles.listFiles`。结果只含名称、资源与 complete／partial 原因，应用 Git 忽略规则，不递归目录链接，不读正文或改变焦点。名称相对于请求的目录；用 `file open --zone` 继续时，把 `file ls --path` 的目录前缀与名称拼成 Zone 相对路径（默认 `.` 可省略）。观察未知时仍保留精确打开能力。

编辑器当前草稿的动作由 [`space-control` 类型](../../packages/core/src/space-control.ts)和[严格 parser](../../packages/core/src/space-control-parser.ts)定义。`file.view` 由 FileRegion 的模式 owner 处理；`file.format` 从 [Renderer control 消费](../../apps/desktop/src/renderer/src/store.ts)进入 [`format-file-region`](../../apps/desktop/src/renderer/src/lib/file-formats/format-file-region.ts)，与 File 动作共享同一个可撤销的草稿编辑。`file.build`／`file.build.inspect`／`file.build.cancel` 进入 [`build-file-region`](../../apps/desktop/src/renderer/src/lib/file-formats/build-file-region.ts) 与 Main 的 [`FileBuilds`](../../apps/desktop/src/main/file-builds.ts)，绑定 Region、build ID、Host 与草稿版本；公开回执含日志和产物元数据，PDF bytes 留在宿主。这些动作不隐式保存、不切换焦点，也不因打开 Preview 自动启动编译器。

### 文件上传与输入边界

设备选择的图片与普通文件由[公共文件类型与 codec](../../packages/core/src/public-rpc-files.ts)提供 `file.upload`／`file.upload.inspect`（CLI `file upload [inspect] --input FILE|-`）。公共服务先确认目标 Host／Session／Run，再委托 Main 注入的 [FileUploadOwner](../../apps/host/src/file-upload-owner.ts) 保存到 Host 指定的私有位置并读回；同一操作不可覆盖，结果未知时核对而不重传。手机的 [MobileAttachments](../../apps/mobile/src/conversation/MobileAttachments.tsx) 消费同一回执，再经[共享文件引用插入](../../packages/client-ui/src/lib/composer-file-reference.ts)进入 Composer；上传本身不发送消息，Core 输入与 Runtime 仍由各自 owner 持有。

输入应用、Prompt 投递、任务接受、Agent 状态和工作完成是不同的事实，边界见 Core 接入说明与 owning 设计。初始 Prompt 的投递事实来自 `createAgentWithDelivery` 的同次返回；回执缺失时不自行重启、重发或换目标。

完整输入经既有的 prompt／message／inspect／rejoin 方法，复用 [Core 输入 owner](../../packages/core/src/prompt-submission.ts)、[冻结记录解析](../../packages/core/src/prompt-submission-record.ts)与实际的 Provider／Runtime 承载；[可选启动上下文预算](../../packages/core/src/agent-prompt-budget.ts)只用于选择上下文，终端观察窗口不授予或撤销输入资格。行为要求见[输入环境判定与复用边界](../design/behavior/agent-capabilities-and-messaging.md#输入环境判定与复用边界)。

- 接收方接续外部消息复用 `rejoinAgentInputWaiting`／`agent.input.rejoin`／`agent input rejoin --input FILE|-`：接收 Agent 以自己的 capability，继续代次仍 enabled、且已确认未派发的请求，作者权限由 Host owner 重新核对。它不取得作者身份、不重新启用已停止的代次，也不扩大 inspect 的读取权限。
- 输入成员及等待控制的增量发现由 [AgentInputChanges](../../packages/core/src/agent-input-changes.ts) 提供 `readAgentInputChanges`／`agent.input.changes`（CLI `agent input changes --input FILE|-`）：同一 journal 按接收者与控制位置返回不含正文的输入 key；首次读取建立位置，之后消费并推进 cursor／checkpoint，再用 `agent.input.inspect` 核对当前事实。来源变化与权限错误不改变输入，该读取不重放历史阶段。
- 当前输入活动由 SDK 的 `readAgentInputActivity` 与 `agent.input.inspect` 的显式 `activity:true` 只读投影。默认 inspect 不额外探测 Provider；请求活动时仍核对 input key、Session、Run 与原生来源，未知时保留输入能力，不授予投递或自动流转资格。Main 的空闲策略组合人类输入的首次原生结束与当前活动，不把维护心跳或客户端时钟当作这一来源。

## CLI 与服务的当前来源

### 命令注册与业务 owner

[`AGENTMUX_CLI_COMMANDS`](../../packages/core/src/agentmux-cli-commands.ts) 是对象命令的共同注册来源，`parseAgentMuxCliInvocation` 从它解析参数，[help 与运行时技能](../../packages/core/src/agentmux-cli-help.ts)从它生成说明。[agentmux.ts](../../packages/core/src/agentmux.ts) 处理 endpoint、调用与流输出；业务查询、角色绑定和消息编排进入 [`AgentMuxRpcService`](../../packages/core/src/public-rpc-service.ts)，CLI 不直接读写本地业务事实。公共方法、参数、结果与订阅类型归 [public-rpc.ts](../../packages/core/src/public-rpc.ts)；Main 在 [ipc.ts](../../apps/desktop/src/main/ipc.ts) 注入各 owner 的真实能力。

### 服务传输与接入层

[Server](../../packages/core/src/public-rpc-server.ts) 与 [Client](../../packages/core/src/public-rpc-client.ts) 使用同一 JSON-RPC 2.0 合同，支持默认的 Unix socket、显式启用的 HTTP／SSE、经 SSH 与 Tailcat stdio 转发到既有 Unix 服务，以及端到端加密的 Relay 帧传输。Hosted SDK 通过该服务管理远端 Core 的 Session；远端 AgentMux owner 消费其所在机器的 ctxmux，此实现不声称 ctxmux 有独立的远程 Run 协议。连接条件与分层边界见[系统接入边界](../architecture/system-ownership.md#当前接入边界)，行为约束见[对象优先 CLI 与统一公共业务服务](../design/behavior/public-control.md#对象优先-cli-与统一公共业务服务)。本页不复制对象树，服务入口存在也不代表所有宿主能力或安装后的可用性。

### 帧、回压与观察成本

JSON-lines 单帧编解码和字节上限由 [public-rpc-frame.ts](../../packages/core/src/public-rpc-frame.ts) 持有；官方 [Performance 脚本](../../apps/desktop/resources/toolkit/performance.mjs) 复用该实现，并顺序等待 stdout drain。CLI 的同步订阅回调由 [agentmux.ts](../../packages/core/src/agentmux.ts) 限制实际待发送的字节：正常的 highWaterMark 回压仍接纳合法帧，积压超限才报告并释放这个读取者。显式取消或积压失败时，释放订阅后丢弃自身待发送的输出；正常结束时完整 flush。

typed Metrics 由 [metrics.ts](../../packages/core/src/metrics.ts) 校验，Settings 的不透明叶子由 [settings-resource-json.ts](../../packages/core/src/settings-resource-json.ts) 校验；[control-codec.ts](../../packages/core/src/control-codec.ts) 对 Host Test／list 与 Executor Refresh 的外层不再按整个回执限制深度。行为边界见 [Toolkit 与官方 Performance](../design/behavior/settings-and-observation.md#toolkit-与官方-performance-工具)；实际脚本、公开 CLI／Unix 往返及变异验证的入口为 [verify-performance-protocol-boundaries.mjs](../../apps/desktop/scripts/verify-performance-protocol-boundaries.mjs)。

### 设备与移动连接

手机连接的来源为 [Relay framing](../../packages/core/src/public-rpc-relay.ts)、[有限浏览器 Hosted adapter](../../packages/core/src/relay-hosted.ts)、[设备领域类型及严格解析](../../packages/core/src/public-rpc-device.ts)和 [Host 的 Authority 组合](../../apps/host/src/host.ts)。`amux device link` 返回当前完整的公有 offer 链接，`device ls` 回读连接与设备事实，`device revoke --device ID` 撤销指定设备；设备命名只经已认证的 `device hello --name NAME`。GUI 复用同一服务，Relay 与手机页面由本机 Host 提供。接入、身份、重连与权限约束见[《手机版 Relay 连接》](../design/behavior/public-control.md#手机版-relay-连接)；构建成功不代替真机验收。

手机 Web 资源版本与页面观察由[中立 DTO](../../packages/core/src/mobile-web.ts)、[严格 codec](../../packages/core/src/mobile-web-codec.ts)和 [Host 资产 owner](../../apps/host/src/mobile-assets-owner.ts) 持有，`app mobile assets inspect/activate` 经公共服务与 Main 到 Host 的反向路由消费同一 owner；真实页面经 [mobile-web producer](../../apps/mobile/src/mobile-web/use-mobile-web-observation.ts) 报告编译与 URL namespace 身份。手机有限诊断经 [Host adapter](../../apps/host/src/mobile-web-report-owner.ts) 进入 `client.incident` 档案，查询复用 `system diagnostics inspect`；只有已认证页面能报送，Agent 不能代报。行为分别见[手机网页诊断](../design/diagnostic-evidence.md#手机网页的有限观察)与[手机客户端的网页诊断与更新](../design/behavior/mobile-client.md#网页诊断与更新)；激活、页面 loaded、用户看到和耐久性不互相代签。

核对能力时，按同一对象依次找业务类型、实际 owner、服务接线、CLI／Client 消费与验证证据；查看事实、修改状态与执行 Agent 的副作用分别明确。CLI 与 GUI 是同一业务 owner 的消费面，不是事实镜像。运行中的 help 只说明该执行版本公开了什么；源码、构建、安装与当前实例的身份需要分别核对。
