# 过程资料的留存与提交边界

**过程性文档不提交。** 本轮调研、计划、评审、交接、交付清单、状态快照、原型、想法和原始测量结果留在本机，根 `.gitignore` 忽略它们。不得用 `git add -f` 将其加入提交；文件已经进入索引或历史时，先保全本机内容和暂存版本，再移出 Git 跟踪，不能为了清理删除未保存的工作。

| 本机目录 | 内容 |
| --- | --- |
| `docs/research/` | 调研素材、参考评估、待确认建议 |
| `docs/plans/`、`docs/reviews/` | 本轮方案、任务计划、评审与验收证据 |
| `docs/handoffs/`、`docs/delivery/`、`docs/status/` | 交接、交付清单和状态快照 |
| `docs/prototypes/` | 探索原型 |
| `docs/ideas/` | 有价值需求或思路的记录与整合，包括待讨论和已确认但尚未执行的内容 |
| `docs/benchmarks/results/` | 原始测量输出与候选结果 |
| `.bagakit/`、`.tmp/`、`.local/` | Tracker、临时脚本和本机证据 |
| `.artifacts/` | 需要持续保留的本机交付物、素材及对应过程记录 |

已审核、具有长期读者价值的结论，应提炼进原 owning 设计、架构、接口、指南或事故案例，注明依据及适用范围；不把整份过程记录搬入长期目录。研究推断不冒充已确认约束，计划不冒充当前实现，旧验收不冒充新候选的通过结果。

## 生命周期与回收

过程资料留在本机不等于永久保留。创建者在生成前先确定用途、消费者和退出条件，能复用的源码、依赖、构建与证据不逐轮复制；隔离或复现确需副本时只保留所需范围。验收或交接完成后保留可追溯的必要结论、原始回执和不可重建或仍有用途的素材，及时回收确认不再使用的可重建构建、缓存、中间截图及重复副本。不要为了清理 worktree 把整个 ignored 树无差别打包留存，否则只是转移占用。

处理 worktree 和残留证据时先核对提交、未提交、未跟踪和 ignored 的独有内容，检查在用进程、工作面及后续消费者；分支不是 main 祖先不证明工作已合入，目录空闲也不证明 Session 或工作已终结。保全未保存工作、原 Session／Run 和恢复所需资料；归属、占用或用途未知时保留并在交接中说明。无需统一按日期删除，任务未结束时不为了清理破坏可复现性。

idea 记录和整合的顺序见[文档事实与维护规范](guides/document-truth-and-maintenance.md#以-idea-为原点记录和整合)。需求确认后，原 idea 仍是本机过程资料；确认内容进入长期文档，不因此将 idea 文件加入提交。

长期文档包括设计专题、架构机制、接口合同、操作指南、测试策略、可复用事故案例，以及 Benchmark 的测量协议。案例的现场草稿、逐轮排查日志和采样证据仍是本机过程资料；进入 `docs/casestudy/` 的是经过整理、来源和历史范围明确的案例，写法见[事故案例写作指南](guides/incident-writing.md)。

长期入口必须在没有本机过程目录时仍能解释规则和机制，不以忽略路径作为必要的合同来源。引用本机证据时明确其可选、仅本机和观察范围；证据缺席说明缺证，不推定通过。日常 diff 检查同时核对提交清单，确保没有过程目录内容；目录改成 ignored 不会自动清除已经暂存或跟踪的文件。

读者入口见[文档导航](README.md)，事实归属与维护规则见[文档事实与维护规范](guides/document-truth-and-maintenance.md)。本页唯一持有留存与提交边界。
